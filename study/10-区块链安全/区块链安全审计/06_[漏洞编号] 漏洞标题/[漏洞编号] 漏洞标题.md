### 5.3 撰写注意事项

1. **客观准确**：基于事实，不夸大不缩小
2. **清晰易懂**：让开发人员能够理解并复现
3. **可操作**：提供具体的修复建议，而非泛泛而谈
4. **完整**：包含所有必要的信息（位置、代码、PoC）
5. **专业**：使用规范的术语和格式
6. **保密**：报告发布前严格保密

### 5.4 常见的报告质量问题

| 问题 | 说明 |
|------|------|
| 描述模糊 | 漏洞描述不清，开发人员无法理解 |
| 缺少 PoC | 只有理论分析，没有实际验证 |
| 修复建议空泛 | 只说「修复这个问题」不说怎么修 |
| 风险等级不准确 | 高估或低估漏洞严重程度 |
| 代码引用错误 | 引用的代码行号或版本不对 |
| 遗漏重要信息 | 缺少影响范围、利用条件等 |
