# 审计实战技巧

### 8.1 审计前准备

1. **环境搭建**
   - 安装 Node.js、Python、Foundry 等工具
   - 配置 Solidity 编译器版本管理
   - 安装 Slither、Mythril 等安全工具

2. **资料阅读**
   - 先读白皮书和技术文档，理解业务逻辑
   - 了解项目的核心功能和设计目标
   - 查看是否有已有的审计报告和已知问题

3. **代码获取**
   - 确认代码版本（commit hash）
   - 安装依赖（npm install / forge install）
   - 确保代码能正常编译

### 8.2 审计技巧

#### 技巧一：从架构入手

- 先画合约关系图
- 理解每个合约的职责
- 找出核心合约和边缘合约
- 优先审计核心合约

#### 技巧二：关注资金流向

- 追踪 ETH 和代币的流动路径
- 检查所有涉及资金转移的函数
- 重点关注 mint、burn、transfer、withdraw 等函数

#### 技巧三：检查权限边界

- 列出所有的权限角色
- 检查每个角色能做什么
- 验证权限检查是否在每个敏感函数上都正确

#### 技巧四：寻找边界情况

- 数值为 0 的情况
- 数值为最大值的情况
- 数组为空的情况
- 第一次调用的情况
- 合约余额为 0 的情况

#### 技巧五：假设攻击者视角

- 如果我是攻击者，我会怎么攻击？
- 哪里是最薄弱的环节？
- 攻击收益是否大于攻击成本？

### 8.3 常见陷阱

1. **只看代码不理解业务**：业务逻辑漏洞往往是最严重的
2. **过度依赖工具**：工具只能发现已知模式的漏洞
3. **忽略经济模型**：很多 DeFi 攻击是经济模型问题
4. **只看单个合约**：漏洞可能在合约交互中产生
5. **忽略继承关系**：漏洞可能在父合约中
6. **不写 PoC**：不验证就无法确认漏洞是否真实存在
