# 共识协议安全分析

### 6.1 PBFT安全

```
PBFT (Practical Byzantine Fault Tolerance):

  容错能力: n >= 3f + 1 (n为节点总数，f为恶意节点数)
  即: 需要2/3+的节点诚实

  流程:
  1. 客户端发送请求给主节点
  2. Pre-prepare: 主节点广播给副本节点
  3. Prepare: 副本节点广播prepare消息
  4. 当收到2f+1个prepare -> 进入commit
  5. Commit: 广播commit消息
  6. 当收到2f+1个commit -> 执行请求
  7. 回复客户端

  安全保证:
  - 最终性: 区块一旦确认不可逆
  - 活性: 只要f < n/3，系统持续运行
  - 一致性: 所有诚实节点状态一致
```

### 6.2 拜占庭容错

```
BFT共识安全边界:

  同步网络: 容忍 f < n 节点(但实际不可能完全同步)
  部分同步: 容忍 f < n/3 节点(PBFT等)
  异步网络: 不可能(FLP不可能定理)

  FLP不可能定理:
  - 在异步网络中
  - 即使只有一个节点故障
  - 也不可能达成确定性共识

  实际解决方案:
  - 假设部分同步(最终同步)
  - 引入随机性
  - 或接受概率性最终性
```

### 6.3 最终性与概率性

```
最终性类型:

1. 概率性最终性 (Bitcoin/Ethereum PoW)
   - 区块越深，被回滚概率越低
   - 没有绝对最终性
   - 确认数增加安全性

2. 经济最终性 (Ethereum PoS)
   - 区块被回滚需要大量ETH被削减
   - 经济上不可行
   - 半确定性

3. 即时最终性 (Tendermint/PBFT)
   - 区块确认后立即最终
   - 不可回滚
   - 高安全性但低灵活性

混合最终性:
  - Ethereum: Casper FFG (checkpoint)
  - 检查点之前: 概率性
  - 检查点之后: 确定性

  安全分析:
  - 概率性: 适合开放网络，但大额交易需等待
  - 即时性: 适合联盟链，快速确认
  - 混合: 平衡安全性和性能
```
