### 11.1 ECDSA随机数重用漏洞

```python
# ECDSA随机数重用导致私钥恢复
# 历史案例: 2012 Android Bitcoin钱包

def recover_ecdsa_private_key(r, s1, s2, z1, z2):
    """
    当两个签名使用相同的随机数k时恢复私钥
    
    参数:
        r: 两个签名的r值(相同，因为k相同)
        s1, s2: 两个签名的s值
        z1, z2: 两个消息的哈希值
    返回:
        d: 私钥
    """
    # ECDSA签名方程:
    # s1 = k^(-1) * (z1 + r * d) mod n
    # s2 = k^(-1) * (z2 + r * d) mod n
    #
    # 两式相减:
    # s1 - s2 = k^(-1) * (z1 - z2) mod n
    # k = (z1 - z2) / (s1 - s2) mod n
    #
    # 代入原式求d:
    # d = (s1 * k - z1) / r mod n

    # 需要模运算库
    from sympy import mod_inverse

    n = 0xFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFEBAAEDCE6AF48A03BBFD25E8CD0364141  # secp256k1阶

    # 恢复k
    delta_s = (s1 - s2) % n
    delta_z = (z1 - z2) % n
    k = (delta_z * mod_inverse(delta_s, n)) % n

    # 恢复私钥d
    d = ((s1 * k - z1) * mod_inverse(r, n)) % n

    return d

# 示例: 两个使用相同k的签名
# 这些是模拟值，实际攻击需要真实的签名数据
r  = 0x79BE667EF9DCBBAC55A06295CE870B07029BFCDB2DCE28D959F2815B16F81798
s1 = 0x381F5B1C8B89F8B8E0E2A6C8D0F3E5B7A1C2D3E4F5A6B7C8D9E0F1A2B3C4D5E6
s2 = 0x4A5B6C7D8E9F0A1B2C3D4E5F6A7B8C9D0E1F2A3B4C5D6E7F8A9B0C1D2E3F4A5B
z1 = 0x1234567890ABCDEF1234567890ABCDEF1234567890ABCDEF1234567890ABCDEF
z2 = 0xFEDCBA0987654321FEDCBA0987654321FEDCBA0987654321FEDCBA0987654321

private_key = recover_ecdsa_private_key(r, s1, s2, z1, z2)
print(f"恢复的私钥: {hex(private_key)}")
```

### 11.2 交易延展性攻击(MT.Gox案例)

```
交易延展性攻击 - MT.Gox事件(2014)

攻击原理:
  ECDSA签名(s, r)中，s可以取 s 或 n-s(n为曲线阶)
  两者都验证通过，但产生不同的交易ID(TXID)

  原始签名: (r, s) -> TXID_1
  修改签名: (r, n-s) -> TXID_2
  同一笔交易，不同TXID

MT.Gox利用:
  1. 用户在MT.Gox提现BTC
  2. MT.Gox广播交易(TXID_1)
  3. 攻击者(或MT.Gox自己)修改签名
  4. 修改后的交易(TXID_2)被打包
  5. MT.Gox查找TXID_1 -> 找不到
  6. 认为提现未成功 -> 重复提现
  7. 用户的BTC实际已转出

影响:
  - MT.Gox声称丢失85万BTC
  - 部分可能是内部利用延展性
  - 2014年MT.Gox破产
  - 促使比特币引入SegWit(修复延展性)

防御:
  - SegWit(隔离见证): 签名数据移到witness字段
  - TXID不再包含签名数据
  - 签名修改不影响TXID
  - 彻底解决延展性问题
```

### 11.3 智能合约重入攻击与区块链底层交互

```
重入攻击与底层机制关系:

虽然重入攻击是智能合约层漏洞，但与底层机制密切相关:

1. 内部交易(Call)的原子性
   - 以太坊中一个交易可以触发多个内部调用
   - 如果合约在更新状态前发送ETH
   - 接收合约的fallback可以重入发送合约
   - 利用Solidity的call.value()不检查重入

2. Gas机制利用
   - 攻击者利用Gas限制控制重入次数
   - 在Gas耗尽前完成攻击
   - EIP-1884调整Gas成本影响了攻击可行性

3. 底层修复:
   - EIP-2200: 引入瞬时存储
   - EIP-2929: 气体成本重定价
   - EIP-3529: 降低退Gas
   - 这些改变了重入攻击的经济性
```
