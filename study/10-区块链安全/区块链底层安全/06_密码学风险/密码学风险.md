# 密码学风险

### 5.1 哈希碰撞

```
区块链哈希函数安全:

  SHA-256 (Bitcoin)
  - 输出: 256位
  - 碰撞阻力: 2^128 (生日攻击)
  - 当前安全

  Keccak-256 (Ethereum)
  - 输出: 256位
  - 与SHA-3标准不同
  - 当前安全

  风险:
  - 量子计算: Grover算法将碰撞搜索降低到2^(n/2)但SHA-256仍有128位安全
  - 算法缺陷: 发现哈希函数弱点可能影响
  - 历史教训: MD5已被攻破，SHA-1已被攻破
```

### 5.2 签名漏洞

```
ECDSA签名风险:

1. 随机数重用 (K重用)
   - 如果两个签名使用相同的随机数k
   - 可以推导出私钥

   攻击公式:
   r = (k * G).x mod n
   s = k^(-1)(z + r * d) mod n
   其中 z = hash(message), d = private key

   如果两个签名使用相同k:
   s1 = k^(-1)(z1 + r * d)
   s2 = k^(-1)(z2 + r * d)
   -> d = (s1*z2 - s2*z1) / (s2*r - s1*r)

   历史案例:
   - 2012 Android Bitcoin钱包随机数问题
   - 2015 Sony PlayStation 3 ECDSA密钥泄露

2. 签名延展性
   - ECDSA签名有多种有效形式
   - 攻击者修改签名但不改变验证结果
   - 导致交易ID变化 -> 影响交易链

3. 侧信道攻击
   - 通过功耗分析推导k值
   - 通过时间分析推导私钥

防御:
  - 使用RFC 6979确定性ECDSA
  - 使用Ed25519(确定性签名)
  - 硬件钱包保护密钥
  - 防止侧信道
```

### 5.3 随机数问题

```
区块链中的随机数用途:
  - 出块者选择
  - 密码学签名
  - 智能合约中的随机数
  - 彩票/博彩应用

随机数安全风险:

1. 区块时间戳作为随机数
   - 矿工可以微调时间戳
   - 影响随机数结果
   - 不安全

2. 区块哈希作为随机数
   - 矿工可以通过不发布区块影响哈希
   - "住手(Grinding)"攻击

3. RANDAO + VRF
   - 多方提交哈希承诺
   - VRF生成可验证随机数
   - 更安全但仍需防住手

4. 链外随机数
   - 使用Oraclize获取外部随机数
   - 信任Oracle
   - 可能被操纵

安全方案:
  - commit-reveal方案
  - VRF (Verifiable Random Function)
  - 多方随机数生成
  - 外部安全随机数源
```

### 5.4 量子计算威胁

```
量子计算对区块链的威胁:

1. Shor算法
   - 可以高效分解大整数 -> RSA不安全
   - 可以高效求解离散对数 -> ECDSA不安全
   - 影响所有基于ECC的签名

2. Grover算法
   - 将哈希碰撞搜索从2^n降低到2^(n/2)
   - SHA-256仍有128位安全(可接受)
   - 但签名安全受影响

时间线估算:
  - 当前: 量子计算能力有限
  - 5-10年: 可能出现对RSA-2048的威胁
  - 15-20年: 可能对ECC-256构成威胁

防御方案:
  - 后量子密码学(PQC)
  - 基于格的签名 (Dilithium, Falcon)
  - 基于哈希的签名 (Lamport, XMSS)
  - 基于编码的签名 (McEliece)

  具体措施:
  - 使用抗量子签名替代ECDSA
  - 增加哈希输出长度
  - 一次性签名(防量子)
  - 密钥轮换减少暴露
```
