# DeFi 安全风险

### 9.1 什么是 DeFi

DeFi（Decentralized Finance，去中心化金融）是建立在区块链上的金融应用生态，无需中心化中介。

**DeFi 生态：**
```
┌─────────────────────────────────────────────────┐
│  应用层：DEX、借贷、衍生品、收益聚合器、保险...    │
├─────────────────────────────────────────────────┤
│  协议层：ERC20、ERC721、借贷协议、AMM...         │
├─────────────────────────────────────────────────┤
│  底层链：Ethereum、BSC、Solana...               │
└─────────────────────────────────────────────────┘
```

### 9.2 DeFi 主要类别

| 类别 | 说明 | 代表项目 |
|------|------|---------|
| **DEX（去中心化交易所）** | 点对点代币交易 | Uniswap、SushiSwap、Curve |
| **借贷协议** | 去中心化存贷款 | Aave、Compound、MakerDAO |
| **收益聚合器** | 自动寻找最高收益策略 | Yearn、Beefy、Convex |
| **衍生品** | 去中心化衍生品交易 | dYdX、Synthetix、GMX |
| **稳定币** | 与法币挂钩的加密货币 | USDT、USDC、DAI、FRAX |
| **流动性挖矿** | 提供流动性获取奖励 | 各类 DeFi 项目 |
| **保险** | 去中心化保险协议 | Nexus Mutual、InsurAce |

### 9.3 DeFi 安全风险分类

#### 9.3.1 智能合约风险

| 风险类型 | 说明 |
|---------|------|
| **重入攻击** | 外部调用前未更新状态 |
| **整数溢出** | 算术运算超出范围 |
| **访问控制漏洞** | 权限校验不严 |
| **逻辑漏洞** | 业务逻辑设计缺陷 |
| **预言机操纵** | 操控价格预言机 |
| **闪电贷攻击** | 利用闪电贷放大攻击效果 |

#### 9.3.2 经济模型风险

| 风险类型 | 说明 |
|---------|------|
| **无常损失** | 流动性提供者因价格波动产生的损失 |
| **死亡螺旋** | 价格下跌 → 清算 → 价格进一步下跌 |
| **挤兑风险** | 用户同时提取资金导致流动性枯竭 |
| **代币经济设计缺陷** | 代币模型不可持续 |

#### 9.3.3 治理风险

| 风险类型 | 说明 |
|---------|------|
| **治理攻击** | 控制投票执行恶意提案 |
| **治理中心化** | 少数人控制大部分投票权 |
| **投票贿赂** | 贿赂选民投票支持特定提案 |

#### 9.3.4 其他风险

| 风险类型 | 说明 |
|---------|------|
| **Rug Pull** | 项目方卷款跑路 |
| **智能合约升级风险** | 升级引入新漏洞或恶意代码 |
| **可组合性风险** | 多个协议组合带来的级联风险 |
| **监管风险** | 政策变化影响项目运营 |

### 9.4 闪电贷攻击详解

#### 9.4.1 什么是闪电贷

闪电贷（Flash Loan）是一种无抵押贷款，借款和还款必须在同一笔交易中完成。如果还款失败，整个交易回滚，就像从未发生过一样。

**特点：**
- 无抵押
- 零风险（对出借方）
- 同一交易内借贷和还款
- 利用交易原子性

#### 9.4.2 闪电贷攻击模式

```
攻击步骤：
  1. 从闪电贷池借出大量资金
  2. 利用资金进行攻击（价格操纵、重入等）
  3. 归还闪电贷本金 + 手续费
  4. 剩余利润归攻击者

如果攻击失败：
  → 整个交易回滚
  → 攻击者只损失 gas 费
  → 零成本试错！
```

#### 9.4.3 著名闪电贷攻击

### 9.5 DeFi 安全建议

#### 对于用户：
1. 只使用经过审计的知名协议
2. 不要把所有资产放在一个协议中
3. 了解协议的风险机制
4. 关注项目方的透明度和声誉
5. 警惕高得离谱的收益（APY）
6. 使用硬件钱包交互
7. 授权前仔细检查授权额度

#### 对于项目方：
1. 进行专业的安全审计
2. 设立安全基金和保险
3. 使用时间锁（Timelock）延迟执行
4. 建立应急响应机制
5. 透明公开团队和资金使用
6. 进行形式化验证
7. 设立漏洞赏金计划
