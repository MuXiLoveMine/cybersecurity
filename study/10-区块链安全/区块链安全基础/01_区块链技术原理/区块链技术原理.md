# 区块链技术原理

### 1.1 什么是区块链

区块链（Blockchain）是一种去中心化的分布式账本技术，通过密码学方法将数据区块按时间顺序链式连接，确保数据的不可篡改性和可追溯性。

**核心特点：**

| 特点 | 说明 |
|------|------|
| **去中心化** | 没有中心化节点，所有节点共同维护账本 |
| **不可篡改** | 一旦数据上链，修改需要控制全网 51% 以上算力 |
| **可追溯** | 所有交易记录公开可查，可追溯到创世区块 |
| **透明公开** | 账本数据对所有参与者公开 |
| **集体维护** | 由全网节点共同验证和维护 |
| **可编程** | 支持智能合约，实现自动化业务逻辑 |

### 1.2 区块结构

每个区块由**区块头（Block Header）**和**区块体（Block Body）**两部分组成。

#### 1.2.1 区块头（Block Header）

```
┌─────────────────────────────────────────────────┐
│                   区块头                          │
├─────────────────────────────────────────────────┤
│ 版本号（Version）         4 字节                   │
│ 前一区块哈希（Prev Hash）  32 字节                  │
│ Merkle 根哈希            32 字节                  │
│ 时间戳（Timestamp）       4 字节                   │
│ 难度目标（Difficulty）    4 字节                   │
│ 随机数（Nonce）           4 字节                   │
└─────────────────────────────────────────────────┘
```

**各字段说明：**

- **版本号**：区块版本，用于协议升级
- **前一区块哈希**：上一个区块头的 SHA-256 哈希值，形成链式结构
- **Merkle 根哈希**：区块体中所有交易的 Merkle 树根哈希，用于快速验证交易
- **时间戳**：区块生成的 Unix 时间戳
- **难度目标**：挖矿难度，决定了哈希计算的目标值
- **随机数（Nonce）**：矿工挖矿时不断调整的数值，用于满足难度要求

#### 1.2.2 区块体（Block Body）

区块体包含该区块中的所有交易记录，以 Merkle 树的形式组织。

**Merkle 树结构示例：**

```
           Merkle Root (H1234)
          /                  \
     H12 (H1+H2)          H34 (H3+H4)
    /         \          /         \
  H1(Tx1)   H2(Tx2)   H3(Tx3)   H4(Tx4)
```

**Merkle 树的作用：**
1. **快速验证**：只需 O(log n) 时间即可验证某笔交易是否在区块中
2. **轻节点支持**：SPV（简单支付验证）节点只需下载区块头即可验证交易
3. **数据完整性**：任何交易的修改都会导致 Merkle 根变化

### 1.3 链式结构

区块链通过每个区块头中的「前一区块哈希」字段形成链式结构。

```
创世区块 ← 区块1 ← 区块2 ← 区块3 ← ... ← 最新区块
  (高度0)  (高度1)  (高度2)  (高度3)         (高度N)
```

**链式结构的安全性：**
- 修改任意一个区块的数据，会导致该区块哈希变化
- 后续所有区块的「前一区块哈希」都需要重新计算
- 在 PoW 链中，这需要重新完成所有后续区块的工作量证明
- 因此，区块确认数越多，被篡改的难度越大

**确认数与安全性的关系：**
- **1 个确认**：交易已被打包进区块，但仍有被回滚的可能
- **6 个确认**：比特币网络的标准安全确认数，篡改概率极低
- **12 个确认**：对于大额交易的更高安全标准

### 1.4 共识机制

共识机制是区块链网络中所有节点就账本状态达成一致的算法。

#### 1.4.1 PoW（工作量证明）

**原理：** 节点通过计算满足特定条件的哈希值（挖矿）来获得记账权。

```
目标：找到一个 Nonce，使得 SHA256(SHA256(区块头 + Nonce)) < 难度目标值
```

**优点：**
- 安全性高，去中心化程度高
- 经过比特币 10+ 年验证
- 抗女巫攻击能力强

**缺点：**
- 能源消耗巨大
- 交易吞吐量低（比特币约 7 TPS）
- 出块时间长（比特币约 10 分钟）

**代表项目：** Bitcoin、Ethereum（2022 年合并前）、Litecoin

#### 1.4.2 PoS（权益证明）

**原理：** 节点根据持有的代币数量（权益）和时间来获得记账权。

```
记账权 ∝ 质押代币数量 × 质押时间
```

**优点：**
- 能源效率高（相比 PoW 节能 99%+）
- 交易吞吐量高
- 出块时间短

**缺点：**
- 富者愈富（马太效应）
- 存在「无利害关系」（Nothing at Stake）问题
- 长程攻击风险

**代表项目：** Ethereum（2022 年合并后）、Cardano、Solana

#### 1.4.3 DPoS（委托权益证明）

**原理：** 持币者投票选举出一定数量的代表节点，由这些代表轮流出块。

**优点：**
- 交易速度快，吞吐量高
- 出块时间短

**缺点：**
- 去中心化程度低
- 容易形成节点寡头

**代表项目：** EOS、TRON

#### 1.4.4 PBFT（实用拜占庭容错）

**原理：** 通过多轮投票达成共识，适用于节点数量有限的联盟链。

```
三阶段提交：
1. Pre-prepare：主节点广播提案
2. Prepare：副本节点验证并广播准备消息
3. Commit：节点确认提交
```

**优点：**
- 交易确认速度快
- 最终性好（一旦确认不可回滚）
- 吞吐量高

**缺点：**
- 节点数有限（通常不超过 100 个）
- 去中心化程度低

**代表项目：** Hyperledger Fabric、FISCO BCOS、联盟链

#### 1.4.5 其他共识机制

| 共识机制 | 原理 | 代表项目 |
|---------|------|---------|
| **PoH（历史证明）** | 用可验证的延迟函数记录事件顺序 | Solana |
| **PoA（权威证明）** | 由可信节点验证交易 | POA Network |
| **PoSpace（空间证明）** | 用存储空间代替算力 | Chia |
| **混合共识** | 多种共识机制结合 | Cosmos、Polkadot |

### 1.5 加密算法

区块链安全的基石是现代密码学。

#### 1.5.1 哈希算法

**SHA-256（比特币使用）：**
- 输出：256 位（32 字节）
- 特点：单向性、抗碰撞性、雪崩效应
- 用途：区块哈希、交易哈希、地址生成

**Keccak-256（以太坊使用）：**
- 输出：256 位
- 特点：SHA-3 标准的前身
- 用途：合约地址、函数选择器、事件主题

**哈希算法的安全特性：**
1. **单向性**：从输出无法反推输入
2. **抗碰撞性**：难以找到两个不同输入产生相同输出
3. **雪崩效应**：输入微小变化导致输出巨大变化

#### 1.5.2 非对称加密

**ECDSA（椭圆曲线数字签名算法）：**

```
密钥生成：
  私钥（privateKey）：随机数，256 位
  公钥（publicKey）：私钥 × 椭圆曲线基点 G
  地址（address）：哈希(公钥)的后 20 字节

签名过程：
  signature = sign(message, privateKey)

验证过程：
  verify(message, signature, publicKey) → true/false
```

**比特币使用：** secp256k1 曲线
**以太坊使用：** secp256k1 曲线

**重要特性：**
- 私钥生成公钥是单向的（无法从公钥反推私钥）
- 签名可以用公钥验证，但无法伪造
- 地址是公钥的哈希（无法从地址反推公钥，除非有交易签名）

#### 1.5.3 默克尔树（Merkle Tree）

**作用：** 高效验证大量数据的完整性

**应用场景：**
- 区块交易验证
- 轻客户端（SPV）
- 状态树（以太坊的状态 Patricia 树）
