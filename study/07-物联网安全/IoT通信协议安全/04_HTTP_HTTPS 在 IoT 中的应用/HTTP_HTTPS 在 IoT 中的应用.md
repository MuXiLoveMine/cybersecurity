# HTTP/HTTPS 在 IoT 中的应用

### 4.1 HTTP 在 IoT 中的应用场景

虽然 HTTP 协议较重，但在物联网中仍有广泛应用：
- 设备固件更新 (OTA)
- 设备注册和激活
- 数据上报（资源相对充足的设备）
- Web 管理界面
- RESTful API 调用

### 4.2 HTTP 安全风险

| 风险类型 | 描述 | IoT 场景示例 |
|---------|------|-------------|
| **明文传输** | HTTP 不加密，数据可被嗅探 | 固件下载时被篡改、凭证被截获 |
| **Web 漏洞** | SQL 注入、XSS、命令注入等 | 设备管理界面存在命令注入 |
| **弱认证** | 简单密码、无认证 | 管理后台弱口令 |
| **API 安全** | API 密钥泄露、越权访问 | 云平台 API 越权 |
| **固件篡改** | OTA 更新时固件被篡改 | 中间人替换固件文件 |

### 4.3 HTTPS 安全配置

#### 4.3.1 TLS 配置最佳实践

```
# 安全的 TLS 配置（适用于 IoT 设备）
协议版本：TLS 1.2 或 TLS 1.3
加密套件（TLS 1.2）：
  - ECDHE-ECDSA-AES128-GCM-SHA256
  - ECDHE-RSA-AES128-GCM-SHA256
  - ECDHE-ECDSA-AES256-GCM-SHA384
  - ECDHE-RSA-AES256-GCM-SHA384
证书验证：启用
主机名验证：启用
证书固定 (Certificate Pinning)：推荐（防止中间人）
```

#### 4.3.2 证书固定 (Certificate Pinning)

证书固定是一种防止中间人攻击的技术，在客户端内置服务器证书或公钥指纹。

**原理**：
```
正常 HTTPS：
客户端 -> 验证证书链 -> 信任 CA 签发的证书

证书固定：
客户端 -> 验证证书链 + 验证证书指纹 -> 必须匹配内置指纹
```

**优点**：
- 有效防止中间人攻击
- 即使 CA 被攻破也能保证安全

**缺点**：
- 证书更新时需要更新设备固件
- 管理复杂度较高

#### 4.3.3 OTA 安全

OTA（Over-The-Air）固件更新是 IoT 设备的重要功能，也是重要的安全攻击面。

**OTA 安全要求**：
1. **固件完整性**：验证固件未被篡改（使用数字签名）
2. **固件真实性**：验证固件来自可信来源（使用厂商签名）
3. **固件机密性**：敏感固件可加密传输
4. **防回滚**：防止降级到有漏洞的旧版本
5. **断点续传**：确保更新过程中断电不影响设备

**安全的 OTA 流程**：
```
┌─────────┐   1. 检查更新     ┌─────────┐
│  IoT 设备│ ---------------> │ 更新服务器│
│         │ <---------------  │         │
│         │   2. 返回版本信息  │         │
│         │                  │         │
│         │   3. 下载固件     │         │
│         │ ---------------> │         │
│         │ <---------------  │         │
│         │   4. 固件数据(加密)│         │
│         │                  │         │
│         │   5. 验证签名     │         │
│         │   6. 解密固件     │         │
│         │   7. 写入闪存     │         │
│         │   8. 重启更新     │         │
└─────────┘                  └─────────┘
```
