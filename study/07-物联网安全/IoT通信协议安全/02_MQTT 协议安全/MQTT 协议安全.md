# MQTT 协议安全

### 2.1 MQTT 协议基础

#### 2.1.1 协议简介

MQTT（Message Queuing Telemetry Transport，消息队列遥测传输）是一个轻量级、基于发布/订阅模式的消息协议，运行在 TCP/IP 协议之上。

**核心特性**：
- 轻量级：协议头最小仅 2 字节
- 发布/订阅模式：解耦生产者和消费者
- 三种 QoS 等级：最多一次、至少一次、恰好一次
- 遗嘱消息 (Will)：设备异常下线通知
- 保留消息 (Retained)：新订阅者可获取最新消息

#### 2.1.2 协议架构

```
                    ┌──────────────┐
                    │  MQTT Broker │
                    │  （代理服务器）│
                    └──────┬───────┘
                           │
          ┌────────────────┼────────────────┐
          ▼                ▼                ▼
    ┌──────────┐     ┌──────────┐     ┌──────────┐
    │ Publisher│     │Subscriber1│     │Subscriber2│
    │ （发布者）│     │（订阅者1） │     │（订阅者2） │
    └──────────┘     └──────────┘     └──────────┘
```

#### 2.1.3 主题 (Topic) 结构

MQTT 使用层级主题结构，用斜杠 `/` 分隔：

```
sensors/room1/temperature        # 房间1的温度传感器
sensors/+/temperature            # 所有房间的温度传感器 (+ 单级通配符)
sensors/#                        # 所有传感器主题 (# 多级通配符)
$SYS/broker/clients/total        # 系统主题（以$开头）
```

### 2.2 MQTT 安全风险

#### 2.2.1 认证相关风险

| 风险类型 | 描述 | 影响 |
|---------|------|------|
| **匿名访问** | Broker 允许匿名连接，无需认证 | 任何人都可以连接并发布/订阅消息 |
| **弱口令** | 使用弱密码或默认密码 | 易被暴力破解 |
| **硬编码凭证** | 客户端凭证硬编码在固件中 | 固件泄露导致凭证泄露 |
| **凭证复用** | 多个设备使用相同凭证 | 一个设备泄露影响所有设备 |

**典型案例**：公网大量 MQTT Broker 允许匿名访问，攻击者可以订阅敏感主题获取设备数据，或发布恶意消息控制设备。

#### 2.2.2 授权相关风险

| 风险类型 | 描述 | 影响 |
|---------|------|------|
| **过度授权** | 用户拥有超出需要的主题权限 | 可越权访问敏感主题 |
| **无 ACL 控制** | 认证用户可访问所有主题 | 横向移动风险大 |
| **通配符滥用** | 允许使用 # 订阅所有主题 | 信息泄露风险 |
| **发布权限过大** | 可向任意主题发布消息 | 可控制设备、注入恶意数据 |

**典型案例**：某智能家居平台的 MQTT Broker 未设置 ACL，攻击者在获得一个设备的凭证后，可以控制平台上的所有设备。

#### 2.2.3 传输安全风险

| 风险类型 | 描述 | 影响 |
|---------|------|------|
| **明文传输** | 未使用 TLS/SSL 加密 | 消息可被嗅探，凭证可被截获 |
| **弱加密套件** | 使用弱 TLS 配置 | 可能被破解 |
| **证书验证缺失** | 客户端不验证服务器证书 | 中间人攻击 |
| **自签名证书** | 使用自签名证书且未正确配置 | 信任链问题 |

#### 2.2.4 协议相关风险

| 风险类型 | 描述 | 影响 |
|---------|------|------|
| **Topic 枚举** | 通过尝试订阅发现有效主题 | 信息收集，为后续攻击做准备 |
| **消息篡改** | 中间人篡改消息内容 | 设备控制指令被篡改 |
| **拒绝服务** | 大量连接或消息耗尽 Broker 资源 | 服务不可用 |
| **保留消息滥用** | 恶意发布保留消息 | 新订阅者收到错误信息 |
| **遗嘱消息伪造** | 伪造设备下线消息 | 干扰系统状态判断 |

### 2.3 MQTT 安全机制

#### 2.3.1 认证机制

**1. 用户名/密码认证**

```
客户端 CONNECT 报文结构：
┌─────────────────────────────────────┐
│ 固定报头 (2字节)                    │
├─────────────────────────────────────┤
│ 可变报头                            │
│ ├── 协议名 "MQTT"                   │
│ ├── 协议级别 (4=3.1.1, 5=5.0)       │
│ ├── 连接标志 (含用户名/密码标志位)   │
│ └── 保持连接时间                    │
├─────────────────────────────────────┤
│ 有效载荷                            │
│ ├── 客户端 ID (Client ID)           │
│ ├── [遗嘱主题]                      │
│ ├── [遗嘱消息]                      │
│ ├── 用户名 (Username)               │
│ └── 密码 (Password)                 │
└─────────────────────────────────────┘
```

**安全配置建议**：
- 禁用匿名访问
- 使用强密码策略
- 每个设备使用唯一凭证
- 定期更换凭证
- 限制登录失败次数（防暴力破解）

**2. 客户端证书认证 (mTLS)**

使用双向 TLS 认证，客户端和服务器互相验证证书：
- 安全性最高
- 每个设备拥有唯一证书
- 管理复杂度较高
- 适用于安全要求高的场景

**3. Token 认证**

使用 JWT 或其他 Token 进行认证：
- 适合云平台集成
- 可设置过期时间
- 便于动态管理

#### 2.3.2 授权机制 (ACL)

MQTT 的访问控制列表 (ACL) 用于控制客户端对主题的发布和订阅权限。

**ACL 规则示例（Mosquitto）**：
```
# 用户 alice 只能向 sensors/room1/# 发布消息
user alice
topic write sensors/room1/#

# 用户 bob 只能订阅 alarms/+ 主题
user bob
topic read alarms/+

# 用户 admin 可以发布和订阅所有主题
user admin
topic readwrite #

# 所有用户可以订阅 $SYS/broker/clients/+/status
pattern read $SYS/broker/clients/%u/status
```

**安全配置建议**：
- 遵循最小权限原则
- 禁止使用 `#` 通配符的全主题访问
- 使用 `%u`（用户名）和 `%c`（Client ID）实现动态 ACL
- 分离发布和订阅权限
- 敏感主题严格控制访问权限

#### 2.3.3 传输加密 (TLS/SSL)

**MQTT over TLS**：
- 默认端口：8883（MQTT/TLS）、443（MQTT over WebSocket/TLS）
- 使用 TLS 1.2 或更高版本
- 禁用 SSLv3、TLS 1.0、TLS 1.1

**TLS 配置最佳实践**：
```
# Mosquitto TLS 配置示例
listener 8883
protocol mqtt
cafile /etc/mosquitto/certs/ca.crt
certfile /etc/mosquitto/certs/server.crt
keyfile /etc/mosquitto/certs/server.key
tls_version tlsv1.2
ciphers ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384
require_certificate true  # 启用客户端证书认证
use_identity_as_username true
```

**推荐的加密套件（强安全）**：
- TLS_AES_256_GCM_SHA384（TLS 1.3）
- TLS_CHACHA20_POLY1305_SHA256（TLS 1.3）
- ECDHE-ECDSA-AES256-GCM-SHA384
- ECDHE-RSA-AES256-GCM-SHA384

#### 2.3.4 MQTT 5.0 安全增强

MQTT 5.0 引入了多项安全增强特性：

| 特性 | 说明 |
|------|------|
| **认证增强** | 支持增强认证 (Enhanced Authentication)，可集成 SASL 等机制 |
| **共享订阅** | 支持共享订阅，提高消息处理安全性 |
| **主题别名** | 减少主题名称传输，降低泄露风险 |
| **用户属性** | 可传递自定义安全属性 |
| **响应主题** | 规范请求/响应模式，提高安全性 |
