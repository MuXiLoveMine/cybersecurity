# IoT 通信协议概述

### 1.1 协议分类

物联网通信协议种类繁多，按照 OSI 模型可分为以下几层：

```
┌─────────────────────────────────────────────────────┐
│                   应用层协议                         │
│  MQTT / CoAP / HTTP / XMPP / AMQP / DDS / LwM2M    │
├─────────────────────────────────────────────────────┤
│                   传输层协议                         │
│  TCP / UDP / DTLS / QUIC                            │
├─────────────────────────────────────────────────────┤
│                   网络层协议                         │
│  IPv4 / IPv6 / 6LoWPAN / RPL                        │
├─────────────────────────────────────────────────────┤
│                   链路层协议                         │
│  WiFi / BLE / ZigBee / LoRa / NB-IoT / Ethernet    │
└─────────────────────────────────────────────────────┘
```

### 1.2 按传输距离分类

| 分类 | 典型协议 | 传输距离 | 适用场景 |
|------|---------|---------|---------|
| **短距离无线** | BLE、ZigBee、Z-Wave、NFC | 数米~数十米 | 智能家居、可穿戴设备 |
| **中距离无线** | WiFi | 数十米~数百米 | 家庭、办公场所 |
| **长距离无线 (LPWAN)** | LoRaWAN、NB-IoT、Sigfox | 数公里~数十公里 | 智慧城市、远程监测 |
| **有线** | Ethernet、RS-485、PLC | 视具体介质 | 工业控制、固定设备 |

### 1.3 协议安全设计原则

1. **认证 (Authentication)**：确认通信双方身份的真实性
2. **授权 (Authorization)**：控制对资源的访问权限
3. **保密性 (Confidentiality)**：确保数据不被未授权方读取
4. **完整性 (Integrity)**：确保数据在传输过程中不被篡改
5. **可用性 (Availability)**：确保通信服务持续可用
6. **不可否认性 (Non-repudiation)**：确保操作不可否认
