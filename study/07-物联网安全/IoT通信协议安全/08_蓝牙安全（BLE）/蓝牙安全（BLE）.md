# 蓝牙安全（BLE）

### 8.1 BLE 基础

BLE（Bluetooth Low Energy，低功耗蓝牙）是蓝牙技术联盟推出的低功耗无线通信技术。

**特点**：
- 低功耗：纽扣电池可工作数月至数年
- 短距离：典型 10~30 米
- 快速连接：连接建立时间 < 6ms
- 应用广泛：可穿戴设备、智能家居、健康医疗

#### 8.1.1 BLE 协议栈

```
┌─────────────────────────────────────┐
│           GAP / GATT                │  通用访问配置文件 / 通用属性配置文件
├─────────────────────────────────────┤
│           L2CAP                     │  逻辑链路控制和适配协议
├─────────────────────────────────────┤
│           HCI                       │  主机控制接口
├─────────────────────────────────────┤
│           Link Layer                │  链路层
├─────────────────────────────────────┤
│           Physical Layer            │  物理层
└─────────────────────────────────────┘
```

#### 8.1.2 GATT 结构

```
GATT 服务 (Service)
├── Characteristic 1 (特征)
│   ├── Value (值)
│   ├── Descriptor 1 (描述符)
│   └── Descriptor 2
├── Characteristic 2
│   ├── Value
│   └── Descriptor 1
└── ...
```

每个 Service 和 Characteristic 都有一个 UUID 标识。

### 8.2 BLE 安全机制

#### 8.2.1 安全模式

**安全模式 1（加密）**：
- 级别 1：无安全（无加密、无认证）
- 级别 2：未认证的加密（Just Works 配对）
- 级别 3：认证的加密（Passkey/Out-of-Band 配对）
- 级别 4：认证的加密 + LE Secure Connections

**安全模式 2（数据签名）**：
- 级别 1：未认证的数据签名
- 级别 2：认证的数据签名

#### 8.2.2 配对方式

| 配对方式 | 说明 | 安全性 | 适用场景 |
|---------|------|--------|---------|
| **Just Works** | 自动配对，无需用户交互 | 低 | 无输入输出设备 |
| **Passkey Entry** | 输入 6 位数字验证码 | 中 | 有显示屏或键盘的设备 |
| **Out of Band (OOB)** | 通过其他通道交换密钥 | 高 | 有 NFC 等辅助通道 |
| **LE Secure Connections** | 蓝牙 4.2+ 引入，使用 ECDH | 高 | 新设备 |

#### 8.2.3 LE Secure Connections

蓝牙 4.2 引入的安全配对机制：
- 使用椭圆曲线 Diffie-Hellman (ECDH) 密钥交换
- 提供前向保密性
- 防止中间人攻击（使用认证方式时）
- 使用 AES-CCM 加密

### 8.3 BLE 安全风险

#### 8.3.1 配对攻击

**攻击 1：Just Works 中间人攻击**

```
正常配对：
设备 A <-------------> 设备 B
       （Just Works）

中间人攻击：
设备 A <---> 攻击者 <---> 设备 B
       配对        配对
```

**攻击条件**：
- 设备使用 Just Works 配对方式
- 攻击者在配对期间处于通信范围内

**防护措施**：
- 使用 Passkey Entry 或 OOB 配对
- 使用 LE Secure Connections

**攻击 2：Passkey 暴力破解**

对于使用 6 位数字 Passkey 的设备，理论上可以暴力破解（100 万种可能）。

**防护措施**：
- 使用 LE Secure Connections
- 限制配对尝试次数

#### 8.3.2 嗅探攻击

BLE 通信在 2.4 GHz 频段，可以被专用设备嗅探。

**攻击工具**：
- Ubertooth One：开源 BLE 嗅探硬件
- nRF Sniffer：Nordic 官方 BLE 嗅探工具
- Wireshark：协议分析

**防护措施**：
- 使用加密连接
- 敏感数据额外使用应用层加密
- 定期更新长期密钥 (LTK)

#### 8.3.3 未授权访问

很多 BLE 设备的 Characteristic 不需要认证即可读写：
- 直接读取敏感数据（健康数据、位置信息）
- 写入控制指令（控制设备）
- 固件更新接口暴露

**典型案例**：
- 智能门锁蓝牙开锁指令可被重放
- 健康手环数据可被任意读取
- BLE 灯泡可被未授权控制

#### 8.3.4 重放攻击

截获 BLE 通信数据后重放，达到欺骗目的。

**示例**：截获智能门锁的开锁指令，重放即可开门。

**防护措施**：
- 使用计数器/随机数防止重放
- 每条消息使用唯一序列号

### 8.4 BLE 安全测试工具与方法

#### 8.4.1 常用工具

| 工具 | 类型 | 用途 |
|------|------|------|
| **Ubertooth One** | 硬件+软件 | BLE 嗅探、注入 |
| **nRF52840 Dongle** | 硬件+软件 | BLE 抓包、测试 |
| **Wireshark** | 软件 | BLE 协议分析 |
| **gatttool** | 软件 | GATT 读写测试 |
| **bluepy** | Python 库 | BLE 开发和测试 |
| **BLEAH** | 软件 | BLE 安全评估工具 |

#### 8.4.2 测试步骤

```bash
# 1. 扫描周围 BLE 设备
hcitool lescan

# 2. 连接设备
gatttool -b <MAC地址> -I
[   ][MAC地址][LE]> connect

# 3. 发现服务
[CON][MAC地址][LE]> primary

# 4. 发现特征
[CON][MAC地址][LE]> characteristics

# 5. 读取特征值（无需认证）
[CON][MAC地址][LE]> char-read-hnd <句柄>

# 6. 写入特征值
[CON][MAC地址][LE]> char-write-req <句柄> <值>

# 7. 启用通知
[CON][MAC地址][LE]> char-write-req <CCC句柄> 0100
```
