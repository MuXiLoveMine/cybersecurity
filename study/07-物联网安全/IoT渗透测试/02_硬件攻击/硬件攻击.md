# 硬件攻击

### 2.1 硬件攻击概述

硬件攻击是 IoT 渗透测试的特色，通过物理接触设备获取固件、提取密钥或绕过安全机制。

**硬件攻击的层次**：
```
┌─────────────────────────────────────┐
│  软件攻击（难度低，破坏性小）         │
│  通过网络/接口利用软件漏洞           │
├─────────────────────────────────────┤
│  接口攻击（难度中，破坏性小）         │
│  UART / JTAG / SWD / USB            │
├─────────────────────────────────────┤
│  芯片攻击（难度高，破坏性中）         │
│  Flash 读取 / 侧信道 / 故障注入      │
├─────────────────────────────────────┤
│  硅级攻击（难度极高，破坏性大）       │
│  芯片逆向 / 物理攻击                 │
└─────────────────────────────────────┘
```

### 2.2 UART 串口攻击

#### 2.2.1 UART 简介

UART（Universal Asynchronous Receiver/Transmitter）是通用异步收发传输器，是嵌入式设备最常见的调试接口。

**信号线**：
- **TX**：发送（Transmit）
- **RX**：接收（Receive）
- **GND**：地线（Ground）
- **VCC**：电源（可选，通常不接）

**常见参数**：
- 波特率：9600、19200、38400、57600、115200（最常见）
- 数据位：8
- 停止位：1
- 校验位：无

#### 2.2.2 寻找串口

**方法 1：目视查找**
- 寻找板上的排针或测试点
- 通常标有 TX、RX、GND、VCC 字样
- 常见位置：主板边缘、芯片附近

**方法 2：万用表测量**
1. 找 GND：用通断档测量，与屏蔽罩/USB 外壳导通的就是 GND
2. 找 VCC：上电后测量电压，3.3V 或 5V 的是 VCC
3. 找 TX：上电瞬间有电压波动的通常是 TX
4. 找 RX：电压稳定的通常是 RX

**方法 3：逻辑分析仪**
- 使用逻辑分析仪同时测量多个测试点
- 分析串口信号确定 TX/RX 和波特率

#### 2.2.3 串口连接步骤

```
设备端                    USB 转 TTL 适配器
┌───────┐                 ┌──────────────┐
│ GND   │─────────────────│ GND          │
│ TX    │─────────────────│ RX           │  ← 注意交叉连接
│ RX    │─────────────────│ TX           │
│ VCC   │     (不接)      │ 3.3V/5V      │
└───────┘                 └──────────────┘
```

**重要提醒**：
- TX 和 RX 要交叉连接（设备 TX → 适配器 RX，设备 RX → 适配器 TX）
- GND 必须连接（共地）
- VCC 通常不接（设备自身供电）
- 确认电压（3.3V 还是 5V），避免烧坏设备

#### 2.2.4 串口终端软件

| 系统 | 软件 | 说明 |
|------|------|------|
| Linux | minicom / screen / picocom | 命令行工具 |
| Windows | SecureCRT / Putty / TeraTerm | 图形化工具 |
| 跨平台 | minicom / PuTTY | |

**minicom 使用示例**：
```bash
# 安装
sudo apt install minicom

# 配置（设置串口、波特率、硬件流控关闭）
sudo minicom -s

# 直接连接
sudo minicom -D /dev/ttyUSB0 -b 115200
```

**screen 使用示例**：
```bash
sudo screen /dev/ttyUSB0 115200
# 退出：Ctrl+A, 然后按 K
```

#### 2.2.5 波特率识别

如果不知道波特率，可以尝试常见值或使用工具识别。

**常见波特率**（从高到低尝试）：
115200 → 57600 → 38400 → 19200 → 9600

**识别工具**：
- **baudrate.py**：自动识别串口波特率
- **sigrok/PulseView**：逻辑分析仪软件
- 手动观察乱码程度判断

#### 2.2.6 串口攻击面

**1. 启动日志信息泄露**

设备启动时会输出大量调试信息：
- 系统版本
- 内存布局
- Flash 分区信息
- 启动参数
- 硬件信息
- 调试信息

**分析价值**：
- 了解设备架构和系统
- 获取内存地址用于漏洞利用
- 发现调试功能和后门

**2. bootloader 命令行**

很多设备的 bootloader（如 U-Boot）可以通过串口中断启动，进入命令行。

**U-Boot 命令行能力**：
- 查看和修改环境变量
- 读取/写入 Flash
- 加载/执行代码
- 修改启动参数
- 绕过固件验证

**常见中断方式**：
- 按任意键（最常见）
- 按特定键（空格键、回车键、ESC）
- 发送特定字符序列

**典型场景**：
```
U-Boot 2013.07 (Sep 15 2020 - 14:38:26)

DRAM:  64 MiB
Flash: 16 MiB
Net:   ag7240_enet_initialize...
Hit any key to stop autoboot:  3  ← 倒计时期间按任意键中断

ar7240>
ar7240> help        ← 查看命令列表
ar7240> printenv    ← 查看环境变量
ar7240> sf probe    ← 探测 SPI Flash
ar7240> sf read 0x80000000 0x0 0x100000  ← 读取 Flash 到内存
```

**3. 登录 Shell**

启动完成后可能提供 shell 登录：
- 尝试默认用户名密码
- 利用漏洞绕过认证
- 通过 bootloader 修改密码

**4. 命令注入**

某些管理功能的命令行界面可能存在命令注入漏洞。

### 2.3 JTAG/SWD 攻击

#### 2.3.1 JTAG 简介

JTAG（Joint Test Action Group）是一种标准的硬件调试接口，主要用于芯片测试和调试。

**JTAG 引脚**：
| 引脚 | 名称 | 方向 | 说明 |
|------|------|------|------|
| TCK | Test Clock | 输入 | 测试时钟 |
| TMS | Test Mode Select | 输入 | 测试模式选择 |
| TDI | Test Data In | 输入 | 测试数据输入 |
| TDO | Test Data Out | 输出 | 测试数据输出 |
| TRST | Test Reset | 输入 | 测试复位（可选） |
| GND | Ground | - | 地 |
| VCC | Power | - | 电源（可选） |

#### 2.3.2 SWD 简介

SWD（Serial Wire Debug）是 ARM 推出的调试接口，使用更少的引脚。

**SWD 引脚**：
| 引脚 | 名称 | 说明 |
|------|------|------|
| SWCLK | Serial Wire Clock | 时钟信号 |
| SWDIO | Serial Wire Data I/O | 数据输入输出 |
| GND | Ground | 地 |
| VCC | Power | 电源（可选） |

#### 2.3.3 寻找 JTAG/SWD 接口

**方法**：
1. 目视查找：找标有 JTAG、SWD、TCK、TMS 等字样的排针或测试点
2. 查找芯片 datasheet：根据芯片型号确定 JTAG 引脚位置
3. JTAGulator：专用 JTAG 引脚识别工具

#### 2.3.4 JTAG 调试工具

| 工具 | 价格 | 说明 |
|------|------|------|
| J-Link | 较贵 | 功能最强大，支持多种芯片 |
| ST-Link | 便宜 | 主要支持 STM32 等 ARM 芯片 |
| FT2232H | 中等 | 通用 USB 转 JTAG 方案 |
| Bus Blaster | 中等 | 开源 JTAG 调试器 |
| Raspberry Pi | 便宜 | 可用树莓派模拟 JTAG |

#### 2.3.5 OpenOCD 使用

OpenOCD（Open On-Chip Debugger）是开源的片上调试器。

**安装**：
```bash
sudo apt install openocd
```

**配置文件示例**（STM32 + ST-Link）：
```tcl
# stm32.cfg
source [find interface/stlink.cfg]
source [find target/stm32f4x.cfg]
```

**启动 OpenOCD**：
```bash
sudo openocd -f stm32.cfg
```

**连接并读取 Flash**：
```bash
# 在另一个终端连接
telnet localhost 4444

> halt                    # 暂停 CPU
> flash banks             # 查看 Flash 信息
> flash read_bank 0 firmware.bin 0 0x100000  # 读取 Flash
> resume                  # 恢复运行
> exit
```

**GDB 调试**：
```bash
arm-none-eabi-gdb
(gdb) target remote :3333
(gdb) file firmware.elf
(gdb) break main
(gdb) continue
```

#### 2.3.6 JTAG 锁定与解锁

很多设备会锁定 JTAG 接口：
- STM32：读保护（RDP Level 1/2）
- NXP：CRP 级别
- ESP32：Secure Boot + Flash Encryption

**绕过方法**（因芯片而异）：
- 故障注入（电压毛刺、时钟毛刺）
- 利用特定芯片的漏洞
- 物理攻击（拆除芯片读取）
- 某些情况下可以通过 UART 解锁

### 2.4 SPI Flash 读取

#### 2.4.1 SPI Flash 简介

SPI Flash 是 IoT 设备中最常见的固件存储芯片，通过 SPI 接口通信。

**常见封装**：
- SOIC-8：8 引脚小外形封装（最常见）
- SOP-8：同上
- WSON-8：8 引脚无引脚封装

**引脚定义（SOIC-8）**：
```
   ┌──────────┐
CS │1     8│ VCC
 SO │2     7│ HOLD
 WP │3     6│ SCK
GND │4     5│ SI
   └──────────┘

CS: Chip Select（片选）
SO: Serial Output（串行输出，也叫 MISO）
WP: Write Protect（写保护）
GND: Ground（地）
SI: Serial Input（串行输入，也叫 MOSI）
SCK: Serial Clock（串行时钟）
HOLD: 挂起
VCC: 电源（通常 3.3V）
```

#### 2.4.2 读取方法

**方法 1：拆芯片 + 编程器（最可靠）**
1. 使用热风枪吹下 Flash 芯片
2. 将芯片放入编程器插座
3. 使用编程器软件读取

**方法 2：在线读取（测试夹）**
1. 使用测试夹夹在芯片上（不用拆）
2. 连接到编程器
3. 读取 Flash 内容
4. 注意：需要断开设备电源或确保芯片不被主控干扰

**方法 3：通过其他接口**
- U-boot 命令行读取
- JTAG 读取
- 固件漏洞读取

#### 2.4.3 CH341A 编程器使用

CH341A 是最廉价的 SPI Flash 编程器。

**软件工具**：
- **Windows**：CH341A Programmer、NeoProgrammer
- **Linux**：flashrom、ch341prog

**Linux 下使用 flashrom**：
```bash
# 安装
sudo apt install flashrom

# 检测芯片
sudo flashrom -p ch341a_spi

# 读取固件
sudo flashrom -p ch341a_spi -r firmware.bin

# 写入固件
sudo flashrom -p ch341a_spi -w firmware_modified.bin

# 验证
sudo flashrom -p ch341a_spi -v firmware.bin
```

### 2.5 其他硬件攻击技术

#### 2.5.1 侧信道攻击 (Side-Channel Attack)

通过分析设备的物理特性（功耗、电磁辐射、运行时间等）来获取密钥等敏感信息。

**常见类型**：
- **功耗分析 (Power Analysis)**：分析设备运行时的电流变化
  - 简单功耗分析 (SPA)
  - 差分功耗分析 (DPA)
- **电磁分析 (EM Analysis)**：分析设备的电磁辐射
- **时间分析 (Timing Analysis)**：分析操作的执行时间

**所需设备**：
- 示波器（高采样率）
- 电流探头/电磁探头
- 低噪声放大器
- 稳定的电源

#### 2.5.2 故障注入攻击 (Fault Injection)

通过向设备注入故障（电压毛刺、时钟毛刺、激光等），使芯片产生错误行为，从而绕过安全机制。

**常见类型**：
- **电压毛刺 (Voltage Glitching)**：在电源上产生短暂的电压脉冲
- **时钟毛刺 (Clock Glitching)**：在时钟上产生异常脉冲
- **激光故障注入**：用激光照射芯片特定区域
- **电磁故障注入**：用电磁脉冲干扰芯片

**攻击效果**：
- 跳过安全检查（如密码验证）
- 泄露敏感数据
- 绕过安全启动
- 解锁调试接口

#### 2.5.3 PCB 逆向

通过分析电路板的走线和元件，理解硬件设计和连接关系。

**方法**：
- 目视观察（放大镜、显微镜）
- 万用表通断测试
- 拍照后用软件追踪走线
- 去层分析（多层板，破坏性）
