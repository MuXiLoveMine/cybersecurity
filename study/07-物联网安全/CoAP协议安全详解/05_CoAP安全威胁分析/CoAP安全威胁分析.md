### 5.2 具体威胁详解

#### 5.2.1 未认证访问

```
威胁: 未启用DTLS的CoAP服务器可被任意访问

攻击场景:
1. 攻击者扫描网络发现CoAP设备
2. 直接访问设备资源
3. 读取传感器数据或控制设备

示例:
# 扫描CoAP设备
coap-scan 2001:db8::/64 -p 5683

# 直接读取传感器数据
coap-client -m get coap://[2001:db8::1]/sensors/temp

# 控制设备
coap-client -m put -e "on" coap://[2001:db8::1]/actuators/led

风险:
- 敏感数据泄露（温度、湿度、位置等）
- 设备被恶意控制
- 拒绝服务
```

#### 5.2.2 重放攻击

```
威胁: 攻击者捕获并重放CoAP消息

攻击流程:
1. 攻击者嗅探网络流量
2. 捕获有效的CoAP请求/响应
3. 在之后重放该消息

示例场景:
  T1: 用户 → 设备: PUT /door {state: open} (MessageID: 100)
  T2: 攻击者捕获该消息
  T3: 用户 → 设备: PUT /door {state: close} (MessageID: 101)
  T4: 攻击者重放: PUT /door {state: open} (MessageID: 100)
  
  问题: 如果设备未做重放检测，门会被重新打开

防御:
- 使用DTLS (提供序号和MAC)
- 使用Token匹配请求响应
- 使用时间戳选项
- 限制Message ID窗口
```

#### 5.2.3 中间人攻击

```
威胁: 攻击者在客户端和服务器之间转发/修改消息

攻击流程:
  Client ←──→ Attacker ←──→ Server
                  │
            篡改/嗅探/注入

未使用DTLS时:
- 攻击者可读取所有明文数据
- 攻击者可修改消息内容
- 攻击者可注入伪造消息

使用PSK-DTLS但密钥泄露时:
- 攻击者可解密流量
- 攻击者可伪造消息

使用X.509-DTLS时:
- 攻击者无法解密或篡改
- 除非获得CA私钥或利用实现缺陷
```

#### 5.2.4 消息伪造与注入

```
威胁: 攻击者伪造CoAP消息发送给设备

攻击示例:
# 伪造传感器响应（欺骗客户端）
import socket

# 构造伪造的CoAP响应
# Type=ACK(2), Code=2.05(Content), MessageID=0x1234
fake_response = bytes([
    0x60,  # Ver=1, Type=ACK(2), TKL=0
    0x45,  # Code=2.05 (Content)
    0x12, 0x34,  # Message ID
    0xFF,  # Payload marker
]) + b'25.5'  # 伪造温度数据

# 发送给客户端
sock = socket.socket(socket.AF_INET6, socket.SOCK_DGRAM)
sock.sendto(fake_response, ('2001:db8::client', 5683))

防御:
- 使用DTLS MAC验证消息完整性
- 使用Token匹配请求和响应
- 验证源IP和端口
```

#### 5.2.5 资源耗尽攻击

```
威胁: 利用CoAP协议特性耗尽设备资源

攻击方式1: DTLS握手耗尽
  - 发送大量ClientHello但不完成握手
  - 迫使设备分配握手状态
  - HelloVerifyRequest可缓解但不能完全防止

攻击方式2: 分块传输耗尽
  - 发送大量Block-wise传输请求
  - 占用设备内存和存储

攻击方式3: Observe注册耗尽
  - 注册大量观察者
  - 迫使设备维护大量观察状态

攻击方式4: CoAP放大攻击
  - 利用多播CoAP获取大量响应
  - 通过CoAP反射进行DDoS
```
