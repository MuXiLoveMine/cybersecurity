# 实战案例分析

### 11.1 2016 Dyn攻击事件

```
攻击时间: 2016年10月21日
攻击目标: Dyn DNS服务提供商
攻击手段: Mirai僵尸网络DDoS
攻击峰值: 1.2Tbps
受影响设备: 约10万台IoT设备（主要为摄像头和DVR）

攻击影响:
- Twitter, Netflix, Reddit, Spotify, GitHub等
  大型网站无法访问
- 美国东海岸大面积互联网中断
- 持续时间约6小时

技术分析:
1. 攻击者利用DNS查询洪水攻击Dyn的DNS服务器
2. Mirai感染的IoT设备向Dyn发送大量DNS查询
3. 查询使用随机子域名，无法缓存
4. Dyn的DNS服务器因过载而无法正常服务

攻击指令分析:
- 下发了多个攻击类型组合
- 针对Dyn的多个Anycast节点
- 逐步切换攻击目标IP
- 使用GRE和TCP SYN混合洪水

经验教训:
1. DNS是互联网的关键单点
2. IoT设备安全直接影响关键基础设施
3. 需要多层次DNS冗余
4. 需要与ISP建立DDoS清洗合作
```

### 11.2 2018年PyMine分析案例

```
案例背景:
某企业发现内部多台IoT摄像头异常流量
怀疑被僵尸网络感染

分析过程:
1. 网络流量捕获
   tcpdump -i eth0 -w capture.pcap host 192.168.1.100

2. 流量分析发现:
   - 大量出站TCP连接到外部IP的23端口
   - 定期向外部服务器发送4字节心跳包
   - 间歇性大量UDP出站流量

3. 固件提取:
   - 通过UART接口连接摄像头
   - dump固件到外部存储
   binwalk -e firmware.bin

4. 恶意程序发现:
   - /tmp/.debug存在未知ELF文件
   - 该文件为Mirai变种的ARM版本
   - 通过strings分析发现C2域名

5. 感染溯源:
   - C2域名: evil-c2.example.com
   - 解析IP: 45.XXX.XXX.XXX
   - 感染方式: Telnet默认密码(admin/12345)

6. 清除与加固:
   - 删除恶意文件
   - 修改Telnet密码
   - 禁用Telnet改用SSH
   - 部署网络隔离
```

### 11.3 Mozi僵尸网络取证分析

```
Mozi感染设备取证流程:

1. 现场保护
   - 立即断网但不断电（保留内存数据）
   - 通过串口/UART连接设备

2. 内存取证
   # 使用dd导出内存
   dd if=/proc/kmem of=/tmp/kmem.dump
   # 导出进程内存
   cat /proc/$(pidof mozi)/maps
   dd if=/proc/$(pidof mozi)/mem of=/tmp/mozi.mem

3. 固件分析
   # 提取固件
   binwalk -e firmware.bin
   # 查找持久化机制
   grep -r "mozi" _firmware.bin.extracted/
   # 发现init.d持久化
   cat _firmware.bin.extracted/etc/init.d/lighttpd
   # 内容:
   # #!/bin/sh
   # cd /tmp; ./mozi

4. 网络行为分析
   # 分析Mozi P2P通信
   tshark -r capture.pcap -Y "udp" -T fields \
     -e ip.src -e ip.dst -e udp.dstport \
     | sort | uniq -c | sort -rn
   
   # 发现大量DHT节点通信
   # 端口: 随机高端口
   # 包大小: 固定128/256字节
   # 通信模式: P2P DHT

5. Mozi样本分析
   # 静态分析
   readelf -h mozi    # ELF头信息
   strings mozi       # 提取字符串
   # 发现特征字符串:
   # - "Mozi"
   # - DHT相关函数名
   # - ECC公钥
   # - C2域名（P2P引导节点）
   
   # 动态分析
   # 使用QEMU模拟运行
   qemu-arm-static mozi
   # 监控系统调用
   strace -f qemu-arm-static mozi
```
