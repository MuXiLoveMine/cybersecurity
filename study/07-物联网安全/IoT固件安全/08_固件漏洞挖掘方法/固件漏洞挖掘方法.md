# 固件漏洞挖掘方法

### 8.1 漏洞挖掘流程

```
┌─────────────┐
│  信息收集    │  了解设备功能、技术栈、攻击面
└──────┬──────┘
       ▼
┌─────────────┐
│  固件获取    │  通过各种方式获取固件
└──────┬──────┘
       ▼
┌─────────────┐
│  固件解包    │  提取文件系统和二进制
└──────┬──────┘
       ▼
┌─────────────┐
│  静态分析    │  代码审计、字符串搜索、配置分析
└──────┬──────┘
       ▼
┌─────────────┐
│  动态分析    │  运行测试、调试、模糊测试
└──────┬──────┘
       ▼
┌─────────────┐
│  漏洞验证    │  在真实/模拟环境中验证漏洞
└──────┬──────┘
       ▼
┌─────────────┐
│  漏洞报告    │  撰写漏洞报告、提交CVE
└─────────────┘
```

### 8.2 静态漏洞挖掘方法

#### 8.2.1 代码审计策略

**1. 从输入点出发**
- 找到所有用户输入入口（Web、网络、串口等）
- 跟踪输入数据的处理流程
- 检查数据验证和过滤

**2. 从危险函数出发**
- 搜索所有危险函数调用
- 回溯检查参数是否可控
- 判断是否可以利用

**3. 从敏感功能出发**
- 认证功能
- 固件更新功能
- 配置管理功能
- 命令执行功能

#### 8.2.2 二进制审计技巧

**利用 IDA/Ghidra 进行审计**：
1. 使用字符串交叉引用定位关键代码
2. 分析导入函数，关注危险函数
3. 使用反编译功能分析 C 伪代码
4. 关注网络协议解析代码
5. 关注文件解析代码

**常见漏洞代码特征**：
- 无长度检查的内存操作
- 直接拼接的系统命令
- 硬编码的密码和密钥
- 过于简单的认证逻辑
- 不安全的随机数生成

### 8.3 动态漏洞挖掘方法

#### 8.3.1 模糊测试 (Fuzzing)

**模糊测试类型**：
- **黑盒模糊测试**：不需要源码，随机生成输入
- **白盒模糊测试**：基于代码覆盖率的模糊测试（如 AFL）
- **灰盒模糊测试**：结合两者特点

**网络服务模糊测试流程**：
1. 识别目标服务和协议
2. 编写模糊测试脚本/模板
3. 运行模糊测试
4. 监控崩溃和异常
5. 分析崩溃原因

**AFL 模糊测试**：
```bash
# 编译目标程序（插桩）
afl-gcc -o target target.c

# 准备测试用例
mkdir in out
echo "test" > in/test1

# 开始模糊测试
afl-fuzz -i in -o out ./target
```

#### 8.3.2 符号执行

符号执行是一种程序分析技术，通过将变量表示为符号值，探索所有可能的执行路径。

**常用工具**：
- **Angr**：Python 符号执行框架
- **KLEE**：LLVM 符号执行引擎
- **S2E**：选择性符号执行平台

**Angr 简单示例**：
```python
import angr

# 加载二进制
proj = angr.Project('./target_binary')

# 创建初始状态
state = proj.factory.entry_state()

# 创建模拟管理器
simgr = proj.factory.simulation_manager(state)

# 寻找到达目标地址的路径
simgr.explore(find=0x401234)

if simgr.found:
    found = simgr.found[0]
    print(found.posix.dumps(0))  # 输出 stdin 的值
```

### 一、binwalk 常用命令速查表

```bash
# ===== 安装 =====
# 源码安装
git clone https://github.com/ReFirmLabs/binwalk.git
cd binwalk
sudo python3 setup.py install

# Kali / Debian 安装
sudo apt install binwalk

# pip 安装
pip install binwalk

# ===== 基本分析 =====
# 快速分析固件（识别文件系统、压缩包等）
binwalk firmware.bin

# 详细分析（显示更多信息）
binwalk -v firmware.bin

# 熵分析（检测加密/压缩区域）
binwalk -E firmware.bin
binwalk -E --save=entropy.png firmware.bin  # 保存熵图

# 字符串搜索
binwalk -S firmware.bin
binwalk --strings firmware.bin

# ===== 固件解包 =====
# 自动提取所有识别的文件系统
binwalk -e firmware.bin
binwalk --extract firmware.bin

# 递归提取（深入提取嵌套的文件）
binwalk -eM firmware.bin
binwalk --extract --matryoshka firmware.bin

# 解压到指定目录
binwalk -e firmware.bin -C ./extracted/

# 强制提取（忽略已知的错误）
binwalk -e --force firmware.bin

# ===== 文件系统提取 =====
# 提取 SquashFS 文件系统
binwalk -e -y squashfs firmware.bin

# 只提取特定类型（如 gzip）
binwalk -e -y gzip firmware.bin

# 排除特定类型
binwalk -e -x gzip firmware.bin

# ===== 签名扫描 =====
# 列出所有支持的签名
binwalk --list

# 添加自定义签名
binwalk -B custom_signatures.txt firmware.bin

# ===== 比较分析 =====
# 比较两个固件版本（查找差异）
binwalk -W firmware_v1.bin firmware_v2.bin
binwalk --diff firmware_v1.bin firmware_v2.bin

# ===== 熵分析进阶 =====
# 计算熵值并输出
binwalk -E -J firmware.bin  # JSON 格式输出
binwalk -E --block=1024 firmware.bin  # 指定块大小

# ===== 插件功能 =====
# 列出所有插件
binwalk --plugins-list

# 使用特定插件
binwalk --plugins="pcommon" firmware.bin
```

**binwalk 分析结果解读速查**：
| 签名类型 | 说明 | 安全关注点 |
|---------|------|-----------|
| Squashfs | 只读压缩文件系统，常见于嵌入式 | 提取后分析配置文件、硬编码密码 |
| Cramfs | 压缩只读文件系统 | 同上 |
| JFFS2 | 闪存文件系统 | 同上 |
| UBIFS | 原始闪存文件系统 | 同上 |
| gzip/zlib | 压缩数据 | 解压后进一步分析 |
| LZMA | 高压缩比压缩 | 解压后进一步分析 |
| uImage | U-Boot 镜像 | 提取内核和 initramfs |
| TRX | 路由器固件格式 | 常见于 DD-WRT/OpenWrt |
| DTB | 设备树 Blob | 硬件配置信息 |
| PNG/JPEG | 图片资源 | Web 界面、Logo |
| HTML/JS/CSS | Web 资源 | 查找 Web 漏洞 |

### 二、Firmware Mod Kit (FMK) 使用命令

```bash
# ===== 安装 =====
git clone https://github.com/rampageX/firmware-mod-kit.git
cd firmware-mod-kit
./configure
make

# 安装依赖
sudo apt install build-essential zlib1g-dev liblzma-dev python3-magic

# ===== 提取固件 =====
# 提取固件（自动识别格式）
./extract-firmware.sh firmware.bin

# 提取后目录结构：
# fmk/
#   ├── rootfs/       # 提取的文件系统
#   ├── image_parts/  # 固件各部分
#   └── build.log     # 构建日志

# 查看提取的文件系统
ls -la fmk/rootfs/

# ===== 重新打包固件 =====
# 修改文件系统后重新打包
./build-firmware.sh fmk/

# 输出：fmk/new-firmware.bin

# ===== 高级用法 =====
# 提取特定偏移位置的数据
dd if=firmware.bin of=kernel.gz bs=1 skip=1024 count=1048576

# 手动解压 SquashFS
unsquashfs -d rootfs/ rootfs.squashfs

# 创建 SquashFS
mksquashfs rootfs/ new_rootfs.squashfs -comp xz -b 131072

# ===== 处理不同固件格式 =====
# D-Link 固件
./extract-dlink.sh firmware.bin

# TP-Link 固件
./extract-tplink.sh firmware.bin

# Netgear 固件
./extract-netgear.sh firmware.bin
```

### 三、radare2 固件分析命令速查

```bash
# ===== 安装 =====
git clone https://github.com/radareorg/radare2.git
cd radare2
sys/install.sh

# ===== 基本操作 =====
# 打开固件二进制
r2 firmware.bin

# 以二进制模式打开（不解析格式）
r2 -b 32 firmware.bin        # 32位
r2 -a arm -b 32 firmware.bin # ARM 32位
r2 -a mips -b 32 firmware.bin # MIPS 32位
r2 -a x86 -b 64 firmware.bin  # x86 64位

# ===== 分析命令 =====
# 分析所有函数
aaa

# 分析入口点
afl    # 列出所有函数
afl~main  # 搜索 main 函数

# 查看反汇编
pdf    # 反汇编当前函数
pd 20  # 反汇编 20 条指令
pd -5  # 反汇编当前位置前 5 条

# ===== 字符串搜索 =====
# 搜索字符串
izz    # 搜索所有字符串
izz~password  # 搜索包含 password 的字符串
iz  # 搜索数据段字符串

# 搜索特定字符串
/ password
/ /bin/sh

# ===== 二进制搜索 =====
# 搜索字节模式
/x 90 90 90        # NOP sled
/x ff e1           # bx lr (ARM)
/x 48 65 6c 6c 6f  # "Hello"

# 搜索所有引用
axt 0x401234       # 查找谁引用了该地址
axf main           # 查找 main 调用了哪些函数

# ===== 交叉引用 =====
# 查找字符串交叉引用
axt str.password

# 查找函数调用者
axt sym.imp.strcpy

# ===== 调试功能 =====
# 以调试模式启动
r2 -d ./binary

# 设置断点
db sym.main
db 0x401234

# 运行程序
dc     # continue
ds     # step into
dso    # step over

# 查看寄存器
dr
dr eax  # 查看特定寄存器

# 查看内存
px 64 @ rsp   # 查看栈上 64 字节
px 256 @ 0x402000  # 查看指定地址

# ===== 脚本与自动化 =====
# 运行 r2 脚本
r2 -i script.r2 firmware.bin

# 搜索危险函数调用
# 保存为 find_dangerous.r2
# aaa
# afl~strcpy
# afl~system
# afl~sprintf
# afl~gets

# Python 脚本 (r2pipe)
pip install r2pipe

cat > analyze.py << 'EOF'
import r2pipe

r2 = r2pipe.open("firmware.bin")
r2.cmd("aaa")

# 获取所有字符串中的密码相关
result = r2.cmd("izz~password")
print("Password-related strings:")
print(result)

# 获取所有函数
funcs = r2.cmd("afl")
print(f"\nTotal functions: {len(funcs.strip().split(chr(10)))}")

r2.quit()
EOF
python3 analyze.py
```

### 五、固件分析工作流脚本

```bash
#!/bin/bash
# firmware_analysis_workflow.sh - 固件分析自动化工作流

FIRMWARE=$1
OUTPUT_DIR="./analysis_output"

if [ -z "$FIRMWARE" ]; then
  echo "Usage: $0 <firmware_file>"
  exit 1
fi

mkdir -p "$OUTPUT_DIR"

echo "=== Firmware Analysis Workflow ==="
echo "Firmware: $FIRMWARE"
echo "Output: $OUTPUT_DIR"

# 1. 基本信息收集
echo ""
echo "[1] Basic Information"
echo "---"
file "$FIRMWARE"
echo "Size: $(du -h $FIRMWARE | cut -f1)"
echo "MD5:  $(md5sum $FIRMWARE | cut -d' ' -f1)"
echo "SHA1: $(sha1sum $FIRMWARE | cut -d' ' -f1)"

# 2. binwalk 分析
echo ""
echo "[2] Binwalk Analysis"
echo "---"
binwalk "$FIRMWARE" > "$OUTPUT_DIR/binwalk.txt"
cat "$OUTPUT_DIR/binwalk.txt"

# 3. 熵分析
echo ""
echo "[3] Entropy Analysis"
echo "---"
binwalk -E --save="$OUTPUT_DIR/entropy.png" "$FIRMWARE" 2>&1 | head -20

# 4. 字符串搜索
echo ""
echo "[4] String Search"
echo "---"
strings "$FIRMWARE" | grep -iE "(password|admin|root|secret|key|token|backdoor|debug|shell)" \
  | sort -u > "$OUTPUT_DIR/interesting_strings.txt"
echo "Found $(wc -l < $OUTPUT_DIR/interesting_strings.txt) interesting strings"
head -20 "$OUTPUT_DIR/interesting_strings.txt"

# 5. 自动解包
echo ""
echo "[5] Extracting Firmware"
echo "---"
binwalk -eM "$FIRMWARE" -C "$OUTPUT_DIR/extracted/" 2>&1 | tail -5

# 6. 查找配置文件
echo ""
echo "[6] Configuration Files"
echo "---"
find "$OUTPUT_DIR/extracted/" -type f \( -name "*.conf" -o -name "*.cfg" -o -name "*.ini" -o -name "*.json" -o -name "*.xml" \) 2>/dev/null | head -20

# 7. 查找可执行文件
echo ""
echo "[7] Executable Files"
echo "---"
find "$OUTPUT_DIR/extracted/" -type f -executable 2>/dev/null | head -20

# 8. 密码哈希搜索
echo ""
echo "[8] Password Hashes"
echo "---"
grep -r "^\$1\$\|^\$2a\$\|^\$5\$\|^\$6\$" "$OUTPUT_DIR/extracted/" 2>/dev/null | head -10

echo ""
echo "=== Analysis Complete ==="
echo "Results saved to: $OUTPUT_DIR"
```
