# 固件漏洞挖掘方法

### 8.1 漏洞挖掘流程

```
┌─────────────┐
│  信息收集    │  了解设备功能、技术栈、攻击面
└──────┬──────┘
       ▼
┌─────────────┐
│  固件获取    │  通过各种方式获取固件
└──────┬──────┘
       ▼
┌─────────────┐
│  固件解包    │  提取文件系统和二进制
└──────┬──────┘
       ▼
┌─────────────┐
│  静态分析    │  代码审计、字符串搜索、配置分析
└──────┬──────┘
       ▼
┌─────────────┐
│  动态分析    │  运行测试、调试、模糊测试
└──────┬──────┘
       ▼
┌─────────────┐
│  漏洞验证    │  在真实/模拟环境中验证漏洞
└──────┬──────┘
       ▼
┌─────────────┐
│  漏洞报告    │  撰写漏洞报告、提交CVE
└─────────────┘
```

### 8.2 静态漏洞挖掘方法

#### 8.2.1 代码审计策略

**1. 从输入点出发**
- 找到所有用户输入入口（Web、网络、串口等）
- 跟踪输入数据的处理流程
- 检查数据验证和过滤

**2. 从危险函数出发**
- 搜索所有危险函数调用
- 回溯检查参数是否可控
- 判断是否可以利用

**3. 从敏感功能出发**
- 认证功能
- 固件更新功能
- 配置管理功能
- 命令执行功能

#### 8.2.2 二进制审计技巧

**利用 IDA/Ghidra 进行审计**：
1. 使用字符串交叉引用定位关键代码
2. 分析导入函数，关注危险函数
3. 使用反编译功能分析 C 伪代码
4. 关注网络协议解析代码
5. 关注文件解析代码

**常见漏洞代码特征**：
- 无长度检查的内存操作
- 直接拼接的系统命令
- 硬编码的密码和密钥
- 过于简单的认证逻辑
- 不安全的随机数生成

### 8.3 动态漏洞挖掘方法

#### 8.3.1 模糊测试 (Fuzzing)

**模糊测试类型**：
- **黑盒模糊测试**：不需要源码，随机生成输入
- **白盒模糊测试**：基于代码覆盖率的模糊测试（如 AFL）
- **灰盒模糊测试**：结合两者特点

**网络服务模糊测试流程**：
1. 识别目标服务和协议
2. 编写模糊测试脚本/模板
3. 运行模糊测试
4. 监控崩溃和异常
5. 分析崩溃原因

**AFL 模糊测试**：
```bash
# 编译目标程序（插桩）
afl-gcc -o target target.c

# 准备测试用例
mkdir in out
echo "test" > in/test1

# 开始模糊测试
afl-fuzz -i in -o out ./target
```

#### 8.3.2 符号执行

符号执行是一种程序分析技术，通过将变量表示为符号值，探索所有可能的执行路径。

**常用工具**：
- **Angr**：Python 符号执行框架
- **KLEE**：LLVM 符号执行引擎
- **S2E**：选择性符号执行平台

**Angr 简单示例**：
```python
import angr

# 加载二进制
proj = angr.Project('./target_binary')

# 创建初始状态
state = proj.factory.entry_state()

# 创建模拟管理器
simgr = proj.factory.simulation_manager(state)

# 寻找到达目标地址的路径
simgr.explore(find=0x401234)

if simgr.found:
    found = simgr.found[0]
    print(found.posix.dumps(0))  # 输出 stdin 的值
```

### 8.4 漏洞验证与利用

#### 8.4.1 漏洞验证步骤

1. **复现漏洞**：构造 PoC 验证漏洞存在
2. **评估影响**：判断漏洞的危害程度
3. **编写利用代码**：开发完整的 exploit
4. **测试利用**：在目标环境中测试

#### 8.4.2 漏洞报告

漏洞报告应包含：
- 漏洞标题
- 漏洞描述
- 影响版本
- 漏洞等级
- 复现步骤
- PoC 代码
- 修复建议
- 参考资料
