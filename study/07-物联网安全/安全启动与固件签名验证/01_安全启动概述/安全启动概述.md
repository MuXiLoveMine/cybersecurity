# 安全启动概述

### 1.1 什么是安全启动

安全启动（Secure Boot）是一种确保设备仅运行经过授权的固件/软件的机制。它通过密码学签名验证，构建从硬件信任根到操作系统的完整信任链：

```
安全启动的核心目标:

1. 完整性验证: 确保固件未被篡改
2. 来源认证: 确认固件来自可信发布者
3. 防回滚: 阻止降级到有漏洞的旧版本
4. 信任链: 从硬件到应用的逐级验证
5. 密钥保护: 防止签名密钥泄露

信任链模型:
┌────────────────────────────────────────────┐
│                                            │
│  ROM代码 (不可变)                          │
│    ↓ 验证                                   │
│  引导加载器 (Bootloader)                   │
│    ↓ 验证                                   │
│  内核 (Kernel)                             │
│    ↓ 验证                                   │
│  根文件系统 (Rootfs)                       │
│    ↓ 验证                                   │
│  应用程序 (Applications)                   │
│                                            │
└────────────────────────────────────────────┘

每一级验证下一级的数字签名
任一环节验证失败 → 启动中止
```

### 1.2 安全启动的必要性

```
无安全启动的风险:

1. 固件植入攻击
   - 攻击者替换固件植入后门
   - 恶意固件持久化存在
   - 即使重置系统也无法清除

2. Bootkit/Rootkit
   - 恶意代码在OS之前加载
   - 对OS不可见
   - 可禁用安全软件

3. 固件降级攻击
   - 将固件降级到有漏洞的版本
   - 利用已知漏洞进行攻击
   - 绕过新版安全补丁

4. 供应链攻击
   - 在固件分发环节篡改
   - 中间人攻击固件更新
   - 第三方组件注入恶意代码

历史案例:
- 2014年: Lenovo预装广告软件Superfish (SSL中间人)
- 2018年: LoJax UEFI rootkit (APT28)
- 2020年: 多款路由器固件后门暴露
- 2021年: iLOBot恶意固件 (HPE iLO)
```

### 1.3 安全启动标准与规范

| 标准 | 适用领域 | 关键要求 |
|------|---------|---------|
| UEFI Secure Boot | PC/服务器 | 签名验证, 密钥管理, 启动策略 |
| Android Verified Boot | 移动设备 | 分区验证, 防回滚, 恢复模式 |
| TPM 2.0 | 通用 | 度量启动, 密封存储, 远程证明 |
| ARM Trusted Board | ARM设备 | 信任根, 信任链, 调试控制 |
| NIST SP 800-147 | 通用固件 | 固件完整性保护指导 |
| NIST SP 800-147B | 服务器 | 服务器固件安全指南 |
| TCG PC Client | PC | TPM规范, 度量启动 |
| GlobalPlatform TEE | 移动/IoT | 可信执行环境 |
