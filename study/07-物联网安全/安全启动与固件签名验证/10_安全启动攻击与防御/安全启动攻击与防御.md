# 安全启动攻击与防御

### 10.1 攻击手法

```
安全启动攻击面:

1. 物理攻击
   - 故障注入攻击 (电压/时钟毛刺)
   - 侧信道攻击 (功耗/电磁)
   - 芯片解封与微探针
   - 激光故障注入

2. 密码学攻击
   - 弱密钥生成
   - 随机数生成器缺陷
   - 签名算法实现缺陷
   - 哈希碰撞(实际不可行)

3. 实现缺陷
   - 验证逻辑漏洞
   - TOCTOU竞态条件
   - 缓冲区溢出
   - 整数溢出

4. 供应链攻击
   - 密钥泄露
   - 构建系统被入侵
   - 签名工具被篡改

5. 配置错误
   - 安全启动未启用
   - 调试接口未关闭
   - 防回滚未配置
   - 密钥管理不当
```

### 10.2 故障注入攻击

```python
# 故障注入攻击安全启动的原理
class FaultInjectionAttack:
    """
    故障注入攻击通过在签名验证过程中引入硬件故障,
    使验证错误地返回成功结果
    
    攻击目标: 
    - 在ECDSA/RSA验证的关键步骤中引入时钟毛刺
    - 使比较指令跳过或返回错误结果
    - 绕过签名验证
    """
    
    """
    典型攻击场景:
    
    正常验证流程:
    1. 计算固件哈希 H
    2. 从固件头读取签名 S
    3. 从公钥计算预期值 E = Verify(PK, H, S)
    4. 比较: if E == EXPECTED → 通过
    
    故障注入:
    - 在步骤4的时钟注入毛刺
    - 使CMP指令的Zero标志位被错误设置
    - 验证错误地返回"通过"
    
    防御:
    1. 双重验证: 执行两次验证, 比较结果
    2. 反向验证: 验证失败标志也被验证
    3. 时间冗余: 在不同时间执行验证
    4. 空间冗余: 使用不同代码验证
    5. 随机延迟: 增加攻击者时序预测难度
    """
    
    # 安全验证实现(抗故障注入)
    @staticmethod
    def secure_verify(hash_value: bytes, signature: bytes, 
                      pubkey: bytes) -> bool:
        """抗故障注入的验证实现"""
        
        # 第一次验证
        result1 = verify_signature(hash_value, signature, pubkey)
        
        # 第二次验证(冗余)
        result2 = verify_signature(hash_value, signature, pubkey)
        
        # 结果一致性检查
        if result1 != result2:
            # 可能遭受故障注入
            secure_log("验证结果不一致，可能遭受攻击")
            return False
        
        # 反向检查(验证失败标志)
        # 如果签名是无效的，verify_invalid应该返回True
        if verify_invalid_signature(hash_value, signature, pubkey):
            secure_log("检测到无效签名标记")
            return False
        
        return result1
```
