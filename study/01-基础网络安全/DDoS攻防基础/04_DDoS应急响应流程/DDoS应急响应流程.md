# DDoS应急响应流程

### 4.1 攻击识别与分类

```
DDoS应急响应 - 攻击识别决策树:

  发现服务异常（响应慢/不可达）
         │
         ↓
  ┌──────────────┐
  │ 1. 确认攻击  │  ← 检查流量监控/带宽图表
  │ 流量是否异常 │    是否有突增？
  └──────────────┘
     │           │
   是 ↓         否 ↓
  ┌──────────────┐    ┌──────────────┐
  │ 2. 攻击分类  │    │ 检查应用/    │
  │              │    │ 服务器故障   │
  └──────────────┘    └──────────────┘
     │
     ├── 带宽突增 → 流量型(UDP/ICMP/Amplification)
     ├── SYN激增 → 协议型(SYN Flood)
     ├── HTTP QPS激增 → 应用层(HTTP Flood/CC)
     └── 混合型 → 多种攻击同时进行
```

**快速诊断命令：**

```bash
# 查看当前连接数统计
ss -s

# 按状态统计TCP连接
ss -ant | awk '{print $1}' | sort | uniq -c | sort -rn

# 检查SYN_RECV数量（判断SYN Flood）
ss -ant | grep SYN-RECV | wc -l

# 查看连接数最多的IP
ss -ntu | awk '{print $5}' | cut -d: -f1 | sort | uniq -c | sort -rn | head -20

# 实时流量监控
iftop -nNP -i eth0
# 或
nload -u M
```

### 4.2 应急处置步骤

```
DDoS应急处置标准流程（PDCERF模型）:

  ┌──────────────────────────────────────────────────────────┐
  │ 1. 准备(Preparation)    - 日常建立监控、预案、联系通道   │
  │ 2. 发现(Identification) - 检测到异常，确认DDoS攻击      │
  │ 3. 抑制(Containment)    - 紧急措施阻止攻击扩散         │
  │ 4. 根除(Eradication)    - 清除攻击源/引入清洗          │
  │ 5. 恢复(Recovery)       - 确认攻击停止，恢复服务       │
  │ 6. 总结(Follow-up)      - 事后分析，改进防护           │
  └──────────────────────────────────────────────────────────┘

抑制阶段紧急措施:
  1. 上联黑洞路由（丢弃所有流量到目标IP）
  2. 启动云清洗服务（Cloudflare/AWS Shield）
  3. 启用本地iptables限速规则
  4. 切换DNS到备用高防IP
  5. 增加服务器资源（弹性扩容）
```

### 4.3 事后分析与改进

```
事后分析检查清单:

  [ ] 攻击时间线重建（开始/峰值/结束时间）
  [ ] 攻击类型与流量规模记录
  [ ] 攻击源IP地域分布分析
  [ ] 受影响服务及持续时间
  [ ] 现有防护措施有效性评估
  [ ] 告警是否及时触发
  [ ] 应急响应流程是否顺畅
  [ ] 需要改进的环节

改进措施:
  - 调整检测阈值（减少漏报）
  - 优化清洗规则（提高精准度）
  - 预签约云防护服务（缩短响应时间）
  - 定期演练（验证预案有效性）
```
