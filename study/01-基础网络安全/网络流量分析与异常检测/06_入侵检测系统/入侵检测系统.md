# 入侵检测系统

### 6.1 Snort 安装与配置

Snort 是经典的开源 IDS/IPS。安装以 Linux 为例：

```bash
# 安装依赖
apt install -y build-essential libpcap-dev libpcre3-dev libdumbnet-dev \
  zlib1g-dev pkg-config libnetfilter-queue-dev

# 安装daq(数据采集库)
tar xvf daq-2.0.7.tar.gz && cd daq-2.0.7
./configure && make && make install

# 安装snort
tar xvf snort-2.9.20.tar.gz && cd snort-2.9.20
./configure --enable-sourcefire && make && make install

# 复制配置
mkdir -p /etc/snort/rules
cp etc/snort.conf /etc/snort/
cp etc/so_preprocessor.conf /etc/snort/

# 下载社区规则
wget https://www.snort.org/downloads/community/community-rules.tar.gz
tar xvf community-rules.tar.gz -C /etc/snort/rules
```

关键配置 `/etc/snort/snort.conf`：

```
# 网络定义
var HOME_NET 192.168.1.0/24
var EXTERNAL_NET !$HOME_NET

# 规则路径
var RULE_PATH /etc/snort/rules

# 启用动态加载规则
include $RULE_PATH/community.rules
include $RULE_PATH/local.rules       # 自定义规则
```

运行模式：

```bash
# 旁路IDS模式(读pcap/镜像口)
snort -A console -q -c /etc/snort/snort.conf -i eth1

# 串行IPS模式(需NFQ)
snort -Q --daq nfq --daq-var queue=0 -c /etc/snort/snort.conf
```

### 6.2 Suricata 安装与配置

Suricata 是 Snort 的现代化继任者，支持多线程、协议解析更强、原生支持 NetFlow 输出。

```bash
# Ubuntu/Debian
apt install suricata

# 或源码安装(支持AF_PACKET万兆抓包)
./configure --with-libnfc --enable-af-packet
make && make install

# 更新规则
suricata-update
suricata-update list-sources
suricata-update enable-source et/open
```

配置 `/etc/surcatata/suricata.yaml`：

```yaml
vars:
  address-groups:
    HOME_NET: "[192.168.1.0/24]"
    EXTERNAL_NET: "!$HOME_NET"

af-packet:                    # 高性能抓包接口
  - interface: eth1
    cluster-id: 99
    cluster-type: cluster_flow

outputs:
  - eve-log:                  # JSON格式事件输出
      enabled: yes
      filetype: file
      filename: /var/log/suricata/eve.json
      types:
        - alert
        - http
        - dns
        - tls
        - flow                # 输出流记录(类NetFlow)
  - unified2:                 # 兼容Snort格式
      enabled: yes
```

```bash
# 启动 Suricata (镜像口旁路模式)
suricata -c /etc/suricata/suricata.yaml -i eth1 --runmode workers

# 实时查看告警
tail -f /var/log/suricata/eve.json | jq 'select(.event_type=="alert")'
```

### 6.3 规则编写实战

**1. 基础检测规则：**

```
# 检测某恶意域名DNS查询
alert dns $HOME_NET any -> any any (msg:"MALWARE C2 DNS Query"; \
  dns.query; content:"evil-c2.net"; sid:20250001; rev:1;)

# 检测SQL注入
alert http any any -> $HOME_NET any (msg:"SQLi UNION SELECT"; \
  flow:to_server,established; \
  http.uri; content:"UNION"; nocase; \
  http.uri; content:"SELECT"; nocase; \
  sid:20250002; rev:2;)

# 检测明文敏感信息外发(响应中含身份证号)
alert http $HOME_NET any -> $EXTERNAL_NET any (msg:"PII Leakage"; \
  flow:to_server,established; \
  http.request_body; content:"1101"; depth:4; \
  pcre:"/\d{17}[\dXx]/"; \
  sid:20250003; rev:1;)
```

**2. 预处理器：** 在规则匹配前对流量做规范化。

```
# suricata.yaml 预处理器配置
app-layer:
  protocols:
    http:
      enabled: yes
      libhtp:
        default-config:
          request-body-limit: 100kb
          response-body-limit: 100kb
    tls:
      enabled: yes
      detection-ports:
        dp: 443
    dns:
      tcp:
        enabled: yes
      udp:
        enabled: yes
```

**3. 性能调优：**

```yaml
# 调整运行模式为workers(每个线程独立)
runmode: workers

af-packet:
  - interface: eth1
    threads: 8                 # 与CPU核心数对应
    cluster-id: 99
    cluster-type: cluster_flow # 按流hash分流,保证同流同线程

# 规则性能: 用 threshold 限流避免规则风暴
alert http any any -> any any (msg:"High rate HTTP"; \
  content:"/api/"; \
  threshold:type both, track by_src, count 100, seconds 10; \
  sid:20250004; rev:1;)
```

### 6.4 告警管理与误报处理

告警多了会淹没真实威胁。管理流程：

1. **告警聚合：** 同一规则短时间内多次触发合并成一条事件。
2. **白名单：** 已知正常业务（备份、扫描器）加入白名单抑制。
3. **优先级：** 按规则 severity、资产价值、是否成功三维度评分，高优处理。
4. **关闭低价值规则：** 永远不会响应的探测规则关掉。
5. **联动威胁情报：** 告警中的 IP/域名与威胁情报库交叉，自动升级置信度。

```
# 用jq过滤高优先级告警
cat eve.json | jq 'select(.event_type=="alert" and .alert.severity==1)'

# 统计各规则告警数, 找到噪音规则
cat eve.json | jq -r 'select(.event_type=="alert") | .alert.signature' | sort | uniq -c | sort -rn | head
```

### 6.5 IDS/IPS 部署模式

```
旁路部署(IDS):
  镜像口 ──→ IDS引擎
  优点: 不影响业务, 不成为瓶颈
  缺点: 只能告警不能阻断

串行部署(IPS):
  业务流量 ──→ IPS引擎 ──→ 目标网络
  优点: 可实时阻断
  缺点: 故障会断业务, 需Bypass机制, 性能要求高

混合部署:
  出口串行IPS(阻断已知攻击) + 内网旁路IDS(深度检测)
```
