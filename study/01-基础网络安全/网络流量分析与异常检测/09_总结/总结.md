# 总结

网络流量分析是安全运营与应急响应的核心能力。掌握要点：

1. **方法论分层：** 实时告警（IDS）+ 离线取证（全流量）+ 趋势基线（NetFlow）三层互补。
2. **工具链打通：** Wireshark 深度解包、Suricata/Zeek 自动化、Arkime 大规模检索、ELK 可视化告警。
3. **异常检测多维度：** 阈值（快速）+ 行为（Beaconing/扫描）+ 签名（已知）+ 机器学习（未知），不可单靠一种。
4. **攻击特征熟悉：** DDoS/扫描/横向/外泄/C2 各有典型流量指纹，熟悉才能快速判定。
5. **实战思维：** 先用元数据/NetFlow 快速定位可疑会话，再用全流量 Wireshark 深挖确认，形成"定位—深挖—取证"工作流。

持续学习路径：先精通 Wireshark 过滤与解密 → 上手 Suricata 规则编写 → 部署 Zeek 日志分析 → 搭建 Arkime+ELK 平台 → 在实战案例中沉淀经验。

### 一、Wireshark 常用过滤表达式速查表

#### 1. 基础过滤（按协议/地址/端口）

| 过滤目的 | 表达式 | 说明 |
|----------|--------|------|
| 按IP地址 | `ip.addr == 192.168.1.100` | 源或目的都是该IP |
| 按源IP | `ip.src == 10.0.0.1` | 仅源地址 |
| 按目的IP | `ip.dst == 10.0.0.2` | 仅目的地址 |
| 按网段 | `ip.addr == 192.168.0.0/16` | 子网过滤 |
| 按端口 | `tcp.port == 80` | TCP源或目的端口 |
| 按目的端口 | `tcp.dstport == 443` | 仅目的端口 |
| 按源端口 | `tcp.srcport == 12345` | 仅源端口 |
| 多端口 | `tcp.port == 80 || tcp.port == 443` | 80或443 |
| 端口范围 | `tcp.port >= 1024 && tcp.port <= 2048` | 范围内端口 |
| 按协议 | `http` / `dns` / `ftp` / `ssh` / `tls` | 直接写协议名 |
| 排除协议 | `!arp` 或 `not arp` | 排除ARP包 |

---

#### 2. TCP/UDP 高级过滤

| 过滤目的 | 表达式 | 说明 |
|----------|--------|------|
| 仅SYN包 | `tcp.flags.syn == 1 && tcp.flags.ack == 0` | 连接发起 |
| 仅SYN-ACK | `tcp.flags.syn == 1 && tcp.flags.ack == 1` | 连接响应 |
| FIN包 | `tcp.flags.fin == 1` | 连接关闭 |
| RST包 | `tcp.flags.reset == 1` | 连接重置 |
| 握手完成标志 | `tcp.flags == 0x012` | SYN+ACK（十六进制） |
| 零窗口 | `tcp.window_size == 0` | 接收方缓冲区满 |
| 重传包 | `tcp.analysis.retransmission` | Wireshark检测的重传 |
| 重复ACK | `tcp.analysis.duplicate_ack` | 丢包迹象 |
| 大包 | `tcp.len > 1000` | TCP载荷大于1000字节 |
| UDP指定端口范围 | `udp.dstport >= 5000 && udp.dstport <= 6000` | UDP目的端口范围 |

---

#### 3. 应用层协议过滤

**HTTP 过滤：**

| 表达式 | 说明 |
|--------|------|
| `http.request.method == "GET"` | 仅GET请求 |
| `http.request.method == "POST"` | 仅POST请求 |
| `http.request.uri contains "login"` | URI包含"login" |
| `http.host == "www.example.com"` | 指定Host头 |
| `http.response.code == 200` | 响应状态码200 |
| `http.response.code >= 400` | 4xx/5xx错误响应 |
| `http.user_agent contains "curl"` | 按User-Agent过滤 |
| `http.cookie contains "session"` | Cookie包含session |
| `http.request.full_uri` | 完整请求URL（列显示用） |

**DNS 过滤：**

| 表达式 | 说明 |
|--------|------|
| `dns.qry.name == "www.example.com"` | 查询指定域名 |
| `dns.qry.name contains "google"` | 域名包含关键字 |
| `dns.flags.response == 0` | 仅查询请求 |
| `dns.flags.response == 1` | 仅响应 |
| `dns.flags.rcode != 0` | 非零响应码（查询失败等） |
| `dns.qry.type == 1` | A记录查询（1=A, 5=CNAME, 15=MX, 28=AAAA） |
| `dns.resp.addr` | DNS响应的IP地址（列显示用） |

**TLS/SSL 过滤：**

| 表达式 | 说明 |
|--------|------|
| `tls.handshake.type == 1` | Client Hello |
| `tls.handshake.type == 2` | Server Hello |
| `tls.handshake.extensions_server_name == "example.com"` | SNI域名（TLS 1.2及以下） |
| `tls.handshake.ciphersuite` | 协商的密码套件 |
| `tls.alert_message` | TLS告警（如证书错误） |
| `ssl.handshake` | SSL握手（旧版协议） |

---

#### 4. 异常流量检测过滤

| 检测目标 | 过滤表达式 | 说明 |
|----------|-----------|------|
| 端口扫描迹象 | `tcp.flags.syn==1 && tcp.flags.ack==0 && tcp.window_size==1024` | 典型nmap扫描特征 |
| SYN Flood | `tcp.flags.syn==1 && tcp.flags.ack==0` | 大量SYN无ACK |
| DNS隧道迹象 | `dns.qry.name.len > 50 && udp.length > 200` | 异常长的DNS查询名 |
| ICMP隧道 | `icmp.data_len > 64` | ICMP载荷异常大 |
| 可疑HTTP方法 | `http.request.method in {"PUT" "DELETE" "TRACE"}` | 危险HTTP方法 |
| 心跳包/Beaconing | 需结合IO Graph分析 | 周期性通信特征 |
| 大包异常 | `frame.len > 1500` | 超过标准MTU |
| 非标准端口跑HTTP | `http && tcp.dstport != 80` | HTTP跑在非80端口 |
| ARP欺骗迹象 | `arp.duplicate-address-detected` | Wireshark检测到重复IP |

#### 6. 实战场景：流量分析工作流

**场景：分析疑似C2通信的pcap文件**

```
Step 1 → 宏观概览
   打开 pcap → Statistics → Protocol Hierarchy
   看协议分布是否正常（异常多的DNS、ICMP等需关注）
   ↓

Step 2 → 端点统计
   Statistics → Conversations（按Bytes排序）
   找异常高流量的IP对，或异常多连接数的IP
   ↓

Step 3 → 过滤HTTP/DNS
   应用过滤：http → 看请求的Host和URI有无可疑域名
   应用过滤：dns → 看查询的域名模式（随机字符→DGA？）
   ↓

Step 4 → 分析TLS握手
   过滤：tls.handshake.type == 1 → 看SNI
   关注：自签证书、异常端口上的TLS、冷门密码套件
   ↓

Step 5 → 检查Beaconing（周期性通信）
   选定可疑IP对 → Statistics → I/O Graph
   看时间分布是否呈规律性间隔（如每60秒一个包）
   ↓

Step 6 → 深度分析
   Follow TCP Stream → 看明文内容
   导出对象：File → Export Objects → HTTP
   提取可疑文件做进一步分析
```

### 二、tcpdump 常用命令速查

#### 1. 基础抓包命令

| 命令 | 说明 |

#### 3. 过滤表达式（进阶）

**主机与网络过滤：**

```bash
# 指定主机
tcpdump -i eth0 host 192.168.1.1

# 源/目的单独指定
tcpdump -i eth0 src host 10.0.0.1
tcpdump -i eth0 dst host 10.0.0.2

# 子网过滤
tcpdump -i eth0 net 192.168.0.0/16
tcpdump -i eth0 src net 10.0.0.0/8

# 排除某主机
tcpdump -i eth0 'not host 192.168.1.100'
```

**端口过滤：**

```bash
# 单个端口
tcpdump -i eth0 'port 443'

# 源/目的端口
tcpdump -i eth0 'dst port 80'
tcpdump -i eth0 'src port 53'

# 端口范围
tcpdump -i eth0 'portrange 1-1024'

# 多端口
tcpdump -i eth0 'port 80 or port 443 or port 8080'
```

**协议过滤：**

```bash
# 按协议名
tcpdump -i eth0 tcp
tcpdump -i eth0 udp
tcpdump -i eth0 icmp
tcpdump -i eth0 arp
tcpdump -i eth0 ip6  # IPv6

# 协议+端口组合
tcpdump -i eth0 'tcp port 80'
tcpdump -i eth0 'udp port 53'
```

**TCP标志位过滤：**

```bash
# 仅SYN包（连接发起）
tcpdump -i eth0 'tcp[tcpflags] & tcp-syn != 0'

# SYN且无ACK（纯SYN）
tcpdump -i eth0 'tcp[tcpflags] & (tcp-syn|tcp-ack) == tcp-syn'

# SYN-ACK
tcpdump -i eth0 'tcp[tcpflags] & (tcp-syn|tcp-ack) == (tcp-syn|tcp-ack)'

# RST包
tcpdump -i eth0 'tcp[tcpflags] & tcp-rst != 0'

# FIN包
tcpdump -i eth0 'tcp[tcpflags] & tcp-fin != 0'
```

**载荷内容过滤：**

```bash
# TCP载荷中包含特定字符串（偏移方式）
# 匹配HTTP GET请求（"GET " = 0x47455420）
tcpdump -i eth0 -A 'tcp dst port 80 and tcp[((tcp[12:1] & 0xf0) >> 2):4] = 0x47455420'

# DNS查询名中包含特定字符（较复杂，一般用-grep管道）
tcpdump -i eth0 -nn -s 0 'udp port 53' | grep -i "suspicious"

# ICMP类型过滤
tcpdump -i eth0 'icmp[icmptype] == icmp-echo'       # ICMP请求
tcpdump -i eth0 'icmp[icmptype] == icmp-echoreply'  # ICMP响应
```

#### 4. 实战场景命令集

**场景1：抓HTTP明文密码**

```bash
# 抓取POST请求中的表单数据
tcpdump -i eth0 -s 0 -A 'tcp dst port 80 and (tcp[((tcp[12:1] & 0xf0) >> 2):4] = 0x504f5354)'
# 0x504f5354 = "POST"
```

**场景2：抓DNS请求分析DGA域名**

```bash
# 抓取所有DNS查询，持续输出
tcpdump -i any -nn -s 0 'udp port 53' | awk '{print $NF}'

# 保存到文件，事后分析
tcpdump -i any -nn -s 0 -w dns_capture.pcap 'udp port 53' -G 3600 -W 24
# 每小时一个文件，保留24小时
```

**场景3：检测端口扫描**

```bash
# 抓取来自外部的SYN包，看短时间内的目标端口分布
tcpdump -i eth0 -n 'tcp[tcpflags] & (tcp-syn|tcp-ack) == tcp-syn and not src net 192.168.0.0/16'
# 若单一源IP访问大量不同目的端口，大概率是扫描
```

**场景4：排查HTTPS连接失败**

```bash
# 抓TLS握手过程
tcpdump -i eth0 -nn -s 0 'tcp port 443 and (tcp[tcpflags] & tcp-syn != 0 or tcp[((tcp[12:1] & 0xf0) >> 2):1] = 0x16)'
# 0x16 = TLS Handshake Content Type

# 更简单的方式：抓443端口用Wireshark分析
tcpdump -i eth0 -nn -s 0 -w tls_handshake.pcap 'host 目标IP and tcp port 443'
```

**场景5：监控进出流量大小**

```bash
# 实时统计（需配合awk计算）
tcpdump -i eth0 -n -e -s 0 'ip' | awk '{
    len = $8; gsub(/[^0-9]/, "", len);
    if ($3 ~ />/) { total += len; count++ }
    if (count % 100 == 0) printf "Total: %d bytes, Packets: %d\r", total, count
}'
```

#### 5. tshark（命令行版Wireshark）常用命令

> tshark 是 Wireshark 的命令行版本，支持 Wireshark 同款过滤语法，功能比 tcpdump 更强。

| 命令 | 说明 |
|------|------|
| `tshark -D` | 列出网卡 |
| `tshark -i eth0 -f "port 80"` | 抓包过滤（-f 是捕获过滤） |
| `tshark -i eth0 -Y "http.request"` | 显示过滤（-Y 是显示过滤，语法同Wireshark） |
| `tshark -r capture.pcap -Y "dns"` | 读pcap并过滤显示 |
| `tshark -r capture.pcap -T fields -e ip.src -e dns.qry.name` | 提取指定字段 |
| `tshark -r capture.pcap -z conv,tcp` | TCP会话统计 |
| `tshark -r capture.pcap -z http_req,tree` | HTTP请求统计 |
| `tshark -i eth0 -w output.pcap -b filesize:100000 -b files:10` | 循环抓包（100MB/文件，共10个） |

**实战示例：从pcap中提取所有HTTP请求的URL**

```bash
tshark -r capture.pcap -Y "http.request" \
  -T fields \
  -e frame.time \
  -e ip.src \
  -e http.request.method \
  -e http.host \
  -e http.request.uri
```
