# 总结

计算机网络是信息安全的基础。从物理层的比特传输，到数据链路层的帧交换、网络层的路由转发、传输层的端到端通信，再到应用层的各类服务，每一层都有其独特的协议和安全挑战。

**关键要点回顾**：

1. OSI 七层模型和 TCP/IP 模型是理解网络的基础框架，分层设计使复杂问题简单化。
2. 各层核心协议：物理层（传输介质）→ 数据链路层（Ethernet、ARP、交换机）→ 网络层（IP、ICMP、路由器）→ 传输层（TCP、UDP）→ 应用层（HTTP、DNS、SSH 等）。
3. 网络安全涉及机密性、完整性、可用性三要素，攻击手段层出不穷，防护需多层纵深防御。
4. 掌握网络排查工具和方法，是安全从业者的必备技能。

---

### 一、网络排查常用命令速查表

#### 1. ping —— 连通性与延迟测试

**常用参数：**

| 参数 | 说明 | 示例 |
|------|------|------|
| `-c N` | 发送 N 个包后停止（Linux） | `ping -c 4 192.168.1.1` |
| `-t` | 持续 ping（Windows） | `ping -t 8.8.8.8` |
| `-n N` | 发送 N 个包（Windows） | `ping -n 10 192.168.1.1` |
| `-i sec` | 发包间隔（秒，Linux） | `ping -i 0.5 10.0.0.1` |
| `-s size` | 指定数据包大小（字节） | `ping -s 1500 192.168.1.1` |
| `-M do` | 设置DF位（不分片，Linux） | `ping -M do -s 1472 8.8.8.8` |
| `-f` | 洪水 ping（压测用，需 root） | `ping -f 192.168.1.1` |

**实战场景：**

```bash
# 场景1：快速判断目标主机是否在线
ping -c 3 -W 2 192.168.1.100
# -W 2 表示每个包超时2秒，快速失败

# 场景2：测试 MTU（路径最大传输单元）
# 1500字节MTU下，ICMP数据=1500-28(IP头+ICMP头)=1472
ping -M do -s 1472 8.8.8.8
# 如果提示"Message too long"，说明路径上MTU小于1500

# 场景3：批量探测网段存活主机（Bash）
for i in {1..254}; do
  ping -c 1 -W 0.5 192.168.1.$i > /dev/null 2>&1 && echo "192.168.1.$i is up"
done
```

#### 2. traceroute / tracert —— 路径追踪

**常用参数：**

| 参数 | 说明 | 示例 |
|------|------|------|
| `-n` | 不解析域名，纯IP输出（更快） | `traceroute -n 8.8.8.8` |
| `-m N` | 最大跳数（默认30） | `traceroute -m 20 10.0.0.1` |
| `-q N` | 每跳发包数（默认3） | `traceroute -q 1 8.8.8.8` |
| `-I` | 使用 ICMP ECHO（类似 ping 方式） | `traceroute -I 8.8.8.8` |
| `-T` | 使用 TCP SYN（需 root，绕过防火墙） | `traceroute -T -p 443 8.8.8.8` |
| `-p port` | 指定 UDP/TCP 目标端口 | `traceroute -T -p 80 example.com` |
| `-w sec` | 每跳超时时间 | `traceroute -w 2 8.8.8.8` |

**Windows 下使用 tracert：**

```cmd
tracert -d -h 20 8.8.8.8
:: -d 不解析地址  -h 20 最大20跳
```

**实战场景：**

```bash
# 场景1：排查访问慢的问题——定位哪一跳延迟高
traceroute -n -q 1 -w 2 slow-server.example.com

# 场景2：防火墙拦截了ICMP？用TCP模式追踪
traceroute -n -T -p 443 -q 1 www.google.com
# 使用TCP 443端口追踪，更容易穿过防火墙

# 场景3：用mtr（整合了ping+traceroute的工具）持续监控路径质量
mtr --report --report-cycles 10 8.8.8.8
# 生成10个周期的统计报告，展示每跳的丢包率和延迟分布
```

#### 3. netstat / ss —— 网络连接与端口查看

> **注意：** netstat 已逐渐被 ss 命令取代，但仍广泛使用。两者都可查看。

**netstat 常用参数：**

| 参数 | 说明 | 示例 |
|------|------|------|
| `-a` | 显示所有连接和监听端口 | `netstat -a` |
| `-n` | 数字形式显示，不解析 | `netstat -an` |
| `-t` | 仅显示 TCP 连接 | `netstat -tn` |
| `-u` | 仅显示 UDP 连接 | `netstat -un` |
| `-l` | 仅显示监听端口 | `netstat -tnl` |
| `-p` | 显示进程名/ PID（需 root） | `netstat -tnlp` |
| `-r` | 显示路由表 | `netstat -rn` |
| `-s` | 显示协议统计 | `netstat -s` |
| `-e` | 显示扩展信息 | `netstat -tne` |

**ss 常用参数（推荐）：**

| 参数 | 说明 | 示例 |
|------|------|------|
| `-t` | TCP 连接 | `ss -t` |
| `-u` | UDP 连接 | `ss -u` |
| `-l` | 监听端口 | `ss -tl` |
| `-n` | 数字形式 | `ss -tn` |
| `-p` | 进程信息 | `ss -tnp` |
| `-a` | 所有状态（监听+已建立） | `ss -tna` |
| `-o state established` | 按状态过滤 | `ss -tn state established` |
| `dst :port` | 按目标端口过滤 | `ss -tn dst :443` |
| `-i` | 显示 TCP 内部信息 | `ss -ti` |

**实战场景：**

```bash
# 场景1：找出哪个进程在监听8080端口
ss -tlnp | grep 8080
# 或
netstat -tlnp | grep 8080

# 场景2：查看与某IP建立的所有连接
ss -tn state established dst 192.168.1.100

# 场景3：统计各状态TCP连接数（排查DDoS/连接耗尽）
ss -tan | awk 'NR>1 {state[$1]++} END {for(s in state) print s, state[s]}'

# 场景4：查看本机路由表
netstat -rn
# 或
route -n
# 或
ip route show
```

**Windows 下常用命令：**

```cmd
:: 查看所有连接和PID
netstat -ano

:: 查看监听端口
netstat -ano | findstr LISTENING

:: 查找占用80端口的进程PID
netstat -ano | findstr :80
:: 再根据PID查进程名
tasklist | findstr <PID>
```

#### 4. tcpdump —— 命令行抓包工具

**常用参数：**

| 参数 | 说明 | 示例 |
|------|------|------|
| `-i iface` | 指定网卡（any 表示所有） | `tcpdump -i eth0` |
| `-n` | 不解析IP和端口 | `tcpdump -n -i eth0` |
| `-nn` | 不解析IP、端口、协议 | `tcpdump -nn -i eth0` |
| `-c N` | 抓 N 个包后退出 | `tcpdump -c 100 -i eth0` |
| `-w file` | 写入 pcap 文件 | `tcpdump -w capture.pcap -i eth0` |
| `-r file` | 读取 pcap 文件 | `tcpdump -r capture.pcap` |
| `-s len` | 抓取长度（0=完整包） | `tcpdump -s 0 -i eth0` |
| `-v / -vv / -vvv` | 详细程度递增 | `tcpdump -vv -i eth0` |
| `-X` | 十六进制+ASCII 显示 | `tcpdump -X -i eth0` |
| `-A` | 仅ASCII显示（看HTTP等） | `tcpdump -A -i eth0` |
| `-e` | 显示链路层信息 | `tcpdump -e -i eth0` |

**常用过滤表达式：**

| 过滤条件 | 表达式 | 说明 |
|----------|--------|------|
| 按主机 | `host 192.168.1.1` | 只看该主机的流量 |
| 按源/目的 | `src host 10.0.0.1` / `dst host 10.0.0.2` | 单向过滤 |
| 按端口 | `port 80` | 所有80端口流量 |
| 按协议 | `tcp` / `udp` / `icmp` / `arp` | 协议过滤 |
| 按端口范围 | `portrange 1-1024` | 端口范围 |
| 按网段 | `net 192.168.0.0/16` | 子网过滤 |
| 组合条件 | `host 10.0.0.1 and port 443` | 逻辑与 |
| 组合条件 | `port 80 or port 443` | 逻辑或 |
| 排除 | `not port 22` | 排除SSH流量 |
| TCP标志位 | `tcp[tcpflags] & tcp-syn != 0` | 仅SYN包 |
| 大于某长度 | `greater 1000` | 数据包>1000字节 |

**实战场景：**

```bash
# 场景1：抓取HTTP请求内容（明文查看GET/POST）
tcpdump -i eth0 -s 0 -A 'tcp dst port 80 and tcp[((tcp[12:1] & 0xf0) >> 2):4] = 0x47455420'
# 解释：匹配TCP载荷开头为"GET "（0x47455420）

# 场景2：抓取DNS查询和响应
tcpdump -i any -nn -s 0 'udp port 53' -v

# 场景3：抓取SYN包（检测端口扫描）
tcpdump -i eth0 -n 'tcp[tcpflags] & tcp-syn != 0 and tcp[tcpflags] & tcp-ack == 0'

# 场景4：抓包存文件，事后用Wireshark分析
tcpdump -i eth0 -s 0 -w /tmp/capture.pcap 'port 443'
# 后台抓包，限制大小和数量
tcpdump -i eth0 -s 0 -C 100 -W 5 -w /tmp/capture.pcap 'host 10.0.0.5'
# -C 100 每个文件100MB，-W 5 最多5个文件（循环覆盖）

# 场景5：读取pcap文件，按条件过滤显示
tcpdump -r capture.pcap -n 'host 192.168.1.100 and port 80'
```

#### 5. nslookup / dig —— DNS 查询工具

**nslookup 常用用法：**

```bash
# 基础查询（A记录）
nslookup www.example.com

# 指定DNS服务器查询
nslookup www.example.com 8.8.8.8

# 交互式查询不同记录类型
nslookup
> set type=mx       # 查询MX记录（邮件服务器）
> example.com
> set type=ns       # 查询NS记录
> example.com
> set type=txt      # 查询TXT记录（SPF/DKIM等）
> example.com
> set type=any      # 查询所有记录
> example.com
> set type=ptr      # 反向解析
> 8.8.8.8
> exit
```

**dig 常用用法（推荐，Linux 下功能更强）：**

| 命令 | 说明 |
|------|------|
| `dig example.com` | 查询A记录 |
| `dig @8.8.8.8 example.com` | 指定DNS服务器 |
| `dig MX example.com` | 查询MX记录 |
| `dig NS example.com` | 查询NS记录 |
| `dig TXT example.com` | 查询TXT记录 |
| `dig -x 8.8.8.8` | 反向解析（PTR） |
| `dig +trace example.com` | 追踪完整解析路径（从根到权威） |
| `dig +short example.com` | 简洁输出（只给结果） |
| `dig ANY example.com` | 查询所有记录类型 |
| `dig +tcp example.com` | 使用TCP查询（测试53端口TCP） |

**实战场景：**

```bash
# 场景1：排查DNS解析慢——追踪完整解析路径
dig +trace www.example.com
# 可以看到根→顶级域→权威→结果的完整链路，定位哪一步慢

# 场景2：验证DNS缓存污染
dig @8.8.8.8 suspicious-domain.com   # 查公共DNS
dig @本地DNS_IP suspicious-domain.com # 查本地DNS
# 对比结果，如果不一致可能存在缓存污染

# 场景3：批量域名解析
cat domains.txt | while read domain; do
  echo -n "$domain -> "
  dig +short $domain | head -1
done

# 场景4：检查SPF记录（反邮件欺诈）
dig TXT example.com +short | grep v=spf
```

### 二、网络排查经典流程（实战思路）

```
现象：某服务器无法访问互联网

Step 1 → 检查本地网卡状态
   ip addr show eth0
   ethtool eth0
   ↓ 网卡正常？是→继续；否→检查网线/驱动/IP配置

Step 2 → 检查网关连通性
   ping -c 3 <网关IP>
   ↓ 通？是→继续；否→检查本机路由和网关

Step 3 → 检查DNS解析
   dig @8.8.8.8 www.baidu.com    # 先用公共DNS确认
   dig @<本地DNS> www.baidu.com   # 再用本地DNS对比
   ↓ 解析正常？是→继续；否→DNS问题

Step 4 → 检查目标端口连通性
   nc -zv www.baidu.com 443
   curl -I https://www.baidu.com
   ↓ 通？是→应用层问题；否→防火墙/路由问题

Step 5 → 抓包分析（定位丢包位置）
   tcpdump -i eth0 -nn host 目标IP and port 443
   ↓ 看SYN是否发出？有无SYN-ACK返回？
   ↓ 发出但无响应→中间被拦；有响应但应用报错→应用层问题
```
