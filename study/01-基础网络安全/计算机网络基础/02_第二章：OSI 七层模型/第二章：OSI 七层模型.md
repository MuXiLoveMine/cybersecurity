# 第二章：OSI 七层模型

### 2.1 OSI 模型概述

OSI（Open Systems Interconnection，开放系统互联）参考模型是国际标准化组织（ISO）制定的一个网络通信的分层架构模型。它将网络通信的功能划分为七个层次，每层各司其职，通过接口与上下层交互。

```
┌─────────────────────────────┐
│    应用层 (Application)     │  ← 用户与网络的接口
├─────────────────────────────┤
│    表示层 (Presentation)    │  ← 数据格式转换、加密解密
├─────────────────────────────┤
│    会话层 (Session)         │  ← 建立、管理、终止会话
├─────────────────────────────┤
│    传输层 (Transport)       │  ← 端到端的可靠传输
├─────────────────────────────┤
│    网络层 (Network)         │  ← 路由选择、IP 寻址
├─────────────────────────────┤
│  数据链路层 (Data Link)     │  ← MAC 寻址、差错检测
├─────────────────────────────┤
│    物理层 (Physical)        │  ← 比特流传输、物理介质
└─────────────────────────────┘
```

### 2.2 各层功能详解

| 层次 | 名称 | 主要功能 | 数据单位 | 典型协议/设备 |
|------|------|---------|---------|--------------|
| 第7层 | 应用层 | 为应用程序提供网络服务接口 | 数据（Data） | HTTP、FTP、SMTP、DNS、Telnet |
| 第6层 | 表示层 | 数据格式转换、加密解密、压缩解压 | 数据（Data） | SSL/TLS、JPEG、ASCII、MPEG |
| 第5层 | 会话层 | 建立、管理和终止会话，会话同步 | 数据（Data） | RPC、SQL、NetBIOS |
| 第4层 | 传输层 | 端到端的可靠传输、流量控制、差错恢复 | 数据段（Segment） | TCP、UDP |
| 第3层 | 网络层 | 路由选择、IP 寻址、分组转发 | 数据包/分组（Packet） | IP、ICMP、ARP / 路由器 |
| 第2层 | 数据链路层 | MAC 寻址、帧的封装、差错检测 | 帧（Frame） | Ethernet、PPP / 交换机、网桥 |
| 第1层 | 物理层 | 比特流传输、物理接口、电气特性 | 比特（Bit） | 光纤、双绞线、中继器、集线器 |

### 2.3 数据封装与解封装

#### 封装过程（发送方，自上而下）

数据从应用层到物理层的传输过程中，每一层都会添加自己的头部信息（Header），这个过程称为**封装**（Encapsulation）。

```
应用层 → 数据 (Data)
  ↓ 添加应用层头部
表示层 → [头部 + 数据]
  ↓ 添加表示层头部
会话层 → [头部 + 数据]
  ↓ 添加传输层头部 (TCP/UDP)
传输层 → [TCP头 + 数据]   → 数据段 (Segment)
  ↓ 添加网络层头部 (IP)
网络层 → [IP头 + TCP头 + 数据]   → 数据包 (Packet)
  ↓ 添加数据链路层头和尾
数据链路层 → [MAC头 + IP头 + TCP头 + 数据 + FCS]   → 帧 (Frame)
  ↓ 转换为比特流
物理层 → 01010101...   → 比特流 (Bits)
```

#### 解封装过程（接收方，自下而上）

接收方从物理层接收到比特流后，逐层向上传递，每一层去除对应的头部信息，这个过程称为**解封装**（Decapsulation）。

> **记忆口诀**：应表会传网数物（从上到下）；物数网传会表应（从下到上）。

### 2.4 OSI 模型的意义

- **标准化**：不同厂商的设备可以互联互通
- **分层设计**：各层独立，修改一层不影响其他层
- **易于学习**：将复杂问题分解为多个简单问题
- **便于排错**：可以逐层定位故障位置
