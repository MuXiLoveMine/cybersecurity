## 第一章：计算机网络概述

### 1.1 什么是计算机网络

计算机网络是指将地理位置不同的、具有独立功能的多台计算机及其外部设备，通过通信线路连接起来，在网络操作系统、网络管理软件及网络通信协议的管理和协调下，实现资源共享和信息传递的计算机系统。

简单来说，计算机网络就是由多台计算机（或其他网络设备）通过传输介质和软件物理（或逻辑）连接在一起组成的集合。

### 1.2 网络的主要功能

| 功能 | 说明 |
|------|------|
| **数据通信** | 实现计算机之间的数据传输，是网络最基本的功能 |
| **资源共享** | 共享硬件资源（打印机、存储）、软件资源和数据资源 |
| **分布式处理** | 将大型任务分解到多台计算机上并行处理，提高效率 |
| **提高可靠性** | 数据和服务可以在多台计算机上备份，避免单点故障 |
| **负载均衡** | 将工作任务均匀分配给网络中的多台计算机 |

### 1.3 网络的分类

#### 1.3.1 按覆盖范围分类

| 类型 | 英文缩写 | 覆盖范围 | 典型场景 |
|------|---------|---------|----------|
| 个域网 | PAN | 几米范围 | 个人设备互联（蓝牙、手机热点） |
| 局域网 | LAN | 几百米到几公里 | 家庭、学校、企业内部网络 |
| 城域网 | MAN | 几公里到几十公里 | 城市范围的网络 |
| 广域网 | WAN | 几十公里到全球 | 互联网、跨城/跨国专线 |

#### 1.3.2 按拓扑结构分类

| 拓扑类型 | 结构特点 | 优点 | 缺点 |
|---------|---------|------|------|
| **星型** | 所有节点连接到中心节点（交换机） | 易管理、故障易定位 | 中心节点故障影响全网 |
| **总线型** | 所有节点共享一条传输线路 | 布线简单、成本低 | 故障难定位、冲突严重 |
| **环型** | 节点首尾相连形成闭合环 | 传输延迟确定 | 单环故障影响全网 |
| **树型** | 星型的层级扩展 | 扩展性好、易于管理 | 根节点故障影响大 |
| **网状** | 节点之间有多条路径相连 | 可靠性高、容错性强 | 成本高、管理复杂 |
| **混合型** | 多种拓扑结构组合 | 灵活适应不同需求 | 设计和管理复杂 |

#### 1.3.3 按传输介质分类

| 介质类型 | 具体介质 | 特点 |
|---------|---------|------|
| **有线** | 双绞线（UTP/STP） | 成本低、易安装、距离短（100m） |
| **有线** | 同轴电缆 | 抗干扰强、带宽有限 |
| **有线** | 光纤 | 带宽高、距离远、抗电磁干扰、成本高 |
| **无线** | 无线电波（Wi-Fi） | 移动性好、易受干扰 |
| **无线** | 微波/卫星 | 远距离、受天气影响 |
| **无线** | 蓝牙 | 短距离、低功耗 |

### 1.4 网络性能指标

| 指标 | 定义 | 单位 |
|------|------|------|
| **带宽** | 链路的最大数据传输能力 | bps（比特每秒） |
| **速率** | 实际的数据传输速度 | bps、Kbps、Mbps、Gbps |
| **延迟** | 数据从一端到另一端的时间 | ms（毫秒） |
| **抖动** | 延迟的变化程度 | ms |
| **丢包率** | 传输中丢失数据包的比例 | % |
| **吞吐量** | 单位时间内实际传输的数据量 | bps |
| **可用性** | 网络正常运行的时间比例 | % |

> **带宽 vs 速率**：带宽是"路的宽度"（理论最大值），速率是"实际车速"（受拥堵、车况影响）。

### 1.5 网络协议

网络协议是计算机网络中进行数据交换而建立的规则、标准或约定的集合。一个网络协议主要由三个要素组成：

- **语法**：数据与控制信息的结构或格式（"怎么说"）
- **语义**：需要发出何种控制信息，完成何种动作以及做出何种响应（"说什么"）
- **同步**：事件实现顺序的详细说明（"什么时候说"）

常见的标准化组织：
- **ISO**（国际标准化组织）：制定 OSI 参考模型
- **IEEE**：制定局域网标准（如 802.3 以太网）
- **IETF**：制定互联网标准（如 TCP/IP 系列 RFC）
- **ITU-T**：制定通信标准

## 第二章：OSI 七层模型

### 2.1 OSI 模型概述

OSI（Open Systems Interconnection，开放系统互联）参考模型是国际标准化组织（ISO）制定的一个网络通信的分层架构模型。它将网络通信的功能划分为七个层次，每层各司其职，通过接口与上下层交互。

```
┌─────────────────────────────┐
│    应用层 (Application)     │  ← 用户与网络的接口
├─────────────────────────────┤
│    表示层 (Presentation)    │  ← 数据格式转换、加密解密
├─────────────────────────────┤
│    会话层 (Session)         │  ← 建立、管理、终止会话
├─────────────────────────────┤
│    传输层 (Transport)       │  ← 端到端的可靠传输
├─────────────────────────────┤
│    网络层 (Network)         │  ← 路由选择、IP 寻址
├─────────────────────────────┤
│  数据链路层 (Data Link)     │  ← MAC 寻址、差错检测
├─────────────────────────────┤
│    物理层 (Physical)        │  ← 比特流传输、物理介质
└─────────────────────────────┘
```

### 2.2 各层功能详解

| 层次 | 名称 | 主要功能 | 数据单位 | 典型协议/设备 |
|------|------|---------|---------|--------------|
| 第7层 | 应用层 | 为应用程序提供网络服务接口 | 数据（Data） | HTTP、FTP、SMTP、DNS、Telnet |
| 第6层 | 表示层 | 数据格式转换、加密解密、压缩解压 | 数据（Data） | SSL/TLS、JPEG、ASCII、MPEG |
| 第5层 | 会话层 | 建立、管理和终止会话，会话同步 | 数据（Data） | RPC、SQL、NetBIOS |
| 第4层 | 传输层 | 端到端的可靠传输、流量控制、差错恢复 | 数据段（Segment） | TCP、UDP |
| 第3层 | 网络层 | 路由选择、IP 寻址、分组转发 | 数据包/分组（Packet） | IP、ICMP、ARP / 路由器 |
| 第2层 | 数据链路层 | MAC 寻址、帧的封装、差错检测 | 帧（Frame） | Ethernet、PPP / 交换机、网桥 |
| 第1层 | 物理层 | 比特流传输、物理接口、电气特性 | 比特（Bit） | 光纤、双绞线、中继器、集线器 |

### 2.3 数据封装与解封装

#### 封装过程（发送方，自上而下）

数据从应用层到物理层的传输过程中，每一层都会添加自己的头部信息（Header），这个过程称为**封装**（Encapsulation）。

```
应用层 → 数据 (Data)
  ↓ 添加应用层头部
表示层 → [头部 + 数据]
  ↓ 添加表示层头部
会话层 → [头部 + 数据]
  ↓ 添加传输层头部 (TCP/UDP)
传输层 → [TCP头 + 数据]   → 数据段 (Segment)
  ↓ 添加网络层头部 (IP)
网络层 → [IP头 + TCP头 + 数据]   → 数据包 (Packet)
  ↓ 添加数据链路层头和尾
数据链路层 → [MAC头 + IP头 + TCP头 + 数据 + FCS]   → 帧 (Frame)
  ↓ 转换为比特流
物理层 → 01010101...   → 比特流 (Bits)
```

#### 解封装过程（接收方，自下而上）

接收方从物理层接收到比特流后，逐层向上传递，每一层去除对应的头部信息，这个过程称为**解封装**（Decapsulation）。

> **记忆口诀**：应表会传网数物（从上到下）；物数网传会表应（从下到上）。

### 2.4 OSI 模型的意义

- **标准化**：不同厂商的设备可以互联互通
- **分层设计**：各层独立，修改一层不影响其他层
- **易于学习**：将复杂问题分解为多个简单问题
- **便于排错**：可以逐层定位故障位置

## 第三章：TCP/IP 协议栈

### 3.1 TCP/IP 模型概述

TCP/IP（Transmission Control Protocol / Internet Protocol）协议栈是互联网实际使用的网络协议体系。它将 OSI 七层模型简化为四层或五层结构，是当今互联网的事实标准。

### 3.2 OSI 模型与 TCP/IP 模型对比

| OSI 七层模型 | TCP/IP 四层模型 | TCP/IP 五层模型 | 典型协议 |
|-------------|----------------|----------------|---------|
| 应用层 | 应用层 | 应用层 | HTTP、FTP、DNS、SSH |
| 表示层 | 应用层 | 应用层 | SSL/TLS、数据格式 |
| 会话层 | 应用层 | 应用层 | 会话管理 |
| 传输层 | 传输层 | 传输层 | TCP、UDP |
| 网络层 | 网际层 | 网络层 | IP、ICMP、ARP |
| 数据链路层 | 网络接口层 | 数据链路层 | Ethernet、PPP |
| 物理层 | 网络接口层 | 物理层 | 光纤、双绞线 |

### 3.3 TCP/IP 协议族

TCP/IP 协议族是一组协议的集合，主要协议及其层次关系：

```
┌─────────────────────────────────────────────────┐
│  FTP  HTTP  SMTP  DNS  SSH  Telnet  ... (应用层) │
├─────────────────────────────────────────────────┤
│         TCP              UDP        (传输层)     │
├─────────────────────────────────────────────────┤
│  ICMP  IGMP         IP         ARP  RARP (网络层)│
├─────────────────────────────────────────────────┤
│  Ethernet  PPP  Frame Relay  ATM ... (网络接口层)│
└─────────────────────────────────────────────────┘
```

### 3.4 数据传输过程

1. **发送端**：应用层数据 → 传输层添加 TCP/UDP 头 → 网络层添加 IP 头 → 数据链路层添加 MAC 头和 FCS → 物理层转为比特流
2. **传输过程**：经过多个路由器转发（每经过一个路由器，解封装到网络层，根据 IP 地址重新选择路径，再重新封装）
3. **接收端**：物理层比特流 → 数据链路层去 MAC 头 → 网络层去 IP 头 → 传输层去 TCP/UDP 头 → 应用层获取数据

## 第四章：物理层

### 4.1 物理层的功能

物理层是 OSI 模型的最底层，负责在物理介质上传输原始比特流（0 和 1）。它不关心数据的含义，只关注如何将比特从一个节点传输到另一个节点。

主要功能：
- 定义物理接口的机械、电气、功能和规程特性
- 比特流的传输与接收
- 编码与调制
- 物理介质的连接

### 4.2 传输介质

#### 4.2.1 双绞线（Twisted Pair）

双绞线是最常用的有线传输介质，由两根绝缘铜线按一定密度互相绞合而成。

| 类别 | 带宽 | 传输速率 | 应用 |
|------|------|---------|------|
| 五类线（Cat 5） | 100 MHz | 100 Mbps | 快速以太网 |
| 超五类（Cat 5e） | 100 MHz | 1000 Mbps | 千兆以太网 |
| 六类线（Cat 6） | 250 MHz | 1000 Mbps / 10 Gbps（短距） | 千兆/万兆以太网 |
| 超六类（Cat 6a） | 500 MHz | 10 Gbps | 万兆以太网 |
| 七类线（Cat 7） | 600 MHz | 10 Gbps+ | 高屏蔽万兆 |

双绞线分为：
- **UTP**（Unshielded Twisted Pair，非屏蔽双绞线）：成本低、易安装，办公环境常用
- **STP**（Shielded Twisted Pair，屏蔽双绞线）：抗干扰能力强，工业环境使用

#### 4.2.2 光纤（Fiber Optic）

光纤通过光信号传输数据，具有带宽高、距离远、抗电磁干扰等优点。

| 类型 | 芯径 | 光源 | 传输距离 | 特点 |
|------|------|------|---------|------|
| 单模光纤（SMF） | 9/125 μm | 激光 | 几十公里 | 带宽高、距离远、成本高 |
| 多模光纤（MMF） | 50/125 μm 或 62.5/125 μm | LED | 几百米到2公里 | 成本低、距离短 |

#### 4.2.3 无线传输介质

| 技术 | 频率范围 | 速率 | 距离 | 应用 |
|------|---------|------|------|------|
| Wi-Fi（802.11） | 2.4 GHz / 5 GHz / 6 GHz | 数 Mbps ~ 数 Gbps | 几十到几百米 | 无线局域网 |
| 蓝牙（Bluetooth） | 2.4 GHz | 数 Mbps | 几米到几十米 | 短距离设备互联 |
| 4G LTE | 700 MHz ~ 2.6 GHz | 数十 Mbps ~ 数百 Mbps | 几公里 | 移动通信 |
| 5G NR | Sub-6 GHz / 毫米波 | 数百 Mbps ~ 数 Gbps | 几百米到几公里 | 第五代移动通信 |

### 4.3 编码与调制

- **编码**：将数字数据转换为数字信号（如曼彻斯特编码、NRZ 编码）
- **调制**：将数字数据转换为模拟信号（如 ASK、FSK、PSK、QAM）

### 4.4 物理层设备

| 设备 | 功能 | 特点 |
|------|------|------|
| **中继器（Repeater）** | 放大和再生信号，扩展传输距离 | 工作在物理层，不识别 MAC/IP 地址 |
| **集线器（Hub）** | 多端口中继器，将信号广播到所有端口 | 共享带宽，半双工，已基本淘汰 |

## 第五章：数据链路层

### 5.1 数据链路层的功能

数据链路层在物理层提供的服务基础上，在相邻节点之间提供可靠的数据帧传输。

主要功能：
- **封装成帧**：将网络层数据封装成帧（Frame）
- **MAC 寻址**：使用 MAC 地址标识网络设备
- **差错检测**：通过 CRC 等机制检测传输错误
- **流量控制**：协调收发双方的数据传输速率
- **介质访问控制**：决定哪个设备可以在共享介质上发送数据

### 5.2 MAC 地址

MAC（Media Access Control）地址是网络设备的物理地址，固化在网卡的 ROM 中，全球唯一。

- **长度**：48 位（6 字节），通常表示为 12 位十六进制数
- **格式**：前 24 位是 OUI（组织唯一标识符，厂商标识），后 24 位是设备序列号
- **示例**：`00:1A:2B:3C:4D:5E` 或 `00-1A-2B-3C-4D-5E`
- **特殊地址**：
  - 广播地址：`FF:FF:FF:FF:FF:FF`（发送给网络中所有设备）
  - 组播地址：第一位为 1 的地址（发送给一组设备）

### 5.3 以太网（Ethernet）

以太网是最广泛使用的局域网技术，由 Xerox、DEC 和 Intel 于 1970 年代共同开发，后由 IEEE 802.3 标准化。

#### 5.3.1 以太网帧格式

```
┌──────────┬──────────┬────────┬─────────┬──────┬──────────┐
│  目的MAC  │  源MAC   │ 类型/长度│  数据    │ 填充  │  FCS     │
│  (6字节)  │  (6字节) │ (2字节) │(46~1500B)│(0~46B)│ (4字节)  │
└──────────┴──────────┴────────┴─────────┴──────┴──────────┘
```

- **目的 MAC**：接收方的物理地址
- **源 MAC**：发送方的物理地址
- **类型/长度**：标识上层协议类型（如 0x0800 表示 IP，0x0806 表示 ARP）
- **数据**：上层数据，范围 46~1500 字节
- **FCS**（帧校验序列）：CRC 校验码，用于检测传输错误

#### 5.3.2 CSMA/CD

传统共享式以太网使用 CSMA/CD（Carrier Sense Multiple Access with Collision Detection，载波监听多路访问/冲突检测）机制来控制介质访问：

1. **载波监听**：发送前先监听信道是否空闲
2. **多路访问**：多个节点共享同一传输介质
3. **冲突检测**：发送过程中检测是否有冲突，若有冲突则立即停止发送，并发送干扰信号
4. **随机退避**：冲突后等待一段随机时间再重试

> 现代交换式以太网（全双工）已不再需要 CSMA/CD。

#### 5.3.3 以太网速率标准

| 标准 | 速率 | 介质 | 距离 |
|------|------|------|------|
| 10BASE-T | 10 Mbps | 双绞线 | 100 m |
| 100BASE-TX | 100 Mbps | 五类双绞线 | 100 m |
| 1000BASE-T | 1000 Mbps | 超五类/六类双绞线 | 100 m |
| 10GBASE-T | 10 Gbps | 六类/七类双绞线 | 55~100 m |
| 1000BASE-LX | 1000 Mbps | 单模光纤 | 10 km |
| 10GBASE-LR | 10 Gbps | 单模光纤 | 10 km |

### 5.4 ARP 协议

ARP（Address Resolution Protocol，地址解析协议）用于将 IP 地址解析为对应的 MAC 地址。

#### ARP 工作过程

1. 主机 A 要向主机 B 发送数据，但只知道 B 的 IP 地址，不知道 MAC 地址
2. 主机 A 发送 **ARP 请求**（广播）："IP 地址为 192.168.1.2 的 MAC 地址是什么？"
3. 网络中所有主机都收到请求，但只有 IP 地址匹配的主机 B 会响应
4. 主机 B 发送 **ARP 应答**（单播）："192.168.1.2 的 MAC 地址是 xx:xx:xx:xx:xx:xx"
5. 主机 A 将 IP-MAC 映射存入 **ARP 缓存表**，后续直接使用

#### ARP 相关命令

```bash
arp -a                    # 查看 ARP 缓存表
arp -d 192.168.1.1        # 删除指定 ARP 条目
```

> **安全提示**：ARP 协议没有身份验证机制，容易遭受 ARP 欺骗攻击（ARP Spoofing），攻击者可以伪造 ARP 响应实现中间人攻击。

### 5.5 数据链路层设备

#### 5.5.1 网桥（Bridge）

- 工作在数据链路层，根据 MAC 地址转发帧
- 可以分割冲突域，提高网络性能
- 透明网桥：自动学习 MAC 地址表

#### 5.5.2 交换机（Switch）

- 多端口网桥，是现代局域网的核心设备
- 工作在数据链路层（二层交换机）或网络层（三层交换机）
- 每个端口都是独立的冲突域，全双工通信
- **MAC 地址学习**：自动学习端口与 MAC 地址的映射关系
- **帧转发**：根据目的 MAC 地址精准转发，不广播（除广播帧和未知单播帧）

#### 交换机转发流程

1. **学习**：收到帧后，记录源 MAC 地址和接收端口到 MAC 地址表
2. **广播**：如果目的 MAC 地址未知（不在地址表中），向除接收端口外的所有端口泛洪
3. **转发**：如果目的 MAC 地址在地址表中，且与接收端口不同，则向对应端口转发
4. **丢弃**：如果目的 MAC 地址在地址表中，且与接收端口相同，则丢弃

## 第六章：网络层

### 6.1 网络层的功能

网络层负责将数据包从源主机传输到目的主机，跨越多个网络和路由器。

主要功能：
- **IP 寻址**：为每台主机分配唯一的 IP 地址
- **路由选择**：选择数据包从源到目的的最佳路径
- **分组转发**：根据路由表转发数据包
- **拥塞控制**：缓解网络拥塞
- **异构网络互联**：连接不同类型的网络

### 6.2 IP 协议

IP（Internet Protocol，网际协议）是 TCP/IP 协议栈的核心协议，提供无连接的、不可靠的数据报传输服务。

**无连接**：发送数据前不需要建立连接，每个数据包独立传输
**不可靠**：不保证数据包一定到达，不保证按序到达，不保证不重复

可靠性由上层协议（如 TCP）保证。

### 6.3 IPv4 地址

#### 6.3.1 IP 地址格式

IPv4 地址长度为 32 位（4 字节），通常用点分十进制表示：

```
二进制：11000000.10101000.00000001.00000001
十进制：192.168.1.1
```

#### 6.3.2 IP 地址分类

| 类别 | 第一位 | 第一字节范围 | 网络号/主机号 | 默认子网掩码 | 用途 |
|------|--------|-------------|--------------|-------------|------|
| A 类 | 0 | 1~126 | 8位网络号 + 24位主机号 | 255.0.0.0 | 大型网络 |
| B 类 | 10 | 128~191 | 16位网络号 + 16位主机号 | 255.255.0.0 | 中型网络 |
| C 类 | 110 | 192~223 | 24位网络号 + 8位主机号 | 255.255.255.0 | 小型网络 |
| D 类 | 1110 | 224~239 | 组播地址 | - | 组播 |
| E 类 | 1111 | 240~255 | 保留地址 | - | 研究用途 |

> **特殊地址**：
> - 127.0.0.0/8：回环地址（Loopback），用于本地测试
> - 0.0.0.0：表示所有网络/未指定地址
> - 255.255.255.255：受限广播地址

#### 6.3.3 私有 IP 地址

以下地址范围为私有地址（RFC 1918），不能在公网上路由，需通过 NAT 转换：

| 类别 | 地址范围 | 数量 |
|------|---------|------|
| A 类 | 10.0.0.0 ~ 10.255.255.255 | 1 个 A 类网络 |
| B 类 | 172.16.0.0 ~ 172.31.255.255 | 16 个 B 类网络 |
| C 类 | 192.168.0.0 ~ 192.168.255.255 | 256 个 C 类网络 |

### 6.4 子网划分

子网划分（Subnetting）是将一个大网络划分为多个小网络的技术，通过借用主机位作为子网位来实现。

#### 6.4.1 子网掩码

子网掩码用于区分 IP 地址中的网络位和主机位：
- 子网掩码中为 1 的位对应 IP 地址的网络位
- 子网掩码中为 0 的位对应 IP 地址的主机位

#### 6.4.2 CIDR 表示法

CIDR（Classless Inter-Domain Routing，无类域间路由）用 `/位数` 表示网络前缀长度：

- `/8` = 255.0.0.0
- `/16` = 255.255.0.0
- `/24` = 255.255.255.0
- `/27` = 255.255.255.224

#### 6.4.3 子网计算

给定 IP 地址和子网掩码，计算：

1. **网络地址**：IP 地址 AND 子网掩码
2. **广播地址**：主机位全为 1 的地址
3. **可用主机数**：2^主机位数 - 2（减去网络地址和广播地址）

**示例**：192.168.1.100/26

- 子网掩码：255.255.255.192
- 网络地址：192.168.1.64
- 广播地址：192.168.1.127
- 可用主机：192.168.1.65 ~ 192.168.1.126（共 62 个）

### 6.5 ICMP 协议

ICMP（Internet Control Message Protocol，互联网控制报文协议）用于在 IP 网络中传递控制消息和错误报告。

常见 ICMP 报文类型：

| 类型 | 代码 | 名称 | 说明 |
|------|------|------|------|
| 0 | 0 | Echo Reply | 回显应答（ping 响应） |
| 3 | - | Destination Unreachable | 目标不可达 |
| 3 | 0 | Network Unreachable | 网络不可达 |
| 3 | 1 | Host Unreachable | 主机不可达 |
| 3 | 3 | Port Unreachable | 端口不可达 |
| 5 | 0 | Redirect | 重定向 |
| 8 | 0 | Echo Request | 回显请求（ping 请求） |
| 11 | 0 | Time Exceeded | 超时（TTL 归零） |

**ping 命令**：发送 ICMP Echo Request 报文，测试网络连通性。
**traceroute 命令**：利用 ICMP 超时消息，追踪数据包的路由路径。

### 6.6 路由基础

#### 6.6.1 路由表

路由器根据路由表转发数据包。路由表包含以下要素：

| 字段 | 说明 |
|------|------|
| 目标网络 | 目的网络地址和子网掩码 |
| 下一跳 | 下一个路由器的 IP 地址 |
| 出接口 | 数据包从哪个接口发出 |
| 度量值 | 路由的优先级/代价（metric） |
| 路由来源 | 直连、静态、动态路由协议 |

#### 6.6.2 路由类型

| 类型 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| **直连路由** | 路由器接口直接相连的网络 | 自动发现、优先级最高 | 仅适用于直连网络 |
| **静态路由** | 管理员手动配置的路由 | 稳定、不占用带宽 | 维护工作量大、无法自动适应拓扑变化 |
| **动态路由** | 通过路由协议自动学习的路由 | 自动适应拓扑变化 | 占用带宽和 CPU 资源 |

#### 6.6.3 动态路由协议

| 协议类型 | 代表协议 | 特点 |
|---------|---------|------|
| 距离矢量（DV） | RIP | 基于跳数，简单但收敛慢 |
| 链路状态（LS） | OSPF | 基于链路状态，收敛快，适合大型网络 |
| 路径矢量 | BGP | 基于路径属性，互联网的外部网关协议 |

### 6.7 网络层设备

#### 路由器（Router）

- 工作在网络层，连接不同的网络
- 根据 IP 地址转发数据包
- 分割广播域（每个接口是一个独立的广播域）
- 路由选择和路径计算
- 支持 NAT、ACL、VPN 等功能

#### 三层交换机

- 兼具二层交换和三层路由功能
- 通常用于局域网内部不同 VLAN 之间的路由

### 6.8 IPv6 简介

IPv6 是下一代互联网协议，解决 IPv4 地址耗尽问题。

| 特性 | IPv4 | IPv6 |
|------|------|------|
| 地址长度 | 32 位 | 128 位 |
| 地址表示 | 点分十进制 | 冒分十六进制 |
| 地址数量 | 约 43 亿 | 约 3.4×10^38 |
| 头部大小 | 20 字节（可变） | 40 字节（固定） |
| 安全性 | 可选 IPSec | 原生支持 IPSec |
| 自动配置 | DHCP 或手动 | 支持 SLAAC 自动配置 |

IPv6 地址示例：`2001:0db8:85a3:0000:0000:8a2e:0370:7334`
简化表示：`2001:db8:85a3::8a2e:370:7334`

## 第七章：传输层

### 7.1 传输层的功能

传输层为应用进程提供端到端的通信服务，是 OSI 模型中负责数据传输的最高层，也是用户功能的最低层。

主要功能：
- **端到端的通信**：在源主机和目的主机的应用进程之间提供逻辑通信
- **端口寻址**：通过端口号标识不同的应用进程
- **可靠传输**：确保数据完整、按序、无差错地到达（TCP）
- **流量控制**：控制发送速率，避免接收方溢出
- **拥塞控制**：根据网络拥塞程度调整发送速率
- **多路复用/分用**：多个应用进程共享传输层服务

### 7.2 端口

端口（Port）是传输层的地址，用于标识主机上的不同应用进程。

- **端口号范围**：0 ~ 65535（共 65536 个）
- **分类**：

| 端口范围 | 名称 | 说明 |
|---------|------|------|
| 0 ~ 1023 | 知名端口（Well-known Ports） | 分配给标准服务，需 root 权限使用 |
| 1024 ~ 49151 | 注册端口（Registered Ports） | 分配给用户进程或应用程序 |
| 49152 ~ 65535 | 动态/私有端口 | 临时端口，客户端随机使用 |

#### 常见知名端口

| 端口 | 协议 | 服务 |
|------|------|------|
| 20 | TCP | FTP 数据端口 |
| 21 | TCP | FTP 控制端口 |
| 22 | TCP | SSH |
| 23 | TCP | Telnet |
| 25 | TCP | SMTP（邮件发送） |
| 53 | UDP/TCP | DNS（域名解析） |
| 67/68 | UDP | DHCP |
| 80 | TCP | HTTP |
| 110 | TCP | POP3（邮件接收） |
| 143 | TCP | IMAP（邮件接收） |
| 161/162 | UDP | SNMP（网络管理） |
| 443 | TCP | HTTPS（HTTP over SSL/TLS） |
| 3389 | TCP | RDP（远程桌面） |
| 3306 | TCP | MySQL |
| 6379 | TCP | Redis |
| 8080 | TCP | HTTP 代理/备用 |

### 7.3 TCP 协议

TCP（Transmission Control Protocol，传输控制协议）是面向连接的、可靠的、基于字节流的传输层协议。

#### 7.3.1 TCP 特点

- **面向连接**：通信前必须先建立连接（三次握手）
- **可靠传输**：通过确认、重传、序号保证数据可靠到达
- **全双工**：同一连接上可同时双向传输数据
- **面向字节流**：数据被看作连续的字节流，不保留消息边界
- **流量控制**：滑动窗口机制防止接收方溢出
- **拥塞控制**：慢启动、拥塞避免、快重传、快恢复

#### 7.3.2 TCP 报文段头部

```
┌───────────────────────────────────────────────────────────┐
│        源端口 (16位)         │      目的端口 (16位)       │
├───────────────────────────────────────────────────────────┤
│                      序列号 (32位)                         │
├───────────────────────────────────────────────────────────┤
│                    确认号 (32位)                           │
├──────┬──────┬──────────────┬──────────────────────────────┤
│头长度│ 保留 │   标志位      │        窗口大小 (16位)       │
│(4位) │(6位) │ (6位)        │                              │
├──────┴──────┴──────────────┼──────────────────────────────┤
│      校验和 (16位)          │        紧急指针 (16位)       │
├───────────────────────────────────────────────────────────┤
│                      选项（可选）                          │
├───────────────────────────────────────────────────────────┤
│                        数据部分                             │
└───────────────────────────────────────────────────────────┘
```

**TCP 标志位**（6 位）：

| 标志位 | 名称 | 说明 |
|--------|------|------|
| URG | 紧急位 | 紧急指针有效 |
| ACK | 确认位 | 确认号有效 |
| PSH | 推送位 | 立即将数据交给应用层 |
| RST | 复位位 | 重置连接 |
| SYN | 同步位 | 建立连接时同步序号 |
| FIN | 终止位 | 释放连接 |

#### 7.3.3 TCP 三次握手（建立连接）

```
客户端                           服务器
   │                                │
   │ ──── SYN (seq=x) ────────────→ │  第1次：客户端发送 SYN
   │                                │
   │ ←── SYN+ACK (seq=y, ack=x+1) ─ │  第2次：服务器回复 SYN+ACK
   │                                │
   │ ──── ACK (ack=y+1) ──────────→ │  第3次：客户端确认
   │                                │
   │          连接建立               │
```

**为什么是三次握手而不是两次？**
- 防止已失效的连接请求报文突然传到服务器，导致服务器错误建立连接
- 双方都确认对方的发送和接收能力正常

#### 7.3.4 TCP 四次挥手（断开连接）

```
客户端                           服务器
   │                                │
   │ ──── FIN ────────────────────→ │  第1次：客户端请求关闭
   │                                │
   │ ←─── ACK ────────────────────  │  第2次：服务器确认
   │                                │
   │ ←─── FIN ────────────────────  │  第3次：服务器也请求关闭
   │                                │
   │ ──── ACK ────────────────────→ │  第4次：客户端确认
   │                                │
   │          连接关闭               │
```

**TIME_WAIT 状态**：客户端发送最后一个 ACK 后，进入 TIME_WAIT 状态，等待 2MSL（最长报文寿命）时间后才关闭。
- 确保最后一个 ACK 能到达服务器
- 防止本连接的迟到报文段影响新连接

#### 7.3.5 TCP 可靠传输机制

1. **序号与确认号**：每个字节都有序号，接收方确认已收到的字节
2. **超时重传**：发送方在超时时间内未收到确认，则重传数据
3. **滑动窗口**：接收方通告窗口大小，发送方根据窗口大小调整发送量
4. **流量控制**：通过滑动窗口防止接收方缓冲区溢出
5. **拥塞控制**：
   - 慢启动（Slow Start）：指数增长
   - 拥塞避免（Congestion Avoidance）：线性增长
   - 快重传（Fast Retransmit）：收到三个重复确认立即重传
   - 快恢复（Fast Recovery）：快重传后执行拥塞避免而非慢启动

### 7.4 UDP 协议

UDP（User Datagram Protocol，用户数据报协议）是无连接的、不可靠的传输层协议。

#### 7.4.1 UDP 特点

- **无连接**：发送数据前不需要建立连接
- **不可靠**：不保证交付、不保证按序、不保证不重复
- **面向报文**：保留应用层报文边界
- **头部开销小**：仅 8 字节
- **无拥塞控制和流量控制**：发送速率不受网络状况影响
- **支持广播和组播**

#### 7.4.2 UDP 报文头部

```
┌───────────────────────────────┐
│  源端口 (16位) │ 目的端口 (16位) │
├───────────────────────────────┤
│   长度 (16位)  │  校验和 (16位)  │
├───────────────────────────────┤
│          数据部分               │
└───────────────────────────────┘
```

#### 7.4.3 UDP 适用场景

- 对实时性要求高、可容忍少量丢包的应用
- 语音通话（VoIP）、视频会议、在线游戏
- DNS 查询、DHCP、SNMP
- 广播和组播应用

### 7.5 TCP vs UDP

| 特性 | TCP | UDP |
|------|-----|-----|
| 连接方式 | 面向连接 | 无连接 |
| 可靠性 | 可靠 | 不可靠 |
| 顺序性 | 保证按序 | 不保证顺序 |
| 传输模式 | 面向字节流 | 面向报文 |
| 头部大小 | 20~60 字节 | 8 字节 |
| 流量控制 | 有（滑动窗口） | 无 |
| 拥塞控制 | 有 | 无 |
| 速度 | 较慢 | 较快 |
| 广播/组播 | 不支持 | 支持 |
| 适用场景 | 文件传输、网页、邮件 | 视频、语音、游戏、DNS |

## 第八章：应用层

### 8.1 应用层概述

应用层是 OSI 模型的最高层，直接为用户的应用程序提供网络服务。应用层协议定义了应用进程之间通信和交互的规则。

### 8.2 Web 相关协议

#### 8.2.1 HTTP

HTTP（HyperText Transfer Protocol，超文本传输协议）是万维网的基础协议，用于 Web 浏览器和 Web 服务器之间的通信。

- **端口**：80（HTTP）
- **工作模式**：请求-响应模式（客户端请求，服务器响应）
- **特点**：无状态（每次请求独立，服务器不保存客户端状态）

**HTTP 请求方法**：

| 方法 | 说明 |
|------|------|
| GET | 请求获取指定资源 |
| POST | 向服务器提交数据（如表单提交） |
| PUT | 上传文件或更新资源 |
| DELETE | 删除指定资源 |
| HEAD | 获取响应头（不含响应体） |
| OPTIONS | 查询服务器支持的方法 |
| PATCH | 局部更新资源 |

**HTTP 状态码**：

| 状态码 | 类别 | 说明 |
|--------|------|------|
| 1xx | 信息性 | 请求已接收，继续处理 |
| 2xx | 成功 | 请求已成功处理 |
| 3xx | 重定向 | 需要进一步操作以完成请求 |
| 4xx | 客户端错误 | 请求有错误 |
| 5xx | 服务器错误 | 服务器处理请求时出错 |

常见状态码：200 OK、301 Moved Permanently、302 Found、400 Bad Request、401 Unauthorized、403 Forbidden、404 Not Found、500 Internal Server Error、502 Bad Gateway、503 Service Unavailable

#### 8.2.2 HTTPS

HTTPS（HTTP Secure）是 HTTP 的安全版本，在 HTTP 和 TCP 之间加入了 SSL/TLS 层。

- **端口**：443
- **加密方式**：对称加密 + 非对称加密 + 数字证书
- **作用**：数据加密、身份验证、完整性保护

**TLS 握手过程**：
1. 客户端发送 Client Hello（支持的加密套件、随机数）
2. 服务器回复 Server Hello（选定加密套件、随机数）+ 数字证书
3. 客户端验证证书，生成预主密钥，用服务器公钥加密后发送
4. 双方用预主密钥计算出会话密钥
5. 切换到对称加密通信

### 8.3 域名系统（DNS）

DNS（Domain Name System，域名系统）用于将易于记忆的域名转换为 IP 地址。

- **端口**：53（UDP 为主，TCP 用于区域传输和大于 512 字节的响应）
- **作用**：域名解析（正向解析）、反向解析（IP → 域名）

#### 8.3.1 域名结构

```
https://  www  .  example  .  com  .
          三级域     二级域     顶级域  根域
```

#### 8.3.2 DNS 记录类型

| 记录类型 | 说明 |
|---------|------|
| A | IPv4 地址记录 |
| AAAA | IPv6 地址记录 |
| CNAME | 别名记录（指向另一个域名） |
| MX | 邮件交换记录 |
| NS | 域名服务器记录 |
| TXT | 文本记录（常用于 SPF、DKIM） |
| PTR | 反向解析记录 |
| SOA | 起始授权记录 |

#### 8.3.3 DNS 解析过程

1. 客户端查询本地缓存
2. 若无，向本地 DNS 服务器（递归查询）
3. 本地 DNS 服务器若无缓存，则向根域名服务器查询（迭代查询）
4. 根服务器返回顶级域（TLD）服务器地址
5. 向 TLD 服务器查询，返回权威 DNS 服务器地址
6. 向权威 DNS 服务器查询，得到 IP 地址
7. 返回给客户端并缓存

#### DHCP 工作过程（DORA）

```
客户端                     DHCP服务器
   │                            │
   │ ── DHCP Discover (广播) → │  发现：寻找 DHCP 服务器
   │                            │
   │ ←── DHCP Offer ────────── │  提供：提供 IP 地址等配置
   │                            │
   │ ── DHCP Request (广播) ─→ │  请求：选择并请求某个 IP
   │                            │
   │ ←── DHCP ACK ──────────── │  确认：确认分配
   │                            │
```

## 第九章：网络设备

### 9.1 网络设备总览

| 设备 | 工作层次 | 主要功能 | 冲突域 | 广播域 |
|------|---------|---------|--------|--------|
| 中继器/集线器 | 物理层 | 信号放大/广播 | 1 个（共享） | 1 个（共享） |
| 网桥/交换机（二层） | 数据链路层 | MAC 地址转发 | 每个端口 1 个 | 1 个（共享） |
| 路由器/三层交换机 | 网络层 | IP 路由转发 | 每个端口 1 个 | 每个端口 1 个 |
| 防火墙 | 网络层/应用层 | 访问控制、安全防护 | - | - |

### 9.2 物理层设备

#### 9.2.1 中继器（Repeater）

- 功能：对衰减的信号进行放大和再生，扩展传输距离
- 特点：不识别 MAC 地址和 IP 地址，只是简单地转发比特流
- 限制：中继器不能无限级联（以太网 5-4-3 规则：5 个网段、4 个中继器、3 个可连接主机）

#### 9.2.2 集线器（Hub）

- 功能：多端口中继器，将一个端口收到的信号从其他所有端口转发出去
- 特点：
  - 共享带宽：所有端口共享总带宽
  - 半双工：同一时间只能有一个设备发送数据
  - 所有端口在同一冲突域和同一广播域
- 现状：已基本被交换机取代

### 9.3 数据链路层设备

#### 9.3.1 网桥（Bridge）

- 功能：连接两个局域网，根据 MAC 地址决定是否转发帧
- 特点：
  - 分割冲突域：每个端口是一个独立的冲突域
  - 不分割广播域：广播帧会转发到所有端口
  - 透明网桥：自动学习 MAC 地址表

#### 9.3.2 二层交换机（Layer 2 Switch）

交换机是现代局域网的核心设备，相当于多端口的网桥。

**主要功能**：
- MAC 地址学习：自动建立 MAC 地址与端口的映射表
- 帧转发/过滤：根据目的 MAC 地址精准转发
- 消除冲突：每个端口是独立的冲突域，支持全双工
- VLAN 支持：将交换机逻辑划分为多个虚拟局域网

**工作原理**：
1. 收到帧后，将源 MAC 地址和接收端口记录到 MAC 地址表（CAM 表）
2. 查询目的 MAC 地址：
   - 已知单播：向对应端口转发
   - 未知单播：向所有其他端口泛洪（广播）
   - 广播/组播：向所有其他端口泛洪
3. MAC 地址表有老化时间（默认 300 秒），过期自动删除

**VLAN（Virtual LAN，虚拟局域网）**：
- 将一台交换机逻辑上划分为多个独立的广播域
- 同一 VLAN 内的设备可以直接通信，不同 VLAN 之间需要三层设备（路由器/三层交换机）才能通信
- 优点：隔离广播域、提高安全性、灵活的网络组织
- VLAN 范围：1 ~ 4094（VLAN 1 为默认 VLAN）

### 9.4 网络层设备

#### 路由器（Router）

路由器是互联网的核心节点设备，负责在不同网络之间转发数据包。

**主要功能**：
- 路由选择：根据路由协议和路由表选择最佳路径
- 数据包转发：根据 IP 地址转发数据包
- 网络隔离：每个接口是一个独立的广播域
- 地址转换（NAT）：将私有 IP 转换为公网 IP
- 访问控制（ACL）：基于 IP/端口的数据包过滤
- VPN 支持：提供虚拟专用网络功能

**路由表**：路由器维护的路由信息表，包含目的网络、下一跳、出接口、度量值等。

**路由来源**：
- 直连路由：路由器接口直接相连的网络，自动发现
- 静态路由：管理员手动配置
- 动态路由：通过路由协议（RIP、OSPF、BGP 等）自动学习

#### 三层交换机（Layer 3 Switch）

- 兼具二层交换和三层路由功能
- 通常用于局域网内部的 VLAN 间路由
- 相比路由器，转发速度更快（硬件转发）
- 功能相对路由器简单（NAT、VPN 等支持较少）

### 9.5 防火墙

防火墙是网络安全设备，用于控制不同安全区域之间的网络访问。

**分类**：
- **按技术分类**：
  - 包过滤防火墙：基于 IP/端口过滤（网络层）
  - 状态检测防火墙：跟踪连接状态（主流技术）
  - 应用层防火墙/代理：深入检查应用层数据
  - 下一代防火墙（NGFW）：集成 IPS、应用识别、URL 过滤等

- **按形态分类**：
  - 硬件防火墙：专用硬件设备，性能高
  - 软件防火墙：安装在操作系统上，如 Windows 防火墙、iptables

**核心功能**：
- 访问控制策略（允许/拒绝）
- NAT 地址转换
- VPN 远程接入
- 入侵防御（IPS）
- 应用识别与控制

|------|------|
| **无线 AP** | 提供无线网络接入点 |
| **无线控制器（AC）** | 统一管理多个瘦 AP |
| **负载均衡器** | 将流量分发到多台服务器 |
| **IDS/IPS** | 入侵检测系统/入侵防御系统 |

## 第十章：网络安全基础

### 10.1 网络安全概述

网络安全是指保护网络系统的硬件、软件及其系统中的数据不因偶然或恶意的原因而遭到破坏、更改、泄露，保证系统连续可靠正常地运行，网络服务不中断。

#### 网络安全三要素（CIA 三元组）

| 要素 | 英文 | 说明 |
|------|------|------|
| **机密性** | Confidentiality | 确保信息不被未授权的人访问 |
| **完整性** | Integrity | 确保信息在传输和存储过程中不被篡改 |
| **可用性** | Availability | 确保授权用户可以正常访问和使用资源 |

#### 网络安全威胁

| 威胁类型 | 说明 | 典型示例 |
|---------|------|---------|
| **窃听** | 非法获取通信内容 | 网络嗅探、密码截获 |
| **篡改** | 修改传输中的数据 | 中间人攻击、数据篡改 |
| **伪造** | 冒充合法身份通信 | IP 欺骗、MAC 欺骗 |
| **拒绝服务** | 使目标无法提供正常服务 | DDoS 攻击 |
| **越权访问** | 访问未授权的资源 | 提权攻击、水平越权 |
| **恶意代码** | 植入恶意软件 | 病毒、木马、蠕虫、勒索软件 |
| **社会工程学** | 利用人的弱点攻击 | 钓鱼邮件、电话诈骗 |

### 10.2 常见网络攻击类型

#### 10.2.1 网络层攻击

| 攻击类型 | 说明 |
|---------|------|
| **IP 欺骗（IP Spoofing）** | 伪造源 IP 地址，隐藏真实身份或冒充他人 |
| **ARP 欺骗（ARP Spoofing）** | 伪造 ARP 响应，实现中间人攻击 |
| **ICMP 洪水（Smurf 攻击）** | 利用 ICMP 回显请求发动 DDoS |
| **死亡之 Ping** | 发送超大的 ICMP 数据包导致系统崩溃 |
| **泪滴攻击（Teardrop）** | 发送重叠的分片导致系统处理异常 |

#### 10.2.2 传输层攻击

| 攻击类型 | 说明 |
|---------|------|
| **SYN 洪水** | 大量伪造源 IP 的 SYN 包耗尽服务器半连接资源 |
| **UDP 洪水** | 大量 UDP 包占满带宽和处理能力 |
| **端口扫描** | 扫描目标开放的端口，发现服务和漏洞 |
| **会话劫持** | 窃取已建立的 TCP 会话 |

#### 10.2.3 应用层攻击

| 攻击类型 | 说明 |
|---------|------|
| **SQL 注入** | 在输入中注入 SQL 语句，操纵数据库 |
| **XSS（跨站脚本）** | 在网页中注入恶意脚本 |
| **CSRF（跨站请求伪造）** | 利用用户已登录身份执行非预期操作 |
| **文件上传漏洞** | 上传恶意文件（如 Webshell） |
| **命令注入** | 通过输入执行系统命令 |
| **DNS 劫持** | 篡改 DNS 解析结果，跳转到恶意网站 |
| **HTTP 洪水（CC 攻击）** | 大量 HTTP 请求耗尽服务器资源 |

### 10.3 网络安全防护技术

#### 10.3.1 加密技术

- **对称加密**：加密和解密使用相同密钥（DES、AES、3DES）
- **非对称加密**：使用公钥和私钥一对密钥（RSA、ECC）
- **哈希算法**：单向不可逆，用于完整性校验（MD5、SHA-1、SHA-256）
- **数字签名**：私钥签名、公钥验证，保证身份和完整性
- **数字证书**：由 CA 签发，证明公钥的合法性

#### 10.3.2 身份认证

- **密码认证**：最常见的认证方式
- **多因素认证（MFA）**：两种或以上认证方式组合（密码 + 短信 / 密码 + 令牌）
- **生物识别**：指纹、人脸、虹膜等
- **证书认证**：基于数字证书的双向认证
- **单点登录（SSO）**：一次登录，访问多个系统

#### 10.3.3 访问控制

- **ACL（访问控制列表）**：基于 IP/端口的数据包过滤
- **防火墙**：网络边界的访问控制
- **VLAN 隔离**：二层网络隔离
- **零信任架构**：永不信任，始终验证

#### 10.3.4 入侵检测与防御

- **IDS（入侵检测系统）**：监控网络流量，发现攻击行为并告警
- **IPS（入侵防御系统）**：在 IDS 基础上增加阻断功能
- **WAF（Web 应用防火墙）**：针对 HTTP/HTTPS 的应用层防护

### 10.4 VPN（虚拟专用网络）

VPN 通过公共网络（如互联网）建立安全的加密通道，实现远程安全访问。

**分类**：
- **IPsec VPN**：网络层 VPN，适用于站点到站点连接
- **SSL VPN**：应用层 VPN，适用于远程用户接入
- **PPTP / L2TP**：较早的 VPN 协议，安全性较低

**优点**：
- 数据加密传输，防止窃听
- 身份认证，防止未授权访问
- 数据完整性保护
- 远程安全办公

### 10.5 网络安全最佳实践

- 定期更新系统和软件补丁
- 使用强密码并定期更换，启用多因素认证
- 最小权限原则：只授予必要的权限
- 安装防火墙和杀毒软件
- 定期备份重要数据
- 关闭不必要的服务和端口
- 对重要数据进行加密
- 网络分段和隔离
- 安全审计和日志监控
- 员工安全意识培训

## 第十一章：网络排查与工具

### 11.1 网络故障排查思路

网络故障排查通常遵循分层排查的原则，从物理层到应用层，逐层定位问题。

```
物理层 → 数据链路层 → 网络层 → 传输层 → 应用层
  （从底层到高层，逐层排除）
```

**排查步骤**：
1. **确认故障现象**：具体什么问题？影响范围？何时开始？
2. **检查物理层**：网线是否插好？指示灯状态？光纤功率？
3. **检查数据链路层**：网卡是否正常？MAC 地址学习？VLAN 配置？
4. **检查网络层**：IP 地址是否正确？能否 ping 通网关？路由是否正常？
5. **检查传输层**：端口是否开放？能否建立 TCP 连接？
6. **检查应用层**：服务是否正常运行？配置是否正确？

### 11.2 常用网络命令

#### 11.2.1 连通性测试

| 命令 | 说明 | 示例 |

| `traceroute` / `tracert` | 追踪数据包路径 | `traceroute google.com` |

| `ip route` / `route` | 查看路由表 | `ip route show`；`route -n` |
| `netstat` / `ss` | 查看网络连接和端口 | `netstat -tulnp`；`ss -tulnp` |
| `hostname` | 查看/设置主机名 | `hostname`；`hostname -I` |

### 11.3 常见故障排查案例

#### 11.3.1 无法上网

1. 检查网卡指示灯是否亮 → 物理层问题
2. 检查 IP 地址是否正确（`ip addr`）→ 配置问题
3. ping 网关 → 内网连通性
4. ping 公网 IP（如 8.8.8.8）→ 路由问题
5. ping 域名 → DNS 问题
6. 检查防火墙规则 → 访问控制问题

#### 11.3.2 端口不通

1. 确认服务是否启动 → 服务端问题
2. 检查服务是否在正确端口监听（`netstat -tulnp`）→ 配置问题
3. 从本机测试端口（`nc -zv 127.0.0.1 端口`）→ 本机服务
4. 检查防火墙（iptables/ufw/安全组）→ 访问控制
5. 检查网络连通性 → 网络问题

#### 11.3.3 网速慢

1. 测试带宽（iperf/speedtest）→ 带宽瓶颈
2. 检查延迟（ping/mtr）→ 网络质量
3. 检查丢包 → 网络拥塞或故障
4. 检查设备负载（CPU/内存）→ 设备性能
5. 抓包分析（tcpdump/wireshark）→ 协议层面分析

### 11.4 Wireshark 使用基础

Wireshark 是最流行的网络协议分析工具，可用于：
- 网络故障排查
- 协议学习和分析
- 安全分析和取证

**常用过滤表达式**：

| 过滤表达式 | 说明 |
|-----------|------|
| `ip.addr == 192.168.1.1` | 显示与指定 IP 相关的数据包 |
| `tcp.port == 80` | 显示 TCP 80 端口的数据包 |
| `http` | 只显示 HTTP 协议数据包 |
| `icmp` | 只显示 ICMP 数据包 |
| `ip.src == 192.168.1.100` | 源 IP 为指定地址的包 |
| `tcp.flags.syn == 1` | 只显示 SYN 包 |
| `dns` | 只显示 DNS 查询 |
| `arp` | 只显示 ARP 包 |

## 总结

计算机网络是信息安全的基础。从物理层的比特传输，到数据链路层的帧交换、网络层的路由转发、传输层的端到端通信，再到应用层的各类服务，每一层都有其独特的协议和安全挑战。

**关键要点回顾**：

1. OSI 七层模型和 TCP/IP 模型是理解网络的基础框架，分层设计使复杂问题简单化。
2. 各层核心协议：物理层（传输介质）→ 数据链路层（Ethernet、ARP、交换机）→ 网络层（IP、ICMP、路由器）→ 传输层（TCP、UDP）→ 应用层（HTTP、DNS、SSH 等）。
3. 网络安全涉及机密性、完整性、可用性三要素，攻击手段层出不穷，防护需多层纵深防御。
4. 掌握网络排查工具和方法，是安全从业者的必备技能。
