# 第七章：传输层

### 7.1 传输层的功能

传输层为应用进程提供端到端的通信服务，是 OSI 模型中负责数据传输的最高层，也是用户功能的最低层。

主要功能：
- **端到端的通信**：在源主机和目的主机的应用进程之间提供逻辑通信
- **端口寻址**：通过端口号标识不同的应用进程
- **可靠传输**：确保数据完整、按序、无差错地到达（TCP）
- **流量控制**：控制发送速率，避免接收方溢出
- **拥塞控制**：根据网络拥塞程度调整发送速率
- **多路复用/分用**：多个应用进程共享传输层服务

### 7.2 端口

端口（Port）是传输层的地址，用于标识主机上的不同应用进程。

- **端口号范围**：0 ~ 65535（共 65536 个）
- **分类**：

| 端口范围 | 名称 | 说明 |
|---------|------|------|
| 0 ~ 1023 | 知名端口（Well-known Ports） | 分配给标准服务，需 root 权限使用 |
| 1024 ~ 49151 | 注册端口（Registered Ports） | 分配给用户进程或应用程序 |
| 49152 ~ 65535 | 动态/私有端口 | 临时端口，客户端随机使用 |

#### 常见知名端口

| 端口 | 协议 | 服务 |
|------|------|------|
| 20 | TCP | FTP 数据端口 |
| 21 | TCP | FTP 控制端口 |
| 22 | TCP | SSH |
| 23 | TCP | Telnet |
| 25 | TCP | SMTP（邮件发送） |
| 53 | UDP/TCP | DNS（域名解析） |
| 67/68 | UDP | DHCP |
| 80 | TCP | HTTP |
| 110 | TCP | POP3（邮件接收） |
| 143 | TCP | IMAP（邮件接收） |
| 161/162 | UDP | SNMP（网络管理） |
| 443 | TCP | HTTPS（HTTP over SSL/TLS） |
| 3389 | TCP | RDP（远程桌面） |
| 3306 | TCP | MySQL |
| 6379 | TCP | Redis |
| 8080 | TCP | HTTP 代理/备用 |

### 7.3 TCP 协议

TCP（Transmission Control Protocol，传输控制协议）是面向连接的、可靠的、基于字节流的传输层协议。

#### 7.3.1 TCP 特点

- **面向连接**：通信前必须先建立连接（三次握手）
- **可靠传输**：通过确认、重传、序号保证数据可靠到达
- **全双工**：同一连接上可同时双向传输数据
- **面向字节流**：数据被看作连续的字节流，不保留消息边界
- **流量控制**：滑动窗口机制防止接收方溢出
- **拥塞控制**：慢启动、拥塞避免、快重传、快恢复

#### 7.3.2 TCP 报文段头部

```
┌───────────────────────────────────────────────────────────┐
│        源端口 (16位)         │      目的端口 (16位)       │
├───────────────────────────────────────────────────────────┤
│                      序列号 (32位)                         │
├───────────────────────────────────────────────────────────┤
│                    确认号 (32位)                           │
├──────┬──────┬──────────────┬──────────────────────────────┤
│头长度│ 保留 │   标志位      │        窗口大小 (16位)       │
│(4位) │(6位) │ (6位)        │                              │
├──────┴──────┴──────────────┼──────────────────────────────┤
│      校验和 (16位)          │        紧急指针 (16位)       │
├───────────────────────────────────────────────────────────┤
│                      选项（可选）                          │
├───────────────────────────────────────────────────────────┤
│                        数据部分                             │
└───────────────────────────────────────────────────────────┘
```

**TCP 标志位**（6 位）：

| 标志位 | 名称 | 说明 |
|--------|------|------|
| URG | 紧急位 | 紧急指针有效 |
| ACK | 确认位 | 确认号有效 |
| PSH | 推送位 | 立即将数据交给应用层 |
| RST | 复位位 | 重置连接 |
| SYN | 同步位 | 建立连接时同步序号 |
| FIN | 终止位 | 释放连接 |

#### 7.3.3 TCP 三次握手（建立连接）

```
客户端                           服务器
   │                                │
   │ ──── SYN (seq=x) ────────────→ │  第1次：客户端发送 SYN
   │                                │
   │ ←── SYN+ACK (seq=y, ack=x+1) ─ │  第2次：服务器回复 SYN+ACK
   │                                │
   │ ──── ACK (ack=y+1) ──────────→ │  第3次：客户端确认
   │                                │
   │          连接建立               │
```

**为什么是三次握手而不是两次？**
- 防止已失效的连接请求报文突然传到服务器，导致服务器错误建立连接
- 双方都确认对方的发送和接收能力正常

#### 7.3.4 TCP 四次挥手（断开连接）

```
客户端                           服务器
   │                                │
   │ ──── FIN ────────────────────→ │  第1次：客户端请求关闭
   │                                │
   │ ←─── ACK ────────────────────  │  第2次：服务器确认
   │                                │
   │ ←─── FIN ────────────────────  │  第3次：服务器也请求关闭
   │                                │
   │ ──── ACK ────────────────────→ │  第4次：客户端确认
   │                                │
   │          连接关闭               │
```

**TIME_WAIT 状态**：客户端发送最后一个 ACK 后，进入 TIME_WAIT 状态，等待 2MSL（最长报文寿命）时间后才关闭。
- 确保最后一个 ACK 能到达服务器
- 防止本连接的迟到报文段影响新连接

#### 7.3.5 TCP 可靠传输机制

1. **序号与确认号**：每个字节都有序号，接收方确认已收到的字节
2. **超时重传**：发送方在超时时间内未收到确认，则重传数据
3. **滑动窗口**：接收方通告窗口大小，发送方根据窗口大小调整发送量
4. **流量控制**：通过滑动窗口防止接收方缓冲区溢出
5. **拥塞控制**：
   - 慢启动（Slow Start）：指数增长
   - 拥塞避免（Congestion Avoidance）：线性增长
   - 快重传（Fast Retransmit）：收到三个重复确认立即重传
   - 快恢复（Fast Recovery）：快重传后执行拥塞避免而非慢启动

### 7.4 UDP 协议

UDP（User Datagram Protocol，用户数据报协议）是无连接的、不可靠的传输层协议。

#### 7.4.1 UDP 特点

- **无连接**：发送数据前不需要建立连接
- **不可靠**：不保证交付、不保证按序、不保证不重复
- **面向报文**：保留应用层报文边界
- **头部开销小**：仅 8 字节
- **无拥塞控制和流量控制**：发送速率不受网络状况影响
- **支持广播和组播**

#### 7.4.2 UDP 报文头部

```
┌───────────────────────────────┐
│  源端口 (16位) │ 目的端口 (16位) │
├───────────────────────────────┤
│   长度 (16位)  │  校验和 (16位)  │
├───────────────────────────────┤
│          数据部分               │
└───────────────────────────────┘
```

#### 7.4.3 UDP 适用场景

- 对实时性要求高、可容忍少量丢包的应用
- 语音通话（VoIP）、视频会议、在线游戏
- DNS 查询、DHCP、SNMP
- 广播和组播应用

### 7.5 TCP vs UDP

| 特性 | TCP | UDP |
|------|-----|-----|
| 连接方式 | 面向连接 | 无连接 |
| 可靠性 | 可靠 | 不可靠 |
| 顺序性 | 保证按序 | 不保证顺序 |
| 传输模式 | 面向字节流 | 面向报文 |
| 头部大小 | 20~60 字节 | 8 字节 |
| 流量控制 | 有（滑动窗口） | 无 |
| 拥塞控制 | 有 | 无 |
| 速度 | 较慢 | 较快 |
| 广播/组播 | 不支持 | 支持 |
| 适用场景 | 文件传输、网页、邮件 | 视频、语音、游戏、DNS |
