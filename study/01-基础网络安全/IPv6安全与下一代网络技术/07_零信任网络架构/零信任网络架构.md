# 零信任网络架构

### 7.1 BeyondCorp模型

BeyondCorp是Google提出的零信任安全模型，核心理念是"从不信任，始终验证"（Never trust, always verify）。它取消了传统VPN的内网信任假设，将所有访问请求都进行身份验证和授权。

**BeyondCorp核心组件：**

```
BeyondCorp架构：

┌────────────────────────────────────────────────────────────┐
│                     用户设备                                  │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐       │
│  │ 信任代理客户端│  │ 设备证书     │  │ MFA Token   │       │
│  └─────────────┘  └─────────────┘  └─────────────┘       │
└────────────────────────┬───────────────────────────────────┘
                         │
                    访问请求
                         │
┌────────────────────────▼───────────────────────────────────┐
│                  访问代理（Access Proxy）                    │
│  ┌────────────────────────────────────────────────────────┐ │
│  │  身份认证 → 设备验证 → 授权决策 → 访问代理              │ │
│  └────────────────────────────────────────────────────────┘ │
└────────────────────────┬───────────────────────────────────┘
                         │
┌────────────────────────▼───────────────────────────────────┐
│                    企业应用                                   │
│  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐             │
│  │ Web应用│ │ API服务│ │数据库   │ │内部工具 │             │
│  └────────┘ └────────┘ └────────┘ └────────┘             │
└────────────────────────────────────────────────────────────┘
```

**BeyondCorp访问决策流程：**

```
用户请求访问应用
    │
    v
1. 身份验证（用户是谁？）
    - SSO/MFA认证
    - 用户身份令牌
    │
    v
2. 设备验证（用什么设备？）
    - 设备证书验证
    - 设备合规性检查
    - 设备信任等级
    │
    v
3. 访问策略评估（允许访问吗？）
    - 用户角色/组
    - 设备信任等级
    - 请求上下文（时间/位置/行为）
    - 应用敏感级别
    │
    v
4. 授权决策
    - ALLOW: 允许访问
    - DENY: 拒绝访问
    - STEP_UP: 需要额外认证（如MFA）
    - QUARANTINE: 隔离访问
    │
    v
5. 访问代理
    - 建立加密通道
    - 应用级访问（非网络级）
    - 持续监控
```

### 7.2 微隔离

微隔离（Micro-segmentation）是在数据中心内部实现细粒度网络隔离的技术，将安全策略细化到工作负载/虚拟机级别。

**微隔离与传统隔离对比：**

```
传统隔离（网络级）：
┌──────────────────────────────────────┐
│              DMZ区                    │
│  ┌────┐ ┌────┐ ┌────┐                │
│  │Web1│ │Web2│ │Web3│                │
│  └────┘ └────┘ └────┘                │
└──────────┬───────────────────────────┘
           │ 防火墙规则（粗粒度）
┌──────────▼───────────────────────────┐
│              内网区                    │
│  ┌────┐ ┌────┐ ┌────┐                │
│  │App1│ │App2│ │DB  │                │
│  └────┘ └────┘ └────┘                │
└──────────────────────────────────────┘

微隔离（工作负载级）：
┌──────────────────────────────────────┐
│  Web1 ──→ App1 ──→ DB1               │
│    ↕      ↕        ↕                │
│  Web2 ──x─→ App2  DB2                │
│    ↕      ↕        ╳                 │
│  Web3    App3    DB3                 │
│  （每条线都有独立策略，App2不能直接    │
│   访问DB2，Web2不能直接访问App1）     │
└──────────────────────────────────────┘
```

**VMware NSX微隔离配置：**

```
# NSX分布式防火墙策略

# 1. 定义安全组
security-group WebTier {
    membership_criteria {
        tag: "app=web"
        tag: "env=prod"
    }
}

security-group AppTier {
    membership_criteria {
        tag: "app=application"
        tag: "env=prod"
    }
}

security-group DBTier {
    membership_criteria {
        tag: "app=database"
        tag: "env=prod"
    }
}

# 2. 定义防火墙策略
distributed-firewall {
    # Web层到App层：只允许HTTP
    rule 1 {
        source: WebTier
        destination: AppTier
        service: "TCP/8080"
        action: ALLOW
        log: true
    }

    # App层到DB层：只允许SQL
    rule 2 {
        source: AppTier
        destination: DBTier
        service: "TCP/3306"
        action: ALLOW
        log: true
    }

    # 禁止Web层直接访问DB层
    rule 3 {
        source: WebTier
        destination: DBTier
        service: ANY
        action: DROP
        log: true
    }

    # 默认拒绝
    rule 999 {
        source: ANY
        destination: ANY
        service: ANY
        action: DROP
        log: true
    }
}
```

### 7.3 软件定义边界SDP

SDP（Software-Defined Perimeter）是云安全联盟（CSA）提出的零信任实现框架，通过动态创建一对一网络连接来隐藏基础设施。

**SDP架构：**

```
SDP组件：
┌──────────┐         ┌──────────┐         ┌──────────┐
│ SDP Client│ ←SPA→ │ SDP     │         │ SDP     │
│ (Initiator│ ←──→ │ Controller│ ←──→ │ Gateway  │
│  IH)      │       │ (CA)    │         │ (SH)    │
└──────────┘       └──────────┘         └──────────┘
                                               │
                                    ┌──────────┴──────────┐
                                    │   保护的服务          │
                                    └─────────────────────┘

SDP连接流程：
1. 客户端发送SPA（Single Packet Authorization）包给控制器
2. 控制器验证SPA包，如通过则响应认证挑战
3. 客户端完成MFA认证
4. 控制器通知网关允许该客户端连接
5. 网关为客户端创建到目标服务的隧道
6. 所有流量经过加密隧道，服务对未认证用户完全不可见
```

**SDP关键特性：**

1. **默认拒绝（Default Deny）**：所有服务默认不可见
2. **单包授权（SPA）**：使用一次性令牌，防止重放和扫描
3. **动态授权**：基于身份、设备、上下文的实时决策
4. **应用级访问**：不提供网络层访问，仅暴露特定应用
