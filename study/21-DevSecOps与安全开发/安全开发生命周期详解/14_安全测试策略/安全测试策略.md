# 安全测试策略

### 6.1 SAST 集成策略

**多工具组合策略**
```yaml
# SAST 集成策略
sast_pipeline:
  # 第一层：快速反馈 - 预提交钩子
  pre_commit:
    tool: semgrep
    rules: [p/owasp-top-ten, p/security-audit]
    fail_fast: true

  # 第二层：构建阶段 - 全量扫描
  build_stage:
    - tool: sonarqube
      config: sonar-project.properties
      quality_gate: true
    - tool: bandit  # Python 专用
      severity: [HIGH, CRITICAL]
    - tool: eslint-security  # JS 专用
      severity: [HIGH, CRITICAL]

  # 第三层：深度分析 - 定期全量
  scheduled:
    tool: fortify
    schedule: weekly
    full_scan: true
```

### 6.2 DAST 集成策略

**DAST 扫描策略**
```yaml
dast_pipeline:
  # 测试环境扫描
  staging_scan:
    tool: owasp_zap
    target: https://staging.app.example.com
    scan_type: active
    schedule: every_deploy

  # 生产环境被动扫描
  production_monitor:
    tool: owasp_zap
    target: https://app.example.com
    scan_type: passive
    schedule: daily

  # Nuclei 漏洞验证
  nuclei_scan:
    tool: nuclei
    templates: [cves, exposures, misconfiguration]
    schedule: daily
```

### 6.3 IAST 集成策略

**IAST 在功能测试中运行**
```yaml
iast_integration:
  # 在自动化测试中启用 IAST
  test_stage:
    tool: openrasp_iast
    agent: java-agent.jar
    inject: functional_tests
    report: real_time

  # 在集成测试中启用 IAST
  integration_test:
    tool: contrast_security
    agent: contrast-agent.jar
    coverage: api_endpoints
    report: dashboard
```

### 6.4 测试覆盖率
**安全测试覆盖率指标**
- 代码覆盖率：被安全扫描覆盖的代码比例
- API 覆盖率：被测试的 API 端点比例
- 数据流覆盖率：被污点分析覆盖的数据流比例
- 认证覆盖率：被测试的认证路径比例
- 授权覆盖率：被测试的权限矩阵比例
