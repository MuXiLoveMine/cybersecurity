# 安全设计原则

### 4.1 最小权限原则
**设计要点**
- 每个组件只授予完成其功能所需的最小权限
- 权限按需分配而非默认最大化
- 定期审查权限配置
- 使用 RBAC 精确控制

**实现示例**
```yaml
# Kubernetes RBAC 最小权限配置
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  namespace: production
  name: app-reader
rules:
# 只授予读取 Pod 的权限，不授予其他权限
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["get", "list", "watch"]
# 不授予 create/update/delete 权限
```

### 4.3 失效安全原则
**设计要点**
- 系统故障时进入安全状态（默认拒绝）
- 异常情况下拒绝访问而非允许
- 错误处理不暴露敏感信息
- 超时断开而非保持连接

**代码示例**
```python
# 失效安全：默认拒绝
def check_permission(user, resource, action):
    """权限检查 - 失败安全设计"""
    try:
        # 检查权限规则
        if has_explicit_permission(user, resource, action):
            return True
        # 默认拒绝
        return False
    except Exception as e:
        # 异常时默认拒绝（安全失败）
        log_error(f"权限检查异常: {e}")
        return False

# 危险做法：默认允许
def check_permission_insecure(user, resource, action):
    try:
        rules = load_permission_rules(user)
        return action not in rules.get('denied', [])
    except Exception:
        # 异常时默认允许（不安全！）
        return True
```

### 4.4 经济性原则
**设计要点**
- 用最简单的方式满足安全需求
- 减少不必要的复杂度
- 复杂度增加攻击面
- 可审计可验证
