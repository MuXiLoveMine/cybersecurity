# 安全编码概述

### 1.1 安全编码的重要性

```
漏洞修复成本随生命周期指数级增长：

需求阶段修复     ●           成本 1x
设计阶段修复     ●●          成本 5x
编码阶段修复     ●●●         成本 10x
测试阶段修复     ●●●●●       成本 50x
生产阶段修复     ●●●●●●●●●   成本 200x
```

安全编码在编码阶段消除 70% 以上的常见漏洞，是成本最低、效果最好的安全投入。

### 1.2 OWASP Secure Coding Practices 核心原则

- **输入验证**：所有外部输入均不可信，必须验证
- **输出编码**：数据输出到不同上下文时需相应编码
- **最小权限**：代码以最小权限运行
- **默认安全**：默认配置应为最安全状态
- **纵深防御**：多层防护，不依赖单一控制
- **失败安全**：异常时进入安全状态而非开放状态

### 1.3 安全编码与业务目标的平衡

安全编码不是追求绝对安全，而是在风险、成本、体验之间取得平衡：

```
安全 ←──────────────────────→ 敏捷
高管控                          低延迟
严格验证  ←── 平衡点 ──→  体验优先
深度防御                       快速迭代
```

**实践原则**：高危路径（支付、认证、权限）严格安全编码，低危路径适度安全投入。
