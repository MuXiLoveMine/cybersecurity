# 第10章 防御与加固建议

### 10.1 控制平面加固

**API Server安全：**
- 禁用匿名认证：`--anonymous-auth=false`
- 启用TLS双向认证
- 配置合理的RBAC策略
- 启用审计日志
- 限制API Server的网络访问
- 定期轮换证书

**etcd安全：**
- 启用TLS认证和加密
- 配置防火墙限制etcd端口访问
- 启用etcd客户端证书认证
- 定期备份etcd数据并加密
- 监控etcd的访问日志

**控制平面组件：**
- 禁用控制器管理器的不安全端口
- 禁用调度器的不安全端口
- 确保所有组件间通信使用TLS
- 控制平面节点最小化安装软件

### 10.2 节点与工作负载加固

**kubelet安全：**
- 禁用匿名认证：`--anonymous-auth=false`
- 禁用只读端口：`--read-only-port=0`
- 启用Webhook授权模式
- 配置证书轮换
- 限制kubelet端口的网络访问

**Pod安全标准（PSA）：**
- Privileged：完全无限制（不推荐）
- Baseline：基本安全限制（最小特权）
- Restricted：严格限制（最佳实践）

**Restricted策略限制项：**
- 禁止特权模式
- 禁止以root用户运行
- 禁止hostPath挂载
- 禁止hostNetwork和hostPID
- 限制Linux Capabilities
- 强制只读根文件系统
- 强制Seccomp Profile

**容器镜像安全：**
- 使用可信的基础镜像
- 定期扫描镜像漏洞
- 最小化镜像（使用distroless镜像）
- 启用镜像签名验证
- 使用私有镜像仓库并配置认证

### 10.3 网络安全加固

**网络策略（NetworkPolicy）：**
```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-all
  namespace: production
spec:
  podSelector: {}
  policyTypes:
  - Ingress
  - Egress
---
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-app-db
  namespace: production
spec:
  podSelector:
    matchLabels:
      app: database
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: frontend
    ports:
    - protocol: TCP
      port: 5432
```

**服务网格（Service Mesh）：**
- 启用mTLS加密东西向流量
- 实现细粒度的服务访问控制
- 流量可视化和审计
- 推荐方案：Istio、Linkerd

### 10.4 身份与访问管理

**RBAC最佳实践：**
- 遵循最小权限原则
- 使用命名空间隔离不同团队/环境
- 优先使用Role而非ClusterRole
- 定期审计RBAC配置
- 避免使用通配符权限
- 禁用默认ServiceAccount的自动挂载

**ServiceAccount安全：**
```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: myapp-sa
  namespace: production
automountServiceAccountToken: false  # 禁用自动挂载
```

**多因素认证：**
- 管理员账户强制MFA
- 使用OIDC集成企业身份提供商
- 定期审计用户访问权限

### 10.5 监控与审计

**审计日志：**
- 启用API Server审计日志
- 审计日志集中存储和分析
- 配置告警规则检测异常行为
- 审计日志保留期限符合合规要求

**运行时安全监控：**
- 部署Falco等运行时检测工具
- 监控异常进程、文件访问、网络连接
- 容器行为基线学习
- 实时告警和响应

**安全事件响应：**
- 建立K8s安全事件响应流程
- 定期进行应急响应演练
- 维护事件响应手册
- 与SIEM系统集成
