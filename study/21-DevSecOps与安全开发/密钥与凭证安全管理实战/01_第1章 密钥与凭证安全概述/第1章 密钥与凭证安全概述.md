# 第1章 密钥与凭证安全概述

### 1.1 密钥与凭证的定义与分类

#### 1.1.1 基本定义

在现代IT系统中，密钥（Key）和凭证（Credential）是身份认证与数据保护的核心基石。理解它们的定义与分类是建立安全管理体系的第一步。

**密钥（Key）**：密钥是密码学运算中的关键参数，用于加密、解密、签名、验证等操作。密钥本身是一串随机或伪随机的二进制数据，其安全性直接决定了密码系统的安全强度。

**凭证（Credential）**：凭证是用于证明身份或获取访问权限的信息载体。凭证的范围比密钥更广，包括密码、API密钥、令牌、证书、生物特征信息等。

#### 1.1.2 密钥的分类

根据密码学体制分类：

| 类别 | 典型算法 | 密钥长度 | 主要用途 |
|------|----------|----------|----------|
| 对称密钥 | AES、DES、3DES、SM4 | 128/256位 | 数据加密、磁盘加密、通信加密 |
| 非对称密钥 | RSA、ECC、SM2 | 2048/4096位(RSA)、256位(ECC) | 身份认证、数字签名、密钥交换 |
| 哈希密钥 | HMAC-SHA256 | 可变 | 消息认证、完整性校验 |

根据密钥功能分类：

- **数据加密密钥（DEK）**：直接用于加密用户数据的密钥
- **密钥加密密钥（KEK）**：用于加密保护其他密钥的密钥
- **主密钥（Master Key）**：密钥层次结构的根密钥，保护整个密钥体系
- **会话密钥（Session Key）**：单次通信会话中临时使用的密钥
- **签名密钥（Signing Key）**：用于数字签名的私钥
- **验证密钥（Verification Key）**：用于验证数字签名的公钥

#### 1.1.3 凭证的分类

按凭证形态分类：

1. **知识类凭证**：密码、PIN码、安全问题答案
2. **持有类凭证**：智能卡、USB Key、硬件令牌
3. **生物特征凭证**：指纹、面部识别、虹膜扫描
4. **数字凭证**：API密钥、访问令牌、数字证书、SSH密钥

按使用场景分类：

- **用户凭证**：用户名密码、多因素认证因子
- **服务凭证**：API密钥、服务账户密码、数据库连接串
- **机器凭证**：SSH密钥、TLS证书、服务账户令牌
- **基础设施凭证**：云平台访问密钥、K8s Secret、CI/CD令牌

### 1.2 凭证泄露的风险与影响

#### 1.2.1 凭证泄露的典型场景

凭证泄露是企业安全事件中最常见也是最危险的类型之一。根据Verizon DBIR 2024报告，超过80%的数据泄露事件与凭证被盗或滥用有关。

**常见泄露场景：**

1. **硬编码凭证**：开发者将API密钥、数据库密码直接写入源代码
2. **配置文件泄露**：敏感配置文件（如.env、application.yml）被意外提交到代码仓库
3. **日志泄露**：应用日志中打印了完整的请求头、连接字符串等敏感信息
4. **内存dump泄露**：进程内存转储文件中包含明文凭证
5. **供应链攻击**：第三方依赖库或服务中的凭证泄露
6. **社交工程**：钓鱼邮件、假冒网站骗取用户凭证
7. **内部人员泄露**：离职员工带走敏感凭证，或内部人员恶意窃取

#### 1.2.2 凭证泄露的危害等级

| 泄露凭证类型 | 影响范围 | 潜在损失 | 紧急程度 |
|-------------|----------|----------|----------|
| 管理员密码 | 系统全量访问 | 极高 | P0 |
| 云平台AK/SK | 云资源全量控制 | 极高 | P0 |
| 数据库密码 | 数据泄露/篡改 | 高 | P1 |
| API密钥 | 服务滥用、数据泄露 | 高 | P1 |
| SSH私钥 | 服务器接管 | 高 | P1 |
| 普通用户密码 | 账户被盗 | 中 | P2 |
| 内部服务令牌 | 横向移动风险 | 中 | P2 |

#### 1.2.3 真实案例警示

**案例：2022年Uber数据泄露事件**

攻击者通过社交工程手段获取了Uber员工的Slack账户凭证，进而在Slack消息历史中发现了AWS访问密钥。利用这些密钥，攻击者访问了Uber的AWS环境，窃取了约5700万用户和司机的个人信息，最终Uber支付了1.48亿美元的和解金。

**案例：2023年Okta支持系统入侵事件**

攻击者通过窃取Okta客户支持团队员工的凭证，访问了Okta的支持案例管理系统，导致包括Cloudflare、1Password在内的多家知名企业客户数据被泄露。事件影响了超过134家Okta客户。

### 1.3 密钥管理生命周期

#### 1.3.1 生命周期模型

密钥管理遵循完整的生命周期管理模型，涵盖从生成到销毁的全过程。NIST SP 800-57标准定义了密钥生命周期的各个阶段。

```
┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
│  密钥生成 │───▶│ 密钥注册 │───▶│ 密钥分发 │───▶│ 密钥存储 │
└─────────┘    └─────────┘    └─────────┘    └────┬────┘
                                                  │
                                                  ▼
┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
│  密钥销毁 │◀───│ 密钥撤销 │◀───│ 密钥轮换 │◀───│ 密钥使用 │
└─────────┘    └─────────┘    └─────────┘    └─────────┘
```

#### 1.3.2 各阶段关键控制点

**密钥生成阶段：**
- 使用经过认证的随机数生成器（CSPRNG）
- 密钥长度符合当前安全标准（AES-256、RSA-3072+、ECC-256+）
- 密钥生成过程必须在安全环境中进行
- 生成后立即进行密钥质量检测

**密钥分发阶段：**
- 采用安全信道传输（TLS、SSH、加密邮件）
- 密钥分片分发（Shamir秘密共享）
- 双人控制原则（Dual Control）
- 分发过程全程审计记录

**密钥使用阶段：**
- 最小权限原则，按需授权
- 使用时解密，使用后立即从内存清除
- 禁止将密钥打印到日志或输出到控制台
- 密钥使用操作必须可审计

**密钥轮换阶段：**
- 制定明确的轮换周期策略
- 支持密钥版本管理，平滑过渡
- 轮换后旧密钥进入退役状态
- 数据重加密策略规划

**密钥销毁阶段：**
- 安全删除所有密钥副本
- 验证销毁的完整性
- 记录销毁操作的审计日志
- 通知相关系统和人员
