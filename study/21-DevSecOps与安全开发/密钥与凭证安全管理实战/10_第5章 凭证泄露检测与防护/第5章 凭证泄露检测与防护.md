# 第5章 凭证泄露检测与防护

### 5.1 代码仓库凭证扫描

#### 5.1.1 GitGuardian

GitGuardian是一款专业的代码仓库凭证检测SaaS服务，支持实时监控公共和私有代码仓库。

**核心能力：**
- 支持350+种凭证类型检测
- 实时监控GitHub、GitLab、Bitbucket等平台
- 高精度检测，低误报率
- 自动通知和事件管理
- 历史提交扫描

**检测的凭证类型：**
- 云平台凭证（AWS、GCP、Azure）
- API密钥（Stripe、Slack、GitHub Personal Access Token）
- 数据库连接字符串
- SSH私钥
- TLS证书私钥
- .env文件中的敏感配置

#### 5.1.2 truffleHog

truffleHog是一款开源的Git历史凭证扫描工具，通过熵值检测和正则表达式匹配发现代码中的敏感信息。

**安装与使用：**
```bash
# 安装
pip install truffleHog

# 扫描远程仓库
trufflehog --regex --entropy=True https://github.com/user/repo.git

# 扫描本地仓库
trufflehog --regex --entropy=True /path/to/local/repo

# 扫描指定分支
trufflehog --regex --branch=main file:///path/to/repo

# 输出JSON格式
trufflehog --json --regex file:///path/to/repo > results.json
```

#### 5.1.3 Gitleaks

Gitleaks是另一款流行的开源凭证扫描工具，使用Go语言编写，速度快、配置灵活。

**安装与使用：**
```bash
# 安装
brew install gitleaks  # macOS
# 或从GitHub Release下载二进制文件

# 扫描当前目录
gitleaks detect --source .

# 扫描指定仓库
gitleaks detect --source /path/to/repo --verbose

# 生成HTML报告
gitleaks detect --source . --report-format html --report-path report.html

# 扫描特定提交
gitleaks detect --source . --log-opts="--all commitA..commitB"

# 忽略特定文件/模式
# 创建.gitleaksignore文件
echo "path/to/file.py:api-key:123" >> .gitleaksignore
```

**自定义规则配置（.gitleaks.toml）：**
```toml
title = "Custom Gitleaks Config"

[allowlist]
  description = "Allowlist for known false positives"
  files = [
    '''.*test.*''',
    '''.*example.*''',
  ]
  regexes = [
    '''password.*example''',
    '''fake.*key''',
  ]

[[rules]]
  description = "Custom API Key Pattern"
  regex = '''api[_-]?key["'=:\s]+([a-zA-Z0-9]{32,})'''
  tags = ["api-key", "custom"]
```

#### 5.1.4 集成到CI/CD流水线

**GitHub Actions集成Gitleaks：**
```yaml
name: Secret Scan

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  secret-scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0  # 需要完整历史
      
      - name: Run Gitleaks
        uses: gitleaks/gitleaks-action@v2
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          GITLEAKS_LICENSE: ${{ secrets.GITLEAKS_LICENSE }}
```

**Git pre-commit钩子：**
```bash
#!/bin/sh
# .git/hooks/pre-commit

# 检查暂存区是否包含凭证
if gitleaks detect --staged --quiet; then
    echo "Error: Potential secrets detected in staged files!"
    echo "Run 'gitleaks detect --staged' for details."
    exit 1
fi

exit 0
```

### 5.2 运行时凭证监控

#### 5.2.1 应用层监控

**凭证使用监控指标：**
- API密钥调用频率和模式
- 异常的凭证使用行为（如地理位置异常）
- 凭证使用的错误率（认证失败次数）
- 并发使用情况（同一密钥是否多处同时使用）

**异常检测规则示例：**
- 同一API密钥在5分钟内从不同国家IP调用
- API密钥的调用量突增10倍以上
- 非工作时间的管理员凭证使用
- 从新的IP地址首次使用高权限凭证

#### 5.2.2 日志监控与告警

**关键日志源：**
- 认证服务日志（成功/失败的认证尝试）
- API网关日志（API密钥使用情况）
- 密钥管理服务日志（KMS、Vault操作日志）
- 数据库审计日志（敏感数据访问）
- 操作系统日志（sudo、ssh登录）

**SIEM关联规则：**
```
规则：凭证爆破检测
条件：
  - 同一账户在10分钟内认证失败超过5次
  - 随后出现一次成功认证
动作：
  - 锁定账户
  - 触发告警通知安全团队
  - 记录事件用于调查
```

### 5.3 凭证泄露应急响应

#### 5.3.1 应急响应流程

**凭证泄露事件响应六步法：**

```
┌──────────┐    ┌──────────┐    ┌──────────┐
│  1.发现  │───▶│  2.遏制  │───▶│  3.根除  │
└──────────┘    └──────────┘    └────┬─────┘
                                     │
┌──────────┐    ┌──────────┐    ┌───▼──────┐
│  6.总结  │◀───│  5.恢复  │◀───│  4.调查  │
└──────────┘    └──────────┘    └──────────┘
```

**步骤1：发现与确认**
- 确认泄露凭证的类型和范围
- 评估凭证的权限等级和影响范围
- 确认泄露时间和泄露渠道

**步骤2：遏制（立即执行）**
- 立即吊销/轮换泄露的凭证
- 阻止未授权访问（IP封禁、会话终止）
- 保护关键系统和数据
- 保存取证证据

**步骤3：调查与分析**
- 追溯泄露源头（代码仓库、日志、配置文件）
- 分析攻击者的活动记录
- 评估数据泄露范围
- 识别其他可能受影响的凭证

**步骤4：根除**
- 修复泄露源头（删除硬编码凭证、修复配置漏洞）
- 全面轮换相关凭证
- 修复安全漏洞
- 加强访问控制

**步骤5：恢复**
- 逐步恢复系统正常运行
- 验证新凭证的有效性
- 加强监控，防止再次入侵

**步骤6：总结与改进**
- 编写事件报告
- 更新安全策略和流程
- 加强安全培训
- 改进检测和防护措施

#### 5.3.2 不同类型凭证的应急措施

| 凭证类型 | 立即措施 | 后续措施 |
|---------|---------|---------|
| 云平台AK/SK | 立即禁用或删除泄露的密钥 | 创建新密钥并更新所有使用点；审计该密钥的历史操作 |
| 数据库密码 | 修改密码；限制数据库访问IP | 审计数据库访问日志；检查是否有数据被窃取 |
| API密钥 | 吊销泄露的密钥 | 生成新密钥；通知调用方更新；审计API调用日志 |
| SSH私钥 | 删除对应公钥的授权 | 生成新密钥对；检查服务器是否被入侵 |
| 管理员密码 | 立即修改密码；启用MFA | 审计管理员操作日志；检查是否有未授权操作 |
| TLS证书私钥 | 吊销证书；更换新证书 | 检查是否存在中间人攻击的迹象 |

#### 5.3.3 Git历史中的凭证清理

如果凭证被提交到了Git仓库，仅删除当前文件中的凭证是不够的，因为Git历史中仍然保留着凭证。

**使用git-filter-repo清理：**
```bash
# 安装git-filter-repo
pip install git-filter-repo

# 创建替换规则文件（replacements.txt）
# 格式：旧字符串==>新字符串
SuperSecret123!==>REDACTED_PASSWORD
AKIAIOSFODNN7EXAMPLE==>AKIA_REDACTED

# 重写整个历史
git filter-repo --replace-text replacements.txt

# 强制推送到远程仓库
git push --force --all
git push --force --tags
```

**使用BFG Repo-Cleaner：**
```bash
# 下载BFG
wget https://repo1.maven.org/maven2/com/madgag/bfg/1.14.0/bfg-1.14.0.jar

# 创建包含要删除的密码的文件
echo "SuperSecret123!" > passwords.txt
echo "AKIAIOSFODNN7EXAMPLE" >> passwords.txt

# 运行清理
java -jar bfg-1.14.0.jar --replace-text passwords.txt my-repo.git

# 清理完成后
cd my-repo.git
git reflog expire --expire=now --all
git gc --prune=now --aggressive
```
