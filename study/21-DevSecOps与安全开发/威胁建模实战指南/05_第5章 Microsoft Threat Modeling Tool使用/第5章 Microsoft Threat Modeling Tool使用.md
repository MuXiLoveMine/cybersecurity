# 第5章 Microsoft Threat Modeling Tool使用

### 5.1 工具介绍与安装

#### 5.1.1 工具介绍

Microsoft Threat Modeling Tool（简称TMT）是微软推出的免费威胁建模工具，是STRIDE方法论的标杆性工具。它通过图形化界面帮助用户绘制系统架构图，并基于STRIDE模型自动生成威胁分析报告。

**核心功能：**
- 图形化绘制系统架构和数据流图
- 内置STRIDE威胁生成引擎
- 自动识别威胁并生成威胁列表
- 提供缓解措施建议
- 生成可导出的威胁报告
- 支持模板自定义

**适用场景：**
- 软件架构设计阶段的威胁分析
- 安全设计评审
- 开发团队安全培训
- 安全需求梳理

#### 5.1.2 安装方法

**系统要求：**
- 操作系统：Windows 7及以上
- .NET Framework：4.7.2或更高版本
- 内存：至少2GB RAM
- 磁盘空间：至少100MB可用空间

**安装步骤：**

1. **下载安装包**
   - 访问微软官方下载页面：https://aka.ms/threatmodelingtool
   - 下载最新版本的MSI安装包

2. **运行安装程序**
   - 双击下载的MSI文件
   - 按照安装向导提示完成安装
   - 选择安装路径（默认即可）

3. **启动工具**
   - 从开始菜单启动"Microsoft Threat Modeling Tool"
   - 首次启动可能需要加载模板

**注意事项：**
- 该工具仅支持Windows平台
- 需要联网获取最新的威胁知识库
- 建议定期更新到最新版本

### 5.2 创建威胁建模项目

#### 5.2.1 新建项目

**操作步骤：**
1. 启动TMT工具
2. 点击"Create a Model"或"新建模型"
3. 选择模板（通常选择"SDL TM Knowledge Base"）
4. 选择保存位置和文件名
5. 点击"保存"创建项目

**项目文件格式：**
- 文件扩展名：`.tb7`（最新版本）或`.tm7`
- 文件本质：包含图表和威胁数据的压缩包
- 可以加入版本控制系统进行管理

#### 5.2.2 项目设置

**基本信息设置：**
- 项目名称
- 项目描述
- 负责人
- 创建日期
- 版本号

**威胁模型选择：**
- 默认使用STRIDE模型
- 可以根据需要选择或自定义威胁生成规则
- 可以导入自定义的威胁知识库

### 5.3 绘制系统架构图

#### 5.3.1 工具栏介绍

TMT的左侧工具栏提供了以下绘图元素：

| 元素类别 | 包含元素 | 说明 |
|---------|---------|------|
| **Generic Elements** | 实体、过程、数据存储、数据流 | 基础DFD元素 |
| **Boundaries** | 信任边界、通用边界 | 边界元素 |
| **Web Model** | Web浏览器、Web应用、Web服务等 | Web相关组件 |
| **Cloud Model** | 云服务、虚拟机、存储等 | 云计算相关 |
| **Mobile Model** | 移动设备、移动应用等 | 移动应用相关 |
| **IoT Model** | IoT设备、网关等 | 物联网相关 |

#### 5.3.2 绘图基本操作

**添加元素：**
1. 从左侧工具栏选择元素类型
2. 在画布上点击或拖拽添加元素
3. 双击元素修改名称和属性

**连接元素（创建数据流）：**
1. 选择数据流工具
2. 从源元素拖拽到目标元素
3. 双击数据流修改名称和属性

**添加信任边界：**
1. 选择信任边界工具
2. 在画布上拖拽绘制边界框
3. 将相关元素拖入边界内

**元素属性设置：**
- 名称（Name）：元素的标识名称
- 描述（Description）：元素的详细说明
- 技术/实现说明：实现方式和技术栈
- 进出数据流：自动列出关联的数据流

#### 5.3.3 绘图技巧

1. **分层绘制**
   - 先画整体架构（上下文视图）
   - 再逐步细化各模块

2. **合理布局**
   - 使用对齐工具保持图面整洁
   - 数据流尽量避免交叉
   - 相关元素放在一起

3. **命名规范**
   - 外部实体：名词短语（如"Web用户"）
   - 过程：动词+名词（如"验证用户凭证"）
   - 数据存储：名词（如"用户配置表"）
   - 数据流：描述数据内容（如"登录请求（用户名/密码）"）

4. **标注敏感数据**
   - 在数据流描述中标注敏感数据
   - 可以使用注释功能补充说明

### 5.4 选择威胁模型（STRIDE）

#### 5.4.1 威胁模型配置

TMT默认使用STRIDE威胁模型。可以通过以下方式查看和配置：

1. 点击菜单栏的"Analysis"（分析）
2. 选择"Threat Model Settings"（威胁模型设置）
3. 查看当前使用的威胁生成规则
4. 根据需要启用或禁用某些威胁类别

#### 5.4.2 STRIDE威胁生成规则

TMT内置的威胁生成规则基于元素类型和交互关系：

| 元素类型 | 生成的STRIDE威胁 |
|---------|-----------------|
| **外部实体** | Spoofing, Repudiation |
| **过程** | Spoofing, Tampering, Repudiation, Information Disclosure, DoS, Elevation of Privilege |
| **数据存储** | Tampering, Repudiation, Information Disclosure, DoS |
| **数据流** | Tampering, Information Disclosure, DoS |
| **信任边界** | Spoofing, Tampering, Information Disclosure, Elevation of Privilege |

#### 5.4.3 自定义威胁规则

高级用户可以自定义威胁生成规则：

1. 打开模板编辑器
2. 添加新的威胁类型
3. 定义触发条件
4. 设置默认的缓解措施

### 5.5 自动生成威胁报告

#### 5.5.1 运行分析

**操作步骤：**
1. 完成系统架构图绘制后
2. 点击工具栏的"Analyze Threats"（分析威胁）按钮
3. 或点击菜单"Analysis" → "Run Analysis"
4. 工具会自动扫描所有元素和数据流
5. 生成威胁列表

#### 5.5.2 威胁列表解读

威胁列表包含以下信息：

| 列名 | 说明 |
|------|------|
| **Priority** | 优先级（高/中/低） |
| **Threat Type** | 威胁类型（STRIDE类别） |
| **Threat Title** | 威胁标题 |
| **Description** | 威胁详细描述 |
| **Interaction** | 涉及的元素交互 |
| **Status** | 状态（未开始/进行中/已缓解/不适用） |

#### 5.5.3 威胁分类筛选

可以通过以下方式筛选威胁：
- 按威胁类型筛选（只看Spoofing类威胁）
- 按优先级筛选（只看高危威胁）
- 按状态筛选（只看未处理的威胁）
- 按涉及元素筛选（查看某个组件的所有威胁）

### 5.6 缓解措施建议

#### 5.6.1 查看缓解建议

对于每个自动生成的威胁，TMT会提供标准的缓解措施建议：

1. 选中某个威胁
2. 在右侧面板查看"Mitigations"（缓解措施）
3. 每种威胁类型都有对应的标准缓解方案

**示例：SQL注入威胁的缓解建议**
- 使用参数化查询或存储过程
- 输入验证和过滤
- 最小权限数据库账户
- Web应用防火墙（WAF）

#### 5.6.2 编辑威胁状态

对每个威胁可以设置处理状态：

| 状态 | 含义 |
|------|------|
| **Not Started** | 未开始处理 |
| **In Progress** | 正在处理中 |
| **Mitigated** | 已缓解 |
| **Not Applicable** | 不适用（该威胁在此场景下不存在） |
| **Needs Investigation** | 需要进一步调查 |

#### 5.6.3 添加自定义备注

可以为每个威胁添加：
- 具体的缓解措施描述
- 负责人和计划完成时间
- 相关的需求或任务编号
- 验证结果和备注

### 5.7 报告生成与导出

#### 5.7.1 生成HTML报告

**操作步骤：**
1. 点击菜单"File" → "Create Report"
2. 选择报告模板（完整报告/摘要报告）
3. 选择报告内容（威胁列表、图、缓解措施等）
4. 选择输出路径
5. 生成HTML格式报告

**报告包含内容：**
- 项目基本信息
- 系统架构图（可包含多级视图）
- 威胁列表（按类型/优先级分类）
- 每个威胁的详细描述
- 缓解措施和状态
- 风险概览统计

#### 5.7.2 其他导出格式

- **HTML**：最常用，支持交互式查看
- **PDF**：需要通过浏览器打印为PDF
- **图片**：可以单独导出架构图为图片
- **Excel/CSV**：威胁列表可以复制到表格软件

#### 5.7.3 报告使用建议

- **设计评审**：在设计评审会议上使用报告
- **任务跟踪**：将威胁转化为开发任务
- **合规审计**：作为安全设计的证据
- **知识沉淀**：作为项目安全文档的一部分

### 5.8 团队协作与版本管理

#### 5.8.1 版本控制

TMT项目文件可以纳入版本控制系统：

**最佳实践：**
- 将`.tb7`文件加入Git/SVN等版本控制
- 每次重大更新提交新版本
- 编写提交说明描述变更内容
- 使用分支管理不同版本的威胁模型

**注意事项：**
- TMT文件是二进制格式，不支持文本diff
- 建议配合变更日志使用
- 避免多人同时编辑同一文件

#### 5.8.2 团队协作流程

**协作模式：**
1. **安全工程师主导**：安全工程师创建和维护威胁模型，开发团队参与评审
2. **共同编辑**：团队成员共同编辑，但需要协调避免冲突
3. **评审模式**：一人负责编辑，其他人通过评审会提供反馈

**协作建议：**
- 定期召开威胁建模评审会
- 威胁变更需要经过评审
- 保持威胁模型与代码同步更新
- 将威胁建模纳入开发流程

#### 5.8.3 与其他工具集成

- **Azure DevOps**：可以将威胁关联到工作项
- **Jira**：手动或通过API创建安全缺陷
- **Confluence**：将报告发布到Wiki
- **静态分析工具**：关联SAST扫描结果
