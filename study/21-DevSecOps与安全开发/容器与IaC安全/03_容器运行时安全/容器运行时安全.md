# 容器运行时安全

### 3.1 Seccomp 配置

Seccomp（Secure Computing Mode）限制容器可用的系统调用。

**默认 Seccomp 配置**
```json
{
  "defaultAction": "SCMP_ACT_ERRNO",
  "defaultErrnoRet": 1,
  "architectures": [
    "SCMP_ARCH_X86_64",
    "SCMP_ARCH_X86",
    "SCMP_ARCH_X32"
  ],
  "syscalls": [
    {
      "names": [
        "accept", "accept4", "access", "bind", "brk",
        "chmod", "chown", "clone", "close", "connect",
        "dup", "dup2", "exit", "exit_group", "fcntl",
        "fork", "getpid", "getuid", "listen", "mmap",
        "mprotect", "munmap", "open", "openat", "read",
        "write", "writev", "socket", "setsockopt"
      ],
      "action": "SCMP_ACT_ALLOW"
    },
    {
      "names": [
        "reboot",
        "mount",
        "umount2",
        "kexec_load",
        "init_module",
        "finit_module",
        "delete_module",
        "iopl",
        "ioperm",
        "kexec_file_load",
        "open_by_handle_at",
        "ptrace",
        "setns",
        "unshare"
      ],
      "action": "SCMP_ACT_ERRNO"
    }
  ]
}
```

**Kubernetes 中使用 Seccomp**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: seccomp-demo
  annotations:
    # 使用默认 seccomp 配置（推荐）
    seccomp.security.alpha.kubernetes.io/pod: "RuntimeDefault"
spec:
  securityContext:
    seccompProfile:
      type: RuntimeDefault  # 使用容器运行时默认配置
  containers:
  - name: app
    image: myapp:1.0.0
    securityContext:
      seccompProfile:
        type: Localhost  # 使用本地自定义配置
        localhostProfile: profiles/custom-seccomp.json
```

### 3.2 AppArmor 配置

AppArmor 通过路径强制访问控制限制容器权限。

**AppArmor 配置示例**
```
#include <tunables/global>

profile docker-app flags=(attach_disconnected,mediate_deleted) {
  #include <abstractions/base>

  network inet,
  network inet6,

  # 允许访问应用目录
  /app/** r,
  /app/** rw,
  /tmp/** rw,
  /app/logs/** rw,

  # 允许读取系统库
  /lib/** mr,
  /usr/lib/** mr,
  /lib64/** mr,

  # 禁止访问敏感路径
  deny /etc/shadow r,
  deny /etc/passwd w,
  deny /proc/*/mem r,
  deny /proc/sys/** rw,
  deny /sys/** rw,
  deny /var/run/docker.sock rw,

  # 允许信号
  signal,
  signal send,
  signal receive,

  # 限制能力
  deny capability sys_admin,
  deny capability sys_ptrace,
  deny capability sys_module,
  deny capability net_admin,
  deny capability net_raw,
}
```

**在 Kubernetes 中使用 AppArmor**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: apparmor-demo
  annotations:
    container.apparmor.security.beta.kubernetes.io/app: localhost/docker-app
spec:
  containers:
  - name: app
    image: myapp:1.0.0
```

### 3.3 Capabilities 最小化

**Linux Capabilities 默认集与危险集**

| Capability | 说明 | 风险 |
|-----------|------|------|
| CAP_SYS_ADMIN | 系统管理（最危险） | 容器逃逸 |
| CAP_NET_ADMIN | 网络配置 | 网络攻击 |
| CAP_SYS_PTRACE | 进程跟踪 | 进程注入 |
| CAP_SYS_MODULE | 加载内核模块 | 内核攻击 |
| CAP_DAC_OVERRIDE | 绕过文件权限 | 任意文件访问 |
| CAP_SETUID | 设置用户ID | 权限提升 |
| CAP_NET_RAW | 原始网络访问 | 网络攻击 |
| CAP_CHOWN | 修改文件属主 | 权限提升 |
| CAP_KILL | 杀死进程 | DoS |

**安全配置：丢弃所有 Capabilities**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: minimal-capabilities
spec:
  containers:
  - name: app
    image: myapp:1.0.0
    securityContext:
      capabilities:
        drop:
          - ALL          # 丢弃所有 capabilities
        add:
          - NET_BIND_SERVICE  # 仅保留绑定 80/443 端口的能力
```

### 3.4 只读根文件系统

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: readonly-rootfs
spec:
  containers:
  - name: app
    image: myapp:1.0.0
    securityContext:
      readOnlyRootFilesystem: true   # 只读根文件系统
      runAsNonRoot: true             # 非 root 运行
      runAsUser: 1000
    volumeMounts:
    - name: tmp
      mountPath: /tmp                # 挂载可写目录
    - name: cache
      mountPath: /app/cache          # 应用缓存目录
    - name: logs
      mountPath: /app/logs           # 日志目录
  volumes:
  - name: tmp
    emptyDir: {}
  - name: cache
    emptyDir:
      sizeLimit: 500Mi
  - name: logs
    emptyDir: {}
```

### 3.5 完整的安全 Dockerfile

```dockerfile
# ==========================================
# 安全 Dockerfile 最佳实践示例
# ==========================================

# 第一阶段：构建阶段
FROM golang:1.21-alpine AS builder

# 安装必要工具
RUN apk add --no-cache git ca-certificates

# 设置工作目录
WORKDIR /build

# 复制依赖文件（利用 Docker 缓存层）
COPY go.mod go.sum ./
RUN go mod download

# 复制源代码
COPY . .

# 编译静态二进制文件
# - CGO_ENABLED=0: 禁用 CGO，生成静态链接
# - -ldflags='-s -w': 去除调试信息，减小镜像
RUN CGO_ENABLED=0 GOOS=linux go build \
    -ldflags='-s -w -extldflags "-static"' \
    -o /app/server \
    ./cmd/server

# 第二阶段：运行阶段
FROM scratch

# 添加 CA 证书（支持 HTTPS 请求）
COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/

# 复制编译好的二进制文件
COPY --from=builder /app/server /server

# 创建非 root 用户（scratch 镜像需要手动指定 UID/GID）
USER 65534:65534

# 设置安全标签
# 使用只读根文件系统
# 不需要设置 EXPOSE 如果应用不需要网络

# 健康检查
HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \
    CMD ["/server", "-health"]

# 启动命令
ENTRYPOINT ["/server"]
```
