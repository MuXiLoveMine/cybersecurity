# 详细子方向

### 2.1 DevSecOps 概述

#### 2.1.1 核心理念
**安全左移（Shift Left）**
- 在开发早期阶段引入安全活动
- 需求阶段进行威胁建模
- 设计阶段进行安全架构评审
- 编码阶段进行安全代码审查
- 越早发现漏洞修复成本越低

**安全无处不在（Security Everywhere）**
- 安全贯穿整个 SDLC
- 不只在测试阶段做安全
- 运维阶段同样需要安全
- 安全是所有人的责任

**安全自动化（Security Automation）**
- 自动化代码扫描（SAST）
- 自动化依赖检查（SCA）
- 自动化动态扫描（DAST）
- 自动化安全门禁
- 减少人工安全审查瓶颈

**安全即代码（Security as Code）**
- 将安全策略编码化管理
- 安全规则版本可控
- 安全配置可审计
- 安全测试可重复执行

#### 2.1.2 安全文化
**文化建设要点**
- 安全责任共担：开发、运维、安全团队共同负责
- 安全赋能而非安全阻碍
- 持续学习和改进
- 失败透明化：安全事件不追责而是改进流程
- 度量驱动：用数据衡量安全成熟度

**DevSecOps 成熟度模型**
- Level 0：无安全意识 - 安全是事后补充
- Level 1：基础安全 - 有基本安全测试但手动
- Level 2：安全集成 - 安全工具集成到 CI/CD
- Level 3：安全自动化 - 全流程安全自动化
- Level 4：安全文化 - 安全融入文化和日常实践
- Level 5：持续优化 - 安全度量驱动持续改进

#### 2.1.3 工具链架构
**DevSecOps 工具链全览**

```
┌─────────────────────────────────────────────────────────────┐
│                    DevSecOps 工具链                          │
├──────────┬──────────┬──────────┬──────────┬─────────────────┤
│  代码阶段 │  构建阶段 │  测试阶段 │  部署阶段 │    运维阶段     │
├──────────┼──────────┼──────────┼──────────┼─────────────────┤
│ Git Hooks│ 镜像扫描  │ SAST扫描  │ IaC扫描   │ 运行时安全      │
│ 预提交检查│ SCA检查   │ DAST扫描  │ 签名验证  │ 容器监控        │
│ IDE插件   │ 密钥扫描  │ IAST插桩  │ 准入控制  │ 漏洞响应        │
│ 密钥扫描  │ 制品签名  │ 模糊测试  │ 蓝绿部署  │ 补丁管理        │
└──────────┴──────────┴──────────┴──────────┴─────────────────┘
```

**工具链集成原则**
- 工具间数据可流通

#### 2.2.1 需求阶段

**安全需求模板示例**
```
[REQ-SEC-001] 用户认证
- 必须支持多因素认证（MFA）
- 密码复杂度：至少12位，包含大小写字母、数字、特殊字符
- 密码存储必须使用 Argon2id 或 bcrypt 加盐哈希
- 登录失败5次后锁定账户30分钟

[REQ-SEC-002] 数据保护
- 敏感数据传输必须使用 TLS 1.2+
- 敏感数据存储必须使用 AES-256 加密
- 日志中不得记录敏感数据
- 必须支持数据导出和删除（GDPR）
```

#### 2.3.3 语言特定安全规范
**Python 安全编码**
```python
# 危险：SQL 注入
cursor.execute(f"SELECT * FROM users WHERE name='{user_input}'")

# 安全：参数化查询
cursor.execute("SELECT * FROM users WHERE name=%s", (user_input,))

# 危险：命令注入
os.system(f"ping {user_input}")

# 安全：使用参数列表
import subprocess
subprocess.run(["ping", user_input], check=True)

# 危险：不安全反序列化
import pickle
data = pickle.loads(user_input)

# 安全：使用 JSON
import json
data = json.loads(user_input)

# 危险：弱随机数
import random
token = random.random()

# 安全：使用安全随机数
import secrets
token = secrets.token_hex(32)
```

**Java 安全编码**
```java
// 危险：SQL 注入
String query = "SELECT * FROM users WHERE name='" + userInput + "'";
Statement stmt = conn.createStatement();
ResultSet rs = stmt.executeQuery(query);

// 安全：PreparedStatement
PreparedStatement pstmt = conn.prepareStatement(
    "SELECT * FROM users WHERE name=?");
pstmt.setString(1, userInput);
ResultSet rs = pstmt.executeQuery();

// 危险：XML 外部实体注入
DocumentBuilderFactory dbf = DocumentBuilderFactory.newInstance();
DocumentBuilder db = dbf.newDocumentBuilder();

// 安全：禁用外部实体
dbf.setFeature("http://apache.org/xml/features/disallow-doctype-decl", true);
dbf.setFeature("http://xml.org/sax/features/external-general-entities", false);
dbf.setFeature("http://xml.org/sax/features/external-parameter-entities", false);
```

**JavaScript/Node.js 安全编码**
```javascript
// 危险：XSS
res.send('<div>' + userInput + '</div>');

// 安全：使用模板引擎自动转义
res.render('page', { data: userInput });

// 危险：eval 注入
eval(userInput);

// 安全：使用 JSON.parse
JSON.parse(userInput);

// 危险：正则表达式拒绝服务
const regex = new RegExp(userInput);

// 安全：使用安全正则库
const safeRegex = require('safe-regex');
if (safeRegex(userInput)) {
    const regex = new RegExp(userInput);
}
```

### 2.4 SAST 静态应用安全测试

#### 2.4.1 SAST 原理
**分析层次**
- 词法分析：将源代码分解为 Token
- 语法分析：构建抽象语法树（AST）
- 语义分析：理解代码含义
- 数据流分析：追踪数据流向
- 控制流分析：理解执行路径
- 污点分析：追踪不可信数据传播

**污点分析流程**
```
污点源（Source）→ 数据传播 → 汇点（Sink）

例如：
Source: request.getParameter("id")  // 用户输入
  ↓ 传播
  variable = request.getParameter("id")
  ↓ 传播
  query = "SELECT * FROM users WHERE id=" + variable
  ↓ 到达 Sink
  statement.execute(query)  // SQL注入！
```

#### 2.4.2 SAST 工具
**商业工具**
- Fortify（Micro Focus）：企业级全语言支持
- Checkmarx：支持 25+ 编程语言
- Veracode：云服务模式
- Coverity（Synopsys）：高精度分析

**开源工具**
- SonarQube：代码质量 + 安全
- Semgrep：轻量级规则引擎
- Bandit：Python 专用
- ESLint + 安全插件：JavaScript
- SpotBugs + Find Security Bugs：Java
- Brakeman：Ruby on Rails

**SonarQube 自定义规则示例**
```java
// SonarQube 自定义规则模板
@Rule(key = "CustomSQLInjectionCheck")
public class CustomSQLInjectionCheck extends AbstractJavaRule {

    @Override
    public void visitNode(Tree tree) {
        // 检查 Statement.executeQuery 中的字符串拼接
        if (tree instanceof MethodInvocationTree) {
            MethodInvocationTree methodInvocation = (MethodInvocationTree) tree;
            if (isExecuteQueryMethod(methodInvocation)) {
                ExpressionTree argument = methodInvocation.arguments().get(0);
                if (isStringConcatenation(argument)) {
                    reportIssue(tree, "检测到SQL拼接，可能存在注入风险");
                }
            }
        }
    }
}
```

2. 主动扫描：发送 Payload 探测漏洞
3. 被动扫描：分析正常请求响应
4. 结果分析：确认漏洞有效性
5. 报告生成：输出漏洞报告

**Payload 注入示例**

```python
# SQL 注入 Payload 示例
sql_payloads = [

xss_payloads = [
    "<script>alert(1)</script>",
    "<img src=x onerror=alert(1)>",
```


#### 2.8.2 运行时安全
**Dockerfile 安全最佳实践**
```dockerfile
# 不安全：使用 root 用户
FROM ubuntu:latest
RUN apt-get install -y python3
COPY app.py /app/
CMD ["python3", "/app/app.py"]

# 安全：最小权限原则
FROM python:3.11-slim
RUN groupadd -r appuser && useradd -r -g appuser appuser
COPY --chown=appuser:appuser app.py /app/
USER appuser
HEALTHCHECK --interval=30s --timeout=3s \
    CMD python3 -c "import urllib.request; urllib.request.urlopen('http://localhost:8080/health')" || exit 1
EXPOSE 8080
CMD ["python3", "/app/app.py"]
```

**Kubernetes Pod 安全配置**
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: secure-app
spec:
  securityContext:
    runAsNonRoot: true        # 禁止 root 运行
    runAsUser: 1000           # 指定非 root UID
    fsGroup: 2000             # 文件系统组
    seccompProfile:
      type: RuntimeDefault     # 使用默认 seccomp 配置
  containers:
  - name: app
    image: myapp:1.0.0
    securityContext:
      allowPrivilegeEscalation: false  # 禁止提权
      readOnlyRootFilesystem: true      # 只读根文件系统
      runAsNonRoot: true
      runAsUser: 1000
      capabilities:
        drop:
          - ALL                 # 丢弃所有 capabilities
        add:
          - NET_BIND_SERVICE    # 仅保留必要 capability
    resources:
      limits:
        memory: "256Mi"
        cpu: "500m"
      requests:
        memory: "128Mi"
        cpu: "250m"
    volumeMounts:
    - name: tmp
      mountPath: /tmp           # 挂载可写目录
    - name: cache
      mountPath: /app/cache
  volumes:
  - name: tmp
    emptyDir: {}
  - name: cache
    emptyDir: {}
```

### 2.9 IaC 基础设施即代码安全

#### 2.9.1 IaC 安全风险
**常见风险**
- 安全组规则过于开放（0.0.0.0/0）
- IAM 策略权限过大（Action: *）
- 存储未启用加密
- 密钥硬编码在代码中
- 资源公开暴露
- 缺少审计日志

#### 2.9.2 IaC 安全扫描
**Checkov 使用示例**
```bash
# 扫描 Terraform 目录
checkov -d terraform/

# 扫描单个文件
checkov -f main.tf

# 扫描 CloudFormation
checkov -f template.yaml --framework cloudformation

# 扫描 Kubernetes
checkov -f deployment.yaml --framework kubernetes

# 输出 JSON
checkov -d terraform/ --output json > checkov-report.json

# 跳过特定检查
checkov -d terraform/ --skip-check CKV_AWS_18

# 只运行特定检查
checkov -d terraform/ --check CKV_AWS_19,CKV_AWS_20
```

```bash

# 忽略特定规则

resource "aws_security_group" "main" {
  # ...
```

### 2.10 安全门禁与流水线集成

#### 2.10.1 安全门禁策略
**门禁级别定义**
| 级别 | 阻断条件 | 处理方式 |
|------|---------|---------|
| P0 阻断 | Critical 漏洞 | 阻断构建/部署 |
| P1 阻断 | High 漏洞 | 阻断部署到生产 |
| P2 警告 | Medium 漏洞 | 警告但允许部署 |
| P3 提示 | Low/Info | 仅记录 |

#### 2.10.2 GitLab CI 安全集成
```yaml
# .gitlab-ci.yml DevSecOps 流水线
stages:
  - security-scan
  - build
  - test
  - deploy

include:
  - template: Security/SAST.gitlab-ci.yml
  - template: Security/Dependency-Scanning.gitlab-ci.yml
  - template: Security/Secret-Detection.gitlab-ci.yml
  - template: Security/Container-Scanning.gitlab-ci.yml

# Semgrep 静态扫描
semgrep:
  stage: security-scan
  image: returntocorp/semgrep:latest
  script:
    - semgrep ci --config p/owasp-top-ten --json -o semgrep-report.json
  artifacts:
    reports:
      json: semgrep-report.json

# Trivy 镜像扫描
container_scanning:
  stage: security-scan
  image: aquasec/trivy:latest
  script:
    - trivy image --severity HIGH,CRITICAL --format json -o trivy-report.json $CI_APPLICATION_REPOSITORY:$CI_COMMIT_SHA
  artifacts:
    reports:
      json: trivy-report.json

# 安全门禁
security_gate:
  stage: deploy
  script:
    - python3 security_gate.py --sast semgrep-report.json --sca trivy-report.json
  rules:
    - if: $CI_COMMIT_BRANCH == "main"
```

#### 2.10.3 Jenkins 安全流水线
```groovy
// Jenkinsfile DevSecOps Pipeline
pipeline {
    agent any

    stages {
        stage('Security Scan') {
            parallel {
                stage('SAST - SonarQube') {
                    steps {
                        script {
                            sh 'sonar-scanner -Dsonar.projectKey=myapp'
                        }
                    }
                }
                stage('SCA - Dependency Check') {
                    steps {
                        sh 'dependency-check.sh --project myapp --scan .'
                    }
                }
                stage('Secret Scan') {
                    steps {
                        sh 'detect-secrets scan --all-secrets > secrets.json'
                    }
                }
            }
        }

        stage('Build & Image Scan') {
            steps {
                sh 'docker build -t myapp:${BUILD_NUMBER} .'
                sh 'trivy image --exit-code 1 --severity CRITICAL myapp:${BUILD_NUMBER}'
            }
        }

        stage('DAST - ZAP Scan') {
            steps {
                sh 'zap-cli quick-scan http://staging-app:8080'
            }
        }

        stage('Security Gate') {
            steps {
                script {
                    def result = sh(script: 'python3 security_gate.py', returnStatus: true)
                    if (result != 0) {
                        error('Security gate failed! Pipeline blocked.')
                    }
                }
            }
        }
    }

    post {
        always {
            archiveArtifacts artifacts: '**/*report*.json', allowEmptyArchive: true
        }
    }
}
```

### 2.12 安全需求与威胁建模

#### 2.12.1 安全需求分类
**功能性安全需求**
- 认证授权功能
- 数据加密功能
- 审计日志功能
- 安全配置功能

**非功能性安全需求**
- 安全性能要求
- 安全可用性要求
- 安全合规要求
- 安全可维护性要求

#### 2.12.2 威胁建模方法
**STRIDE 威胁分类**
| 威胁类型 | 安全属性 | 示例 |
|---------|---------|------|
| Spoofing（欺骗） | 认证 | 伪造身份 |
| Tampering（篡改） | 完整性 | 修改数据 |
| Repudiation（否认） | 不可抵赖 | 否认操作 |
| Information Disclosure（信息泄露） | 机密性 | 数据泄露 |
| Denial of Service（拒绝服务） | 可用性 | 服务中断 |
| Elevation of Privilege（提权） | 授权 | 权限提升 |

**STRIDE 威胁建模流程**
1. 组件识别：识别系统组件
2. 信任边界：划分信任边界
3. 数据流图：绘制数据流
4. 威胁识别：用 STRIDE 识别威胁
5. 风险评估：评估威胁风险
6. 缓解措施：制定缓解方案
