# 工控协议详解

> 本文档详细分析常见工业控制协议的报文结构、通信原理、抓包分析方法以及安全风险与漏洞。工业协议是工控安全的核心，掌握协议分析是工控安全从业者的必备技能。

---

## 一、Modbus TCP/RTU 协议详解

### 1.1 Modbus 协议概述

Modbus 是由 Modicon（现施耐德）于 1979 年开发的工业通信协议，是工业领域应用最广泛的协议之一。

**协议变体：**

| 变体 | 传输介质 | 数据链路 | 典型应用 |
|------|---------|---------|---------|
| Modbus RTU | 串行（RS-485/232） | 二进制编码，CRC 校验 | 现场设备通信 |
| Modbus ASCII | 串行（RS-485/232） | ASCII 编码，LRC 校验 | 调试、简单设备 |
| Modbus TCP | 以太网 | TCP/IP 封装 | 工业以太网 |
| Modbus UDP | 以太网 | UDP/IP 封装 | 较少使用 |
| Modbus Plus | 专用令牌网 | 高速令牌传递 | 施耐德专用 |

### 1.2 Modbus 数据模型

Modbus 定义了四种基本数据类型：

| 数据类型 | 访问方式 | 大小 | 功能码示例 |
|----------|---------|------|-----------|
| **线圈（Coils）** | 读/写 | 1 bit（布尔量） | 01 读、05 写单个、15 写多个 |
| **离散输入（Discrete Inputs）** | 只读 | 1 bit（布尔量） | 02 读 |
| **保持寄存器（Holding Registers）** | 读/写 | 16 bit（字） | 03 读、06 写单个、16 写多个 |
| **输入寄存器（Input Registers）** | 只读 | 16 bit（字） | 04 读 |

**地址空间：**
```
线圈地址：        00001 ~ 09999  (0x0000 ~ 0x270F)
离散输入地址：    10001 ~ 19999  (0x0000 ~ 0x270F)
输入寄存器地址：  30001 ~ 39999  (0x0000 ~ 0x270F)
保持寄存器地址：  40001 ~ 49999  (0x0000 ~ 0x270F)
```

> 注意：Modbus 协议中的地址是从 0 开始的（0-based），而文档中常用的地址编号是从 1 开始的（1-based）。例如保持寄存器 40001 对应的协议地址是 0x0000。

### 1.3 Modbus RTU 帧格式

Modbus RTU 使用二进制编码，帧结构如下：

```
┌────────────┬────────────┬─────────────────┬──────────┐
│ 从站地址   │ 功能码     │ 数据             │ CRC 校验 │
│ (1 字节)   │ (1 字节)   │ (N 字节)         │ (2 字节) │
└────────────┴────────────┴─────────────────┴──────────┘
```

**字段说明：**
- **从站地址**：1 字节，范围 1-247（0 为广播地址）
- **功能码**：1 字节，指示操作类型
- **数据**：变长，包含寄存器地址、数量、数据值等
- **CRC**：2 字节，循环冗余校验，低字节在前（小端序）

**示例：读取保持寄存器（功能码 03）**

请求帧（读取从站 1 的 40001-40002 寄存器）：
```
从站地址: 0x01
功能码:   0x03
起始地址: 0x00 0x00 (寄存器 40001)
寄存器数: 0x00 0x02 (读取 2 个)
CRC:      0x84 0x0A

完整帧: 01 03 00 00 00 02 84 0A
```

响应帧：
```
从站地址: 0x01
功能码:   0x03
字节计数: 0x04 (2个寄存器 × 2字节 = 4字节)
数据值:   0x12 0x34 (寄存器1值 = 0x1234)
          0x56 0x78 (寄存器2值 = 0x5678)
CRC:      0x?? 0x??

完整帧: 01 03 04 12 34 56 78 ?? ??
```

### 1.4 Modbus TCP 帧格式

Modbus TCP 在 TCP/IP 上传输，增加了 MBAP 头（Modbus Application Protocol Header）：

```
┌───────────────────────────────────────────────────────────┐
│                     MBAP 头 (7 字节)                      │
├──────────┬──────────┬──────────┬───────────┬─────────────┤
│ 事务标识 │ 协议标识 │ 长度     │ 单元标识  │ PDU 数据    │
│ (2 字节) │ (2 字节) │ (2 字节) │ (1 字节)  │ (N 字节)   │
└──────────┴──────────┴──────────┴───────────┴─────────────┘
                                 └──────┬──────┘
                                        │
                                   Modbus PDU
                        (功能码 + 数据，与 RTU 相同)
```

**MBAP 头字段说明：**

| 字段 | 长度 | 说明 |
|------|------|------|
| 事务标识符（Transaction ID） | 2 字节 | 请求/响应匹配，由客户端生成 |
| 协议标识符（Protocol ID） | 2 字节 | 固定为 0x0000（表示 Modbus） |
| 长度（Length） | 2 字节 | 后续字段的字节数（单元标识 + PDU） |
| 单元标识符（Unit ID） | 1 字节 | 从站地址 / 设备标识，相当于 RTU 的从站地址 |

**示例：Modbus TCP 读取保持寄存器**

请求报文（读取 40001-40002）：
```
事务标识: 0x00 0x01
协议标识: 0x00 0x00
长度:     0x00 0x06 (单元标识1 + 功能码1 + 起始地址2 + 数量2 = 6字节)
单元标识: 0x01
功能码:   0x03
起始地址: 0x00 0x00
寄存器数: 0x00 0x02

完整报文(十六进制): 00 01 00 00 00 06 01 03 00 00 00 02
```

响应报文：
```
事务标识: 0x00 0x01 (与请求一致)
协议标识: 0x00 0x00
长度:     0x00 0x05 (单元标识1 + 功能码1 + 字节计数1 + 数据4 = 5字节)
单元标识: 0x01
功能码:   0x03
字节计数: 0x04
寄存器1:  0x12 0x34
寄存器2:  0x56 0x78

完整报文(十六进制): 00 01 00 00 00 05 01 03 04 12 34 56 78
```

### 1.5 常用 Modbus 功能码

| 功能码 | 名称 | 数据类型 | 操作 | 说明 |
|--------|------|---------|------|------|
| 0x01 | 读线圈 | 线圈 | 读 | 读取多个线圈状态 |
| 0x02 | 读离散输入 | 离散输入 | 读 | 读取多个离散输入 |
| 0x03 | 读保持寄存器 | 保持寄存器 | 读 | 读取多个保持寄存器 |
| 0x04 | 读输入寄存器 | 输入寄存器 | 读 | 读取多个输入寄存器 |
| 0x05 | 写单个线圈 | 线圈 | 写 | 写入单个线圈 |
| 0x06 | 写单个寄存器 | 保持寄存器 | 写 | 写入单个保持寄存器 |
| 0x07 | 读异常状态 | - | 读 | 读取 8 个异常状态 |
| 0x08 | 诊断 | - | - | 诊断功能，子功能码多种 |
| 0x0B | 读事件计数 | - | 读 | 读取通信事件计数器 |
| 0x0C | 读事件日志 | - | 读 | 读取通信事件日志 |
| 0x0F | 写多个线圈 | 线圈 | 写 | 写入多个线圈 |
| 0x10 | 写多个寄存器 | 保持寄存器 | 写 | 写入多个保持寄存器 |
| 0x11 | 报告从站ID | - | 读 | 读取从站标识信息 |
| 0x14 | 读文件记录 | - | 读 | 读取文件记录 |
| 0x15 | 写文件记录 | - | 写 | 写入文件记录 |
| 0x17 | 读写多个寄存器 | 保持寄存器 | 读写 | 同时读写多个寄存器 |
| 0x2B | 封装接口传输 | - | - | 用于设备识别等扩展功能 |

### 1.6 异常响应

当从站无法正确处理请求时，返回异常响应：

```
┌────────────┬──────────────┬──────────────┐
│ 功能码     │ 异常码       │ (异常码最高位设为1)
│ (0x80 + 原功能码) │ (1 字节) │
└────────────┴──────────────┴──────────────┘
```

**常见异常码：**

| 异常码 | 名称 | 说明 |
|--------|------|------|
| 0x01 | 非法功能码 | 从站不支持该功能码 |
| 0x02 | 非法数据地址 | 请求的数据地址不存在 |
| 0x03 | 非法数据值 | 数据值超出范围或格式错误 |
| 0x04 | 从站设备故障 | 从站处理时发生错误 |
| 0x05 | 确认 | 从站已接受请求，但需要更长时间处理 |
| 0x06 | 从站忙碌 | 从站正在处理其他请求 |
| 0x08 | 存储奇偶校验错误 | 存储区数据校验错误 |
| 0x0A | 网关路径不可用 | 网关无法建立通信路径 |
| 0x0B | 网关目标设备无响应 | 目标设备未响应 |

### 1.7 Modbus 安全风险

**1. 无身份认证**
- 任何能连接到 Modbus 端口的设备都可以发送指令
- 没有用户名/密码机制
- 无法验证请求者身份

**2. 无数据加密**
- 所有数据明文传输
- 抓包即可获取所有寄存器值和控制指令
- 敏感生产数据泄露

**3. 无完整性校验（TCP 版）**
- Modbus TCP 仅依靠 TCP 校验和
- 报文在传输过程中可被篡改
- 中间人攻击可行

**4. 功能码滥用风险**
- 写入功能码（05/06/15/16）可直接控制设备
- 攻击者可以修改控制参数
- 可能导致生产事故

**5. 广播攻击**
- 地址 0 为广播地址
- 一条指令可控制所有从站
- 可用于大规模破坏

**攻击示例 - Modbus 写线圈攻击：**
```python
# 向 PLC 写入线圈，关闭所有输出
# 功能码 0x0F (15) - 写多个线圈
# 地址 0x0000 ~ 0x000F，全部置为 OFF
# 攻击者可通过此命令停止生产线
```

## 二、Siemens S7 协议分析

### 2.1 S7 协议概述

S7 协议是西门子（Siemens）S7 系列 PLC 的通信协议，广泛应用于工业自动化领域。

**协议家族：**

| 协议 | 全称 | 适用设备 | 传输层 |
|------|------|---------|--------|
| S7comm (S7 Basic) | S7 Communication | S7-200/300/400 | TCP 102 端口 |
| S7comm-plus | S7 Communication Plus | S7-1200/1500 | TCP 102 端口 |
| S7 Protocol (ISO-on-TCP) | - | 所有 S7 系列 | RFC1006 (ISO over TCP) |

**端口号：** TCP 102（ISO-on-TCP / RFC1006）

### 2.2 S7 协议栈结构

S7 协议采用多层封装结构：

```
┌─────────────────────────────────────────┐
│           S7 PDU (S7 协议数据单元)      │ ← 应用层
├─────────────────────────────────────────┤
│           COTP (ISO 8073)               │ ← 会话层
├─────────────────────────────────────────┤
│           ISO-on-TCP (RFC1006)          │ ← 表示层封装
├─────────────────────────────────────────┤
│           TCP (端口 102)                │ ← 传输层
├─────────────────────────────────────────┤
│           IP / Ethernet                 │ ← 网络层/链路层
└─────────────────────────────────────────┘
```

### 2.3 ISO-on-TCP (RFC1006) 头

```
┌──────────┬──────────┬─────────────────┐
│ 版本     │ 保留     │ 长度             │
│ (1 字节) │ (1 字节) │ (2 字节)         │
└──────────┴──────────┴─────────────────┘
```

- 版本：固定为 0x03
- 保留：固定为 0x00
- 长度：整个 TPKT 包的长度（包括头部）

### 2.4 COTP 头

```
┌──────────┬──────────┬──────────┐
│ 长度     │ PDU 类型 │ 字段     │
│ (1 字节) │ (1 字节) │ (可变)   │
└──────────┴──────────┴──────────┘
```

**常见 PDU 类型：**
- 0xE0：连接请求（CR - Connect Request）
- 0xD0：连接确认（CC - Connect Confirm）
- 0xF0：数据（DT - Data）
- 0x80：断开请求（DR - Disconnect Request）

### 2.5 S7 PDU 结构

S7 数据报文的头部结构：

```
┌──────────────┬──────────────┬──────────────┐
│ 协议标识     │ 消息类型     │ 保留         │
│ (1 字节)     │ (1 字节)     │ (2 字节)     │
├──────────────┼──────────────┼──────────────┤
│ PDU 参考     │ 参数长度     │ 数据长度     │
│ (2 字节)     │ (2 字节)     │ (2 字节)     │
├──────────────┴──────────────┴──────────────┤
│ 参数区 (Parameter)                         │
├────────────────────────────────────────────┤
│ 数据区 (Data)                              │
└────────────────────────────────────────────┘
```

**关键字段：**

| 字段 | 说明 |
|------|------|
| 协议标识 | 固定为 0x32 |
| 消息类型 | 0x01=请求, 0x02=响应, 0x03=用户数据 |
| PDU 参考 | 请求/响应匹配标识 |
| 参数长度 | 参数区长度 |
| 数据长度 | 数据区长度 |

### 2.6 常用 S7 功能（Function Code）

| 功能码 | 名称 | 说明 |
|--------|------|------|
| 0x04 | 读变量（Read Var） | 读取数据块/输入/输出/存储器 |
| 0x05 | 写变量（Write Var） | 写入数据块/输入/输出/存储器 |
| 0x00 | 设置通信（Setup） | 协商 PDU 大小 |
| 0x1A | 读 SZL（系统状态列表） | 读取系统信息 |
| 0x28 | 块功能 | 上传/下载程序块 |
| 0x29 | PLC 控制 | 启动/停止 PLC |
| 0xF0 | 编程器通信 | 编程、调试功能 |

### 2.7 S7 通信流程示例

**建立连接 → 读取数据的完整流程：**

```
客户端 (HMI/编程器)                    服务器 (PLC)
     │                                     │
     ├────── TCP 三次握手 ────────────────▶│
     │                                     │
     ├────── CR (连接请求) ───────────────▶│
     │  ISO-on-TCP + COTP CR               │
     │                                     │
     │◀───── CC (连接确认) ────────────────┤
     │  ISO-on-TCP + COTP CC               │
     │                                     │
     ├────── Setup Communication ─────────▶│
     │  S7 功能码 0x00                     │
     │  协商 PDU 大小                      │
     │                                     │
     │◀───── Setup 响应 ───────────────────┤
     │                                     │
     ├────── Read Var 请求 ───────────────▶│
     │  S7 功能码 0x04                     │
     │  读取 DB1.DBW0 (1个数据字)          │
     │                                     │
     │◀───── Read Var 响应 ────────────────┤
     │  返回数据值 0x1234                   │
     │                                     │
     ├────── TCP 关闭 ────────────────────▶│
```

### 2.8 读取数据块（Read Var）详解

**请求报文参数区：**
```
功能码: 0x04
条目数: 0x01 (读取 1 个变量)

地址说明 (每个变量 12 字节):
  规范类型: 0x12 (ANY 类型)
  语法类型: 0x10 (S7 基本类型)
  长度:     0x00 0x02 (2 字节 = 1 个字)
  地址类型: 0x84 (数据块 DB)
  DB号:    0x00 0x01 (DB1)
  起始地址: 0x00 0x00 0x00 (偏移 0 字节)
```

**地址类型码：**
- 0x81：输入区（I）
- 0x82：输出区（Q）
- 0x83：存储器区（M）
- 0x84：数据块（DB）
- 0x1D：计数器（C）
- 0x1C：定时器（T）

### 2.9 S7 协议安全风险

**1. 弱认证或无认证**
- S7-200/300/400 基本没有认证机制
- S7-1200/1500 虽有认证机制，但存在已知绕过漏洞
- 知道 IP 地址就可以读写 PLC 数据

**2. 明文传输**
- 所有数据和指令明文传输
- 抓包即可获取程序、数据、密码
- 可被中间人篡改

**3. 程序上传下载风险**
- 攻击者可以上传恶意程序到 PLC
- 可以下载 PLC 中的程序进行分析
- 可以修改控制逻辑

**4. PLC 启停控制**
- 可以远程将 PLC 切换到 STOP 模式
- 导致生产线停机
- 严重影响生产

**5. 已知漏洞**
- CVE-2019-13944：S7-1200/1500 认证绕过
- CVE-2020-15782：S7-1200/1500 内存损坏
- CVE-2022-38465：S7-1200/1500 拒绝服务

## 三、DNP3 协议

### 3.1 DNP3 协议概述

DNP3（Distributed Network Protocol 3）是电力系统中广泛使用的通信协议，主要用于 SCADA 系统与远程终端单元（RTU）之间的通信。

**特点：**
- 设计用于恶劣通信环境（高误码率、低带宽）
- 支持主站-从站模式（Master-Outstation）
- 支持多种传输介质（串行、TCP、UDP）
- 具有时间同步和事件数据传输机制
- 支持安全认证（可选）

**应用行业：**
- 电力系统（配电自动化、变电站）
- 水务系统（泵站、管网）
- 石油天然气（管线监控）
- 交通信号控制

### 3.2 DNP3 帧结构

**数据链路层帧：**

```
┌──────────┬──────────┬──────────┬──────────┬──────────┐
│ 起始字节 │ 长度     │ 控制字段 │ 目的地址 │ 源地址   │
│ 0x05 0x64│ (1 字节) │ (1 字节) │ (2 字节) │ (2 字节) │
├──────────┴──────────┴──────────┴──────────┴──────────┤
│ 数据区 (可变)                                         │
├───────────────────────────────────────────────────────┤
│ CRC 校验 (每 16 字节数据一个 CRC)                     │
└───────────────────────────────────────────────────────┘
```

**起始字节：** 固定为 `0x05 0x64`

**控制字段（FCV/FCB/功能码）：**
```
bit 7: 保留
bit 6: FCB (Frame Count Bit) - 帧计数位
bit 5: FCV (Frame Count Valid) - 帧计数有效位
bit 4-0: 功能码
```

### 3.3 DNP3 功能码

| 功能码 | 主站→从站 | 从站→主站 | 名称 |
|--------|----------|----------|------|
| 0 | 是 | - | 确认（ACK） |
| 1 | 是 | - | 读（Read） |
| 2 | 是 | - | 写（Write） |
| 3 | 是 | - | 选择（Select） |
| 4 | 是 | - | 操作（Operate） |
| 5 | 是 | - | 直接操作（Direct Operate） |
| 6 | 是 | - | 直接操作（无应答） |
| 7 | 是 | - | 冻结命令 |
| 8 | 是 | - | 冻结并清除 |
| 9 | 是 | - | 冻结带时间 |
| 10 | 是 | - | 冷重启 |
| 11 | 是 | - | 热重启 |
| 12 | 是 | - | 停止应用 |
| 13 | 是 | - | 保存配置 |
| 14 | 是 | - | 启用/禁用自发报告 |
| 15 | 是 | - | 延迟测量 |
| - | - | 129 | 响应（Response） |
| - | - | 130 | 自发响应（Unsolicited Response） |

### 3.4 DNP3 数据对象

DNP3 定义了丰富的数据对象类型：

| 组号 | 对象类型 | 说明 |
|------|---------|------|
| 组 1 | 二进制输入 | 开关量输入状态 |
| 组 2 | 二进制输入事件 | 开关量变化事件 |
| 组 3 | 双位二进制输入 | 两位开关量 |
| 组 10 | 二进制输出 | 控制继电器输出块 |
| 组 11 | 二进制输出命令 | 控制输出命令 |
| 组 20 | 模拟输入 | 模拟量测量值 |
| 组 21 | 模拟输入事件 | 模拟量变化事件 |
| 组 30 | 模拟输入（浮点） | 浮点型模拟量 |
| 组 40 | 模拟输出 | 模拟输出（设定值） |
| 组 41 | 模拟输出命令 | 模拟输出命令 |
| 组 50 | 时间和日期 | 时间同步 |
| 组 70 | 文件传输 | 文件操作 |
| 组 80 | 内部指示位 | 设备状态指示 |
| 组 120-127 | 安全认证 | 安全相关功能 |

### 3.5 DNP3 安全机制

DNP3 v5 增加了安全认证机制（Secure Authentication）：

**功能：**
- 基于挑战-应答的认证机制
- 使用 HMAC-SHA1/SHA256
- 支持密钥管理
- 支持用户权限管理

**安全对象组：**
- 组 120：认证查询
- 组 121：认证挑战
- 组 122：认证回复
- 组 123：密钥状态
- 组 124：密钥配置
- 组 125：用户统计
- 组 126：认证命令

**实际情况：**
- 很多现场设备不启用安全认证
- 安全认证增加了配置复杂度
- 老旧设备不支持 DNP3 v5

### 3.6 DNP3 安全风险

**1. 安全认证可选**
- 很多部署未启用安全认证
- 默认配置不安全
- 攻击者可直接发送控制命令

**2. 明文传输**
- 数据和命令明文传输
- 可被窃听和篡改
- 无加密机制

**3. 控制命令风险**
- 写操作可直接控制输出
- 可操作断路器、阀门等设备
- 可能造成严重后果

**4. 已知漏洞**
- DNP3 实现栈的各种漏洞
- 畸形报文导致拒绝服务
- 缓冲区溢出漏洞

## 四、IEC 60870-5-104 协议

### 4.1 IEC 104 概述

IEC 60870-5-104（简称 IEC 104）是国际电工委员会制定的电力系统远动通信协议标准，是 IEC 60870-5-101 的网络传输版本。

**特点：**
- 基于 TCP/IP 传输
- 使用端口号 2404
- 主站-子站架构（控制站-被控站）
- 广泛应用于电力调度自动化系统
- 中国电力行业普遍使用

**协议家族：**
- IEC 60870-5-101：串行链路版本（RTU/FT1.2）
- IEC 60870-5-102：电能计量传输
- IEC 60870-5-103：继电保护设备通信
- IEC 60870-5-104：网络版（TCP/IP）
- IEC 60870-5-105：配套标准导则

### 4.2 IEC 104 协议栈

```
┌─────────────────────────────────────────┐
│     IEC 60870-5-101 应用层（ASDU）      │ ← 应用数据
├─────────────────────────────────────────┤
│     应用规约控制（APCI）                 │ ← 链路层功能
├─────────────────────────────────────────┤
│     TCP (端口 2404)                     │ ← 传输层
├─────────────────────────────────────────┤
│     IP / Ethernet                       │ ← 网络/链路层
└─────────────────────────────────────────┘
```

### 4.3 APCI（应用规约控制信息）

```
┌─────────────────────────────────────────┐
│ 启动字符 0x68 (1 字节)                  │
├─────────────────────────────────────────┤
│ APDU 长度 (1 字节)                      │
├─────────────────────────────────────────┤
│ 控制域 (4 字节)                         │
├─────────────────────────────────────────┤
│ ASDU (应用服务数据单元) [可选]          │
└─────────────────────────────────────────┘
```

**控制域格式（三种类型）：**

**类型 1：I 格式（信息传输）**
```
bit 0: 0 (标识 I 格式)
bit 1-7: 发送序列号 N(S) (低7位)
bit 8: 0
bit 9-15: 接收序列号 N(R) (低7位)
```
用于传输应用数据（ASDU）

**类型 2：S 格式（监视）**
```
bit 0: 1
bit 1: 0 (标识 S 格式)
bit 2-7: 0
bit 8: 0
bit 9-15: 接收序列号 N(R) (低7位)
```
用于确认收到的 I 帧

**类型 3：U 格式（未编号）**
```
bit 0: 1
bit 1: 1 (标识 U 格式)
bit 2: TESTFR 测试命令
bit 3: STOPDT 停止数据传输
bit 4: STARTDT 启动数据传输
bit 5-7: 其他标志
```
用于链路控制（启动、停止、测试）

### 4.4 ASDU（应用服务数据单元）

```
┌──────────────┬──────────────┬──────────────┐
│ 类型标识     │ 可变结构限定词│ 传送原因     │
│ TypeID       │ VSQ          │ COT          │
│ (1 字节)     │ (1 字节)     │ (2 字节)     │
├──────────────┴──────────────┴──────────────┤
│ 应用服务数据单元公共地址                     │
│ ASDU Address (2 字节)                      │
├────────────────────────────────────────────┤
│ 信息体 (Information Objects)               │
│ (可变长度)                                  │
└────────────────────────────────────────────┘
```

**常用类型标识（TypeID）：**

| TypeID | 名称 | 说明 |
|--------|------|------|
| M_SP_NA_1 (1) | 单点信息 | 单个开关量状态 |
| M_DP_NA_1 (3) | 双点信息 | 双位开关量状态 |
| M_ME_NC_1 (13) | 测量值（浮点） | 模拟量测量值（短浮点数） |
| M_ME_TF_1 (36) | 带CP56Time2a的测量值 | 带时间标记的测量值 |
| C_SC_NA_1 (45) | 单点命令 | 单命令控制（合/分） |
| C_DC_NA_1 (46) | 双点命令 | 双命令控制 |
| C_RC_NA_1 (47) | 步调节命令 | 升降控制 |
| C_SE_NA_1 (48) | 设定值（归一化） | 模拟设定值 |
| C_SE_TA_2 (49) | 设定值（标度化） | 标度化设定值 |
| C_SE_NB_1 (50) | 设定值（短浮点数） | 浮点设定值 |
| M_EI_NA_1 (70) | 初始化结束 | 设备初始化完成 |
| C_IC_NA_1 (100) | 总召唤命令 | 召唤所有数据 |
| C_CS_NA_1 (103) | 时钟同步命令 | 对时命令 |
| C_RP_NA_1 (105) | 复位进程 | 复位命令 |
| P_ME_NA_1 (110) | 参数（归一化） | 参数设置 |
| P_ME_NC_1 (112) | 参数（短浮点数） | 浮点参数设置 |

### 4.5 IEC 104 通信流程

```
主站（调度端）                         子站（厂站端）
     │                                     │
     ├──── TCP 连接请求 ─────────────────▶│
     │                                     │
     │◀─── TCP 连接确认 ──────────────────┤
     │                                     │
     ├──── STARTDT (启动数据传输) ────────▶│
     │  U 格式，启动命令                   │
     │                                     │
     │◀─── STARTDT 确认 ──────────────────┤
     │  U 格式，确认启动                   │
     │                                     │
     ├──── 总召唤 (C_IC_NA_1) ───────────▶│
     │  Type=100，召唤所有数据            │
     │                                     │
     │◀─── 总召唤确认 ────────────────────┤
     │  传送原因=7 (激活确认)             │
     │                                     │
     │◀─── 数据上送 ──────────────────────┤
     │  各类数据（遥信、遥测、电度等）     │
     │                                     │
     │◀─── 总召唤结束 ────────────────────┤
     │  传送原因=10 (激活终止)            │
     │                                     │
     ├──── 遥控命令 (C_SC_NA_1) ─────────▶│
     │  选择/执行命令                      │
     │                                     │
     │◀─── 遥控确认 ──────────────────────┤
     │  命令执行结果                       │
```

### 4.6 IEC 104 安全风险

**1. 无认证机制**
- 建立连接后即可发送控制命令
- 没有身份验证
- 攻击者可伪装成主站

**2. 明文传输**
- 所有数据明文传输
- 可被窃听和篡改
- 控制命令可被截获修改

**3. 遥控命令风险**
- 遥控命令直接控制开关/断路器
- 虽然有选择-执行机制，但无认证
- 攻击者可伪造遥控命令

**4. 对时攻击**
- 篡改时钟同步命令
- 导致设备时间错误
- 影响数据时间戳和事件顺序

**5. 拒绝服务**
- 大量连接请求耗尽资源
- 畸形报文导致设备崩溃
- 大量数据报文导致拥塞

## 五、OPC UA 协议

### 5.1 OPC UA 概述

OPC UA（Open Platform Communications Unified Architecture，开放平台通信统一架构）是 OPC 基金会推出的新一代工业通信标准，是 OPC 经典（DA/AE/HDA）的继承者。

**与经典 OPC 的区别：**

| 特性 | 经典 OPC (DA/AE/HDA) | OPC UA |
|------|----------------------|--------|
| 平台依赖 | Windows 平台（依赖 COM/DCOM） | 跨平台（Windows/Linux/嵌入式） |
| 安全机制 | 依赖 DCOM 安全，很弱 | 内置安全机制（认证/加密/签名） |
| 数据模型 | 简单的标签-值模型 | 丰富的面向对象模型 |
| 通信方式 | COM/DCOM | TCP/HTTP/HTTPS 多种传输 |
| 防火墙友好 | 不友好（DCOM 端口动态） | 友好（固定端口） |
| 互操作性 | 较差 | 标准化程度高 |

**OPC UA 的核心优势：**
- 平台无关性
- 内置安全机制
- 统一的数据模型
- 支持多种传输协议
- 面向服务的架构

### 5.2 OPC UA 架构

```
┌─────────────────────────────────────────┐
│           OPC UA 应用层                 │
│  数据访问 / 报警事件 / 历史数据 / 方法  │
├─────────────────────────────────────────┤
│           OPC UA 服务层                 │
│  会话服务 / 节点管理 / 订阅服务         │
├─────────────────────────────────────────┤
│           OPC UA 通信层                 │
│  UA TCP / UA HTTPS / UA WebSocket      │
├─────────────────────────────────────────┤
│           传输层 (TCP / HTTPS)          │
└─────────────────────────────────────────┘
```

### 5.3 OPC UA 安全模型

OPC UA 定义了完整的安全模型，包括：

**安全策略（Security Policy）：**
| 安全策略 | 说明 |
|----------|------|
| None | 无安全（明文，无认证） |
| Basic128Rsa15 | 基本安全（RSA-15 密钥，128位加密） |
| Basic256 | 256位加密 |
| Basic256Sha256 | SHA-256 哈希 + 256位加密 |
| Aes128_Sha256_RsaOaep | AES-128 + SHA-256 + RSA-OAEP |
| Aes256_Sha256_RsaPss | AES-256 + SHA-256 + RSA-PSS |

**安全模式（Security Mode）：**
- `None`：无安全
- `Sign`：仅签名（验证完整性和身份）
- `SignAndEncrypt`：签名并加密（最安全）

**用户认证方式：**
- 匿名（Anonymous）
- 用户名/密码（Username/Password）
- X.509 证书
- 颁发的令牌（如 JWT）

### 5.4 OPC UA 地址空间模型

OPC UA 使用节点（Node）和引用（Reference）构建地址空间：

```
对象 (Object)
  ├── 变量 (Variable) → 数据值
  ├── 方法 (Method)   → 可调用的函数
  ├── 对象 (Object)   → 子对象
  └── ...

节点属性：
  - NodeId: 节点唯一标识
  - NodeClass: 节点类型（对象/变量/方法/视图等）
  - BrowseName: 浏览名称
  - DisplayName: 显示名称
  - Description: 描述
  - Value: 值（仅变量节点）
  - DataType: 数据类型
```

### 5.5 OPC UA 服务

OPC UA 定义了丰富的服务集：

| 服务集 | 主要服务 | 说明 |
|--------|---------|------|
| 发现服务 | FindServers, GetEndpoints | 发现服务器和端点 |
| 会话服务 | CreateSession, ActivateSession | 创建和激活会话 |
| 节点管理 | Browse, Read, Write | 浏览和读写节点 |
| 订阅服务 | CreateSubscription, Publish | 数据订阅和发布 |
| 监控项 | CreateMonitoredItems | 监控数据变化 |
| 方法服务 | Call | 调用方法 |
| 历史数据 | HistoryRead, HistoryUpdate | 读写历史数据 |
| 报警事件 | EventSubscription, Condition | 事件和报警 |

### 5.6 OPC UA 安全风险

**1. 配置不当风险**
- 很多部署使用默认配置（无安全模式）
- 管理员安全意识不足
- 证书管理不当

**2. 匿名访问风险**
- 启用匿名访问
- 攻击者可直接读取所有数据
- 可调用敏感方法

**3. 证书漏洞**
- 自签名证书未验证
- 过期证书继续使用
- 私钥泄露

**4. 已知漏洞**
- OPC UA 实现库的漏洞
- 栈溢出、空指针引用
- 认证绕过漏洞

**5. 横向移动风险**
- OPC UA 服务器连接多个 PLC
- 攻破 OPC UA 服务器即可控制大量设备
- 作为横向移动的跳板

4. 提取关键数据（寄存器值、控制命令等）

- 统计通信模式（周期/事件）

- 查看设备间通信关系
- 识别异常通信对

- File → Export Packet Dissections
- 导出为 CSV/JSON 进行进一步分析

### 6.2 Scapy 协议分析

Scapy 是 Python 的数据包操作库，可以用于构造和解析工业协议报文。

**安装：**
```bash
pip install scapy
```

**Modbus TCP 报文构造示例：**
```python
from scapy.all import *
from scapy.contrib.modbus import *

# 构造 Modbus TCP 读保持寄存器请求
# 功能码 0x03，读取 40001 开始的 10 个寄存器
pkt = IP(dst="192.168.1.100")/TCP(dport=502)/ModbusADU()/ModbusPDU03ReadHoldingRegisters(
    startAddr=0x0000,  # 起始地址 0 (对应 40001)
    quantity=10        # 读取 10 个寄存器
)

# 发送并接收响应
resp = sr1(pkt, timeout=2)
if resp and resp.haslayer(ModbusPDU03ReadHoldingRegisters):
    print(f"寄存器值: {resp[ModbusPDU03ReadHoldingRegisters].registerVal}")
```

## 七、协议漏洞与安全风险

### 7.1 工控协议漏洞分类

#### 7.1.1 认证绕过漏洞

**漏洞描述：** 协议缺乏认证机制或认证机制存在缺陷，攻击者可以绕过认证直接发送控制指令。

**典型案例：**
- Modbus 无认证
- S7comm 弱认证或无认证
- 各种协议的认证绕过漏洞

**危害：**
- 攻击者可直接控制设备
- 读取所有敏感数据
- 修改控制参数
- 造成生产事故

#### 7.1.2 缓冲区溢出漏洞

**漏洞描述：** 协议解析代码对输入长度检查不足，导致缓冲区溢出。

**成因：**
- 嵌入式设备资源有限，开发时忽视安全
- 协议实现代码质量不高
- 缺乏安全编码规范

**危害：**
- 远程代码执行
- 设备崩溃（拒绝服务）
- 设备被完全控制

#### 7.1.3 拒绝服务漏洞

**漏洞描述：** 畸形报文或大量请求导致设备资源耗尽，无法正常工作。

**类型：**
- 协议 Flood 攻击
- 畸形报文崩溃
- 资源耗尽（连接数、内存、CPU）
- 协议状态机异常

**危害：**
- 设备不可用
- 生产中断
- 需要现场重启恢复

#### 7.1.4 信息泄露漏洞

**漏洞描述：** 协议响应中包含敏感信息，攻击者可获取设备配置、程序、数据等。

**类型：**
- 设备信息探测（型号、版本、配置）
- 生产数据泄露
- 程序代码泄露
- 密码或密钥泄露

#### 7.1.5 命令注入漏洞

**漏洞描述：** 协议参数未经过滤，被拼接到系统命令中执行。

**常见场景：**
- 诊断功能
- 文件操作
- 配置管理
- 维护接口

### 7.3 协议攻击方法

#### 7.3.1 中间人攻击（MITM）

**原理：** 攻击者位于通信双方之间，拦截并篡改通信数据。

```
正常通信： 主站 ──────────────── 从站
中间人攻击：主站 ─── 攻击者 ─── 从站
            拦截、篡改、伪造
```

**攻击步骤：**
1. ARP 欺骗或其他方式进入通信路径
2. 拦截正常通信数据
3. 修改控制指令或数据值
4. 转发给对端，保持通信正常

**危害：**
- 控制指令被篡改
- 数据被伪造
- 监控显示虚假数据
- 隐蔽性强，难以发现

#### 7.3.2 重放攻击

**原理：** 截获合法的控制指令，在需要时重新发送。

**攻击步骤：**
1. 抓包收集正常通信数据
2. 识别控制指令报文
3. 在适当的时机重新发送
4. 触发非法操作

**危害：**
- 重复执行控制指令
- 利用合法身份执行非法操作
- 绕过简单的认证机制

#### 7.3.3 扫描探测

**原理：** 通过发送协议请求来发现设备和收集信息。

**常用扫描：**
- 端口扫描（发现工控设备）
- 协议识别（确认协议类型）
- 设备信息探测（型号、版本）
- 数据读取（获取寄存器值）

**工具：**
- Nmap + NSE 脚本
- 专用工控扫描器
- 自定义脚本

#### 7.3.4 模糊测试

**原理：** 发送大量畸形报文，发现协议实现漏洞。

**Fuzz 策略：**
- 随机变异
- 边界值测试
- 格式破坏
- 状态机模糊

## 八、实践建议

### 8.1 学习路径

1. **从 Modbus 开始**：最简单、最通用，容易理解
2. **学习 S7 协议**：西门子设备应用广泛，资料较多
3. **深入电力协议**：DNP3、IEC 104 等电力行业协议
4. **学习 OPC UA**：新一代协议，安全机制完善
5. **协议逆向**：学习未知协议的分析方法

### 8.2 实践环境

- **Modbus 模拟器**：Modbus Poll / Modbus Slave
- **PLC 模拟器**：PLCSIM Advanced、各种开源模拟器
- **OPC UA 服务器/客户端**：UA Expert、open62541
- **抓包工具**：Wireshark（必须）
- **编程工具**：Python + Scapy

### 8.3 安全提示

- 协议分析务必在测试环境中进行
- 不要对真实生产设备进行模糊测试
- 工控协议攻击可能导致严重后果
- 学习协议安全是为了防护，不是攻击
