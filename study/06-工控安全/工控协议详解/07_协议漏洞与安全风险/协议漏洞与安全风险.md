# 协议漏洞与安全风险

### 7.1 工控协议漏洞分类

#### 7.1.1 认证绕过漏洞

**漏洞描述：** 协议缺乏认证机制或认证机制存在缺陷，攻击者可以绕过认证直接发送控制指令。

**典型案例：**
- Modbus 无认证
- S7comm 弱认证或无认证
- 各种协议的认证绕过漏洞

**危害：**
- 攻击者可直接控制设备
- 读取所有敏感数据
- 修改控制参数
- 造成生产事故

#### 7.1.2 缓冲区溢出漏洞

**漏洞描述：** 协议解析代码对输入长度检查不足，导致缓冲区溢出。

**成因：**
- 嵌入式设备资源有限，开发时忽视安全
- 协议实现代码质量不高
- 缺乏安全编码规范

**危害：**
- 远程代码执行
- 设备崩溃（拒绝服务）
- 设备被完全控制

#### 7.1.3 拒绝服务漏洞

**漏洞描述：** 畸形报文或大量请求导致设备资源耗尽，无法正常工作。

**类型：**
- 协议 Flood 攻击
- 畸形报文崩溃
- 资源耗尽（连接数、内存、CPU）
- 协议状态机异常

**危害：**
- 设备不可用
- 生产中断
- 需要现场重启恢复

#### 7.1.4 信息泄露漏洞

**漏洞描述：** 协议响应中包含敏感信息，攻击者可获取设备配置、程序、数据等。

**类型：**
- 设备信息探测（型号、版本、配置）
- 生产数据泄露
- 程序代码泄露
- 密码或密钥泄露

#### 7.1.5 命令注入漏洞

**漏洞描述：** 协议参数未经过滤，被拼接到系统命令中执行。

**常见场景：**
- 诊断功能
- 文件操作
- 配置管理
- 维护接口

### 7.3 协议攻击方法

#### 7.3.1 中间人攻击（MITM）

**原理：** 攻击者位于通信双方之间，拦截并篡改通信数据。

```
正常通信： 主站 ──────────────── 从站
中间人攻击：主站 ─── 攻击者 ─── 从站
            拦截、篡改、伪造
```

**攻击步骤：**
1. ARP 欺骗或其他方式进入通信路径
2. 拦截正常通信数据
3. 修改控制指令或数据值
4. 转发给对端，保持通信正常

**危害：**
- 控制指令被篡改
- 数据被伪造
- 监控显示虚假数据
- 隐蔽性强，难以发现

#### 7.3.2 重放攻击

**原理：** 截获合法的控制指令，在需要时重新发送。

**攻击步骤：**
1. 抓包收集正常通信数据
2. 识别控制指令报文
3. 在适当的时机重新发送
4. 触发非法操作

**危害：**
- 重复执行控制指令
- 利用合法身份执行非法操作
- 绕过简单的认证机制

#### 7.3.3 扫描探测

**原理：** 通过发送协议请求来发现设备和收集信息。

**常用扫描：**
- 端口扫描（发现工控设备）
- 协议识别（确认协议类型）
- 设备信息探测（型号、版本）
- 数据读取（获取寄存器值）

**工具：**
- Nmap + NSE 脚本
- 专用工控扫描器
- 自定义脚本

#### 7.3.4 模糊测试

**原理：** 发送大量畸形报文，发现协议实现漏洞。

**Fuzz 策略：**
- 随机变异
- 边界值测试
- 格式破坏
- 状态机模糊
