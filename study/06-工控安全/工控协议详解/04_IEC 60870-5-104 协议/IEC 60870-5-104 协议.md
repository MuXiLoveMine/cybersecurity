# IEC 60870-5-104 协议

### 4.1 IEC 104 概述

IEC 60870-5-104（简称 IEC 104）是国际电工委员会制定的电力系统远动通信协议标准，是 IEC 60870-5-101 的网络传输版本。

**特点：**
- 基于 TCP/IP 传输
- 使用端口号 2404
- 主站-子站架构（控制站-被控站）
- 广泛应用于电力调度自动化系统
- 中国电力行业普遍使用

**协议家族：**
- IEC 60870-5-101：串行链路版本（RTU/FT1.2）
- IEC 60870-5-102：电能计量传输
- IEC 60870-5-103：继电保护设备通信
- IEC 60870-5-104：网络版（TCP/IP）
- IEC 60870-5-105：配套标准导则

### 4.2 IEC 104 协议栈

```
┌─────────────────────────────────────────┐
│     IEC 60870-5-101 应用层（ASDU）      │ ← 应用数据
├─────────────────────────────────────────┤
│     应用规约控制（APCI）                 │ ← 链路层功能
├─────────────────────────────────────────┤
│     TCP (端口 2404)                     │ ← 传输层
├─────────────────────────────────────────┤
│     IP / Ethernet                       │ ← 网络/链路层
└─────────────────────────────────────────┘
```

### 4.3 APCI（应用规约控制信息）

```
┌─────────────────────────────────────────┐
│ 启动字符 0x68 (1 字节)                  │
├─────────────────────────────────────────┤
│ APDU 长度 (1 字节)                      │
├─────────────────────────────────────────┤
│ 控制域 (4 字节)                         │
├─────────────────────────────────────────┤
│ ASDU (应用服务数据单元) [可选]          │
└─────────────────────────────────────────┘
```

**控制域格式（三种类型）：**

**类型 1：I 格式（信息传输）**
```
bit 0: 0 (标识 I 格式)
bit 1-7: 发送序列号 N(S) (低7位)
bit 8: 0
bit 9-15: 接收序列号 N(R) (低7位)
```
用于传输应用数据（ASDU）

**类型 2：S 格式（监视）**
```
bit 0: 1
bit 1: 0 (标识 S 格式)
bit 2-7: 0
bit 8: 0
bit 9-15: 接收序列号 N(R) (低7位)
```
用于确认收到的 I 帧

**类型 3：U 格式（未编号）**
```
bit 0: 1
bit 1: 1 (标识 U 格式)
bit 2: TESTFR 测试命令
bit 3: STOPDT 停止数据传输
bit 4: STARTDT 启动数据传输
bit 5-7: 其他标志
```
用于链路控制（启动、停止、测试）

### 4.4 ASDU（应用服务数据单元）

```
┌──────────────┬──────────────┬──────────────┐
│ 类型标识     │ 可变结构限定词│ 传送原因     │
│ TypeID       │ VSQ          │ COT          │
│ (1 字节)     │ (1 字节)     │ (2 字节)     │
├──────────────┴──────────────┴──────────────┤
│ 应用服务数据单元公共地址                     │
│ ASDU Address (2 字节)                      │
├────────────────────────────────────────────┤
│ 信息体 (Information Objects)               │
│ (可变长度)                                  │
└────────────────────────────────────────────┘
```

**常用类型标识（TypeID）：**

| TypeID | 名称 | 说明 |
|--------|------|------|
| M_SP_NA_1 (1) | 单点信息 | 单个开关量状态 |

| M_ME_NC_1 (13) | 测量值（浮点） | 模拟量测量值（短浮点数） |
| M_ME_TF_1 (36) | 带CP56Time2a的测量值 | 带时间标记的测量值 |
| C_SC_NA_1 (45) | 单点命令 | 单命令控制（合/分） |

| C_RC_NA_1 (47) | 步调节命令 | 升降控制 |
| C_SE_NA_1 (48) | 设定值（归一化） | 模拟设定值 |
| C_SE_TA_2 (49) | 设定值（标度化） | 标度化设定值 |
| C_SE_NB_1 (50) | 设定值（短浮点数） | 浮点设定值 |
| M_EI_NA_1 (70) | 初始化结束 | 设备初始化完成 |
| C_IC_NA_1 (100) | 总召唤命令 | 召唤所有数据 |
| C_CS_NA_1 (103) | 时钟同步命令 | 对时命令 |

### 4.5 IEC 104 通信流程

```
主站（调度端）                         子站（厂站端）
     │                                     │
     ├──── TCP 连接请求 ─────────────────▶│
     │                                     │
     │◀─── TCP 连接确认 ──────────────────┤
     │                                     │
     ├──── STARTDT (启动数据传输) ────────▶│
     │  U 格式，启动命令                   │
     │                                     │
     │◀─── STARTDT 确认 ──────────────────┤
     │  U 格式，确认启动                   │
     │                                     │
     ├──── 总召唤 (C_IC_NA_1) ───────────▶│
     │  Type=100，召唤所有数据            │
     │                                     │
     │◀─── 总召唤确认 ────────────────────┤
     │  传送原因=7 (激活确认)             │
     │                                     │
     │◀─── 数据上送 ──────────────────────┤
     │  各类数据（遥信、遥测、电度等）     │
     │                                     │
     │◀─── 总召唤结束 ────────────────────┤
     │  传送原因=10 (激活终止)            │
     │                                     │
     ├──── 遥控命令 (C_SC_NA_1) ─────────▶│
     │  选择/执行命令                      │
     │                                     │
     │◀─── 遥控确认 ──────────────────────┤
     │  命令执行结果                       │
```

### 4.6 IEC 104 安全风险

**1. 无认证机制**
- 建立连接后即可发送控制命令
- 没有身份验证
- 攻击者可伪装成主站

**2. 明文传输**
- 所有数据明文传输
- 可被窃听和篡改
- 控制命令可被截获修改

**3. 遥控命令风险**
- 遥控命令直接控制开关/断路器
- 虽然有选择-执行机制，但无认证
- 攻击者可伪造遥控命令

**4. 对时攻击**
- 篡改时钟同步命令
- 导致设备时间错误
- 影响数据时间戳和事件顺序

**5. 拒绝服务**
- 大量连接请求耗尽资源
- 畸形报文导致设备崩溃
- 大量数据报文导致拥塞
