# Modbus TCP/RTU 协议详解

### 1.1 Modbus 协议概述

Modbus 是由 Modicon（现施耐德）于 1979 年开发的工业通信协议，是工业领域应用最广泛的协议之一。

**协议变体：**

| 变体 | 传输介质 | 数据链路 | 典型应用 |
|------|---------|---------|---------|
| Modbus RTU | 串行（RS-485/232） | 二进制编码，CRC 校验 | 现场设备通信 |
| Modbus ASCII | 串行（RS-485/232） | ASCII 编码，LRC 校验 | 调试、简单设备 |
| Modbus TCP | 以太网 | TCP/IP 封装 | 工业以太网 |
| Modbus UDP | 以太网 | UDP/IP 封装 | 较少使用 |
| Modbus Plus | 专用令牌网 | 高速令牌传递 | 施耐德专用 |

### 1.2 Modbus 数据模型

Modbus 定义了四种基本数据类型：

| 数据类型 | 访问方式 | 大小 | 功能码示例 |
|----------|---------|------|-----------|
| **线圈（Coils）** | 读/写 | 1 bit（布尔量） | 01 读、05 写单个、15 写多个 |
| **离散输入（Discrete Inputs）** | 只读 | 1 bit（布尔量） | 02 读 |
| **保持寄存器（Holding Registers）** | 读/写 | 16 bit（字） | 03 读、06 写单个、16 写多个 |
| **输入寄存器（Input Registers）** | 只读 | 16 bit（字） | 04 读 |

**地址空间：**
```
线圈地址：        00001 ~ 09999  (0x0000 ~ 0x270F)
离散输入地址：    10001 ~ 19999  (0x0000 ~ 0x270F)
输入寄存器地址：  30001 ~ 39999  (0x0000 ~ 0x270F)
保持寄存器地址：  40001 ~ 49999  (0x0000 ~ 0x270F)
```

> 注意：Modbus 协议中的地址是从 0 开始的（0-based），而文档中常用的地址编号是从 1 开始的（1-based）。例如保持寄存器 40001 对应的协议地址是 0x0000。

### 1.3 Modbus RTU 帧格式

Modbus RTU 使用二进制编码，帧结构如下：

```
┌────────────┬────────────┬─────────────────┬──────────┐
│ 从站地址   │ 功能码     │ 数据             │ CRC 校验 │
│ (1 字节)   │ (1 字节)   │ (N 字节)         │ (2 字节) │
└────────────┴────────────┴─────────────────┴──────────┘
```

**字段说明：**
- **从站地址**：1 字节，范围 1-247（0 为广播地址）
- **功能码**：1 字节，指示操作类型
- **数据**：变长，包含寄存器地址、数量、数据值等
- **CRC**：2 字节，循环冗余校验，低字节在前（小端序）

**示例：读取保持寄存器（功能码 03）**

请求帧（读取从站 1 的 40001-40002 寄存器）：
```
从站地址: 0x01
功能码:   0x03
起始地址: 0x00 0x00 (寄存器 40001)
寄存器数: 0x00 0x02 (读取 2 个)
CRC:      0x84 0x0A

完整帧: 01 03 00 00 00 02 84 0A
```

响应帧：
```
从站地址: 0x01
功能码:   0x03
字节计数: 0x04 (2个寄存器 × 2字节 = 4字节)
数据值:   0x12 0x34 (寄存器1值 = 0x1234)
          0x56 0x78 (寄存器2值 = 0x5678)
CRC:      0x?? 0x??

完整帧: 01 03 04 12 34 56 78 ?? ??
```

### 1.4 Modbus TCP 帧格式

Modbus TCP 在 TCP/IP 上传输，增加了 MBAP 头（Modbus Application Protocol Header）：

```
┌───────────────────────────────────────────────────────────┐
│                     MBAP 头 (7 字节)                      │
├──────────┬──────────┬──────────┬───────────┬─────────────┤
│ 事务标识 │ 协议标识 │ 长度     │ 单元标识  │ PDU 数据    │
│ (2 字节) │ (2 字节) │ (2 字节) │ (1 字节)  │ (N 字节)   │
└──────────┴──────────┴──────────┴───────────┴─────────────┘
                                 └──────┬──────┘
                                        │
                                   Modbus PDU
                        (功能码 + 数据，与 RTU 相同)
```

**MBAP 头字段说明：**

| 字段 | 长度 | 说明 |
|------|------|------|
| 事务标识符（Transaction ID） | 2 字节 | 请求/响应匹配，由客户端生成 |
| 协议标识符（Protocol ID） | 2 字节 | 固定为 0x0000（表示 Modbus） |
| 长度（Length） | 2 字节 | 后续字段的字节数（单元标识 + PDU） |
| 单元标识符（Unit ID） | 1 字节 | 从站地址 / 设备标识，相当于 RTU 的从站地址 |

**示例：Modbus TCP 读取保持寄存器**

请求报文（读取 40001-40002）：
```
事务标识: 0x00 0x01
协议标识: 0x00 0x00
长度:     0x00 0x06 (单元标识1 + 功能码1 + 起始地址2 + 数量2 = 6字节)
单元标识: 0x01
功能码:   0x03
起始地址: 0x00 0x00
寄存器数: 0x00 0x02

完整报文(十六进制): 00 01 00 00 00 06 01 03 00 00 00 02
```

响应报文：
```
事务标识: 0x00 0x01 (与请求一致)
协议标识: 0x00 0x00
长度:     0x00 0x05 (单元标识1 + 功能码1 + 字节计数1 + 数据4 = 5字节)
单元标识: 0x01
功能码:   0x03
字节计数: 0x04
寄存器1:  0x12 0x34
寄存器2:  0x56 0x78

完整报文(十六进制): 00 01 00 00 00 05 01 03 04 12 34 56 78
```

### 1.5 常用 Modbus 功能码

| 功能码 | 名称 | 数据类型 | 操作 | 说明 |
|--------|------|---------|------|------|
| 0x01 | 读线圈 | 线圈 | 读 | 读取多个线圈状态 |
| 0x02 | 读离散输入 | 离散输入 | 读 | 读取多个离散输入 |
| 0x03 | 读保持寄存器 | 保持寄存器 | 读 | 读取多个保持寄存器 |
| 0x04 | 读输入寄存器 | 输入寄存器 | 读 | 读取多个输入寄存器 |
| 0x05 | 写单个线圈 | 线圈 | 写 | 写入单个线圈 |
| 0x06 | 写单个寄存器 | 保持寄存器 | 写 | 写入单个保持寄存器 |
| 0x07 | 读异常状态 | - | 读 | 读取 8 个异常状态 |
| 0x08 | 诊断 | - | - | 诊断功能，子功能码多种 |
| 0x0B | 读事件计数 | - | 读 | 读取通信事件计数器 |
| 0x0C | 读事件日志 | - | 读 | 读取通信事件日志 |
| 0x0F | 写多个线圈 | 线圈 | 写 | 写入多个线圈 |
| 0x10 | 写多个寄存器 | 保持寄存器 | 写 | 写入多个保持寄存器 |
| 0x11 | 报告从站ID | - | 读 | 读取从站标识信息 |
| 0x14 | 读文件记录 | - | 读 | 读取文件记录 |
| 0x15 | 写文件记录 | - | 写 | 写入文件记录 |
| 0x17 | 读写多个寄存器 | 保持寄存器 | 读写 | 同时读写多个寄存器 |
| 0x2B | 封装接口传输 | - | - | 用于设备识别等扩展功能 |

### 1.6 异常响应

当从站无法正确处理请求时，返回异常响应：

```
┌────────────┬──────────────┬──────────────┐
│ 功能码     │ 异常码       │ (异常码最高位设为1)
│ (0x80 + 原功能码) │ (1 字节) │
└────────────┴──────────────┴──────────────┘
```

**常见异常码：**

| 异常码 | 名称 | 说明 |
|--------|------|------|
| 0x01 | 非法功能码 | 从站不支持该功能码 |
| 0x02 | 非法数据地址 | 请求的数据地址不存在 |
| 0x03 | 非法数据值 | 数据值超出范围或格式错误 |
| 0x04 | 从站设备故障 | 从站处理时发生错误 |
| 0x05 | 确认 | 从站已接受请求，但需要更长时间处理 |
| 0x06 | 从站忙碌 | 从站正在处理其他请求 |
| 0x08 | 存储奇偶校验错误 | 存储区数据校验错误 |
| 0x0A | 网关路径不可用 | 网关无法建立通信路径 |
| 0x0B | 网关目标设备无响应 | 目标设备未响应 |

### 1.7 Modbus 安全风险

**1. 无身份认证**
- 任何能连接到 Modbus 端口的设备都可以发送指令
- 没有用户名/密码机制
- 无法验证请求者身份

**2. 无数据加密**
- 所有数据明文传输
- 抓包即可获取所有寄存器值和控制指令
- 敏感生产数据泄露

**3. 无完整性校验（TCP 版）**
- Modbus TCP 仅依靠 TCP 校验和
- 报文在传输过程中可被篡改
- 中间人攻击可行

**4. 功能码滥用风险**
- 写入功能码（05/06/15/16）可直接控制设备
- 攻击者可以修改控制参数
- 可能导致生产事故

**5. 广播攻击**
- 地址 0 为广播地址
- 一条指令可控制所有从站
- 可用于大规模破坏

**攻击示例 - Modbus 写线圈攻击：**
```python
# 向 PLC 写入线圈，关闭所有输出
# 功能码 0x0F (15) - 写多个线圈
# 地址 0x0000 ~ 0x000F，全部置为 OFF
# 攻击者可通过此命令停止生产线
```
