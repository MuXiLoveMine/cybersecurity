# 工控安全基础

> 本文档系统介绍工业控制系统（ICS）安全的基础知识，包括工控系统概述、体系架构、常见协议、与 IT 系统的区别、安全威胁、相关标准以及著名安全事件。

---

## 一、ICS/SCADA 概述

### 1.1 基本概念

**工业控制系统（Industrial Control System, ICS）** 是一类用于控制工业生产过程的系统总称，由各种自动化控制组件和实时监测组件共同构成，其核心作用是确保工业生产的可靠性、安全性和高效性。

**SCADA（Supervisory Control And Data Acquisition）** 即数据采集与监视控制系统，是 ICS 的一种典型形态，广泛应用于电力、水利、石油、天然气、轨道交通等行业，主要用于地理分布广泛的远程监控场景。

### 1.2 工控系统的核心特点

| 特点 | 详细说明 |
|------|----------|
| **实时性要求高** | 控制响应通常在毫秒级，延迟可能导致生产事故 |
| **可用性优先** | 与 IT 系统保密性优先不同，OT 系统以可用性为第一目标 |
| **生命周期长** | 设备运行年限可达 15-30 年，远超 IT 设备 |
| **专用软硬件** | 使用专用操作系统、专用协议、专用硬件 |
| **更新困难** | 停机更新成本极高，很多系统常年不更新 |
| **物理影响大** | 安全事件可能导致物理破坏、环境污染、人员伤亡 |
| **环境特殊** | 高温、高湿、强电磁干扰等恶劣工业环境 |

### 1.3 常见工控系统类型

#### 1.3.1 SCADA 系统（数据采集与监视控制系统）

```
┌─────────────────────────────────────────────────────────┐
│                    控制中心（主站）                       │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐              │
│  │ SCADA    │  │ 历史数据 │  │ 工程师站 │              │
│  │ 服务器   │  │ 库       │  │          │              │
│  └────┬─────┘  └──────────┘  └──────────┘              │
│       │                                                 │
│  ┌────┴─────┐                                            │
│  │ 通信网关 │                                            │
│  └────┬─────┘                                            │
└───────┼──────────────────────────────────────────────────┘
        │ 广域网（光纤/无线/卫星）
        │
┌───────┼──────────────────────────────────────────────────┐
│       │              现场站点（子站）                      │
│  ┌────┴─────┐  ┌──────────┐  ┌──────────┐              │
│  │ RTU/PLC  │  │ 现场设备 │  │ 传感器   │              │
│  └──────────┘  └──────────┘  └──────────┘              │
└──────────────────────────────────────────────────────────┘
```

**特点：**
- 分布式架构，主站-子站模式
- 地理分布广泛，通过广域网连接
- 以数据采集和远程监控为主
- 典型应用：电力调度、输油管线、水利调度

#### 1.3.2 DCS 系统（分布式控制系统）

DCS（Distributed Control System）主要应用于流程工业（如化工、炼油、电力），特点是"集中管理、分散控制"。

**特点：**
- 控制功能分散到各个现场控制站
- 操作和管理集中在操作站
- 高可靠性，冗余设计
- 实时性强，闭环控制
- 典型应用：化工厂、炼油厂、发电厂

#### 1.3.3 PLC（可编程逻辑控制器）

PLC（Programmable Logic Controller）是工业控制的核心设备，专门用于工业环境的数字运算操作电子系统。

**主流 PLC 厂商：**
| 厂商 | 系列 | 典型应用行业 |
|------|------|-------------|
| 西门子（Siemens） | S7-200/S7-1200/S7-300/S7-400/S7-1500 | 汽车、化工、电力 |
| 罗克韦尔（AB） | ControlLogix/CompactLogix/PLC-5 | 汽车、食品饮料 |
| 施耐德（Schneider） | Modicon M340/M580/Quantum | 电力、水处理 |
| 三菱（Mitsubishi） | Q系列/FX系列/L系列 | 制造业、电梯 |
| 欧姆龙（OMRON） | CJ/CS/NX系列 | 汽车零部件、包装 |
| GE Fanuc | Series 90/ PACSystems | 电力、轨道交通 |

#### 1.3.4 RTU（远程终端单元）

RTU（Remote Terminal Unit）是对现场信号和设备进行监测和控制的装置，主要用于 SCADA 系统的现场端。

**与 PLC 的区别：**
- RTU 更强调远程通信能力和环境适应性
- PLC 更强调逻辑控制功能
- RTU 常用于无人值守的远程站点
- RTU 通常支持多种通信接口和协议

#### 1.3.5 其他重要系统

| 系统名称 | 英文缩写 | 作用 |
|----------|---------|------|
| 安全仪表系统 | SIS | 安全联锁保护，防止事故发生 |
| 制造执行系统 | MES | 生产过程管理，连接 ERP 和控制层 |
| 企业资源计划 | ERP | 企业级资源管理，属于 IT 层 |
| 人机界面 | HMI | 操作人员与控制系统交互的界面 |
| 历史数据库 | Historian | 存储工业过程历史数据 |

## 二、工控系统架构（Purdue 模型）

### 2.1 Purdue 模型层级详解

Purdue 模型（普渡模型）是工业控制系统的经典参考架构，将工业企业网络划分为不同层级，每层具有不同的功能和安全要求。

```
Level 5 ─────────────────────────────────────────────────
         │                 互联网
Level 4 ─────────────────────────────────────────────────
         │              企业层（ERP / 办公网）
         │           ┌─────────────────────┐
         │           │ 企业资源计划(ERP)   │
         │           │ 办公自动化系统      │
         │           │ 邮件 / 文件服务     │
         │           └─────────────────────┘
Level 3.5 ──────────── DMZ 区 ───────────────────────────
         │         （工业隔离区 / 非军事区）
         │           ┌─────────────────────┐
         │           │ 工业防火墙          │
         │           │ 数据交换服务器      │
         │           │ 远程访问网关        │
         │           └─────────────────────┘
Level 3 ─────────────────────────────────────────────────
         │            生产管理层（MES / 历史库）
         │           ┌─────────────────────┐
         │           │ 制造执行系统(MES)   │
         │           │ 实时历史数据库      │
         │           │ 生产调度系统        │
         │           └─────────────────────┘
Level 2 ─────────────────────────────────────────────────
         │             监控层（SCADA / HMI）
         │           ┌─────────────────────┐
         │           │ SCADA 服务器        │
         │           │ HMI 操作站          │
         │           │ 工程师站            │
         │           │ OPC 服务器          │
         │           └─────────────────────┘
Level 1 ─────────────────────────────────────────────────
         │             控制层（PLC / DCS 控制器）
         │           ┌─────────────────────┐
         │           │ PLC / DCS 控制器    │
         │           │ 安全控制器(SIS)     │
         │           │ 运动控制器          │
         │           └─────────────────────┘
Level 0 ─────────────────────────────────────────────────
         │            现场设备层（传感器 / 执行器）
         │           ┌─────────────────────┐
         │           │ 传感器              │
         │           │ 执行器              │
         │           │ 智能仪表            │
         │           │ 变频器 / 电机       │
         │           └─────────────────────┘
```

### 2.2 各层级详细说明

#### Level 0 - 物理层 / 现场设备层

**功能：** 直接与生产过程交互，感知物理量并执行控制指令

**设备类型：**
- 传感器：温度、压力、流量、液位、位移等
- 执行器：阀门、电机、继电器、变频器
- 智能仪表：具有通信功能的测量仪表
- 现场总线设备：连接到现场总线的各类设备

**安全特点：**
- 设备资源极其有限，计算能力弱
- 通常无法安装安全软件
- 物理接触可能导致安全问题
- 协议简单，几乎没有安全机制

#### Level 1 - 控制层

**功能：** 直接控制工业过程，运行控制逻辑

**设备类型：**
- PLC（可编程逻辑控制器）
- DCS 控制站 / 控制器
- RTU（远程终端单元）
- 安全控制器 / SIS 控制器
- 运动控制器、数控系统（CNC）

**安全特点：**
- 实时性要求极高（毫秒级响应）
- 运行专用实时操作系统
- 使用专用工业协议通信
- 固件更新困难，漏洞长期存在

#### Level 2 - 监控层

**功能：** 监视和控制生产过程，提供人机交互界面

**设备类型：**
- SCADA 服务器 / DCS 操作站
- HMI（人机界面）工作站
- 工程师站（编程组态）
- OPC 服务器
- 报警服务器

**安全特点：**
- 运行 Windows 操作系统居多
- 常年不更新补丁
- 使用工业专用软件
- 是攻击的重点目标（跳板）

#### Level 3 - 生产管理层

**功能：** 生产调度、质量管理、过程优化

**设备类型：**
- MES（制造执行系统）
- 实时历史数据库（如 PI、InfoPlus）
- 生产调度系统
- 实验室信息管理系统（LIMS）
- 工业云平台边缘节点

**安全特点：**
- 连接控制层和企业层
- 存储大量敏感生产数据
- 是横向移动的关键区域

#### Level 3.5 - DMZ 区（工业隔离区）

**功能：** 生产网与企业网之间的隔离缓冲区

**设备类型：**
- 工业防火墙
- 网闸 / 正向反向隔离装置
- 数据交换服务器
- 远程访问 VPN 网关
- 补丁服务器 / 更新服务器

**安全特点：**
- 是 IT 与 OT 的边界
- 安全防护最严格的区域
- 通常实施严格的访问控制

#### Level 4 - 企业层

**功能：** 企业级资源管理和办公

**设备类型：**
- ERP 系统（SAP、Oracle 等）
- 办公自动化系统
- 邮件服务器、文件服务器
- 企业办公终端

**安全特点：**
- 典型的 IT 环境
- 与互联网连接
- 是攻击进入工控系统的跳板

### 2.3 网络分区与防护原则

根据等保 2.0 工控扩展要求和行业实践，工控网络防护遵循以下原则：

```
┌─────────────────────────────────────────────────────────┐
│                    企业网络（IT 区）                     │
└────────────────────────┬────────────────────────────────┘
                         │ 工业防火墙 / 网闸
┌────────────────────────┴────────────────────────────────┐
│                    生产管理区（Level 3）                 │
│  MES / 历史数据库 / 生产调度                             │
└────────────────────────┬────────────────────────────────┘
                         │ 工业防火墙
┌────────────────────────┴────────────────────────────────┐
│                    过程监控区（Level 2）                 │
│  SCADA / HMI / 工程师站 / OPC 服务器                    │
└────────────────────────┬────────────────────────────────┘
                         │ 工业交换机
┌────────────────────────┴────────────────────────────────┐
│                    现场控制区（Level 1/0）               │
│  PLC / 控制器 / 传感器 / 执行器                          │
└─────────────────────────────────────────────────────────┘
```

**防护原则（十六字方针）：**
- **安全分区**：按功能和安全等级划分区域
- **网络专用**：工控网络独立建设，不与办公网混用
- **横向隔离**：不同区域之间实施隔离措施
- **纵向认证**：上下层之间通信需要认证

## 三、常见工控协议

### 3.1 工控协议分类

```
工控协议
├── 现场总线协议（串行）
│   ├── Modbus RTU/ASCII
│   ├── Profibus DP/PA
│   ├── CAN/CANopen
│   ├── DeviceNet
│   ├── HART
│   └── Foundation Fieldbus
│
├── 工业以太网协议
│   ├── Modbus TCP
│   ├── Profinet
│   ├── EtherNet/IP (CIP)
│   ├── EtherCAT
│   ├── S7 协议（S7comm/S7comm-plus）
│   ├── FINS（欧姆龙）
│   ├── MELSEC（三菱）
│   ├── Powerlink
│   └── SERCOS III
│
├── 电力系统协议
│   ├── IEC 60870-5-101/104
│   ├── DNP3
│   ├── IEC 61850 (MMS/GOOSE/SV)
│   ├── Modbus（电力常用）
│   └── CDT（部颁规约）
│
└── 过程控制协议
    ├── OPC DA / OPC UA
    ├── DNP3
    ├── ICCP (TASE.2)
    └── MMS
```

### 3.2 常见协议速览

| 协议名称 | 全称 | 传输层 | 默认端口 | 主要厂商/行业 | 安全性 |
|----------|------|--------|---------|-------------|--------|
| Modbus TCP | Modbus TCP | TCP | 502 | 通用，施耐德 | 无认证加密 |
| S7comm | Siemens S7 Protocol | TCP | 102 | 西门子 | 弱认证 |
| Profinet | Process Field Net | TCP/UDP | 34962-34964 | 西门子/PI组织 | 有限 |
| EtherNet/IP | Ethernet Industrial Protocol | TCP/UDP | 44818 (TCP) / 2222 (UDP) | 罗克韦尔/ODVA | 有限 |
| DNP3 | Distributed Network Protocol 3 | TCP/UDP/Serial | 20000 | 电力/水务 | 有认证可选 |
| IEC 104 | IEC 60870-5-104 | TCP | 2404 | 电力系统 | 弱安全 |
| OPC UA | OPC Unified Architecture | TCP/HTTPS | 4840 / 4843 | OPC基金会 | 有安全机制 |
| FINS | Factory Interface Network Service | TCP/UDP | 9600 | 欧姆龙 | 无认证 |
| MELSEC | Mitsubishi Electric | TCP/UDP | 5007/5006 | 三菱 | 弱安全 |
| HART | Highway Addressable Remote Transducer | 4-20mA/Serial | - | 过程仪表 | 有限 |

### 3.3 协议安全共性问题

**1. 缺乏身份认证**
- 大多数协议没有认证机制
- 知道协议格式即可发送控制指令
- 攻击者可以伪造合法设备

**2. 缺乏数据加密**
- 明文传输，抓包即可看到所有数据
- 控制指令和参数可见
- 敏感生产数据泄露

**3. 缺乏完整性校验**
- 数据在传输中可被篡改
- 中间人攻击可修改控制指令
- 重放攻击可行

**4. 协议设计缺陷**
- 设计时未考虑安全因素
- 功能码滥用、边界检查缺失
- 缓冲区溢出风险

**5. 专有协议不透明**
- 协议规范不公开
- 安全问题难以发现和评估
- 依赖厂商单一来源

## 四、工控系统与 IT 系统的区别

### 4.1 核心差异对比

| 对比维度 | IT 系统（信息技术） | OT 系统（运营技术） |
|----------|---------------------|---------------------|
| **首要目标** | 保密性（Confidentiality） | 可用性（Availability） |
| **次要目标** | 完整性 > 可用性 | 完整性 > 保密性 |
| **风险偏好** | 宁错杀不放过 | 宁可漏报不可误报 |
| **更新频率** | 频繁更新、快速迭代 | 常年不更新、求稳 |
| **生命周期** | 3-5 年 | 15-30 年 |
| **停机成本** | 业务中断，财务损失 | 生产事故，人员伤亡 |
| **操作系统** | Windows/Linux/Unix 通用系统 | 专用实时系统（VxWorks、QNX、uClinux） |
| **网络协议** | TCP/IP 为主，HTTP/HTTPS | 专用工业协议（Modbus、S7、Profinet 等） |
| **安全机制** | 防火墙、IDS、杀毒、加密 | 网络隔离、物理防护 |
| **人员技能** | IT 人员、网络工程师 | 自动化工程师、工艺工程师 |
| **法规合规** | 等保、网安法、数据安全法 | 等保工控扩展、行业规范 |

### 4.2 为什么不能把 IT 安全直接搬到 OT

**1. 可用性优先原则冲突**
- IT 安全：发现威胁立即阻断
- OT 安全：不能影响生产，即使有风险也要保证运行
- 示例：工控系统发现病毒不能直接断网，可能导致生产事故

**2. 补丁管理困难**
- IT 系统：补丁及时更新
- OT 系统：补丁需要严格测试，可能几个月甚至几年才能更新
- 很多老旧系统根本没有补丁支持

**3. 安全软件兼容性问题**
- 杀毒软件可能影响工业软件运行
- 工控软件对系统环境要求苛刻
- 安全软件误报可能导致系统异常

**4. 实时性要求**
- 工业控制对延迟要求极高
- 安全检测不能引入明显延迟
- 加密解密可能影响实时性

### 4.3 IT 与 OT 融合趋势

工业互联网的发展推动了 IT 与 OT 的深度融合：

```
传统模式：IT ═══隔离═══ OT
融合模式：IT ───协作─── OT（工业互联网）
```

**融合带来的好处：**
- 生产数据可视化、智能化
- 远程运维和诊断
- 优化生产效率
- 预测性维护

**融合带来的安全挑战：**
- OT 网络暴露面扩大
- IT 侧的风险可以传导到 OT
- 攻击路径增多
- 供应链风险增加

## 五、工控安全威胁与攻击面

```
                    │   社会工程学    │

                             │

│  Level 1: 控制层（PLC/控制器）← 最终控制目标         │
│       │                                                │
│  Level 0: 现场设备（传感器/执行器）← 物理破坏目标    │
└────────────────────────────────────────────────────────┘
```

### 5.2 主要威胁类型

#### 5.2.1 网络攻击

| 攻击类型 | 说明 | 典型案例 |
|----------|------|----------|
| **勒索病毒** | 加密工控系统数据，勒索赎金 | 2017 WannaCry 影响全球工控系统 |
| **恶意代码** | 专门针对工控系统的恶意软件 | Stuxnet、Triton、Industroyer |
| **漏洞利用** | 利用工控设备/软件漏洞获取权限 | 各类 PLC 漏洞利用 |
| **拒绝服务** | 导致工控系统不可用 | 协议 Flood、资源耗尽 |
| **中间人攻击** | 篡改工控通信数据 | 协议劫持、指令篡改 |
| **未授权访问** | 绕过认证访问工控系统 | 弱口令、默认口令、认证绕过 |
| **横向移动** | 从 IT 网络渗透到 OT 网络 | 利用跳板机逐步深入 |

#### 5.2.2 物理威胁

- 物理接触攻击：直接接触设备进行攻击
- 电磁干扰：影响设备正常运行
- 环境破坏：火灾、水灾等破坏物理设施
- 设备盗窃：工控设备丢失导致信息泄露
- USB 介质攻击：通过 U 盘传入恶意代码

#### 5.2.3 内部威胁

- 人员误操作：操作失误导致生产事故
- 恶意内部人员：有目的的破坏行为
- 权限滥用：越权操作
- 维护人员风险：第三方维护人员的安全风险

#### 5.2.4 供应链威胁

- 设备预置后门
- 固件被篡改
- 软件供应链攻击
- 维护工具带毒
- 备件安全问题

### 5.3 典型攻击路径

**路径一：互联网 → 企业层 → 生产管理层 → 监控层 → 控制层**
```
攻击者 → 互联网暴露面 → 攻破办公网 → 横向移动到生产网 → 
获取 SCADA/HMI 权限 → 攻击 PLC → 控制生产过程
```

**路径二：供应链 → 设备出厂即带毒**
```
攻击者 → 入侵设备厂商 → 修改设备固件/软件 → 
设备部署到工厂 → 后门激活 → 控制系统
```

**路径三：物理接触 → U 盘摆渡 → 内网传播**
```
攻击者 → 物理接触现场 → U 盘植入恶意代码 → 
插入工控主机 → 内网传播 → 控制系统
```

**路径四：远程维护 → 弱口令/漏洞 → 直接控制**
```
攻击者 → 扫描发现远程维护端口 → 利用弱口令或漏洞 → 
登录工程师站 → 下载/修改 PLC 程序 → 控制生产
```

## 六、工控安全标准

### 6.1 国际标准

#### 6.1.1 IEC 62443 系列标准

IEC 62443 是国际电工委员会制定的工业控制系统安全标准，是目前最权威、最系统的工控安全标准体系。

**标准结构：**

| 部分 | 编号 | 名称 | 内容 |
|------|------|------|------|
| 第1部分 | IEC 62443-1-1 | 术语、概念和模型 | 定义工控安全的基本概念 |
| | IEC 62443-1-2 | 术语和缩略语 | 术语表 |
| | IEC 62443-1-3 | 系统安全合规性度量 | 安全合规性评估方法 |
| 第2部分 | IEC 62443-2-1 | 资产所有者的安全管理体系 | 企业级安全管理要求 |
| | IEC 62443-2-3 | 补丁管理 | 工控系统补丁管理指南 |
| | IEC 62443-2-4 | 服务提供商的安全管理 | 服务提供商安全要求 |
| 第3部分 | IEC 62443-3-1 | 安全技术和系统要求 | 安全技术要求 |
| | IEC 62443-3-2 | 安全等级和目标 | 安全等级划分（SL1-SL4） |
| | IEC 62443-3-3 | 系统安全要求和安全等级 | 系统级安全要求 |
| 第4部分 | IEC 62443-4-1 | 产品开发生命周期 | 安全开发生命周期要求 |
| | IEC 62443-4-2 | 组件的技术安全要求 | 产品级安全要求 |

**安全等级（Security Level, SL）：**
- **SL0**：无特殊安全要求
- **SL1**：防止偶然或无意的违规访问
- **SL2**：防止使用简单手段的故意攻击
- **SL3**：防止使用复杂手段的故意攻击
- **SL4**：防止使用高级持续威胁（APT）的攻击

#### 6.1.2 NIST SP 800-82

美国国家标准技术研究院（NIST）发布的《工业控制系统安全指南》。

**主要内容：**
- 工控系统概述和特点
- 工控系统威胁和漏洞
- 工控安全控制措施
- 工控安全架构
- 与 IT 安全的区别
- 推荐的安全实践

#### 6.1.3 ISA-99 / IEC 62443 关系

ISA-99 是国际自动化学会制定的工控安全标准，后来与 IEC 合作，演变为 IEC 62443 系列。两者内容基本一致。

### 6.2 国内标准

#### 6.2.1 等保 2.0（GB/T 22239-2019）

**工控扩展要求**是等保 2.0 的重要组成部分，在基本要求基础上增加了工控系统特有的安全要求。

**工控扩展要求主要内容：**

| 层面 | 主要要求 |
|------|----------|
| **安全物理环境** | 电子门禁、视频监控、防盗窃防破坏、电磁防护 |
| **安全通信网络** | 安全分区、网络专用、横向隔离、纵向认证 |
| **安全区域边界** | 边界防护、访问控制、入侵防范、可信验证 |
| **安全计算环境** | 身份鉴别、访问控制、安全审计、入侵防范、恶意代码防范、数据完整性/保密性 |
| **安全建设管理** | 方案设计、产品采购、工程实施、测试验收、服务供应商 |
| **安全运维管理** | 环境管理、资产管理、介质管理、设备管理、漏洞和风险管理、应急处置 |

**核心要求：**
1. **安全分区**：根据业务特点和安全需求划分安全区域
2. **网络专用**：工业控制网络独立建设，与其他网络隔离
3. **横向隔离**：不同安全区域之间采用隔离技术
4. **纵向认证**：上下级控制中心之间采用认证加密技术

## 七、著名工控安全事件

### 7.1 Stuxnet（震网病毒）—— 2010 年

**概述：** 世界上第一个被发现的针对工控系统的网络武器，彻底改变了网络安全的格局。

**攻击目标：** 伊朗纳坦兹核设施的铀浓缩离心机

**技术特点：**
- 利用了 4 个 0day 漏洞（Windows 漏洞 + 西门子 PLC 漏洞）
- 攻击西门子 Step7 软件和 S7-300/400 PLC
- 通过 U 盘摆渡传播（利用 .LNK 文件漏洞）
- 具有高度的目标针对性
- 复杂的隐身机制

**攻击原理：**
```
1. 感染途径：U 盘摆渡 → 感染工程师站
2. 传播方式：利用 Windows 漏洞在内网传播
3. 目标识别：识别特定型号的 PLC 和离心机配置
4. 攻击执行：修改离心机转速控制参数
   - 正常转速：~1000 rpm
   - 攻击时：交替加速到 1400 rpm 或减速到 2 rpm
5. 隐身机制：向监控系统返回虚假的正常数据
```

**影响：**
- 破坏了约 1000 台离心机
- 延缓了伊朗核计划约 2-3 年
- 证明了网络攻击可以造成物理破坏
- 开启了网络战的新时代

**启示：**
- 工控系统不是绝对安全的"孤岛"
- 物理隔离不能完全阻止攻击
- 供应链和 U 盘是重要攻击途径
- 工控安全需要高度重视

### 7.2 Havex —— 2013 年

**概述：** 针对工控系统的间谍软件，主要攻击能源行业。

**攻击目标：** 欧洲和北美的能源、航空、制药等行业的工控系统

**技术特点：**
- 利用供应链攻击（工控厂商网站被植入恶意代码）
- 攻击 OPC 服务器，收集工业网络信息
- 窃取 SCADA 系统数据
- 模块化设计，功能可扩展
- 与 Stuxnet/Duqu 有相似之处

**感染方式：**
```
攻击者入侵工控软件厂商网站 → 在软件安装包中植入后门 →
用户下载安装 → Havex 植入系统 → 扫描工控网络 →
收集 OPC 服务器和设备信息 → 回传数据给攻击者
```

**影响：**
- 全球超过 2000 个工控系统被感染
- 大量工业网络拓扑和设备信息被窃取
- 暴露了工控供应链的脆弱性

### 7.3 BlackEnergy —— 2015 年

**概述：** 首次成功对电力系统实施网络攻击并造成大规模停电。

**攻击目标：** 乌克兰电力公司

**技术特点：**
- 利用宏病毒（Office 文档）作为初始感染载体
- 攻击 SCADA 系统和人机界面（HMI）
- 破坏数据和系统配置
- 配合拒绝服务攻击
- 具有 KillDisk 组件（数据销毁）

**攻击过程：**
```
1. 鱼叉式钓鱼邮件 → 员工打开带宏的 Office 文档
2. 植入 BlackEnergy 恶意软件 → 获取系统权限
3. 横向移动 → 渗透到 SCADA 网络
4. 攻击 HMI → 断开断路器
5. KillDisk 破坏系统 → 使运维人员无法恢复
6. DDoS 攻击客服电话 → 加剧混乱
```

**影响：**
- 乌克兰约 140 万人停电数小时
- 首次证明网络攻击可以导致大规模电力中断
- 电力系统成为网络战的重要目标

### 7.4 Industroyer / CrashOverride —— 2016 年

**概述：** 首个专门设计用于攻击电力系统的恶意软件，比 BlackEnergy 更专业。

**攻击目标：** 乌克兰输电系统

**技术特点：**
- 直接攻击电力保护继电器（不是只攻击 HMI）
- 支持多种电力协议（IEC 60870-5-101/104、IEC 61850 MMS、S7、DNP3）
- 可以直接操作断路器
- 具有数据擦除模块
- 模块化、可扩展的框架
- 可作为电力系统攻击的"武器平台"

**攻击原理：**
```
1. 获取电力网络访问权限
2. 扫描识别保护继电器型号
3. 使用对应协议模块连接继电器
4. 发送指令打开断路器 → 造成停电
5. 擦除继电器固件 → 阻止快速恢复
```

**影响：**
- 乌克兰首都基辅部分地区停电
- 电力系统攻击能力进一步提升
- 专用工控协议攻击成为现实威胁

### 7.5 Triton / Trisis / HatMan —— 2017 年

**概述：** 最危险的工控恶意代码，首次攻击安全仪表系统（SIS）。

**攻击目标：** 中东某石化工厂的安全仪表系统

**技术特点：**
- 专门攻击 Triconex 安全仪表系统（SIS）
- SIS 是工厂的最后一道安全防线
- 可以修改 SIS 的逻辑程序
- 可能导致安全保护失效
- 最严重可能导致爆炸、人员伤亡

**攻击原理：**
```
安全仪表系统（SIS）的作用：
正常生产 → 出现异常 → SIS 触发安全联锁 → 紧急停车 → 防止事故

Triton 的攻击：
感染 SIS 工程站 → 修改 SIS 逻辑程序 → 
当发生异常时 SIS 不动作 → 安全保护失效 → 可能发生爆炸
```

**危险性评估：**
- 攻击 SIS 是最危险的工控攻击类型
- SIS 是防止重大事故的最后一道防线
- 一旦 SIS 被控制，可能造成灾难性后果
- 人员伤亡风险极高

### 7.6 事件对比总结

| 事件 | 年份 | 目标行业 | 攻击对象 | 主要影响 | 危险性 |
|------|------|---------|---------|---------|--------|
| Stuxnet | 2010 | 核工业 | 西门子 PLC | 物理破坏设备 | ⭐⭐⭐⭐⭐ |
| Havex | 2013 | 能源等 | OPC 服务器 | 信息窃取 | ⭐⭐⭐ |
| BlackEnergy | 2015 | 电力 | SCADA/HMI | 大规模停电 | ⭐⭐⭐⭐ |
| Industroyer | 2016 | 电力 | 保护继电器 | 停电+难恢复 | ⭐⭐⭐⭐⭐ |
| Triton | 2017 | 石化 | 安全仪表系统 | 可能爆炸伤亡 | ⭐⭐⭐⭐⭐+ |

### 7.7 工控安全事件的发展趋势

1. **攻击目标越来越底层**：从攻击 HMI 到攻击 PLC，再到攻击 SIS
2. **攻击专业化程度越来越高**：从通用恶意软件到专用工控武器
3. **物理破坏能力越来越强**：从信息窃取到设备损坏，再到可能的人员伤亡
4. **攻击门槛逐渐降低**：攻击工具和技术逐渐扩散
5. **APT 组织参与度提高**：国家级背景的攻击越来越多

## 八、学习建议

### 8.1 入门路径

1. **先了解工控系统**：学习 PLC、SCADA、DCS 基本概念
2. **学习工业协议**：从 Modbus 开始，逐步深入
3. **掌握网络基础**：TCP/IP、网络抓包分析
4. **了解安全事件**：通过案例学习攻击原理
5. **搭建实验环境**：使用模拟器进行实践

### 8.2 实践环境建议

- **软件模拟**：PLC 模拟器、Modbus 模拟器、OPC 模拟器
- **虚拟环境**：VMware + 虚拟工控软件
- **低成本硬件**：二手 PLC（淘宝/闲鱼）、树莓派 + 工业模块
- **在线靶场**：ControlThings、ICS Village CTF

### 8.3 注意事项

- 永远不要在真实生产环境中进行测试
- 所有实验必须在授权的测试环境中进行
- 工控安全关乎生产安全和人身安全，务必谨慎
- 遵守法律法规和道德规范

---

> ⚠️ **重要提示**：工控安全关系到生产安全和国家安全，学习和研究务必在合法、授权的前提下进行。严禁对任何真实生产系统进行未经授权的扫描、探测或攻击。
