# 工控安全防护体系

> 本文档系统介绍工业控制系统安全防护体系，包括纵深防御框架、边界防护、主机加固、网络监测、安全管理和应急响应等内容。工控安全防护是一项系统工程，需要技术、管理、人员多维度协同。

---

## 一、工控安全防护框架（纵深防御）

### 1.1 纵深防御理念

工控安全纵深防御（Defense in Depth）是指在工控系统的不同层面和环节部署多重安全防护措施，即使某一层防护被突破，其他层防护仍然能够发挥作用，保障系统安全。

**核心理念：**
- 不依赖单一防护手段
- 多层防护，层层设防
- 任何单点突破都不能危及整体安全
- 技术 + 管理 + 人员 三位一体

### 1.2 纵深防御体系架构

```
┌─────────────────────────────────────────────────────────────┐
│                     第 6 层：安全管理                        │
│  策略制度 / 人员管理 / 合规审计 / 应急响应 / 培训教育         │
├─────────────────────────────────────────────────────────────┤
│                     第 5 层：数据安全                        │
│  数据加密 / 数据备份 / 数据脱敏 / 数据防泄露                 │
├─────────────────────────────────────────────────────────────┤
│                     第 4 层：应用安全                        │
│  软件加固 / 访问控制 / 安全审计 / 接口安全                   │
├─────────────────────────────────────────────────────────────┤
│                     第 3 层：主机安全                        │
│  操作系统加固 / 白名单 / 防病毒 / 主机入侵防护               │
├─────────────────────────────────────────────────────────────┤
│                     第 2 层：网络安全                        │
│  安全分区 / 边界防护 / 访问控制 / 入侵检测 / 网络审计        │
├─────────────────────────────────────────────────────────────┤

│  门禁监控 / 环境安全 / 设备防护 / 介质管理                   │
├─────────────────────────────────────────────────────────────┤

│  设备身份认证 / 固件安全 / 协议安全 / 漏洞管理               │

```

### 1.3 工控安全防护原则

#### 原则一：安全分区、网络专用

根据业务功能和安全等级，将工控网络划分为不同的安全区域，每个区域独立组网，实施差异化的防护策略。

```
┌──────────────────────────────────────────────────────────┐
│                       企业网络（IT）                      │
└───────────────────────┬──────────────────────────────────┘
                        │  边界防护（工业防火墙 / 网闸）
┌───────────────────────┴──────────────────────────────────┐
│                    生产管理区（Level 3）                  │
│  MES / 历史数据库 / 生产调度                              │
└───────────────────────┬──────────────────────────────────┘
                        │  区域隔离（工业防火墙）
┌───────────────────────┴──────────────────────────────────┐
│                    过程监控区（Level 2）                  │
│  SCADA / HMI / 工程师站 / OPC 服务器                     │
└───────────────────────┬──────────────────────────────────┘
                        │  工业交换机（VLAN/ACL）
┌───────────────────────┴──────────────────────────────────┐
│                    现场控制区（Level 1/0）                │
│  PLC / 控制器 / 传感器 / 执行器                           │
└──────────────────────────────────────────────────────────┘
```

#### 原则二：横向隔离、纵向认证

- **横向隔离**：同一层级的不同区域之间进行隔离，防止攻击横向扩散
- **纵向认证**：上下层级之间的通信进行身份认证和加密，防止未授权访问

#### 原则三：最小权限原则

- 用户只赋予完成工作所需的最小权限
- 程序只允许运行必要的功能
- 网络只开放必要的端口和协议
- 设备只启用必要的服务

#### 原则四：可用性优先原则

- 所有安全措施不能影响生产正常运行
- 安全设备部署不能成为单点故障
- 安全策略调整需谨慎评估生产影响
- 应急情况下有降级运行方案

#### 原则五：持续改进原则

- 安全防护不是一劳永逸的
- 定期评估和优化安全策略
- 跟踪新的威胁和漏洞
- 持续完善安全管理体系

### 1.4 安全防护成熟度模型

| 等级 | 名称 | 特征 |
|------|------|------|
| L1 | 初始级 | 基本无防护，依赖物理隔离 |
| L2 | 基础级 | 有基本的边界防护和网络分区 |
| L3 | 规范级 | 建立了较完善的技术防护体系和管理制度 |
| L4 | 优化级 | 主动防御、态势感知、持续改进 |
| L5 | 引领级 | 智能化安全运营，行业标杆水平 |

## 二、边界防护（工业防火墙/网闸）

### 2.1 边界防护的重要性

网络边界是攻击进入工控系统的第一道防线，也是最重要的防线之一。

**主要边界：**
1. **IT-OT 边界**：企业网与生产网之间的边界
2. **区域边界**：生产管理区与过程监控区之间的边界
3. **单元边界**：不同生产单元之间的边界
4. **对外接口**：远程维护、数据上报等对外连接

### 2.2 工业防火墙

#### 2.2.1 工业防火墙与传统防火墙的区别

| 对比项 | 传统 IT 防火墙 | 工业防火墙 |
|--------|---------------|-----------|
| **设计目标** | 通用网络防护 | 工业环境专用 |
| **协议支持** | TCP/IP、HTTP 等 | 支持 Modbus/S7/Profinet 等工业协议深度解析 |
| **环境适应** | 机房环境 | 工业级（宽温、抗干扰、防尘） |
| **部署方式** | 路由/透明模式 | 支持在线部署、旁路部署 |
| **可靠性** | 一般 | 高可靠（Bypass、冗余） |
| **性能特点** | 吞吐量优先 | 低延迟优先（不影响实时性） |
| **管理方式** | Web/CLI | 支持工业协议管理、图形化策略配置 |

#### 2.2.2 工业防火墙核心功能

**1. 工业协议深度解析（DPI）**
- 支持 Modbus TCP、S7、Profinet、EtherNet/IP、DNP3、IEC 104 等
- 基于协议功能码的访问控制
- 基于寄存器地址/标签的访问控制
- 协议异常检测

**2. 白名单访问控制**
- 基于 IP/MAC 的白名单
- 基于工业协议的白名单
- 基于功能码的白名单
- 默认拒绝，仅允许已知通信

**3. 实时性保障**
- 低延迟转发（微秒级）
- 硬件加速
- 不影响工业控制实时性

**4. 高可靠性**
- 硬件 Bypass（断电直通）
- 双机热备
- 链路冗余

#### 2.2.3 工业防火墙部署位置

```
位置 1：IT-OT 边界（最重要）
  企业网 ─── 工业防火墙 ─── 生产管理网

位置 2：生产管理与监控区边界
  MES区 ─── 工业防火墙 ─── SCADA区

位置 3：关键设备前
  工业网络 ─── 工业防火墙 ─── 关键PLC/控制器

位置 4：远程访问入口
  外部 ─── VPN网关 + 工业防火墙 ─── 工控网络
```

### 2.3 工业网闸（物理隔离装置）

#### 2.3.1 网闸的工作原理

网闸（又称物理隔离装置、正向/反向隔离装置）通过物理断开的方式实现两个网络之间的数据交换，确保不会有直接的网络连接。

```
外网处理单元 ─── 私有协议摆渡 ─── 内网处理单元
            (物理断开，仅数据摆渡)
```

**核心特点：**
- 内外网物理断开
- 仅允许特定格式的数据通过
- 不支持 TCP 连接转发
- 安全性最高，但灵活性低

#### 2.3.2 网闸的类型

**正向隔离装置：**
- 数据只能从内网（生产侧）向外网（管理侧）单向传输
- 用于生产数据上报
- 安全性最高

**反向隔离装置：**
- 数据只能从外网向内网单向传输
- 用于程序下载、参数下发等
- 需要严格的认证和审批

**双向隔离装置：**
- 两个方向各有独立的摆渡通道
- 仍保持物理断开
- 适用于需要双向数据交换的场景

#### 2.3.3 网闸与防火墙的区别

| 对比项 | 工业防火墙 | 网闸（物理隔离） |
|--------|-----------|-----------------|
| 隔离方式 | 逻辑隔离 | 物理隔离 |
| 安全性 | 高 | 极高 |
| 灵活性 | 高 | 低 |
| 协议支持 | 丰富的工业协议 | 仅支持特定数据格式 |
| 实时性 | 好 | 有延迟（摆渡时间） |
| 适用场景 | 区域边界防护 | 高安全等级的跨网数据交换 |

### 2.4 边界防护最佳实践

1. **分层防护**：不要只依赖一道边界防线
2. **默认拒绝**：白名单机制，只允许必要的通信
3. **最小化暴露面**：只开放必要的端口和协议
4. **定期审计**：定期检查边界策略的合理性
5. **冗余设计**：关键边界部署冗余设备
6. **集中管理**：统一管理所有边界设备

## 三、工控主机安全加固

### 3.1 工控主机的特点与风险

**常见工控主机：**
- SCADA 服务器 / DCS 操作站
- HMI（人机界面）工作站
- 工程师站
- OPC 服务器
- 历史数据库服务器
- 工业网关

**主要安全风险：**
- 操作系统老旧（Windows XP/2000/7 占比高）
- 常年不打补丁（担心兼容性问题）
- 弱口令/默认口令
- 安装了大量工控软件，漏洞面广
- USB 接口管控不严
- 杀毒软件缺失或不更新
- 共享账户、权限过大

### 3.2 操作系统加固

#### 3.2.1 Windows 系统加固

**1. 账户安全**
```
- 禁用或删除不必要的账户
- 重命名管理员账户
- 设置强密码策略
- 启用账户锁定策略
- 禁用 Guest 账户
- 定期更换密码
```

**2. 服务优化**
```
- 禁用不必要的服务：
  · Telnet
  · FTP
  · Remote Registry
  · SSDP Discovery
  · TCP/IP NetBIOS Helper
  · Print Spooler（如不需要打印）
  · Windows Update（谨慎，建议测试后手动更新）
- 仅保留工控软件必需的服务
```

**3. 网络配置**
```
- 禁用 NetBIOS
- 禁用 LLMNR
- 关闭不必要的端口
- 配置本地防火墙规则
- 绑定 IP 和 MAC 地址
```

**4. 安全策略配置**
```
- 配置本地安全策略
- 启用安全审计
- 配置用户权限分配
- 限制远程访问
- 启用数据执行保护 (DEP)
```

#### 3.2.2 补丁管理

工控系统补丁管理的特殊挑战：
- 补丁可能导致工控软件兼容性问题
- 停机打补丁成本高
- 很多老旧系统没有补丁支持
- 补丁测试周期长

**补丁管理策略：**
```
1. 建立补丁管理流程
   · 补丁获取 → 兼容性评估 → 测试环境验证 → 生产部署
   
2. 分类管理
   · 严重漏洞补丁：紧急评估，尽快部署
   · 一般安全补丁：定期评估，择机部署
   · 功能更新：谨慎评估，通常不更新
   
3. 风险缓解
   · 无法打补丁的，通过其他防护手段弥补
   · 如网络隔离、端口限制、白名单等
   
4. 回滚方案
   · 打补丁前必须有备份和回滚方案
   · 优先在非关键系统测试
```

### 3.3 应用白名单

#### 3.3.1 为什么需要白名单

传统杀毒软件的问题：
- 病毒库更新可能影响系统稳定
- 误报可能导致工控软件异常
- 对未知病毒效果有限
- 占用系统资源，可能影响实时性

应用白名单的优势：
- 只允许已知的合法程序运行
- 对未知恶意代码效果好
- 不会误杀合法程序（配置正确的话）
- 资源占用低
- 适合工控环境

#### 3.3.2 白名单实现方式

**1. 系统自带功能**
- Windows 软件限制策略 (SRP)
- Windows AppLocker
- WDAC（Windows Defender 应用程序控制）

**2. 专用工控白名单软件**
- 360 工控主机卫士
- 奇安信工控主机安全
- 启明星辰天珣工控版
- 威努特工控主机防护

#### 3.3.3 白名单配置步骤

```
步骤 1：基线采集
  · 在干净的系统上采集所有合法程序
  · 包括操作系统文件、驱动、工控软件等
  · 记录文件哈希、路径、签名信息

步骤 2：策略制定
  · 基于哈希的白名单（最严格）
  · 基于路径的白名单（较灵活）
  · 基于签名的白名单（可信厂商）
  · 组合策略

步骤 3：测试验证
  · 在测试环境验证白名单策略
  · 确保所有工控软件正常运行
  · 检查是否有误拦截

步骤 4：试运行
  · 先启用"审计模式"（只记录不阻止）
  · 运行一段时间，分析日志
  · 补充完善白名单

步骤 5：正式启用
  · 切换到"强制模式"
  · 监控运行状态
  · 建立变更流程
```

### 3.4 USB 外设管控

**风险：**
- U 盘是病毒摆渡的重要途径（如 Stuxnet）
- 数据泄露风险
- 恶意程序引入

**管控措施：**
```
1. 物理管控
   · 封闭 USB 接口（物理封堵）
   · 使用带锁的 USB 端口盖
   
2. 软件管控
   · 禁用 USB 存储设备
   · 启用 USB 白名单
   · USB 设备使用审计
   
3. 管理措施
   · 制定 USB 使用管理制度
   · 专用 U 盘统一管理
   · 外来 U 盘查杀后才能使用
   · 重要系统完全禁止使用 U 盘
   
4. 替代方案
   · 使用专用的工业级安全 U 盘
   · 通过网络传输文件
   · 使用专用的文件交换区
```

## 四、工控网络审计与监测

### 4.1 工控安全监测概述

工控安全监测是指通过技术手段对工控网络的流量、行为、状态进行持续监控，及时发现安全威胁和异常行为。

**与 IT 监测的区别：**
- 工控网络流量相对固定，规律性强
- 重点监测工业协议和控制行为
- 不能影响生产系统的正常运行
- 以旁路监测为主，避免在线风险

### 4.2 工控入侵检测系统（IDS）

#### 4.2.1 工控 IDS 的特点

| 特点 | 说明 |
|------|------|
| **旁路部署** | 不串联在网络中，通过镜像流量监测 |
| **协议识别** | 支持多种工业协议深度解析 |
| **行为基线** | 自学习建立正常行为基线 |
| **异常检测** | 检测偏离基线的异常行为 |
| **实时告警** | 发现威胁实时告警 |
| **低误报率** | 针对工业场景优化，减少误报 |

#### 4.2.2 工控 IDS 检测能力

**1. 协议异常检测**
- 畸形报文检测
- 协议规范违反检测
- 未知功能码检测
- 报文异常检测

**2. 行为异常检测**
- 新设备接入检测
- 异常通信关系检测
- 异常通信频率检测
- 异常数据量检测
- 非常规功能码使用检测

**3. 攻击检测**
- 端口扫描检测
- 漏洞利用检测
- 暴力破解检测
- 已知攻击特征匹配

**4. 操作审计**
- 控制操作记录（写操作、启停操作）
- 参数修改记录
- 程序下载/上传记录
- 配置变更记录

#### 4.2.3 部署方式

```
方式一：端口镜像（最常用）
  交换机镜像端口 ─── 工控 IDS
  优点：不影响网络，部署灵活
  缺点：需要交换机支持镜像功能

方式二：网络分流器（TAP）
  链路 ─── TAP 设备 ─── 工控 IDS
  优点：不依赖交换机，更可靠
  缺点：需要额外硬件，需断网部署

方式三：混合部署
  核心交换机用镜像，关键链路用 TAP
  兼顾成本和可靠性
```

### 4.3 工控安全审计系统

#### 4.3.1 审计对象

| 审计对象 | 审计内容 |
|----------|---------|
| **网络通信审计** | 所有网络访问记录、协议使用、通信关系 |
| **操作行为审计** | 控制操作、参数修改、程序变更 |
| **设备状态审计** | 设备在线状态、配置变更、固件更新 |
| **系统日志审计** | 操作系统日志、应用日志、安全日志 |
| **人员操作审计** | 登录登出、操作记录、权限变更 |

#### 4.3.2 审计日志要求

**日志内容要求：**
- 操作时间（精确到毫秒）
- 操作人员（账号、IP、终端）
- 操作类型（读/写/配置/管理）
- 操作对象（设备、寄存器、参数）
- 操作结果（成功/失败/异常）
- 原始数据（请求和响应报文）

**日志存储要求：**
- 日志存储时间不少于 6 个月
- 重要系统不少于 1 年
- 日志防篡改（只读存储、哈希校验）
- 日志备份策略

### 4.4 工控态势感知

#### 4.4.1 什么是态势感知

工控安全态势感知是指在一定时空条件下，对工控系统安全状态的感知、理解和预测。

**三个层次：**
1. **感知**：知道当前发生了什么（数据采集和展示）
2. **理解**：理解发生的事情意味着什么（关联分析和研判）
3. **预测**：预测接下来会发生什么（趋势分析和预警）

#### 4.4.2 态势感知平台功能

```
┌─────────────────────────────────────────────────────────┐
│                    态势感知与展示层                       │
│  总览大屏 / 安全态势 / 威胁地图 / 趋势分析 / 报表         │
├─────────────────────────────────────────────────────────┤
│                    分析与研判层                           │
│  关联分析 / 威胁建模 / 风险评估 / 事件研判 / 溯源分析     │
├─────────────────────────────────────────────────────────┤
│                    数据采集与处理层                       │
│  流量采集 / 日志采集 / 资产采集 / 漏洞采集 / 威胁情报     │
└─────────────────────────────────────────────────────────┘
```

**核心能力：**
- 全网资产可视化
- 安全威胁实时监测
- 安全事件智能分析
- 攻击路径溯源
- 风险量化评估
- 安全趋势预测

### 4.5 监测技术发展趋势

1. **AI/ML 赋能**：机器学习用于异常检测和威胁识别
2. **威胁情报驱动**：基于工控威胁情报提升检测能力
3. **资产指纹化**：建立设备指纹库，精准识别资产
4. **行为建模**：建立正常行为模型，检测异常
5. **协同联动**：监测与防护设备联动响应

## 六、应急响应

### 6.1 工控应急响应概述

工控应急响应是指在工控系统发生安全事件时，为控制事态、减少损失、恢复生产而采取的一系列措施。

**工控应急响应的特殊性：**
- 生产影响大，时间紧迫
- 技术复杂，专业要求高
- 需要多部门协同
- 恢复难度大，周期可能较长
- 可能涉及人身安全和环境安全

### 6.2 应急响应组织

#### 6.2.1 应急组织架构

```
应急领导小组
    │
    ├── 应急指挥部
    │    ├── 生产指挥组
    │    ├── 技术处置组
    │    ├── 安全监测组
    │    └── 协调保障组
    │
    └── 专家顾问组
```

#### 6.2.2 职责分工

| 角色 | 职责 |
|------|------|
| **应急领导小组** | 重大决策、资源调配、对外发布 |
| **生产指挥组** | 生产调度、工艺处置、生产恢复 |
| **技术处置组** | 技术分析、事件处置、系统恢复 |
| **安全监测组** | 监测跟踪、取证分析、态势研判 |
| **协调保障组** | 物资保障、通信保障、后勤保障 |
| **专家顾问组** | 技术指导、方案咨询 |

### 6.3 应急响应流程

#### 6.3.1 标准流程

```
┌──────────┐    ┌──────────┐    ┌──────────┐
│  事件发现 │ →  │  事件研判 │ →  │  应急启动 │
└──────────┘    └──────────┘    └──────────┘
                                          │
                                          ↓
┌──────────┐    ┌──────────┐    ┌──────────┐
│ 总结改进 │ ←  │ 恢复生产 │ ←  │  应急处置 │
└──────────┘    └──────────┘    └──────────┘
```

#### 6.3.2 各阶段详细说明

**阶段一：事件发现**

**发现途径：**
- 安全设备告警（IDS、防火墙、审计系统）
- 运维人员发现异常
- 生产异常（怀疑被攻击）
- 外部通报（厂商、监管部门）
- 威胁情报预警

**初步报告内容：**
- 事件发生时间
- 事件现象描述
- 影响范围初步判断
- 已采取的措施
- 报告人和联系方式

**阶段二：事件研判**

**研判内容：**
- 是否为安全事件
- 事件类型（病毒、入侵、误操作等）
- 影响范围和严重程度
- 是否需要启动应急预案

**研判方法：**
- 现场检查
- 日志分析
- 流量分析
- 对比正常状态
- 专家会商

**事件分级：**

| 级别 | 名称 | 判定标准 |
|------|------|---------|
| I 级 | 特别重大 | 全厂停产、可能造成人员伤亡或重大环境影响 |
| II 级 | 重大 | 关键生产线停产、重大经济损失 |
| III 级 | 较大 | 部分生产线受影响、可较快恢复 |
| IV 级 | 一般 | 影响较小、局部影响 |

**阶段三：应急启动**

- 根据事件级别启动相应应急预案
- 成立应急指挥机构
- 通知相关人员到位
- 调集应急资源
- 通报相关部门

**阶段四：应急处置**

**处置原则：**
1. **安全第一**：确保人员安全，防止事故扩大
2. **保障生产**：尽快恢复生产，减少损失
3. **控制源头**：隔离攻击源，防止扩散
4. **保全证据**：注意保护现场和证据

**常用处置措施：**

| 措施 | 适用场景 | 注意事项 |
|------|---------|---------|
| **网络隔离** | 攻击扩散中 | 注意不要影响正常生产通信 |
| **设备断开** | 单设备被控制 | 评估对生产的影响 |
| **切换备用** | 有备用系统 | 确保备用系统未被感染 |
| **清除恶意代码** | 病毒/木马感染 | 工控环境慎用杀毒软件 |
| **恢复备份** | 系统被破坏 | 确认备份未被感染 |
| **修改口令** | 口令泄露 | 全面排查所有相关账户 |
| **封堵漏洞** | 漏洞利用攻击 | 先在测试环境验证 |
| **工艺处置** | 影响生产安全 | 由工艺人员操作 |

**特别注意：工控应急中的"不能做"**
- 不能随意重启 PLC（可能导致生产事故）
- 不能随意在工控主机上运行杀毒软件
- 不能随意断开网络（可能影响控制通信）
- 不能随意安装软件或工具
- 不能在未评估风险的情况下进行操作

**阶段五：恢复生产**

**恢复策略：**
- 先恢复关键系统
- 先恢复生产再完善安全
- 逐步恢复，验证正常后再推进

**恢复步骤：**
1. 制定恢复方案
2. 准备恢复资源
3. 逐系统恢复
4. 功能验证
5. 投入运行
6. 持续监控

**阶段六：总结改进**

**事后总结内容：**
- 事件原因分析
- 处置过程回顾
- 经验教训总结
- 改进措施制定
- 预案修订完善

**改进措施：**
- 技术层面：补充防护措施、加固薄弱环节
- 管理层面：完善制度、优化流程
- 人员层面：加强培训、提升能力
- 预案层面：修订预案、加强演练

### 6.4 典型场景应急预案

#### 6.4.1 勒索病毒应急预案

```
触发条件：发现文件被加密、勒索提示、大量主机异常

处置步骤：
1. 立即隔离受感染主机（断开网络）
2. 判断感染范围（哪些系统、哪些区域）
3. 保护未感染系统（加固、断网隔离）
4. 评估对生产的影响
5. 尝试恢复（从备份恢复，优先关键系统）
6. 溯源分析（感染途径、病毒类型）
7. 清理加固（清除残留、打补丁）
8. 逐步恢复生产

注意事项：
· 不要支付赎金（违法、有风险）
· 不要在生产系统上尝试解密
· 优先从备份恢复
· 防止二次感染
```

#### 6.4.2 PLC 异常应急预案

```
触发条件：PLC 程序异常、输出异常、状态异常

处置步骤：
1. 立即通知工艺人员和操作人员
2. 判断是否影响生产安全
3. 必要时切换到手动操作或紧急停车
4. 检查 PLC 程序和配置
5. 对比备份，确认是否被篡改
6. 分析异常原因（故障/攻击/误操作）
7. 恢复正常程序
8. 验证功能正常
9. 恢复生产

注意事项：
· 安全第一，必要时紧急停车
· 不要贸然重启 PLC
· 先确认程序完整性
· 保留异常状态的证据
```

#### 6.4.3 网络入侵应急预案

```
触发条件：发现未授权访问、异常操作、可疑连接

处置步骤：
1. 监测跟踪攻击者行为（在可控范围内）
2. 判断攻击范围和目的
3. 隔离受影响系统
4. 封堵攻击路径
5. 排查所有受影响账户
6. 全面口令更换
7. 系统加固和漏洞修复
8. 持续监控，防止反复

注意事项：
· 不要过早打草惊蛇
· 注意保全证据
· 全面排查，防止有后门
· 横向移动风险评估
```

### 6.5 应急演练

#### 6.5.1 演练目的

- 检验应急预案的有效性
- 提升应急响应能力
- 磨合团队协作
- 发现问题和不足
- 增强安全意识

#### 6.5.2 演练类型

| 类型 | 特点 | 频率 |
|------|------|------|
| **桌面演练** | 模拟场景，讨论推演 | 每半年 1 次 |
| **功能演练** | 针对某个环节实操 | 每年 1 次 |
| **全面演练** | 全流程实战演练 | 每 1-2 年 1 次 |

#### 6.5.3 演练注意事项

- 演练不能影响正常生产
- 优先在测试环境或非关键系统开展
- 演练前制定详细方案
- 演练过程做好记录
- 演练后及时总结改进

## 七、工控安全建设路线图

### 7.1 分阶段建设建议

#### 阶段一：基础防护（0-6 个月）

**目标：** 建立基本的安全防护能力，堵住明显的安全漏洞。

**重点工作：**
- 资产梳理，摸清家底
- 网络分区，边界隔离
- 工业防火墙部署
- 主机基础加固
- 禁用不必要的服务和端口
- 修改默认/弱口令
- 制定基本管理制度
- 全员安全意识培训

#### 阶段二：体系建设（6-12 个月）

**目标：** 建立较完善的安全防护体系，具备基本的监测和响应能力。

**重点工作：**
- 部署工控安全监测系统
- 部署工控主机防护（白名单）
- 建立安全审计体系
- 完善安全管理制度
- 建立应急响应机制
- 开展定期风险评估
- 建设安全运营团队

#### 阶段三：深度防御（12-24 个月）

**目标：** 纵深防御体系成熟，具备主动防御和态势感知能力。

**重点工作：**
- 建设工控态势感知平台
- 建立威胁情报体系
- 实现安全运营自动化
- 完善纵深防御体系
- 建立供应链安全管理
- 定期开展攻防演练
- 安全与生产深度融合

### 7.2 投资优先级建议

按 ROI（投入产出比）排序：

| 优先级 | 措施 | 说明 |
|--------|------|------|
| 1 | 网络分区与边界隔离 | 最有效、投资相对不高 |
| 2 | 修改弱口令/默认口令 | 零成本，效果明显 |
| 3 | 主机基础加固 | 投入小，收益大 |
| 4 | 工业防火墙 | 重要防线，必要投资 |
| 5 | 安全监测/审计 | 发现威胁，不可缺少 |
| 6 | 应用白名单 | 有效防病毒，工控场景推荐 |
| 7 | 管理制度建设 | 管理提升，长期价值 |
| 8 | 态势感知平台 | 高级阶段，投资较大 |

---

> ⚠️ **结语**：工控安全是一项持续的系统工程，没有一劳永逸的解决方案。需要技术、管理、人员多方面协同，持续改进，才能有效保障工业控制系统的安全。安全的最终目标是保障生产的安全稳定运行，所有安全措施都不能脱离这个根本目标。
