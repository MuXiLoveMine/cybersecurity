# 工控主机安全加固

### 3.1 工控主机的特点与风险

**常见工控主机：**
- SCADA 服务器 / DCS 操作站
- HMI（人机界面）工作站
- 工程师站
- OPC 服务器
- 历史数据库服务器
- 工业网关

**主要安全风险：**
- 操作系统老旧（Windows XP/2000/7 占比高）
- 常年不打补丁（担心兼容性问题）
- 弱口令/默认口令
- 安装了大量工控软件，漏洞面广
- USB 接口管控不严
- 杀毒软件缺失或不更新
- 共享账户、权限过大

### 3.2 操作系统加固

#### 3.2.1 Windows 系统加固

**1. 账户安全**
```
- 禁用或删除不必要的账户
- 重命名管理员账户
- 设置强密码策略
- 启用账户锁定策略
- 禁用 Guest 账户
- 定期更换密码
```

**2. 服务优化**
```
- 禁用不必要的服务：
  · Telnet
  · FTP
  · Remote Registry
  · SSDP Discovery
  · TCP/IP NetBIOS Helper
  · Print Spooler（如不需要打印）
  · Windows Update（谨慎，建议测试后手动更新）
- 仅保留工控软件必需的服务
```

**3. 网络配置**
```
- 禁用 NetBIOS
- 禁用 LLMNR
- 关闭不必要的端口
- 配置本地防火墙规则
- 绑定 IP 和 MAC 地址
```

**4. 安全策略配置**
```
- 配置本地安全策略
- 启用安全审计
- 配置用户权限分配
- 限制远程访问
- 启用数据执行保护 (DEP)
```

#### 3.2.2 补丁管理

工控系统补丁管理的特殊挑战：
- 补丁可能导致工控软件兼容性问题
- 停机打补丁成本高
- 很多老旧系统没有补丁支持
- 补丁测试周期长

**补丁管理策略：**
```
1. 建立补丁管理流程
   · 补丁获取 → 兼容性评估 → 测试环境验证 → 生产部署
   
2. 分类管理
   · 严重漏洞补丁：紧急评估，尽快部署
   · 一般安全补丁：定期评估，择机部署
   · 功能更新：谨慎评估，通常不更新
   
3. 风险缓解
   · 无法打补丁的，通过其他防护手段弥补
   · 如网络隔离、端口限制、白名单等
   
4. 回滚方案
   · 打补丁前必须有备份和回滚方案
   · 优先在非关键系统测试
```

### 3.3 应用白名单

#### 3.3.1 为什么需要白名单

传统杀毒软件的问题：
- 病毒库更新可能影响系统稳定
- 误报可能导致工控软件异常
- 对未知病毒效果有限
- 占用系统资源，可能影响实时性

应用白名单的优势：
- 只允许已知的合法程序运行
- 对未知恶意代码效果好
- 不会误杀合法程序（配置正确的话）
- 资源占用低
- 适合工控环境

#### 3.3.2 白名单实现方式

**1. 系统自带功能**
- Windows 软件限制策略 (SRP)
- Windows AppLocker
- WDAC（Windows Defender 应用程序控制）

**2. 专用工控白名单软件**
- 360 工控主机卫士
- 奇安信工控主机安全
- 启明星辰天珣工控版
- 威努特工控主机防护

#### 3.3.3 白名单配置步骤

```
步骤 1：基线采集
  · 在干净的系统上采集所有合法程序
  · 包括操作系统文件、驱动、工控软件等
  · 记录文件哈希、路径、签名信息

步骤 2：策略制定
  · 基于哈希的白名单（最严格）
  · 基于路径的白名单（较灵活）
  · 基于签名的白名单（可信厂商）
  · 组合策略

步骤 3：测试验证
  · 在测试环境验证白名单策略
  · 确保所有工控软件正常运行
  · 检查是否有误拦截

步骤 4：试运行
  · 先启用"审计模式"（只记录不阻止）
  · 运行一段时间，分析日志
  · 补充完善白名单

步骤 5：正式启用
  · 切换到"强制模式"
  · 监控运行状态
  · 建立变更流程
```

### 3.4 USB 外设管控

**风险：**
- U 盘是病毒摆渡的重要途径（如 Stuxnet）
- 数据泄露风险
- 恶意程序引入

**管控措施：**
```
1. 物理管控
   · 封闭 USB 接口（物理封堵）
   · 使用带锁的 USB 端口盖
   
2. 软件管控
   · 禁用 USB 存储设备
   · 启用 USB 白名单
   · USB 设备使用审计
   
3. 管理措施
   · 制定 USB 使用管理制度
   · 专用 U 盘统一管理
   · 外来 U 盘查杀后才能使用
   · 重要系统完全禁止使用 U 盘
   
4. 替代方案
   · 使用专用的工业级安全 U 盘
   · 通过网络传输文件
   · 使用专用的文件交换区
```
