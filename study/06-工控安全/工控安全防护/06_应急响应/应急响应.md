# 应急响应

### 6.1 工控应急响应概述

工控应急响应是指在工控系统发生安全事件时，为控制事态、减少损失、恢复生产而采取的一系列措施。

**工控应急响应的特殊性：**
- 生产影响大，时间紧迫
- 技术复杂，专业要求高
- 需要多部门协同
- 恢复难度大，周期可能较长
- 可能涉及人身安全和环境安全

### 6.2 应急响应组织

#### 6.2.1 应急组织架构

```
应急领导小组
    │
    ├── 应急指挥部
    │    ├── 生产指挥组
    │    ├── 技术处置组
    │    ├── 安全监测组
    │    └── 协调保障组
    │
    └── 专家顾问组
```

#### 6.2.2 职责分工

| 角色 | 职责 |
|------|------|
| **应急领导小组** | 重大决策、资源调配、对外发布 |
| **生产指挥组** | 生产调度、工艺处置、生产恢复 |
| **技术处置组** | 技术分析、事件处置、系统恢复 |
| **安全监测组** | 监测跟踪、取证分析、态势研判 |
| **协调保障组** | 物资保障、通信保障、后勤保障 |
| **专家顾问组** | 技术指导、方案咨询 |

### 6.3 应急响应流程

#### 6.3.1 标准流程

```
┌──────────┐    ┌──────────┐    ┌──────────┐
│  事件发现 │ →  │  事件研判 │ →  │  应急启动 │
└──────────┘    └──────────┘    └──────────┘
                                          │
                                          ↓
┌──────────┐    ┌──────────┐    ┌──────────┐
│ 总结改进 │ ←  │ 恢复生产 │ ←  │  应急处置 │
└──────────┘    └──────────┘    └──────────┘
```

#### 6.3.2 各阶段详细说明

**阶段一：事件发现**

**发现途径：**
- 安全设备告警（IDS、防火墙、审计系统）
- 运维人员发现异常
- 生产异常（怀疑被攻击）
- 外部通报（厂商、监管部门）
- 威胁情报预警

**初步报告内容：**
- 事件发生时间
- 事件现象描述
- 影响范围初步判断
- 已采取的措施
- 报告人和联系方式

**阶段二：事件研判**

**研判内容：**
- 是否为安全事件
- 事件类型（病毒、入侵、误操作等）
- 影响范围和严重程度
- 是否需要启动应急预案

**研判方法：**
- 现场检查
- 日志分析
- 流量分析
- 对比正常状态
- 专家会商

**事件分级：**

| 级别 | 名称 | 判定标准 |
|------|------|---------|
| I 级 | 特别重大 | 全厂停产、可能造成人员伤亡或重大环境影响 |
| II 级 | 重大 | 关键生产线停产、重大经济损失 |
| III 级 | 较大 | 部分生产线受影响、可较快恢复 |
| IV 级 | 一般 | 影响较小、局部影响 |

**阶段三：应急启动**

- 根据事件级别启动相应应急预案
- 成立应急指挥机构
- 通知相关人员到位
- 调集应急资源
- 通报相关部门

**阶段四：应急处置**

**处置原则：**
1. **安全第一**：确保人员安全，防止事故扩大
2. **保障生产**：尽快恢复生产，减少损失
3. **控制源头**：隔离攻击源，防止扩散
4. **保全证据**：注意保护现场和证据

**常用处置措施：**

| 措施 | 适用场景 | 注意事项 |
|------|---------|---------|
| **网络隔离** | 攻击扩散中 | 注意不要影响正常生产通信 |
| **设备断开** | 单设备被控制 | 评估对生产的影响 |
| **切换备用** | 有备用系统 | 确保备用系统未被感染 |
| **清除恶意代码** | 病毒/木马感染 | 工控环境慎用杀毒软件 |
| **恢复备份** | 系统被破坏 | 确认备份未被感染 |
| **修改口令** | 口令泄露 | 全面排查所有相关账户 |
| **封堵漏洞** | 漏洞利用攻击 | 先在测试环境验证 |
| **工艺处置** | 影响生产安全 | 由工艺人员操作 |

**特别注意：工控应急中的"不能做"**
- 不能随意重启 PLC（可能导致生产事故）
- 不能随意在工控主机上运行杀毒软件
- 不能随意断开网络（可能影响控制通信）
- 不能随意安装软件或工具
- 不能在未评估风险的情况下进行操作

**阶段五：恢复生产**

**恢复策略：**
- 先恢复关键系统
- 先恢复生产再完善安全
- 逐步恢复，验证正常后再推进

**恢复步骤：**
1. 制定恢复方案
2. 准备恢复资源
3. 逐系统恢复
4. 功能验证
5. 投入运行
6. 持续监控

**阶段六：总结改进**

**事后总结内容：**
- 事件原因分析
- 处置过程回顾
- 经验教训总结
- 改进措施制定
- 预案修订完善

**改进措施：**
- 技术层面：补充防护措施、加固薄弱环节
- 管理层面：完善制度、优化流程
- 人员层面：加强培训、提升能力
- 预案层面：修订预案、加强演练

### 6.4 典型场景应急预案

#### 6.4.1 勒索病毒应急预案

```
触发条件：发现文件被加密、勒索提示、大量主机异常

处置步骤：
1. 立即隔离受感染主机（断开网络）
2. 判断感染范围（哪些系统、哪些区域）
3. 保护未感染系统（加固、断网隔离）
4. 评估对生产的影响
5. 尝试恢复（从备份恢复，优先关键系统）
6. 溯源分析（感染途径、病毒类型）
7. 清理加固（清除残留、打补丁）
8. 逐步恢复生产

注意事项：
· 不要支付赎金（违法、有风险）
· 不要在生产系统上尝试解密
· 优先从备份恢复
· 防止二次感染
```

#### 6.4.2 PLC 异常应急预案

```
触发条件：PLC 程序异常、输出异常、状态异常

处置步骤：
1. 立即通知工艺人员和操作人员
2. 判断是否影响生产安全
3. 必要时切换到手动操作或紧急停车
4. 检查 PLC 程序和配置
5. 对比备份，确认是否被篡改
6. 分析异常原因（故障/攻击/误操作）
7. 恢复正常程序
8. 验证功能正常
9. 恢复生产

注意事项：
· 安全第一，必要时紧急停车
· 不要贸然重启 PLC
· 先确认程序完整性
· 保留异常状态的证据
```

#### 6.4.3 网络入侵应急预案

```
触发条件：发现未授权访问、异常操作、可疑连接

处置步骤：
1. 监测跟踪攻击者行为（在可控范围内）
2. 判断攻击范围和目的
3. 隔离受影响系统
4. 封堵攻击路径
5. 排查所有受影响账户
6. 全面口令更换
7. 系统加固和漏洞修复
8. 持续监控，防止反复

注意事项：
· 不要过早打草惊蛇
· 注意保全证据
· 全面排查，防止有后门
· 横向移动风险评估
```

### 6.5 应急演练

#### 6.5.1 演练目的

- 检验应急预案的有效性
- 提升应急响应能力
- 磨合团队协作
- 发现问题和不足
- 增强安全意识

#### 6.5.2 演练类型

| 类型 | 特点 | 频率 |
|------|------|------|
| **桌面演练** | 模拟场景，讨论推演 | 每半年 1 次 |
| **功能演练** | 针对某个环节实操 | 每年 1 次 |
| **全面演练** | 全流程实战演练 | 每 1-2 年 1 次 |

#### 6.5.3 演练注意事项

- 演练不能影响正常生产
- 优先在测试环境或非关键系统开展
- 演练前制定详细方案
- 演练过程做好记录
- 演练后及时总结改进
