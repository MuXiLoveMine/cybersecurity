# 实战案例：IEC 62443 在工业企业的落地实践

### 10.1 案例背景

某大型离散制造业企业，含 3 个厂区、200+ PLC、50+ HMI、12 条产线，原架构无网络分段、PLC 暴露在办公网、无统一日志，目标是用 18 个月达到 IEC 62443 SL2-T 合规。

### 10.2 落地阶段与里程碑

| 阶段 | 周期 | 主要工作 | 交付物 |
|------|------|----------|--------|
| 1.资产盘点 | M1-M2 | 全量资产清单、数据流图 | 资产台账、流量矩阵 |
| 2.风险评估 | M2-M3 | 威胁建模、SL-T 划定 | 风险报告、SL-T 矩阵 |
| 3.架构设计 | M3-M5 | 区域划分、DMZ 设计 | 安全架构蓝图 |
| 4.设备选型 | M5-M7 | 对照 4-2 选防火墙/网关 | 选型对比表 |
| 5.分步实施 | M7-M14 | 分厂区分批部署 | 验收报告 |
| 6.运维固化 | M14-M18 | 流程、培训、监测 | 运维手册 |

### 10.3 关键实践要点

**1）资产清单的"双维度"记录：**
```
资产ID    | 名称        | 类型 | IP            | 厂商  | 型号    | SL-C | SL-T | 关键性
A-PLC-001 | 1号线主控   | PLC | 10.10.30.10   | 西门子| S7-1500 | SL2  | SL2  | 高
A-HMI-005 | 1号线操作站 | HMI | 10.10.20.5    | 倍福  | CP6600  | SL2  | SL2  | 中
```
> 工控资产清单的难点是"暗资产"——未登记的工程师笔记本、临时调试设备。建议通过被动流量发现 + 准入控制双手段补全。

**2）分批实施降低风险：**
- 先在非关键辅线试点，再推广到主线
- 每次变更预留 4 小时观察窗口，关键指标（产量、停机时长）无异常方可推进
- 配置回退快照，确保 15 分钟内回退

**3）OPC UA 网关替代直接互联：**
- 原方案：MES 直接通过 Modbus TCP 访问 PLC（无认证、跨网段）
- 改造后：PLC 侧部署 OPC UA Server，MES 经 OPC UA 网关（TLS + 证书 + RBAC）访问
- 收益：消除 PLC 直连、统一审计、为后续 SL3 升级预留空间

**4）变更冻结期管理：**
- 关键订单交付期定义为"变更冻结期"，期间仅允许安全紧急补丁
- 冻结期前 2 周完成所有计划变更部署并验收

### 10.4 经验教训总结

| 教训 | 描述 | 规避方法 |
|------|------|----------|
| 设备能力虚标 | 部分厂商宣称 SL3 实际仅 SL2 | 要求第三方认证（ISASecure/IECEE） |
| 补丁影响实时性 | 某安全补丁导致 PLC 通信抖动 | 离线仿真验证 + 性能基线对比 |
| IT 工具不兼容 OT | EDR 误杀 PLC 通信进程 | OT 专用白名单 + 测试网先行 |
| 运维抵抗 | OT 运维拒绝接受新流程 | 联合培训 + 共同 KPI + 渐进推进 |
| 日志量爆炸 | 工控设备日志特性差 | 分级采集 + 关键事件优先策略 |

### 10.5 安全基线配置片段（工业防火墙）

```
# 工业防火墙安全基线（片段）
security-baseline:
  device-hardening:
    disable-telnet: true
    disable-http: true
    enable-ssh-v2-only: true
    snmp-v3-only: true
    ntp-auth: true
  logging:
    send-to: 10.10.40.10           # 日志服务器
    min-severity: warning
    include-payload: false         # 工控载荷可含敏感配方，默认不下发
  zones:
    - name: OT-Control
      sl-target: 2
      allowed-conduits:
        - to: DMZ
          protocol: opcua-tls
          direction: outbound-only
        - from: OT-Mgmt
          protocol: modbus-tcp
          function-codes: [3, 4, 6, 16]
          time-range: maintenance-window
```
