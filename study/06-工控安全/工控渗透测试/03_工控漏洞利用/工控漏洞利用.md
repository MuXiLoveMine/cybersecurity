# 工控漏洞利用

### 3.1 PLC 漏洞

#### 3.1.1 PLC 漏洞类型

| 漏洞类型 | 说明 | 危害 |
|----------|------|------|
| **认证绕过** | 可绕过 PLC 的认证机制 | 未授权读写程序和数据 |
| **命令注入** | 通过协议注入系统命令 | 完全控制 PLC |
| **缓冲区溢出** | 协议解析溢出 | 远程代码执行 / 拒绝服务 |
| **拒绝服务** | 畸形报文导致 PLC 崩溃 | 生产中断 |
| **固件篡改** | 可修改 PLC 固件 | 植入后门，长期控制 |
| **程序下载** | 未授权下载 PLC 程序 | 窃取工艺逻辑 |
| **程序上传** | 未授权上传恶意程序 | 修改控制逻辑 |
| **硬编码密码** | 固件中存在后门密码 | 直接登录设备 |

#### 3.1.2 常见 PLC 漏洞示例

**西门子 S7 系列：**
- CVE-2019-13944：S7-1200/1500 认证绕过漏洞，攻击者可以绕过认证读写 PLC 数据
- CVE-2020-15782：S7-1200/1500 内存损坏漏洞，可能导致拒绝服务
- CVE-2022-38465：S7-1200/1500 拒绝服务漏洞

**罗克韦尔 ControlLogix：**
- CVE-2017-6030：EtherNet/IP 模块漏洞，可导致拒绝服务
- CVE-2021-22681：Studio 5000 Logix Designer 漏洞

**施耐德 Modicon：**
- CVE-2018-7839：Modicon M340 信息泄露漏洞
- CVE-2019-6815：Modicon M580 拒绝服务漏洞

**三菱 Q 系列：**
- CVE-2019-10935：三菱 Q 系列 PLC 缓冲区溢出
- CVE-2020-5580：三菱 MELSEC iQ-R 系列漏洞

#### 3.1.3 PLC 攻击方式

**方式一：直接协议攻击**
```
攻击者 → 连接 PLC 通信端口 → 发送恶意协议报文 → 
利用漏洞 → 控制 PLC / 造成拒绝服务
```

**方式二：工程师站攻击**
```
攻击者 → 攻破工程师站 → 获取编程软件权限 → 
通过编程软件下载恶意程序到 PLC → 控制生产过程
```

**方式三：固件攻击**
```
攻击者 → 获取固件 → 修改固件植入后门 → 
通过各种方式刷入 PLC → 长期控制
```

### 3.2 HMI 漏洞

#### 3.2.1 HMI 安全问题

HMI（人机界面）是工控系统中最常被攻击的目标之一：

**常见问题：**
- 操作系统老旧（Windows XP/2000/7）
- 常年不打补丁
- 弱口令或默认口令
- 开启了不必要的服务
- 安装了多个工控软件，组件复杂
- 作为连接上层网络和控制层的跳板

#### 3.2.2 HMI 攻击路径

```
1. 发现 HMI 主机（端口扫描、网络侦察）
2. 攻击 HMI 操作系统
   - 利用 Windows 漏洞
   - 弱口令爆破（RDP/VNC）
   - 社会工程学
3. 获取 HMI 权限后
   - 查看生产画面和数据
   - 通过 HMI 操作控制设备
   - 利用 HMI 上的组态软件攻击 PLC
   - 作为跳板横向移动
```

### 3.3 工程师站漏洞

#### 3.3.1 工程师站的重要性

工程师站（Engineering Workstation）是工控系统的"大脑"：
- 用于 PLC 程序的编写和下载
- 存储有完整的源程序
- 拥有对 PLC 的完全控制权限
- 通常装有各种组态和编程软件

#### 3.3.2 攻击工程师站的价值

- 获取 PLC 源程序（商业秘密）
- 修改控制逻辑（物理破坏）
- 植入后门程序
- 控制整个生产线
- 作为深入渗透的跳板

#### 3.4.2 ISF（Industrial Control System Exploitation Framework）

ISF 是一个专门的工控渗透测试框架。

**主要功能：**
- PLC 漏洞利用
- 工控协议攻击
- HMI 攻击
- 信息收集
- 后渗透模块

**支持的设备：**
- 西门子 S7-300/400/1200/1500
- 罗克韦尔 ControlLogix/CompactLogix
- 施耐德 Modicon 系列
- 欧姆龙 PLC
- 三菱 PLC
