### 4.2 无认证/弱认证风险

```
认证机制分析:

S7Comm (经典协议):
- 默认无认证
- 可选密码保护 (但加密极弱)
- 密码通过XOR 0x55 "加密"
- 无证书认证
- 无会话绑定

风险:
1. 未授权读取PLC程序和数据
   - 攻击者可直接连接PLC读取数据块、标志位
   - 获取工艺参数和配方数据
   - 了解生产流程和控制系统逻辑

2. 未授权修改PLC程序
   - 直接写入恶意逻辑
   - 修改控制参数
   - 改变报警阈值

3. CPU控制
   - 停止PLC运行
   - 导致生产中断
   - 可能引发安全事故

示例攻击序列:
   连接 -> 读MW100 -> 写MW200 -> 停止CPU
   整个过程无需任何认证
```

### 4.3 明文传输风险

```
S7Comm明文传输风险:

所有S7Comm通信均以明文传输, 包括:
- 读取的PLC数据 (寄存器值、标志位)
- 写入的控制数据 (控制指令、参数)
- 密码验证数据 (XOR加密, 等同明文)
- PLC诊断信息
- 程序代码上传/下载

攻击场景:
1. 网络嗅探:
   - 使用Wireshark/tcpdump抓包
   - 直接获取所有PLC通信数据
   - 提取工艺参数和配置信息

2. 中间人攻击:
   - ARP欺骗重定向流量
   - 修改读写数据
   - 注入恶意控制命令

3. 流量重放:
   - 录制合法操作
   - 在之后重放
   - 例如重放停止CPU的命令
```

### 4.4 缓冲区溢出风险

```
S7协议实现中的缓冲区溢出:

已知漏洞类型:
1. TSAP处理溢出
   - 过长的TSAP字段
   - 导致COTP层缓冲区溢出

2. 变量规格溢出
   - 超长Item数据
   - 超大读取长度字段
   - 导致S7协议层缓冲区溢出

3. PDU长度溢出
   - Length字段与实际数据不匹配
   - 整数溢出导致缓冲区过小

4. 密码字段溢出
   - 超长密码字段
   - 导致密码验证函数溢出

历史CVE:
- CVE-2019-13926: S7-300/400 PLC认证绕过
- CVE-2020-6905: S7-1500缓冲区溢出
- CVE-2021-3564: S7-1200/1500权限提升
```

### 4.5 重放攻击风险

```
S7Comm重放攻击:

攻击原理:
1. 录制合法的S7通信会话
2. 提取关键操作 (如写操作)
3. 在之后重放该操作

示例:
   时间T1: 操作员写MW100=1 (启动泵)
   时间T2: 攻击者重放 "写MW100=1"
   时间T3: 操作员写MW100=0 (停止泵)
   时间T4: 攻击者重放 "写MW100=1" (重新启动泵)

缓解:
- S7Comm无防重放机制
- S7CommPlus有序列号和时间戳保护
```
