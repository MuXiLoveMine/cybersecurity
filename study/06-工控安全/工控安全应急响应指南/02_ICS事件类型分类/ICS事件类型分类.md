# ICS事件类型分类

### 2.1 恶意代码事件

```
恶意代码事件类型:

1. 工控专用恶意代码:
   ├── Stuxnet类: 直接攻击PLC, 修改控制逻辑
   ├── BlackEnergy类: 攻击SCADA系统, 远程操作设备
   ├── Industroyer类: 通过工控协议直接操控设备
   └── Triton类: 攻击安全仪表系统(SIS)

2. 通用恶意代码波及:
   ├── 勒索软件: 加密工程站/HMI文件
   ├── 蠕虫: 通过网络传播感染OT网络
   ├── 木马: 远程控制工程站
   └── 矿机: 占用工程站计算资源

3. 恶意代码行为特征:
   ├── 网络扫描: 枚举工控设备
   ├── 协议操作: 发送控制命令
   ├── 数据窃取: 上传工艺参数
   ├── 代码注入: 修改PLC程序
   └── 数据擦除: 破坏恢复能力
```

### 2.2 勒索软件事件

```
工控勒索软件事件分析:

特征:
- 目标: 工程站、SCADA服务器、历史数据库
- 影响: 加密项目文件、配置文件、HMI画面
- 后果: 无法操作PLC, 无法查看工艺状态
- 间接影响: 可能导致生产中断
- 不直接攻击: PLC固件 (通常)

历史案例:
- 2021 Colonial Pipeline: DarkSide勒索软件
  影响: 燃油管道停运6天, 美国东海岸燃油短缺
  原因: IT网络被攻击, 主动关闭OT网络
  
- 2020 Molex: EKANS勒索软件
  影响: 生产线停机
  特征: 专门终止工控相关进程
  
- 2019 Norsk Hydro: LockerGoga
  影响: 铝业生产中断, 手动操作
  损失: 约7100万美元

响应策略:
1. 不要支付赎金 (鼓励未来攻击)
2. 立即隔离受感染系统
3. 使用离线备份恢复
4. 验证OT系统完整性
5. 加强IT/OT隔离
```

### 2.3 拒绝服务事件

```
ICS拒绝服务(DoS)攻击类型:

1. 网络层DoS:
   ├── SYN Flood: 耗尽PLC连接资源
   ├── UDP Flood: 耗尽网络带宽
   ├── ICMP Flood: Ping洪水
   └── 畸形包: 导致设备崩溃

2. 应用层DoS:
   ├── 连接耗尽: 大量S7/Modbus连接
   ├── 请求洪泛: 快速发送读写请求
   ├── 长连接: 占用连接不释放
   └── 超大PDU: 发送超大数据单元

3. 协议特定DoS:
   ├── Modbus: 大量写线圈操作
   ├── S7: 快速CPU启停命令
   ├── DNP3: 链路层洪泛
   └── OPC: DCOM连接耗尽

4. 资源耗尽DoS:
   ├── CPU过载: 复杂运算请求
   ├── 内存耗尽: 大量数据请求
   ├── 连接表耗尽: 大量连接
   └── 通信缓冲区: 超大报文
```

### 2.4 物理破坏事件

```
物理破坏攻击:

1. 直接物理破坏:
   ├── PLC代码修改: 改变控制参数导致超速/超压
   ├── 安全联锁禁用: 禁用SIS保护功能
   ├── 阀门控制: 关闭/打开错误阀门
   ├── 温度控制: 修改加热/冷却参数
   └── 电机控制: 修改频率/方向

2. 间接物理破坏:
   ├── 报警抑制: 隐藏异常状态
   ├── 数据伪造: 使操作员看到正常值
   ├── HMI劫持: 在HMI上显示虚假数据
   └── 传感器欺骗: 注入虚假传感器信号

3. 破坏后果:
   ├── 设备损坏: 泵/阀/电机损坏
   ├── 产品报废: 不合格产品
   ├── 环境污染: 有害物质泄漏
   ├── 火灾爆炸: 可燃物失控
   └── 人员伤亡: 机械/化学伤害
```

### 2.5 操作员误操作事件

```
操作员误操作分类:

1. 配置错误:
   ├── PLC参数修改: 错误设定值
   ├── 量程范围: 传感器量程配置错误
   ├── 联锁逻辑: 安全联锁被误禁用
   └── 通信配置: 错误的网络地址

2. 操作错误:
   ├── 错误操作: 按错按钮/选错设备
   ├── 时序错误: 操作顺序不当
   ├── 参数输入: 输入错误数值
   └── 维护错误: 维护后未恢复

3. 程序错误:
   ├── 下载错误: 下载了错误的程序版本
   ├── 在线修改: 运行中错误修改
   ├── 强制变量: 强制了错误的变量值
   └── 删除程序: 误删除功能块

4. 预防措施:
   ├── 变更管理: 严格的变更审批流程
   ├── 操作确认: 关键操作双人确认
   ├── 模拟验证: 先在模拟器测试
   └── 权限管理: 最小权限原则
```
