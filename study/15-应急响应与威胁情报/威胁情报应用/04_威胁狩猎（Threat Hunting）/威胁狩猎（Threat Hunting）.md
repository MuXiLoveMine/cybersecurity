# 威胁狩猎（Threat Hunting）

### 4.1 威胁狩猎概述

**威胁狩猎（Threat Hunting）** 是主动、有计划地搜索网络和系统中潜伏的、未被检测到的威胁的过程。

**与应急响应的区别：**

| 维度 | 应急响应 | 威胁狩猎 |
|------|----------|----------|
| **触发方式** | 被动，事件发生后响应 | 主动，主动寻找威胁 |
| **驱动因素** | 告警驱动 | 假设/情报驱动 |
| **目标** | 处理已发生的事件 | 发现未知的潜伏威胁 |
| **频率** | 按需（事件发生时） | 持续/定期 |
| **类比** | 救火 | 消防检查/找隐患 |

**威胁狩猎的价值：**
- 发现绕过防御的攻击
- 缩短攻击者的停留时间（Dwell Time）
- 提升检测能力
- 改进防御措施
- 验证安全控制的有效性

### 4.2 威胁狩猎方法

#### 4.2.1 假设驱动狩猎（Hypothesis-Driven Hunting）

**方法：** 基于威胁情报和攻击知识，提出假设，然后验证假设是否成立。

**流程：**
1. 提出假设（"攻击者可能使用了 XX 技术进行持久化"）
2. 设计狩猎方案（需要哪些数据，如何分析）
3. 收集和分析数据
4. 验证假设（成立或不成立）
5. 如果成立，进行响应和处置
6. 总结和改进

**假设来源：**
- 威胁情报（新的攻击技术、攻击组织活动）
- ATT&CK 框架（有哪些攻击技术我们没检测）
- 安全事件（从事件中学习，找同类问题）
- 行业报告（同行遇到的攻击）
- 红队经验（红队用了什么方法）

**示例假设：**
- "攻击者可能使用了注册表 Run 键进行持久化"
- "攻击者可能通过 Pass-the-Hash 进行横向移动"
- "攻击者可能使用了 WMI 进行远程执行"
- "攻击者可能在 DNS 流量中隐藏 C2 通信"

#### 4.2.2 情报驱动狩猎（Intelligence-Driven Hunting）

**方法：** 基于威胁情报（IOC、TTP、攻击者画像），在环境中寻找匹配的威胁。

**流程：**
1. 获取威胁情报（如新的 IOC、新的攻击手法）
2. 在环境中搜索匹配的指标和行为
3. 分析搜索结果
4. 确认是否有威胁存在
5. 响应和处置

**情报来源：**
- 商业威胁情报
- 开源威胁情报
- 行业共享情报
- 内部历史事件

**示例：**
- 收到新的 C2 IP 情报 → 在网络流量和日志中搜索
- 了解到新的 Webshell 特征 → 在 Web 服务器中搜索
- 发现新的 APT 组织活动 → 检查是否有类似攻击

#### 4.2.3 数据驱动狩猎（Data-Driven Hunting）

**方法：** 通过数据分析和异常检测，发现异常行为和潜在威胁。

**流程：**
1. 收集大量数据（日志、流量、终端数据等）
2. 使用统计分析、机器学习等方法
3. 发现异常模式和行为
4. 分析异常，判断是否为威胁
5. 进一步调查和验证

**常用技术：**
- 统计异常检测（基线对比）
- 机器学习（聚类、分类）
- UEBA（用户和实体行为分析）
- 数据可视化
- 关联分析

**示例：**
- 分析用户登录时间，发现异常时间登录
- 分析网络流量，发现异常的数据传输
- 分析进程行为，发现可疑的进程活动
- 分析文件访问模式，发现异常的数据访问

#### 4.2.4 攻击链狩猎（Kill Chain Hunting）

**方法：** 按照攻击链（Cyber Kill Chain 或 ATT&CK）的各个阶段，系统性地搜索攻击痕迹。

**流程：**
1. 选择攻击框架（如 ATT&CK）
2. 逐个战术/技术检查是否有检测覆盖
3. 对没有检测覆盖的技术进行狩猎
4. 寻找攻击链的各个环节的痕迹
5. 拼凑完整的攻击链

**优势：**
- 系统性强，不遗漏
- 可以发现防御盲区
- 从整体上理解攻击

### 4.3 威胁狩猎流程

**标准狩猎流程（7步）：**

```
1. 假设 → 2. 计划 → 3. 数据收集 → 4. 分析 → 5. 验证 → 6. 响应 → 7. 改进
```

#### 步骤 1：假设（Hypothesis）
- 确定狩猎的目标和范围
- 提出明确的假设
- 评估假设的优先级

#### 步骤 2：计划（Plan）
- 设计狩猎方案
- 确定需要的数据来源
- 选择分析工具和方法
- 制定时间计划

#### 步骤 3：数据收集（Data Collection）
- 收集相关数据（日志、流量、终端数据等）
- 数据清洗和预处理
- 数据整合和关联

#### 步骤 4：分析（Analysis）
- 使用各种分析方法
- 寻找异常和可疑行为
- 深入调查可疑线索
- 记录分析过程

#### 步骤 5：验证（Verification）
- 验证发现是否为真实威胁
- 排除误报和正常行为
- 评估威胁的严重程度
- 确定影响范围

#### 步骤 6：响应（Response）
- 如果发现真实威胁，启动应急响应
- 遏制、根除、恢复
- 收集攻击 IOC 和 TTP
- 更新检测规则

#### 步骤 7：改进（Improve）
- 总结狩猎结果
- 更新检测规则
- 改进安全防护
- 记录狩猎知识
- 优化狩猎流程

### 4.4 威胁狩猎工具

#### 4.4.1 数据平台
- **SIEM**：Splunk、Elastic SIEM、QRadar 等
- **数据湖**：Hadoop、ClickHouse 等
- **时序数据库**：InfluxDB 等

#### 4.4.2 分析工具
- **Jupyter Notebook**：交互式数据分析
- **Python/R**：数据分析和可视化
- **ELK Stack**：日志搜索和分析
- **Splunk**：大数据搜索和分析

#### 4.4.3 端点工具
- **EDR**：CrowdStrike、SentinelOne、奇安信等
- **Sysmon**：系统监视工具
- **Auditd**：Linux 审计
- **OSQuery**：SQL 查询系统信息

#### 4.4.4 网络工具
- **NDR**：网络检测与响应
- **Wireshark**：流量分析
- **Zeek (Bro)**：网络流量分析
- **Suricata**：IDS/IPS

#### 4.4.5 威胁情报工具
- **TIP**：威胁情报平台
- **MISP**：开源威胁情报平台
- **ATT&CK Navigator**：ATT&CK 可视化

### 4.5 实战案例：威胁狩猎发现潜伏的 APT

**背景：**
某金融企业安全团队在参加安全会议时了解到某 APT 组织针对金融行业的最新攻击手法——使用 DNS 隧道进行 C2 通信。决定进行一次威胁狩猎。

**狩猎过程：**

1. **提出假设**
   - 假设：该 APT 组织可能已经渗透到我们的网络，使用 DNS 隧道进行 C2 通信
   - 依据：我们属于该组织的目标行业，且 DNS 流量监控较弱
   - 优先级：高

2. **制定计划**
   - 狩猎周期：2 周
   - 数据来源：DNS 日志、防火墙日志、EDR 数据
   - 分析方法：
     - 统计异常 DNS 查询（超长域名、异常记录类型）
     - 查找罕见的 DNS 记录类型（TXT、NULL 等）
     - 分析 DNS 查询的时间模式
     - 关联 DNS 查询和进程

3. **数据收集**
   - 收集过去 30 天的 DNS 日志（约 5 亿条）
   - 收集同期的 EDR 进程数据
   - 数据清洗和预处理

4. **分析过程**
   - 第一周：统计分析
     - 按域名长度排序，发现部分超长域名
     - 分析 DNS 查询频率，发现几个 IP 有异常高频查询
     - 发现一些罕见的 TXT 记录查询

   - 第二周：深入调查
     - 聚焦几个可疑的内部 IP
     - 关联 EDR 进程数据，发现 DNS 查询来自一个名为 `svchost.exe` 的进程
     - 进一步分析：该 `svchost.exe` 的路径异常（在用户临时目录）
     - 确认：这是一个伪装成 svchost 的恶意程序，通过 DNS 隧道进行 C2 通信

5. **验证确认**
   - 对可疑主机进行深入分析
   - 确认存在恶意程序和 DNS 隧道 C2
   - 追溯发现：攻击者 3 个月前通过钓鱼邮件入侵
   - 评估影响：2 台服务器被入侵，部分数据被窃取

6. **应急响应**
   - 立即隔离受感染主机
   - 全面排查其他主机是否被入侵
   - 清除恶意程序和后门
   - 修补被利用的漏洞
   - 加强 DNS 监控和检测

7. **总结改进**
   - 狩猎成果：发现了一个潜伏 3 个月的 APT 攻击
   - 新增 DNS 隧道检测规则
   - 加强 DNS 流量监控
   - 将该 TTP 加入检测库
   - 定期开展类似的威胁狩猎

**经验教训：**
- 威胁狩猎可以发现传统检测手段遗漏的威胁
- 威胁情报是威胁狩猎的重要输入
- DNS 流量是重要的监控对象
- 持续狩猎比单次狩猎更有价值

### 4.6 威胁狩猎成熟度

**等级 1：初始级**
- 没有正式的威胁狩猎
- 偶尔进行临时调查
- 依赖告警和事件

**等级 2：可重复级**
- 有基本的狩猎流程
- 定期进行狩猎活动
- 使用简单的分析工具

**等级 3：已定义级**
- 有明确的狩猎团队
- 标准化的狩猎流程
- 多种狩猎方法
- 与威胁情报结合

**等级 4：已管理级**
- 成熟的狩猎项目
- 量化的效果度量
- 自动化狩猎工具
- 知识管理和共享

**等级 5：优化级**
- 持续优化的狩猎能力
- 高级分析和机器学习
- 预测性狩猎
- 情报驱动的主动防御
