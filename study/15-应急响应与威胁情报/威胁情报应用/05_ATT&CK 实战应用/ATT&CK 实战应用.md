# ATT&CK 实战应用

### 5.1 ATT&CK 的应用场景

MITRE ATT&CK 不仅仅是一个知识库，更是一个实用的工具，可以应用于多个场景：

| 应用场景 | 说明 |
|----------|------|
| **威胁建模** | 基于 ATT&CK 评估可能面临的威胁 |
| **检测开发** | 针对具体技术开发检测规则 |
| **红队评估** | 基于 ATT&CK 规划和执行红队行动 |
| **蓝队防御** | 基于 ATT&CK 提升防御能力 |
| **威胁情报** | 用 ATT&CK 描述和共享威胁情报 |
| **安全评估** | 评估安全能力覆盖度 |
| **SOC 运营** | 指导安全运营工作 |
| **工具开发** | 基于 ATT&CK 开发安全工具 |

### 5.2 威胁建模应用

#### 5.2.1 基于 ATT&CK 的威胁建模方法

**步骤：**

1. **确定范围**
   - 确定要评估的系统和环境
   - 确定关注的攻击者类型（犯罪软件、APT、内部威胁等）

2. **识别威胁**
   - 基于 ATT&CK 列出可能的攻击技术
   - 参考相关行业的攻击案例
   - 结合威胁情报

3. **评估影响**
   - 评估每种技术成功后的影响
   - 考虑业务影响、数据影响等

4. **评估可能性**
   - 评估每种攻击发生的可能性
   - 考虑攻击者能力、目标价值、防护水平等

5. **排序优先级**
   - 综合影响和可能性，确定风险等级
   - 确定应对的优先级

#### 5.2.2 实战：某企业基于 ATT&CK 的威胁建模

**背景：**
某互联网企业希望基于 ATT&CK 建立威胁模型，评估安全风险，指导安全建设。

**实施过程：**

1. **确定范围**
   - 评估对象：核心业务系统
   - 关注的威胁：Web 攻击、勒索软件、内部威胁

2. **技术映射**
   - 从 ATT&CK 中选出相关的战术和技术
   - 针对每个技术，评估当前的防护和检测能力
   - 用 ATT&CK Navigator 生成覆盖热力图

3. **风险评估**
   - 高风险高影响的技术：优先加强
   - 高风险低影响的技术：适当关注
   - 低风险高影响的技术：做好准备
   - 低风险低影响的技术：常规监控

4. **输出成果**
   - ATT&CK 覆盖图（当前防护覆盖情况）
   - 风险矩阵
   - 安全建设路线图

### 5.3 检测规则开发

#### 5.3.1 基于 ATT&CK 的检测开发流程

1. **选择技术**
   - 从威胁建模的结果中选择高优先级技术
   - 参考威胁情报，关注活跃的攻击技术

2. **研究技术细节**
   - 阅读 ATT&CK 技术页面
   - 了解技术的实现方式
   - 研究检测方法和思路
   - 参考公开的检测规则

3. **开发检测规则**
   - 选择合适的数据源（日志、EDR、网络等）
   - 编写检测规则（Sigma、Snort、Splunk SPL 等）
   - 考虑误报和漏报的平衡

4. **测试验证**
   - 在测试环境测试
   - 用攻击工具/红队验证
   - 统计误报率和检测率

5. **部署上线**
   - 部署到生产环境
   - 监控运行情况
   - 持续优化规则

#### 5.3.2 Sigma 规则示例

Sigma 是一种通用的检测规则格式，可以转换为各种 SIEM 的查询语句。

**示例：检测 WMI 远程执行（T1047）**

```yaml
title: WMI Remote Command Execution
id: 12345678-1234-1234-1234-123456789012
status: experimental
description: 检测通过 WMI 在远程系统执行命令的行为
author: Security Team
date: 2024/01/01
references:
    - https://attack.mitre.org/techniques/T1047/
tags:
    - attack.execution
    - attack.t1047
logsource:
    product: windows
    service: security
detection:
    selection:
        EventID: 4688
        NewProcessName|endswith: '\wmic.exe'
        CommandLine|contains|all:
            - '/node:'
            - 'process call create'
    condition: selection
falsepositives:
    - 合法的系统管理
    - 监控工具
level: medium
```

### 5.4 红队与蓝队应用

#### 5.4.1 红队应用

**ATT&CK 在红队中的用途：**

1. **规划攻击路径**
   - 基于 ATT&CK 设计攻击方案
   - 选择合适的战术和技术
   - 确保攻击覆盖多个阶段

2. **记录攻击行为**
   - 用 ATT&CK 技术记录使用的攻击方法
   - 标准化攻击记录格式
   - 便于后续分析和报告

3. **评估防御能力**
   - 用 ATT&CK 矩阵展示哪些技术被检测到
   - 哪些技术成功绕过
   - 识别防御盲区

4. **生成报告**
   - 用 ATT&CK 矩阵展示评估结果
   - 直观展示防御覆盖情况
   - 提供改进建议

**红队评估报告中的 ATT&CK 矩阵示例：**
- 绿色：被检测到的技术
- 黄色：部分检测到
- 红色：未被检测到（攻击成功）
- 空白：未使用该技术

#### 5.4.2 蓝队应用

**ATT&CK 在蓝队中的用途：**

1. **防御差距分析**
   - 对照 ATT&CK 检查防御覆盖
   - 发现防御盲区
   - 规划防御建设优先级

2. **检测能力评估**
   - 每个技术的检测覆盖率
   - 哪些技术完全没有检测
   - 哪些技术检测能力弱

3. **告警分析**
   - 将告警映射到 ATT&CK 技术
   - 理解攻击处于哪个阶段
   - 关联同一攻击的多个告警

4. **威胁狩猎**
   - 基于 ATT&CK 技术设计狩猎方案
   - 系统性地检查每种技术
   - 发现绕过检测的攻击

### 5.5 威胁情报应用

#### 5.5.1 ATT&CK 在威胁情报中的作用

1. **标准化描述**
   - 用 ATT&CK 技术描述攻击手法
   - 统一术语和分类
   - 便于理解和共享

2. **情报关联**
   - 通过共享的 ATT&CK 技术关联不同攻击事件
   - 识别同一攻击者的不同活动
   - 构建攻击者画像

3. **检测映射**
   - 情报中的 TTP 可以直接映射到检测规则
   - 快速将情报转化为检测能力
   - 提高情报的可操作性

#### 5.5.2 实战：基于 ATT&CK 的威胁情报分析

**场景：**
安全团队收到一份威胁报告，描述了某 APT 组织的最新攻击活动。报告使用自然语言描述，信息分散。

**处理过程：**

1. **提取 TTP**
   - 仔细阅读报告
   - 提取攻击手法
   - 映射到 ATT&CK 技术

2. **结构化整理**
   - 将提取的 TTP 整理成 ATT&CK 格式
   - 标注每个技术的置信度
   - 补充相关的 IOC

3. **内部映射**
   - 将这些技术与内部的检测规则映射
   - 检查哪些技术我们已有检测
   - 哪些技术没有检测，需要补充

4. **应用部署**
   - 已有检测的技术：加强监控，提高优先级
   - 没有检测的技术：紧急开发检测规则
   - 将 IOC 导入 SIEM 和 EDR
   - 开展针对性的威胁狩猎

**成果：**
- 将非结构化的威胁报告转化为可操作的情报
- 快速提升了对该 APT 组织的检测能力
- 明确了防御差距和改进方向

### 5.6 ATT&CK Navigator 使用

ATT&CK Navigator 是一个可视化工具，用于操作和展示 ATT&CK 矩阵。

**主要功能：**
- 查看 ATT&CK 矩阵
- 创建图层（Layer），标记不同的状态
- 支持多种着色方案（检测覆盖率、攻击频率等）
- 支持多图层叠加对比
- 导出和分享图层

**应用场景：**
- 检测覆盖率可视化
- 红队评估结果展示
- 威胁组织 TTP 展示
- 安全能力评估
- 威胁狩猎规划

**使用技巧：**
1. **创建检测覆盖图层**：标记哪些技术有检测，哪些没有
2. **创建威胁情报图层**：标记某攻击组织使用的技术
3. **图层叠加对比**：将威胁图层和检测图层对比，找出防御盲区
4. **按战术查看**：逐个战术分析，系统性评估
