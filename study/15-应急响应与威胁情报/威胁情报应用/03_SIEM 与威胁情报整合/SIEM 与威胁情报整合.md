# SIEM 与威胁情报整合

### 3.1 为什么要整合

**SIEM 的痛点：**
- 告警太多，真假难辨
- 缺乏上下文，不知道告警的严重性
- 检测已知威胁能力不足
- 无法快速判断告警的影响和风险

**威胁情报的价值：**
- 提供威胁上下文
- 提高检测准确率
- 加速响应
- 识别高级威胁

**整合的效果：**
- 1 + 1 > 2
- SIEM 提供数据，情报提供认知
- 提升整体检测和响应能力

### 3.2 整合场景

#### 3.2.1 IOC 匹配告警
**场景**：将威胁情报中的 IOC（IP、域名、哈希等）导入 SIEM，当日志中匹配到 IOC 时产生告警。

**实现方式：**
- 将 IOC 导入 SIEM 的威胁情报库
- 配置关联规则，将日志与 IOC 匹配
- 匹配成功则触发告警

**价值：**
- 自动检测已知威胁
- 提高告警的准确性和优先级
- 减少人工分析时间

**示例规则（伪代码）：**
```
当 防火墙日志.目的IP 在 威胁情报.恶意IP 列表中
并且 连接状态 = 已建立
则 产生高优先级告警
  告警名称：连接到已知恶意 IP
  告警等级：高
  附加信息：IP信誉、关联恶意软件、关联攻击者
```

#### 3.2.2 告警丰富化
**场景**：对 SIEM 产生的告警，自动查询威胁情报，补充上下文信息，帮助分析师快速判断。

**实现方式：**
- 告警产生后，自动提取 IOC（IP、域名、哈希等）
- 查询威胁情报平台，获取该 IOC 的详细信息
- 将情报信息附加到告警中

**丰富化内容：**
- IOC 的信誉评级（恶意/可疑/正常）
- 关联的恶意软件家族
- 关联的攻击组织
- 首次发现时间、最近发现时间
- 地理位置和 ASN
- 标签和分类
- 置信度

**价值：**
- 分析师无需手动查询情报
- 快速判断告警的严重性
- 减少 MTTD/MTTR
- 提高分析效率

#### 3.2.3 告警优先级调整
**场景**：根据威胁情报信息动态调整告警的优先级。

**实现方式：**
- 根据告警匹配的 IOC 信誉调整优先级
- 匹配高置信度恶意 IOC → 提升优先级
- 匹配已知白名单 → 降低优先级
- 关联 APT 组织 → 大幅提升优先级

**价值：**
- 分析师优先处理高优先级告警
- 减少告警疲劳
- 重要告警不被淹没

#### 3.2.4 上下文关联分析
**场景**：利用威胁情报中的 TTP 和攻击者信息，进行更深层次的关联分析。

**实现方式：**
- 将告警与 ATT&CK 技术关联
- 判断攻击者所处的攻击阶段
- 关联同一攻击者的多个告警
- 构建完整的攻击链

**价值：**
- 从单点告警到完整攻击链
- 更好地理解攻击意图
- 预测攻击者的下一步行动
- 支持主动防御

### 3.3 整合架构

```
┌─────────────────┐
│  威胁情报源       │
│ (商业/开源/内部)  │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  威胁情报平台     │  ← 情报收集、处理、分析、管理
│  (TIP/MISP)     │
└────────┬────────┘
         │ API / TAXII
         ▼
┌─────────────────┐
│   SIEM 平台      │  ← 日志收集、关联分析、告警
│                 │
│  ┌───────────┐  │
│  │ 威胁情报库 │  │  ← IOC、TTP 等情报数据
│  └───────────┘  │
│                 │
│  ┌───────────┐  │
│  │ 关联规则   │  │  ← 情报匹配规则
│  └───────────┘  │
│                 │
│  ┌───────────┐  │
│  │ 告警丰富化 │  │  ← 自动补充情报上下文
│  └───────────┘  │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  SOC 分析师      │  ← 告警分析和响应
└─────────────────┘
```

### 3.4 整合最佳实践

#### 3.4.1 IOC 管理
- **去重**：多个来源的相同 IOC 要合并
- **评分**：综合多个来源给出置信度评分
- **过期管理**：IOC 有生命周期，定期清理过期 IOC
- **白名单**：维护内部白名单，防止误报
- **分类**：按类型、严重程度、攻击家族等分类

#### 3.4.2 性能优化
- **增量更新**：只更新变化的 IOC，减少全量同步
- **本地缓存**：在 SIEM 本地缓存 IOC，提高匹配速度
- **批量处理**：批量导入和匹配，提高效率
- **分级匹配**：高优先级 IOC 实时匹配，低优先级定时匹配

#### 3.4.3 误报控制
- **白名单机制**：内部 IP、域名、常用软件等加入白名单
- **上下文判断**：不是所有匹配都告警，结合上下文判断
- **阈值调整**：根据误报情况调整匹配阈值
- **反馈闭环**：分析师标记误报，反馈给情报团队，优化 IOC 质量

#### 3.4.4 运营流程
- **情报更新频率**：高优先级情报实时更新，普通情报定期更新
- **告警响应流程**：情报相关告警的特殊处理流程
- **反馈机制**：建立情报质量反馈机制
- **度量指标**：监控情报的命中率、误报率、检测效果等

### 3.5 实战案例：SIEM 情报整合提升检测效率

**背景：**
某企业 SIEM 每天产生大量告警，分析师疲于应付，很多重要告警被淹没，MTTD 长达数小时。

**实施：**

1. **第一阶段：IOC 导入与匹配**
   - 接入商业威胁情报源
   - 将恶意 IP、域名、URL 导入 SIEM
   - 配置 IOC 匹配规则
   - 效果：新增一类高置信度告警，检测出了之前漏报的 C2 通信

2. **第二阶段：告警丰富化**
   - 开发自动化脚本，告警产生后自动查询情报
   - 将信誉、恶意软件家族、攻击者等信息附加到告警
   - 按情报信誉自动调整告警优先级
   - 效果：分析师分析告警的时间缩短 60%

3. **第三阶段：TTP 关联**
   - 将告警映射到 ATT&CK 战术和技术
   - 开发攻击链关联规则，识别多阶段攻击
   - 接入 TTP 类情报，指导威胁狩猎
   - 效果：MTTD 从 4 小时缩短到 30 分钟

**成果：**
- MTTD 降低 87.5%（4小时 → 30分钟）
- 告警误报率降低 40%
- 分析师人均处理告警数提升 2 倍
- 发现了多个之前未发现的潜伏威胁
