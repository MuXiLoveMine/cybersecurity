# 事件总结报告

### 事件统计
- 发现到隔离: 5分钟
- 完全遏制: 1小时
- 根除完成: 2小时
- 业务恢复: 4小时(核心), 48小时(全部)
- 影响主机: 3台服务器 + 1台工作站
- 加密文件: ~85000个
- 数据泄露: 200GB (含客户PII数据)

### 根因分析
1. VPN设备存在未修补漏洞(CVE-2023-27997)
2. 缺乏网络分段,工作站可直连文件服务器
3. 域服务账户使用弱密码,可被Kerberoasting
4. Print Spooler服务未禁用
5. 终端缺少EDR防护

### 改进措施
1. [已完成] VPN设备升级到最新固件
2. [已完成] 部署网络分段,工作站不可直连服务器
3. [已完成] 服务账户使用强密码+定期轮换
4. [已完成] 所有域控禁用Print Spooler
5. [进行中] 全量部署EDR到所有终端
6. [进行中] 备份策略改为3-2-1-1,增加不可变备份
7. [计划中] 实施AD Tier模型
8. [计划中] 部署RDP网关+MFA
9. [计划中] 定期进行勒索软件演练
```

### 10.3 关键经验教训

| 经验 | 教训 | 改进方向 |
|------|------|----------|
| 备份是救命稻草 | 3天前备份可用,避免了支付赎金 | 加强备份频率和不可变备份 |
| 隔离必须快速 | 5分钟内完成隔离阻止了更大范围扩散 | 自动化隔离脚本和流程 |
| 监控有盲区 | EDR只覆盖了部分服务器 | 全量覆盖所有终端 |
| 横向移动未检测 | Kerberoasting和PrintNightmare未被检测 | 部署AD审计和异常检测 |
| 数据泄露先于加密 | 攻击者提前6小时外传数据 | 加强出站流量监控 |
| 员工意识不足 | VPN漏洞被利用获取初始访问 | 安全意识培训+MFA |
