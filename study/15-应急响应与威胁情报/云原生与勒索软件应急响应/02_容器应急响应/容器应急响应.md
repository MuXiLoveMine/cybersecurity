# 容器应急响应

### 2.1 容器取证概述

容器取证是云原生应急响应的核心技能。与传统主机取证不同，容器具有生命周期短、文件系统分层、网络命名空间隔离等特点。

**容器取证三大挑战：**

1. **瞬态性**：容器随时可能被销毁，证据转瞬即逝
2. **分层文件系统**：容器修改层（writable layer）在容器删除后丢失
3. **资源隔离**：PID/网络/IPC命名空间隔离导致取证工具受限

**取证原则：**

| 原则 | 说明 | 操作要点 |
|------|------|----------|
| 快速响应 | 容器随时可能被销毁 | 第一时间暂停容器或制作快照 |
| 非侵入式 | 不修改容器状态 | 只读模式挂载，使用工具导出 |
| 完整性 | 确保证据不被篡改 | 计算哈希，记录时间线 |
| 可重现 | 取证过程可复现 | 记录所有命令和参数 |
| 链式保管 | 证据流转可追踪 | 记录交接过程 |

### 2.2 容器入侵常见场景

**场景1：恶意镜像运行**

攻击者通过漏洞或配置缺陷拉取并运行恶意容器镜像，在集群中植入后门。

```bash
# 检查最近创建的容器
docker ps -a --format "table {{.ID}}\t{{.Image}}\t{{.CreatedAt}}\t{{.Status}}" | head -20

# 检查容器镜像来源
docker inspect <container_id> --format '{{.Config.Image}} {{.Image}}'
docker history <image_name> --no-trunc

# 检查可疑镜像层（查找异常命令）
docker history <image_name> --format "table {{.CreatedBy}}\t{{.Size}}" --no-trunc

# 检查镜像中的可疑文件
docker run --rm -it <image_name> find / -name "*.sh" -o -name "*.py" | grep -v proc
```

**场景2：容器逃逸**

攻击者从容器突破隔离，获取宿主机权限。

```bash
# 检查容器是否以特权模式运行
docker inspect <container_id> --format '{{.HostConfig.Privileged}}'

# 检查容器能力(capabilities)
docker inspect <container_id> --format '{{.HostConfig.CapAdd}}'

# 检查是否挂载了敏感目录
docker inspect <container_id> --format '{{json .Mounts}}' | jq .

# 检查容器是否使用host网络
docker inspect <container_id> --format '{{.HostConfig.NetworkMode}}'

# 检查容器是否使用host PID
docker inspect <container_id> --format '{{.HostConfig.PidMode}}'

# 检查宿主机是否有可疑进程
ps auxf | grep -E "containerd|docker|kubelet"
```

**容器逃逸检测规则（Falco）：**

```yaml
# falco_rules.local.yaml - 容器逃逸检测规则
- rule: Container Escaped to Host
  desc: Detect processes running on host that originated from a container
  condition: >
    spawned_process and container and proc.vpid=1
  output: >
    Container escape detected (user=%user.name
    proc=%proc.name pid=%proc.pid container_id=%container.id
    image=%container.image.repository)
  priority: CRITICAL
  tags: [container, escape, mitre_privilege_escalation]

- rule: Privileged Container Started
  desc: Detect privileged container creation
  condition: >
    container and container.privileged=true
    and evt.type=container
  output: >
    Privileged container started (user=%user.name
    container_id=%container.id image=%container.image.repository)
  priority: WARNING
  tags: [container, privilege_escalation]

- rule: Sensitive Mount in Container
  desc: Detect container mounting sensitive host paths
  condition: >
    container and evt.type=mount and
    (fd.name startswith /proc or
     fd.name startswith /sys or
     fd.name startswith /var/run/docker.sock or
     fd.name startswith /var/run/containerd.sock)
  output: >
    Sensitive path mounted in container
    (user=%user.name container_id=%container.id
    mount=%fd.name proc=%proc.name)
  priority: WARNING
  tags: [container, sensitive_mount]
```

### 2.3 容器入侵应急响应流程

```
发现异常容器 → 立即冻结(暂停) → 收集证据 → 分析定位 → 隔离遏制 → 根除恢复
     ↓              ↓             ↓          ↓          ↓          ↓
  告警/巡检      docker pause   导出镜像    分析日志    网络隔离   删除容器
               保存现场         dump内存   检查挂载    清理后门    镜像更新
                               抓取流量   追溯来源    修复配置    重建部署
```

**详细操作步骤：**

```bash
# 步骤1: 冻结容器（不停止，保持内存状态）
docker pause <container_id>

# 步骤2: 导出容器文件系统快照
docker export <container_id> -o /forensics/container_$(date +%s).tar
docker commit <container_id> forensic_snapshot:$(date +%s)

# 步骤3: 收集容器运行时信息
docker inspect <container_id> > /forensics/inspect_$(date +%s).json
docker top <container_id> > /forensics/top_$(date +%s).txt
docker stats --no-stream <container_id> > /forensics/stats_$(date +%s).txt
docker port <container_id> > /forensics/port_$(date +%s).txt

# 步骤4: 导出容器日志
docker logs -t <container_id> > /forensics/logs_$(date +%s).txt 2>&1

# 步骤5: 计算证据哈希
sha256sum /forensics/*.tar /forensics/*.json /forensics/*.txt > /forensics/hashes.txt

# 步骤6: 隔离容器网络（断开网络连接但不停止容器）
docker network disconnect bridge <container_id>
# 或创建隔离网络
docker network create --internal quarantine_net
docker network connect quarantine_net <container_id>
docker network disconnect bridge <container_id>
```
