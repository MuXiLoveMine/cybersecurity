# 实战案例: 勒索软件应急响应全过程

### 10.1 案例背景

> **事件背景**: 某中型企业（500人规模，混合云架构）在周五凌晨发现文件服务器上的文件被加密，桌面出现勒索说明文件。
>
> **环境**: 本地数据中心（10台Windows服务器 + 5台Linux服务器）+ AWS云环境（3台EC2 + RDS + S3）
>
> **勒索说明文件内容**: 文件名`HOW_TO_DECRYPT.txt`，内容包含LockBit 3.0的标识和Tor链接。

### 10.2 响应过程

**T+0分钟 - 发现与报告**

```
02:15 值班安全运营人员收到EDR告警：文件服务器(FS-01)检测到批量文件加密行为
02:16 同时收到用户报告：共享文件夹无法打开文件，文件扩展名变为.lockbit
02:17 启动应急响应流程，通知IR团队
```

**T+5分钟 - 紧急隔离**

```bash
# 步骤1: 隔离文件服务器FS-01的网络
# 禁用网络适配器（保留管理网段）
netsh advfirewall set allprofiles firewall policy blockinbound,blockoutbound
netsh advfirewall firewall add rule name="IR-Management" dir=in action=allow protocol=TCP localport=5985 remoteip=10.10.10.0/24

# 步骤2: 隔离备份服务器
# 物理断开备份存储（立即拔除备份存储网线）
# 确认备份服务器BU-01未被感染

# 步骤3: 隔离云环境
# AWS安全组限制（仅允许管理网段）
aws ec2 modify-security-group-rules --group-id sg-xxx --ip-permissions ...

# 步骤4: 禁用可能被攻击的VPN账户
# Active Directory中禁用可疑账户
```

**T+15分钟 - 识别与评估**

```bash
# 步骤1: 确认勒索家族
# 检查勒索说明文件
type C:\HOW_TO_DECRYPT.txt
# 内容包含 "LockBit 3.0" 标识
# 确认为 LockBit 3.0 勒索软件

# 步骤2: 确认加密范围
# 扫描所有服务器
for /f %i in (servers.txt) do dir \\%i\C$\*.lockbit /s 2>nul | findstr "lockbit"

# 结果:
# FS-01: ~50000 文件被加密
# FS-02: ~30000 文件被加密
# APP-01: ~5000 文件被加密
# DC-01: 未被加密（域控未被直接影响）

# 步骤3: 检查是否有解密工具
# 访问 nomoreransom.org 查询
# LockBit 3.0 暂无公开解密工具

# 步骤4: 评估数据泄露
# 检查防火墙日志，发现大量出站流量到 185.xx.xx.xx
# 检查FS-01上的Rclone配置
type C:\Users\Public\rclone.conf
# 发现配置了外传到MEGA网盘
```

**T+30分钟 - 抑制与遏制**

```bash
# 步骤1: 终止恶意进程
# 在FS-01上查找加密进程
tasklist | findstr /i "encrypt\|lock\|crypt"
# 发现 encryptor.exe (PID 4521)
taskkill /F /PID 4521

# 步骤2: 清除持久化
# 检查计划任务
schtasks /query /fo LIST /v | findstr /i "encrypt\|lock\|update"
# 发现可疑任务 "WindowsUpdate" 运行 encryptor.exe
schtasks /delete /tn "WindowsUpdate" /f

# 检查启动项
reg query "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run"
# 发现 "SecurityUpdate" = "C:\Users\Public\svchost.exe"
reg delete "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run" /v "SecurityUpdate" /f
del C:\Users\Public\svchost.exe

# 步骤3: 检查横向移动痕迹
# 检查RDP登录日志
wevtutil qe Security /q:"*[System[EventID=4624]] and *[EventData[Data[@Name='LogonType']='10']]" /c:50 /f:text
# 发现来自 WS-05 (192.168.1.50) 的RDP登录
# 该IP是某员工工作站

# 检查该工作站
# 发现被植入Cobalt Strike beacon
dir C:\Users\public\beacon.exe
```

**T+60分钟 - 攻击链还原**

```
攻击时间线还原:
T-72h (周二): 攻击者通过VPN漏洞(CVE-2023-27997)获取初始访问
T-48h (周三): 部署Cobalt Strike beacon, 进行AD侦察
T-24h (周四): 通过Kerberoasting获取域服务账户哈希
T-12h (周四晚): 利用PrintNightmare获取域管权限
T-6h  (周四深夜): 使用Rclone外传200GB数据到MEGA网盘
T-1h  (周五凌晨01:00): 通过PsExec推送LockBit到FS-01, FS-02, APP-01
T+0   (周五凌晨02:00): LockBit开始批量加密
```

**T+2小时 - 根除**

```bash
# 1. 清除所有后门
# 在所有受影响服务器上清除恶意文件
del C:\Users\Public\*.exe
del C:\Users\Public\beacon.exe
del C:\Users\Public\encryptor.exe
del C:\Users\Public\rclone.exe
del C:\Users\Public\rclone.conf

# 2. 清除后门账户
net user HelpdeskSvc /delete
net user BackupSvc /delete

# 3. 轮换所有凭据
# 重置所有域用户密码
# 轮换所有服务账户密码
# 轮换所有SSH密钥
# 轮换所有API密钥

# 4. 修补漏洞
# VPN设备固件升级
# Windows全量补丁更新
# 禁用Print Spooler服务
# 在域控上: 
Set-Service -Name Spooler -StartupType Disabled
Stop-Service -Name Spooler -Force
```

**T+4小时 - 恢复**

```bash

# 从VHD恢复

# 3. 逐步恢复业务
# 先恢复核心业务系统
# 逐个验证后恢复用户访问
```
