# 威胁情报生命周期

### 2.1 生命周期概述

威胁情报生命周期（Threat Intelligence Lifecycle）描述了威胁情报从需求到应用的完整过程。

**经典的六阶段模型：**

```
规划与方向 → 收集 → 处理 → 分析 → 传播 → 反馈
     ↑                                       ↓
     +---------------------------------------+
```

### 2.2 阶段一：规划与方向（Planning & Direction）

**目标**：确定情报需求，明确情报方向。

**主要工作：**

1. **确定情报需求**
   - 业务需求（需要保护什么）
   - 安全需求（面临什么威胁）
   - 决策需求（谁需要情报，用来做什么）
   - 优先级排序（哪些情报最重要）

2. **确定情报范围**
   - 关注的威胁类型（勒索软件、APT、内部威胁等）
   - 关注的行业和地区
   - 关注的攻击者和攻击组织
   - 情报的详细程度要求

3. **制定情报计划**
   - 情报来源规划
   - 人员和资源配置
   - 时间节点和交付物
   - 质量要求和标准

4. **需求收集方法**
   - 与管理层沟通
   - 与安全团队沟通
   - 与业务部门沟通
   - 分析安全事件
   - 参考行业最佳实践

**情报需求示例：**

| 需求来源 | 情报需求 | 用途 | 优先级 |
|----------|----------|------|--------|
| CISO | 行业威胁态势报告 | 战略决策 | 高 |
| SOC 经理 | 最新 IOC 列表 | 检测告警 | 高 |
| 应急响应 | 勒索软件家族分析 | 事件响应 | 高 |
| 威胁猎手 | APT 组织 TTP | 威胁狩猎 | 中 |
| 安全架构师 | 攻击技术趋势 | 安全架构设计 | 中 |

### 2.3 阶段二：收集（Collection）

**目标**：从各种来源收集原始数据和信息。

**主要工作：**

1. **确定收集来源**
   - 开源情报来源（博客、论坛、社交媒体等）
   - 商业情报来源（威胁情报供应商）
   - 内部情报来源（安全设备、日志、事件等）
   - 政府/行业情报来源

2. **实施收集**
   - 自动收集（API 接口、爬虫等）
   - 人工收集（阅读报告、跟踪动态等）
   - 定期收集和实时收集结合

3. **收集管理**
   - 收集任务调度
   - 数据质量监控
   - 收集范围调整
   - 来源有效性评估

**常见情报来源类型：**

| 来源类型 | 具体来源 | 收集方式 |
|----------|----------|----------|
| 安全博客/网站 | FreeBuf、安全客、先知社区等 | RSS、爬虫 |
| 社交媒体 | Twitter、微博、LinkedIn 等 | API、监控 |
| 技术论坛 | 看雪、吾爱破解、各种地下论坛 | 人工监控、爬虫 |
| 暗网 | 暗网市场、论坛 | 专门的监控服务 |
| 安全厂商报告 | Mandiant、FireEye、奇安信等 | 订阅、官网 |
| 漏洞信息 | CVE、CNNVD、CNVD 等 | API、RSS |
| 威胁情报平台 | VirusTotal、微步在线、MISP 等 | API、平台 |
| 内部安全数据 | SIEM、EDR、IDS/IPS 等 | 日志、告警 |
| 政府/行业组织 | CERT、ISAC 等 | 订阅、通告 |

### 2.4 阶段三：处理（Processing）

**目标**：对收集到的原始数据进行加工处理，使其便于分析。

**主要工作：**

1. **数据清洗**
   - 去除重复数据
   - 过滤无关数据
   - 修正错误数据
   - 标准化数据格式

2. **数据标准化**
   - 统一数据格式（如 STIX）
   - 统一字段命名
   - 统一分类标准
   - 数据结构规范化

3. **数据丰富化（Enrichment）**
   - IP 地址补充地理位置、ASN、WHOIS 等信息
   - 域名补充注册信息、解析历史等
   - 文件哈希补充多引擎扫描结果
   - 关联分析（同一攻击者的多个 IOC）

4. **数据存储**
   - 建立情报数据库
   - 建立索引
   - 数据备份
   - 数据安全保护

**处理示例：原始 IP → 处理后的情报条目**

```
原始数据：
192.168.1.100

处理后：
{
  "type": "ipv4-addr",
  "value": "192.168.1.100",
  "labels": ["malicious-ip", "c2"],
  "confidence": "high",
  "first_seen": "2024-01-01T00:00:00Z",
  "last_seen": "2024-01-15T00:00:00Z",
  "country": "CN",
  "asn": "12345",
  "related_malware": ["Trojan.XXX"],
  "related_actor": "APT-XX",
  "source": "internal-sensor",
  "references": ["..."]
}
```

### 2.5 阶段四：分析（Analysis）

**目标**：对处理后的数据进行深入分析，产生有价值的情报。

**主要工作：**

1. **关联分析**
   - 将不同来源的信息关联起来
   - 发现 IOC 之间的关系
   - 发现攻击事件之间的联系
   - 建立攻击组织画像

2. **模式识别**
   - 识别攻击模式和规律
   - 识别攻击者行为特征
   - 识别攻击趋势变化
   - 发现异常活动

3. **归因分析**
   - 分析攻击来源
   - 识别攻击组织
   - 判断攻击动机
   - 评估攻击能力

4. **趋势预测**
   - 预测攻击发展趋势
   - 预警新的威胁
   - 评估威胁风险
   - 提供决策建议

**分析方法：**

| 方法 | 说明 | 应用场景 |
|------|------|----------|
| **IOC 关联分析** | 通过共享的 IOC 关联不同事件 | 识别同一攻击者的不同活动 |
| **TTP 对比分析** | 对比攻击手法与已知 TTP | 识别攻击组织和攻击类型 |
| **时间序列分析** | 分析随时间变化的趋势 | 发现攻击规律和趋势 |
| **聚类分析** | 将相似的事件/指标分组 | 发现攻击活动集群 |
| **攻击链分析** | 按攻击阶段分析完整攻击链 | 理解完整攻击过程 |
| **钻石模型分析** | 从四个维度分析入侵事件 | 全面理解攻击事件 |

### 2.6 阶段五：传播（Dissemination）

**目标**：将情报产品传递给需要的用户。

**主要工作：**

1. **确定受众**
   - 高管和决策者
   - 安全管理人员
   - SOC 分析师
   - 应急响应人员
   - 威胁猎手
   - 安全架构师

2. **情报产品形式**
   - IOC 列表（机器可读，用于自动检测）
   - 威胁简报（定期更新，文字形式）
   - 深度分析报告（详细分析，长篇报告）
   - 告警和预警（紧急威胁，即时通知）
   - 威胁画像（攻击者/威胁的详细描述）

3. **传播方式**
   - API 接口（自动化集成）
   - Web 平台（人工查询）
   - 邮件推送（定期报告）
   - 即时通讯（紧急告警）
   - 仪表盘和报表（可视化展示）

4. **分级分类**
   - 按紧急程度分级（一般、重要、紧急）
   - 按密级分类（公开、内部、机密）
   - 按受众分类（不同受众不同内容）
   - 按类型分类（IOC、报告、预警等）

**情报产品示例：**

| 产品类型 | 受众 | 频率 | 形式 | 内容 |
|----------|------|------|------|------|
| 每日威胁简报 | 全体安全人员 | 每日 | 邮件/Web | 每日重要威胁动态摘要 |
| 每周态势报告 | 安全管理层 | 每周 | PDF/PPT | 一周威胁态势总结分析 |
| IOC 数据流 | SIEM/EDR 系统 | 实时 | API | 可自动匹配的 IOC 列表 |
| 紧急威胁预警 | 应急响应/SOC | 按需 | 短信/邮件/IM | 紧急威胁的即时通知 |
| 深度分析报告 | 威胁情报团队/管理层 | 按需 | PDF | 特定威胁的深度分析 |
| 月度战略报告 | CISO/高管 | 每月 | PPT/会议 | 月度威胁态势和战略建议 |

### 2.7 阶段六：反馈（Feedback）

**目标**：收集用户反馈，持续改进情报工作。

**主要工作：**

1. **收集反馈**
   - 情报产品的质量评价
   - 情报的有用性评价
   - 情报需求变化
   - 改进建议

2. **评估效果**
   - 情报的使用率
   - 检测效果提升
   - 响应效率提升
   - 安全事件减少

3. **持续改进**
   - 调整情报收集方向
   - 优化分析方法
   - 改进情报产品
   - 提升服务质量

4. **需求更新**
   - 根据反馈更新情报需求
   - 调整优先级
   - 增加新的情报来源
   - 停止无效的情报工作

### 2.8 生命周期的特点

1. **循环往复**
   - 生命周期不是一次性的，而是持续循环的
   - 每次循环都有改进和提升
   - 情报工作是持续的过程

2. **各阶段相互影响**
   - 规划指导收集和分析
   - 收集和分析的结果反馈给规划
   - 传播的效果影响后续工作
   - 各阶段紧密联系

3. **质量控制贯穿始终**
   - 每个阶段都要保证质量
   - 低质量的输入导致低质量的输出
   - 质量控制是情报工作的生命线
