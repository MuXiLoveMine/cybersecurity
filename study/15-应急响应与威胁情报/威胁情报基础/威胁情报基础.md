# 威胁情报基础

> 威胁情报（Threat Intelligence）是安全运营的眼睛，帮助我们了解威胁、预测威胁、应对威胁。本文档详细介绍威胁情报的基础概念、生命周期、分类框架、攻击模型和情报源，帮助读者建立系统化的威胁情报知识体系。

---

## 一、威胁情报概述

### 1.1 威胁情报定义

**威胁情报**是关于现有或潜在威胁的经过加工和分析的信息，可用于决策，帮助组织更好地防御和应对安全威胁。

**简单来说**：威胁情报 = 数据 + 上下文 + 分析 + 可操作的建议

**核心要素：**
- **数据**：原始的威胁信息（IP、域名、文件哈希等）
- **上下文**：背景信息（谁、为什么、怎么做等）
- **分析**：对数据的加工和解读
- **可操作性**：能够指导行动和决策

**与原始数据的区别：**

| 类型 | 说明 | 例子 |
|------|------|------|
| **数据** | 原始事实 | IP 地址 1.2.3.4 |
| **信息** | 有上下文的数据 | IP 1.2.3.4 是恶意 IP |
| **情报** | 经过分析、可指导行动 | IP 1.2.3.4 属于 APT28 组织，用于 C2 通信，建议立即封禁并排查内网是否有主机连接该 IP |

### 1.2 威胁情报的价值

威胁情报的价值体现在以下几个方面：

#### 1.2.1 提升检测能力
- 基于 IOC 匹配检测已知威胁
- 基于 TTP 识别未知威胁
- 缩短检测时间（MTTD）
- 提高检测准确率

#### 1.2.2 加速响应速度
- 提供威胁上下文信息
- 指导响应措施
- 缩短响应时间（MTTR）
- 提高响应效率

#### 1.2.3 支持安全决策
- 帮助了解威胁态势
- 支持风险评估
- 指导安全投入
- 辅助战略决策

#### 1.2.4 主动防御
- 威胁狩猎（主动寻找威胁）
- 预测攻击趋势
- 提前部署防护
- 防范未然

#### 1.2.5 态势感知
- 了解整体威胁环境
- 跟踪攻击者活动
- 感知攻击趋势变化
- 预警重大威胁

### 1.3 威胁情报的分类

#### 1.3.1 按情报来源分类

| 类型 | 英文 | 说明 | 例子 |
|------|------|------|------|
| **开源情报** | OSINT (Open Source Intelligence) | 从公开渠道获取的情报 | 安全博客、社交媒体、公开报告、暗网信息 |
| **商业情报** | Commercial Intelligence | 从商业供应商购买的情报 | 商业威胁情报平台、安全厂商报告 |
| **政府情报** | Government Intelligence | 政府机构提供的情报 | 国家级 CERT、执法部门、情报机构 |
| **行业情报** | Industry Intelligence | 行业内共享的情报 | 行业 ISAC、行业协会、同业共享 |
| **内部情报** | Internal Intelligence | 组织内部产生的情报 | 自身安全事件、日志分析、红蓝对抗 |
| **信号情报** | SIGINT (Signals Intelligence) | 从信号/流量中获取的情报 | 网络流量分析、通信监听 |
| **人力情报** | HUMINT (Human Intelligence) | 从人员获取的情报 | 内部人员、线人、社交工程 |

#### 1.3.2 按情报内容分类

| 类型 | 说明 | 例子 |
|------|------|------|
| **IOC（指标）** | 技术指标，用于检测和匹配 | IP 地址、域名、URL、文件哈希、注册表项 |
| **TTP（战术/技术/程序）** | 攻击者的行为模式和方法 | 攻击手法、工具使用、操作流程 |
| **攻击者画像** | 关于攻击者的信息 | 攻击者身份、动机、能力、目标 |
| **威胁态势** | 整体威胁环境的信息 | 攻击趋势、威胁热点、重大威胁事件 |

### 1.4 威胁情报的误区

#### 误区1：威胁情报就是 IOC
- **错误认识**：威胁情报就是 IP、域名、哈希这些 IOC
- **正确理解**：IOC 只是威胁情报的一部分，TTP、攻击者画像等也是重要的情报类型
- **IOC 的局限性**：IOC 容易过时，攻击者可以快速更换 IP 和域名

#### 误区2：威胁情报越多越好
- **错误认识**：收集的情报越多越好
- **正确理解**：情报的质量比数量更重要，需要关注相关性和准确性
- **问题**：情报过载会导致重要信息被淹没，增加分析成本

#### 误区3：威胁情报能解决所有问题
- **错误认识**：有了威胁情报就能防御所有攻击
- **正确理解**：威胁情报是安全体系的一部分，需要与其他安全措施配合使用
- **现实**：威胁情报不能替代基础安全防护，也不能防御未知威胁

#### 误区4：威胁情报只适合大企业
- **错误认识**：只有大企业才需要威胁情报
- **正确理解**：各种规模的组织都可以从威胁情报中受益
- **建议**：根据自身需求和能力，选择合适的情报来源和应用方式

## 二、威胁情报生命周期

### 2.1 生命周期概述

威胁情报生命周期（Threat Intelligence Lifecycle）描述了威胁情报从需求到应用的完整过程。

**经典的六阶段模型：**

```
规划与方向 → 收集 → 处理 → 分析 → 传播 → 反馈
     ↑                                       ↓
     +---------------------------------------+
```

### 2.2 阶段一：规划与方向（Planning & Direction）

**目标**：确定情报需求，明确情报方向。

**主要工作：**

1. **确定情报需求**
   - 业务需求（需要保护什么）
   - 安全需求（面临什么威胁）
   - 决策需求（谁需要情报，用来做什么）
   - 优先级排序（哪些情报最重要）

2. **确定情报范围**
   - 关注的威胁类型（勒索软件、APT、内部威胁等）
   - 关注的行业和地区
   - 关注的攻击者和攻击组织
   - 情报的详细程度要求

3. **制定情报计划**
   - 情报来源规划
   - 人员和资源配置
   - 时间节点和交付物
   - 质量要求和标准

4. **需求收集方法**
   - 与管理层沟通
   - 与安全团队沟通
   - 与业务部门沟通
   - 分析安全事件
   - 参考行业最佳实践

**情报需求示例：**

| 需求来源 | 情报需求 | 用途 | 优先级 |
|----------|----------|------|--------|
| CISO | 行业威胁态势报告 | 战略决策 | 高 |
| SOC 经理 | 最新 IOC 列表 | 检测告警 | 高 |
| 应急响应 | 勒索软件家族分析 | 事件响应 | 高 |
| 威胁猎手 | APT 组织 TTP | 威胁狩猎 | 中 |
| 安全架构师 | 攻击技术趋势 | 安全架构设计 | 中 |

### 2.3 阶段二：收集（Collection）

**目标**：从各种来源收集原始数据和信息。

**主要工作：**

1. **确定收集来源**
   - 开源情报来源（博客、论坛、社交媒体等）
   - 商业情报来源（威胁情报供应商）
   - 内部情报来源（安全设备、日志、事件等）
   - 政府/行业情报来源

2. **实施收集**
   - 自动收集（API 接口、爬虫等）
   - 人工收集（阅读报告、跟踪动态等）
   - 定期收集和实时收集结合

3. **收集管理**
   - 收集任务调度
   - 数据质量监控
   - 收集范围调整
   - 来源有效性评估

**常见情报来源类型：**

| 来源类型 | 具体来源 | 收集方式 |
|----------|----------|----------|
| 安全博客/网站 | FreeBuf、安全客、先知社区等 | RSS、爬虫 |
| 社交媒体 | Twitter、微博、LinkedIn 等 | API、监控 |
| 技术论坛 | 看雪、吾爱破解、各种地下论坛 | 人工监控、爬虫 |
| 暗网 | 暗网市场、论坛 | 专门的监控服务 |
| 安全厂商报告 | Mandiant、FireEye、奇安信等 | 订阅、官网 |
| 漏洞信息 | CVE、CNNVD、CNVD 等 | API、RSS |
| 威胁情报平台 | VirusTotal、微步在线、MISP 等 | API、平台 |
| 内部安全数据 | SIEM、EDR、IDS/IPS 等 | 日志、告警 |
| 政府/行业组织 | CERT、ISAC 等 | 订阅、通告 |

### 2.4 阶段三：处理（Processing）

**目标**：对收集到的原始数据进行加工处理，使其便于分析。

**主要工作：**

1. **数据清洗**
   - 去除重复数据
   - 过滤无关数据
   - 修正错误数据
   - 标准化数据格式

2. **数据标准化**
   - 统一数据格式（如 STIX）
   - 统一字段命名
   - 统一分类标准
   - 数据结构规范化

3. **数据丰富化（Enrichment）**
   - IP 地址补充地理位置、ASN、WHOIS 等信息
   - 域名补充注册信息、解析历史等
   - 文件哈希补充多引擎扫描结果
   - 关联分析（同一攻击者的多个 IOC）

4. **数据存储**
   - 建立情报数据库
   - 建立索引
   - 数据备份
   - 数据安全保护

**处理示例：原始 IP → 处理后的情报条目**

```
原始数据：
192.168.1.100

处理后：
{
  "type": "ipv4-addr",
  "value": "192.168.1.100",
  "labels": ["malicious-ip", "c2"],
  "confidence": "high",
  "first_seen": "2024-01-01T00:00:00Z",
  "last_seen": "2024-01-15T00:00:00Z",
  "country": "CN",
  "asn": "12345",
  "related_malware": ["Trojan.XXX"],
  "related_actor": "APT-XX",
  "source": "internal-sensor",
  "references": ["..."]
}
```

### 2.5 阶段四：分析（Analysis）

**目标**：对处理后的数据进行深入分析，产生有价值的情报。

**主要工作：**

1. **关联分析**
   - 将不同来源的信息关联起来
   - 发现 IOC 之间的关系
   - 发现攻击事件之间的联系
   - 建立攻击组织画像

2. **模式识别**
   - 识别攻击模式和规律
   - 识别攻击者行为特征
   - 识别攻击趋势变化
   - 发现异常活动

3. **归因分析**
   - 分析攻击来源
   - 识别攻击组织
   - 判断攻击动机
   - 评估攻击能力

4. **趋势预测**
   - 预测攻击发展趋势
   - 预警新的威胁
   - 评估威胁风险
   - 提供决策建议

**分析方法：**

| 方法 | 说明 | 应用场景 |
|------|------|----------|
| **IOC 关联分析** | 通过共享的 IOC 关联不同事件 | 识别同一攻击者的不同活动 |
| **TTP 对比分析** | 对比攻击手法与已知 TTP | 识别攻击组织和攻击类型 |
| **时间序列分析** | 分析随时间变化的趋势 | 发现攻击规律和趋势 |
| **聚类分析** | 将相似的事件/指标分组 | 发现攻击活动集群 |
| **攻击链分析** | 按攻击阶段分析完整攻击链 | 理解完整攻击过程 |
| **钻石模型分析** | 从四个维度分析入侵事件 | 全面理解攻击事件 |

### 2.6 阶段五：传播（Dissemination）

**目标**：将情报产品传递给需要的用户。

**主要工作：**

1. **确定受众**
   - 高管和决策者
   - 安全管理人员
   - SOC 分析师
   - 应急响应人员
   - 威胁猎手
   - 安全架构师

2. **情报产品形式**
   - IOC 列表（机器可读，用于自动检测）
   - 威胁简报（定期更新，文字形式）
   - 深度分析报告（详细分析，长篇报告）
   - 告警和预警（紧急威胁，即时通知）
   - 威胁画像（攻击者/威胁的详细描述）

3. **传播方式**
   - API 接口（自动化集成）
   - Web 平台（人工查询）
   - 邮件推送（定期报告）
   - 即时通讯（紧急告警）
   - 仪表盘和报表（可视化展示）

4. **分级分类**
   - 按紧急程度分级（一般、重要、紧急）
   - 按密级分类（公开、内部、机密）
   - 按受众分类（不同受众不同内容）
   - 按类型分类（IOC、报告、预警等）

**情报产品示例：**

| 产品类型 | 受众 | 频率 | 形式 | 内容 |
|----------|------|------|------|------|
| 每日威胁简报 | 全体安全人员 | 每日 | 邮件/Web | 每日重要威胁动态摘要 |
| 每周态势报告 | 安全管理层 | 每周 | PDF/PPT | 一周威胁态势总结分析 |
| IOC 数据流 | SIEM/EDR 系统 | 实时 | API | 可自动匹配的 IOC 列表 |
| 紧急威胁预警 | 应急响应/SOC | 按需 | 短信/邮件/IM | 紧急威胁的即时通知 |
| 深度分析报告 | 威胁情报团队/管理层 | 按需 | PDF | 特定威胁的深度分析 |
| 月度战略报告 | CISO/高管 | 每月 | PPT/会议 | 月度威胁态势和战略建议 |

### 2.7 阶段六：反馈（Feedback）

**目标**：收集用户反馈，持续改进情报工作。

**主要工作：**

1. **收集反馈**
   - 情报产品的质量评价
   - 情报的有用性评价
   - 情报需求变化
   - 改进建议

2. **评估效果**
   - 情报的使用率
   - 检测效果提升
   - 响应效率提升
   - 安全事件减少

3. **持续改进**
   - 调整情报收集方向
   - 优化分析方法
   - 改进情报产品
   - 提升服务质量

4. **需求更新**
   - 根据反馈更新情报需求
   - 调整优先级
   - 增加新的情报来源
   - 停止无效的情报工作

### 2.8 生命周期的特点

1. **循环往复**
   - 生命周期不是一次性的，而是持续循环的
   - 每次循环都有改进和提升
   - 情报工作是持续的过程

2. **各阶段相互影响**
   - 规划指导收集和分析
   - 收集和分析的结果反馈给规划
   - 传播的效果影响后续工作
   - 各阶段紧密联系

3. **质量控制贯穿始终**
   - 每个阶段都要保证质量
   - 低质量的输入导致低质量的输出
   - 质量控制是情报工作的生命线

## 三、情报分类（战略/战役/战术/技术）

### 3.1 概述

威胁情报可以根据其用途和抽象程度分为四个层次：战略情报、战役情报、战术情报和技术情报。

```
        战略情报（Strategic）
           /            \
          /              \
    战役情报（Operational）  战术情报（Tactical）
          \              /
           \            /
        技术情报（Technical）
```

### 3.2 战略情报（Strategic Intelligence）

**定义**：面向高层决策者的宏观情报，用于战略决策和长期规划。

**特点：**
- 宏观、抽象、长期
- 关注整体威胁态势
- 面向高管和决策者
- 指导安全战略和资源分配

**主要内容：**
- 全球/区域威胁态势
- 攻击趋势和发展方向
- 重大威胁事件分析
- 威胁行为体的战略意图
- 行业威胁对比分析
- 安全风险评估

**产品形式：**
- 月度/季度/年度威胁态势报告
- 战略风险评估
- 安全趋势预测
- 高管简报

**案例：年度威胁态势报告**

> **报告主题**：2024 年网络安全威胁态势报告
>
> **目标受众**：CISO、CIO、CEO 等高管
>
> **主要内容：**
> 1. 2024 年威胁态势总览
> 2. 主要威胁类型变化趋势（勒索软件、APT、数据泄露等）
> 3. 重点威胁组织分析
> 4. 行业威胁对比（金融、能源、医疗、政府等）
> 5. 攻击技术发展趋势
> 6. 2025 年威胁预测
> 7. 战略建议和安全投入方向
>
> **价值**：帮助高管了解整体威胁环境，制定安全战略，分配安全预算

### 3.3 战役情报（Operational Intelligence）

**定义**：面向安全运营和管理的情报，用于规划和组织安全运营活动。

**特点：**
- 中观、计划性
- 关注具体的威胁活动
- 面向安全管理人员
- 指导安全运营和项目规划

**主要内容：**
- 具体威胁组织的活动分析
- 攻击活动的时间、目标、手法
- 威胁活动的趋势和变化
- 行业相关的威胁活动
- 漏洞利用趋势
- 恶意软件家族分析

**产品形式：**
- 威胁活动简报
- 攻击者画像
- 恶意软件分析报告
- 漏洞威胁分析

**案例：某 APT 组织活动分析报告**

> **报告主题**：APT28 组织 2024 年上半年活动分析
>
> **目标受众**：安全经理、威胁狩猎团队、应急响应团队
>
> **主要内容：**
> 1. APT28 组织概述（背景、动机、能力）
> 2. 2024 年上半年活动概览
> 3. 主要攻击活动详细分析
>    - 针对政府机构的钓鱼攻击活动
>    - 针对国防工业的供应链攻击
>    - 针对智库的水坑攻击
> 4. 使用的工具和 TTP
> 5. IOC 列表
> 6. 攻击趋势和预测
> 7. 防护建议
>
> **价值**：帮助安全团队了解具体威胁，规划威胁狩猎和防护措施

### 3.4 战术情报（Tactical Intelligence）

**定义**：面向一线安全人员的情报，用于具体的检测、响应和防御操作。

**特点：**
- 具体、可操作
- 关注攻击的具体手法
- 面向 SOC 分析师、应急响应人员
- 直接指导日常安全操作

**主要内容：**
- 攻击 TTP（战术、技术、程序）
- 检测规则和方法
- 响应建议和步骤
- 攻击指标和特征
- 漏洞利用细节

**产品形式：**
- IOC 列表
- 检测规则（Sigma、Snort 等）
- 攻击技术分析
- 应急响应指南
- 威胁狩猎剧本

**案例：钓鱼邮件检测指南**

> **指南主题**：最新钓鱼邮件攻击手法和检测方法
>
> **目标受众**：SOC 分析师、安全运营人员
>
> **主要内容：**
> 1. 当前钓鱼邮件的主要手法
>    - 主题和内容伪装
>    - 附件类型（Office 宏、ISO、LNK 等）
>    - 钓鱼链接特征
> 2. 检测方法
>    - 邮件头分析要点
>    - 可疑附件特征
>    - 可疑链接特征
>    - 检测规则示例（Sigma 规则）
> 3. 处置建议
>    - 收到可疑邮件怎么办
>    - 已点击链接/打开附件的处置
>    - 上报流程
>
> **价值**：直接指导一线人员检测和处置钓鱼邮件

### 3.5 技术情报（Technical Intelligence）

**定义**：最底层的技术指标情报，用于自动化检测和匹配。

**特点：**
- 具体、技术性强
- 机器可读
- 面向安全设备和系统
- 用于自动化检测

**主要内容（即 IOC）：**
- IP 地址
- 域名
- URL
- 文件哈希（MD5、SHA1、SHA256）
- 证书指纹
- 注册表键值
- 文件名和路径
- 进程特征
- 网络特征

**产品形式：**
- IOC 数据文件（CSV、JSON、STIX 等）
- API 接口
- 检测规则

### 3.6 四层情报的关系

| 层次 | 受众 | 时间范围 | 抽象程度 | 更新频率 |
|------|------|----------|----------|----------|
| **战略** | 高管 | 月/季/年 | 高 | 低（月/季） |
| **战役** | 安全经理 | 周/月 | 中 | 中（周/月） |
| **战术** | 一线人员 | 天/周 | 低 | 高（天/周） |
| **技术** | 安全设备 | 小时/天 | 最低 | 最高（实时） |

**相互关系：**
- 高层情报指导低层情报的方向
- 低层情报是高层情报的基础
- 各层情报相互支撑，缺一不可
- 组织需要各层次的情报来满足不同需求

### 3.7 情报成熟度模型

组织的威胁情报能力可以分为不同的成熟度等级：

**等级 1：初始级**
- 没有正式的威胁情报工作
- 偶尔使用免费的威胁情报
- 被动接收信息

**等级 2：可重复级**
- 有基本的威胁情报收集
- 使用商业或开源 IOC
- 简单的情报应用（如黑名单）

**等级 3：已定义级**
- 有正式的威胁情报团队
- 完整的情报生命周期流程
- 多种情报来源和产品
- 情报与安全运营集成

**等级 4：已管理级**
- 成熟的威胁情报体系
- 高质量的情报分析
- 情报驱动安全运营
- 量化的效果评估

**等级 5：优化级**
- 持续优化的情报能力
- 自动化和智能化程度高
- 主动预测和防御
- 情报共享和协作

## 四、ATT&CK 框架详解

### 4.1 ATT&CK 概述

**MITRE ATT&CK**（Adversarial Tactics, Techniques, and Common Knowledge）是 MITRE 公司提出的一个全球可访问的基于真实观察的对手战术和技术知识库。

**全称解释：**
- **A**dversarial - 对手的、攻击者的
- **T**actics - 战术（攻击的目标/目的）
- **T**echniques - 技术（实现目标的方法）
- **and** - 和
- **C**ommon - 通用的、常见的
- **K**nowledge - 知识

**ATT&CK 的核心思想：**
- 从攻击者的角度思考问题
- 基于真实的攻击数据（不是理论假设）
- 用统一的框架描述攻击行为
- 社区协作，持续更新

### 4.2 ATT&CK 矩阵结构

ATT&CK 以矩阵（Matrix）的形式呈现：

```
|          战术（列）           |
| 侦察 | 初始访问 | 执行 | ... |
--------------------------------
  技    技术1     技术1    ...
  术    技术2     技术2
  （    技术3     ...
  行）   ...
```

- **列（战术/Tactics）**：攻击的目标/目的，即攻击者"想要做什么"
- **行（技术/Techniques）**：实现战术目标的具体方法，即攻击者"怎么做"
- **子技术（Sub-techniques）**：技术的更细粒度划分

### 4.3 ATT&CK 战术详解

ATT&CK for Enterprise 包含 14 个战术：

#### 战术 1：侦察（Reconnaissance）
**目标**：收集信息，为后续攻击做准备。

**常用技术：**
- 主动扫描（Active Scanning）
- 钓鱼（Phishing，侦察阶段的钓鱼，如钓鱼邮件探测）
- Gather Victim Host Information
- Gather Victim Identity Information
- Gather Victim Network Information
- Gather Victim Org Information
- 搜索开放网站/域名（Search Open Websites/Domains）
- 搜索开放数据库（Search Open Technical Databases）
- 搜索victim 自有网站（Search Victim-Owned Websites）

**说明**：侦察是攻击的第一步，攻击者通过各种方式收集目标信息。

#### 战术 2：资源开发（Resource Development）
**目标**：建立攻击所需的资源和基础设施。

**常用技术：**
- 获取账号（Acquire Account）
- 获取基础设施（Acquire Infrastructure）
- 攻陷基础设施（Compromise Infrastructure）
- 开发能力（Develop Capabilities）
- 建立账户（Establish Accounts）
- 搭建基础设施（Stage Capabilities）

**说明**：攻击者在攻击前需要准备各种资源，如域名、服务器、恶意代码等。

#### 战术 3：初始访问（Initial Access）
**目标**：获得对目标网络/系统的初始访问权限。

**常用技术：**
- 钓鱼（Phishing） - T1566
- 利用面向公众的应用漏洞（Exploit Public-Facing Application） - T1190
- 利用外部远程服务（External Remote Services） - T1133
- 硬件添加（Hardware Additions） - T1200
- 供应链妥协（Supply Chain Compromise） - T1195
- 可移动介质（Replication Through Removable Media） - T1091
- 可信关系（Trusted Relationship） - T1199
- 有效账户（Valid Accounts） - T1078

**案例**：通过钓鱼邮件获取用户凭证，利用 Web 漏洞获取服务器权限。

#### 战术 4：执行（Execution）
**目标**：在目标系统上执行恶意代码。

**常用技术：**
- 命令和脚本解释器（Command and Scripting Interpreter） - T1059
- 利用客户端执行（User Execution） - T1204
- 利用漏洞执行（Exploitation for Client Execution） - T1203
- 计划任务/作业（Scheduled Task/Job） - T1053
- 服务执行（Service Execution） - T1569
- WMI（Windows Management Instrumentation） - T1047
- 引导或登录初始化脚本（Boot or Logon Initialization Scripts） - T1037
- 办公应用程序（Office Application Startup） - T1137

**案例**：用户打开钓鱼邮件附件中的恶意 Word 文档，宏代码执行。

#### 战术 5：持久化（Persistence）
**目标**：保持对系统的持续访问，即使系统重启也不丢失。

**常用技术：**
- 账户操作（Account Manipulation） - T1098
- 引导或登录初始化脚本（Boot or Logon Initialization Scripts） - T1037
- 浏览器扩展（Browser Extensions） - T1176
- 组件固件（Component Firmware） - T1542
- 创建或修改系统进程（Create or Modify System Process） - T1543
- 事件触发执行（Event Triggered Execution） - T1546
- 内核模块和扩展（Kernel Modules and Extensions） - T1547
- 启动或登录自动启动（Boot or Logon Autostart Execution） - T1547
- 办公应用程序启动（Office Application Startup） - T1137
- 计划任务/作业（Scheduled Task/Job） - T1053
- 服务器软件组件（Server Software Component） - T1505
- 服务（Create or Modify System Process: Windows Service）
- 有效账户（Valid Accounts） - T1078

**案例**：攻击者创建后门账户，或添加注册表启动项。

#### 战术 6：权限提升（Privilege Escalation）
**目标**：获取更高的系统权限。

**常用技术：**
- 访问令牌操作（Access Token Manipulation） - T1134
- 利用漏洞提权（Exploitation for Privilege Escalation） - T1068
- 进程注入（Process Injection） - T1055
- 计划任务/作业（Scheduled Task/Job） - T1053
- 服务（Services）
- 引导或登录自动启动（Boot or Logon Autostart Execution） - T1547
- 内核模块和扩展（Kernel Modules and Extensions） - T1547
- 有效账户（Valid Accounts） - T1078

**案例**：攻击者利用系统漏洞从普通用户提升到 SYSTEM/root 权限。

#### 战术 7：防御绕过（Defense Evasion）
**目标**：躲避安全检测和防护。

**常用技术：**
- 禁用或修改安全工具（Disable or Modify Tools） - T1562
- 混淆文件和信息（Obfuscated Files or Information） - T1027
- 防虚拟化/反调试（Virtualization/Sandbox Evasion） - T1497
- 系统配置修改（Modify System Configuration） - T1601
- 间接命令执行（Indirect Command Execution） - T1202
- 进程注入（Process Injection） - T1055
- 根套件（Rootkit） - T1014
- 有效账户（Valid Accounts） - T1078
- 系统二进制文件代理执行（Signed Binary Proxy Execution） - T1218
- 伪装/伪装（Masquerading） - T1036
- 文件删除（File Deletion） - T1070
- 清除命令历史（Clear Command History） - T1070

**案例**：攻击者使用加壳、混淆技术躲避杀毒软件检测。

#### 战术 8：凭证访问（Credential Access）
**目标**：获取账号密码等凭证信息。

**常用技术：**
- 凭证转储（Credential Dumping） - T1003
  - LSASS 内存（LSASS Memory） - T1003.001
  - SAM 数据库（Security Account Manager） - T1003.002
  - NTDS（NTDS） - T1003.003
  - 凭证管理器（Credential Manager） - T1003.005
- 键盘记录（Input Capture: Keylogging） - T1056
- 浏览器凭证（Credentials from Password Stores） - T1555
- 网络嗅探（Network Sniffing） - T1040
- 暴力破解（Brute Force） - T1110
- 凭证钓鱼（Credential Phishing）
- 未授权的密码重置（Unauthorized Password Reset）

**案例**：攻击者使用 Mimikatz 从内存中提取明文密码和哈希。

#### 战术 9：发现（Discovery）
**目标**：探索系统和网络，了解环境。

**常用技术：**
- 账户发现（Account Discovery） - T1087
- 应用窗口发现（Application Window Discovery） - T1010
- 浏览器书签发现（Browser Information Discovery） - T1217
- 文件和目录发现（File and Directory Discovery） - T1083
- 网络服务发现（Network Service Discovery） - T1046
- 网络共享发现（Network Share Discovery） - T1135
- 网络拓扑发现（Network Sniffing） - T1040
- 权限组发现（Permission Groups Discovery） - T1069
- 进程发现（Process Discovery） - T1057
- 远程系统发现（Remote System Discovery） - T1018
- 软件发现（Software Discovery） - T1518
- 系统信息发现（System Information Discovery） - T1082
- 系统网络配置发现（System Network Configuration Discovery） - T1016
- 系统网络连接发现（System Network Connections Discovery） - T1049
- 系统所有者/用户发现（System Owner/User Discovery） - T1033
- 系统服务发现（System Service Discovery） - T1033

**案例**：攻击者执行 `whoami`、`ipconfig`、`net view` 等命令了解系统环境。

#### 战术 10：横向移动（Lateral Movement）
**目标**：从一台机器移动到网络中的其他机器。

**常用技术：**
- 利用远程服务（Remote Services） - T1021
  - SSH（SSH） - T1021.004
  - RDP（Remote Desktop Protocol） - T1021.001
  - SMB/Admin Shares（SMB/Windows Admin Shares） - T1021.002
  - WinRM（Windows Remote Management） - T1021.006
  - VNC（VNC） - T1021.005
- 传递哈希（Pass the Hash） - T1550.002
- 传递票据（Pass the Ticket） - T1550.003
- 替代身份验证材料（Use Alternate Authentication Material） - T1550
- 内部幽灵（Internal Spearphishing）
- 利用远程服务漏洞（Exploitation of Remote Services） - T1210
- 软件部署工具（Software Deployment Tools） - T1072

**案例**：攻击者使用获取到的管理员哈希，通过 PsExec 登录其他服务器。

#### 战术 11：收集（Collection）
**目标**：收集有价值的数据和信息。

**常用技术：**
- 音频捕获（Audio Capture） - T1123
- 剪贴板数据（Clipboard Data） - T1115
- 数据存贮设备（Data from Removable Media） - T1025

- 数据从网络共享收集（Data from Network Shared Drive） - T1039
- 数据从信息库收集（Data from Information Repositories） - T1213

**案例**：攻击者扫描并收集目标系统中的文档、表格等敏感文件。

#### 战术 12：命令与控制（Command and Control，C2）
**目标**：攻击者与被控系统通信，发送指令、接收数据。

**常用技术：**
- 应用层协议（Application Layer Protocol） - T1071
  - Web 协议（Web Protocols） - T1071.001
  - DNS 协议（DNS） - T1071.004
  - 邮件协议（Mail Protocols） - T1071.003
- 非应用层协议（Non-Application Layer Protocol） - T1095
- 加密通道（Encrypted Channel） - T1573
- 协议隧道（Protocol Tunneling） - T1572
- 代理（Proxy） - T1090
- 远程访问工具（Remote Access Software） - T1219
- 流量签名（Traffic Signaling） - T1049
- 连接代理（Connection Proxy） - T1090
- 滥用连接控件（Abuse Elevation Control Mechanism）

**案例**：恶意软件通过 HTTPS 与 C2 服务器通信，流量伪装成正常 Web 流量。

#### 战术 13：数据渗出（Exfiltration）
**目标**：将窃取的数据从目标网络传输出去。

**常用技术：**
- 通过 C2 通道渗出（Exfiltration Over C2 Channel） - T1041

- 传输数据大小限制限制（Exfiltration Over Asymmetric Encrypted Non-C2 Protocol）
- 数据压缩（Data Compressed） - T1560
- 数据加密（Data Encrypted） - T1560

**案例**：攻击者将窃取的数据加密后，通过 FTP 上传到境外服务器。

#### 战术 14：影响（Impact）
**目标**：对目标系统、数据或业务造成破坏和影响。

**常用技术：**
- 数据破坏（Data Destruction） - T1485
- 拒绝服务（Denial of Service） - T1498
- 磁盘结构擦除（Disk Structure Wipe） - T1561
- 资源劫持（Resource Hijacking） - T1496（如挖矿）
- 勒索软件（Data Encrypted for Impact） - T1486
- 服务停止（Service Stop） - T1489
- 固件破坏（Firmware Corruption） - T1495
- 账户访问权限删除（Account Access Removal） - T1531
- 数据篡改（Data Manipulation） - T1565
- 系统 shutdown/reboot（System Shutdown/Reboot） - T1529
- 抑制恢复（Inhibit System Recovery） - T1490

**案例**：勒索软件加密用户文件并索要赎金，造成业务中断和数据损失。

### 4.5 ATT&CK 的应用

#### 4.5.1 威胁建模
- 使用 ATT&CK 框架梳理可能的攻击路径

- 识别防御盲区

#### 4.5.2 检测规则开发
- 针对具体技术开发检测规则
- 用 ATT&CK 标签管理检测规则
- 评估检测覆盖率

#### 4.5.3 红队评估
- 基于 ATT&CK 规划红队行动
- 用 ATT&CK 描述红队活动
- 评估蓝队检测能力

#### 4.5.4 威胁情报
- 用 ATT&CK 描述攻击组织的 TTP
- 标准化威胁情报格式
- 情报关联和共享

#### 4.5.5 安全评估
- 使用 ATT&CK 评估安全能力
- 识别防御差距
- 指导安全建设

### 4.6 ATT&CK 导航器

**主要功能：**
- 可视化展示 ATT&CK 矩阵

- 对比不同组织的覆盖情况
- 标记攻击组织使用的技术
- 导出和分享图层

**应用场景：**
- 展示检测覆盖率
- 展示攻击组织 TTP
- 红蓝对抗评估
- 安全能力评估

## 五、Cyber Kill Chain

### 5.1 Cyber Kill Chain 概述

**Cyber Kill Chain**（网络杀伤链）是 Lockheed Martin 公司提出的攻击模型，描述了攻击者从开始到完成攻击的七个阶段。

**模型来源**：军事领域的 "Kill Chain"（杀伤链）概念，描述攻击从发现到命中的过程。

**核心思想**：防御者只要在攻击链的任何一个阶段打断攻击，就能阻止攻击成功。

### 5.2 七个阶段详解

```
侦察 → 武器化 → 投递 → 利用 → 安装 → 命令与控制 → 目标行动
```

#### 阶段 1：侦察（Reconnaissance）
**目标**：收集目标信息，研究目标弱点。

**攻击者行为：**
- 收集目标组织信息（官网、社交媒体、招聘信息等）
- 收集目标员工信息（邮箱、职位等）
- 扫描目标网络和系统
- 研究目标使用的技术栈
- 寻找目标的弱点和漏洞

**防御措施：**
- 减少信息泄露
- 监控针对组织的侦察活动
- 部署反侦察措施
- 安全意识培训

#### 阶段 2：武器化（Weaponization）
**目标**：准备攻击工具和载荷。

**攻击者行为：**
- 开发或购买恶意代码
- 将恶意代码与合法文件绑定（如 Office 文档、PDF）
- 准备漏洞利用工具
- 搭建 C2 服务器
- 准备攻击基础设施

**防御措施：**
- 威胁情报（了解攻击者的工具和方法）
- 终端防护（EDR、杀毒软件）
- 邮件安全（附件检测）
- 漏洞管理

#### 阶段 3：投递（Delivery）
**目标**：将攻击载荷送到目标。

**攻击者行为：**
- 发送钓鱼邮件
- 利用 Web 漏洞
- 通过移动介质（U盘等）
- 通过供应链
- 通过即时通讯软件

**防御措施：**
- 邮件安全网关
- Web 应用防火墙
- 终端安全
- 安全意识培训
- 移动介质管理

#### 阶段 4：利用（Exploitation）
**目标**：利用漏洞执行恶意代码。

**攻击者行为：**
- 利用软件漏洞
- 利用配置缺陷
- 利用人为失误（如点击恶意链接）
- 社会工程学
- 利用零日漏洞

**防御措施：**
- 补丁管理
- 漏洞修复
- 最小权限原则
- 攻击面缩减
- 安全配置加固

#### 阶段 5：安装（Installation）
**目标**：在目标系统上安装恶意软件/后门，建立持久化。

**攻击者行为：**
- 安装木马/后门
- 创建持久化机制（注册表、服务、计划任务等）
- 提升权限
- 隐藏恶意代码
- 安装 Rootkit

**防御措施：**
- 终端检测与响应（EDR）
- 应用白名单
- 行为检测
- 系统加固
- 权限管理

#### 阶段 6：命令与控制（Command and Control，C2）
**目标**：建立攻击者与被控主机之间的通信通道。

**攻击者行为：**
- 建立 C2 连接
- 使用各种协议（HTTP、HTTPS、DNS、ICMP 等）
- 加密通信
- 使用代理和跳板
- 通信混淆和伪装

**防御措施：**
- 网络流量监控
- 入侵检测/防御系统
- DNS 监控
- 网络分段
- 威胁情报匹配

#### 阶段 7：目标行动（Actions on Objectives）
**目标**：实现攻击的最终目标。

**攻击者行为：**
- 窃取数据（数据渗出）
- 破坏数据和系统
- 勒索
- 横向移动到其他系统
- 长期潜伏
- 收集情报

**防御措施：**
- 数据防泄漏（DLP）
- 数据加密
- 网络分段
- 访问控制
- 数据备份
- 威胁狩猎

### 5.3 Cyber Kill Chain 的防御思想

**核心思想**："打破杀伤链"（Breaking the Kill Chain）

- 攻击要成功，需要所有阶段都成功完成
- 防御者只要在任何一个阶段成功阻断，攻击就会失败
- 防御的层次越多，攻击成功的概率越低

**防御的"纵深防御"理念：**
- 在攻击链的每个阶段都部署防御措施
- 一层防御被突破还有下一层
- 多层防御叠加，显著降低攻击成功率

### 5.4 Cyber Kill Chain 与 ATT&CK 的对比

| 维度 | Cyber Kill Chain | MITRE ATT&CK |
|------|------------------|--------------|
| **提出者** | Lockheed Martin | MITRE |
| **阶段数** | 7 个阶段 | 14 个战术 |
| **侧重点** | 攻击的线性过程 | 攻击的行为和技术 |
| **详细程度** | 较抽象，阶段较少 | 很详细，技术和子技术多 |
| **适用场景** | 攻击过程理解、防御体系设计 | 检测规则、威胁情报、红蓝对抗 |
| **更新频率** | 相对稳定 | 持续更新，社区贡献 |
| **覆盖范围** | 传统外部攻击 | 各种攻击场景（包括内部威胁、云等） |

**两者关系：**
- 都是描述攻击的模型
- ATT&CK 比 Cyber Kill Chain 更详细、更全面
- 可以结合使用：用 Kill Chain 理解攻击过程，用 ATT&CK 指导具体工作

## 六、Diamond Model（钻石模型）

### 6.1 钻石模型概述

**钻石模型（Diamond Model of Intrusion Analysis）** 是由美国国土安全部等机构提出的入侵分析模型，用于系统地分析入侵事件。

**模型名称来源**：模型的四个核心要素排列成钻石形状。

**核心思想**：每一个入侵事件都包含四个核心要素，通过分析这四个要素及其关系来理解入侵事件。

### 6.2 四个核心要素

钻石模型的四个核心要素：

```
           对手（Adversary）
              /       \
             /         \
    能力（Capability）  基础设施（Infrastructure）
             \         /
              \       /
           受害者（Victim）
```

#### 要素 1：对手（Adversary）
**定义**：实施入侵的攻击者/组织。

**包含内容：**
- 攻击者身份（已知/未知）
- 攻击组织
- 攻击动机
- 攻击目标
- 资源和能力

**分析要点：**
- 攻击者是谁？
- 攻击者的动机是什么？
- 攻击者的能力如何？
- 攻击者针对什么目标？

#### 要素 2：能力（Capability）
**定义**：攻击者使用的工具、技术和能力。

**包含内容：**
- 恶意软件
- 漏洞利用工具
- 攻击技术和手法
- 工具集
- TTP

**分析要点：**
- 攻击者使用了什么工具？
- 使用了什么攻击技术？
- 工具的来源（自研/购买/开源）？
- 技术的复杂度如何？

#### 要素 3：基础设施（Infrastructure）
**定义**：攻击者用于实施攻击的物理或逻辑资源。

**包含内容：**
- IP 地址
- 域名
- 服务器
- 代理/跳板
- 证书
- 邮件账号
- 社交媒体账号

**分析要点：**
- 攻击者使用了什么基础设施？
- 基础设施位于哪里？
- 基础设施是攻击者自己的还是攻陷的？
- 基础设施的规模和复杂度？

#### 要素 4：受害者（Victim）
**定义**：攻击的目标，被攻击的组织或个人。

**包含内容：**
- 受害者身份
- 受害者的行业和领域
- 被攻击的系统和数据
- 遭受的损失
- 受害者的价值

**分析要点：**
- 受害者是谁？
- 攻击者针对受害者的什么资产？
- 受害者为什么被攻击？
- 受害者遭受了什么损失？

### 6.3 要素之间的关系

四个要素之间存在六种关系：

| 关系 | 说明 |
|------|------|
| 对手 → 能力 | 对手拥有和使用某种能力 |
| 对手 → 基础设施 | 对手拥有或控制某种基础设施 |
| 对手 → 受害者 | 对手针对受害者 |
| 能力 → 基础设施 | 能力通过基础设施部署 |
| 基础设施 → 受害者 | 基础设施用于攻击受害者 |
| 能力 → 受害者 | 能力作用于受害者 |

### 6.4 钻石模型的应用

#### 6.4.1 入侵事件分析
- 系统地梳理入侵事件的各个方面
- 确保不遗漏重要信息
- 全面理解攻击事件

#### 6.4.2 事件关联
- 通过共享的要素关联不同事件
- 发现同一攻击者的不同活动
- 建立攻击者画像

#### 6.4.3 威胁评估
- 评估攻击者的能力和威胁程度
- 评估自身面临的风险
- 指导防御策略

#### 6.4.4 预测和预警
- 基于攻击者的模式预测下一个目标
- 提前部署防护措施
- 发布预警

### 6.5 钻石模型的分析步骤

1. **识别受害者**
   - 什么被攻击了？
   - 造成了什么影响？

2. **识别能力**
   - 使用了什么攻击工具和技术？
   - 如何实施的攻击？

3. **识别基础设施**
   - 攻击来自哪里？
   - 使用了什么 IP/域名/服务器？

4. **识别对手**
   - 谁发起的攻击？
   - 攻击动机是什么？

5. **分析关系**
   - 各要素之间的关系是什么？
   - 能关联到其他已知事件吗？

6. **得出结论**
   - 攻击的全貌是什么？
   - 应该如何应对？

### 6.6 三大模型对比

| 模型 | 特点 | 优势 | 适用场景 |
|------|------|------|----------|
| **Cyber Kill Chain** | 线性的七阶段攻击模型 | 简单易懂，适合理解攻击过程 | 防御体系设计、安全意识培训 |
| **ATT&CK** | 矩阵式的战术-技术模型 | 详细全面，基于真实数据 | 检测开发、威胁情报、红蓝对抗 |
| **Diamond Model** | 四要素的钻石模型 | 系统性强，适合事件分析 | 入侵分析、事件关联、威胁评估 |

**建议**：三个模型不是互斥的，可以结合使用，从不同角度理解和分析攻击。

## 七、IOC 与 TTP

### 7.1 IOC（Indicator of Compromise，失陷指标）

#### 7.1.1 IOC 定义
IOC 是指表明系统或网络已被入侵的技术指标。

**简单理解**：IOC 是攻击者留下的"脚印"和"指纹"，可以用来检测攻击。

#### 7.1.2 IOC 分类

| 类别 | 具体指标 | 说明 |
|------|----------|------|
| **网络指标** | IP 地址 | 攻击者使用的 IP |
| | 域名 | 攻击者注册的恶意域名 |
| | URL | 恶意链接、钓鱼页面 URL |
| | 端口 | 异常的通信端口 |
| **文件指标** | MD5/SHA1/SHA256 哈希 | 恶意文件的哈希值 |
| | 文件名 | 恶意文件的名称 |
| | 文件路径 | 恶意文件的路径 |
| | 证书指纹 | 恶意代码签名证书 |
| **主机指标** | 注册表项 | 恶意软件创建的注册表项 |
| | 计划任务 | 恶意软件创建的计划任务 |
| | 服务名 | 恶意软件创建的服务 |
| | 互斥量 | 恶意软件创建的互斥量 |
| | 进程名 | 恶意进程的名称 |
| **行为指标** | 异常命令 | 可疑的命令行参数 |
| | 异常行为模式 | 攻击行为的特征模式 |
| **邮件指标** | 发件人地址 | 钓鱼邮件发件人 |
| | 邮件主题 | 钓鱼邮件主题特征 |
| | 附件哈希 | 恶意附件哈希 |

#### 7.1.3 IOC 的特点

**优点：**
- 简单易懂，容易使用
- 可以自动化检测和匹配
- 检测速度快
- 容易共享和交换

**缺点：**
- 容易过期（攻击者经常更换 IP 和域名）
- 容易绕过（攻击者更换哈希、域名等）
- 只能检测已知威胁
- 误报率可能较高

**IOC 的生命周期：**
```
创建 → 活跃 → 老化 → 失效
```
- IOC 不是永久有效的，需要定期更新
- 不同类型的 IOC 生命周期不同
- IP 地址的生命周期通常较短，TTP 的生命周期较长

### 7.2 TTP（Tactics, Techniques, and Procedures）

#### 7.2.1 TTP 定义
TTP 描述攻击者的行为模式和操作方法。

**三个层次：**

| 层次 | 英文 | 说明 | 例子 |
|------|------|------|------|
| **战术** | Tactics | 攻击的目标/目的（为什么做） | 持久化、权限提升、横向移动 |
| **技术** | Techniques | 实现目标的方法（怎么做） | 创建注册表启动项、利用漏洞提权、Pass-the-Hash |
| **程序** | Procedures | 具体的操作步骤和细节（具体怎么做） | 使用 reg add 命令添加 HKCU\Software\Microsoft\Windows\CurrentVersion\Run 下的启动项 |

#### 7.2.2 TTP 的特点

**优点：**
- 更难绕过（攻击者改变工具容易，改变习惯难）
- 可以检测未知威胁（基于行为模式）
- 生命周期更长
- 更有情报价值

**缺点：**
- 检测难度大，需要行为分析能力
- 误报率可能较高
- 难以自动化（需要人工分析）
- 共享和交换不如 IOC 方便

### 7.3 IOC 与 TTP 的对比

| 维度 | IOC | TTP |
|------|-----|-----|
| **本质** | 技术指标（"是什么"） | 行为模式（"怎么做"） |
| **抽象程度** | 具体、底层 | 抽象、高层 |
| **检测方式** | 特征匹配 | 行为分析 |
| **检测速度** | 快 | 慢 |
| **自动化程度** | 高 | 低 |
| **误报率** | 较低 | 较高 |
| **生命周期** | 短（天/周） | 长（月/年） |
| **绕过难度** | 容易（换个IP就行） | 困难（改变行为习惯难） |
| **检测范围** | 已知威胁 | 已知 + 部分未知威胁 |
| **情报价值** | 较低 | 较高 |
| **共享难度** | 容易（标准化格式） | 困难（需要上下文） |

### 7.4 IOC 和 TTP 的关系

**互补关系**：
- IOC 是 TTP 的具体表现
- TTP 是 IOC 的抽象总结
- IOC 适合快速检测已知威胁
- TTP 适合深度分析和检测未知威胁
- 两者结合使用效果最佳

**检测的层次：**

```
        ┌─────────────────────────┐
        │    TTP 检测（行为）      │  ← 高级，检测未知威胁
        └─────────────────────────┘
                  ▲
                  │
        ┌─────────────────────────┐
        │    IOC 检测（特征）      │  ← 基础，检测已知威胁
        └─────────────────────────┘
```

### 7.5 IOC 的格式标准

#### 7.5.1 STIX（Structured Threat Information Expression）
STIX 是 OASIS 组织制定的结构化威胁信息表达标准，用于标准化威胁情报的表示和交换。

**特点：**
- 结构化数据格式
- 支持多种情报类型（IOC、TTP、攻击者等）
- 基于 XML/JSON
- 机器可读

#### 7.5.2 OpenIOC
OpenIOC 是 Mandiant 提出的 IOC 描述格式，基于 XML。

**特点：**
- 专门用于描述 IOC
- 支持逻辑组合（AND/OR）
- 可以描述复杂的检测条件

#### 7.5.3 简单格式
- CSV（逗号分隔值）
- JSON
- 纯文本（每行一个 IOC）

### 7.6 IOC 质量评估

评估 IOC 质量的几个维度：

1. **准确性（Accuracy）**
   - IOC 是否真的是恶意的
   - 误报率高低

2. **时效性（Timeliness）**
   - IOC 是否仍然有效
   - 发现和提供的速度

3. **完整性（Completeness）**
   - IOC 信息是否完整
   - 是否有足够的上下文

4. **相关性（Relevance）**
   - IOC 是否与自身环境相关
   - 是否会遇到这类威胁

5. **置信度（Confidence）**
   - 对 IOC 准确性的信心程度
   - 高/中/低置信度

## 八、威胁情报源

### 8.1 威胁情报源分类

威胁情报来源多种多样，可以按不同方式分类：

**按获取方式分：**
- 免费/开源情报源
- 商业情报源
- 政府/行业情报源
- 内部情报源

**按情报类型分：**
- IOC 情报源
- 漏洞情报源
- 威胁分析报告
- 威胁态势信息

### 8.5 内部情报源

外部情报很重要，但内部情报同样不可忽视：

1. **安全设备日志**
   - 防火墙日志
   - IDS/IPS 日志
   - WAF 日志
   - EDR 日志
   - SIEM 告警

2. **安全事件**
   - 历史安全事件
   - 渗透测试报告
   - 红蓝对抗结果
   - 漏洞扫描结果

3. **业务信息**
   - 业务系统信息
   - 资产信息
   - 人员信息
   - 合作伙伴信息

**内部情报的价值：**
- 更贴近自身环境
- 相关性更高
- 更容易发现针对性攻击
- 可以用来改进外部情报的使用

### 8.6 情报源选择建议

1. **根据需求选择**
   - 不需要所有情报源
   - 根据自身需求选择合适的
   - 从几个核心情报源开始

2. **质量优先**
   - 情报质量比数量重要
   - 选择信誉好的情报源
   - 定期评估情报源质量

3. **多层覆盖**
   - 多种类型的情报源
   - 免费和付费结合
   - 内部和外部结合

4. **持续评估**
   - 定期评估情报源的有效性
   - 淘汰不好的情报源
   - 增加新的情报源

**推荐组合（入门级）：**
- VirusTotal（多引擎查询）
- 微步在线（国内威胁情报）
- MITRE ATT&CK（攻击框架）
- FreeBuf/安全客（安全资讯）
- CNCERT（国家漏洞和预警）

**推荐组合（进阶级）：**
- 商业威胁情报平台（微步在线/奇安信等）
- MISP/OpenCTI（自建情报平台）
- 多个安全厂商的威胁报告
- 漏洞情报源（CVE/CNNVD 等）
- 暗网监控服务

## 九、总结

威胁情报是安全运营的核心能力之一，从基础的 IOC 匹配到高级的 TTP 分析，从战略决策到战术执行，威胁情报在各个层次都发挥着重要作用。

**核心要点回顾：**

1. **威胁情报概述**：理解威胁情报的定义、价值和分类，区分数据、信息和情报的不同

2. **威胁情报生命周期**：掌握六阶段模型——规划与方向、收集、处理、分析、传播、反馈

3. **情报分层**：了解战略、战役、战术、技术四层情报的特点和受众，各层情报相互支撑

4. **ATT&CK 框架**：掌握 14 个战术和常用技术，理解 ATT&CK 在检测、情报、红队等方面的应用

5. **Cyber Kill Chain**：理解七阶段攻击模型和"打破杀伤链"的防御思想

6. **钻石模型**：了解四要素（对手、能力、基础设施、受害者）的分析方法

7. **IOC 与 TTP**：理解两者的特点和区别，IOC 适合快速检测已知威胁，TTP 适合深度分析

8. **威胁情报源**：了解各类情报源，根据需求选择合适的情报源组合

> "知彼知己，百战不殆。" 威胁情报就是"知彼"的重要手段。只有深入了解威胁，才能更好地防御威胁。
