# IOC 与 TTP

### 7.1 IOC（Indicator of Compromise，失陷指标）

#### 7.1.1 IOC 定义
IOC 是指表明系统或网络已被入侵的技术指标。

**简单理解**：IOC 是攻击者留下的"脚印"和"指纹"，可以用来检测攻击。

#### 7.1.2 IOC 分类

| 类别 | 具体指标 | 说明 |
|------|----------|------|
| **网络指标** | IP 地址 | 攻击者使用的 IP |
| | 域名 | 攻击者注册的恶意域名 |
| | URL | 恶意链接、钓鱼页面 URL |
| | 端口 | 异常的通信端口 |
| **文件指标** | MD5/SHA1/SHA256 哈希 | 恶意文件的哈希值 |
| | 文件名 | 恶意文件的名称 |
| | 文件路径 | 恶意文件的路径 |
| | 证书指纹 | 恶意代码签名证书 |
| **主机指标** | 注册表项 | 恶意软件创建的注册表项 |
| | 计划任务 | 恶意软件创建的计划任务 |
| | 服务名 | 恶意软件创建的服务 |
| | 互斥量 | 恶意软件创建的互斥量 |
| | 进程名 | 恶意进程的名称 |
| **行为指标** | 异常命令 | 可疑的命令行参数 |
| | 异常行为模式 | 攻击行为的特征模式 |
| **邮件指标** | 发件人地址 | 钓鱼邮件发件人 |
| | 邮件主题 | 钓鱼邮件主题特征 |
| | 附件哈希 | 恶意附件哈希 |

#### 7.1.3 IOC 的特点

**优点：**
- 简单易懂，容易使用
- 可以自动化检测和匹配
- 检测速度快
- 容易共享和交换

**缺点：**
- 容易过期（攻击者经常更换 IP 和域名）
- 容易绕过（攻击者更换哈希、域名等）
- 只能检测已知威胁
- 误报率可能较高

**IOC 的生命周期：**
```
创建 → 活跃 → 老化 → 失效
```
- IOC 不是永久有效的，需要定期更新
- 不同类型的 IOC 生命周期不同
- IP 地址的生命周期通常较短，TTP 的生命周期较长

### 7.2 TTP（Tactics, Techniques, and Procedures）

#### 7.2.1 TTP 定义
TTP 描述攻击者的行为模式和操作方法。

**三个层次：**

| 层次 | 英文 | 说明 | 例子 |
|------|------|------|------|
| **战术** | Tactics | 攻击的目标/目的（为什么做） | 持久化、权限提升、横向移动 |
| **技术** | Techniques | 实现目标的方法（怎么做） | 创建注册表启动项、利用漏洞提权、Pass-the-Hash |
| **程序** | Procedures | 具体的操作步骤和细节（具体怎么做） | 使用 reg add 命令添加 HKCU\Software\Microsoft\Windows\CurrentVersion\Run 下的启动项 |

#### 7.2.2 TTP 的特点

**优点：**
- 更难绕过（攻击者改变工具容易，改变习惯难）
- 可以检测未知威胁（基于行为模式）
- 生命周期更长
- 更有情报价值

**缺点：**
- 检测难度大，需要行为分析能力
- 误报率可能较高
- 难以自动化（需要人工分析）
- 共享和交换不如 IOC 方便

### 7.3 IOC 与 TTP 的对比

| 维度 | IOC | TTP |
|------|-----|-----|
| **本质** | 技术指标（"是什么"） | 行为模式（"怎么做"） |
| **抽象程度** | 具体、底层 | 抽象、高层 |
| **检测方式** | 特征匹配 | 行为分析 |
| **检测速度** | 快 | 慢 |
| **自动化程度** | 高 | 低 |
| **误报率** | 较低 | 较高 |
| **生命周期** | 短（天/周） | 长（月/年） |
| **绕过难度** | 容易（换个IP就行） | 困难（改变行为习惯难） |
| **检测范围** | 已知威胁 | 已知 + 部分未知威胁 |
| **情报价值** | 较低 | 较高 |
| **共享难度** | 容易（标准化格式） | 困难（需要上下文） |

### 7.4 IOC 和 TTP 的关系

**互补关系**：
- IOC 是 TTP 的具体表现
- TTP 是 IOC 的抽象总结
- IOC 适合快速检测已知威胁
- TTP 适合深度分析和检测未知威胁
- 两者结合使用效果最佳

**检测的层次：**

```
        ┌─────────────────────────┐
        │    TTP 检测（行为）      │  ← 高级，检测未知威胁
        └─────────────────────────┘
                  ▲
                  │
        ┌─────────────────────────┐
        │    IOC 检测（特征）      │  ← 基础，检测已知威胁
        └─────────────────────────┘
```

### 7.5 IOC 的格式标准

#### 7.5.1 STIX（Structured Threat Information Expression）
STIX 是 OASIS 组织制定的结构化威胁信息表达标准，用于标准化威胁情报的表示和交换。

**特点：**
- 结构化数据格式
- 支持多种情报类型（IOC、TTP、攻击者等）
- 基于 XML/JSON
- 机器可读

#### 7.5.2 OpenIOC
OpenIOC 是 Mandiant 提出的 IOC 描述格式，基于 XML。

**特点：**
- 专门用于描述 IOC
- 支持逻辑组合（AND/OR）
- 可以描述复杂的检测条件

#### 7.5.3 简单格式
- CSV（逗号分隔值）
- JSON
- 纯文本（每行一个 IOC）

### 7.6 IOC 质量评估

评估 IOC 质量的几个维度：

1. **准确性（Accuracy）**
   - IOC 是否真的是恶意的
   - 误报率高低

2. **时效性（Timeliness）**
   - IOC 是否仍然有效
   - 发现和提供的速度

3. **完整性（Completeness）**
   - IOC 信息是否完整
   - 是否有足够的上下文

4. **相关性（Relevance）**
   - IOC 是否与自身环境相关
   - 是否会遇到这类威胁

5. **置信度（Confidence）**
   - 对 IOC 准确性的信心程度
   - 高/中/低置信度
