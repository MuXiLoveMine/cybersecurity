# 实战案例

### 案例1：企业内网蜜罐捕获攻击者

**背景**：某大型企业部署了HFish蜜罐框架，在内网核心区部署了SSH蜜罐、Redis蜜罐和MySQL蜜罐，用于检测内网横向移动。

**事件经过：**

某日凌晨2:15，HFish管理平台发出高优先级告警——内网SSH蜜罐（10.10.20.50）被成功登录，攻击者使用了弱口令"admin123"。

**SOC团队调查过程：**

1. **确认告警有效性**：该IP为蜜罐专用IP，无合法用户会访问，告警确认为真实攻击行为。
2. **溯源攻击源IP**：攻击来自10.10.10.35，是办公网一台开发人员工作站。
3. **关联其他蜜罐告警**：查看HFish日志发现，同一IP在2:10先扫描了10.10.20.0/24网段，2:15尝试登录SSH蜜罐成功，2:20尝试连接Redis蜜罐（6379端口）。
4. **工作站取证**：安全团队对该工作站进行取证，发现该机器感染了Emotet木马，攻击者通过C2通道远程控制该机器进行内网横向移动。
5. **影响评估**：由于蜜罐及时告警，攻击者在到达真实核心系统之前即被发现，未造成数据泄露。

**处置措施：**
- 立即从网络隔离感染工作站
- 对该用户账户重置所有凭据
- 全网扫描相同的Emotet变种
- 增加更多内网蜜罐节点覆盖
- 检查所有使用"admin123"弱口令的账户

**经验总结：**
- 内网蜜罐是检测横向移动的有效手段，且误报率极低
- 蜜罐部署在核心区入口（如10.10.20.0/24网段）效果最佳
- 蜜罐告警应设置最高优先级，因为任何蜜罐交互都是真实攻击
- 与终端EDR联动可快速定位攻击源机器

### 案例2：利用Cowrie分析SSH暴力破解趋势

**背景**：某安全研究团队部署了多个公网Cowrie蜜罐，分布在不同云区域，持续运行6个月收集SSH攻击数据。

**数据分析发现：**

**发现1：攻击源地理分布**
- TOP3攻击源国家：中国（18%）、俄罗斯（15%）、美国（12%）
- 但需注意：攻击源IP所在国不等于攻击者所在国

**发现2：暴力破解字典趋势**
```
TOP 10 密码（6个月统计）：
1. admin       - 32,156次
2. 123456      - 28,987次
3. password    - 25,432次
4. root        - 22,108次
5. 1q2w3e      - 18,765次
6. admin123    - 15,321次
7. test        - 14,876次
8. user        - 12,543次
9. default     - 11,234次
10. P@ssw0rd   - 10,876次
```

**发现3：攻击模式演变**
- 第1-2月：以传统字典攻击为主（每IP尝试10-50个密码）
- 第3-4月：出现高并发攻击（单IP短时间尝试上千次）
- 第5-6月：出现精准攻击（针对特定用户名+密码组合，疑似使用泄露凭据库）

**发现4：攻击后行为**
- 约15%的成功登录后执行了"uname -a"命令（系统信息收集）
- 约10%尝试下载并执行恶意软件（加密货币挖矿程序）
- 约5%尝试添加SSH公钥到authorized_keys（持久化）
- 约2%尝试修改防火墙规则
- 约1%执行了内网扫描命令

**威胁情报产出：**
- 向MISP上传了3,200+个恶意IP
- 提取了42个恶意软件样本
- 生成了SSH暴力破解趋势报告
- 向社区共享了暴力破解密码字典

**经验总结：**
- 公网蜜罐是低成本的威胁情报生产手段
- 攻击趋势在持续演变，安全策略需要同步更新
- 暴力破解密码字典可直接用于内部密码审计
- 捕获的恶意软件样本可用于AV规则更新

### 案例3：欺骗防御阻止横向移动

**背景**：某金融机构部署了商业欺骗防御平台（AttackerTrap），在内部网络投放了虚假的数据库服务、文件共享和域控服务。

**事件经过：**

某日，攻击者通过钓鱼邮件获取了一个员工的VPN访问权限，进入内网后开始横向移动侦察。

**攻击者行为与欺骗防御触发：**

**T+0小时**：攻击者通过VPN进入内网，开始nmap扫描10.0.0.0/16网段。
- 欺骗防御平台自动检测到扫描行为，动态部署了3个虚假主机

**T+1小时**：攻击者发现并尝试登录虚假的SMB文件共享（\\DECOY-FS01\shared）。
- Canary文件"财务季度报告.xlsx"被访问
- 系统立即触发紧急告警

**T+1.5小时**：攻击者使用mimikatz提取了该员工工作站的凭据，发现了一个假的管理员凭据。
- 假凭据被使用时触发Canarytoken告警
- SOAR平台自动将该凭据使用行为关联到之前的SMB告警

**T+2小时**：SOC团队收到告警，开始响应。
- 确认攻击者VPN会话
- 识别被攻陷的员工工作站
- 隔离受影响主机
- 重置相关凭据

**T+2.5小时**：攻击者尝试使用假凭据登录虚假域控。
- 虚假域控记录了攻击者的完整LDAP查询
- 获取了攻击者关注的AD对象列表（高权限用户、计算机列表）

**T+3小时**：安全团队完成全面隔离和清除。

**关键经验：**
1. **动态欺骗效果显著**：欺骗防御平台动态生成的虚假主机成功引诱了攻击者，使攻击者在虚假目标上花费了大量时间。
2. **多层诱饵协同**：SMB共享+Canary文件+假凭据的多层部署形成了完整的检测链。
3. **自动化响应关键**：SOAR平台自动关联多源告警，大幅缩短了MTTD（平均检测时间）。
4. **攻击者画像完整**：通过虚假域控记录的LDAP查询，完整了解了攻击者的侦察目标，为后续防御加固提供了情报。
5. **欺骗防御不影响业务**：整个过程中，真实业务系统未受影响，攻击者在虚假环境中活动。

**改进措施：**
- 增加虚假云资源（假S3存储桶、假IAM角色）
- 部署虚假Kubernetes服务，吸引容器环境攻击
- 增加Canarytoken在代码仓库中的覆盖
- 将欺骗防御告警与EDR自动响应联动
