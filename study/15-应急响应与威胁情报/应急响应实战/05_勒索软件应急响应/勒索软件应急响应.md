# 勒索软件应急响应

### 5.1 勒索软件概述

勒索软件（Ransomware）是一种恶意软件，通过加密用户数据或锁定系统，向受害者索要赎金以换取解密密钥。

**常见勒索软件家族：**
- WannaCry
- Locky
- CryptoLocker
- Ryuk
- Conti
- REvil
- GandCrab
- 等等

**传播方式：**
- 钓鱼邮件（最常见）
- 漏洞利用（如永恒之蓝）
- 软件捆绑
- 暴力破解 RDP
- 供应链攻击
- 网页挂马

**感染迹象：**
- 文件被加密，扩展名被修改（如 .encrypted、.locky、.xxx 等）
- 出现勒索信（桌面背景、文本文件等）
- 无法打开文件
- 系统运行缓慢
- 大量文件被修改

### 5.2 勒索软件应急响应流程

#### 阶段1：发现与确认（立即行动）

**操作步骤：**

1. **确认勒索软件感染**
   - 查看文件是否被加密
   - 查看是否有勒索信
   - 查看异常进程和网络连接

2. **评估影响范围**
   - 多少台机器被感染
   - 哪些系统被感染
   - 哪些数据被加密
   - 业务影响程度

3. **启动应急响应**
   - 根据影响范围启动相应级别响应
   - 通知应急响应团队
   - 通知管理层

**注意：不要立即重启或关机，可能丢失内存证据！**

#### 阶段2：遏制（最重要，防止扩散）

**操作步骤：**

1. **立即隔离受感染主机**
   ```
   - 断开网络连接（拔网线/禁用网卡）
   - 关闭 WiFi
   - 断开与共享存储的连接
   - 从虚拟化平台隔离
   ```

2. **防止进一步扩散**
   ```
   - 在防火墙封禁已知恶意 IP 和域名
   - 禁用可疑账号
   - 暂停文件共享服务（如果必要）
   - 暂停备份系统（防止备份也被加密）
   ```

3. **保护备份**
   - 断开离线备份的连接
   - 确保备份不会被加密
   - 验证备份的完整性

4. **保护证据**
   - 对受感染主机进行内存镜像
   - 备份系统日志和安全日志
   - 保存勒索信样本
   - 保存加密文件样本
   - 记录网络连接信息

**遏制优先级：**
1. 核心业务系统
2. 数据库服务器
3. 文件服务器
4. 备份系统
5. 终端用户电脑

#### 阶段3：分析

**操作步骤：**

1. **确定勒索软件家族**
   - 通过勒索信特征判断
   - 通过加密文件扩展名判断
   - 通过恶意样本哈希查询威胁情报
   - 使用在线工具识别（如 ID Ransomware）

2. **分析入侵路径**
   - 分析网络流量和日志
   - 查找最初感染点
   - 分析横向移动路径
   - 确定入侵方式（钓鱼邮件？漏洞？弱口令？）

3. **评估影响**
   - 统计受感染的系统数量
   - 统计被加密的文件数量
   - 评估业务影响
   - 评估数据恢复可能性

4. **判断是否可以解密**
   - 查询是否有公开的解密工具
   - 联系安全厂商咨询
   - 评估解密的可行性

**常见勒索软件解密工具：**
- No More Ransom 项目（https://www.nomoreransom.org/）
- 卡巴斯基解密工具
- 各大安全厂商的解密工具

#### 阶段4：根除

**操作步骤：**

1. **清除恶意软件**
   - 使用杀毒软件扫描清除
   - 手动删除恶意文件和进程
   - 清除持久化机制（启动项、服务、计划任务等）

2. **修补漏洞**
   - 修补被利用的漏洞
   - 更新系统补丁
   - 更新杀毒软件病毒库

3. **加固安全配置**
   - 加强账号安全（密码策略、多因素认证）
   - 加强网络分段
   - 加强端点防护（EDR）
   - 加强邮件安全（反钓鱼）

#### 阶段5：恢复

**操作步骤：**

1. **制定恢复计划**
   - 确定恢复顺序（优先恢复核心业务）
   - 确定恢复方式（备份恢复/解密/重建）
   - 预估恢复时间

2. **数据恢复**
   ```
   方案一：从备份恢复（首选）
   - 使用干净的备份恢复数据
   - 验证备份未被感染
   - 恢复后进行安全扫描
   
   方案二：使用解密工具
   - 下载对应的解密工具
   - 备份加密文件（防止解密失败）
   - 按照说明进行解密
   - 验证解密后的文件完整性
   
   方案三：重建系统
   - 重装操作系统
   - 重新部署应用
   - 手动恢复重要数据
   ```

3. **系统恢复**
   - 优先恢复核心业务系统
   - 逐步恢复其他系统
   - 验证系统功能正常
   - 加强监控

4. **业务验证**
   - 业务部门验证业务功能
   - 数据完整性验证
   - 用户测试

#### 阶段6：总结与改进

**操作步骤：**

1. **编写事件报告**
2. **总结经验教训**
3. **提出改进措施**
4. **更新应急预案**
5. **加强员工培训**

### 5.3 关于支付赎金

**重要提示：通常不建议支付赎金！**

**不支付赎金的原因：**
1. 支付赎金不保证能恢复数据
2. 资助犯罪行为，助长攻击者
3. 可能成为后续攻击的目标
4. 可能违反法律法规
5. 数据可能已经泄露

**什么情况下可考虑支付：**
- 数据极其重要，无法通过其他方式恢复
- 业务中断损失远大于赎金
- 经过管理层决策和法务评估
- 确认攻击者可信（极少数情况）

**注意事项：**
- 支付前咨询专业安全公司
- 保留交易记录
- 向执法部门报案
- 不要在被感染机器上进行支付操作

### 5.4 勒索软件防护建议

1. **数据备份**
   - 遵循 3-2-1 备份原则
   - 离线备份（物理隔离）
   - 定期验证备份可用性
   - 备份加密

2. **端点防护**
   - 部署杀毒软件/EDR
   - 及时更新系统和软件补丁
   - 禁用不必要的服务和端口
   - 应用白名单

3. **邮件安全**
   - 部署反垃圾邮件/反钓鱼系统
   - 邮件附件沙箱检测
   - 加强员工钓鱼邮件识别培训

4. **网络防护**
   - 网络分段
   - 防火墙策略最小化
   - 入侵检测/防御系统
   - 网络流量监控

5. **账号安全**
   - 强密码策略
   - 多因素认证（MFA）
   - 最小权限原则
   - 管理员账号特殊保护

6. **员工培训**
   - 安全意识培训
   - 钓鱼邮件演练
   - 应急响应培训

### 5.5 实战案例：WannaCry 勒索软件事件

**事件背景：**
2017年5月，WannaCry 勒索软件利用"永恒之蓝"（EternalBlue）漏洞在全球范围内大规模传播，感染了超过150个国家的30多万台电脑。

**攻击原理：**
- 利用 Windows SMB 协议的漏洞（MS17-010）
- 无需用户交互，自动传播
- 加密文件后索要比特币赎金

**应急响应过程：**

1. **发现与预警**
   - 安全厂商率先发现攻击
   - 发布紧急安全预警
   - 提供检测和防护工具

2. **遏制措施**
   - 立即安装 MS17-010 安全补丁
   - 在防火墙封禁 445 端口（SMB）
   - 隔离受感染主机
   - 断开内部网络中不必要的 SMB 访问

3. **分析与处置**
   - 分析勒索软件样本
   - 研究解密方法（后来发现了一个" killswitch "域名，可以阻止传播）
   - 发布应急工具
   - 提供技术支持

4. **恢复措施**
   - 从备份恢复数据
   - 对于没有备份的，暂时无法解密（后来有了解密工具）
   - 系统重装和加固

**经验教训：**
- 及时安装安全补丁的重要性
- 数据备份是应对勒索软件的最佳手段
- 网络分段可以限制攻击扩散
- 安全意识和应急准备至关重要
- 漏洞披露和武器化利用的速度越来越快
