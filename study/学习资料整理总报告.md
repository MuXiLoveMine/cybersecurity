## 📁 二、文件夹结构整理

### 2.1 整理规则

每个 md 文件按照以下规则重新组织为文件夹结构：

```
主题名称/
├── README.md                    # 索引与导航、内容审核总览
├── 01_章节一名称/
│   └── 章节一名称.md            # 章节内容 + 实战拓展 + 内容审核建议
├── 02_章节二名称/
│   └── 章节二名称.md
└── ...
```

### 2.2 结构特点

- **按二级标题分割**：以原文档的 `##` 二级标题作为大类分割依据
- **编号排序**：每个章节文件夹以 `01_`、`02_` 等编号前缀，保证阅读顺序
- **索引文件**：每个主题根目录有 `README.md`，包含目录导航和内容审核总览
- **内容保留**：原始内容完整保留，补充内容以明确标题区分

## 🔍 三、内容审核体系

### 3.1 审核维度

每个章节自动进行以下 9 个维度的内容审核：

| 维度 | 检测内容 | 图标 |
|------|---------|------|
| 代码示例 | 是否包含代码示例、PoC、EXP | 💻 |
| 工具推荐 | 是否包含工具介绍和使用方法 | 🔧 |
| 命令帮助 | 是否包含命令行操作指导 | ⌨️ |
| 知识点补充 | 是否有系统的知识点讲解 | 📚 |
| 实战练习 | 是否有实战案例和练习 | 🎯 |
| 防御方案 | 是否包含防御和加固方法 | 🛡️ |
| 攻击技术 | 是否包含攻击和利用技术 | ⚔️ |
| 内容深度 | 内容是否足够详实 | 📝 |
| 参考资料 | 是否有延伸阅读和参考 | 📖 |

### 3.2 审核结果呈现

- 每个主题的 `README.md` 包含「📊 内容审核总览」
- 每个章节文件末尾包含「📋 内容审核与补充建议」
- 标注待完善项数量，便于后续补充
