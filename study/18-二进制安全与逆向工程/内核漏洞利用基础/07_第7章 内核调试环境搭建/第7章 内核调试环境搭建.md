# 第7章 内核调试环境搭建

内核漏洞的分析和利用离不开调试环境。本章介绍Windows和Linux内核调试环境的搭建方法，以及常用的调试技巧。

### 7.1 Windows内核调试

#### 7.1.1 WinDbg简介

WinDbg是Windows官方的内核调试工具，功能强大，是Windows内核调试的标准工具。

**版本**：
- **WinDbg (Classic)**：传统版本，随Windows SDK/DDK发布
- **WinDbg Preview**：新版本，基于UWP，界面更现代，功能更丰富
- **kd.exe**：命令行版本的内核调试器

**安装**：
1. 下载Windows SDK（或Windows Driver Kit）
2. 安装时选择Debugging Tools for Windows
3. WinDbg Preview可从Microsoft Store直接安装

#### 7.1.2 双机调试配置

双机调试是最常用的内核调试方式，一台机器作为调试主机（Host）运行WinDbg，另一台作为被调试目标（Target）。

**物理机双机调试**：
- 通过1394火线（已淘汰）
- 通过USB 3.0调试线
- 通过串口（COM端口，速度慢）

**虚拟机双机调试（推荐）**：
- 使用VMware或VirtualBox
- 通过命名管道（Named Pipe）模拟串口
- 设置简单，成本低

**VMware + WinDbg配置步骤**：

1. **在虚拟机（Target）中启用调试模式**：
   ```cmd
   # 查看当前启动项
   bcdedit /enum
   
   # 创建调试启动项（复制当前项）
   bcdedit /copy {current} /d "Debug"
   
   # 启用内核调试
   bcdedit /debug {新创建的项标识符} on
   
   # 设置调试方式为串口，端口1，波特率115200
   bcdedit /dbgsettings serial debugport:1 baudrate:115200
   ```

2. **在VMware中配置串口**：
   - 虚拟机设置 → 添加 → 串行端口
   - 使用命名管道：`\\.\pipe\com_1`
   - 该端是服务器，另一端是应用程序
   - 勾选"轮询时主动放弃CPU"

3. **在主机启动WinDbg**：
   ```
   WinDbg -k com:pipe,port=\\.\pipe\com_1,resets=0
   ```
   或在WinDbg中选择 File → Kernel Debug → COM → 输入端口名

4. **启动虚拟机**：
   - 选择"Debug"启动项
   - WinDbg会在系统启动早期中断下来
   - 输入`g`继续运行

#### 7.1.3 本地内核调试

本地内核调试是在同一台机器上调试当前运行的内核，功能受限（无法设置断点、无法单步），但可以查看内存、结构体等。

**启用本地内核调试**：
```cmd
bcdedit /debug on
bcdedit /dbgsettings local
```

**使用WinDbg进行本地调试**：
1. 以管理员身份运行WinDbg
2. File → Kernel Debug → Local → OK
3. 即可查看内核内存和数据结构

**常用本地调试命令**：
- `!process 0 0`：列出所有进程
- `!drvobj`：查看驱动对象
- `dd` / `dq`：查看内存
- `u` / `uf`：反汇编

#### 7.1.4 常用WinDbg命令

**基础命令**：
- `g`：继续运行（Go）
- `bp <地址>`：设置断点
- `bl`：列出断点
- `bc <编号>`：清除断点
- `p`：单步步过（Step Over）
- `t`：单步步入（Step Into）
- `r`：查看/修改寄存器
- `kv`：查看调用栈

**内存查看**：
- `db <地址>`：以字节形式查看内存
- `dd <地址>`：以双字（32位）形式查看内存
- `dq <地址>`：以四字（64位）形式查看内存
- `du <地址>`：以Unicode字符串形式查看
- `da <地址>`：以ASCII字符串形式查看
- `u <地址>`：反汇编

**扩展命令（!开头）**：
- `!process <地址> <级别>`：查看进程信息
- `!thread <地址>`：查看线程信息
- `!drvobj <驱动名> <级别>`：查看驱动对象
- `!devobj <设备地址>`：查看设备对象
- `!irp <irp地址>`：查看IRP
- `!pool <地址>`：查看池信息
- `!vtop`：虚拟地址转物理地址
- `!pte <地址>`：查看页表项

**符号相关**：
- `.sympath <路径>`：设置符号路径
- `.reload`：重新加载符号
- `x <模块!符号>`：查找符号地址
- `ln <地址>`：列出地址附近的符号

**设置符号服务器**：
```
.sympath SRV*c:\symbols*http://msdl.microsoft.com/download/symbols
```

### 7.2 Linux内核调试

#### 7.2.1 KGDB

KGDB是Linux内核的GDB调试器stub，允许通过串口或网络从另一台机器使用GDB调试内核。

**配置内核**：
需要启用以下内核配置选项：
```
CONFIG_KGDB=y
CONFIG_KGDB_SERIAL_CONSOLE=y  # 串口方式
CONFIG_GDB_SCRIPTS=y
CONFIG_DEBUG_INFO=y
CONFIG_FRAME_POINTER=y
```

**启动参数**：
在grub的kernel参数中添加：
```
kgdboc=ttyS0,115200 kgdbwait
```
- `kgdboc`：指定KGDB使用的串口和波特率
- `kgdbwait`：在内核启动早期等待GDB连接

**连接调试**：
```bash
# 在调试主机上
gdb vmlinux
(gdb) target remote /dev/ttyS0
```

#### 7.2.2 QEMU + GDB

使用QEMU虚拟机调试Linux内核是最灵活、最常用的方式。

**编译调试版内核**：
```bash
# 内核配置
make defconfig
make menuconfig
# 启用：
#   CONFIG_DEBUG_INFO=y
#   CONFIG_GDB_SCRIPTS=y
#   CONFIG_KGDB=y (可选)
#   关闭CONFIG_RANDOMIZE_BASE (关闭KASLR方便调试)

# 编译
make -j$(nproc)
```

**制作根文件系统**：
使用Buildroot或busybox制作最小根文件系统：
```bash
# 使用Buildroot
git clone https://git.buildroot.net/buildroot
cd buildroot
make qemu_x86_64_defconfig
make -j$(nproc)
# 输出在 output/images/rootfs.ext2
```

**启动QEMU并开启GDB调试**：
```bash
qemu-system-x86_64 \
    -kernel linux/arch/x86/boot/bzImage \
    -hda buildroot/output/images/rootfs.ext2 \
    -append "root=/dev/sda console=ttyS0 nokaslr" \
    -nographic \
    -s -S  # -s: 在tcp:1234开启gdbserver; -S: 启动时暂停
```

**连接GDB**：
```bash
gdb linux/vmlinux
(gdb) target remote :1234
(gdb) hb start_kernel  # 设置硬件断点
(gdb) c               # 继续运行
```

**常用GDB调试命令**：
- `b <函数名/地址>`：设置断点
- `hbreak`：硬件断点（在内核调试中更可靠）
- `c`：继续
- `n` / `s`：单步
- `p <变量>`：打印变量
- `x/10gx <地址>`：以16进制查看10个8字节
- `bt`：调用栈
- `info registers`：查看寄存器
- `lx-*`：Linux内核GDB脚本命令（需CONFIG_GDB_SCRIPTS）

#### 7.2.3 kdb

kdb是Linux内核内置的简单调试器，可以直接在目标机器上操作（通过键盘或串口），功能不如KGDB强大，但不需要第二台机器。

**进入kdb**：
- 按`SysRq` + `G`键
- 或使用`echo g > /proc/sysrq-trigger`
- 内核Oops时自动进入

**常用kdb命令**：
- `go`：继续运行
- `bt`：调用栈
- `md <地址>`：查看内存
- `rd`：查看寄存器
- `bp`：设置断点

#### 7.2.4 常用调试工具

**crash工具**：
- 分析内核转储文件（vmcore）
- 支持实时系统分析
- 类似WinDbg的扩展命令集

```bash
# 分析vmcore
crash vmlinux vmcore

# 实时分析
crash /usr/lib/debug/boot/vmlinux-$(uname -r) /dev/mem
```

**ftrace**：
- 内核内置的函数追踪工具
- 无需额外工具，通过`/sys/kernel/debug/tracing`操作
- 可追踪函数调用、函数返回、事件等

```bash
# 追踪某个函数的调用
echo function > /sys/kernel/debug/tracing/current_tracer
echo do_sys_open > /sys/kernel/debug/tracing/set_ftrace_filter
cat /sys/kernel/debug/tracing/trace_pipe
```

**perf**：
- Linux性能分析工具
- 可用于内核代码路径分析
- 支持硬件性能计数器

### 7.3 内核漏洞调试技巧

#### 7.3.1 崩溃分析

**Windows蓝屏分析**：
1. 获取蓝屏转储文件（通常在`C:\Windows\Minidump\`或`C:\Windows\MEMORY.DMP`）
2. 用WinDbg打开转储文件
3. 使用`!analyze -v`命令自动分析
4. 查看崩溃时的调用栈和寄存器

**Linux Oops分析**：
1. 从dmesg或串口输出获取Oops信息
2. Oops信息包含：
   - 崩溃原因（如"unable to handle kernel NULL pointer dereference"）
   - 崩溃地址（RIP）
   - 寄存器状态
   - 调用栈（Call Trace）
3. 使用`addr2line`或GDB定位崩溃代码
4. 分析根因

#### 7.3.2 漏洞复现技巧

**1. 缩小触发条件**：
- 从复杂的PoC逐步简化，找到最小触发条件
- 使用二分法定位关键操作

**2. 内存污染辅助分析**：
- 在分配的内存中填充特定模式（如0x41414141、0xdeadbeef）
- 崩溃时查看内存中的标记，追踪数据流向

**3. 日志输出**：
- 在驱动/内核代码关键位置添加日志输出
- 使用`printk`（Linux）或`DbgPrint`（Windows）
- 注意日志级别，避免信息过多

#### 7.3.3 利用开发调试

**1. 利用编写的一般流程**：
1. 先在关闭保护的环境中调试（无KASLR、无SMEP、无NX）
2. 逐步启用保护机制，逐一绕过
3. 最后在完全保护的环境中测试

**2. 地址泄露调试**：
- 使用`printk`打印关键地址（调试内核时）
- 在GDB中查看符号地址，与泄露地址对比
- 验证偏移计算的正确性

**3. ROP链调试**：
- 在ROP链的每一步设置断点
- 验证每个gadget执行后的寄存器和内存状态
- 使用硬件断点监控关键内存位置

**4. 稳定性优化**：
- 增加堆喷射的数量，提高内存布局可靠性
- 添加重试逻辑，处理竞态条件
- 增加恢复代码，避免系统崩溃

### 7.4 VMware/VirtualBox调试配置

#### 7.4.1 VMware调试配置

**串口调试**：
1. 虚拟机设置 → 硬件 → 添加 → 串行端口
2. 选择"使用命名管道"
3. 命名：`\\.\pipe\dbgpipe`（Windows主机）或`/tmp/dbgpipe`（Linux主机）
4. 一端：服务器，另一端：应用程序
5. 勾选"启动时连接"

**GDB调试VMware中的Linux内核**：
```
# VMware支持通过GDB调试虚拟机
# 在.vmx文件中添加：
debugStub.listen.guest64 = "TRUE"
debugStub.listen.guest64.remote = "TRUE"
debugStub.port.guest64 = "8864"
```

#### 7.4.2 VirtualBox调试配置

**串口调试**：
1. 虚拟机设置 → 串口 → 启用串口
2. 端口模式：Host Pipe
3. 端口/文件路径：`\\.\pipe\vboxdbg`（Windows）或`/tmp/vboxdbg`（Linux）
4. 勾选"创建管道"

**VirtualBox内置调试器**：
VirtualBox自带一个简单的调试器，可通过VBoxManage控制：
```bash
# 启动虚拟机并开启调试
VBoxManage startvm "VM Name" --dbg

# 连接调试控制台
VBoxManage debugvm "VM Name" --dbg
```

#### 7.4.3 调试环境搭建建议

1. **快照管理**：
   - 安装好基础系统后立即创建快照
   - 每次重大修改前创建快照
   - 利用快照快速恢复环境

2. **内核版本管理**：
   - 保留多个内核版本的调试环境
   - 使用GRUB多启动选择不同内核

3. **符号文件**：
   - Windows：配置符号服务器，自动下载符号
   - Linux：自行编译带调试信息的内核

4. **网络配置**：
   - 使用Host-Only网络，调试机和目标机互通
   - 配置好文件共享，方便传输PoC和工具
