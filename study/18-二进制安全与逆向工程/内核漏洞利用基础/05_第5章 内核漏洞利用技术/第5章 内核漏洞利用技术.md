# 第5章 内核漏洞利用技术

内核漏洞利用的最终目标是从用户态权限提升到内核态权限，进而控制系统。本章详细讲解各种内核提权技术。

### 5.1 提权原理

#### 5.1.1 Linux提权基础

**cred结构体**：

Linux内核中，每个进程的权限信息存储在`cred`结构体中（`include/linux/cred.h`）：

```c
struct cred {
    atomic_t    usage;
    kuid_t      uid;        /* real UID */
    kgid_t      gid;        /* real GID */
    kuid_t      suid;       /* saved UID */
    kgid_t      sgid;       /* saved GID */
    kuid_t      euid;       /* effective UID */
    kgid_t      egid;       /* effective GID */
    kuid_t      fsuid;      /* file system UID */
    kgid_t      fsgid;      /* file system GID */
    // ... 其他字段
    struct group_info *group_info;
    kernel_cap_t  cap_inheritable;
    kernel_cap_t  cap_permitted;
    kernel_cap_t  cap_effective;
    kernel_cap_t  cap_bset;
    kernel_cap_t  cap_ambient;
    // ...
};
```

`current->cred`指向当前进程的凭证结构体。提权的核心就是修改当前进程的cred结构体，将uid、euid等设置为0（root），并赋予全部能力（capabilities）。

**`commit_creds`和`prepare_kernel_cred`**：

这两个函数是内核中用于修改进程凭证的标准函数，也是提权利用中最常用的函数：

```c
// 准备一个新的cred结构体（从init进程复制）
struct cred *prepare_kernel_cred(struct task_struct *daemon);

// 将cred应用到当前进程
int commit_creds(struct cred *new);
```

**经典提权代码（内核态执行）**：
```c
typedef int (*commit_creds_t)(struct cred *);
typedef struct cred * (*prepare_kernel_cred_t)(struct task_struct *);

commit_creds_t commit_creds = (commit_creds_t)COMMIT_CREDS_ADDR;
prepare_kernel_cred_t prepare_kernel_cred = (prepare_kernel_cred_t)PREPARE_KERNEL_CRED_ADDR;

commit_creds(prepare_kernel_cred(0));
```

这段代码的含义是：以init进程（PID 0/1）为模板创建一个新的cred（即root权限），然后将其应用到当前进程。

#### 5.1.2 Windows提权基础

**Token机制**：

Windows中进程的权限由访问令牌（Access Token）表示，存储在内核的`TOKEN`对象中。每个进程的`EPROCESS`结构中有一个指向Token的指针。

**提权原理**：
- 找到系统进程（如`System`进程，PID 4）的Token
- 将当前进程的Token替换为System进程的Token
- 或者直接修改当前进程Token的权限字段

**关键结构体**：
- `EPROCESS`：进程内核结构体，包含进程的所有内核态信息
- `KPROCESS`：EPROCESS的内核部分，包含调度相关信息
- `PEB`：进程环境块（用户态可访问）

**EPROCESS中的关键字段（Win10为例）**：
- `ActiveProcessLinks`：双向链表，链接所有活动进程
- `UniqueProcessId`：进程ID
- `Token`：访问令牌
- `ImageFileName`：进程镜像名

**经典提权方法（Token Stealing）**：
1. 通过`PsInitialSystemProcess`或遍历`ActiveProcessLinks`找到System进程
2. 获取System进程的Token
3. 将当前进程的Token替换为System的Token
4. 返回用户态，此时当前进程已具有SYSTEM权限

### 5.2 内核ROP

#### 5.2.1 为什么需要ROP

随着SMEP（内核态禁止执行用户态代码）的普及，传统的ret2usr技术（跳转到用户态shellcode）已失效。攻击者必须在内核态完成所有操作，因此需要使用ROP（Return-Oriented Programming）技术。

内核ROP的核心思想：
- 在内存中的内核代码段（.text）中寻找一系列"gadget"
- 每个gadget以`ret`指令结尾，执行一些有用的操作
- 通过控制栈，将这些gadget串联起来，形成完整的ROP链
- ROP链完成提权操作后，再安全返回用户态

#### 5.2.2 寻找Gadget

常用的ROP gadget搜索工具：
- **ROPgadget**：支持Linux和Windows内核的gadget搜索
- **rp++**：快速ROP gadget搜索工具
- **Ropper**：交互式ROP gadget搜索

**关键gadget类型**：
- 寄存器控制类：`pop rax; ret`、`pop rdi; ret`等
- 内存读写类：`mov [rax], rdi; ret`、`mov rax, [rsi]; ret`等
- 算术运算类：`add rax, rbx; ret`、`xor rax, rax; ret`等
- 栈迁移类：`xchg esp, eax; ret`、`leave; ret`等

#### 5.2.3 绕过SMEP的ROP策略

**方法1：通过ROP直接调用commit_creds(prepare_kernel_cred(0))**

ROP链结构（x86_64示例）：
```
pop rdi; ret          # 将0放入rdi（prepare_kernel_cred的参数）
0
prepare_kernel_cred   # 调用prepare_kernel_cred(0)
pop rdi; ret          # 此时rax中是新的cred指针
                      # 需要将rax的值移动到rdi
                      # （需要一个"mov rdi, rax; ret"或类似gadget）
commit_creds          # 调用commit_creds(new_cred)
swapgs_restore_args   # 准备返回用户态
iretq                 # 返回用户态
```

**方法2：关闭CR4寄存器中的SMEP位**

SMEP由CR4寄存器的第20位控制。如果能清除这一位，SMEP就被禁用了，就可以跳转到用户态shellcode：

```
pop rcx; ret
0x100406e4            # cr4原值 & ~(1<<20)，需要根据实际情况计算
mov cr4, rcx; ret     # 写入cr4，禁用SMEP
user_shellcode_addr   # 跳转到用户态shellcode
```

**注意**：较新的内核中，`mov cr4`指令所在的函数可能受到CFG保护，或者cr4的值受到检查。

#### 5.2.4 返回用户态

ROP链执行完提权操作后，需要安全地返回用户态。x86_64下使用`iretq`指令：

**iretq需要的栈布局**：
```
rip    → 用户态代码地址
cs     → 用户态代码段选择子
rflags → 标志寄存器
rsp    → 用户态栈地址
ss     → 用户态栈段选择子
```

Linux内核中常用的"返回用户态"gadget通常包含`swapgs; iretq`或`swapgs; sysretq`序列。

**注意事项**：
- 返回前必须确保`gs`寄存器正确切换（通过`swapgs`指令）
- 用户态栈必须是有效的
- 返回地址必须是用户态的合法地址
- 修复内核栈，避免内核崩溃

### 5.3 ret2usr

ret2usr（Return to User）是一种传统的内核漏洞利用技术，适用于没有SMEP保护的系统。

#### 5.3.1 原理

1. 用户态准备好提权shellcode
2. 通过内核漏洞控制内核栈上的返回地址
3. 将返回地址设置为用户态shellcode的地址
4. 内核从漏洞函数返回时，跳转到用户态shellcode
5. Shellcode在内核态权限下执行提权操作
6. Shellcode执行完毕后，通过`iret`/`sysret`返回用户态

#### 5.3.2 Linux ret2usr shellcode示例

```c
// 用户态shellcode（在内核态执行）
void __attribute__((naked)) shellcode(void) {
    asm volatile (
        // 保存当前寄存器
        "push rax\n"
        "push rbx\n"
        "push rcx\n"
        "push rdx\n"
        "push rsi\n"
        "push rdi\n"
        "push rbp\n"
        
        // 调用commit_creds(prepare_kernel_cred(0))
        "mov rdi, 0\n"
        "mov rax, %0\n"  // prepare_kernel_cred地址
        "call rax\n"
        "mov rdi, rax\n"
        "mov rax, %1\n"  // commit_creds地址
        "call rax\n"
        
        // 恢复寄存器
        "pop rbp\n"
        "pop rdi\n"
        "pop rsi\n"
        "pop rdx\n"
        "pop rcx\n"
        "pop rbx\n"
        "pop rax\n"
        
        // 返回用户态
        "swapgs\n"
        "iretq\n"
        : : "m"(prepare_kernel_cred), "m"(commit_creds)
    );
}
```

**注意**：在实际利用中，`prepare_kernel_cred`和`commit_creds`的地址需要通过KASLR绕过技术获取。

### 5.4 堆喷与内存布局控制

#### 5.4.1 堆喷的目的

1. **增加可靠性**：堆内存布局通常是不确定的，堆喷可以"铺满"内存，增加漏洞利用的成功率
2. **控制内存内容**：在特定位置放置攻击者可控的数据
3. **为UAF/类型混淆准备占位对象**：释放对象后，用可控数据重新占用

#### 5.4.2 Linux内核堆喷方法

**消息队列（msgqueue）方式**：

```c
// 创建消息队列
int msqid = msgget(IPC_PRIVATE, 0666 | IPC_CREAT);

// 发送消息（分配内核内存）
struct msgbuf {
    long mtype;
    char mtext[1024 - sizeof(long)];
} msg;

msg.mtype = 1;
memset(msg.mtext, 'A', sizeof(msg.mtext));

for (int i = 0; i < 1000; i++) {
    msgsnd(msqid, &msg, sizeof(msg.mtext), 0);
}
```

消息队列的优势：可以精确控制分配的大小（通过mtext长度）和内容。

**其他堆喷方法**：
- **setxattr**：文件扩展属性，可以设置任意大小和内容
- **sendmsg + MSG_CMSG_COMPAT**：控制消息的ancillary data
- **timerfd** / **eventfd** / **signalfd**：创建大量文件描述符
- **mmap + madvise(MADV_DONTNEED)**：用户态内存喷射（配合某些漏洞）

#### 5.4.3 堆布局操纵

**holes（空洞）技术**：
1. 分配大量对象，填满一个slab
2. 间隔释放一些对象，形成空洞
3. 分配目标对象，使其落入空洞中
4. 精确控制目标对象周围的内存布局

**Freelist操控**：
- SLUB分配器的per-cpu freelist是LIFO（后进先出）的
- 最后释放的对象最先被重新分配
- 利用这一特性，可以精确控制哪个对象占用释放的内存

### 5.5 内核地址泄露

#### 5.5.1 为什么需要地址泄露

KASLR将内核的基地址随机化，使得攻击者无法预先知道：
- 内核函数的地址（如commit_creds、prepare_kernel_cred）
- 内核gadget的地址
- 重要数据结构的地址（如current_task、init_task）

因此，内核漏洞利用通常需要一个信息泄露漏洞（信息泄露原语）来获取内核地址，然后才能进行代码执行。

#### 5.5.2 常见泄露方法

**1. 未初始化内存泄露**：

内核从堆或栈上分配内存后未完全初始化，返回给用户态时泄露了其中的旧数据（可能包含内核指针）。

**2. 越界读（OOB Read）**：

通过数组越界读取等漏洞，读取超出缓冲区边界的数据，从中获取内核地址。

**3. format string漏洞**：

内核中的格式化字符串漏洞可以泄露栈上的数据，包括内核指针。

**4. procfs/sysfs信息泄露**：

某些系统文件可能暴露内核地址（如`/proc/kallsyms`、`/proc/modules`）。现代内核通常对普通用户隐藏这些地址。

**5. 侧信道攻击**：

通过 timing side-channel 等方式推断内核地址信息。

#### 5.5.3 利用泄露的地址

一旦获得一个内核地址，就可以通过偏移计算出其他所有内核符号的地址：

```c
// 假设泄露了commit_creds的地址
unsigned long leak_addr = get_leaked_address();

// 计算内核基址（需要知道commit_creds相对于基址的偏移）
unsigned long kernel_base = leak_addr - COMMIT_CREDS_OFFSET;

// 计算其他符号的地址
unsigned long prepare_kernel_cred = kernel_base + PREPARE_KERNEL_CRED_OFFSET;
unsigned long pop_rdi_ret = kernel_base + POP_RDI_RET_OFFSET;
unsigned long swapgs_iretq = kernel_base + SWAPGS_IRETQ_OFFSET;
```

**注意**：偏移量可以通过对内核二进制文件（vmlinux/zImage/ntoskrnl.exe）的分析获得，对于特定内核版本是固定的。

### 5.6 利用原语（Primitives）

内核漏洞利用通常不是一步到位的，而是通过构建各种"原语"逐步达到目标。

#### 5.6.1 任意地址读（Arbitrary Read）

能够读取内核任意地址的数据。用途：
- 泄露内核地址，绕过KASLR
- 读取敏感数据结构（如cred、task_struct）
- 获取后续利用所需的信息

#### 5.6.2 任意地址写（Arbitrary Write）

能够向内核任意地址写入数据。用途：
- 修改函数指针劫持控制流
- 修改cred结构体直接提权
- 修改页表属性
- 关闭安全机制

#### 5.6.3 从原语到提权

**路径1：任意写 → 写cred结构体**
1. 通过任意读泄露current->cred的地址
2. 用任意写将cred中的uid、euid等字段改为0
3. 将capabilities设置为全1

**路径2：任意写 → 写函数指针 → ROP → commit_creds**
1. 找到一个可被触发的函数指针
2. 用任意写修改函数指针为ROP链的起点
3. 触发函数指针调用，执行ROP提权

**路径3：任意写 → 修改页表 → 用户态页映射为内核可写**
1. 修改页表项，使用户态某页在内核态可执行
2. 跳转到用户态shellcode执行提权

#### 5.6.4 常见原语构造方法

**通过list_head覆盖构造任意写**：

经典的"unlink"技术：如果能覆盖链表节点的next和prev指针，那么当链表删除该节点时，会执行类似`next->prev = prev; prev->next = next;`的操作，从而实现任意地址写。

```
// 正常的链表删除操作
node->next->prev = node->prev;
node->prev->next = node->next;

// 如果攻击者控制了node->next和node->prev：
// node->next = target_addr - offset_of_prev
// node->prev = value_to_write
// 那么 node->next->prev = node->prev 就变成了
// *(target_addr) = value_to_write
```

**通过虚函数表覆盖构造代码执行**：

如果能覆盖对象的虚函数表指针（vtable pointer），就可以将其指向伪造的虚函数表。当对象调用虚函数时，就会执行攻击者控制的代码（在有SMEP时需要伪造在可执行的内核内存中）。
