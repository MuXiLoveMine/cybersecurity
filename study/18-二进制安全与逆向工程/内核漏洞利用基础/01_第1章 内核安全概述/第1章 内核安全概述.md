# 第1章 内核安全概述

### 1.1 操作系统内核架构

操作系统内核是计算机系统的核心，负责管理硬件资源、提供系统调用接口、调度进程与内存管理。内核架构的设计直接影响系统的安全性、稳定性与性能。

#### 1.1.1 微内核架构 vs 宏内核架构

**宏内核（Monolithic Kernel）**：将所有操作系统服务（进程管理、内存管理、文件系统、设备驱动、网络协议栈等）都运行在内核态的同一地址空间中。Linux和传统的UNIX内核是典型的宏内核设计。宏内核的优势在于性能高，各模块间直接函数调用；缺点是代码量大、攻击面广，单个驱动漏洞可能危及整个内核安全。

**微内核（Microkernel）**：将尽可能多的操作系统服务移到用户态，内核仅保留最基本的功能（如进程间通信IPC、基本调度、内存管理原语）。QNX、Minix是典型的微内核。微内核的优势在于隔离性好，单个服务崩溃不影响整个系统；缺点是IPC开销较大，性能相对较低。

现代操作系统普遍采用"混合内核"设计：Windows NT内核在宏内核基础上引入了微内核的一些思想（如用户态驱动框架），而Linux也通过可加载内核模块（LKM）实现了模块化。

#### 1.1.2 Windows内核架构概览

Windows内核采用分层设计，从底向上依次为：

- **硬件抽象层（HAL）**：屏蔽硬件差异，提供统一的硬件访问接口
- **内核层（NTOS Kernel）**：提供基础原语，如调度、同步、中断处理
- **执行体层（Executive）**：提供高级服务，如进程管理、内存管理、I/O管理、对象管理、安全引用监视器等
- **驱动程序**：设备驱动、文件系统驱动、网络驱动等
- **系统调用接口**：Ntdll.dll中的syscall存根（stub）

Windows内核的核心文件是`ntoskrnl.exe`，它包含了内核层和执行体层的大部分代码。

#### 1.1.3 Linux内核架构概览

Linux内核是典型的宏内核设计，主要子系统包括：

- **进程调度子系统**：负责进程创建、销毁、调度
- **内存管理子系统**：虚拟内存、物理内存管理、页表管理
- **文件系统子系统**：VFS抽象层及各具体文件系统（ext4、btrfs等）
- **网络子系统**：TCP/IP协议栈、网络设备驱动
- **设备驱动子系统**：字符设备、块设备、网络设备驱动
- **中断与异常处理**：中断控制器驱动、异常向量表

Linux内核采用模块化设计，支持运行时加载/卸载内核模块（.ko文件），这极大地扩展了内核的功能，同时也带来了安全挑战。

### 1.2 内核态与用户态区别

现代操作系统通过特权级分离实现安全隔离。x86架构提供了4个特权级（Ring 0~3），而实际操作系统通常只使用两个：Ring 0（内核态）和Ring 3（用户态）。

#### 1.2.1 权限差异

| 特性 | 用户态（Ring 3） | 内核态（Ring 0） |
|------|-----------------|-----------------|
| 内存访问 | 仅能访问用户态虚拟地址空间 | 可访问全部虚拟地址空间（含内核地址空间） |
| 指令执行 | 仅能执行非特权指令 | 可执行全部指令（含特权指令如mov cr0、in/out等） |
| I/O操作 | 需通过系统调用间接完成 | 可直接操作I/O端口和内存映射I/O |
| 中断处理 | 无法直接处理中断 | 可注册中断处理函数 |
| 寄存器访问 | 受限（如无法直接修改CR3、GDTR等控制寄存器） | 完全控制 |

#### 1.2.2 地址空间隔离

在32位系统中，典型的地址空间划分是用户态2GB + 内核态2GB（Windows）或用户态3GB + 内核态1GB（Linux经典配置）。在64位系统中，用户态和内核态拥有独立的巨大地址空间（通常为256TB级别），通过页表的全局位（G位）和CR3切换实现隔离。

关键概念：
- **用户态地址空间**：每个进程独立拥有，包含代码段、数据段、堆、栈、映射文件等
- **内核态地址空间**：所有进程共享，包含内核代码、内核数据结构、内核栈、页表等
- **进程上下文切换**：切换CR3寄存器以切换页表，同时切换内核栈

#### 1.2.3 系统调用流程

用户态程序通过系统调用（System Call）进入内核态请求内核服务。典型的系统调用流程：

1. 用户态程序将系统调用号存入指定寄存器（x86_64下为rax）
2. 准备系统调用参数（存入rdi、rsi、rdx、r10、r8、r9等寄存器）
3. 执行`syscall`指令（x86_64）或`int 0x80`（x86 32位）
4. CPU切换到内核态，跳转到内核的系统调用入口点
5. 内核根据系统调用号分发到对应的处理函数
6. 处理完成后，通过`sysret`或`iret`返回用户态

内核漏洞利用的核心目标就是：在只有用户态权限的情况下，通过利用内核代码中的漏洞，实现从用户态到内核态的权限提升（Privilege Escalation）。

### 1.3 内核漏洞的危害与影响

内核漏洞的危害性远大于普通的用户态漏洞，原因如下：

#### 1.3.1 权限提升（Privilege Escalation）

- **本地提权（LPE）**：攻击者从普通用户权限提升到系统最高权限（Windows的SYSTEM、Linux的root）
- **容器逃逸**：在Docker等容器环境中，通过内核漏洞逃逸到宿主机
- **沙箱绕过**：绕过浏览器沙箱、AppContainer等安全沙箱机制

#### 1.3.2 安全机制完全绕过

一旦控制了内核，攻击者可以：
- 关闭所有安全机制（如PatchGuard、Driver Signature Enforcement等）
- 直接修改任意进程的内存和权限
- 隐藏进程、文件、网络连接（Rootkit技术）
- 绕过杀毒软件和EDR检测

#### 1.3.3 影响范围广泛

- 内核漏洞通常影响同一内核版本的所有系统
- 共享内核的虚拟化环境中，一个虚拟机的内核漏洞可能影响宿主机和其他虚拟机
- 移动设备（Android）的内核漏洞可用于root设备

### 1.4 内核安全机制概述

现代操作系统部署了多层安全防护机制，大大增加了内核漏洞利用的难度。

#### 1.4.1 KASLR（内核地址空间布局随机化）

KASLR将内核代码、数据、栈、堆等的地址随机化，使得攻击者无法预先知道内核中关键函数和数据结构的地址。攻击者必须首先泄露内核地址（信息泄露漏洞），才能构造有效的利用链。

- **Windows**：自Windows 8开始引入内核ASLR，每次系统启动时内核基址随机化
- **Linux**：自2.6.12开始支持KASLR，可通过启动参数`kaslr`启用

#### 1.4.2 SMEP / SMAP

**SMEP（Supervisor Mode Execution Protection）**：当CPU处于内核态（Supervisor Mode）时，禁止执行用户态页面中的代码。这直接阻止了传统的"ret2usr"技术——即内核漏洞利用中跳转到用户态shellcode的方法。

**SMAP（Supervisor Mode Access Prevention）**：当CPU处于内核态时，禁止访问用户态页面中的数据。这使得内核态下直接读写用户态数据变得困难，必须使用特定的API（如`copy_from_user`/`copy_to_user`）。

- **支持情况**：Intel Ivy Bridge及以后的CPU支持SMEP，Broadwell及以后支持SMAP
- **Windows**：Windows 8及以上启用SMEP，Windows 10 1703及以上启用SMAP
- **Linux**：内核3.0+支持SMEP，3.7+支持SMAP

#### 1.4.3 NX / DEP

**NX（No eXecute）** / **DEP（Data Execution Prevention）**：将内存页面标记为不可执行，防止数据段中的代码被执行。这在内核中同样有效，内核堆、栈默认都是不可执行的。

#### 1.4.4 CFG / CFI

**CFG（Control Flow Guard）**：微软推出的控制流完整性保护机制，在编译时为间接调用添加检查，确保调用目标是合法的函数入口。内核CFG（kCFG）在Windows 10 1709及以上版本启用。

**CET（Control-flow Enforcement Technology）**：Intel推出的硬件级控制流完整性保护，包括影子栈（Shadow Stack）和间接分支跟踪（IBT）。影子栈用于保护返回地址，IBT用于保护间接跳转。

#### 1.4.5 其他缓解机制

- **Stack Canary / GS Cookie**：内核栈溢出保护
- **Heap Cookie**：堆元数据保护
- **PatchGuard（Windows）**：内核完整性保护，阻止未授权的内核补丁
- **Driver Signature Enforcement（DSE）**：驱动数字签名强制
- **KPTI（Kernel Page Table Isolation）**：页表隔离，缓解Meltdown漏洞
- **FG-KASLR**：细粒度内核ASLR，将内核代码随机化到函数级别
