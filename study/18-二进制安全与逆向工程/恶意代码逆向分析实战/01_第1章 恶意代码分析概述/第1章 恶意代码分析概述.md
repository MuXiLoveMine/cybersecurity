# 第1章 恶意代码分析概述

### 1.1 恶意代码分类

恶意代码（Malware）是指在未经授权的情况下，在信息系统中安装、执行以达到不正当目的的具有攻击性、破坏性、窃密性的程序。随着攻击技术的演进，恶意代码家族不断分化，呈现出多样化的攻击形态。

#### 1.1.1 病毒（Virus）

病毒是一种能够自我复制的恶意程序，它通过将自身代码嵌入到其他可执行文件或文档中进行传播。病毒的核心特征是**需要宿主文件**才能存活和传播。

- **文件型病毒**：感染 `.exe`、`.dll` 等可执行文件，通过修改程序入口点或附加代码实现感染
- **引导型病毒**：感染硬盘主引导记录（MBR）或分区引导扇区，在系统启动时优先获得控制权
- **宏病毒**：利用 Office 文档中的宏语言（VBA）编写，感染 Word、Excel 等文档文件
- **脚本病毒**：使用 VBScript、JavaScript 等脚本语言编写，通过网页或邮件附件传播

典型代表：CIH病毒、宏病毒 Melissa、Sality 文件感染器。

#### 1.1.2 蠕虫（Worm）

蠕虫与病毒的本质区别在于**蠕虫不需要宿主文件**，它是一个独立的程序，能够主动利用系统漏洞或社会工程学手段在网络中自我复制和传播。

- **网络蠕虫**：利用操作系统或应用服务的漏洞（如缓冲区溢出）进行远程传播
- **邮件蠕虫**：伪装成邮件附件，诱导用户点击后通过用户的邮件通讯录继续传播
- **即时通讯蠕虫**：通过QQ、微信等即时通讯软件发送恶意链接或文件
- **P2P蠕虫**：利用点对点文件共享网络进行传播

典型代表：Code Red（红色代码）、SQL Slammer、Conficker（Conficker蠕虫）、WannaCry（利用永恒之蓝漏洞）。

#### 1.1.3 木马（Trojan）

木马程序伪装成正常软件，在用户不知情的情况下在后台执行恶意操作。木马不具备自我复制能力，主要通过欺骗手段诱导用户手动安装。

- **远控木马（RAT）**：提供完整的远程控制功能，包括文件操作、屏幕监控、摄像头控制、键盘记录等
- **盗号木马**：专门窃取网络游戏、银行账户、社交平台等账号密码
- **下载者木马（Downloader）**：体积小巧，主要功能是从远程服务器下载并执行更大型的恶意程序
- **反弹Shell木马**：建立反向连接，绕过防火墙入站规则限制

典型代表：Gh0st RAT（鬼影木马）、PlugX、Cobalt Strike Beacon、Zeus。

#### 1.1.4 勒索软件（Ransomware）

勒索软件通过加密用户文件或锁定系统，向受害者索要赎金以换取解密密钥或解锁方式。

- **加密型勒索软件**：使用对称加密（如AES）和非对称加密（如RSA）混合加密用户文件，扩展名为 `.encrypted`、`.locky`、`.cry` 等
- **锁屏型勒索软件**：修改系统配置使受害者无法正常使用桌面，显示勒索信息
- **恐吓软件（Scareware）**：伪装成杀毒软件，谎称系统感染病毒以骗取用户付费

典型代表：WannaCry、NotPetya、Locky、CryptoLocker、REvil/Sodinokibi、Conti。

#### 1.1.5 Rootkit

Rootkit 是一种能够隐匿自身及其他恶意程序存在的工具集，通常工作在内核层以获得最高权限。

- **用户态Rootkit**：通过Hook用户态API（如 `NtQueryDirectoryFile`）隐藏文件和进程
- **内核态Rootkit**：加载恶意驱动程序，直接修改内核数据结构实现隐藏
- **Bootkit**：感染MBR或UEFI固件，在操作系统加载前就获得控制权
- **固件Rootkit**：植入BIOS、网卡固件等硬件层面，极难检测和清除

典型代表：ZeroAccess（零访问Rootkit）、TDL4、Stuxnet（含有Rootkit组件）。

#### 1.1.6 僵尸网络（Botnet）

僵尸网络是由大量被感染的计算机（僵尸主机）组成的网络，受攻击者（Bot herder）统一控制。

- **集中式僵尸网络**：通过IRC频道或HTTP C2服务器进行指令下发
- **P2P僵尸网络**：采用点对点通信，无中心服务器，难以摧毁
- **僵尸网络用途**：DDoS攻击、垃圾邮件发送、点击欺诈、虚拟货币挖矿、密码暴力破解

典型代表：Mirai（物联网僵尸网络）、Zeus botnet、Sality botnet。

#### 1.1.7 其他类型

- **广告软件（Adware）**：强制弹出广告或劫持浏览器主页，部分具有隐私收集行为
- **间谍软件（Spyware）**：秘密收集用户的浏览记录、输入内容、个人信息等
- **逻辑炸弹（Logic Bomb）**：在特定条件触发时执行破坏行为，如特定日期或特定操作
- **后门程序（Backdoor）**：绕过正常认证机制，为攻击者提供秘密访问通道
- **无文件恶意软件（Fileless Malware）**：完全驻留内存，不落地磁盘文件，利用系统自带工具（如PowerShell、WMI）执行恶意操作

### 1.2 分析方法论

恶意代码分析是一个由浅入深、层层递进的过程。成熟的分析方法论能够提高分析效率，降低分析风险。

#### 1.2.1 分析层次模型

恶意代码分析通常分为四个层次，按照从易到难、从外到内的顺序进行：

**第一层：静态分析（Static Analysis）**

在不执行恶意代码的前提下，通过分析文件本身的结构、字符串、反汇编代码等获取信息。

- 优点：安全、快速、能够获取程序的完整代码逻辑
- 缺点：面对加壳、混淆的恶意代码分析难度大，无法观察运行时行为
- 适用场景：初步分类、特征提取、IOC提取、代码逻辑理解

**第二层：动态分析（Dynamic Analysis）**

在受控环境中运行恶意代码，观察其运行时的行为表现。

- 优点：能够直观看到恶意代码的实际行为，快速获取网络通信、文件操作等信息
- 缺点：只能观察到触发的代码路径，存在分析不全面的风险
- 适用场景：行为分析、网络流量捕获、沙箱报告生成

**第三层：行为分析（Behavioral Analysis）**

对恶意代码的行为进行系统性分类和深度分析，理解其攻击链和攻击目的。

- 文件系统行为：创建、修改、删除哪些文件
- 注册表行为：修改了哪些注册表项，实现了什么功能
- 网络行为：与哪些IP/域名通信，通信内容是什么
- 进程行为：创建了哪些进程，注入了哪些进程
- 持久化机制：通过什么方式实现开机自启

**第四层：代码分析（Code Analysis）**

通过反汇编和逆向工程，深入理解恶意代码的实现细节和核心算法。

- 核心算法分析：加密算法、混淆算法、通信协议
- 漏洞利用分析：利用了哪些漏洞，利用方式是什么
- 对抗技术分析：反调试、反虚拟机、反沙箱的实现原理
- 功能模块还原：将汇编代码还原为高级语言逻辑

#### 1.2.2 分析流程设计

一个规范的恶意代码分析流程应包含以下阶段：

1. **接收与登记**：记录样本基本信息（来源、文件名、大小、哈希值）
2. **初步鉴定**：文件类型识别、快速杀毒引擎扫描、初步风险评估
3. **静态分析**：文件结构分析、字符串提取、加壳检测、反汇编
4. **动态分析**：沙箱运行、行为监控、流量捕获
5. **深度逆向**：脱壳、代码还原、算法分析、协议逆向
6. **IOC提取**：提取所有可用于检测和响应的指标
7. **报告撰写**：整理分析结果，输出分析报告
8. **归档与共享**：样本归档、IOC入库、威胁情报共享

### 1.3 分析环境搭建与隔离

恶意代码分析必须在严格隔离的环境中进行，任何疏忽都可能导致分析环境被感染甚至扩散到生产网络。

#### 1.3.1 虚拟机环境

虚拟机是恶意代码分析的基础环境，提供了快照恢复、网络隔离等便利功能。

**推荐配置：**

- **虚拟化软件**：VMware Workstation Pro 或 VirtualBox（各有利弊，VMware功能更强，VirtualBox免费开源）
- **分析主机操作系统**：Windows 7 SP1 / Windows 10（根据目标样本适配）
- **硬件配置**：至少 4核CPU、8GB内存、100GB磁盘空间
- **必备设置**：
  - 禁用拖放功能和共享文件夹
  - 网络适配器设置为"仅主机模式"或"自定义虚拟网络"
  - 安装完成后立即创建干净快照
  - 关闭Windows自动更新和Windows Defender（分析专用环境）

**多版本环境准备：**

不同的恶意代码可能针对不同版本的操作系统，建议准备多个虚拟机模板：
- Windows XP SP3（用于分析较老的恶意代码）
- Windows 7 SP1 x86/x64（最常用的分析环境）
- Windows 10 x64（分析现代恶意代码）
- Ubuntu 20.04（Linux恶意代码分析）

#### 1.3.2 网络隔离方案

**方案一：仅主机模式（Host-Only）**

虚拟机只能与宿主机通信，无法访问外部网络。适用于不需要网络功能的纯静态分析或简单动态分析。

**方案二：自定义隔离网络**

创建一个独立的虚拟网络，其中包含多台虚拟机（分析机、模拟服务器），完全与外部网络隔离。适用于需要模拟网络服务的场景。

**方案三：使用INetSim/FakeNet模拟网络**

在隔离网络中部署网络模拟工具，模拟DNS、HTTP、SMTP等常见服务，使恶意代码能够正常进行网络通信，同时捕获通信内容。

#### 1.3.3 分析工具预装清单

在干净的虚拟机中预装以下工具，然后创建快照：

| 类别 | 工具 | 用途 |
|------|------|------|
| 文件分析 | PEview、010 Editor、HxD | PE结构查看、十六进制编辑 |
| 加壳检测 | PEiD、DiE（Detect It Easy） | 识别加壳器和编译器 |
| 反汇编/反编译 | IDA Pro、Ghidra、x64dbg | 静态代码分析和动态调试 |
| 进程监控 | Process Monitor、Process Explorer | 监控进程行为和系统调用 |
| 网络分析 | Wireshark、FakeNet-NG | 抓包和网络模拟 |
| 注册表监控 | Regshot、Process Monitor | 对比注册表变化 |
| 字符串提取 | Strings、FLOSS | 提取和分析字符串 |
| 脱壳工具 | Universal PE Unpacker、Scylla | 通用脱壳和Import重建 |
| 其他 | CFF Explorer、Resource Hacker | PE编辑和资源查看 |

#### 1.3.4 安全注意事项

1. **永远不要在生产环境分析恶意代码**：分析工作必须在专用的隔离环境中进行
2. **定期恢复快照**：每次分析结束后恢复到干净快照，避免残留感染
3. **谨慎处理可疑文件**：不要双击运行不明程序，使用命令行或工具调用
4. **网络隔离检查**：分析前确认网络隔离配置，防止意外外联
5. **样本安全存储**：恶意样本应加密存储或打包为受密码保护的压缩包（密码通常为 `infected`）
6. **分析主机加固**：禁用不必要的服务，限制账户权限
7. **备份重要数据**：定期备份分析环境中的重要工具和数据

### 1.4 分析流程与报告规范

#### 1.4.1 标准分析工作流

```
样本接收 → 哈希计算 → 初步鉴定 → 静态分析 → 动态分析 → 深度逆向 → IOC提取 → 报告输出
```

**步骤详解：**

1. **样本接收**：记录样本来源、接收时间、提交人信息
2. **哈希计算**：计算MD5、SHA-1、SHA-256哈希值，作为样本唯一标识
3. **初步鉴定**：使用多引擎扫描（VirusTotal）、文件类型识别
4. **静态分析**：PE结构分析、字符串分析、加壳检测、反汇编初步
5. **动态分析**：沙箱运行、行为监控、流量分析
6. **深度逆向**：脱壳、代码分析、算法还原
7. **IOC提取**：整理所有威胁指标
8. **报告输出**：撰写结构化分析报告

#### 1.4.2 分析报告结构

一份专业的恶意代码分析报告应包含以下部分：

**1. 基本信息**
- 样本名称/文件名
- 文件类型与大小
- 哈希值（MD5、SHA-1、SHA-256）
- 首次发现时间与来源
- 威胁等级评估

**2. 概要描述**
- 恶意代码类型判定
- 主要功能和危害概述
- 攻击链简要说明
- 影响范围评估

**3. 技术分析**
- 文件结构与加壳情况
- 核心功能模块分析
- 持久化机制
- 网络通信机制
- 对抗检测技术
- 关键算法说明

**4. 行为分析**
- 文件系统行为
- 注册表行为
- 进程行为
- 网络行为
- 服务/驱动行为

**5. IOC列表**
- 文件哈希
- IP地址与域名
- URL
- 注册表项
- 互斥量名称
- 文件名与路径

**6. 检测与防护建议**
- 检测规则（YARA、Snort）
- 防护措施
- 应急处置建议
- 清除步骤

- 相关截图
- 反汇编代码片段
- 参考资料
