# 第5章 常见恶意软件家族分析

不同类型的恶意软件具有不同的攻击模式和技术特征。掌握典型恶意软件家族的分析方法，能够快速识别和应对新的威胁。

### 5.1 勒索软件分析

勒索软件是近年来危害最大的恶意软件类型之一，通过加密用户文件或锁定系统来敲诈赎金。

#### 5.1.1 勒索软件的典型架构

一个完整的勒索软件通常包含以下模块：

1. **传播模块**：利用漏洞、钓鱼邮件、恶意广告等方式传播
2. **持久化模块**：通过注册表Run键、服务、计划任务等实现自启动
3. **提权模块**：利用漏洞或社会工程学获取管理员权限
4. **信息收集模块**：收集系统信息、网络信息、文件列表
5. **加密模块**：核心模块，负责加密用户文件
6. **通信模块**：与C2服务器通信，上报感染信息、获取密钥
7. **销毁模块**：删除卷影副本、备份文件，增加恢复难度
8. **勒索信展示模块**：显示勒索信息和支付指引

#### 5.1.2 加密算法识别

**混合加密架构：**

绝大多数现代勒索软件采用"非对称加密 + 对称加密"的混合加密方案：

1. 恶意代码作者生成一对RSA密钥对（公钥和私钥）
2. 公钥嵌入到勒索软件中
3. 每台感染机器生成一个随机的AES密钥（文件加密密钥）
4. 使用AES密钥加密用户文件（速度快）
5. 使用RSA公钥加密AES密钥（只有私钥持有者才能解密）
6. 将加密后的AES密钥保存在本地或发送到C2

**识别要点：**

- **AES加密特征**：
  - 搜索AES S盒常量（63 7C 77 7B...）
  - 查找16字节数据块处理循环
  - 查找CryptoAPI调用：`CryptGenKey`、`CryptEncrypt` 等

- **RSA加密特征**：
  - 查找硬编码的RSA公钥（通常以Base64形式存储）
  - 查找大整数模幂运算代码
  - 使用 `CryptImportKey` 导入公钥
  - 公钥Blob特征：以 `06 02 00 00 A4 00 00 00 52 53 41 32` 开头（RSA 2048位）

- **加密文件扩展名**：
  - 常见扩展名：`.encrypted`、`.locky`、`.cry`、`.zepto`、`.odin`、`.satan`
  - 勒索软件通常会修改被加密文件的扩展名
  - 部分勒索软件还会修改文件头，添加自定义标识

- **勒索信文件名**：
  - 典型名称：`README.txt`、`DECRYPT_INSTRUCTIONS.txt`、`HELP_DECRYPT.txt`
  - 通常在每个被加密文件的目录中生成
  - 内容包含比特币地址、Tor网站地址、个人ID等

#### 5.1.3 密钥恢复可能性分析

在分析勒索软件时，判断是否存在密钥恢复的可能性是一项重要工作。

**可能恢复密钥的情况：**

1. **硬编码密钥**：部分简单的勒索软件将加密密钥硬编码在程序中，可以通过逆向提取
2. **弱随机数生成**：如果密钥生成使用了可预测的随机数源（如 `srand(GetTickCount())`），可能暴力破解
3. **在线密钥存储**：部分勒索软件将密钥保存在C2服务器，如果服务器被接管可以找回
4. **漏洞利用**：勒索软件自身的加密实现可能存在漏洞
   - 例如CryptoLocker的早期版本曾被发现存在实现缺陷
   - 某些勒索软件错误地使用了ECB模式
5. **解密工具发布**：安全厂商或研究人员有时会发布针对特定勒索软件的解密工具

**已知可解密的勒索软件家族：**
- TeslaCrypt（密钥已被公布）
- Shade/Troldesh（部分版本可解密）
- AES_NI（存在漏洞）
- Chimera（密钥泄露）

**无法恢复的情况：**
- 正确实现的RSA+AES混合加密，私钥仅在攻击者手中
- 使用了强随机数生成器（如 `CryptGenRandom`）
- 私钥从未在受害机器上出现过

#### 5.1.4 通信协议分析

勒索软件的C2通信通常用于：
- 上报感染信息（机器ID、IP、系统信息）
- 发送加密密钥（部分勒索软件会将密钥回传）
- 接收命令和配置更新
- 部分勒索软件完全没有C2（纯加密型，密钥硬编码）

**常见通信方式：**
- HTTP/HTTPS POST请求
- 域名生成算法（DGA）生成大量备用域名
- Tor隐藏服务（.onion地址）
- 即时通讯渠道（如Telegram）

**分析方法：**
1. 使用Wireshark或FakeNet捕获网络流量
2. 分析HTTP请求的URL、方法、请求体
3. 如果数据加密，尝试在内存中查找加密密钥
4. 在逆向中定位网络通信相关的代码
5. 分析DGA算法，生成可能的域名列表用于防御

### 5.2 远控木马分析

远控木马（RAT，Remote Access Trojan）能够为攻击者提供对受害机器的完全远程控制能力，是APT攻击和网络犯罪的常用工具。

#### 5.2.1 RAT功能模块

典型的远控木马通常具备以下功能模块：

1. **连接管理模块**
   - 建立与C2服务器的连接（正向连接/反向连接）
   - 连接保活与重连机制
   - 多C2服务器切换

2. **文件管理模块**
   - 文件浏览、上传、下载、删除
   - 文件搜索
   - 压缩/解压

3. **进程管理模块**
   - 进程枚举
   - 进程创建/终止
   - 进程注入

4. **系统信息收集模块**
   - 系统版本、硬件信息、网络配置
   - 已安装软件列表
   - 浏览器密码、Cookie
   - 邮件客户端密码
   - FTP密码

5. **屏幕监控模块**
   - 屏幕截图
   - 实时屏幕监控（类似VNC）

6. **摄像头/音频模块**
   - 摄像头拍照/录像
   - 麦克风录音

7. **键盘记录模块**
   - 全局键盘钩子
   - 记录窗口标题和按键内容
   - 定期回传记录

8. **远程Shell模块**
   - 远程命令执行（cmd.exe / powershell.exe）
   - 交互式Shell

9. **权限提升模块**
   - 利用系统漏洞提权
   - 绕过UAC

10. **持久化模块**
    - 注册表Run键
    - 服务安装
    - 计划任务
    - WMI事件订阅

#### 5.2.2 C2通信协议

RAT的C2通信协议各有特色，分析通信协议是理解RAT功能和追踪攻击的关键。

**常见通信方式：**

1. **HTTP/HTTPS协议**
   - 伪装成正常的Web流量
   - 使用GET请求获取命令，POST请求返回结果
   - 数据可能加密或编码（Base64、自定义编码）
   - User-Agent可能伪造常见浏览器

2. **TCP自定义协议**
   - 使用自定义的二进制协议
   - 通常有固定的报文头格式（魔数+长度+命令+数据）
   - 数据部分可能加密

3. **DNS隧道**
   - 将数据编码在DNS查询中
   - 利用DNS协议穿透防火墙
   - 速度较慢，通常用于轻量级通信

4. **ICMP隧道**
   - 将数据封装在ICMP Echo Request/Reply中
   - 利用ping命令的数据包传输数据

**协议分析方法：**
1. 抓包获取原始通信数据
2. 在逆向中定位发送和接收数据的函数
3. 分析加密/编码算法
4. 还原报文格式和命令字
5. 编写协议解析脚本（Python + Scapy）

#### 5.2.3 持久化机制

RAT通常使用多种持久化机制确保即使一种方式被清除也能继续运行：

1. **注册表Run键**：最基础也最常用
2. **服务安装**：注册为系统服务，以SYSTEM权限运行
3. **计划任务**：创建定时任务定期执行
4. **驱动级持久化**：安装恶意驱动
5. **WMI事件订阅**：通过WMI永久事件订阅实现自启动
6. **映像劫持**：设置IFEO的Debugger值
7. **浏览器扩展/插件**：注入到浏览器中
8. **Startup文件夹**：放置快捷方式到启动目录

**分析要点：**
- 使用ProcMon监控注册表和文件系统操作
- 使用Regshot对比注册表变化
- 查看服务列表和计划任务
- 检查WMI仓库

### 5.3 银行木马分析

银行木马是专门针对金融机构和网上银行用户的恶意软件，目的是窃取银行账号密码和转账凭证。

#### 5.3.1 银行木马的特点

1. **精准打击**：只针对特定银行的网银系统
2. **复杂的注入机制**：能够在浏览器中注入JavaScript，修改网页内容
3. **实时性要求高**：需要在用户登录网银时实时窃取信息
4. **高收益**：直接窃取资金，单次攻击收益巨大
5. **高度定制化**：每个家族都有大量的银行配置文件

#### 5.3.2 浏览器注入技术

银行木马的核心技术是浏览器注入，即在浏览器进程中注入代码，监控和修改用户与网银页面的交互。

**注入方式：**
1. **BHO（浏览器辅助对象）**：注册为IE的BHO插件
2. **API Hook**：Hook WinInet、WinHTTP等网络API
3. **LSP（分层服务提供者）**：安装分层服务提供者，拦截所有网络流量
4. **进程注入**：将DLL注入到浏览器进程中
5. **浏览器扩展**：伪装成浏览器扩展/插件

**表单劫持（Form Grabbing）：**
- Hook浏览器的表单提交函数
- 在用户点击"提交"或"登录"按钮时捕获表单数据
- 获取用户名、密码、验证码、动态口令等
- 将窃取的数据发送到C2服务器

**WebInject技术：**
- 当用户访问特定银行网站时，向网页中注入恶意JavaScript
- 修改页面显示内容（如修改转账金额、收款人）
- 添加虚假的输入框（如骗取动态口令、身份证号）
- 实时监控用户输入

#### 5.3.3 VNC模块

部分高级银行木马内置VNC（虚拟网络计算）模块，攻击者可以实时查看用户桌面并远程操作：

- 在用户进行网银操作时实时介入
- 手动转账，绕过各种安全验证
- 操纵用户浏览器完成交易

**分析要点：**
- 查找VNC相关的字符串和函数
- 分析屏幕抓取和远程输入功能
- 识别VNC通信端口和协议

### 5.4 挖矿木马分析

挖矿木马利用受害机器的计算资源挖掘加密货币（如比特币、门罗币等），近年来呈现爆发式增长。

#### 5.4.1 挖矿木马的特点

1. **资源消耗高**：CPU/GPU占用率极高，导致系统变慢
2. **隐匿性需求**：需要尽量隐藏自身存在，避免被用户发现
3. **数量庞大**：感染机器越多，收益越高
4. **传播方式多样**：漏洞利用、弱口令爆破、捆绑软件、网页挖矿等

#### 5.4.2 矿池连接分析

**常见加密货币与矿池：**

| 货币 | 算法 | 默认端口 | 典型矿池 |
|------|------|----------|----------|
| 比特币（BTC） | SHA-256 | 8333 | Slush Pool、F2Pool |
| 门罗币（XMR） | CryptoNight | 3333/5555/7777 | Minergate、SupportXMR |
| 以太坊（ETH） | Ethash | 8008/9999 | Ethermine、SparkPool |
| 莱特币（LTC） | Scrypt | 9333 | F2Pool、Litecoinpool |

**Stratum协议分析：**

绝大多数矿池使用Stratum协议进行通信，这是一种基于JSON-RPC的协议。

**典型通信流程：**
1. 客户端连接到矿池服务器（TCP连接）
2. 客户端发送 `mining.subscribe` 订阅任务
3. 客户端发送 `mining.authorize` 认证矿工身份
4. 服务器发送 `mining.notify` 下发挖矿任务
5. 客户端计算后发送 `mining.submit` 提交结果

**识别特征：**
- 连接到已知的矿池域名/IP
- 通信内容中包含 "mining.subscribe"、"mining.authorize"、"mining.notify" 等字符串
- 特定的端口号（如3333、5555、8899等）
- 持续的高CPU使用率

#### 5.4.3 隐匿技术

挖矿木马为了避免被用户发现，通常采用多种隐匿技术：

1. **CPU使用率限制**：
   - 设置CPU使用率上限（如只使用50%的CPU）
   - 检测用户活动，用户活跃时降低挖矿强度
   - 多核心CPU只使用部分核心

2. **进程隐藏**：
   - 注入到系统进程中运行
   - 改名成系统进程名（如 `svchost.exe`、`dllhost.exe`）
   - 使用Rootkit技术隐藏进程

3. **文件隐藏**：
   - 将挖矿程序放在系统目录或临时目录
   - 使用随机文件名
   - 设置文件属性为隐藏和系统

4. **绕过检测**：
   - 加密挖矿程序本体
   - 运行时解密执行
   - 修改矿池通信端口，使用443端口伪装成HTTPS流量

**分析要点：**
- 使用Process Explorer查看高CPU占用的进程
- 检查进程路径和数字签名
- 使用Wireshark分析网络连接，识别矿池通信
- 查找挖矿程序配置文件（通常包含钱包地址、矿池地址）
