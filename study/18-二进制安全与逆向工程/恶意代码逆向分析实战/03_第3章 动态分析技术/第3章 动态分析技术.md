# 第3章 动态分析技术

静态分析能够获取程序的代码结构，但面对加壳、混淆严重的恶意代码时往往进展缓慢。动态分析通过在受控环境中实际运行恶意代码，直接观察其行为表现，能够快速获得大量有价值的信息。

### 3.1 沙箱分析

沙箱是自动化动态分析的重要工具，能够在隔离环境中运行样本并自动生成详细的行为报告。

#### 3.1.1 Cuckoo Sandbox

Cuckoo Sandbox是一款开源的自动化恶意软件分析系统，支持Windows、Linux、macOS、Android等多种平台。

**核心功能：**
- 自动运行样本并跟踪文件系统、注册表、进程、网络行为
- 捕获API调用序列
- 生成完整的分析报告（HTML、JSON、PDF格式）
- 支持内存转储和数据包捕获
- 可扩展的分析模块和签名检测

**部署架构：**
- **Host主机**：运行Cuckoo核心服务，负责任务调度和结果处理
- **Guest虚拟机**：运行待分析样本的隔离环境
- **网络组件**：虚拟网络适配器、流量捕获和重定向

**分析流程：**
1. 提交样本到Cuckoo
2. Cuckoo恢复虚拟机到干净快照
3. 将样本传输到虚拟机中
4. 启动监控Agent，运行样本
5. 监控所有系统活动（文件、注册表、进程、网络）
6. 分析时间到后，关闭虚拟机，收集数据
7. 生成分析报告

**报告解读要点：**
- **File Operations**：关注创建、修改、删除了哪些文件，特别是系统目录和启动目录下的文件
- **Registry Operations**：关注Run键、服务注册表项、映像劫持等持久化相关的修改
- **Network Traffic**：查看DNS查询、HTTP请求、TCP连接，提取C2域名和IP
- **Processes Tree**：观察进程创建关系，分析注入行为
- **API Calls**：查看关键API调用序列，理解程序执行逻辑
- **Dropped Files**：分析样本释放的其他文件，提取哈希值
- **Signatures**：查看Cuckoo自动检测到的恶意行为特征

#### 3.1.2 Joe Sandbox

Joe Sandbox是一款商业级的深度行为分析沙箱，以分析深度和检测能力著称。

**特色功能：**
- **深度系统监控**：基于驱动级的系统调用监控，捕捉更全面的行为
- **反沙箱绕过**：能够检测并绕过多种反沙箱技术
- **静态+动态混合分析**：结合静态分析和动态分析的结果
- **Office文档分析**：深度分析宏、OLE对象、嵌入对象
- **PDF分析**：分析PDF中的JavaScript、嵌入文件、漏洞利用
- **YARA规则集成**：内置丰富的YARA规则进行家族匹配
- **分类和归因**：自动进行恶意软件家族分类和威胁归因

#### 3.1.3 在线沙箱服务

**VirusTotal**：
- 集成了多家杀毒引擎和沙箱的检测结果
- 提供基础的动态分析信息（行为摘要、网络通信）
- 可查询文件哈希、URL、域名、IP的信誉信息

**Hybrid Analysis**：
- 基于Falcon Sandbox的在线分析服务
- 提供详细的行为报告和进程树
- 支持提取内存中的Payload
- 提供威胁标签和家族识别

**ANY.RUN**：
- 交互式在线沙箱，可以实时操作虚拟机
- 支持手动触发恶意行为（如点击按钮、输入命令）
- 实时显示进程、文件、注册表、网络活动
- 适合分析需要用户交互的恶意代码

**Joe Sandbox Cloud**：
- Joe Sandbox的云服务版本
- 提供深度分析报告
- 支持多种格式的样本分析

#### 3.1.4 沙箱报告解读实战

**沙箱报告的典型结构：**

1. **摘要（Summary）**：威胁等级、恶意软件家族、主要行为摘要
2. **静态分析（Static Analysis）**：文件信息、哈希、字符串、导入表、加壳检测
3. **行为分析（Behavioral Analysis）**：
   - 文件系统行为
   - 注册表行为
   - 进程行为
   - 服务/驱动行为
   - 网络行为
4. **网络流量（Network Traffic）**：
   - DNS查询
   - HTTP/HTTPS请求
   - TCP/UDP连接
   - 完整PCAP下载
5. **内存分析（Memory Analysis）**：
   - 内存中的字符串
   - 注入检测
   - 内存Dump提取
6. **检测签名（Detections / Signatures）**：
   - 触发的恶意行为规则
   - 家族匹配结果
7. **IOC列表（Indicators of Compromise）**：
   - 文件哈希
   - IP地址和域名
   - URL
   - 注册表项
   - 互斥量

**快速阅读技巧：**
- 先看摘要和威胁等级，快速了解整体情况
- 查看网络行为部分，提取C2通信IOC
- 查看持久化相关行为（注册表Run键、服务、计划任务）
- 查看进程树，分析注入行为和执行链
- 查看触发的检测签名，辅助判断恶意代码类型

### 3.2 进程监控

#### 3.2.1 Process Explorer

Process Explorer是Sysinternals工具集中的进程管理工具，可以看作是任务管理器的增强版。

**核心功能：**
- 显示进程树结构（父子进程关系）
- 显示每个进程加载的DLL和打开的句柄
- 显示进程的命令行参数
- 显示进程的用户和安全上下文
- 验证进程签名（Verify Signatures）
- 在线查询进程信息（VirusTotal集成）

**恶意代码分析中的应用：**

1. **识别可疑进程**：
   - 检查进程路径是否位于系统目录（如 `C:\Windows\`、`C:\Program Files\`）
   - 检查进程名称是否与正常系统进程一致（注意名称伪装，如 `svch0st.exe` vs `svchost.exe`）
   - 使用 "Verify Signatures" 功能验证数字签名

2. **分析父子进程关系**：
   - 正常的系统进程有固定的父进程（如 `services.exe` 的父进程是 `wininit.exe`）
   - 异常的父子关系可能是进程注入或恶意启动的迹象
   - 例如：`winword.exe` 创建 `cmd.exe` 进程是宏病毒的典型特征

3. **查看加载的DLL**：
   - 按 `Ctrl+D` 切换到底部面板显示DLL
   - 检查是否有可疑路径的DLL被加载
   - 检查DLL是否有有效签名
   - 异常注入的DLL通常不在正常系统路径下

4. **查看打开的句柄**：
   - 按 `Ctrl+H` 切换到底部面板显示句柄
   - 查看进程打开了哪些文件、注册表项、互斥量、网络连接
   - 互斥量名称是重要的IOC指标

5. **进程替换检测**：
   - 对比进程路径和内存中实际执行的镜像是否一致
   - 使用 "Strings" 功能分别查看进程映像文件和内存中的字符串

#### 3.2.2 Process Monitor

Process Monitor（ProcMon）是Sysinternals的另一款重量级工具，能够实时监控文件系统、注册表、进程/线程、网络等几乎所有的系统活动。

**核心功能：**
- 实时监控文件系统操作（创建、读取、写入、删除等）
- 实时监控注册表操作（打开、读取、写入、删除等）
- 实时监控进程和线程活动（创建、退出、加载DLL等）
- 实时监控网络活动（TCP/UDP连接、发送接收）
- 强大的过滤功能，精确筛选感兴趣的事件
- 支持启动时监控（Boot Logging）

**常用过滤操作：**

1. **按进程名过滤**：
   - 打开 Filter → Filter...
   - 选择 "Process Name" → "is" → 输入进程名 → Include
   - 只显示特定进程的活动

2. **按操作类型过滤**：
   - 只显示 "RegSetValue" 操作（注册表写入）
   - 只显示 "WriteFile" 操作（文件写入）
   - 只显示 "Process Create" 操作（进程创建）

3. **按路径过滤**：
   - 只显示对特定注册表键的操作
   - 只显示对特定目录的文件操作

**恶意代码分析中的应用：**

1. **持久化分析**：
   - 过滤 `RegSetValue` 操作，查看写入了哪些注册表项
   - 重点关注 `...\Run`、`...\RunOnce`、`...\Services\` 等路径
   - 过滤 `CreateFile` + `WriteFile` 操作，查看在启动目录创建了哪些文件

2. **文件行为分析**：
   - 查看恶意代码创建了哪些文件，写入了什么内容
   - 查看恶意代码读取了哪些系统文件和用户文件
   - 关注 `%APPDATA%`、`%TEMP%`、`%SystemRoot%\System32` 等目录

3. **网络行为辅助分析**：
   - 查看TCP/UDP连接信息
   - 结合Wireshark进行关联分析

4. **分析启动流程**：
   - 启用 Boot Logging（Options → Enable Boot Logging）
   - 重启系统后运行恶意代码
   - 再次启动ProcMon查看启动期间的所有活动

**使用技巧：**
- 分析前先清除历史事件（`Ctrl+X`），减少干扰
- 设置好过滤器再运行样本，避免事件过多
- 使用书签（`Ctrl+B`）标记重要事件
- 可以保存事件日志（PCAP格式）供后续分析
- 关注 "Result" 列，注意 "ACCESS DENIED" 等失败操作

### 3.3 网络行为分析

#### 3.3.1 Wireshark抓包分析

Wireshark是最流行的网络协议分析工具，能够捕获和分析网络数据包。

**抓包准备：**
1. 确保分析虚拟机的网络配置正确（建议使用仅主机模式+FakeNet）
2. 启动Wireshark，选择正确的网卡接口
3. 开始抓包后再运行恶意代码
4. 运行足够时间后停止抓包并保存

**常用过滤表达式：**

| 过滤需求 | 表达式 |
|----------|--------|
| HTTP请求 | `http.request` |
| DNS查询 | `dns` |
| 特定IP通信 | `ip.addr == 192.168.1.100` |
| 特定端口 | `tcp.port == 443` 或 `udp.port == 53` |
| POST请求 | `http.request.method == "POST"` |
| 域名包含特定字符串 | `http.host contains "evil"` |

**分析步骤：**

1. **DNS流量分析**：
   - 过滤 `dns`，查看所有DNS查询
   - 记录恶意代码解析的所有域名
   - 注意DGA（域名生成算法）产生的随机域名
   - 分析域名的解析顺序和频率

2. **HTTP流量分析**：
   - 过滤 `http`，查看所有HTTP请求
   - 分析请求方法（GET/POST）、URL、User-Agent
   - 查看请求体和响应体内容
   - 右键 → Follow → HTTP Stream，查看完整的HTTP会话
   - 识别C2通信协议特征

3. **HTTPS流量分析**：
   - 恶意代码使用HTTPS加密通信时，默认无法看到明文内容
   - 可以通过SSLKEYLOGFILE方式解密（需配合浏览器或注入SSL密钥）
   - 或使用中间人代理工具（如Burp Suite、Fiddler）
   - 也可以分析证书特征、SNI信息等进行判断

4. **其他协议分析**：
   - IRC通信：通常使用6667端口，特征明显
   - DNS隧道：DNS查询中携带编码的数据
   - ICMP隧道：ICMP数据包中携带数据
   - 自定义TCP协议：非标准端口的二进制数据

#### 3.3.2 FakeNet-NG

FakeNet-NG是一款Windows平台的网络模拟工具，能够模拟多种常见的网络服务，使恶意代码在隔离环境中也能正常进行网络通信。

**支持的服务：**
- DNS服务器：响应所有DNS查询，将域名解析到指定IP
- HTTP服务器：响应所有HTTP请求，可返回自定义内容
- HTTPS服务器：使用自签名证书响应HTTPS请求
- FTP服务器
- SMTP服务器
- 等等

**使用方法：**
1. 以管理员身份运行FakeNet-NG
2. FakeNet会自动修改系统DNS设置，将DNS指向自身
3. 启动所有配置的服务（HTTP、HTTPS、DNS等）
4. 运行恶意代码，所有网络请求都会被FakeNet拦截和响应
5. 查看FakeNet的日志，记录所有请求信息

**高级配置：**
- 修改配置文件 `fakenet.ini` 自定义服务行为
- 设置HTTP默认响应内容
- 配置重定向规则
- 启用或禁用特定服务

#### 3.3.3 INetSim

INetSim是Linux平台的网络模拟工具，功能更强大，适合搭建专用的分析网络。

**部署方式：**
- 在独立的Linux虚拟机中安装INetSim
- 将分析机的网关和DNS指向INetSim服务器
- INetSim模拟各种网络服务并记录所有请求

**主要功能：**
- 模拟DNS、HTTP、HTTPS、FTP、SMTP、POP3、TFTP等服务
- 支持自定义响应内容
- 详细的日志记录和统计
- 支持SSL/TLS加密连接
- 支持时间欺骗（修改系统时间以触发时间相关的恶意行为）

### 3.4 文件系统监控

#### 3.4.1 文件行为分析要点

恶意代码的文件操作行为包含大量线索：

1. **释放文件（Dropper）**：
   - 恶意代码本体可能是一个下载者或释放器
   - 运行后会释放真正的Payload到系统目录或临时目录
   - 关注释放文件的路径、名称、大小、哈希值

2. **配置文件和日志**：
   - 部分恶意代码会创建配置文件保存C2地址、加密密钥等
   - 有些会记录操作日志或窃取的数据
   - 配置文件可能使用加密或自定义格式存储

3. **感染文件**：
   - 文件型病毒会感染其他可执行文件
   - 观察被感染文件的大小变化、入口点变化
   - 分析感染方式（附加式、插入式、入口点替换）

4. **删除自身**：
   - 部分恶意代码执行完后会删除自身文件
   - 通常使用批处理文件或计划任务实现自删除
   - 常见手法：创建 `.bat` 文件，执行后删除自身和原文件

#### 3.4.2 监控工具与方法

**Process Monitor**：
- 最全面的文件操作监控工具
- 可以看到每个文件操作的详细信息（路径、操作类型、结果、调用栈）
- 支持过滤和搜索

**Filesystem Watcher工具**：
- 专门的文件系统监控工具
- 实时显示文件变化
- 适合监控特定目录的变化

**手工分析技巧：**
- 分析前记录系统状态（文件列表、注册表快照）
- 分析后对比变化
- 关注以下敏感目录的变化：
  - `C:\Windows\`、`C:\Windows\System32\`
  - `C:\Users\<用户名>\AppData\Roaming\`
  - `C:\Users\<用户名>\AppData\Local\Temp\`
  - `C:\ProgramData\`
  - 启动目录：`C:\Users\<用户名>\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup\`

### 3.5 注册表监控

#### 3.5.1 注册表分析要点

注册表是Windows系统的核心配置数据库，也是恶意代码实现持久化和窃取信息的重要目标。

**重点关注的注册表项：**

1. **自启动项（持久化）**：
   - `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
   - `HKLM\Software\Microsoft\Windows\CurrentVersion\Run`
   - `HKCU\Software\Microsoft\Windows\CurrentVersion\RunOnce`
   - `HKLM\Software\Microsoft\Windows\CurrentVersion\RunOnce`
   - `HKCU\Software\Microsoft\Windows\CurrentVersion\RunServices`
   - `HKLM\System\CurrentControlSet\Services\`（服务项）
   - `HKCU\Software\Microsoft\Windows NT\CurrentVersion\Windows\Load`
   - `HKCU\Software\Microsoft\Windows NT\CurrentVersion\Windows\Run`

2. **映像劫持**：
   - `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\`
   - 恶意代码可能在此处设置Debugger值实现劫持

3. **浏览器相关**：
   - `HKCU\Software\Microsoft\Internet Explorer\`
   - 主页、代理设置、插件等
   - 浏览器劫持木马常修改这些位置

4. **系统配置**：
   - `HKLM\SYSTEM\CurrentControlSet\Control\`
   - 安全策略、防火墙设置等

5. **恶意代码自身配置**：
   - 部分恶意代码会在注册表中存储自己的配置信息
   - 可能使用加密或二进制数据存储
   - 位置可能在 `HKCU\Software\` 下创建随机名称的子键

#### 3.5.2 Regshot对比工具

Regshot是一款轻量级的注册表对比工具，通过拍摄注册表快照并进行对比来发现变化。

**使用方法：**

1. **拍摄第一份快照**：
   - 启动Regshot
   - 点击 "1st shot" → "Shot"
   - 等待扫描完成（可能需要1-2分钟）
   - 这是分析前的基线快照

2. **运行恶意代码**：
   - 运行待分析的样本
   - 等待足够时间让恶意代码完成操作
   - 可以进行一些触发操作（如重启、登录等）

3. **拍摄第二份快照**：
   - 回到Regshot
   - 点击 "2nd shot" → "Shot"
   - 等待扫描完成

4. **对比结果**：
   - 点击 "Compare" 按钮
   - 查看添加、删除、修改的注册表项
   - 重点关注新增的值和修改的关键项

**输出解读：**
- **Keys added**：新增的注册表键
- **Keys deleted**：删除的注册表键
- **Values added**：新增的值
- **Values modified**：修改的值
- **Values deleted**：删除的值

### 3.6 系统调用追踪

#### 3.6.1 API Monitor

API Monitor是一款Windows API调用监控工具，能够捕获和显示应用程序调用的所有API函数。

**核心功能：**
- 支持监控数千个API函数（涵盖大部分系统DLL）
- 显示函数调用的参数和返回值
- 支持按DLL、分类、函数名进行过滤
- 支持过滤特定进程
- 支持查看调用堆栈
- 支持修改API调用（拦截和修改参数）

**使用方法：**

1. 启动API Monitor（注意选择正确的位数：32位或64位）
2. 在左侧API定义面板中选择要监控的API
   - 建议先选择常用分类：File I/O、Registry、Process and Thread、Networking、Memory
3. 通过 "File → Monitor New Process" 启动要监控的程序
   - 或附加到已运行的进程（"File → Attach to Process"）
4. 在右侧面板查看API调用序列
5. 点击每个调用查看详细的参数和返回值

**恶意代码分析中的应用：**
- 分析文件操作的细节（打开了哪些文件，写入了什么内容）
- 分析注册表操作的细节
- 分析网络通信的API调用
- 查看动态加载的DLL和函数
- 分析加密相关的API调用（CryptoAPI系列函数）

#### 3.6.2 strace / ltrace（Linux平台）

在Linux平台上分析恶意代码时，`strace` 和 `ltrace` 是常用的系统调用追踪工具。

**strace：**
- 跟踪进程的系统调用
- 显示每个系统调用的名称、参数和返回值

```bash
# 基本用法
strace -o strace.log ./malware

# 只跟踪特定的系统调用
strace -e trace=open,read,write,connect -o strace.log ./malware

# 跟踪网络相关系统调用
strace -e trace=network -o strace.log ./malware

# 跟踪文件相关系统调用
strace -e trace=file -o strace.log ./malware

# 跟踪子进程
strace -f -o strace.log ./malware
```

**ltrace：**
- 跟踪进程的库函数调用
- 类似于strace，但追踪的是用户态库函数

```bash
# 基本用法
ltrace -o ltrace.log ./malware
```
