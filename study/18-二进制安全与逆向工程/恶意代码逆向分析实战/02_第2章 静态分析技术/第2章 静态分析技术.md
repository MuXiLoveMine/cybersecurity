# 第2章 静态分析技术

静态分析是恶意代码分析的第一道工序，在不运行样本的前提下尽可能多地提取信息。扎实的静态分析能力能够大幅提升分析效率。

### 2.1 文件格式识别与初步分析

#### 2.1.1 文件类型识别

文件扩展名可能被恶意代码伪造，必须通过文件头（Magic Number）来判断真实的文件类型。

**常见文件头特征：**

| 文件类型 | 文件头标识（十六进制） | 说明 |
|----------|----------------------|------|
| PE可执行文件 | `4D 5A`（MZ） | Windows可执行文件 |
| ELF可执行文件 | `7F 45 4C 46`（.ELF） | Linux可执行文件 |
| Mach-O | `FE ED FA CE` 或 `CF FA ED FE` | macOS可执行文件 |
| ZIP压缩包 | `50 4B 03 04`（PK..） | ZIP格式文件 |
| RAR压缩包 | `52 61 72 21`（Rar!） | RAR格式文件 |
| PDF文档 | `25 50 44 46`（%PDF） | PDF文件 |
| Office旧版 | `D0 CF 11 E0` | OLE复合文档（.doc/.xls） |
| Office新版 | `50 4B 03 04` | OpenXML格式（.docx/.xlsx） |
| JPEG图片 | `FF D8 FF` | JPEG图像文件 |

**实操步骤：**

1. 使用十六进制编辑器（HxD、010 Editor）打开文件，查看文件头
2. 使用 `file` 命令（Linux）或工具自动识别
3. 检查文件尾，确认文件是否完整，有无附加数据
4. 对比文件扩展名和真实类型，判断是否存在伪装

#### 2.1.2 PE结构分析

PE（Portable Executable）是Windows平台的可执行文件格式，深入理解PE结构是静态分析的基础。

**PE文件整体结构：**

```
+---------------------+
| DOS Header          |  64字节，以"MZ"开头
+---------------------+
| DOS Stub            |  DOS下的存根程序
+---------------------+
| PE Signature        |  "PE\0\0"（50 45 00 00）
+---------------------+
| COFF File Header    |  机器类型、节区数量、时间戳等
+---------------------+
| Optional Header     |  入口点、基地址、节区对齐、数据目录表
+---------------------+
| Section Headers     |  各个节区的头部信息
+---------------------+
| .text 节区          |  代码节，存储程序指令
+---------------------+
| .data 节区          |  数据节，存储初始化的全局变量
+---------------------+
| .rdata 节区         |  只读数据节，存储常量和导入表
+---------------------+
| .rsrc 节区          |  资源节，存储图标、对话框、字符串资源
+---------------------+
| .reloc 节区         |  重定位节，存储基址重定位信息
+---------------------+
```

**关键字段分析要点：**

1. **AddressOfEntryPoint（OEP）**：程序入口点的RVA（相对虚拟地址），正常程序通常指向 `.text` 节区。如果入口点指向 `.rsrc`、`.data` 等非代码节区，很可能加了壳。

2. **ImageBase**：程序首选加载基址，EXE默认为 `0x00400000`，DLL默认为 `0x10000000`。

3. **Section Alignment / File Alignment**：节区在内存和文件中的对齐粒度。内存中通常是4KB（0x1000），文件中通常是512字节（0x200）。

4. **SizeOfImage**：映像在内存中的总大小。

5. **数据目录表（Data Directory）**：包含导入表、导出表、资源表、重定位表、TLS表等的位置和大小信息。

**使用PEview分析PE结构：**

1. 打开PEview，载入目标PE文件
2. 依次查看 IMAGE_DOS_HEADER、IMAGE_NT_HEADERS、IMAGE_FILE_HEADER、IMAGE_OPTIONAL_HEADER
3. 查看各个节区的名称、虚拟大小、虚拟地址、原始大小、原始偏移、属性
4. 重点关注 IMAGE_IMPORT_DESCRIPTOR（导入表）和 IMAGE_EXPORT_DIRECTORY（导出表）

**节区异常分析：**

正常PE文件的节区名称通常是 `.text`、`.data`、`.rdata`、`.rsrc`、`.reloc` 等。出现以下情况需要警惕：

- 节区名称异常：如 `.upx`（UPX壳）、`.themida`（Themida壳）、`yp`、`G` 等
- 节区属性异常：`.data` 节区具有可执行属性，可能存在代码注入或自修改
- 节区大小异常：虚拟大小远大于原始大小，可能是运行时解密的代码
- 节区数量过多或过少：正常程序通常有5-10个节区

#### 2.1.3 导入导出表分析

**导入表（Import Table）**

导入表记录了程序从哪些DLL导入了哪些函数，是分析程序功能的重要线索。

**分析要点：**

- **常见系统DLL**：`kernel32.dll`（核心API）、`user32.dll`（窗口和消息）、`advapi32.dll`（注册表、服务）、`ws2_32.dll`（网络通信）、`wininet.dll`（HTTP/FTP）
- **可疑API组合**：
  - `CreateRemoteThread` + `WriteProcessMemory` → 进程注入
  - `SetWindowsHookEx` → 钩子注入/键盘记录
  - `WinExec` / `ShellExecute` / `CreateProcess` → 执行命令/启动程序
  - `InternetOpenUrl` / `HttpSendRequest` → 网络下载
  - `RegSetValueEx` → 注册表修改（可能实现持久化）
  - `GetAsyncKeyState` / `SetWindowsHookEx(WH_KEYBOARD_LL)` → 键盘记录
  - `CryptEncrypt` / `CryptGenKey` → 加密操作（勒索软件特征）

**恶意代码常用的隐藏导入手法：**

1. **动态获取API地址**：使用 `GetProcAddress` 和 `LoadLibrary` 动态加载，导入表中看不到具体函数名
2. **直接解析PEB**：通过遍历PEB（进程环境块）的LDR链表手工解析导出表
3. **API哈希匹配**：将API名称进行哈希计算，运行时通过哈希值查找地址
4. **直接系统调用（Syscall）**：不经过用户态API，直接通过 `syscall` 或 `int 0x2e` 进入内核

**导出表（Export Table）**

导出表主要存在于DLL文件中，记录了DLL对外提供的函数。对于EXE文件，如果存在导出表，通常比较可疑。

分析导出表可以了解DLL提供了哪些功能。恶意DLL的导出函数可能具有以下特征：
- 导出函数数量极少（只有1-2个，且名称模糊）
- 使用序号导出而不是名称导出
- 导出函数名具有误导性（如 `Install`、`ServiceMain`）

### 2.2 字符串提取与分析

字符串分析是静态分析中效率最高的方法之一，往往能直接发现关键线索。

#### 2.2.1 字符串提取方法

**使用Strings工具提取：**

```bash
# 基本用法 - 提取所有可打印字符串（长度≥4）
strings sample.exe > strings.txt

# 只提取宽字符字符串（Unicode）
strings -el sample.exe > unicode_strings.txt

# 显示字符串在文件中的偏移
strings -t x sample.exe > strings_offset.txt
```

**使用FLOSS（FLARE Obfuscated String Solver）：**

FLOSS是Mandiant公司开发的高级字符串提取工具，不仅能提取普通字符串，还能通过模拟执行解密堆栈字符串和加密字符串。

```bash
# 基本分析
floss sample.exe > floss_strings.txt

# 详细输出模式
floss -v sample.exe > floss_detailed.txt
```

#### 2.2.2 可疑字符串特征

**高价值字符串类型：**

1. **URL和域名**：`http://`、`https://`、`ftp://` 开头的网络地址
2. **IP地址**：形如 `xxx.xxx.xxx.xxx` 的IPv4地址
3. **文件路径**：`C:\Windows\`、`%APPDATA%`、`Startup` 等路径
4. **注册表项**：`Software\Microsoft\Windows\CurrentVersion\Run` 等自启动项
5. **命令行参数**：`-install`、`-service`、`-hide` 等
6. **错误提示和状态信息**：如 "Connection failed"、"Decrypting..."
7. **加密密钥和配置**：硬编码的密钥、密码、C2地址
8. **互斥量名称**：用于确保单实例运行的互斥体名字
9. **DLL和函数名**：动态加载的模块和函数名称
10. **PDB路径**：编译时残留的调试符号路径

#### 2.2.3 加密/混淆字符串识别

恶意代码经常对字符串进行加密，运行时才解密使用，以逃避静态特征检测。

**常见加密字符串特征：**

1. **大量不可打印字符**：字符串中包含大量 `0x00-0x1F` 和 `0x7F-0xFF` 范围的字节
2. **Base64编码特征**：长串的大小写字母+数字+`+/`，以 `=` 结尾（可选）
3. **十六进制字符串**：连续的0-9、A-F字符
4. **高熵值数据**：使用熵分析工具检测，加密数据的熵值接近8
5. **数据段中的大块数据**：`.data` 或 `.rdata` 节区中存在大块连续数据

**加密算法初步判断：**

- **XOR加密**：最简单的加密方式，通常是单字节密钥循环异或。特征是存在固定的密钥字节和循环解密模式
- **Base64编码**：有明显的编码字符集特征，通常用于编码二进制数据或配置信息
- **AES加密**：数据块大小为16字节的倍数，通常配合Base64或十六进制编码使用
- **RC4加密**：流加密，密钥长度可变，常用于加密网络通信内容

**手动解密XOR字符串示例：**

如果发现一个可疑的数据块，可以尝试用常见单字节密钥（如0xFF、0xAA、0x55）进行XOR解密，观察是否出现可读字符串。

### 2.3 加壳检测与脱壳初步

#### 2.3.1 加壳检测工具

**PEiD（PE Identifier）：**

PEiD是最经典的加壳检测工具，内置了数千种壳和编译器的特征签名。

使用方法：
1. 打开PEiD，拖入目标文件
2. 查看识别结果，如 "UPX 3.94 [LZMA] -> Markus Oberhumer, Laszlo Molnar & John Reiser"
3. 点击子面板查看详细的PE结构信息
4. 使用 "-> EP Section" 查看入口点所在的节区

**DiE（Detect It Easy）：**

DiE是新一代的加壳检测工具，支持更多的格式和更准确的识别，界面友好且持续更新。

使用方法：
1. 打开DiE，载入目标文件
2. 主界面显示检测结果，包括编译器、加壳器、保护类型
3. "Sections" 标签页查看节区信息
4. "Entropy" 标签页查看各节区熵值（高熵值表示可能加密/压缩）

**熵值分析：**

熵值（Entropy）衡量数据的无序程度，范围为0-8。

- 熵值接近0：数据高度有序（如全零填充）
- 熵值接近8：数据高度无序（如加密或压缩数据）
- 正常代码节区：熵值通常在4-6之间
- 加密/压缩数据：熵值通常在7以上

**判断加壳的辅助特征：**

1. 入口点不在 `.text` 节区
2. 节区名称异常（如 `.upx`、`.packed`、`.themida`）
3. 导入表函数极少（可能只有 `LoadLibraryA` 和 `GetProcAddress`）
4. 文件中存在大量不可读数据（高熵值）
5. 节区的虚拟大小远大于原始大小
6. 字符串数量极少，几乎都是乱码

#### 2.3.2 常见壳的识别与脱壳

**UPX壳：**

UPX是最常见的开源压缩壳，广泛用于合法软件和恶意软件。

- 识别特征：节区名为 `UPX0`、`UPX1`，入口点在 `UPX1` 节区
- 手动脱壳命令：`upx -d sample.exe -o sample_unpacked.exe`
- 注意：恶意代码可能修改UPX特征或使用修改版UPX，此时需要手动脱壳

**ASPack壳：**

ASPack是另一款常见的压缩壳。

- 识别特征：节区名为 `.aspack`，导入表可能只有几个函数
- 脱壳方法：使用专用脱壳工具或在OEP处Dump

**Themida / VMProtect：**

这两款是商业级的强保护壳，大量使用代码虚拟化、反调试、完整性校验等技术。

- 识别特征：节区名称各异（如 `.themida`、`vmp0`、`vmp1`），有大量异常的节区
- 脱壳难度：非常高，通常需要花费大量时间分析
- 分析策略：优先使用动态分析，必要时针对关键函数进行虚拟化还原

#### 2.3.3 通用脱壳思路

对于未知壳或修改版壳，通常采用"找OEP + Dump + 重建Import表"的通用脱壳思路：

1. **查找OEP（Original Entry Point）**：
   - 使用ESP定律（堆栈平衡原理）
   - 单步跟踪法
   - 内存断点法（在 `.text` 节区设内存执行断点）
   - 最后一次异常法

2. **Dump内存镜像**：
   - 到达OEP后，使用Scylla或OllyDump转储进程内存
   - 修正ImageBase

3. **重建导入表**：
   - 使用Scylla的IAT AutoSearch功能自动查找IAT
   - 使用Get Imports获取导入函数
   - 修复转储文件的导入表

### 2.4 反汇编基础

#### 2.4.1 IDA Pro分析流程

IDA Pro是业界最强大的反汇编和反编译工具，是恶意代码分析的利器。

**标准分析流程：**

1. **载入文件**：
   - 打开IDA，选择New，载入目标文件
   - 选择正确的文件格式和处理器类型（通常自动识别）
   - 等待自动分析完成（根据文件大小，可能需要几秒到几分钟）

2. **初步浏览**：
   - 查看 Functions window 中的函数列表
   - 查看 Names window 中的命名符号
   - 查看 Strings window 中的字符串列表
   - 查看 Imports/Exports 窗口

3. **定位关键函数**：
   - 通过字符串引用定位（双击字符串，按X键查看引用）
   - 通过导入API定位（查看导入函数的交叉引用）
   - 通过函数特征识别（如加密算法的常量特征）

4. **代码分析**：
   - 反编译为伪C代码（F5键，需要Hex-Rays插件）
   - 分析函数调用关系（View → Graphs → Function calls）
   - 重命名变量和函数，添加注释
   - 分析关键算法和数据结构

5. **标注和输出**：
   - 保存idb数据库（分析工作保存在idb中）
   - 生成反汇编列表（File → Produce file → Create LST file）
   - 导出分析结果

#### 2.4.2 Ghidra分析流程

Ghidra是NSA开源的逆向工程套件，功能强大且免费，是IDA Pro的优秀替代品。

**基本使用：**

1. **创建项目**：启动Ghidra，新建项目（Non-Shared Project）
2. **导入文件**：将目标文件拖入项目窗口
3. **双击打开**：确认语言和编译器设置，开始分析
4. **自动分析**：勾选分析选项（默认即可），等待分析完成
5. **代码浏览**：
   - 左侧Program Tree：程序结构树
   - Symbol Tree：符号树（函数、标签、类等）
   - Listing：反汇编代码
   - Decompile：反编译伪代码

**常用快捷键：**

- `G`：跳转到指定地址
- `L`：编辑标签/函数名
- `;`：添加注释
- `/`：添加可折叠注释
- `F12`：反编译当前函数
- `Ctrl+Shift+F`：搜索字符串
- `Ctrl+Shift+E`：搜索字节序列

#### 2.4.3 x86/x64汇编关键知识点

**常见寄存器：**

| 寄存器 | 用途 |
|--------|------|
| EAX/RAX | 累加器，函数返回值通常存在这里 |
| EBX/RBX | 基址寄存器 |
| ECX/RCX | 计数器，循环计数；x64下第一个参数 |
| EDX/RDX | 数据寄存器；x64下第二个参数 |
| ESI/RSI | 源索引寄存器，字符串操作源地址 |
| EDI/RDI | 目的索引寄存器，字符串操作目的地址 |
| EBP/RBP | 基址指针，指向栈帧底部 |
| ESP/RSP | 栈指针，指向栈顶 |
| EIP/RIP | 指令指针，指向下一条要执行的指令 |

**常见指令模式：**

- `call <address>`：函数调用，将返回地址压栈后跳转到目标地址
- `ret`：函数返回，从栈顶弹出返回地址并跳转
- `push` / `pop`：栈操作
- `mov`：数据传送
- `add` / `sub` / `imul` / `idiv`：算术运算
- `and` / `or` / `xor` / `not` / `shl` / `shr`：位运算
- `cmp` + `jcc`：比较和条件跳转
- `lea`：加载有效地址，也常用于算术运算
- `rep movsb` / `rep stosb`：字符串操作

**函数调用约定：**

**cdecl（C调用约定）：**
- 参数从右往左压栈
- 调用者平衡堆栈
- EAX保存返回值

**stdcall（标准调用约定）：**
- 参数从右往左压栈
- 被调用者平衡堆栈（ret n）
- Windows API的默认约定

**fastcall（快速调用约定）：**
- 前两个参数分别放入ECX和EDX
- 其余参数从右往左压栈
- 被调用者平衡堆栈

**x64调用约定（Microsoft x64）：**
- 前四个参数分别放入RCX、RDX、R8、R9
- 第五个及以后的参数压栈
- 调用者分配32字节的影子空间（shadow space）
- 调用者平衡堆栈
- RAX保存返回值，RDX保存返回值的高64位（如果需要）

#### 2.4.4 常见代码模式识别

**循环结构：**

```asm
    mov ecx, 10         ; 循环计数器
loop_start:
    ; 循环体代码
    ...
    dec ecx             ; 计数器减1
    jnz loop_start      ; 非零则继续循环
```

**条件分支：**

```asm
    cmp eax, 0          ; 比较
    jz is_zero          ; 等于0则跳转
    ; 不等于0的代码
    ...
    jmp end_if
is_zero:
    ; 等于0的代码
    ...
end_if:
```

**函数调用（带参数）：**

```asm
    push 0              ; 第四个参数
    push offset String  ; 第三个参数
    push 0              ; 第二个参数
    push hWnd           ; 第一个参数
    call MessageBoxA    ; 调用函数
```

**解密循环：**

```asm
    mov esi, offset encrypted_data
    mov edi, offset decrypted_buffer
    mov ecx, data_len
    mov bl, 0xAA        ; XOR密钥
decrypt_loop:
    lodsb               ; 取一字节到AL
    xor al, bl          ; XOR解密
    stosb               ; 保存结果
    loop decrypt_loop   ; 循环直到ECX为0
```

### 2.5 常见恶意代码模式识别

#### 2.5.1 解密循环模式

恶意代码经常将配置信息、C2地址、Shellcode等数据加密存储，运行时动态解密。

**XOR解密循环特征：**
- 有一个循环计数器（ECX）
- 有一个密钥（可以是单字节、多字节或密钥流）
- 每次循环取一个字节与密钥进行XOR运算
- 将解密结果写回原位置或新的缓冲区

**Base64解码特征：**
- 引用Base64编码表（通常是 `ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/`）
- 每4个编码字符解码为3个字节
- 处理 `=` 填充字符

**AES解密特征：**
- 存在S盒常量（256字节的查找表）
- 有明显的轮密钥扩展过程
- 通常处理16字节（128位）的数据块

#### 2.5.2 注入代码模式

**进程注入的典型步骤：**

1. 使用 `OpenProcess` 打开目标进程
2. 使用 `VirtualAllocEx` 在目标进程中分配内存
3. 使用 `WriteProcessMemory` 将Shellcode或DLL路径写入目标进程
4. 使用 `CreateRemoteThread` 或 `QueueUserAPC` 启动远程线程执行注入代码

**Shellcode特征：**
- 短小精悍的汇编代码片段
- 不依赖导入表，动态查找API地址
- 通常通过PEB遍历LDR链表查找kernel32.dll基址
- 通过解析导出表查找所需API的地址

**经典Shellcode结构：**
```
获取kernel32基址 → 解析导出表 → 查找LoadLibraryA → 查找所需函数 → 执行功能
```

#### 2.5.3 Hook函数模式

Hook是恶意代码实现各种功能的常用技术，包括API Hook、Inline Hook、IAT Hook等。

**IAT Hook特征：**
- 修改导入地址表（IAT）中的函数地址
- 将原函数地址替换为Hook函数地址
- Hook函数执行自定义逻辑后可能调用原函数

**Inline Hook特征：**
- 修改目标函数的前几个字节（通常5字节）
- 写入跳转指令跳转到Hook函数
- 执行Hook逻辑后需要执行被覆盖的原指令再跳回

#### 2.5.4 持久化模式

恶意代码实现持久化的常见方式及其特征：

1. **注册表Run键**：
   - 操作 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 或 `HKLM` 对应路径
   - 字符串值指向恶意程序路径

2. **服务安装**：
   - 调用 `CreateService` 创建系统服务
   - 服务名称通常具有迷惑性（如 `Windows Update Service`）

3. **计划任务**：
   - 使用 `schtasks.exe` 或 `at` 命令创建计划任务
   - 或通过任务计划COM接口创建

4. **映像劫持**：
   - 修改 `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options`
   - 在某个正常程序名下设置 `Debugger` 值指向恶意程序

5. **WMI事件订阅**：
   - 通过WMI创建永久事件订阅
   - 在特定条件触发时执行恶意代码
