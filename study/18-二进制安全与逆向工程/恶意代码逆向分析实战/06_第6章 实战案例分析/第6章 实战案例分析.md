# 第6章 实战案例分析

理论知识需要通过实战来巩固。本章通过三个典型案例，完整展示恶意代码分析的流程和方法。

### 6.1 案例一：某勒索软件完整分析流程

#### 6.1.1 案例背景

收到一个可疑文件 `invoice_2024.exe`，用户运行后发现所有文档都被加密，文件扩展名变为 `.lock`，桌面出现 `README_DECRYPT.txt` 文件。

**分析目标：**
- 确定勒索软件类型和家族
- 分析加密算法，评估解密可能性
- 提取所有IOC指标
- 分析C2通信机制

#### 6.1.2 初步分析

**步骤1：计算哈希值**

使用工具计算样本哈希：
- MD5：`3f8e5a9c7d2b1f4a6e8c0a2d4f6b8e0c`
- SHA-1：`a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0`
- SHA-256：`1a2b3c4d5e6f7a8b9c0d1e2f3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1a2b`

**步骤2：文件类型识别**

使用PEiD或DiE检测：
- 文件类型：Win32 PE可执行文件
- 编译器：Microsoft Visual C++
- 加壳检测：UPX 3.95

**步骤3：脱壳处理**

使用UPX命令脱壳：
```
upx -d invoice_2024.exe -o invoice_unpacked.exe
```

脱壳后再次检测，确认为无壳的VC++程序。

#### 6.1.3 静态分析

**字符串分析：**

使用FLOSS提取字符串，发现以下关键线索：
- `README_DECRYPT.txt` — 勒索信文件名
- `Your files have been encrypted!` — 勒索信息
- `bitcoin:1A1zP1eP5QGefi2DMPTfTL5SLmv7DivfNa` — 比特币地址
- `http://lock67v3zb5xq7f.onion/` — Tor网站地址
- `AES-256` — 加密算法提示
- `RSA-2048` — 加密算法提示
- `.lock` — 文件扩展名
- `Software\Microsoft\Windows\CurrentVersion\Run` — 自启动注册表项
- `CryptoGenKey`、`CryptEncrypt` — CryptoAPI函数名

**PE结构分析：**

使用PEview分析：
- 入口点：0x12345（位于.text节区，正常）
- 节区：.text、.rdata、.data、.rsrc、.reloc
- 导入表包含：kernel32.dll、advapi32.dll、user32.dll、wininet.dll、shell32.dll
- 重点关注advapi32.dll中的CryptoAPI系列函数

**反汇编分析：**

使用IDA Pro载入脱壳后的文件：

1. **定位加密主函数**：
   - 通过 `CryptEncrypt` 的交叉引用找到加密函数
   - 该函数接收文件路径参数，打开文件后进行加密
   - 加密后修改文件扩展名为 `.lock`

2. **分析加密流程**：
   - 调用 `CryptAcquireContext` 获取CSP句柄
   - 调用 `CryptGenKey` 生成AES-256密钥
   - 读取文件内容，调用 `CryptEncrypt` 加密
   - 使用硬编码的RSA公钥加密AES密钥
   - 将加密后的AES密钥写入文件末尾
   - 重命名文件，添加 `.lock` 扩展名

3. **确认RSA公钥**：
   - 在.data节区找到Base64编码的公钥数据
   - 解码后确认为2048位RSA公钥
   - 对应的私钥不在样本中，无法直接解密

4. **分析文件遍历逻辑**：
   - 程序递归遍历所有驱动器和目录
   - 跳过系统目录（避免加密系统文件导致无法运行）
   - 只加密特定扩展名的文件（文档、图片、视频、压缩包等）
   - 目标扩展名列表硬编码在程序中

5. **分析持久化机制**：
   - 程序将自身复制到 `%APPDATA%\WindowsUpdate\` 目录
   - 修改注册表Run键：`HKCU\Software\Microsoft\Windows\CurrentVersion\Run\WindowsUpdate`
   - 值为复制后的程序路径，实现开机自启

6. **分析勒索信生成**：
   - 程序在每个被加密文件的目录中生成 `README_DECRYPT.txt`
   - 勒索信内容包含：加密说明、比特币地址、Tor网站、个人ID
   - 个人ID基于机器信息生成，用于在Tor网站上识别受害者

#### 6.1.4 动态分析

**沙箱运行：**

将样本提交到在线沙箱（Hybrid Analysis），获得以下信息：

1. **进程行为**：
   - 创建自身副本到 `%APPDATA%\` 目录
   - 创建多个子进程遍历文件
   - 运行后删除原始文件（自删除）

2. **文件系统行为**：
   - 加密测试目录中的所有文档文件
   - 在每个目录生成 `README_DECRYPT.txt`
   - 删除卷影副本（`vssadmin delete shadows /all /quiet`）

3. **注册表行为**：
   - 写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\WindowsUpdate`
   - 在 `HKCU\Software\LockCrypto\` 下存储配置信息

4. **网络行为**：
   - 向 `lock67v3zb5xq7f.onion` 发送HTTP请求（通过Tor）
   - POST数据包含：机器ID、IP地址、加密文件数量
   - 由于沙箱环境未连接Tor网络，请求失败

5. **检测结果**：
   - 45/68 杀毒引擎检测为恶意软件
   - 家族识别：LockCrypto（一个较新的勒索软件家族）

**手动动态分析：**

在隔离虚拟机中运行样本，使用以下工具监控：
- Process Monitor：监控文件和注册表操作
- Wireshark + FakeNet：捕获网络流量
- Regshot：对比注册表变化

验证了静态分析中发现的所有行为。

#### 6.1.5 结论与处置

**分析结论：**
- 这是一个名为LockCrypto的勒索软件家族
- 使用AES-256加密文件，RSA-2048加密AES密钥
- 加密强度高，无已知解密工具
- 通过注册表Run键实现持久化
- C2通信使用Tor网络

**IOC提取：**
- 文件哈希（原始文件和脱壳后文件）
- C2域名：`lock67v3zb5xq7f.onion`
- 比特币地址：`1A1zP1eP5QGefi2DMPTfTL5SLmv7DivfNa`
- 注册表项：`HKCU\Software\Microsoft\Windows\CurrentVersion\Run\WindowsUpdate`
- 互斥量：`LockCrypto_Mutex_2024`
- 文件名：`README_DECRYPT.txt`
- 文件扩展名：`.lock`

**处置建议：**
1. 隔离受感染机器，断开网络连接
2. 终止恶意进程
3. 删除恶意文件和注册表自启动项
4. 评估数据备份情况，从备份恢复文件
5. 若无备份，文件无法恢复（不建议支付赎金）
6. 加强网络防护，封锁相关IOC

### 6.2 案例二：某远控木马逆向分析

#### 6.2.1 案例背景

某企业网络中发现多台主机存在异常外联行为，防火墙日志显示有主机定期向境外IP的443端口发送数据。应急响应团队提取了可疑程序 `svchost.exe`（位于 `%APPDATA%\` 目录下）。

**分析目标：**
- 确认是否为远控木马
- 分析其功能模块
- 还原C2通信协议
- 提取所有IOC

#### 6.2.2 初步分析

**基础信息：**
- 文件名：svchost.exe（注意：正常的svchost.exe位于System32目录）
- 文件大小：256KB
- 路径：%APPDATA%\Microsoft\svchost.exe
- 数字签名：无

**加壳检测：**
- PEiD检测：Microsoft Visual C++ / .NET
- DiE检测：ConfuserEx（.NET混淆器）
- 确认这是一个.NET程序，使用了ConfuserEx进行混淆保护

**.NET程序去混淆：**

由于是.NET程序，可以使用dnSpy进行反编译和调试。

1. 使用dnSpy打开程序
2. 发现代码被严重混淆（类名、方法名、变量名都是随机字符串）
3. 字符串全部加密
4. 使用de4dot工具尝试脱混淆：
   ```
   de4dot.exe svchost.exe -o svchost_clean.exe
   ```
5. 脱混淆后类名和方法名仍然是随机的，但控制流更清晰，部分字符串已解密

#### 6.2.3 功能模块分析

**入口点分析：**

在dnSpy中定位入口点（`Main` 函数），分析启动流程：

1. 检查是否已安装（通过互斥量判断）
2. 如果未安装，执行安装流程：
   - 将自身复制到 `%APPDATA%\Microsoft\svchost.exe`
   - 创建注册表Run键实现自启动
   - 创建计划任务（每30分钟执行一次，确保存活）
3. 如果已安装，进入主功能循环

**C2通信模块：**

通过搜索网络相关函数（`HttpWebRequest`、`TcpClient`）定位通信模块：

1. 通信方式：HTTPS（443端口）
2. C2地址：硬编码在程序中，加密存储
3. 通信协议：HTTP POST，数据格式为JSON
4. 心跳间隔：60秒
5. User-Agent：`Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36`

**通信数据格式分析：**

通过逆向加密函数，还原通信数据的加密流程：
1. 构造JSON格式的请求数据
2. 使用AES-128-CBC加密JSON数据
3. 使用Base64编码加密后的数据
4. 将编码后的数据作为POST参数发送
5. 响应数据采用相同的加密方式

**AES密钥提取：**
- 密钥硬编码在程序中，经过简单的XOR加密
- 密钥：`K9x#2pL$8mQ@4vB1`
- IV：`N7w%9rT^6yH&3gF0`

**支持的命令字：**

通过分析命令分发函数，识别出以下命令：

| 命令ID | 功能 | 说明 |
|--------|------|------|
| 0x01 | 心跳 | 上报系统信息，获取命令 |
| 0x02 | 文件下载 | 从C2下载文件到本地 |
| 0x03 | 文件上传 | 将本地文件上传到C2 |
| 0x04 | 执行命令 | 执行cmd命令并返回结果 |
| 0x05 | 屏幕截图 | 截取屏幕并上传 |
| 0x06 | 键盘记录 | 开启/停止键盘记录 |
| 0x07 | 进程列表 | 获取进程列表 |
| 0x08 | 进程终止 | 终止指定进程 |
| 0x09 | 卸载 | 卸载自身，清除痕迹 |
| 0x0A | 更新 | 更新木马程序 |

**持久化机制分析：**

该木马使用了三重持久化机制：

1. **注册表Run键**：
   - `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\Microsoft Update`
   - 值：`%APPDATA%\Microsoft\svchost.exe`

2. **计划任务**：
   - 任务名：`Microsoft Update Task`
   - 触发器：每30分钟执行一次 + 用户登录时执行
   - 操作：启动 `%APPDATA%\Microsoft\svchost.exe`

3. **Startup目录快捷方式**：
   - 在启动目录创建 `Microsoft Update.lnk`
   - 指向木马程序路径

#### 6.2.4 行为分析

**动态验证：**

在隔离环境中运行去混淆后的程序，使用以下工具验证分析结果：

1. **Process Monitor**：
   - 验证文件创建、注册表写入
   - 观察网络连接的频率和内容
   - 确认计划任务创建

2. **Wireshark**：
   - 捕获HTTPS流量
   - 虽然数据加密，但可以看到连接的目标IP和频率
   - 验证心跳间隔约为60秒

3. **API Monitor**：
   - 监控HTTP请求的具体内容
   - 在 `HttpWebRequest.GetRequestStream` 处设置断点
   - 查看发送的数据，验证加密方式

#### 6.2.5 结论与IOC

**分析结论：**
- 这是一个功能完善的远控木马（RAT）
- 使用.NET编写，使用ConfuserEx混淆保护
- C2通信使用HTTPS + AES加密
- 具备完整的远控功能（文件管理、命令执行、屏幕监控、键盘记录等）
- 三重持久化机制确保存活
- 疑似某APT组织使用的定制化RAT

**IOC列表：**
- 文件哈希（SHA-256）：`d9e8c7b6a5f4e3d2c1b0a9f8e7d6c5b4a3f2e1d0c9b8a7f6e5d4c3b2a1f0e9d8`
- C2 IP：`198.51.100.23`、`203.0.113.45`
- C2域名：`update.microsoft-check.com`、`service.windows-updatee.com`
- 注册表项：`HKCU\Software\Microsoft\Windows\CurrentVersion\Run\Microsoft Update`
- 计划任务名：`Microsoft Update Task`
- 互斥量名：`Global\{A1B2C3D4-E5F6-7890-ABCD-EF1234567890}`
- 安装路径：`%APPDATA%\Microsoft\svchost.exe`

### 6.3 案例三：蠕虫传播机制分析

#### 6.3.1 案例背景

某企业内网爆发蠕虫病毒，短时间内大量主机被感染。病毒通过网络共享和U盘传播，感染后会在每个目录下生成同名的 `.exe` 文件（如 `report.doc.exe`），图标伪装成文件夹或文档。

**分析目标：**
- 分析蠕虫的传播机制
- 理解感染方式和触发条件
- 提取检测特征
- 制定清除方案

#### 6.3.2 样本获取与初步分析

从感染主机获取样本 `report.doc.exe`（实际是伪装成Word文档的EXE文件）。

**基础信息：**
- 文件大小：143,360 字节
- 文件类型：Win32 PE EXE
- 图标：Word文档图标（具有迷惑性）
- 加壳检测：ASPack 2.12

**脱壳：**
使用ASPack专用脱壳工具或手动脱壳，获得原始代码。

#### 6.3.3 传播机制分析

**传播方式一：网络共享传播**

通过逆向分析，发现蠕虫有专门的网络传播模块：

1. **枚举网络共享**：
   - 调用 `WNetOpenEnum` / `WNetEnumResource` 枚举局域网中的计算机和共享
   - 尝试连接所有可访问的共享文件夹
   - 对需要认证的共享，尝试使用内置的弱口令字典进行暴力破解

2. **感染共享文件**：
   - 在共享文件夹中递归遍历所有目录
   - 找到 `.doc`、`.xls`、`.pdf`、`.txt` 等文档文件
   - 在同目录下生成同名的 `.exe` 文件（如 `report.doc` → `report.doc.exe`）
   - 蠕虫副本使用对应类型文件的图标，具有很强的迷惑性
   - 设置文件属性为"隐藏"的原始文件，用户只能看到伪装的EXE

3. **利用漏洞传播**：
   - 检测目标主机是否存在永恒之蓝（MS17-010）漏洞
   - 如果存在漏洞，利用漏洞直接执行代码
   - 将蠕虫副本上传到目标主机并执行

**传播方式二：U盘/移动存储传播**

1. **检测U盘插入**：
   - 注册窗口消息，监听 `WM_DEVICECHANGE` 消息
   - 检测到新的移动存储设备时开始感染流程

2. **感染U盘**：
   - 在U盘根目录生成 `autorun.inf` 文件
   - `autorun.inf` 指向蠕虫程序
   - 在U盘中的每个文件夹旁生成同名EXE（图标伪装成文件夹）
   - 设置隐藏属性，诱使用户双击执行

3. **U盘传播原理**：
   - 当用户在其他机器上插入U盘时
   - 如果开启了自动播放功能，`autorun.inf` 会自动执行蠕虫
   - 如果未开启自动播放，用户浏览U盘时容易误点伪装的文件夹EXE

**传播方式三：感染本地文件**

1. 在本地硬盘的每个目录中生成蠕虫副本
2. 副本名称与目录中的文档同名，添加 `.exe` 后缀
3. 使用文件类型对应的图标
4. 将原始文件设置为隐藏属性
5. 用户看到的"文档"实际上是蠕虫程序

#### 6.3.4 恶意行为分析

除了传播功能外，蠕虫还具有以下恶意行为：

1. **关闭安全软件**：
   - 检测并终止常见杀毒软件和安全工具的进程
   - 修改注册表禁用安全软件的自启动
   - 关闭Windows防火墙和Windows Defender

2. **创建后门**：
   - 开启远程桌面服务
   - 修改防火墙规则开放3389端口
   - 创建后门账户（用户名：`sysadmin`，密码：`admin@123`）

3. **信息窃取**：
   - 收集系统信息和网络配置
   - 窃取浏览器中保存的密码
   - 将收集的信息发送到指定邮箱

4. **下载其他恶意软件**：
   - 从远程服务器下载其他木马或挖矿程序
   - 执行下载的程序

#### 6.3.5 检测与清除方案

**检测方法：**
- 检查是否存在大量同名的 `.exe` 文件（与文档同名）
- 检查注册表中是否有异常的启动项
- 检查是否有可疑的用户账户（如 `sysadmin`）
- 检查3389端口是否开放
- 使用杀毒软件全盘扫描

**清除步骤：**
1. 断开网络连接，防止继续传播
2. 进入安全模式
3. 使用杀毒软件或手动清除蠕虫文件
4. 删除所有生成的蠕虫副本（同名.exe文件）
5. 恢复被隐藏的原始文件（取消隐藏属性）
6. 清理注册表自启动项
7. 删除可疑用户账户
8. 修复被修改的系统设置
9. 更新系统补丁（特别是MS17-010）
10. 全盘扫描确认清除干净

**预防措施：**
- 关闭U盘自动播放功能
- 显示文件扩展名，避免被伪装文件欺骗
- 及时安装系统安全补丁
- 禁用不必要的网络共享
- 使用强密码，避免弱口令
- 安装杀毒软件并及时更新病毒库
