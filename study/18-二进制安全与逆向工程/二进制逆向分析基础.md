## 一、PE文件格式详解

PE（Portable Executable）是Windows操作系统的可执行文件格式，其扩展名包括.exe、.dll、.sys、.ocx等。理解PE格式是Windows平台逆向分析的基础。

### 1.1 PE文件整体布局

```
+---------------------------+  文件起始
|    DOS MZ Header          |  64字节，固定大小
+---------------------------+
|    DOS Stub               |  变长，实模式下的提示程序
+---------------------------+
|    PE Signature           |  4字节 "PE\0\0"
+---------------------------+
|    COFF File Header       |  20字节，固定大小
+---------------------------+
|    Optional Header        |  PE32: 224字节 / PE32+: 240字节
+---------------------------+
|    Section Table          |  每项40字节，节区数量由File Header指定
+---------------------------+
|    Sections (.text)       |
|    Sections (.data)       |  各节区的实际数据
|    Sections (.rsrc)       |
|    ...                    |
+---------------------------+  文件结束
```

### 1.2 DOS头

DOS头位于文件最开始，共64字节。在32/64位PE文件中，它的主要作用是定位PE签名。

**IMAGE_DOS_HEADER结构（C语言表示）：**

```c
typedef struct _IMAGE_DOS_HEADER {
    WORD e_magic;      // MZ签名 0x5A4D ("MZ")
    WORD e_cblp;       // 最后一页的字节数
    WORD e_cp;         // 文件中的页数
    WORD e_crlc;       // 重定位项数
    WORD e_cparhdr;    // 头部大小（以段落为单位）
    WORD e_minalloc;   // 所需最小额外段落数
    WORD e_maxalloc;   // 所需最大额外段落数
    WORD e_ss;         // 初始SS
    WORD e_sp;         // 初始SP
    WORD e_csum;       // 校验和
    WORD e_ip;         // 初始IP
    WORD e_cs;         // 初始CS
    WORD e_lfarlc;     // 重定位表偏移
    WORD e_ovno;       // 覆盖号
    WORD e_res[4];      // 保留字
    WORD e_oemid;       // OEM标识符
    WORD e_oeminfo;     // OEM信息
    WORD e_res2[10];    // 保留字
    LONG e_lfanew;      // PE签名的文件偏移 ★关键字段
} IMAGE_DOS_HEADER;
```

**关键字段解析：**
- `e_magic`：固定为0x5A4D（小端存储为"MZ"），用于标识DOS/PE文件
- `e_lfanew`：指向PE签名的文件偏移，通常为0x80或更大值，是定位PE头的核心字段

**Python解析DOS头示例：**

```python
import struct

def parse_dos_header(data):
    """解析PE文件的DOS头"""
    if len(data) < 64:
        return None
    
    # 解包DOS头结构
    dos_header = struct.unpack_from('<2sHHHHHHHHHHHHHHHHHHH4xHH10xI', data, 0)
    
    result = {
        'e_magic': dos_header[0],       # MZ签名
        'e_lfanew': dos_header[-1],     # PE签名偏移
    }
    
    # 验证MZ签名
    if result['e_magic'] != b'MZ':
        print("[!] 无效的DOS头：缺少MZ签名")
        return None
    
    print(f"[+] DOS头解析成功")
    print(f"    MZ签名: {result['e_magic']}")
    print(f"    PE偏移: 0x{result['e_lfanew']:08X}")
    
    return result
```

### 1.3 PE头

PE头由PE签名、COFF文件头和可选头三部分组成。

**PE签名：** 4字节，固定为"PE\0\0"（0x00004550）

**IMAGE_FILE_HEADER（COFF文件头）结构：**

```c
typedef struct _IMAGE_FILE_HEADER {
    WORD Machine;              // 目标机器类型
    WORD NumberOfSections;     // 节区数量
    DWORD TimeDateStamp;       // 时间戳
    DWORD PointerToSymbolTable;// 符号表偏移（COFF格式，通常为0）
    DWORD NumberOfSymbols;     // 符号数量
    WORD SizeOfOptionalHeader; // 可选头大小
    WORD Characteristics;      // 文件属性标志

```

| 0xAA64 | IMAGE_FILE_MACHINE_ARM64 | ARM64 |

**Characteristics标志位：**

| 位 | 常量 | 说明 |

### 1.4 节表

节表紧跟在可选头之后，每个节表项描述对应节区的属性。

**IMAGE_SECTION_HEADER结构：**

```c
typedef struct _IMAGE_SECTION_HEADER {
    BYTE Name[8];               // 节区名称（最长8字符）
    union {
        DWORD PhysicalAddress;
        DWORD VirtualSize;      // 虚拟大小
    } Misc;
    DWORD VirtualAddress;       // 虚拟地址(RVA)
    DWORD SizeOfRawData;        // 文件中的原始大小
    DWORD PointerToRawData;     // 文件中的偏移
    DWORD PointerToRelocations; // 重定位项偏移
    DWORD PointerToLinenumbers;// 行号信息偏移
    WORD NumberOfRelocations;   // 重定位项数
    WORD NumberOfLinenumbers;   // 行号数
    DWORD Characteristics;      // 节区属性 ★关键
} IMAGE_SECTION_HEADER;
```

**常见节区说明：**

| 节名 | 内容 | 典型属性 |
|------|------|---------|
| .text | 程序代码 | 可读+可执行 |
| .data | 已初始化数据 | 可读+可写 |
| .rdata | 只读数据 | 只读 |
| .bss | 未初始化数据 | 可读+可写 |
| .rsrc | 资源 | 只读 |
| .reloc | 重定位信息 | 只读 |
| .tls | 线程局部存储 | 可读+可写 |
| .gfids | CFG信息 | 只读 |
| .idata | 导入表 | 可读+可写(IAT) |

**节区属性标志位（Characteristics）：**

| 值 | 常量 | 说明 |
|----|------|------|
| 0x00000020 | IMAGE_SCN_CNT_CODE | 包含代码 |
| 0x00000040 | IMAGE_SCN_CNT_INITIALIZED_DATA | 包含已初始化数据 |
| 0x00000080 | IMAGE_SCN_CNT_UNINITIALIZED_DATA | 包含未初始化数据 |
| 0x20000000 | IMAGE_SCN_MEM_EXECUTE | 可执行 |
| 0x40000000 | IMAGE_SCN_MEM_READ | 可读 |
| 0x80000000 | IMAGE_SCN_MEM_WRITE | 可写 |

**RVA与文件偏移转换：**

RVA（Relative Virtual Address）是相对虚拟地址，需要转换为文件偏移才能在文件中定位。

```
文件偏移 = RVA - 节区VirtualAddress + 节区PointerToRawData
```

转换步骤：
1. 找到包含该RVA的节区（VirtualAddress <= RVA < VirtualAddress + VirtualSize）
2. 计算节内偏移：offset_in_section = RVA - Section.VirtualAddress
3. 文件偏移 = Section.PointerToRawData + offset_in_section

```python
def rva_to_offset(rva, sections):
    """将RVA转换为文件偏移"""
    for section in sections:
        section_start = section['VirtualAddress']
        section_end = section_start + section['VirtualSize']
        if section_start <= rva < section_end:
            offset = rva - section_start + section['PointerToRawData']
            return offset
    return None  # RVA不在任何节区内，可能在头部
```

### 1.5 导入表

导入表记录了程序调用的所有外部DLL函数，是逆向分析中定位关键功能的重要依据。

**IMAGE_IMPORT_DESCRIPTOR结构：**

```c
typedef struct _IMAGE_IMPORT_DESCRIPTOR {
    union {
        DWORD Characteristics;
        DWORD OriginalFirstThunk;   // 原始Thunk（INT）的RVA
    };
    DWORD TimeDateStamp;            // 时间戳
    DWORD ForwarderChain;           // 转发链
    DWORD Name;                      // DLL名称字符串的RVA
    DWORD FirstThunk;               // 第一Thunk（IAT）的RVA
} IMAGE_IMPORT_DESCRIPTOR;
```

**导入机制详解：**

1. **INT（Import Name Table）**：OriginalFirstThunk指向的数组，每项是一个RVA，指向IMAGE_IMPORT_BY_NAME结构（包含hint和函数名）
2. **IAT（Import Address Table）**：FirstThunk指向的数组，加载前与INT相同，加载后被写入函数实际地址
3. **绑定导入**：如果IAT在文件中已被绑定（预先填充），可以加速加载

**IMAGE_IMPORT_BY_NAME结构：**

```c
typedef struct _IMAGE_IMPORT_BY_NAME {
    WORD Hint;    // 函数导出序号提示
    BYTE Name[1]; // 函数名（以null结尾的变长字段）
} IMAGE_IMPORT_BY_NAME;
```

**Python解析导入表示例：**

```python
def parse_import_table(data, pe_header, sections):
    """解析PE文件的导入表"""
    # 获取导入表的数据目录
    import_dir_rva = pe_header['DataDirectory'][1]['VirtualAddress']
    import_dir_size = pe_header['DataDirectory'][1]['Size']
    
    if import_dir_rva == 0:
        print("[*] 无导入表")
        return []
    
    # RVA转文件偏移
    offset = rva_to_offset(import_dir_rva, sections)
    if offset is None:
        return []
    
    imports = []
    while True:
        # 读取IMAGE_IMPORT_DESCRIPTOR（20字节）
        if offset + 20 > len(data):
            break
        
        descriptor = struct.unpack_from('<IIIII', data, offset)
        original_thunk = descriptor[0]
        name_rva = descriptor[3]
        first_thunk = descriptor[4]
        
        # 全零表示导入表结束
        if original_thunk == 0 and name_rva == 0:
            break
        
        # 读取DLL名称
        name_offset = rva_to_offset(name_rva, sections)
        if name_offset:
            dll_name = read_cstring(data, name_offset)
        else:
            dll_name = "未知"
        
        # 读取导入函数列表
        thunk = original_thunk if original_thunk else first_thunk
        func_offset = rva_to_offset(thunk, sections)
        
        while func_offset:
            if pe_header['Magic'] == 0x20B:  # PE32+
                thunk_data = struct.unpack_from('<Q', data, func_offset)[0]
                func_offset += 8
            else:  # PE32
                thunk_data = struct.unpack_from('<I', data, func_offset)[0]
                func_offset += 4
            
            if thunk_data == 0:
                break
            
            # 检查是否为序号导入
            if thunk_data & 0x80000000:  # 最高位为1
                ordinal = thunk_data & 0xFFFF
                imports.append({
                    'dll': dll_name,
                    'function': f'序号#{ordinal}',
                    'type': 'ordinal'
                })
            else:  # 名称导入
                func_name_rva = thunk_data
                func_name_offset = rva_to_offset(func_name_rva, sections)
                if func_name_offset:
                    # 跳过2字节的Hint
                    func_name = read_cstring(data, func_name_offset + 2)
                    imports.append({
                        'dll': dll_name,
                        'function': func_name,
                        'type': 'name'
                    })
        
        offset += 20  # 下一个描述符
    
    return imports
```

### 1.6 导出表

导出表用于DLL文件，记录该DLL对外提供的函数。

**IMAGE_EXPORT_DIRECTORY结构：**

```c
typedef struct _IMAGE_EXPORT_DIRECTORY {
    DWORD Characteristics;      // 保留
    DWORD TimeDateStamp;       // 时间戳
    WORD MajorVersion;
    WORD MinorVersion;
    DWORD Name;                 // DLL名称的RVA
    DWORD Base;                 // 导出函数起始序号
    DWORD NumberOfFunctions;    // 导出函数数量
    DWORD NumberOfNames;        // 有名称的导出函数数量
    DWORD AddressOfFunctions;    // 函数地址表(EAT)的RVA
    DWORD AddressOfNames;        // 函数名表(ENT)的RVA
    DWORD AddressOfNameOrdinals; // 序号表的RVA
} IMAGE_EXPORT_DIRECTORY;
```

**导出函数查找流程：**
1. 在ENT（名称表）中搜索函数名，获取索引
2. 用该索引在序号表中获取序号
3. 用序号在EAT（地址表）中获取函数RVA

### 1.7 资源表与重定位表

**资源表**采用树形结构，分为三层：
- 资源类型层（Type）：RT_CURSOR=1, RT_BITMAP=2, RT_DIALOG=5, RT_STRING=6, RT_VERSION=16, RT_MANIFEST=24等
- 资源名称层（Name）
- 资源语言层（Language）

**基址重定位表**记录了需要修正的地址，当模块无法加载到首选基址时使用。重定位项以页（4KB）为单位分组。

## 二、ELF文件格式详解

ELF（Executable and Linkable Format）是Unix/Linux系统的标准可执行文件格式，同样用于目标文件(.o)、共享库(.so)和core dump文件。

### 2.1 ELF整体布局

```
+---------------------------+
|    ELF Header             |  52字节(32位) / 64字节(64位)
+---------------------------+
|    Program Header Table   |  描述段(Segment)信息
+---------------------------+
|    Section .text          |
|    Section .rodata        |  各节区数据
|    Section .data          |
|    Section .bss           |
|    ...                    |
+---------------------------+
|    Section Header Table   |  描述节区(Section)信息
+---------------------------+
```

### 2.2 ELF头

**32位ELF头结构：**

```c
typedef struct {
    unsigned char e_ident[16];  // ELF标识
    Elf32_Half e_type;          // 文件类型
    Elf32_Half e_machine;       // 目标机器
    Elf32_Word e_version;       // ELF版本
    Elf32_Addr e_entry;         // 入口点地址 ★关键
    Elf32_Off e_phoff;          // 程序头表偏移
    Elf32_Off e_shoff;          // 节区头表偏移
    Elf32_Word e_flags;         // 处理器特定标志
    Elf32_Half e_ehsize;        // ELF头大小
    Elf32_Half e_phentsize;     // 程序头表项大小
    Elf32_Half e_phnum;         // 程序头表项数
    Elf32_Half e_shentsize;     // 节区头表项大小
    Elf32_Half e_shnum;         // 节区头表项数
    Elf32_Half e_shstrndx;      // 节区名字符串表索引
} Elf32_Ehdr;
```

**e_ident魔数：**

| 偏移 | 值 | 说明 |
|------|-----|------|
| 0-3 | 0x7F 'E' 'L' 'F' | 魔数标识 |
| 4 | EI_CLASS | 1=32位, 2=64位 |
| 5 | EI_DATA | 1=小端, 2=大端 |
| 6 | EI_VERSION | ELF版本(=1) |
| 7 | EI_OSABI | 操作系统ABI |
| 8-15 | EI_PAD | 保留 |

**e_type文件类型：**

| 值 | 常量 | 说明 |
|----|------|------|
| 0 | ET_NONE | 无类型 |
| 1 | ET_REL | 可重定位文件(.o) |
| 2 | ET_EXEC | 可执行文件 |
| 3 | ET_DYN | 共享库(.so) |
| 4 | ET_CORE | Core dump文件 |

### 2.3 程序头表

程序头描述了加载到内存时的段信息。

```c
typedef struct {
    Elf32_Word p_type;     // 段类型
    Elf32_Off p_offset;   // 文件中的偏移
    Elf32_Addr p_vaddr;   // 虚拟地址
    Elf32_Addr p_paddr;   // 物理地址（通常忽略）
    Elf32_Word p_filesz;  // 文件中的大小
    Elf32_Word p_memsz;   // 内存中的大小
    Elf32_Word p_flags;   // 段标志
    Elf32_Word p_align;   // 对齐
} Elf32_Phdr;
```

**p_type常见值：**

| 值 | 常量 | 说明 |
|----|------|------|
| 0 | PT_NULL | 无效段 |
| 1 | PT_LOAD | 需加载的段 |
| 2 | PT_DYNAMIC | 动态链接信息 |

### 2.5 动态链接机制

**PLT/GOT工作原理：**

1. 程序调用外部函数时，跳转到PLT表项
2. PLT表项跳转到GOT表中存储的地址
3. 首次调用时，GOT表项指向PLT中的resolver代码
4. Resolver调用`_dl_runtime_resolve`解析函数地址
5. 解析后将真实地址写入GOT表
6. 后续调用直接通过GOT跳转到真实地址

```
代码中调用 printf:
    call printf@plt      -> 跳转到 .plt 中 printf 的表项

.plt 中 printf 表项:
    jmp *printf@GOTPLT   -> 第一次: 指向 resolver
                          -> 后续: 指向 printf 真实地址
```

**.dynamic节结构：**

```c
typedef struct {
    Elf32_Sword d_tag;    // 标签类型
    union {
        Elf32_Word d_val; // 值
        Elf32_Addr d_ptr;  // 指针
    } d_un;
} Elf32_Dyn;
```

关键d_tag：DT_NEEDED（依赖的共享库）、DT_PLTGOT（GOT地址）、DT_JMPREL（PLT重定位表）等。

### 3.2 寻址方式

**x86寻址模式通用公式：**

```
[Base + Index*Scale + Displacement]
```

- Base：基址寄存器（EAX/RAX等，可为空）
- Index：变址寄存器（可为空）
- Scale：比例因子（1, 2, 4, 8）
- Displacement：位移量（8位/16位/32位立即数）

**寻址方式示例：**

```asm
mov eax, 0x42            ; 立即数寻址
mov eax, ebx             ; 寄存器寻址
mov eax, [0x403000]      ; 直接寻址（内存地址）
mov eax, [ebx]           ; 寄存器间接寻址
mov eax, [ebx+0x10]     ; 基址+位移
mov eax, [ebx+esi]      ; 基址+变址
mov eax, [ebx+esi*4]    ; 基址+变址*比例
mov eax, [ebx+esi*4+8]  ; 完整寻址公式
lea eax, [ebx+0x10]     ; LEA用于计算地址（不访问内存）
```

### 3.4 函数调用与栈帧

**函数调用过程中栈的变化：**

```asm
; 调用者代码
push arg3          ; 参数3入栈（右到左）
push arg2          ; 参数2入栈
push arg1          ; 参数1入栈
call function      ; 返回地址入栈，跳转到function

; 被调用函数
function:
    push ebp           ; 保存调用者的EBP
    mov ebp, esp       ; 建立新栈帧（EBP指向栈帧基址）
    sub esp, 0x20      ; 分配局部变量空间
    
    ; 函数体...
    ; [ebp+8]  = arg1   访问参数
    ; [ebp+12] = arg2
    ; [ebp-4]  = 局部变量1
    ; [ebp-8]  = 局部变量2
    
    mov esp, ebp       ; 释放局部变量（等同于leave的mov部分）
    pop ebp            ; 恢复调用者的EBP
    ret 12             ; 返回并清理3个参数（cdecl则用ret，调用者清栈）
```

**栈帧布局图：**

```
高地址
+--------------------+
|   参数3            |  [ebp+16]
+--------------------+
|   参数2            |  [ebp+12]
+--------------------+
|   参数1            |  [ebp+8]
+--------------------+
|   返回地址(RET)    |  [ebp+4]
+--------------------+
|   保存的EBP        |  [ebp+0]  ← EBP指向这里
+--------------------+
|   局部变量1        |  [ebp-4]
+--------------------+
|   局部变量2        |  [ebp-8]
+--------------------+
|   ...              |
+--------------------+  ← ESP指向栈顶
低地址
```

**x64调用约定的变化：**

Linux x64 (System V ABI)：
- 参数1-6：RDI, RSI, RDX, RCX, R8, R9
- 参数7+：通过栈传递
- 返回值：RAX
- 栈必须16字节对齐（call前）

Windows x64 (Microsoft ABI)：
- 参数1-4：RCX, RDX, R8, R9
- 参数5+：通过栈传递
- 返回值：RAX
- 调用者必须在栈上为4个寄存器参数预留空间（shadow space）

## 四、ARM指令集基础

### 4.1 ARM架构概述

ARM（Advanced RISC Machines）是一种精简指令集（RISC）架构，广泛应用于移动设备、嵌入式系统和IoT设备。

**ARM架构特点：**
- Load/Store架构：数据处理指令不能直接操作内存，必须先加载到寄存器
- 固定长度指令：ARM模式32位，Thumb模式16/32位
- 大量通用寄存器：R0-R15
- 多数指令可条件执行
- 偏移寻址：支持前后索引和自动更新

**ARM架构版本：**

| 版本 | 说明 | 典型应用 |
|------|------|---------|
| ARMv7-A | 32位ARM | Cortex-A系列（旧手机） |
| ARMv8-A | 64位ARM(AArch64) | Cortex-A53/A72等（现代手机） |
| ARMv7-M | 微控制器 | Cortex-M系列（IoT设备） |
| ARMv6-M | 超低功耗 | Cortex-M0 |

### 4.2 寄存器与异常模式

**ARM寄存器组（ARM模式）：**

| 寄存器 | 名称 | 说明 |
|--------|------|------|
| R0-R7 | 通用寄存器 | 所有模式下可用 |
| R8-R12 | 通用寄存器 | 部分模式下有影子寄存器 |
| R13 | SP | 栈指针（各模式有独立副本） |
| R14 | LR | 链接寄存器（保存返回地址） |
| R15 | PC | 程序计数器 |
| CPSR | | 当前程序状态寄存器 |
| SPSR | | 保存的程序状态寄存器 |

**ARM处理器模式：**

| 模式 | 说明 |
|------|------|
| User | 用户模式（普通程序运行） |
| FIQ | 快速中断模式 |
| IRQ | 普通中断模式 |
| Supervisor | 超级用户模式（系统调用） |
| Abort | 存储访问异常模式 |
| Undefined | 未定义指令异常模式 |
| System | 系统模式（与User共享寄存器） |

### 4.3 ARM指令详解

**数据处理指令：**

```asm
MOV R0, #42        ; 立即数加载
MOV R0, R1         ; 寄存器间传送
ADD R0, R1, R2     ; R0 = R1 + R2
SUB R0, R1, R2     ; R0 = R1 - R2
MUL R0, R1, R2     ; R0 = R1 * R2
AND R0, R1, R2     ; R0 = R1 & R2
ORR R0, R1, R2     ; R0 = R1 | R2
EOR R0, R1, R2     ; R0 = R1 ^ R2 (XOR)
CMP R0, R1         ; 比较 R0 和 R1
```

**条件执行（ARM独特特性）：**

```asm
; 每条指令可附带条件后缀
MOVEQ R0, #1       ; 如果相等(Zero标志)，R0 = 1
MOVNE R0, #0       ; 如果不等，R0 = 0
ADDGT R0, R1, R2   ; 如果大于，R0 = R1 + R2
SUBLE R0, R1, R2   ; 如果小于等于，R0 = R1 - R2
```

**条件后缀表：**

| 后缀 | 含义 | 标志条件 |
|------|------|---------|
| EQ | Equal | Z=1 |
| NE | Not Equal | Z=0 |
| GT | Greater Than (signed) | Z=0, N=V |
| LT | Less Than (signed) | N!=V |
| GE | Greater or Equal | N=V |
| LE | Less or Equal | Z=1 or N!=V |
| HI | Higher (unsigned) | C=1, Z=0 |
| LS | Lower or Same | C=0 or Z=1 |
| CS/HS | Carry Set/Higher or Same | C=1 |
| CC/LO | Carry Clear/Lower | C=0 |

**内存访问指令（Load/Store）：**

```asm
LDR R0, [R1]         ; R0 = *(R1)  从内存加载到R0
STR R0, [R1]         ; *(R1) = R0  将R0存储到内存
LDR R0, [R1, #4]     ; R0 = *(R1+4)  带偏移加载
STR R0, [R1, #4]     ; *(R1+4) = R0  带偏移存储

; 前索引（带更新）
LDR R0, [R1, #4]!    ; R0 = *(R1+4), R1 = R1+4  (!表示更新基址)
STR R0, [R1, #4]!    ; *(R1+4) = R0, R1 = R1+4

; 后索引
LDR R0, [R1], #4     ; R0 = *R1, R1 = R1+4  (先用后更新)
STR R0, [R1], #4     ; *R1 = R0, R1 = R1+4

; 批量加载/存储
LDM R1, {R0, R2, R3}     ; 批量加载
STM R1, {R0, R2, R3}     ; 批量存储
LDMIA R1!, {R0-R3}       ; Increment After, 批量加载后R1自增
STMFD SP!, {R0-R3, LR}   ; Full Descending, 入栈（保存现场）
LDMFD SP!, {R0-R3, PC}   ; Full Descending, 出栈并返回（恢复现场+返回）

; PUSH/POP（等价于STMFD/LDMFD）
PUSH {R0-R3, LR}     ; 入栈
POP {R0-R3, PC}      ; 出栈，PC=R14(LR)实现返回
```

**分支指令：**

```asm
B label             ; 无条件跳转
BL label            ; 带链接跳转（LR=返回地址）
BX R0               ; 间接跳转（切换ARM/Thumb模式）
BLX R0              ; 带链接间接跳转
BEQ label           ; 条件跳转（相等）
BNE label           ; 条件跳转（不等）
```

### 4.4 Thumb指令集

Thumb指令集是ARM的16/32位混合编码指令集，主要用于减小代码体积。

**Thumb特点：**
- 16位指令编码（Thumb-1），部分指令为32位（Thumb-2）
- 寄存器使用受限（通常R0-R7可直接访问）
- 不支持条件执行（Thumb-1中，Thumb-2通过IT指令支持）
- 代码密度更高，适合存储受限场景

**ARM/Thumb模式切换：**
```asm
; 通过BX指令的最低位决定模式
BX R0              ; R0[0]=0: 切换到ARM模式, R0[0]=1: 切换到Thumb模式
; 当跳转地址的最低位为1时，处理器切换到Thumb模式
```

**AArch64（ARMv8 64位）变化：**
- 寄存器扩展为64位：X0-X30, SP, PC
- 32位视图为W0-W30
- 参数传递：X0-X7
- 返回值：X0
- LR为X30，SP独立寄存器

## 五、静态分析方法

### 5.1 反汇编技术

反汇编是将机器码转换为汇编语言的过程。

**线性扫描（Linear Sweep）：**
- 从入口点开始，逐条反汇编指令
- 优点：简单、快速
- 缺点：无法区分数据和代码，遇到数据会产生错误反汇编
- 代表工具：objdump、NDISASM

**递归下降（Recursive Descent）：**
- 从入口点开始，跟随控制流反汇编
- 遇到分支指令时，记录两个目标地址并继续向下分析
- 遇到函数调用时，递归分析被调用函数
- 优点：能正确区分代码和数据
- 缺点：间接跳转目标难以确定
- 代表工具：IDA Pro、Ghidra

**两种算法对比：**

```
代码示例：
    0x00: jmp 0x08      ; 跳过下面的数据
    0x02: 0x90909090    ; 数据（被线性扫描误认为nop）
    0x06: 0xC3          ; 数据（被误认为ret）
    0x08: mov eax, 0    ; 真正的代码

线性扫描结果：
    0x00: jmp 0x08
    0x02: nop; nop; nop; nop  (错误！)
    0x06: ret                  (错误！)
    0x08: mov eax, 0

递归下降结果：
    0x00: jmp 0x08      (跳转到0x08，跳过0x02-0x06)
    0x08: mov eax, 0    (正确识别代码区域)
    (0x02-0x06标记为数据)
```

### 5.2 反编译技术

反编译是将机器码转换为高级语言伪代码的过程。

**反编译流程：**
1. 反汇编：机器码 → 汇编
2. 中间表示：汇编 → 中间语言（IR）
3. 数据流分析：变量识别、类型恢复
4. 控制流分析：结构识别（if/while/for）
5. 代码生成：中间表示 → C伪代码

**反编译器比较：**

| 反编译器 | 平台 | 优势 | 劣势 |
|---------|------|------|------|
| Hex-Rays (IDA) | 全平台 | 最成熟的反编译 | 商业软件，价格高 |
| Ghidra decompiler | 全平台 | 免费开源 | 略逊于Hex-Rays |
| RetDec | 全平台 | 开源 | 维护不活跃 |
| Snowman | Linux | 免费 | 功能有限 |

### 5.3 控制流图分析

控制流图（Control Flow Graph, CFG）是程序控制流的图形表示。

**基本概念：**
- 基本块（Basic Block）：一段连续的、没有内部跳转的指令序列
- 边（Edge）：基本块之间的控制流转移
- 入口点：基本块的第一条指令
- 出口点：基本块的最后一条指令（跳转或返回）

**基本块识别规则：**
1. 每个函数入口是一个新基本块的开始
2. 每个跳转目标是一个新基本块的开始
3. 每条跳转/调用指令的下一条指令是新基本块的开始

**CFG示例：**

```
基本块A:              基本块B:              基本块C:
  cmp eax, 0           add eax, 1           sub eax, 1
  jg B                 ...                  ...
  jmp C
  (条件跳转到B或C)

CFG:
    A
   / \
  B   C
```

### 5.4 数据流分析

数据流分析追踪数据在程序中的流动，用于：
- 变量定义与使用关系
- 常量传播
- 死代码检测
- 类型推断

**定义-使用链（DU Chain）：**
```
定义点: MOV [EBP-4], 42    (定义局部变量)
使用点: MOV EAX, [EBP-4]   (使用局部变量)

DU链: 定义点 → 使用点
```

from ghidra.program.model.data import StringDataType

def find_xor_decryption():
    """查找XOR解密模式"""
    listing = currentProgram.getListing()
    instIter = listing.getInstructions(True)
    
    while instIter.hasNext():
        inst = instIter.next()
        mnemonic = inst.getMnemonicString()
        
        # 查找XOR指令
        if mnemonic == "XOR":
            # 检查是否为异或解密
            refs = getReferencesTo(inst.getAddress())
            if refs:
                print("[+] 可能的XOR解密: %s" % inst.getAddress())

def extract_all_strings():
    """提取所有字符串"""
    dataIterator = currentProgram.getListing().getDefinedData(True)
    strings = []
    
    while dataIterator.hasNext():
        data = dataIterator.next()
        if data.getDataType() instanceof StringDataType:
            addr = data.getAddress()
            value = data.getValue()
            strings.append((addr.toString(), value))
    
    return strings

## 九、实战案例：逆向一个简单的CrackMe

### 9.1 目标程序介绍

**程序源码（模拟）：**

```c

#include <string.h>

int check_serial(const char *serial) {
    int i;
    int sum = 0;
    int len = strlen(serial);
    
    if (len != 8) {
        return 0;  // 序列号必须是8位
    }
    
    // 每个字符ASCII值相加

int check_serial(const char *serial) {
    int i;
    int sum = 0;
    int len = strlen(serial);
    
    if (len != 8)
        return 0;
    
    for (i = 0; i < 8; ++i)
        sum += serial[i];
    
    if (sum == 0x320)  // 800
        return 1;
    
    return 0;
}
```

### 9.3 求解序列号

从分析结果可知：
1. 序列号长度为8
2. 8个字符的ASCII码之和为800
3. 800 / 8 = 100，每个字符平均ASCII值为100

ASCII 100对应的字符是'd'，所以一个可能的解是"dddddddd"。
