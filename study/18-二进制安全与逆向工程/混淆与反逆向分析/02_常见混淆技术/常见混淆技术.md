# 常见混淆技术

### 2.1 控制流混淆

#### 控制流平坦化（Control Flow Flattening）

将函数的所有基本块拆散，放入一个由调度器（dispatcher）控制的 switch-case 循环中。每个基本块执行完毕后，更新一个状态变量，调度器根据该变量选择下一个要执行的基本块。

**原始控制流：**
```
        ┌─────────┐
        │ Block A  │
        └────┬────┘
             │
        ┌────▼────┐
        │ Block B  │
        └────┬────┘
             │
        ┌────▼────┐
        │ Block C  │
        └─────────┘
```

**平坦化后：**
```
         ┌──────────────┐
         │  dispatcher  │ ◄──────────┐
         └──────┬───────┘            │
                │ switch(state)      │
       ┌────────┼────────┐          │
       ▼        ▼        ▼          │
   ┌──────┐ ┌──────┐ ┌──────┐      │
   │Blk A │ │Blk B │ │Blk C │──────┘
   │state=│ │state=│ │state=│ (更新state)
   │  B   │ │  C   │ │ EXIT │
   └──────┘ └──────┘ └──────┘
```

**OLLVM 平坦化伪代码：**
```c
// 原始
void func(int x) {
    if (x > 0)
        positive(x);
    else
        negative(x);
}

// 平坦化后
void func(int x) {
    int state = 1;  // 初始状态
    while (1) {
        switch (state) {
            case 1:  // 初始块
                state = (x > 0) ? 2 : 3;
                break;
            case 2:  // positive分支
                positive(x);
                state = 4;  // 退出
                break;
            case 3:  // negative分支
                negative(x);
                state = 4;
                break;
            case 4:  // 退出
                return;
        }
    }
}
```

#### 虚假控制流（Bogus Control Flow）

在基本块之间插入永远不执行的虚假分支，这些分支通过不透明谓词（见下节）保证不会被执行，但静态分析工具无法确定其真假，从而扩大控制流图。

```c
// 原始
if (x > 0) { do_work(); }

// 虚假控制流插入后
if (x > 0 || opaque_predicate()) {
    do_work();
}
// opaque_predicate() 总是返回false，但静态分析无法确定
```

#### 不透明谓词（Opaque Predicates）

构造一个结果在编译时已知、但静态分析难以推断的布尔表达式。

```c
// 经典不透明谓词：对于任意整数x，x*(x-1)总是偶数
int opaque_predicate(int x) {
    return (x * (x - 1) % 2) == 1;  // 恒为false
}

// 利用全局不变量
static int global_flag = 0x12345678;
if ((global_flag & 0xFFFF) == 0x5678) {
    // 永远执行的真实分支
} else {
    // 永远不执行的虚假分支（含垃圾代码）
}
```

### 2.2 数据混淆

#### 变量编码

将变量存储为编码后的形式，运算时实时解码。

```c
// 原始
int secret = 0xDEADBEEF;

// 编码后
int encoded = 0xDEADBEEF ^ 0x12345678;  // 0xCC99E897
int get_secret() {
    return encoded ^ 0x12345678;  // 运行时解码
}
```

#### 字符串加密

将明文字符串加密存储，运行时在内存中解密使用，避免静态分析直接提取字符串。

```c
// 加密后的字符串（XOR密钥0x37）
unsigned char encrypted[] = {0x53, 0x54, 0x4B, 0x4B, 0x52, 0x00};
//                   明文 "Hello" ^ 0x37

char* decrypt_string(unsigned char* enc, int len) {
    char* buf = malloc(len + 1);
    for (int i = 0; i < len; i++)
        buf[i] = enc[i] ^ 0x37;
    buf[len] = 0;
    return buf;
}
```

#### 常量拆分

将一个大常量拆分为多个小常量的运算结果。

```c
// 原始
int key = 0xDEADBEEF;

// 拆分后
int key = (0xDEAD << 16) | 0xBEEF;  // 或更复杂的拆分
int key = 0xDEAD * 0x10000 + 0xBEEF;
int key = 0x1234 ^ 0xCC990EAB;  // XOR拆分
```

### 2.3 指令混淆

#### 指令替换

用功能等价但更复杂的指令序列替换简单指令。

```asm
; 原始
mov eax, 0

; 曻换方案1：xor
xor eax, eax

; 替换方案2：sub
sub eax, eax

; 替换方案3：and
and eax, 0

; 替换方案4：乘法
imul eax, eax, 0
```

```asm
; 原始：add eax, 5
; 替换：
sub eax, -5
; 或
neg eax
add eax, -5
neg eax
add eax, 10
; 等效但复杂度增加
```

#### 等价指令替换

利用数学等价关系替换运算。

```asm
; 原始：x * 2
shl eax, 1

; 等价替换（利用恒等式 x*2 = x + x）
mov ebx, eax
add eax, ebx

; 或利用 x*2 = (x<<1)
lea eax, [eax*2]
```

#### 垃圾代码插入

在有效指令之间插入不影响程序结果的无效指令。

```asm
; 原始
mov eax, [ecx]
push eax
call func

; 插入垃圾代码后
mov eax, [ecx]
xchg ebx, ebx          ; 垃圾：空操作
push eax
test esp, esp          ; 垃圾：不影响后续
call func
lea edx, [edx]         ; 垃圾：空操作
```

### 2.4 代码虚拟化

#### VMP/Themida虚拟机原理

代码虚拟化将原始的 x86/ARM 指令编译为自定义的虚拟指令集（字节码），运行时由嵌入的虚拟机解释执行。

```
保护流程：
原始代码 → [VMP编译器] → 虚拟字节码 + VM解释器
                                  ↓ (运行时)
                          VM解释器执行字节码

运行时内存布局：
┌──────────────────┐
│ 原始PE文件壳      │
├──────────────────┤
│ VM解释器（dispatcher）│
├──────────────────┤
│ 虚拟字节码区      │
├──────────────────┤
│ 虚拟栈/虚拟寄存器  │
└──────────────────┘
```

**VM解释器核心循环（伪代码）：**
```c
void vm_run(uint8_t* bytecode, VM_Context* ctx) {
    while (1) {
        uint8_t opcode = *ctx->vip++;   // 读取虚拟指令
        switch (opcode) {
            case VM_ADD:  ctx->vreg[ctx->bytecode[ctx->vip++]] += ctx->vreg[ctx->bytecode[ctx->vip++]]; break;
            case VM_MOV:  /* ... */ break;
            case VM_JMP:   ctx->vip = bytecode + ctx->vreg[...]; break;
            case VM_RET:   return;
            // ...数十到上百条虚拟指令
        }
    }
}
```

#### 虚拟指令集设计

不同保护工具设计不同的虚拟指令集，且每次保护可能随机化指令编码：

```
VMP特点：
  - 指令集庞大（100+条虚拟指令）
  - 每次保护指令编码可能不同
  - 解释器使用间接跳转（jmp eax）
  - 多层嵌套虚拟化

Themida特点：
  - 结合反调试、反Dump
  - 部分代码虚拟化（可选择保护函数）
  - 运行时解密虚拟字节码
```

#### 调度器分析

调度器（dispatcher）是 VM 的核心，分析调度器是还原虚拟化代码的关键。

```asm
; 典型VMP调度器结构（简化）
vmp_entry:
    push ebp
    mov ebp, esp
    call vmp_init          ; 初始化VM上下文
    jmp dispatcher

dispatcher:
    movzx eax, byte ptr [esi]  ; esi = VIP（虚拟指令指针）
    inc esi
    jmp [jmptable + eax*4]     ; 间接跳转到handler

jmptable:
    dd handler_0
    dd handler_1
    dd handler_2
    ; ...
```
