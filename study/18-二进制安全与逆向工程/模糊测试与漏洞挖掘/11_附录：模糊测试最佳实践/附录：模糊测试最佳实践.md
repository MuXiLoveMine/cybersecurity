# 附录：模糊测试最佳实践

### 选择目标

| 目标类型 | 适合度 | 推荐工具 | 说明 |
|---------|--------|---------|------|
| 文件解析器 | 高 | AFL, libFuzzer | 输入格式明确，易构造 |
| 网络服务 | 中 | Boofuzz, AFL | 需要处理状态机 |
| 编译器 | 中 | libFuzzer | 输入为源码，需要语法感知 |
| 内核驱动 | 低 | syzkaller | 需要特殊环境 |
| 加密库 | 低 | libFuzzer | 输入格式严格 |
| 浏览器引擎 | 高 | libFuzzer, Domato | 输入格式复杂 |

### 优化模糊测试效率

1. **最小化语料库**：减少无效变异，提高覆盖率
2. **使用持久化模式**：减少进程创建开销
3. **合理设置超时**：避免慢路径拖累整体速度
4. **多维度模糊**：ASan + MSan + UBSan并行
5. **字典引导**：提供格式关键字
6. **分布式模糊**：利用多台机器
7. **种子调度优化**：优先探索有价值的种子

### 模糊测试局限性

- 难以触发需要特定状态序列的漏洞
- 对加密/签名输入效果差
- 无法发现逻辑漏洞
- 需要合理的harness设计
- 覆盖率不完全等于漏洞率

## 🛠️ 补充：实战拓展 — Fuzzing 工具命令速查表

### 一、AFL++ 常用命令速查

**1. 编译插桩**

```bash
# 使用 afl-clang-fast 编译（推荐，速度最快）
afl-clang-fast -o target target.c
afl-clang-fast++ -o target target.cpp

# 使用 gcc 前端
afl-gcc -o target target.c
afl-g++ -o target target.cpp

# 启用 LTO（链接时优化，更精确的覆盖）
AFL_LLVM_LTO=1 afl-clang-fast -o target target.c

# 启用 cmplog（比较记录，帮助绕过比较）
afl-clang-fast -o target target.c
# 运行时配合 -c 参数

# 地址消毒（ASAN）编译
AFL_USE_ASAN=1 afl-clang-fast -fsanitize=address -o target_asan target.c

# 内存消毒（MSAN）
AFL_USE_MSAN=1 afl-clang-fast -fsanitize=memory -o target_msan target.c

# 未定义行为消毒（UBSan）
AFL_USE_UBSAN=1 afl-clang-fast -fsanitize=undefined -o target_ubsan target.c

# CMPLOG 插桩（记录比较操作）
AFL_LLVM_CMPLOG=1 afl-clang-fast -o target_cmplog target.c

# 仅对部分代码插桩（黑名单模式）
AFL_LLVM_DOCUMENT_IDS=1 afl-clang-fast ...  # 生成插桩ID列表
# 编辑列表，重新编译时跳过某些函数
```

**2. 运行 Fuzzing**

```bash
# 基本运行
afl-fuzz -i input_dir -o output_dir ./target @@

# 指定内存限制（默认 200MB）
afl-fuzz -i in -o out -m 500 ./target @@
afl-fuzz -i in -o out -m none ./target @@   # 不限制内存（ASAN需要）

# 指定超时时间（默认 1000ms）
afl-fuzz -i in -o out -t 2000 ./target @@   # 2秒超时
afl-fuzz -i in -o out -t 500+ ./target @@   # 500ms + 自动调整

# 指定Fuzzer名称（多实例时用）
afl-fuzz -i in -o out -M fuzzer01 ./target @@  # 主节点
afl-fuzz -i in -o out -S fuzzer02 ./target @@  # 从节点

# 字典引导
afl-fuzz -i in -o out -x dict.txt ./target @@

# CMPLOG 模式（配合插桩版本）
afl-fuzz -i in -o out -c ./target_cmplog ./target @@

# 从特定文件开始
afl-fuzz -i in -o out -f test_input ./target @@

# 仅确定性模式（慢但深入）
afl-fuzz -i in -o out -d ./target @@   # 跳过确定性步骤（更快）

# 并行Fuzzing（多进程）
# 终端1（主节点）
afl-fuzz -i in -o out_sync -M main ./target @@
# 终端2-n（从节点）
afl-fuzz -i in -o out_sync -S slave1 ./target @@
afl-fuzz -i in -o out_sync -S slave2 ./target @@

# 查看所有实例状态
afl-whatsup output_dir
afl-whatsup -s output_dir   # 汇总统计
```

**3. 结果分析**

```bash
# 查看崩溃样本
ls output_dir/default/crashes/
ls output_dir/default/hangs/

# 统计信息
cat output_dir/default/fuzzer_stats

# 用 GDB 调试崩溃
gdb -batch -ex "run < output_dir/default/crashes/id:000000*" -ex "bt" ./target

# 最小化崩溃用例
afl-tmin -i crash_input -o minimized_crash ./target @@
afl-tmin -i crash_input -o crash_min -x ./target @@

# 最小化语料库
afl-cmin -i input_dir -o minimized_corpus ./target @@

# 显示崩溃的独特性
afl-collect output_dir/crashes/ unique_crashes/ -- ./target @@
```

**4. 语料库操作**

```bash
# 生成初始语料库
# 手动创建: in/ 目录下放几个最小有效输入

# 语料库最小化（去除冗余样本）
afl-cmin -i in -o out_min ./target @@

# 样本大小最小化（每个样本尽可能小）
afl-tmin -i sample -o sample_min ./target @@

# 显示语料库统计
ls -la input_dir/ | wc -l
du -sh input_dir/

# 从现有样本创建字典
afl-analyze -i sample -o dict.txt
```

**5. 实用环境变量**

```bash
# 加快Fuzzing速度
export AFL_SKIP_CPUFREQ=1      # 跳过CPU频率检查
export AFL_NO_AFFINITY=1       # 不绑定CPU核心
export AFL_I_DONT_CARE_ABOUT_MISSING_CRASHES=1  # 忽略崩溃不唯一警告

# 调试
export AFL_DEBUG=1             # 调试模式
export AFL_DEBUG_CHILD=1       # 子进程调试输出

# 自定义行为
export AFL_HANG_TMOUT=1000     # hang超时（ms）
export AFL_FORKSRV_INIT_TMOUT=1000  # fork server初始化超时
export AFL_CMPLOG_ONLY_NEW=1   # cmplog只对新路径启用
```

### 二、libFuzzer 常用命令速查

**1. 编译**

```bash
# 基本编译（clang）
clang -fsanitize=fuzzer -o fuzz_target fuzz_target.c

# C++
clang++ -fsanitize=fuzzer -o fuzz_target fuzz_target.cpp

# 配合 ASAN（最常用，检测内存错误）
clang -fsanitize=fuzzer,address -o fuzz_asan fuzz_target.c

# 配合 UBSAN（检测未定义行为）
clang -fsanitize=fuzzer,undefined -o fuzz_ubsan fuzz_target.c

# 配合 MSAN（检测未初始化内存）
clang -fsanitize=fuzzer,memory -o fuzz_msan fuzz_target.c

# 多sanitizer组合
clang -fsanitize=fuzzer,address,undefined -o fuzz_asan_ubsan fuzz_target.c

# 覆盖率追踪
clang -fsanitize=fuzzer -fprofile-instr-generate -fcoverage-mapping -o fuzz_cov fuzz_target.c

# Release模式（更快）
clang -fsanitize=fuzzer -O2 -o fuzz_target fuzz_target.c

# 调试符号
clang -fsanitize=fuzzer -g -o fuzz_target fuzz_target.c
```

**2. 运行**

```bash
# 基本运行
./fuzz_target

# 指定语料库目录
./fuzz_target corpus_dir/

# 多个语料库目录
./fuzz_target corpus1/ corpus2/ seeds/

# 最大运行时间
./fuzz_target -max_total_time=3600 corpus/   # 运行1小时

# 最大内存使用
./fuzz_target -rss_limit_mb=2048 corpus/     # 2GB内存限制

# 超时设置
./fuzz_target -timeout=5 corpus/              # 单个输入5秒超时
./fuzz_target -timeout=30 corpus/             # 30秒超时

# 并行运行（多worker）
./fuzz_target -workers=8 -jobs=32 corpus/    # 8个并行worker，32个job

# 字典
./fuzz_target -dict=dict.txt corpus/

# 仅运行单个输入（验证崩溃）
./fuzz_target crash_input.bin

# 输出详细信息
./fuzz_target -print_final_stats=1 corpus/
./fuzz_target -print_coverage=1 corpus/
./fuzz_target -print_pcs=1 corpus/            # 打印所有覆盖的PC

#  artifact 前缀（崩溃文件命名）
./fuzz_target -artifact_prefix=./crashes/ corpus/

# 忽略超时
./fuzz_target -ignore_ooms=1 corpus/
./fuzz_target -ignore_timeouts=1 corpus/
```

**3. 覆盖率分析**

```bash
# 编译时启用覆盖率
clang -fsanitize=fuzzer -fprofile-instr-generate -fcoverage-mapping -o fuzz fuzz.c

# 运行并生成覆盖率数据
LLVM_PROFILE_FILE="fuzz.profraw" ./fuzz -runs=0 corpus/

# 处理覆盖率数据
llvm-profdata merge -sparse fuzz.profraw -o fuzz.profdata

# 生成覆盖率报告
llvm-cov show ./fuzz -instr-profile=fuzz.profdata
llvm-cov report ./fuzz -instr-profile=fuzz.profdata

# 生成HTML覆盖率报告
llvm-cov show ./fuzz -instr-profile=fuzz.profdata -format=html -output-dir=coverage_html/

# 查看特定文件的覆盖率
llvm-cov show ./fuzz -instr-profile=fuzz.profdata -name-regex='target_func'
```

**4. libFuzzer Harness 模板**

```c
// fuzz_target.c - libFuzzer harness 模板
#include <stdint.h>
#include <stddef.h>
#include <string.h>

// 目标函数声明
int target_function(const uint8_t *data, size_t size);

// libFuzzer 入口函数
int LLVMFuzzerTestOneInput(const uint8_t *data, size_t size) {
    // 1. 基本过滤（可选，提高效率）
    if (size < 4) return 0;
    
    // 2. 检查魔数（可选）
    if (data[0] != 'M' || data[1] != 'A') return 0;
    
    // 3. 调用目标函数
    target_function(data, size);
    
    // 4. 返回0表示正常
    return 0;
}

// === 进阶：自定义初始化 ===
__attribute__((constructor))
void fuzz_init() {
    // 只执行一次的初始化代码
    // 如加载配置、初始化数据结构等
}

// === 进阶：自定义内存清理 ===
// 对于有全局状态的目标，需要在每次输入后重置状态
static void reset_state() {
    // 清理全局状态
}

int LLVMFuzzerTestOneInput(const uint8_t *data, size_t size) {
    reset_state();
    target_function(data, size);
    return 0;
}
```

### 三、WinAFL 常用命令速查

```bash

session = Session(
    target=Target(
        connection=SocketConnection("127.0.0.1", 9999, proto='tcp')
    ),
    sleep_time=0.1,
)

# 定义协议格式
s_initialize("fuzz_protocol")
if s_block_start("header"):
    s_word(0xdeadbeef, name="magic")
    s_byte(0x01, name="version")
    s_byte(0x00, name="type")
    s_size("body", length=2, name="length")
s_block_end("header")

if s_block_start("body"):
    s_string("hello", name="payload")
    s_bytes(b"\x00" * 4, name="padding")
s_block_end("body")

# 开始Fuzzing
session.connect(s_get("fuzz_protocol"))
session.fuzz()
```

### 六、Fuzzing 实战技巧

**1. 初始语料库优化**

```
语料库质量原则：
1. 小而多样 - 优先选最小但覆盖不同路径的样本
2. 格式正确 - 初始样本应该是合法有效的输入
3. 边界情况 - 包含空输入、最大输入、特殊值等
4. 代码覆盖 - 尽量覆盖更多代码分支

优化步骤：
1. 收集多种来源的样本（单元测试、示例文件、fuzz历史产出）
2. 使用 afl-cmin 最小化（去冗余）
3. 使用 afl-tmin 逐个最小化（减小体积）
4. 检查初始覆盖率，补充缺失路径的样本
```

**2. 崩溃分析与Triage**

```bash
# 步骤1: 确认崩溃可复现
./target < crash_input

# 步骤2: 获取调用栈
gdb -batch -ex "r < crash_input" -ex "bt" -ex "info registers" ./target

# 步骤3: ASAN 详细信息
ASAN_OPTIONS=detect_leaks=0:symbolize=1 ./target_asan < crash_input

# 步骤4: 定位崩溃原因
# - 读越界: heap-buffer-overflow on address READ
# - 写越界: heap-buffer-overflow on address WRITE
# - 释放后使用: heap-use-after-free
# - 栈溢出: stack-buffer-overflow
# - 双重释放: attempting double-free
# - 内存泄漏: detected memory leaks

# 步骤5: 评估严重程度
# 可利用性: 能否控制溢出内容 / 能否控制执行流
# 影响范围: 远程 / 本地 / 需要认证
```

**3. Fuzzing 效率优化**

```
1. 选择正确的Harness
   - 尽量减少初始化开销
   - 使用持久化模式 (persistent mode)
   - 跳过不必要的初始化代码

2. 优化编译
   - 使用 afl-clang-fast（比 afl-gcc 快很多）
   - O2 优化级别
   - 只插桩目标模块

3. 语料库维护
   - 定期运行 afl-cmin 精简语料库
   - 合并不同fuzzer实例的语料库
   - 添加新发现的有趣输入

4. 并行Fuzzing
   - 多实例并行（-M / -S）
   - 不同sanitizer并行（ASAN/MSAN/UBSan各跑一份）
   - 不同字典/策略并行

5. 资源利用
   - 绑定CPU核心（避免上下文切换）
   - 使用 tmpfs 放输出目录（减少IO）
   - 合理设置超时和内存限制
```
