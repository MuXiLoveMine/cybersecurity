# 实战场景

### 6.1 Crackme分析流程

一个典型 Crackme 的逆向流程：

```
1. 初步运行：观察程序行为（输入→输出）
2. 静态分析：IDA打开，定位字符串比较/校验函数
3. 动态调试：
   - 在输入函数（GetDlgItemText/scanf）设断点
   - 输入测试数据后断下
   - 跟踪数据流向（Step Into/Over）
   - 在比较指令（cmp/test/strcmp）处断下
   - 观察比较的两个值
4. 算法分析：跟踪校验算法，理解正确值的生成方式
5. 验证：输入正确值，确认程序输出"成功"
```

x64dbg 中定位关键比较：
```
# 方法1：字符串引用
  1. 右键反汇编窗口 → Search for → All references
  2. 搜索 "Success"/"Wrong" 等字符串
  3. 在引用处设断点，查看附近的cmp指令

# 方法2：API断点
  bp GetWindowTextA          # 文本输入API
  bp lstrcmpA                 # 字符串比较API
  bp memcmp                   # 内存比较API
```

### 6.2 恶意代码动态分析

使用沙箱环境观察恶意代码行为：

```
# strace跟踪文件操作
strace -f -e trace=open,openat,write,unlink ./malware

# ltrace跟踪库函数
ltrace -f -e 'create_process+URLDownload*+socket*' ./malware

# 网络流量捕获（同时在另一终端运行）
tcpdump -i any -w capture.pcap

# GDB跟踪解密
gdb ./malware
(gdb) b malloc              # 跟踪内存分配（解密缓冲区）
(gdb) b write               # 跟踪输出（写入解密后数据）
(gdb) run
```

### 6.3 漏洞调试与利用验证

```
# GDB调试栈溢出
gdb ./vuln
(gdb) pattern_create 200      # pwndbg命令
(gdb) run
# 程序崩溃
(gdb) pattern_offset $rsp     # 查找偏移
# 返回地址偏移 = N

# 验证payload
(gdb) run $(python -c 'print("A"*N + "\x40\x40\x40\x40")')
(gdb) x/4wx $rsp             # 确认返回地址被覆盖
```

### 6.4 协议逆向

通过动态跟踪网络通信函数，逆向私有协议。

```
# x64dbg 跟踪send/recv
bp send                      # 发送数据时断下
bp recv                      # 接收数据时断下
# 断下后查看[esp+4]=socket, [esp+8]=buf, [esp+12]=len
# 查看buf内存：d [esp+8]

# 自动化日志脚本
bp send
bpcnd send, "1"              # 每次都断
loop:
    log "send: socket={?,[esp+4]}, len={?,[esp+12]}"
    d [esp+8]                # dump发送的数据
    run
    cmp eip, send
    je loop
```
