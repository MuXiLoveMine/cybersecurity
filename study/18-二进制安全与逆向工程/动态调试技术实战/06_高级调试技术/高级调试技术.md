# 高级调试技术

### 5.1 反调试检测与绕过

恶意软件和保护壳常使用反调试技术检测调试器存在，检测到后改变行为或退出。

**IsDebuggerPresent / PEB 检测**：

```c
// 方法1：直接调用API
if (IsDebuggerPresent()) ExitProcess(0);

// 方法2：直接读取PEB的BeingDebugged标志
BOOL detected = FALSE;
__asm {
    mov eax, fs:[0x30]       // TEB->ProcessEnvironmentBlock
    movzx eax, byte ptr [eax+2] // PEB->BeingDebugged
    mov detected, eax
}
if (detected) ExitProcess(0);

// 方法3：检查NtGlobalFlag（x86偏移0x68, x64偏移0xBC）
DWORD NtGlobalFlag = *(DWORD*)(__readgsqword(0x60) + 0xBC);
if (NtGlobalFlag & 0x70) ExitProcess(0); // FLG_HEAP_ENABLE_TAIL_CHECK|FREE_CHECK|VALIDATE
```

绕过方法：在 x64dbg 中使用 ScyllaHide 插件，自动 patch PEB 标志位；或手动修改：

```
// x64dbg中手动清除BeingDebugged
1. 命令行: SetPEBBeingDebugged 0
2. 或在内存窗口跳转到PEB地址，将偏移2处改为0
3. 同样清除NtGlobalFlag的相关标志位
```

**硬件断点检测**：检查 DR0-DR7 寄存器是否被设置。

```c
CONTEXT ctx;
ctx.ContextFlags = CONTEXT_DEBUG_REGISTERS;
GetThreadContext(GetCurrentThread(), &ctx);
if (ctx.Dr0 || ctx.Dr1 || ctx.Dr2 || ctx.Dr3)
    ExitProcess(0); // 检测到硬件断点
```

绕过：在 x64dbg 中用 ScyllaHide 清除 DR 寄存器，或改用内存断点。

**时间检测**：利用 `RDTSC` 指令测量代码执行时间，调试时单步会导致时间异常。

```c
DWORD64 t1, t2;
t1 = __rdtsc();
// ... 关键代码 ...
t2 = __rdtsc();
if (t2 - t1 > 0x10000) // 阈值
    ExitProcess(0); // 检测到调试
```

绕过：在 x64dbg 中对 `RDTSC` 设断点，修改返回的时间值；或使用 ScyllaHide 的时间检测绕过选项。

### 5.2 JIT调试

**.NET JIT调试**：.NET 程序编译为 MSIL 中间语言，运行时由 CLR JIT 编译为本地代码。使用 dnSpy 或 ILSpy 进行调试：

```
1. dnSpy → File → Open（加载.exe/.dll）
2. Debug → Start Executable
3. 在IL代码上设断点
4. 调试时查看变量和调用栈
```

**Java 调试**：通过 JDWP（Java Debug Wire Protocol）调试。

```bash
java -agentlib:jdwp=transport=dt_socket,server=y,address=8000 -jar target.jar
# IDE（如IntelliJ）连接到 localhost:8000
```

### 5.3 虚拟机内调试

在虚拟机中运行目标程序，通过虚拟化层提供的调试接口进行调试。

```
# VMware + GDB stub
1. .vmx配置文件添加:
   debugStub.listen.guest64 = "TRUE"
   debugStub.port.guest64 = "8864"
2. 主机GDB连接:
   (gdb) target remote localhost:8864
3. 此时主机GDB可以调试虚拟机内核态
```

### 5.4 多线程调试

```
# GDB多线程调试
info threads                       # 列出所有线程
thread 3                          # 切换到线程3
thread apply all bt                # 所有线程的调用栈
set scheduler-locking on          # 锁定其他线程（仅调试当前线程）
set scheduler-locking step         # 单步时锁定
break foo thread 3               # 仅在线程3的foo函数断下
```

```
# x64dbg多线程调试
1. Threads标签页列出所有线程
2. 双击线程可切换上下文
3. 命令: setthreadpriority / suspendthread / resumethread
4. 每个线程有独立的断点上下文
```

### 5.5 异常处理跟踪

```
SEH（结构化异常处理）跟踪：
  - x64dbg: Options → Exceptions → 添加自定义异常处理范围
  - 设置"异常时忽略"可让异常传递到程序自己的SEH
  - 设置"异常时暂停"可在异常发生时断下

VEH（向量异常处理）：
  - 通过AddVectoredExceptionHandler注册
  - 调试器先于VEH收到异常
  - 跟踪VEH链: bp AddVectoredExceptionHandler
```

### 5.6 ASLR与PIE调试

```
# Linux PIE程序调试（每次基址不同）
# GDB中自动计算偏移：
b *main+42          # 基于main函数偏移设断点（自动计算）

# 在脚本中获取基址：
base = int(gdb.execute("info proc mappings", to_string=True)
           .split("r-x")[0].strip().split()[-1], 16)

# Windows ASLR: 每次加载基址不同
# x64dbg命令: efe or dbh 可查看基址
# 或使用label/符号，x64dbg自动重定位断点
```
