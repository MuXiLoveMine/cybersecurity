# 小结

动态调试是逆向工程不可或缺的能力。掌握不同平台调试器（x64dbg/WinDbg/GDB/IDA）的使用、理解断点机制和调试事件循环、熟悉反调试技术及其绕过方法，是成为一名合格逆向工程师的基础。实践中应将静态分析与动态调试结合，利用脚本和自动化工具提高分析效率。在实际分析中，建议始终在隔离的虚拟机环境中操作，并遵守相关法律法规。

**2. 运行控制**

```

### 四、x64dbg 调试技巧进阶

**1. 条件断点与日志断点**

```
# 条件断点
# 右键断点 -> Edit breakpoint -> Condition
[eax] == 0x41414141       ; eax指向的值等于0x41414141
strstr(addr, "flag") != 0 ; 字符串中包含"flag"
$breakpointcounter == 100  ; 第100次触发时断下

# 日志断点（不中断，只记录）
# 右键断点 -> 设置为"Log"断点
# Log Text: hit at {eip}, eax={eax}
# 断点触发时打印日志但不暂停

# 命令断点
# 触发断点时自动执行命令，然后自动继续
# 设置"Command"文本框，例如:
# "eax={eax}; msg" 打印eax并弹框
```

**2. 脚本（Script）自动化**

```
# x64dbg 脚本示例 - 跟踪函数调用
# 保存为 .txt 文件，File -> Script -> Open

// 设置变量
var count
mov count, 0

// 在目标函数设断点
bp 0x401000

// 定义断点命令
// 每次触发时计数+1，打印参数，然后继续
// 在Breakpoints窗口右键Edit -> 设置Command:
// "inc count; log 'call #{count}, arg1={arg1}'; g"

// 脚本循环示例
loop_start:
    // 单步
    step
    // 检查是否到达目标
    cmp eip, 0x402000
    je loop_end
    // 记录指令
    log "{eip}: {disasm(eip)}"
    jmp loop_start
loop_end:
    msg "Reached target!"
    ret
```

### 五、反调试技术与绕过速查

**1. 常见反调试技术**

| 技术 | 检测方法 | 绕过方法 |
|------|---------|---------|

| NtQueryInformationProcess | `ProcessDebugFlags` (0x1f) | Hook / 返回0 |
| NtQueryInformationProcess | `ProcessDebugObjectHandle` (0x1e) | Hook / 返回0 |
| CheckRemoteDebuggerPresent | 调用API检测 | Hook API |

| GetTickCount 时间差 | 单步导致时间差大 | 改系统时间 / Hook |
| RDTSC 指令 | 读取时间戳计数器 | 模拟 / Hook |
| INT 2D / ICE | 利用调试器异常处理差异 | 调整异常设置 |
| 父进程检测 | 检查父进程是否为调试器 | 伪造父进程 |

### 六、动态调试实战工作流

```
CTF PWN 题调试工作流：
1. 检查保护机制 → checksec
2. 运行程序观察行为 → 输入测试数据

6. 构造payload → 逐步调试验证每一步
7. 本地调试通过 → 远程测试

逆向 CrackMe 调试工作流：
1. 查壳 → DIE / PEiD / upx -l
2. 运行程序 → 观察输入输出行为
3. 字符串搜索 → 定位关键判断逻辑
4. 交叉引用 → 找到校验函数
5. 动态验证 → 在判断处下断点看比较值
6. 算法还原 → 单步跟踪理解逻辑
7. 写注册机 → 逆算法

恶意代码动态分析工作流：
1. 快照备份 → 虚拟机快照
