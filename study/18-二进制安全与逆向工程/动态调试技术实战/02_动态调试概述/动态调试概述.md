# 动态调试概述

### 1.1 静态分析 vs 动态分析

逆向分析通常分为静态分析和动态分析两条路径，两者互补使用才能高效完成逆向任务。

| 维度 | 静态分析 | 动态分析 |
|------|----------|----------|
| 执行状态 | 不运行目标程序 | 实际运行目标程序 |
| 信息来源 | 反汇编/反编译代码 | 运行时寄存器、内存、I/O |
| 优势 | 全局视野、控制流完整 | 真实值、执行路径、解密数据 |
| 劣势 | 难以应对混淆/加密/自修改代码 | 只能看到执行到的路径 |
| 典型工具 | IDA Pro、Ghidra、radare2 | x64dbg、WinDbg、GDB |
| 适用场景 | 理解程序结构、定位关键函数 | 验证推测、提取解密数据、跟踪算法 |

实践中的典型流程：先用静态分析定位关键函数和数据结构，再切换到动态调试验证运行时行为，两者交替迭代。

### 1.2 动态调试在逆向中的角色

动态调试在逆向工程中承担以下核心角色：

- **验证推测**：静态分析推断出的算法逻辑，通过运行时寄存器和内存值加以确认。
- **数据解密**：对运行时解密的字符串、配置或代码，在解密完成后从内存中提取。
- **算法追踪**：跟踪加密/校验算法的每一步运算，还原算法细节。
- **行为分析**：观察程序的外部行为（文件、注册表、网络、进程操作），用于恶意代码分析。
- **漏洞验证**：在漏洞利用开发中，调试 payload 的执行过程，定位偏移和覆盖效果。

### 1.3 调试器分类

调试器按所处的运行级别可分为两类：

**用户态调试器**：运行在 Ring 3，通过操作系统提供的调试接口（Windows 的 Debug API、Linux 的 ptrace）调试目标进程。典型代表：x64dbg、OllyDbg、GDB。

**内核态调试器**：运行在 Ring 0，直接控制 CPU 和物理内存，可调试操作系统内核和驱动程序。典型代表：WinDbg（内核模式）、SoftICE（已淘汰）、windbgkd。

```
Ring 0  ┌─────────────────────────────────┐
        │  内核调试器 WinDbg (kernel mode) │  可调试OS内核、驱动
Ring 3  ├─────────────────────────────────┤
        │  用户态调试器 x64dbg / GDB       │  调试普通应用程序
        └─────────────────────────────────┘
```

用户态调试器依赖操作系统的调试接口：

```c
// Windows 调试API核心
DebugActiveProcess()    // 附加到进程
WaitForDebugEvent()     // 等待调试事件
ContinueDebugEvent()    // 继续执行
ReadProcessMemory()     // 读内存
WriteProcessMemory()    // 写内存
```

```c
// Linux ptrace 接口
ptrace(PTRACE_ATTACH, pid, 0, 0);       // 附加
ptrace(PTRACE_CONT, pid, 0, 0);         // 继续
ptrace(PTRACE_SINGLESTEP, pid, 0, 0);   // 单步
ptrace(PTRACE_PEEKDATA, pid, addr, 0);   // 读内存
```
