# 动态分析方法

### 3.1 动态分析概述

**什么是动态分析**

动态分析是指在受控环境中运行恶意代码，观察其行为的分析方法。与静态分析相比，动态分析可以更直观地了解恶意代码的实际行为，但需要安全的分析环境。

**动态分析的优缺点**

| 优点 | 缺点 |
|------|------|
| 可以观察恶意代码的实际行为 | 需要安全的隔离环境 |
| 可以分析加壳/混淆的代码 | 恶意代码可能检测分析环境 |
| 更容易理解恶意代码的功能 | 可能触发恶意行为造成破坏 |
| 可以获取网络行为特征 | 某些行为可能需要特定条件触发 |
| 可以提取运行时解密的代码 | 分析时间较长 |

**分析环境搭建**

```
分析环境基本要求：
1. 隔离网络：物理隔离或虚拟网络隔离
2. 虚拟机：VMware、VirtualBox、Hyper-V 等
3. 快照功能：分析前保存快照，分析后恢复
4. 分析工具：各种监控和分析工具

推荐分析环境：
- Windows XP/7/10/11 虚拟机
- REMnux：Linux 恶意软件分析发行版
- Flare VM：Windows 恶意软件分析环境
- Cuckoo Sandbox：自动化沙箱
- ANY.RUN：交互式在线沙箱
- Joe Sandbox：高级沙箱分析
```

**动态分析安全注意事项**

1. 确保分析环境与生产网络隔离
2. 使用虚拟机并保存干净快照
3. 不要在物理机上直接运行恶意代码
4. 分析后立即恢复快照
5. 重要数据做好备份
6. 遵守法律法规，仅分析授权的样本

### 3.2 进程行为监控

**进程监控工具**

**Process Monitor (ProcMon)**

```
Process Monitor 是 Sysinternals 工具集的核心工具之一，
可以实时监控进程的文件系统、注册表、网络和进程/线程操作。

主要功能：
- 实时监控文件系统操作
- 实时监控注册表操作
- 实时监控网络操作
- 实时监控进程/线程操作
- 强大的过滤功能
- 启动时监控（boot logging）

常用过滤条件：
- Process Name → 只监控特定进程
- Path → 只监控特定路径
- Operation → 只监控特定操作类型
- Result → 只看成功/失败的操作
- PID → 只监控特定进程 ID

分析技巧：
1. 先设置过滤再运行恶意程序，减少噪音
2. 关注 WriteFile、CreateFile 等写入操作
3. 关注 RegSetValue 等注册表写入操作
4. 关注 CreateProcess 等进程创建操作
5. 使用 Ctrl+F 搜索特定关键词
```

**Process Explorer**

```
Process Explorer 是增强版的任务管理器，可以查看进程的详细信息。

主要功能：
- 进程树视图
- 查看进程加载的 DLL
- 查看进程打开的句柄
- 验证进程签名
- 查看进程的网络连接
- 替换任务管理器

分析用途：
1. 发现隐藏或可疑的进程
2. 检查进程注入（异常 DLL、异常路径）
3. 查看父子进程关系
4. 验证数字签名
5. 查看进程的 TCP/UDP 连接
```

**进程创建监控**

```
监控进程创建的方法：

1. Process Monitor 过滤
   Operation = Process Create

2. Sysmon（系统监控）
   事件 ID 1：进程创建
   事件 ID 5：进程终止

3. 安全审计
   事件 ID 4688：进程创建
   需要启用审核策略 + 命令行审计

4. WMI 事件订阅
   监控 __InstanceCreationEvent of Win32_Process

关键分析点：
- 父进程和子进程关系是否正常
- 进程路径是否在临时目录或用户目录
- 命令行参数是否可疑
- 进程是否有有效签名
- 是否创建了大量子进程
```

### 3.3 文件系统监控

**文件监控方法**

```
1. Process Monitor
   过滤文件操作：Operation 包含 File
   关注：CreateFile、WriteFile、DeleteFile、SetDispositionInformationFile

2. Regshot
   对比恶意程序运行前后的注册表和文件系统变化
   使用方法：
   - 运行 Regshot，拍摄第一张快照（First Shot）
   - 运行恶意程序并等待其执行完成
   - 拍摄第二张快照（Second Shot）
   - 对比差异（Compare）

3. inotifywait（Linux）
   inotifywait -m -r /tmp /etc -e create,modify,delete

4. 文件系统过滤驱动
   如 FileMon（已被 ProcMon 取代）
```

**常见文件操作行为**

| 行为 | 可能的目的 |
|------|-----------|
| 在临时目录创建文件 | 释放 payload、临时文件 |
| 在启动目录创建文件 | 持久化 |
| 修改系统文件 | 破坏系统、Rootkit |
| 加密用户文件 | 勒索软件 |
| 窃取文档文件 | 间谍软件、数据窃取 |
| 删除自身 | 自我销毁、痕迹清理 |
| 创建大量文件 | 蠕虫、病毒感染 |
| 修改 hosts 文件 | 劫持网络访问 |

**勒索软件文件行为特征**

```
1. 大量文件被修改/重命名
   - 文件被加密并添加新的后缀
   - 修改数量：通常是数千到数万个文件

2. 特定文件类型被加密
   - 文档：.doc, .docx, .xls, .xlsx, .ppt, .pdf
   - 图片：.jpg, .png, .bmp
   - 压缩包：.zip, .rar, .7z
   - 数据库：.mdb, .sql, .bak
   - 源代码：.cpp, .py, .java

3. 创建勒索信文件
   - README.txt、README_加密.txt
   - 通常在每个目录下都有一份
   - 文件名包含特定关键字

4. 文件读写模式
   - 先读取原文件内容
   - 加密后写入新文件
   - 删除或重命名原文件
```

### 3.4 注册表监控

**注册表监控方法**

```
1. Process Monitor
   过滤注册表操作：Operation 包含 Reg
   关注：RegSetValue、RegCreateKey、RegDeleteKey、RegDeleteValue

2. Regshot
   对比运行前后注册表变化
   特别关注：
   - 启动项键值变化
   - 服务相关键值变化
   - 文件关联变化
   - 驱动相关键值变化

3. 注册表实时监控工具
   - RegFromApp：监视特定进程的注册表操作
   - Regmon（已被 ProcMon 取代）
```

**常见注册表操作行为**

```
启动项持久化：
- HKCU\Software\Microsoft\Windows\CurrentVersion\Run
- HKLM\Software\Microsoft\Windows\CurrentVersion\Run
- HKCU\Software\Microsoft\Windows\CurrentVersion\RunOnce
- HKLM\Software\Microsoft\Windows\CurrentVersion\RunOnce

服务持久化：
- HKLM\SYSTEM\CurrentControlSet\Services\<服务名>

映像劫持：
- HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\

Winlogon：
- HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon\Userinit
- HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon\Shell

AppInit_DLLs：
- HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Windows\AppInit_DLLs

浏览器相关：
- 代理设置：HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings
- 首页设置：HKCU\Software\Microsoft\Internet Explorer\Main
- BHO：HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Explorer\Browser Helper Objects

安全软件相关：
- 尝试禁用杀毒软件和防火墙
- 修改安全中心设置
```

### 3.5 网络行为监控

**网络监控工具**

**Wireshark**

```
Wireshark 是最流行的网络协议分析工具，可以捕获和分析网络流量。

常用过滤规则：
- ip.addr == 192.168.1.100  → 特定 IP 地址
- tcp.port == 4444            → 特定 TCP 端口
- http                         → HTTP 协议
- dns                          → DNS 协议
- http.request.method == POST  → HTTP POST 请求
- tcp.flags.reset == 1         → RST 包

分析恶意软件网络流量的技巧：
1. 先运行恶意程序前开始抓包
2. 过滤掉正常的系统流量
3. 关注可疑的出站连接
4. 分析 HTTP 请求的 URL、User-Agent、Cookie
5. 分析 DNS 查询（特别是 DGA 域名）
6. 关注非标准端口的连接
7. 检查加密流量的证书信息
```

**TCPView / Process Explorer**

```
TCPView 可以实时查看所有 TCP/UDP 连接及其对应的进程。

分析用途：
1. 发现可疑的网络连接
2. 查看连接的远程地址和端口
3. 查看连接所属的进程
4. 识别哪些进程在监听端口

关注要点：
- 监听非标准端口的进程
- 连接到可疑 IP/域名的进程
- 大量出站连接（可能是扫描或 C2 通信）
- 系统进程（如 svchost.exe）的异常连接
```

**FakeNet / INetSim**

```
FakeNet 和 INetSim 是网络模拟工具，可以模拟各种网络服务，
使恶意软件认为自己连接到了真实的 C2 服务器。

FakeNet-NG 功能：
- DNS 模拟：解析所有域名为指定 IP
- HTTP/HTTPS 模拟：响应 HTTP 请求
- SMTP/POP3/IMAP 模拟：邮件服务模拟
- FTP 模拟：文件传输模拟
- 其他常见服务模拟

使用场景：
1. 让恶意软件正常运行（需要网络才能运行的恶意软件）
2. 捕获恶意软件的网络请求
3. 分析恶意软件的通信协议
4. 触发更多行为（如下载 payload）
```

**常见网络行为特征**

```
HTTP C2 通信特征：
- 定期回连（beacon），间隔固定或随机
- 使用特定的 User-Agent（常见、随机或伪造）
- 特定的 URL 路径（如 /news、/login、/api）
- POST 请求上传数据，GET 请求下载命令
- 数据编码：Base64、URL 编码、自定义编码
- Cookie 中包含数据
- HTTP 头异常（缺失、顺序异常等）

DNS 隧道特征：
- 大量 DNS 查询
- 查询的子域名异常长
- 子域名看起来像随机字符串
- TXT 记录返回数据
- 查询频率高

加密流量特征：
- 非标准端口的 SSL/TLS 流量
- 自签名证书或无效证书
- 异常的 JA3 指纹
- 流量模式异常（心跳包、固定大小数据包）

常见 C2 端口：
- 4444：Metasploit 默认端口
- 8080、8443：常用替代端口
- 53：DNS 隧道
- 443：伪装成 HTTPS
- 22：伪装成 SSH
```

### 3.6 沙箱技术

**什么是沙箱**

沙箱是一种隔离环境，用于安全地运行不可信的程序。恶意代码分析沙箱可以自动运行恶意软件并收集其行为数据，生成分析报告。

**常见沙箱产品**

| 沙箱 | 类型 | 说明 |
|------|------|------|
| Cuckoo Sandbox | 开源 | 最流行的开源沙箱，高度可定制 |
| Joe Sandbox | 商业 | 功能强大的商业沙箱 |
| ANY.RUN | 在线 | 交互式在线沙箱，可以实时操作 |
| Hybrid Analysis | 在线 | Falcon Sandbox 的免费在线版 |
| VirusTotal | 在线 | 多引擎扫描 + 沙箱分析 |
| Sandboxie | 本地 | 轻量级沙箱工具 |
| FireEye | 商业 | 企业级沙箱解决方案 |
| Lastline | 商业 | 高级沙箱，反逃逸能力强 |

**Cuckoo Sandbox**

```
Cuckoo Sandbox 是最流行的开源自动化恶意软件分析系统。

主要功能：
- 支持多种文件类型（EXE、DLL、PDF、Office 文档、脚本等）
- 自动分析文件行为
- 生成详细的分析报告
- 支持自定义分析模块
- 支持多种虚拟化后端（VirtualBox、VMware、KVM 等）

分析内容：
- 进程行为（创建、终止、注入等）
- 文件操作（创建、修改、删除等）
- 注册表操作
- 网络行为（DNS、HTTP、TCP/UDP）
- 内存数据提取
- 截图
- API 调用追踪
- 恶意软件家族识别

部署方式：
- Cuckoo 主机（管理节点）
- 分析机（运行恶意软件的虚拟机）
- 网络配置（模拟网络服务）
```

**沙箱的局限性**

```
1. 反沙箱技术
   恶意软件可以检测沙箱环境，检测到后不执行恶意行为：
   - 检测虚拟机（VMware、VirtualBox 特征）
   - 检测分析工具（ProcMon、Wireshark 等）
   - 检测沙箱特有的文件、注册表、进程
   - 检测硬件资源（CPU 核心数、内存大小、磁盘大小）
   - 检测用户交互（鼠标移动、键盘输入）
   - 延迟执行（等待沙箱超时）
   - 需要特定条件才触发（特定文件、特定时间）

2. 环境差异
   - 沙箱环境与真实环境可能存在差异
   - 某些恶意软件需要特定条件才能运行
   - 网络条件可能不同（是否有真实网络访问）

3. 行为不完全触发
   - 有些功能需要特定命令才执行
   - 有些行为需要 C2 指令触发
   - 有些恶意软件有多阶段 payload
```
