# 勒索软件分析要点

### 4.1 勒索软件的典型行为

**感染阶段**

1. **初始访问**：钓鱼邮件、漏洞利用、弱口令、横向移动
2. **执行投递器**：运行下载器或初始 payload
3. **权限提升**：利用漏洞或配置错误获取管理员权限
4. **持久化**：创建服务、注册表启动项、计划任务等
5. **防御规避**：禁用安全软件、删除卷影副本、白名单利用

**侦察阶段**

1. **系统信息收集**：操作系统版本、网络配置、已安装软件
2. **网络扫描**：扫描内网其他主机
3. **凭据窃取**：从内存中提取密码哈希（Mimikatz 等）
4. **数据窃取**：在加密前窃取敏感数据（双重勒索）

**加密阶段**

1. **生成加密密钥**：生成随机的 AES 对称密钥
2. **加密文件**：使用 AES 密钥加密用户文件
3. **加密密钥保护**：使用 RSA 公钥加密 AES 密钥（随文件保存）
4. **修改文件后缀**：给加密文件添加特定后缀
5. **创建勒索信**：在每个目录放置勒索说明

**勒索阶段**

1. **显示勒索信息**：弹出勒索窗口、更改桌面背景、创建勒索信文件
2. **提供联系方式**：Tor 网站、邮件、即时通讯等
3. **设置倒计时**：限时支付，逾期涨价或销毁密钥
4. **支付验证**：验证支付后提供解密工具/密钥

### 4.2 勒索软件加密算法分析

**常见加密方案**

勒索软件通常采用混合加密方案：

```
混合加密流程：
1. 生成随机的 AES 密钥（对称加密，速度快，适合加密大量文件）
2. 使用 AES 密钥加密用户文件
3. 使用攻击者的 RSA 公钥加密 AES 密钥
4. 将加密后的 AES 密钥保存在加密文件中
5. 只有攻击者拥有 RSA 私钥，才能解密 AES 密钥

为什么使用混合加密：
- 对称加密（AES）速度快，适合加密大量文件
- 非对称加密（RSA）适合加密密钥（密钥长度小）
- 只有攻击者有私钥，受害者无法自己解密
```

**常见加密算法**

| 算法 | 类型 | 常见用途 |
|------|------|----------|
| AES-128/256 | 对称加密 | 加密文件内容（最常用） |
| RSA-1024/2048/4096 | 非对称加密 | 加密 AES 密钥 |
| RC4 | 流加密 | 一些旧勒索软件使用 |
| ChaCha20 | 流加密 | 一些新勒索软件使用 |
| Salsa20 | 流加密 | 部分勒索软件使用 |

**加密算法识别方法**

```
1. 字符串分析
   - 搜索 "AES"、"RSA"、"encrypt"、"decrypt" 等关键词
   - 查找加密常量（如 AES S-box、RSA 公钥模数）

2. 导入函数分析
   - CryptEncrypt、CryptDecrypt（CryptoAPI）
   - BCryptEncrypt、BCryptDecrypt（CNG）
   - 自定义加密（无加密库导入）

3. 动态分析
   - 监控加密 API 调用
   - 分析内存中的加密密钥
   - 对比加密前后的文件内容

4. 静态分析
   - 反汇编分析加密函数
   - 识别加密算法特征常量
   - 使用加密算法识别工具（如 FindCrypt、KANAL）
```

### 4.3 勒索软件分析流程

**第一步：样本获取和初步分析**

```
1. 获取样本文件
2. 计算文件哈希（MD5、SHA-1、SHA-256）
3. 文件类型识别（查壳、识别编程语言）
4. 查询在线沙箱报告（VirusTotal、Hybrid Analysis）
5. 字符串分析（勒索信内容、C2 地址、加密相关）
6. 导入表分析（加密 API、系统 API）
```

**第二步：静态详细分析**

```
1. 脱壳（如果有壳）
2. 反汇编和反编译分析
3. 识别加密算法
4. 分析文件加密流程
5. 分析密钥生成和管理
6. 查找硬编码的密钥或弱点
7. 分析持久化机制
8. 分析横向移动模块
```

**第三步：动态分析**

```
1. 准备分析环境（虚拟机、快照、网络模拟）
2. 运行勒索软件
3. 监控进程行为
4. 监控文件系统变化
5. 监控注册表变化
6. 捕获网络流量
7. 观察加密过程和勒索信
8. 提取内存中的密钥（可能）
```

**第四步：IOC 提取和报告编写**

```
提取 IOC（Indicators of Compromise）：
1. 文件哈希（MD5、SHA-1、SHA-256）
2. IP 地址和域名
3. URL 和路径
4. 互斥体名称
5. 注册表键值
6. 文件名和路径
7. 加密文件后缀
8. 勒索信文件名
9. 服务名和计划任务名
10. C2 通信特征

编写分析报告：
1. 样本基本信息
2. 技术分析（感染流程、加密方式、持久化等）
3. IOC 列表
4. 防护建议
5. 附录（截图、代码片段等）
```

### 4.4 勒索软件防御要点

**预防措施**

```
1. 数据备份（3-2-1 原则）
   - 至少 3 份数据副本
   - 存储在 2 种不同介质上
   - 1 份异地存储（离线或云）
   - 定期测试备份的可用性

2. 补丁管理
   - 及时安装系统和应用补丁
   - 重点关注 RCE 漏洞补丁
   - 定期漏洞扫描

3. 端点防护
   - 部署杀毒软件和 EDR
   - 启用实时保护
   - 启用行为监控
   - 定期更新病毒库

4. 邮件安全
   - 部署邮件网关
   - 过滤可疑附件和链接
   - 启用沙箱检测
   - 员工钓鱼意识培训

5. 网络分段
   - 按业务和安全级别分段
   - 限制横向移动路径
   - 部署网络访问控制（NAC）
   - 监控内部网络流量

6. 最小权限原则
   - 用户使用普通权限账户
   - 限制本地管理员权限
   - 实施特权访问管理（PAM）
   - 定期审计权限分配

7. 应用白名单
   - 只允许授权程序运行
   - 使用 AppLocker 或软件限制策略
   - 限制脚本执行权限
   - 禁用 Office 宏（默认禁用）
```

**检测措施**

```
1. 文件系统监控
   - 监控大量文件修改事件
   - 监控特定文件类型的修改
   - 监控勒索信文件的创建
   - 监控文件重命名操作

2. 网络监控
   - 监控可疑的出站连接
   - 监控大量数据上传（数据窃取）
   - 监控访问已知恶意 IP/域名
   - 监控 Tor 网络访问

3. 行为监控
   - 监控异常的进程行为
   - 监控卷影副本删除
   - 监控安全软件被禁用
   - 监控大量文件加密操作

4. 威胁狩猎
   - 主动搜索入侵迹象
   - 分析日志异常
   - 威胁情报匹配
   - 红队演练
```

**应急响应**

```
勒索软件攻击应急响应流程：

1. 遏制（Containment）
   - 立即隔离受感染主机（断开网络）
   - 防止进一步传播
   - 保护未感染的系统

2. 评估（Assessment）
   - 确定感染范围
   - 确定勒索软件家族
   - 评估数据损失
   - 评估业务影响

3. 调查（Investigation）
   - 确定入侵路径
   - 分析攻击时间线
   - 提取 IOC
   - 评估是否有数据泄露

4. 恢复（Recovery）
   - 从备份恢复数据
   - 修复被利用的漏洞
   - 清理持久化机制
   - 逐步恢复业务

5. 改进（Improvement）
   - 分析事件原因
   - 加强安全防护
   - 更新安全策略
   - 员工安全培训

是否支付赎金？
- 一般建议：不支付赎金
- 原因：
  1. 不保证能恢复所有数据
  2. 资助犯罪行为
  3. 可能成为后续攻击目标
  4. 可能违反法律法规
- 例外情况（需要管理层决策）：
  1. 没有可用备份
  2. 数据极其重要且无法替代
  3. 业务中断损失远大于赎金
```
