# 静态分析方法

### 2.1 文件特征分析

**文件类型识别**

```
Windows 平台（PE 文件）：
- 特征签名：MZ（0x4D 0x5A）
- 文件扩展名：.exe, .dll, .sys, .ocx, .scr, .drv
- PE 头签名：PE\0\0（0x50 0x45 0x00 0x00）

Linux 平台（ELF 文件）：
- 特征签名：\x7FELF（0x7F 0x45 0x4C 0x46）
- 文件扩展名：无（可执行文件）, .so, .o
- ELF 类型：ET_EXEC（可执行）, ET_DYN（共享库）, ET_REL（目标文件）

其他类型：
- 脚本文件：.vbs, .js, .ps1, .bat, .cmd, .py, .sh
- 文档文件（含宏）：.doc, .xls, .ppt, .pdf
- 压缩包：.zip, .rar, .7z, .tar, .gz
- Java：.jar, .class
- .NET：.exe, .dll（PE 格式，但包含 CLR 头）
```

**文件哈希计算**

```bash
# MD5
md5sum file.exe
Get-FileHash -Algorithm MD5 file.exe

# SHA-1
sha1sum file.exe
Get-FileHash -Algorithm SHA1 file.exe

# SHA-256
sha256sum file.exe
Get-FileHash -Algorithm SHA256 file.exe

# SHA-512
sha512sum file.exe
Get-FileHash -Algorithm SHA512 file.exe
```

**文件大小和熵值**

```
熵值（Entropy）衡量文件数据的随机性：
- 低熵（< 6）：文件可能未加密/未压缩
- 中高熵（6-7.5）：文件可能经过压缩或简单加密
- 高熵（接近 8）：文件很可能经过强加密或加壳

工具：
- Detect It Easy (DIE)：熵值分析
- PEiD：查壳工具
- ent：命令行熵值计算工具
- x64dbg：内存熵值分析
```

**数字签名验证**

```
数字签名可以验证文件的来源和完整性。
恶意软件通常没有有效签名，或者使用伪造的签名。

Windows 签名验证：
- signtool verify /pa /v file.exe
- Get-AuthenticodeSignature file.exe
- 查看文件属性 → 数字签名

Linux 签名验证：
- dpkg-sig --verify package.deb （Debian 包）
- rpm -K package.rpm （RPM 包）
```

### 2.2 字符串分析

**字符串分析的作用**

字符串分析是静态分析的重要步骤，通过提取文件中的可打印字符串，可以获取大量有用信息：

- IP 地址和域名（C2 服务器地址）
- URL 和路径
- 命令行参数
- 注册表键路径
- 文件名和目录
- 加密密钥和密码
- 错误信息和提示信息
- 加壳器/编译器特征
- 互斥体名称
- 配置信息

**字符串提取工具**

```bash
# Windows 工具：
# - Strings（Sysinternals）
# - IDA Pro 字符串窗口
# - Ghidra 字符串搜索
# - x64dbg 字符串搜索
# - PEStudio

# Linux 工具：
strings file.exe
strings -n 8 file.exe  # 最小长度 8 个字符
strings -a file.exe   # 扫描整个文件（默认只扫描数据段）
strings -t x file.exe  # 显示偏移地址（十六进制）

# 提取 Unicode 字符串
strings -el file.exe
```

**常见可疑字符串特征**

```
网络相关：
- http://、https://、ftp://
- IP 地址格式：xxx.xxx.xxx.xxx
- 域名：example.com、xxx.ddns.net
- 端口号：:4444、:8080
- User-Agent 字符串
- "Mozilla/" 等 HTTP 头

系统相关：
- "SOFTWARE\\Microsoft\\Windows\\CurrentVersion\\Run"（启动项）
- "cmd.exe /c"、"/c start"、"powershell -enc"（命令执行）
- "svchost.exe"、"explorer.exe"（可能用于注入）
- "\\Temp\\"、"\\AppData\\"（常见写入路径）

安全相关：
- "IsDebuggerPresent"、"CheckRemoteDebuggerPresent"（反调试）
- "VirtualProtect"、"VirtualAlloc"（内存操作）
- "CreateRemoteThread"（进程注入）
- "ADVAPI32.dll"、"ntdll.dll"（系统 DLL）

加密相关：
- "AES"、"RSA"、"XOR"、"RC4"
- 明显的 Base64 字符串
- 长串无意义字符（可能是加密的配置或 Shellcode）

勒索软件特征：
- "README"、"INSTRUCTION"、"DECRYPT"
- "bitcoin"、".onion"、"Tor"
- 加密文件后缀列表
- 钱包地址格式
```

**字符串分析案例**

```
分析一个可疑的 PE 文件，提取字符串后发现：

1. "http://192.168.1.100:4444/beacon" 
   → 可能是 C2 服务器地址，beacon 模式常见于 Cobalt Strike

2. "cmd.exe /c whoami && ipconfig"
   → 执行系统命令，信息收集

3. "SOFTWARE\\Microsoft\\Windows\\CurrentVersion\\Run"
   → 注册表启动项持久化

4. "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36"
   → 伪造的 User-Agent，用于 HTTP 通信

5. "VirtualAlloc"、"CreateRemoteThread"、"WriteProcessMemory"
   → 进程注入相关函数

6. "IsDebuggerPresent"、"GetTickCount"
   → 反调试和反沙箱函数

7. "aHR0cDovL2V4YW1wbGUuY29tL2JhY2tkb29y"
   → Base64 编码，解码后可能是 C2 地址

综合判断：这很可能是一个远控木马（RAT）或后门程序。
```

### 2.3 导入表分析

**导入表的作用**

导入表（Import Table）记录了程序从哪些 DLL 导入了哪些函数。分析导入表可以快速了解程序的功能和行为特征。

**PE 导入表结构**

```
PE 文件的导入表位于 .idata 节（通常与 .rdata 合并），包含：
1. 导入 DLL 列表（每个 DLL 对应一个 IMAGE_IMPORT_DESCRIPTOR）
2. 导入函数名称列表（INT - Import Name Table）
3. 导入地址表（IAT - Import Address Table）
```

**导入表查看工具**

```bash
# 查看导入表
# 工具：Dependency Walker (depends.exe)
# 工具：PEiD
# 工具：CFF Explorer
# 工具：IDA Pro / Ghidra

# 命令行工具：
dumpbin /imports file.exe
objdump -p file.exe | grep -A 100 "DLL Name"
readelf -d file.so  # ELF 文件
```

**常见可疑导入函数分类**

**进程/线程操作**
```
Kernel32.dll:
- CreateProcess / CreateProcessA / CreateProcessW  → 创建新进程
- CreateRemoteThread / CreateRemoteThreadEx       → 远程线程注入
- OpenProcess                                    → 打开远程进程
- VirtualAlloc / VirtualAllocEx                  → 分配内存
- VirtualProtect / VirtualProtectEx              → 修改内存保护属性
- WriteProcessMemory / ReadProcessMemory         → 读写进程内存
- QueueUserAPC                                   → APC 注入
- GetThreadContext / SetThreadContext            → 线程上下文操作
- CreateThread / CreateRemoteThread              → 线程创建
- TerminateProcess                               → 终止进程
```

**文件操作**
```
Kernel32.dll:
- CreateFile / CreateFileA / CreateFileW         → 创建/打开文件
- WriteFile / ReadFile                           → 读写文件
- DeleteFile                                     → 删除文件
- CopyFile / MoveFile                            → 复制/移动文件
- FindFirstFile / FindNextFile                   → 文件查找
- GetFileAttributes / SetFileAttributes          → 文件属性操作
- CreateFileMapping / MapViewOfFile              → 文件映射
```

**注册表操作**
```
Advapi32.dll:
- RegOpenKeyEx / RegOpenKeyExA / RegOpenKeyExW   → 打开注册表键
- RegSetValueEx / RegSetValueExA / RegSetValueExW → 设置注册表值
- RegQueryValueEx                                → 查询注册表值
- RegCreateKeyEx                                 → 创建注册表键
- RegDeleteKey / RegDeleteValue                  → 删除注册表键/值
- RegEnumKey / RegEnumValue                      → 枚举注册表键/值
```

**网络通信**
```
Wininet.dll:
- InternetOpen / InternetOpenUrl                 → 初始化 WinINet / 打开 URL
- InternetConnect / HttpOpenRequest              → 连接服务器 / 打开 HTTP 请求
- HttpSendRequest / InternetReadFile             → 发送请求 / 读取响应
- InternetWriteFile / FtpPutFile                 → 上传文件

Ws2_32.dll (Winsock):
- WSAStartup / socket / connect                  → 初始化 / 创建套接字 / 连接
- send / recv / sendto / recvfrom                → 收发数据
- bind / listen / accept                         → 服务端操作
- gethostbyname / getaddrinfo                    → DNS 解析

Winhttp.dll:
- WinHttpOpen / WinHttpConnect                   → WinHTTP 接口
- WinHttpOpenRequest / WinHttpSendRequest        → HTTP 请求
```

**调试/反调试**
```
Kernel32.dll:
- IsDebuggerPresent                              → 检测调试器
- CheckRemoteDebuggerPresent                     → 检测远程调试器
- OutputDebugString                              → 调试输出
- GetTickCount / GetTickCount64                  → 获取系统时间（时间检测）
- QueryPerformanceCounter                        → 高精度计时器
- Sleep                                          → 睡眠（延迟执行）

Ntdll.dll:
- NtQueryInformationProcess                      → 查询进程信息（检测调试端口）
- NtSetInformationThread                         → 设置线程信息
- NtClose                                        → 关闭句柄（异常检测）
```

**权限/令牌操作**
```
Advapi32.dll:
- OpenProcessToken / OpenThreadToken             → 打开进程/线程令牌
- AdjustTokenPrivileges                          → 调整令牌特权
- LookupPrivilegeValue                           → 查找特权值
- ImpersonateLoggedOnUser                        → 模拟登录用户
- DuplicateToken / DuplicateTokenEx              → 复制令牌
- CreateProcessAsUser                            → 以指定用户创建进程
```

**服务相关**
```
Advapi32.dll:
- OpenSCManager / OpenService                    → 打开服务管理器/服务
- CreateService                                  → 创建服务
- StartService / ControlService                  → 启动/控制服务
- ChangeServiceConfig                            → 修改服务配置
- DeleteService                                  → 删除服务
```

**加密/哈希**
```
Advapi32.dll (CryptoAPI):
- CryptAcquireContext                            → 获取 CSP 句柄
- CryptGenKey / CryptImportKey                   → 生成/导入密钥
- CryptEncrypt / CryptDecrypt                    → 加密/解密
- CryptHashData / CryptCreateHash                → 哈希计算

Bcrypt.dll (CNG):
- BCryptEncrypt / BCryptDecrypt                  → 加密/解密
- BCryptHashData                                 → 哈希计算
```

**导入表分析案例**

```
分析一个可疑程序的导入表，发现以下特征：

1. 大量进程/内存操作函数：
   OpenProcess, VirtualAllocEx, WriteProcessMemory, CreateRemoteThread
   → 高度可疑，可能进行进程注入

2. 网络相关函数：
   InternetOpenA, InternetConnectA, HttpOpenRequestA, InternetReadFile
   → 使用 WinINet 进行 HTTP 通信

3. 注册表操作函数：
   RegOpenKeyExA, RegSetValueExA
   → 可能修改注册表（持久化、配置存储等）

4. 反调试函数：
   IsDebuggerPresent, CheckRemoteDebuggerPresent, GetTickCount
   → 具有反调试能力

5. 服务相关函数：
   OpenSCManagerA, CreateServiceA, StartServiceA
   → 可能创建服务进行持久化

综合判断：
这是一个具有以下功能的恶意程序：
- 网络通信（HTTP C2）
- 进程注入
- 服务持久化
- 反调试能力
可能是一个远控木马（RAT）或下载器。
```

### 2.4 加壳识别

**什么是加壳**

加壳是指通过特殊算法修改可执行文件，将原始代码和数据加密或压缩，运行时先执行壳代码解密/解压原始代码，再跳转到原始入口点执行。加壳最初用于软件保护和反盗版，但也被恶意软件广泛用于免杀和反分析。

**加壳的分类**

| 类型 | 特点 | 示例 |
|------|------|------|
| 压缩壳 | 仅压缩代码和数据，保护程度低 | UPX、MPRESS、PECompact |
| 加密壳 | 加密代码和数据，带有反调试、反分析 | ASProtect、Armadillo |
| 虚拟化壳 | 将代码转换为自定义虚拟机指令，强度最高 | VMProtect、Themida、Obsidium |
| 混淆器 | 代码混淆、控制流平坦化等 | Obfuscator-LLVM、VMProtect |

**常见加壳器**

| 加壳器 | 类型 | 平台 | 说明 |
|--------|------|------|------|
| UPX | 压缩壳 | 多平台 | 最常见的开源压缩壳，易于脱壳 |
| MPRESS | 压缩壳 | Windows | 免费的压缩壳 |
| PECompact | 压缩壳 | Windows | 带一些保护功能的压缩壳 |
| ASProtect | 加密壳 | Windows | 经典加密壳，带反调试 |
| Armadillo | 加密壳 | Windows | 带多种保护机制 |
| ExeCryptor | 加密壳 | Windows | 代码变形 + 虚拟化 |
| VMProtect | 虚拟化壳 | 多平台 | 代码虚拟化，强度很高 |
| Themida | 虚拟化壳 | Windows | WinLicense 的保护引擎 |
| Obsidium | 加密壳 | Windows | 带授权管理 |
| Enigma Protector | 加密壳 | Windows | 功能丰富的保护工具 |

**加壳识别方法**

**方法1：查壳工具**

```
最常用的查壳工具：
- PEiD：经典查壳工具，特征库丰富（已停止更新）
- Detect It Easy (DIE)：功能强大的查壳工具，持续更新
- Exeinfo PE：另一个流行的查壳工具
- CFF Explorer：PE 编辑器，也有查壳功能
- FileAlyzer：文件分析工具
```

**方法2：节区分析**

```
加壳后的程序通常有特殊的节区名称：
- UPX: UPX0, UPX1, UPX2
- ASProtect: .aspack, .adata
- VMProtect: .vmp0, .vmp1, .vmp2
- Themida: .themida, .taz, .per
- Enigma: .enigma1, .enigma2

节区特征：
- 入口点不在 .text 节，而在最后一个节（壳代码节）
- .text 节的 VirtualSize 远大于 SizeOfRawData
- 节区名称奇怪或无意义
- 只有少量节区
```

**方法3：导入表分析**

```
加壳后导入表通常很简单：
- 只有少量导入函数
- 常见函数：LoadLibraryA/W, GetProcAddress
- 可能只有 kernel32.dll 和 ntdll.dll
- 运行时动态解析其他导入函数
```

**方法4：入口点分析**

```
入口点（AddressOfEntryPoint）特征：
- 入口点在最后一个节中
- 入口点代码是异常的解码/解压循环
- IDA 打开后只有少量代码能识别
```

**方法5：熵值分析**

```
加壳后文件熵值通常较高：
- 原始 PE 文件熵值约 5-6
- 压缩后熵值约 7-7.5
- 强加密后熵值接近 8
- 熵值高的节区通常是加密的数据区
```

**UPX 脱壳方法**

```bash
# 方法1：使用 UPX 自带脱壳功能
upx -d file.exe -o unpacked.exe

# 方法2：手动脱壳（ESP 定律 - 适用于很多压缩壳）
# 1. 用 x64dbg 打开加壳程序
# 2. 在入口点，观察 ESP 寄存器
# 3. 在 ESP 指向的地址下硬件写入断点（HW break on access）
# 4. 按 F9 运行，程序会断在 OEP 附近
# 5. 确认到达 OEP（原始入口点）
# 6. 使用 Scylla 插件：
#    - IAT Autosearch
#    - Get Imports
#    - Dump 进程
#    - Fix Dump（修复 IAT）

# 方法3：使用专用脱壳工具
# - QuickUnpack
# - Universal Unpacker
# - 各种专用脱壳脚本
```

### 2.5 资源分析

**PE 资源节**

PE 文件的资源节（.rsrc）包含各种资源数据，恶意软件常利用资源节存储恶意代码、配置信息、解密后的 payload 等。

**常见资源类型**

| 类型 ID | 类型名 | 说明 |
|---------|--------|------|
| 1 | RT_CURSOR | 光标资源 |
| 2 | RT_BITMAP | 位图资源 |
| 3 | RT_ICON | 图标资源 |
| 4 | RT_MENU | 菜单资源 |
| 5 | RT_DIALOG | 对话框资源 |
| 6 | RT_STRING | 字符串资源 |
| 9 | RT_ACCELERATOR | 快捷键表 |
| 11 | RT_VERSION | 版本信息 |
| 24 | RT_MANIFEST | 程序清单（Manifest） |
| 自定义 | 自定义 | 攻击者自定义的资源类型 |

**资源分析工具**

```
- Resource Hacker：查看和编辑 PE 资源
- Resource Tuner：资源编辑工具
- IDA Pro：查看资源节
- CFF Explorer：PE 编辑器，可查看资源
- PEView：PE 结构查看器
- x64dbg：内存中查看资源
```

**恶意软件利用资源的常见方式**

1. **存储 Payload**：将加密的恶意代码存储在资源中，运行时解密执行
2. **存储配置**：C2 地址、加密密钥、版本信息等
3. **存储其他文件**：DLL、驱动、配置文件等
4. **伪造版本信息**：伪造正常软件的版本信息和图标
5. **本地化字符串**：不同语言的勒索信等

**资源分析技巧**

```
1. 查看资源节的大小和熵值
   - 异常大的资源节可能包含加密的 payload
   - 高熵值的资源可能是加密数据

2. 检查自定义资源类型
   - 正常程序通常使用标准资源类型
   - 自定义类型和命名可能是可疑的

3. 提取和分析资源数据
   - 提取资源数据到文件
   - 分析是否是 PE 文件（MZ 头）
   - 分析是否是加密数据
   - 尝试常见的解密方法（XOR、AES 等）

4. 版本信息检查
   - 检查版本信息是否合理
   - 对比公司名、产品名是否与文件实际功能一致
   - 检查数字签名是否有效
```
