# 红队终端对抗技术

> 本文档从红队攻防视角系统讲解终端层面的权限提升、进程注入、持久化、EDR绕过、凭证获取与横向移动技术，并从防御角度给出检测与审计方法。内容仅供安全教育与研究用途，不提供可直接使用的攻击工具。

---

## 一、权限提升技术

权限提升（Privilege Escalation）是红队渗透测试中从普通用户权限跃迁到高权限用户的关键环节，分为垂直提权（低权限→高权限）与水平提权（同权限级别横向获取其他用户权限）。

### 1.1 Windows 提权

#### 1.1.1 信息收集

提权的前提是充分了解目标系统状态。核心收集命令如下：

| 命令 | 用途 |
|------|------|
| `systeminfo` | 系统版本、补丁列表、域信息 |
| `whoami /all` | 当前用户SID、所属组、特权列表 |
| `whoami /priv` | 专门查看当前用户权限（SeImpersonate等） |
| `net localgroup administrators` | 查看本地管理员组成员 |
| `cmdkey /list` | 查看存储的凭据 |
| `wmic qfe list` | 查看已安装补丁 |

通过 `whoami /priv` 可以快速发现可利用的高危特权，例如 `SeImpersonatePrivilege` 可用于 JuicyPotato/Potato 系列提权，`SeDebugPrivilege` 可直接读取 LSASS 进程内存。

#### 1.1.2 内核漏洞提权

内核漏洞提权利用操作系统内核层面的漏洞实现权限提升。红队常用的思路是对比 `systeminfo` 输出的补丁列表与已知漏洞库，定位缺失补丁对应的 CVE。

**CVE-2021-1732（Win10/Win11打印机提权）**：利用 `win32kfull.sys` 中 `NtCreateWindowEx` 函数的 UAF（Use-After-Free）漏洞，通过触发窗口对象释放后重用实现内核态代码执行。

**MS16-032**：利用 Windows 二次登录服务（seclogon）中 `CreateProcessWithTokenW` 的句柄竞争条件，通过让 `CreateProcessWithTokenW` 在高权限上下文中创建进程实现提权。原理在于该函数内部使用了临时令牌复制，竞争窗口期内可令牌劫持。

> 教育要点：内核漏洞提权存在稳定性风险（蓝屏），红队通常仅在必要场景使用，且优先选择已知可靠的公开 exploit。

#### 1.1.3 服务配置不当提权

**可写服务路径**：当 Windows 服务的可执行文件路径所在目录对普通用户可写时，攻击者可替换可执行文件，服务重启时以 SYSTEM 权限执行恶意代码。可通过以下命令枚举：

```
# WMIC 查询服务路径与启动方式
wmic service get name,pathname,startmode | findstr "Auto"
# AccessChk 检查目录可写性
accesschk.exe -uwcqv "Users" C:\SomeServicePath\
```

**Unquoted Service Path（未引用路径）**：当服务路径包含空格且未加引号时（如 `C:\Program Files\My Service\svc.exe`），Windows 会按顺序尝试解析路径。若攻击者在 `C:\Program.exe` 位置放置恶意文件，服务启动时会优先执行该文件。

#### 1.1.4 令牌窃取与模拟

Windows 令牌（Token）代表用户的安全上下文。具备 `SeImpersonatePrivilege` 或 `SeAssignPrimaryTokenPrivilege` 的用户可以模拟其他用户的令牌，从而以该用户身份执行操作。核心 API 调用链：

1. `OpenProcess` 获取目标进程句柄
2. `OpenProcessToken` 获取令牌句柄
3. `DuplicateTokenEx` 复制令牌
4. `CreateProcessWithTokenW` 使用复制令牌创建进程

经典场景：IIS 服务账户（IUSR）具备 `SeImpersonatePrivilege`，可配合 Potato 工具族通过 NTLM 中继或 RPC 模拟窃取 SYSTEM 令牌。

#### 1.1.5 UAC 绕过方法

UAC（用户账户控制）是 Windows Vista 引入的权限隔离机制。部分系统自带程序被标记为 `auto-elevate`，启动时自动提升权限且不弹出 UAC 提示。红队利用这些程序作为跳板：

| 方法 | 原理 |
|------|------|
| **fodhelper.exe** | 修改 `HKCU\Software\Classes\ms-settings\Shell\Open\command` 注册表键，fodhelper 启动时自动读取并执行该键值，继承高权限 |
| **SDCLT.exe** | 利用备份面板程序的 `-kickoff` 参数和注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\User Shell Folders` 劫持 |
| **computerdefaults.exe** | 通过修改 `HKCU\Software\Classes\ms-settings\Shell\Open\command` 实现 DLL 加载劫持 |
| **ICMLuaUtil COM 接口** | 通过 `Elevation:Administrator!new:` COM 提升命名格式调用自动提升的 COM 对象 |

> 防御要点：监控 `HKCU\Software\Classes\ms-settings` 注册表写入行为，以及 fodhelper/SDCLT 等自动提升进程的子进程创建行为。

#### 1.1.6 AlwaysInstallElevated

当注册表 `HKCU\Software\Policies\Microsoft\Windows\Installer\AlwaysInstallElevated` 设为 `1` 时，Windows Installer（msiexec）会以 SYSTEM 权限安装 MSI 包，不论当前用户权限。攻击者只需生成一个包含恶意 payload 的 MSI 文件并执行即可获得 SYSTEM 权限。检测方法为查询该注册表键值状态。

#### 1.1.7 注册表凭据提取

部分应用在注册表中以明文或弱加密方式存储凭据：

- **VNC**：`HKLM\SOFTWARE\RealVNC\WinVNC4\Password` 存储 VNC 密码（DES 加密，已知固定密钥）
- **AutoLogon**：`HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon` 下的 `DefaultUserName` 和 `DefaultPassword` 可能存储自动登录凭据（明文）
- **WinSCP**：`HKCU\SOFTWARE\Martin Prikryl\WinSCP 2\Sessions` 下存储 SSH 会话信息

### 1.2 Linux 提权

#### 1.2.1 信息收集

```
uname -a          # 内核版本与架构
cat /etc/os-release # 发行版信息
ps aux             # 运行进程列表
find / -perm -4000 2>/dev/null  # SUID 文件
crontab -l         # 当前用户计划任务
ls -la /etc/cron*  # 系统级 cron 配置
sudo -l            # 当前用户可执行的 sudo 命令
getcap -r / 2>/dev/null  # 文件 capabilities
```

#### 1.2.2 内核漏洞提权

**DirtyCow（CVE-2016-5195）**：利用 Linux 内核内存子系统中 COW（Copy-On-Write）机制的竞争条件。`get_user_page` 函数在处理写时复制时存在 TOCTOU 竞争窗口，攻击者可利用该窗口将只读映射变为可写映射，从而修改 `/etc/passwd` 等只读文件实现提权。

**DirtyPipe（CVE-2022-0847）**：Linux 内核 5.8+ 中 `splice` 系统调用与管道（pipe）缓冲区标志位处理存在缺陷。管道缓冲区的 `PIPE_BUF_FLAG_CAN_MERGE` 标志未被正确清除，导致后续写入操作合并到任意文件的可写页面中。攻击者可覆盖任意只读文件（如 `/etc/passwd`）中的内容。

> 教育要点：DirtyPipe 比 DirtyCow 更稳定、更可靠，但仅影响特定内核版本范围，且需要已有一个可读文件描述符指向目标文件。

#### 1.2.3 SUID 提权（GTFOBins 利用）

当某个具备 SUID 权限的程序存在功能滥用可能时，攻击者可利用该程序以文件属主（通常是 root）权限执行命令。GTFOBins 项目（<https://gtfobins.github.io>）系统记录了可被滥用的二进制文件。

常见 SUID 提权路径示例：

| 二进制文件 | 利用方式 |
|------------|----------|
| `find` | `find . -exec /bin/sh \;` |
| `python` | `python -c 'import os; os.setuid(0); os.system("/bin/sh")'` |
| `nmap` | 旧版本支持 `nmap --interactive` 后 `!sh` |
| `perl` | `perl -e 'exec("/bin/sh")'` |
| `cp` | 复制并替换 `/etc/passwd` |

#### 1.2.4 Sudo 配置滥用

`sudo -l` 查看当前用户可执行的 sudo 命令后，若发现可执行特定命令（如 `sudo /usr/bin/vim`），可通过 Vim 的 `:!sh` 或 `:py3 import os; os.system("/bin/sh")` 获取 root shell。还需检查 `/etc/sudoers` 中的 `NOPASSWD` 配置和通配符规则。

#### 1.2.5 Cron 任务利用

- **路径注入**：cron 脚本中使用相对路径调用程序时，攻击者在可写目录放置同名恶意脚本
- **通配符注入**：cron 任务使用 `*` 通配符配合 tar 等命令时，利用文件名注入参数（如 `--checkpoint=1 --checkpoint-action=exec=sh exploit.sh`）
- **权限继承**：root 用户的 cron 任务执行脚本若对普通用户可写，直接修改脚本内容

#### 1.2.6 PATH 变量劫持

当 SUID 程序调用其他命令时使用未限定路径（如 `system("ps")` 而非 `system("/bin/ps")`），攻击者可将恶意 `ps` 脚本置于 PATH 优先目录中。SUID 程序执行时会在 PATH 搜索路径中找到恶意版本并以 root 权限运行。

#### 1.2.7 Capabilities 利用

Linux Capabilities 将 root 权限拆分为细粒度能力。具备 `cap_setuid` 的程序可调用 `setuid(0)` 切换为 root。通过 `getcap -r /` 可搜索具备特殊 capabilities 的文件，参考 GTFOBins 中 Capabilities 章节判断可利用项。

### 1.3 提权信息收集自动化

红队常用自动化脚本思路为：枚举系统信息 → 比对漏洞库 → 检查配置弱点 → 输出可利用路径。Windows 端对应 WinPEAS 思路，Linux 端对应 LinPEAS 思路。自研脚本的核心逻辑示例：

```python
# Linux 提权信息收集脚本框架（仅教育示例）
import subprocess, os, re

def collect_suid_files():
    """枚举 SUID 文件并匹配 GTFOBins 已知列表"""
    result = subprocess.run(['find', '/', '-perm', '-4000'],
                          capture_output=True, text=True, timeout=60)
    known_gtfo = ['find', 'python', 'perl', 'nmap', 'vim', 'cp', 'cat']
    suid_files = result.stdout.strip().split('\n')
    exploitable = [f for f in suid_files
                   if os.path.basename(f) in known_gtfo]
    return exploitable

def check_sudo_rules():
    """检查 sudo 配置，发现可利用规则"""
    result = subprocess.run(['sudo', '-l'], capture_output=True, text=True)
    nopasswd = re.findall(r'NOPASSWD:\s*(.+)', result.stdout)
    return nopasswd

if __name__ == '__main__':
    print("=== SUID 可利用文件 ===")
    for f in collect_suid_files():
        print(f"  [!] {f}")
    print("=== Sudo 规则 ===")
    for rule in check_sudo_rules():
        print(f"  [!] {rule}")
```

## 二、进程注入与迁移

进程注入是红队在目标内存中执行代码的核心技术，进程迁移则用于将 payload 从临时进程转移到稳定进程中。

### 2.1 Windows 进程注入

#### 2.1.1 DLL 注入（CreateRemoteThread/LoadLibrary）

经典 DLL 注入的核心步骤：

1. `OpenProcess` 获取目标进程句柄
2. `VirtualAllocEx` 在目标进程内存中分配空间
3. `WriteProcessMemory` 写入 DLL 路径字符串
4. `GetProcAddress(GetModuleHandle("kernel32"), "LoadLibraryA")` 获取 LoadLibrary 地址
5. `CreateRemoteThread` 在目标进程中创建线程，线程函数为 `LoadLibraryA`，参数为 DLL 路径

> 检测特征：`VirtualAllocEx` + `WriteProcessMemory` + `CreateRemoteThread` 的 API 调用序列是 EDR 重点监控的行为链。

#### 2.1.2 反射式 DLL 注入

反射式注入不依赖 `LoadLibrary`，DLL 内部自行实现 PE 加载器：解析 PE 头、映射节区、处理导入表、修复重定位、调用 DllMain。由于不调用系统 API 加载 DLL，不会在模块列表中注册，更难被常规模块枚举检测。

#### 2.1.3 Process Hollowing（进程镂空）

1. 以挂起状态创建合法进程（如 `svchost.exe`）：`CreateProcess(..., CREATE_SUSPENDED, ...)`
2. `ZwUnmapViewOfSection` 卸载原进程内存镜像
3. `VirtualAllocEx` + `WriteProcessMemory` 写入恶意 PE
4. 修改 `CONTEXT.ThreadContext` 中的入口点地址
5. `ResumeThread` 恢复线程执行

进程镂空的优势在于任务管理器中显示为合法进程名，且数字签名信息可保留。

#### 2.1.4 APC 注入

异步过程调用（APC）注入向目标进程的 APC 队列排队执行函数。通过 `QueueUserAPC` 将恶意函数地址排入目标线程的 APC 队列，线程进入可告警状态时执行。通常目标选择有消息循环的进程，或通过强制线程进入可告警状态触发。

#### 2.1.5 进程迁移技术

C2 框架中的进程迁移指将 Shellcode 从注入进程迁移到另一个更稳定的进程（如 `explorer.exe`）。常用方法为 `CreateRemoteThread` 在目标进程执行迁移 Shellcode，或通过注入反射式 DLL 实现完整迁移。

### 2.2 Linux 进程注入

#### 2.2.1 LD_PRELOAD

`LD_PRELOAD` 环境变量指定优先加载的共享库，攻击者可利用此机制劫持目标进程的函数调用。编写恶意 `.so` 文件，在 `LD_PRELOAD` 中指定后启动目标程序，恶意库中的同名函数会优先于系统库被执行。限制：对设置了 `setgid`/`setuid` 的程序无效（内核会忽略 LD_PRELOAD）。

#### 2.2.2 ptrace 注入

`ptrace` 系统调用用于进程跟踪与调试，也可用于注入：

1. `ptrace(PTRACE_ATTACH, target_pid)` 附加目标进程
2. `ptrace(PTRACE_GETREGS)` 获取寄存器状态
3. `ptrace(PTRACE_POKEDATA)` 写入 Shellcode 到目标内存
4. 修改指令指针寄存器指向 Shellcode
5. `ptrace(PTRACE_DETACH)` 分离，目标进程继续执行 Shellcode

限制：需要 `CAP_SYS_PTRACE` 能力或 root 权限，且 `/proc/sys/kernel/yama/ptrace_scope` 控制可附加范围。

#### 2.2.3 /proc/pid/mem 写入

`/proc/pid/mem` 是 Linux 提供的直接访问进程内存的接口。通过 `open("/proc/<pid>/mem", O_RDWR)` 打开后 `lseek` 到目标地址，直接写入 Shellcode。需要在 `maps` 文件中定位可写可执行内存区域。

## 三、持久化技术

持久化是红队在目标系统上维持访问能力的技术，确保重启后仍可重新获取控制权。

### 3.1 Windows 持久化

#### 3.1.1 注册表自启动

| 位置 | 说明 |
|------|------|
| `HKLM\...\Run` | 系统启动时执行，所有用户生效 |
| `HKCU\...\Run` | 当前用户登录时执行 |
| `HKLM\...\Winlogon\Userinit` | 用户登录时执行，可追加路径 |
| `HKLM\...\Winlogon\Shell` | 替换或追加 Explorer 启动项 |
| `HKLM\...\RunOnce` | 执行一次后自动删除 |

#### 3.1.2 计划任务

`schtasks /create /tn "TaskName" /tr "payload" /sc onlogon /ru SYSTEM` 创建以 SYSTEM 权限在登录时执行的计划任务。红队常伪装任务名为系统更新类名称。

#### 3.1.3 服务创建

通过 `sc create` 创建 Windows 服务，服务以 SYSTEM 权限运行。服务名伪装为系统服务名称（如 `Microsoft Update`）可降低被发现的概率。

#### 3.1.4 WMI 事件订阅

WMI 永久事件订阅是一种隐蔽的持久化方式，包含三个组件：

- **事件过滤器（EventFilter）**：定义触发条件（如启动、登录、时间间隔）
- **事件消费者（EventConsumer）**：定义执行动作（CommandLineEventConsumer 执行命令）
- **绑定（FilterToConsumerBinding）**：将过滤器与消费者关联

WMI 事件订阅存储在 `root\subscription` 命名空间中，不易被常规检查发现。

#### 3.1.5 DLL 劫持

在应用程序搜索 DLL 的目录路径中放置同名恶意 DLL，应用程序加载时优先执行恶意版本。已知可被劫持的系统 DLL 搜索路径包括应用程序目录、当前工作目录、PATH 环境变量目录。

#### 3.1.6 COM 对象劫持

修改 `HKCU\Software\Classes\CLSID` 下的 COM 对象注册信息，将合法 COM 对象的 `InprocServer32` 或 `LocalServer32` 指向恶意 DLL/EXE。当系统或应用加载该 COM 对象时执行恶意代码，由于修改位于 HKCU 而非 HKLM，不需要管理员权限。

#### 3.1.7 Logon Script

在用户属性中设置登录脚本路径（`HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon` 或通过域策略），用户每次登录时自动执行指定脚本。

### 3.2 Linux 持久化

#### 3.2.1 Bashrc/Profile 后门

在 `~/.bashrc`、`~/.bash_profile` 或 `/etc/profile` 中追加恶意命令，用户每次打开 Shell 时自动执行。可配合条件判断（如仅在特定时间或特定参数时触发）以增强隐蔽性。

#### 3.2.2 Cron 定时任务

```
# crontab -e
*/30 * * * * /tmp/.malicious_script.sh  # 每30分钟执行
```

隐藏 Cron 任务的方法：将任务写入 `/var/spool/cron/` 下的用户文件，或使用 `/etc/cron.d/` 目录放置伪装为系统任务的文件。

#### 3.2.3 Systemd 服务

创建自定义 systemd 服务文件 `/etc/systemd/system/update-service.service`，设置 `[Install]` 段为 `WantedBy=multi-user.target`，实现开机自启。服务名伪装为系统服务。

#### 3.2.4 PAM 模块后门

在 PAM 认证模块（如 `pam_unix.so`）中插入代码，记录用户密码或植入后门密码。修改 `/etc/pam.d/` 下配置文件加载恶意 PAM 模块。由于 PAM 模块以 root 权限运行且涉及所有认证流程，隐蔽性极高。

#### 3.2.5 SSH 后门

- **SSH 密钥后门**：在目标 `~/.ssh/authorized_keys` 中追加攻击者公钥
- **SSH Wrapper 后门**：替换 sshd 或在 sshd 配置中植入密码记录逻辑
- **SSH 软连接后门**：创建 `sshd` 的软链接到特殊名称（如 `/tmp/su`），利用 PAM 认证绕过

#### 3.2.6 Rootkit 基础

Rootkit 通过修改操作系统内核或底层组件实现隐藏。用户态 Rootkit（LKM）通过加载内核模块 hook 系统调用，隐藏进程、文件、网络连接。检测手段包括对比 `ps` 输出与 `/proc` 目录、使用 `chkrootkit`/`rkhunter` 扫描。

## 四、红队终端检测绕过（EDR Bypass）

### 4.1 AMSI 绕过

AMSI（Anti-Malware Scan Interface）是 Windows 10 引入的恶意脚本扫描接口，PowerShell、VBScript 等脚本引擎在执行前将内容提交给 AMSI 扫描。绕过思路：

- **反射式 patching**：在内存中将 `amsi.dll` 的 `AmsiScanBuffer` 函数入口修改为直接返回 `S_OK`（`0x80070057`），使扫描结果始终为"干净"
- **反射式加载**：通过反射式加载.NET 程序集绕过 AMSI 的脚本扫描
- **编码混淆**：Base64/XOR 编码 payload 规避签名匹配

> 防御要点：监控 `amsi.dll` 内存修改行为，以及 PowerShell 脚本块日志（ScriptBlock Logging）中的混淆模式。

### 4.2 PowerShell 安全日志绕过

PowerShell 存在多级日志机制：模块日志（Event ID 4103）、脚本块日志（Event ID 4104）、转录日志。绕过思路包括使用 `PowerShell CLM（Constrained Language Mode）` 兼容路径、间接调用 `System.Management.Automation` 程序集，以及使用 C# 直接编译执行替代 PowerShell 脚本。

### 4.3 直接系统调用（Syscall）

EDR 通常通过用户态 hook（如 `ntdll.dll` 中的 API）监控系统调用。直接系统调用技术绕过用户态 hook，直接通过 `syscall` 指令调用内核函数。实现方式：在代码中硬编码或动态解析系统调用号，使用内联汇编 `syscall` 指令直接进入内核。高级 EDR 可能通过内核回调（ETW Threat Intelligence、ObRegisterCallbacks 等）在内核态检测。

### 4.4 Living off the Land（LOTL）

红队利用系统自带的合法工具执行攻击操作，避免投放自定义工具被 EDR 检测。

### 4.5 LOLBins 利用

| 工具 | 用途 | 检测难点 |
|------|------|----------|
| `certutil` | 下载文件、Base64 解码 | 合法证书工具被滥用 |
| `bitsadmin` | 后台下载文件 | 系统内置传输工具 |
| `msiexec` | 执行远程 MSI 包 | 正常安装行为 |
| `rundll32` | 加载任意 DLL | 系统核心工具 |
| `regsvr32` | 注册 COM 组件 | 合法功能被滥用 |
| `wmic` | WMI 命令执行 | 系统管理工具 |
| `mshta` | 执行 HTA 文件 | HTML 应用宿主 |

### 4.6 内存执行无文件攻击

无文件攻击指不在磁盘留下可执行文件，全程在内存中执行 payload。典型方式：通过 PowerShell 将 Shellcode 加载到内存并执行，或通过 .NET 反射式加载程序集。由于磁盘上无恶意文件，传统文件扫描无法检测。

### 4.7 混淆与加密 Shellcode

- **编码器**：对 Shellcode 进行 XOR/AES 加密，运行时在内存中解密后执行
- **分段加载**：将 Shellcode 分割为多段分散加载，规避内存扫描的单段特征
- **动态 API 解析**：不直接引用 API 函数，运行时通过 hash 查找动态解析

### 4.8 C2 框架检测绕过思路

C2（Command & Control）通信是 EDR 检测重点。绕过方向包括：使用合法协议（HTTPS/DNS）伪装正常流量、域名前置（Domain Fronting）、使用云服务作为中继（如 Cloudflare Workers）、Jitter 抖动打乱通信间隔规律性、自定义加密协议规避流量特征匹配。

## 五、凭证获取技术

### 5.1 Windows 凭据

#### 5.1.1 LSASS 进程 Dump

LSASS（Local Security Authority Subsystem Service）进程内存中存储了 NTLM Hash、Kerberos 票据、明文凭据（启用 WDigest 时）等。提取方式：

- **Mimikatz**：通过 `sekurlsa::logonpasswords` 直接从 LSASS 内存提取凭据，原理为使用 `LsaEnumerateLogonSessions` 枚举登录会话并解析凭据结构
- **Task Manager/ProcDump**：创建 LSASS 的 minidump 文件后离线解析，降低在目标主机上的行为特征
- **comsvcs.dll**：`rundll32 comsvcs.dll MiniDump <pid> dump.dmp full`，利用系统自带 DLL

> 防御要点：Windows Defender Credential Guard 可将凭据隔离在虚拟安全模式（VSM）中，阻止 LSASS 读取。

#### 5.1.2 SAM 数据库提取

SAM（Security Account Manager）存储本地用户 NTLM Hash。在线提取通过注册表转储：`reg save HKLM\SAM sam.hive`、`reg save HKLM\SYSTEM system.hive`，离线使用 `impacket-secretsdump` 解析。需要 SYSTEM 权限或物理访问（离线挂载磁盘）。

#### 5.1.3 NTDS.dit 提取

域控制器的 `NTDS.dit` 存储所有域用户的凭据 Hash。提取方式包括：VSS 卷影复制后复制 `NTDS.dit` 和 `SYSTEM` hive、`ntdsutil` 原生工具 IFM 生成、`dcsync`（通过 `IDR_DRSGetNCChanges` 复制接口模拟域控同步行为，无需接触文件系统）。

#### 5.1.4 LAPS 密码读取

LAPS（Local Administrator Password Solution）将本地管理员密码存储在 AD 计算机对象的 `ms-Mcs-AdmPwd` 属性中。具备读取权限的用户可通过 LDAP 查询直接获取明文密码。红队常利用 LAPS 委派配置不当扩大读取范围。

#### 5.1.5 DPAPI 解密

DPAPI（Data Protection API）保护浏览器密码、证书私钥等敏感数据。主密钥存储在 `APPDATA\Microsoft\Protect` 下，需要用户密码或域备份密钥解密。获取主密钥后可解密 Chrome/Edge 存储的密码数据库。

#### 5.1.6 浏览器密码提取

Chrome/Edge 密码存储在 `Login Data` SQLite 数据库中，使用 DPAPI 加密。提取流程：定位数据库文件 → 使用 DPAPI 解密主密钥 → 解密 `encrypted_value` 字段。Firefox 使用 `key4.db` + `cert9.db`，加密机制不同但可类似提取。

### 5.2 Linux 凭据

#### 5.2.1 /etc/shadow 破解

`/etc/shadow` 存储 Hash 后的用户密码。提取后使用 `hashcat` 或 `john` 离线破解：

```
# hashcat 模式参考
hashcat -m 1800 hash.txt wordlist.txt   # sha512crypt ($6$)
hashcat -m 500 hash.txt wordlist.txt    # md5crypt ($1$)
```

#### 5.2.2 SSH 私钥收集

搜索 `~/.ssh/id_rsa`、`~/.ssh/id_ed25519` 等私钥文件，配合已知密码或弱密码字典破解 passphrase。同时收集 `known_hosts` 和 `config` 文件获取目标主机信息。

#### 5.2.3 历史命令中的凭据

```
cat ~/.bash_history | grep -iE "password|passwd|pwd|secret|token"
cat ~/.mysql_history | grep -i password
cat ~/.psql_history
```

#### 5.2.4 环境变量中的凭据

```
env | grep -iE "PASS|SECRET|TOKEN|KEY|CREDENTIAL"
cat /proc/*/environ 2>/dev/null | tr '\0' '\n' | grep -i pass
```

## 六、横向移动基础

### 6.1 Pass-the-Hash（PTH）

PTH 利用 NTLM 认证协议的设计特性：认证过程中使用 NTLM Hash 而非明文密码。攻击者获取用户 NTLM Hash 后，可直接构造 NTLM 认证请求访问该用户有权限的资源，无需破解密码。典型工具思路为 `psexec -hashes <LM:NT>` 或 `crackmapexec smb --hashes`。

### 6.2 Pass-the-Ticket（PTT）

PTT 利用 Kerberos 票据机制：Kerberos 认证依赖 TGT（票据授予票据）和 ST（服务票据），票据本身即为访问凭据。攻击者注入窃取的 TGT/ST 到当前会话票据缓存中，随后以票据所有者身份访问对应服务。典型操作为 `klist` 管理票据缓存、Rubeus `ptt` 注入。

### 6.3 Overpass-the-Hash

Overpass-the-Hash（Pass-the-Key）使用 NTLM Hash 向 KDC 请求 TGT，然后使用 TGT 进行 Kerberos 认证。场景：在无法直接 PTH 但可获取 TGT 的情况下，将 NTLM Hash 转换为 Kerberos TGT 以获得更强的认证能力。

### 6.4 远程执行技术

| 协议/工具 | 端口 | 说明 |
|-----------|------|------|
| WMI | 135（DCE/RPC） | 通过 `Win32_Process.Create` 远程创建进程 |
| WinRM | 5985（HTTP）/5986（HTTPS） | PowerShell Remoting 底层协议 |
| SMB | 445 | 通过 `IPC$` 共享执行远程命令 |
| DCOM | 135 | 通过 `MMC20.Application` 等 DCOM 对象远程执行 |

### 6.5 PsExec/WMIC/DCOM 利用

- **PsExec**：通过 SMB 在远程主机创建临时服务执行命令，完成后删除服务。特征为 SYSTEM 临时服务创建和服务删除行为
- **WMIC**：`wmic /node:target process call create "cmd"` 远程创建进程，依赖于 WMI 服务和 135 端口
- **DCOM**：利用 `DCOM` 分布式组件对象模型远程激活 COM 对象，如通过 `MMC20.Application` 的 `ExecuteShellCommand` 方法远程执行命令

## 七、防御视角与检测

### 7.1 Windows 日志审计关键事件 ID

| 事件 ID | 日志来源 | 说明 |
|---------|----------|------|
| 4624 | Security | 登录成功（关注 Logon Type 3/10） |
| 4625 | Security | 登录失败（爆破检测） |
| 4672 | Security | 特权用户登录 |
| 4688 | Security | 进程创建（需开启进程审核） |
| 4697 | Security | 服务安装 |
| 4720 | Security | 用户账户创建 |
| 4732 | Security | 用户加入本地管理员组 |
| 7045 | System | 服务创建（SYSTEM 来源） |
| 4698 | Security | 计划任务创建 |
| 4688 | Security | 命令行参数（需启用命令行审核策略） |

启用命令行审核：`计算机配置 → 策略 → 管理模板 → 系统 → 审核进程创建 → 在进程创建事件中包含命令行`。

### 7.2 Sysmon 配置与检测规则

Sysmon（System Monitor）是 Sysinternals 提供的轻量级系统行为监控工具。关键监控事件类型：

```xml
<!-- Sysmon 配置示例：监控关键提权与持久化行为 -->
<SysmonScheme>
  <EventFiltering>
    <!-- 进程创建：监控可疑父进程子进程关系 -->
    <RuleGroup name="ProcessCreation" groupRelation="or">
      <ProcessCreate onmatch="include">
        <!-- 监控 PowerShell 执行（AMSI绕过/脚本执行） -->
        <Image condition="contains">powershell.exe</Image>
        <!-- 监控可疑 LOLBins -->
        <Image condition="contains">certutil.exe</Image>
        <Image condition="contains">mshta.exe</Image>
        <!-- 监控从临时目录执行 -->
        <Image condition="begin with">C:\Users\*\AppData\Local\Temp\</Image>
      </ProcessCreate>
    </RuleGroup>
    <!-- 注册表持久化监控 -->
    <RuleGroup name="RegistryPersistence" groupRelation="or">
      <RegistryEvent onmatch="include">
        <TargetObject condition="contains">\Run\</TargetObject>
        <TargetObject condition="contains">\RunOnce\</TargetObject>
        <TargetObject condition="contains">\Winlogon\Userinit</TargetObject>
      </RegistryEvent>
    </RuleGroup>
    <!-- DLL 加载监控 -->
    <RuleGroup name="ImageLoad" groupRelation="or">
      <ImageLoad onmatch="include">
        <!-- 监控可疑 DLL 注入 -->
        <ImageLoaded condition="contains">\Temp\</ImageLoaded>
      </ImageLoad>
    </RuleGroup>
  </EventFiltering>
</SysmonScheme>
```

Sigma 是通用的 SIEM 检测规则格式，可转换为各 SIEM 平台的查询语法。以下为检测 UAC 绕过（fodhelper）的 Sigma 规则示例：

### 7.4 检测提权/持久化/横向移动的日志特征

| 攻击阶段 | 关键日志特征 |
|----------|-------------|
| 提权 | 4688: `whoami /priv`、`systeminfo` 连续调用；服务创建（7045）后进程以 SYSTEM 运行 |

### 7.5 Python 日志分析脚本示例

以下 Python 脚本模拟分析 Windows 安全日志中的提权与横向移动特征：

```python
"""
Windows 安全日志分析脚本（教育示例）
分析模拟日志数据，检测提权、持久化、横向移动行为
"""
from dataclasses import dataclass
from collections import defaultdict
from datetime import datetime

@dataclass
class LogEvent:
    timestamp: str
    event_id: int
    user: str
    source_ip: str
    process: str
    command_line: str

# 模拟日志数据
sample_logs = [
    LogEvent("2026-09-12 08:15:23", 4624, "admin", "192.168.1.5",
             "", "Network logon Type 3"),
    LogEvent("2026-09-12 08:15:30", 4688, "user01", "192.168.1.5",
             "whoami.exe", "whoami /priv"),
    LogEvent("2026-09-12 08:15:35", 4688, "user01", "192.168.1.5",
             "powershell.exe",
             "powershell -enc <base64_payload>"),
    LogEvent("2026-09-12 08:16:00", 7045, "user01", "192.168.1.5",
             "services.exe", "Service: Updatesvc path: C:\\Temp\\svc.exe"),
    LogEvent("2026-09-12 08:16:15", 4624, "admin", "192.168.1.10",
             "", "Network logon Type 3 - PsExec"),
    LogEvent("2026-09-12 08:16:20", 4688, "SYSTEM", "192.168.1.10",
             "cmd.exe", "cmd.exe /c whoami"),
]

def detect_privilege_escalation(events):
    """检测提权行为：whoami/priv 后服务创建"""
    alerts = []
    for i, event in enumerate(events):
        if event.event_id == 4688 and "/priv" in event.command_line:
            # 检查后续是否有服务创建
            for next_event in events[i:i+5]:
                if next_event.event_id == 7045:
                    alerts.append(
                        f"[提权告警] {event.timestamp} "
                        f"用户 {event.user} 枚举权限后创建服务 "
                        f"{next_event.command_line}"
                    )
                    break
    return alerts

def detect_lateral_movement(events):
    """检测横向移动：网络登录后 SYSTEM 进程创建"""
    alerts = []
    for i, event in enumerate(events):
        if (event.event_id == 4624 and
            "Type 3" in event.command_line):
            # 检查后续是否有 SYSTEM 权限进程创建
            for next_event in events[i:i+5]:
                if (next_event.event_id == 4688 and
                    next_event.user == "SYSTEM"):
                    alerts.append(
                        f"[横向移动告警] {event.timestamp} "
                        f"网络登录 {event.source_ip} 后 "
                        f"SYSTEM 进程创建 "
                        f"{next_event.process}"
                    )
                    break
    return alerts

def detect_persistence(events):
    """检测持久化行为：服务创建/计划任务"""
    alerts = []
    for event in events:
        if event.event_id == 7045:
            alerts.append(
                f"[持久化告警] {event.timestamp} "
                f"新服务创建: {event.command_line}"
            )
    return alerts

if __name__ == "__main__":
    print("=" * 60)
    print("Windows 安全日志分析报告")
    print("=" * 60)

    privesc = detect_privilege_escalation(sample_logs)
    lateral = detect_lateral_movement(sample_logs)
    persist = detect_persistence(sample_logs)

    print(f"\n提权告警 ({len(privesc)} 条):")
    for a in privesc:
        print(f"  {a}")

    print(f"\n横向移动告警 ({len(lateral)} 条):")
    for a in lateral:
        print(f"  {a}")

    print(f"\n持久化告警 ({len(persist)} 条):")
    for a in persist:
        print(f"  {a}")

    print(f"\n告警总计: {len(privesc) + len(lateral) + len(persist)} 条")
```

## 总结

红队终端对抗技术体系涵盖了从初始立足到权限提升、持久化、凭证获取、横向移动的完整攻击链，以及对应的 EDR 绕过与检测方法。理解这些技术的原理对于防御方同样至关重要——只有了解攻击者的思路，才能构建有效的检测与响应体系。

| 阶段 | 关键技术 | 核心检测手段 |
|------|----------|-------------|
| 权限提升 | 内核漏洞/服务配置/令牌模拟 | 进程创建日志/Sysmon/Sigma |
| 进程注入 | DLL注入/Process Hollowing | API调用链监控/ETW |
| 持久化 | 注册表/服务/WMI/COM | 注册表监控/服务审计 |
| EDR绕过 | AMSI绕过/Syscall/LOLBins | 内存扫描/行为基线 |
| 凭证获取 | LSASS Dump/SAM/NTDS | LSASS访问监控/DPAPI |
| 横向移动 | PTH/PTT/WMI/WinRM | 网络登录日志/异常连接 |

> 声明：本文档仅供网络安全教育与研究使用。所有技术描述旨在帮助防御方理解威胁并构建检测能力，不得用于未经授权的系统攻击。在实际环境中测试上述技术需获得书面授权并遵守适用法律法规。
