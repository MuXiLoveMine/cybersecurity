## 一、数字取证概述

### 1.1 数字取证基本原则

数字取证是运用科学方法对电子证据进行识别、收集、保全、分析和呈现的过程，遵循以下核心原则：

| 原则 | 说明 | 实践要求 |
|------|------|----------|
| 不修改原则 | 不改变原始证据的任何数据 | 写阻断器、只读挂载 |
| 可重复性 | 同一方法应得到同一结果 | 详细记录操作步骤 |
| 链式保管 | 证据从收集到呈堂全程可追踪 | 证据标签+交接记录 |
| 合规性 | 遵循法律法规和取证标准 | 符合 RFC 3227 等规范 |
| 时效性 | 易失性数据优先采集 | 按易失性等级排序 |

**证据采集优先级（RFC 3227 顺序）**：

```
易失性从高到低:

1. CPU 缓存和寄存器          ← 最易丢失，几乎无法采集
2. ARP 表、路由表             ← 网络状态信息
3. 内存（RAM）               ← 关机即丢失，最高优先级
4. 临时文件系统/swap          ← 运行时数据
5. 正在运行的进程             ← 进程信息、网络连接
6. 网络连接状态               ← 当前活动连接
7. 登录用户信息               ← 当前登录会话
8. 系统日志                   ← 持久化但可能被覆盖
9. 文件系统                   ← 持久化存储
10. 远程日志/备份             ← 离线存储
```

### 1.2 证据保全

```
证据保全操作流程:

1. 拍照记录现场
   ├── 设备外观照片
   ├── 屏幕显示内容
   ├── 连接线缆状态
   └── 周围环境

2. 证据标识
   ├── 唯一证据编号（如 EV-2026-001）
   ├── 采集时间（精确到秒）
   ├── 采集人签名
   ├── 设备型号和序列号
   └── 存储介质容量和哈希值

3. 写阻断保护
   ├── 硬件写阻断器（推荐）
   └── 软件只读挂载

4. 哈希校验
   ├── 采集后立即计算 MD5/SHA-256
   ├── 记录原始哈希值
   └── 分析完成后再次校验确认未修改

5. 链式保管记录
   ├── 每次交接记录时间和人员
   ├── 存储环境（温度、湿度）
   └── 任何操作都需记录
```

```bash
# 证据哈希校验示例
# 计算磁盘镜像的哈希值
md5sum disk_image.dd
sha256sum disk_image.dd

# 输出示例:
# a1b2c3d4e5f6...  disk_image.dd  (MD5)
# 1234abcd...      disk_image.dd  (SHA-256)
```

### 2.4 USN 日志分析

**USN（Update Sequence Number）日志** 是 NTFS 的变更日志，记录文件系统上所有的文件变更操作。

```powershell
# 使用 fsutil 查看 USN 日志
fsutil usn readjournal C: |
    Select-String "Add|Delete|Modify" |
    Select-Object -First 100

# 使用第三方工具分析 USN
# Tool: UsnJrnl2csv / python-evt
# python usn_parser.py C:\forensics\usnjrnl.bin -o usn_output.csv
```

```python
# Python USN 日志解析示例
import struct

def parse_usn_journal(journal_path):
    """
    解析 USN 日志记录
    """
    with open(journal_path, 'rb') as f:
        # 跳过 $J 的 $DATA 属性头部
        # 实际解析需要先从 MFT 中定位 $J
        offset = 0
        records = []
        
        while offset < os.path.getsize(journal_path):
            f.seek(offset)
            data = f.read(8)
            if len(data) < 8:
                break
            
            record_len = struct.unpack('<I', data[:4])[0]
            if record_len == 0:
                offset += 4
                continue
            
            f.seek(offset)
            record_data = f.read(record_len)
            
            # 解析 USN 记录结构
            # 偏移 0:  RecordLength (4 bytes)
            # 偏移 4:  MajorVersion (2 bytes)
            # 偏移 6:  MinorVersion (2 bytes)
            # 偏移 8:  FileReferenceNumber (8 bytes)
            # 偏移 16: ParentFileReference (8 bytes)
            # 偏移 24: Usn (8 bytes)
            # 偏移 32: TimeStamp (8 bytes)
            # 偏移 40: Reason (4 bytes) - 变更原因标志
            # 偏移 44: SourceInfo (4 bytes)
            # 偏移 48: SecurityId (4 bytes)
            # 偏移 52: FileAttributes (4 bytes)
            # 偏移 56: FileNameLength (2 bytes)
            # 偏移 58: FileNameOffset (2 bytes)
            # 偏移 60: FileName (Unicode)
            
            reason = struct.unpack('<I', record_data[40:44])[0]
            file_ref = struct.unpack('<Q', record_data[8:16])[0]
            
            reason_map = {
                0x00000001: 'DATA_OVERWRITE',
                0x00000002: 'DATA_EXTEND',
                0x00000004: 'DATA_TRUNCATION',
                0x00000010: 'NAMED_DATA_OVERWRITE',
                0x00000100: 'FILE_CREATE',
                0x00000200: 'FILE_DELETE',
                0x00000400: 'EA_CHANGE',
                0x00000800: 'SECURITY_CHANGE',
                0x00001000: 'RENAME_OLD_NAME',
                0x00002000: 'RENAME_NEW_NAME',
                0x00008000: 'BASIC_INFO_CHANGE',
                0x00010000: 'CLOSE',
            }
            
            reasons = [name for bit, name in reason_map.items() 
                       if reason & bit]
            
            name_len = struct.unpack('<H', record_data[56:58])[0]
            name = record_data[60:60+name_len].decode('utf-16-le')
            
            records.append({
                'file': name,
                'actions': reasons,
                'file_ref': file_ref
            })
            
            offset += record_len
        
        return records
```

# Python 文件时间线异常检测
import os
from datetime import datetime, timedelta

def detect_timeline_anomalies(timeline_csv):
    """
    检测文件时间线中的可疑模式
    """
    anomalies = []
    
    with open(timeline_csv) as f:
        for line in f:
            parts = line.strip().split(',')
            if len(parts) < 6:
                continue
            
            timestamp_str = parts[0]
            filepath = parts[5]
            
            # 异常1: 临时目录中的可执行文件
            if '/tmp/' in filepath and filepath.endswith(('.sh', '.py', '.elf')):
                anomalies.append(f"[临时目录可执行文件] {timestamp_str} {filepath}")
            
            # 异常2: 非工作时间的大量文件修改
            try:
                ts = datetime.fromisoformat(timestamp_str)
                if ts.hour < 6 or ts.hour > 23:
                    if '/etc/' in filepath:
                        anomalies.append(f"[非工作时间修改系统文件] {timestamp_str} {filepath}")
            except:
                pass
            
            # 异常3: timestomp 检测（修改时间 < 创建时间）
            # 需要对比 MACE 时间戳
    
    return anomalies

## 四、内存取证原理

### 4.1 内存获取方法

| 方法 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| 硬件采集 | DMA/PCI 设备读取内存 | 最可靠 | 需专用硬件 |
| 虚拟机快照 | 导出 VM 内存 | 方便 | 仅虚拟机 |
| 崩溃转储 | BlueScreen 后转储 | 完整 | 需触发蓝屏 |
| 工具采集 | 内存采集软件 | 便捷 | 可能被 Rootkit 干扰 |

**常用内存采集工具**：

```
Windows:
├── WinPmem      - 开源，支持 Windows 7-11
├── Magnet RAM Capture - 商业，免费使用
└── FTW Imager   - 转储工具

Linux:
├── LiME         - 内核模块，最可靠
└── AVML         - 微软开源

跨平台:
├── VirtualBox/VMware 快照
└── Live CD (Helix, CAIN)
```

### 4.2 内存结构

```
Windows 内存结构:

物理内存:
├── 物理页 (4KB/2MB)
└── 物理地址 (PA)

虚拟内存:
├── 虚拟地址 (VA) 空间
├── 页目录 (Page Directory)
├── 页表 (Page Table)
└── 页帧号 (PFN)

进程虚拟地址空间 (x64):
├── 0x000000000000 - 0x00007FFFFFFFFFFF  用户空间
├── 0xFFFF800000000000 - 0xFFFFFFFFFFFFFFFF  内核空间
│   ├── 进程 EPROCESS 结构
│   ├── PEB (进程环境块)
│   ├── VAD (虚拟地址描述符) - 记录进程内存分配
│   └── 句柄表
└── EPROCESS 中的关键字段:
    ├── UniqueProcessId (PID)
    ├── ActiveProcessLinks (进程链表 - 遍历所有进程)
    ├── ImageFileName (进程名)
    ├── PEB (进程环境块)
    └── VadRoot (VAD 树根)
```

## 五、Volatility 框架使用

### 5.1 安装与基础

```bash
# Volatility 2 (Python 2 - 经典版本)
pip install volatility
# 需要对应的 profile 文件

# Volatility 3 (Python 3 - 推荐版本)
pip install volatility3

# 基本用法 (Volatility 3)
python vol.py -f memory.raw windows.info          # 系统信息
python vol.py -f memory.raw windows.pslist        # 进程列表
python vol.py -f memory.raw windows.netscan       # 网络连接
python vol.py -f memory.raw windows.filescan     # 文件扫描
python vol.py -f memory.raw windows.dumpfiles    # 提取文件
python vol.py -f memory.raw windows.handles      # 句柄
python vol.py -f memory.raw windows.malfind       # 注入检测
python vol.py -f memory.raw windows.registry.*   # 注册表
python vol.py -f memory.raw windows.hashdump     # 密码哈希
python vol.py -f memory.raw windows.cmdline      # 命令行
```

### 5.2 关键命令详解

**（1）imageinfo / 系统信息**

```bash
# Volatility 2
vol.py -f memory.raw --profile=Win10x64_19041 imageinfo

# Volatility 3
python vol.py -f memory.raw windows.info

# 输出示例:
# DTB: 0x1ab000
# Win10x64_19041
# NtBuildNumber: 19041
# KdDebuggerEnabled: False
# CheckedBuild: 0
```

**（2）pslist / 进程列表**

```bash
# 进程列表（按 EPROCESS 链表遍历）
python vol.py -f memory.raw windows.pslist

# 进程树（显示父子关系）
python vol.py -f memory.raw windows.pstree

# 输出示例:
# PID   PPID  ImageFileName      Threads Handles
# 4     0     System              152    0
# 684   4     smss.exe            2      0
# 768   684   csrss.exe           13     0
# 852   768   winlogon.exe        4      0
# ...
# 4520  852   powershell.exe      11     156   ← 可疑进程
# 5644  4520  cmd.exe             1      32    ← PowerShell 子进程

# 检测异常:
# - 进程名与系统进程不符 (如小写的 svchost.exe)
# - PPID 异常 (svchost.exe 父进程不是 services.exe)
# - 无 PPID 的孤儿进程
# - 短暂存在已退出的进程 (psscan 可发现)
```

**（3）psscan / 隐藏进程检测**

```bash
# 扫描内存中所有 EPROCESS 结构（不依赖链表）
# 可发现被 Rootkit 从链表中摘除的隐藏进程

python vol.py -f memory.raw windows.psscan

# 对比 pslist 和 psscan 的差异
# psscan 找到但 pslist 没有的进程 = 隐藏进程
```

**（4）netscan / 网络连接**

```bash
# 提取内存中的网络连接信息
python vol.py -f memory.raw windows.netscan

# 输出示例:
# Offset     Proto  LocalAddr      LocalPort  ForeignAddr  ForeignPort  State     PID
# 0x12345    TCP    0.0.0.0:0     0          10.0.0.5     443          SYN_SENT  4520
# 0x67890    TCP    0.0.0.0:135   0          0.0.0.0:0    0            LISTEN    768
# 0xABCDE    TCP    192.168.1.100:49152  10.8.8.8:443  ESTABLISHED 5644  ← C2连接?

# 可疑指标:
# - 到未知外网IP的ESTABLISHED连接
# - 非常规端口(如非443/80的出站连接)
# - LISTEN端口异常
# - 已知C2 IP地址匹配
```

**（5）malfind / 注入检测**

```bash
# 检测进程内存中的注入代码
python vol.py -f memory.raw windows.malfind -p 4520

# 输出示例:
# Process: powershell.exe (4520)
# Range: 0x1a000000 - 0x1a001000
# Tag: MEM_PRIVATE
# Protection: PAGE_EXECUTE_READWRITE  ← 可执行+可写 = 注入特征
# Disasm:
# 0x1a000000  48 83 ec 28       sub rsp, 0x28
# 0x1a000004  48 8b 05 f0 00 00 mov rax, [rip+0xf0]
# 0x1a00000b  ff d0             call rax  ← shellcode 调用

# 判断标准:
# 1. 内存区域为 PRIVATE (私有分配)
# 2. 保护属性为 RWX (可读可写可执行)
# 3. 包含可执行代码 (非数据)
# 4. 无对应磁盘文件 (内存中独立存在)
```

**（6）hashdump / 凭据提取**

```bash
# 从内存中提取 NTLM 哈希
python vol.py -f memory.raw windows.hashdump --lsa

# 输出示例:
# Administrator:500:aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0:::
# Guest:501:aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0:::
# user1:1001:aad3b435b51404eeaad3b435b51404ee:8846f7eaee8fb117ad06bddbb7b06477:::

# 哈希格式: RID:LM_Hash:NT_Hash:::
# 可使用 hashcat/john 离线破解 NTLM 哈希
# hashcat -m 1000 hashes.txt wordlist.txt
```

**（7）文件提取**

```bash
# 扫描内存中的文件对象
python vol.py -f memory.raw windows.filescan | grep -i "temp\|powershell\|malware"

# 提取内存中的文件
python vol.py -f memory.raw windows.dumpfiles --virtaddr 0xFFFFAB001234
python vol.py -f memory.raw windows.dumpfiles --pid 4520

# 提取进程可执行文件
python vol.py -f memory.raw windows.pslist --pid 4520 --dump
```

### 5.3 内存取证实战场景

```
场景1: 恶意代码检测
步骤:
1. pslist + pstree → 查找可疑进程
2. malfind → 检测注入代码
3. dumpfiles → 提取恶意文件
4. netscan → 检查C2连接
5. cmdline → 查看进程命令行
6. handles → 检查打开的文件和资源

场景2: 凭据提取
步骤:
1. hashdump → 提取NTLM哈希
2. lsadump → 提取LSA密钥
3. clipboard → 提取剪贴板内容
4. hashdump --lsa → 提取LSASS中的凭据

场景3: 网络连接恢复
步骤:
1. netscan → 所有TCP/UDP连接
2. 结合进程PID对应到具体进程
3. 检查连接状态(LISTEN/ESTABLISHED)
4. 匹配威胁情报(已知C2 IP/域名)

场景4: 注入检测
步骤:
1. malfind → 扫描所有进程的注入代码
2. 检查 RWX 私有内存区域
3. 提取注入代码进行逆向分析
4. 对比合法DLL加载情况
```

## 六、磁盘取证

### 6.1 磁盘镜像

```bash
# dd 镜像（传统方式）
dd if=/dev/sda of=disk_image.dd bs=4M conv=sync,noerror status=progress

# 计算哈希
md5sum /dev/sda > disk_image.dd.md5
sha256sum /dev/sda > disk_image.dd.sha256

# AFF4 格式（高级取证格式）
# 支持压缩、加密、元数据
# 使用 LogTom或 dcfldd

# dcfldd（支持实时哈希）
dcfldd if=/dev/sda of=disk_image.dd hash=sha256 hashlog=hash.txt bs=4M

# FTK Imager (Windows)
# GUI 工具，支持多种格式转换
# 创建取证镜像 -> 选择来源 -> 选择格式(DD/E01) -> 计算
```

### 6.2 Autopsy / The Sleuth Kit 分析

```bash
# The Sleuth Kit 命令行工具

# 查看分区信息
mmls disk_image.dd

# 输出示例:
# DOS Partition Table
# Start: 0
# Slot    Start       End         Length      Description
# 00      0000000000  0000000000  0000000000  Primary Table
# 01:     2048        209715199   209713152   NTFS (0x07)

# 列出文件系统中的文件
fls -r disk_image.dd  # 递归列出
fls -r -d disk_image.dd  # 包含已删除文件

# 获取文件元数据
istat disk_image.dd 1234  # inode 1234

# 提取文件
icat disk_image.dd 1234 > extracted_file.exe

# 时间线分析
fls -r -m / disk_image.dd > timeline.body
mactime -b timeline.body > timeline.csv
```
