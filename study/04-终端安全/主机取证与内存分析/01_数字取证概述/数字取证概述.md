# 数字取证概述

### 1.1 数字取证基本原则

数字取证是运用科学方法对电子证据进行识别、收集、保全、分析和呈现的过程，遵循以下核心原则：

| 原则 | 说明 | 实践要求 |
|------|------|----------|
| 不修改原则 | 不改变原始证据的任何数据 | 写阻断器、只读挂载 |
| 可重复性 | 同一方法应得到同一结果 | 详细记录操作步骤 |
| 链式保管 | 证据从收集到呈堂全程可追踪 | 证据标签+交接记录 |
| 合规性 | 遵循法律法规和取证标准 | 符合 RFC 3227 等规范 |
| 时效性 | 易失性数据优先采集 | 按易失性等级排序 |

**证据采集优先级（RFC 3227 顺序）**：

```
易失性从高到低:

1. CPU 缓存和寄存器          ← 最易丢失，几乎无法采集
2. ARP 表、路由表             ← 网络状态信息
3. 内存（RAM）               ← 关机即丢失，最高优先级
4. 临时文件系统/swap          ← 运行时数据
5. 正在运行的进程             ← 进程信息、网络连接
6. 网络连接状态               ← 当前活动连接
7. 登录用户信息               ← 当前登录会话
8. 系统日志                   ← 持久化但可能被覆盖
9. 文件系统                   ← 持久化存储
10. 远程日志/备份             ← 离线存储
```

### 1.2 证据保全

```
证据保全操作流程:

1. 拍照记录现场
   ├── 设备外观照片
   ├── 屏幕显示内容
   ├── 连接线缆状态
   └── 周围环境

2. 证据标识
   ├── 唯一证据编号（如 EV-2026-001）
   ├── 采集时间（精确到秒）
   ├── 采集人签名
   ├── 设备型号和序列号
   └── 存储介质容量和哈希值

3. 写阻断保护
   ├── 硬件写阻断器（推荐）
   └── 软件只读挂载

4. 哈希校验
   ├── 采集后立即计算 MD5/SHA-256
   ├── 记录原始哈希值
   └── 分析完成后再次校验确认未修改

5. 链式保管记录
   ├── 每次交接记录时间和人员
   ├── 存储环境（温度、湿度）
   └── 任何操作都需记录
```

```bash
# 证据哈希校验示例
# 计算磁盘镜像的哈希值
md5sum disk_image.dd
sha256sum disk_image.dd

# 输出示例:
# a1b2c3d4e5f6...  disk_image.dd  (MD5)
# 1234abcd...      disk_image.dd  (SHA-256)
```
