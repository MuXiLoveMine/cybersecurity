# 反调试与反分析技术

### 2.1 常见反调试手法

**API级反调试**

```
1. IsDebuggerPresent（Kernel32.dll）
   - 检查PEB.BeingDebugged标志
   - 返回TRUE表示有调试器附加
   - 最常见也最简单的反调试

2. CheckRemoteDebuggerPresent（Kernel32.dll）
   - 检查是否有远程调试器附加
   - 比IsDebuggerPresent覆盖面更广
   - 内部调用NtQueryInformationProcess

3. NtQueryInformationProcess（Ntdll.dll）
   - ProcessDebugPort（0x07）：返回调试端口
   - ProcessDebugObjectHandle（0x1E）：调试对象句柄
   - ProcessDebugFlags（0x1F）：调试标志
   - NoDebugInherit（0x1E）：更隐蔽的检查
```

**PEB检查**

```
进程环境块（PEB）中包含调试相关字段：

BeingDebugged（PEB偏移0x02）：
- 直接读取PEB地址（FS:[0x30] x86 / GS:[0x60] x64）
- 绕过IsDebuggerPresent的Hook

NtGlobalFlag（PEB偏移0x68 x86 / 0xBC x64）：
- 调试器启动进程时会设置特定标志位
- FLG_HEAP_ENABLE_TAIL_CHECK (0x10)
- FLG_HEAP_ENABLE_FREE_CHECK (0x20)
- FLG_HEAP_VALIDATE_PARAMETERS (0x40)
- 这三个标志同时被设置时 = 被调试

NtHeap（堆调试标志）：
- 调试器创建的堆有特殊标志
- 检查ProcessHeap（PEB偏移0x18）的Flags字段
- 正常值0x02，调试时为0x40000000+（含HEAP_GROWABLE等）
```

**时间检测**

```
利用调试器暂停导致的执行时间异常：

1. rdtsc指令（汇编）
   - 读取CPU时间戳计数器
   - 两次rdtsc之间执行一段代码
   - 时间差远大于正常值 → 被调试（单步执行）

   示例逻辑：
   rdtsc → 保存eax/edx
   执行若干指令
   rdtsc → 保存eax/edx
   比较两次差值，超过阈值则判定被调试

2. GetTickCount / GetTickCount64
   - 获取系统启动后的毫秒数
   - 在关键代码前后调用
   - 时间差过大 → 被调试

3. QueryPerformanceCounter
   - 高精度计时器
   - 精度比GetTickCount更高
   - 更难绕过

4. timeGetTime（Winmm.dll）
   - 另一种计时方式
   - 多种计时API交叉验证
```

**硬件断点检测**

```
硬件断点利用CPU调试寄存器（DR0-DR7）：

检测方法：
1. 读取DR7寄存器判断是否设置断点
   - 通过SEH异常触发获取DR寄存器
   - 设置DR0=地址，执行到该地址时触发异常
   - 如果异常被调试器拦截 → 被调试

2. 检测单步执行（Trap Flag）
   - 设置EFLAGS的TF位
   - 每条指令后触发INT 1异常
   - 如果异常处理程序未被正常调用 → 被调试

3. 代码校验和
   - 计算自身代码段校验和
   - 调试器设置软件断点会修改INT 3（0xCC）
   - 校验和不匹配 → 被下断点
```

**调试器窗口检测**

```
通过查找常见调试器和分析工具的窗口：

检测的窗口标题：
- "OLLYDBG" / "OllyDbg"
- "x64dbg" / "x32dbg"
- "IDA" / "IDA Pro"
- "WinDbg"
- "Immunity Debugger"
- "IDA - Disassembly"

API调用：
  FindWindowA / FindWindowW（查找窗口标题）
  FindWindowExA / FindWindowExW
  EnumWindows（枚举所有窗口）

也可检测进程名：
  CreateToolhelp32Snapshot + Process32First/Next
  查找 "ollydbg.exe"、"x64dbg.exe"、"ida.exe" 等
```

### 2.2 反虚拟机技术

```
恶意代码检测是否运行在虚拟机中，以逃避沙箱分析：

1. CPUID指令检测
   - CPUID with EAX=0x40000000
   - VMware返回 "VMwareVMware"
   - Hyper-V返回 "Microsoft Hv"
   - VirtualBox返回 "VBoxVBoxVBox"

2. MAC地址检测
   - VMware：00:0C:29 / 00:50:56 / 00:05:69
   - VirtualBox：08:00:27
   - Hyper-V：00:15:5D
   - 通过获取网卡MAC并匹配前缀

3. 注册表键检测
   - VMware：
     HKLM\HARDWARE\DESCRIPTION\System\BIOS
     "SystemManufacturer" = "VMware, Inc."
   - VirtualBox：
     HKLM\SOFTWARE\Oracle\VirtualBox Guest Additions
   - 通用：
     HKLM\SYSTEM\CurrentControlSet\Services\VBoxGuest
     HKLM\SYSTEM\CurrentControlSet\Services\vmhgfs

4. 进程/文件检测
   - VMware：vmtools.exe、vmwaretray.exe
   - VirtualBox：VBoxService.exe、VBoxTray.exe
   - 文件：C:\Program Files\VMware\...
   - 驱动：VBoxGuest.sys、vmhgfs.sys

5. 硬件特征检测
   - CPU核心数（沙箱通常1-2核）
   - 内存大小（沙箱通常1-2GB）
   - 磁盘大小（沙箱通常较小）
   - 串口号/USB设备数量
```

### 2.3 反沙箱技术

```
沙箱通常运行时间有限（几分钟），恶意代码利用此限制：

1. 延时执行
   - 调用Sleep()长时间等待（如5分钟）
   - 大量无意义循环消耗时间
   - 时间炸弹（等待特定日期才执行）
   - 多层嵌套Sleep

2. 用户交互检测
   - 检测鼠标移动（GetCursorPos连续比较）
   - 检测鼠标点击（GetAsyncKeyState）
   - 检测键盘输入
   - 检测窗口移动/大小调整
   - 沙箱通常无真实用户交互

3. 系统资源检测
   - CPU核心数 < 4 → 沙箱
   - 内存 < 3GB → 沙箱
   - 磁盘空间 < 60GB → 沙箱
   - 最近文档数量少 → 沙箱

4. 最近文件检测
   - 检查Recent文件夹是否为空
   - 检查Prefetch目录文件数量
   - 检查用户文档目录是否有文件
   - 真实系统通常有大量历史文件

5. 域名/网络环境检测
   - 检查是否在已知的分析域名环境中
   - 检测inetsim/fakedns的响应特征
```

### 2.4 绕过方法

**ScyllaHide / x64dbg反反调试插件**

```
ScyllaHide：
- x64dbg/x32dbg的插件
- 自动Hook所有反调试API
  - IsDebuggerPresent → 返回FALSE
  - CheckRemoteDebuggerPresent → 返回FALSE
  - NtQueryInformationProcess → 清除调试标志
- 修改PEB中的BeingDebugged和NtGlobalFlag
- 处理堆调试标志
- 支持自定义Hook规则

x64dbg内置反反调试：
- Options → Preferences → Anti-anti-debug
- 自动处理常见反调试
```

**Frida绕过**

```javascript
// Frida绕过IsDebuggerPresent示例
Interceptor.attach(Module.getExportByName('kernel32.dll', 'IsDebuggerPresent'), {
    onLeave: function(retval) {
        retval.replace(0);  // 强制返回FALSE
    }
});

// 绕过CheckRemoteDebuggerPresent
Interceptor.attach(Module.getExportByName('kernel32.dll', 'CheckRemoteDebuggerPresent'), {
    onLeave: function(retval) {
        retval.replace(1);  // 返回成功但无调试器
    }
});

// 绕过Sleep延时
Interceptor.attach(Module.getExportByName('kernel32.dll', 'Sleep'), {
    onEnter: function(args) {
        args[0] = ptr(0);  // 将等待时间改为0
    }
});

// 绕过时间检测（GetTickCount）
Interceptor.attach(Module.getExportByName('kernel32.dll', 'GetTickCount'), {
    onLeave: function(retval) {
        // 返回递增的正常时间值
    }
});
```

**沙箱配置修改**

```
通过修改沙箱环境欺骗恶意代码：

1. 反虚拟机绕过
   - 修改CPUID响应（定制hypervisor）
   - 修改MAC地址为真实厂商前缀
   - 删除VMware Tools/VBox Guest Additions
   - 修改注册表中的虚拟机特征键

2. 反沙箱绕过
   - 增加CPU核心数和内存
   - 模拟用户交互（鼠标移动脚本）
   - 预填充Recent文件夹和Prefetch
   - 延长沙箱超时时间（5分钟→30分钟）

3. 时间加速
   - Hook Sleep/gettimeofday加速时间
   - Cuckoo的clock manipulator模块
```
