# 恶意代码分析方法论回顾与进阶

### 1.1 分析方法论体系

恶意代码分析遵循"先静态、后动态、相互验证"的方法论。基础篇已覆盖PE结构识别、字符串提取、导入表查看和基本动态监控。进阶分析需要在每个维度上深入，并能够应对反分析技术。

```
进阶分析路线：
1. 快速分类 → 文件特征/哈希/查壳/熵值
2. 静态深挖 → PE结构深入/导入表交叉分析/字符串语境分析/反汇编
3. 动态深挖 → API Hook/文件系统监控/注册表监控/网络全流量捕获
4. 沙箱验证 → 自动化分析 + 人工交互触发
5. 对抗分析 → 反调试绕过/脱壳/反混淆
6. 情报关联 → IOC提取/家族归因/C2基础设施追踪
```

### 1.2 静态分析进阶

**PE结构深入分析**

PE（Portable Executable）文件是Windows平台最核心的恶意代码载体。进阶分析需要关注以下深层结构：

```
关键PE结构字段及分析意义：

DOS Header → e_lfanew（PE头偏移，被篡改可阻碍解析器）
File Header → TimeDateStamp（编译时间，用于时间线归因）
              NumberOfSections（节数量异常可能表示加壳）
              Characteristics（DLL属性/可执行属性）
Optional Header → AddressOfEntryPoint（OEP，入口点）
                  ImageBase（镜像基址，ASLR影响）
                  DataDirectory[LOAD] → 绑定导入表
                  DataDirectory[TLS]  → TLS回调函数（隐藏执行点）
Sections → .text/.data/.rdata/.rsrc/.tls
           异常节名（UPX0/UPX1/.vmp0/.themida）暗示加壳
           可写且可执行的节 → 可疑（自修改代码）
           节的VirtualSize与RawSize差异 → 可能被压缩/填充

TLS回调函数：
- 在入口点（OEP）之前执行
- 很多壳和恶意代码利用TLS回调进行反分析
- 分析时必须检查TLS目录，不能只看OEP
```

**导入表交叉分析**

基础篇列出了可疑API分类，进阶分析关注API的组合模式和行为推断：

```
组合模式分析示例：

模式A（进程注入）：
  OpenProcess + VirtualAllocEx + WriteProcessMemory
  + CreateRemoteThread → 经典DLL注入

模式B（进程镂空/Hollowing）：
  CreateProcess(SUSPENDED) + ZwUnmapViewOfSection
  + VirtualAllocEx + WriteProcessMemory + SetThreadContext
  + ResumeThread → 进程镂空

模式C（凭据窃取）：
  OpenProcessToken + AdjustTokenPrivileges
  + RegOpenKeyEx(SAM) + LsaCallAuthenticationPackage → Mimikatz风格

模式D（反调试组合）：
  IsDebuggerPresent + NtQueryInformationProcess
  + GetTickCount + FindWindow("OLLYDBG") → 多层反调试

模式E（勒索加密）：
  FindFirstFile/FindNextFile + CryptEncrypt/CryptGenKey
  + WriteFile + DeleteFile → 文件遍历+加密
```

**字符串语境分析**

基础篇关注字符串的字面含义，进阶分析需要从字符串的上下文和编码方式中挖掘更多信息：

```
进阶字符串分析维度：

1. 编码识别
   - ASCII vs Unicode（编译器/语言推断）
   - Base64/Base32 → 解码后重新分析
   - ROT13/Caesar → 简单偏移解码
   - XOR编码 → 需要找到异或密钥

2. 语境关联
   - 字符串在反汇编中的引用位置（xref）
   - 字符串前后的API调用（如CryptDecrypt引用特定字符串→可能是密钥）
   - 字符串在资源段还是代码段

3. 结构化数据提取
   - 配置块解析（C2地址列表、加密密钥、互斥体名）
   - JSON/XML/INI格式的内嵌配置
   - 硬编码的PE文件（内嵌DLL/Shellcode）

4. 语言与编译器特征
   - "Microsoft Visual C++" / "Go build" / "Rust" / ".NET"
   - 编译器版本可缩小样本归因范围
```

### 1.3 动态分析进阶

**API监控（API Hooking）**

```
API监控工具与技术：

1. API Monitor
   - 实时监控API调用序列和参数
   - 可过滤特定DLL/函数
   - 显示调用栈和返回值

2. Frida（动态插桩框架）
   - 跨平台支持（Windows/Linux/macOS/Android）
   - JavaScript脚本动态Hook任意函数
   - 可在运行时修改参数和返回值
   - 绕过反调试能力强

3. Detours / EasyHook
   - 编程式API Hook
   - 可自定义Hook逻辑

关键监控API类别：
- 内存操作：VirtualAlloc/VirtualProtect（Shellcode解密）
- 进程操作：CreateProcess/OpenProcess/CreateRemoteThread
- 文件操作：CreateFile/WriteFile/DeleteFile（勒索/释放）
- 注册表：RegSetValueEx（持久化）
- 网络：InternetConnect/socket/connect（C2通信）
- 加密：CryptEncrypt/CryptGenKey（勒索加密）
- 服务：CreateService/StartService（持久化/驱动加载）
```

**文件系统监控**

```
工具：Sysinternals Process Monitor (ProcMon)

过滤策略：
- Process Name = malware.exe → 该进程所有文件操作
- Operation = WriteFile → 仅写操作（勒索加密检测）
- Operation = CreateFile + Result = NAME NOT FOUND → 探测行为
- Path contains "AppData" → 常见恶意软件释放路径
- Path contains "Temp" → 临时目录释放

文件系统行为分类：
- 释放（Drop）：创建新可执行文件/DLL
- 修改（Modify）：感染已有文件/修改配置
- 删除（Delete）：删除备份/日志/安全工具
- 遍历（Enumerate）：FindFirstFile/FindNextFile
- 映射（Map）：CreateFileMapping/MapViewOfFile
```

**注册表监控**

```
关键监控位置：

持久化：
- HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run
- HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run
- HKLM\SYSTEM\CurrentControlSet\Services（服务创建）
- HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options（映像劫持）
- HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon（Userinit/Shell）

配置存储：
- HKCU\SOFTWARE\<随机名>（配置数据隐藏）
- HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Environment

防御规避：
- 禁用安全工具的注册表键
- 修改Windows Defender设置
- HKLM\SOFTWARE\Policies\Microsoft\Windows Defender
```

**网络监控**

```
网络监控层次：

1. DNS层
   - 工具：Wireshark DNS过滤 / Sysmon Event ID 22
   - 关注：DGA域名、异常TLD、TXT记录异常

2. HTTP/HTTPS层
   - 工具：Fiddler / Burp Suite / mitmproxy
   - 关注：User-Agent异常、POST数据编码、Cookie滥用
   - HTTPS拦截需要安装代理CA证书

3. TCP/UDP层
   - 工具：Wireshark / tcpdump / NetCat
   - 关注：非标准端口、固定大小心跳包、长连接

4. 全流量捕获
   - 工具：Wireshark（pcap）/ NetworkMiner（pcap分析）
   - 建议：分析环境配置端口镜像或TAP
```

### 1.4 沙箱分析

**Cuckoo Sandbox**

```
Cuckoo Sandbox 是最流行的开源自动化恶意软件分析系统。

核心架构：
- Cuckoo Host（管理节点）：任务调度、报告生成
- Analysis VM（分析虚拟机）：运行恶意样本
- Network：支持模拟网络（inetsim/fakedns）或真实网络

分析能力：
- 进程行为追踪（API Hook）
- 文件系统操作记录
- 注册表操作记录
- 网络流量捕获（pcap）
- 内存dump
- 截图
- Cuckoo Signatures（特征签名匹配）

进阶定制：
- 自定义分析包（package）适配特殊文件类型
- 自定义YARA规则在内存中扫描
- 集成调试器获取更深级行为
- 配置反反分析插件
```

**Dragonbreaker**

```
Dragonbreaker 是一个反反调试的动态分析工具。

特点：
- 针对反调试/反虚拟机/反沙箱技术设计
- 自动Hook反调试API并返回正常值
- 支持时间加速（绕过Sleep延时检测）
- 可与Cuckoo集成使用
```

**Joe Sandbox**

```
Joe Sandbox 是功能强大的商业沙箱。

特点：
- 深层行为分析（数百个行为分类）
- 集成威胁情报（域名/URL/IP信誉）
- 多维度评分（恶意度、风险度）
- 支持多种文件类型和平台
- 提供详细的网络流量分析和协议解析
- 支持深度反反分析（反反调试、反反虚拟机）
```

### 1.5 分析环境隔离与安全

```
安全分析环境搭建原则：

1. 物理隔离
   - 分析机不连接生产网络
   - 使用独立网卡或禁用宿主网络
   - 可选：专用物理机（高威胁样本）

2. 虚拟化隔离
   - VMware/VirtualBox + 快照回滚
   - 分析后立即恢复快照
   - 禁用共享文件夹、拖拽、剪贴板

3. 网络控制
   - 使用inetsim/fakedns模拟网络
   - 或配置受控的互联网出口（代理+NAT）
   - INetSim：模拟HTTP/FTP/DNS等服务器

4. 环境硬化
   - 分析VM不安装敏感数据
   - 关闭 Guest → Host 的文件共享
   - 分析VM不登录任何真实账户

5. 操作安全
   - 不在宿主机直接打开样本
   - 分析环境定期重置
   - 高威胁样本使用离线物理机分析
```
