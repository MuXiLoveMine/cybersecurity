# C2通信协议分析

### 4.1 常见C2框架协议特征

**Cobalt Strike Beacon通信**

```
Cobalt Strike是最常用的红队和攻击者C2框架。

Beacon通信模式：
1. 回连（Beaconing）
   - 定期回连C2服务器
   - 间隔可配置（如60秒 + 10%抖动）
   - 使用HTTP/HTTPS或DNS协议

2. HTTP Beacon
   - GET请求获取任务
   - POST请求提交结果
   - URI格式：/dpixel /submit.php /api/等（可定制）
   - 默认User-Agent可被修改

3. DNS Beacon
   - 通过DNS查询的子域名编码数据
   - TXT/A记录返回C2指令
   - 极低流量，难以检测

4. SMB Beacon
   - 通过命名管道通信
   - 适用于内网横向移动
   - 管道名默认 \pipe\mssvc_XX（可定制）

5. Metadata编码
   - Beacon元数据使用AES加密
   - 可配置在Cookie/Body/URI中
   - 默认使用公钥加密阶段密钥

检测特征：
- 固定间隔的beaconing流量
- 特定大小的请求/响应
- 自签名或异常证书
- 异常的MIME类型或HTTP头顺序
```

**Metasploit Meterpreter通信**

```
Meterpreter是Metasploit的payload组件。

通信特征：
1. 反向TCP
   - 默认端口4444
   - 被害者主动连接攻击者
   - TLV（Type-Length-Value）协议

2. HTTP/HTTPS
   - 反向HTTP Meterpreter
   - URI模式：/4We5W2vT5gX9t3k0（随机）
   - 4字节校验头 + 加密payload

3. Meterpreter协议
   - TLV格式：Type(4) + Length(4) + Value
   - 常见Type：0x0000001（TLV_TYPE_COMMAND_ID）
   - 数据使用AES-256加密
   - 会话密钥通过DH交换协商

检测特征：
- 端口4444流量
- 特定的TLV头部模式
- 高频率的心跳包
- 固定大小的初始握手包
```

**隧道通信**

```
HTTP/HTTPS隧道：
- 数据封装在HTTP请求中
- 常见工具：Cobalt Strike HTTP/S、dnscat2 over HTTP
- 特征：大量POST请求、固定URL、异常编码数据

DNS隧道：
- 数据编码到DNS查询的子域名中
- 每个DNS查询携带一段数据（约63字节/标签，253字节/域名）
- C2响应通过TXT/CNAME/A记录返回
- 常见工具：dnscat2、Cobalt Strike DNS Beacon、IODINE

检测特征：
- 大量DNS查询（正常主机很少做高频DNS）
- 子域名异常长（>50字符）
- 子域名看起来像Base32/Base64编码
- TXT记录返回大量数据
- 查询的域名注册时间短/信誉低

ICMP隧道：
- 数据封装在ICMP payload中
- 常见工具：ICMP Shell、pingtunnel
- 利用ICMP echo request/reply的data字段

检测特征：
- ICMP包payload异常大（正常ping通常32-64字节）
- 高频率ICMP通信
- ICMP payload包含非ASCII数据
- 单一主机大量ICMP通信
```

### 4.2 流量分析与检测

**JA3/JA3S TLS指纹**

```
JA3：客户端TLS指纹
- 提取Client Hello中的关键字段
- SSLVersion + CipherSuites + Extensions + EllipticCurves + ECPointFormats
- 拼接后计算MD5

JA3S：服务端TLS指纹
- 提取Server Hello中的关键字段
- SSLVersion + CipherSuites + Extensions

用途：
- 识别C2工具的TLS库（如Cobalt Strike的M2后门指纹）
- 不依赖证书内容，即使证书变化也能识别
- 与已知恶意JA3指纹库比对

常见恶意JA3指纹：
- Cobalt Strike默认beacon: 6d5...（特征MD5）
- Metasploit: 多个已知指纹
- 不同恶意软件家族使用不同的TLS库 → 不同JA3
```

**Beaconing模式检测**

```
检测规律性回连行为：

检测维度：
1. 时间维度
   - 通信间隔的方差/标准差（低方差=规律性）
   - 抖动（Jitter）通常10-30%，完全规律=可疑
   - 统计周期分析（傅里叶变换找周期性）

2. 数据维度
   - 请求大小固定或模式固定
   - 响应大小模式（有命令时大，无命令时小）
   - 超时行为模式

3. 行为维度
   - 单一主机频繁连接同一外部IP
   - 连接后立即断开（短连接）
   - 只有出站流量（反向连接）

检测方法：
- RITA（Real Intelligence Threat Analysis）
- Beacon Analyzer（Zeek/Suricata日志分析）
- 机器学习异常检测
```

**DGA域名检测**

```
域名生成算法（DGA）生成大量随机域名作为C2备用地址：

DGA特征：
- 域名看起来随机无意义（如 xkqjfyt.com）
- 每日/每周生成不同的域名集
- 大量NXDOMAIN（域名不存在）响应
- 域名注册时间短（当天注册）

检测方法：
1. 词典检测
   - 元音/辅音比例异常
   - 字符熵值高
   - 不含常见英文单词

2. 流量分析
   - 大量NXDOMAIN响应（>某阈值）
   - 短时间大量不同域名解析到同一IP
   - 域名注册时间与查询时间接近

3. 机器学习
   - 基于域名特征的分类器
   - LSTM序列模型
   - 与已知DGA算法生成的域名比对
```

### 4.3 C2基础设施追踪

```
C2基础设施追踪与归因：

1. 基础设施收集
   - 被动DNS数据库（查询域名历史解析）
   - WHOIS信息（注册人/邮箱/电话）
   - SSL证书透明度日志（crt.sh）
   - IP反查（同一IP上的其他域名）

2. 关联分析
   - 相同SSL证书 → 同一运营者
   - 相同WHOIS信息 → 同一注册者
   - 相同IP段 → 同一主机商
   - 相同JA3指纹 → 同一C2工具

3. 威胁情报平台
   - VirusTotal（域名/IP信誉）
   - AlienVault OTX
   - ThreatConnect
   - Mandiant Advantage

4. 家族归因
   - C2协议特征匹配
   - 基础设施模式（域名格式、证书模式）
   - 与已知APT组织的基础设施重叠

实战建议：
- C2基础设施常快速更换（fast flux）
- 重点追踪长期稳定的锚点（证书指纹、注册模式）
- 结合恶意软件代码特征与基础设施特征双重归因
```
