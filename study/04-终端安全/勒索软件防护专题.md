# 勒索软件防护专题

> 勒索软件（Ransomware）已成为企业面临的最大网络安全威胁之一。本文档系统介绍勒索软件的演进历史、技术原理、防护体系、事件响应流程及解密资源，并提供Python检测脚本。仅用于安全教育和授权研究。

---

## 一、勒索软件概述

### 1.1 勒索软件演进史

```
第一代（1989-2009）：萌芽期
- 1989年AIDS Trojan：首个勒索软件，通过软盘分发，要求邮寄赎金
- 使用简单加密或文件锁定，技术不成熟
- 易于破解，影响有限

第二代（2010-2015）：加密勒索期
- 2009年融合比特币支付通道，解决匿名收款问题
- CryptoLocker（2013）：首次大规模使用RSA+AES加密
- CryptoWall系列：继承和改进CryptoLocker
- 强加密使得无备份情况下几乎无法解密
- 攻击范围从个人扩大到中小企业

第三代（2016-2019）：双重勒索期
- RaaS（勒索软件即服务）模式兴起
- 2019年Maze率先引入"双重勒索"：先窃取数据再加密
  不付赎金则公开泄露数据
- 攻击目标转向企业（更高赎金、更多数据）
- Ryuk、GandCrab、REvil等活跃

第四代（2020-至今）：三重勒索+供应链期
- 三重勒索：加密+数据泄露+DDoS攻击
- 供应链攻击：利用MOVEit、Kaseya等漏洞
- 针对关键基础设施（Colonial Pipeline事件）
- BlackCat/ALPHV用Rust编写，跨平台
- LockBit成为最活跃的RaaS家族

演进趋势总结：
1. 加密算法越来越强（AES+RSA/ECDH混合）
2. 勒索手段从单一加密→数据泄露→DDoS叠加
3. 商业模式从个人开发→RaaS专业化分工
4. 攻击目标从个人→中小企业→大型企业→关键设施
5. 攻击路径从钓鱼邮件→漏洞利用→供应链→RDP暴力破解
```

### 1.2 常见勒索软件家族

|------|----------|----------|------|

### 1.3 勒索软件即服务（RaaS）商业模式

```
RaaS（Ransomware-as-a-Service）将勒索软件运营拆分为两个角色：

开发者（RaaS运营者）：
- 开发和维护勒索软件
- 提供构建器（Builder）生成定制化勒索软件
- 运营泄露网站（Data Leak Site）
- 处理赎金支付和分配
- 提供技术支持和运营手册

附属者（Affiliates）：
- 负责入侵目标企业（初始访问+横向移动）
- 部署勒索软件执行加密
- 谈判和收款
- 不需要开发能力

利益分配：
- 赎金通常按比例分成（常见80%附属者/20%开发者）
- 高价值目标可能调整比例
- 部分RaaS按订阅收费

RaaS提供的工具和服务：
1. 勒索软件构建器（定制加密后缀/勒索信/C2）
2. 管理面板（受害者管理/谈判/状态跟踪）
3. 泄露网站（数据发布/倒计时）
4. 加密货币洗钱通道
5. 解密工具（支付后提供）
6. 运营手册（攻击指南/谈判技巧）

当前活跃的RaaS平台：
- LockBit（最活跃， affiliates众多）
- BlackCat/ALPHV
- Cl0p
- Akira
- Play
- 8Base
```

### 1.4 攻击路径分析

```
勒索软件常见初始入侵路径：

1. 钓鱼邮件（最常见）
   - 恶意附件（Office宏文档/ISO/IMG/ZIP/JS）
   - 恶意链接（仿冒登录页/恶意下载）
   - 鱼叉式定向钓鱼
   - 载荷：→ PowerShell → 下载器 → 勒索软件

2. RDP暴力破解
   - 暴力破解暴露的RDP端口（3389）
   - 凭据泄露后直接RDP登录
   - RDP会话劫持
   - 一旦获得RDP访问→部署勒索软件

3. VPN漏洞利用
   - Fortinet/Pulse/SonicWall等VPN设备漏洞
   - 凭据窃取后VPN接入
   - 未启用MFA的VPN

4. 供应链攻击
   - 利用MSP（托管服务提供商）作为跳板
   - 软件更新通道植入（Kaseya VSA）
   - 第三方软件漏洞（MOVEit Transfer）

5. 公开服务漏洞
   - Web应用漏洞（RCE/SQL注入/SSRF）
   - 邮件服务器漏洞（Exchange ProxyShell/ProxyLogon）
   - 文件服务器漏洞（SMB/FTP）

6. 双重勒索的数据泄露路径
   - ExWare（数据外泄工具）
   - 压缩+加密数据上传到云存储
   - 通过C2隧道传输

攻击链典型路径：
钓鱼邮件 → 宏文档执行 → PowerShell下载器 → Cobalt Strike Beacon
→ 横向移动 + 凭据窃取(Mimikatz) → 域控沦陷 → 部署勒索软件
→ 批量加密 + 数据外泄
```

## 二、勒索软件技术原理

### 2.1 加密机制分析

**混合加密方案**

```
现代勒索软件采用对称+非对称混合加密：

加密流程详解：

1. 密钥生成阶段
   - 生成随机AES密钥（每文件独立或全局共享）
   - 部分家族使用ChaCha20/Salsa20替代AES
   - 密钥长度：AES-256 / AES-128

2. 文件加密阶段
   - 使用对称密钥（AES/ChaCha20）加密文件内容
   - 对称加密速度快，适合大文件
   - 部分勒索软件只加密文件头部（加速）
   - 部分勒索软件加密全文件

3. 密钥保护阶段
   - 使用攻击者的RSA/ECDH公钥加密对称密钥
   - 加密后的密钥写入文件尾部或单独文件
   - RSA公钥可能硬编码在样本中或从C2获取

4. 不可逆性
   - 只有攻击者拥有RSA私钥
   - 对称密钥被RSA公钥加密后无法恢复
   - 即使分析出加密算法也无法解密

密钥管理方案对比：

方案A（每文件独立密钥）：
  生成AES Key → 加密文件 → RSA公钥加密AES Key → 写入文件
  优点：单个文件解密不影响其他文件
  缺点：性能开销大

方案B（会话密钥+文件密钥）：
  生成会话AES Key → 每文件生成随机IV/Nonce
  会话Key用RSA加密一次 → 每文件用会话Key+IV加密
  优点：性能好
  缺点：会话Key泄露则全部文件可解密

方案C（ECDH密钥协商）：
  生成临时密钥对 → 与硬编码公钥做ECDH协商 → 共享密钥
  优点：前向安全性更强
  使用者：REvil、BlackCat
```

**文件加密流程**

```
典型勒索软件加密执行流程：

1. 发现阶段
   - 遍历磁盘分区和目录
   - 枚举目标文件（文档/图片/数据库/备份）
   - 排除系统关键文件（保证系统可运行以显示勒索信）
   - 排除特定目录（Windows/system32等）

2. 加密阶段
   - 读取文件内容
   - 使用对称密钥加密文件
   - 写入加密后的内容（覆盖原文件或创建新文件）
   - 修改文件扩展名（添加家族特征后缀）
   - 将加密的密钥信息写入文件元数据

3. 勒索信放置
   - 在每个加密的目录放置勒索信
   - 修改桌面背景为勒索说明
   - 部分家族弹出勒索窗口

4. 清理阶段（防御规避）
   - 删除卷影副本（Shadow Copy）
   - 清理事件日志
   - 删除备份软件的备份
   - 终止可能干扰加密的进程（数据库/Office/安全软件）
   - 删除自身样本

常见加密文件后缀示例：
  .lockbit / .conti / .blackcat / .clop / .akira
  .encrypted / .locked / .crypto / .ransom
  家族特定后缀是快速识别家族的重要线索
```

**影子副本删除**

```
勒索软件删除卷影副本以阻止文件恢复：

常用命令：
  vssadmin delete shadows /all /quiet
  wmic shadowcopy delete
  wbadmin delete catalog -quiet
  bcdedit /set {default} recoveryenabled no
  bcdedit /set {default} bootstatuspolicy ignoreallfailures

防御/检测：
  - 监控vssadmin.exe的异常调用（Sysmon Event ID 1）
  - 监控wmic.exe的shadowcopy delete命令
  - 使用Windows事件转发（WEF）集中收集日志
  - 部署honeypot卷影副本（检测删除行为）

Sysmon检测规则示例（Event ID 1）：
  进程名: vssadmin.exe
  命令行包含: "delete shadows"
  → 高危告警
```

**安全模式重启**

```
部分勒索软件强制系统进入安全模式以绕过安全软件：

技术：
- 修改BCD（启动配置数据）进入安全模式
- 安全模式下安全软件通常不启动
- 安全模式下加密效率更高

相关命令：
  bcdedit /set safeboot network
  → 重启后进入安全模式
  → 安全软件不加载
  → 执行加密

案例：Snatch勒索软件使用此技术
```

### 2.2 常见IOC特征

```
勒索软件IOC（妥协指标）分类：

文件扩展名（加密后缀）：
  .lockbit     → LockBit
  .conti      → Conti
  .blackcat    → BlackCat/ALPHV
  .clop        → Cl0p
  .akira      → Akira
  .revil/.sodinokibi → REvil
  .ryuk       → Ryuk
  .encrypted  → 多种家族

勒索信文件名：
  Restore-My-Files.txt → LockBit
  READ_INSTRUCTIONS.txt → Conti
  ransom.txt / HOW_TO_RECOVER.txt → 多种家族
  readme.txt / READ_ME.txt → 多种家族
  HELP_DECRYPT_YOUR_FILES.txt → 多种家族

注册表键：
  HKCU\SOFTWARE\<家族名> → 配置/密钥存储
  HKLM\SYSTEM\CurrentSet\Services\<随机名> → 服务持久化
  修改 HKLM\SOFTWARE\...\Windows Defender → 禁用安全软件

网络通信：
  C2 IP/域名（部分家族从C2获取公钥）
  Tor隐藏服务地址（.onion）
  泄露网站域名（数据发布站点）
  加密货币钱包地址

进程行为：
  vssadmin delete shadows → 删除卷影副本
  bcdedit /set safeboot → 安全模式
  大量文件写入操作（加密）
  大量文件扩展名修改
  短时间内大量文件被修改（加密爆发期）

文件系统变化：
  每个目录出现勒索信文件
  文件扩展名批量变更
  文件内容被加密（高熵值）
  桌面背景被修改
```

## 三、勒索软件防护体系

### 3.1 备份策略

**3-2-1备份原则**

```
3-2-1原则是勒索软件防护的核心：

3 → 至少保留3份数据副本
    - 1份生产数据
    - 2份备份副本

2 → 使用至少2种不同存储介质
    - 例如：磁盘+磁带 / 本地磁盘+云存储
    - 防止单一介质故障导致全部丢失

1 → 至少1份异地/离线备份
    - 离线备份：不连接网络的备份介质
    - 异地备份：不同物理位置
    - 云备份：不可变（immutable）对象存储

进阶备份策略：

离线备份（Air-Gap）：
  - 备份完成后断开物理连接
  - 使用磁带/移动硬盘离线存储
  - 勒索软件无法触达离线介质
  - 缺点：恢复速度慢，需要人工操作

不可变备份（Immutable Backup）：
  - 使用支持WORM（Write Once Read Many）的存储
  - AWS S3 Object Lock / Azure Immutable Blob Storage
  - 备份数据在保留期内不可删除/不可修改
  - 即使攻击者获得管理员权限也无法加密
  - 是目前最有效的防勒索备份方案

快照备份：
  - 存储级快照（VSS/存储阵列快照）
  - 可快速恢复到特定时间点
  - 注意：卷影副本是勒索软件的首要删除目标
  - 需要保护快照不被删除（权限隔离）
```

**备份验证与恢复演练**

```
备份不只是"有"，更要"能用"：

定期验证：
  - 每月验证备份完整性
  - 随机抽取文件验证可读性
  - 验证备份不包含勒索软件（已被感染的数据）
  - 验证恢复后系统功能正常

恢复演练：
  - 每季度进行完整恢复演练
  - 模拟勒索软件攻击场景
  - 记录恢复时间（RTO）和恢复点目标（RPO）
  - 发现恢复流程中的问题和瓶颈
  - 训练IT团队的应急恢复能力

关键指标：
  RTO（Recovery Time Objective）：恢复时间目标
  RPO（Recovery Point Objective）：恢复点目标（可容忍的数据丢失量）
  勒索软件场景下RTO通常需要数小时到数天
```

### 3.2 终端防护

**EDR/XDR检测与拦截**

```
EDR/XDR是勒索软件防护的核心终端防护层：

检测能力：
  - 行为检测（非仅签名匹配）
  - 文件加密行为检测（短时间大量文件修改）
  - 卷影副本删除检测
  - 异常进程链检测（Office→PowerShell→下载器）
  - 内存扫描（无文件攻击检测）

拦截能力：
  - 进程终止（检测到加密行为时阻止）
  - 文件回滚（加密发生时自动恢复文件）
  - 自动隔离（断开网络连接）
  - 传播阻断（横向移动检测）

配置建议：
  - 开启勒索软件防护模块（Windows Defender的"受控文件夹访问"）
  - 配置行为检测规则（文件修改频率阈值）
  - 启用自动隔离（检测到威胁时自动断网）
  - 部署Sysmon收集详细行为日志

推荐EDR/XDR产品：
  - Microsoft Defender for Endpoint
  - CrowdStrike Falcon
  - SentinelOne Singularity
  - Trellix EDR
  - Sophos Intercept X
```

**应用白名单**

```
应用白名单只允许已知可信程序运行，阻止未授权的可执行文件：

AppLocker（Windows内置）：
  - 基于路径/发布者/哈希的规则
  - 限制可执行文件/脚本/Windows Installer/DLL
  - 阻止从Temp/AppData/Downloads目录执行
  - 组策略部署，审计模式→强制模式

WDAC（Windows Defender Application Control）：
  - 更强大的白名单方案
  - 基于代码签名策略
  - 内核级强制执行（无法被用户态绕过）
  - 支持智能安全图（ISG）自动信任
  - 与AppLocker互补使用

关键白名单规则：
  1. 阻止从用户可写目录执行EXE/DLL
     %AppData%\* / %Temp%\* / %Downloads%\*
  2. 阻止Office应用生成子进程
     阻止 WINWORD.EXE / EXCEL.EXE → powershell.exe/cmd.exe
  3. 阻止LOLBins的异常使用
     certutil.exe /bitsadmin.exe /mshta.exe 异常调用
  4. 只允许签名可信的程序执行
```

**宏安全策略**

```
Office宏是勒索软件最常见的投递载体之一：

宏安全配置建议：
  1. 禁用所有宏（最安全）
     - GPO: 禁用所有宏而不通知
     - 适合不需要宏的部门

  2. 禁用互联网来源的宏
     - MOTW（Mark of the Web）标记
     - 来自互联网的文档自动禁用宏
     - Windows/Office默认行为（2022年后）

  3. 仅允许受信任位置的宏
     - 将需要宏的文档放在受信任位置
     - 其他位置的宏全部禁用

  4. 阻止Office生成子进程
     - Attack Surface Reduction（ASR）规则
     - "阻止Office应用程序创建子进程"
     - 阻止 Office → PowerShell/cmd 的攻击链

ASR规则配置（通过Defender GPO）：
  D4F940AB-... → 阻止Office应用创建子进程
  3B576869-... → 阻止Office应用创建子进程（增强）
  75668C1C-... → 阻止Office应用注入其他进程
  BE9BA2D9-... → 阻止可执行文件运行除非满足普及度/年龄/信任标准
```

**LOLBins利用防护**

```
通过ASR规则和Sysmon监控限制LOLBins滥用：

关键ASR规则：
  - 阻止certutil.exe下载URL内容
  - 阻止WMI事件订阅持久化
  - 阻止PSExec的远程执行
  - 阻止从USB运行不受信任的进程
  - 阻止凭据窃取（lsass.exe访问）

Sysmon监控配置：
  - Event ID 1：进程创建（记录命令行）
  - Event ID 3：网络连接（监控异常外连）
  - Event ID 7：镜像加载（监控DLL加载）
  - Event ID 8：远程线程创建（注入检测）
  - Event ID 11：文件创建（监控勒索信/释放）
  - Event ID 22：DNS查询（监控DGA/隧道）
```

### 3.3 网络防护

**网络分段**

```
网络分段阻止勒索软件在内网横向传播：

分段原则：
  1. 将网络按功能/安全级别分段
     - 用户网络 / 服务器网络 / 管理网络 / IoT网络
     - 生产网络 / 测试网络 / DMZ

  2. VLAN + 防火墙策略
     - 不同VLAN间通过防火墙ACL控制
     - 默认拒绝（Default Deny）策略
     - 仅开放必要端口和协议

  3. 关键资产隔离
     - 域控/备份服务器/安全管理系统单独网段
     - 管理网络使用独立VLAN和跳板机
     - 备份网络与生产网络物理/逻辑隔离

  4. 微分段（主机级）
     - 使用分布式防火墙（如Windows Defender Firewall）
     - 主机间访问控制（Zero Trust网络）
     - 限制横向端口（SMB 445 / RDP 3389 / WMI 135）
```

**RDP安全**

```
RDP是勒索软件最常见的远程入侵通道之一：

RDP安全加固：
  1. 限制访问
     - 不要将RDP直接暴露到互联网
     - 使用VPN+跳板机访问RDP
     - 限制RDP源IP（防火墙白名单）
     - 修改默认端口（降低扫描效率，非根本解决）

  2. 启用MFA
     - Azure AD条件访问 / RD Gateway + MFA
     - 使用第三方MFA网关（Duo/Okta）
     - 强制所有RDP连接通过MFA验证

  3. 账户安全
     - 禁用Administrator重命名
     - 账户锁定策略（5次失败锁定30分钟）
     - 强密码策略（16位+复杂度）
     - 限制本地管理员组成员

  4. NLA（网络级别认证）
     - 启用NLA（要求认证后才建立会话）
     - 减少DoS和预认证攻击风险

  5. 会话安全
     - 限制并发会话数
     - 设置空闲超时自动断开
     - 记录RDP登录日志（Event ID 4624/4625）
```

**SMB安全**

```
SMB协议安全加固：

  1. 禁用SMBv1
     - SMBv1存在多个严重漏洞（永恒之蓝MS17-010）
     - Windows 10 1709+默认禁用
     - 检测：Get-SmbServerConfiguration | Select EnableSMB1Protocol
     - 禁用：Set-SmbServerConfiguration -EnableSMB1Protocol $false

  2. SMB签名
     - 启用SMB签名防止中继攻击
     - 要求所有SMB连接签名
     - GPO: Microsoft网络客户端：数字签名通信（始终要求）

  3. 限制SMB访问
     - 限制445端口的横向访问
     - 仅允许必要主机间的SMB通信
     - 防火墙规则限制源/目标

  4. SMB over QUIC
     - Windows Server 2022支持SMB over QUIC
     - 替代传统VPN的SMB访问
     - TLS加密传输
```

### 3.4 身份安全

**MFA强制部署**

```
多因素认证（MFA）是阻断凭据泄露后横向移动的关键：

MFA部署范围：
  - VPN远程访问
  - RDP远程桌面
  - 云服务（Office 365 / AWS Console / Azure Portal）
  - 管理员账户登录
  - 邮件系统（OWA / IMAP）

MFA方式选择：
  推荐顺序：
  1. FIDO2硬件密钥（最安全，抗钓鱼）
  2. Authenticator App + Push通知
  3. TOTP（Google Authenticator等）
  4. SMS短信（最弱，易被SIM劫持）

注意事项：
  - 避免仅依赖SMS短信MFA（SIM交换攻击）
  - 配置条件访问策略（设备合规性+位置+风险）
  - 监控MFA疲劳攻击（连续推送通知）
  - 对管理员账户强制MFA
```

**特权账户保护**

```
特权账户是勒索软件攻击的最高价值目标：

保护措施：
  1. 最小权限原则
     - 普通用户不授予本地管理员权限
     - 管理员使用专用管理账户（非日常登录账户）
     - 按需授权，定期审查权限

  2. PAM（特权访问管理）
     - 使用PAM解决方案（CyberArk / BeyondTrust）
     - 特权凭据存储在保险箱中，按需取出
     - 自动轮换密码
     - 会话录制和审计

  3. 分层管理模型（Tier Model）
     - Tier 0：域控级（最高权限）
     - Tier 1：服务器级
     - Tier 2：用户级
     - 不同层级间隔离管理，防止凭据跨层泄露

  4. 凭据保护
     - 启用LSA Protection（防止lsass.exe内存被读取）
     - Credential Guard（虚拟化安全保护凭据）
     - 禁止WDigest明文密码存储
```

**LAPS管理本地管理员密码**

```
LAPS（Local Administrator Password Solution）：

功能：
  - 自动随机化每台机器的本地管理员密码
  - 密码存储在Active Directory计算机对象属性中
  - 定期自动轮换密码
  - 按需查看密码（基于权限）

部署价值：
  - 消除"同一本地管理员密码在所有机器上使用"的问题
  - 阻止Pass-the-Hash横向移动
  - 即使一台机器沦陷，无法用同一密码访问其他机器

LAPS Next Gen（Windows LAPS）：
  - Windows 11 22H2+ / Server 2019+内置
  - 支持Azure AD和AD DS
  - 支持密码加密存储
  - 替代旧版Group Policy LAPS

配置要点：
  - 设置密码复杂度（12位+，大小写+数字+符号）
  - 设置密码轮换周期（如30天）
  - 限制密码查看权限（仅特定管理员组）
```

## 四、勒索软件事件响应

### 4.1 检测与隔离

```
勒索软件事件响应的第一步是止损：

检测信号：
  - EDR告警：大量文件修改行为 / vssadmin删除
  - 用户报告：文件无法打开 / 桌面背景变为勒索信
  - 备份系统告警：卷影副本被删除
  - 网络监控：异常大量数据外泄

立即隔离措施（按优先级）：

1. 网络断开（最高优先级）
   - 断开感染主机的网络连接（物理拔网线/交换机端口禁用）
   - 阻止勒索软件继续加密和横向传播
   - 阻止数据继续外泄
   - 注意：不要关闭电源（保留内存取证数据）

2. 终端隔离
   - 通过EDR远程隔离功能断开网络但保留连接
   - 或通过防火墙规则阻断该主机的所有出站流量
   - 保留主机运行状态用于取证

3. 账户冻结
   - 禁用可能在攻击中泄露的账户
   - 重置受影响用户的密码
   - 吊销可能被窃取的Kerberos票据

4. 范围控制
   - 评估是否有更多主机被感染
   - 对可能受影响的主机进行预防性隔离
   - 禁用RDP/SMB等横向移动通道
```

### 4.2 评估影响范围

```
评估勒索软件事件的影响范围：

受影响范围评估清单：

1. 感染主机范围
   - 哪些主机被加密？
   - 哪些主机被感染但未加密？
   - 哪些主机被用作跳板？
   - 域控制器是否被攻陷？

2. 数据影响范围
   - 哪些文件/目录被加密？
   - 哪些数据被外泄（双重勒索）？
   - 备份是否被加密/删除？
   - 关键业务系统是否受影响？

3. 攻击路径还原
   - 初始入侵点是什么？（钓鱼/RDP/VPN/供应链）
   - 横向移动路径是怎样的？
   - 哪些凭据被窃取/滥用？
   - 攻击者在内网停留了多长时间？

4. 勒索软件识别
   - 加密文件后缀是什么？
   - 勒索信内容分析（识别家族）
  - 勒索信中是否提供联系方式/Tor链接？

取证数据收集：
  - 内存dump（Volatility分析）
  - 磁盘镜像（用于深度取证）
  - 事件日志（Windows Event Log）
  - Sysmon日志
  - EDR检测记录
  - 网络流量pcap
  - 防火墙/VPN日志
```

### 4.3 勒索信分析

```
勒索信分析步骤：

1. 识别勒索软件家族
   - 通过勒索信文件名识别
   - 通过加密文件后缀识别
   - 通过勒索信内容和格式识别
   - 使用在线工具：ID Ransomware (id-ransomware.malwarehunterteam.com)
   - 使用NoMoreRansom项目（nomoreransom.org）的解密工具查询

2. 检查解密可能性
   - 查询是否有已知解密工具
   - 检查是否是已知有缺陷的版本
   - 检查加密文件结构是否有弱点
   - 咨询专业安全公司

3. 勒索信内容分析
   - 赎金金额和支付方式（比特币/门罗币）
   - 支付期限和威胁（数据泄露/涨价）
   - 联系方式（Tor网站/邮件/Tox ID）
   - 是否提及已窃取的数据（双重勒索）

4. 谈判评估
   - 是否值得谈判？（一般不建议支付）
   - 赎金是否在可承受范围？
   - 支付后是否能获得解密工具？（不保证）
   - 法律合规性（部分国家禁止向制裁实体支付赎金）
```

### 4.4 恢复策略

```
勒索软件事件恢复策略（按优先级）：

策略1：备份恢复（最佳方案）
  - 从离线/不可变备份恢复
  - 验证备份未被感染
  - 恢复后进行全面安全检查
  - 恢复关键业务系统优先

策略2：解密工具恢复
  - 检查NoMoreRansom项目是否有解密工具
  - 检查安全厂商发布的解密工具
  - 部分勒索软件因实现缺陷可解密
  - 即使有解密工具也要验证恢复文件完整性

策略3：谈判支付（最后手段，不推荐）
  - 通常不建议支付（助长犯罪）
  - 法律风险：部分国家/行业禁止支付
  - 运营风险：支付后可能不给解密工具/二次勒索
  - 如必须支付，通过专业谈判公司
  - 支付前确保解密工具有效（样本解密验证）

策略4：重建环境
  - 无法恢复时从干净镜像重建
  - 修复被利用的漏洞和弱点
  - 加强安全防护后再上线
  - 确保攻击者无法通过相同路径再次入侵

恢复注意事项：
  - 不要急于恢复，先确认攻击者已被清除
  - 检查是否有后门/持久化机制残留
  - 重置所有可能泄露的凭据
  - 修补被利用的漏洞
  - 恢复后加强监控（攻击者可能尝试二次攻击）
```

### 4.5 取证与溯源

```
勒索软件事件取证溯源：

1. 时间线重建
   - 确定初始入侵时间
   - 梳理攻击者在内网的活动时间线
   - 确定勒索软件执行时间
   - 确定数据外泄时间

2. 攻击路径分析
   - 初始入侵向量（钓鱼/RDP/VPN/漏洞）
   - 横向移动手法（Pass-the-Hash/RDP/WMI/SMB）
   - 权限提升手法（漏洞/配置错误/Mimikatz）
   - 持久化机制（服务/计划任务/注册表）

3. 溯源归因
   - 勒索软件家族识别
   - 与已知RaaS组织TTP对比
   - MITRE ATT&CK技术映射
   - 基础设施关联（C2 IP/域名/证书）

4. 数据外泄评估
   - 确定哪些数据被窃取
   - 评估数据泄露的法律影响
   - 评估对客户/合作伙伴的影响
   - 评估合规通知义务（GDPR/数据安全法等）

5. 取证报告
   - 事件概述
   - 详细攻击时间线
   - 影响范围评估
   - 改进建议
   - 合规要求文件
```

### 4.6 事后改进

```
勒索软件事件后的安全改进：

1. 漏洞修补
   - 修补被利用的漏洞
   - 全面漏洞扫描和修补
   - 建立漏洞管理流程

2. 安全加固
   - 部署缺失的安全控制
   - 加强身份认证（MFA覆盖）
   - 网络分段优化
   - 终端安全策略加固

3. 备份改进
   - 验证备份策略有效性
   - 增加离线/不可变备份
   - 增加恢复演练频率

4. 监控改进
   - 增强EDR检测规则
   - 增加勒索软件专项监控
   - 优化告警响应流程

5. 人员培训
   - 钓鱼邮件安全意识培训
   - IT团队应急响应培训
   - 管理层事件响应决策培训

6. 流程改进
   - 更新事件响应预案
   - 建立勒索软件专项响应流程
   - 完善外部联络机制（安全公司/执法机构/保险）
```

### 5.1 NoMoreRansom项目

```
NoMoreRansom（nomoreransom.org）：
- 由Europol、Intel Security、Kaspersky、荷兰国家警察联合发起
- 汇集各安全厂商开发的解密工具
- 完全免费
- 提供多种语言支持

使用方式：
1. 访问 nomoreransom.org
2. 使用"Crypto Sheriff"功能
3. 上传勒索信和一个加密文件

覆盖的勒索软件家族（持续增加）：
- 根据上传的特征匹配
- 包括多种已知有解密工具的家族
```

### 5.3 解密可行性判断

```
判断是否可以解密的检查清单：

1. 家族查询
   - 使用ID Ransomware在线工具识别家族
   - 查询NoMoreRansom是否有解密工具
   - 查询安全厂商是否发布过解密工具

2. 版本确认
   - 同一家族不同版本可能加密实现不同
   - 早期版本可能有缺陷可解密
   - 新版本通常使用更强加密

3. 加密实现分析
   - 密钥管理是否有缺陷（如硬编码密钥）
   - 是否使用对称加密且密钥可恢复
   - 是否有密钥留在本地（未正确删除）

4. 对称密钥恢复可能性
   - 部分勒索软件将加密密钥存储在本地
   - 通过内存取证可能恢复密钥
   - 如果加密前密钥曾存在于内存中

5. 离线密钥 vs 在线密钥
   - 离线密钥（无C2通信时使用硬编码密钥）→ 可能可解密
   - 在线密钥（从C2获取随机密钥）→ 几乎不可解密

结论：
   大多数现代勒索软件（LockBit/BlackCat/Conti等）使用在线随机密钥
   无已知解密工具，恢复依赖备份
   少数勒索软件因实现缺陷可解密
```

## 六、Python勒索软件检测脚本示例

### 6.1 勒索信特征检测脚本

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
勒索信特征检测脚本
扫描指定目录，检测已知勒索软件的勒索信文件
仅用于安全教育和授权研究
"""

import os
import re
from pathlib import Path


# 已知勒索信文件名模式
RANSOM_NOTE_PATTERNS = [
    # 文件名模式
    "restore-my-files.txt", "restore_files.txt",
    "read_instructions.txt", "read_me.txt", "readme.txt",
    "how_to_decrypt.txt", "how_to_recover.txt",
    "help_decrypt.txt", "help_recover.txt",
    "ransom.txt", "ransom_note.txt",
    "decryption_instructions.txt",
    "your_files_are_locked.txt",
    "recovery_key.txt",
    "!!!_readme_!!!.txt",
    "_readme_.txt",
    "info.txt", "note.txt",
    # 带家族特征
    "lockbit.txt", "conti.txt", "blackcat.txt",
    "clop_readme.txt", "akira_readme.txt",
]

# 勒索信内容关键词模式（多语言）
RANSOM_CONTENT_PATTERNS = [
    r"your files.*encrypt",       # 你的文件已被加密
    r"all.*files.*encrypt",
    r"to decrypt.*files",
    r"bitcoin|btc|monero|xmr",   # 加密货币
    r"\.onion",                    # Tor隐藏服务
    r"tor browser",
    r"ransom|payment|decrypt",   # 赎金/支付/解密
    r"your data.*stolen",         # 数据已窃取（双重勒索）
    r"leak.*data|publish.*data",
    r"private key|recovery key",
    r"deadline|countdown|timer", # 倒计时
]

# 加密文件后缀模式（常见勒索软件后缀）
ENCRYPTED_EXTENSIONS = [
    ".lockbit", ".conti", ".blackcat", ".clop", ".akira",
    ".revil", ".sodinokibi", ".ryuk", ".locky",
    ".encrypted", ".locked", ".crypto", ".enc",
    ".ransom", ".lockedby", ".crypted",
    ".encrypted_rsa", ".wcry", ".wnry",
]


def scan_ransom_notes(directory):
    """扫描目录中的勒索信文件"""
    found_notes = []
    found_encrypted = []
    found_by_content = []

    print("=" * 60)
    print(f"勒索信特征扫描: {directory}")
    print("=" * 60)

    file_count = 0
    for root, dirs, files in os.walk(directory):
        for filename in files:
            filepath = os.path.join(root, filename)
            file_count += 1

            # 检查文件名是否匹配已知勒索信
            filename_lower = filename.lower()
            for pattern in RANSOM_NOTE_PATTERNS:
                if pattern in filename_lower:
                    found_notes.append(filepath)
                    break

            # 检查文件后缀是否为已知加密后缀
            for ext in ENCRYPTED_EXTENSIONS:
                if filename_lower.endswith(ext):
                    found_encrypted.append(filepath)
                    break
```

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
文件熵值异常检测脚本
计算文件熵值，识别被加密的高熵值文件
仅用于安全教育和授权研究
"""

import os
import sys
import math
from collections import defaultdict


def calculate_entropy(filepath, max_size=1024 * 1024):
    """计算文件熵值（限制读取大小以提高性能）"""
    try:
        with open(filepath, 'rb') as f:
            data = f.read(max_size)
    except (PermissionError, OSError):
        return None

    if not data:
        return 0.0

    # 统计字节频率
    freq = defaultdict(int)
    for byte in data:
        freq[byte] += 1

    # 香农熵
    length = len(data)
    entropy = 0.0
    for count in freq.values():
        if count > 0:
            p = count / length
            entropy -= p * math.log2(p)

    return entropy


def is_likely_text(filepath):
    """判断文件是否为文本文件"""
    text_extensions = ['.txt', '.log', '.csv', '.json', '.xml',
                      '.ini', '.cfg', '.py', '.js', '.html',
                      '.md', '.bat', '.ps1', '.sh']
    ext = os.path.splitext(filepath)[1].lower()
    return ext in text_extensions


def scan_entropy_anomalies(directory, threshold=7.0, max_files=None):
    """扫描目录中熵值异常的文件"""
    print("=" * 60)
    print(f"文件熵值异常检测: {directory}")
    print(f"熵值阈值: {threshold} (高熵值可能表示加密)")
    print("=" * 60)

    high_entropy_files = []
    encrypted_candidates = []
    total_files = 0
    scanned = 0
    errors = 0

    for root, dirs, files in os.walk(directory):
        for filename in files:
            filepath = os.path.join(root, filename)
            total_files += 1

            # 跳过目录过多的情况
            if max_files and scanned >= max_files:
                continue

            entropy = calculate_entropy(filepath)
            if entropy is None:
                errors += 1
                continue
            scanned += 1

            # 文本文件高熵值 = 异常（文本文件熵值通常 < 5）
            if entropy >= threshold:
                ext = os.path.splitext(filename)[1].lower()
                if is_likely_text(filepath):
                    # 文本文件高熵值 → 极可疑
                    encrypted_candidates.append(
                        (filepath, entropy, "文本文件但熵值极高"))
                else:
                    high_entropy_files.append(
                        (filepath, entropy, ext))

    print(f"\n扫描文件总数: {total_files}")
    print(f"成功扫描: {scanned}")
    print(f"扫描失败: {errors}")

    if encrypted_candidates:
        print(f"\n[!!!] 极可疑 - 文本文件被加密 ({len(encrypted_candidates)}个)")
        print("  文本文件熵值正常应 < 5.0，高于7.0极可能被加密")
        for f, e, note in encrypted_candidates[:20]:
            print(f"  熵值={e:.4f} | {f}")
            print(f"         ({note})")

    if high_entropy_files:
        print(f"\n[!] 高熵值文件 ({len(high_entropy_files)}个)")
        print("  这些文件可能被加密或压缩")
        for f, e, ext in high_entropy_files[:20]:
            print(f"  熵值={e:.4f} | {ext or '(无后缀)'} | {f}")
        if len(high_entropy_files) > 20:
            print(f"  ... 共 {len(high_entropy_files)} 个")

    # 熵值分布统计
    print("\n--- 熵值分布统计 ---")
    if scanned > 0:
        ranges = [(0, 3, "低(正常文本)"), (3, 5, "中低(正常文件)"),
                  (5, 7, "中高(压缩/二进制)"), (7, 7.5, "高(可能加密)"),
                  (7.5, 8, "极高(很可能加密)")]
        # 重新扫描计算分布（简化：使用已收集数据）
        # 实际实现中可以在此循环中累计统计
        print(f"  扫描了 {scanned} 个文件")
        print(f"  高熵值(>{threshold}): {len(high_entropy_files) + len(encrypted_candidates)} 个")
        print(f"  异常比例: {(len(high_entropy_files) + len(encrypted_candidates)) / scanned * 100:.1f}%")

    # 建议
    if encrypted_candidates or (len(high_entropy_files) > 10):
        print("\n[建议] 检测到大量高熵值文件，可能正在发生文件加密")
        print("  1. 立即检查是否有活跃的勒索软件进程")
        print("  2. 检查最近创建的文件（勒索信）")
        print("  3. 断开网络连接并启动事件响应")


if __name__ == "__main__":
    if len(sys.argv) < 2:
        print("用法: python entropy_detector.py <目录路径> [熵值阈值]")
        sys.exit(1)

    directory = sys.argv[1]
    threshold = float(sys.argv[2]) if len(sys.argv) > 2 else 7.0
    scan_entropy_anomalies(directory, threshold)
```

```python
vssadmin删除行为检测脚本
分析Windows事件日志，检测卷影副本删除行为
仅用于安全教育和授权研究
"""

import re
import sys
import xml.etree.ElementTree as ET
from collections import defaultdict
from datetime import datetime


# 可疑命令模式
SUSPICIOUS_COMMANDS = [
    {
        "pattern": r"vssadmin.*delete.*shadow",
        "severity": "极高",
        "description": "vssadmin删除卷影副本（勒索软件常见行为）",

        "description": "禁用恢复模式",

        "severity": "高",
        "description": "修改启动状态策略（阻止恢复界面）",
    },
    {
        "pattern": r"vssadmin.*list\s+shadow",
        "severity": "中",
        "description": "枚举卷影副本（勒索软件侦察阶段）",

        "severity": "中",
        "description": "枚举VSS写入器（勒索软件侦察阶段）",
    },
]


def parse_sysmon_xml(filepath):
    """解析Sysmon导出的XML事件日志"""
    findings = []

    try:
        tree = ET.parse(filepath)
        root = tree.getroot()
    except ET.ParseError:
        print(f"[!] 无法解析XML文件: {filepath}")
        return findings
    except FileNotFoundError:
        print(f"[!] 文件不存在: {filepath}")
        return findings

    # 遍历事件
    for event in root:
        event_data = {}
        ns = {'ns': 'http://schemas.microsoft.com/win/2004/08/events/event'}

        event_id_elem = event.find('.//ns:EventID', ns)
        if event_id_elem is None:
            continue
        event_id = event_id_elem.text

        # 只处理进程创建事件（Event ID 1）
        if event_id != "1":
            continue

        # 提取EventData
        for data in event.findall('.//ns:Data', ns):
            name = data.get('Name', '')
            value = data.text or ''
            event_data[name] = value

        command_line = event_data.get('CommandLine', '')
        image = event_data.get('Image', '')
        utc_time = event_data.get('UtcTime', '')
        user = event_data.get('User', '')
        parent_image = event_data.get('ParentImage', '')

        if not command_line:
            continue

        # 检查可疑命令
        for rule in SUSPICIOUS_COMMANDS:
            if re.search(rule["pattern"], command_line, re.IGNORECASE):
                findings.append({
                    'time': utc_time,
                    'severity': rule["severity"],
                    'description': rule["description"],
                    'image': image,
                    'command': command_line[:200],
                    'parent': parent_image,
                    'user': user,
                })

    return findings


def parse_evtx_text(filepath):
    """解析文本格式的Windows事件日志（如wevtutil qe导出）"""
    findings = []

    with open(filepath, 'r', encoding='utf-8', errors='replace') as f:
        content = f.read()

    # 简化的文本解析：查找包含可疑命令的行
    for rule in SUSPICIOUS_COMMANDS:
        for match in re.finditer(rule["pattern"], content, re.IGNORECASE):
            # 获取上下文
            start = max(0, match.start() - 200)
            end = min(len(content), match.end() + 200)
            context = content[start:end].replace('\n', ' ')

            findings.append({
                'time': '未知',
                'severity': rule["severity"],
                'description': rule["description"],
                'image': '未知',
                'command': match.group(0)[:200],
                'parent': '未知',
                'user': '未知',
                'context': context[:200],
            })

    return findings


def analyze_log(filepath):
    """主分析函数"""
    print("=" * 60)
    print(f"卷影副本删除行为检测: {filepath}")
    print("=" * 60)

    # 根据文件类型选择解析方式
    if filepath.lower().endswith('.xml'):
        findings = parse_sysmon_xml(filepath)
    else:
        findings = parse_evtx_text(filepath)

    if not findings:
        print("\n[OK] 未检测到卷影副本删除行为")
        return

    print(f"\n[!] 检测到 {len(findings)} 条可疑事件")

    # 按严重程度排序
    severity_order = {"极高": 0, "高": 1, "中": 2, "低": 3}
    findings.sort(key=lambda x: severity_order.get(x['severity'], 99))

    # 统计
    severity_count = defaultdict(int)
    for f in findings:
        severity_count[f['severity']] += 1

    print("\n--- 严重程度统计 ---")
    for sev in ["极高", "高", "中", "低"]:
        if severity_count[sev]:
            print(f"  {sev}: {severity_count[sev]} 条")

    # 显示详情

        print(f"  进程: {f['image']}")
```
