# 勒索软件事件响应

### 4.1 检测与隔离

```
勒索软件事件响应的第一步是止损：

检测信号：
  - EDR告警：大量文件修改行为 / vssadmin删除
  - 用户报告：文件无法打开 / 桌面背景变为勒索信
  - 备份系统告警：卷影副本被删除
  - 网络监控：异常大量数据外泄

立即隔离措施（按优先级）：

1. 网络断开（最高优先级）
   - 断开感染主机的网络连接（物理拔网线/交换机端口禁用）
   - 阻止勒索软件继续加密和横向传播
   - 阻止数据继续外泄
   - 注意：不要关闭电源（保留内存取证数据）

2. 终端隔离
   - 通过EDR远程隔离功能断开网络但保留连接
   - 或通过防火墙规则阻断该主机的所有出站流量
   - 保留主机运行状态用于取证

3. 账户冻结
   - 禁用可能在攻击中泄露的账户
   - 重置受影响用户的密码
   - 吊销可能被窃取的Kerberos票据

4. 范围控制
   - 评估是否有更多主机被感染
   - 对可能受影响的主机进行预防性隔离
   - 禁用RDP/SMB等横向移动通道
```

### 4.2 评估影响范围

```
评估勒索软件事件的影响范围：

受影响范围评估清单：

1. 感染主机范围
   - 哪些主机被加密？
   - 哪些主机被感染但未加密？
   - 哪些主机被用作跳板？
   - 域控制器是否被攻陷？

2. 数据影响范围
   - 哪些文件/目录被加密？
   - 哪些数据被外泄（双重勒索）？
   - 备份是否被加密/删除？
   - 关键业务系统是否受影响？

3. 攻击路径还原
   - 初始入侵点是什么？（钓鱼/RDP/VPN/供应链）
   - 横向移动路径是怎样的？
   - 哪些凭据被窃取/滥用？
   - 攻击者在内网停留了多长时间？

4. 勒索软件识别
   - 加密文件后缀是什么？
   - 勒索信内容分析（识别家族）
  - 勒索信中是否提供联系方式/Tor链接？

取证数据收集：
  - 内存dump（Volatility分析）
  - 磁盘镜像（用于深度取证）
  - 事件日志（Windows Event Log）
  - Sysmon日志
  - EDR检测记录
  - 网络流量pcap
  - 防火墙/VPN日志
```

### 4.3 勒索信分析

```
勒索信分析步骤：

1. 识别勒索软件家族
   - 通过勒索信文件名识别
   - 通过加密文件后缀识别
   - 通过勒索信内容和格式识别
   - 使用在线工具：ID Ransomware (id-ransomware.malwarehunterteam.com)
   - 使用NoMoreRansom项目（nomoreransom.org）的解密工具查询

2. 检查解密可能性
   - 查询是否有已知解密工具
   - 检查是否是已知有缺陷的版本
   - 检查加密文件结构是否有弱点
   - 咨询专业安全公司

3. 勒索信内容分析
   - 赎金金额和支付方式（比特币/门罗币）
   - 支付期限和威胁（数据泄露/涨价）
   - 联系方式（Tor网站/邮件/Tox ID）
   - 是否提及已窃取的数据（双重勒索）

4. 谈判评估
   - 是否值得谈判？（一般不建议支付）
   - 赎金是否在可承受范围？
   - 支付后是否能获得解密工具？（不保证）
   - 法律合规性（部分国家禁止向制裁实体支付赎金）
```

### 4.4 恢复策略

```
勒索软件事件恢复策略（按优先级）：

策略1：备份恢复（最佳方案）
  - 从离线/不可变备份恢复
  - 验证备份未被感染
  - 恢复后进行全面安全检查
  - 恢复关键业务系统优先

策略2：解密工具恢复
  - 检查NoMoreRansom项目是否有解密工具
  - 检查安全厂商发布的解密工具
  - 部分勒索软件因实现缺陷可解密
  - 即使有解密工具也要验证恢复文件完整性

策略3：谈判支付（最后手段，不推荐）
  - 通常不建议支付（助长犯罪）
  - 法律风险：部分国家/行业禁止支付
  - 运营风险：支付后可能不给解密工具/二次勒索
  - 如必须支付，通过专业谈判公司
  - 支付前确保解密工具有效（样本解密验证）

策略4：重建环境
  - 无法恢复时从干净镜像重建
  - 修复被利用的漏洞和弱点
  - 加强安全防护后再上线
  - 确保攻击者无法通过相同路径再次入侵

恢复注意事项：
  - 不要急于恢复，先确认攻击者已被清除
  - 检查是否有后门/持久化机制残留
  - 重置所有可能泄露的凭据
  - 修补被利用的漏洞
  - 恢复后加强监控（攻击者可能尝试二次攻击）
```

### 4.5 取证与溯源

```
勒索软件事件取证溯源：

1. 时间线重建
   - 确定初始入侵时间
   - 梳理攻击者在内网的活动时间线
   - 确定勒索软件执行时间
   - 确定数据外泄时间

2. 攻击路径分析
   - 初始入侵向量（钓鱼/RDP/VPN/漏洞）
   - 横向移动手法（Pass-the-Hash/RDP/WMI/SMB）
   - 权限提升手法（漏洞/配置错误/Mimikatz）
   - 持久化机制（服务/计划任务/注册表）

3. 溯源归因
   - 勒索软件家族识别
   - 与已知RaaS组织TTP对比
   - MITRE ATT&CK技术映射
   - 基础设施关联（C2 IP/域名/证书）

4. 数据外泄评估
   - 确定哪些数据被窃取
   - 评估数据泄露的法律影响
   - 评估对客户/合作伙伴的影响
   - 评估合规通知义务（GDPR/数据安全法等）

5. 取证报告
   - 事件概述
   - 详细攻击时间线
   - 影响范围评估
   - 改进建议
   - 合规要求文件
```
