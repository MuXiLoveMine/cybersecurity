# 勒索软件防护体系

### 3.1 备份策略

**3-2-1备份原则**

```
3-2-1原则是勒索软件防护的核心：

3 → 至少保留3份数据副本
    - 1份生产数据
    - 2份备份副本

2 → 使用至少2种不同存储介质
    - 例如：磁盘+磁带 / 本地磁盘+云存储
    - 防止单一介质故障导致全部丢失

1 → 至少1份异地/离线备份
    - 离线备份：不连接网络的备份介质
    - 异地备份：不同物理位置
    - 云备份：不可变（immutable）对象存储

进阶备份策略：

离线备份（Air-Gap）：
  - 备份完成后断开物理连接
  - 使用磁带/移动硬盘离线存储
  - 勒索软件无法触达离线介质
  - 缺点：恢复速度慢，需要人工操作

不可变备份（Immutable Backup）：
  - 使用支持WORM（Write Once Read Many）的存储
  - AWS S3 Object Lock / Azure Immutable Blob Storage
  - 备份数据在保留期内不可删除/不可修改
  - 即使攻击者获得管理员权限也无法加密
  - 是目前最有效的防勒索备份方案

快照备份：
  - 存储级快照（VSS/存储阵列快照）
  - 可快速恢复到特定时间点
  - 注意：卷影副本是勒索软件的首要删除目标
  - 需要保护快照不被删除（权限隔离）
```

**备份验证与恢复演练**

```
备份不只是"有"，更要"能用"：

定期验证：
  - 每月验证备份完整性
  - 随机抽取文件验证可读性
  - 验证备份不包含勒索软件（已被感染的数据）
  - 验证恢复后系统功能正常

恢复演练：
  - 每季度进行完整恢复演练
  - 模拟勒索软件攻击场景
  - 记录恢复时间（RTO）和恢复点目标（RPO）
  - 发现恢复流程中的问题和瓶颈
  - 训练IT团队的应急恢复能力

关键指标：
  RTO（Recovery Time Objective）：恢复时间目标
  RPO（Recovery Point Objective）：恢复点目标（可容忍的数据丢失量）
  勒索软件场景下RTO通常需要数小时到数天
```

### 3.2 终端防护

**EDR/XDR检测与拦截**

```
EDR/XDR是勒索软件防护的核心终端防护层：

检测能力：
  - 行为检测（非仅签名匹配）
  - 文件加密行为检测（短时间大量文件修改）
  - 卷影副本删除检测
  - 异常进程链检测（Office→PowerShell→下载器）
  - 内存扫描（无文件攻击检测）

拦截能力：
  - 进程终止（检测到加密行为时阻止）
  - 文件回滚（加密发生时自动恢复文件）
  - 自动隔离（断开网络连接）
  - 传播阻断（横向移动检测）

配置建议：
  - 开启勒索软件防护模块（Windows Defender的"受控文件夹访问"）
  - 配置行为检测规则（文件修改频率阈值）
  - 启用自动隔离（检测到威胁时自动断网）
  - 部署Sysmon收集详细行为日志

推荐EDR/XDR产品：
  - Microsoft Defender for Endpoint
  - CrowdStrike Falcon
  - SentinelOne Singularity
  - Trellix EDR
  - Sophos Intercept X
```

**应用白名单**

```
应用白名单只允许已知可信程序运行，阻止未授权的可执行文件：

AppLocker（Windows内置）：
  - 基于路径/发布者/哈希的规则
  - 限制可执行文件/脚本/Windows Installer/DLL
  - 阻止从Temp/AppData/Downloads目录执行
  - 组策略部署，审计模式→强制模式

WDAC（Windows Defender Application Control）：
  - 更强大的白名单方案
  - 基于代码签名策略
  - 内核级强制执行（无法被用户态绕过）
  - 支持智能安全图（ISG）自动信任
  - 与AppLocker互补使用

关键白名单规则：
  1. 阻止从用户可写目录执行EXE/DLL
     %AppData%\* / %Temp%\* / %Downloads%\*
  2. 阻止Office应用生成子进程
     阻止 WINWORD.EXE / EXCEL.EXE → powershell.exe/cmd.exe
  3. 阻止LOLBins的异常使用
     certutil.exe /bitsadmin.exe /mshta.exe 异常调用
  4. 只允许签名可信的程序执行
```

**宏安全策略**

```
Office宏是勒索软件最常见的投递载体之一：

宏安全配置建议：
  1. 禁用所有宏（最安全）
     - GPO: 禁用所有宏而不通知
     - 适合不需要宏的部门

  2. 禁用互联网来源的宏
     - MOTW（Mark of the Web）标记
     - 来自互联网的文档自动禁用宏
     - Windows/Office默认行为（2022年后）

  3. 仅允许受信任位置的宏
     - 将需要宏的文档放在受信任位置
     - 其他位置的宏全部禁用

  4. 阻止Office生成子进程
     - Attack Surface Reduction（ASR）规则
     - "阻止Office应用程序创建子进程"
     - 阻止 Office → PowerShell/cmd 的攻击链

ASR规则配置（通过Defender GPO）：
  D4F940AB-... → 阻止Office应用创建子进程
  3B576869-... → 阻止Office应用创建子进程（增强）
  75668C1C-... → 阻止Office应用注入其他进程
  BE9BA2D9-... → 阻止可执行文件运行除非满足普及度/年龄/信任标准
```

**LOLBins利用防护**

```
通过ASR规则和Sysmon监控限制LOLBins滥用：

关键ASR规则：
  - 阻止certutil.exe下载URL内容
  - 阻止WMI事件订阅持久化
  - 阻止PSExec的远程执行
  - 阻止从USB运行不受信任的进程
  - 阻止凭据窃取（lsass.exe访问）

Sysmon监控配置：
  - Event ID 1：进程创建（记录命令行）
  - Event ID 3：网络连接（监控异常外连）
  - Event ID 7：镜像加载（监控DLL加载）
  - Event ID 8：远程线程创建（注入检测）
  - Event ID 11：文件创建（监控勒索信/释放）
  - Event ID 22：DNS查询（监控DGA/隧道）
```

### 3.3 网络防护

**网络分段**

```
网络分段阻止勒索软件在内网横向传播：

分段原则：
  1. 将网络按功能/安全级别分段
     - 用户网络 / 服务器网络 / 管理网络 / IoT网络
     - 生产网络 / 测试网络 / DMZ

  2. VLAN + 防火墙策略
     - 不同VLAN间通过防火墙ACL控制
     - 默认拒绝（Default Deny）策略
     - 仅开放必要端口和协议

  3. 关键资产隔离
     - 域控/备份服务器/安全管理系统单独网段
     - 管理网络使用独立VLAN和跳板机
     - 备份网络与生产网络物理/逻辑隔离

  4. 微分段（主机级）
     - 使用分布式防火墙（如Windows Defender Firewall）
     - 主机间访问控制（Zero Trust网络）
     - 限制横向端口（SMB 445 / RDP 3389 / WMI 135）
```

**RDP安全**

```
RDP是勒索软件最常见的远程入侵通道之一：

RDP安全加固：
  1. 限制访问
     - 不要将RDP直接暴露到互联网
     - 使用VPN+跳板机访问RDP
     - 限制RDP源IP（防火墙白名单）
     - 修改默认端口（降低扫描效率，非根本解决）

  2. 启用MFA
     - Azure AD条件访问 / RD Gateway + MFA
     - 使用第三方MFA网关（Duo/Okta）
     - 强制所有RDP连接通过MFA验证

  3. 账户安全
     - 禁用Administrator重命名
     - 账户锁定策略（5次失败锁定30分钟）
     - 强密码策略（16位+复杂度）
     - 限制本地管理员组成员

  4. NLA（网络级别认证）
     - 启用NLA（要求认证后才建立会话）
     - 减少DoS和预认证攻击风险

  5. 会话安全
     - 限制并发会话数
     - 设置空闲超时自动断开
     - 记录RDP登录日志（Event ID 4624/4625）
```

**SMB安全**

```
SMB协议安全加固：

  1. 禁用SMBv1
     - SMBv1存在多个严重漏洞（永恒之蓝MS17-010）
     - Windows 10 1709+默认禁用
     - 检测：Get-SmbServerConfiguration | Select EnableSMB1Protocol
     - 禁用：Set-SmbServerConfiguration -EnableSMB1Protocol $false

  2. SMB签名
     - 启用SMB签名防止中继攻击
     - 要求所有SMB连接签名
     - GPO: Microsoft网络客户端：数字签名通信（始终要求）

  3. 限制SMB访问
     - 限制445端口的横向访问
     - 仅允许必要主机间的SMB通信
     - 防火墙规则限制源/目标

  4. SMB over QUIC
     - Windows Server 2022支持SMB over QUIC
     - 替代传统VPN的SMB访问
     - TLS加密传输
```

### 3.4 身份安全

**MFA强制部署**

```
多因素认证（MFA）是阻断凭据泄露后横向移动的关键：

MFA部署范围：
  - VPN远程访问
  - RDP远程桌面
  - 云服务（Office 365 / AWS Console / Azure Portal）
  - 管理员账户登录
  - 邮件系统（OWA / IMAP）

MFA方式选择：
  推荐顺序：
  1. FIDO2硬件密钥（最安全，抗钓鱼）
  2. Authenticator App + Push通知
  3. TOTP（Google Authenticator等）
  4. SMS短信（最弱，易被SIM劫持）

注意事项：
  - 避免仅依赖SMS短信MFA（SIM交换攻击）
  - 配置条件访问策略（设备合规性+位置+风险）
  - 监控MFA疲劳攻击（连续推送通知）
  - 对管理员账户强制MFA
```

**特权账户保护**

```
特权账户是勒索软件攻击的最高价值目标：

保护措施：
  1. 最小权限原则
     - 普通用户不授予本地管理员权限
     - 管理员使用专用管理账户（非日常登录账户）
     - 按需授权，定期审查权限

  2. PAM（特权访问管理）
     - 使用PAM解决方案（CyberArk / BeyondTrust）
     - 特权凭据存储在保险箱中，按需取出
     - 自动轮换密码
     - 会话录制和审计

  3. 分层管理模型（Tier Model）
     - Tier 0：域控级（最高权限）
     - Tier 1：服务器级
     - Tier 2：用户级
     - 不同层级间隔离管理，防止凭据跨层泄露

  4. 凭据保护
     - 启用LSA Protection（防止lsass.exe内存被读取）
     - Credential Guard（虚拟化安全保护凭据）
     - 禁止WDigest明文密码存储
```

**LAPS管理本地管理员密码**

```
LAPS（Local Administrator Password Solution）：

功能：
  - 自动随机化每台机器的本地管理员密码
  - 密码存储在Active Directory计算机对象属性中
  - 定期自动轮换密码
  - 按需查看密码（基于权限）

部署价值：
  - 消除"同一本地管理员密码在所有机器上使用"的问题
  - 阻止Pass-the-Hash横向移动
  - 即使一台机器沦陷，无法用同一密码访问其他机器

LAPS Next Gen（Windows LAPS）：
  - Windows 11 22H2+ / Server 2019+内置
  - 支持Azure AD和AD DS
  - 支持密码加密存储
  - 替代旧版Group Policy LAPS

配置要点：
  - 设置密码复杂度（12位+，大小写+数字+符号）
  - 设置密码轮换周期（如30天）
  - 限制密码查看权限（仅特定管理员组）
```
