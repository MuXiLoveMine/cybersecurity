# 云渗透测试实战案例

### 案例一：Capital One 数据泄露事件复盘

**背景**：2019 年，Capital One 银行超过 1.06 亿客户数据泄露。

**攻击路径复盘**：

```
1. 信息收集
   - 发现 Capital One 使用 AWS
   - 发现其 Web 应用使用 WAF

2. 漏洞发现
   - 发现 WAF 配置存在 SSRF 漏洞
   - 可以通过 WAF 发起内部请求

3. 元数据服务攻击
   - 利用 SSRF 访问 169.254.169.254
   - 获取 EC2 实例角色名称
   - 获取角色的临时凭证

4. 权限评估
   - 角色拥有 S3 列表和读取权限
   - 角色权限范围超出最小权限原则

5. 数据窃取
   - 使用临时凭证列出 S3 存储桶
   - 发现存储客户数据的桶
   - 下载 1.06 亿客户记录

6. 数据外传
   - 将数据下载到攻击者本地
```

**失败的安全措施**：
- WAF 规则配置错误（存在 SSRF）
- EC2 角色权限过大（违反最小权限）
- 使用 IMDSv1（无需令牌）
- 缺乏异常 API 调用检测
- S3 访问日志未及时分析

### 案例二：从泄露的 Access Key 到域管理员（模拟）

**场景**：在 GitHub 上发现目标公司代码仓库中泄露了 AWS Access Key。

**攻击路径**：

```
1. 凭证验证
   - 验证 Access Key 有效
   - 确认是 IAM 用户而非根账号

2. 权限枚举
   - 查看用户附加的策略
   - 发现有 AmazonEC2FullAccess 权限
   - 发现有 S3 读取权限

3. 数据收集
   - 列出所有 S3 存储桶
   - 在一个备份桶中找到数据库备份
   - 下载备份，获取数据库密码

4. 进一步利用
   - 使用 EC2 权限创建新实例
   - 在目标 VPC 中创建堡垒机
   - 利用数据库密码连接 RDS

5. 权限提升
   - 发现数据库中有员工表，包含邮箱
   - 钓鱼攻击管理员
   - 或继续利用 AWS 权限提升

6. 持久化
   - 创建新的 IAM 用户作为后门
   - 创建信任外部账户的角色
```

### 案例三：Kubernetes 渗透测试路径

**场景**：发现目标公司的 Kubernetes API Server 暴露在公网上。

**攻击路径**：

```
1. 信息收集
   - 发现 k8s API Server（6443 端口）
   - 测试匿名访问

2. 匿名访问利用
   - 如果匿名访问被允许
   - 列出所有 Pod、Service、Secret
   - 获取敏感信息

3. 权限提升
   - 如果有 create pods 权限
   - 创建特权容器挂载宿主机磁盘
   - 读取宿主机文件，获取 kubelet 凭证

4. 容器逃逸
   - 特权容器 + 挂载 /
   - 写入 SSH 公钥到宿主机
   - 直接控制节点

5. 集群控制
   - 获取节点上的 ServiceAccount Token
   - 使用 Token 访问 API Server
   - 可能获得集群管理员权限

6. 数据窃取
   - 读取所有 Secret
   - 获取应用数据库密码
   - 获取云服务凭证
   - 窃取业务数据
```
