# 信息收集

### 2.1 子域名枚举

#### 2.1.1 子域名收集的意义

云环境中，子域名往往对应着不同的云服务：
- 对象存储（S3/OSS）
- CDN 节点
- 云服务器（EC2/ECS）
- 容器服务
- API 网关
- 无服务器函数

#### 2.1.2 常用子域名枚举工具

| 工具 | 说明 |
|------|------|
| Subfinder | 快速子域名发现工具 |
| Amass | OWASP 项目，功能强大 |
| Assetfinder | 轻量级子域名发现 |
| Sublist3r | 基于搜索引擎的子域名枚举 |
| OneForAll | 国产子域名收集工具 |

**Subfinder 使用示例**：
```bash
# 基本使用
subfinder -d example.com -o subdomains.txt

# 使用多个数据源
subfinder -d example.com -all -o subdomains.txt

# 结合 httpx 验证存活
subfinder -d example.com -silent | httpx -title -tech-detect -status-code
```

### 2.2 对象存储发现

#### 2.2.1 S3 存储桶发现方法

**方法一：基于公司名称猜测**
```bash
# 常见命名模式
company-name
companyname
company-name-assets
company-name-prod
company-name-backup
company-name-logs
companyname-static
```

**方法二：子域名 CNAME 检测**
```bash
# 检查子域名是否指向 S3
dig +short assets.example.com
# 如果输出包含 s3.amazonaws.com 或 s3-website 则是 S3 桶
```

**方法三：使用自动化工具**
- **S3Scanner**：扫描 S3 存储桶权限
- **bucket-stream**：实时发现 S3 桶
- **cloud_enum**：多云资源枚举工具

**S3Scanner 使用示例**：
```bash
# 安装
pip install s3scanner

# 扫描单个桶的权限
s3scanner bucket --bucket my-bucket

# 从文件中批量扫描
s3scanner scan --buckets-file bucket_names.txt

# 检查权限类型：公开读、公开写、公开读写、私有
```

#### 2.2.2 阿里云 OSS 存储桶发现

**命名规则**：
```
bucket-name.oss-cn-hangzhou.aliyuncs.com
```

**常见发现方法**：
1. 子域名 CNAME 检测
2. 证书透明度（CT）日志
3. 网页源代码中的 OSS 链接
4. APP 逆向中的 API 地址

**OSS 权限检测**：
```bash
# 检查是否为公共读
curl -I https://bucket-name.oss-cn-hangzhou.aliyuncs.com/
# 返回 200 OK 且有内容 = 公共读权限
# 返回 403 Forbidden = 私有
# 返回 404 Not Found = 桶不存在

# 检查是否可列举文件
curl https://bucket-name.oss-cn-hangzhou.aliyuncs.com/?max-keys=1000
# 返回 XML 格式的文件列表 = 公共读 + 列表权限
```

#### 2.2.3 存储桶命名规律

| 类型 | 命名模式 | 示例 |
|------|----------|------|
| 公司名 | {company} | acme |
| 环境名 | {company}-{env} | acme-prod, acme-dev |
| 业务名 | {company}-{service} | acme-assets, acme-backup |
| 日期/版本 | {company}-{date} | acme-2023, acme-v2 |
| 区域 | {company}-{region} | acme-us-east-1 |

### 2.4 凭证泄露检测

#### 2.4.1 凭证泄露来源

| 来源 | 说明 |
|------|------|
| 代码仓库 | GitHub/Gitee 公开代码中的密钥 |
| 代码片段 | Pastebin、Gist 等 |
| 公开文档 | PDF、Word 文档中的配置 |
| 网站源码 | 前端代码中的硬编码密钥 |
| 移动应用 | APP 反编译后的密钥 |
| 配置文件泄露 | `.env`、`config.json` 等 |
| 日志文件 | 日志中打印的密钥 |

#### 2.4.2 GitHub 密钥搜索

**使用 GitHub 搜索**：
```
# 搜索 AWS 密钥
"AKIA" extension:py
"AWS_SECRET_ACCESS_KEY" filename:.env

# 搜索阿里云密钥
"AccessKeyId" extension:js
"accessKeySecret" filename:config.json

# 搜索通用密钥
"password" filename:.env companyname
"api_key" extension:yaml example.com
```

**自动化工具**：
- **GitGuardian**：GitHub 密钥监控
- **TruffleHog**：Git 历史密钥扫描
- **Gitleaks**：Git 仓库密钥扫描
- **Keyhacks**：验证泄露密钥的有效性

**TruffleHog 使用示例**：
```bash
# 扫描 GitHub 仓库
trufflehog github --repo=https://github.com/user/repo

# 扫描本地 Git 仓库
trufflehog filesystem /path/to/repo

# 只显示已验证的密钥
trufflehog github --repo=https://github.com/user/repo --only-verified
```

#### 2.4.3 云凭证验证

**AWS 凭证验证**：
```bash
# 配置凭证
aws configure --profile test
# 输入 Access Key ID 和 Secret Access Key

# 验证凭证有效性
aws sts get-caller-identity --profile test
# 返回用户/角色信息 = 有效凭证
# 返回 InvalidClientTokenId = 无效凭证

# 查看权限范围
aws iam list-attached-user-policies --user-name username --profile test
aws iam list-user-policies --user-name username --profile test
```

**阿里云凭证验证**：
```bash
# 配置凭证
aliyun configure --profile test

# 验证凭证有效性
aliyun sts GetCallerIdentity --profile test
```
