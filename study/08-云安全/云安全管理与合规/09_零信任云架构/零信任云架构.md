# 零信任云架构

### 9.1 零信任模型

```text
零信任架构核心原则:

1. 从不信任,始终验证
   - 每次访问请求都需要认证和授权
   - 不因网络位置而给予信任
   - 不信任任何设备或用户

2. 最小权限访问
   - 仅授予完成任务所需的最小权限
   - 基于身份和上下文的动态授权
   - 及时(JIT)和足够(JEA)访问

3. 假设已被入侵
   - 持续监控异常行为
   - 微分段限制横向移动
   - 快速检测和响应

零信任实现层次:

  身份零信任:
    ├── 多因素认证(MFA)
    ├── 条件访问策略
    ├── 基于风险的认证
    └── 无密码认证(FIDO2)

  设备零信任:
    ├── 设备健康检查
    ├── MDM注册验证
    ├── 端点检测响应(EDR)
    └── 设备证书认证

  网络零信任:
    ├── 微分段
    ├── 身份感知代理
    ├── 软件定义边界(SDP)
    └── 安全访问服务边缘(SASE)

  应用零信任:
    ├── 每个应用独立认证
    ├── API网关统一入口
    ├── 应用级权限控制
    └── 持续会话验证

  数据零信任:
    ├── 数据分类分级
    ├── 字段级加密
    ├── 动态脱敏
    └── 数据访问审计
```

### 9.2 云零信任实现方案

```bash
# AWS零信任实现
# 1. IAM Identity Center (SSO)
aws identitystore create-group \
    --identity-store-id d-1234567890 \
    --display-name "Production-Access"

# 2. 条件访问策略(IAM Policy)
# 基于IP、时间、设备等条件
cat > trust-policy.json << 'EOF'
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": Allow",
      "Action": ["s3:GetObject", "s3:PutObject"],
      "Resource": "arn:aws:s3:::sensitive-data/*",
      "Condition": {
        "IpAddress": {"aws:SourceIp": "10.0.0.0/8"},
        "DateGreaterThan": {"aws:CurrentTime": "2026-09-01T00:00:00Z"},
        "DateLessThan": {"aws:CurrentTime": "2026-12-31T23:59:59Z"},
        "StringEquals": {
          "aws:RequestedRegion": "us-east-1"
        }
      }
    }
  ]
}
EOF

# 3. VPC端点策略(网络层零信任)
aws ec2 create-vpc-endpoint \
    --vpc-id vpc-123 \
    --service-name com.amazonaws.us-east-1.s3 \
    --policy-document file://endpoint-policy.json

# Azure零信任实现
# 1. 条件访问策略
az ad conditional-access policy create \
    --name "Require-MFA-Production" \
    --conditions '{"conditions":{"users":{"includeGroups":["prod-users"]},"applications":{"includeApplications":["All"]},"locations":{"includeLocations":["All"]}}}' \
    --grant-controls '{"controls":[{"controlId":"Mfa","type":"grant"}]}'

# 2. Azure AD Privileged Identity Management
az rest --method POST \
    --url https://graph.microsoft.com/v1.0/roleManagement/directory/roleAssignments \
    --body '{"principalId":"user-id","roleDefinitionId":"role-id","scheduleInfo":{"startDateTime":"2026-09-15T10:00:00Z","expiration":{"type":"AfterDuration","duration":"PT4H"}}}'

# 3. Just-In-Time VM访问
az network bastion create \
    --name myBastion \
    --resource-group rg-network \
    --vnet vnet-prod
```

### 9.3 SASE(安全访问服务边缘)

```text
SASE架构组件:

  网络安全:
    ├── SD-WAN: 智能路由优化
    ├── SWG: 安全Web网关
    ├── CASB: 云访问安全代理
    ├── ZTNA: 零信任网络访问
    └── FWaaS: 防火墙即服务

  数据安全:
    ├── DLP: 数据防泄漏
    ├── 加密传输
    └── 内容过滤

  身份安全:
    ├── IAM: 身份管理
    ├── MFA: 多因素认证
    └── SSO: 单点登录

  威胁防护:
    ├── IPS: 入侵防护
    ├── ATP: 高级威胁防护
    └── UEBA: 用户行为分析

SASE厂商对比:
  | 厂商 | SD-WAN | ZTNA | CASB | SWG | FWaaS |
  |------|--------|------|------|-----|-------|
  | Zscaler | - | 强 | 强 | 强 | 中 |
  | Netskope | - | 强 | 强 | 强 | 中 |
  | Palo Alto | 强 | 中 | 中 | 强 | 强 |
  | Cisco | 强 | 中 | 中 | 强 | 强 |
  | Cato Networks | 强 | 强 | 中 | 强 | 强 |
```
