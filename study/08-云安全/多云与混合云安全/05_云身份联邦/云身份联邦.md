# 云身份联邦

### 5.1 跨云 IAM 挑战

多云下身份管理面临：
- 每个云一套 IAM，账号重复
- 权限粒度定义不一致
- 跨云角色切换复杂
- 审计日志分散

### 5.2 身份联邦方案

通过企业身份提供者（IdP）集中管理身份，联邦到各云：

```text
+------------------+        SAML/OIDC         +------------------+
|  企业 IdP        |<------------------------>|  云 IAM          |
| Azure AD / Okta  |    (信任关系 / 联邦)      |  AWS / 阿里云     |
|  用户/组/角色     |                          |  角色 / 权限策略   |
+------------------+                          +------------------+
```

### 5.3 SAML 联邦

SAML（Security Assertion Markup Markup Language）是跨域单点登录标准。流程：

1. 用户访问云控制台，重定向到企业 IdP
2. IdP 验证用户身份（含 MFA）
3. IdP 签发 SAML 断言（Assertion）
4. 云 IAM 验证断言签名，映射到本地角色，授予临时凭证

#### AWS SAML 联邦角色信任策略示例

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Federated": "arn:aws:iam::123456789012:saml-provider/CorpIdP"
      },
      "Action": "sts:AssumeRoleWithSAML",
      "Condition": {
        "StringEquals": {
          "SAML:aud": "https://signin.aws.amazon.com/saml"
        },
        "StringLike": {
          "SAML:sub": ".*corp\\.example\\.com.*"
        }
      }
    }
  ]
}
```

### 5.4 SCIM 自动化配置

SCIM（System for Cross-domain Identity Management）是用户配置自动化协议，实现：
- IdP 中创建用户后自动在云中创建对应账号
- 用户属性变更自动同步
- 离职后自动禁用 / 删除各云中的账号

这解决了多云环境下账号生命周期管理痛点，避免幽灵账号。

### 5.5 OIDC 联邦

OIDC（OpenID Connect）基于 OAuth 2.0，常用于应用层联邦。例如 GitHub Actions 通过 OIDC 获取 AWS 临时凭证，无需长期 AccessKey：

```yaml
# GitHub Actions 通过 OIDC 联邦访问 AWS
permissions:
  id-token: write   # 允许获取 OIDC token
  contents: read

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: aws-actions/configure-aws-credentials@v2
        with:
          role-to-assume: arn:aws:iam::123456789012:role/github-actions-deploy
          aws-region: us-east-1
          # 无需 access-key-id / secret-access-key
```
