# 多云架构概述

### 1.1 什么是多云

多云（Multi-Cloud）是指组织同时使用两个或多个公有云厂商的服务（例如 AWS + 阿里云 + 腾讯云），而非将全部业务绑定到单一云厂商。与之容易混淆的混合云（Hybrid Cloud）是指公有云与本地数据中心（或私有云）的组合。两者常被同时采用。

多云的核心特征：
- 多个独立的控制平面与身份体系
- 各云厂商的 API、命名、资源模型不一致
- 数据和计算跨云分布
- 网络通过专线 / VPN / SD-WAN 互联

### 1.2 采用多云的驱动因素

| 驱动因素 | 说明 |
| --- | --- |
| 避免厂商锁定 | 防止全部业务依赖单一云厂商导致议价能力下降、迁移困难 |
| 区域覆盖 | 利用不同云在不同地理区域的可用区，满足本地化与低延迟需求 |
| 成本优化 | 不同云在不同服务上的定价差异，按需选择最具性价比的组合 |
| 合规与数据主权 | 部分国家/行业要求数据必须驻留在特定云或本地 |
| 业务连续性 | 一个云发生大规模故障时，业务可切换到另一个云 |
| 最佳能力组合 | A 云的 AI 服务强、B 云的数据库强，按服务优势组合使用 |

### 1.3 多云架构模式

1. **按业务线划分**：不同业务线分配到不同云，互不交叉。例如电商在 AWS、游戏在腾讯云。
2. **按服务层划分**：计算在一个云、存储在另一个云。例如训练在 A 云、推理在 B 云。
3. **主备模式**：一个云为主，另一个云作为灾备，定期同步数据。
4. **负载分担**：流量在多个云之间动态分配，基于延迟、成本动态调度。
5. **数据驻留模式**：敏感数据存于本地或合规云，非敏感计算在公有云。
