# 多云安全挑战

### 2.1 统一管理难题

每个云厂商都有独立的控制台、API、权限模型与资源抽象方式。例如：
- AWS 用 IAM Policy（JSON）、阿里云用 RAM 策略、Azure 用 RBAC 角色定义
- 安全组在 AWS 是 VPC 级、在阿里云是 ECS 级、在 Azure 是 NSG（网络安全组）
- 日志格式各异：AWS CloudTrail、阿里云 ActionTrail、Azure Activity Log

这导致安全团队难以用一套流程统一管理，容易产生安全盲区。

### 2.2 配置一致性问题

同一安全基线在不同云中需要用不同方式实现。例如"禁止公网暴露对象存储"：
- AWS：S3 Bucket Policy + Block Public Access
- 阿里云：OSS Bucket ACL + 访问控制
- Azure：Storage Account Firewall + Private Endpoint

手工配置极易遗漏，导致跨云配置漂移（Configuration Drift）。

### 2.3 身份联邦挑战

多云环境下用户身份分散在各云 IAM 中：
- 同一个员工在 AWS、阿里云、Azure 各有一个账号
- 权限授予、回收需要在每个云重复操作
- 离职清理不彻底，产生幽灵账号
- 跨云访问缺乏统一审计

### 2.4 网络互通安全

跨云网络互通带来新的攻击面：
- 专线 / VPN 的加密与认证
- 跨云流量的网络安全组策略一致性
- 一旦某云被攻破，横向移动可能蔓延到其他云
- 跨云流量可见性差，入侵检测覆盖不足

### 2.5 数据安全与合规

- 跨云数据流动的加密与审计
- 数据驻留要求难以保证
- 各云加密服务（KMS）不互通，密钥管理分散
- 跨云备份与数据生命周期管理
