# 多云合规一致性管理

### 7.1 跨云合规挑战

- 各云厂商提供的合规认证不同
- 同一控制要求在不同云的实现方式不同
- 合规检查需要跨云统一出报告
- 合规要求随法规更新频繁

### 7.2 合规框架映射

将法规要求映射到各云的具体控制项：

| 法规要求 | AWS 控制项 | 阿里云控制项 | Azure 控制项 |
| --- | --- | --- | --- |
| 数据加密 | S3 SSE-KMS | OSS KMS | Storage CMK |
| 访问审计 | CloudTrail | ActionTrail | Activity Log |
| 网络隔离 | VPC + 安全组 | VPC + 安全组 | VNet + NSG |
| 密钥自主 | CloudHSM | KMS HSM | Dedicated HSM |

### 7.3 策略即代码实现合规

使用 Open Policy Agent（OPA）/ Rego 或 Checkov 统一定义跨云合规策略：

#### Checkov 策略示例（YAML）

```yaml
# 禁止对象存储桶公开可写
framework: cis
metadata:
  id: CKV_AWS_20
  name: Ensure S3 bucket is not publicly readable
  category: general
definition:
  cond_type: attribute
  resource_types:
    - aws_s3_bucket
  attribute: acl
  operator: not_equals
  value: public-read
```

#### Rego 策略示例

```rego
package multi_cloud.compliance

# 禁止任何云的安全组开放 0.0.0.0/0 入站
deny[msg] {
  some sg
  sg := input.security_groups[_]
  sg.ingress[_].cidr == "0.0.0.0/0"
  msg := sprintf("安全组 %s 在 %s 云开放了 0.0.0.0/0 入站", [sg.name, sg.cloud])
}
```
