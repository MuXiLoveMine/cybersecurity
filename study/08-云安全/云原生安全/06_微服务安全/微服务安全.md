# 微服务安全

### 6.1 微服务安全挑战

| 挑战 | 说明 |
|------|------|
| 攻击面增大 | 服务数量多，接口多 |
| 服务间通信安全 | 内部服务调用的认证和加密 |
| 身份管理复杂 | 服务间身份认证、用户身份传递 |
| 数据一致性 | 分布式事务、数据安全 |
| 监控与审计 | 分布式追踪、统一审计 |
| 配置管理 | 多服务配置、密钥管理 |

### 6.2 API 网关安全

#### 6.2.1 API 网关的安全功能

| 功能 | 说明 |
|------|------|
| 认证鉴权 | JWT、OAuth2、API Key 验证 |
| 流量控制 | 限流、熔断、降级 |
| 安全防护 | WAF、防 SQL 注入、防 XSS |

### 6.3 服务网格（Service Mesh）安全

#### 6.3.1 服务网格概述

服务网格是微服务架构中的基础设施层，负责处理服务间通信，提供流量管理、可观测性和安全功能。

**主流服务网格**：
- Istio：最流行，功能全面
- Linkerd：轻量级，简单易用
- Cilium Service Mesh：基于 eBPF，高性能

#### 6.3.2 Istio 安全功能

| 功能 | 说明 |
|------|------|
| mTLS | 服务间双向 TLS 认证，自动加密通信 |
| 身份认证 | 基于 SPIFFE 的服务身份 |
| 授权策略 | 细粒度的服务访问控制 |
| 对等认证 | 服务到服务的认证 |
| 请求认证 | 用户到服务的认证（JWT） |

#### 6.3.3 Istio mTLS 配置

**启用全局 mTLS（STRICT 模式）**：
```yaml
apiVersion: security.istio.io/v1beta1
kind: PeerAuthentication
metadata:
  name: default
  namespace: istio-system
spec:
  mtls:
    mode: STRICT  # 强制 mTLS
```

**服务级授权策略**：
```yaml
apiVersion: security.istio.io/v1beta1
kind: AuthorizationPolicy
metadata:
  name: httpbin-require-jwt
  namespace: default
spec:
  selector:
    matchLabels:
      app: httpbin
  action: ALLOW
  rules:
  - from:
    - source:
        requestPrincipals: ["*"]   # 需要有效的 JWT
    when:
    - key: request.auth.claims[role]
      values: ["admin", "user"]   # JWT 中需要有 role 声明
```

#### 6.3.4 零信任与服务网格

服务网格是实现零信任架构的重要技术基础：

- **身份认证**：每个服务都有唯一身份（SPIFFE ID）
- **mTLS**：所有服务间通信自动加密
- **细粒度授权**：基于身份的访问控制策略
- **可观测性**：完整的流量日志和追踪
