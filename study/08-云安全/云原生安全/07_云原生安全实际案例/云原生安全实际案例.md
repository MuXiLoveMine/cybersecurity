# 云原生安全实际案例

### 案例一：Tesla 云账号被入侵（2018）

**事件**：攻击者发现 Tesla 的 Kubernetes 管理控制台暴露在公网上，其中一个 Pod 包含 AWS 访问密钥，攻击者利用密钥访问了 Tesla 的 AWS 资源。

**攻击路径**：
```
Kubernetes Dashboard 公网暴露
    │
    ▼
未授权访问 Dashboard
    │
    ▼
查看 Pod 中的环境变量
    │
    ▼
获取 AWS Access Key
    │
    ▼
访问 AWS 资源（数据窃取、挖矿）
```

**安全教训**：
- Kubernetes Dashboard 不应暴露在公网
- 不应在环境变量中存储敏感信息
- RBAC 应严格配置，禁止匿名访问
- 定期审计云凭证权限

### 案例二：容器挖矿事件

**场景**：某公司 Kubernetes 集群中出现异常 CPU 占用，排查发现被植入挖矿木马。

**入侵途径**：
1. 攻击者扫描公网，发现暴露的 Docker API（2375 端口）
2. 通过 Docker API 启动挖矿容器
3. 利用容器逃逸或横向移动感染更多节点

**防护措施**：
1. 禁止 Docker API 公网暴露
2. 启用 TLS 认证
3. 部署运行时安全监控（Falco）
4. 设置资源限制防止影响业务
5. 镜像仓库准入控制

### 案例三：CI/CD 流水线供应链攻击

**场景**：攻击者通过提交 PR（Pull Request）注入恶意代码到 CI/CD 流水线，窃取构建凭证。

**攻击方式**：
1. 在开源项目中提交看似正常的 PR
2. PR 中的代码修改了 CI/CD 配置
3. CI/CD 运行时执行了恶意代码
4. 恶意代码读取并外传了 CI Secrets

**防护措施**：
1. 对外部贡献者的 PR 进行人工审核
2. CI 流水线中敏感操作需要审批
3. Secrets 最小权限原则
4. 构建环境隔离
5. 监控 CI 运行异常

---

> **小结**：云原生安全是云安全的进阶方向，涵盖容器安全、Kubernetes 安全、DevSecOps 和微服务安全。核心思想是"安全左移"和"纵深防御"，通过自动化工具将安全融入开发流程的每个环节，同时在运行时持续监控和防护。

### 二、核心工具实践命令

#### 1. Trivy - 镜像与配置扫描

```bash
# ===== 安装 =====
curl -sfL https://raw.githubusercontent.com/aquasecurity/trivy/main/contrib/install.sh | sh -s -- -b /usr/local/bin

# ===== 镜像扫描 =====
# 基本扫描
trivy image nginx:latest

# 只显示高危以上漏洞
trivy image --severity CRITICAL,HIGH nginx:latest

# 忽略未修复的漏洞
trivy image --ignore-unfixed nginx:latest

# 输出 SBOM (CycloneDX/SPDX)
trivy image --format cyclonedx --output sbom.cdx.json nginx:latest

# 扫描本地镜像（Docker 构建后立即扫描）
docker build -t myapp:latest .
trivy image myapp:latest

# ===== 配置扫描 =====
# 扫描 Dockerfile
trivy config --severity CRITICAL,HIGH ./Dockerfile

# 扫描 Kubernetes 清单
trivy config ./k8s-manifests/

# 扫描 Helm Chart
trivy config ./my-chart/

# 扫描 Terraform
trivy config ./terraform/

# ===== K8s 集群扫描 =====
# 扫描整个集群
trivy k8s --report=summary cluster

# 扫描指定命名空间
trivy k8s --report=all -n production cluster

# 只扫描配置问题（misconfig）
trivy k8s --scanners misconfig cluster

# ===== 漏洞数据库管理 =====
# 下载漏洞数据库（离线使用）
trivy image --download-db-only

# 使用轻量级数据库
trivy image --light nginx:latest
```

#### 2. Falco - 运行时威胁检测

```bash
# ===== 安装 =====
# Helm 安装
helm repo add falcosecurity https://falcosecurity.github.io/charts
helm repo update
helm install falco falcosecurity/falco --namespace falco --create-namespace

# ===== 常用规则 =====
# 查看已加载的规则
kubectl exec -n falco falco-pod-name -- falco -L

# 自定义规则示例（创建 ConfigMap）
cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: ConfigMap
metadata:
  name: falco-custom-rules
  namespace: falco
data:
  custom_rules.yaml: |
    # 检测敏感文件读取
    - rule: Read sensitive file untrusted
      desc: >
        an attempt to read any sensitive file (e.g. files containing user/password/authentication
        information). Exceptions are made for known trusted programs.
      condition: >
        sensitive_files and open_read
        and proc_name_exists
        and not proc.name in (user_mgmt_binaries, usermgmt_binaries,
          package_mgmt_binaries, salt_mgmt_binaries,
          vpn_mgmt_binaries, shell_mgmt_binaries, other_allowed_binaries,
          falco_sensitive_files_allowed_procs)
        and not proc.cmdline in (known_sensitive_file_reads_other_allowed_cmds)
        and not user.name in (falco_sensitive_files_allowed_users)
        and not container.image.repository in (falco_sensitive_files_allowed_images)
      output: Sensitive file opened for reading by non-trusted program (user=%user.name user_loginuid=%user.loginuid program=%proc.name command=%proc.cmdline file=%fd.name parent=%proc.pname pcmdline=%proc.pcmdline gparent=%proc.aname[2] container_id=%container.id image=%container.image.repository)
      priority: WARNING
      tags: [filesystem, mitre_credential_access, T1003]
EOF

# ===== Falco 输出配置 =====
# 实时查看 Falco 告警
kubectl logs -n falco -l app.kubernetes.io/name=falco -f

# 配置告警输出到 Slack
# 编辑 falco.yaml 添加：
# json_output: true
# program_output:
#   enabled: true
#   keep_alive: false
#   program: "curl -s -X POST --data-binary @- https://hooks.slack.com/services/XXX/YYY/ZZZ"

# ===== Falco Sidekick =====
# 安装 Falco Sidekick（多通道告警）
helm upgrade --install falco falcosecurity/falco \
  --namespace falco --create-namespace \
  --set falcosidekick.enabled=true \
  --set falcosidekick.config.slack.webhookurl=https://hooks.slack.com/services/XXX \
  --set falcosidekick.config.elasticsearch.host=elasticsearch:9200
```

#### 3. Kyverno - 策略引擎实践

```bash
# ===== 安装 =====
helm repo add kyverno https://kyverno.github.io/kyverno/
helm repo update
helm install kyverno kyverno/kyverno -n kyverno --create-namespace

# ===== 常用策略 =====
# 1. 要求镜像必须来自可信仓库
cat <<EOF | kubectl apply -f -
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: restrict-image-registries
  annotations:
    policies.kyverno.io/title: Restrict Image Registries
    policies.kyverno.io/category: Best Practices
spec:
  validationFailureAction: enforce
  background: true
  rules:
  - name: validate-registries
    match:
      any:
      - resources:
          kinds:
          - Pod
    validate:
      message: "Images must come from trusted registry."
      pattern:
        spec:
          containers:
          - image: "registry.example.com/*"
EOF

# 2. 禁止特权容器
cat <<EOF | kubectl apply -f -
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: disallow-privileged-containers
spec:
  validationFailureAction: enforce
  rules:
  - name: priviledged-containers
    match:
      any:
      - resources:
          kinds:
          - Pod
    validate:
      message: "Privileged containers are not allowed."
      pattern:
        spec:
          containers:
          - =(securityContext):
              =(privileged): "false"
EOF

# 3. 自动添加网络策略（变异策略）
cat <<EOF | kubectl apply -f -
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: add-default-networkpolicy
spec:
  rules:
  - name: add-default-deny
    match:
      any:
      - resources:
          kinds:
          - Namespace
    generate:
      kind: NetworkPolicy
      name: default-deny
      namespace: "{{request.object.metadata.name}}"
      data:
        spec:
          podSelector: {}
          policyTypes:
          - Ingress
          - Egress
EOF

# 4. 要求设置资源限制
cat <<EOF | kubectl apply -f -
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: require-pod-requests-limits
spec:
  validationFailureAction: audit
  rules:
  - name: validate-resources
    match:
      any:
      - resources:
          kinds:
          - Pod
    validate:
      message: "CPU and memory resource requests and limits are required."
      pattern:
        spec:
          containers:
          - resources:
              requests:
                memory: "?*"
                cpu: "?*"
              limits:
                memory: "?*"
                cpu: "?*"
EOF

# ===== 查看策略报告 =====
kubectl get clusterpolicies
kubectl describe clusterpolicy disallow-privileged-containers

# 查看策略违规报告
kubectl get policyreport -A
kubectl describe policyreport -n default
```

#### 4. Cosign - 镜像签名与验证

```bash
# ===== 安装 =====
go install github.com/sigstore/cosign/v2/cmd/cosign@latest

# ===== 密钥管理 =====
# 生成密钥对
cosign generate-key-pair
# 生成 cosign.key 和 cosign.pub

# 使用 KMS 密钥（支持 AWS KMS, GCP KMS, Azure Key Vault）
cosign generate-key-pair --kms gcpkms://projects/PROJECT/locations/global/keyRings/KEYRING/cryptoKeys/KEY

# ===== 签名镜像 =====
# 基本签名
cosign sign --key cosign.key myrepo/myimage:v1.0.0

# 签名并上传到 OCI 仓库
cosign sign --key cosign.key --upload=true myrepo/myimage:v1.0.0

# 对镜像摘要签名（更安全，避免标签替换攻击）
DIGEST=$(cosign triangulate myrepo/myimage:v1.0.0 --type digest)
cosign sign --key cosign.key $DIGEST

# 使用 Keyless 签名（无需密钥，基于 OIDC）
COSIGN_EXPERIMENTAL=1 cosign sign myrepo/myimage:v1.0.0

# ===== 验证签名 =====
# 基本验证
cosign verify --key cosign.pub myrepo/myimage:v1.0.0

# 验证并输出证书信息
cosign verify --key cosign.pub --output json myrepo/myimage:v1.0.0 | jq .

# 在 Kubernetes 准入控制中验证
# 使用 Kyverno 或 admission-webhook

# ===== 在 CI/CD 中集成 =====
# GitHub Actions 示例
# - name: Sign image
#   run: |
#     cosign sign --key ${{ secrets.COSIGN_PRIVATE_KEY }} \
#       ghcr.io/${{ github.repository }}:${{ github.sha }}

# ===== 签名附件（SBOM等） =====
# 签名 SBOM 附件
cosign attach sbom --sbom sbom.spdx myrepo/myimage:v1.0.0
cosign sign --key cosign.key --attachment sbom myrepo/myimage:v1.0.0
```

#### 5. HashiCorp Vault - Secrets 管理

```bash
# ===== 安装与启动 =====
# 开发模式（仅测试）
vault server -dev &
export VAULT_ADDR='http://127.0.0.1:8200'

# 生产模式部署（Helm）
helm repo add hashicorp https://helm.releases.hashicorp.com
helm install vault hashicorp/vault --namespace vault --create-namespace \
  --set "server.ha.enabled=true" \
  --set "server.ha.raft.enabled=true"

# ===== KV Secrets Engine =====
# 启用 KV v2
vault secrets enable -version=2 kv

# 写入 Secret
vault kv put kv/myapp/config username=admin password=secret123

# 读取 Secret
vault kv get kv/myapp/config

# 列出 Secrets
vault kv list kv/myapp/

# ===== 动态数据库凭证 =====
# 启用数据库 Secret 引擎
vault secrets enable database

# 配置 PostgreSQL 连接
vault write database/config/my-postgresql \
  plugin_name=postgresql-database-plugin \
  allowed_roles="my-role" \
  connection_url="postgresql://{{username}}:{{password}}@postgres:5432/mydb?sslmode=disable" \
  username="vaultuser" \
  password="vaultpass"

# 创建角色（动态生成凭证）
vault write database/roles/my-role \
  db_name=my-postgresql \
  creation_statements="CREATE ROLE \"{{name}}\" WITH LOGIN PASSWORD '{{password}}' VALID UNTIL '{{expiration}}'; GRANT SELECT ON ALL TABLES IN SCHEMA public TO \"{{name}}\";" \
  default_ttl="1h" \
  max_ttl="24h"

# 生成动态凭证
vault read database/creds/my-role

# ===== Kubernetes 认证 =====
# 启用 K8s 认证
vault auth enable kubernetes

# 配置 K8s 认证
vault write auth/kubernetes/config \
  kubernetes_host="https://kubernetes.default.svc" \
  kubernetes_ca_cert=@/var/run/secrets/kubernetes.io/serviceaccount/ca.crt

# 创建策略
vault policy write myapp-policy - <<EOF
path "kv/data/myapp/*" {
  capabilities = ["read"]
}
EOF

# 绑定角色到服务账号
vault write auth/kubernetes/role/myapp \
  bound_service_account_names=myapp-sa \
  bound_service_account_namespaces=default \
  policies=myapp-policy \
  ttl=1h

# ===== Vault Agent 注入（Sidecar） =====
# 安装 Vault Agent Injector
helm install vault hashicorp/vault --namespace vault \
  --set "injector.enabled=true" \
  --set "server.dev.enabled=true"

# Pod 注解启用注入
# annotations:
#   vault.hashicorp.com/agent-inject: "true"
#   vault.hashicorp.com/role: "myapp"
#   vault.hashicorp.com/agent-inject-secret-config: "kv/myapp/config"
```

#### 6. Tetragon - eBPF 运行时安全

```bash
# ===== 安装 =====
helm repo add cilium https://helm.cilium.io/
helm install tetragon cilium/tetragon -n kube-system

# ===== 查看进程执行 =====
# 实时监控所有进程执行
kubectl logs -n kube-system -l app.kubernetes.io/name=tetragon -c export-stdout -f | tetra getevents -o compact

# 监控特定命名空间
kubectl logs -n kube-system -l app.kubernetes.io/name=tetragon -c export-stdout -f | tetra getevents --namespace production -o compact

# ===== 安全策略 (TracingPolicy) =====
# 检测敏感文件访问
cat <<EOF | kubectl apply -f -
apiVersion: cilium.io/v1alpha1
kind: TracingPolicy
metadata:
  name: "sensitive-files"
spec:
  kprobes:
  - call: "fd_install"
    syscall: false
    args:
    - index: 0
      type: "int"
    - index: 1
      type: "file"
    selectors:
    - matchArgs:
      - index: 1
        operator: "Equal"
        values:
        - "/etc/shadow"
        - "/etc/passwd"
      matchActions:
      - action: Sigkill
EOF

# 检测权限提升
cat <<EOF | kubectl apply -f -
apiVersion: cilium.io/v1alpha1
kind: TracingPolicy
metadata:
  name: "detect-privilege-escalation"
spec:
  kprobes:
  - call: "commit_creds"
    syscall: false
    args:
    - index: 0
      type: "cred"
    selectors:
    - matchBinaries:
      - operator: "NotIn"
        values:
        - "/usr/bin/sudo"
        - "/usr/bin/su"
      matchArgs:
      - index: 0
        operator: "Uid"
        values:
        - "0"
EOF

# ===== Tetragon CLI =====
# 安装 tetra CLI
curl -LO https://github.com/cilium/tetragon/releases/latest/download/tetra-linux-amd64.tar.gz
tar xzf tetra-linux-amd64.tar.gz

# 导出事件
tetra getevents -o json > tetragon-events.json

# 查看网络事件
tetra getevents --types process_exec,process_exit,kprobe
```

### 三、DevSecOps CI/CD 安全集成命令

```yaml
# .gitlab-ci.yml - 完整 DevSecOps 流水线示例
stages:
  - build
  - scan
  - sign
  - deploy

build:
  stage: build
  script:
    - docker build -t $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA .
    - docker push $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA

# 镜像漏洞扫描
trivy-scan:
  stage: scan
  image: aquasec/trivy:latest
  script:
    - trivy image --exit-code 1 --severity CRITICAL $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA
    - trivy image --format json --output trivy-report.json $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA
  artifacts:
    paths:
      - trivy-report.json

# 密钥扫描
secret-scan:
  stage: scan
  image: trufflesecurity/trufflehog:latest
  script:
    - trufflehog filesystem . --fail

# IaC 配置扫描
iac-scan:
  stage: scan
  image: aquasec/trivy:latest
  script:
    - trivy config --exit-code 1 --severity HIGH,CRITICAL ./k8s/

# 镜像签名
sign-image:
  stage: sign
  image: bitnami/cosign:latest
  script:
    - echo "$COSIGN_PRIVATE_KEY" > cosign.key
    - cosign sign --key cosign.key $CI_REGISTRY_IMAGE:$CI_COMMIT_SHA
  variables:
    COSIGN_PASSWORD: "$COSIGN_PASSWORD"

# K8s 部署前验证
deploy:
  stage: deploy
  image: bitnami/kubectl:latest
  script:
    - kubectl apply -f k8s/
    - kubectl rollout status deployment/myapp
  environment: production
```
