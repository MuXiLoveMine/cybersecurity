### 2.2 云原生威胁检测

```
云原生威胁检测用例：

1. 异常API调用
   - 非常规时间的API调用
   - 异常频率的API请求
   - 来自异常IP的API调用
   - 权限提升API序列

2. 资源异常操作
   - 大量创建EC2实例(加密货币挖矿)
   - 异常的S3存储桶访问
   - 安全组修改(开放端口)
   - IAM策略变更

3. 数据外传检测
   - 大量数据从S3下载
   - 异常的数据传输量
   - 到异常目标的数据传输
   - 加密通道数据传输

4. 横向移动检测
   - EC2实例间异常连接
   - 跨账户访问
   - 角色链滥用
   - Lambda函数异常调用
```

**AWS GuardDuty检测示例**

```bash
# 启用GuardDuty
```

### 2.3 自动化响应

```python
# AWS Lambda自动化响应示例
# 当检测到恶意EC2实例时自动隔离

import json
import boto3

def lambda_handler(event, context):
    """GuardDuty发现事件的自动响应"""
    finding = json.loads(event['detail']['finding'])
    finding_type = finding['type']

    ec2 = boto3.client('ec2')
    instance_id = finding.get('resource', {}).get('instanceDetails', {}).get('instanceId')

    if not instance_id:
        return {"status": "no_instance_id"}

    # 根据发现类型执行不同响应
    if finding_type.startswith('UnauthorizedAccess') or \
       finding_type.startswith('Impact'):
        # 隔离实例：替换安全组为隔离安全组
        try:
            ec2.modify_instance_attribute(
                InstanceId=instance_id,
                Groups=['sg-isolated']  # 隔离安全组
            )
            print(f"实例 {instance_id} 已隔离")

            # 发送通知
            sns = boto3.client('sns')
            sns.publish(
                TopicArn='arn:aws:sns:us-east-1:123:security-alerts',
                Subject=f'安全事件: {finding_type}',
                Message=f'实例 {instance_id} 因 {finding_type} 已自动隔离'
            )

        except Exception as e:
            print(f"隔离失败: {e}")
            return {"status": "error", "message": str(e)}

    elif finding_type.startswith('Exfiltration'):
        # 阻断出口流量
        # 修改安全组拒绝所有出站
        pass

    return {"status": "success"}
```

### 3.3 SOC 2

```
SOC 2五大信任服务原则:

1. 安全性 (Security)
   - 系统和数据的逻辑和物理保护

2. 可用性 (Availability)
   - 系统和数据的可访问性

3. 处理完整性 (Processing Integrity)
   - 数据处理的完整性和准确性

4. 保密性 (Confidentiality)
   - 机密数据的保护

5. 隐私性 (Privacy)
   - 个人信息的收集、使用和披露

SOC 2 Type I: 控制设计有效性（某一时点）
SOC 2 Type II: 控制运行有效性（一段时间）
```

## 四、CSPM云安全态势管理

### 4.1 CSPM概念

CSPM (Cloud Security Posture Management) 是持续监控、评估和修复云基础设施安全配置的工具。

```
CSPM工作流程：

  持续扫描 --> 评估风险 --> 优先级排序 --> 自动修复 --> 报告合规
     |             |             |             |           |
     v             v             v             v           v
  配置发现     风险评分     修复建议     自动行动    合规报告
  API查询     基于上下文   按严重度     Lambda/    等保/ISO/
  配置比对    和业务影响   排列优先级    函数执行    SOC2/PCI
```

### 4.2 CSPM核心功能

```
1. 配置审计
   - 自动发现云资源
   - 检查配置合规性
   - 与安全基线对比
   - 持续监控配置漂移

2. 合规报告
   - 映射合规框架
   - 生成合规报告
   - 跟踪合规状态
   - 提供修复建议

3. 风险评估
   - 识别暴露的资源
   - 评估权限过宽
   - 检测加密缺失
   - 评估网络暴露

4. 自动修复
   - 自动修复配置
   - 执行安全策略
   - 阻止不合规变更
   - 通知安全团队

5. 可视化
   - 云资源拓扑图
   - 安全态势仪表盘
   - 风险热图
   - 趋势分析
```

**Cloud Custodian策略示例**

```yaml
# 确保所有S3存储桶启用加密
policies:
  - name: s3-encryption-check
    resource: aws.s3
    filters:
      - type: bucket-encryption
        state: False
    actions:
      - type: set-bucket-encryption
        crypto: AES256

  # 检测公共EC2实例
  - name: ec2-public-instance-alert
    resource: aws.ec2
    filters:
      - type: instance-attribute
        key: SourceDestCheck
        value: false
    actions:
      - type: mark-for-op
        op: stop
        days: 1

  # 确保安全组不开放22端口到公网
  - name: ssh-open-to-world
    resource: aws.security-group
    filters:
      - type: ingress
        IpProtocol: tcp
        FromPort: 22
        Cidr: 0.0.0.0/0
    actions:
      - type: remove-permissions
        ip-protocol: tcp
        from-port: 22
```

## 五、多云安全治理

### 5.1 多云挑战

```
多云环境安全挑战：

1. 可见性碎片化
   - 不同云平台管理控制台
   - 不同的API和工具集
   - 难以获得统一视图

2. 配置不一致
   - 各云厂商默认配置不同
   - 安全控制实现方式不同
   - 容易出现配置漏洞

3. 身份管理复杂
   - 各云独立的IAM体系
   - 跨云权限难以统一管理
   - 身份联邦配置复杂

4. 合规碎片化
   - 各云厂商合规认证不同
   - 审计日志格式不统一
   - 合规报告难以统一

5. 成本与效率
   - 多套工具采购成本高
   - 运维团队技能要求高
   - 自动化难以统一
```

### 5.3 云安全基线

```

身份与访问管理:
  [ ] MFA已为所有用户启用
  [ ] 无root/admin直接使用
  [ ] 最小权限原则
  [ ] 定期清理未使用账号
  [ ] 服务账号使用角色而非密钥
  [ ] 密钥/密码定期轮换
```

## 六、安全自动化与基础设施即代码

```yaml
# Terraform安全配置示例

# 启用S3加密
resource "aws_s3_bucket_server_side_encryption_configuration" "example" {
  bucket = aws_s3_bucket.example.id
  rule {
    apply_server_side_encryption_by_default {
      sse_algorithm = "aws:kms"
      kms_master_key_id = aws_kms_key.s3_key.arn
    }
  }
}

# 私有子网中的RDS
resource "aws_db_instance" "database" {
  engine               = "mysql"
  instance_class       = "db.r5.large"
  publicly_accessible  = false  # 不公开访问
  storage_encrypted    = true   # 存储加密
  kms_key_id          = aws_kms_key.rds_key.arn
  backup_retention_period = 30  # 备份保留30天
  deletion_protection = true   # 删除保护
  multi_az            = true   # 多可用区

  vpc_security_group_ids = [aws_security_group.db.id]
  db_subnet_group_name   = aws_db_subnet_group.private.name

  parameter_group_name = aws_db_parameter_group.secure.name
}

# 限制性安全组
resource "aws_security_group" "db" {
  name        = "database-sg"
  vpc_id      = aws_vpc.main.id
}

resource "aws_security_group_rule" "db_ingress" {
  type                     = "ingress"
  from_port                = 3306
  to_port                  = 3306
  protocol                 = "tcp"
  source_security_group_id = aws_security_group.app.id  # 只允许应用SG
  security_group_id        = aws_security_group.db.id
}

# 无出站规则，默认拒绝所有出站
resource "aws_security_group_rule" "db_egress" {
  type              = "egress"
  from_port         = 0
  to_port           = 0
  protocol          = "-1"
  cidr_blocks       = ["10.0.0.0/8"]  # 只允许内网出站
  security_group_id = aws_security_group.db.id
}
```

## 七、云安全最佳实践

```
云安全最佳实践清单：

1. 身份与访问
   - 启用MFA
   - 使用IAM角色而非用户密钥
   - 定期审查权限
   - 实施条件访问
   - 使用SSO/SAML/OIDC

2. 网络安全
   - 默认拒绝原则
   - 网络分段
   - 流量日志和监控
   - 专用连接(VPN/Direct Connect)
   - WAF/DDoS防护

3. 数据安全
   - 全量加密(存储+传输)
   - 客户管理密钥(CMK)
   - 密钥轮换
   - 数据分类分级
   - DLP数据防泄漏

4. 日志与监控
   - 全量审计日志
   - 集中日志管理(SIEM)
   - 异常检测
   - 安全事件告警
   - 日志不可篡改
```
