# 安全配置实际案例

### 案例一：初创公司云安全配置

**场景**：某 20 人初创公司，业务全部在 AWS 上运行。

**安全配置方案**：

| 领域 | 配置措施 |
|------|----------|
| IAM | 所有用户启用 MFA；开发人员使用 IAM 用户，不使用根账号；EC2 使用角色而非密钥 |
| 网络 | VPC 分为公有和私有子网；Web 服务器放私有子网，通过 ALB 对外提供服务 |
| 存储 | S3 全部私有，启用加密和版本控制；敏感数据使用 KMS 加密 |
| 数据库 | RDS 放私有子网，不分配公网 IP；启用加密和自动备份 |
| 审计 | 开启 CloudTrail 全区域跟踪；关键操作配置告警 |
| 服务器 | 使用 Amazon Linux 2，启用自动更新；安装 SSM Agent 统一管理 |

### 案例二：金融企业云安全合规配置

**场景**：某金融机构，需要满足等保三级和行业监管要求。

**安全配置方案**：

| 领域 | 配置措施 |
|------|----------|
| 身份认证 | 强密码策略 + MFA + IP 白名单 + 登录审计 |
| 网络安全 | 网络分层架构 + 安全组严格控制 + WAF + DDoS 防护 |
| 数据安全 | 全链路加密（传输+存储）+ 数据分类分级 + 密钥分级管理 |
| 审计日志 | 操作审计 + 数据库审计 + 应用日志 + 日志保存 1 年以上 |
| 访问控制 | 最小权限 + 权限定期审计 + 特权操作审批 |
| 安全运营 | 7×24 安全监控 + 漏洞管理 + 渗透测试 + 应急响应 |

---

> **小结**：云平台安全配置的核心是遵循最小权限原则，从身份、网络、数据、审计四个维度构建纵深防御体系。配置错误是云安全最大的风险，必须建立持续的配置审计和合规检查机制。

### 一、AWS 安全配置命令速查表

#### 1. IAM 身份与访问管理

```bash
# 列出所有 IAM 用户
aws iam list-users

# 为用户启用 MFA（创建虚拟 MFA 设备）
aws iam create-virtual-mfa-device --virtual-mfa-device-name MyUserMFA --outfile qr.png --bootstrap-method QRCodePNG
aws iam enable-mfa-device --user-name myuser --serial-number arn:aws:iam::123456789012:mfa/myuser --authentication-code1 123456 --authentication-code2 789012

# 强制用户首次登录修改密码（设置密码策略）
aws iam update-account-password-policy \
  --minimum-password-length 12 \
  --require-symbols \
  --require-numbers \
  --require-uppercase-characters \
  --require-lowercase-characters \
  --allow-users-to-change-password \
  --max-password-age 90 \
  --password-reuse-prevention 5

# 列出 IAM 用户的访问密钥
aws iam list-access-keys --user-name myuser

# 创建 IAM 角色（EC2 用）
aws iam create-role --role-name EC2ReadOnlyRole \
  --assume-role-policy-document file://trust-policy.json
aws iam attach-role-policy --role-name EC2ReadOnlyRole \
  --policy-arn arn:aws:iam::aws:policy/AmazonS3ReadOnlyAccess
```

**Trust Policy 示例 (trust-policy.json)**：
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": { "Service": "ec2.amazonaws.com" },
      "Action": "sts:AssumeRole"
    }
  ]
}
```

#### 2. S3 存储安全

```bash
# 阻止公开访问（账户级别）
aws s3control put-public-access-block \
  --account-id 123456789012 \
  --public-access-block-configuration \
  BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true

# 为 S3 桶启用服务器端加密 (SSE-KMS)
aws s3api put-bucket-encryption --bucket my-bucket \
  --server-side-encryption-configuration '{
    "Rules": [
      {
        "ApplyServerSideEncryptionByDefault": {
          "SSEAlgorithm": "aws:kms",
          "KMSMasterKeyID": "alias/my-key"
        }
      }
    ]
  }'

# 启用 S3 桶版本控制
aws s3api put-bucket-versioning --bucket my-bucket --versioning-configuration Status=Enabled

# 启用 S3 访问日志记录
aws s3api put-bucket-logging --bucket my-bucket \
  --bucket-logging-status file://logging.json

# 检查 S3 桶是否公开
aws s3api get-bucket-policy-status --bucket my-bucket
```

#### 3. VPC 网络安全

```bash
# 创建安全组（仅允许特定 IP 访问 SSH）
aws ec2 create-security-group --group-name SSH-SG --description "SSH access" --vpc-id vpc-xxxx
aws ec2 authorize-security-group-ingress --group-id sg-xxxx \
  --protocol tcp --port 22 --cidr 192.168.1.0/24

# 创建网络 ACL
aws ec2 create-network-acl --vpc-id vpc-xxxx
aws ec2 create-network-acl-entry --network-acl-id acl-xxxx \
  --rule-number 100 --protocol tcp --port-range From=22,To=22 \
  --cidr-block 0.0.0.0/0 --rule-action DENY --ingress

# 启用 VPC 流日志
aws ec2 create-flow-logs --resource-type VPC --resource-ids vpc-xxxx \
  --traffic-type ALL --log-group-name vpc-flow-logs \
  --deliver-logs-permission-arn arn:aws:iam::123456789012:role/vpc-flow-logs-role
```

#### 4. CloudTrail 审计日志

```bash
# 创建全区域 CloudTrail 跟踪
aws cloudtrail create-trail --name my-trail \
  --s3-bucket-name my-cloudtrail-logs \
  --is-multi-region-trail \
  --enable-log-file-validation \
  --kms-key-id alias/cloudtrail-key

# 开启日志记录
aws cloudtrail start-logging --name my-trail

# 查询 CloudTrail 事件
aws cloudtrail lookup-events \
  --lookup-attributes AttributeKey=Username,AttributeValue=admin \
  --start-time $(date -u -d "-1 day" +%Y-%m-%dT%H:%M:%SZ)
```

### 二、Azure 安全配置命令速查表

#### 1. Azure AD 身份管理

```powershell
# 安装 Azure AD 模块
Install-Module AzureAD

# 连接 Azure AD
Connect-AzureAD

# 启用条件访问策略（要求 MFA）
# 使用 Az CLI
az login

# 创建条件访问策略（要求所有用户 MFA）
az rest --method POST --uri 'https://graph.microsoft.com/v1.0/identity/conditionalAccess/policies' \
  --headers 'Content-Type=application/json' \
  --body '{
    "displayName": "Require MFA for all users",
    "state": "enabled",
    "conditions": {
      "users": { "includeUsers": ["All"] },
      "applications": { "includeApplications": ["All"] }
    },
    "grantControls": {
      "operator": "OR",
      "builtInControls": ["mfa"]
    }
  }'

# 启用密码哈希同步
az ad sync configure --password-hash-sync enabled

# 列出所有用户及其 MFA 状态
az ad user list --query "[].{name:displayName, upn:userPrincipalName}"
```

#### 2. 存储账户安全

```bash
# 创建存储账户（启用 HTTPS 强制和最小 TLS 版本）
az storage account create --name mystorageaccount \
  --resource-group my-rg \
  --sku Standard_GRS \
  --enable-hierarchical-namespace true \
  --min-tls-version TLS1_2 \
  --allow-blob-public-access false \
  --https-only true

# 启用存储账户客户管理密钥加密
az storage account update --name mystorageaccount \
  --resource-group my-rg \
  --encryption-key-source Microsoft.Keyvault \
  --encryption-key-vault https://myvault.vault.azure.net \
  --encryption-key-name mykey

# 启用存储日志
az storage logging update --log rwd --retention 90 \
  --services b \
  --account-name mystorageaccount

# 启用软删除
az storage account blob-service properties update \
  --account-name mystorageaccount \
  --resource-group my-rg \
  --enable-delete-retention true \
  --delete-retention-days 30 \
  --enable-container-delete-retention true \
  --container-delete-retention-days 30
```

#### 3. 网络安全组 (NSG)

```bash
# 创建 NSG
az network nsg create --name my-nsg --resource-group my-rg

# 添加入站安全规则（拒绝 SSH 公网访问）
az network nsg rule create --name DenySSH \
  --nsg-name my-nsg --resource-group my-rg \
  --priority 100 --access Deny --direction Inbound \
  --protocol Tcp --source-address-prefixes '*' \
  --source-port-ranges '*' --destination-address-prefixes '*' \
  --destination-port-ranges 22

# 启用 NSG 流日志
az network watcher flow-log create --name my-flow-log \
  --resource-group my-rg --nsg my-nsg \
  --storage-account mystorageaccount \
  --enabled true --retention 90
```

#### 4. Azure Policy 合规检查

```bash
# 分配内置策略（要求所有资源使用指定位置）
az policy assignment create --name 'allowed-locations' \
  --policy 'e56962a6-4747-49cd-b67b-bf8b01975c4c' \
  --location eastus \
  --params '{ "listOfAllowedLocations": { "value": ["eastus", "westus"] } }'

# 查看合规状态
az policy state summarize --resource-group my-rg

# Azure 安全中心快速扫描
az security assessment list --resource-group my-rg
```

### 三、阿里云安全配置命令速查表

#### 1. RAM 访问控制

```bash
# 安装阿里云 CLI
pip install aliyun-python-sdk-core aliyun-python-sdk-ram

# 配置凭证
aliyun configure set \
  --access-key-id <your-access-key-id> \
  --access-key-secret <your-access-key-secret> \
  --region cn-hangzhou

# 创建 RAM 用户
aliyun ram CreateUser --UserName devuser --DisplayName "Developer"

# 为用户创建 AccessKey
aliyun ram CreateAccessKey --UserName devuser

# 为用户启用 MFA
aliyun ram CreateVirtualMFADevice --VirtualMFADeviceName devuser-mfa

# 绑定 MFA 设备
aliyun ram BindMFADevice \
  --UserName devuser \
  --SerialNumber acs:ram::123456789012:mfa/devuser \
  --AuthenticationCode1 123456 \
  --AuthenticationCode2 789012

# 设置密码策略
aliyun ram SetPasswordPolicy \
  --MinimumPasswordLength 12 \
  --RequireLowercaseCharacters true \
  --RequireUppercaseCharacters true \
  --RequireNumbers true \
  --RequireSymbols true \
  --PasswordReusePrevention 5 \
  --MaxPasswordAge 90

# 创建 RAM 角色（ECS 用）
aliyun ram CreateRole --RoleName ECSReadOnlyRole \
  --AssumeRolePolicyDocument file://ram-role-trust.json
aliyun ram AttachPolicyToRole --PolicyType System \
  --PolicyName AliyunOSSReadOnlyAccess --RoleName ECSReadOnlyRole
```

**RAM Role Trust Policy (ram-role-trust.json)**：
```json
{
  "Statement": [
    {
      "Action": "sts:AssumeRole",
      "Effect": "Allow",
      "Principal": {
        "Service": ["ecs.aliyuncs.com"]
      }
    }
  ],
  "Version": "1"
}
```

#### 2. OSS 对象存储安全

```bash
# 使用 ossutil 工具
# 安装 ossutil

# 启用 KMS 加密
./ossutil64 set-sse oss://my-bucket --sse-algorithm KMS --kms-key-id alias/my-key

# 启用版本控制
./ossutil64 bucket-versioning oss://my-bucket --versioning-status Enabled

# 设置防盗链（Referer 白名单）
./ossutil64 set-referer oss://my-bucket --referer-url "https://*.example.com" --empty-referer false

# 查看桶访问日志配置
./ossutil64 get-bucket-logging oss://my-bucket
```

### 五、云安全配置最佳实践检查清单

```bash
# AWS 快速安全检查脚本（可保存为 aws_security_check.sh）
#!/bin/bash
echo "=== AWS Security Quick Check ==="
echo "[1] Checking IAM users without MFA..."
aws iam list-users --query 'Users[].UserName' --output text | tr '\t' '\n' | while read user; do
  mfa=$(aws iam list-mfa-devices --user-name "$user" --query 'MFADevices' --output text)
  if [ -z "$mfa" ]; then echo "  WARNING: $user has no MFA"; fi
done

echo "[2] Checking access keys older than 90 days..."
# 使用 access-advisor 或自定义脚本检查密钥年龄

echo "[3] Checking public S3 buckets..."
aws s3api list-buckets --query 'Buckets[].Name' --output text | tr '\t' '\n' | while read bucket; do
  status=$(aws s3api get-bucket-policy-status --bucket "$bucket" --query 'PolicyStatus.IsPublic' --output text 2>/dev/null)
  if [ "$status" = "True" ]; then echo "  WARNING: $bucket is public"; fi
done

echo "[4] Checking CloudTrail status..."
aws cloudtrail describe-trails --query 'trailList[].{Name:Name, IsMultiRegion:IsMultiRegionTrail, LogFileValidationEnabled:LogFileValidationEnabled}' --output table

echo "[5] Checking Security Groups with 0.0.0.0/0 SSH access..."
aws ec2 describe-security-groups --filters Name=ip-permission.to-port,Values=22 Name=ip-permission.cidr,Values=0.0.0.0/0 \
  --query 'SecurityGroups[].{GroupId:GroupId, Name:GroupName}' --output table
```
