# 阿里云安全配置

### 2.1 RAM（资源访问管理）

#### 2.1.1 RAM 核心概念

| 概念 | 对应 AWS | 说明 |
|------|----------|------|
| RAM 用户 | IAM User | 具有长期凭证的身份 |
| RAM 用户组 | IAM Group | 用户的集合 |
| RAM 角色 | IAM Role | 临时凭证身份 |
| 权限策略 | IAM Policy | JSON 格式权限定义 |
| AccessKey | Access Key | API 访问密钥 |
| 身份提供商 | Identity Provider | SSO/SAML 联合身份 |

#### 2.1.2 RAM 策略结构

阿里云 RAM 策略与 AWS IAM 策略类似，也是 JSON 格式。

```json
{
    "Version": "1",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "oss:GetObject",
                "oss:ListObjects"
            ],
            "Resource": [
                "acs:oss:*:*:my-bucket",
                "acs:oss:*:*:my-bucket/*"
            ],
            "Condition": {
                "IpAddress": {
                    "acs:SourceIp": "192.168.1.0/24"
                }
            }
        }
    ]
}
```

**与 AWS 的主要区别**：
- Version 为 "1"（AWS 为 "2012-10-17"）
- 资源 ARN 前缀为 `acs:`（阿里云），AWS 为 `arn:aws:`
- 条件前缀为 `acs:`，AWS 为 `aws:`

#### 2.1.3 RAM 安全最佳实践

| 最佳实践 | 配置路径 |
|----------|----------|
| 启用 MFA | RAM 控制台 → 用户 → 安全信息 → 虚拟 MFA |
| 密码策略 | RAM 控制台 → 设置 → 密码策略 |
| 最小权限原则 | 使用自定义策略，避免使用 AliyunFullAccess |
| 定期轮换 AccessKey | RAM 控制台 → 用户 → AccessKey 管理 |
| 使用 RAM 角色 | ECS 实例 RAM 角色、函数计算执行角色 |
| 审计登录事件 | 操作审计（ActionTrail） |
| 限制登录 IP | RAM 策略中添加 IP 条件 |

### 2.2 OSS（对象存储服务）安全配置

#### 2.2.1 OSS 安全配置清单

| 配置项 | 安全要求 | 风险等级 |
|--------|----------|----------|
| 访问权限 | 私有（Private） | 高危 |
| Bucket 策略 | 最小权限原则 | 高危 |
| 服务端加密 | 启用（SSE-KMS 或 SSE-OSS） | 中危 |
| 版本控制 | 启用 | 中危 |
| 访问日志 | 启用 | 中危 |
| 防盗链 | 按需配置 Referer 白名单 | 中危 |
| HTTPS 传输 | 强制 HTTPS | 中危 |
| 跨域配置 | 最小化允许的来源 | 低危 |

#### 2.2.2 OSS Bucket 策略示例

**示例 1：仅允许 VPC 内访问**
```json
{
    "Version": "1",
    "Statement": [
        {
            "Effect": "Allow",
            "Principal": "*",
            "Action": [
                "oss:GetObject"
            ],
            "Resource": [
                "acs:oss:*:*:my-secure-bucket/*"
            ],
            "Condition": {
                "StringEquals": {
                    "oss:SourceVpc": "vpc-bp1234567890abcdef"
                }
            }
        }
    ]
}
```

**示例 2：仅允许特定 IP 段访问**
```json
{
    "Version": "1",
    "Statement": [
        {
            "Effect": "Deny",
            "Principal": "*",
            "Action": [
                "oss:*"
            ],
            "Resource": [
                "acs:oss:*:*:my-secure-bucket",
                "acs:oss:*:*:my-secure-bucket/*"
            ],
            "Condition": {
                "NotIpAddress": {
                    "acs:SourceIp": "10.0.0.0/8"
                }
            }
        }
    ]
}
```

#### 2.2.3 常见 OSS 安全问题与修复

**问题 1：Bucket 设置为公共读**
- **风险**：任何人都可以读取 Bucket 中的文件
- **检测**：控制台查看访问权限为"公共读"或"公共读写"
- **修复**：将访问权限改为"私有"

**问题 2：Bucket Policy 配置过宽**
- **风险**：策略中允许 `Principal: "*"` 且 Effect 为 Allow
- **检测**：检查 Bucket 策略中的 Principal 和 Action
- **修复**：限制 Principal 为特定 RAM 用户/角色，或添加条件限制

**问题 3：服务端加密未启用**
- **风险**：数据明文存储在磁盘上
- **检测**：查看 Bucket 加密配置
- **修复**：启用 SSE-OSS 或 SSE-KMS 加密

### 2.3 ECS（云服务器）安全配置

#### 2.3.1 ECS 安全基线

| 配置项 | 安全要求 |
|--------|----------|
| 远程访问 | 限制安全组来源 IP |
| 密钥对 | 使用 SSH 密钥对，禁用密码登录 |
| RAM 角色 | 为 ECS 实例绑定 RAM 角色 |
| 安全组 | 最小权限原则 |
| 系统加固 | 禁用 root 远程登录、修改 SSH 端口 |
| 补丁管理 | 定期更新系统补丁 |
| 安全软件 | 安装云安全中心 Agent |
| 磁盘加密 | 系统盘和数据盘启用加密 |

#### 2.3.2 ECS 实例元数据服务

阿里云 ECS 也提供元数据服务，地址为 `100.100.100.200`。

**可获取的敏感信息**：
- 实例 ID、IP、hostname
- RAM 角色的临时凭证
- 用户数据（user-data）

**防护措施**：
- 使用 IMDSv2（需要令牌）
- 为 ECS 实例角色授予最小权限
- 防御 SSRF 漏洞

### 2.4 安全组配置

阿里云安全组与 AWS 安全组功能类似，都是实例级别的有状态防火墙。

#### 2.4.1 安全组最佳实践

| 最佳实践 | 说明 |
|----------|------|
| 最小化入站规则 | 只开放必要的端口 |
| 限制授权对象 | 使用安全组 ID 或具体 IP，避免 0.0.0.0/0 |
| 按用途分组 | Web、数据库、应用分别使用不同安全组 |
| 禁止公网开放高危端口 | 22、3389、3306、6379 等不应对公网开放 |
| 定期审计 | 定期检查安全组规则的合理性 |

#### 2.4.2 常见高危端口清单

| 端口 | 服务 | 风险 | 建议 |
|------|------|------|------|
| 22 | SSH | 暴力破解 | 限制来源 IP，使用密钥登录 |
| 3389 | RDP | 暴力破解 | 限制来源 IP，使用强密码 |
| 3306 | MySQL | 数据泄露 | 禁止公网访问，放私有子网 |
| 6379 | Redis | 未授权访问 | 禁止公网访问，设置密码 |
| 27017 | MongoDB | 未授权访问 | 禁止公网访问，设置认证 |
| 11211 | Memcached | 未授权访问 | 禁止公网访问 |
| 2375 | Docker API | 远程代码执行 | 禁止公网访问 |

### 2.5 操作审计（ActionTrail）

#### 2.5.1 操作审计概述

阿里云操作审计（ActionTrail）记录阿里云账户的所有 API 操作日志，功能类似 AWS CloudTrail。

**记录内容**：
- 操作人（RAM 用户/角色/主账号）
- 操作时间
- 操作名称（API 名称）
- 源 IP 地址
- 操作结果
- 请求参数

#### 2.5.2 关键监控事件

| 事件名称 | 说明 | 风险等级 |
|----------|------|----------|
| ConsoleSignin | 控制台登录 | 高危（失败登录） |
| CreateUser / DeleteUser | RAM 用户变更 | 高危 |
| CreateAccessKey | 创建 AccessKey | 高危 |
| AssumeRole | 扮演角色 | 中危 |
| SetBucketPolicy / PutBucketPolicy | 修改 OSS 策略 | 高危 |
| AuthorizeSecurityGroup | 安全组添加规则 | 高危 |
| CreateInstance / RunInstances | 创建实例 | 中危 |
| DeleteInstance / StopInstance | 删除/停止实例 | 高危 |
| CreateTrail / UpdateTrail / DeleteTrail | 操作审计配置变更 | 高危 |
