# 跨组织认证

### 5.1 跨域信任建立

```text
跨域信任建立流程

步骤1: 信任协商
  组织A ←→ 组织B: 确定联邦范围、安全要求
  确定认证协议（SAML/OIDC）
  确定属性映射规则
  确定安全策略

步骤2: 元数据交换
  组织A → 组织B: A的IdP/SP元数据
  组织B → 组织A: B的IdP/SP元数据
  元数据包含: 实体ID、端点、证书、支持的功能

步骤3: 证书交换与验证
  交换签名证书
  验证证书信任链
  导入信任存储

步骤4: 属性映射配置
  组织A的属性 → 组织B的属性
  例: A的"employeeId" → B的"staffNumber"
  配置映射规则

步骤5: 测试验证
  测试认证流程
  测试属性传递
  测试单点注销
  测试异常处理

步骤6: 监控与审计
  建立联合审计日志
  异常告警机制
  定期信任审查
```

### 5.2 身份映射与属性转换

```text
属性映射与转换

场景: 组织A的用户访问组织B的资源

组织A的用户属性:
{
  "employeeId": "EMP001",
  "displayName": "张三",
  "email": "zhangsan@orgA.com",
  "department": "研发部",
  "clearance": "L3"
}

组织B需要的属性:
{
  "staffNumber": "EMP001",      ← 从employeeId映射
  "fullName": "Zhang San",      ← 从displayName转换(拼音)
  "email": "zhangsan@orgA.com", ← 直接传递
  "org": "R&D",                 ← 从department映射
  "accessLevel": "CONFIDENTIAL" ← 从clearance L3映射
}

映射类型:
├── 直接映射: A→B (email → email)
├── 重命名: employeeId → staffNumber
├── 值转换: 研发部 → R&D
├── 格式转换: 中文名 → 拼音
└── 级别映射: L3 → CONFIDENTIAL

映射实现:
├── IdP端映射: IdP在断言中直接提供SP需要的属性
├── SP端映射: SP接收原始属性后本地映射
└── 中间件映射: 联邦中间件负责属性转换
```
