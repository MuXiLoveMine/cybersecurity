# 企业身份联邦

### 6.1 企业联邦架构

```text
企业身份联邦典型架构

场景1: 企业与SaaS联邦
┌──────────┐     SAML/OIDC     ┌──────────┐
│ 企业IdP  │◄─────────────────►│ SaaS应用 │
│ (AD FS  │                    │ (Office  │
│  Okta)  │                    │  365)    │
└──────────┘                    └──────────┘
员工用企业账号 → 访问SaaS

场景2: 企业间联邦
┌──────────┐     SAML联邦     ┌──────────┐
│ 企业A    │◄────────────────►│ 企业B    │
│ IdP     │                    │ SP      │
└──────────┘                    └──────────┘
企业A员工 → 访问企业B的协作系统

场景3: 多云联邦
┌──────────┐     OIDC     ┌──────────┐     OIDC     ┌──────────┐
│ 企业IdP  │◄────────────►│ 云平台A   │◄────────────►│ 云平台B   │
│         │              │ (AWS)   │              │ (Azure)  │
└──────────┘              └──────────┘              └──────────┘
企业账号 → 统一访问多个云

场景4: 教育联邦 (eduGainer)
┌──────────┐     Shibboleth     ┌──────────┐
│ 大学A    │◄─────────────────►│ 大学B    │
│ IdP     │     联邦联盟       │ SP      │
└──────────┘                    └──────────┘
学生用本校账号 → 访问其他大学资源
```

### 6.2 常见联邦场景

```text
常见企业联邦场景

1. Office 365联邦
   ├── 企业AD FS → Office 365 (SAML)
   ├── 员工用AD账号登录Office 365
   └── 密码同步或联邦认证

2. Salesforce联邦
   ├── 企业IdP → Salesforce (SAML)
   ├── 支持Just-In-Time用户配置
   └── 自动创建/更新Salesforce用户

3. AWS联邦
   ├── 企业IdP → AWS (SAML/OIDC)
   ├── 支持角色映射(IdP组 → AWS角色)
   └── STS临时凭证

4. GitHub联邦
   ├── 企业IdP → GitHub (SAML)
   ├── 团队映射(IdP组 → GitHub团队)
   └── 组织级SCIM用户同步

5. 自定义应用联邦
   ├── 企业IdP → 内部应用 (SAML/OIDC)
   ├── 自定义属性映射
   └── 自定义授权策略

联邦产品:
├── 微软: Azure AD / AD FS
├── Okta: Okta Identity Cloud
├── Ping: PingIdentity
├── Google: Google Workspace
├── Keycloak: 开源方案
└── Shibboleth: 教育行业方案
```
