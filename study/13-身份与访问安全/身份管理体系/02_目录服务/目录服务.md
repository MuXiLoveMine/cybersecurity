# 目录服务

### 2.1 目录服务概述

**目录服务（Directory Service）**：一种专门用于存储、检索和管理分布式信息的数据库服务，主要存储用户、设备、应用等身份相关信息。

**目录服务的特点**：
- 读多写少的优化（查询频繁，修改较少）
- 树形层次结构
- 支持复杂查询
- 分布式架构，可复制
- 标准协议访问（LDAP）

### 2.2 LDAP 协议

**LDAP（Lightweight Directory Access Protocol）**：轻量级目录访问协议，是访问目录服务的标准协议。

**LDAP 数据模型**：

| 概念 | 说明 | 类比 |
|------|------|------|
| 条目（Entry） | 目录中的基本单元 | 数据库中的一行记录 |
| 属性（Attribute） | 条目的特性 | 数据库中的字段 |
| 对象类（ObjectClass） | 属性的集合，定义条目类型 | 数据库中的表结构 |
| DN（Distinguished Name） | 条目的唯一标识 | 主键 + 完整路径 |
| RDN（Relative DN） | 相对唯一标识 | 相对路径 |

**LDAP 目录树示例**：
```
dc=example,dc=com
├── ou=people
│   ├── uid=alice
│   │   ├── cn: Alice Wang
│   │   ├── mail: alice@example.com
│   │   ├── telephoneNumber: 12345
│   │   └── objectClass: inetOrgPerson
│   └── uid=bob
│       ├── cn: Bob Li
│       └── ...
├── ou=groups
│   ├── cn=developers
│   │   ├── member: uid=alice,ou=people,...
│   │   └── member: uid=bob,ou=people,...
│   └── cn=admins
│       └── ...
└── ou=devices
    └── ...
```

**常用 LDAP 操作**：

| 操作 | 说明 |
|------|------|
| Bind | 认证连接 |
| Search | 搜索查询条目 |
| Add | 添加新条目 |
| Modify | 修改条目属性 |
| Delete | 删除条目 |
| Compare | 比较属性值 |

**LDAP 搜索过滤器示例**：
```
# 查找所有用户
(objectClass=person)

# 查找用户名为alice的用户
(&(objectClass=person)(uid=alice))

# 查找开发部门的所有用户
(&(objectClass=person)(ou=developers))

# 查找姓"王"且邮箱在example.com的用户
(&(objectClass=person)(sn=王*)(mail=*@example.com))
```

### 2.3 Active Directory (AD)

**Active Directory**：微软的目录服务，是 Windows 域环境的核心，广泛应用于企业 IT 基础设施。

#### AD 核心概念

| 概念 | 说明 |
|------|------|
| 域（Domain） | 安全边界，一组计算机和用户的集合 |
| 域控制器（DC） | 运行 AD 服务的服务器 |
| 林（Forest） | 一个或多个域树的集合，最高安全边界 |
| 域树（Tree） | 共享连续命名空间的域集合 |
| OU（组织单元） | 域内的管理单元，用于组织对象 |
| 组（Group） | 用户/计算机的集合，用于分配权限 |
| GPO（组策略） | 批量配置计算机和用户设置 |

**AD 逻辑结构**：
```
Forest: example.com
├── Tree: example.com
│   ├── Domain: example.com
│   │   ├── OU: HQ
│   │   │   ├── OU: Users
│   │   │   ├── OU: Computers
│   │   │   └── OU: Groups
│   │   └── OU: Servers
│   └── Domain: child.example.com
│       └── ...
└── Tree: otherdomain.com
    └── ...
```

#### AD 对象类型

| 对象类型 | 说明 | 安全标识符（SID） |
|----------|------|-------------------|
| 用户（User） | 人员账号 | 用户SID |
| 计算机（Computer） | 加入域的计算机 | 计算机SID |
| 组（Group） | 用户/计算机的集合 | 组SID |
| OU | 组织单元 | 无SID（不是安全主体） |
| 联系人（Contact） | 外部联系人信息 | 无SID |
| 打印机 | 共享打印机 | 无SID |

#### AD 组类型与作用域

**组类型**：
- **安全组**：用于分配权限，也可用于邮件
- **通讯组**：仅用于邮件分发，无安全功能

**组作用域**：

| 作用域 | 成员来源 | 权限范围 | 可嵌套 |
|--------|---------|----------|--------|
| 本地域组（Domain Local） | 所有信任域 | 本域 | 不能嵌套全局组 |
| 全局组（Global） | 本域 | 所有信任域 | 可嵌套到本地域组 |
| 通用组（Universal） | 林中所有域 | 林中所有域 | 可互相嵌套 |

**AGDLP 原则**（推荐的组策略使用方式）：
```
用户账户 (Accounts)
   → 加入全局组 (Global Groups)
      → 加入本地域组 (Domain Local Groups)
         → 分配权限 (Permissions)
```

#### AD 认证协议

| 协议 | 说明 | 用途 |
|------|------|------|
| Kerberos | 票据认证协议 | 域内主要认证协议 |
| NTLM | 挑战-响应认证 | 旧系统兼容、工作组环境 |
| LDAP Bind | LDAP绑定认证 | 应用集成 |
| Certificate | 证书认证 | 智能卡等 |

### 2.4 AD 安全 - Kerberos 协议

#### Kerberos 简介

**Kerberos**：一种网络认证协议，使用票据机制，无需在网络上传输密码，是 AD 域环境的核心认证协议。

**Kerberos 三个角色**：

| 角色 | 名称 | 说明 |
|------|------|------|
| 客户端 | Client | 请求访问的用户/服务 |
| 服务端 | Server | 提供资源的服务 |
| KDC | Key Distribution Center | 密钥分发中心（AS + TGS） |

**KDC 的两个组件**：
- **AS（Authentication Service）**：认证服务，颁发 TGT
- **TGS（Ticket Granting Service）**：票据授予服务，颁发 ST

#### Kerberos 认证流程

```
用户登录阶段：
1. 客户端 → AS: 认证请求 (预认证数据)
2. AS → 客户端: TGT (票据授予票据，用krbtgt哈希加密)

服务访问阶段：
3. 客户端 → TGS: 请求服务票据 + TGT
4. TGS → 客户端: ST (服务票据，用服务账号哈希加密)
5. 客户端 → 服务端: ST + Authenticator
6. 服务端 → 客户端: 验证响应 (可选)
```

**详细步骤**：

**第一步：获取 TGT（AS-REQ / AS-REP）**
```
AS-REQ (客户端 → KDC)：
- 用户Principal名称
- 服务Principal名称: krbtgt/域
- 时间戳（用用户密码哈希加密，用于预认证）

AS-REP (KDC → 客户端)：
- TGT (包含：会话密钥、用户信息、有效期)
  TGT 使用 krbtgt 账号的密码哈希加密
- 登录会话密钥 (用用户密码哈希加密)
```

**第二步：获取 ST（TGS-REQ / TGS-REP）**
```
TGS-REQ (客户端 → KDC)：
- TGT
- 认证符 (Authenticator，用会话密钥加密)
- 请求的服务Principal名称

TGS-REP (KDC → 客户端)：
- 服务票据 ST (包含：服务会话密钥、用户信息、有效期)
  ST 使用服务账号的密码哈希加密
- 服务会话密钥 (用登录会话密钥加密)
```

**第三步：访问服务（AP-REQ / AP-REP）**
```
AP-REQ (客户端 → 服务端)：
- ST
- 认证符 (用服务会话密钥加密)

服务端验证：
1. 用自己的密码哈希解密ST，获得服务会话密钥
2. 用服务会话密钥解密认证符
3. 验证时间戳（防重放）
4. 验证用户权限

AP-REP (服务端 → 客户端)：
- 可选，用于双向认证
```

#### Kerberos 安全特性

| 特性 | 说明 |
|------|------|
| 不传输密码 | 网络中没有明文或哈希密码 |
| 对称加密 | 使用对称加密（通常AES） |
| 时间敏感 | 票据有有效期，防重放 |
| 单点登录 | 一次认证，访问多个服务 |
| 相互认证 | 客户端和服务端互相验证 |

### 2.5 AD 攻击与防护

#### 常见 AD 攻击技术

| 攻击名称 | 原理 | 风险等级 |
|----------|------|----------|
| Pass-the-Hash (PtH) | 传递NTLM哈希进行认证 | 高 |
| Pass-the-Ticket (PtT) | 传递Kerberos票据进行认证 | 高 |
| 黄金票据（Golden Ticket） | 伪造TGT，拥有域内所有权限 | 极高 |
| 白银票据（Silver Ticket） | 伪造ST，访问特定服务 | 高 |
| Kerberoasting | 请求服务票据，离线破解服务账号密码 | 中高 |
| AS-REP Roasting | 对不需要预认证的用户，离线破解密码 | 中 |
| DCSync | 模拟DC同步，获取域内所有密码哈希 | 极高 |
| DCShadow | 伪造DC，注入恶意对象 | 极高 |

#### 攻击详解：黄金票据（Golden Ticket）

**原理**：
- 攻击者获取 krbtgt 账号的密码哈希
- 使用 krbtgt 哈希伪造任意用户的 TGT
- 拥有伪造的 TGT 就可以访问域内任何资源

**攻击步骤**：
```
1. 获取域管理员权限（或krbtgt哈希）
2. 提取krbtgt账号的NTLM哈希
3. 使用Mimikatz等工具伪造TGT：
   mimikatz "kerberos::golden /user:Administrator /domain:example.com /sid:S-1-5-21-... /krbtgt:哈希值 /ptt"
4. 注入伪造的TGT到内存
5. 以域管理员身份访问任意服务
```

**防护措施**：
- 保护 krbtgt 账号（强密码、定期更改）
- 限制域管理员登录范围
- 实施分层架构（Tier Model）
- 监控异常的 Kerberos 票据
- 定期轮换 krbtgt 密码（建议每半年）

#### 攻击详解：白银票据（Silver Ticket）

**原理**：
- 攻击者获取服务账号的密码哈希
- 伪造针对该服务的 ST（服务票据）
- 只能访问特定服务，比黄金票据范围小

**与黄金票据对比**：

| 特性 | 黄金票据 | 白银票据 |
|------|----------|----------|
| 所需哈希 | krbtgt 哈希 | 服务账号哈希 |
| 票据类型 | TGT | ST |
| 访问范围 | 所有服务 | 特定服务 |
| 与KDC交互 | 不需要 | 不需要 |
| 检测难度 | 较难（流量少） | 较难（流量少） |

#### 攻击详解：Kerberoasting

**原理**：
- 任何域用户都可以请求任意服务的服务票据（ST）
- ST 使用服务账号的密码哈希加密
- 攻击者可以请求 ST 后离线破解服务账号密码

**攻击步骤**：
```
1. 查找SPN（服务主体名称）对应的服务账号
2. 请求该服务的ST（不需要特殊权限）
3. 导出ST
4. 使用Hashcat等工具离线破解
5. 获得服务账号明文密码
```

**防护措施**：
- 服务账号使用强密码（越长越好）
- 定期轮换服务账号密码
- 监控异常的 TGS 请求
- 使用托管服务账号（MSA/组MSA）
- 限制普通用户可请求的SPN

#### 攻击详解：Pass-the-Hash

**原理**：
- NTLM 认证使用密码哈希
- 攻击者不需要明文密码，只要哈希就能认证

**攻击步骤**：
```
1. 从内存或SAM数据库中获取用户NTLM哈希
2. 使用Mimikatz或其他工具进行PtH攻击
3. 直接使用哈希进行认证，访问目标系统
```

**防护措施**：
- 限制管理员登录范围（防止哈希被窃取）
- 实施 LSA 保护（RunAsPPL）
- 使用 Windows Defender Credential Guard
- 禁用 NTLM，改用 Kerberos
- 管理员账号使用受保护的用户组

#### 攻击详解：DCSync

**原理**：
- 利用 AD 复制功能
- 模拟域控制器向其他DC请求同步数据
- 获取域内所有用户的密码哈希

**前提条件**：
- 拥有以下权限之一：
  - 域管理员权限
  - 复制目录更改（DS-Replication-Get-Changes）
  - 复制目录更改全部（DS-Replication-Get-Changes-All）

**防护措施**：
- 严格控制复制权限
- 监控域控制器之间的复制流量
- 监控异常的复制请求来源
- 实施分层架构

#### AD 防护体系：分层架构（Tier Model）

**微软推荐的 AD 分层安全模型**：

```
Tier 0: 管理员层（最高权限）
├── 域控制器
├── 域管理员
├── 企业管理员
└── 关键基础设施
    │
    │ 严格隔离，只能从专用管理工作站访问
    ▼
Tier 1: 服务器/应用层
├── 成员服务器
├── 应用服务器
├── 数据库服务器
└── 服务器管理员
    │
    ▼
Tier 2: 工作站/用户层
├── 用户计算机
├── 普通用户
└── 帮助台
```

**分层原则**：
- 高层级账号不能登录低层级设备
- 低层级账号不能管理高层级资源
- 各层之间使用独立的管理员账号
- Tier 0 账号只能在专用管理工作站使用
