# 身份生命周期管理

### 3.1 什么是身份生命周期

**身份生命周期（Identity Lifecycle）**：指一个身份从创建到删除的整个过程，涵盖身份存在的所有阶段。

**生命周期阶段**：
```
创建 → 变更 → 停用 → 删除
  │      │      │
  └──────┴──────┴──→ 审计（贯穿始终）
```

### 3.2 各阶段详细说明

#### 阶段一：创建（Create）

**触发事件**：
- 新员工入职
- 新合作伙伴接入
- 新应用系统上线
- 临时人员加入

**关键活动**：
1. **身份创建**：在目录系统中创建账号
2. **属性维护**：填写姓名、部门、职位等信息
3. **权限分配**：根据角色分配初始权限
4. **账号开通**：开通相关系统访问权限
5. **通知**：通知用户和相关人员

**最佳实践**：
- 自动化：与HR系统集成，入职自动创建账号
- 标准化：统一命名规则、初始密码策略
- 最小权限：只分配岗位必需的初始权限
- 审核：关键账号需要审批

#### 阶段二：变更（Change）

**触发事件**：
- 岗位调整、晋升
- 部门调动
- 职位变更
- 姓名变更

**关键活动**：
1. **属性更新**：更新部门、职位、上级等信息
2. **权限调整**：增加/移除权限
3. **角色变更**：分配新角色，回收旧角色
4. **权限审查**：确保新权限合理

**常见问题**：
- 权限只加不减（权限累积）
- 调动后原部门权限未回收
- 角色变更没有审批

**最佳实践**：
- 基于角色的权限调整
- 自动触发：HR系统变更自动同步
- 权限变更需要审批
- 定期清理过期权限

#### 阶段三：停用（Disable/Suspend）

**触发事件**：
- 员工离职
- 长期休假
- 账号异常
- 合同到期

**关键活动**：
1. **禁用账号**：立即禁用登录权限
2. **回收权限**：回收所有访问权限
3. **数据处理**：处理用户数据（转交、归档）
4. **通知**：通知相关人员和系统管理员

**离职流程关键控制点**：
```
离职申请 → HR确认 → 直属经理确认
    ↓
IT账号回收（邮件、系统、VPN等）
    ↓
物理权限回收（门禁、钥匙等）
    ↓
资产回收（电脑、手机等）
    ↓
最终确认 → 账号归档/删除
```

**重要原则**：离职即停用，零时差！

#### 阶段四：删除（Delete）

**触发事件**：
- 离职一段时间后
- 确认不再需要该身份
- 合规要求的清理

**关键活动**：
1. **数据归档**：必要数据归档保存
2. **权限清理**：清理所有关联权限
3. **账号删除**：从目录系统中删除
4. **审计记录**：保留操作日志

**保留策略**：
- 账号可以删除，但审计日志应长期保留
- 员工邮件和数据按法规要求保留
- 建议保留30-90天后再永久删除

### 3.3 身份生命周期自动化

#### HR 驱动的身份管理

```
HR系统 (数据源)
    │
    ├── 入职 → 自动创建账号 + 分配角色权限
    ├── 调岗 → 自动调整属性 + 权限变更
    ├── 离职 → 自动禁用账号 + 回收权限
    └── 信息更新 → 自动同步属性
```

**自动化的价值**：
- 减少人工操作错误
- 提高效率，缩短账号开通时间
- 确保权限及时回收
- 满足合规要求

#### 工作流驱动

| 操作 | 审批流程 |
|------|----------|
| 新账号创建 | 直属经理审批 → IT执行 |
| 权限申请 | 资源所有者审批 → IT执行 |
| 特权权限申请 | 多级审批 → 安全团队审核 |
| 账号删除 | HR确认 → IT执行 |
