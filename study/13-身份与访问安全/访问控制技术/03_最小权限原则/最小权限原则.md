# 最小权限原则

### 3.1 什么是最小权限原则

**定义**：最小权限原则（Principle of Least Privilege，PoLP）规定每个用户、程序或进程只应拥有完成其预定任务所必需的**最少权限**。

**核心思想**：
- "够用即可"，不要过度授权
- 权限是一种风险，多余的权限就是多余的风险
- 默认拒绝，按需授予

**最小权限的三个层面**：

| 层面 | 说明 | 示例 |
|------|------|------|
| 用户权限 | 用户只拥有工作需要的权限 | 普通员工没有管理员权限 |
| 进程权限 | 程序只运行在必要的权限下 | Web服务器不以root运行 |
| 系统权限 | 系统组件间权限隔离 | 数据库账号只有SELECT权限 |

### 3.2 为什么需要最小权限

**安全收益**：

1. **减少攻击面**：权限越小，被攻破后的影响范围越小
2. **限制横向移动**：攻击者难以从一个系统跳到另一个系统
3. **减少误操作**：权限受限，误操作的破坏也有限
4. **降低内部威胁**：内部人员也无法滥用权限

**真实案例**：
> 2013年 Target 数据泄露事件中，攻击者最初通过钓鱼获取了一个 HVAC（暖通空调）供应商的账号。该供应商账号本应只有有限的访问权限，但实际上却拥有广泛的网络访问权，导致攻击者能够横向移动到POS系统，窃取了4000万张信用卡信息。
>
> **教训**：第三方账号也应遵循最小权限原则，严格限制其访问范围。

### 3.3 最小权限实践

#### 用户权限管理

| 实践 | 说明 |
|------|------|
| 默认无权限 | 新用户默认没有任何权限，按需申请 |
| 按需申请 | 用户根据工作需要申请具体权限 |
| 定期审查 | 每季度/半年审查一次权限，回收不再需要的 |
| 离职清理 | 员工离职时立即回收所有权限 |
| 权限分级 | 普通权限/敏感权限/特权权限分级管理 |

#### 系统服务配置

**错误做法**：
```bash
# 以 root 身份运行 Nginx（危险！）
nginx: master process /usr/sbin/nginx  # root 运行
```

**正确做法**：
```bash
# 主进程以 root 运行（绑定80端口需要），工作进程以 nobody 运行
nginx: master process /usr/sbin/nginx     # root (仅绑定端口)
nginx: worker process                     # nobody (处理请求)
```

#### 数据库权限

**错误做法**：
```sql
-- 应用使用 root 账号（危险！）
GRANT ALL PRIVILEGES ON *.* TO 'app'@'%' IDENTIFIED BY 'password';
```

**正确做法**：
```sql
-- 只授予必要的权限
GRANT SELECT, INSERT, UPDATE ON mydb.* TO 'app'@'app-server' IDENTIFIED BY 'strong_password';

-- 删除权限用单独的账号
GRANT DELETE ON mydb.* TO 'app_delete'@'app-server' IDENTIFIED BY 'another_password';
```

### 3.4 最小权限的常见误区

| 误区 | 正确做法 |
|------|----------|
| "图省事"给多一点权限 | 严格按职责分配，宁可少给也不多给 |
| 权限分配后从不审查 | 定期审查权限，及时回收 |
| 一个账号用到底 | 按场景使用不同权限的账号 |
| 第三方/供应商权限宽松 | 第三方权限更要严格限制 |
| 测试环境无所谓 | 测试环境也可能有真实数据 |
