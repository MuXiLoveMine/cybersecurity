# 权限分离（职责分离）

### 4.1 什么是权限分离

**定义**：权限分离（Separation of Duties，SoD），也叫职责分离，指将关键任务拆分为多个步骤，分别由不同的人或角色负责，以防止单个人能够独立完成舞弊行为。

**核心思想**：
- 权力制衡，相互监督
- 任何人都不能独立完成高风险操作
- "两个人才能开金库"

### 4.2 常见的职责分离场景

| 场景 | 应分离的职责 | 原因 |
|------|-------------|------|
| 财务 | 申请人 ≠ 审批人 ≠ 出纳 | 防止虚报冒领 |
| IT运维 | 开发 ≠ 测试 ≠ 生产部署 | 防止代码后门 |
| 采购 | 采购员 ≠ 验收员 ≠ 付款员 | 防止虚假采购 |
| 系统管理 | 系统管理员 ≠ 安全管理员 ≠ 审计员 | 防止滥用权限 |
| 数据库 | DBA ≠ 业务用户 ≠ 审计员 | 防止数据篡改 |

### 4.3 SoD 在访问控制中的实现

#### 静态职责分离（Static SoD）
- 在角色分配阶段就实施分离
- 用户不能同时拥有两个互斥角色

```
互斥角色对示例：
- "采购申请" 和 "采购审批" 互斥
- "记账" 和 "审计" 互斥
- "系统管理员" 和 "安全审计员" 互斥

规则：
IF 用户有角色A AND 角色A与角色B互斥
THEN 用户不能被分配角色B
```

#### 动态职责分离（Dynamic SoD）
- 用户可以拥有多个互斥角色，但不能在同一会话中同时激活

```
示例：
用户张三同时拥有"采购员"和"审批员"两个角色
但在同一会话中，他只能激活其中一个角色
不能既以采购员身份申请，又以审批员身份审批
```

#### 基于操作的职责分离
- 同一用户不能对同一记录执行两个互斥操作

```
示例：
创建合同的人不能审批同一份合同
发起转账的人不能审核同一笔转账
```

### 4.4 SoD 冲突检测

**SoD 矩阵示例**：

| 角色 | 采购申请 | 采购审批 | 财务付款 | 合同审核 |
|------|----------|----------|----------|----------|
| 采购申请 | - | ✅冲突 | ❌ | ❌ |
| 采购审批 | ✅冲突 | - | ✅冲突 | ❌ |
| 财务付款 | ❌ | ✅冲突 | - | ❌ |
| 合同审核 | ❌ | ❌ | ❌ | - |

**冲突检测算法**：
```
检查用户是否同时拥有互斥角色对中的两个角色：
1. 获取用户的所有角色列表
2. 遍历所有互斥角色对
3. 检查互斥对中的两个角色是否都在用户角色列表中
4. 如果存在冲突，阻止分配或触发告警
```
