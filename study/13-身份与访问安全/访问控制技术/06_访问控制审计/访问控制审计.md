# 访问控制审计

### 6.1 审计的目的

访问控制审计是对访问控制机制的有效性进行审查和评估，确保：
- 访问控制策略正确实施
- 权限分配合理合规
- 异常访问行为被发现
- 满足合规要求（等保、ISO27001、GDPR等）

### 6.2 审计类型

| 审计类型 | 说明 | 频率 |
|----------|------|------|
| 实时审计 | 实时监控访问行为，异常告警 | 持续 |
| 定期审计 | 定期审查权限分配和访问日志 | 月度/季度 |
| 专项审计 | 针对特定事件或问题的审计 | 按需 |
| 合规审计 | 为满足合规要求的审计 | 年度 |

### 6.3 审计内容

#### 权限分配审计
- 检查是否有权限过大的用户
- 检查离职人员权限是否回收
- 检查角色分配是否合理
- 检查职责分离是否违反

#### 访问行为审计
- 特权账号使用情况
- 异常时间的访问
- 异常地点的访问
- 敏感资源的访问
- 失败的登录尝试

#### 策略合规审计
- 访问控制策略是否符合安全要求
- 策略执行是否到位
- 例外情况是否有审批

### 6.4 关键审计指标（KRI）

| 指标 | 说明 | 关注阈值 |
|------|------|----------|
| 特权账号数量 | 拥有特权的账号数 | 应保持最小化 |
| 孤儿账号 | 无主账号、离职未回收 | 应为0 |
| 权限超标率 | 权限超出岗位需求的比例 | 应<5% |
| SoD冲突数 | 职责分离违规数量 | 应为0 |
| 失败登录率 | 登录失败/总登录 | 异常升高告警 |
| 特权操作数 | 特权命令执行数量 | 异常升高告警 |
| 权限审查覆盖率 | 定期审查覆盖的比例 | 应100% |

### 6.5 审计日志要求

**日志应记录的内容**：

| 字段 | 说明 | 示例 |
|------|------|------|
| 时间戳 | 事件发生时间 | 2024-01-15 14:30:25 |
| 主体 | 谁发起的 | 用户ID、IP地址 |
| 客体 | 访问了什么 | 资源路径、文件名 |
| 操作 | 执行了什么动作 | 登录、读取、修改、删除 |
| 结果 | 成功还是失败 | 成功/失败/拒绝 |
| 详情 | 额外信息 | 失败原因、数据量 |

**日志管理要求**：
- 日志不可篡改（WORM存储、区块链等）
- 日志保留足够时间（如6个月-1年）
- 日志集中管理（SIEM）
- 定期备份
- 访问日志本身也需要权限控制
