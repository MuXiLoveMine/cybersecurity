# 特权账号管理（PAM）

### 5.1 什么是特权账号

**特权账号（Privileged Account）**：指拥有超出普通用户权限的账号，通常可以访问敏感资源、执行管理操作、修改系统配置。

**常见特权账号类型**：

| 类型 | 说明 | 示例 |
|------|------|------|
| 超级管理员 | 系统最高权限 | root、Administrator、域管理员 |
| 系统管理员 | 操作系统管理 | Linux sudo用户、Windows管理员组 |
| 数据库管理员 | 数据库管理 | DBA、sa、sys |
| 网络管理员 | 网络设备管理 | 路由器、交换机、防火墙管理员 |
| 应用管理员 | 应用系统管理 | ERP管理员、邮件管理员 |
| 服务账号 | 应用/服务运行账号 | 应用池账号、定时任务账号 |
| 应急账号 | 紧急情况下使用 | break-glass账号 |
| 测试账号 | 测试环境使用 | test_admin |

**为什么特权账号需要特殊管理**：
- 权限最大，攻击价值最高
- 是攻击者的首要目标
- 一旦泄露，影响范围最广
- 内部人员滥用风险高

### 5.2 PAM 核心功能

**PAM（Privileged Access Management，特权访问管理）**是一套用于管理、控制和审计特权账号访问的安全解决方案。

**PAM 核心功能模块**：

```
┌─────────────────────────────────────────────────┐
│              特权访问管理 (PAM)                   │
├─────────────┬─────────────┬───────────┬─────────┤
│  密码金库    │  会话管理    │  命令控制  │  审计   │
│  (Vault)    │  (Session)  │  (Command)│ (Audit) │
└─────────────┴─────────────┴───────────┴─────────┘
```

#### 1. 特权账号金库（Password Vault）

**功能**：
- 集中存储所有特权账号密码
- 加密存储（AES-256等）
- 严格的访问控制
- 自动密码轮换

**密码轮换**：
```
传统方式：密码手动管理，可能几年不改
PAM方式：每次使用后自动轮换，密码随机生成
```

#### 2. 会话管理（Session Management）

**功能**：
- 用户不直接接触密码
- 通过PAM系统代理连接
- 会话录制（录像/键盘记录）
- 实时监控和会话中断

**工作原理**：
```
用户 → PAM系统 → 目标服务器
        │
        ├── 用户不知道真实密码
        ├── PAM记录所有操作
        └── 管理员可以实时监控和中断
```

#### 3. 命令控制（Command Control）

**功能**：
- 命令白名单/黑名单
- 危险命令拦截
- 高风险命令需要审批
- 命令级别的细粒度控制

**示例规则**：
```
允许：ls, cd, cat, grep, systemctl status
禁止：rm -rf /, fdisk, mkfs, useradd, passwd root
需审批：reboot, shutdown, yum update, 修改防火墙规则
```

#### 4. 即时权限（Just-In-Time，JIT）

**核心思想**：特权权限不常驻，按需申请、即时授权、用完即收。

**JIT 工作流程**：
```
1. 用户申请特权权限（选择服务器、时长、原因）
2. 审批人审批
3. 审批通过后，临时授予权限（如30分钟）
4. 用户在有效期内使用特权
5. 到期后自动回收权限
6. 操作记录归档审计
```

**JIT 的优势**：
- 大幅减少特权账号的暴露时间
- 符合最小权限原则
- 所有特权使用都有申请和审批记录
- 降低持久化特权的风险

### 5.3 PAM 实施最佳实践

1. **发现和盘点**：找出所有特权账号，包括服务账号、应急账号
2. **集中管理**：所有特权账号纳入金库管理
3. **自动轮换**：密码定期自动更换，使用后立即更换
4. **MFA保护**：访问PAM系统必须经过多因素认证
5. **最小权限**：只授予必要的特权，能用普通权限就不用特权
6. **会话审计**：所有特权会话全程录制
7. **即时权限**：尽量用JIT替代常驻特权
8. **定期审查**：定期审查特权账号和访问权限
