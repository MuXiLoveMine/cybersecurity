# FIDO2 安全分析

### 4.1 抗钓鱼原理

FIDO2 天然具备抗钓鱼能力，这是其相比传统密码的核心优势。

**传统密码钓鱼攻击流程：**

```
攻击者                           用户                      真实网站
   │                              │                          │
   │  1.创建钓鱼网站               │                          │
   │  (fake-bank.com)             │                          │
   │─────────────────────────────→│                          │
   │                              │                          │
   │  2.用户输入密码               │                          │
   │←─────────────────────────────│                          │
   │                              │                          │
   │  3.攻击者用密码登录真实网站     │                          │
   │────────────────────────────────────────────────────────→│
   │                              │                          │
   │  4.登录成功，攻击者接管账号     │                          │
```

**FIDO2 抗钓鱼机制：**

```
攻击者                           用户/认证器              真实网站
   │                              │                          │
   │  1.创建钓鱼网站               │                          │
   │  (fake-bank.com)             │                          │
   │─────────────────────────────→│                          │
   │                              │                          │
   │  2.认证器收到Challenge        │                          │
   │     origin=fake-bank.com     │                          │
   │                              │                          │
   │  3.认证器查找fake-bank.com   │                          │
   │     的私钥 → 不存在！        │                          │
   │     （认证器按RP ID存储密钥）  │                          │
   │                              │                          │
   │  4.认证器拒绝签名             │                          │
   │  （或使用不同密钥，签名无效）   │                          │
   │←─────────────────────────────│                          │
   │                              │                          │
   │  5.即使签名了，origin不匹配    │                          │
   │     服务端验证失败            │                          │
   │     Challenge来自fake-bank    │                          │
   │     而非real-bank.com         │                          │
```

**抗钓鱼的两层防御：**

1. **认证器层**：认证器按 `rpId` 存储密钥，钓鱼域名与真实域名不同，认证器不会使用真实域名的私钥签名
2. **服务端层**：`clientDataJSON` 中的 `origin` 必须匹配 RP 的域名，即使认证器签名了，服务端也会拒绝

### 4.2 蓝牙跨设备认证安全

Hybrid Transport 使用 BLE + TLS 实现 手机为电脑认证，其安全性设计精妙。

```
Hybrid Transport 安全机制：

1. BLE广播（不可靠通道）
   └── 电脑广播BLE + 显示二维码
   └── 包含：session_id、routing_id

2. QR码扫描建立信任
   └── 手机扫描二维码获取路由信息
   └── QR码包含：origin（网站域名）、公钥指纹

3. BLE配对确认（带外验证）
   └── 两个设备都显示相同配对码
   └── 用户确认匹配（防MITM）

4. WLAN建立TLS隧道
   └── ECDH密钥协商
   └── TLS 1.3加密所有CTAP消息

安全分析：
  - BLE仅用于初始发现，不传敏感数据
  - 实际数据通过WLAN+TLS传输
  - QR码中的origin被认证器验证（抗钓鱼）
  - 用户物理确认配对（防远程攻击）
```

### 4.3 中继攻击风险

尽管 FIDO2 设计上抗钓鱼，但仍面临中继攻击（Relay Attack）风险。

```
中继攻击场景（针对蓝牙跨设备认证）：

攻击者A（接近用户手机）     中继通道      攻击者B（接近电脑）
     │                                       │
     │  1.模拟电脑BLE广播                     │
     │←─────────────────────────────────────│
     │                                       │
     │  2.用户手机响应，开始认证              │
     │  用户完成生物验证                       │
     │                                       │
     │  3.攻击者A截获CTAP消息                  │
     │─────────────────────────────────────→│  (通过攻击者B中继到电脑)
     │                                       │
     │                                       │  4.攻击者B在电脑端
     │                                       │     完成登录
```

**缓解措施：**

| 缓解方案 | 原理 | 效果 |
|----------|------|------|
| 距离绑定协议 | 在签名中包含信号到达时间差 | 缩短中继距离限制 |
| BLE测距 | 利用RSSI或UWB精确测距 | 检测异常距离 |
| 时间约束 | 限制认证窗口时间 | 增加中继延迟检测 |
| 用户确认 | 二次确认设备信息 | 社会层面防护 |
