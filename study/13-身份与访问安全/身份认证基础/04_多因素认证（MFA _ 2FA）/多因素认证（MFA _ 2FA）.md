# 多因素认证（MFA / 2FA）

### 4.1 MFA 基础概念

**定义**：多因素认证（Multi-Factor Authentication）要求用户提供**两种或以上不同类型**的认证因素。

**为什么需要 MFA**：
- 单一因素认证（如密码）容易被攻破
- MFA 大幅提高攻击成本
- 即使密码泄露，攻击者仍无法登录

**MFA 认证强度对比**：

| 认证方式 | 安全等级 | 说明 |
|----------|----------|------|
| 仅密码 | ★☆☆☆☆ | 极易被攻破 |
| 密码+短信 | ★★☆☆☆ | SIM劫持可绕过 |
| 密码+TOTP | ★★★★☆ | 较安全，需手机 |
| 密码+推送 | ★★★☆☆ | 疲劳攻击风险 |
| 密码+U2F | ★★★★★ | 最安全，防钓鱼 |

### 4.2 短信认证与安全

**工作原理**：
```
用户登录 → 系统发送验证码短信 → 用户输入验证码 → 验证通过
```

**优点**：
- 用户接受度高，普及广泛
- 实现简单
- 不需要额外安装应用

**安全风险**：

| 风险 | 说明 |
|------|------|
| **SIM劫持** | 攻击者通过社工让运营商补办SIM卡，接管手机号 |
| **短信嗅探** | 通过伪基站拦截短信 |
| **SS7漏洞** | 利用信令网漏洞拦截短信 |
| **钓鱼攻击** | 假网站诱导输入验证码 |
| **号码转移** | 手机号转网/过户导致 |

**真实案例**：
> 2019年，Twitter CEO Jack Dorsey 的Twitter账号被黑客通过 SIM Swap 攻击劫持，发布了多条种族歧视言论。黑客通过社工攻击运营商，将Dorsey的手机号转移到自己的SIM卡上，从而绕过了短信验证。

**短信验证防护建议**：
- 关键账号不要仅依赖短信验证
- 使用 TOTP 或硬件密钥作为更强的MFA方式
- 手机号设置运营商PIN码保护
- 监控手机号异常活动

### 4.3 TOTP 基于时间的一次性密码

**TOTP 简介**：
- Time-based One-Time Password
- 基于时间的一次性密码算法
- RFC 6238 标准
- 基于 HOTP（RFC 4226）发展而来

**工作原理**：
```
密钥 (Secret Key) + 当前时间戳 → HMAC-SHA1 → 截断 → 6位数字验证码

验证码每30秒刷新一次
```

**TOTP 算法步骤**：
```python
# 1. 获取当前时间步长（每30秒为一步）
time_step = floor(current_timestamp / 30)

# 2. 将时间步长转为8字节
time_bytes = time_step.to_bytes(8, byteorder='big')

# 3. 使用密钥计算HMAC-SHA1
hmac_result = hmac.new(secret_key, time_bytes, sha1).digest()

# 4. 动态截断（DT）
offset = hmac_result[19] & 0x0F  # 取最后一个字节的低4位作为偏移
binary_code = ((hmac_result[offset] & 0x7F) << 24) |
              ((hmac_result[offset+1] & 0xFF) << 16) |
              ((hmac_result[offset+2] & 0xFF) << 8) |
              (hmac_result[offset+3] & 0xFF)

# 5. 取模得到6位数字
otp = binary_code % 1000000
```

**常用 TOTP 应用**：
- Google Authenticator
- Microsoft Authenticator
- Authy
- 1Password（内置）
- Bitwarden（内置）

**TOTP 的安全风险**：
- 密钥泄露（手机丢失、备份泄露）
- 钓鱼攻击（假网站诱导输入验证码）
- 时间偏移问题
- 无法防止中间人攻击

### 4.4 推送通知认证

**工作原理**：
```
用户登录 → 服务器推送通知到用户手机App → 用户确认/拒绝
```

**优点**：
- 用户体验好，一键确认
- 比TOTP更便捷
- 可显示登录详情（位置、设备、时间）

**安全风险 — MFA 疲劳攻击（MFA Fatigue Attack）**：

> **攻击原理**：攻击者不断发送MFA推送请求，直到用户不堪其扰而误点确认。

**真实案例**：
> 2022年 Uber 被黑客入侵，黑客获取了一名员工的密码后，不断向该员工发送 Duo MFA 推送请求，最终员工不堪其扰点击了"接受"，黑客成功登录系统。

**防护措施**：
- 限制推送频率
- 增加"拒绝并阻止"选项
- 显示详细登录信息
- 异常推送自动告警
- 使用号码匹配（Number Matching）

### 4.5 生物识别认证

**生物识别系统组成**：
```
采集 → 预处理 → 特征提取 → 特征匹配 → 结果输出
```

**关键指标**：

| 指标 | 英文 | 说明 |
|------|------|------|
| 误识率 | FAR (False Acceptance Rate) | 把假的认成真的概率 |
| 拒真率 | FRR (False Rejection Rate) | 把真的当成假的概率 |
| 等错误率 | EER (Equal Error Rate) | FAR=FRR时的错误率，越小越好 |

**常见生物识别技术对比**：

| 技术 | 准确率 | 便利性 | 抗欺骗性 | 隐私风险 | 成本 |
|------|--------|--------|----------|----------|------|
| 指纹 | 高 | 高 | 中 | 中 | 低 |
| 人脸 | 中 | 很高 | 低 | 高 | 低 |
| 虹膜 | 很高 | 中 | 高 | 高 | 高 |
| 声纹 | 低 | 高 | 低 | 中 | 低 |
| 静脉 | 很高 | 中 | 高 | 中 | 中 |

**生物识别安全风险**：

1. **不可逆性**：生物特征泄露后无法更改（密码可以改，指纹改不了）
2. **欺骗攻击**：
   - 指纹：硅胶假指纹、打印指纹
   - 人脸：3D面具、照片、视频
   - 声纹：语音合成、录音
3. **隐私问题**：生物特征属于敏感个人信息
4. **偏见问题**：对不同种族/性别准确率不同

**生物识别最佳实践**：
- 存储特征模板而非原始生物数据
- 本地比对，不上传原始数据（如iPhone Face ID）
- 作为多因素之一，不单独使用
- 提供备用认证方式（如密码）
- 遵守相关法规（个人信息保护法、GDPR）
