# 实际案例分析

### 案例一：密码泄露导致的大规模账户入侵

**事件**：某社交平台数据库泄露，包含5亿用户的密码哈希（MD5，未加盐）。

**攻击过程**：
1. 攻击者获取数据库备份
2. 使用彩虹表快速破解了90%以上的弱密码
3. 使用破解的密码尝试登录其他网站（凭证填充）
4. 大量用户在其他平台的账户也被入侵

**根本原因**：
- 使用了不安全的 MD5 哈希算法
- 没有加盐
- 没有强制强密码策略

**改进措施**：
1. 立即将密码哈希算法升级为 Argon2id
2. 所有用户强制重置密码
3. 强制启用 MFA
4. 接入密码泄露检测 API（如 HIBP）
5. 实施凭证填充防护

### 案例二：SIM 劫持攻击盗取加密货币

**事件**：某加密货币投资者手机号被 SIM 劫持，价值100万的加密货币被盗。

**攻击过程**：
1. 攻击者通过社交媒体收集受害者个人信息
2. 打电话给运营商，冒充受害者要求补办SIM卡
3. 运营商客服被社工，成功补办SIM卡
4. 攻击者使用短信验证码登录交易所
5. 重置密码，转走所有加密货币

**教训**：
- 不要仅依赖短信作为MFA方式
- 交易所应提供更强的MFA选项（TOTP/U2F）
- 用户应设置运营商服务密码/PIN
- 大额资产应使用硬件钱包

### 案例三：MFA 疲劳攻击入侵企业

**事件**：某企业遭到勒索软件攻击，最初入口是通过 MFA 疲劳攻击获取的员工VPN账号。

**攻击过程**：
1. 攻击者通过钓鱼获取了一名员工的密码
2. 攻击者开始不断尝试VPN登录，触发MFA推送
3. 员工在深夜被持续的推送打扰，不慎点击了"接受"
4. 攻击者成功登录VPN，进入内网
5. 横向移动，部署勒索软件

**改进措施**：
1. 限制MFA推送频率（如每小时最多5次）
2. 启用号码匹配（Number Matching）
3. 显示登录详情（地理位置、设备信息）
4. 异常登录自动告警
5. 员工安全意识培训
