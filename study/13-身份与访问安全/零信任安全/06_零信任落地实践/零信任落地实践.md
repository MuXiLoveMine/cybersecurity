# 零信任落地实践

### 6.1 Google BeyondCorp

**背景**：
- Google在2009年极光行动（Operation Aurora）后启动
- 目标是消除对内部网络的信任
- 2014年公开发表相关论文，成为零信任的标杆实践

**核心原则**：
1. 不信任内部网络
2. 所有访问都需要认证和授权
3. 访问决策基于设备状态和用户身份
4. 所有服务都通过BeyondCorp网关访问

**架构组件**：

| 组件 | 功能 |
|------|------|
| 身份提供商（IdP） | 用户认证 |
| 设备清单 | 设备管理和状态 |
| 访问控制引擎 | 授权决策 |
| 访问代理 | 执行访问策略 |
| 证书系统 | 设备证书认证 |

**访问流程**：
```
1. 用户从任何网络访问企业应用
2. 设备证书 + 用户凭证认证
3. 评估设备健康状态
4. 基于用户角色和设备状态授权
5. 通过访问代理访问应用
6. 全程记录和监控
```

**关键经验**：
- 零信任是可行的，Google已经全面运行多年
- 用户体验可以做得很好（用户几乎感觉不到差异）
- 设备信任和用户身份同样重要
- 需要持续投资和演进

### 6.3 零信任场景实践

#### 场景一：远程办公零信任

**传统方式**：VPN → 接入内网 → 内部完全访问

**零信任方式**：ZTNA → 基于身份授权 → 只访问需要的应用

| 维度 | 传统VPN | ZTNA |
|------|---------|------|
| 访问范围 | 整个内网 | 特定应用 |
| 验证方式 | 一次性认证 | 持续验证 |
| 设备检查 | 无/简单 | 全面健康检查 |
| 可见性 | 网络层 | 应用层 |
| 用户体验 | 较差 | 好（无感） |

**实施要点**：
- 优先替换VPN用于远程办公
- 按应用逐步接入ZTNA
- 设备准入检查
- 应用级细粒度授权

#### 场景二：第三方访问零信任

**传统方式**：创建账号 → 开通VPN → 权限过大

**零信任方式**：独立身份 → 最小权限 → 全程审计

**关键措施**：
- 第三方使用独立的身份源
- 只授权必要的应用和数据
- 即时权限（JIT），用完即收
- 全程会话录制和审计
- 访问时间限制

#### 场景三：特权访问零信任

**传统方式**：共享管理员密码 → 权限常驻

**零信任方式**：PAM金库 → 即时权限 → 全程审计

**关键措施**：
- 所有特权账号纳入金库
- 密码自动轮换
- JIT即时权限申请审批
- 命令级控制和审计
- MFA保护PAM访问

#### 场景四：微服务零信任

**传统方式**：内网调用免认证 → 横向移动容易

**零信任方式**：服务身份 → mTLS → 服务间授权

**关键措施**：
- 每个服务有独立身份（SPIFFE）
- 服务间mTLS双向认证
- 服务网格（Istio）实现策略执行
- API级细粒度授权
