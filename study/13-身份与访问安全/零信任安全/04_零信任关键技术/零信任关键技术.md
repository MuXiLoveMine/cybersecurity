# 零信任关键技术

### 4.1 软件定义边界（SDP）

**SDP（Software Defined Perimeter）**：零信任网络访问的核心技术，也称为"黑云"架构。

**核心思想**：
- 隐藏基础设施，不让攻击者看到
- 先认证，再连接（先验证身份，再开放网络访问）
- 软件定义的动态边界

**SDP 工作原理**：

```
传统网络：
  服务器 → 端口开放 → 任何人都可以尝试连接 → 攻击面大

SDP：
  服务器 → 端口关闭（默认拒绝）
  用户 → 认证通过 → SDP控制器下发策略 → 临时开放连接
  攻击面 = 0（未认证的用户完全看不到服务）
```

**SDP 架构组件**：

| 组件 | 功能 |
|------|------|
| SDP 控制器 | 认证、策略管理、连接授权 |
| SDP 主机（IH） | 发起连接的客户端（如用户电脑） |
| SDP 网关（AH） | 保护服务端资源，执行访问控制 |

**SDP 连接流程（SPA 单包授权）**：
```
1. IH（发起主机）向控制器认证
2. 认证通过后，控制器告诉IH可以访问哪些AH
3. IH发送SPA包（单包授权）给AH
4. AH验证SPA包，临时开放端口
5. 建立加密连接（TLS/WireGuard）
6. 访问资源
```

**SDP 的优势**：
- 端口隐藏，减少攻击面
- 先认证后连接
- 动态访问控制
- 细粒度访问策略
- 支持任意网络环境

### 4.2 微隔离（Microsegmentation）

**微隔离**：将网络划分为非常小的安全区域，每个区域独立防护，限制攻击者的横向移动。

#### 传统网络分段 vs 微隔离

| 维度 | 传统分段 | 微隔离 |
|------|----------|--------|
| 粒度 | 网段/VLAN级 | 工作负载/应用级 |
| 数量 | 几个到几十个 | 成百上千个 |
| 策略 | 基于IP/端口 | 基于身份/标签 |
| 灵活性 | 静态，调整麻烦 | 动态，随业务变化 |
| 管理 | 网络团队管理 | 安全/应用团队管理 |

#### 微隔离实现方式

| 方式 | 说明 | 适用场景 |
|------|------|----------|
| 基于防火墙 | 在每个主机上安装软件防火墙 | 物理服务器、VM |
| 基于主机代理 | EDR/安全代理提供隔离能力 | 终端和服务器 |
| 基于Overlay网络 | VXLAN等叠加网络实现 | 云环境、容器 |
| 基于服务网格 | Istio等服务网格实现mTLS和授权 | 微服务 |
| 基于云安全组 | 云厂商提供的安全组 | 公有云 |

#### 微隔离策略模型

```
标签体系：
  应用 = 电商平台
  环境 = 生产
  层级 = Web / App / DB

策略示例：
  允许：应用=电商平台, 层级=Web → 应用=电商平台, 层级=App, 端口=8080
  允许：应用=电商平台, 层级=App → 应用=电商平台, 层级=DB, 端口=3306
  拒绝：其他所有流量
```

**微隔离的价值**：
- 限制横向移动：攻破一个工作负载也无法访问其他的
- 减少攻击面：默认拒绝，只允许必要的通信
- 应用级安全：每个应用独立防护
- 适应动态环境：云原生、容器环境下自动适配

### 4.3 持续自适应风险与信任评估（CARTA）

**CARTA（Continuous Adaptive Risk and Trust Assessment）**：Gartner提出的安全理念，强调持续的、自适应的风险评估和信任决策。

**核心思想**：
- 信任不是二元的（是/否），而是一个连续的等级
- 风险和信任是动态变化的，需要持续评估
- 安全策略应根据风险自适应调整

**CARTA 评估维度**：

```
信任评分 (0-100)
    ↑
    │  高信任 → 完全访问
    │
    │  中信任 → 限制访问 / 额外验证
    │
    │  低信任 → 拒绝访问
    └──────────────────→ 风险等级
```

**信任评估输入**：

| 类别 | 具体因素 |
|------|----------|
| 身份因素 | 用户角色、安全级别、历史行为 |
| 设备因素 | 设备合规性、安全状态、是否受管 |
| 环境因素 | 时间、地点、网络环境 |
| 行为因素 | 是否异常、风险行为、基线偏离 |
| 资源因素 | 资源敏感度、重要程度 |
| 威胁因素 | 实时威胁情报、攻击告警 |

**自适应响应**：

| 风险等级 | 响应措施 |
|----------|----------|
| 低风险 | 正常访问，完整权限 |
| 中低风险 | 正常访问，加强监控 |
| 中风险 | 限制敏感操作，触发MFA |
| 中高风险 | 只读访问，需要额外审批 |
| 高风险 | 拒绝访问，触发告警 |

### 4.4 身份驱动安全

**身份是零信任的核心**：
- 所有访问决策围绕身份展开
- 身份包括用户身份、设备身份、服务身份
- 身份属性是动态授权的基础

**关键技术**：

| 技术 | 作用 |
|------|------|
| 统一身份管理（IAM） | 集中管理所有身份 |
| 多因素认证（MFA） | 强身份验证 |
| 无密码认证 | 更安全便捷的认证方式 |
| 基于属性的访问控制（ABAC） | 动态细粒度授权 |
| 特权访问管理（PAM） | 保护高价值身份 |
| 身份联邦 | 跨组织身份共享 |

### 4.5 无密码认证

**为什么需要无密码**：
- 密码是最薄弱的环节
- 密码管理成本高
- 用户体验差
- MFA仍然依赖密码作为第一因素

**无密码认证方式**：

| 方式 | 原理 | 安全性 | 便利性 |
|------|------|--------|--------|
| WebAuthn / FIDO2 | 公钥密码学，硬件/生物识别 | 很高 | 高 |
| 魔法链接（Magic Link） | 邮件链接登录 | 中 | 高 |
| 短信/邮件验证码 | 验证码登录 | 中低 | 中 |
| 推送通知 | App推送确认 | 中高 | 高 |
| 证书认证 | 客户端证书 | 很高 | 低 |

**WebAuthn 无密码登录流程**：
```
注册：
1. 用户在网站注册
2. 浏览器调用 WebAuthn API
3. 认证器（手机/安全密钥）生成密钥对
4. 公钥发送给网站存储

登录：
1. 用户输入用户名（或自动识别）
2. 网站发送挑战
3. 用户用生物识别/按键确认
4. 认证器用私钥签名挑战
5. 网站用公钥验证签名
6. 登录成功
```
