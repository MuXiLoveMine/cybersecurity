# 零信任架构（ZTA）核心组件

### 2.1 NIST 零信任逻辑架构

NIST SP 800-207 定义了零信任架构的核心组件：

```
                        ┌───────────────────────┐
                        │   策略引擎 (PE)        │
                        │   Policy Engine       │
                        │  (决策：允许/拒绝)     │
                        └──────────┬────────────┘
                                   │
                                   │ 策略
                                   ▼
┌──────────┐              ┌───────────────────────┐
│ 主体      │              │   策略管理员 (PA)      │
│(Subject) │───请求──────▶│   Policy Admin        │
│ 用户/设备 │              │  (执行策略、会话管理)  │
└──────────┘              └──────────┬────────────┘
                                     │
                                     │  允许/拒绝
                                     ▼
                              ┌──────────────┐
                              │  资源         │
                              │ (Resource)    │
                              │  应用/数据    │
                              └──────────────┘
                                      │
                                      │
                         ┌────────────▼────────────┐
                         │    持续诊断与缓解 (CDM)  │
                         │  Continuous Diagnostics  │
                         │  and Mitigation         │
                         │ (收集数据、评估状态)     │
                         └─────────────────────────┘
```

### 2.2 核心组件详解

#### 1. 策略引擎（Policy Engine, PE）

**职责**：做出"是否允许访问"的最终决策。

**功能**：
- 评估访问请求的风险
- 根据策略规则做出决策
- 综合考虑身份、设备、环境等多维度信息
- 持续调整信任等级

**输入数据**：
- 主体身份和属性
- 设备安全状态
- 资源属性和分类
- 环境上下文（时间、地点、网络）
- 行为历史和风险评分
- 威胁情报

**输出**：
- 允许 / 拒绝 / 需要额外验证
- 信任等级评分
- 权限范围
- 会话限制条件

#### 2. 策略执行点（Policy Enforcement Point, PEP）

**职责**：执行策略引擎的决策，建立并维护访问会话。

**功能**：
- 拦截访问请求
- 转发到策略引擎获取决策
- 执行决策（允许或拒绝）
- 管理会话生命周期
- 监控会话活动

**常见 PEP 形式**：
- 反向代理 / API 网关
- 软件定义边界（SDP）控制器
- 微隔离防火墙
- 应用内权限中间件

#### 3. 持续诊断与缓解（CDM）

**职责**：持续收集和分析系统状态信息，提供给策略引擎决策依据。

**数据源**：

| 类别 | 数据源 | 说明 |
|------|--------|------|
| 身份数据 | IAM/IdP | 用户身份、角色、属性 |
| 设备数据 | EDR/MDM | 设备健康状态、合规性 |
| 网络数据 | NDR/防火墙 | 流量分析、威胁检测 |
| 应用数据 | APM/WAF | 应用行为、攻击检测 |
| 行为数据 | UEBA/SIEM | 用户行为分析、异常检测 |
| 威胁情报 | TI 平台 | 已知威胁、IoC |

### 2.3 零信任三大支柱

零信任架构通常围绕三大支柱构建：

```
            ┌──────────────────┐
            │    零信任架构     │
            └────────┬─────────┘
         ┌───────────┼───────────┐
         ▼           ▼           ▼
    ┌────────┐  ┌────────┐  ┌────────┐
    │ 身份   │  │  设备  │  │  应用  │
    │(Identity)│ │(Device)│ │  (App)  │
    └────────┘  └────────┘  └────────┘
```

#### 支柱一：身份（Identity）

**核心思想**：身份是新的安全边界。

**关键能力**：
- 统一身份管理（IAM）
- 强认证（MFA/无密码）
- 动态授权（ABAC）
- 身份治理与合规
- 特权访问管理（PAM）

**身份的扩展**：
- 用户身份（员工、客户、合作伙伴）
- 设备身份（PC、手机、IoT）
- 应用身份（服务、API）
- 工作负载身份（容器、虚拟机）

#### 支柱二：设备（Device）

**核心思想**：只有合规的设备才能访问资源。

**关键能力**：
- 设备注册和管理（MDM/UEM）
- 设备健康检查（EDR/XDR）
- 设备合规性评估
- 设备信任评级
- 终端安全防护

**设备信任评估维度**：

| 维度 | 检查项 |
|------|--------|
| 设备身份 | 是否是受管设备、设备证书 |
| 系统状态 | OS版本、补丁级别 |
| 安全状态 | 是否有杀毒软件、EDR是否运行 |
| 合规状态 | 是否加密、是否越狱/Root |
| 风险状态 | 是否有异常行为、是否有威胁 |

#### 支柱三：应用 / 数据（Application & Data）

**核心思想**：保护应用和数据本身，而不是网络边界。

**关键能力**：
- 应用级访问控制
- 数据分类和保护
- API 安全
- 微服务安全
- 数据防泄漏（DLP）
