# 零信任概念与原则

### 1.1 什么是零信任

**零信任（Zero Trust）**：一种安全理念和架构范式，核心原则是**"永不信任，始终验证"（Never Trust, Always Verify）**。它不基于网络位置（内网/外网）自动授予信任，而是对每一次访问请求都进行身份验证和授权决策。

**零信任的本质**：
- 信任不是一次性获得的，而是需要持续验证
- 信任不是基于位置的，而是基于身份和上下文的
- 信任是有等级的，不是非黑即白
- 信任是动态评估的，随风险变化而调整

**零信任的起源**：
- 2010年：Forrester分析师John Kindervag提出"零信任"概念
- 2014年：Google发布"BeyondCorp"零信任实践
- 2018年：Gartner提出"持续自适应风险与信任评估（CARTA）"
- 2020年：NIST发布SP 800-207零信任标准
- 2021年：美国发布零信任行政命令
- 至今：零信任已成为网络安全的主流方向

### 1.2 传统网络安全 vs 零信任

#### 传统边界安全模型（城堡与护城河）

```
          互联网
             │
        ┌────▼────┐
        │  防火墙  │  ← 边界防护
        └────┬────┘
             │
        ┌────▼────┐
        │  内网   │  ← 默认信任
        │ (可信)  │
        └─────────┘
```

**传统安全假设**：
- 内网 = 可信，外网 = 不可信
- 守住边界就安全了
- 内部用户都是可信的
- 一次认证，长期有效

**传统安全的问题**：

| 问题 | 说明 |
|------|------|
| 边界模糊 | 云计算、移动办公、远程办公让边界消失 |
| 内部威胁 | 内部人员滥用权限或账号被盗 |
| 横向移动 | 攻破一台机器就能在内网横行 |
| 过度信任 | 内网缺乏访问控制，权限过大 |
| 静态防护 | 认证一次就长期信任，缺乏持续验证 |

#### 零信任安全模型

```
         ┌─────────────────────────────────┐
         │          零信任架构              │
         │  ┌─────┐  ┌─────┐  ┌─────┐    │
         │  │ 应用 │  │ 数据 │  │ 服务 │    │
         │  └──┬──┘  └──┬──┘  └──┬──┘    │
         │     │        │        │         │
         │  ┌──▼────────▼────────▼──┐     │
         │  │   策略引擎（每次验证）  │     │
         │  └──┬────────┬────────┬──┘     │
         │     │        │        │         │
         │  ┌──▼──┐  ┌──▼──┐  ┌──▼──┐    │
         │  │身份  │  │设备  │  │环境  │    │
         │  └─────┘  └─────┘  └─────┘    │
         └─────────────────────────────────┘
```

**核心差异对比**：

| 维度 | 传统边界安全 | 零信任安全 |
|------|-------------|-----------|
| 信任基础 | 网络位置（内网/外网） | 身份、设备、行为 |
| 假设前提 | 内部可信，外部不可信 | 所有位置都不可信 |
| 防护重点 | 网络边界（防火墙） | 身份、数据、应用 |
| 访问控制 | 粗粒度（网段级） | 细粒度（每次请求） |
| 验证方式 | 一次性认证 | 持续验证 |
| 权限模型 | 静态权限 | 动态自适应 |
| 网络模型 | 扁平内网 | 微隔离 |
| 攻击面 | 边界突破后内部敞开 | 每一步都需要验证 |

### 1.3 零信任核心原则

NIST SP 800-207 定义了零信任的七条基本原则：

#### 原则一：永不信任，始终验证
- 对任何访问请求都进行验证，不因其来自内网而信任
- 每次访问都需要认证和授权
- 没有"可信内部网络"的概念

#### 原则二：最小权限原则
- 只授予完成任务所需的最少权限
- 权限按需分配，及时回收
- 使用即时权限（JIT）和及时访问（JEA）
- 限制访问范围和时间

#### 原则三：假设已经被入侵（Assume Breach）
- 假设攻击者已经在网络内部
- 设计防御纵深，限制横向移动
- 每个组件都要自我保护
- 即使单点被攻破，也不会导致全面沦陷

#### 原则四：持续验证与动态评估
- 不是"一次认证，永久信任"
- 访问过程中持续评估风险
- 风险变化时动态调整权限
- 高风险操作触发额外验证

#### 原则五：全面的可见性和分析
- 收集所有访问数据
- 分析行为模式，发现异常
- 利用机器学习检测威胁
- 持续优化安全策略

#### 原则六：以身份为新边界
- 身份是安全的核心控制点
- 每个用户、设备、服务都有身份
- 访问决策基于身份和上下文
- 统一身份管理是零信任的基础

#### 原则七：自动化和编排
- 策略自动执行
- 事件自动响应
- 身份生命周期自动化
- 安全运维自动化
