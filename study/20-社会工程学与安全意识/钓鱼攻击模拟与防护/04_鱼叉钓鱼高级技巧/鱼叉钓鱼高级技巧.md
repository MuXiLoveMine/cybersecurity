### 3.2 Pretexting（借口编造）深度

```python
# Pretexting场景设计框架

class PretextDesign:
    """社会工程学pretexting场景设计框架"""

    def __init__(self, target_profile):
        self.target = target_profile
        self.pretext = {}

    def design_scenario(self):
        """设计攻击场景"""
        scenarios = []

        # 场景1：IT系统维护
        scenarios.append({
            'name': 'IT系统维护',
            'identity': 'IT运维中心工程师',
            'reason': f'系统安全升级需要验证账户',
            'urgency': '本月内完成，否则影响系统访问',
            'authority': '引用IT部门主管名义',
            'social_proof': '同部门其他同事已完成',
            'target_action': '点击链接进行账户验证',
            'applicable_to': ['所有岗位'],
            'credibility_score': 8,
            'notes': '需了解目标IT系统名称和流程'
        })

        # 场景2：供应商/客户事务
        scenarios.append({
            'name': '供应商事务',
            'identity': '合作供应商联系人',
            'reason': f'需要确认订单/发票/合同信息',
            'urgency': '截止日期临近',
            'authority': '引用采购部门名义',
            'social_proof': '其他供应商已确认',
            'target_action': '打开附件或点击链接',
            'applicable_to': ['财务', '采购', '行政'],
            'credibility_score': 7,
            'notes': '需了解目标供应商关系'
        })

        # 场景3：HR事务
        scenarios.append({
            'name': 'HR事务',
            'identity': '人力资源部员工',
            'reason': '需要更新个人信息/确认薪资条',
            'urgency': '薪资发放前需确认',
            'authority': '引用HR总监名义',
            'social_proof': '同部门同事已完成更新',
            'target_action': '登录HR系统更新信息',
            'applicable_to': ['所有岗位'],
            'credibility_score': 9,
            'notes': '利用员工对HR通知的重视心理'
        })

        # 场景4：合规审计
        scenarios.append({
            'name': '合规审计',
            'identity': '外部审计/合规顾问',
            'reason': '年度合规审计需要文件',
            'urgency': '审计截止日期临近',
            'authority': '引用法务/合规部门名义',
            'social_proof': '其他部门已提交',
            'target_action': '通过链接上传文件',
            'applicable_to': ['管理层', '财务', '法务'],
            'credibility_score': 8,
            'notes': '需了解目标合规要求'
        })

        # 选择最佳场景
        best = max(scenarios, key=lambda x: x['credibility_score'])
        self.pretext = best
        return scenarios

    def generate_email_content(self):
        """基于场景生成邮件内容"""
        if not self.pretext:
            return None

        template = f"""
身份: {self.pretext['identity']}
场景: {self.pretext['reason']}
紧迫感: {self.pretext['urgency']}
权威引用: {self.pretext['authority']}
社会认同: {self.pretext['social_proof']}
期望行为: {self.pretext['target_action']}
"""
        return template
```

### 3.3 Beacon Payload投递

```
鱼叉钓鱼中的payload投递策略：

1. 附件投递
   ├── 恶意Office文档（含宏/VBA）
   │   - 利用宏代码下载和执行payload
   │   - 需要目标启用宏
   │   - 利用模板注入（远程模板）
   │
   ├── 恶意PDF
   │   - 利用JavaScript漏洞
   │   - 嵌入恶意链接
   │
   ├── 恶意快捷方式（.lnk）
   │   - 伪装成文档
   │   - 执行PowerShell命令
   │
   ├── ISO/IMG镜像
   │   - 绕过Mark-of-the-Web(MotW)
   │   - 包含恶意payload
   │
   └── 压缩文件
       - 加密ZIP（绕过邮件网关扫描）
       - 密码在邮件正文中提供

2. 链接投递
   ├── 直接链接到C2服务器
   ├── 利用合法云服务中转
   │   - OneDrive/Google Drive托管payload
   │   - GitHub Raw内容
   │   - AWS S3/Azure Blob存储
   └── 利用重定向链
       - URL缩短服务
       - 合法网站重定向

3. Payload执行技术
   ├── PowerShell Empire/Stager
   ├── Cobalt Strike Beacon
   ├── Sliver C2框架
   ├── 基于Web的execution（浏览器漏洞）
   └── LOLBins（Living off the Land Binaries）
       - mshta.exe
       - certutil.exe
       - bitsadmin.exe
       - regsvr32.exe
```
