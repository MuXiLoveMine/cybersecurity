### 3.1 邮件伪造技术

#### 3.1.1 SMTP协议与发件人欺骗

SMTP协议本身不验证发件人地址，这是邮件欺骗的根本原因：

```python
# 示例：理解SMTP发件人欺骗原理（仅用于理解，不可用于非法用途）
# 此代码仅展示SMTP协议的缺陷，实际发送需要授权

import smtplib
from email.mime.text import MIMEText
from email.mime.multipart import MIMEMultipart

# SMTP协议允许指定任意发件人地址
# 这就是为什么需要SPF/DKIM/DMARC来验证

# 邮件头中的关键字段：
# - From: 显示在邮件客户端的发件人（可被伪造）
# - Reply-To: 回复地址（常与From不同）
# - Return-Path: 退信地址（邮件服务器使用）
# - Sender: 实际发送者（当From与实际不同时使用）

# 钓鱼邮件常利用的技巧：
# 1. From: ceo@company.com（伪造）, Reply-To: attacker@evil.com
# 2. From: "CEO Name" <attacker@lookalike-domain.com>
# 3. From: ceo@company.com<attacker@evil.com>（某些客户端显示问题）
```

#### 3.1.2 域名相似度攻击

```
原始域名: company.com

域名相似度攻击类型:

1. 同形异义字（Homograph）
   - cоmpany.com（用西里尔字母'о'替代拉丁'o'）
   - cоmpаny.com（多个字符被替换）

2. 拼写错误（Typosquatting）
   - compnay.com（字母顺序错误）
   - companyy.com（多打字母）
   - cmpany.com（漏打字母）

3. 添加字符
   - company-secure.com
   - company-login.com
   - company-support.com

4. 不同TLD
   - company.cn（如果原域名是.com）
   - company.net
   - company.co

5. 子域名滥用
   - company.com.evil.com（利用子域名结构）
   - evil.com/company.com（路径混淆）
```

#### 3.1.3 显示名欺骗

显示名欺骗是最简单但有效的欺骗手段：

```
# 攻击者设置邮件显示名为可信来源

发件人: "IT安全部" <random-user@freemail.com>
发件人: "CEO 张伟" <ceo.name@lookalike-domain.com>
发件人: "Microsoft 365" <noreply@microsoft-support-portal.com>
发件人: "HR 人力资源" <hr@company.com.attacker.net>

# 在邮件列表/移动端中，通常只显示显示名
# 许多用户不会展开查看实际邮箱地址
```

### 3.2 钓鱼邮件模板设计

#### 3.2.1 钓鱼邮件设计原则

```
┌──────────────────────────────────────────────┐
│            钓鱼邮件设计框架                     │
├──────────────────────────────────────────────┤
│                                              │
│  1. 场景选择                                  │
│     - 选择目标熟悉的日常场景                    │
```

### 3.3 鱼叉钓鱼定制

#### 3.3.1 目标画像构建

```
目标画像模板：

个人信息：
├── 姓名：李明
├── 职位：财务部经理
├── 入职时间：2023年6月（入职2年+，非新人）
├── 工作地点：上海总部
├── 汇报对象：CFO 王强

社交信息：
├── LinkedIn活动：近期参加了"企业财务数字化转型"论坛
├── 微博：关注多家财务软件厂商
├── GitHub：无活跃账号
├── 学术背景：上海财经大学硕士

邮件格式推断：
├── liming@company.com
├── li.ming@company.com
├── liming.zhao@company.com

可利用场景：
├── "供应商发票确认"（与财务工作相关）
├── "审计资料提交"（利用权威压力）
├── "税务系统更新"（利用合规要求）
├── "财务系统VPN升级"（利用技术借口）

最佳攻击时机：
├── 月底财务结账期（工作繁忙，警惕降低）
├── 季度审计期间（收到大量正式邮件，鱼龙混杂）
```

#### 3.3.2 鱼叉钓鱼邮件定制

基于上述目标画像定制的鱼叉钓鱼邮件：

```
发件人: "IT运维中心" <it-support@company-it-service.com>
主题: 【重要】财务系统VPN升级 - 需重新验证账户

正文：
李明经理您好，

我是IT运维中心的张伟。

根据上周财务数字化转型论坛上讨论的系统升级计划，
财务系统VPN将于本周五（9月12日）22:00-23:00进行安全升级。

升级后，所有财务部门用户需要重新验证账户信息
才能继续访问ERP和报税系统。

考虑到月底结账期临近，建议您尽快完成验证，
避免影响正常工作。

验证入口：[财务系统账户验证]

如有疑问，可致电IT运维热线：400-xxxx-xxxx

IT运维中心
2026年9月11日
```

此邮件的关键定制点：
1. 使用了目标真实姓名和职位
2. 引用了目标近期参加的论坛活动（OSINT获取）
3. 场景与目标工作职责（财务）高度相关
4. 时机选择月底结账期前
5. 域名使用 `company-it-service.com` 混淆
6. 提供了电话号码增加可信度
