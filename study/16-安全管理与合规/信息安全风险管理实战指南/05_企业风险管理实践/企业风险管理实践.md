# 企业风险管理实践

### 5.1 风险管理体系建设

**组织架构**：

```
信息安全委员会（董事会下设）
  └── CISO/CIO（首席信息安全官）
      └── 风险管理负责人
          ├── 风险评估团队（执行评估）
          ├── 风险处置团队（落实控制）
          └── 风险监控团队（持续跟踪）
```

信息安全委员会职责：
- 审批组织风险偏好和容忍度
- 审批年度风险管理计划
- 审议高风险事件和处置方案
- 向董事会报告风险态势

风险管理负责人职责：
- 制定风险管理策略和流程
- 组织年度风险评估
- 维护风险登记表
- 定期向CISO和高管层报告风险态势

**制度体系**：

三层制度文件：
1. 一级文件：《信息安全风险管理政策》——原则性框架，由信息安全委员会审批
2. 二级文件：《风险评估管理办法》《风险处置管理流程》《风险接受审批规程》——操作规范
3. 三级文件：各类模板、检查表、技术标准——执行工具

### 5.2 年度风险评估流程

**年度风险评估六步法**：

第一步：评估准备（第1-2周）
- 确定评估范围（全组织还是分系统分批）
- 组建评估团队（内部安全人员+外部专家辅助）
- 制定评估计划和时间表
- 准备评估工具和模板

第二步：风险识别（第3-5周）
- 资产盘点和更新（对照上年度资产清单更新增量）
- 威胁情报收集（参考行业威胁报告和自身历史事件）
- 漏洞扫描和渗透测试（技术脆弱性识别）
- 访谈关键人员（管理脆弱性识别）
- 现有控制措施评估

第三步：风险分析（第6-8周）
- 对每个识别的风险进行定性和定量分析
- 计算风险值和ALE
- 评估残余风险

第四步：风险评价（第9周）
- 对照风险容忍度标准排序
- 确定需处置风险清单
- 提出处置策略建议

第五步：风险处置计划（第10周）
- 制定具体控制措施方案
- 分配责任人和时间节点
- 估算预算和资源需求

第六步：报告与审批（第11-12周）
- 编写年度风险评估报告
- 提交信息安全委员会审批
- 发布处置计划并启动执行

### 5.3 专项风险评估

**新系统上线风险评估**：

触发条件：新系统部署或重大系统改造上线前

评估内容：
- 系统架构安全评审
- 安全需求合规对照（等保要求/PCI DSS要求）
- 安全测试报告审查（SAST/DAST/渗透测试结果）
- 数据流分析（数据分级、流向、存储）
- 第三方组件风险（SBOM分析）
- 运维安全准备度评估（监控、日志、应急方案）

输出：《新系统上线安全评估报告》，包含通过/有条件通过/不通过的结论和整改清单。

**重大变更风险评估**：

触发条件：架构变更、数据迁移、关键设备更换、网络拓扑调整

评估内容：
- 变更影响范围分析
- 变更过程风险评估（执行中风险）
- 变更后安全状态评估
- 回退方案评估
- 应急预案准备度

**安全事件后风险评估**：

触发条件：重大安全事件处置完成后

评估内容：
- 事件根因分析
- 暴露面评估（还有哪些类似风险未发现）
- 控制措施失效原因
- 同类风险全面排查
- 控制措施改进方案

### 5.4 风险报告与沟通

**向管理层报告（月度/季度）**：
- 风险态势总览：风险数量分布（极高/高/中/低各多少）
- Top10风险清单和处置进展
- 新增风险和已关闭风险
- 风险趋势（与上月/上季度对比）
- 关键KPI（MTTR、处置率、接受率）

**向董事会报告（年度）**：
- 年度风险态势总结
- 重大风险事件回顾
- 风险偏好达成情况
- 安全投入ROI分析
- 下年度风险计划

**风险沟通原则**：
- 用业务语言而非技术术语（"年损失预期50万"而非"CVSS 9.8的RCE漏洞"）
- 量化优于定性（"降低风险70%"优于"显著降低"）
- 可视化优于文字（热力图/趋势图优于表格）
- 对比优于绝对（"行业平均水平""监管要求"作为参照）

### 5.5 风险管理持续改进

PDCA持续改进循环：
- **Plan（计划）**：制定年度风险管理计划
- **Do（执行）**：执行风险评估和处置
- **Check（检查）**：定期复核风险状态和处置效果
- **Act（改进）**：根据复核结果优化流程和方法

持续改进的具体措施：
- 每季度复核风险登记表，更新风险值和状态
- 每半年回顾处置计划完成率和有效性
- 每年评估风险管理流程成熟度（对照CMM或风险成熟度模型）
- 根据外部环境变化（新法规、新威胁、新技术）调整风险策略
