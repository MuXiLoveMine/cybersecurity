# 供应链风险管理

### 6.1 第三方供应商风险评估

供应链已成为网络攻击的主要入口——SolarWinds供应链攻击、Kaseya REvil勒索攻击等重大事件证明，一个供应商的安全薄弱环节可能波及成百上千家客户企业。

**供应商风险评估流程**：

1. 供应商分类分级：
   - 按数据接触面：是否接触客户数据/核心数据
   - 按网络接入：是否有内部网络访问权限
   - 按服务关键性：服务中断对业务的影响程度
   - 分为高/中/低三个等级，高等级供应商需要深度评估

2. 评估内容：
   - 安全资质认证：ISO 27001、SOC 2报告、等保级别
   - 安全管理制度：安全策略、人员管理、应急响应
   - 技术安全措施：加密、访问控制、监控审计
   - 数据保护能力：数据处理流程、数据留存、数据销毁
   - 历史安全事件：过去的安全事件和处置情况
   - 分包商管理：是否将服务再分包及分包商安全

3. 合同安全条款：
   - 安全责任和义务条款
   - 数据保密和处理限制
   - 安全审计权利（有权进行现场安全审计）
   - 安全事件通知义务（24-72小时内通知）
   - 违约和赔偿责任

4. 持续监控：
   - 每年更新评估问卷
   - 每年/每两年进行现场审计（高等级供应商）
   - 订阅供应商安全事件通知服务
   - 监控供应商的公开安全态势（如证书、DNS、漏洞情报）

### 6.2 软件供应链安全

软件供应链攻击是近年增长最快的威胁类型，攻击者通过污染软件供应商的分发渠道，间接攻击下游用户。

**SBOM（软件物料清单）**：
- SBOM是软件组件的完整清单，记录所有直接和间接依赖项
- 包括组件名称、版本、供应商、许可证、已知漏洞
- 格式标准：SPDX、CycloneDX
- 用途：快速识别受影响范围（当某组件爆出漏洞时，查SBOM即可知道哪些系统受影响）

**依赖风险**：
- 恶意包：攻击者上传与知名包名称相似的恶意包（typosquatting），诱导开发者误安装
- 依赖混淆：攻击者向公开包管理器注册与内部私有包同名的恶意包
- 版本固定问题：不锁版本号的依赖可能自动更新到被篡改的版本
- 过期依赖：长期不更新的依赖可能含有已知漏洞

**DevSecOps供应链安全实践**：
- 代码阶段：SCA（软件成分分析）工具扫描依赖漏洞（Snyk、OWASP Dependency-Check）
- 构建阶段：签名验证、构建环境隔离、制品签名（Sigstore/Cosign）
- 分发阶段：镜像签名验证、制品仓库安全
- 运行阶段：运行时行为监控、文件完整性监控

### 6.3 云服务商风险评估

云服务商评估特殊考量：

1. 责任共担模型理解：
   - IaaS：云厂商负责底层设施安全，客户负责OS及以上安全
   - PaaS：云厂商负责运行时环境，客户负责应用和数据
   - SaaS：云厂商负责大部分安全，客户主要负责配置和数据访问

2. 评估要素：
   - 合规认证：SOC 2 Type II、ISO 27001、CSA STAR、等保
   - 数据安全：数据加密（传输+存储）、密钥管理（KMS/HSM）、数据主权
   - 访问控制：IAM策略、多因素认证、特权访问管理
   - 日志审计：CloudTrail/Activity Log完整性、日志留存时间
   - 灾备能力：多区域可用性、RTO/RPO承诺
   - 退出机制：数据可移植性、数据销毁证明

3. 持续监控：
   - 云安全态势管理（CSPM）：持续扫描云资源配置合规性
   - 云工作负载保护（CWPP）：运行时保护云上工作负载
   - 云异常检测：监控异常API调用和资源变更

### 6.4 供应链攻击防护

综合防护策略：

1. 准入阶段：严格供应商安全准入评估，高风险供应商不予引入或要求整改后引入
2. 合同阶段：合同中嵌入安全条款和数据保护义务，约定审计权和违约责任
3. 运行阶段：零信任——不因信任供应商就放行其流量，持续验证
4. 监控阶段：部署网络分段隔离供应商访问通道，监控异常行为
5. 应急阶段：制定供应商安全事件应急预案，包含快速切换替代方案
