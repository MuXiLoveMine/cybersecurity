# 网络安全等级保护（等保 2.0）详解

> 本文档详细介绍网络安全等级保护制度（等保 2.0）的标准体系、等级划分、基本要求、管理要求和实施方法，结合实际案例帮助理解和应用。

---

## 一、等级保护制度概述

### 1.1 等级保护制度的定义

网络安全等级保护制度是我国网络安全的基本制度，是国家信息安全保障工作的基本国策。国家对信息系统实行分等级保护、分等级监管，确保信息系统的安全。

**制度定位**：
- 国家网络安全基本制度
- 网络安全的强制要求
- 各单位必须遵守的法定责任
- 网络安全工作的基础

### 1.2 等级保护的发展历程

| 阶段 | 时间 | 标志事件 | 特点 |
|------|------|----------|------|
| 等保1.0 | 2007-2019 | 《信息安全等级保护管理办法》发布 | 传统信息系统、三级为主 |
| 等保2.0 | 2019至今 | GB/T 22239-2019 等标准发布 | 一个中心、三重防护、全覆盖 |

**关键时间节点**：
- 1994年：《中华人民共和国计算机信息系统安全保护条例》首次提出等级保护
- 2007年：《信息安全等级保护管理办法》发布，等保1.0正式启动
- 2017年：《网络安全法》正式实施，等级保护上升为法律制度
- 2019年：等保2.0系列标准发布实施
- 2024年：《网络安全等级保护条例》正式发布

### 1.3 等保 2.0 的法律地位

《网络安全法》第二十一条明确规定：
> "国家实行网络安全等级保护制度。网络运营者应当按照网络安全等级保护制度的要求，履行下列安全保护义务，保障网络免受干扰、破坏或者未经授权的访问，防止网络数据泄露或者被窃取、篡改："

**法律责任**：
- 第五十九条：不履行等保义务的，处一万元以上十万元以下罚款
- 导致危害后果的，处十万元以上一百万元以下罚款
- 对直接负责的主管人员处五千元以上五万元以下罚款

### 1.4 等级保护的核心思想

**一个中心、三重防护**：

```
                    ┌─────────────────────┐
                    │    安全管理中心      │
                    │ （统一管理、监控、审计）│
                    └─────────┬───────────┘
                              │
    ┌─────────────────────────┼─────────────────────────┐
    │                         │                         │
┌───▼─────┐            ┌──────▼──────┐            ┌─────▼──────┐
│ 安全计算 │            │  安全区域边界 │            │ 安全通信网络 │
│  环境    │            │              │            │              │
│ （主机、│            │ （防火墙、    │            │ （网络架构、│
│  应用、  │            │  入侵检测、   │            │  通信加密、│
│  数据）  │            │  访问控制）   │            │  传输安全）│
└──────────┘            └──────────────┘            └────────────┘
```

- **一个中心**：安全管理中心（系统管理、审计管理、安全管理、集中管控）
- **三重防护**：安全通信网络、安全区域边界、安全计算环境

### 1.5 等保 2.0 的适用范围

**适用对象**：
- 网络运营者
- 信息系统（包括传统信息系统、云计算平台、大数据平台）
- 物联网系统
- 工业控制系统
- 移动互联应用

**全覆盖**：等保2.0实现了对新技术、新应用的全覆盖。

## 二、等保 2.0 变化与特点

### 2.1 等保 1.0 与 2.0 的主要区别

| 对比项 | 等保 1.0 | 等保 2.0 |
|--------|----------|----------|
| 法律地位 | 部门规章 | 上升为法律制度 |
| 覆盖范围 | 传统信息系统 | 传统系统+云+物联网+工控+移动互联 |
| 体系架构 | 以技术为主 | 一个中心、三重防护 |
| 管理要求 | 五项管理要求 | 安全管理中心+五项管理 |
| 安全理念 | 被动防御 | 主动防御、动态防御、整体防御 |
| 测评方法 | 符合性测评 | 验证+量化评估 |
| 标准数量 | 5个标准 | 10+个标准 |

### 2.2 等保 2.0 的主要变化

#### 变化1：名称变化
- 从"信息系统安全等级保护"变为"网络安全等级保护"
- 范围从信息系统扩展到整个网络空间

#### 变化2：体系架构变化
- 引入"一个中心、三重防护"理念
- 增加安全管理中心要求
- 从技术+管理二维变为中心+三重防护+管理

#### 变化3：扩展保护对象
- **云计算安全扩展要求**：针对云计算平台
- **移动互联安全扩展要求**：针对移动应用
- **物联网安全扩展要求**：针对物联网系统
- **工业控制安全扩展要求**：针对工业控制系统

#### 变化4：强化主动防御
- 增加入侵防范、恶意代码防范
- 增加安全审计、集中管控
- 增加态势感知、威胁情报
- 从被动防护变为主动防御

#### 变化5：强化可信验证
- 增加可信计算要求
- 增加可信验证要求
- 从设备可信到应用可信

#### 变化6：强化个人信息保护
- 增加个人信息保护要求
- 增加数据分类分级要求
- 增加数据脱敏、加密要求

### 2.3 等保 2.0 的特点

1. **主动防御**：从被动防护到主动发现、主动响应
2. **动态防御**：从静态防护到动态感知、动态调整
3. **纵深防御**：从单点防护到多层次、全方位防护
4. **精准防护**：从一刀切到基于风险的精准防护
5. **整体防护**：从分散防护到统一管理、整体协同

### 2.4 等保 2.0 标准体系

等保2.0形成了完整的标准体系，包括基础标准、应用标准和产品标准。

## 三、等级划分与定级方法

### 3.1 五个安全等级

| 等级 | 名称 | 定义 | 监管方式 | 典型系统 |
|------|------|------|----------|----------|
| 第一级 | 自主保护级 | 系统遭到破坏后，对公民、法人和其他组织的合法权益造成损害，但不损害国家安全、社会秩序和公共利益 | 自主保护 | 企业内部一般系统 |
| 第二级 | 指导保护级 | 系统遭到破坏后，对公民、法人和其他组织的合法权益造成严重损害，或者对社会秩序和公共利益造成损害，但不损害国家安全 | 公安机关指导 | 中小型企业网站、一般业务系统 |
| 第三级 | 监督保护级 | 系统遭到破坏后，对社会秩序和公共利益造成严重损害，或者对国家安全造成损害 | 公安机关监督、检查 | 金融、电力、交通等重要系统，大中型企业核心系统 |
| 第四级 | 强制保护级 | 系统遭到破坏后，对社会秩序和公共利益造成特别严重损害，或者对国家安全造成严重损害 | 公安机关强制监督、检查 | 国家重要部门、核心金融系统 |
| 第五级 | 专控保护级 | 系统遭到破坏后，对国家安全造成特别严重损害 | 国家指定部门专门监督、检查 | 国防、国家核心机密系统 |

**常见等级分布**：
- 一级系统：约 10%
- 二级系统：约 60%（最常见）
- 三级系统：约 25%（重点监管）
- 四级系统：约 5%
- 五级系统：极少

### 3.2 定级要素

等级保护定级由两个要素决定：

**受侵害的客体**：
1. 公民、法人和其他组织的合法权益
2. 社会秩序和公共利益
3. 国家安全

**对客体的侵害程度**：
1. 造成一般损害
2. 造成严重损害
3. 造成特别严重损害

### 3.3 定级方法

#### 3.3.1 定级步骤

```
确定定级对象 → 确定受侵害客体 → 确定侵害程度 → 初步确定等级
                                                    ↓
                                        专家评审 → 主管部门审核 → 公安机关备案
```

#### 3.3.2 定级矩阵

| 受侵害客体\侵害程度 | 一般损害 | 严重损害 | 特别严重损害 |
|---------------------|----------|----------|--------------|
| 公民、法人和其他组织的合法权益 | 第一级 | 第二级 | 第二级 |
| 社会秩序和公共利益 | 第二级 | 第三级 | 第四级 |
| 国家安全 | 第三级 | 第四级 | 第五级 |

#### 3.3.3 就高原则

如果系统同时侵害多个客体，按最高等级确定。

**示例**：
某系统遭到破坏后，对公民合法权益造成严重损害（对应二级），对社会秩序造成严重损害（对应三级），则系统等级定为三级（就高原则）。

### 3.4 定级对象确定

**定级原则**：
- 独立的系统单独定级
- 大型系统可分解为多个子系统分别定级
- 云平台单独定级，云上系统单独定级
- 关键信息基础设施不低于三级

**常见定级对象**：
- 门户网站
- 业务管理系统
- 数据中心/云平台
- 工控系统
- 物联网平台
- 移动应用系统

### 3.5 定级备案

**备案流程**：
1. 系统运营者确定等级
2. 主管部门审核同意
3. 向公安机关提交备案材料
4. 公安机关审核
5. 颁发备案证明

**备案材料**：
- 信息系统安全等级保护备案表
- 系统定级报告
- 安全建设方案
- 安全管理制度
- 其他材料

**备案时限**：系统上线后 30 日内完成备案。

### 3.6 等保定级案例

**案例1：电商平台定级**

**系统描述**：某电商平台，注册用户500万，日均订单10万，涉及用户个人信息、交易数据、支付数据。

**分析过程**：
1. 受侵害客体：
   - 用户合法权益：严重损害（对应二级）
   - 社会秩序：严重损害（大量用户受影响，对应三级）
   - 国家安全：一般损害（对应三级）
2. 就高原则：三级

**定级结果**：第三级（监督保护级）

---

**案例2：企业内部办公系统定级**

**系统描述**：某企业OA系统，仅内部员工使用，包含员工信息、审批流程、内部文档。

**分析过程**：
1. 受侵害客体：
   - 企业合法权益：严重损害（对应二级）
   - 社会秩序：一般损害（对应二级）
   - 国家安全：无影响
2. 就高原则：二级

**定级结果**：第二级（指导保护级）

---

**案例3：银行核心系统定级**

**系统描述**：某国有银行核心业务系统，处理全国客户的存款、贷款、转账等业务。

**分析过程**：
1. 受侵害客体：
   - 用户合法权益：特别严重损害
   - 社会秩序：特别严重损害（对应四级）
   - 国家安全：严重损害（对应四级）
2. 就高原则：四级

**定级结果**：第四级（强制保护级）

## 四、等保 2.0 标准体系详解

### 4.1 基本要求的总体结构

等保2.0基本要求分为两大类：安全技术要求和安全管理要求。

```
等保2.0基本要求
├── 安全技术要求
│   ├── 安全物理环境
│   ├── 安全通信网络
│   ├── 安全区域边界
│   ├── 安全计算环境
│   └── 安全管理中心
└── 安全管理要求
    ├── 安全管理制度
    ├── 安全管理机构
    ├── 安全管理人员
    ├── 安全建设管理
    └── 安全运维管理
```

### 4.2 不同等级的要求强度

| 要求类别 | 一级 | 二级 | 三级 | 四级 |
|----------|------|------|------|------|
| 安全物理环境 | 基本要求 | + 增强要求 | + 更多增强 | + 最高要求 |
| 安全通信网络 | 基本要求 | + 增强要求 | + 更多增强 | + 最高要求 |
| 安全区域边界 | 基本要求 | + 增强要求 | + 更多增强 | + 最高要求 |
| 安全计算环境 | 基本要求 | + 增强要求 | + 更多增强 | + 最高要求 |
| 安全管理中心 | - | - | 要求 | 更高要求 |
| 安全管理制度 | 基本要求 | + 增强要求 | + 更多增强 | + 最高要求 |
| 安全管理机构 | 基本要求 | + 增强要求 | + 更多增强 | + 最高要求 |
| 安全管理人员 | 基本要求 | + 增强要求 | + 更多增强 | + 最高要求 |
| 安全建设管理 | 基本要求 | + 增强要求 | + 更多增强 | + 最高要求 |
| 安全运维管理 | 基本要求 | + 增强要求 | + 更多增强 | + 最高要求 |

> 注：安全管理中心是三级及以上系统的要求，一、二级不做要求。

### 4.3 等保 2.0 与新技术扩展

#### 4.3.1 云计算安全扩展

**适用场景**：使用云计算服务的系统

**核心扩展要求**：
- 云平台和云上系统分别定级
- 云服务商的安全责任
- 虚拟化安全
- 云平台管理安全
- 数据隔离
- 云租户安全

#### 4.3.2 移动互联安全扩展

**适用场景**：有移动应用的系统

**核心扩展要求**：
- 移动终端安全
- 移动应用安全
- 无线接入安全
- 移动应用分发
- 移动端数据保护

#### 4.3.3 物联网安全扩展

**适用场景**：物联网系统

**核心扩展要求**：
- 感知节点安全
- 感知网络安全
- 数据采集安全
- 设备身份认证
- 边缘计算安全

#### 4.3.4 工业控制安全扩展

**适用场景**：工业控制系统

**核心扩展要求**：
- 工控系统分区隔离
- 工控设备安全
- 工控协议安全
- 工控数据安全
- 工控应急响应

## 五、基本要求（安全技术要求）

### 5.1 安全物理环境

#### 5.1.1 物理位置选择

**要求**：
- 机房场地应选择在具有防震、防风和防雨等能力的建筑内
- 机房场地应避免设在建筑物的顶层或地下室
- 机房场地应远离强振源和强噪声源
- 机房场地应避开强电磁场干扰

**三级要求**：除上述要求外，还应考虑：
- 机房场地应符合抗震设计规范
- 应设置在建筑物的中间楼层

#### 5.1.2 物理访问控制

**要求**：
- 机房出入口应配置电子门禁系统
- 应鉴别进入人员的身份
- 应记录进入人员的进出时间

**三级要求**：
- 重要区域应配置第二道门禁系统
- 应设置机房出入口专人值守
- 应对进出机房的人员进行登记

#### 5.1.3 防盗窃和防破坏

**要求**：
- 应将主要设备放置在机房内
- 应将设备或主要部件进行固定和标识
- 应将通信线缆铺设在隐蔽处
- 应设置防盗报警系统

**三级要求**：
- 应设置监控摄像系统
- 应设置报警装置并与公安联动
- 应对介质介质进行分类管理和标识

#### 5.1.4 防雷击

**要求**：
- 机房建筑应设置避雷装置
- 应设置防雷保安器
- 应设置交流电源地线

**三级要求**：
- 应设置防雷接地
- 应定期检测防雷装置

#### 5.1.5 防火

**要求**：
- 机房应设置火灾自动消防系统
- 机房及相关建筑应配备灭火器材
- 应设置火灾报警装置

**三级要求**：
- 应设置气体灭火系统
- 应设置防火分区
- 应定期进行消防检查

#### 5.1.6 防水和防潮

**要求**：
- 应采取措施防止雨水渗透
- 应采取措施防止结露
- 应安装漏水检测装置

**三级要求**：
- 应安装漏水检测报警系统
- 应定期检查防水设施

#### 5.1.7 温湿度控制

**要求**：
- 应配备空调系统
- 应保持温湿度在规定范围内

**三级要求**：
- 应配备精密空调
- 应进行温湿度监控和记录

#### 5.1.8 电力供应

**要求**：
- 应保证机房电力供应稳定可靠
- 应配备UPS电源

**三级要求**：
- 应采用双路供电
- UPS应提供至少2小时的备用时间
- 应配备柴油发电机
- 应定期进行供电系统测试

#### 5.1.9 电磁防护

**要求**：
- 应采用接地方式防止电磁干扰
- 电源线和通信线缆应隔离铺设

**三级要求**：
- 重要设备应进行电磁屏蔽
- 应定期进行电磁检测

### 5.2 安全通信网络

#### 5.2.1 网络架构

**要求**：
- 应保证网络设备的业务处理能力满足业务高峰期需要
- 应保证网络各个部分的带宽满足业务高峰期需要
- 应划分不同的网络区域
- 应在网络边界部署访问控制设备

**三级要求**：
- 应绘制与当前运行情况相符的网络拓扑结构图
- 应根据各部门的工作职能、重要性等因素划分不同的子网或网段
- 重要网络区域与其他网络区域之间应采取可靠的技术隔离手段
- 应避免将重要网段部署在网络边界处

**案例**：某公司网络架构设计
- 办公区：员工办公终端
- DMZ区：对外服务器
- 业务区：内部业务系统
- 数据区：数据库服务器
- 管理区：运维管理系统
- 各区之间通过防火墙隔离

#### 5.2.2 通信传输

**要求**：
- 应采用校验技术或密码技术保证通信过程中数据的完整性
- 应采用密码技术保证通信过程中数据的保密性

**三级要求**：
- 应采用密码技术保证通信过程中数据的完整性和保密性
- 重要数据传输应使用加密通道
- 应对通信过程中的数据进行完整性校验

#### 5.2.3 可信验证

**三级要求**：
- 可基于可信根对通信设备的系统引导程序、系统程序等进行可信验证
- 可在关键节点进行配置和链路可信验证

### 5.3 安全区域边界

#### 5.3.1 边界防护

**要求**：
- 应保证跨越边界的访问和数据流通过边界设备提供的受控接口进行通信
- 应能够对非授权设备私自联到内部网络的行为进行检查或限制
- 应能够对内部用户非授权联到外部网络的行为进行检查或限制

**三级要求**：
- 应在网络边界或区域之间根据访问控制策略设置访问控制规则
- 应限制无线网络的使用，无线网络应通过可控边界接入
- 应在关键网络节点处对链路状态进行实时检测

#### 5.3.2 访问控制

**要求**：
- 应在网络边界部署访问控制设备，启用访问控制功能
- 应根据访问控制策略对数据流进行控制
- 访问控制策略应能控制到端口级
- 应对进出网络的信息内容进行过滤

**三级要求**：
- 应根据安全策略允许或拒绝访问
- 访问控制规则应明确源地址、目的地址、源端口、目的端口和协议
- 应设置默认拒绝规则
- 应定期评审和优化访问控制策略

#### 5.3.3 入侵防范

**要求**：
- 应在关键网络节点处检测和防止从外部发起的攻击行为
- 应在关键网络节点处检测和防止从内部发起的攻击行为

**三级要求**：
- 应在关键网络节点处部署入侵检测系统
- 应在关键网络节点处部署入侵防御系统
- 应能检测常见攻击类型（端口扫描、暴力破解、SQL注入、XSS等）
- 应能对攻击行为进行阻断
- 应记录攻击源、类型、时间等信息

#### 5.3.4 恶意代码和垃圾邮件防范

**要求**：
- 应在关键网络节点处对恶意代码进行检测和清除
- 应维护恶意代码库的升级和更新

**三级要求**：
- 应在网络边界、电子邮件服务器等位置部署恶意代码检测和防护
- 应支持对压缩文件中的恶意代码进行检测
- 应具备实时检测和清除能力
- 应定期更新恶意代码特征库

#### 5.3.5 安全审计

**要求**：
- 应在网络边界、重要网络节点进行安全审计
- 审计记录应包括事件的日期和时间、用户、事件类型、事件是否成功等
- 应保护审计记录，避免受到未预期的删除、修改或覆盖

**三级要求**：
- 应对网络系统中的网络设备运行状况、网络流量、用户行为等进行日志记录
- 审计记录应包括事件的日期和时间、用户、事件类型、事件是否成功及其他与审计相关的信息
- 应能够根据记录数据进行分析，并生成审计报表
- 应对审计记录进行保护，定期备份，避免受到未预期的删除、修改或覆盖等
- 审计记录保存时间不少于6个月

#### 5.3.6 可信验证

**三级要求**：
- 可基于可信根对边界设备的系统引导程序、系统程序、重要配置参数和边界防护应用程序等进行可信验证
- 可在应用程序的关键执行环节进行动态可信验证

### 5.4 安全计算环境

#### 5.4.1 身份鉴别

**要求**：
- 应对登录的用户进行身份标识和鉴别
- 身份标识具有唯一性
- 应具有登录失败处理功能

**三级要求**：
- 应对登录的用户进行身份标识和鉴别，身份标识具有唯一性
- 应提供身份鉴别信息复杂度检查功能，保证鉴别信息满足复杂度要求
- 应具有登录失败处理功能，应配置并启用结束会话、限制非法登录次数和登录连接超时等措施
- 当进行远程管理时，应采取必要措施防止鉴别信息在网络传输过程中被窃听
- 应采用口令、密码技术、生物技术等两种或两种以上组合的鉴别技术对用户进行身份鉴别（重要系统）

**密码策略要求（三级）**：
- 口令长度不少于8位
- 包含大小写字母、数字和特殊字符中两种以上
- 口令使用期限不超过90天
- 不能与最近5次使用的口令相同
- 连续5次登录失败锁定账号

#### 5.4.2 访问控制

**要求**：
- 应对登录的用户分配账户和权限
- 应重命名或删除默认账户，修改默认口令
- 应及时删除或停用多余的、过期的账户
- 应授予管理用户所需的最小权限

**三级要求**：
- 应依据安全策略控制主体对客体的访问
- 访问控制的粒度应达到主体为用户级或进程级，客体为文件、数据库表级
- 应由授权主体配置访问控制策略
- 应严格限制默认账户的访问权限
- 应对重要信息资源设置敏感标记
- 应依据安全策略严格控制用户对有敏感标记重要信息资源的操作

#### 5.4.3 安全审计

**要求**：
- 应启用安全审计功能，审计覆盖到每个用户
- 应记录重要的安全相关事件
- 应保护审计进程，避免受到未预期的中断
- 应保护审计记录，避免受到未预期的删除、修改或覆盖

**三级要求**：
- 应启用安全审计功能，审计覆盖到每个用户，对重要的用户行为和重要安全事件进行审计
- 审计记录应包括事件的日期和时间、用户、事件类型、事件是否成功及其他与审计相关的信息
- 应对审计记录进行保护，定期备份，避免受到未预期的删除、修改或覆盖等
- 应对审计进程进行保护，防止未经授权的中断
- 审计记录保存时间不少于6个月

#### 5.4.4 入侵防范

**要求**：
- 应遵循最小安装的原则，仅安装需要的组件和应用程序
- 应关闭不需要的系统服务、默认共享和高危端口
- 应通过设定终端接入方式或网络地址范围对通过网络进行管理的管理终端进行限制
- 应能发现可能存在的已知漏洞，并在经过充分测试评估后，及时修补漏洞

**三级要求**：
- 应遵循最小安装的原则，仅安装需要的组件和应用程序
- 应关闭不需要的系统服务、默认共享和高危端口
- 应通过设定终端接入方式或网络地址范围对通过网络进行管理的管理终端进行限制
- 应能发现可能存在的已知漏洞，并在经过充分测试评估后，及时修补漏洞
- 应能够检测到对重要服务器进行入侵的行为，能够记录入侵的源IP、攻击的类型、攻击的目的、攻击的时间，并在发生严重入侵事件时提供报警
- 应能够对重要程序的完整性进行检测，并在检测到完整性受到破坏后具有恢复的措施

#### 5.4.5 恶意代码防范

**要求**：
- 应安装防恶意代码软件或配置具有相应功能的软件
- 应定期进行恶意代码检测和查杀
- 应及时更新防恶意代码软件版本和恶意代码库

**三级要求**：
- 应安装防恶意代码软件或配置具有相应功能的软件，并定期进行升级和更新防恶意代码库
- 应支持防恶意代码的统一管理
- 应及时更新防恶意代码软件版本和恶意代码库
- 主机防恶意代码产品应具有与网络防恶意代码产品不同的恶意代码库
- 应支持由管理中心统一进行防恶意代码软件的更新、检测和查杀

#### 5.4.6 可信验证

**三级要求**：
- 可基于可信根对计算设备的系统引导程序、系统程序、重要配置参数和应用程序等进行可信验证
- 可在应用程序的关键执行环节进行动态可信验证
- 可在检测到可信验证结果不符合预期时进行报警

#### 5.4.7 数据完整性

**要求**：
- 应采用校验技术或密码技术保证重要数据在传输过程中的完整性
- 应采用校验技术或密码技术保证重要数据在存储过程中的完整性

**三级要求**：
- 应采用密码技术保证重要数据在传输过程中的完整性
- 应采用密码技术保证重要数据在存储过程中的完整性
- 在检测到完整性错误时，应能采取必要的恢复措施

#### 5.4.8 数据保密性

**要求**：
- 应采用加密或其他有效措施实现传输过程中重要数据的保密性
- 应采用加密或其他保护措施实现存储过程中重要数据的保密性

**三级要求**：
- 应采用加密或其他有效措施实现传输过程中重要数据的保密性
- 应采用加密或其他保护措施实现存储过程中重要数据的保密性
- 应使用密码技术保证重要数据的保密性
- 应采取措施防止鉴别信息在存储和传输过程中被窃听

#### 5.4.9 数据备份恢复

**要求**：
- 应提供重要数据的本地数据备份与恢复功能
- 应提供异地数据备份功能
- 应定期进行备份恢复测试

**三级要求**：
- 应提供重要数据的本地数据备份与恢复功能
- 应提供异地实时备份功能，利用通信网络将重要数据实时备份至备份场地
- 应提供重要数据处理系统的热冗余，保证系统的高可用性
- 应建立异地灾难备份中心，配置灾难恢复所需的通信线路和数据处理系统
- 应定期进行备份恢复测试

**备份策略要求**：
- 本地备份：每日增量备份，每周全量备份
- 异地备份：实时或准实时备份
- 备份介质：至少保存两份
- 备份测试：每季度至少一次

#### 5.4.10 剩余信息保护

**要求**：
- 应保证鉴别信息所在的存储空间被释放或重新分配前得到完全清除
- 应保证存有敏感数据的存储空间被释放或重新分配前得到完全清除

**三级要求**：
- 应保证鉴别信息所在的存储空间被释放或重新分配前得到完全清除
- 应保证存有敏感数据的存储空间被释放或重新分配前得到完全清除
- 应能对存储的重要数据进行删除或销毁，确保无法恢复

#### 5.4.11 个人信息保护

**三级要求**：
- 应仅采集和保存业务必需的用户个人信息
- 应禁止未授权访问和非法使用用户个人信息
- 应采取措施防止个人信息泄露
- 应对个人信息进行分类管理
- 应对个人信息的访问进行审计

### 5.5 安全管理中心

- 应通过系统管理员对系统的资源和运行进行配置、控制和管理

#### 5.5.3 安全管理

**三级要求**：

- 安全管理员的操作权限应仅限于安全管理相关操作

**三级要求**：

- 应能够对分布在各处的网络设备、安全设备、服务器等进行集中管理
- 应能够对安全事件进行集中分析和响应
- 应能够对全网流量进行监控和分析
- 应能够对安全策略进行统一管理
- 应能对审计数据进行集中存储和分析
- 安全管理中心自身应有足够的安全保障

## 六、安全管理要求

### 6.1 安全管理制度

#### 6.1.1 安全策略

**要求**：
- 应制定信息安全工作的总体方针和安全策略
- 应说明机构安全工作的总体目标、范围、原则和安全框架等
- 安全策略应由最高管理者批准

**三级要求**：
- 应制定信息安全工作的总体方针和安全策略
- 安全策略应说明机构安全工作的总体目标、范围、原则和安全框架等
- 应对安全策略进行定期评审和修订
- 安全策略应以正式文件形式发布
- 安全策略应由最高管理者批准

#### 6.1.2 管理制度

**要求**：
- 应制定安全管理制度，对信息安全活动进行规范
- 安全管理制度应覆盖各个方面

**三级要求**：
- 应建立完善的安全管理制度体系
- 安全管理制度应包括：
  - 安全管理机构和人员安全管理制度

  - 系统运维管理制度
  - 应急处理制度
  - 访问控制管理制度

  - 物理安全管理制度
- 应对安全管理制度进行定期评审和修订

#### 6.1.3 制定和发布

**要求**：
- 应组织相关人员制定安全管理制度
- 安全管理制度应以正式文件形式发布
- 应对安全管理制度进行宣传和培训

**三级要求**：
- 应组织相关人员制定安全管理制度
- 安全管理制度应以正式文件形式发布
- 应对安全管理制度进行宣传和培训
- 应指定专门的部门或人员负责安全管理制度的制定和维护
- 安全管理制度发布前应进行评审

#### 6.1.4 评审和修订

**要求**：
- 应定期对安全管理制度进行评审
- 应根据需要及时修订安全管理制度
- 修订后的制度应及时发布

**三级要求**：
- 应定期对安全管理制度进行评审（每年至少一次）
- 应根据需要及时修订安全管理制度
- 修订后的制度应及时发布
- 应对制度的执行情况进行检查
- 重大变更时应及时修订

### 6.2 安全管理机构

#### 6.2.1 岗位设置

**要求**：
- 应设立信息安全管理工作的职能部门
- 应设立安全主管、安全管理等岗位
- 应明确各岗位职责

**三级要求**：
- 应设立信息安全管理工作的职能部门
- 应设立安全主管、安全管理、安全审计等岗位

## 七、测评流程与方法

### 7.1 等级测评概述

**等级测评定义**：
等级测评是指经国家有关部门认可的测评机构，依据国家网络安全等级保护制度规定，对信息系统安全等级保护状况进行检测评估的活动。

**测评目的**：
- 验证系统是否达到相应等级的安全要求
- 发现系统存在的安全问题和隐患
- 为安全整改提供依据
- 为监督检查提供技术支撑

### 7.2 测评流程

```
测评准备 → 方案编制 → 现场测评 → 分析与报告编制 → 报告提交
    │           │           │              │               │
    ▼           ▼           ▼              ▼               ▼
  项目启动    编制测评    现场访谈      单项结果分析     提交测评
  资料收集    方案        现场检查      整体结果分析     报告
  人员准备    准备工具    工具测试      风险分析         整改建议
```

### 7.3 测评方法

#### 7.3.1 访谈

**访谈对象**：
- 安全管理人员
- 系统管理员
- 网络管理员
- 运维人员
- 业务人员

**访谈内容**：
- 安全管理制度
- 安全组织架构
- 安全运维流程
- 安全事件处理
- 应急响应

#### 7.3.2 检查

**检查内容**：
- 安全管理制度文件
- 安全配置文档
- 运维记录
- 安全设备配置
- 系统配置
- 物理环境

#### 7.3.3 测试

**测试内容**：
- 网络安全测试
- 主机安全测试
- 应用安全测试
- 数据安全测试
- 渗透测试

**测试工具**：
- 漏洞扫描器
- 渗透测试工具

### 7.4 测评指标

**测评结果分类**：

| 结果类型 | 说明 |
|----------|------|
| 符合 | 完全满足要求 |
| 部分符合 | 部分满足要求，存在不足 |
| 不符合 | 不满足要求 |
| 不适用 | 该要求不适用于被测系统 |

**测评结论**：
- 优：符合率 ≥ 90%
- 良：符合率 ≥ 80%
- 中：符合率 ≥ 70%
- 差：符合率 < 70%

> 注：三级系统一般要求符合率达到 70% 以上才算通过，但具体标准可能因地区和行业而异。

  确定等级   对照标准   技术方案   技术整改   第三方测评  定期检查
  专家评审   识别差距   管理方案   制度建设   问题整改    持续改进

### 8.8 等保建设常见问题

#### 问题1：等保就是买设备？

**答案**：不是。等保包括技术和管理两方面，设备只是技术的一部分，还需要制度、人员、流程等管理方面的建设。

#### 问题2：等保测评通过就一劳永逸了？

**答案**：不是。等保是持续的过程，需要每年进行测评，日常持续运维，持续改进。

#### 问题3：二级系统比三级简单很多？

**答案**：二级和三级的要求框架基本一致，但三级要求更高，特别是安全管理中心、异地备份、入侵防御等方面。

#### 问题4：等保只是安全部门的事？

**答案**：不是。等保涉及技术、管理、人员等各方面，需要各部门共同参与，是全员的责任。

### 8.9 等保建设案例

**案例：某企业三级等保建设项目**

**项目背景**：
某中型互联网企业，主要业务是在线教育，注册用户300万。根据业务特点和规模，系统定为第三级。企业之前没有系统的安全建设，需要从零开始进行等保建设。

**项目周期**：6个月

**项目过程**：

**第1个月：定级备案+差距分析**
- 完成系统定级（三级）
- 向当地公安局备案
- 进行全面差距分析
- 发现差距项：技术类35项，管理类25项

**主要差距**：
- 缺少安全管理中心
- 未部署IDS/IPS
- 网络未有效分段
- 数据传输未加密
- 日志保存时间不足
- 没有异地备份
- 安全制度不完善
- 缺少专职安全人员

**第2个月：方案设计**
- 设计安全架构
- 确定产品选型
- 制定实施计划
- 预算：约150万（设备100万+服务50万）

**第3-4个月：技术整改**
- 网络重新规划和分段
- 部署防火墙、IPS、WAF
- 部署日志审计系统
- 部署堡垒机
- 服务器安全加固
- 部署SSL证书，实现HTTPS
- 建设异地备份
- 建设安全管理中心

**第5个月：管理整改+试运行**
- 编写安全制度文件（20+份）
- 建立安全组织
- 开展安全培训
- 完善运维流程
- 系统试运行

**第6个月：等级测评**
- 选择测评机构
- 现场测评
- 发现问题8项（主要是细节问题）
- 整改后复测通过
- 最终得分：82分

**项目成果**：
- 顺利通过等保三级测评
- 安全防护能力大幅提升
- 建立了完善的安全管理体系
- 员工安全意识显著提高
- 满足了监管和客户要求

**经验总结**：
1. 领导重视是关键
2. 提前规划，分步实施
3. 技术和管理并重
4. 选择专业的服务商
5. 全员参与，持续改进
