# ISMS 建设流程（PDCA）

### 3.1 PDCA 循环模型

ISMS 建设遵循 PDCA（戴明环）模型，实现持续改进：

```
        ┌─────────────┐
        │   Plan 策划  │ ←── 确定方针、目标、风险评估
        └──────┬──────┘
               │
        ┌──────▼──────┐
        │    Do 实施   │ ←── 实施控制措施、运行管理
        └──────┬──────┘
               │
        ┌──────▼──────┐
        │  Check 检查  │ ←── 监控、内审、管理评审
        └──────┬──────┘
               │
        ┌──────▼──────┐
        │   Act 改进   │ ←── 纠正措施、持续改进
        └─────────────┘
```

### 3.2 第一阶段：Plan（策划）

#### 3.2.1 启动准备

**步骤1：获得管理层支持**
- 向高层汇报 ISMS 建设的必要性和价值
- 获得管理层的批准和资源承诺
- 任命管理者代表

**关键文档**：
- ISMS 项目立项申请
- 管理层批准文件
- 项目章程

**案例**：某制造业企业 CEO 在 ISMS 启动会上明确表示："ISMS 建设不是可选项，而是必选项。各部门必须全力配合，安全部门拥有跨部门协调的权力。"

#### 3.2.2 确定范围

**确定 ISMS 范围需要考虑**：
1. 组织的业务范围
2. 涉及的信息系统和资产
3. 涉及的部门和人员
4. 地理位置
5. 外部相关方

**范围声明示例**：
> "本信息安全管理体系适用于XX公司总部及全国各分公司的办公网络、业务系统、数据中心及相关人员，涵盖研发、生产、销售、财务、人力资源等所有业务领域。"

#### 3.2.3 风险评估

**风险评估流程**：
1. 资产识别与估价
2. 威胁识别
3. 脆弱性识别
4. 风险分析
5. 风险评价
6. 风险处置计划

**风险评估方法**：
- 定性评估：专家判断、矩阵法
- 定量评估：数值计算、统计分析
- 半定量评估：分级赋值

**详细内容见「安全风险管理」章节。**

#### 3.2.4 制定方针和目标

**信息安全方针要点**：
- 与组织战略一致
- 包含安全目标框架
- 满足法律法规要求
- 承诺持续改进
- 形成文件并传达
- 定期评审

**方针示例**：
> "本公司坚持'安全第一、预防为主、全员参与、持续改进'的信息安全方针，通过建立和实施信息安全管理体系，保护信息资产的保密性、完整性和可用性，确保业务持续稳定运行，满足法律法规和客户要求。"

**安全目标示例**：
| 目标类别 | 目标内容 | 衡量指标 | 责任部门 |
|----------|----------|----------|----------|
| 风险管理 | 重大安全风险得到有效控制 | 高风险项数量 ≤ 5项 | 安全部 |
| 事件管理 | 安全事件及时响应处置 | 重大事件响应时间 ≤ 2小时 | 安全部 |
| 培训教育 | 全员安全意识达标 | 培训覆盖率 100%，通过率 ≥ 95% | 人力资源部 |
| 合规管理 | 满足法律法规要求 | 合规达标率 ≥ 98% | 合规部 |
| 业务连续性 | 核心业务系统持续可用 | 可用性 ≥ 99.9% | IT部 |

### 3.3 第二阶段：Do（实施）

#### 3.3.1 建立安全组织

**安全组织架构示例**：
```
信息安全委员会（CEO/CIO担任主席）
        │
        ├── 信息安全部（CISO/安全总监）
        │     ├── 安全管理组
        │     ├── 安全技术组
        │     ├── 安全运营组
        │     └── 合规审计组
        │
        ├── 各部门安全责任人
        │     ├── 研发部安全责任人
        │     ├── 运维部安全责任人
        │     ├── 财务部安全责任人
        │     └── ...
        │
        └── 全员安全责任
```

#### 3.3.2 建立制度体系

**制度体系层级**：
```
一级文件：信息安全方针（1份）
    │
二级文件：管理制度（10-20份）
    ├── 信息安全组织管理办法
    ├── 信息安全风险管理办法
    ├── 人员安全管理办法
    ├── 物理安全管理办法
    ├── 访问控制管理办法
    ├── ...
    │
三级文件：操作规范/流程（30-50份）
    ├── 账号权限申请流程
    ├── 变更管理流程
    ├── 事件响应流程
    ├── 备份恢复操作规范
    ├── ...
    │
四级文件：记录表单（50+份）
    ├── 权限申请表
    ├── 变更申请单
    ├── 事件报告单
    ├── 培训记录表
    ├── ...
```

**案例**：某金融机构建立了完整的安全制度体系，包含 3 份一级文件、18 份二级文件、45 份三级文件和 60 多份记录表单，覆盖了信息安全的各个方面。

#### 3.3.3 部署技术控制措施

根据风险评估结果和控制要求，部署相应的技术措施：

| 控制类别 | 典型措施 |
|----------|----------|
| 网络安全 | 防火墙、IDS/IPS、VPN、网络分段 |
| 主机安全 | 防病毒、主机加固、补丁管理 |
| 应用安全 | WAF、代码审计、安全测试 |
| 数据安全 | 加密、脱敏、备份、DLP |
| 身份认证 | 统一身份认证、多因素认证 |
| 访问控制 | RBAC、最小权限、权限审计 |
| 安全监控 | SIEM、日志审计、态势感知 |

#### 3.3.4 开展安全培训

**培训分类**：
- 全员安全意识培训
- 管理层安全培训
- 技术人员安全培训
- 新员工入职安全培训
- 特定岗位专项培训

**培训内容示例（全员培训）**：
1. 信息安全基础知识
2. 公司安全制度介绍
3. 密码安全
4. 钓鱼邮件识别与防范
5. 数据安全保护
6. 办公安全规范
7. 移动设备安全
8. 安全事件报告流程

### 3.4 第三阶段：Check（检查）

#### 3.4.1 日常监控

**监控内容**：
- 安全事件监控
- 系统运行监控
- 网络流量监控
- 漏洞扫描监控
- 合规性监控

**监控工具**：
- SIEM（安全信息与事件管理）
- SOC（安全运营中心）
- 漏洞扫描器
- 日志审计系统

#### 3.4.2 内部审核

**内审流程**：
1. 制定内审计划
2. 组建审核组
3. 审核准备（文件评审、检查表编制）
4. 现场审核（首次会议、访谈、检查、末次会议）
5. 编制审核报告
6. 跟踪整改

**内审频次**：每年至少一次，可根据需要增加。

#### 3.4.3 管理评审

**管理评审输入**：
- 以往管理评审的跟踪措施
- 与信息安全管理体系相关的内外部因素的变化
- 信息安全绩效方面的信息
- 资源充分性
- 风险评估结果和风险处置计划的状态
- 不合格及纠正措施的状态
- 改进机会

**管理评审输出**：
- 改进的决定
- 信息安全目标更新的需要
- 资源需求
- 任何相关决定和措施

**频次**：每年至少一次。

### 3.5 第四阶段：Act（改进）

#### 3.5.1 不符合与纠正措施

**不符合来源**：
- 内部审核发现
- 外部审核发现
- 安全事件
- 日常监控发现
- 管理评审输出

**纠正措施流程**：
1. 识别不符合
2. 原因分析
3. 制定纠正措施
4. 实施纠正措施
5. 验证效果
6. 记录归档

#### 3.5.2 持续改进

**持续改进方法**：
- 定期风险评估
- 定期内审和管理评审
- 安全事件复盘
- 最佳实践学习
- 技术更新升级
- 流程优化

**改进机会来源**：
- 风险评估结果
- 安全事件分析
- 审核发现
- 技术发展
- 业务变化
- 法规更新

### 3.6 ISMS 建设时间规划（参考）

| 阶段 | 工作内容 | 时间（中小企业） | 时间（大型企业） |
|------|----------|----------------|----------------|
| 启动准备 | 立项、组建团队、培训 | 1-2周 | 2-4周 |
| 差距分析 | 现状调研、差距评估 | 2-3周 | 4-6周 |
| 体系策划 | 方针目标、风险评估 | 3-4周 | 6-8周 |
| 文件编写 | 制度文件编写 | 4-6周 | 8-12周 |
| 实施运行 | 制度落地、技术部署 | 2-3个月 | 4-6个月 |
| 内部审核 | 内审、整改 | 1-2周 | 2-4周 |
| 管理评审 | 管理评审 | 1周 | 1-2周 |
| 认证审核 | 认证机构审核 | 1-2周 | 2-3周 |
| **合计** | | **约6个月** | **约12个月** |
