# 访问控制

### 10.1 访问控制概述

**访问控制定义**：对主体访问客体的权限进行管理和控制，确保只有授权用户才能访问资源。

**访问控制三要素**：
- 主体（Subject）：访问者（用户、进程、设备）
- 客体（Object）：被访问的资源（文件、系统、数据）
- 权限（Permission）：访问的方式（读、写、执行）

### 10.2 访问控制模型

#### 10.2.1 自主访问控制（DAC）

**特点**：
- 资源所有者可以自主分配访问权限
- 灵活性高
- 安全性较低

**适用场景**：个人文件、小型系统

#### 10.2.2 强制访问控制（MAC）

**特点**：
- 由系统强制分配安全标签
- 用户和资源都有安全级别
- 严格的安全规则
- 安全性高，灵活性低

**适用场景**：高安全等级系统、涉密系统

#### 10.2.3 基于角色的访问控制（RBAC）

**特点**：
- 权限与角色关联
- 用户通过角色获得权限
- 便于权限管理
- 是最常用的访问控制模型

**RBAC 模型结构**：
```
用户 ←→ 角色 ←→ 权限
  │       │       │
  └── 多对多 ────┘
```

**RBAC 优势**：
- 简化权限管理
- 便于职责分离
- 易于审计
- 灵活高效

#### 10.2.4 基于属性的访问控制（ABAC）

**特点**：
- 根据属性（用户属性、资源属性、环境属性）动态决策
- 灵活性最高
- 策略定义复杂

**适用场景**：复杂业务场景、云环境

### 10.3 访问控制原则

#### （1）最小权限原则
用户只拥有完成工作所需的最小权限。

**案例**：某公司普通员工默认只有文件读取权限，只有在申请并获批后才能获得写入权限。

#### （2）职责分离原则
关键任务由多人分担，防止单人舞弊。

**典型职责分离**：
- 申请与审批分离
- 开发与运维分离
- 操作与审计分离
- 出纳与会计分离

#### （3）知其所需原则
只向需要知道该信息的人授权。

#### （4）默认拒绝原则
默认情况下拒绝所有访问，只开放明确授权的访问。

### 10.4 用户账号管理

#### 10.4.1 账号生命周期管理

```
账号申请 → 账号审批 → 账号创建 → 权限分配 → 使用监控 → 权限变更 → 账号注销
    │          │          │          │          │          │          │
    ▼          ▼          ▼          ▼          ▼          ▼          ▼
  提交申请   主管审批   系统创建   按需分配   审计监控   定期复核   及时注销
  说明用途   安全审核   初始密码   最小权限   异常检测   权限清理   资料归档
```

#### 10.4.2 账号分类

| 账号类型 | 用途 | 管理要求 |
|----------|------|----------|
| 普通用户账号 | 员工日常使用 | 实名、定期审计 |
| 管理员账号 | 系统管理 | 严格管控、双人审批 |
| 服务账号 | 应用程序使用 | 密码复杂、定期更换 |
| 临时账号 | 临时使用 | 设有效期、到期删除 |
| 测试账号 | 测试使用 | 仅测试环境、定期清理 |
| 共享账号 | 多人共用 | 尽量避免、严格审计 |

#### 10.4.3 密码管理

**密码策略要求**：
- 最小长度：8位以上（重要系统12位以上）
- 复杂度：包含大小写字母、数字、特殊字符
- 有效期：90天更换
- 历史密码：不能使用最近5次的密码
- 登录失败锁定：连续5次失败锁定账号
- 禁止共享密码

**密码管理最佳实践**：
- 使用密码管理器
- 启用多因素认证（MFA）
- 重要系统使用硬件令牌
- 定期进行密码审计

### 10.5 权限管理

#### 10.5.1 权限申请与审批

**权限申请流程**：
1. 员工提交权限申请
2. 部门负责人审批
3. 系统管理员审核
4. 安全部门审核（重要权限）
5. 权限分配
6. 通知申请人

#### 10.5.2 权限审计

**审计内容**：
- 账号是否合规（是否有多余账号）
- 权限是否合理（是否过度授权）
- 权限是否使用（是否有僵尸权限）
- 权限变更是否有记录

**审计频次**：
- 普通权限：每季度
- 管理员权限：每月
- 重要系统：每月

#### 10.5.3 特权账号管理

**特权账号范围**：
- 系统管理员（root、administrator）
- 数据库管理员（DBA）
- 网络设备管理员
- 应用管理员

**管理措施**：
1. 专人专用，一人一号
2. 多因素认证
3. 操作全程审计
4. 定期轮换密码
5. 最小权限原则
6. 堡垒机统一管理

### 10.6 认证管理

#### 10.6.1 认证方式

| 认证方式 | 特点 | 安全性 |
|----------|------|--------|
| 密码认证 | 简单、常用 | 低 |
| 短信验证码 | 方便 | 中 |
| 动态令牌 | 安全 | 高 |
| 数字证书 | 安全可靠 | 高 |
| 生物识别 | 便捷 | 中高 |
| 多因素认证 | 组合认证 | 最高 |

#### 10.6.2 多因素认证（MFA）

**常见组合**：
- 密码 + 短信验证码
- 密码 + 动态令牌
- 密码 + 指纹
- 密码 + 数字证书

**应启用MFA的场景**：
- 管理员登录
- VPN 远程访问
- 重要系统登录
- 云服务控制台
- 敏感操作确认

### 10.7 访问控制审计

**审计内容**：
- 登录日志审计
- 权限变更审计
- 敏感操作审计
- 异常访问审计

**审计要求**：
- 日志不可删除
- 日志保留足够时间
- 定期审计分析
- 异常及时告警

### 10.8 访问控制案例

**案例：内部数据泄露事件**
某公司离职员工利用未及时注销的账号，登录系统下载了大量客户数据并出售给竞争对手。

**原因分析**：
- 离职账号未及时注销
- 权限过大（可下载全部数据）
- 没有异常访问检测
- 敏感操作没有审计

**改进措施**：
- 建立离职账号自动注销机制
- 实施最小权限原则
- 部署数据防泄漏（DLP）系统
- 加强异常访问监控
- 敏感操作增加审批流程
