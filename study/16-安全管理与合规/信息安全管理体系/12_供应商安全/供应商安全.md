# 供应商安全

### 12.1 供应商安全概述

**供应商安全的重要性**：
- 供应链攻击日益增多
- 供应商可能成为攻击入口
- 第三方风险是重要安全风险
- 合规要求（等保、ISO 27001等）

**供应商安全风险**：
- 产品/服务存在安全漏洞
- 供应商人员访问内部系统
- 数据泄露给供应商
- 供应商服务中断影响业务
- 供应链投毒攻击

### 12.2 供应商分类分级

**按重要性分级**：

| 级别 | 定义 | 示例 | 管理要求 |
|------|------|------|----------|
| 核心供应商 | 对业务有重大影响 | 云服务商、核心系统开发商 | 严格安全评估、定期审计 |
| 重要供应商 | 对业务有较大影响 | 安全服务商、运维外包 | 安全评估、安全协议 |
| 一般供应商 | 对业务有一定影响 | 办公软件供应商 | 基本安全要求 |
| 次要供应商 | 影响较小 | 普通办公用品 | 简单管理 |

### 12.3 供应商全生命周期安全管理

```
供应商选择 → 合同签署 → 服务交付 → 持续监控 → 定期评估 → 终止合作
    │            │           │           │           │           │
    ▼            ▼           ▼           ▼           ▼           ▼
  安全评估     安全协议     访问控制     绩效监控     安全审计     权限回收
  资质审查     责任条款     安全监督     事件响应     风险评估     数据清理
  背景调查     SLA约定     质量检查     合规检查     续约决策     资料归档
```

### 12.4 供应商安全评估

#### 12.4.1 评估内容

| 评估维度 | 评估内容 |
|----------|----------|
| 安全资质 | 是否有安全认证（ISO 27001、等保等） |
| 安全组织 | 是否有安全部门和专职人员 |
| 安全制度 | 是否有完善的安全管理制度 |
| 技术能力 | 安全技术能力和经验 |
| 历史记录 | 过往安全事件和违规记录 |
| 财务状况 | 财务稳定性 |
| 合规情况 | 法律法规合规性 |

#### 12.4.2 评估方法

- 问卷调查
- 文档审查
- 现场考察
- 客户访谈
- 背景调查

### 12.5 供应商安全协议

**安全协议核心条款**：

1. **安全责任条款**：明确双方安全责任
2. **数据保护条款**：数据保密、使用限制
3. **访问控制条款**：访问权限、审批流程
4. **安全事件条款**：事件报告、应急响应
5. **合规性条款**：遵守相关法律法规
6. **审计条款**：甲方有权审计
7. **违约责任条款**：违约处理方式
8. **数据返还/销毁条款**：合作结束后数据处理

### 12.6 供应商访问管理

**供应商人员访问管理**：
1. 访问申请：供应商提交访问申请
2. 审批：甲方相关部门审批
3. 账号创建：创建临时账号，设有效期
4. 权限分配：最小权限原则
5. 访问监控：全程监控操作
6. 账号注销：访问结束后立即注销

**远程访问管理**：
- 使用 VPN 或堡垒机
- 多因素认证
- 全程录屏审计
- 访问时间限制

**现场访问管理**：
- 访客登记
- 佩戴访客证
- 甲方人员陪同
- 限制活动区域

### 12.7 软件供应链安全

#### 12.7.1 软件供应链风险

**风险类型**：
- 开源组件漏洞
- 第三方库后门
- 构建工具被篡改
- 依赖混淆攻击
- 软件更新投毒

#### 12.7.2 开源组件安全管理

**管理措施**：
1. 建立开源组件清单（SBOM）
2. 开源组件漏洞扫描
3. 开源组件许可证合规检查
4. 建立组件使用审批流程
5. 及时更新有漏洞的组件

**工具推荐**：
- Snyk
- Sonatype Nexus
- OWASP Dependency-Check
- Black Duck

### 12.8 供应商安全案例

**案例：SolarWinds 供应链攻击**
2020年，SolarWinds 公司的 Orion 平台软件更新包中被植入恶意代码，导致约 18000 个客户受到影响，包括美国政府机构和众多 Fortune 500 企业。

**攻击方式**：
- 攻击者入侵 SolarWinds 开发环境
- 在软件更新包中植入后门
- 通过正常更新渠道分发
- 受害者安装更新后被入侵

**教训**：
- 供应链安全极其重要
- 开发环境安全防护不足
- 软件完整性校验缺失
- 供应商安全管理不到位

**防护措施**：
- 加强供应商安全评估
- 软件更新签名验证
- 监控异常行为
- 网络分段隔离
- 最小权限原则
