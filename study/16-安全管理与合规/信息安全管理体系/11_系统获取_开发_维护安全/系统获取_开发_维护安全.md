# 系统获取/开发/维护安全

### 11.1 系统安全概述

**系统全生命周期安全**：
```
需求分析 → 设计 → 开发 → 测试 → 上线 → 运维 → 下线
    │        │       │       │       │       │       │
    ▼        ▼       ▼       ▼       ▼       ▼       ▼
  安全需求  安全设计  安全编码  安全测试  安全上线  安全运维  安全下线
```

### 11.2 安全需求分析

**安全需求来源**：
1. 法律法规要求
2. 行业标准要求
3. 客户合同要求
4. 风险评估结果
5. 业务安全需求

**安全需求分类**：
- 身份认证需求
- 访问控制需求
- 数据安全需求
- 审计日志需求
- 通信安全需求
- 可靠性需求
- 合规性需求

### 11.3 安全设计

#### 11.3.1 安全设计原则

1. **最小权限原则**：每个模块只拥有必要的权限
2. **纵深防御原则**：多层防护，一层失效还有下一层
3. **失败安全原则**：系统失败时进入安全状态
4. **不信任原则**：不信任任何外部输入
5. **简单性原则**：安全机制越简单越可靠
6. **公开设计原则**：安全不依赖于算法保密

#### 11.3.2 常见安全设计模式

- 检查点模式：在关键操作前进行安全检查
- 代理模式：通过代理控制访问
- 审计模式：记录所有安全相关操作
- 哨兵模式：统一的入口检查
- 安全会话模式：安全的会话管理

### 11.4 安全编码

#### 11.4.1 常见安全编码漏洞

| 漏洞类型 | 描述 | 危害 |
|----------|------|------|
| SQL注入 | 恶意SQL语句插入 | 数据泄露、篡改 |
| XSS跨站脚本 | 恶意脚本注入 | 会话劫持、钓鱼 |
| CSRF跨站请求伪造 | 伪造用户请求 | 恶意操作 |
| 文件上传漏洞 | 恶意文件上传 | 服务器控制 |
| 命令注入 | 系统命令注入 | 服务器控制 |
| 路径遍历 | 访问非授权文件 | 敏感文件泄露 |
| 弱密码 | 密码强度不足 | 账号被盗 |
| 敏感信息泄露 | 错误信息泄露 | 信息收集 |

#### 11.4.2 安全编码规范

**输入验证**：
- 所有外部输入都要验证
- 使用白名单验证
- 验证数据类型、长度、格式、范围

**输出编码**：
- 输出到HTML进行HTML编码
- 输出到JavaScript进行JS编码
- 输出到URL进行URL编码

**错误处理**：
- 不向用户暴露详细错误信息
- 错误信息记录到日志
- 统一的错误处理机制

**密码安全**：
- 不存储明文密码
- 使用强哈希算法（bcrypt、scrypt、Argon2）
- 添加盐值（Salt）

### 11.5 安全测试

#### 11.5.1 安全测试类型

| 测试类型 | 说明 | 阶段 |
|----------|------|------|
| 静态代码分析（SAST） | 源代码安全扫描 | 开发阶段 |
| 动态应用安全测试（DAST） | 运行时安全扫描 | 测试阶段 |
| 渗透测试 | 模拟攻击测试 | 上线前 |
| 代码审计 | 人工代码审查 | 开发阶段 |
| 模糊测试 | 异常输入测试 | 测试阶段 |
| 配置审计 | 安全配置检查 | 运维阶段 |

#### 11.5.2 DevSecOps

**DevSecOps 理念**：
- 将安全融入 DevOps 流程
- 安全左移，在开发早期考虑安全
- 自动化安全测试
- 全员安全责任

**DevSecOps 工具链**：
```
代码提交 → 静态扫描 → 构建 → 依赖检查 → 测试 → 动态扫描 → 部署 → 运行监控
    │          │         │        │          │        │          │        │
    ▼          ▼         ▼        ▼          ▼        ▼          ▼        ▼
  Git       SonarQube   Jenkins   Snyk      JUnit    OWASP ZAP   Ansible   SIEM
```

### 11.7 系统维护安全

**日常维护安全**：
- 补丁管理：及时安装安全补丁
- 漏洞管理：定期扫描和修复漏洞
- 配置管理：定期审计安全配置
- 账号管理：定期清理无效账号
- 日志审计：定期审计安全日志

**变更安全**：
- 所有变更需经过审批
- 变更前进行风险评估
- 变更后进行安全验证
- 变更有回退方案

### 11.8 安全开发案例

**案例：某电商平台SQL注入漏洞**
某电商平台用户登录接口存在SQL注入漏洞，攻击者利用漏洞获取了全部用户数据，包括密码、手机号、地址等。

**原因分析**：
- 开发人员安全意识不足
- 代码中使用字符串拼接SQL
- 没有输入验证
- 没有安全测试环节

**改进措施**：
- 使用预编译语句（PreparedStatement）
- 实施安全编码规范
- 增加代码安全扫描
- 进行安全开发培训
- 上线前安全测试
