# 等保测评与GRC平台实践

> 等级保护测评是合规落地的关键环节，GRC平台是企业安全治理的技术支撑。

---

## 一、网络安全等级保护测评详解

### 1.1 等保2.0测评流程

**测评标准体系**
- GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》
- GB/T 28448-2019《信息安全技术 网络安全等级保护测评要求》
- GB/T 28449-2018《信息安全技术 网络安全等级保护测评过程指南》
- GB/T 22240-2020《信息安全技术 网络安全等级保护定级指南》

**测评流程**
```
1. 测评准备阶段
   ├── 收集被测系统资料
   ├── 编制测评方案
   ├── 准备测评工具
   └── 确定测评人员

2. 方案编制阶段
   ├── 确定测评边界
   ├── 确定测评对象
   ├── 编制测评指标
   └── 制定测评实施计划

3. 测评实施阶段
   ├── 现场测评（访谈、核查、测试）
   ├── 记录测评结果
   ├── 发现问题确认
   └── 问题风险分析

4. 分析与报告编制阶段
   ├── 单项测评结果判定
   ├── 单元测评结果判定
   ├── 整体测评结果判定
   ├── 风险分析
   └── 编制测评报告
```

### 1.2 等保2.0技术要求详解

#### 1.2.1 安全物理环境

**物理位置选择**
- 机房应选择在具有防震、防风、防雨能力的建筑内
- 机房场地应避免设在地下室的最底层

**物理访问控制**
- 机房入口配置电子门禁系统
- 访客需登记并陪同
- 门禁记录保存至少6个月

**防盗窃和防破坏**
- 设备标识、主要设备固定、通信线缆隐蔽

**防雷击**
- 机房应设置雷电压保护器
- 应设置交流电源地线

**防火**
- 机房应设置火灾自动消防系统
- 应配置温感/烟感探测器

**防水和防潮**
- 安装防雨水渗漏和防结露装置
- 地面应有防水措施

**防静电**
- 采用防静电地板
- 配置静电消除器

**温湿度控制**
- 配置精密空调
- 温度18-28°C，湿度35-75%

**电力供应**
- 配置UPS不间断电源
- 备用发电机

**电磁防护**
- 电源线和通信线缆隔离敷设
- 电磁屏蔽

#### 1.2.2 安全通信网络

**网络架构**
- 划分不同网络区域
- 避免将重要网络区域部署在边界处
- 重要区域与其他区域隔离
- 通信传输应采用校验技术或加密技术

**通信传输**
- 通信过程中数据完整性校验
- 通信过程中数据加密传输

**可信接入**
- 设备接入网络前进行身份鉴别
- 接入后进行安全验证

#### 1.2.3 安全区域边界

**边界防护**
- 跨边界访问和数据流通过边界防护设备
- 非授权设备不能接入网络
- 内部设备不能私自连接外部网络

**访问控制**
- 边界设备配置访问控制策略
- 精确到端口和会话级别

**入侵防范**
- 检测和阻挡网络攻击
- 分析攻击行为并告警

**恶意代码防范**
- 边界处检测和清除恶意代码
- 防范策略和恶意代码库更新

**安全审计**
- 对边界访问行为进行审计
- 审计记录保存至少6个月

#### 1.2.4 安全计算环境

**身份鉴别**
- 身份唯一性
- 身份鉴别信息复杂度
- 鉴别信息传输加密
- 登录失败处理
- 会话超时
- 远程管理加密

**访问控制**
- 访问主体和客体权限控制
- 权限分离
- 最小权限
- 默认拒绝

**安全审计**
- 审计覆盖范围
- 审计内容（用户创建/删除、权限变更等）
- 审计记录保护
- 审计记录保存6个月以上
- 防止审计中断

**入侵防范**
- 检测入侵行为
- 检测系统完整性
- 重要节点部署入侵检测

**恶意代码防范**
- 安装防病毒软件
- 策略统一管理

**可信验证**
- 基于可信根对系统进行可信验证

**数据完整性**
- 数据传输和存储的完整性校验

**数据保密性**
- 数据传输和存储的加密保护

**数据备份恢复**
- 数据本地备份与恢复
- 数据异地备份与恢复
- 数据处理系统热冗余

**剩余信息保护**
- 鉴别信息存储空间释放前清除
- 存储空间分配前清除

**个人信息保护**
- 个人信息收集最小化
- 个人信息访问控制
- 个人信息脱敏与匿名化

### 1.4 测评报告模板

**单项测评结果判定**
```
判定标准:
- 符合：完全满足要求
- 部分符合：部分满足要求
- 不符合：不满足要求
- 不适用：该要求不适用于被测系统

风险分析:
- 高风险：系统面临严重安全威胁
- 中风险：系统面临中等安全威胁
- 低风险：系统面临轻微安全威胁

整体结论:
- 优：无高风险项，符合率≥90%
- 良：无高风险项，符合率≥80%
- 中：无高风险项，符合率≥70%
- 差：有高风险项或符合率<70%
```

## 三、GRC平台实践

### 3.1 GRC概念

**GRC = Governance + Risk + Compliance**
- Governance（治理）：组织治理结构、策略、方针
- Risk（风险）：风险管理框架与流程
- Compliance（合规）：法律法规与标准合规

**GRC平台核心功能**
- 策略管理：安全策略生命周期管理
- 风险管理：风险识别、评估、处置、跟踪
- 合规管理：合规框架映射、控制评估、审计
- 审计管理：内部审计、外部审计、审计跟踪
- 事件管理：安全事件记录与跟踪
- 供应商管理：第三方风险评估
- 培训管理：安全意识培训跟踪

### 3.2 主流GRC平台

| 平台 | 特点 | 适用场景 |
|------|------|---------|
| ServiceNow GRC | 集成ITSM，企业级 | 大型企业 |
| RSA Archer | 功能全面，可定制 | 大型企业 |
| MetricStream | 模块化，云端 | 中大型企业 |
| OneTrust | 隐私合规突出 | 有隐私合规需求企业 |
| AuditBoard | 审计为核心 | 审计部门 |
| 自研GRC | 定制化 | 特殊需求企业 |

### 3.3 GRC平台实施实践

**实施步骤**
```
1. 需求分析
   ├── 梳理合规要求（等保、ISO27001、GDPR等）
   ├── 梳理风险管理流程
   ├── 梳理审计需求
   └── 确定用户角色

2. 框架搭建
   ├── 导入合规框架（控制矩阵）
   ├── 配置风险评估模型
   ├── 配置审批流程
   ├── 配置报表与仪表盘
   └── 集成数据源（SIEM、资产库等）

3. 试点运行
   ├── 选择一个业务线试点
   ├── 导入风险数据
   ├── 执行风险评估
   ├── 执行合规评估
   └── 收集反馈

4. 全面推广
   ├── 扩展到全组织
   ├── 集成更多数据源
   ├── 建立运营流程
   └── 持续优化
```

## 四、其他合规框架

### 4.1 NIST CSF（网络安全框架）

**核心功能**
1. 识别（Identify）
2. 保护（Protect）
3. 检测（Detect）
4. 响应（Respond）
5. 恢复（Recover）

**NIST CSF 2.0新增**
- 治理（Govern）作为第六大功能

### 4.2 SOC 2

**SOC 2信任服务标准**
- 安全（Security）
- 可用性（Availability）
- 处理完整性（Processing Integrity）
- 保密性（Confidentiality）
- 隐私（Privacy）

**SOC 2报告类型**
- Type I：特定时间点控制设计有效性
- Type II：一段时间内控制运行有效性

### 4.3 COBIT

**COBIT 2019核心**
- 治理目标和管理目标
- 40个治理和管理目标
- 设计因素和目标层级

### 4.4 GDPR合规

**GDPR核心要求**
- 数据处理的合法性基础
- 数据主体权利（访问、更正、删除、限制处理、数据可携带性、反对）
- 数据保护影响评估（DPIA）
- 数据泄露通知（72小时内）
- 数据保护官（DPO）
- 跨境数据传输

### 4.5 个人信息保护法（PIPL）

**PIPL核心要求**
- 处理个人信息的原则（合法、正当、必要）
- 告知-同意机制
- 敏感个人信息处理规则
- 个人信息跨境提供
- 个人信息主体权利
- 个人信息处理者义务

## 五、合规自动化实践

### 5.1 自动化合规检查工具

**CSPM（云安全态势管理）**
- 自动扫描云环境配置
- 对标合规框架
- 识别配置偏差
- 自动修复建议

# AWS合规规则示例：检测公开的S3桶
import json
import boto3

def check_s3_public_access():
    """检查S3存储桶是否公开可访问"""
    s3 = boto3.client('s3')
    buckets = s3.list_buckets()
    违规列表 = []

    for bucket in buckets['Buckets']:
        name = bucket['Name']
        acl = s3.get_bucket_acl(Bucket=name)
        for grant in acl['Grants']:
            if grant['Grantee'].get('URI') == 'http://acs.amazonaws.com/groups/global/AllUsers':
                违规列表.append({
                    "存储桶": name,
                    "违规": "公开可读",
                    "权限": grant['Permission']
                })

    return 违规列表

def check_iam_mfa():
    """检查IAM用户是否启用MFA"""
    iam = boto3.client('iam')
    users = iam.list_users()
    违规列表 = []

    for user in users['Users']:
        mfa = iam.list_mfa_devices(UserName=user['UserName'])
        if not mfa['MFADevices']:
            违规列表.append({
                "用户": user['UserName'],
                "违规": "未启用MFA"
            })

    return 违规列表
