# 等保2.0测评流程详解

### 7.1 定级阶段

**定级对象确定**
- 信息系统整体定级
- 信息系统主要子系统分别定级
- 大型信息系统按业务或功能拆分后分别定级

**定级要素分析**

| 受侵害客体 | 侵害程度 | 安全保护等级 |
|------------|---------|-------------|
| 公民、法人合法权益 | 损害 | 第一级 |
| 公民、法人合法权益 | 严重损害 | 第二级 |
| 社会秩序、公共利益 | 损害 | 第二级 |
| 社会秩序、公共利益 | 严重损害 | 第三级 |
| 国家安全 | 损害 | 第三级 |
| 国家安全 | 严重损害 | 第四级 |
| 国家安全 | 特别严重损害 | 第五级 |

**定级报告模板**
```
一、定级对象描述
   1. 信息系统名称
   2. 信息系统描述（功能、结构、边界）
   3. 信息系统主要硬件资产清单

二、定级对象分析
   1. 业务信息安全性分析
   2. 业务服务保证性分析

三、定级要素分析
   1. 受侵害的客体分析
   2. 对客体的侵害程度分析

四、定级结论
   1. 信息系统安全保护等级
   2. 定级理由说明
```

### 7.2 备案阶段

**备案流程**
```
1. 准备备案材料
   ├── 定级报告（加盖公章）
   ├── 信息系统备案表
   ├── 信息系统拓扑图
   └── 安全组织架构说明

2. 提交备案
   ├── 向所在地设区的市级公安机关备案
   ├── 三级以上系统向省级公安机关备案
   └── 提交电子版和纸质版材料

3. 公安机关审核
   ├── 审核定级准确性
   ├── 审核材料完整性
   └── 发放备案证明

4. 备案变更
   ├── 系统变更后10个工作日内变更备案
   ├── 系统废止后30日内注销备案
   └── 每年至少一次备案信息核查
```

### 7.3 建设整改阶段

**差距分析**
```
整改工作流程:
1. 对照等保标准逐项检查
   ├── 技术要求（物理/通信网络/区域边界/计算环境/管理中心）
   └── 管理要求（制度/机构/人员/建设/运维）

2. 编制差距分析报告
   ├── 符合项清单
   ├── 不符合项清单（需整改）
   ├── 部分符合项清单（需完善）
   └── 不适用项说明

3. 制定整改方案
   ├── 整改目标与范围
   ├── 整改措施（技术+管理）
   ├── 整改预算与资源
   ├── 整改时间表
   └── 责任人分工
```

**常见整改措施**

| 不符合项 | 整改措施 | 预算参考 |
|---------|---------|---------|
| 缺少安全审计 | 部署日志审计系统/SIEM | 10-50万 |
| 无入侵检测 | 部署IDS/IPS或NDR | 5-30万 |
| 未加密传输 | 部署VPN/启用HTTPS/TLS | 1-10万 |
| 无访问控制 | 部署堡垒机/4A系统 | 10-50万 |
| 缺少备份 | 建设异地灾备中心 | 50-200万 |
| 无安全管理中心 | 建设集中安全运营平台 | 30-100万 |

### 7.5 维护阶段

**持续运维要求**
- 每年至少进行一次等级测评（三级以上系统）
- 安全事件发生时及时报告和处置
- 系统重大变更后重新评估
- 定期进行安全检查和渗透测试
- 持续跟踪和修复漏洞
