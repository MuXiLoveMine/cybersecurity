# 蓝队防御与检测

### 4.1 日志采集体系

#### 4.1.1 Windows 日志

**关键日志源**
- 安全日志（Event ID）
  - 4624: 成功登录
  - 4625: 登录失败
  - 4634: 注销
  - 4648: 显式凭据登录
  - 4661: SAM 对象操作
  - 4672: 特权登录
  - 4688: 进程创建
  - 4720: 用户账户创建
  - 4726: 用户账户删除
  - 4732: 成员添加到安全组
  - 4776: NTLM 认证
  - 4771: Kerberos 预认证失败
  - 4779: 会话断开
  - 4798: 用户本地组枚举

**Sysmon 配置**
```xml
<Sysmon schemaversion="4.82">
  <HashAlgorithms>SHA256</HashAlgorithms>
  <EventFiltering>
    <!-- 进程创建 -->
    <ProcessCreate onmatch="include">
      <CommandLine condition="contains">powershell</CommandLine>
      <CommandLine condition="contains">cmd.exe</CommandLine>
      <CommandLine condition="contains">mimikatz</CommandLine>
    </ProcessCreate>

    <!-- 网络连接 -->
    <NetworkConnect onmatch="include">
      <DestinationPort condition="is">4444</DestinationPort>
      <DestinationPort condition="is">8443</DestinationPort>
    </NetworkConnect>

    <!-- 文件创建 -->
    <FileCreate onmatch="include">
      <TargetFilename condition="contains">.exe</TargetFilename>
      <TargetFilename condition="contains">.dll</TargetFilename>
    </FileCreate>

    <!-- 注册表修改 -->
    <RegistryEvent onmatch="include">
      <TargetObject condition="contains">Run</TargetObject>
      <TargetObject condition="contains">RunOnce</TargetObject>
    </RegistryEvent>
  </EventFiltering>
</Sysmon>
```

#### 4.1.2 Linux 日志

**关键日志源**
- /var/log/auth.log: 认证日志
- /var/log/syslog: 系统日志
- /var/log/audit/audit.log: 审计日志
- ~/.bash_history: 命令历史
- /var/log/secure: 安全日志

**auditd 配置**
```
# /etc/audit/rules.d/audit.rules
-w /etc/passwd -p wa -k identity
-w /etc/shadow -p wa -k identity
-w /etc/sudoers -p wa -k identity
-w /bin/su -p x -k privileged
-w /usr/bin/sudo -p x -k privileged
-a always,exit -F arch=b64 -S execve -F auid>=1000 -F auid!=4294967295 -k exec
-a always,exit -F arch=b64 -S ptrace -k tracing
```

### 4.2 检测规则

#### 4.2.1 Sigma 规则

**Sigma 规则示例：检测 Mimikatz**
```yaml
title: Detect Mimikatz
status: experimental
description: Detects Mimikatz LSASS dump activity
author: Security Team
logsource:
    product: windows
    service: security
detection:
    selection:
        EventID: 4663
        ObjectType: 'SC_MANAGER'
        AccessMask: '0x2'
    condition: selection
falsepositives:
    - Legitimate service installation
level: high
```

**Sigma 规则示例：检测 Pass the Hash**
```yaml
title: Detect Pass the Hash
status: experimental
description: Detects Pass the Hash attack
logsource:
    product: windows
    service: security
detection:
    selection:
        EventID: 4624
        LogonType: 3
        AuthenticationPackageName: 'NTLM'
        WorkstationName: null
    condition: selection
falsepositives:
    - Legacy systems using NTLM
level: medium
```

#### 4.2.2 YARA 规则

**YARA 规则示例：检测恶意文档**
```yara
rule Malicious_Document_Macro
{
    meta:
        description = "Detects malicious macro documents"
        author = "Security Team"
    strings:
        $auto_open = "Auto_Open" ascii
        $shell = "Shell" ascii
        $wscript = "WScript.Shell" ascii
        $powershell = "powershell" ascii nocase
        $cmd = "cmd.exe" ascii nocase
        $base64 = "FromBase64String" ascii
    condition:
        3 of ($auto_open, $shell, $wscript, $powershell, $cmd, $base64)
}
```

### 4.3 威胁狩猎

#### 4.3.1 基于 ATT&CK 的威胁狩猎

**狩猎方法论**
```
1. 选择 ATT&CK 技术
   - 优先选择高频出现的技术
   - 优先选择对业务影响大的技术

2. 分析数据需求
   - 哪些日志源能检测该技术
   - 日志是否已采集
   - 是否有检测规则

3. 构建假设
   - "攻击者可能使用 PowerShell 执行恶意代码"
   - "攻击者可能通过 Kerberoasting 获取服务账户凭据"

4. 数据查询
   - 在 SIEM 中编写查询语句
   - 分析异常模式

5. 验证与响应
   - 验证发现的异常是否为攻击
   - 如果确认攻击，启动响应流程
```

#### 4.3.2 常见威胁狩猎场景

**场景1: 检测异常 PowerShell 执行**
```sql
-- Splunk SPL 查询
index=windows source="*WinEventLog:Microsoft-Windows-PowerShell*"
(EventCode=4104 OR EventCode=4103)
| eval is_encoded=if(match(Message, "FromBase64String"), 1, 0)
| eval is_download=if(match(Message, "Net\.WebClient|DownloadString|Invoke-WebRequest"), 1, 0)
| eval is_exec=if(match(Message, "Invoke-Expression|IEX|Invoke-Command"), 1, 0)
| where is_encoded=1 OR is_download=1 OR is_exec=1
| stats count by host, user, Message
```

**场景2: 检测横向移动**
```sql
-- 检测 4624 类型 3（网络登录）+ 异常源
index=windows EventCode=4624 LogonType=3
| stats count as login_count by src_host, dest_host, user
| where login_count > 10
| sort -login_count
```

**场景3: 检测 Kerberoasting**
```sql
-- 检测 TGS 请求异常
index=windows EventCode=4769
| stats count as req_count by user, service, src_ip
| where req_count > 50
| sort -req_count
```

### 4.4 蜜罐与欺骗防御

#### 4.4.1 蜜罐部署

**蜜罐类型**
- 系统蜜罐：模拟操作系统
- 服务蜜罐：模拟特定服务（HTTP/SSH/SMB）
- 应用蜜罐：模拟 Web 应用
- 数据蜜罐：虚假数据（蜜标）
- 网络蜜罐：虚拟网络段

**蜜罐部署策略**
- 在内网部署 SMB 蜜罐（检测横向扫描）
- 部署 Web 蜜罐（检测 Web 攻击）
- 部署 SSH 蜜罐（检测爆破）
- 部署 Canary Token（检测文档泄露）
- 部署虚假服务账户（检测 Kerberoasting）

**Canary Token 部署**
```
# 常见 Canary Token 类型
- AWS API Key Token
- Microsoft Word Token
- PDF Token
- SQL Server Token
- Excel Macro Token
- Custom Exe Token
```
