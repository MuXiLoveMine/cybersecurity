# 红蓝对抗演练

> 红蓝对抗是检验组织安全防御体系有效性的实战演练，红队模拟真实攻击者，蓝队进行检测、响应和防御。

---

## 一、红蓝对抗概述

### 1.1 红蓝对抗定义

红蓝对抗（Red Team vs Blue Team Exercise）是一种安全评估方法：
- **红队（Red Team）**：模拟真实攻击者的 TTPs，测试防御体系的检测和响应能力
- **蓝队（Blue Team）**：防御方，负责检测攻击、分析告警、响应处置
- **紫队（Purple Team）**：红蓝协作，红队攻击与蓝队检测同步进行，持续改进

### 1.2 红蓝对抗 vs 渗透测试

| 维度 | 渗透测试 | 红蓝对抗 |
|------|---------|---------|
| 目标 | 发现漏洞 | 检验整体防御能力 |
| 范围 | 特定系统/应用 | 全组织范围 |
| 时间 | 数天-数周 | 数周-数月 |
| 通知 | 通常已知 | 通常不通知蓝队 |
| 防御绕过 | 不涉及 | 核心内容 |
| 检测评估 | 不涉及 | 核心内容 |
| 深度 | 技术漏洞 | 完整攻击链 |

### 1.3 红蓝对抗类型

**按目标分类**
- 驻场红蓝对抗：在客户现场进行
- 远程红蓝对抗：远程进行攻击
- 混合模式：远程+现场结合

**按范围分类**
- 全场景对抗：覆盖人员、物理、网络、应用
- 技术对抗：仅技术攻击
- 桌面推演：推演式对抗，不实际执行攻击

**按通知方式分类**
- 盲测：蓝队不知道红队活动
- 半知：蓝队知道有红队但不知具体时间
- 全知：红蓝双方充分协调

## 二、MITRE ATT&CK 框架

### 2.1 ATT&CK 概述

**ATT&CK 定义**
- MITRE ATT&CK 是一个全球可访问的对抗性战术和技术知识库
- 基于真实观察到的攻击行为
- 包含战术（Tactics）、技术（Techniques）、程序（Procedures）

**ATT&CK 矩阵**
```
1. 侦察 (Reconnaissance)
2. 资源开发 (Resource Development)
3. 初始访问 (Initial Access)
4. 执行 (Execution)
5. 持久化 (Persistence)
6. 权限提升 (Privilege Escalation)
7. 防御绕过 (Defense Evasion)
8. 凭据访问 (Credential Access)
9. 发现 (Discovery)
10. 横向移动 (Lateral Movement)
11. 收集 (Collection)
12. 命令与控制 (Command and Control)
13. 数据外传 (Exfiltration)
14. 影响 (Impact)
```

### 2.2 ATT&CK 在红蓝对抗中的应用

**红队使用 ATT&CK**
- 攻击链设计：选择 ATT&CK 技术点组成攻击链
- TTPs 映射：将攻击行为映射到 ATT&CK 技术
- 覆盖率评估：评估攻击技术多样性

**蓝队使用 ATT&CK**
- 检测覆盖评估：评估每项 ATT&CK 技术的检测能力
- 规则开发：基于 ATT&CK 技术开发检测规则
- 威胁狩猎：基于 ATT&CK 框架进行威胁狩猎
- 差距分析：发现检测覆盖缺口

#### 3.2.2 C2 隐蔽配置

**域名策略**
- 选择与目标行业相关的域名
- 域名年龄大于 1 年
- 分类为新闻/教育/金融等正常分类
- SSL 证书配置
- CDN 代理

**Malleable C2 配置**
```
# Cobalt Strike Malleable C2 示例
http-get {
    set uri "/api/v1/data";

    client {
        metadata {
            base64url
            prepend "session="
            header "Cookie"
        }
    }

    server {
        header "Content-Type" "application/json";
        output {
            base64url
            prepend "{\"data\":\""
            append "\"}"
        }
    }
}

http-post {
    set uri "/api/v1/report";
    set verb "POST";

    client {
        body {
            base64url
            prepend "report="
            append "&format=json"
        }
    }
}
```

**流量伪装策略**
- 使用合法域名作为 C2 域名
- 模拟正常 HTTP 流量特征
- 使用 HTTPS + 合法证书
- CDN 代理隐藏真实 IP
- 域前置（Domain Fronting）
- 多级 C2 信道

**关键日志源**

  - 4720: 用户账户创建
  - 4726: 用户账户删除
  - 4732: 成员添加到安全组
  - 4776: NTLM 认证
  - 4771: Kerberos 预认证失败
  - 4779: 会话断开
  - 4798: 用户本地组枚举

**Sysmon 配置**
```xml
<Sysmon schemaversion="4.82">
  <HashAlgorithms>SHA256</HashAlgorithms>
  <EventFiltering>
    <!-- 进程创建 -->
    <ProcessCreate onmatch="include">
      <CommandLine condition="contains">powershell</CommandLine>
      <CommandLine condition="contains">cmd.exe</CommandLine>
      <CommandLine condition="contains">mimikatz</CommandLine>
    </ProcessCreate>

    <!-- 网络连接 -->
    <NetworkConnect onmatch="include">
      <DestinationPort condition="is">4444</DestinationPort>
      <DestinationPort condition="is">8443</DestinationPort>
    </NetworkConnect>

    <!-- 文件创建 -->
    <FileCreate onmatch="include">
      <TargetFilename condition="contains">.exe</TargetFilename>
      <TargetFilename condition="contains">.dll</TargetFilename>
    </FileCreate>

    <!-- 注册表修改 -->
    <RegistryEvent onmatch="include">
      <TargetObject condition="contains">Run</TargetObject>
      <TargetObject condition="contains">RunOnce</TargetObject>
    </RegistryEvent>
  </EventFiltering>
</Sysmon>
```

#### 4.2.2 YARA 规则

**YARA 规则示例：检测恶意文档**
```yara
rule Malicious_Document_Macro
{
    meta:
        description = "Detects malicious macro documents"
        author = "Security Team"
    strings:
        $auto_open = "Auto_Open" ascii
        $shell = "Shell" ascii
        $wscript = "WScript.Shell" ascii

}
```

### 4.3 威胁狩猎

#### 4.3.1 基于 ATT&CK 的威胁狩猎

**狩猎方法论**
```
1. 选择 ATT&CK 技术
   - 优先选择高频出现的技术
   - 优先选择对业务影响大的技术

2. 分析数据需求
   - 哪些日志源能检测该技术
   - 日志是否已采集
   - 是否有检测规则

3. 构建假设
   - "攻击者可能使用 PowerShell 执行恶意代码"
   - "攻击者可能通过 Kerberoasting 获取服务账户凭据"

4. 数据查询
   - 在 SIEM 中编写查询语句
   - 分析异常模式

5. 验证与响应
   - 验证发现的异常是否为攻击
   - 如果确认攻击，启动响应流程
```

#### 4.3.2 常见威胁狩猎场景

**场景1: 检测异常 PowerShell 执行**
```sql
-- Splunk SPL 查询
index=windows source="*WinEventLog:Microsoft-Windows-PowerShell*"
(EventCode=4104 OR EventCode=4103)
| eval is_encoded=if(match(Message, "FromBase64String"), 1, 0)
| eval is_download=if(match(Message, "Net\.WebClient|DownloadString|Invoke-WebRequest"), 1, 0)
| eval is_exec=if(match(Message, "Invoke-Expression|IEX|Invoke-Command"), 1, 0)
| where is_encoded=1 OR is_download=1 OR is_exec=1
| stats count by host, user, Message
```

**场景2: 检测横向移动**
```sql
-- 检测 4624 类型 3（网络登录）+ 异常源
index=windows EventCode=4624 LogonType=3
| stats count as login_count by src_host, dest_host, user
| where login_count > 10
| sort -login_count
```

**场景3: 检测 Kerberoasting**
```sql
-- 检测 TGS 请求异常
index=windows EventCode=4769
| stats count as req_count by user, service, src_ip
| where req_count > 50
| sort -req_count
```

```python
# 持续红队测试编排示例
class ContinuousRedTeam:
    def __init__(self):
        self.attack_techniques = self.load_attack_library()
        self.detection_results = {}
    
    def load_attack_library(self):
        """加载ATT&CK技术测试库"""
        return {
            "T1566.001": {"name": "鱼叉钓鱼附件", "automation": "manual"},
            "T1059.001": {"name": "PowerShell执行", "automation": "atomic"},
            "T1003.001": {"name": "LSASS内存转储", "automation": "atomic"},
            "T1550.002": {"name": "Pass the Hash", "automation": "script"},
            "T1071.001": {"name": "Web C2通信", "automation": "script"},
            "T1053.005": {"name": "计划任务", "automation": "atomic"},
            "T1547.001": {"name": "注册表Run键", "automation": "atomic"},
            "T1110.001": {"name": "密码爆破", "automation": "script"},
        }
    
    def execute_test(self, technique_id):
        """执行单项ATT&CK技术测试"""
        tech = self.attack_techniques[technique_id]
        print(f"[CRT] 执行测试: {technique_id} - {tech['name']}")
        
        # 记录开始时间
        start_time = datetime.now()
        
        # 执行攻击模拟
        attack_result = self.run_attack(technique_id)
        
        # 等待检测窗口（如5分钟）
        time.sleep(300)
        
        # 检查SIEM/EDR是否产生告警
        detection_result = self.check_detection(technique_id, start_time)
        
        # 记录结果
        self.detection_results[technique_id] = {
            "attack_time": start_time,
            "attack_success": attack_result,
            "detected": detection_result["detected"],
            "detection_delay": detection_result.get("delay_seconds", 0),
            "alert_source": detection_result.get("source", ""),
            "response_action": detection_result.get("response", ""),
        }
        
        return self.detection_results[technique_id]
    
    def generate_report(self):
        """生成持续评估报告"""
        total = len(self.detection_results)
        detected = sum(1 for r in self.detection_results.values() if r["detected"])
        avg_delay = np.mean([r["detection_delay"] for r in self.detection_results.values() if r["detected"]])
        
        report = {
            "total_tests": total,
            "detected_count": detected,
            "coverage_rate": f"{detected}/{total} ({detected/total*100:.1f}%)",
            "avg_detection_delay": f"{avg_delay:.1f}秒",
            "gaps": [tid for tid, r in self.detection_results.items() if not r["detected"]],
        }
        return report

# 运行CRT
crt = ContinuousRedTeam()
```
