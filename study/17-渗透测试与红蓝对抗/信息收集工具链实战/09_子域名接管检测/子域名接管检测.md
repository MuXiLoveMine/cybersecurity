# 子域名接管检测

### 9.1 子域名接管原理

子域名接管（Subdomain Takeover）是指当子域名指向的外部服务已被删除，但DNS的CNAME记录未清理时，攻击者可以在该外部服务上注册自己的账户并接管该子域名。

```text
子域名接管风险等级:

  高危: 云服务CNAME失效 (AWS S3 / GitHub Pages / Heroku)
  中危: 自定义服务CNAME失效
  低危: A记录指向失效IP

常见可被接管的云服务:
  ├── AWS S3 Bucket        -> s3.amazonaws.com
  ├── GitHub Pages         -> github.io
  ├── Heroku               -> herokuapp.com
  ├── Azure                -> azurewebsites.net
  ├── Tumblr               -> tumblr.com
  ├── Shopify              -> myshopify.com
  ├── Tumblr              -> tumblr.com
  └── WordPress.com        -> wordpress.com
```

### 9.2 subjack - 子域名接管扫描

```bash
# subjack - 子域名接管检测工具
# 安装
go install github.com/haccer/subjack@latest

# 基本扫描
subjack -w subdomains.txt -t 50 -timeout 30

# 输出到文件
subjack -w subdomains.txt -o results.txt

# 使用HTTPS
subjack -w subdomains.txt -ssl

# 指定指纹文件(自定义服务)
subjack -w subdomains.txt -c fingerprints.json

# 手动验证
# 1. 检查CNAME记录
dig CNAME sub.example.com

# 2. 检查返回内容
curl -s http://sub.example.com | grep -i "nosuchbucket\|not found\|no such app"

# 3. 在对应云服务上注册接管
# AWS S3: aws s3api create-bucket --bucket sub-example-com
# GitHub Pages: 在GitHub创建同名仓库
```

### 9.3 nuclei子域名接管模板

```bash
# nuclei - 使用模板检测子域名接管
nuclei -l subdomains.txt -t takeovers/

# 常用接管检测模板
nuclei -l subdomains.txt -t http/cves/ -t http/takeovers/

# 自定义接管检测
nuclei -l subdomains.txt -t custom-takeover.yaml

# 自定义接管检测模板示例
cat > custom-takeover.yaml << 'EOF'
id: custom-s3-takeover

info:
  name: S3 Bucket Takeover
  author: security
  severity: high

requests:
  - method: GET
    path:
      - "{{BaseURL}}"
    matchers:
      - type: word
        words:
          - "NoSuchBucket"
          - "The specified bucket does not exist"
        condition: or
EOF
```
