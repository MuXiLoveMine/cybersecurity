# 车载网关安全

### 5.1 中央网关架构

现代车辆采用中央网关（Central Gateway）作为各域控制器之间的通信枢纽，实现域间隔离与路由控制：

```
车辆网络拓扑（中央网关架构）：

  信息娱乐域                  动力域                    底盘域
  ┌──────────┐              ┌──────────┐              ┌──────────┐
  │ IVI MCU  │              │ Powertrain│              │ Chassis  │
  │ Head Unit│              │   ECU    │              │   ECU    │
  └─────┬────┘              └─────┬────┘              └─────┬────┘
        │ CAN-A                    │ CAN-B                   │ CAN-C
        │                           │                          │
  ┌─────┴───────────────────────────┴──────────────────────────┴────┐
  │                    中央网关 (Central Gateway)                      │
  │  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌───────────────┐   │
  │  │ 路由引擎  │  │防火墙规则│  │ 诊断代理  │  │  IDS/IPS 引擎  │   │
  │  │Routing   │  │ Firewall │  │ Diag Proxy│  │  Intrusion   │   │
  │  └──────────┘  └──────────┘  └──────────┘  └───────────────┘   │
  └──────────────────────────┬──────────────────────────────────────┘
                             │ 车载以太网
                    ┌────────┴────────┐
                    │   OBD-II 接口     │
                    │  诊断/外部接入    │
                    └─────────────────┘
```

### 5.2 路由规则

网关路由引擎基于预定义的规则表控制帧在不同总线间的转发：

```
路由规则表示例：

规则ID | 源总线 | 源CAN ID | 目标总线 | 目标CAN ID | 方向     | 安全级别
-------|--------|----------|----------|-----------|----------|--------
R001   | CAN-A  | 0x100    | CAN-B    | 0x200     | 单向     | 高
R002   | CAN-B  | 0x201    | CAN-A    | 0x101     | 单向     | 高
R003   | OBD    | 0x7DF    | CAN-B    | 0x7E0     | 双向     | 诊断
R004   | CAN-A  | *        | CAN-C    | *         | 禁止     | -
R005   | CAN-C  | 0x300    | CAN-A    | 0x102     | 单向     | 中
```

**关键路由安全原则：**
1. **默认拒绝**：未在路由表中定义的帧一律不转发
2. **最小权限**：仅允许必要的跨域通信
3. **诊断隔离**：OBD 诊断必须通过诊断代理过滤后转发
4. **安全域与非安全域隔离**：信息娱乐域不得直接访问制动域

### 5.3 网关防火墙

车载网关防火墙在 CAN 帧和 IP 包层面实施访问控制：

```c
// 网关防火墙规则引擎示例
typedef enum {
    ACTION_ALLOW = 0,
    ACTION_DENY  = 1,
    ACTION_LOG   = 2,
    ACTION_RATE_LIMIT = 3
} firewall_action_t;

typedef struct {
    uint8_t  src_bus;        // 源总线 ID
    uint16_t src_can_id;     // 源 CAN ID
    uint8_t  src_can_id_mask; // CAN ID 掩码
    uint8_t  dst_bus;        // 目标总线 ID
    uint16_t dst_can_id;     // 目标 CAN ID
    uint8_t  direction;      // 0=单向, 1=双向
    firewall_action_t action;
    uint32_t rate_limit;     // 速率限制 (帧/秒)
    uint8_t  security_level; // 安全级别
} firewall_rule_t;

firewall_rule_t firewall_rules[] = {
    // 动力域 → 信息娱乐域：仅允许状态信息
    {BUS_CAN_B, 0x201, 0x7FF, BUS_CAN_A, 0x101, 0, ACTION_ALLOW, 10, 2},

    // OBD 诊断 → 动力域：允许但限速
    {BUS_OBD, 0x7DF, 0x7FF, BUS_CAN_B, 0x7E0, 1, ACTION_RATE_LIMIT, 5, 3},

    // 信息娱乐域 → 底盘域：禁止！
    {BUS_CAN_A, 0x000, 0x000, BUS_CAN_C, 0x000, 0, ACTION_DENY, 0, 0},

    // 外部以太网 → 内部 CAN：默认拒绝
    {BUS_ETH_EXT, 0x0000, 0x0000, BUS_CAN_B, 0x0000, 0, ACTION_DENY, 0, 0},
};

int process_can_frame(can_frame_t *frame, uint8_t src_bus) {
    for (int i = 0; i < ARRAY_SIZE(firewall_rules); i++) {
        firewall_rule_t *rule = &firewall_rules[i];
        if (rule->src_bus != src_bus) continue;
        if ((frame->id & rule->src_can_id_mask) != (rule->src_can_id & rule->src_can_id_mask))
            continue;

        switch (rule->action) {
            case ACTION_ALLOW:
                forward_frame(frame, rule->dst_bus, rule->dst_can_id);
                break;
            case ACTION_DENY:
                log_security_event("DENY", frame, src_bus);
                return -1;
            case ACTION_RATE_LIMIT:
                if (!rate_limit_check(rule->rate_limit)) {
                    log_security_event("RATE_LIMIT_EXCEEDED", frame, src_bus);
                    return -1;
                }
                forward_frame(frame, rule->dst_bus, rule->dst_can_id);
                break;
            case ACTION_LOG:
                log_traffic(frame, src_bus);
                break;
        }
    }
    return 0;
}
```
