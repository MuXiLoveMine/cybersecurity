# 功能安全与信息安全融合

### 8.1 ISO 26262 与 ISO 21434 的关系

ISO 26262 是道路车辆功能安全标准，关注由**系统故障**引起的危害；ISO 21434 关注由**恶意攻击**引起的危害。两者在以下方面需要协同：

```
ISO 26262 (功能安全)           ISO 21434 (网络安全)
├── 关注：随机硬件故障          ├── 关注：恶意攻击
├── 目标：避免人身伤害          ├── 目标：避免安全威胁
├── 方法：HARA (危害分析)       ├── 方法：TARA (威胁分析)
├── ASIL 分级 (A-D)            ├── 风险分级 (1-5)
├── 安全需求                   ├── 网络安全需求
└── 安全验证                   └── 网络安全验证

协同需求：
  - 信息安全措施不得影响功能安全（安全降级原则）
  - 功能安全措施不得引入新的网络安全漏洞
  - 共享的安全/安全需求需联合评审
```

### 8.2 融合实践要点

```
融合框架示例（制动系统安全+安全协同）：

功能安全层面 (ISO 26262)：
  ASIL D 制动控制
  ├── 安全需求: 制动指令必须有 ECU 内部冗余校验
  ├── 安全需求: 检测到传感器异常时安全降级
  └── 安全需求: 看门狗超时后进入安全状态

网络安全层面 (ISO 21434)：
  ├── 安全需求: 制动指令 CAN 帧必须经过认证
  ├── 安全需求: 检测到异常 CAN 帧时阻断并告警
  └── 安全需求: OBD 接口速率限制

冲突解决：
  ├── 场景：IDS 检测到攻击后断开 CAN 总线
  ├── 安全影响：制动指令无法传输 → 危险！
  ├── 融合方案：IDS 阻断攻击帧但保持安全关键帧通信
  └── 降级策略：进入安全限速模式而非完全断开
```

**融合设计检查清单：**

| 检查项                                      | ISO 26262 | ISO 21434 | 融合要求              |
|---------------------------------------------|----------|-----------|----------------------|
| 安全措施的失效模式是否引入安全漏洞            | -        | 需检查     | 安全措施不得影响安全  |
| 网络安全措施是否影响安全功能                  | 需检查   | -         | 安全降级优先          |
| OTA 更新是否影响 ASIL 功能                   | 需检查   | 需检查     | 联合评审              |
| 诊断功能是否可用于绕过安全功能               | 需检查   | 需检查     | 诊断访问控制          |
| IDS 触发后的系统行为是否符合安全目标          | 需检查   | 需检查     | 安全状态定义          |
