### 2.1 用户角色与权限模型

车云平台涉及多种用户角色，需要精细化的权限管理。

```text

角色层级:
┌────────────────────────────────────────────────────────┐

├────────────────────────────────────────────────────────┤

│ → 车辆管理、OTA发布、批量操作、数据分析                   │
├────────────────────────────────────────────────────────┤

│ → 车辆激活、诊断、局部数据访问                           │
├────────────────────────────────────────────────────────┤
│ 车主 (Vehicle Owner)                                   │
│ → 查看自己车辆状态、远程控制、设置                       │
```

### 2.2 多租户隔离机制

车云平台通常服务于多个OEM（整车厂）或多个业务线，需要严格的租户隔离。

```text
多租户隔离模型

┌──────────────────────────────────────────────────────────┐
│                    共享平台基础设施                        │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐ │
│  │   租户A       │  │   租户B       │  │   租户C       │ │
│  │  (OEM-X)     │  │  (OEM-Y)     │  │  (OEM-Z)     │ │
│  │              │  │              │  │              │ │
│  │  车辆数据     │  │  车辆数据     │  │  车辆数据     │ │
│  │  用户数据     │  │  用户数据     │  │  用户数据     │ │
│  │  OTA数据     │  │  OTA数据     │  │  OTA数据     │ │
│  └──────────────┘  └──────────────┘  └──────────────┘ │
└──────────────────────────────────────────────────────────┘

隔离维度:
├── 计算隔离: 独立容器/虚拟机
├── 存储隔离: 数据库Schema隔离或行级隔离
├── 网络隔离: 虚拟网络/VPC隔离
├── 密钥隔离: 每租户独立密钥
├── API隔离: 租户级API路由
└── 日志隔离: 租户级日志分区
```

**租户隔离实现：**

```python
class TenantIsolation:
    """多租户隔离管理"""

    def __init__(self):
        self.tenant_configs = {}
        self.tenant_keys = {}  # 租户级加密密钥

    def register_tenant(self, tenant_id, config):
        """注册租户"""
        self.tenant_configs[tenant_id] = config
        # 为租户生成独立密钥
        self.tenant_keys[tenant_id] = self._generate_tenant_key()

    def get_tenant_context(self, tenant_id, user_id):
        """获取租户上下文"""
        if tenant_id not in self.tenant_configs:
            raise ValueError(f"未知租户: {tenant_id}")

        return {
            'tenant_id': tenant_id,
            'encryption_key': self.tenant_keys[tenant_id],
            'db_schema': f'tenant_{tenant_id}',
            'storage_prefix': f'tenant-{tenant_id}/',
            'allowed_apis': self.tenant_configs[tenant_id].get('allowed_apis', [])
        }

    def verify_data_access(self, tenant_id, vehicle_id):
        """验证租户是否有权访问特定车辆数据"""
        tenant_config = self.tenant_configs.get(tenant_id, {})
        allowed_vehicle_prefix = tenant_config.get('vehicle_prefix', '')

        if not vehicle_id.startswith(allowed_vehicle_prefix):
            raise PermissionError(
                f"租户{tenant_id}无权访问车辆{vehicle_id}"
            )

    @staticmethod
    def _generate_tenant_key():
        import os
        return os.urandom(32)


# 数据库行级隔离示例
TENANT_FILTER_SQL = """
-- PostgreSQL RLS (Row Level Security) 策略
-- 确保租户只能访问自己的数据

CREATE POLICY tenant_isolation ON vehicle_data
    USING (tenant_id = current_setting('app.current_tenant')::uuid);

-- 应用层设置当前租户
SET app.current_tenant = 'tenant_001';

-- 查询自动过滤
SELECT * FROM vehicle_data;
-- 只返回 tenant_id = 'tenant_001' 的数据
"""
```

### 2.3 用户认证流程

```text
用户认证流程

1. 用户注册
   用户 → 平台: 提交注册信息
   平台: 验证信息 → 创建用户 → 发送验证链接
   用户: 验证邮箱/手机

2. 用户登录
   用户 → 平台: 提交凭据（用户名+密码）
   平台: 验证密码哈希 → 生成JWT → 返回Token
   用户: 存储Token → 后续请求携带Token

3. 车辆-用户绑定
   用户 → 平台: 提交VIN码和验证码
   平台: 验证VIN → 检查绑定状态 → 创建绑定关系
   用户: 获得车辆操作权限

4. 多因素认证（高敏感操作）
   远程开锁 → 需要密码 + 短信验证码
   OTA发布 → 需要密码 + 硬件令牌
   系统配置 → 需要密码 + 生物认证
```
