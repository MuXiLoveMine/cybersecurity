### 7.2 API安全测试

#### 7.2.1 API发现

**方法：**
- 反编译移动App，提取API接口
- 抓包分析App与服务端的通信
- 分析T-Box固件中的API地址
- 字典爆破API路径
- GitHub等代码托管平台搜索

**常见API端点：**
```
/api/v1/user/login          # 用户登录
/api/v1/vehicle/list        # 车辆列表
/api/v1/vehicle/control     # 车辆控制
/api/v1/vehicle/status      # 车辆状态
/api/v1/ota/check           # OTA检查
/api/v1/device/register     # 设备注册
```

#### 7.2.2 常见API安全漏洞

| 漏洞类型 | 说明 | 危害 |
|---------|------|------|
| 越权访问 | 可访问/控制其他用户的车辆 | 严重 |
| 未授权访问 | 无需认证即可访问敏感接口 | 严重 |
| 弱口令 | 默认密码、简单密码 | 高 |
| 注入攻击 | SQL注入、命令注入 | 高 |
| 敏感信息泄露 | 错误信息泄露、调试信息 | 中 |
| 重放攻击 | 请求可被重放 | 中高 |
| 速率限制缺失 | 可暴力破解、短信轰炸 | 中 |
| JWT漏洞 | 密钥泄露、算法混淆 | 高 |

#### 7.2.3 越权测试示例

```
# 测试水平越权
正常请求：
GET /api/v1/vehicle/status?vin=LBV1Z3101KM123456
Authorization: Bearer <userA_token>

越权测试：
GET /api/v1/vehicle/status?vin=LBV1Z3101KM654321  (其他用户的VIN)
Authorization: Bearer <userA_token>

如果返回了其他车辆的状态信息 → 存在水平越权
```

### 7.3 设备身份安全

#### 7.3.1 设备认证机制

车联网平台需要认证接入的T-Box设备身份：
- **设备证书**：每台设备一个唯一证书
- **设备密钥**：设备出厂时烧录的密钥
- **IMEI/ICCID**：使用设备标识作为身份

#### 7.3.2 常见问题

- **设备密钥硬编码**：固件中可提取密钥
- **设备身份可伪造**：无强认证机制
- **设备注册漏洞**：可注册虚假设备
- **一机多密**：密钥泄露后可批量伪造

### 7.4 OTA平台安全

#### 7.4.1 攻击面

- **固件篡改**：篡改OTA升级包
- **降级攻击**：推送旧版本（有已知漏洞）
- **恶意固件**：植入后门的固件
- **升级包泄露**：升级包未加密，可被下载分析
- **拒绝服务**：恶意升级使车辆变砖

#### 7.4.2 安全测试要点

1. **固件签名验证**：设备端是否验证固件签名
2. **完整性校验**：是否校验固件完整性
3. **版本管理**：是否允许降级安装
4. **传输安全**：升级包是否加密传输
5. **差分升级安全**：差分包是否可被篡改

### 7.5 数据安全测试

#### 7.5.1 敏感数据类型

- **个人信息**：姓名、手机号、身份证号
- **车辆数据**：VIN码、车牌、车辆配置
- **位置数据**：实时位置、行驶轨迹
- **驾驶行为**：车速、加速度、驾驶习惯
- **车内数据**：语音录音、摄像头画面
- **支付数据**：支付账号、交易记录

#### 7.5.2 测试要点

- 数据传输是否加密
- 数据存储是否加密
- 是否存在数据泄露接口
- 数据脱敏是否到位
- 日志中是否包含敏感数据
- 是否符合数据安全法规要求
