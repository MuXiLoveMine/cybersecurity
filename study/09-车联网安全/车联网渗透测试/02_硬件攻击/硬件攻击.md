# 硬件攻击

### 2.1 硬件攻击概述

硬件攻击是车联网渗透测试的重要组成部分，通过物理接触获取系统访问权限或提取敏感信息。

**常见硬件攻击目标：**
- OBD-II接口
- USB接口
- ECU芯片
- T-Box
- IVI系统
- 调试接口

### 2.2 OBD-II接口攻击

#### 2.2.1 接口探测

**步骤：**
1. 找到OBD-II接口位置（通常在驾驶位下方）
2. 使用万用表测量针脚电压，确定CAN_H（6脚）和CAN_L（14脚）
3. 连接CAN适配器，监听总线流量

**工具：**
- USB-CAN适配器（PCAN、USB2CAN、CANable等）
- 万用表
- OBD公头转接线

#### 2.2.2 总线嗅探

```bash
# Linux下使用can-utils
sudo ip link set can0 type can bitrate 500000
sudo ip link set can0 up
candump can0
```

**分析内容：**
- 识别总线上活跃的CAN ID
- 记录各ID的发送周期
- 分析数据变化规律
- 识别诊断报文（ID: 0x7xx）

#### 2.2.3 诊断功能探测

**方法：** 发送UDS诊断请求，探测支持的服务。

```
# 探测0x7DF（功能寻址）
发送: 02 10 01 00 00 00 00 00  (默认会话)
响应: 各ECU的响应（0x7E8, 0x7E9等）

# 读取DTC
发送: 03 19 02 0B 00 00 00 00  (读取当前DTC)
```

### 2.3 USB接口攻击

#### 2.3.1 攻击面

- **USB调试模式**：Android车机可能开启ADB调试
- **USB存储**：通过U盘传播恶意软件
- **USB配件模式**：Android Auto / CarPlay 接口
- **固件更新**：通过USB进行固件升级

#### 2.3.2 ADB调试攻击

**条件：** IVI系统开启了USB调试

```bash
# 连接后检查设备
adb devices

# 获取Shell
adb shell

# 查看系统信息
adb shell getprop

# 安装应用
adb install malicious.apk
```

#### 2.3.3 BadUSB攻击

**原理：** 使用可编程USB设备（如Rubber Ducky、BadUSB）模拟键盘输入，自动执行攻击命令。

**攻击场景：**
- 车机系统可通过USB键盘操作
- 自动打开开发者选项
- 自动安装恶意应用

### 2.4 芯片拆解与读取

#### 2.4.1 芯片类型

| 芯片类型 | 用途 | 读取难度 |
|---------|------|---------|
| SPI Flash | 存储固件、配置 | 低 |
| I2C EEPROM | 存储数据、密钥 | 低 |
| MCU内部Flash | 主程序存储 | 中高（可能有读保护） |
| eMMC | 大容量存储（IVI） | 中 |
| NOR Flash | 启动代码存储 | 中 |

#### 2.4.2 芯片读取步骤

```
① 查找芯片
   ↓ 使用芯片丝印信息查找型号和数据手册
② 确认引脚定义
   ↓ 根据数据手册确定引脚（VCC、GND、CLK、DIO等）
③ 连接编程器
   ↓ 使用飞线或测试夹连接编程器
④ 读取固件
   ↓ 使用编程软件读取芯片内容
⑤ 验证完整性
   ↓ 校验和、多次读取比对
```

#### 2.4.3 常用工具

| 工具 | 支持芯片 | 说明 |
|------|---------|------|
| CH341A编程器 | SPI Flash、I2C EEPROM | 廉价，入门首选 |
| TL866II+ | 多种Flash、MCU | 支持芯片多 |
| J-Link | ARM MCU调试 | JTAG/SWD调试 |
| ST-Link | STM32调试 | STM32专用 |
| 逻辑分析仪 | 各种数字信号 | 分析通信协议 |
| 示波器 | 模拟/数字信号 | 信号级分析 |

#### 2.4.4 Flash读保护绕过

很多MCU有读保护（Read Protection）机制，常见的绕过方法：

1. **故障注入攻击（Glitching）**：通过电压或时钟故障使保护机制失效
2. **调试接口利用**：利用调试接口的漏洞
3. **固件更新漏洞**：通过官方更新通道提取固件
4. **物理攻击**：芯片开盖、微探针

### 2.5 调试接口攻击

#### 2.5.1 常见调试接口

| 接口 | 特点 | 识别方法 |
|------|------|---------|
| UART | 串行调试口，最常见 | 找测试点：TX、RX、VCC、GND |
| JTAG | 边界扫描，功能强大 | 找测试点：TCK、TMS、TDI、TDO |
| SWD | ARM调试接口，简化版JTAG | 找测试点：SWDIO、SWCLK |
| SWIM | STM8调试接口 | 找测试点：SWIM |

#### 2.5.2 UART调试口发现

**方法：**
1. 观察PCB上的测试点（Test Point）
2. 查找丝印标识（TX、RX、UART、TXD、RXD等）
3. 用万用表找VCC和GND
4. 用逻辑分析仪观察各测试点的信号
5. 尝试不同波特率连接

**典型波特率：** 9600、19200、38400、57600、115200、921600

**连接工具：** USB转TTL模块（CH340、CP2102、PL2303等）

#### 2.5.3 JTAG/SWD调试

**JTAG接口引脚：**
- TCK（Test Clock）：测试时钟
- TMS（Test Mode Select）：测试模式选择
- TDI（Test Data In）：测试数据输入
- TDO（Test Data Out）：测试数据输出
- TRST（Test Reset）：测试复位（可选）
- GND：地
- VCC：电源

**JTAG调试能力：**
- 读取/修改CPU寄存器
- 读取/修改内存
- 单步执行代码
- 设置断点
- 读取Flash内容
- 烧写固件

### 2.6 硬件攻击防护建议

1. **物理防护**：关键ECU采用防拆设计
2. **调试接口**：量产时禁用调试接口
3. **芯片保护**：启用Flash读保护
4. **固件加密**：Flash中的固件加密存储
5. **安全启动**：验证固件签名后才执行
6. **OBD防护**：增加诊断网关和认证机制
