# 学习要点与思考题

### 10.1 核心知识点总结

1. **方法论**：合法授权、安全第一、信息收集→威胁建模→漏洞挖掘→验证→报告
2. **硬件攻击**：OBD接口、USB接口、芯片读取、调试接口（UART/JTAG）
3. **CAN攻击**：嗅探、重放、注入、DoS、模糊测试，各有不同的检测和防御方法
4. **无线攻击**：蓝牙、Wi-Fi、车钥匙（中继攻击）、4G/5G、V2X
5. **车机攻击**：Android车机（ADB、应用漏洞、提权）、QNX系统
6. **T-Box测试**：硬件拆解、固件分析、通信安全、远程控制
7. **云平台安全**：API安全、设备认证、OTA安全、数据安全
8. **APP安全**：静态分析、动态分析、关联安全、SDK安全

### 10.2 思考题

1. 为什么物理攻击在车联网安全中占有重要地位？物理攻击的门槛真的很高吗？
2. CAN总线重放攻击和注入攻击哪个危害更大？为什么？
3. 中继攻击为什么能破解智能钥匙？UWB为什么能防御中继攻击？
4. T-Box为什么是车联网安全的"兵家必争之地"？攻破T-Box能做什么？
5. 车联网云平台和传统互联网平台的安全测试有什么不同？

#### 阶段3：硬件攻击实战

```bash
# ===== OBD接口攻击 =====
# 1. 连接OBD接口
# 2. 扫描可用CAN ID（被动监听）
candump can0 -t z | awk '{print $3}' | sort -u > can_ids.txt
# 统计活跃ID数量
wc -l can_ids.txt

# 3. OBD-II PID扫描
for pid in $(seq 0 255); do
    pid_hex=$(printf "%02X" $pid)
    echo -n "PID 0x$pid_hex: "
    # 发送模式1PID请求（7DF=功能寻址，01=模式1）
    echo "01 $pid_hex" | isotpsend -s 0x7DF -d 0x7E8 can0 2>/dev/null
    sleep 0.1
done

# ===== 硬件调试接口发现 =====
# 1. 拆解设备，寻找调试接口
# 2. 使用万用表确认引脚（VCC/GND/TX/RX）
# 3. UART接口探测（使用FTDI）
# 尝试多种波特率
for baud in 9600 19200 38400 57600 115200 230400 460800 921600; do
    echo "尝试波特率: $baud"
    screen /dev/ttyUSB0 $baud
    # 观察是否有可读输出
done

# 4. JTAG接口探测
# 使用jtagulator或手动测试
# 识别TCK/TMS/TDI/TDO引脚

# ===== 固件提取 =====
# 1. SPI Flash读取（使用CH341A或TL866）
flashrom -p ch341a_spi -r firmware_dump.bin

# 2. 通过U-boot提取（如果有串口Shell）

# sf read 0x82000000 0x0 0x100000  # 读取Flash到内存
```

```
### 漏洞1：CAN总线无认证导致可远程控制（严重）
- 漏洞等级：严重 (9.8)
- 漏洞描述：攻击者通过T-BOX漏洞进入车内网络后，可向CAN总线注入任意报文
- 影响范围：动力系统、车身系统、制动系统
- 复现步骤：
  1. 通过XX漏洞获取T-BOX Shell
```
