# 车联网渗透测试方法论

### 1.1 渗透测试原则

#### 1.1.1 合法性原则

- **必须获得授权**：在进行任何测试前，必须获得车辆所有者或制造商的书面授权
- **遵守法律法规**：遵守《网络安全法》《数据安全法》《个人信息保护法》等相关法规
- **不影响公共安全**：测试过程中不得影响道路交通安全和公共安全
- **报告义务**：发现高危漏洞应及时报告厂商，不公开未修复的漏洞

#### 1.1.2 安全原则

- **安全第一**：人的安全始终是第一位的
- **可控环境**：优先在实验环境、台架、报废车辆上测试
- **影响最小化**：尽可能减少对车辆和系统的影响
- **可恢复性**：确保测试后系统能恢复到正常状态

### 1.2 渗透测试流程

```
┌─────────────┐
│  1. 授权与规划 │ ← 确定范围、目标、时间、约束
└──────┬──────┘
       │
┌──────▼──────┐
│  2. 信息收集  │ ← 公开信息、硬件信息、固件获取
└──────┬──────┘
       │
┌──────▼──────┐
│  3. 威胁建模  │ ← 攻击面分析、威胁场景构建
└──────┬──────┘
       │
┌──────▼──────┐
│  4. 漏洞挖掘  │ ← 硬件、固件、网络、应用、协议
└──────┬──────┘
       │
┌──────▼──────┐
│  5. 漏洞验证  │ ← PoC验证、影响评估
└──────┬──────┘
       │
┌──────▼──────┐
│  6. 报告输出  │ ← 漏洞详情、风险评级、修复建议
└─────────────┘
```

### 1.3 测试范围与分类

#### 1.3.1 按测试对象分类

| 测试对象 | 测试内容 | 难度 |
|---------|---------|------|
| 车载系统 | IVI、智能座舱、仪表盘 | 中 |
| 车载网络 | CAN/CAN FD/LIN/以太网 | 中高 |
| T-Box | 固件、通信、远程控制 | 高 |
| OBD/诊断 | UDS诊断、刷写、安全访问 | 中高 |
| 无线攻击 | 蓝牙、Wi-Fi、车钥匙、NFC | 中高 |
| 移动App | 安卓/iOS App、数据安全 | 中 |
| 云平台 | API安全、数据安全、权限控制 | 中 |
| 自动驾驶 | 传感器、算法、决策系统 | 很高 |

#### 1.3.2 按攻击距离分类

```
远程攻击（远）
    │
    ├── 4G/5G 蜂窝网络 → T-Box、车云通信
    ├── V2X 通信 → 车车/车路通信
    ├── 云平台 API → 远程服务
    └── 移动 App → 远程控制

近场攻击（中）
    │
    ├── 蓝牙 → 手机互联、车钥匙
    ├── Wi-Fi → 车内热点、车机互联
    ├── UWB → 数字钥匙
    └── NFC → 车钥匙、支付

物理攻击（近）
    │
    ├── OBD-II 接口 → 诊断、CAN接入
    ├── USB 接口 → 车机系统
    ├── 拆解 → 芯片读取、调试接口
    ├── JTAG/SWD → 硬件调试
    └── 传感器 → 物理攻击
```

### 1.4 风险评级方法

参考CVSS评分体系，结合车联网特点：

| 维度 | 评估因素 | 说明 |
|------|---------|------|
| 攻击向量 | 远程/近场/物理 | 攻击距离越远，风险越高 |
| 攻击复杂度 | 低/中/高 | 需要的专业知识和资源 |
| 权限要求 | 无/低/高 | 攻击前需要的权限 |
| 用户交互 | 无需/需要 | 是否需要用户配合 |
| 安全影响 | 驾驶安全/财产/隐私 | 对人身安全的影响权重最高 |
| 影响范围 | 单台车/批量 | 影响车辆数量 |

**车联网安全特别关注：** 对驾驶安全的影响是最重要的评级因素。
