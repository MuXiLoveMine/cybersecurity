# 实战案例

### 7.1 案例1：特斯拉自动驾驶欺骗实验

**背景：** 研究人员发现可以通过物理世界对抗样本欺骗特斯拉Autopilot系统。

**实验设计：**

```
实验1: 交通标志欺骗
- 在STOP标志上贴对抗性贴纸
- 贴纸经过物理鲁棒性优化
- 测试不同距离和角度
- 结果: Autopilot将STOP标志识别为限速标志

实验2: 车道线欺骗
- 在路面上粘贴特定图案
- 图案设计为干扰车道检测
- 测试: 车辆偏离正常车道
- 结果: 车辆被引导到错误车道

实验3: 障碍物欺骗
- 使用对抗性涂装的物体
- 使物体被感知系统忽略
- 测试: 车辆未减速撞上物体
- 结果: 潜在碰撞风险
```

**安全启示：**

| 启示 | 说明 | 防御方向 |
|------|------|----------|
| 感知脆弱性 | 深度学习感知易受对抗攻击 | 对抗训练/多模态融合 |
| 物理可行性 | 对抗样本在物理世界有效 | 物理鲁棒性训练 |
| 安全边界 | 单一传感器不可靠 | 多传感器交叉验证 |
| 实时检测 | 需要运行时异常检测 | 感知结果一致性监控 |

**防御建议：**
- 对抗训练：在训练集中加入对抗样本
- 多模态融合：摄像头+雷达+LiDAR交叉验证
- 感知一致性检查：多帧时序一致性验证
- 异常检测：识别异常感知结果
- 功能降级：感知异常时安全停车

### 7.2 案例2：车云平台API越权测试

**场景：** 安全团队对车云平台API进行渗透测试，发现越权漏洞。

**测试目标：** 车辆远程控制API（开锁/启动/空调控制）

**测试过程：**

```
步骤1: API发现
- 通过APP抓包发现API端点
- 使用Swagger/OpenAPI文档了解API结构
- 发现关键API:
  - GET /api/v1/vehicles/{vehicle_id}/status
  - POST /api/v1/vehicles/{vehicle_id}/control
  - POST /api/v1/vehicles/{vehicle_id}/unlock

步骤2: 认证分析
- APP使用JWT认证
- JWT payload包含user_id和user_role
- 车辆关联通过user_vehicle_mapping表

步骤3: 水平越权测试
- 用户A的JWT请求用户B的车辆
- 测试: GET /api/v1/vehicles/{B_vehicle_id}/status
  - 期望: 403 Forbidden
  - 实际: 200 OK → 返回用户B的车辆状态!
  - 发现: 水平越权漏洞

步骤4: 远程控制越权
- 测试: POST /api/v1/vehicles/{B_vehicle_id}/unlock
  - 请求体: {"action": "unlock"}
  - 期望: 403 Forbidden
  - 实际: 200 OK → 用户B的车辆被解锁!
  - 严重: 远程控制越权漏洞

步骤5: 影响评估
- 攻击者可控制任意车辆
- 可远程开锁/启动/控制空调
- 可查看任意车辆位置和状态
- 严重等级: Critical
```

**漏洞根因分析：**

```python
# 越权漏洞根因（概念示意）
# 漏洞代码:
@app.route('/api/v1/vehicles/<vehicle_id>/control', methods=['POST'])
@jwt_required
def control_vehicle(vehicle_id):
    # 漏洞: 仅验证JWT有效性，未验证车辆所有权
    action = request.json.get('action')
    vehicle = Vehicle.query.get(vehicle_id)
    # 直接执行控制，未检查当前用户是否拥有该车辆
    vehicle.execute_control(action)
    return jsonify({'status': 'success'})

# 修复代码:
@app.route('/api/v1/vehicles/<vehicle_id>/control', methods=['POST'])
@jwt_required
def control_vehicle(vehicle_id):
    user_id = get_jwt_identity()
    # 验证车辆所有权
    mapping = UserVehicleMapping.query.filter_by(
        user_id=user_id, vehicle_id=vehicle_id
    ).first()
    if not mapping:
        return jsonify({'error': 'Unauthorized'}), 403
    action = request.json.get('action')
    vehicle = Vehicle.query.get(vehicle_id)
    vehicle.execute_control(action)
    return jsonify({'status': 'success'})
```

**防护建议：**
- 实施车辆所有权验证（每个API请求验证用户-车辆关联）
- 使用ABAC细粒度授权
- API网关统一鉴权
- 远程控制二次确认（APP弹窗确认+短信验证码）
- 远程控制审计日志
- 异常控制行为检测与告警

### 7.3 案例3：OTA升级中间人攻击

**场景：** 攻击者在OTA升级过程中实施中间人攻击，尝试注入恶意固件。

**攻击场景：**

```
攻击前提:
- 车辆在公共Wi-Fi网络下进行OTA升级
- 攻击者控制Wi-Fi接入点
- OTA升级未使用端到端加密或签名验证不足

攻击流程:
步骤1: 网络劫持
- 攻击者设置恶意Wi-Fi热点
- 车辆连接到攻击者的热点
- 攻击者成为车辆与OTA服务器之间的中间人

步骤2: 固件篡改
- 拦截OTA升级请求
- 下载合法固件
- 修改固件中的关键组件(如植入后门)
- 重新打包固件

步骤3: 伪造签名(尝试)
- 尝试伪造固件签名
- 如果签名验证不严格 → 签名验证可能被绕过
- 如果使用弱哈希算法 → 可能碰撞攻击

步骤4: 注入恶意固件
- 将篡改固件发送给车辆
- 车辆验证签名...
```

**防御验证（签名验证有效的情况）：**

```
防御效果(假设实现了完整的签名验证):
├── 固件签名验证
│   ├── 车辆验证固件签名(RSA-2048/ECDSA)
│   ├── 签名验证失败 → 拒绝升级
│   ├── 攻击者无法伪造签名(无私钥)
│   └── 恶意固件被拒绝 → 攻击失败

├── 传输安全
│   ├── mTLS双向认证
│   ├── 服务器证书固定(Certificate Pinning)
│   ├── 攻击者无法建立mTLS连接
│   └── 中间人攻击被阻断

└── 防回滚保护
    ├── 版本号验证
    ├── 安全存储最高版本号
    └── 防止降级到有漏洞版本
```

**安全加固代码（概念示意）：**

```python
# OTA升级安全验证（概念示意）
import hashlib
from cryptography.hazmat.primitives import hashes
from cryptography.hazmat.primitives.asymmetric import ec
from cryptography.hazmat.primitives import serialization

class OTASecurityVerifier:
    def __init__(self):
        # 车辆预置的OTA签名公钥
        self.ota_public_key = self._load_public_key()
        # 安全存储的最高版本号
        self.min_version = self._read_secure_version()
    
    def verify_firmware(self, firmware_data, signature, firmware_version):
        """验证固件安全性"""
        # 1. 版本检查(防回滚)
        if firmware_version <= self.min_version:
            raise SecurityError("Firmware version rollback detected")
        
        # 2. 完整性检查
        expected_hash = hashlib.sha256(firmware_data).hexdigest()
        
        # 3. 签名验证
        try:
            self.ota_public_key.verify(
                signature,
                firmware_data,
                ec.ECDSA(hashes.SHA256())
            )
        except Exception as e:
            raise SecurityError(f"Signature verification failed: {e}")
        
        # 4. 硬件兼容性检查
        if not self._check_hardware_compat(firmware_data):
            raise SecurityError("Hardware incompatibility")
        
        # 5. 安全自检
        if not self._security_self_test():
            raise SecurityError("Security self-test failed")
        
        return True
    
    def safe_install(self, firmware_data, target_partition):
        """安全安装固件(A/B分区)"""
        # 写入非活动分区
        inactive_partition = self._get_inactive_partition()
        self._write_partition(inactive_partition, firmware_data)
        # 验证写入完整性
        if not self._verify_partition(inactive_partition):
            raise SecurityError("Partition write verification failed")
        # 设置watchdog后切换
        self._set_watchdog(timeout=30)
        self._switch_partition(inactive_partition)
        # 新分区启动后需通过健康检查
        # 失败则watchdog超时自动回滚到旧分区
```

```
OTA安全检查清单:
□ 固件使用强签名算法(RSA-2048+/ECDSA-P256+)

□ 升级审计日志

```
