### 4.1 ISO 26262功能安全标准

ISO 26262是汽车功能安全的国际标准，覆盖汽车电子电气系统的完整生命周期：

```
ISO 26262标准框架:
├── Part 1: 术语定义
├── Part 2: 功能安全管理
│   ├── 安全生命周期管理
│   ├── 组织级安全管理
│   └── 项目级安全管理
├── Part 3: 概念阶段
│   ├── 相关项定义
│   ├── 危险分析和风险评估
│   └── 功能安全概念
├── Part 4-6: 产品开发
│   ├── 系统级产品开发
│   ├── 硬件级产品开发
│   └── 软件级产品开发
├── Part 7: 生产/运行/服务/退役
├── Part 8: 支持过程
│   ├── 接口/配置管理
│   ├── 验证/确认
│   └── 功能安全评估
├── Part 9: ASIL导向分析
├── Part 10: 指南
└── Part 11-12: 半导体/摩托车
```

### 4.2 ASIL等级划分

汽车安全完整性等级（ASIL）是ISO 26262定义的安全等级，基于三个维度评估：

```
ASIL评估维度:
┌────────────────┬──────────────────────────────────────┐
│ 严重性(S)      │ 伤害的严重程度                        │
│                ├── S0: 无伤害                          │
│                ├── S1: 轻微/中度伤害                   │
│                ├── S2: 严重/致命伤害（可能存活）        │
│                └── S3: 致命伤害（可能危及生命）        │
├────────────────┼──────────────────────────────────────┤
│ 暴露率(E)      │ 驾驶员处于危险情境的概率              │
│                ├── E0: 非常低（不可信）                 │
│                ├── E1: 低（罕见）                     │
│                ├── E2: 中等                            │
│                └── E3: 高（频繁发生）                  │
├────────────────┼──────────────────────────────────────┤
│ 可控性(C)      │ 驾驶员避免伤害的能力                  │
│                ├── C0: 容易控制                        │
│                ├── C1: 简单控制                        │
│                ├── C2: 一般控制                        │
│                └── C3: 难以控制（大多数无法避免）     │
└────────────────┴──────────────────────────────────────┘

ASIL等级矩阵:
┌──────────────────────────────────────────────┐
│ C0:                                           │
│   任意 S + 任意 E → QM (质量管理)              │
│                                               │
│ C1:                                           │
│   S1+S2 + E1 → QM                             │
│   S1+S2 + E2 → QM/ASIL A                     │
│   S1+S2 + E3 → ASIL A/B                      │
│   S3 + E1 → QM                                │
│   S3 + E2 → ASIL A                            │
│   S3 + E3 → ASIL B                            │
│                                               │
│ C2/C3: 逐级提升到 ASIL A/B/C/D               │
│                                               │
│ 等级: QM < ASIL A < B < C < D (最高)          │
└──────────────────────────────────────────────┘
```

**各ASIL等级要求：**

| 等级 | 要求 | 适用场景示例 |
|------|------|-------------|
| QM | 标准质量管理 | 车载娱乐系统 |
| ASIL A | 基本安全要求 | 大灯控制 |
| ASIL B | 中等安全要求 | 胎压监测 |
| ASIL C | 较高安全要求 | ABS系统 |
| ASIL D | 最高安全要求 | 制动/转向控制、AEB |

### 4.3 SOTIF（ISO 21448）预期功能安全

SOTIF（Safety of the Intended Functionality）补充了ISO 26262的不足，关注系统功能本身的预期安全性：

```
SOTIF vs ISO 26262:
┌──────────────┬──────────────────────┬──────────────────────┐
│   维度       │    ISO 26262         │    SOTIF (ISO 21448) │
├──────────────┼──────────────────────┼──────────────────────┤
│ 关注问题     │ 系统故障导致的安全   │ 功能限制导致的安全   │
│              │ (E/E系统故障)        │ (无故障但不安全)     │
├──────────────┼──────────────────────┼──────────────────────┤
│ 触发原因     │ 硬件/软件故障        │ 感知不足/合理可预见  │
│              │                      │ 的误用/环境复杂性    │
├──────────────┼──────────────────────┼──────────────────────┤
│ 适用范围     │ 传统汽车电子         │ 自动驾驶系统         │
│              │                      │ (高度依赖AI/传感器)  │
├──────────────┼──────────────────────┼──────────────────────┤
│ 示例         │ 刹失灵导致事故       │ 大雾导致感知失效     │
│              │ (系统故障)           │ (无故障但不安全)     │
└──────────────┴──────────────────────┴──────────────────────┘
```

**SOTIF核心流程：**

```
SOTIF安全生命周期:
├── 阶段1: 规范与设计
│   ├── 定义预期功能
│   ├── 定义操作设计域(ODD)
│   └── 定义安全目标
│
├── 阶段2: 危险识别
│   ├── 识别功能不足导致的危险
│   ├── 识别触发事件
│   └── 场景分析
│
├── 阶段3: 风险评估
│   ├── 评估危险的可控性
│   ├── 评估触发事件概率
│   └── 确定可接受风险
│
├── 阶段4: 安全措施
│   ├── 改进系统设计
│   ├── 增强感知能力
│   ├── 冗余设计
│   └── 运行时监控
│
└── 阶段5: 验证与确认
    ├── 场景测试验证
    ├── 统计验证（大数定律）
    └── 残余风险评估
```

### 4.4 安全关键系统设计

```
自动驾驶安全关键系统设计原则:
├── 冗余设计
│   ├── 传感器冗余（多模态融合）
│   ├── 计算冗余（双/三冗余处理器）
│   ├── 通信冗余（双总线架构）
│   └── 执行冗余（双制动系统）
│
├── 多样性设计
│   ├── 不同原理传感器（摄像头+雷达+LiDAR）
│   ├── 不同算法实现（多模型投票）
│   └── 避免共因失效
│
├── 故障安全（Fail-Safe）
│   ├── 检测故障 → 进入安全状态
│   ├── 安全状态: 减速停车/靠边停车
│   ├── 最小风险策略(MRC)
│   └── 故障传播分析
│
├── 运行时监控
│   ├── 传感器健康监测
│   ├── 模型置信度监控
│   ├── 执行器反馈验证
│   └── 实时安全检查
│
└── 安全文化
    ├── 安全第一原则
    ├── 设计审查流程
    └── 安全生命周期管理
```
