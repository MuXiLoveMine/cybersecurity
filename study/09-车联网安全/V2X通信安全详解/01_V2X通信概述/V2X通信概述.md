# V2X通信概述

### 1.1 V2X定义与发展历程

**V2X（Vehicle-to-Everything）** 是指车辆与外部环境之间进行信息交互的通信技术总称，旨在通过车辆与车辆、基础设施、行人以及云端的实时通信，提升道路安全、交通效率和自动驾驶能力。

**发展历程：**

| 阶段 | 时间 | 特征 |
|------|------|------|
| 概念提出 | 2003-2008 | IEEE开始DSRC标准化 |
| 标准形成 | 2008-2015 | IEEE 1609系列、SAE J2735发布 |
| 技术竞争 | 2015-2019 | DSRC与C-V2X并行发展 |
| 产业化推进 | 2019-2023 | 多国启动V2X部署 |
| 规模部署 | 2023-至今 | 与自动驾驶融合 |

**V2X安全的核心挑战：**

```text
┌────────────────────────────────────────────────────────────────┐
│                     V2X安全核心挑战                              │
├────────────────────────────────────────────────────────────────┤
│ 1. 高移动性：车辆高速移动，通信窗口短（毫秒级）                    │
│ 2. 大规模：数百万车辆同时通信，证书管理复杂                        │
│ 3. 隐私性要求：身份认证与隐私保护存在矛盾                          │
│ 4. 实时性要求：安全消息延迟容忍度极低（<100ms）                    │
│ 5. 异构性：不同厂商、不同地区标准不完全统一                        │
│ 6. 资源约束：车载单元（OBU）计算和存储资源有限                    │
└────────────────────────────────────────────────────────────────┘
```

### 1.2 V2V车车通信

**V2V（Vehicle-to-Vehicle）** 是车辆之间的直接通信，是V2X最核心的通信模式。

**主要应用场景：**

- **前向碰撞预警（FCW）**：前方车辆急刹时预警后方车辆
- **交叉路口碰撞预警（ICA）**：无信号灯路口的车辆碰撞避免
- **紧急电子制动灯（EEBL）**：前方车辆紧急制动时广播预警
- **变道预警（LCW）**：变道时检测盲区是否有车
- **协作式自适应巡航（CACC）**：多车辆编队行驶

**通信特点：**

```text
V2V通信链路特征：
┌──────────┐                    ┌──────────┐
│  车辆 A  │ ◄── DSRC/C-V2X ──► │  车辆 B  │
│  OBU     │    直线通信          │  OBU     │
└──────────┘                    └──────────┘
  通信距离: 300-1000米
  通信频率: 5.9 GHz (DSRC) / 5.9 GHz (C-V2X PC5)
  消息频率: 10 Hz (BSM每100ms发送一次)
  延迟要求: < 100ms
  消息类型: BSM (Basic Safety Message)
```

**安全需求分析：**

| 安全需求 | 说明 | 优先级 |
|---------|------|--------|
| 消息真实性 | 确认消息来自真实车辆 | 最高 |
| 消息完整性 | 消息未被篡改 | 最高 |
| 消息时效性 | 消息未被延迟或重放 | 高 |
| 发送者匿名性 | 不暴露驾驶员身份 | 高 |
| 可追溯性 | 出现事故时可追踪责任 | 中 |
| 可用性 | 通信不被干扰 | 高 |

### 1.3 V2I车路通信

**V2I（Vehicle-to-Infrastructure）** 是车辆与路边基础设施（RSU）之间的通信。

**主要应用场景：**

- **信号灯相位与配时（SPaT）**：车辆获取前方信号灯状态
- **MAP数据**：路口车道拓扑信息
- **弯道速度预警**：基于路侧传感器的弯道预警
- **学校区域预警**：接近学校时的限速提醒
- **工作区预警**：道路施工区域预警
- **电子收费（ETC）**：不停车收费

**架构模型：**

```text
              V2I通信架构
┌──────────────────────────────────┐
│         路侧单元 (RSU)            │
│  ┌─────────┐  ┌──────────┐      │
│  │ 信号灯   │  │ 路侧传感器 │     │
│  │ 控制器   │  │ (雷达/摄像头)│    │
│  └────┬────┘  └─────┬────┘     │
│       └──────┬──────┘           │
│          ┌────┴────┐             │
│          │ RSU处理  │             │
│          │ 单元     │             │
│          └────┬────┘             │
└───────────────┼──────────────────┘
                │ DSRC / C-V2X
┌───────────────▼──────────────────┐
│         车载单元 (OBU)            │
│  接收SPaT/MAP消息 → 驾驶决策       │
└───────────────────────────────────┘
```

**安全威胁场景：**

```
攻击场景：伪造信号灯状态
1. 攻击者部署伪造RSU
2. 向经过车辆发送伪造SPaT消息
3. 车辆收到绿灯信号时实际为红灯
4. 可能导致交叉路口碰撞事故

防御机制：
- RSU消息必须使用合法证书签名
- 车辆验证RSU证书链
- 异常消息检测（如信号灯状态跳变异常）
```

### 1.4 V2P车人通信

**V2P（Vehicle-to-Pedestrian）** 是车辆与行人之间的通信，主要通过行人携带的智能手机实现。

**主要应用场景：**

- **行人碰撞预警**：行人进入车辆盲区时预警
- **弱势道路使用者保护**：保护老人、儿童等
- **交叉路口行人检测**：无信号灯路口
- **紧急行人横穿预警**：行人突然横穿马路

**技术挑战：**

```text
V2P独特挑战：
┌─────────────────────────────────────────┐
│ 1. 手机功耗约束 → 不能持续高频发送        │
│ 2. 定位精度有限 → GPS误差5-10米          │
│ 3. 行人轨迹不可预测 → 难以预判运动方向     │
│ 4. 手机认证困难 → 缺乏车辆那样的PKI体系    │
│ 5. 大规模部署 → 城市级别数百万手机         │
└─────────────────────────────────────────┘
```

### 1.5 V2N车云通信

**V2N（Vehicle-to-Network）** 是车辆与云端服务器之间的通信，通常通过蜂窝网络实现。

**主要应用场景：**

- **实时交通信息**：云端提供拥堵信息
- **OTA升级**：固件和软件更新
- **远程车辆诊断**：云端分析车辆状态
- **紧急呼叫（eCall）**：事故自动呼叫救援
- **云端导航**：基于云端的高精度地图和路径规划

**安全模型：**

```text
V2N安全通信架构

┌──────────┐      ┌──────────┐      ┌──────────┐
│  车辆    │      │ 蜂窝网络  │      │  云平台   │
│  T-Box  │─────►│ 4G/5G   │─────►│  服务端   │
│         │◄─────│ 基站    │◄─────│          │
└──────────┘      └──────────┘      └──────────┘

安全层：
├── 传输层：TLS 1.3加密
├── 认证层：双向证书认证（mTLS）
├── 应用层：API签名验证
└── 数据层：敏感数据端到端加密
```
