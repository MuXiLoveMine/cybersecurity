# CAN总线协议详解

### 1.1 CAN协议基础

#### 1.1.1 协议概述

**CAN（Controller Area Network，控制器局域网）** 由博世（Bosch）公司于1986年开发，是一种面向工业控制的串行通信协议。

**核心特性：**
- **多主站架构**：任何节点都可以主动发起通信
- **非破坏性仲裁**：基于ID的优先级仲裁，高优先级报文优先发送
- **广播通信**：所有节点都能接收总线上的所有报文
- **差分信号**：使用CAN_H和CAN_L两根线，抗干扰能力强
- **错误检测**：CRC校验、位错误检测、格式错误检测
- **无地址概念**：通过标识符（ID）区分报文类型

#### 1.1.2 物理层

**信号电平：**

```
  隐性电平(Recessive): CAN_H ≈ CAN_L ≈ 2.5V  (逻辑1)
  显性电平(Dominant):  CAN_H ≈ 3.5V, CAN_L ≈ 1.5V  (逻辑0)
  差分电压: 显性时约2V, 隐性时约0V

CAN_H ────╮     ╭─────╮     ╭───
          ╲   ╱       ╲   ╱
           ╲ ╱         ╲ ╱
            ╳           ╳     ← 差分信号
           ╱ ╲         ╱ ╲
          ╱   ╲       ╱   ╲
CAN_L ────╯     ╰─────╯     ╰───

     隐性  显性  隐性  显性  隐性
     (1)   (0)   (1)   (0)   (1)
```

**总线拓扑：**
- 总线型拓扑，两端各接一个120Ω终端电阻
- 最大传输距离：1Mbps时40m，125kbps时500m
- 最多节点数：理论上不限，实际受总线负载限制（通常≤30个）

### 1.2 CAN帧格式

#### 1.2.1 标准数据帧（11位ID）

```
┌──────┬──────┬──────┬────┬──────┬─────┬──────┬──────┐
│  SOF  │仲裁场│控制场│数据场│ CRC场 │ACK场│ EOF  │IFS   │
│  1位  │ 12位 │ 6位  │0-64b│ 16位 │ 2位 │ 7位  │ 3位  │
└──────┴──────┴──────┴────┴──────┴─────┴──────┴──────┘
```

**各字段详解：**

| 字段 | 长度 | 说明 |
|------|------|------|
| SOF | 1位 | 帧起始，显性电平（0），标志帧的开始 |
| 仲裁场 | 12位 | 11位ID + RTR位（0=数据帧，1=远程帧） |
| 控制场 | 6位 | IDE位 + 保留位 + DLC（4位数据长度码） |
| 数据场 | 0~8字节 | 数据内容，长度由DLC决定 |
| CRC场 | 16位 | 15位CRC序列 + 1位CRC界定符 |
| ACK场 | 2位 | ACK槽 + ACK界定符，接收正确发送方拉低ACK槽 |
| EOF | 7位 | 帧结束，7个隐性电平 |
| IFS | 3位 | 帧间间隔 |

#### 1.2.2 扩展数据帧（29位ID）

```
┌──────┬───────────────┬──────┬──────┬────┬──────┬─────┬──────┬──────┐
│  SOF  │   仲裁场      │控制场│控制场│数据场│ CRC场 │ACK场│ EOF  │IFS   │
│  1位  │    32位       │ 6位  │      │0-8B │ 16位 │ 2位 │ 7位  │ 3位  │
└──────┴───────────────┴──────┴──────┴────┴──────┴─────┴──────┴──────┘
```

扩展帧的仲裁场包含：
- 基础ID（11位）
- SRR位（替代远程请求）
- IDE位（1=扩展帧）
- 扩展ID（18位）
- RTR位

#### 1.2.3 CAN FD帧格式

CAN FD（CAN with Flexible Data Rate）在标准CAN基础上扩展了数据长度和数据段速率。

**关键变化：**
- **数据长度**：0~64字节（原0~8字节）
- **数据段速率**：最高8Mbps（仲裁段仍为1Mbps）
- **新增字段**：FDF位（标识FD帧）、BRS位（波特率切换）、ESI位（错误状态指示）

### 1.3 帧类型

| 帧类型 | 用途 | 说明 |
|--------|------|------|
| 数据帧 | 传输数据 | 最常用，携带数据由发送节点发出 |
| 远程帧 | 请求数据 | 请求其他节点发送指定ID的数据 |
| 错误帧 | 错误通知 | 检测到错误时发送，通知所有节点 |
| 过载帧 | 延迟通知 | 接收节点繁忙，请求延迟下一帧 |
| 帧间隔 | 帧间分隔 | 分隔数据帧/远程帧与前面的帧 |

### 1.4 CAN仲裁机制

CAN采用**载波监听多路访问/冲突检测+非破坏性仲裁**（CSMA/CD+NDA）。

**仲裁规则：**
- 所有节点监听总线，总线空闲时才发送
- 发送时同时监听总线电平
- 当某个节点发送隐性电平（1），但检测到总线上是显性电平（0）时，说明有更高优先级的帧在发送，该节点停止发送（退出仲裁）
- ID值越小，优先级越高（因为显性电平0会胜出）

**仲裁示例：**

```
节点A发送: ID=0x100 (001 0000 0000)
节点B发送: ID=0x200 (010 0000 0000)

时间轴:  ↓ 仲裁点
位序:    1 2 3 4 5 ...
节点A:   0 0 1 0 0 ...
节点B:   0 1 0 0 0 ...
总线:    0 0 0 0 0 ...  (显性优先)
            ↑
            第2位：节点B发1，总线是0 → 节点B退出仲裁
            节点A获得总线使用权
```

### 1.5 CAN错误处理

#### 1.5.1 错误检测机制

1. **位错误（Bit Error）**：发送的位与总线上的位不一致（仲裁场除外）
2. **填充错误（Stuff Error）**：检测到连续6个相同电平（违反位填充规则）
3. **CRC错误（CRC Error）**：接收节点计算的CRC与收到的CRC不一致
4. **格式错误（Form Error）**：帧格式不符合规定
5. **应答错误（Acknowledgment Error）**：发送节点未检测到ACK

#### 1.5.2 错误帧格式

```
┌─────────────────────┬─────────────────────┐
│  错误标志（6位）      │  错误界定符（8位）    │
│  主动错误:6个显性位   │  8个隐性位           │
│  被动错误:6个隐性位   │                     │
└─────────────────────┴─────────────────────┘
```

#### 1.5.3 错误状态

节点有三种错误状态：

| 状态 | 发送错误计数器(TEC) | 接收错误计数器(REC) | 行为 |
|------|-------------------|-------------------|------|
| 错误主动 | TEC < 128 | REC < 128 | 正常工作，发送主动错误标志 |
| 错误被动 | 128 ≤ TEC < 256 或 128 ≤ REC < 256 |  | 发送被动错误标志，发送后需等待额外时间 |
| 总线关闭 | TEC ≥ 256 | - | 脱离总线，无法收发 |

### 1.6 典型CAN报文示例

**示例1：发动机转速报文（ID: 0x100）**

```
CAN ID: 0x100 (标准帧)
DLC: 8
Data: 0x12 0x34 0x00 0x00 0x00 0x00 0x00 0x00

解析：
  发动机转速 = (0x12 << 8) | 0x34 = 4660 rpm
  （具体定义需参考DBC文件）
```

**示例2：车速报文（ID: 0x200）**

```
CAN ID: 0x200
DLC: 8
Data: 0x00 0xFA 0x00 0x00 0x00 0x00 0x00 0x00

解析：
  车速 = 0x00FA = 250 → 250 / 10 = 25 km/h
  （比例因子1/10，偏移量0）
```
