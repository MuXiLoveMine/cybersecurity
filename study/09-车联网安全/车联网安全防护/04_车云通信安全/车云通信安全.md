# 车云通信安全

### 4.1 通信安全架构

#### 4.1.1 安全通信模型

```
车辆端（T-Box/IVI）              云端（平台）
     │                              │
     │── 1. 身份认证 ────────────→ │
     │←── 2. 认证响应 ──────────── │
     │                              │
     │── 3. 密钥协商 ────────────→ │
     │←── 4. 会话密钥 ──────────── │
     │                              │
     │── 5. 加密数据传输 ────────→ │
     │←── 6. 加密数据传输 ──────── │
     │                              │
```

#### 4.1.2 常用安全协议

| 协议 | 层级 | 用途 | 说明 |
|------|------|------|------|
| TLS 1.2/1.3 | 传输层 | HTTPS、MQTT over TLS | 最常用，安全性高 |
| DTLS | 传输层 | UDP应用、CoAP | TLS的UDP版本 |
| IPSec | 网络层 | VPN、端到端安全 | 网络层加密 |
| MQTT TLS | 应用层 | 消息队列遥测传输 | 车云消息常用 |
| CoAP DTLS | 应用层 | 受限设备通信 | 轻量级协议 |

### 4.2 身份认证

#### 4.2.1 设备身份认证

**认证方式：**

**1. 基于预共享密钥（PSK）**
```
车辆端存储密钥K ←──────────→ 云端存储密钥K
认证: 双方使用K进行身份验证
```
- 优点：简单、高效
- 缺点：密钥分发和管理困难，扩展性差

**2. 基于证书的认证（PKI）**
```
车辆端证书 + 私钥 ←──────→ 根CA证书
认证: 双向证书认证，验证对方身份
```
- 优点：安全性高，扩展性好
- 缺点：实现复杂，需要PKI体系

**3. 基于令牌的认证**
```
车辆端登录获取Token ←──────→ 认证服务签发Token
通信: 携带Token进行身份验证
```
- 优点：灵活，可控制有效期
- 缺点：Token泄露风险

#### 4.2.2 双向认证

车云通信应使用双向认证（Mutual Authentication）：
- 车辆验证云端身份（防止连接到伪基站/伪服务器）
- 云端验证车辆身份（防止伪造设备接入）

### 4.3 数据传输安全

#### 4.3.1 传输加密

**加密算法选择：**
- **对称加密**：AES-128/256-GCM（推荐，提供加密+完整性）
- **非对称加密**：RSA-2048/3072、ECC-256（用于密钥交换）
- **哈希算法**：SHA-256/384
- **密钥交换**：ECDHE（前向安全）

#### 4.3.2 消息完整性与认证

- **MAC（消息认证码）**：确保消息未被篡改
- **数字签名**：确保消息来源可信
- **时间戳/序列号**：防止重放攻击

#### 4.3.3 常见安全问题

| 问题 | 风险 | 防护措施 |
|------|------|---------|
| 明文传输 | 数据泄露、篡改 | 启用TLS/DTLS |
| 不验证证书 | 中间人攻击 | 严格验证服务器证书 |
| 弱加密算法 | 加密被破解 | 使用强加密算法 |
| 硬编码密钥 | 密钥泄露 | 安全存储密钥（HSM/TEE） |
| 无重放防护 | 重放攻击 | 时间戳、序列号 |
| 不安全的TLS配置 | 降级攻击 | 禁用弱密码套件 |

### 4.4 MQTT安全

MQTT是车云通信最常用的协议之一。

#### 4.4.1 MQTT安全措施

```
┌─────────────────────────────────────┐
│         应用层安全                   │
│  Topic权限控制 | 消息过滤 | Payload加密 │
├─────────────────────────────────────┤
│         会话层安全                   │
│  客户端认证 | 会话管理 | 遗嘱消息     │
├─────────────────────────────────────┤
│         传输层安全                   │
│  TLS/DTLS加密 | 双向认证             │
├─────────────────────────────────────┤
│         网络层安全                   │
│  防火墙 | VPN | IP白名单             │
└─────────────────────────────────────┘
```

#### 4.4.2 关键安全配置

1. **启用TLS**：使用8883端口（MQTT over TLS）
2. **客户端认证**：每个设备独立的用户名/密码或证书
3. **Topic权限**：严格控制每个客户端的发布/订阅权限
4. **QoS级别**：重要消息使用QoS 1或2
5. **遗嘱消息**：异常断开时通知系统
6. **Keep Alive**：合理设置心跳间隔
