# ECU安全加固

### 2.1 ECU安全架构

#### 2.1.1 安全启动（Secure Boot）

**概念：** ECU启动时验证固件的完整性和真实性，确保只有经过授权的固件才能运行。

**启动流程：**

```
┌─────────────┐
│   复位启动   │
└──────┬──────┘
       │
┌──────▼──────┐    ┌──────────────┐
│  Boot ROM   │───→│ 验证Bootloader │  ← 验证Bootloader签名
│  (不可变)   │    │   签名        │
└──────┬──────┘    └──────────────┘
       │ 验证通过
┌──────▼──────┐    ┌──────────────┐
│ Bootloader  │───→│ 验证应用固件   │  ← 验证应用程序签名
│             │    │   签名        │
└──────┬──────┘    └──────────────┘
       │ 验证通过
┌──────▼──────┐
│  应用程序    │  ← 正常运行
│  (App)      │
└─────────────┘
```

**关键要素：**
- **信任根（RoT, Root of Trust）**：Boot ROM，硬件实现，不可修改
- **签名算法**：通常使用RSA或ECC非对称加密
- **证书链**：逐级验证，建立信任链
- **失败处理**：验证失败时拒绝启动或进入恢复模式

**常见实现：**
- ARM TrustZone
- 硬件安全模块（HSM）
- 安全元件（SE）

#### 2.1.2 可信执行环境（TEE）

**概念：** 在主处理器中划分出一个安全区域，与普通操作系统隔离，提供安全的执行环境。

**ARM TrustZone架构：**

```
┌─────────────────────────────────────────┐
│            应用层                        │
│  Normal World            Secure World    │
│  ┌──────────┐          ┌──────────┐     │
│  │  Rich OS  │          │  TEE OS  │     │
│  │ (Linux/  │          │ (安全OS) │     │
│  │  Android)│          │          │     │
│  └────┬─────┘          └────┬─────┘     │
│       │                     │           │
│  ┌────▼─────┐          ┌────▼─────┐     │
│  │  内核    │          │  安全内核 │     │
│  └────┬─────┘          └────┬─────┘     │
└───────┼─────────────────────┼───────────┘
        │    Monitor Mode     │
        └─────────────────────┘
              CPU硬件隔离
```

**TEE中的安全服务：**
- 密钥存储与管理
- 加密/解密运算
- 安全启动验证
- 安全认证
- 敏感数据处理
- 支付安全

**车载应用场景：**
- 数字钥匙安全存储
- V2X消息签名
- 车云通信密钥管理
- 车内支付安全
- 生物识别数据处理

#### 2.1.3 硬件安全模块（HSM）

**HSM（Hardware Security Module）** 是专门的硬件安全模块，提供加密运算和密钥管理功能。

**车载HSM功能：**
- **密钥生成与存储**：安全生成和存储密钥，密钥不可导出
- **加密运算加速**：硬件实现AES、SHA、ECC等算法
- **安全启动验证**：验证固件签名
- **消息认证码生成**：生成/验证CAN报文MAC
- **真随机数生成**：提供高质量随机数

**常见车载HSM：**
- Infineon HSM（集成在AURIX系列MCU中）
- NXP HSE（Hardware Security Engine）
- 独立安全芯片（如ATAES、ATECC系列）

### 2.2 内存安全

#### 2.2.1 常见内存漏洞

| 漏洞类型 | 说明 | 防护措施 |
|---------|------|---------|
| 缓冲区溢出 | 写入数据超过缓冲区大小 | 栈保护、边界检查 |
| 整数溢出 | 整数运算结果超出表示范围 | 输入校验、安全函数 |
| 格式化字符串 | 格式化字符串参数可被控制 | 代码审计、编译选项 |
| 堆溢出 | 堆内存越界写入 | 堆保护、隔离 |
| Use-After-Free | 释放后继续使用内存 | 内存安全检查 |
| 空指针引用 | 引用空指针 | 代码审计、静态分析 |

#### 2.2.2 防护技术

**编译期防护：**
- **Stack Canary（栈金丝雀）**：栈帧中插入保护值，检测栈溢出
- **ASLR（地址空间随机化）**：随机化内存布局，增加攻击难度
- **DEP/NX（数据执行保护）**：数据页不可执行，防止shellcode执行
- **FORTIFY_SOURCE**：强化库函数的安全检查
- **Control Flow Integrity（CFI）**：控制流完整性保护

**运行期防护：**
- **MPU（内存保护单元）**：隔离不同内存区域的访问权限
- **MMU（内存管理单元）**：虚拟内存隔离
- **Watchdog**：监控程序运行状态，异常时复位
- **内存ECC**：错误检测与纠正

### 2.3 ECU固件安全

#### 2.3.1 固件加密

**目的：** 防止固件被提取和分析。

**实现方式：**
- Flash中的固件加密存储
- 运行时解密到RAM执行
- 由HSM或安全启动流程解密

**注意：** 单纯的固件加密不能防止运行时攻击，需要配合其他安全机制。

#### 2.3.2 固件更新安全

详见第六章"OTA升级安全"。

#### 2.3.3 调试接口安全

**防护措施：**
1. **量产时禁用调试接口**：关闭JTAG/SWD/UART等调试接口
2. **调试保护机制**：启用MCU的调试保护功能
3. **安全调试**：如需保留调试功能，应增加认证机制
4. **芯片级保护**：启用Flash读保护、写保护
