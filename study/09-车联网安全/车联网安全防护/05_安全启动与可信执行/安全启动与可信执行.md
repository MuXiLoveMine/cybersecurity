# 安全启动与可信执行

### 5.1 安全启动（Secure Boot）

#### 5.1.1 信任链

安全启动建立了一条从硬件到应用的信任链：

```
硬件信任根 (Boot ROM)
    │ 验证签名
    ▼
第一级Bootloader (BL1)
    │ 验证签名
    ▼
第二级Bootloader (BL2)
    │ 验证签名
    ▼
操作系统内核 (OS Kernel)
    │ 验证签名
    ▼
应用程序 (Applications)
```

每一级都验证下一级的签名，确保整个启动过程的完整性和真实性。

#### 5.1.2 签名验证过程

```
固件包结构：
┌───────────────┐
│  固件数据      │
├───────────────┤
│  数字签名      │  ← 使用厂商私钥签名
├───────────────┤
│  公钥证书      │  ← 由根证书签发
└───────────────┘

验证过程：
  1. 使用根公钥验证证书签名
  2. 使用证书中的公钥验证固件签名
  3. 计算固件数据的哈希值
  4. 解密签名得到预期哈希
  5. 比较两个哈希值是否一致
```

#### 5.1.3 安全启动的关键要素

1. **信任根（RoT）不可篡改**：Boot ROM在硬件中实现，无法修改
2. **签名算法安全**：使用安全的签名算法（RSA-2048+、ECC-256+）
3. **密钥安全存储**：私钥严格保密，使用HSM存储
4. **版本管理**：防止版本回退（降级攻击）
5. **失败处理**：验证失败时进入安全恢复模式

### 5.2 可信执行环境（TEE）

#### 5.2.1 车载TEE应用场景

| 应用 | 说明 |
|------|------|
| 数字钥匙 | 安全存储车钥匙凭证，执行认证协议 |
| V2X安全 | V2X消息的签名和验证 |
| 车内支付 | 支付密钥存储和交易处理 |
| 生物识别 | 人脸/指纹数据处理和存储 |
| 数据加密 | 敏感数据的加密解密 |
| 安全启动 | 启动过程中的验证逻辑 |
| 密钥管理 | 车辆密钥的生成、存储和更新 |

#### 5.2.2 主流TEE方案

| 方案 | 厂商 | 特点 |
|------|------|------|
| TrustZone | ARM | 硬件隔离，广泛使用 |
| QNX Safe Kernel | 黑莓 | 安全微内核，车规级 |
| OP-TEE | Linaro | 开源，ARM TrustZone上实现 |
| Trusty | Google | Android系统配套 |
| T6 / i.MX | NXP | 车载芯片内置安全模块 |

### 5.3 安全元件（SE）

**SE（Secure Element）** 是独立的安全芯片，提供更高的安全级别。

**特点：**
- 独立的CPU和内存
- 防物理攻击（防篡改、防侧信道）
- 安全存储密钥
- 硬件加密加速
- 通过高等级安全认证（如CC EAL5+）

**车载应用：**
- eSIM安全
- 数字钥匙安全
- V2X安全证书存储
- 支付安全
