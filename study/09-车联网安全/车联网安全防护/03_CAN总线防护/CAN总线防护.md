# CAN总线防护

### 3.1 CAN总线安全方案概览

| 方案 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| 入侵检测（IDS） | 监控异常行为 | 部署简单，不影响正常通信 | 只能检测，不能阻止 |
| 入侵防御（IPS） | 过滤恶意报文 | 可主动阻止攻击 | 误判可能影响正常功能 |
| 报文认证（MAC） | 附加认证码验证报文 | 从根源防止伪造 | 增加开销，需要密钥管理 |
| 报文加密 | 加密数据内容 | 防止嗅探和数据泄露 | 增加延迟，ECU负载大 |
| 安全网关 | 域间隔离与过滤 | 保护关键域 | 网关自身成为目标 |
| 总线监控 | 集中监控总线状态 | 全局视角 | 无法阻止攻击 |

### 3.2 CAN报文认证

#### 3.2.1 认证原理

在CAN报文中附加消息认证码（MAC），接收方验证MAC的正确性，确保报文来自合法节点且未被篡改。

```
发送方:
  原始报文: [ID | 数据]
  计算MAC: MAC = AES-CMAC(密钥, ID + 数据 + 新鲜值)
  发送: [ID | 数据 | MAC]

接收方:
  收到报文: [ID | 数据 | MAC]
  计算MAC: MAC' = AES-CMAC(密钥, ID + 数据 + 新鲜值)
  验证: MAC == MAC' ? 合法 : 丢弃
```

#### 3.2.2 新鲜值（Freshness Value）

**作用：** 防止重放攻击。

**实现方式：**
- **计数器方式**：每个报文包含递增的计数器
- **时间戳方式**：使用同步的时间戳
- **随机数方式**：每次使用新的随机数

**计数器方式的问题：**
- 需要同步计数器值
- 计数器溢出处理
- 丢包时的处理

#### 3.2.3 常见CAN认证方案

**1. CANAuth（CAN Authentication）**
- 基于分组密码的认证方案
- 使用CMAC生成认证码
- 支持新鲜值计数器

**2. VeCure（Vehicle Security）**
- 提供认证和加密
- 适用于CAN和FlexRay

**3. SecOC（Secure On-board Communication）**
- AUTOSAR标准中的安全通信方案
- 使用CMAC进行报文认证
- 支持新鲜值管理
- 已成为行业主流方案

**4. CANsec（CAN Security Protocol）**
- 由CAN总线创始公司Bosch等推动
- 提供认证和可选加密
- 兼容CAN FD

#### 3.2.4 SecOC详解（AUTOSAR标准）

**SecOC（Secure On-board Communication）** 是AUTOSAR标准定义的车载安全通信方案。

**核心组件：**
```
┌─────────────────────────────────────────┐
│          应用层（SWC）                    │
├─────────────────────────────────────────┤
│          PDU Router                     │
├─────────────────────────────────────────┤
│          SecOC模块                       │
│  ┌─────────┐  ┌──────────┐  ┌────────┐ │
│  │ 认证/验证│  │ 新鲜值管理│  │密钥管理 │ │
│  └─────────┘  └──────────┘  └────────┘ │
├─────────────────────────────────────────┤
│          CAN/LIN/以太网                  │
└─────────────────────────────────────────┘
```

**认证数据（Authenticator）：**
- 通常使用CMAC（Cipher-based MAC）
- MAC长度可配置（8位、16位、32位、64位等）
- 权衡：MAC越长越安全，但占用数据空间越大

**新鲜值管理：**
- 发送方维护计数器，每次发送递增
- 接收方维护期望的计数器值
- 收到的计数器必须大于期望值（防止重放）
- 支持计数器同步机制

**数据截断：**
- CAN数据场只有8字节（CAN FD 64字节）
- 认证数据需要占用部分数据空间
- 可配置认证数据的长度和位置
- 有时需要将认证数据放在单独的报文中

### 3.3 CAN总线加密

#### 3.3.1 加密的挑战

- **带宽限制**：CAN 8字节数据，加密后数据膨胀
- **实时性要求**：加密解密需要计算时间
- **资源限制**：低端ECU算力不足
- **密钥管理**：多节点密钥分发和更新困难
- **向后兼容**：不能影响现有ECU的正常工作

#### 3.3.2 适用场景

CAN加密通常不用于所有报文，只保护敏感报文：
- 安全相关的控制指令
- 敏感数据（如位置、个人信息）
- 诊断通信
- 固件更新

### 3.4 入侵检测与防御系统（IDPS）

#### 3.4.1 CAN IDS/IPS部署位置

```
                    ┌──────────┐
                    │ 安全网关  │  ← 集中式IDPS，全局监控
                    └────┬─────┘
         ┌───────────────┼───────────────┐
    ┌────▼────┐     ┌───▼───┐      ┌────▼────┐
    │  动力域  │     │ 车身域 │      │ 信息域  │
    └────┬────┘     └───┬───┘      └────┬────┘
         │              │               │
    ┌────▼────┐    ┌────▼────┐     ┌───▼─────┐
    │关键ECU  │    │ 普通ECU │     │  IVI    │
    │内置IDS  │    │         │     │         │
    └─────────┘    └─────────┘     └─────────┘
```

**集中式部署（网关）：**
- 优点：全局视角，统一管理
- 缺点：网关性能瓶颈，单点故障

**分布式部署（各ECU）：**
- 优点：就近检测，响应快
- 缺点：资源占用大，管理复杂

**混合部署：**
- 关键ECU本地检测 + 网关集中监控
- 兼顾性能和安全

#### 3.4.2 检测技术对比

| 检测方法 | 原理 | 可检测的攻击 | 误报率 | 实现难度 |
|---------|------|-------------|--------|---------|
| 频率/周期检测 | 监控报文发送频率 | 洪泛DoS、异常注入 | 低 | 低 |
| 未知ID检测 | 检测白名单外的ID | 未知报文注入 | 低 | 很低 |
| 数据范围检测 | 检查信号值是否在合法范围 | 数据伪造 | 中 | 中 |
| 数据跳变检测 | 检查信号变化速率 | 数据篡改 | 中 | 中 |
| 时钟指纹检测 | 基于ECU时钟偏移识别身份 | 报文伪造 | 低 | 高 |
| 基于规则检测 | 预定义安全规则 | 已知攻击 | 低 | 中 |
| 机器学习检测 | AI模型检测异常 | 未知攻击 | 中高 | 高 |

#### 3.4.3 响应策略

| 响应级别 | 动作 | 适用场景 |
|---------|------|---------|
| 日志记录 | 记录异常事件 | 低风险异常 |
| 告警上报 | 上报网关/云端 | 中等风险 |
| 报文过滤 | 丢弃恶意报文 | 明确的攻击 |
| 速率限制 | 限制异常ID的发送速率 | 洪泛攻击 |
| 总线隔离 | 断开受影响的网段 | 严重攻击 |
| 功能降级 | 进入安全运行模式 | 影响安全功能 |
| 安全停车 | 控制车辆安全停下 | 危及驾驶安全 |

### 3.5 安全网关

#### 3.5.1 安全网关的作用

安全网关是车载网络的"安全枢纽"，负责不同域之间的安全通信。

**核心功能：**
- **域间隔离**：防止一个域被攻破后渗透到其他域
- **报文过滤**：基于白名单/黑名单过滤跨域报文
- **协议转换**：不同网络协议之间的转换
- **入侵检测**：监控各域的异常行为
- **访问控制**：控制跨域访问的权限
- **安全审计**：记录跨域通信日志

#### 3.5.2 网关安全规则示例

```
规则1：信息域 → 动力域
  允许的CAN ID：0x100, 0x200 （仅仪表显示用的状态数据）
  禁止：所有控制类ID（刹车、油门、转向等）
  方向：单向（只读）

规则2：诊断接口 → 各域
  允许：诊断相关ID（0x7DF, 0x7E0~0x7EF）
  限制：需要安全访问认证
  速率：限制诊断报文的发送频率

规则3：T-Box → 各域
  允许：特定的数据采集和控制ID
  限制：需要身份认证和权限校验
  审计：所有操作记录日志
```
