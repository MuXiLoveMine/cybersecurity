# 车联网安全基础

> 本文档详细介绍车联网安全的基础知识，包括架构、协议、威胁、标准和典型安全事件。适合车联网安全初学者系统学习。

---

## 一、车联网概述与架构

### 1.1 车联网定义

**车联网（Internet of Vehicles, IoV）** 是指车辆通过车载传感器、电子控制单元（ECU）、通信模块等设备，实现车与万物（V2X）的信息交互和数据共享，以提升驾驶安全、交通效率和用户体验的综合信息系统。

**核心特征：**
- **智能化**：车辆具备感知、计算、决策能力
- **网联化**：车辆与外部网络持续连接
- **数据驱动**：海量车辆数据支撑服务优化
- **生态融合**：汽车、交通、通信、互联网多行业融合

### 1.2 端-管-云三层架构

车联网典型架构分为"端-管-云"三层，每层都有各自的安全挑战。

```
┌─────────────────────────────────────────────────────┐
│                    云平台层（Cloud）                  │
│  车云平台 | 大数据平台 | OTA平台 | 应用服务 | API服务  │
└──────────────────────────┬──────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────┐
│                    网络层（Pipe）                     │
│  4G/5G | V2X | Wi-Fi | 蓝牙 | 车载以太网 | CAN总线    │
└──────────────────────────┬──────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────┐
│                    终端层（Edge）                     │
│  ECU | IVI | T-Box | 传感器 | 智能座舱 | 自动驾驶系统  │
└─────────────────────────────────────────────────────┘
```

#### 1.2.1 端（终端层）

**组成部分：**
- **车载ECU**：发动机控制、制动控制、车身控制等
- **IVI（车载信息娱乐系统）**：中控大屏、导航、多媒体
- **T-Box（远程通信终端）**：4G/5G通信、远程控制
- **智能座舱**：仪表盘、HUD、语音交互、人脸识别
- **ADAS/自动驾驶系统**：摄像头、雷达、激光雷达、计算平台
- **传感器**：速度、温度、压力、位置等各类传感器

**安全风险特点：**
- 计算资源有限，安全机制难以部署
- 物理可接触，存在硬件攻击面
- 系统异构性强，安全标准不统一
- 生命周期长，漏洞修复困难

#### 1.2.2 管（网络层）

**组成部分：**
- **车载内部网络**：CAN / CAN FD / LIN / FlexRay / MOST / 车载以太网
- **车-云通信**：4G / 5G 蜂窝网络
- **车-车/车-路通信**：V2X（C-V2X / DSRC）
- **近场通信**：蓝牙、Wi-Fi、NFC、UWB（数字钥匙）

**安全风险特点：**
- 传统车载协议（如CAN）缺乏认证加密
- 无线通信存在被窃听、干扰、欺骗风险
- 多网络互联扩大攻击面
- 实时性要求与安全机制存在矛盾

#### 1.2.3 云（平台层）

**组成部分：**
- **车云平台**：车辆管理、用户管理、数据采集
- **OTA平台**：固件升级管理
- **大数据平台**：数据分析、AI训练
- **应用服务平台**：导航、音乐、支付等
- **API网关**：对外提供服务接口

**安全风险特点：**
- 传统云安全问题（漏洞、配置错误等）
- 海量车辆数据集中存储，数据泄露风险高
- API接口众多，攻击面大
- 多租户隔离风险
- 供应链安全风险

### 1.3 车联网应用场景

| 场景分类 | 具体应用 | 安全关注点 |
|---------|---------|-----------|
| 智能驾驶 | ADAS辅助驾驶、自动驾驶 | 传感器安全、决策安全、控制安全 |
| 智能交通 | 车路协同、智能红绿灯、交通调度 | V2X通信安全、数据真实性 |
| 信息娱乐 | 在线导航、音乐、视频、应用商店 | 应用安全、数据隐私、系统完整性 |
| 远程服务 | 远程控制、车辆诊断、紧急救援 | 身份认证、授权控制、通信加密 |
| 车联网金融 | 车载支付、UBI保险 | 支付安全、数据隐私、欺诈防护 |
| 车队管理 | 物流车队、网约车管理 | 数据安全、位置隐私 |

## 二、车辆系统架构

### 2.1 ECU（电子控制单元）

#### 2.1.1 ECU概述

**ECU（Electronic Control Unit，电子控制单元）** 是汽车的"大脑"，负责控制车辆的各个系统。现代汽车通常包含 50~150 个 ECU。

**ECU 硬件组成：**
- **MCU（微控制器）**：核心计算单元（常见：Infineon AURIX、NXP S32、Renesas RH850）
- **存储器**：Flash（程序存储）、RAM（运行内存）、EEPROM（数据存储）
- **通信接口**：CAN / LIN / FlexRay / 以太网 收发器
- **模拟/数字接口**：传感器输入、执行器输出
- **电源管理**：稳压、休眠/唤醒控制

**ECU 软件组成：**
- **Bootloader**：启动引导程序，负责固件更新
- **RTOS（实时操作系统）**：AUTOSAR OS、FreeRTOS、μC/OS等
- **应用层软件**：具体控制逻辑
- **通信协议栈**：CAN/LIN协议栈、诊断协议栈

#### 2.1.2 典型ECU分类

| ECU类型 | 功能 | 所属域 | 安全等级 |
|---------|------|--------|---------|
| ECM（发动机控制模块） | 控制燃油喷射、点火等 | 动力域 | ASIL D |
| BCM（车身控制模块） | 控制车灯、门锁、车窗等 | 车身域 | ASIL B |
| ABS/ESC | 防抱死制动、车身稳定控制 | 底盘域 | ASIL D |
| EPS（电动助力转向） | 转向助力控制 | 底盘域 | ASIL D |
| SRS（安全气囊） | 碰撞检测与气囊触发 | 车身域 | ASIL D |
| TCM（变速箱控制） | 自动变速箱控制 | 动力域 | ASIL C |
| IC（仪表盘） | 仪表显示、报警提示 | 座舱域 | ASIL B |
| ADAS ECU | 高级驾驶辅助 | 自动驾驶域 | ASIL B/D |

#### 2.1.3 ECU安全风险

**常见安全漏洞：**
1. **固件漏洞**：缓冲区溢出、整数溢出、命令注入
2. **调试接口未关闭**：JTAG、SWD、UART等调试接口暴露
3. **固件未加密**：可直接读取Flash提取固件
4. **缺乏安全启动**：可刷入恶意固件
5. **认证机制薄弱**：诊断服务缺少身份认证
6. **硬编码密钥**：密钥、密码硬编码在固件中

**案例：** 2015年，研究人员发现特斯拉Model S的车载网关存在漏洞，攻击者可通过CAN总线注入恶意报文控制车辆。

### 2.2 CAN总线

#### 2.2.1 CAN总线概述

**CAN（Controller Area Network，控制器局域网）** 是由博世公司于1986年开发的串行通信协议，是目前汽车中最主要的车载网络。

**CAN总线特点：**
- **多主架构**：任何节点都可主动发送消息
- **广播通信**：所有节点都能收到总线上的消息
- **基于优先级的仲裁**：通过ID优先级解决总线冲突
- **差分信号传输**：抗干扰能力强
- **错误检测与处理**：CRC校验、错误帧机制
- **缺乏安全机制**：无认证、无加密

#### 2.2.2 CAN在汽车中的应用

现代汽车通常有多条CAN总线，按功能和速率划分：

```
                    ┌─────────────┐
                    │   网关 ECU  │
                    └──┬───┬───┬──┘
                       │   │   │
          ┌────────────┘   │   └────────────┐
          ▼                ▼                ▼
    ┌──────────┐    ┌──────────┐    ┌──────────┐
    │ 动力CAN  │    │ 车身CAN  │    │ 信息CAN  │
    │ 500kbps  │    │ 125kbps  │    │ 250kbps  │
    └────┬─────┘    └────┬─────┘    └────┬─────┘
         │                │                │
    ┌────┴────┐      ┌────┴────┐      ┌───┴────┐
    │  ECM    │      │  BCM    │      │  IVI   │
    │  TCM    │      │  门锁   │      │  导航   │
    │  ABS    │      │  车灯   │      │  娱乐   │
    └─────────┘      └─────────┘      └────────┘
```

### 2.3 车载网关

#### 2.3.1 网关的作用

**车载网关（Gateway）** 是连接不同车载网络的核心设备，负责协议转换和数据转发。

**核心功能：**
- **协议转换**：CAN ↔ LIN ↔ FlexRay ↔ 以太网
- **报文路由**：根据ID和内容转发报文
- **信号聚合**：汇总各总线数据供上层使用
- **诊断路由**：统一诊断入口，转发诊断请求
- **安全防护**：防火墙、入侵检测（新一代网关）

#### 2.3.2 网关安全意义

网关是车载网络的"交通枢纽"，也是安全防护的关键节点：
- **攻击跳板**：攻破信息域后，可通过网关渗透到动力域
- **防护核心**：在网关部署防火墙/IDS可有效隔离攻击
- **安全瓶颈**：网关一旦被控制，全车网络沦陷

**案例：** Jeep Cherokee 事件中，攻击者通过Uconnect娱乐系统进入信息CAN，再通过网关转发恶意报文到动力CAN，实现远程控制。

### 2.4 IVI（车载信息娱乐系统）

#### 2.4.1 IVI系统架构

**IVI（In-Vehicle Infotainment）** 是车载信息娱乐系统，是用户接触最多的车载系统。

```
┌─────────────────────────────────────────┐
│              应用层                      │
│  导航 | 音乐 | 视频 | 蓝牙电话 | 应用商店 │
├─────────────────────────────────────────┤
│              系统层                      │
│  Android Automotive / QNX / Linux / 自研 │
├─────────────────────────────────────────┤
│              服务层                      │
│  蓝牙协议栈 | Wi-Fi | 4G模块 | CAN接口   │
├─────────────────────────────────────────┤
│              硬件层                      │
│  SoC | 显示屏 | 触控 | 麦克风 | 摄像头   │
└─────────────────────────────────────────┘
```

#### 2.4.2 常见IVI系统

| 系统 | 厂商 | 特点 | 代表车型 |
|------|------|------|---------|
| Android Automotive | Google | 开源、生态丰富、安全机制完善 | 沃尔沃、雷诺、极星 |
| QNX | 黑莓 | 安全可靠、通过ISO 26262认证 | 宝马、奔驰、奥迪 |
| Linux（AGL） | 汽车级Linux联盟 | 开源、可定制 | 丰田、马自达 |
| 自研系统 | 各车企 | 深度定制、差异化 | 特斯拉、比亚迪、蔚来 |

#### 2.4.3 IVI安全风险

1. **系统漏洞**：操作系统本身的漏洞（如Linux内核漏洞）
2. **应用漏洞**：第三方应用存在安全问题
3. **恶意应用**：应用商店审核不严导致恶意APP进入
4. **供应链攻击**：第三方SDK、组件存在后门
5. **蓝牙/Wi-Fi攻击**：通过无线接口远程入侵
6. **数据泄露**：通讯录、行驶轨迹、语音数据泄露
7. **提权漏洞**：从普通应用提权到系统权限

### 2.5 T-Box（远程通信终端）

#### 2.5.1 T-Box概述

**T-Box（Telematics Box）** 是车辆与云端通信的核心设备，是车联网的"通信枢纽"。

**主要功能：**
- **远程控制**：远程启动、开闭锁、空调控制
- **数据采集**：车辆状态、行驶数据、位置信息
- **OTA升级**：接收云端推送的固件更新
- **紧急救援**：碰撞自动求助、道路救援
- **WiFi热点**：为车内提供无线网络
- **定位服务**：GPS/北斗定位

#### 2.5.2 T-Box硬件架构

```
┌─────────────────────────────────┐
│         通信模块                 │
│  4G/5G模组 | GPS/北斗 | WiFi/BT │
├─────────────────────────────────┤
│         主控单元                 │
│  MCU/SoC | Flash | RAM | SIM卡  │
├─────────────────────────────────┤
│         车辆接口                 │
│  CAN总线 | OBD | 电源管理        │
└─────────────────────────────────┘
```

#### 2.5.3 T-Box安全重要性

T-Box是车辆的"远程入口"，安全至关重要：
- **直接联网**：暴露在公网，面临远程攻击
- **权限高**：可直接向CAN总线发送报文
- **数据多**：掌握大量车辆和用户数据
- **OTA入口**：被攻破可下发恶意固件

**案例：** 2020年，某品牌T-Box被发现存在未授权访问漏洞，攻击者可远程控制车辆的门锁、启动等功能，涉及数十万辆汽车。

## 三、车联网通信协议

### 3.1 CAN / CAN FD

#### 3.1.1 标准CAN

- **速率**：最高1Mbps（典型500kbps）
- **数据长度**：0~8字节
- **帧格式**：标准帧（11位ID）、扩展帧（29位ID）
- **应用场景**：动力系统、车身系统、底盘系统

#### 3.1.2 CAN FD

- **全称**：CAN with Flexible Data Rate
- **速率**：仲裁段最高1Mbps，数据段最高8Mbps
- **数据长度**：0~64字节
- **兼容性**：向后兼容标准CAN
- **应用场景**：需要更高带宽的场景（如ADAS数据传输）

### 3.2 LIN（本地互联网络）

**LIN（Local Interconnect Network）** 是低成本的串行通信协议，用于非关键的车身电子系统。

**特点：**
- **速率**：最高20kbps
- **拓扑**：单主多从（1个主节点，最多16个从节点）
- **成本**：极低（单线传输，无需晶振）
- **应用**：车窗、座椅、后视镜、雨刮等简单控制

**安全考量：** LIN总线安全性更低，但通常控制非安全相关功能。

### 3.3 FlexRay

**FlexRay** 是高速、确定性的车载网络协议，用于安全相关的实时系统。

**特点：**
- **速率**：最高10Mbps（双通道）
- **拓扑**：总线型或星型
- **确定性**：时间触发机制，保证实时性
- **冗余**：支持双通道冗余
- **应用**：线控系统（X-by-Wire）、主动悬架、ADAS

**现状：** 因成本较高，逐渐被车载以太网取代。

### 3.4 MOST（媒体导向系统传输）

**MOST（Media Oriented Systems Transport）** 是面向多媒体的车载网络。

**特点：**
- **速率**：MOST25（25Mbps）、MOST50（50Mbps）、MOST150（150Mbps）
- **拓扑**：环形结构
- **应用**：车载音响、视频、导航等多媒体系统
- **现状**：逐渐被车载以太网取代

### 3.5 车载以太网

**车载以太网** 是基于IEEE 802.3标准的车载高速网络，是未来的发展方向。

**特点：**
- **速率**：100Mbps（100BASE-T1）、1Gbps（1000BASE-T1）、10Gbps
- **单对线传输**：使用非屏蔽双绞线，减轻重量
- **IP化**：支持TCP/IP协议栈
- **应用**：智能座舱、ADAS、OTA升级、诊断

**常用协议：**
- **SOME/IP**：面向服务的中间件协议
- **DoIP**：基于IP的诊断协议（Diagnostics over IP）
- **AVB/TSN**：音视频桥接/时间敏感网络
- **PTP**：精确时间协议

**安全挑战：**
- 传统IT网络安全问题全部引入车载场景
- 与CAN等传统网络的网关安全
- 实时性与安全的平衡
- 协议复杂度高，攻击面大

### 3.6 车载无线通信

| 无线技术 | 速率 | 距离 | 应用场景 | 安全风险 |
|---------|------|------|---------|---------|
| 蓝牙BLE | ~1Mbps | ~10m | 车钥匙、手机互联 | 嗅探、配对攻击 |
| Wi-Fi | 数百Mbps | ~50m | 车内热点、OTA | 中间人、漏洞利用 |
| 4G/5G | 10Mbps~1Gbps+ | 广域 | 车云通信 | 伪基站、协议漏洞 |
| UWB | ~10Mbps | ~10m | 数字钥匙 | 中继攻击 |
| NFC | ~424kbps | ~10cm | 车钥匙、支付 | 窃听、篡改 |
| V2X | ~27Mbps | ~300m | 车车/车路通信 | 消息伪造、重放 |

## 四、车联网安全威胁与挑战

### 4.1 威胁模型

#### 4.1.1 攻击面分析

```
                    攻击面由内向外扩展
┌─────────────────────────────────────────────┐
│  物理攻击面  │  近场攻击面  │  远程攻击面    │
│             │             │               │
│  OBD接口    │  蓝牙       │  4G/5G        │
│  USB接口    │  Wi-Fi      │  V2X          │
│  拆解芯片   │  车钥匙     │  云平台API     │
│  调试接口   │  NFC        │  移动APP       │
│  JTAG/SWD   │  UWB        │  OTA服务器     │
└─────────────────────────────────────────────┘
```

#### 4.1.2 攻击者分类

| 攻击者类型 | 能力 | 动机 | 典型攻击 |
|-----------|------|------|---------|
| 脚本小子 | 使用公开工具 | 炫耀、恶作剧 | 复制车钥匙、OBD恶作剧 |
| 黑客爱好者 | 一定技术能力 | 兴趣、研究 | 破解IVI、刷固件 |
| 专业研究员 | 深厚技术功底 | 漏洞研究、赏金 | 发现重大安全漏洞 |
| 犯罪团伙 | 组织化、专业化 | 经济利益 | 偷车、数据贩卖、勒索 |
| 国家级APT | 资源充足、持久化 | 情报、破坏 | 供应链攻击、基础设施破坏 |

### 4.2 主要安全威胁

#### 4.2.1 远程控制威胁

**描述：** 攻击者通过远程方式控制车辆的关键功能，如刹车、油门、转向等。

**攻击路径：**
1. 通过4G/5G网络入侵T-Box
2. 控制T-Box向CAN总线注入恶意报文
3. 通过网关渗透到动力域CAN
4. 发送伪造的控制指令实现远程操控

**危害程度：** 极高（直接威胁人身安全）

#### 4.2.2 数据泄露威胁

**描述：** 车辆数据（位置轨迹、驾驶习惯、车内语音、个人信息等）被非法获取。

**泄露途径：**
- 云平台数据库泄露
- T-Box通信数据被窃听
- IVI系统恶意应用窃取
- 车辆维修/保养时的数据泄露

**危害程度：** 高（隐私侵犯、数据贩卖）

#### 4.2.3 固件篡改威胁

**描述：** 攻击者篡改车辆ECU固件，植入后门或恶意逻辑。

**攻击方式：**
- 利用OTA漏洞注入恶意固件
- 物理接触刷写恶意固件
- 通过诊断接口刷写固件

**危害程度：** 极高（持久化控制、功能破坏）

#### 4.2.4 拒绝服务威胁

**描述：** 攻击者使车辆系统或功能无法正常工作。

**攻击方式：**
- CAN总线洪泛攻击（占用总线带宽）
- 发送大量错误帧（导致总线关闭）
- 耗尽系统资源（CPU、内存）

**危害程度：** 中高（功能失效、影响驾驶）

#### 4.2.5 供应链威胁

**描述：** 通过攻击供应链环节（零部件、软件组件、第三方服务）植入威胁。

**攻击点：**
- ECU供应商的软件开发
- 第三方SDK和库
- OTA服务提供商
- 云服务供应商
- 维修诊断设备

**危害程度：** 极高（影响面广、隐蔽性强）

### 4.3 车联网安全挑战

#### 4.3.1 安全与功能的平衡

- **实时性要求**：CAN报文要求微秒级响应，加密认证会增加延迟
- **资源受限**：ECU算力和内存有限，难以部署复杂安全机制
- **可靠性要求**：安全机制不能影响车辆正常功能

#### 4.3.2 生命周期挑战

- **使用周期长**：汽车使用寿命通常10~15年
- **更新困难**：大量存量车辆无法及时修复漏洞
- **零部件供应周期**：ECU等零部件供货周期长

#### 4.3.3 复杂性挑战

- **ECU数量多**：50~150个ECU，来自不同供应商
- **协议异构**：多种总线协议并存
- **软件代码量**：高端汽车代码量超过1亿行
- **供应链复杂**：涉及数百家供应商

#### 4.3.4 法规与标准挑战

- 各地区法规要求不同（欧盟、中国、美国）
- 标准更新快，合规成本高
- 跨国车企需同时满足多地区要求

## 五、车联网安全标准

### 5.1 国际标准

#### 5.1.1 ISO/SAE 21434

**全称：** ISO/SAE 21434:2021 Road vehicles — Cybersecurity engineering

**定位：** 汽车网络安全工程的核心标准，规定了汽车全生命周期的网络安全要求。

**核心内容：**

| 章节 | 内容 | 说明 |
|------|------|------|
| 第5章 | 组织层面网络安全管理 | 建立CSMS（网络安全管理体系） |
| 第6章 | 项目层面网络安全管理 | 项目中的网络安全活动 |
| 第7章 | 持续网络安全活动 | 漏洞管理、事件响应等 |
| 第8章 | 风险评估方法 | 威胁分析与风险评估（TARA） |
| 第9章 | 概念阶段 | 网络安全概念、目标定义 |
| 第10章 | 产品开发 | 系统/硬件/软件层面的安全要求 |
| 第11章 | 生产与运营 | 生产安全、运维安全 |
| 第12章 | 报废阶段 | 报废时的安全处理 |

**TARA（威胁分析与风险评估）方法：**
1. **资产识别**：识别需要保护的资产
2. **威胁场景**：识别潜在的威胁场景
3. **影响评级**：评估安全事件的影响（安全、财产、运营、隐私）
4. **攻击路径分析**：分析攻击可行性
5. **风险确定**：综合影响和可行性确定风险等级
6. **风险处置**：制定风险缓解措施

#### 5.1.2 ISO 26262

**全称：** ISO 26262 Road vehicles — Functional safety

**定位：** 汽车功能安全标准，确保电子系统在故障情况下仍能安全运行。

**ASIL（汽车安全完整性等级）：**

| 等级 | 风险程度 | 典型应用 |
|------|---------|---------|
| ASIL D | 最严重 | 制动系统、转向系统、安全气囊 |
| ASIL C | 严重 | 变速箱控制、灯光控制 |
| ASIL B | 中等 | 仪表盘、车灯 |
| ASIL A | 轻微 | 后视镜调节 |
| QM | 无特殊要求 | 娱乐系统、导航 |

**与网络安全的关系：**
- 功能安全关注随机故障，网络安全关注人为攻击
- 两者相辅相成，共同保障车辆安全
- ISO 21434与ISO 26262在开发流程上有对应关系

#### 5.1.3 ISO 21448 (SOTIF)

**全称：** ISO 21448 Road vehicles — Safety of the Intended Functionality

**定位：** 预期功能安全，关注系统在没有故障情况下的安全问题（如感知局限、误用等）。

**主要应用：** ADAS和自动驾驶系统。

#### 5.1.4 UNECE R155 & R156

**UN R155 — 网络安全管理体系（CSMS）：**
- 要求车企建立网络安全管理体系
- 覆盖车辆全生命周期
- 需通过型式认证
- 2022年7月起在欧盟强制实施

**UN R156 — 软件更新管理体系（SUMS）：**
- 要求车企建立软件更新管理体系
- 确保OTA更新的安全性
- 需记录更新过程和版本信息
- 防止降级攻击

**实施意义：** 是汽车网络安全合规的强制性要求，未通过认证的车型无法在欧盟销售。

#### 5.1.5 SAE J3061

**全称：** SAE J3061 Cybersecurity Guidebook for Cyber-Physical Vehicle Systems

**定位：** 汽车网络安全指南，提供汽车网络安全的最佳实践。

**核心内容：**
- 网络安全生命周期
- 威胁分析方法
- 安全设计原则
- 验证与确认方法

## 六、著名车联网安全事件

### 6.1 Jeep Cherokee 远程破解事件（2015）

#### 事件概述

2015年，安全研究员Charlie Miller和Chris Valasek公开了对Jeep Cherokee的远程攻击研究，震惊了整个汽车行业。

#### 攻击过程

```
① 攻击入口：Uconnect车载娱乐系统（3G蜂窝网络连接）
   ↓
② 发现Uconnect系统存在远程代码执行漏洞
   ↓
③ 通过漏洞获取IVI系统控制权
   ↓
④ 利用车载网关将恶意报文转发到动力CAN总线
   ↓
⑤ 发送伪造的控制指令，实现：
   - 控制转向（低速时）
   - 控制刹车
   - 控制油门
   - 禁用刹车
```

#### 技术细节

1. **入口点**：Uconnect系统的3G模块分配了公网IP，且开放了6667端口
2. **漏洞利用**：通过缓冲区溢出漏洞获得系统权限
3. **CAN注入**：通过车载系统的CAN接口发送恶意报文
4. **影响范围**：2013-2015款Jeep Cherokee、Chrysler 200等车型，约140万辆

#### 事件影响

- **FCA（菲亚特克莱斯勒）** 宣布召回140万辆车进行软件升级
- 成为汽车网络安全的标志性事件
- 推动了汽车行业对网络安全的重视
- 促成了UNECE R155/R156等法规的制定

### 6.2 特斯拉破解事件系列

#### 6.2.1 2014年 Nitesh Dhanjani 研究

- 发现特斯拉Model S的移动APP存在安全漏洞
- 可通过API获取车辆位置信息
- 可远程控制车辆功能

#### 6.2.2 2016年 Keen Team（腾讯科恩实验室）

- 通过浏览器漏洞攻破特斯拉Model S车载系统
- 实现了行驶中远程刹车
- 获得特斯拉官方认可和致谢
- 是国内团队首次成功破解特斯拉

#### 6.2.3 2018年 Keen Team 再次破解

- 发现特斯拉Autopilot的视觉感知漏洞
- 通过投影特定图案可诱导Autopilot驶入对向车道
- 展示了自动驾驶系统的安全脆弱性

#### 6.2.4 2023年 自动驾驶系统漏洞

- 多个研究团队发现特斯拉FSD存在安全漏洞
- 对抗样本攻击可导致自动驾驶误判
- 传感器欺骗攻击可干扰自动驾驶决策

### 6.3 通用汽车OnStar漏洞（2015）

#### 事件概述

安全研究员Samy Kamkar发现通用汽车的OnStar系统存在漏洞，可远程控制车辆。

#### 攻击方式

- 利用OnStar的远程通信协议漏洞
- 可远程解锁车门、启动车辆
- 影响数百万辆通用汽车

#### 事件结果

- 通用汽车修复了相关漏洞
- 加强了远程控制的身份认证

### 6.4 宝马ConnectedDrive漏洞（2015）

#### 事件概述

德国ADAC汽车协会发现宝马ConnectedDrive系统存在安全漏洞。

#### 漏洞详情

- 通过蜂窝网络可远程解锁车辆
- 攻击需要知道车辆的VIN码
- 影响宝马、MINI、劳斯莱斯等品牌车型

#### 修复措施

- 宝马通过OTA推送了安全更新
- 加强了身份验证机制

### 6.5 比亚迪云服务漏洞（2017）

#### 事件概述

安全研究员发现比亚迪云服务存在漏洞，可越权访问其他车主的车辆信息。

#### 漏洞详情

- 云服务API存在越权访问漏洞
- 可获取其他车辆的位置信息
- 可远程控制其他车辆（开闭锁、启动等）

#### 事件结果

- 比亚迪紧急修复了漏洞
- 加强了API的权限控制

### 6.6 蔚来汽车漏洞事件（2021）

#### 事件概述

安全研究人员发现蔚来汽车存在多个安全漏洞。

#### 漏洞详情

- IVI系统存在远程代码执行漏洞
- 可通过蓝牙攻击入侵车机系统
- 数据安全问题导致用户信息泄露

#### 事件结果

- 蔚来通过OTA推送了安全更新
- 加强了安全团队建设

### 6.7 丰田汽车供应链攻击（2022）

#### 事件概述

丰田汽车的供应商小岛冲压工业（Kojima Industries）遭到网络攻击，导致丰田日本全部工厂停产。

#### 事件影响

- 丰田日本14家工厂全部停工
- 单日产量损失约1.3万辆
- 暴露了汽车供应链的脆弱性

| 年份 | 事件 | 影响 | 意义 |
|------|------|------|------|

| 2015 | 宝马/通用/特斯拉漏洞 | 多款车型受影响 | 智能网联汽车安全问题集中爆发 |

| 2018 | 自动驾驶攻击演示 | 感知安全受关注 | 自动驾驶安全成新热点 |

## 七、学习要点与思考题

### 7.1 核心知识点总结

1. **三层架构**：端（终端）、管（网络）、云（平台）各有不同的安全挑战
2. **核心组件**：ECU、CAN总线、网关、IVI、T-Box是车联网的核心
3. **主要协议**：CAN是基础，车载以太网是发展方向
4. **最大威胁**：远程控制、数据泄露、固件篡改、供应链攻击
5. **核心标准**：ISO 21434是网络安全的核心标准，UNECE R155是强制法规
6. **标志性事件**：Jeep Cherokee事件是车联网安全的转折点

### 7.2 思考题

1. 为什么CAN总线设计之初没有考虑安全机制？这反映了什么设计理念的变化？
2. 为什么说网关是车载网络安全的关键节点？网关被攻破会有什么后果？
3. 车联网安全与传统IT安全最大的区别是什么？为什么不能直接照搬IT安全方案？
4. ISO 21434中的TARA方法与传统的风险评估方法有什么不同？
5. Jeep Cherokee事件为什么对行业影响这么大？它改变了什么？
