# Burp Suite 高级技巧和绕过技术

> 本文整理了 Burp Suite 的高级使用技巧、WAF 绕过方法和各种提升测试效率的技术。

## 一、WAF 绕过技术

### 1.1 检测 WAF

**方法一：手工检测**
```
1. 发送正常请求，记录响应
2. 在参数中添加 SQL 注入 payload：' OR 1=1 --
3. 对比响应：
   - 返回 403/406 → 可能有 WAF
   - 页面内容变化 → 可能有 WAF
   - 连接重置 → 可能有 WAF
   
4. 发送大量恶意请求：
   - 被拦截/封禁 → 有 WAF
```

**方法二：使用 WAF 检测工具**
```
Nmap 脚本：
nmap --script=http-waf-detect,http-waf-fingerprint -p 80 target.com

SQLMap：
sqlmap -u "http://target.com/page?id=1" --check-waf

Wafw00f：
wafw00f http://target.com
```

**方法三：Burp 插件**
```
- Wafdetector 插件
- ActiveScan++ 插件
- 手动检测响应特征
```

### 1.2 常见 WAF 指纹

### 1.3 绕过方法：大小写混淆

```
原理：WAF 规则可能是大小写敏感的

示例：
UNION SELECT → UnIoN SeLeCt
order by → OrDeR By
and 1=1 → AnD 1=1
<script> → <ScRiPt>
onerror → oNeRrOr

Burp 实现：
1. 使用 Intruder 的 Payload Processing
   Add → Case modification → ToGGLe case
   
2. 或使用 Hackvertor 插件
   <@randomcase_6>UNION SELECT</@randomcase_6>
```

### 1.4 绕过方法：URL 编码

```
原理：WAF 可能只检测原始 URL，不做解码

单层编码：
' → %27
" → %22
< → %3C
> → %3E
空格 → %20

双层编码：
' → %2527
< → %253C

Unicode 编码：
' → %u0027
< → %u003c

Burp 实现：
1. 选中内容 → Ctrl+Shift+U（URL 编码）
2. 多次编码：选中已编码内容 → 再次编码
3. 使用 Decoder 模块进行多层编码
```

### 1.5 绕过方法：注释注入

```
原理：在关键字中插入注释，绕过关键字检测

SQL 注入绕过：
UNION → U/**/NION
SELECT → SEL/**/ECT
OR 1=1 → O/**/R 1=1
空格 → /**/

XSS 绕过：
<script> → <scr<!-- -->ipt>
onerror → oner<!-- -->ror

Burp 实现：
1. Intruder Payload Processing → Match/replace
2. 用正则在关键字中插入注释
3. 使用 Hackvertor 插件自定义转换
```

### 1.6 绕过方法：特殊字符

```
SQL 注入绕过空格：
%09 (Tab)
%0a (换行)
%0d (回车)
%0c (换页)
%a0 (非断空格)
/**/ (注释)
+ (加号)
() (括号)

XSS 绕过：
/ (斜杠代替空格)
%00 (空字节)
\\ (反斜杠)
```

### 1.7 绕过方法：分块传输

```
原理：将 HTTP 请求体分成多个块传输，WAF 可能不重组

请求示例：
POST /login HTTP/1.1
Host: target.com
Transfer-Encoding: chunked
Content-Type: application/x-www-form-urlencoded

5
user=
6
admin&
4
pass=
3
123
0

Burp 实现：
1. 使用 Repeater 手动构造分块请求
2. 使用 HTTP/2 相关插件
3. 或使用 Burp 的 chunked 编码插件
```

### 1.8 绕过方法：HTTP 方法混淆

```
原理：WAF 可能只检测 GET/POST，其他方法可能绕过

GET → HEAD
POST → PUT
POST → DELETE
POST → PATCH
GET → ARBITRARY（自定义方法）

如果参数在 URL 中：
   改为 POST 方法，参数放 Body 中

如果参数在 Body 中：
   改为 GET 方法，参数放 URL 中
   
Content-Type 绕过：
   application/x-www-form-urlencoded
   → multipart/form-data
   → application/json
   → text/plain
   → application/xml
```

### 1.9 绕过方法：HTTP 参数污染

```
原理：WAF 和后端对重复参数的处理方式不同

示例：
?id=1&id=2
- WAF 可能只检测第一个 id
- 后端可能使用第二个 id

不同后端处理方式：
- PHP/Apache：使用最后一个参数
- JSP/Tomcat：使用第一个参数
- ASP/IIS：所有值都用

Burp 测试：
1. 复制参数，添加不同值
2. 观察后端使用哪个值
3. 在第二个参数中注入 payload
```

### 1.10 绕过方法：HTTP 头注入

```
原理：通过特定 HTTP Header 绕过 WAF 检测

常见 Header：
X-Forwarded-For: 127.0.0.1           # 伪装来源 IP
X-Originating-IP: 127.0.0.1
X-Remote-IP: 127.0.0.1
X-Rewrite-URL: /admin                  # 路径重写
X-Original-URL: /admin
X-Host: target.com
X-Forwarded-Host: target.com

测试 WAF 白名单 IP：
X-Forwarded-For: 127.0.0.1
X-Forwarded-For: localhost
X-Forwarded-For: 192.168.1.1
```

## 二、Intruder 高级技巧

### 2.1 递归 Grep（Recursive Grep）

```
用途：从上一个响应中提取数据，作为下一个请求的 payload

场景：
- CSRF Token 爆破（需要从页面提取 Token）
- 分页遍历（从响应中获取下一页 ID）
- 会话续传

使用方法：
1. Attack type: Recursive grep
2. 初始 payload：第一个值
3. 设置 Grep - Extract 提取规则
4. 提取的数据作为下一次请求的 payload
```

### 2.2 Grep - Extract 高级用法

```
用途：从响应中提取特定数据，显示在结果列表中

配置步骤：
1. Options → Grep - Extract
2. 勾选 "Extract the following information from responses"
3. 点击 Add
4. 在响应中选中要提取的内容
5. 自动生成正则表达式
6. 结果列表中会新增一列

应用场景：
- 提取 CSRF Token
- 提取用户 ID / 用户名
- 提取响应中的错误信息
- 提取 API 返回的关键字段
- 批量提取数据
```

### 2.3 Grep - Match 高级用法

```
用途：在响应中匹配特定关键词，标记匹配的请求

配置步骤：
1. Options → Grep - Match
2. 添加要匹配的关键词
3. 结果列表中会显示匹配数量

常用匹配项：
- "error" / "错误" → 错误信息
- "password" → 密码相关
- "admin" → 管理员
- "success" → 成功标志
- "token" → Token
```

### 2.4 重定向处理

```
Options → Redirections：

1. Follow redirections：
   - Never：不跟随（默认）
   - On-site only：只跟随站内
   - Always：总是跟随

2. Process cookies in redirections：
   - 处理重定向中的 Cookie

3. 应用场景：
   - 登录后 302 跳转 → 跟随查看跳转后页面
   - 判断登录是否成功
```

### 2.5 竞态条件测试（Race Condition）

```
用途：测试并发请求下的逻辑漏洞

操作步骤：
1. 发送请求到 Intruder
2. 设置一个无用的 payload 位置（空格等）
3. Payload type: Null payloads
4. Generate: 选择数量（如 100）
5. Options → Request Engine：
   - Number of threads: 50 (或更高)
   - Pause between requests: 0
6. Start attack
7. 观察是否有竞态漏洞

常见场景：
- 优惠券重复使用
- 抽奖多次中奖
- 提现多次到账
- 投票刷票
- 库存超卖
```

### 2.6 Payload Processing 链式处理

```
可以添加多个处理规则，按顺序执行：

示例：生成 Base64 编码的 MD5 密码
1. Add prefix → （无前缀）
2. Hash → MD5
3. Encode → Base64
4. Add suffix → （无后缀）

示例：URL 编码 + 大小写混淆
1. Case modification → ToGGLe case
2. Encode → URL-encode key characters

示例：多重编码
1. Encode → URL-encode
2. Encode → URL-encode again（双层编码）
```

            # 处理代理请求
            pass

### 4.2 自定义 Scanner 检查（BChecks）

## 六、流量处理技巧

### 6.1 Match and Replace 高级用法

```
添加自定义替换规则：

Proxy settings → Match and Replace

常见规则：

1. 添加自定义 Header：
   Match: (空)
   Replace: X-Forwarded-For: 127.0.0.1
   Type: Request header

2. 修改 User-Agent：
   Match: User-Agent:.*
   Replace: User-Agent: CustomBot/1.0
   Type: Request header

3. 添加 Cookie：
   Match: Cookie: (.*)
   Replace: Cookie: test=1; $1
   Type: Request header

4. 修改响应头：
   Match: X-Frame-Options:.*
   Replace: (空)
   Type: Response header
   （移除 X-Frame-Options 头）

5. 修改响应内容：
   Match: <script src="analytics.js">
   Replace: <!-- <script src="analytics.js"> -->
   Type: Response body
```

### 6.2 SSL Pass Through

```
用途：跳过指定 HTTPS 站点的拦截/解密

配置：
Proxy settings → TLS Pass Through

场景：
- 某些 App 有证书固定（Pinning），无法解密
- 某些网站使用客户端证书认证
- 不想影响某些站点的正常访问
```

### 6.3 WebSocket 拦截规则

```
Burp 支持 WebSocket 拦截和修改：

Proxy → WebSockets history：
- 查看所有 WebSocket 消息历史
- 过滤特定消息
- 发送到 Repeater 重放

Intercept WebSocket messages：
- 拦截 WebSocket 消息
- 修改后转发
- 或丢弃消息
```

## 九、实战绕过组合拳

### 9.1 SQL 注入 WAF 绕过组合

```
组合一：大小写 + 注释 + URL编码
   原始：UNION SELECT 1,2,3--
   绕过：UnIoN/**/SeLeCt%201,2,3--

组合二：双层编码 + 特殊字符
   原始：' OR 1=1--
   绕过：%2527%20Or%201=1--

组合三：分块传输 + 注释
   使用 Transfer-Encoding: chunked
   将 Payload 分散到多个块中

组合四：参数污染
   ?id=1&id=1' UNION SELECT...
```

### 9.2 XSS WAF 绕过组合

```
组合一：事件 + 编码
   <img src=x onerror="alert(1)">
   → <IMG SRC=x ONERROR=&#97;lert(1)>

组合二：标签 + 伪协议
   <script>alert(1)</script>
   → <svg/onload=alert(1)>
   → <body onpageshow=alert(1)>

组合三：HTML 实体 + 事件
   onerror=alert(1)
   → onerror=&#97;&#108;&#101;&#114;&#116;(1)
```
