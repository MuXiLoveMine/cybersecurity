## 1. 代码审计概述

### 1.1 白盒测试 vs 黑盒测试

| 维度 | 白盒测试（代码审计） | 黑盒测试（渗透测试） |
|------|----------------------|----------------------|
| 信息可见性 | 拥有完整源代码 | 仅了解外部接口 |
| 覆盖深度 | 可发现逻辑层深层漏洞 | 受限于输入覆盖率 |
| 误报率 | 较高，需人工确认 | 较低，已验证可利用 |
| 适用阶段 | 开发期 / 上线前 | 上线后 / 验收期 |
| 典型工具 | SonarQube、CodeQL | Burp Suite、AWVS |

实际项目中两者互补：代码审计定位"问题在哪里"，渗透测试验证"能否利用"。

### 1.2 代码审计方法论

**自顶向下（Top-Down）**：从入口点（路由、Controller）出发，跟踪用户输入流经的数据流，直至到达 Sink（危险函数）。适合审计结构清晰的大型框架应用。

**自底向上（Bottom-Up）**：先搜索所有危险函数调用点（Sink），再反向追溯参数来源是否可控。适合快速扫描，容易发现高危漏洞但覆盖面有限。

**关注点驱动（Concern-Driven）**：针对特定漏洞类型（如 SQL 注入、反序列化）在整个代码库中搜索相关模式，适合专项安全评估。

实际审计中三者常组合使用：先用自底向上快速定位高危 Sink，再用自顶向下深入追踪数据流，最后用关注点驱动做专项查漏。

### 1.3 代码审计流程

```
信息收集 → 威胁建模 → 代码审查 → 漏洞验证 → 报告输出
```

| 阶段 | 关键动作 |
|------|----------|
| 信息收集 | 确定技术栈、框架版本、第三方依赖；梳理路由表与功能模块 |
| 威胁建模 | 绘制数据流图（DFD），标注信任边界，识别高风险入口点 |
| 代码审查 | 使用工具扫描 + 人工审计，追踪 Source → Sink 数据流 |
| 漏洞验证 | 搭建本地环境，构造 PoC 验证漏洞可利用性 |
| 报告输出 | 记录漏洞详情、风险评级、修复建议，跟踪修复闭环 |

### 1.4 常用代码审计工具

| 工具 | 类型 | 特点 |
|------|------|------|
| **SonarQube** | 静态分析平台 | 支持 20+ 语言，集成 CI/CD，提供质量门禁 |
| **Fortify** | 商业 SAST | 规则库丰富，支持企业级合规扫描，误报较高 |
| **CodeQL** | 语义化查询 | GitHub 出品，支持自定义 Datalog/QL 查询，精准度高 |
| **Semgrep** | 模式匹配 | 开源轻量，规则可读性强，支持多语言快速扫描 |
| **RIPS** | PHP 专用 | 针对 PHP 污点分析，对框架支持好 |

工具是辅助，核心仍在于审计人员对漏洞模式的理解与数据流追踪能力。

## 2. PHP 代码审计

### 2.1 危险函数速查

| 漏洞类型 | 危险函数 |
|----------|----------|
| 代码执行 | `eval()` `assert()` `preg_replace(/e)` `create_function()` |
| 命令执行 | `system()` `exec()` `passthru()` `shell_exec()` `popen()` `proc_open()` `` ` `` |
| 文件包含 | `include()` `require()` `include_once()` `require_once()` |
| 文件读取 | `file_get_contents()` `fread()` `fopen()` `readfile()` `show_source()` |
| 文件写入 | `file_put_contents()` `fwrite()` |
| 反序列化 | `unserialize()` |
| SQL 注入 | `mysql_query()` `mysqli_query()`（拼接 SQL 时） |

### 2.2 文件操作漏洞审计

**文件包含漏洞**

```php
// —— 漏洞代码 ——
$page = $_GET['page'];
include("templates/" . $page . ".php");  // 可包含任意文件
```

```php
// —— 修复代码 ——
$whitelist = ['index', 'about', 'contact'];
$page = $_GET['page'];
if (in_array($page, $whitelist, true)) {
    include "templates/{$page}.php";
} else {
    http_response_code(404);
    exit('非法请求');
}
```

**任意文件读取**

```php
// —— 漏洞代码 ——
echo file_get_contents($_GET['file']);  // 直接读取用户传入路径
```

```php
// —— 修复代码 ——
$base = realpath(__DIR__ . '/uploads/');
$file = realpath($base . '/' . basename($_GET['file']));
if ($file && strpos($file, $base) === 0) {
    echo file_get_contents($file);
}
```

审计要点：追踪 `$_GET/$_POST/$_REQUEST` 是否直接传入文件操作函数，关注路径拼接时是否使用 `realpath()` + 前缀校验。

### 2.3 SQL 注入审计

```php
// —— 漏洞代码：直接拼接 ——
$id = $_GET['id'];
$result = mysqli_query($conn, "SELECT * FROM users WHERE id = $id");

// —— 漏洞代码：预处理误用 ——
$stmt = $conn->prepare("SELECT * FROM users WHERE id = ?");
$stmt->bind_param("s", $_GET['id']);  // bind_param("s", ...) - 这里 bind 的是字符串
$result = $stmt->execute();
// 实际上 bind_param 的 "s" 类型对整数注入防护有限，建议使用 "i"
```

```php
// —— 修复代码：PDO 预处理 ——
$stmt = $pdo->prepare("SELECT * FROM users WHERE id = :id");
$stmt->execute([':id' => $_GET['id']]);
$result = $stmt->fetchAll(PDO::FETCH_ASSOC);
```

审计要点：全局搜索 `query(`、`execute(`，检查 SQL 语句中是否存在变量拼接；预处理语句的参数类型是否匹配预期。

### 2.4 反序列化漏洞审计

```php
// —— 漏洞代码 ——
$data = unserialize($_COOKIE['data']);
// 若存在可利用的魔术方法链，可导致 RCE
```

```php
// —— 危险魔术方法链示例 ——
class Logger {
    public $logFile;
    public $content;
    function __destruct() {
        file_put_contents($this->logFile, $this->content);  // Sink
    }
}
class Cache {
    public $obj;
    function __destruct() {
        $this->obj->flush();  // 触发其他类方法
    }
}
// 攻击者构造 POP 链：Cache -> Logger -> __destruct -> file_put_contents
```

```php
// —— 修复代码 ——
$data = json_decode($_COOKIE['data'], true);  // 使用 JSON 替代序列化
// 或限制反序列化类型
$data = unserialize($_COOKIE['data'], ['allowed_classes' => false]);
```

审计要点：搜索 `unserialize(`，检查参数是否用户可控；梳理 `__wakeup`、`__destruct`、`__toString`、`__call` 等魔术方法是否形成 POP 链。

### 2.5 PHP 框架审计要点

| 框架 | 重点审计位置 |
|------|-------------|
| **ThinkPHP** | 路由参数解析（`$_GET[路由参数]`）、控制器方法名可控、模板渲染函数 |
| **Laravel** | ` unserialize()` 调用、Blade 模板 `{!! !!}` 原始输出、Eloquent 原生查询 `DB::raw()` |

```php
// ThinkPHP 危险模式：方法名可控
// index.php?m=Home&c=Index&a=phpinfo  → 可调用任意公开方法
```

### 2.6 PHP 配置安全

| 配置项 | 安全建议 |
|--------|----------|
| `disable_functions` | 禁用 `exec,system,passthru,shell_exec,proc_open,popen` |
| `open_basedir` | 限制 PHP 文件操作目录范围 |
| `display_errors` | 生产环境设为 `Off` |
| `magic_quotes_gpc` | 已废弃，不应依赖 |
| `allow_url_include` | 设为 `Off`，防止远程文件包含 |

### 2.7 审计实战：模拟审计简化 CMS

以一个简化 CMS 为例，审计流程如下：

```
1. 信息收集：CMS 基于 ThinkPHP 5.0，入口 public/index.php
2. 路由梳理：GET /index/index/hello?name=xxx → Index::hello()
3. 代码审查：
```

```php
// application/index/controller/Index.php
public function hello($name) {
    echo "Hello, " . $name;        // [低危] XSS：未转义直接输出
    $file = input('get.file');
    include($file);                // [高危] 任意文件包含
    $id = input('get.id/d');
    $user = Db::table('users')->where('id', $id)->find();  // [安全] 参数化查询
}
```

```php
// 修复后
public function hello($name) {
    echo "Hello, " . htmlspecialchars($name, ENT_QUOTES);
    $whitelist = ['header', 'footer'];
    $file = input('get.file');
    if (!in_array($file, $whitelist, true)) {
        abort(404);
    }
    include "template/{$file}.php";
    $id = input('get.id/d');
    $user = Db::table('users')->where('id', $id)->find();
}
```

## 3. Java 代码审计

### 3.1 Java Web 应用架构理解

```
请求 → DispatcherServlet → Filter 链 → Interceptor → Controller → Service → DAO → DB
```

| 组件 | 职责 | 审计关注点 |
|------|------|-----------|
| Servlet | 最底层请求处理 | `doGet/doPost` 中参数直接使用 |
| Filter | 请求过滤/鉴权 | 是否所有路由都经过安全 Filter |
| Interceptor | 业务拦截 | 鉴权逻辑是否完整 |
| Controller | 参数接收 | `@RequestParam`、`@PathVariable` 注入的参数流向 |

### 3.2 SQL 注入审计

```java
// —— 漏洞代码：JDBC 拼接 ——
String sql = "SELECT * FROM users WHERE name = '" + username + "'";
Statement stmt = conn.createStatement();
ResultSet rs = stmt.executeQuery(sql);
```

```java
// —— 漏洞代码：MyBatis ${} 注入 ——
// UserMapper.xml
@Select("SELECT * FROM users WHERE name = ${name}")  // ${} 是文本替换
List<User> findByName(@Param("name") String name);
```

```java
// —— 修复代码：PreparedStatement ——
String sql = "SELECT * FROM users WHERE name = ?";
PreparedStatement ps = conn.prepareStatement(sql);
ps.setString(1, username);
ResultSet rs = ps.executeQuery();

// —— 修复代码：MyBatis #{} ——
@Select("SELECT * FROM users WHERE name = #{name}")  // #{} 使用预编译占位符
List<User> findByName(@Param("name") String name);
```

审计要点：全局搜索 `Statement`、`createStatement`、`${`，判断 SQL 是否拼接用户输入。MyBatis 中 `${}` 是文本替换（危险），`#{}` 是预编译占位符（安全）。

### 3.3 命令注入审计

```java
// —— 漏洞代码 ——
String cmd = "ping " + request.getParameter("host");
Runtime.getRuntime().exec(cmd);
```

```java
// —— 修复代码 ——
String host = request.getParameter("host");
// 白名单校验
if (!host.matches("^[a-zA-Z0-9.\\-]+$")) {
    throw new IllegalArgumentException("非法参数");
}
ProcessBuilder pb = new ProcessBuilder("ping", host);
pb.start();
```

审计要点：搜索 `Runtime.exec`、`ProcessBuilder`，检查命令参数是否来自用户输入且未做白名单过滤。

### 3.4 反序列化漏洞审计

```java
// —— 漏洞代码：原生反序列化 ——
ObjectInputStream ois = new ObjectInputStream(request.getInputStream());
Object obj = ois.readObject();  // 可触发任意 readObject/readResolve
```

```java
// —— 漏洞代码：Fastjson ——
String json = request.getParameter("data");
Object obj = JSON.parseObject(json, Object.class);  // Fastjson <1.2.68 可 RCE
```

```java
// —— 修复代码 ——
// 使用 ObjectInputFilter（JDK 9+）
ObjectInputStream ois = new ObjectInputStream(request.getInputStream());
ois.setObjectInputFilter(info -> {
    return info.serialClass() != null ? ObjectInputFilter.Status.REJECTED
                                       : ObjectInputFilter.Status.UNDECIDED;
});

// Fastjson 修复：升级到最新版 + 关闭 AutoType
ParserConfig.getGlobalInstance().setAutoTypeSupport(false);
```

审计要点：搜索 `readObject(`、`JSON.parseObject`、`ObjectMapper.readValue`（开启默认类型），检查反序列化输入是否用户可控。

### 3.5 SSRF 审计

```java
// —— 漏洞代码 ——
URL url = new URL(request.getParameter("url"));
HttpURLConnection conn = (HttpURLConnection) url.openConnection();
InputStream is = conn.getInputStream();  // 可探测内网/读云元数据
```

```java
// —— 修复代码 ——
String urlStr = request.getParameter("url");
URL url = new URL(urlStr);
String host = url.getHost();
InetAddress addr = InetAddress.getByName(host);
// 拒绝内网地址
if (addr.isSiteLocalAddress() || addr.isLoopbackAddress()
        || addr.isLinkLocalAddress() || addr.isAnyLocalAddress()) {
    throw new SecurityException("禁止访问内网地址");
}
// 限制协议与端口
if (!url.getProtocol().matches("https?") || !url.getPort() isInAllowedPorts) {
    throw new SecurityException("协议或端口非法");
}
```

审计要点：搜索 `new URL(`、`HttpClient.execute`、`OkHttpClient.newCall`，检查 URL 参数是否用户可控且未做内网地址过滤。

### 3.6 表达式注入审计

| 引擎 | 触发场景 |
|------|----------|
| OGNL | Struts2 参数传递 |
| SpEL | Spring `@Value`、`ExpressionParser` |
| EL | JSP `${}`、`#{}` |

```java
// —— 漏洞代码：SpEL 注入 ——
ExpressionParser parser = new SpelExpressionParser();
Expression exp = parser.parseExpression(request.getParameter("expr"));
String result = exp.getValue(String.class);  // 可执行任意代码
```

```java
// —— 修复代码 ——
// 避免将用户输入传入表达式引擎
// 若必须使用，采用 SimpleEvaluationContext 限制能力
EvaluationContext context = SimpleEvaluationContext.forReadOnlyDataBinding().build();
Expression exp = parser.parseExpression(safeExpr);
String result = exp.getValue(context, String.class);
```

审计要点：搜索 `parseExpression`、`Ognl.getValue`、`MethodExpression`，检查表达式字符串是否用户可控。

### 3.7 文件上传审计

```java
// —— 漏洞代码 ——
// ServletFileUpload 直接保存用户文件名
String filename = item.getName();
File file = new File(uploadDir, filename);  // 路径穿越 + 任意文件类型
item.write(file);
```

```java
// —— 修复代码 ——
String filename = item.getName();
// 去除路径穿越
filename = new File(filename).getName();
// 白名单校验后缀
String ext = filename.substring(filename.lastIndexOf(".") + 1).toLowerCase();
if (!Arrays.asList("jpg", "png", "gif").contains(ext)) {
    throw new SecurityException("非法文件类型");
}
// 重命名文件
String safeName = UUID.randomUUID() + "." + ext;
item.write(new File(uploadDir, safeName));
```

### 3.8 Java 框架审计要点

| 框架 | 高危模式 |
|------|----------|
| **Spring** | SpEL 注入、`@PathVariable` 可控路由、Actuator 端点暴露 |
| **Struts2** | OGNL 表达式注入（S2-045 等历史漏洞） |

## 4. Python 代码审计

### 4.1 Flask / Django 审计要点

| 框架 | 关注点 |
|------|--------|
| **Flask** | `render_template_string` SSTI、`debug=True` 信息泄露、`send_file` 路径穿越 |
| **Django** | `extra()` / `raw()` SQL 注入、`mark_safe` XSS、模板 `|safe` 过滤器 |

### 4.2 模板注入审计

```python
# —— 漏洞代码：Flask SSTI ——
from flask import Flask, request, render_template_string
app = Flask(__name__)

@app.route('/')
def index():
    name = request.args.get('name', '')
    template = f"<h1>Hello {name}</h1>"           # [高危] 用户输入直接拼入模板
    return render_template_string(template)       # 可执行 {{ config }} / {{ ''.__class__ }}
```

```python
# —— 修复代码 ——
@app.route('/')
def index():
    name = request.args.get('name', '')
    return render_template_string("<h1>Hello {{ name }}</h1>", name=name)  # 参数化
```

审计要点：搜索 `render_template_string`、`Template(`，检查模板字符串是否包含用户输入。Jinja2 中 `{{ }}` 语法可执行 Python 表达式。

### 4.3 SQL 注入审计

```python
# —— 漏洞代码：原生 SQL 拼接 ——
cursor.execute(f"SELECT * FROM users WHERE name = '{name}'")

# —— 漏洞代码：Django raw ——
User.objects.raw("SELECT * FROM users WHERE name = '%s'" % name)

# —— 漏洞代码：Django extra ——
User.objects.extra(where=["name = '%s'" % name])
```

```python
# —— 修复代码：参数化查询 ——
cursor.execute("SELECT * FROM users WHERE name = %s", (name,))

# —— 修复代码：Django ORM ——
User.objects.filter(name=name)

# —— 修复代码：Django raw 参数化 ——
User.objects.raw("SELECT * FROM users WHERE name = %s", [name])
```

### 4.4 反序列化审计

```python
# —— 漏洞代码：pickle ——
import pickle
data = request.get_data()
obj = pickle.loads(data)  # __reduce__ 可执行任意代码

# —— 漏洞代码：yaml.load ——
import yaml
config = yaml.load(request.data, Loader=yaml.Loader)  # 默认 Loader 支持任意 Python 对象
```

```python
# —— 修复代码 ——
import json
obj = json.loads(data)  # JSON 不支持代码执行

# yaml 修复
config = yaml.load(request.data, Loader=yaml.SafeLoader)  # SafeLoader 禁止任意对象
```

审计要点：搜索 `pickle.loads`、`yaml.load(`（注意区分 `load` 和 `safe_load`），检查反序列化输入是否来自用户。

### 4.5 命令注入审计

```python
# —— 漏洞代码 ——
import os
os.system("nslookup " + request.args.get('host'))

import subprocess
subprocess.call("ping " + host, shell=True)  # shell=True 时可注入
```

```python
# —— 修复代码 ——
import subprocess
host = request.args.get('host')
if not re.match(r'^[a-zA-Z0-9.\-]+$', host):
    abort(400)
result = subprocess.run(["ping", host], capture_output=True)  # 列表参数，shell=False
```

审计要点：搜索 `os.system`、`subprocess.call`、`subprocess.Popen`、`os.popen`，重点关注 `shell=True` 和字符串拼接。

### 4.6 审计实战：模拟审计 Flask 应用

```python
from flask import Flask, request, render_template_string
import pickle, subprocess

app = Flask(__name__)

@app.route('/')
def index():
    name = request.args.get('name', 'guest')
    return render_template_string(f'<h1>Hi {name}</h1>')   # [高危] SSTI

@app.route('/exec')
def exec_cmd():
    cmd = request.args.get('cmd')
    return subprocess.check_output(cmd, shell=True)         # [高危] 命令注入

@app.route('/config')
def load_config():
    data = request.cookies.get('config')
    return str(pickle.loads(data))                          # [高危] 反序列化 RCE
```

```python
# 修复后
@app.route('/')
def index():
    name = request.args.get('name', 'guest')
    return render_template_string('<h1>Hi {{ name }}</h1>', name=name)

@app.route('/exec')
def exec_cmd():
    cmd = request.args.get('cmd')
    allowed = {'uptime', 'df'}
    if cmd not in allowed:
        abort(403)
    return subprocess.check_output(cmd.split())

@app.route('/config')
def load_config():
    import json
    data = request.cookies.get('config')
    return str(json.loads(data))
```

### 5.1 Semgrep 规则编写

```ql
// find-sql-injection.ql
/**
 * @name SQL 注入检测
 * @description 检测拼接用户输入到 SQL 查询中的模式
 * @kind problem
 * @id java/sql-injection
 */

import java
import semmle.code.java.dataflow.TaintTracking
import semmle.code.java.StringBuilder

class SqlInjectionConfig extends TaintTracking::Configuration {
    SqlInjectionConfig() { this = "SqlInjectionConfig" }
    override predicate isSource(DataFlow::Node source) {
        exists(Parameter p |
            p = source.asParameter() and
            p.getCallable().hasAnnotation(".*RequestMapping.*")
        )
    }
    override predicate isSink(DataFlow::Node sink) {
        exists(MethodAccess ma |
            ma.getMethod().hasName("executeQuery") and
            sink = ma.getArgument(0)
        )
    }
}

from SqlInjectionConfig config, DataFlow::PathNode source, DataFlow::PathNode sink
where config.hasFlowPath(source, sink)
select sink, source, "SQL 注入：用户输入从 $source 流入 SQL 查询 $sink"
```

### 5.4 Python 简单 AST 审计脚本

```python
"""simple_ast_audit.py — 基于 AST 的 Python 代码安全扫描器"""
import ast
import sys
import os

DANGER_SINKS = {
    'os.system', 'subprocess.call', 'subprocess.Popen',
    'subprocess.run', 'os.popen', 'pickle.loads', 'pickle.load',
    'yaml.load', 'eval', 'exec',
}
SHELL_TRUE_FUNCS = {'subprocess.call', 'subprocess.Popen', 'subprocess.run'}

class AuditVisitor(ast.NodeVisitor):
    def __init__(self, filepath):
        self.filepath = filepath
        self.issues = []

    def _report(self, node, msg):
        self.issues.append(f"[{self.filepath}:{node.lineno}] {msg}")

    def visit_Call(self, node):
        func_name = self._get_full_name(node.func)
        if func_name in DANGER_SINKS:
            self._report(node, f"检测到危险函数调用: {func_name}")
        # 检查 shell=True
        if func_name in SHELL_TRUE_FUNCS:
            for kw in node.keywords:
                if kw.arg == 'shell' and isinstance(kw.value, ast.Constant) and kw.value.value is True:
                    self._report(node, f"{func_name} 使用 shell=True，存在命令注入风险")
        # 检查 render_template_string 拼接
        if func_name == 'render_template_string' and node.args:
            arg = node.args[0]
            if isinstance(arg, ast.JoinedStr):  # f-string
                for value in arg.values:
                    if isinstance(value, ast.FormattedValue):
                        self._report(node, "render_template_string 使用 f-string 拼接，存在 SSTI 风险")
        self.generic_visit(node)

    def _get_full_name(self, node):
        if isinstance(node, ast.Name):
            return node.id
        if isinstance(node, ast.Attribute):
            parent = self._get_full_name(node.value)
            return f"{parent}.{node.attr}" if parent else node.attr
        return ''

def audit_file(filepath):
    with open(filepath, 'r', encoding='utf-8') as f:
        tree = ast.parse(f.read(), filename=filepath)
    visitor = AuditVisitor(filepath)
    visitor.visit(tree)
    return visitor.issues

def main(path):
    for root, _, files in os.walk(path):
        for f in files:
            if f.endswith('.py'):
                issues = audit_file(os.path.join(root, f))
                for issue in issues:
                    print(issue)

if __name__ == '__main__':
    main(sys.argv[1] if len(sys.argv) > 1 else '.')
```

## 6. 代码审计报告撰写

### 6.1 漏洞描述模板

```
【漏洞名称】[漏洞类型] - [功能模块/接口]
【漏洞位置】文件路径:行号 / 接口 URL
【漏洞描述】简要描述漏洞成因与触发条件
【攻击场景】描述攻击者如何利用该漏洞
【危害等级】[严重/高危/中危/低危]
【修复建议】给出具体修复方案
```

### 6.2 风险评级标准（CVSS v3.1）

CVSS 向量由以下维度组成：

| 维度 | 取值 | 说明 |
|------|------|------|
| Attack Vector (AV) | N/A/L/P | 网络/邻接/物理 |
| Attack Complexity (AC) | L/H | 低/高 |
| Privileges Required (PR) | N/L/H | 无/低/高 |
| User Interaction (UI) | N/R | 无/需要 |
| Scope (S) | U/C | 不变/改变 |
| Confidentiality (C) | N/L/H | 无/低/高 |
| Integrity (I) | N/L/H | 无/低/高 |
| Availability (A) | N/L/H | 无/低/高 |

| CVSS 分数 | 等级 | 颜色 |
|-----------|------|------|
| 9.0 - 10.0 | 严重 | 红色 |
| 7.0 - 8.9 | 高危 | 橙色 |
| 4.0 - 6.9 | 中危 | 黄色 |
| 0.1 - 3.9 | 低危 | 蓝色 |

示例向量：`CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H` → 分数 9.8（严重）

### 6.3 修复建议撰写规范

修复建议应遵循以下原则：

1. **具体性**：给出可直接实施的代码级修复方案，而非泛泛而谈
2. **可行性**：方案需适配当前技术栈，不能引入新的风险
3. **完整性**：从输入校验、处理逻辑、输出编码三方面给出纵深防御建议
4. **优先级**：按修复紧急程度排序，区分临时缓解措施与根因修复

## 总结

代码审计的核心能力在于：

1. **Sink 识别**：熟练掌握各语言的危险函数与漏洞模式
2. **数据流追踪**：从 Source（用户输入）到 Sink（危险操作）的完整追踪
3. **漏洞验证**：搭建环境构造 PoC，确认漏洞可利用性
4. **工具辅助**：合理利用 Semgrep / CodeQL 提升效率，但不依赖工具替代人工判断
5. **持续学习**：关注 CVE 漏洞披露与新的攻击技术，不断更新审计知识库
