# 业务逻辑漏洞测试方法论

### 8.1 业务流程梳理

以电商为例绘制完整业务链路：

```
浏览商品 → 加入购物车 → 创建订单 → 选择支付 → 输入优惠码 → 完成支付 → 发货
     ↓           ↓           ↓          ↓          ↓          ↓
  价格篡改    数量篡改    越权下单    金额篡改    重复使用    状态竞争
```

在每个节点标注可篡改参数和业务约束，形成测试矩阵。

### 8.2 状态机分析

关注状态转换是否可控：

- 订单状态：`待支付 → 已支付 → 已发货`。能否跳过"已支付"直接设为"已发货"？
- 是否能将"已取消"订单重新置为"待支付"？

### 8.3 数据流追踪

追踪用户可控数据从前端到后端再到数据库的完整路径，标注每个环节是否做了校验：

```
前端输入 price → HTTP请求 → Controller → Service → DAO → 数据库
  [可篡改]      [抓包改]    [校验?]    [校验?]    [校验?]   [约束?]
```

### 8.4 并发场景测试

对以下操作进行并发测试：
- 余额扣减 / 积分消费
- 优惠券核销
- 库存扣减
- 投票计数
- 抽奖参与

### 8.5 业务逻辑漏洞检查清单

- [ ] 所有接口是否做了对象归属校验（防 IDOR）
- [ ] 支付金额是否由服务端计算（防金额篡改）
- [ ] 数量是否校验正整数且不超限（防负数/溢出）
- [ ] 扣款是否原子操作（防条件竞争）
- [ ] 优惠券是否幂等使用（防重复使用）
- [ ] 验证码是否一次性使用且有 TTL（防复用）
- [ ] 验证码是否服务端校验（防客户端绕过）
- [ ] 短信接口是否限流（防轰炸）
- [ ] 密码重置 Token 是否足够随机（防预测）
- [ ] 验证码是否回传在响应中（防泄露）
- [ ] 登录错误是否统一响应（防枚举）
- [ ] 登录后是否重生成 Session（防固定）
- [ ] 注册是否接受角色字段（防提权）
- [ ] 状态机是否校验前置状态（防跳步）
- [ ] 关键操作是否审计日志（防抵赖）
