# 验证码漏洞

### 4.1 验证码复用（不过期）

服务端将验证码存入 Session 但不设置过期时间，攻击者用同一验证码值反复提交：

```
POST /login  -> 验证码: a8Xk (服务端记录)
POST /login  -> 验证码: a8Xk (再次提交，仍通过)
```

### 4.2 验证码客户端校验

验证码校验逻辑写在 JavaScript 前端代码中：

```javascript
// 漏洞：前端校验验证码
function checkCaptcha(input) {
    return input === sessionStorage.getItem('captcha');
}
```

攻击者直接绕过前端，用 Burp 发包即可，验证码字段填任意值或空值。

### 4.3 验证码绕过（空值/万能验证码）

```php
// 漏洞：未校验空值
if ($_POST['captcha'] == $_SESSION['captcha']) { ... }
// 当两者均为空字符串时 0==0 为 true
```

部分系统存在调试遗留的万能验证码（如 `0000`、`admin`），硬编码在后端。

### 4.4 短信验证码轰炸

短信发送接口无频率限制：

```http
POST /api/sms/send  HTTP/1.1
{"phone": "13800000000"}
```

攻击者循环请求，导致目标手机号被短信轰炸，产生资费骚扰。

### 4.5 防御方案

| 漏洞 | 防御措施 |
|------|----------|
| 验证码复用 | 服务端校验后立即销毁，设置 5 分钟 TTL |
| 客户端校验 | 所有校验必须在服务端执行 |
| 空值绕过 | 显式校验 `if (captcha == null \|\| captcha.isEmpty()) reject` |
| 万能码 | 删除所有硬编码后门，使用标准库生成 |
| 短信轰炸 | 同一手机号 60 秒内限 1 次，同一 IP 10 分钟限 5 次，图形验证码前置 |

安全验证码校验（Python）：

```python
import random, string, time

class CaptchaManager:
    def __init__(self, redis_client):
        self.redis = redis_client

    def generate(self, session_id):
        code = ''.join(random.choices(string.digits, k=6))
        self.redis.setex(f"captcha:{session_id}", 300, code)  # 5分钟过期
        return code

    def verify(self, session_id, user_input):
        key = f"captcha:{session_id}"
        stored = self.redis.get(key)
        if not stored:
            return False, "验证码已过期"
        # 一次性使用：校验后立即删除
        self.redis.delete(key)
        if not user_input or not user_input.strip():
            return False, "验证码不能为空"
        return user_input == stored.decode(), "校验结果"
```
