# 注册登录逻辑漏洞

### 6.1 用户名枚举（响应差异）

登录接口对不同错误返回不同提示：

```
用户不存在 -> "用户名不存在"
密码错误   -> "密码错误"
```

攻击者据此判断用户名是否存在，为后续撞库提供目标。

### 6.2 万能密码绕过

```php
// 漏洞：SQL拼接
$sql = "SELECT * FROM users WHERE username='{$_POST['user']}' AND password='{$_POST['pass']}'";
```

输入 `admin' -- ` 即可绕过密码校验。虽属 SQL 注入，但常在登录场景触发。

### 6.3 注册逻辑绕过

部分系统注册时服务端未校验用户角色字段：

```http
POST /register  -> {"username":"hacker","password":"123","role":"admin"}
```

后端直接将 `role` 写入数据库，导致任意用户可自注册管理员。

### 6.4 Session 固定攻击

攻击者预先获取一个 Session ID，诱使目标用户用该 ID 登录：

```
1. 攻击者访问站点获取 session_id=ABC123
2. 通过钓鱼链接让受害者使用 session_id=ABC123 登录
3. 受害者登录后，攻击者用 ABC123 即获得已认证会话
```

### 6.5 防御方案

1. **统一响应**：登录失败统一返回"用户名或密码错误"，不区分具体原因。
2. **参数化查询**：使用预编译语句彻底消除 SQL 注入。
3. **角色服务端控制**：注册接口不接受 `role` 等敏感字段，默认赋予普通用户角色。
4. **会话重生成**：登录成功后调用 `session_regenerate_id(true)` 销毁旧 Session。

```php
// 安全：登录后重生成Session
if (password_verify($input_pass, $user['password_hash'])) {
    session_regenerate_id(true);  // 防Session固定
    $_SESSION['user_id'] = $user['id'];
    $_SESSION['role'] = 'user';  // 角色 != 用户输入
}
// 统一错误
echo json_encode(['error' => '用户名或密码错误']);
```
