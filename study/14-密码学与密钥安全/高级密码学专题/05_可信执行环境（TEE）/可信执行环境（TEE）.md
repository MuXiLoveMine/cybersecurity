# 可信执行环境（TEE）

### 5.1 TEE 概念与架构

**可信执行环境（Trusted Execution Environment, TEE）** 是处理器内的安全隔离区域，保证内部代码和数据的机密性与完整性，即使操作系统被攻破。

```
┌─────────────────────────────────────────────────┐
│                 处理器芯片                        │
│  ┌──────────────────────┐  ┌─────────────────┐ │
│  │    REE (富执行环境)   │  │   TEE (可信执行  │ │
│  │                      │  │    环境)         │ │
│  │  - 普通操作系统       │  │                 │ │
│  │  - 普通应用程序       │  │  - 安全OS       │ │
│  │  - 不可信环境         │  │  - 可信App      │ │
│  │                      │←→│  - 安全存储     │ │
│  └──────────────────────┘  └─────────────────┘ │
│         │                           │           │
│         └─────── 安全通信通道 ───────┘           │
└─────────────────────────────────────────────────┘
```

**TEE 的核心保证：**
- **机密性**：TEE 内代码和数据被加密，外部无法读取
- **完整性**：TEE 内执行不受篡改
- **可证明性**：TEE 可向远程方证明自身身份和状态

### 5.2 Intel SGX

**Intel SGX（Software Guard Extensions）** 是 Intel 处理器的 TEE 实现。

```
SGX 架构：
┌─────────────────────────────────┐
│         应用程序                 │
│  ┌───────────┐  ┌───────────┐  │
│  │ 不安全代码  │  │  Enclave   │  │
│  │           │  │ (飞地)     │  │
│  └───────────┘  └───────────┘  │
│         │              │        │
│  ┌──────┴──────┐  ┌────┴────┐  │
│  │   OS        │  │ SGX硬件  │  │
│  │  (不可信)    │  │  (可信)  │  │
│  └─────────────┘  └─────────┘  │
└─────────────────────────────────┘

Enclave 特性：
- 内存加密（MEE）
- 密封数据（Sealing）：加密存储到不可信磁盘
- 远程证明（Remote Attestation）
```

```python
# SGX 远程证明流程（概念示意）
"""
1. 客户端请求 Enclave 生成报告
2. Enclave 生成 REPORT（包含测量值和 nonce）
3. SGX 硬件签名 REPORT → QUOTE
4. 客户端将 QUOTE 发给服务端验证
5. 服务端通过 Intel 证明服务验证 QUOTE
6. 验证通过后建立安全通道
7. 双方通过密钥协商加密通信
"""
```

### 5.3 ARM TrustZone

```
ARM TrustZone 架构：

      ┌──────────────────────┐
      │       安全世界         │ ← TrustZone
      │   - 安全OS (OP-TEE)   │
      │   - 安全应用           │
      │   - 密钥存储           │
      ├──────────────────────┤
      │      监控模式          │ ← 安全世界切换
      ├──────────────────────┤
      │      普通世界          │ ← 常规执行
      │   - Linux/Android     │
      │   - 普通应用           │
      └──────────────────────┘

TrustZone 特点：
- 硬件隔离（安全世界 vs 普通世界）
- 硬件外设可配置为安全/非安全
- 通过 SMC 指令切换世界
```

### 5.4 AMD SEV

**AMD SEV（Secure Encrypted Virtualization）** 在虚拟化层面提供加密保护。

```
SEV 特点：
- 每个 VM 的内存独立加密
- VM 即使在云服务商不可信时也安全
- 密钥由 AMD 安全处理器管理
- 客户可验证 VM 运行在加密环境

演进：
SEV → SEV-ES（加密状态保护）→ SEV-SNP（防回滚）
```

### 5.5 TEE 安全分析与攻击

```
TEE 已知攻击：
┌──────────────────────┬──────────────────────────────┐
│ 攻击                  │ 说明                         │
├──────────────────────┼──────────────────────────────┤
│ Foreshadow (SGX1)    │ 利用推测执行读取SGX内存       │
│ LVI                   │ 推测执行注入攻击              │
│ Prime+Probe           │ 缓存侧信道推断密钥           │
│ Rollback              │ 回滚TEE状态到旧版本           │
│ 恶意hypervisor       │ SEV场景中Hypervisor攻击      │
│ SCA-SEV              │ SEV内存加密侧信道            │
└──────────────────────┴──────────────────────────────┘
```

**缓解措施：**
- 推测执行屏障（Microcode 更新）
- 恒定时间编程
- 缓存分区
- SEV-SNP 添加完整性保护
