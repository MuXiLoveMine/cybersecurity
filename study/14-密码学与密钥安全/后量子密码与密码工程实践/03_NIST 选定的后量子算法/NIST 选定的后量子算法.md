# NIST 选定的后量子算法

### 3.1 ML-KEM（FIPS 203）：基于格的密钥封装机制

**ML-KEM（Module-Lattice-based Key Encapsulation Mechanism）**，前身 CRYSTALS-Kyber，是 NIST 选定的后量子密钥封装标准。

**数学基础：格上的模块学习误差（Module-LWE）问题：**

```
格（Lattice）定义：
  给定线性无关向量 b1, b2, ..., bn ∈ Z^m
  格 L = { Σ ai·bi : ai ∈ Z }
  即所有基向量整数线性组合的集合

LWE问题：
  给定 A（n×m矩阵，随机），s（秘密向量），e（误差向量）
  计算 b = A·s + e（模q）
  
  困难：已知(A, b)，求s
  - 经典算法：指数时间
  - 量子算法（Shor）：无加速（不是因式分解/离散对数问题）

ML-KEM使用的Module-LWE：
  - 矩阵A的元素在多项式环 Rq = Zq[x]/(x^n+1) 中
  - 比纯LWE更灵活（模块维度可调）
  - n=256（多项式次数），q=3329（模数）
```

**ML-KEM 密钥封装流程：**

```
ML-KEM 三阶段流程：

阶段1：密钥生成（KeyGen）
  ┌─────────────────────────────────────────────┐
  │  1. 采样矩阵 A ∈ Rq^(k×k)  （公开参数）       │
  │  2. 采样秘密向量 s ∈ Rq^k （小系数）          │
  │  3. 采样误差向量 e ∈ Rq^k （小系数）          │
  │  4. 计算 t = A·s + e                        │
  │                                              │
  │  公钥 pk = (A, t)                            │
  │  私钥 sk = s                                 │
  └─────────────────────────────────────────────┘

阶段2：封装（Encapsulate）→ 生成共享密钥和密文
  ┌─────────────────────────────────────────────┐
  │  1. 采样随机向量 r ∈ Rq^k （小系数）          │
  │  2. 采样误差向量 e1, e2                      │
  │  3. 计算 u = A^T·r + e1                      │
  │  4. 计算 v = t^T·r + e2 + ⌈q/2⌉·m           │
  │     （m为消息比特编码）                       │
  │  5. 密文 ct = (u, v)                         │
  │  6. 共享密钥 K = Hash(r || ct)               │
  │                                              │
  │  输出：密文ct + 共享密钥K                     │
  └─────────────────────────────────────────────┘

阶段3：解封装（Decapsulate）→ 从密文恢复共享密钥
  ┌─────────────────────────────────────────────┐
  │  1. 计算 m' = v - s^T·u                      │
  │     （误差项 e1·s + e2 - e·r 可控，          │
  │      使得 m' ≈ ⌈q/2⌉·m）                    │
  │  2. 解码 m' → 恢复消息m                      │
  │  3. 从m恢复r（编码逆操作）                    │
  │  4. 重新计算u' = A^T·r, v' = t^T·r + ...     │
  │  5. 若u'==u且v'==v：                          │
  │       K = Hash(r || ct)                      │
  │     否则：                                    │
  │       K = Hash(z || ct)  （z为私钥中的随机数） │
  └─────────────────────────────────────────────┘
```

**ML-KEM 参数集：**

| 参数集 | 安全等级 | n | k | 公钥大小 | 私钥大小 | 密文大小 | 对应对称安全 |
|--------|----------|---|---|----------|----------|----------|-------------|
| ML-KEM-512 | Level 1 | 256 | 2 | 800 B | 1632 B | 768 B | AES-128 |
| ML-KEM-768 | Level 3 | 256 | 3 | 1184 B | 2400 B | 1088 B | AES-192 |
| ML-KEM-1024 | Level 5 | 256 | 4 | 1568 B | 3168 B | 1568 B | AES-256 |

**与 RSA/ECDH 密钥尺寸对比：**

```
密钥尺寸对比（公钥 + 密文/签名）：

算法         公钥     私钥     密文/签名    总开销
────────────────────────────────────────────────
RSA-2048     256B     256B     256B       512B
ECDH-P256    32B      32B      32B        64B
ML-KEM-768   1184B    2400B    1088B      2272B   ← 约4.5倍RSA
────────────────────────────────────────────────
代价：更大的密钥和密文 → 更高带宽和存储需求
```

### 3.2 ML-DSA（FIPS 204）：基于格的数字签名

**ML-DSA（Module-Lattice-based Digital Signature Algorithm）**，前身 CRYSTALS-Dilithium，是 NIST 选定的主签名标准。

**ML-DSA 签名原理：**

```
ML-DSA 基于 Fiat-Shamir with Aborts 范式

密钥生成：
  1. 采样矩阵 A ∈ Rq^(k×l)（种子扩展）
  2. 私钥向量 s1 ∈ Rq^l, s2 ∈ Rq^k（小系数）
  3. 计算公钥 t = A·s1 + s2
  4. 公钥 pk = (rho, t)，私钥 sk = (rho, K, tr, s1, s2, t)

签名过程：
  1. 采样随机向量 y ∈ Rq^l（掩蔽向量）
  2. 计算 w = A·y（高位）
  3. 计算挑战哈希 c = H(t || message || w)（Fiat-Shamir）
  4. 计算签名 z = y + c·s1
  5. 检查z的系数范围 → 若过大则"abort"重新采样
  6. 计算 hint h 使得 w的低位可由(t, z, c)恢复
  7. 签名 sig = (z, h)

验证过程：
  1. 从签名恢复 c = H(t || message || w')（w'=A·z - c·t）
  2. 检查z的系数范围
  3. 验证 hint h 与 w' 一致
  4. 验证通过 → 签名有效

关键安全设计：
  - "with Aborts"：若z系数过大则放弃重签，防止私钥泄漏
  - y的随机性：每次签名使用新随机y，防止私钥提取
  - 多次哈希：增强 Fiat-Shamir 变换安全性
```

**ML-DSA 参数集：**

| 参数集 | 安全等级 | 公钥大小 | 私钥大小 | 签名大小 |
|--------|----------|----------|----------|----------|
| ML-DSA-44 | Level 2 | 1312 B | 2528 B | 2420 B |
| ML-DSA-65 | Level 3 | 1952 B | 4000 B | 3309 B |
| ML-DSA-87 | Level 5 | 2592 B | 4864 B | 4627 B |

### 3.3 SLH-DSA（FIPS 205）：基于哈希的数字签名

**SLH-DSA（Stateless Hash-based Digital Signature Algorithm）**，前身 SPHINCS+，是基于哈希函数的签名方案。

**SLH-DSA 特点：**

```
基于哈希的签名原理：
  - 仅依赖哈希函数安全性
  - 不依赖任何数论假设
  - 最保守的安全假设：只要哈希函数安全，签名就安全
  - 无状态（stateless）：无需维护签名计数器

技术架构：
  ┌──────────────────────────────────┐
  │        WOTS+ (一次性签名)          │
  │    └── Lamport签名改进            │
  │        └── 基于哈希链              │
  ├──────────────────────────────────┤
  │     Merkle树（多次签名聚合）        │
  │    └── 2^d个WOTS+叶子             │
  │    └── 树根为公钥                 │
  ├──────────────────────────────────┤
  │   多层Merkle树（MSS）             │
  │    └── 层间认证用WOTS+            │
  │    └── 底层树叶子用于消息签名       │
  └──────────────────────────────────┘

SLH-DSA = 多层Merkle树 + WOTS+ + FORS（叶签名）

安全性仅基于哈希函数：
  - SHA-256 或 SHAKE-256
  - 无数论假设 → 量子攻击面最小
```

**SLH-DSA 参数集与权衡：**

| 参数集 | 安全等级 | 公钥大小 | 签名大小 | 签名时间 | 验证时间 |
|--------|----------|----------|----------|----------|----------|
| SLH-DSA-SHA2-128s | Level 1 | 32 B | 7856 B | 慢（~1s） | 快 |
| SLH-DSA-SHA2-192s | Level 3 | 48 B | 16224 B | 很慢（~3s） | 中 |
| SLH-DSA-SHA2-256s | Level 5 | 64 B | 29792 B | 极慢（~10s） | 中 |
| SLH-DSA-SHA2-128f | Level 1 | 32 B | 17088 B | 中（~50ms） | 快 |

```
SLH-DSA 的核心权衡：
  - "s"变体：小签名，慢签名速度
  - "f"变体：快签名，大签名尺寸
  
  由于签名尺寸巨大（8-30KB），SLH-DSA 不适合：
    ├── TLS证书链（增大握手包）
    ├── 嵌入式设备（存储有限）
    └── 高频签名场景

  但适合作为：
    ├── 根CA签名（低频，高安全要求）
    ├── 密码货币冷钱包签名
    └── ML-DSA的备选方案
```

### 3.4 FN-DSA（FIPS 206草案）：基于 FFT 的签名

**FN-DSA（FFT over NTRU Lattice Digital Signature Algorithm）**，前身 Falcon，是基于 NTRU 格和 FFT 技术的签名方案。

**FN-DSA 特点：**

```
FN-DSA 核心技术：
  - 基于NTRU格（更紧凑的格结构）
  - 使用FFT（快速傅里叶变换）实现高效签名
  - 采用"Fiat-Shamir with GPV"签名范式

签名流程概述：
  1. 密钥生成：
     - 在NTRU格中生成短基（Babai最近平面算法）
     - 公钥：格的紧凑表示
     - 私钥：短格基
  
  2. 签名：
     - c = H(message)（哈希到格中的点）
     - 用私钥基进行最近平面归约 → 短向量z
     - 签名 = z（仅需传输z，格紧凑）
  
  3. 验证：
     - 重算 c = H(message)
     - 检查z是格中向量且z-c的范数小于阈值

FN-DSA 优势：
  ├── 签名尺寸最小（~666B at Level 1）
  ├── 验证速度快
  └── 格论安全证明强（平均情况归约）

FN-DSA 劣势：
  ├── 实现复杂（FFT精度要求高）
  ├── 签名时间较ML-DSA慢
  └── 侧信道防护难度大（浮点运算泄漏）
```

**四种标准签名算法对比：**

| 特性 | ML-DSA | SLH-DSA | FN-DSA | 传统ECDSA |
|------|--------|---------|--------|-----------|
| 数学基础 | 格(Module-LWE) | 哈希函数 | 格(NTRU) | 椭圆曲线 |
| 公钥大小 | 1312-2592B | 32-64B | 897-1793B | 32-64B |
| 签名大小 | 2420-4627B | 7856-29792B | 666-1480B | 64-96B |
| 签名速度 | 快 | 慢/很慢 | 中 | 快 |
| 验证速度 | 中 | 快/中 | 快 | 快 |
| 实现难度 | 中等 | 较简单 | 高 | 成熟 |
| 安全假设 | 格假设 | 仅哈希安全 | 格假设 | ECDLP |
| 量子安全 | 是 | 是 | 是 | 否 |
