# 后量子密码迁移策略

### 4.1 混合部署方案

过渡期推荐使用混合方案：传统算法 + 后量子算法同时使用。

```
混合密钥交换方案（Hybrid KEM）：

方案：X25519 + ML-KEM-768

┌──────────┐                          ┌──────────┐
│  Client  │                          │  Server  │
└────┬─────┘                          └────┬─────┘
     │                                     │
     │  1. ClientHello                     │
     │  + kyber768 key_share               │
     │  + x25519 key_share                 │
     │─────────────────────────────────────→│
     │                                     │
     │  2. ServerHello                     │
     │  + kyber768 ciphertext              │
     │  + x25519 ephemeral                 │
     │←─────────────────────────────────────│
     │                                     │
     │  3. Server计算:                      │
     │     K_kem = Decaps(sk_kem, ct_kem)  │
     │     K_ecdh = X25519(sk, pk_client)  │
     │     K = KDF(K_kem || K_ecdh)        │
     │                                     │
     │  4. Client计算:                      │
     │     K_kem = Encaps(pk_kem, r)       │
     │     K_ecdh = X25519(sk, pk_server)  │
     │     K = KDF(K_kem || K_ecdh)        │
     │                                     │
     │  最终密钥K = KDF(K_PQC || K_classic) │
     │  安全性：只要任一算法安全 → K安全     │
     └─────────────────────────────────────┘
```

**混合方案安全性论证：**

```
安全性分析：
  K = KDF(K_PQC || K_classic)
  
  攻击者需要同时破解PQC和经典算法才能获得K
  - 若PQC被破但经典未破 → K_classical仍保护K
  - 若经典被破但PQC未破 → K_PQC仍保护K
  - 只有两者同时被破才泄露K

代价：
  - 带宽增加：公钥+密文尺寸是两者之和
  - 计算增加：两种算法都要计算
  - 但过渡期安全收益远大于性能损失
```

### 4.2 密钥尺寸影响分析

```
后量子迁移对系统的影响：

TLS握手影响：
  传统ECDHE：密钥交换开销 ~100 bytes
  混合方案：密钥交换开销 ~2300 bytes（ML-KEM-768 + X25519）
  增幅：~23倍
  
  影响：首次握手延迟增加约1-5ms（通常可接受）

证书影响：
  传统RSA-2048证书：签名256B，证书链约2-4KB
  ML-DSA-65签名：签名3309B，证书链约8-12KB
  增幅：~3-5倍
  
  影响：握手数据包增大，可能需要更多TCP包

X.509证书扩展：
  需要新OID标识后量子算法公钥
  需要新签名算法标识
  可能需要分片（Cross-Certificate签名链）

DNSSEC影响：
  DNS记录有UDP 512B限制（TCP回退）
  ML-DSA签名可能超出单条记录
  需要EDNS0或TCP
```

### 4.3 迁移路线图

```
PQC迁移成熟度模型：

Level 0：感知（2024-2025）
  └── 了解PQC威胁和标准
  └── 识别系统中的密码资产

Level 1：评估（2025-2026）
  └── 密码资产盘点（Crypto Inventory）
  └── 识别使用RSA/ECC的位置
  └── 评估PQC兼容性

Level 2：实验（2026-2027）
  └── 在测试环境部署混合方案
  └── 验证TLS+PQC功能正确性
  └── 性能基准测试

Level 3：试点（2027-2029）
  └── 生产环境小范围试点
  └── 部分服务支持PQC
  └── 监控兼容性和性能

Level 4：过渡（2029-2032）
  └── 新系统默认使用PQC
  └── 关密钥更新使用混合方案
  └── 逐步废弃纯RSA/ECC

Level 5：后量子（2032+）
  └── 全面使用PQC
  └── 仅在特殊场景保留传统算法
  └── 完成迁移
```
