# 实战案例：企业密码合规改造

### 11.1 改造背景

```
案例背景：
  某金融机构（约5000员工），需符合《密码法》和等保2.0要求
  
  现状问题：
  1. 使用RSA-2048 + SHA-256（非国密）
  2. TLS使用国际算法密码套件
  3. 数据存储加密使用AES-256（非国密）
  4. 签名验签使用RSA-PSS
  
  合规要求：
  - 等保三级：核心系统使用国密算法
  - 《密码法》：关键信息基础设施使用商用密码
  - 金融行业：JR/T系列标准要求SM2/SM3/SM4
```

```
密码合规改造方案：

阶段1：算法替换（1-3个月）
  ┌──────────────────────────────────────────┐
  │ 替换映射表                                 │
```

### 11.3 Nginx 国密 TLS 配置

```nginx
# Nginx + GmSSL/Tongsuo 国密TLS配置

server {
    listen 443 ssl;
    server_name secure.example.com;
    
    # 国密双证书（签名证书+加密证书）
    ssl_certificate      /etc/ssl/gm/sm2_sign.crt;
    ssl_certificate_key  /etc/ssl/gm/sm2_sign.key;
    ssl_certificate      /etc/ssl/gm/sm2_enc.crt;
    ssl_certificate_key  /etc/ssl/gm/sm2_enc.key;
    
    # 国密密码套件
    ssl_ciphers ECC-SM4-GCM-SM3:ECC-SM4-CBC-SM3:ECDHE-SM4-GCM-SM3;
    ssl_prefer_server_ciphers on;
    
    # 仅允许国密TLS（严格合规模式）
    # ssl_ciphers ECC-SM4-GCM-SM3;
    
    # 双栈模式：同时支持国密和国际算法
    ssl_certificate      /etc/ssl/rsa/server.crt;
    ssl_certificate_key  /etc/ssl/rsa/server.key;
    ssl_ciphers ECC-SM4-GCM-SM3:ECDHE-RSA-AES256-GCM-SHA384;
    
    # SSL协议版本
    ssl_protocols TLSv1.2 TLSv1.3;
    
    # HSTS
    add_header Strict-Transport-Security "max-age=63072000" always;
}

# 国密客户端证书认证（双向认证）
server {
    listen 8443 ssl;
    server_name internal.example.com;
    
    ssl_certificate      /etc/ssl/gm/sm2_sign.crt;
    ssl_certificate_key  /etc/ssl/gm/sm2_sign.key;
    ssl_ciphers ECC-SM4-GCM-SM3;
    
    # 客户端证书验证
    ssl_client_certificate /etc/ssl/gm/ca.crt;
    ssl_verify_client on;
    ssl_verify_depth 2;
}
```

### 11.4 后量子+国密双合规方案

```
未来展望：后量子 + 国密融合方案

挑战：
  - 国密算法（SM2/SM3/SM4）也是基于传统数学难题
  - SM2基于椭圆曲线离散对数 → 量子计算下不安全
  - 需要同时满足国密合规和后量子安全

混合方案设计：
  ┌──────────────────────────────────────────┐
  │ 密钥交换：SM2 + ML-KEM-768（混合）         │
  │   K = KDF(K_SM2 || K_MLKEM)              │
  │                                          │
  │ 数字签名：SM2 + ML-DSA-65（双签名）        │
  │   签名 = (Sig_SM2, Sig_MLDSA)             │
  │   验证：两个签名都验证                     │
  │                                          │
  │ 对称加密：SM4-256（Grover安全）             │
  │   SM4扩展为256位密钥（需算法扩展）           │
  │   或使用SM4-128 + 二次加密                 │
  │                                          │
  │ 哈希：SM3（256位输出，Grover安全）          │
  └──────────────────────────────────────────┘

注：SM4后量子安全性需关注
  - SM4为128位密钥 → Grover攻击后64位安全
  - 可考虑双密钥方案：K1||K2各128位
  - C = SM4_Enc(P, K1) → SM4_Enc(C, K2)
  - 安全性 ≈ 256位（需形式化证明）
```

### 11.5 改造效果评估

```
合规改造效果：

┌──────────┬───────────────────┬───────────────────┐
│ 指标      │ 改造前              │ 改造后              │
├──────────┼───────────────────┼───────────────────┤
│ 公钥算法  │ RSA-2048           │ SM2-256            │
│ 哈希算法  │ SHA-256           │ SM3                │
│ 对称算法  │ AES-256           │ SM4-128            │
│ TLS套件  │ ECDHE-RSA-AES-GCM │ ECC-SM4-GCM-SM3   │
│ 证书类型  │ RSA证书            │ SM2国密证书         │
│ 合规状态  │ 不满足             │ 满足等保/密码法     │
│ 性能影响  │ -                  │ 约5-15%开销        │
│ 互操作性  │ 广泛               │ 需客户端支持国密    │
└──────────┴───────────────────┴───────────────────┘

性能优化建议：
  1. SM4使用AES-NI类似的指令加速（SM4-NI，部分CPU支持）
  2. SM2使用预计算优化标量乘法
  3. TLS会话恢复减少握手开销
  4. 硬件密码机（HSM）加速SM2/SM3/SM4运算
  5. 连接池减少TLS握手次数
```
