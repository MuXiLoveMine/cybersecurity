# 密钥分级

### 3.1 为什么需要密钥分级

**问题：** 如果所有密钥都用相同的保护级别：
- 高安全级别的密钥保护不足
- 低安全级别的密钥保护过度（成本高）
- 一个密钥泄露可能影响整个系统

**解决方案：密钥分层架构**
```
用高级密钥保护低级密钥
高级密钥数量少、保护强、使用少
低级密钥数量多、保护相对弱、使用多
```

### 3.2 密钥分层模型

典型的三层密钥分层架构：

```
┌─────────────────────────────────────┐
│  主密钥 (Master Key / Root Key)      │  ← 第 0 层：最高级
│  数量最少，安全级别最高              │
│  用于保护密钥加密密钥                │
└─────────────────────────────────────┘
                   │ 加密保护
                   ▼
┌─────────────────────────────────────┐
│  密钥加密密钥 (KEK)                  │  ← 第 1 层：中间层
│  用于加密保护数据加密密钥            │
│  也叫密钥加密密钥、密钥包装密钥      │
└─────────────────────────────────────┘
                   │ 加密保护
                   ▼
┌─────────────────────────────────────┐
│  数据加密密钥 (DEK)                  │  ← 第 2 层：工作层
│  直接用于加密用户数据                │
│  数量最多，轮换最频繁                │
└─────────────────────────────────────┘
```

### 3.3 各层密钥详解

#### （1）主密钥（Master Key / Root Key）

**特点：**
- 整个密钥体系的根基
- 数量最少（通常每个系统只有 1 个或几个）
- 安全级别最高
- 不直接用于加密数据，只用于加密其他密钥
- 轮换周期最长（1-2 年或更长）

**存储要求：**
- 必须存储在 HSM 或同等安全级别的设备中
- 多重身份认证才能访问
- 物理安全保护

**风险：**
- 主密钥泄露 = 所有密钥泄露
- 主密钥丢失 = 所有加密数据丢失
- 必须有备份和恢复机制

#### （2）密钥加密密钥（KEK / Key Encryption Key）

**特点：**
- 用于加密/解密数据加密密钥（密钥包装）
- 也叫 Key Wrapping Key
- 不直接加密用户数据
- 轮换周期中等（6-12 个月）

**密钥包装（Key Wrapping）：**
```
包装（加密密钥）：
  包装后的密钥 = E(KEK, 原始DEK)

解包（解密密钥）：
  原始DEK = D(KEK, 包装后的密钥)
```

**优势：**
- DEK 可以安全地存储在普通存储中（因为被 KEK 加密了）
- KEK 不需要频繁更换（更换 KEK 只需要重新包装所有 DEK）
- DEK 可以方便地传输和备份

#### （3）数据加密密钥（DEK / Data Encryption Key）

**特点：**
- 直接用于加密用户数据
- 数量最多（每个用户/每个文件/每个会话可能一个）
- 轮换周期最短（30-90 天）
- 安全级别相对较低（因为有上层密钥保护）

**存储方式：**
- 被 KEK 加密后存储
- 可以和加密数据存储在一起
- 使用时解密到内存

#### （4）会话密钥（Session Key）

**特点：**
- 单次会话使用的临时密钥
- 会话结束后立即销毁
- 安全性要求：前向保密
- 数量非常多

**用途：**
- TLS 会话密钥
- VPN 会话密钥
- 即时通信会话密钥

### 3.4 密钥分层的优势

1. **降低风险**：高级密钥使用频率低，泄露概率小
2. **便于管理**：大量 DEK 的管理通过少数 KEK 实现
3. **灵活轮换**：更换 DEK 不需要更换主密钥
4. **职责分离**：不同层级的密钥由不同角色管理
5. **成本优化**：只对少量高级密钥使用高成本保护
6. **影响限制**：一个 DEK 泄露只影响对应的数据
