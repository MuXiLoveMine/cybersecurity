# 密钥分发协议

### 5.1 密钥分发的需求

**核心问题：** 如何在不安全的信道上安全地共享密钥？

**解决方案分类：**

```
密钥分发方案
├── 人工分发（带外传输）
├── 对称密钥分发
│   ├── 密钥分发中心（KDC）
│   └── 预共享密钥（PSK）
├── 非对称密钥分发
│   ├── 公钥加密密钥
│   └── 证书 + PKI
└── 密钥协商
    ├── DH / ECDH
    └── 认证密钥交换（如 TLS）
```

### 5.2 密钥分发中心（KDC）

**KDC（Key Distribution Center）** 是一个可信的第三方，负责分发密钥。

**典型代表：Kerberos**

```
Kerberos 协议流程：

  Alice (用户)          KDC                  Bob (服务器)
     │                    │                     │
     │── AS 请求 ────────→│                     │
     │←── TGT ────────────│                     │
     │   (用 TGS 密钥加密)  │                     │
     │                    │                     │
     │── TGS 请求 ───────→│                     │
     │   (包含 TGT)        │                     │
     │←── 服务票据 ────────│                     │
     │   (用 Bob 密钥加密)  │                     │
     │                    │                     │
     │────────────── 服务票据 ─────────────────→│
     │                    │                     │
     │←──────────── 认证响应 ───────────────────│
     │                    │                     │
     │     双方获得会话密钥                      │
```

**Kerberos 的特点：**
- 中心化的密钥管理
- 支持单点登录（SSO）
- 使用对称加密
- 依赖 KDC 的可用性和安全性
- 有时间同步要求（防止重放攻击）

### 5.3 公钥加密分发

**原理：** 用接收方的公钥加密对称密钥，发送给接收方。

```
Alice 想给 Bob 发送密钥 K：

1. Alice 获取 Bob 的公钥（通过证书等方式）
2. Alice 生成随机对称密钥 K
3. Alice 用 Bob 的公钥加密 K：C = E(PK_Bob, K)
4. Alice 将 C 发送给 Bob
5. Bob 用私钥解密：K = D(SK_Bob, C)
6. 双方共享密钥 K
```

**特点：**
- 不需要第三方在线服务
- 需要公钥基础设施（PKI）来认证公钥
- 适合密钥交换，但不适合大量数据加密

### 5.4 Diffie-Hellman 密钥交换

（详细原理见「非对称密码学详解」第六章）

**DH 的问题：** 不提供身份认证，容易遭受中间人攻击。

**解决方案：认证 DH**

```
静态 DH（Static DH）：
- 双方使用固定的公钥（经过证书认证）
- 每次会话使用相同的私钥
- 不提供前向保密

临时 DH（Ephemeral DH, DHE）：
- 每次会话生成临时密钥对
- 用长期私钥签名临时公钥
- 提供前向保密
- 需要身份认证（签名）
```

**实际应用中的认证密钥交换：**

| 协议 | 说明 |
|------|------|
| TLS-DHE-RSA | DH 密钥交换 + RSA 认证 |
| TLS-ECDHE-RSA | ECDH 密钥交换 + RSA 认证 |
| TLS-ECDHE-ECDSA | ECDH 密钥交换 + ECDSA 认证 |
| IKE | IPsec 的密钥交换协议 |
| SSH | SSH 协议的密钥交换 |

### 5.5 预共享密钥（PSK）

**PSK（Pre-Shared Key）**：双方事先通过安全渠道共享密钥，直接使用。

**特点：**
- 简单直接
- 不需要复杂的协议
- 适合小规模、固定的场景
- 扩展性差（n 个用户需要 n(n-1)/2 个密钥）

**应用场景：**
- WiFi（WPA-PSK）
- VPN（预共享密钥模式）
- 小型设备之间的通信
