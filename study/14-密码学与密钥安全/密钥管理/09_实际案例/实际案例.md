# 实际案例

### 案例 1：Code Spaces 被黑客删除所有数据

**背景：**
- Code Spaces 是一家代码托管服务
- 使用 AWS 云服务

**事件经过：**
1. 黑客获取了 Code Spaces 的 AWS 访问密钥
2. 黑客登录 AWS 控制台
3. 黑客先是勒索，要求支付赎金
4. Code Spaces 试图恢复访问权限
5. 黑客发现后，删除了所有数据（EC2、S3、EBS 等）
6. Code Spaces 因此倒闭

**原因分析：**
- AWS 访问密钥管理不当
- 可能是硬编码在代码中或配置文件泄露
- 没有启用 MFA 保护
- 权限过大（一个密钥可以访问所有资源）

**教训：**
- 密钥权限要最小化
- 启用多因素认证
- 定期轮换密钥
- 监控异常访问
- 数据备份要隔离（不能用同一个账号）

### 案例 2：Uber 数据泄露（2016）

**背景：**
- Uber 5700 万用户数据泄露
- 包括司机和乘客的个人信息

**事件经过：**
1. 黑客在 GitHub 上发现了 Uber 工程师提交的 AWS 密钥
2. 黑客用这个密钥访问了 Uber 的 AWS 账户
3. 下载了 5700 万用户的数据
4. 黑客向 Uber 勒索 10 万美元
5. Uber 支付了赎金，并试图掩盖事件

**后果：**
- Uber 被罚款 1.48 亿美元
- CEO 被迫辞职
- 声誉严重受损

**教训：**
- 绝对不能把密钥提交到版本控制
- 密钥扫描和检测很重要
- 密钥权限要最小化
- 安全事件不能隐瞒

### 案例 3：DigiNotar CA 被黑

**背景：**
- DigiNotar 是荷兰的一家 CA 机构
- 2011 年被黑客入侵

**事件经过：**
1. 黑客入侵了 DigiNotar 的系统
2. 黑客签发了数百张伪造的证书
3. 包括 Google、Yahoo、Mozilla 等知名网站的证书
4. 这些伪造证书被用于伊朗的中间人攻击
5. 浏览器厂商紧急撤销 DigiNotar 的根证书
6. DigiNotar 破产

**影响：**
- 整个 PKI 体系的信任受到质疑
- 数百万用户面临安全风险
- CA 的安全标准被提高

**教训：**
- CA 是 PKI 的信任根基，必须最高级别保护
- CA 被攻破 = 整个信任体系崩塌
- 证书透明性（CT）很重要
- 根 CA 应该离线保护
