# 实际案例

### 案例 1：WEP 协议破解

**背景：**
- WEP（Wired Equivalent Privacy）是 802.11 无线网络的加密协议
- 使用 RC4 流密码加密
- 24 位 IV + 40/104 位密钥

**漏洞：**
1. IV 太短（24 位），容易重复
2. RC4 的 KSA 有偏置（FMS 攻击）
3. 没有完整性保护（可以篡改数据）
4. CRC 校验不是密码学安全的

**攻击过程：**
1. 监听无线数据包，收集 IV
2. 收集到足够多的 IV（约 5000-10000 个弱 IV）
3. 使用 FMS 攻击或 KoreK 攻击恢复密钥
4. 几分钟内即可破解

**结果：**
- WEP 完全不安全
- 被 WPA/WPA2 取代

### 案例 2：SSL BEAST 攻击

**背景：**
- BEAST（Browser Exploit Against SSL/TLS）攻击
- 针对 TLS 1.0 和更早版本的 CBC 模式

**原理：**
- 利用 CBC 模式的 IV 可预测性（IV 是前一个密文块）
- 结合选择明文攻击，逐字节解密数据

**影响：**
- 可以解密 HTTPS 通信中的 Cookie 等敏感信息
- 影响所有使用 TLS 1.0 CBC 模式的网站

**修复：**
- 升级到 TLS 1.1+（每个记录使用新 IV）
- 或者使用 RC4 模式（但 RC4 本身也不安全）
- 最终方案：使用 GCM 等认证加密模式

### 案例 3：Heartbleed 漏洞

**背景：**
- OpenSSL 的 Heartbeat 扩展漏洞（CVE-2014-0160）
- 2014 年披露，影响巨大

**原理：**
- Heartbeat 请求中包含长度字段
- 服务器不验证长度是否真实
- 攻击者可以请求最多 64KB 的内存数据

**影响：**
- 可以读取服务器内存中的敏感数据
- 包括私钥、会话密钥、用户密码等
- 影响全球约 50 万台服务器

**教训：**
- 输入验证很重要
- 密码学库的实现质量至关重要
- 即使算法安全，实现错误也会导致严重漏洞
