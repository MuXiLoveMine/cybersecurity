# DES 与双重 DES 中间人攻击

### 3.1 为什么需要 3DES？

DES 不安全了，但：
- 很多系统已经大量部署 DES
- 硬件投资巨大
- 直接迁移到新算法成本高

解决方案：**三重 DES（3DES / Triple DES）**，在不更换硬件的前提下提高安全性。

### 3.2 双重 DES（2DES）

首先尝试的是双重 DES：

```
C = E(K₂, E(K₁, P))
P = D(K₁, D(K₂, C))
```

密钥长度：112 位（两个 56 位密钥）

**问题：中间人攻击（Meet-in-the-Middle Attack）**

### 3.3 双重 DES 中间人攻击详解

**攻击原理：**

双重 DES 的加密过程是：
```
C = E(K₂, E(K₁, P))
```

我们可以将其拆分为：
```
X = E(K₁, P)    （中间值）
C = E(K₂, X)
```

**攻击步骤：**

```
已知一对明文-密文 (P, C)

步骤 1：加密表（前向）
  对所有可能的 K₁（2^56 个）：
    X = E(K₁, P)
    将 (X, K₁) 存入哈希表

步骤 2：解密表（后向）
  对所有可能的 K₂（2^56 个）：
    X' = D(K₂, C)
    在哈希表中查找 X'
    如果找到，则得到候选的 (K₁, K₂)

步骤 3：验证
  用另一对明文-密文验证候选密钥
```

**攻击复杂度分析：**

| 项目 | 暴力破解 DES | 暴力破解 2DES | 中间人攻击 2DES |
|------|-------------|--------------|----------------|
| 时间复杂度 | 2^56 | 2^112 | 2^57 ≈ 2 × 2^56 |
| 空间复杂度 | - | - | 2^56 |

> 中间人攻击将双重 DES 的安全性从 2^112 降低到约 2^57，几乎和单重 DES 差不多！

**案例：**
- 1977 年 Diffie 和 Hellman 就提出了中间人攻击
- 这也是为什么没有广泛使用 2DES，而是直接使用 3DES

### 3.4 三重 DES（3DES）

为了抵抗中间人攻击，使用三重 DES：

**模式一：EDE（Encrypt-Decrypt-Encrypt）- 最常用**

```
C = E(K₃, D(K₂, E(K₁, P)))
P = D(K₁, E(K₂, D(K₃, C)))
```

**模式二：EEE（Encrypt-Encrypt-Encrypt）**

```
C = E(K₃, E(K₂, E(K₁, P)))
```

**密钥选项：**

| 选项 | 密钥配置 | 有效密钥长度 | 说明 |
|------|---------|-------------|------|
| 3TDEA | K₁ ≠ K₂ ≠ K₃ | 168 位（实际安全强度约 112 位） | 最安全 |
| 2TDEA | K₁ = K₃ ≠ K₂ | 112 位 | 兼容模式，常用 |
| 1TDEA | K₁ = K₂ = K₃ | 56 位 | 等价于单 DES，兼容用 |

> **为什么用 EDE 而不是 EEE？**
> 当 K₁ = K₂ = K₃ 时，EDE 模式退化为单 DES：
> C = E(K, D(K, E(K, P))) = E(K, P)
> 这样可以向后兼容单 DES 系统。

### 3.5 3DES 的安全性

**对 3DES 的中间人攻击：**

3DES 也存在中间人攻击，但复杂度更高：

```
C = E(K₃, D(K₂, E(K₁, P)))

攻击思路：
- 前向：计算 E(K₁, P)，2^56
- 后向：计算 D(K₃, C)，2^56
- 中间：对所有 K₂ 进行匹配，2^56 × 2^56 = 2^112

总复杂度：2^112 时间 + 2^56 空间
```

所以 3DES 的有效安全强度约为 112 位。

### 3.6 3DES 的缺点

1. **速度慢**：是 DES 的 3 倍
2. **块大小小**：64 位块在现代应用中太小
3. **安全性逐渐降低**：112 位安全强度在长期来看不够
4. **NIST 计划**：2023 年后禁止在新应用中使用 3DES
