# AES 工作模式

分组密码只能加密固定长度的数据块。要加密任意长度的数据，需要使用**工作模式（Mode of Operation）**。

### 5.1 ECB 模式（Electronic Codebook）

**电子密码本模式**，最简单的模式。

```
明文：P₁ P₂ P₃ ... Pₙ
      │  │  │       │
      E  E  E       E   ← 相同密钥 K
      │  │  │       │
密文：C₁ C₂ C₃ ... Cₙ

C_i = E(K, P_i)
P_i = D(K, C_i)
```

**特点：**
- 每个块独立加密
- 相同的明文块产生相同的密文块
- 可并行加密/解密
- 错误不传播（一个块错了不影响其他块）

**问题：**
- **不安全！** 相同明文块产生相同密文块，泄露信息模式
- 不能隐藏数据结构

**经典案例：ECB 企鹅**

```
明文图片（Linux 企鹅 Tux）：
    加密前          ECB加密后        CBC加密后
  ┌─────────┐    ┌─────────┐    ┌─────────┐
  │  ****   │    │  ****   │    │ ░▒▓█▓▒░ │
  │ ******  │ →  │ ******  │    │ █▓░▒█▓▒ │  ← 完全乱码
  │  ****   │    │  ****   │    │ ▒█▓░▒█▓ │
  └─────────┘    └─────────┘    └─────────┘
```

ECB 模式加密的图片，相同颜色的像素块加密后颜色也相同，图案清晰可见。

**使用建议：绝对不要使用 ECB 模式！**

### 5.2 CBC 模式（Cipher Block Chaining）

**密码分组链接模式**，最常用的模式之一。

```
        IV        IV        IV
         │         │         │
P₁ ────⊕─┘  P₂ ──⊕─┘  P₃ ──⊕─┘
        │         │         │
        E         E         E   ← 密钥 K
        │         │         │
        C₁        C₂        C₃

C₀ = IV
C_i = E(K, P_i ⊕ C_{i-1})
P_i = D(K, C_i) ⊕ C_{i-1}
```

**初始化向量 IV（Initialization Vector）：**
- 第一个块需要一个初始值
- IV 不需要保密，但必须是随机的（不可预测）
- IV 长度等于块大小（128 位）

**特点：**
- 相同明文块产生不同密文块（依赖前面的密文）
- 加密是串行的（不能并行加密）
- 解密可以并行（因为解密只需要前一个密文块）
- 错误传播：一个密文块出错，影响两个明文块

**错误传播示例：**
```
如果 C₂ 被篡改：
- P₂ = D(K, C₂) ⊕ C₁  →  完全错误
- P₃ = D(K, C₃) ⊕ C₂  →  完全错误
- P₁, P₄, P₅... 不受影响
```

**常见问题：**
1. **IV 重复**：如果相同 IV 用于两个消息，那么两个消息的第一个明文块相同则密文也相同
2. **IV 可预测**：攻击者可以利用可预测的 IV 进行选择明文攻击
3. **填充 oracle 攻击**：利用填充错误信息进行攻击（Padding Oracle Attack）

### 5.3 CFB 模式（Cipher Feedback）

**密码反馈模式**，将分组密码转化为流密码。

```
        IV        C₁        C₂
         │         │         │
         E         E         E   ← 密钥 K
         │         │         │
P₁ ─────⊕─ P₂ ───⊕─ P₃ ───⊕─
         │         │         │
         C₁        C₂        C₃

C_i = P_i ⊕ E(K, C_{i-1})，其中 C₀ = IV
P_i = C_i ⊕ E(K, C_{i-1})
```

**特点：**
- 将分组密码变为自同步流密码
- 加密和解密都使用加密函数 E（不需要解密函数 D）
- 有不同的反馈大小（1位、8位、128位等）
- 错误传播：一个位错误影响当前块和下一块

### 5.4 OFB 模式（Output Feedback）

**输出反馈模式**，也是将分组密码转化为流密码。

```
        IV        O₁        O₂
         │         │         │
         E         E         E   ← 密钥 K
         │         │         │
         O₁        O₂        O₃  ← 密钥流
         │         │         │
P₁ ─────⊕─ P₂ ───⊕─ P₃ ───⊕─
         │         │         │
         C₁        C₂        C₃

O₀ = IV
O_i = E(K, O_{i-1})
C_i = P_i ⊕ O_i
P_i = C_i ⊕ O_i
```

**特点：**
- 生成密钥流，与明文异或
- 密钥流与明文无关
- 没有错误传播（一位错误只影响对应位）
- 不能自同步（丢失同步后需要重新同步）
- 加密和解密完全相同

**问题：**
- 如果密钥流重复（IV 重复），就不安全了
- 类似一次性密码本，密钥流不能重复使用

### 5.5 CTR 模式（Counter）

**计数器模式**，现代应用中非常常用。

```
       CTR₀      CTR₁      CTR₂
         │         │         │
         E         E         E   ← 密钥 K
         │         │         │
         O₁        O₂        O₃  ← 密钥流
         │         │         │
P₁ ─────⊕─ P₂ ───⊕─ P₃ ───⊕─
         │         │         │
         C₁        C₂        C₃

CTR_i = Nonce || Counter（128位）
O_i = E(K, CTR_i)
C_i = P_i ⊕ O_i
P_i = C_i ⊕ O_i
```

**计数器构造：**
- 通常前 96 位是 nonce（随机数，每个消息唯一）
- 后 32 位是计数器（从 0 开始递增）
- 也可以是其他划分方式

**特点：**
- 完全可并行（加密解密都可以并行处理）
- 没有错误传播
- 加密和解密完全相同
- 只需要加密函数（不需要解密函数）
- 可以随机访问（解密任意位置的块）
- 效率高，性能好

**注意事项：**
- Nonce 必须唯一（同一个密钥下不能重复）
- 计数器不能溢出
- 不需要 IV 是随机的，但必须是唯一的

### 5.6 GCM 模式（Galois/Counter Mode）

**伽罗瓦/计数器模式**，是一种**认证加密（AEAD）** 模式，同时提供加密和认证。

```
GCM = CTR 模式 + GHASH 认证

加密过程：
1. 使用 CTR 模式加密数据，得到密文
2. 使用 GHASH 计算认证标签（Tag）
3. 输出：密文 + 认证标签

认证过程：
1. 重新计算 GHASH
2. 与收到的标签比较
3. 匹配则认证通过，否则拒绝
```

**GHASH（伽罗瓦哈希）：**
- 在 GF(2^128) 上进行多项式求值
- 使用认证密钥 H = E(K, 0^128)
- 输入：关联数据（AAD）+ 密文 + 长度信息
- 输出：128 位认证标签

**关联数据 AAD（Additional Authenticated Data）：**
- 也叫关联数据 AD
- 不需要加密，但需要认证的数据
- 例如：包头、序列号、地址等
- AAD 不加密，但被纳入标签计算

**特点：**
- 同时提供保密性、完整性、认证性
- 可并行计算（高性能）
- 已标准化（NIST SP 800-38D）
- 广泛用于 TLS 1.3、SSH、IPsec 等

**安全注意：**
- Nonce 绝对不能重复（同一密钥下）
- Nonce 重复会导致密钥泄露和认证失效
- 推荐 96 位 nonce + 32 位计数器
- 认证标签推荐 128 位，最低 96 位

### 5.7 XTS 模式（XEX Tweakable Block Cipher with Ciphertext Stealing）

**XTS 模式**是专门为磁盘加密设计的模式。

**为什么磁盘加密需要特殊模式？**
- 磁盘扇区是独立的（需要随机访问）
- 不能存储额外数据（IV、标签等）
- 每个扇区大小固定（通常 512 字节或 4KB）
- 相同明文在不同位置应该加密成不同密文

**XTS 原理：**
```
使用两个密钥 K1 和 K2

对于扇区 i 的第 j 个块：
Tweak T_i = E(K2, i)  （i 是扇区号）
C = E(K1, P ⊕ T_i) ⊕ T_i

其中 Tweak 每个扇区不同，确保相同明文在不同扇区加密结果不同
```

**特点：**
- 专门用于扇区级加密
- 支持密文窃取（处理非完整块）
- 每个扇区独立（支持随机访问）
- 不提供认证（磁盘加密通常不需要）
- 用于：BitLocker、VeraCrypt、LUKS 等

### 5.8 工作模式对比

| 模式 | 全称 | 加密并行 | 解密并行 | 错误传播 | 认证 | 特点/用途 |
|------|------|---------|---------|---------|------|----------|
| ECB | Electronic Codebook | ✅ | ✅ | 无 | ❌ | 不安全，不推荐 |
| CBC | Cipher Block Chaining | ❌ | ✅ | 1块 | ❌ | 常用，但有填充攻击风险 |
| CFB | Cipher Feedback | ❌ | ✅ | 1块+ | ❌ | 流密码模式 |
| OFB | Output Feedback | ❌ | ❌ | 无 | ❌ | 流密码模式，无错误传播 |
| CTR | Counter | ✅ | ✅ | 无 | ❌ | 高性能，可并行，推荐 |
| GCM | Galois/Counter | ✅ | ✅ | 无 | ✅ | 认证加密，推荐 |
| XTS | XEX Tweakable ... | ✅ | ✅ | 1块 | ❌ | 磁盘加密专用 |
