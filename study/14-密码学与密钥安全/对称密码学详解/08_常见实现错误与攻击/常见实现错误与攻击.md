# 常见实现错误与攻击

### 8.1 ECB 模式使用错误

**错误：** 使用 ECB 模式加密数据
**后果：** 相同明文块产生相同密文，泄露数据模式
**修复：** 使用 CBC、CTR、GCM 等模式

**案例：**
- 早期的一些加密软件使用 ECB 模式
- 数据库加密使用 ECB 模式导致数据模式泄露

### 8.2 IV/Nonce 使用错误

**错误 1：IV 固定不变**
```python
# 错误！每次都用相同的 IV
iv = b'0123456789abcdef'
cipher = AES.new(key, AES.MODE_CBC, iv)
```
**后果：** 相同的明文开头产生相同的密文开头

**错误 2：IV 可预测**
```python
# 错误！计数器作为 IV 是可预测的
iv = counter.to_bytes(16, 'big')
```
**后果：** 可能遭受选择明文攻击

**错误 3：CTR/GCM 模式 nonce 重复**
```python
# 错误！同一个密钥下 nonce 不能重复
nonce = b'fixed_nonce_123'
```
**后果：** GCM 模式下 nonce 重复会导致密钥和认证失效

**正确做法：**
```python
# CBC 模式：随机 IV
iv = os.urandom(16)

# GCM 模式：随机 nonce（96位推荐）
nonce = os.urandom(12)

# 注意：IV/nonce 不需要保密，但要和密文一起存储
```

### 8.3 填充 Oracle 攻击

**攻击原理：**
攻击者通过观察解密时的填充错误信息，逐字节解密密文。

**攻击条件：**
- 使用 CBC 模式
- 有 PKCS#5/PKCS#7 填充
- 攻击者可以向服务器发送密文
- 服务器会返回填充是否正确的信息

**攻击复杂度：**
- 每个字节只需要最多 256 次尝试
- n 字节密文只需要 256×n 次尝试

**防护措施：**
1. 使用 GCM 等认证加密模式
2. 解密前先验证认证标签
3. 统一错误信息，不要泄露填充错误
4. 使用填充验证时保持恒定时间

**案例：**
- POODLE 攻击（SSL 3.0 CBC 模式）
- Lucky 13 攻击（TLS CBC 模式时序差异）

### 8.4 密钥派生错误

**错误：** 直接用用户密码作为加密密钥
```python
# 错误！用户密码熵不够
key = password.encode()
```

**正确做法：** 使用 KDF（密钥派生函数）
```python
# 正确：使用 PBKDF2 派生密钥
from hashlib import pbkdf2_hmac
salt = os.urandom(16)
key = pbkdf2_hmac('sha256', password.encode(), salt, 100000, dklen=32)
```

### 8.5 侧信道攻击

**时序攻击（Timing Attack）：**
- 利用不同输入的执行时间差异
- 例如：字符串比较的提前终止

```python
# 危险！存在时序漏洞
def compare(a, b):
    if len(a) != len(b):
        return False
    for x, y in zip(a, b):
        if x != y:
            return False  # 提前返回，时间不同
    return True

# 安全：恒定时间比较
def constant_time_compare(a, b):
    if len(a) != len(b):
        return False
    result = 0
    for x, y in zip(a, b):
        result |= x ^ y
    return result == 0
```

**功耗分析（Power Analysis）：**
- 简单功耗分析（SPA）：直接观察功耗波形
- 差分功耗分析（DPA）：统计分析多次功耗数据

**防护：**
- 恒定时间实现
- 功耗平衡
- 随机化操作顺序
- 屏蔽技术（Masking）
- 硬件防护（HSM、智能卡）

### 8.6 弱随机数生成

**错误：** 使用不安全的随机数生成器
```python
# 错误！random 模块不是密码学安全的
import random
iv = bytes([random.randint(0, 255) for _ in range(16)])
```

**正确做法：**
```python
# 正确：使用密码学安全的随机数
import os
iv = os.urandom(16)

# 或者使用 secrets 模块
import secrets
iv = secrets.token_bytes(16)
```

**案例：**
- Netscape 早期 SSL 的随机数漏洞（用时间和 PID 生成随机数）
- 安卓 SecureRandom 漏洞（2013 年）
- 很多比特币钱包因为弱随机数导致私钥被盗

### 8.7 密钥硬编码

**错误：** 将密钥硬编码在代码中
```python
# 错误！密钥硬编码，反编译就能拿到
key = b'mysecretkey12345'
```

**正确做法：**
- 从环境变量读取
- 从配置文件读取（配置文件加密）
- 使用 KMS / HSM
- 使用密钥管理服务

### 8.8 明文保留

**错误：** 加密后忘记清除明文内存

**问题：**
- 明文可能残留在内存中
- 可能被内存dump获取
- 可能被交换到磁盘

**防护：**
- 加密后立即清除明文缓冲区
- 使用安全内存（锁定内存，防止交换）
- 敏感数据使用后立即清零
