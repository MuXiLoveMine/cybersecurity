# DH 密钥交换

### 6.1 DH 概述

**Diffie-Hellman 密钥交换** 是 Whitfield Diffie 和 Martin Hellman 于 1976 年提出的，是第一个公钥密码学协议。

**核心思想：** 双方在不安全的信道上协商出一个共享密钥，攻击者即使监听了所有通信也无法计算出密钥。

**基于难题：** 有限域上的离散对数问题（DLP）

### 6.2 DH 原理

```
公开参数（所有人都知道）：
  p：大素数
  g：生成元（g 是模 p 的原根）

Alice                        Bob
  │                            │
  │  生成私钥 a（随机数）       │  生成私钥 b（随机数）
  │  计算公钥 A = g^a mod p    │  计算公钥 B = g^b mod p
  │                            │
  ├───────── 发送 A ──────────→│
  │                            │
  │←──────── 发送 B ───────────┤
  │                            │
  │  计算共享密钥：             │  计算共享密钥：
  │  s = B^a mod p             │  s = A^b mod p
  │    = (g^b)^a mod p         │    = (g^a)^b mod p
  │    = g^(ab) mod p          │    = g^(ab) mod p
  │                            │
  │         双方得到相同的 s     │
```

**数学验证：**
```
Alice 计算：s = B^a mod p = (g^b mod p)^a mod p = g^(ab) mod p
Bob 计算：  s = A^b mod p = (g^a mod p)^b mod p = g^(ab) mod p

结果相同！
```

### 6.3 离散对数问题（DLP）

攻击者知道 p、g、A、B，但不知道 a、b，要计算共享密钥 s = g^(ab) mod p。

这就是**计算 Diffie-Hellman 问题（CDH）**：
```
已知 g、g^a、g^b，求 g^(ab)
```

CDH 被认为是困难的，它的难度与离散对数问题相关：
- 如果能解决离散对数问题（从 g^a 求 a），就能解决 CDH
- 但反过来不一定成立

### 6.4 DH 的问题：中间人攻击

DH 密钥交换本身**不提供身份认证**，容易遭受中间人攻击（Man-in-the-Middle, MITM）。

```
Alice                      攻击者 Eve                       Bob
  │                            │                            │
  │  生成 a                    │  生成 a'                   │  生成 b
  │  A = g^a                   │  A' = g^a'                 │  B = g^b
  │                            │                            │
  ├────── 发送 A ─────────────→│                            │
  │                            ├────── 发送 A' ────────────→│
  │                            │                            │
  │←───── 发送 B' ─────────────┤←────── 发送 B ─────────────┤
  │         B' = g^b'          │         b' 是 Eve 的私钥   │
  │                            │                            │
  │  s1 = B'^a = g^(ab')       │  s1 = A^b' = g^(ab')      │
  │                            │  s2 = B^a' = g^(a'b)      │  s2 = A'^b = g^(a'b)
  │                            │                            │
  │      Alice 以为和 Bob 共享s1  Eve 和 Alice共享s1，和Bob共享s2  Bob 以为和 Alice 共享s2
```

**结果：**
- Alice 和 Eve 共享密钥 s1
- Bob 和 Eve 共享密钥 s2
- Eve 可以解密所有通信并转发（或篡改）

**解决方案：**
- 结合数字签名（验证对方身份）
- 使用证书（PKI 体系）
- 使用 PSK（预共享密钥）
- 口令认证密钥交换（PAKE）

### 6.5 DH 参数选择

**素数 p：**
- 足够大（至少 2048 位，推荐 3072 位）
- 安全素数（p = 2q + 1，q 也是素数）更好

**生成元 g：**
- 应该是大阶的生成元
- 阶应该是大素数 q

**Logjam 攻击：**
- 如果使用 512 位或 1024 位的 DH 组
- 攻击者可以预先计算离散对数表
- 然后快速解密通信
- 影响大量使用 1024 位 DH 的服务器

**建议：**
- 使用至少 2048 位的 DH 组
- 或者使用 ECDH（椭圆曲线版本，更安全高效）
- 使用标准的 DH 组（如 RFC 3526 定义的组）

### 6.6 前向保密（Forward Secrecy）

**前向保密（Forward Secrecy / Perfect Forward Secrecy, PFS）**：
即使长期私钥泄露，也不会导致之前的会话密钥泄露。

**实现方式：** 使用临时 DH（DHE）或临时 ECDH（ECDHE）

```
普通 RSA 密钥交换（无前向保密）：
- 服务器私钥是长期的
- 如果私钥泄露，所有之前的会话都可以解密
- 因为会话密钥是用服务器私钥加密传输的

DHE/ECDHE（有前向保密）：
- 每次会话生成临时密钥对
- 会话结束后销毁临时私钥
- 即使长期私钥泄露，也无法解密之前的会话
- 因为长期私钥只用于签名认证临时公钥
```
