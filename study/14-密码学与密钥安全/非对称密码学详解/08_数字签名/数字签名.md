# 数字签名

### 8.1 数字签名概述

**数字签名（Digital Signature）** 是附加在数据上的一串数据，用于证明数据的来源和完整性。

**作用：**
1. **身份认证**：验证消息是谁发送的
2. **完整性**：验证消息没有被篡改
3. **不可否认性**：发送者不能否认发送过消息

**与手写签名的对比：**

| 特性 | 手写签名 | 数字签名 |
|------|---------|---------|
| 与消息的关系 | 物理附加 | 数学关联 |
| 复制难度 | 容易伪造 | 不可伪造 |
| 验证方式 | 人工比对 | 算法验证 |
| 不可否认性 | 较弱 | 强 |

### 8.2 数字签名原理

**基本流程：**

```
签名：
  消息 M → 哈希 → 摘要 H → 私钥签名 → 签名 S
  发送：消息 M + 签名 S

验证：
  收到：消息 M' + 签名 S'
  消息 M' → 哈希 → 摘要 H'
  公钥验证签名 S' → 得到摘要 H
  比较 H' 和 H：
    相等 → 验证通过
    不等 → 验证失败
```

**为什么要先哈希再签名？**
1. **效率**：非对称加密慢，哈希快，只对短摘要签名
2. **安全**：直接对消息签名有安全隐患（如 RSA 的同态性）
3. **格式**：消息长度任意，签名算法需要固定长度输入

### 8.3 RSA 签名

#### PKCS#1 v1.5 签名

```
签名：
  1. 计算 H = Hash(M)
  2. 填充：EM = 0x00 || 0x01 || PS || 0x00 || T || H
     其中 PS 是 0xFF 填充，T 是算法标识
  3. S = EM^d mod n

验证：
  1. EM' = S^e mod n
  2. 解析 EM'，检查填充格式
  3. 提取 H'，与 Hash(M) 比较
```

**问题：**
- 存在伪造攻击（Bleichenbacher 签名伪造）
- 填充验证不严格可能被利用

#### RSA-PSS 签名

```
PSS (Probabilistic Signature Scheme)

特点：
- 概率性（每次签名结果不同）
- 可证明安全
- 推荐使用
```

### 8.4 ECDSA 签名

（详见第四章 4.4 节）

**特点：**
- 签名短（两个坐标分量）
- 速度快
- 对随机数 k 的质量要求很高
- k 泄露或重用都会导致私钥泄露

### 8.5 EdDSA / Ed25519

**EdDSA（Edwards-curve Digital Signature Algorithm）** 是基于 Edwards 曲线的签名算法。

**特点：**
- 不需要随机数 k（使用确定性的方式生成）
- 避免了 ECDSA 的 k 重用问题
- 快速、安全、实现简单
- Ed25519 是最常用的实例

**签名过程（简化）：**
```
1. 计算 r = Hash(Hash(sk) || M)  （确定性生成，不需要随机数）
2. 计算 R = r × B
3. 计算 S = (r + Hash(R || A || M) × a) mod L
   其中 A = a × B 是公钥，a 是私钥

签名：(R, S)
```

### 8.6 SM2 签名

（详见第五章 5.3 节）

SM2 签名的特点：
- 包含用户标识 Z_A
- 使用 SM3 哈希算法
- 国密标准

### 8.7 签名算法对比

| 算法 | 密钥长度 | 签名长度 | 安全性 | 特点 |
|------|---------|---------|--------|------|
| RSA 2048 | 2048 位 | 256 字节 | 112 位 | 广泛使用，速度较慢 |
| RSA 3072 | 3072 位 | 384 字节 | 128 位 | 更安全，更慢 |
| ECDSA P-256 | 256 位 | 64 字节 | 128 位 | 标准椭圆曲线 |
| Ed25519 | 256 位 | 64 字节 | 128 位 | 快速安全，无随机数问题 |
| SM2 | 256 位 | 64 字节 | 128 位 | 国密标准 |
