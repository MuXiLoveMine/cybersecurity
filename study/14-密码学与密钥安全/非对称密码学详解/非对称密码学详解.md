# 非对称密码学详解

> 非对称加密（公钥密码学）是现代密码学的里程碑，解决了密钥分发和数字签名的核心问题。本文详细讲解 RSA、ECC、国密 SM2、密钥交换和数字签名。

---

## 一、公钥密码学原理

### 1.1 基本概念

**非对称加密（Asymmetric Encryption）**，又称公钥加密（Public Key Cryptography），使用一对密钥：公钥和私钥。

```
┌─────────────┐                    ┌─────────────┐
│   公钥 PK   │  ←── 公开分发 ──→  │   公钥 PK   │
│ (Public Key)│                    │ (Public Key)│
└─────────────┘                    └─────────────┘
         │                                  │
         │ 加密                              │ 验证签名
         ▼                                  ▼
      密文                                签名
         │                                  │
         │ 解密                              │ 签名
         ▼                                  ▼
┌─────────────┐                    ┌─────────────┐
│   私钥 SK   │                    │   私钥 SK   │
│ (Private Key)│                    │ (Private Key)│
└─────────────┘                    └─────────────┘
```

**核心特性：**
- **双向性**：公钥加密 → 私钥解密（加密）
- **单向性**：私钥签名 → 公钥验证（签名）
- **不可推导**：从公钥无法计算出私钥（计算上不可行）

### 1.2 数学基础：陷门单向函数

公钥密码学的核心是**陷门单向函数（Trapdoor One-way Function）**：

```
单向函数：
  f(x) = y    容易计算（正向）
  f⁻¹(y) = x  很难计算（反向）

陷门单向函数：
  f(x) = y    容易计算
  f⁻¹(y) = x  很难计算（除非知道陷门信息）
  有了陷门（私钥），反向计算变得容易
```

**常见的数学难题（陷门基础）：**

| 数学难题 | 代表算法 | 描述 |
|----------|---------|------|
| 大整数分解 | RSA | 分解两个大素数的乘积很难 |
| 离散对数 | DH、DSA、ElGamal | 有限域上求离散对数很难 |
| 椭圆曲线离散对数 | ECC、ECDH、ECDSA | 椭圆曲线上求离散对数很难 |
| 格上最短向量 | 格密码 | 格中找最短非零向量很难 |

### 1.3 对称 vs 非对称对比

| 特性 | 对称加密 | 非对称加密 |
|------|---------|-----------|
| 密钥 | 一个密钥（加密解密相同） | 一对密钥（公钥/私钥） |
| 密钥分发 | 困难 | 容易（公钥公开） |
| 速度 | 快（适合大数据） | 慢（不适合大数据） |
| 典型算法 | AES、DES、SM4 | RSA、ECC、SM2 |
| 密钥长度 | 128-256 位 | 2048-4096 位（RSA） |
| 数字签名 | 不能 | 可以 |
| 不可否认性 | 不提供 | 提供 |

**混合加密（Hybrid Encryption）：**
实际应用中通常结合使用：
1. 用非对称加密交换对称密钥（密钥交换）
2. 用对称加密加密实际数据（数据加密）

```
发送方：
  1. 生成随机对称密钥 K
  2. 用接收方公钥加密 K → Ck = E(PK_recv, K)
  3. 用 K 加密数据 → Cd = E(K, data)
  4. 发送 (Ck, Cd)

接收方：
  1. 用私钥解密 Ck → K = D(SK_recv, Ck)
  2. 用 K 解密 Cd → data = D(K, Cd)
```

## 二、RSA 算法原理

### 2.1 RSA 概述

**RSA** 是由 Ron Rivest、Adi Shamir、Leonard Adleman 于 1977 年提出的公钥加密算法。

- **基于难题**：大整数分解难题
- **用途**：加密、解密、数字签名、密钥交换
- **密钥长度**：1024（已不安全）、2048（最低）、3072（推荐）、4096（高安全）

### 2.2 数学基础

#### （1）素数与互质

- **素数（Prime）**：大于 1 的自然数，除了 1 和自身外没有其他因数
- **互质（Coprime）**：两个数的最大公约数是 1，即 gcd(a, b) = 1

#### （2）欧拉函数 φ(n)

欧拉函数 φ(n) 表示小于等于 n 且与 n 互质的正整数的个数。

**性质：**
- 如果 p 是素数，则 φ(p) = p - 1
- 如果 n = p × q，且 p、q 都是素数，则 φ(n) = (p-1)(q-1)

**示例：**
- φ(7) = 6（1, 2, 3, 4, 5, 6）
- φ(15) = φ(3×5) = 2×4 = 8（1, 2, 4, 7, 8, 11, 13, 14）

#### （3）欧拉定理

如果 a 和 n 互质，则：
```
a^φ(n) ≡ 1 (mod n)
```

**推论（费马小定理）：**
如果 p 是素数，且 a 不是 p 的倍数，则：
```
a^(p-1) ≡ 1 (mod p)
```

#### （4）模逆元

如果 a × b ≡ 1 (mod n)，则称 b 是 a 在模 n 下的逆元，记为 a⁻¹ mod n。

**存在条件：** 当且仅当 a 和 n 互质时，a 的逆元存在。

**计算方法：** 扩展欧几里得算法

### 2.3 RSA 密钥生成

```
步骤 1：选择两个大素数 p 和 q
  p ≠ q，都是大素数（推荐 1024 位以上）

步骤 2：计算 n = p × q
  n 称为模数（Modulus）
  n 的二进制长度就是密钥长度

步骤 3：计算 φ(n) = (p-1) × (q-1)
  欧拉函数值

步骤 4：选择整数 e，满足 1 < e < φ(n)，且 gcd(e, φ(n)) = 1
  e 称为公钥指数（Public Exponent）
  常用值：e = 65537 (0x10001)

步骤 5：计算 d ≡ e⁻¹ (mod φ(n))
  d 称为私钥指数（Private Exponent）
  即 e × d ≡ 1 (mod φ(n))

公钥：(e, n)
私钥：(d, n)
```

**示例（小数字演示）：**
```
p = 61, q = 53
n = 61 × 53 = 3233
φ(n) = 60 × 52 = 3120
选择 e = 17（gcd(17, 3120) = 1）
计算 d = 2753（17 × 2753 = 46801 ≡ 1 mod 3120）

公钥：(e=17, n=3233)
私钥：(d=2753, n=3233)
```

### 2.4 RSA 加密解密

**加密：**
```
C = P^e mod n

其中：
- P 是明文（必须小于 n）
- C 是密文
- (e, n) 是公钥
```

**解密：**
```
P = C^d mod n

其中：
- C 是密文
- P 是明文
- (d, n) 是私钥
```

**正确性证明（为什么解密能得到明文？）：**
```
需要证明：(P^e mod n)^d mod n = P

即证明：P^(ed) ≡ P (mod n)

因为 e × d ≡ 1 (mod φ(n))
所以 e × d = k × φ(n) + 1，k 是某个整数

根据欧拉定理：P^φ(n) ≡ 1 (mod n)  （假设 P 与 n 互质）

所以 P^(ed) = P^(k×φ(n) + 1) = (P^φ(n))^k × P^1 ≡ 1^k × P ≡ P (mod n)

证毕。
```

**加密示例（接上面小例子）：**
```
明文 P = 65（小于 3233）
公钥 (e=17, n=3233)

加密：
C = 65^17 mod 3233 = 2790

解密：
P = 2790^2753 mod 3233 = 65 ✓
```

### 2.5 RSA 数字签名

RSA 也可以用于数字签名，原理是"用私钥加密，用公钥验证"。

**签名：**
```
S = M^d mod n

其中：
- M 是消息（通常是消息的哈希值）
- S 是签名
- (d, n) 是私钥
```

**验证：**
```
验证 M' = S^e mod n
如果 M' == M，则签名有效
```

**为什么能证明身份？**
- 只有持有私钥的人才能生成有效的签名
- 任何人都可以用公钥验证签名
- 签名不能被伪造（没有私钥无法生成）

**注意：**
- 实际中不会直接对消息签名，而是对消息的哈希值签名
- 需要使用填充方案（PKCS#1 v1.5 或 PSS）

### 2.6 RSA 填充方案

直接使用 RSA 加密有很多问题，需要填充（Padding）方案。

#### PKCS#1 v1.5 填充（加密）

```
加密填充格式（以 2048 位 RSA 为例，256 字节）：
┌────┬────────────────────────────────────┬────┬──────────┐
│0x00│ 0x02 │  随机非零字节 (至少8字节)    │0x00│ 明文消息 │
└────┴────────────────────────────────────┴────┴──────────┘
 1字节 1字节        可变长度                  1字节   可变长度
```

**特点：**
- 结构简单
- 广泛使用
- 存在 Bleichenbacher 攻击（自适应选择密文攻击）

#### OAEP 填充（最优非对称加密填充）

```
OAEP (Optimal Asymmetric Encryption Padding)

结构：
┌──────────────────────────────────────────────────┐
│                  消息 M                           │
│  用随机数 r 和哈希函数进行变换                      │
│  确保安全性证明                                    │
└──────────────────────────────────────────────────┘
```

**特点：**
- 可证明安全（在随机预言机模型下）
- 推荐使用
- 比 PKCS#1 v1.5 更安全

#### PSS 填充（签名）

```
PSS (Probabilistic Signature Scheme)

特点：
- 概率性签名（每次签名结果不同）
- 可证明安全
- 推荐用于 RSA 签名
```

### 2.7 RSA 实现优化

#### （1）快速幂运算（模幂）

RSA 加密解密需要计算大指数的模幂，直接计算太慢，使用**快速幂算法**（平方-乘算法）。

```
计算 a^b mod n：

result = 1
base = a
while b > 0:
    if b % 2 == 1:
        result = (result * base) % n
    base = (base * base) % n
    b = b // 2
return result
```

时间复杂度：O(log b) 次乘法

#### （2）中国剩余定理（CRT）加速解密

私钥运算可以用中国剩余定理加速，速度提高约 4 倍。

```
已知 p、q（私钥保存了 p 和 q）：
计算 C^d mod p 和 C^d mod q
然后用 CRT 合并结果

因为 p 和 q 比 n 小一半，运算量小很多
```

## 三、RSA 常见攻击

### 3.1 因数分解攻击

**原理：** 如果能分解 n = p × q，就能计算出私钥 d。

**分解算法：**

| 算法 | 时间复杂度 | 适用场景 |
|------|-----------|---------|
| 试除法 | O(√n) | 小数字 |
| Pollard's p-1 | 依赖 n 的结构 | p-1 只有小因子时 |
| Pollard's ρ | O(n^(1/4)) | 中等大小数字 |
| 二次筛法（QS） | L_n[1/2, 1] | 100-300 位数字 |
| 数域筛法（NFS） | L_n[1/3, 1.923] | 大数字（最快的通用算法） |

**RSA 因数分解里程碑：**

| 年份 | 密钥长度 | 方法 |
|------|---------|------|
| 1991 | 330 位（100 位十进制） | 二次筛法 |
| 1996 | 430 位（130 位十进制） | 数域筛法 |
| 1999 | 512 位（155 位十进制） | 数域筛法 |
| 2009 | 768 位（232 位十进制） | 数域筛法 |
| 至今 | 1024 位 | 理论上可行但成本极高 |

**结论：**
- 512 位 RSA 完全不安全（几天内可分解）
- 768 位 RSA 已被公开分解
- 1024 位 RSA 应该淘汰（国家水平可能已能分解）
- 2048 位 RSA 目前安全，但应准备迁移
- 4096 位 RSA 长期安全

### 3.2 共模攻击（Common Modulus Attack）

**场景：** 多个用户使用同一个模数 n，但不同的公钥指数 e。

**攻击原理：**
```
假设：
- 两个用户共享模数 n
- 公钥分别为 (e1, n) 和 (e2, n)
- gcd(e1, e2) = 1

同一消息 m 用两个公钥加密：
c1 = m^e1 mod n
c2 = m^e2 mod n

攻击者知道 c1、c2、e1、e2、n

用扩展欧几里得算法找到 a、b 满足：
a × e1 + b × e2 = 1

则：
m = (c1^a) × (c2^b) mod n
  = m^(a×e1 + b×e2) mod n
  = m^1 mod n
  = m
```

**教训：**
- 每个用户必须有独立的 n
- 不能共享 RSA 模数

### 3.3 低加密指数攻击

#### （1）广播攻击（Hastad's Broadcast Attack）

**场景：** 相同消息用相同的小 e（如 e=3）加密给多个接收者。

**攻击原理：**
```
如果 e=3，且同一消息 m 加密给 3 个不同的接收者：
c1 = m^3 mod n1
c2 = m^3 mod n2
c3 = m^3 mod n3

用中国剩余定理（CRT）可以找到：
C = m^3 mod (n1 × n2 × n3)

因为 m < n1, n2, n3，所以 m^3 < n1×n2×n3
因此 C = m^3（没有取模）
直接开三次方即可得到 m
```

**防护：** 使用 OAEP 填充（随机化密文）

#### （2）Coppersmith 攻击

当 e 很小（如 e=3），且明文的高位或低位已知时，可以快速求出明文。

**防护：**
- 使用较大的 e（推荐 65537）
- 使用 OAEP 填充

### 3.4 低解密指数攻击（Wiener's Attack）

**场景：** 私钥指数 d 很小（为了加速解密）

**攻击原理：**
如果 d < n^0.25，可以用连分数展开从公钥 (e, n) 恢复出 d。

**案例：**
- 一些嵌入式设备为了加速，选择了小的 d
- 导致私钥可以被快速恢复

**防护：**
- 不要使用小的 d
- 标准做法是选择 e=65537，d 由 e 计算得出
- 如果需要加速解密，使用 CRT 而不是减小 d

### 3.5 选择密文攻击（CCA）

**Bleichenbacher 攻击（针对 PKCS#1 v1.5）：**

攻击者向服务器发送大量修改过的密文，根据服务器返回的错误信息（填充正确/错误），逐步推导出明文。

**条件：**
- 使用 RSA PKCS#1 v1.5 加密
- 服务器会泄露填充是否正确
- 攻击者可以多次询问

**影响：**
- 可以解密任意密文
- 影响 SSL/TLS 中的 RSA 密钥交换

**防护：**
- 使用 OAEP 填充
- 不泄露填充错误信息
- 统一错误响应

### 3.6 侧信道攻击

RSA 实现也容易受到侧信道攻击：

- **时序攻击**：利用模幂运算的时间差异
- **简单功耗分析（SPA）**：通过功耗波形区分平方和乘操作
- **差分功耗分析（DPA）**：统计分析功耗数据

**防护：**
- 恒定时间实现
- 随机化盲化技术（Blinding）
- 指数随机化

## 四、ECC 椭圆曲线密码学

### 4.1 ECC 概述

**ECC（Elliptic Curve Cryptography）** 是基于椭圆曲线离散对数难题的公钥密码学。

- **提出者**：Neal Koblitz 和 Victor Miller（1985 年独立提出）
- **基于难题**：椭圆曲线离散对数问题（ECDLP）
- **优势**：相同安全强度下，密钥更短、速度更快、功耗更低

**安全强度对比：**

| 对称密钥长度 | RSA 密钥长度 | ECC 密钥长度 |
|-------------|-------------|-------------|
| 80 位 | 1024 位 | 160 位 |
| 112 位 | 2048 位 | 224 位 |
| 128 位 | 3072 位 | 256 位 |
| 192 位 | 7680 位 | 384 位 |
| 256 位 | 15360 位 | 512 位 |

> 256 位 ECC 的安全强度 ≈ 3072 位 RSA

### 4.2 椭圆曲线数学基础

#### （1）椭圆曲线方程

椭圆曲线的 Weierstrass 方程：
```
y² = x³ + ax + b
```

其中 a、b 是系数，满足 4a³ + 27b² ≠ 0（确保曲线没有奇点）。

**图形（实数域上）：**
```
      │
      │    ╭───╮
      │    │   │
      │   ╭╯   ╰╮
──────┼───┴─────┴──────
      │
      │        ╭
      │         ╲
      │          ╲
```

#### （2）群运算（点加）

椭圆曲线上的点构成一个交换群，定义了加法运算。

**几何解释：**

1. **两点相加 P + Q：**
   - 过 P 和 Q 画一条直线
   - 直线与曲线交于第三点 R
   - P + Q = -R（关于 x 轴对称的点）

2. **倍点运算 2P：**
   - 过 P 点画切线
   - 切线与曲线交于另一点 R
   - 2P = -R

3. **单位元（无穷远点 O）：**
   - P + O = P
   - P + (-P) = O

**代数计算：**

```
设 P = (x₁, y₁), Q = (x₂, y₂)

如果 P = Q（倍点）：
  λ = (3x₁² + a) / (2y₁)

如果 P ≠ Q（点加）：
  λ = (y₂ - y₁) / (x₂ - x₁)

P + Q = (x₃, y₃)，其中：
  x₃ = λ² - x₁ - x₂
  y₃ = λ(x₁ - x₃) - y₁
```

#### （3）有限域上的椭圆曲线

密码学中使用的是**有限域 GF(p) 上的椭圆曲线**（所有运算模 p）。

**曲线参数（域参数）：**
- p：大素数（有限域的阶）
- a, b：椭圆曲线系数（y² = x³ + ax + b mod p）
- G：基点（生成元）
- n：G 的阶（n × G = O，n 是素数）
- h：余因子（h = #E(Fp) / n，通常 h=1）

#### （4）椭圆曲线离散对数问题（ECDLP）

```
已知 P 和 Q = k × P，求 k
```

其中 k 是整数，Q 是 P 的 k 倍点。

这个问题被认为是困难的，没有已知的多项式时间算法（经典计算机上）。

### 4.3 ECC 加密（ECIES）

ECC 本身不直接用于加密，而是通过 ECIES（Elliptic Curve Integrated Encryption Scheme）方案。

```
发送方（Alice）想给接收方（Bob）发送消息：

1. Bob 的公钥：Q_B = d_B × G（d_B 是私钥）

2. Alice 生成随机数 k
   计算 R = k × G
   计算 S = k × Q_B

3. 从 S 派生出对称密钥 K
   K = KDF(S)  （密钥派生函数）

4. 用 K 加密消息（对称加密）
   C = E(K, M)

5. 发送 (R, C)

Bob 解密：
1. 计算 S = d_B × R  （d_B × R = d_B × k × G = k × d_B × G = k × Q_B）
2. 派生出相同的 K = KDF(S)
3. 解密 M = D(K, C)
```

### 4.4 ECDSA 椭圆曲线数字签名算法

**ECDSA（Elliptic Curve Digital Signature Algorithm）** 是基于 ECC 的数字签名标准。

**签名过程：**
```
私钥：d（随机整数，1 < d < n）
公钥：Q = d × G

对消息 m 签名：
1. 计算 e = H(m)  （哈希消息）
2. 生成随机数 k（1 < k < n）
3. 计算点 (x₁, y₁) = k × G
4. 计算 r = x₁ mod n
   如果 r = 0，返回步骤 2
5. 计算 s = k⁻¹ × (e + d × r) mod n
   如果 s = 0，返回步骤 2

签名：(r, s)
```

**验证过程：**
```
公钥 Q，消息 m，签名 (r, s)

1. 验证 r、s 在 [1, n-1] 范围内
2. 计算 e = H(m)
3. 计算 w = s⁻¹ mod n
4. 计算 u₁ = e × w mod n
5. 计算 u₂ = r × w mod n
6. 计算点 (x₁, y₁) = u₁ × G + u₂ × Q
7. 验证 v = x₁ mod n == r

如果相等，签名有效
```

**ECDSA 注意事项：**
- 随机数 k 必须是密码学安全的
- k 泄露会导致私钥泄露
- k 重复使用也会导致私钥泄露

**案例：PS3 破解**
- Sony PS3 使用 ECDSA 签名验证游戏
- 但 Sony 在所有签名中使用了相同的 k
- 攻击者通过两个签名即可恢复私钥
- 导致 PS3 被破解

### 4.5 常见椭圆曲线

| 曲线名称 | 位长 | 来源 | 说明 |
|----------|------|------|------|
| secp256k1 | 256 | SECG | 比特币使用 |
| secp256r1 (P-256) | 256 | NIST | 广泛使用 |
| secp384r1 (P-384) | 384 | NIST | 高安全级别 |
| Curve25519 | 255 | DJB | ECDH 专用，高效安全 |
| Ed25519 | 255 | DJB | EdDSA 签名，高效安全 |
| SM2 | 256 | 国密 | 中国标准 |

### 4.6 Curve25519 / Ed25519

**Curve25519** 是 Daniel J. Bernstein 设计的椭圆曲线，专门用于 ECDH 密钥交换。

**特点：**
- 255 位素数域（p = 2^255 - 19）
- 蒙哥马利曲线形式
- 设计避免了很多安全陷阱
- 恒定时间实现容易
- 性能优异

**Ed25519** 是基于 Edwards 曲线的签名算法，与 Curve25519 数学上等价。

**特点：**
- 快速签名和验证
- 小签名（64 字节）、小公钥（32 字节）
- 防碰撞（不需要随机数 k，避免了 ECDSA 的 k 重用问题）
- 已广泛应用于 SSH、TLS 1.3、区块链等

## 五、国密 SM2 算法

### 5.1 SM2 概述

**SM2** 是中国国家密码管理局发布的椭圆曲线公钥密码标准。

- **标准号**：GM/T 0003-2012
- **发布时间**：2012 年
- **基于难题**：椭圆曲线离散对数问题（ECDLP）
- **曲线类型**：256 位素数域椭圆曲线
- **用途**：加密、解密、数字签名、密钥交换

### 5.2 SM2 曲线参数

SM2 使用一条 256 位的推荐曲线：

```
素数 p = 0xFFFFFFFEFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFF00000000FFFFFFFFFFFFFFFF
系数 a = 0xFFFFFFFEFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFF00000000FFFFFFFFFFFFFFFC
系数 b = 0x28E9FA9E9D9F5E344D5A9E4BCF6509A7F39789F515AB8F92DDBCBD414D940E93
基点 G 的 x 坐标 = 0x32C4AE2C1F1981195F9904466A39C9948FE30BBFF2660BE1715A4589334C74C7
基点 G 的 y 坐标 = 0xBC3736A2F4F6779C59BDCEE36B692153D0A9877CC62A474002DF32E52139F0A0
基点阶 n = 0xFFFFFFFEFFFFFFFFFFFFFFFFFFFFFFFF7203DF6B21C6052B53BBF40939D54123
余因子 h = 1
```

### 5.3 SM2 数字签名

SM2 签名算法与 ECDSA 类似，但有一些差异。

**签名前的预处理：**
SM2 签名需要先计算 Z 值（用户标识 + 曲线参数 + 公钥的哈希）：
```
Z_A = H(ENTL_A || ID_A || a || b || x_G || y_G || x_A || y_A)

其中：
- ENTL_A：用户 ID 的长度（位）
- ID_A：用户标识
- a, b：曲线系数
- x_G, y_G：基点坐标
- x_A, y_A：公钥坐标
```

**签名过程：**
```
私钥：d_A（1 < d_A < n-1）
公钥：P_A = d_A × G

对消息 M 签名：
1. 计算 Z_A
2. 计算 M' = Z_A || M
3. 计算 e = H(M')  （SM3 哈希）
4. 生成随机数 k（1 ≤ k ≤ n-1）
5. 计算点 (x₁, y₁) = k × G
6. 计算 r = (e + x₁) mod n
   如果 r = 0 或 r + k = n，返回步骤 4
7. 计算 s = ((1 + d_A)⁻¹ × (k - r × d_A)) mod n
   如果 s = 0，返回步骤 4

签名：(r, s)
```

**验证过程：**
```
公钥 P_A，消息 M，签名 (r, s)

1. 验证 r ∈ [1, n-1]，s ∈ [1, n-1]
2. 计算 Z_A
3. 计算 M' = Z_A || M
4. 计算 e = H(M')
5. 计算 t = (r + s) mod n
   如果 t = 0，验证失败
6. 计算点 (x₁, y₁) = s × G + t × P_A
7. 验证 R = (e + x₁) mod n == r

如果相等，签名有效
```

### 5.4 SM2 加密解密

SM2 使用 ECIES 类似的方案进行加密。

**加密过程：**
```
接收方公钥：P_B = d_B × G

对消息 M 加密：
1. 生成随机数 k（1 ≤ k ≤ n-1）
2. 计算点 C₁ = k × G
3. 计算点 S = h × P_B（如果 h=1，就是 P_B）
   如果 S 是无穷远点，错误
4. 计算点 (x₂, y₂) = k × P_B
5. 计算 t = KDF(x₂ || y₂, klen)  （密钥派生函数）
   如果 t 全为 0，返回步骤 1
6. 计算 C₂ = M ⊕ t
7. 计算 C₃ = Hash(x₂ || M || y₂)

密文：C = C₁ || C₃ || C₂  （注意顺序）
```

**解密过程：**
```
私钥 d_B，密文 C = C₁ || C₃ || C₂

1. 验证 C₁ 是否在曲线上
2. 计算 S = h × C₁
   如果 S 是无穷远点，错误
3. 计算点 (x₂, y₂) = d_B × C₁
4. 计算 t = KDF(x₂ || y₂, klen)
   如果 t 全为 0，解密失败
5. 计算 M' = C₂ ⊕ t
6. 计算 u = Hash(x₂ || M' || y₂)
   验证 u == C₃，如果不等，解密失败

明文：M'
```

### 5.5 SM2 密钥交换

SM2 也定义了密钥交换协议，与 ECDH 类似但增加了身份验证。

```
双方：A（发起方）和 B（响应方）
各自有密钥对：(d_A, P_A) 和 (d_B, P_B)

过程：
1. A 生成随机数 r_A，计算 R_A = r_A × G，发送给 B
2. B 生成随机数 r_B，计算 R_B = r_B × G，发送给 A
3. A 计算共享点 V = (x_V, y_V) = 2^w × (d_A + r_A × x₁) × (P_B + x₂ × R_B)
   其中 x₁ 是 R_A 的 x 坐标，x₂ 是 R_B 的 x 坐标
4. B 计算共享点 V = (x_V, y_V) = 2^w × (d_B + r_B × x₂) × (P_A + x₁ × R_A)
5. 双方得到相同的 V
6. 用 KDF 从 V 派生出会话密钥
```

### 5.6 SM2 与 ECDSA 对比

| 特性 | SM2 | ECDSA |
|------|-----|-------|
| 曲线 | 256 位国密推荐曲线 | secp256k1、P-256 等 |
| 签名公式 | 不同 | 不同 |
| 用户标识 | 包含 Z_A（用户ID） | 不包含 |
| 哈希函数 | SM3 | SHA-2 等 |
| 标准 | 中国国密 | 国际标准 |
| 安全性 | 256 位安全强度 | 取决于曲线 |

## 六、DH 密钥交换

### 6.1 DH 概述

**Diffie-Hellman 密钥交换** 是 Whitfield Diffie 和 Martin Hellman 于 1976 年提出的，是第一个公钥密码学协议。

**核心思想：** 双方在不安全的信道上协商出一个共享密钥，攻击者即使监听了所有通信也无法计算出密钥。

**基于难题：** 有限域上的离散对数问题（DLP）

### 6.2 DH 原理

```
公开参数（所有人都知道）：
  p：大素数
  g：生成元（g 是模 p 的原根）

Alice                        Bob
  │                            │
  │  生成私钥 a（随机数）       │  生成私钥 b（随机数）
  │  计算公钥 A = g^a mod p    │  计算公钥 B = g^b mod p
  │                            │
  ├───────── 发送 A ──────────→│
  │                            │
  │←──────── 发送 B ───────────┤
  │                            │
  │  计算共享密钥：             │  计算共享密钥：
  │  s = B^a mod p             │  s = A^b mod p
  │    = (g^b)^a mod p         │    = (g^a)^b mod p
  │    = g^(ab) mod p          │    = g^(ab) mod p
  │                            │
  │         双方得到相同的 s     │
```

**数学验证：**
```
Alice 计算：s = B^a mod p = (g^b mod p)^a mod p = g^(ab) mod p
Bob 计算：  s = A^b mod p = (g^a mod p)^b mod p = g^(ab) mod p

结果相同！
```

### 6.3 离散对数问题（DLP）

攻击者知道 p、g、A、B，但不知道 a、b，要计算共享密钥 s = g^(ab) mod p。

这就是**计算 Diffie-Hellman 问题（CDH）**：
```
已知 g、g^a、g^b，求 g^(ab)
```

CDH 被认为是困难的，它的难度与离散对数问题相关：
- 如果能解决离散对数问题（从 g^a 求 a），就能解决 CDH
- 但反过来不一定成立

### 6.4 DH 的问题：中间人攻击

DH 密钥交换本身**不提供身份认证**，容易遭受中间人攻击（Man-in-the-Middle, MITM）。

```
Alice                      攻击者 Eve                       Bob
  │                            │                            │
  │  生成 a                    │  生成 a'                   │  生成 b
  │  A = g^a                   │  A' = g^a'                 │  B = g^b
  │                            │                            │
  ├────── 发送 A ─────────────→│                            │
  │                            ├────── 发送 A' ────────────→│
  │                            │                            │
  │←───── 发送 B' ─────────────┤←────── 发送 B ─────────────┤
  │         B' = g^b'          │         b' 是 Eve 的私钥   │
  │                            │                            │
  │  s1 = B'^a = g^(ab')       │  s1 = A^b' = g^(ab')      │
  │                            │  s2 = B^a' = g^(a'b)      │  s2 = A'^b = g^(a'b)
  │                            │                            │
  │      Alice 以为和 Bob 共享s1  Eve 和 Alice共享s1，和Bob共享s2  Bob 以为和 Alice 共享s2
```

**结果：**
- Alice 和 Eve 共享密钥 s1
- Bob 和 Eve 共享密钥 s2
- Eve 可以解密所有通信并转发（或篡改）

**解决方案：**
- 结合数字签名（验证对方身份）
- 使用证书（PKI 体系）
- 使用 PSK（预共享密钥）
- 口令认证密钥交换（PAKE）

### 6.5 DH 参数选择

**素数 p：**
- 足够大（至少 2048 位，推荐 3072 位）
- 安全素数（p = 2q + 1，q 也是素数）更好

**生成元 g：**
- 应该是大阶的生成元
- 阶应该是大素数 q

**Logjam 攻击：**
- 如果使用 512 位或 1024 位的 DH 组
- 攻击者可以预先计算离散对数表
- 然后快速解密通信
- 影响大量使用 1024 位 DH 的服务器

**建议：**
- 使用至少 2048 位的 DH 组
- 或者使用 ECDH（椭圆曲线版本，更安全高效）
- 使用标准的 DH 组（如 RFC 3526 定义的组）

### 6.6 前向保密（Forward Secrecy）

**前向保密（Forward Secrecy / Perfect Forward Secrecy, PFS）**：
即使长期私钥泄露，也不会导致之前的会话密钥泄露。

**实现方式：** 使用临时 DH（DHE）或临时 ECDH（ECDHE）

```
普通 RSA 密钥交换（无前向保密）：
- 服务器私钥是长期的
- 如果私钥泄露，所有之前的会话都可以解密
- 因为会话密钥是用服务器私钥加密传输的

DHE/ECDHE（有前向保密）：
- 每次会话生成临时密钥对
- 会话结束后销毁临时私钥
- 即使长期私钥泄露，也无法解密之前的会话
- 因为长期私钥只用于签名认证临时公钥
```

## 七、ECDH 椭圆曲线密钥交换

### 7.1 ECDH 原理

**ECDH（Elliptic Curve Diffie-Hellman）** 是椭圆曲线版本的 DH 密钥交换。

```
公开参数：
  椭圆曲线（含 p, a, b, G, n, h）

Alice                        Bob
  │                            │
  │  生成私钥 a（随机数）       │  生成私钥 b（随机数）
  │  计算公钥 A = a × G        │  计算公钥 B = b × G
  │                            │
  ├──────── 发送 A ───────────→│
  │                            │
  │←─────── 发送 B ────────────┤
  │                            │
  │  计算共享点：               │  计算共享点：
  │  S = a × B                 │  S = b × A
  │    = a × (b × G)           │    = b × (a × G)
  │    = (ab) × G              │    = (ab) × G
  │                            │
  │         相同的共享点 S       │
  │  共享密钥 = x 坐标（或 KDF） │  共享密钥 = x 坐标（或 KDF）
```

### 7.2 ECDH 的优势

| 特性 | DH (有限域) | ECDH (椭圆曲线) |
|------|------------|----------------|
| 密钥长度 | 2048-4096 位 | 256-384 位 |
| 计算量 | 大 | 小 |
| 速度 | 慢 | 快 |
| 带宽 | 大（公钥大） | 小（公钥小） |
| 安全强度 | 2048 位 ≈ 112 位 | 256 位 ≈ 128 位 |

**ECDH 的应用：**
- TLS 1.2/1.3（ECDHE 密钥交换）
- SSH
- 无线通信
- 物联网设备

### 7.3 ECDH 安全注意事项

1. **曲线选择**：使用标准的、经过安全评估的曲线
2. **点验证**：接收到对方公钥后，验证点是否在曲线上
3. **小群攻击**：确保点的阶是大素数 n
4. **侧信道防护**：实现需要抗侧信道攻击
5. **身份认证**：ECDH 本身也不提供身份认证，需要结合签名

## 八、数字签名

### 8.1 数字签名概述

**数字签名（Digital Signature）** 是附加在数据上的一串数据，用于证明数据的来源和完整性。

**作用：**
1. **身份认证**：验证消息是谁发送的
2. **完整性**：验证消息没有被篡改
3. **不可否认性**：发送者不能否认发送过消息

**与手写签名的对比：**

| 特性 | 手写签名 | 数字签名 |
|------|---------|---------|
| 与消息的关系 | 物理附加 | 数学关联 |
| 复制难度 | 容易伪造 | 不可伪造 |
| 验证方式 | 人工比对 | 算法验证 |
| 不可否认性 | 较弱 | 强 |

### 8.2 数字签名原理

**基本流程：**

```
签名：
  消息 M → 哈希 → 摘要 H → 私钥签名 → 签名 S
  发送：消息 M + 签名 S

验证：
  收到：消息 M' + 签名 S'
  消息 M' → 哈希 → 摘要 H'
  公钥验证签名 S' → 得到摘要 H
  比较 H' 和 H：
    相等 → 验证通过
    不等 → 验证失败
```

**为什么要先哈希再签名？**
1. **效率**：非对称加密慢，哈希快，只对短摘要签名
2. **安全**：直接对消息签名有安全隐患（如 RSA 的同态性）
3. **格式**：消息长度任意，签名算法需要固定长度输入

### 8.3 RSA 签名

#### PKCS#1 v1.5 签名

```
签名：
  1. 计算 H = Hash(M)
  2. 填充：EM = 0x00 || 0x01 || PS || 0x00 || T || H
     其中 PS 是 0xFF 填充，T 是算法标识
  3. S = EM^d mod n

验证：
  1. EM' = S^e mod n
  2. 解析 EM'，检查填充格式
  3. 提取 H'，与 Hash(M) 比较
```

**问题：**
- 存在伪造攻击（Bleichenbacher 签名伪造）
- 填充验证不严格可能被利用

#### RSA-PSS 签名

```
PSS (Probabilistic Signature Scheme)

特点：
- 概率性（每次签名结果不同）
- 可证明安全
- 推荐使用
```

### 8.4 ECDSA 签名

（详见第四章 4.4 节）

**特点：**
- 签名短（两个坐标分量）
- 速度快
- 对随机数 k 的质量要求很高
- k 泄露或重用都会导致私钥泄露

### 8.5 EdDSA / Ed25519

**EdDSA（Edwards-curve Digital Signature Algorithm）** 是基于 Edwards 曲线的签名算法。

**特点：**
- 不需要随机数 k（使用确定性的方式生成）
- 避免了 ECDSA 的 k 重用问题
- 快速、安全、实现简单
- Ed25519 是最常用的实例

**签名过程（简化）：**
```
1. 计算 r = Hash(Hash(sk) || M)  （确定性生成，不需要随机数）
2. 计算 R = r × B
3. 计算 S = (r + Hash(R || A || M) × a) mod L
   其中 A = a × B 是公钥，a 是私钥

签名：(R, S)
```

### 8.6 SM2 签名

（详见第五章 5.3 节）

SM2 签名的特点：
- 包含用户标识 Z_A
- 使用 SM3 哈希算法
- 国密标准

### 8.7 签名算法对比

| 算法 | 密钥长度 | 签名长度 | 安全性 | 特点 |
|------|---------|---------|--------|------|
| RSA 2048 | 2048 位 | 256 字节 | 112 位 | 广泛使用，速度较慢 |
| RSA 3072 | 3072 位 | 384 字节 | 128 位 | 更安全，更慢 |
| ECDSA P-256 | 256 位 | 64 字节 | 128 位 | 标准椭圆曲线 |
| Ed25519 | 256 位 | 64 字节 | 128 位 | 快速安全，无随机数问题 |
| SM2 | 256 位 | 64 字节 | 128 位 | 国密标准 |

## 九、实际案例

### 案例 1：索尼 PS3 ECDSA 破解

**背景：**
- Sony PlayStation 3 使用 ECDSA 签名验证游戏和系统更新
- 只有签名正确的软件才能运行

**漏洞：**
- Sony 在生成签名时使用了固定的随机数 k
- 根据 ECDSA 原理，如果知道两个使用相同 k 的签名：
  ```
  s1 = k⁻¹ × (e1 + d × r) mod n
  s2 = k⁻¹ × (e2 + d × r) mod n
  
  两式相减：s1 - s2 = k⁻¹ × (e1 - e2) mod n
  可求出：k = (e1 - e2) × (s1 - s2)⁻¹ mod n
  
  然后求出私钥：d = (s1 × k - e1) × r⁻¹ mod n
  ```

**结果：**
- 攻击者获取了 Sony 的签名私钥
- 可以运行任何自制软件
- PS3 安全体系被攻破

**教训：**
- ECDSA 中的随机数 k 必须是密码学安全的
- 不能重复使用 k
- 推荐使用 EdDSA（确定性签名，不需要随机数）

### 案例 2：Heartbleed 与私钥泄露

**背景：**
- OpenSSL Heartbleed 漏洞（CVE-2014-0160）
- 可以读取服务器内存中的 64KB 数据

**影响：**
- 可能泄露服务器的 RSA 私钥
- 私钥一旦泄露，整个 PKI 信任链就崩了
- 攻击者可以解密所有之前的 TLS 会话（如果没有前向保密）
- 攻击者可以伪造服务器证书

**应对：**
- 立即升级 OpenSSL
- 吊销受影响的证书
- 重新颁发证书
- 启用前向保密（ECDHE）

### 案例 3：ROCA 漏洞（Return of Coppersmith's Attack）

**背景：**
- 2017 年发现的 RSA 密钥生成漏洞
- 影响 Infineon 公司的 TPM 芯片和智能卡
- 涉及大量设备（YubiKey、银行卡、护照等）

**原理：**
- 芯片生成的 RSA 素数有特殊结构
- 可以使用 Coppersmith 方法快速分解
- 1024 位密钥几天内可分解，2048 位密钥几个月

**影响：**
- 数百万设备的 RSA 密钥不安全
- 需要更换硬件或更新固件

**教训：**
- 密钥生成的随机性和安全性至关重要
- 硬件实现也可能有漏洞
- 定期更换密钥是好的实践
