# 彩虹表原理

### 8.1 什么是彩虹表

**彩虹表（Rainbow Table）** 是一种用于破解哈希值的预先计算表，是时间-空间权衡的典型应用。

**核心思想：**
- 预先计算大量明文及其哈希值，存储在表中
- 破解时只需要查表
- 用存储空间换破解时间

**为什么叫"彩虹"表？**
- 表中有很多"链"（chains）
- 每条链使用不同的归约函数（颜色）
- 不同颜色的链交替排列，像彩虹一样

### 8.2 基本概念

**归约函数 R（Reduction Function）：**
- 将哈希值映射回明文空间的函数
- 不是哈希的逆函数（不可能）
- 只是一种映射（哈希 → 可能的明文）
- 例如：R(h) = h mod N （将哈希映射为数字密码）

**链（Chain）：**
```
明文 P₀ → H → 哈希 H₀ → R → 明文 P₁ → H → 哈希 H₁ → R → ... → 明文 P_k → H → 哈希 H_k

链起点：P₀
链终点：H_k（或者 P_k）
链长度：k
```

**表的结构：**
- 存储每条链的起点和终点
- 不存储中间值
- 节省空间

### 8.3 查表过程

**目标：** 给定哈希值 H，找出对应的明文 P。

```
步骤 1：检查当前哈希
  当前 = H

步骤 2：从链尾向链头搜索
  对于 i = k down to 0:
    计算 R_i(当前)
    在表中查找是否有链的终点等于当前值
    如果找到，进入步骤 3
    否则继续

步骤 3：重建链
  从匹配链的起点开始，重新计算整条链
  同时检查每一步的哈希值是否等于目标 H
  如果找到对应的明文，成功

步骤 4：如果所有链都不匹配，失败（哈希不在表中）
```

### 8.4 为什么需要多种归约函数

**只用一种归约函数的问题：碰撞合并**

```
链 1: P₀ → H → R → P₁ → H → R → P₂ → H → R → ... → 终点 E₁
                           ↗
链 2: Q₀ → H → R → Q₁ → H → R → ... → 终点 E₂

如果两条链在中间碰撞（P₂ = Q₁），它们之后就合并了
这浪费了存储空间，降低了表的覆盖率
```

**彩虹表的解决方案：** 每一步使用不同的归约函数

```
链: P₀ → H → R₀ → P₁ → H → R₁ → P₂ → H → R₂ → ... → 终点

每一步使用不同的 R_i（不同"颜色"）
两条链只有在相同位置碰撞才会合并
大大降低了合并的概率
```

### 8.5 彩虹表的大小和效果

**时间-空间权衡：**

| 表大小 | 破解时间 | 成功率 |
|--------|---------|--------|
| 大 | 快 | 高 |
| 小 | 慢 | 低 |

**典型参数：**
- 链长：几千到几万
- 链数：几百万到几十亿
- 成功率：取决于覆盖的明文空间比例

**例子：**
- 8 位数字密码（1 亿种可能）
- 彩虹表可能只需要几百 MB
- 破解时间：几秒到几分钟
- 成功率：99%+

### 8.6 彩虹表 vs 暴力破解 vs 字典攻击

| 方法 | 预先计算 | 存储 | 破解时间 | 适用场景 |
|------|---------|------|---------|---------|
| 暴力破解 | 不需要 | 极少 | 很慢 | 密码空间小时 |
| 字典攻击 | 不需要 | 字典大小 | 快 | 常见密码 |
| 预计算全表 | 慢 | 极大 | 极快 | 小密码空间 |
| 彩虹表 | 中等 | 中等 | 较快 | 中等密码空间 |

### 8.7 防护彩虹表攻击

#### 方法 1：加盐（Salt）

**原理：** 在密码哈希前加入随机盐值。

```
普通哈希：H(password)
加盐哈希：H(salt || password) 或 H(password || salt)
```

**效果：**
- 每个密码有不同的盐
- 彩虹表需要为每个盐值单独建表
- 大大增加了攻击成本

**正确做法：**
```python
import os
import hashlib

salt = os.urandom(16)  # 每个用户不同的盐
hash = hashlib.sha256(salt + password.encode()).digest()
# 存储 salt + hash
```

#### 方法 2：使用慢哈希算法

加盐仍然可以用彩虹表（只是更大），慢哈希让暴力破解也变得很慢。

**常见慢哈希算法：**
- bcrypt
- scrypt
- Argon2（推荐，密码哈希竞赛获胜者）
- PBKDF2

**特点：**
- 计算成本高（可以调整参数）
- 每次哈希需要几毫秒到几秒
- 暴力破解速度大大降低

**示例（bcrypt）：**
```python
import bcrypt

# 哈希密码（自动生成盐）
hashed = bcrypt.hashpw(password.encode(), bcrypt.gensalt(rounds=12))

# 验证密码
if bcrypt.checkpw(password.encode(), hashed):
    print("密码正确")
```

#### 方法 3：使用 HMAC

用 HMAC 而不是普通哈希，密钥作为"全局盐"。

```
HMAC(key, password + salt)
```

即使数据库泄露，只要 key 不泄露，也无法计算彩虹表。

### 8.8 实际案例

**案例：LinkedIn 密码泄露（2012 年）**
- 650 万用户密码哈希泄露
- 使用了 SHA-1，没有加盐
- 黑客很快就破解了大量密码
- 事后 LinkedIn 升级为加盐的 bcrypt

**案例：RockYou 密码泄露（2009 年）**
- 3200 万用户密码明文泄露
- 成为最大的密码字典之一
- 很多彩虹表基于这个字典
