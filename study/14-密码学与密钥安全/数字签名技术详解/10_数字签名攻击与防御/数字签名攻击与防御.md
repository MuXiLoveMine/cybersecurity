### 10.1 常见攻击类型

#### 10.1.1 随机数攻击

```python
"""
ECDSA随机数k攻击演示
当k泄露或重复使用时，可以恢复私钥
"""

def attack_repeated_k(
    msg1_hash: int, sig1_r: int, sig1_s: int,
    msg2_hash: int, sig2_r: int, sig2_s: int,
    n: int
) -> int:
    """
    从重复使用k的两次签名中恢复私钥
    
    当k相同时: sig1_r == sig2_r
    
    s1 = k^(-1) * (h1 + r * d) mod n
    s2 = k^(-1) * (h2 + r * d) mod n
    
    s1 - s2 = k^(-1) * (h1 - h2) mod n
    k = (h1 - h2) / (s1 - s2) mod n
    
    d = (s1 * k - h1) / r mod n
    """
    if sig1_r != sig2_r:
        raise ValueError("r值不同，k可能不同")
    
    r = sig1_r
    
    # 恢复k
    k = ((msg1_hash - msg2_hash) * 
         pow(sig1_s - sig2_s, -1, n)) % n
    
    # 恢复私钥d
    d = ((sig1_s * k - msg1_hash) * pow(r, -1, n)) % n
    
    return d

"""
索尼PS3 ECDSA私钥泄露事件（2010年）：

  但在实现中使用了固定的k值
  研究人员发现后直接恢复了Sony的私钥

教训：
  1. ECDSA/DSA签名的随机数k绝不能重复使用
  2. k必须是密码学安全的随机数

  4. 使用经过审计的密码学库
```

#### 10.1.2 填充攻击

```
Bleichenbacher攻击（针对RSA PKCS#1 v1.5）：
  利用签名验证的错误响应进行攻击
  通过大量试探恢复签名内容
  
防护：
  1. 使用PSS替代PKCS#1 v1.5
  2. 验证时使用恒定时间比较
  3. 不泄露验证失败的具体原因
```

#### 10.1.3 侧信道攻击

```
时序攻击：
  不同输入导致不同的处理时间
  通过测量时间泄露密钥信息

功耗分析攻击：
  不同操作消耗不同电量
  通过测量功耗分析密钥

故障攻击：
  在签名过程中注入故障
  产生错误签名以恢复密钥

防护措施：
  1. 使用恒定时间实现
  2. 使用抗侧信道的算法（如Ed25519）
  3. 硬件安全模块（HSM）
  4. 签名结果验证（签名后重新验证）
```

### 10.3 证书混淆攻击

```
证书混淆攻击：
  攻击者获取一个合法的证书（通过正规CA签发）
  用这个证书的签名替换目标网站的签名
  受害者可能误以为通信是安全的

防御：
  1. 证书透明度（CT）监控
  2. 证书绑定（Pinning）
  3. HSTS
  4. DNS CAA记录
  5. 多方授权（MPA）
```
