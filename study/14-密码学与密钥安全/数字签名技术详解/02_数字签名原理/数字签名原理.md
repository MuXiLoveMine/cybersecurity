# 数字签名原理

### 2.1 数字签名的基本流程

```
签名过程（发送方）：

  原始消息 ──→ 哈希函数 ──→ 消息摘要 ──→ 私钥签名 ──→ 数字签名
                                                                  │
  原始消息 ─────────────────────────────────────────────┐         │
                                                         ↓         ↓
                                                    发送给接收方

验证过程（接收方）：

  接收消息 ──→ 哈希函数 ──→ 消息摘要1 ─────────────────────┐
                                                             │
  数字签名 ──→ 公钥验证 ──→ 消息摘要2 ─────────────────────┤
                                                             │
                                                        比较摘要1和摘要2
                                                             │
                                                   相同 → 验证通过
                                                   不同 → 验证失败
```

### 2.2 签名过程的详细步骤

#### 2.2.1 签名步骤

```python
"""
数字签名基本原理实现
"""
from cryptography.hazmat.primitives import hashes, serialization
from cryptography.hazmat.primitives.asymmetric import rsa, padding
from cryptography.hazmat.primitives.serialization import Encoding, PublicFormat

class DigitalSignatureDemo:
    """数字签名演示"""
    
    def __init__(self):
        # 生成RSA密钥对
        self.private_key = rsa.generate_private_key(
            public_exponent=65537,
            key_size=2048
        )
        self.public_key = self.private_key.public_key()
    
    def sign(self, message: bytes) -> bytes:
        """
        签名过程
        
        步骤1: 计算消息的哈希值
        步骤2: 用私钥对哈希值进行签名
        """
        # 步骤1: 计算哈希（实际上签名函数内部会自动计算）
        digest = hashes.Hash(hashes.SHA256())
        digest.update(message)
        hash_value = digest.finalize()
        print(f"消息哈希: {hash_value.hex()}")
        
        # 步骤2: 用私钥签名
        signature = self.private_key.sign(
            message,
            padding.PSS(
                mgf=padding.MGF1(hashes.SHA256()),
                salt_length=padding.PSS.MAX_LENGTH
            ),
            hashes.SHA256()
        )
        
        return signature
    
    def verify(self, message: bytes, signature: bytes) -> bool:
        """
        验证过程
        
        步骤1: 用公钥解密签名，得到签名时的哈希值
        步骤2: 重新计算消息的哈希值
        步骤3: 比较两个哈希值
        """
        try:
            # 验证签名（内部会比较哈希值）
            self.public_key.verify(
                signature,
                message,
                padding.PSS(
                    mgf=padding.MGF1(hashes.SHA256()),
                    salt_length=padding.PSS.MAX_LENGTH
                ),
                hashes.SHA256()
            )
            return True
        except Exception:
            return False
    
    def demonstrate(self):
        """演示签名和验证"""
        message = b"Hello, this is a secret message!"
        print(f"原始消息: {message.decode()}")
        
        # 签名
        print("\n--- 签名过程 ---")
        signature = self.sign(message)
        print(f"数字签名: {signature.hex()[:60]}...")
        print(f"签名长度: {len(signature)} bytes")
        
        # 验证正确消息
        print("\n--- 验证正确消息 ---")
        valid = self.verify(message, signature)
        print(f"验证结果: {'通过' if valid else '失败'}")
        
        # 验证篡改消息
        print("\n--- 验证篡改消息 ---")
        tampered = message.replace(b"secret", b"public")
        valid = self.verify(tampered, signature)
        print(f"验证结果: {'通过' if valid else '失败'}")
        
        # 导出公钥
        print("\n--- 公钥信息 ---")
        pub_pem = self.public_key.public_bytes(
            Encoding.PEM, PublicFormat.SubjectPublicKeyInfo
        )
        print(pub_pem.decode())


# 运行演示
demo = DigitalSignatureDemo()
demo.demonstrate()
```

### 2.3 哈希函数在签名中的作用

**为什么签名前要先哈希？**

| 不使用哈希 | 使用哈希 |
|----------|---------|
| 签名整个消息，计算量大 | 只签名固定长度的哈希，效率高 |
| 签名长度随消息长度变化 | 签名长度固定 |
| 可能存在数学弱点 | 哈希增加安全性 |
| 无法处理大文件 | 可以处理任意大小文件 |

**签名中使用的哈希算法选择：**

| 哈希算法 | 输出长度 | 安全性 | 推荐使用 |
|----------|---------|--------|---------|
| MD5 | 128位 | 不安全 | 禁止使用 |
| SHA-1 | 160位 | 不安全 | 禁止使用 |
| SHA-256 | 256位 | 安全 | 推荐 |
| SHA-384 | 384位 | 安全 | 推荐（高安全场景） |
| SHA-512 | 512位 | 安全 | 推荐（高安全场景） |
| SM3 | 256位 | 安全 | 推荐（国密场景） |
| SHA-3-256 | 256位 | 安全 | 推荐 |

### 2.4 签名方案的安全性要求

一个安全的数字签名方案需要满足以下安全属性：

1. **存在性不可伪造（EUF）**：在不知道私钥的情况下，攻击者无法产生合法签名
2. **强不可伪造（SUF）**：即使对已签名的消息，攻击者也无法产生不同的合法签名
3. **选择消息攻击安全（CMA）**：即使攻击者可以获得任意消息的签名，也无法伪造其他消息的签名
