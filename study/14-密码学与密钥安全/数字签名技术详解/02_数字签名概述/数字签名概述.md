# 数字签名概述

### 1.1 什么是数字签名

**数字签名（Digital Signature）** 是一种用密码学技术实现的、类似于手写签名的电子签名机制。它使用发送方的私钥对消息进行签名，接收方使用发送方的公钥验证签名。

**数字签名与手写签名的对比：**

| 特性 | 手写签名 | 数字签名 |
|------|---------|---------|
| 签名与文件的关系 | 独立于文件内容 | 与文件内容绑定（哈希） |
| 伪造难度 | 相对容易（可模仿） | 极难（需破解密码算法） |
| 复制检测 | 难（无法区分原件和复印件 | 易（每次签名不同） |
| 文件完整性 | 无法保证 | 保证（签名验证内容） |
| 不可抵赖性 | 弱 | 强（只有私钥持有者能签名） |
| 身份认证 | 依赖笔迹鉴定 | 基于数学证明 |

### 1.2 数字签名的安全服务

数字签名提供三大核心安全服务：

```
┌─────────────────────────────────────────────────┐
│              数字签名的安全服务                    │
├──────────────┬──────────────────────────────────┤
│  完整性       │ 签名与消息内容绑定，任何篡改       │
│  Integrity   │ 都会使签名验证失败                 │
├──────────────┼──────────────────────────────────┤
│  身份认证     │ 签名是用私钥生成的，只有私钥       │
│  Authentication│ 持有者能产生有效签名              │
├──────────────┼──────────────────────────────────┤
│  不可抵赖性   │ 签名者无法否认自己签过的消息       │
│  Non-repudiation│ （因为没有其他人能产生相同签名）  │
└──────────────┴──────────────────────────────────┘
```

### 1.3 数字签名的发展历史

| 年份 | 事件 | 意义 |
|------|------|------|
| 1976 | Diffie-Hellman提出公钥密码概念 | 公钥密码学诞生 |
| 1977 | RSA算法发表 | 第一个可用于签名的公钥算法 |
| 1985 | ElGamal签名方案提出 | 基于离散对数的签名 |
| 1991 | DSA（数字签名算法）标准化 | FIPS 186发布 |
| 1994 | RSA PKCS#1 v1.5签名标准发布 | 广泛使用的签名格式 |
| 1999 | ECDSA提出 | 椭圆曲线签名算法 |
| 2001 | SM2算法发布（中国） | 国密签名算法 |
| 2011 | Ed25519发布 | 高性能EdDSA签名 |
| 2015 | RFC 8032 EdDSA标准化 | EdDSA正式标准化 |
| 2016 | PSS填充方案成为推荐 | 更安全的RSA签名方案 |
| 2024 | 后量子签名标准化推进 | NIST PQC标准发布 |

### 1.4 法律地位

**电子签名法律效力：**

| 国家/地区 | 法律法规 | 效力 |
|----------|---------|------|
| 中国 | 电子签名法（2005） | 可靠的电子签名与手写签名具有同等效力 |
| 美国 | ESIGN法案（2000） | 电子签名具有法律效力 |
| 欧盟 | eIDAS法规（2016） | 高级电子签名和合格电子签名有法律效力 |
| 国际 | UNCITRAL电子签名示范法 | 国际电子签名法律框架 |

**中国电子签名法对"可靠电子签名"的要求：**
1. 签名制作数据用于电子签名时，属于电子签名人专有
2. 签名时签名制作数据仅由电子签名人控制
3. 签署后对签名制作数据的任何改动能够被发现
4. 签署后对电文内容和形式的任何改动能够被发现

**数字签名完全满足以上四个条件。**
