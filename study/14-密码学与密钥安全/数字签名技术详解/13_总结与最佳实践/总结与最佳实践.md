# 总结与最佳实践

### 13.1 签名算法选择指南

| 场景 | 推荐算法 | 理由 |
|------|---------|------|
| Web TLS证书 | RSA-2048+ / ECDSA-P256 | 广泛兼容性 |
| SSH认证 | Ed25519 | 高性能，小密钥 |
| JWT令牌 | HS256(HMAC) / EdDSA | 性能好 |
| 代码签名 | RSA-4096 / ECDSA-P384 | 高安全 |
| 区块链 | ECDSA secp256k1 | 行业标准 |
| 移动应用 | ECDSA-P256 / Ed25519 | 性能和大小 |
| 物联网设备 | Ed25519 | 资源效率 |
| 中国合规 | SM2 | 法规要求 |
| 后量子准备 | ML-DSA / Falcon | 抗量子攻击 |

### 13.2 数字签名最佳实践

1. **使用经过审计的密码学库**：不要自己实现签名算法
2. **选择合适的算法和参数**：根据安全需求选择
3. **使用确定性签名**：ECDSA使用RFC 6979，或使用EdDSA
4. **保护私钥安全**：使用HSM或安全存储
5. **验证时检查所有条件**：签名有效性、证书链、证书状态
6. **使用恒定时间比较**：防止时序攻击
7. **添加时间戳**：长期保存的签名需要时间戳
8. **使用标准格式**：CMS/PKCS#7、JWS等
9. **定期轮换密钥**：防止密钥老化
10. **记录审计日志**：记录所有签名操作

### 13.3 常见错误

| 错误 | 后果 | 正确做法 |
|------|------|---------|
| 使用MD5/SHA-1哈希 | 碰撞攻击 | 使用SHA-256以上 |
| RSA不用填充 | 签名可伪造 | 使用PSS或PKCS1v15 |
| ECDSA随机数k泄露 | 私钥泄露 | 使用RFC 6979 |
| 不验证证书链 | 中间人攻击 | 完整证书链验证 |
| 签名后修改数据 | 签名失效 | 先签后存 |
| 私钥硬编码 | 密钥泄露 | 使用HSM/KMS |
| 不使用时间戳 | 无法证明签名时间 | 添加RFC 3161时间戳 |

### 13.4 参考标准

| 标准 | 说明 |
|------|------|
| FIPS 186-5 | 数字签名标准（DSA/ECDSA/EdDSA） |
| RFC 8032 | EdDSA: Ed25519和Ed448 |
| RFC 6979 | 确定性ECDSA |
| RFC 3447 | PKCS#1 RSA密码标准 |
| RFC 3161 | 时间戳协议 |
| RFC 5652 | CMS（Cryptographic Message Syntax） |
| GB/T 32918 | SM2椭圆曲线公钥密码算法 |
| ETSI EN 319 132 | XAdES XML电子签名 |
| ETSI EN 319 142 | PAdES PDF电子签名 |

---

> **总结：** 数字签名是信息安全基础设施的核心技术。从传统的RSA签名到现代的EdDSA，从国际标准到国密SM2，数字签名技术不断发展以应对新的安全挑战。随着量子计算的发展，后量子签名算法将成为未来的主流。掌握各种签名算法的原理、实现和安全使用方法，是网络安全从业者的必备技能。在实际应用中，选择合适的算法、使用经过审计的实现、遵循最佳实践，才能确保数字签名提供真正的安全保障。
