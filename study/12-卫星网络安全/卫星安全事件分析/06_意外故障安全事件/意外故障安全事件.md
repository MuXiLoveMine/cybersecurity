# 意外故障安全事件

### 6.1 Galaxy 15"僵尸卫星"事件(2010)

```
事件: Galaxy 15"僵尸卫星"

时间: 2010年4月
卫星: Galaxy 15(Intelsat运营)
故障: 卫星停止响应指令但继续发射

事件经过:
1. 2010年4月5日: Galaxy 15停止响应地面指令
2. 但转发器仍在工作
3. 卫星开始漂移(不再保持轨道位置)
4. 可能干扰其他GEO卫星
5. 地面持续尝试通信(失败)
6. 2010年12月: 太阳食导致断电
7. 卫星重置后恢复通信
8. 最终恢复控制

技术分析:
- 故障原因: 可能是SEU导致
- 星载计算机寄存器翻转
- 指令处理模块异常
- 看门狗定时器未触发复位

安全影响:
- 卫星漂移可能碰撞其他卫星
- 转发器信号可能干扰其他卫星
- 无法通过指令关闭
- 对GEO轨道安全构成威胁

教训:
1. SEU可能导致安全功能失效
2. 需要硬件看门狗强制复位
3. 需要故障安全模式(断电复位)
4. 星载软件需要异常自恢复能力
5. 抗辐射设计至关重要
```

### 6.2 在轨碰撞事件

```
事件: Iridium 33与Cosmos 2251碰撞(2009)

时间: 2009年2月10日
卫星1: Iridium 33(铱星, 商业通信)
卫星2: Cosmos 2251(俄罗斯, 已报废)

事件经过:
1. 两颗卫星在790km高度相撞
2. 相对速度约11.6km/s
3. 两颗卫星完全摧毁
4. 产生约1800个可追踪碎片
5. 碎片散布在LEO广泛区域

技术分析:
- 碰撞高度: 790km
- 相对速度: 11.6km/s
- 碎片数量: 约1800个可追踪
- 碎片寿命: 数百年

安全影响:
- 首次在轨大型碰撞事件
- 碎片威胁其他LEO卫星
- ISS可能受碎片威胁
- 突显空间碎片问题严重性

教训:
1. 碰撞预警系统不足
2. 需要改进空间态势感知
3. 需要自动碰撞规避
4. 空间碎片管理至关重要
5. 需要更好的轨道数据共享
```
