# 供应链安全事件

### 7.1 卫星终端供应链后门

```
事件: 卫星终端预置后门(多种案例)

案例1: VSAT终端后门
┌─────────────────────────────────────────┐
│  • 某品牌VSAT终端固件中发现后门          │
│  • 硬编码管理员凭证                      │
│  • Telnet后门(默认开放)                 │
│  • 可远程控制终端                        │
│  • 影响数万台部署的终端                   │
└─────────────────────────────────────────┘

案例2: 卫星调制解调器漏洞
┌─────────────────────────────────────────┐
│  • 某型号卫星调制解调器存在命令注入       │
│  • 通过Web管理界面可注入命令             │
│  • 可获取root权限                       │
│  • 影响企业卫星通信                      │
└─────────────────────────────────────────┘

案例3: GPS接收机固件漏洞
┌─────────────────────────────────────────┐
│  • 多款GPS接收机固件存在缓冲区溢出        │
│  • 可通过伪造NMEA数据利用                │
│  • 可远程执行代码                        │
│  • 影响导航设备安全                      │
└─────────────────────────────────────────┘

教训:
1. 供应链安全是卫星系统的薄弱环节
2. 设备固件需要安全审计
3. 硬编码凭证是重大风险
4. 需要设备安全认证标准
5. 需要固件签名验证
6. 需要漏洞披露和修复机制
```

### 7.2 卫星地面设备供应链攻击

```
事件: 地面设备供应链入侵

模式: 通过设备供应商入侵卫星运营网络

攻击链:
1. 入侵设备供应商网络
2. 在固件更新中植入后门
3. 通过正常OTA推送到客户设备
4. 后门建立C2通道
5. 从设备跳板攻击运营网络

类似Viasat攻击的供应链维度:
- 管理协议漏洞(非固件后门)
- 但攻击路径经过供应链信任链
- 利用了供应商-客户的信任关系

防护:
1. 固件签名验证(安全启动)
2. 供应链风险评估
3. 设备到货安全检测
4. OTA更新加密认证
5. 设备行为基线监控
6. 零信任架构(不信任任何设备)
```
