## 1. OWASP Mobile Top 10 详解

OWASP Mobile Top 10 是移动应用安全风险的权威分类标准，最新版本为 2024 年发布。

### M1: Improper Platform Usage（平台使用不当）

**定义**：未正确利用平台提供的安全控制机制，如 Android 的 Intent 机制、iOS 的 Keychain。

**风险场景**：
- Android 组件未设置 `exported="false"` 导致未授权访问
- 未正确使用 Android 权限模型
- 未利用 iOS 的 Keychain/App Group 隔离
- WebView 中未限制文件访问和 JavaScript 交互

**测试方法**：
```bash
# Android 组件导出检测
drozer console connect -c "run app.provider.info com.example.app"
drozer console connect -c "run app.service.info com.example.app"

# 检查 AndroidManifest.xml 中的组件 exported 属性
```

### M2: Insecure Data Storage（不安全的数据存储）

**定义**：敏感数据（密码、Token、个人信息）以明文或不安全的方式存储在设备上。

**风险场景**：
- SharedPrefs 明文存储密码/Token
- SQLite 数据库未加密
- 日志中打印敏感信息
- SD 卡明文存储文件
- iOS UserDefaults 明文存储

**测试方法**：
```bash
# Android 数据存储检查
adb shell run-as com.example.app cat /data/data/com.example.app/shared_prefs/*.xml
adb shell run-as com.example.app cat /data/data/com.example.app/databases/*.db
adb logcat | grep -iE "password|token|secret|key"

# iOS Keychain 检查
objection -g com.example.app explore
ios keychain dump
ios nsuserdefaults dump
```

### M3: Insecure Communication（不安全的通信）

**定义**：应用与服务端之间的通信未加密或使用了弱加密。

**风险场景**：
- 使用 HTTP 明文传输
- HTTPS 但未做证书校验（自签名证书被信任）
- 未实现 SSL Pinning
- 使用弱 TLS 版本（TLS 1.0）
- 消息层加密使用 ECB 模式或固定 IV

**测试方法**：
```bash
# MITM 测试（详见第4节）
# 使用 Burp Suite / mitmproxy 抓包
# 测试 SSL Pinning 是否存在
```

### M4: Insufficient Authentication（认证不足）

**定义**：身份认证机制薄弱，可被绕过或暴力破解。

**风险场景**：
- 客户端本地校验密码（不与服务端校验）
- PIN 码无锁定机制
- 生物认证后无后端二次验证
- Token 过期时间过长或永不过期
- 密码策略过于简单

### M5: Insufficient Cryptography（加密不足）

**定义**：使用了不安全的加密算法或加密实现。

**风险场景**：
- 使用 DES/3DES 等过时算法
- AES 使用 ECB 模式
- 固定密钥硬编码在代码中
- 使用不安全的随机数生成器（java.util.Random）
- 自定义加密算法

### M6: Insecure Authorization（授权不足）

**定义**：授权检查仅在客户端实现，可被绕过。

**风险场景**：
- 客户端判断用户角色后直接显示功能
- API 未做服务端权限校验
- IDOR（不安全直接对象引用）
- 越权访问其他用户数据

### M7: Insecure Code Quality（不安全的代码质量）

**定义**：代码中存在安全缺陷，如硬编码密钥、调试接口未关闭。

**风险场景**：
- 代码中硬编码 API Key / Secret
- 调试日志未关闭
- 第三方 SDK 安全漏洞
- 未启用代码混淆和加固

### M8: Code Tampering（代码篡改）

**定义**：应用可被篡改（修改代码、重打包、注入）。

**风险场景**：
- 未做签名校验
- 未做完整性校验
- Root/越狱后可修改应用行为
- 可通过 Frida/Xposed 注入修改逻辑

### M9: Reverse Engineering（逆向工程）

**定义**：应用可被轻松逆向分析。

**风险场景**：
- 未使用代码混淆（ProGuard/R8）
- 未使用应用加固
- 关键逻辑未做 Native 化
- 资源文件未加密

### M10: Extraneous Functionality（多余功能）

**定义**：发布版本中残留了开发/测试功能。

**风险场景**：
- 残留调试开关
- 残留测试账号/密码
- 隐藏的后门接口
- 开发环境的 API 地址未替换

## 2. Android 渗透测试完整流程

### 2.1 信息收集

```bash
# APK 信息提取
aapt dump badging target.apk | grep -E "package|launchable|permission|sdkVersion"

# 提取 URL 和密钥
apktool d target.apk -o target_decoded
grep -rniE "https?://|api[_-]?key|secret|password|token" target_decoded/

# 检查原生库
find target_decoded/lib -name "*.so"

# 检查资源文件中的敏感信息
find target_decoded/assets -type f | xargs file
```

### 2.2 静态分析（反编译 / 敏感信息 / 硬编码）

```bash
# 使用 jadx 反编译
jadx -d ./jadx_output target.apk

# 搜索硬编码密钥
grep -rniE "AES|DES|RSA|secret|key|password|token|http" jadx_output/sources/

# 检查 AndroidManifest 安全配置
# - 组件导出 (exported="true")
# - debuggable="true"
# - allowBackup="true"
# - usesCleartextTraffic="true"
# - 网络安全配置 (networkSecurityConfig)
```

**敏感信息检查清单**：

| 检查项 | 方法 | 风险等级 |
|--------|------|----------|
| 硬编码密钥 | grep 搜索源码 | 高危 |
| 调试日志 | 搜索 Log.d/Log.v | 中危 |
| 测试接口 | 搜索 test/staging URL | 高危 |
| 密码硬编码 | 搜索 password= | 严重 |
| API Token | 搜索 Bearer/Authorization | 高危 |

### 2.3 动态分析（Frida Hook / 调试 / MITM）

```javascript
// Frida 动态分析模板: 监控所有 HTTP 请求
Java.perform(function() {
    // Hook OkHttp
    var OkHttpClient = Java.use("okhttp3.OkHttpClient");
    OkHttpClient.newCall.implementation = function(request) {
        console.log("[HTTP] " + request.method() + " " + request.url());
        var headers = request.headers();
        for (var i = 0; i < headers.size(); i++) {
            console.log("  " + headers.name(i) + ": " + headers.value(i));
        }
        return this.newCall(request);
    };

    // Hook HttpURLConnection
    var URL = Java.use("java.net.URL");
    URL.openConnection.overload().implementation = function() {
        console.log("[URL] " + this.toString());
        return this.openConnection();
    };
});
```

### 2.4 数据存储安全

```bash
# 1. SharedPrefs 检查
adb shell run-as com.example.app ls -la shared_prefs/
adb shell run-as com.example.app cat shared_prefs/*.xml

# 2. SQLite 检查
adb shell run-as com.example.app ls -la databases/
adb shell run-as com.example.app sqlite3 databases/app.db ".tables"
adb shell run-as com.example.app sqlite3 databases/app.db "SELECT * FROM users;"

# 3. 内部文件检查
adb shell run-as com.example.app ls -laR files/
adb shell run-as com.example.app ls -laR cache/

# 4. 外部存储检查
adb shell ls -la /sdcard/Android/data/com.example.app/
```

**数据存储安全检查表**：

| 存储位置 | 安全要求 | 检查方法 |
|----------|----------|----------|
| SharedPrefs | 敏感数据不存明文 | 检查 xml 文件 |
| SQLite | 敏感数据库需 SQLCipher 加密 | 检查 .db 文件是否可读 |
| 内部文件 | 不存储明文敏感数据 | 检查 files/ 目录 |
| 外部存储 | 不存储敏感数据 | 检查 SD 卡 |
| 备份 | allowBackup="false" | 检查 manifest |

### 2.7 WebView 安全

```javascript
// WebView 安全检查项
// 1. JavaScript 是否启用
// 2. 是否允许 file 访问
// 3. 是否有 JS 桥接接口
// 4. 是否允许混合内容

// Frida Hook WebView 检查
Java.perform(function() {
    var WebView = Java.use("android.webkit.WebView");

    WebView.settings.getJavaScriptEnabled.implementation = function() {
        var result = this.getJavaScriptEnabled();
        console.log("[WebView] JavaScript Enabled:", result);
        return result;
    };

    WebView.addJavascriptInterface.implementation = function(obj, name) {
        console.log("[WebView] JS Interface:", name, "对象:", obj.$className);
        return this.addJavascriptInterface(obj, name);
    };

    WebView.loadUrl.overload('java.lang.String').implementation = function(url) {
        console.log("[WebView] 加载URL:", url);
        return this.loadUrl(url);
    };
});
```

**WebView 安全检查清单**：

| 检查项 | 安全配置 | 风险 |
|--------|----------|------|
| JavaScript | 仅在需要时启用 | XSS |
| setAllowFileAccess | 应设为 false | 本地文件泄露 |
| setAllowUniversalAccessFromFileURLs | 应设为 false | 跨域文件访问 |
| JsBridge | 检查暴露的方法 | 远程代码执行 |
| 密码保存 | setSavePassword(false) | 凭据泄露 |

### 2.9 Root 检测与绕过

详见《Frida Hook 系统教程》第 3.6 节，核心绕过方法：

- Hook `File.exists()` 过滤 su/busybox 路径

### 2.10 完整性校验与绕过

```javascript
// 绕过签名校验
Java.perform(function() {
    var PackageManager = Java.use("android.app.ApplicationPackageManager");
    PackageManager.getPackageInfo.overload('int').implementation = function(flags) {
        var info = this.getPackageInfo(flags);
        // 如果应用检查 signatures 字段，需要伪造
        if ((flags & 0x40) !== 0) { // GET_SIGNATURES
            console.log("[签名校验] 被触发");
            // 返回原始签名信息
        }
        return info;
    };

    // 绕过 CRC/MD5 文件完整性校验
    var ZipFile = Java.use("java.util.zip.ZipFile");
    ZipFile.getEntry.implementation = function(name) {
        var entry = this.getEntry(name);
        if (entry !== null) {
            console.log("[完整性校验] 检查文件:", name);
        }
        return entry;
    };
});
```

## 4. 移动端 MITM 测试

### 4.1 证书安装与信任

```bash
# === Android ===

# 1. 导出 Burp 证书
# Burp Suite → Proxy → Options → Import/Export CA Certificate → DER format

# 2. 转换为系统证书格式
openssl x509 -inform DER -in burp.der -out burp.pem
hash=$(openssl x509 -inform PEM -subject_hash_old -in burp.pem | head -1)
mv burp.pem ${hash}.0

# 3. 安装为系统证书（需 root, Android 6+ 不会信任用户证书）
adb push ${hash}.0 /system/etc/security/certificates/
adb shell "su -c 'mount -o remount,rw /system'"
adb shell "su -c 'cp /sdcard/${hash}.0 /system/etc/security/certificates/'"
adb shell "su -c 'mount -o remount,ro /system'"

# === iOS ===
# 1. 下载 Burp 证书 (http://burp/cert)
# 2. 安装到设备: 设置 → 通用 → VPN与设备管理 → 安装
# 3. 信任证书: 设置 → 通用 → 关于本机 → 证书信任设置 → 启用
```

### 4.2 SSL Pinning 绕过方法汇总

| 方法 | 工具 | 适用场景 |
|------|------|----------|
| Frida 脚本 | objection / 自定义脚本 | Android + iOS 通用 |
| Xposed 模块 | JustTrustMe / SSLUnpinning | Android（需 Xposed） |
| Magisk 模块 | MagiskTrustUserCerts | Android（系统证书） |
| Cycript | 运行时修改 | iOS |
| APK 修改 | 反编译 → 修改网络配置 → 重打包 | Android（无 root） |

```bash
# Objection 一键绕过（最常用）
objection -g com.example.app explore
android sslpinning disable   # Android
ios sslpinning disable       # iOS

# Frida 脚本绕过
frida -U -f com.example.app -l ssl_pinning_bypass.js --no-pause
```

### 4.3 流量分析与篡改

```
MITM 工具链:
  ├── Burp Suite (最常用, 功能全面)
  ├── mitmproxy (命令行, 可编程)
  ├── Charles (图形界面, 易用)
  ├── HTTP Toolkit (快速部署)
  └── Wireshark (底层协议分析)

测试流程:
  1. 配置代理 → 安装证书 → 绕过 Pinning
  2. 捕获所有 HTTP/HTTPS 请求
  3. 分析请求中的敏感参数
  4. 测试参数篡改（越权/注入）
  5. 测试重放攻击
  6. 测试会话固定/Token 泄露
```

### 4.4 WebSocket / gRPC 流量

```bash
# Burp Suite 支持 WebSocket 拦截
# WebSocket 流量在 Proxy → WebSocket history 中查看

# mitmproxy 拦截 WebSocket
mitmproxy --set websocket=true

# gRPC 测试
# gRPC 使用 HTTP/2 + Protobuf
# 需要使用 grpcurl 或 Postman 进行测试

# Frida Hook gRPC 层获取明文
Interceptor.attach(Module.findExportByName("libgrpc.so", "grpc_slice_buffer_add"), {
    onEnter: function(args) {
        // 获取 gRPC 数据
    }
});
```

### 5.2 Drozer Android 攻击面分析

```bash
# 安装 Drozer
pip install drozer

# 连接设备

# 攻击面概览
dz> run app.package.attacksurface com.example.app

#   5 activities exported

#   1 content providers exported
```

### 5.4 Python 自动化测试脚本示例

```python
#!/usr/bin/env python3
"""
移动应用渗透测试自动化脚本
功能: APK 静态分析 + 组件安全检测 + 敏感信息提取
"""

import os
import re
import json
import subprocess
from pathlib import Path

class AndroidPentestScanner:
    def __init__(self, apk_path):
        self.apk_path = apk_path
        self.results = {
            "apk_info": {},
            "manifest_issues": [],
            "hardcoded_secrets": [],
            "exported_components": [],
            "security_config": {},
            "summary": {}
        }

    def run_command(self, cmd):
        result = subprocess.run(cmd, shell=True, capture_output=True, text=True)
        return result.stdout

    def get_apk_info(self):
        """获取 APK 基本信息"""
        output = self.run_command(f'aapt dump badging {self.apk_path}')
        info = {}
        for pattern, key in [
            (r"package: name='(\S+)'", "package_name"),
            (r"versionName='(\S+)'", "version_name"),
            (r"versionCode='(\d+)'", "version_code"),
            (r"launchable-activity: name='(\S+)'", "main_activity"),
            (r"targetSdkVersion:'(\d+)'", "target_sdk"),
            (r"minSdkVersion:'(\d+)'", "min_sdk"),
        ]:
            match = re.search(pattern, output)
            if match:
                info[key] = match.group(1)
        self.results["apk_info"] = info
        return info

    def check_manifest(self, decoded_dir):
        """检查 AndroidManifest 安全配置"""
        manifest_path = os.path.join(decoded_dir, "AndroidManifest.xml")
        with open(manifest_path, 'r', encoding='utf-8') as f:
            content = f.read()

        issues = []

        # 检查 debuggable
        if 'android:debuggable="true"' in content:
            issues.append({"issue": "debuggable=true", "severity": "HIGH"})

        # 检查 allowBackup
        if 'android:allowBackup="true"' in content:
            issues.append({"issue": "allowBackup=true", "severity": "MEDIUM"})

        # 检查明文流量
        if 'android:usesCleartextTraffic="true"' in content:
            issues.append({"issue": "usesCleartextTraffic=true", "severity": "HIGH"})

        # 检查导出组件
        exported_pattern = r'<(activity|service|receiver|provider)[^>]*android:exported="true"[^>]*'
        exported = re.findall(exported_pattern, content)
        for comp in exported:
            issues.append({
                "issue": f"exported {comp}",
                "severity": "MEDIUM"
            })

        self.results["manifest_issues"] = issues

    def scan_hardcoded_secrets(self, source_dir):
        """扫描硬编码密钥"""
        patterns = [
            (r'(?i)(api[_-]?key\s*[=:]\s*["\'])(\w{16,})', "API Key"),
            (r'(?i)(secret\s*[=:]\s*["\'])(\w{8,})', "Secret"),
            (r'(?i)(password\s*[=:]\s*["\'])(\w{4,})', "Password"),
            (r'(?i)(token\s*[=:]\s*["\'])(\w{16,})', "Token"),
            (r'(AES|DES|RSA|ECB|CBC)', "Crypto Reference"),
            (r'(http://[^\s"\']+)', "HTTP URL"),
        ]

        findings = []
        for root, dirs, files in os.walk(source_dir):
            for file in files:
                if file.endswith(('.java', '.smali', '.kt')):
                    filepath = os.path.join(root, file)
                    try:
                        with open(filepath, 'r', errors='ignore') as f:
                            content = f.read()
                        for pattern, desc in patterns:
                            matches = re.findall(pattern, content)
                            for match in matches:
                                value = match[1] if isinstance(match, tuple) else match
                                findings.append({
                                    "type": desc,
                                    "value": value[:50] + "..." if len(value) > 50 else value,
                                    "file": filepath
                                })
                    except Exception:
                        pass

        self.results["hardcoded_secrets"] = findings

    def generate_report(self):
        """生成报告摘要"""
        self.results["summary"] = {
            "total_issues": len(self.results["manifest_issues"]) + len(self.results["hardcoded_secrets"]),
            "manifest_issues_count": len(self.results["manifest_issues"]),
            "hardcoded_secrets_count": len(self.results["hardcoded_secrets"]),
            "high_severity": sum(1 for i in self.results["manifest_issues"] if i.get("severity") == "HIGH"),
        }
        return json.dumps(self.results, indent=2, ensure_ascii=False)

# 使用示例
if __name__ == "__main__":
    scanner = AndroidPentestScanner("target.apk")
    scanner.get_apk_info()

    # 需先反编译
    scanner.check_manifest("target_decoded")
    scanner.scan_hardcoded_secrets("jadx_output/sources")

    report = scanner.generate_report()
    print(report)

    with open("pentest_report.json", "w") as f:
        f.write(report)
```

## 结语

移动应用渗透测试是一项系统性工程，涵盖静态分析、动态分析、网络流量分析、组件安全等多个维度。核心要点：

1. **以 OWASP Mobile Top 10 为框架**，确保覆盖全面的安全风险面
2. **静态与动态结合**，静态分析发现问题线索，动态分析验证利用
3. **重视数据流追踪**，从输入到存储到传输，全程跟踪敏感数据
4. **自动化工具提效**，MobSF/Drozer/QARK 负责批量扫描，人工负责深度挖掘
5. **服务端安全不可忽视**，移动端只是入口，API 安全同样重要

> **安全声明**：本文档仅供安全研究与教学使用。渗透测试必须在获得明确授权的前提下进行，切勿对未授权目标进行测试。
