# 小程序接口安全测试

### 3.1 接口安全概述

小程序的后端 API 接口是攻击的核心目标。由于小程序代码可被反编译，后端接口不能依赖客户端的任何"保密"逻辑，必须建立完善的服务端安全验证体系。

**小程序接口常见安全模型**：

```
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│  小程序前端    │      │  后端 API     │      │  数据库       │
│              │      │              │      │              │
│ 获取 code    │─────→│ code2session │      │              │
│              │←─────│ session_key  │      │              │
│              │      │ + openid     │      │              │
│              │      │              │      │              │
│ 业务请求      │─────→│ Token 验证    │─────→│ 数据读写      │
│ + Token      │      │ 权限校验      │      │              │
│              │←─────│ 返回数据      │←─────│              │
└──────────────┘      └──────────────┘      └──────────────┘
```

### 3.2 越权漏洞测试

**水平越权**：用户 A 可以访问用户 B 的数据。

```javascript
// 漏洞示例：某小程序订单查询接口
// 前端请求
wx.request({
    url: 'https://api.target.com/v1/order/detail',
    data: {
        orderId: 'ORD20240101001',
        userId: 'USER10001'  // 危险：后端仅校验 userId 是否合法，不校验是否属于当前登录用户
    }
});

// 测试方法：
// 1. 抓包获取正常请求
// 2. 修改 userId 为其他用户ID
// 3. 修改 orderId 为其他订单号
// 4. 观察是否返回非本用户的订单数据

// 利用 Burp Suite Intruder 批量遍历：
// Payload: userId=USER${num:10001:10050}
// 观察响应长度/内容差异，判断是否越权成功
```

**垂直越权**：普通用户可以访问管理员接口。

```bash
# 测试方法
# 1. 反编译小程序获取所有 API 路径
# 2. 识别管理类接口（通常包含 admin/manage/operate 等关键词）
grep -rn "admin\|manage\|operate\|backend" ./decompiled_src/

# 3. 使用普通用户 Token 直接调用管理接口
curl -X POST https://api.target.com/v1/admin/user/list \
  -H "Authorization: Bearer <normal_user_token>" \
  -H "Content-Type: application/json"

# 4. 观察是否返回管理数据或拒绝访问
```

### 3.3 未授权访问测试

```bash
# 测试方法：直接去除鉴权信息访问接口

# 原始请求（带 Token）
curl https://api.target.com/v1/user/profile \
  -H "Authorization: Bearer eyJhbGc..."

# 未授权测试（去除 Token）
curl https://api.target.com/v1/user/profile

# 常见未授权场景
# 1. 接口仅校验 Token 存在性，不验证有效性
# 2. Token 过期后接口仍可访问
# 3. 接口完全无鉴权（内部接口误暴露）
# 4. GraphQL 接口未授权内省查询
curl -X POST https://api.target.com/graphql \
  -H "Content-Type: application/json" \
  -d '{"query":"{__schema{types{name fields{name}}}}"}'
```

### 3.4 参数篡改测试

```bash
# 价格篡改测试（支付场景高危）
# 原始请求
POST /v1/order/create HTTP/1.1
Host: api.target.com
Content-Type: application/json

{"productId":"P001","quantity":1,"price":99.00,"totalAmount":99.00}

# 篡改测试
# 1. 修改 price 为 0.01
{"productId":"P001","quantity":1,"price":0.01,"totalAmount":0.01}

# 2. 修改 quantity 为负数
{"productId":"P001","quantity":-1,"price":99.00,"totalAmount":-99.00}

# 3. 修改 totalAmount 与 price*quantity 不一致
{"productId":"P001","quantity":1,"price":99.00,"totalAmount":0.01}

# 4. 添加额外参数尝试覆盖
{"productId":"P001","quantity":1,"price":99.00,"totalAmount":99.00,"discount":99.00,"isVip":true}

# 正确防御：后端不信任客户端传入的任何价格参数
# 价格应由服务端根据 productId 查询数据库获取
```

### 3.6 接口枚举与信息收集

```bash
# 从反编译源码中提取所有 API 接口
# 方法1：grep 提取
grep -rohE "https?://[a-zA-Z0-9./_-]+" ./decompiled_src/ | sort -u

# 方法2：提取 API 路径
grep -rnE "url:\s*['\"]" ./decompiled_src/ | grep -oE "['\"].*['\"]"

# 方法3：提取所有 API 配置
find ./decompiled_src/ -name "config*" -o -name "api*" -o -name "env*" | xargs cat

# API 接口字典扫描
# 使用 ffuf / gobuster 对 API 路径进行模糊测试
ffuf -u https://api.target.com/FUZZ \
  -w /usr/share/wordlists/api-endpoints.txt \
  -mc 200,201,403 \
  -ac

# 常见 API 路径模式
# /api/v1/user/list
# /api/v1/admin/dashboard
# /api/v1/internal/health
# /api/v2/order/detail
```
