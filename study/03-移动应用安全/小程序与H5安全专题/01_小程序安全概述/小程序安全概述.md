# 小程序安全概述

### 1.1 小程序生态全景

小程序自 2017 年微信率先推出以来，已发展为覆盖社交、支付、电商、政务等多个领域的庞大生态。各平台小程序的核心架构相似，但安全模型各有差异。

| 平台 | 宿主 | 开发框架 | 运行环境 | 包大小限制 |
|------|------|---------|---------|-----------|
| 微信小程序 | 微信客户端 | WXML/WXSS/JS | 双线程（逻辑层+渲染层） | 主包 2MB / 总 20MB |
| 支付宝小程序 | 支付宝客户端 | AXML/ACSS/JS | 双线程 | 主包 4MB / 总 20MB |
| 百度小程序 | 百度 App | SWAN | 双线程 | 主包 4MB / 总 30MB |
| 抖音小程序 | 抖音客户端 | TTMPL | 双线程 | 主包 4MB / 总 20MB |

### 1.2 微信小程序架构与安全模型

微信小程序采用双线程架构，这是理解其安全模型的基础：

```
┌──────────────────────────────────────────┐
│              微信客户端进程                 │
│                                          │
│  ┌─────────────┐    ┌─────────────────┐ │
│  │  渲染层      │    │  逻辑层（JSCore）│ │
│  │  (WebView)   │    │  (JavaScript    │ │
│  │              │    │   Core / V8)    │ │
│  │  WXML 渲染   │    │                 │ │
│  │  WXSS 样式   │    │  JS 业务逻辑    │ │
│  │              │    │  API 调用       │ │
│  └──────┬───────┘    └────────┬────────┘ │
│         │                      │          │
│         └──────┬───────────────┘          │
│                │                          │
│         ┌──────┴──────┐                   │
│         │  WeixinJSBridge │                │
│         │  (消息通信层)   │                │
│         └─────────────┘                   │
│                │                          │
│         ┌──────┴──────┐                   │
│         │  原生能力层    │                  │
│         │  (相机/位置/   │                  │
│         │   支付/存储)   │                  │
│         └─────────────┘                   │
└──────────────────────────────────────────┘
```

**双线程架构的安全含义**：

1. **逻辑层隔离**：JS 代码运行在 JSCore（iOS）或 V8（Android）中，无法直接操作 DOM，杜绝了 XSS 通过修改 DOM 劫持页面的传统攻击路径。
2. **通信桥接**：两线程通过 `WeixinJSBridge` 进行 `postMessage` 通信，所有 API 调用需要经过 Native 层转发。
3. **权限管控**：微信通过 `app.json` 中的 `permission` 字段和用户授权弹窗控制敏感 API 访问（位置、通讯录、相册等）。

**安全沙箱机制**：

- 小程序运行在微信的沙箱环境中，无法访问其他小程序的数据
- `wx.setStorageSync` 存储的数据按 AppID 隔离，不同小程序之间无法互相读取
- 网络请求域名必须在管理后台配置 `request合法域名`，默认仅允许 HTTPS
- 小程序代码包在客户端以加密形式缓存，需要特定工具解包

### 1.3 支付宝小程序安全模型

支付宝小程序安全模型与微信类似，但在支付场景下增加了额外的安全保障：

```
安全层级：
┌─────────────────────────────────────┐
│ 1. 应用签名验证（AppID + 签名校验）    │
│ 2. 小程序包加密存储（客户端缓存）       │
│ 3. API 网关鉴权（OpenAPI Token）       │
│ 4. 支付链路加固（RSA2 签名 + AES）     │
│ 5. 风控引擎（设备指纹 + 行为分析）       │
└─────────────────────────────────────┘
```

支付宝小程序特有的安全要素：

- **OpenID 体系**：每个用户在每个小程序中有唯一的 OpenID，跨小程序无法关联用户身份
- **服务器签名**：服务端调用支付宝接口需使用 RSA2 签名，私钥严格保存在服务端
- **支付回调验证**：异步通知需验证签名，防止伪造支付成功通知
- **沙箱环境**：提供沙箱版支付宝客户端用于开发测试，与生产环境完全隔离

### 1.4 百度/抖音小程序安全模型

**百度小程序**特点：
- 支持 SWAN 框架，语法与微信类似但 API 命名空间为 `swan.*`
- 搜索开放生态，可被百度搜索直接索引，增大了攻击面
- 智能小程序可运行在百度系多端（搜索/贴吧/地图），跨端安全一致性挑战大

**抖音小程序**特点：
- 基于 TTMPL 框架，运行在抖音客户端内
- 视频相关 API 丰富，视频内容安全是重点
- 与抖音账号体系打通，社交关系链可能被恶意利用
- 分享裂变场景多，需防范诱导分享和刷量

### 1.5 各平台安全模型对比总结

```
安全维度对比：
                    微信      支付宝     百度      抖音
代码包加密          ✔          ✔          ✔        ✔
域名白名单(HTTPS)  ✔          ✔          ✔        ✔
用户授权弹窗        ✔          ✔          ✔        ✔
逻辑层沙箱          ✔          ✔          ✔        ✔
存储隔离(AppID)     ✔          ✔          ✔        ✔
额外支付风控        ✘          ✔(强)      ✘        ✘
跨端一致性          中         高         低        中
```
