# H5 与原生交互安全

### 7.1 WebView JS Bridge 安全

WebView 与原生代码通过 JS Bridge 进行通信，是 H5 与原生交互的核心机制，也是高发漏洞区域。

**JS Bridge 架构**：

```
┌────────────────────────────────────────────────┐
│                  WebView                         │
│                                                 │
│  ┌─────────────────────────────────────────┐   │
│  │  H5 页面 JavaScript                       │   │
│  │                                         │   │
│  │  window.WebViewBridge.callNative(       │   │
│  │      'getUserInfo',                     │   │
│  │      { userId: 123 },                    │   │
│  │      function(response) { ... }         │   │
│  │  );                                     │   │
│  └──────────────┬──────────────────────────┘   │
│                 │                               │
│         ┌───────┴───────┐                       │
│         │ JS Bridge 层   │                      │
│         │ (prompt/URL    │                      │
│         │  Scheme 拦截)   │                     │
│         └───────┬───────┘                       │
│                 │                               │
└─────────────────┼───────────────────────────────┘
                  │
          ┌───────┴───────┐
          │  Native 层     │
          │  Java/Swift    │
          │  处理 Bridge    │
          │  调用          │
          └───────────────┘
```

**Android JS Bridge 实现**：

```java
// Android WebView JS Bridge 实现

// 方法1：addJavascriptInterface（高风险）
webView.addJavascriptInterface(new Object() {
    @JavascriptInterface
    public String getUserInfo(String userId) {
        // 危险：未验证来源，任意 H5 页面可调用
        return getUserInfoFromDB(userId);
    }

    @JavascriptInterface
    public void saveToken(String token) {
        // 危险：任意 H5 页面可存储任意 Token
        SharedPreferences.Editor editor = prefs.edit();
        editor.putString("auth_token", token);
        editor.apply();
    }
}, "AppBridge");

// 方法2：shouldOverrideUrlLoading 拦截（较安全）
webView.setWebViewClient(new WebViewClient() {
    @Override
    public boolean shouldOverrideUrlLoading(WebView view, WebResourceRequest request) {
        String url = request.getUrl().toString();
        if (url.startsWith("app://bridge/")) {
            // 解析 URL 中的方法名和参数
            String method = request.getUrl().getPathSegments().get(0);
            String params = request.getUrl().getQueryParameter("data");

            // 处理 Bridge 调用
            handleBridgeCall(method, params, new BridgeCallback(view));
            return true; // 拦截 URL
        }
        return false;
    }
});
```

**JS Bridge 安全漏洞**：

```javascript
// 漏洞1：Bridge 未验证来源页面
// 攻击者构造恶意 H5 页面，通过 WebView 加载
// 直接调用原生 Bridge 获取敏感数据

// 恶意页面代码
<script>
// 直接调用原生方法（如果 Bridge 未做域名白名单验证）
AppBridge.getUserInfo('10001'); // 获取任意用户信息

AppBridge.getDeviceId(); // 获取设备标识

AppBridge.readFile('/data/data/com.target/files/config.xml'); // 读取应用文件
</script>

// 漏洞2：Bridge 方法暴露过多
// 开发者将所有原生能力通过 Bridge 暴露
AppBridge.execShell('ls /data/data/com.target/'); // 执行 Shell 命令
AppBridge.setClipboard('malicious_content'); // 修改剪贴板
AppBridge.installApp('/sdcard/malware.apk'); // 安装应用
```

**JS Bridge 安全加固**：

```java
// 安全实现：域名白名单 + 方法权限控制

public class SecureJSBridge {
    private static final Set<String> ALLOWED_ORIGINS = new HashSet<>(Arrays.asList(
        "https://h5.target.com",
        "https://m.target.com"
    ));

    private static final Map<String, Set<String>> METHOD_PERMISSIONS = new HashMap<>();

    static {
        // 每个方法只允许特定域名调用
        METHOD_PERMISSIONS.put("getUserInfo", new HashSet<>(Arrays.asList(
            "https://h5.target.com/profile"
        )));
        METHOD_PERMISSIONS.put("getLocation", new HashSet<>(Arrays.asList(
            "https://h5.target.com/map"
        )));
    }

    @JavascriptInterface
    public String handleBridgeCall(String method, String params, String callback) {
        // 1. 验证调用来源
        String currentUrl = webView.getUrl();
        if (!isAllowedOrigin(currentUrl, method)) {
            Log.w(TAG, "Unauthorized bridge call from: " + currentUrl);
            return "{\"error\":\"unauthorized\"}";
        }

        // 2. 参数验证
        if (!validateParams(method, params)) {
            return "{\"error\":\"invalid_params\"}";
        }

        // 3. 执行方法
        return executeMethod(method, params);
    }

    private boolean isAllowedOrigin(String url, String method) {
        Set<String> allowedOrigins = METHOD_PERMISSIONS.get(method);
        if (allowedOrigins == null) return false;
        return allowedOrigins.stream().anyMatch(url::startsWith);
    }
}
```

### 7.2 URL Scheme 安全

```xml
<!-- AndroidManifest.xml 中注册 URL Scheme -->
<activity android:name=".DeepLinkActivity">
    <intent-filter>
        <action android:name="android.intent.action.VIEW" />
        <category android:name="android.intent.category.DEFAULT" />
        <category android:name="android.intent.category.BROWSABLE" />
        <data android:scheme="targetapp" />
    </intent-filter>
</activity>
```

```java
// DeepLinkActivity.java
public class DeepLinkActivity extends Activity {
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);

        Uri uri = getIntent().getData();
        if (uri != null) {
            String action = uri.getHost();
            String params = uri.getQueryParameter("data");

            // 安全风险：未验证 Deep Link 来源
            // 攻击者可构造恶意链接引导用户访问

            switch (action) {
                case "webview":
                    // 危险：从 Deep Link 获取 URL 并加载
                    String url = uri.getQueryParameter("url");
                    // 如果未验证 url，可加载任意页面
                    openWebView(url); // 可能被利用进行钓鱼攻击
                    break;

                case "transfer":
                    // 危险：从 Deep Link 获取转账参数
                    String toAccount = uri.getQueryParameter("to");
                    String amount = uri.getQueryParameter("amount");
                    // 攻击者可构造链接自动跳转到转账页面
                    startTransfer(toAccount, amount);
                    break;
            }
        }
    }

    // 安全实现
    private void openWebView(String url) {
        // 验证 URL 白名单
        if (!isValidDomain(url)) {
            return; // 拒绝非白名单 URL
        }
        // 使用内部 WebView 打开
        Intent intent = new Intent(this, WebViewActivity.class);
        intent.putExtra("url", url);
        startActivity(intent);
    }

    private boolean isValidDomain(String url) {
        String[] allowedDomains = {"target.com", "cdn.target.com"};
        try {
            Uri uri = Uri.parse(url);
            String host = uri.getHost();
            for (String domain : allowedDomains) {
                if (host != null && host.endsWith(domain)) {
                    return true;
                }
            }
        } catch (Exception e) {
            return false;
        }
        return false;
    }
}
```

### 7.3 Deep Link 劫持

```bash
# Deep Link 劫持场景：
# 1. 攻击者注册相同 Scheme 的恶意 App
# 2. 当用户点击 Deep Link 时，系统弹出选择对话框
# 3. 用户可能选择恶意 App 而非目标 App

# 测试方法：
# 构造测试 App 注册相同 Scheme
adb shell am start -W -a android.intent.action.VIEW \
  -d "targetapp://webview?url=https://evil.com" \
  com.attacker.app

# 防御建议：
# 1. 使用 App Links（Android 6.0+）代替传统 Scheme
# 2. App Links 通过域名验证确保唯一性
# 3. 在 AndroidManifest 中配置 autoVerify="true"
```

**App Links 安全配置**：

```xml
<!-- AndroidManifest.xml -->
<activity android:name=".DeepLinkActivity">
    <intent-filter android:autoVerify="true">
        <action android:name="android.intent.action.VIEW" />
        <category android:name="android.intent.category.DEFAULT" />
        <category android:name="android.intent.category.BROWSABLE" />
        <data android:scheme="https" />
        <data android:host="app.target.com" />
        <data android:pathPrefix="/open" />
    </intent-filter>
</activity>

<!-- 服务端需配置 assetlinks.json -->
<!-- https://app.target.com/.well-known/assetlinks.json -->
```
