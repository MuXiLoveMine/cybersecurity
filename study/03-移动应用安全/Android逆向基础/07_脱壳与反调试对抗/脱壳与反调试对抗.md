# 脱壳与反调试对抗

### 7.1 加壳原理

#### 整体加固流程

```
加固流程：
原始 APK → 提取 DEX → 加密 DEX → 生成壳程序 → 替换 Application → 打包签名 → 加固后的 APK

运行流程：
启动应用 → 壳 Application 运行 → 解密 DEX → 动态加载 DEX → 切换到真实 Application → 业务代码运行
```

#### 壳的类型

| 类型 | 原理 | 难度 |
|------|------|------|
| 整体壳 | 加密整个 DEX，运行时解密加载 | 较易脱壳 |
| 函数级壳 | 对每个函数单独加密，调用时解密 | 中等 |
| VMP 壳 | 将代码转为自定义虚拟机指令 | 困难 |
| 混淆壳 | 控制流平坦化、指令替换等 | 较难 |

### 7.2 常见壳的识别

#### 识别方法

**1. 查看 APK 结构**：
- classes.dex 很小（壳的 dex）
- assets 目录下有加密的 dex 文件
- lib 目录下有壳的 so 文件

**2. 查看 Application**：
- AndroidManifest.xml 中的 Application 类名是壳的类
- 常见壳的 Application 类名特征

**3. 查看特征文件**：
- 梆梆：libsecexe.so、libsecshell.so
- 爱加密：libexec.so、libexecmain.so
- 360 加固：libjiagu.so、libjiagu_art.so
- 腾讯乐固：libshell-super.2019.so
- 百度加固：libbaiduprotect.so

### 7.3 脱壳方法

#### 方法1：内存 dump 脱壳

**原理**：壳在运行时会将 DEX 解密加载到内存中，直接从内存 dump 出来。

**使用 Frida-DEXDump**：
```bash
# 安装
pip install frida-dexdump

# 使用
frida-dexdump -U -f com.example.app
# 或附加到已运行的进程
frida-dexdump -U -n com.example.app
```

**使用 FART（系统级脱壳）**：
- 基于定制 ROM 的脱壳方案
- 在 ART 层面主动调用所有方法，触发类加载
- 能够脱函数级壳和 VMP 壳

#### 方法2：动态调试脱壳

**原理**：在壳解密完成后下断点，dump 内存中的 dex。

**步骤**：
1. 使用 IDA 附加到应用进程
2. 在 dex 加载完成的位置下断点
3. 断点命中后，从内存中 dump dex 数据
4. 修复 dex 文件结构

#### 方法3：Hook 脱壳

**原理**：Hook 系统加载 dex 的函数，在加载时保存 dex 数据。

**Hook 点**：
- `DexFile::DexFile()`
- `OpenMemory()`
- `CookieToDexFile()`
- `dexFileLoad()`

#### 脱壳工具对比

| 工具 | 原理 | 支持的壳 | 优点 | 缺点 |
|------|------|---------|------|------|
| Frida-DEXDump | 内存搜索 dump | 大部分整体壳 | 使用简单 | 不支持 VMP/函数级壳 |
| FART | 系统级主动调用 | 大部分加固 | 脱壳彻底 | 需要刷定制 ROM |
| Youpk | 系统级脱壳 | 大部分加固 | 脱壳彻底 | 需要特定版本 ROM |
| BlackDex | 内存 dump | 整体壳 | 快速方便 | 不支持复杂壳 |

### 7.4 反调试对抗

#### 常见反调试手段

**1. ptrace 检测**
```c
// 检测是否被 ptrace 附加
if (ptrace(PTRACE_TRACEME, 0, 0, 0) == -1) {
    // 已被调试
    exit(0);
}
```

**2. 读取 /proc/pid/status**
```c
// 查看 TracerPid 字段，非 0 表示被调试
FILE *fp = fopen("/proc/self/status", "r");
// 读取 TracerPid 行
```

**3. 时间差检测**
```c
// 检测代码执行时间，断点会导致时间变长
long start = get_timestamp();
// 执行一段代码
long end = get_timestamp();
if (end - start > THRESHOLD) {
    // 可能被调试
}
```

**4. 检测调试端口**
- 检测 27042 端口（Frida 默认端口）
- 检测 23946 端口（IDA 调试端口）

**5. 检测 Frida**
- 检查 /proc/pid/maps 中是否有 frida 相关的库
- 检查 Java 层是否有 Frida 相关的类

#### 反调试绕过方法

**1. Frida Hook 绕过**
```javascript
// Hook ptrace 函数
var ptrace = Module.findExportByName(null, "ptrace");
Interceptor.replace(ptrace, new NativeCallback(function(request, pid, addr, data) {
    console.log("[*] ptrace 被调用, request=" + request);
    // 假装成功
    return 0;
}, 'int', ['int', 'int', 'pointer', 'pointer']));
```

**2. 修改 Smali/So**
- 静态修改反调试判断逻辑
- 将条件跳转改为无条件跳转或相反

**3. 使用 Magisk 模块**
- 隐藏 Root 状态
- 隐藏调试环境
- 隐藏 Frida

### 7.5 脱壳实战流程

```
1. 识别壳的类型
   ├── 查看 APK 结构
   ├── 查看 Application 类名
   └── 查看 lib 目录下的 so

2. 选择脱壳方案
   ├── 简单整体壳 → Frida-DEXDump / BlackDex
   ├── 函数级壳 → FART / Youpk
   └── VMP 壳 → 手工分析 / 定制方案

3. 执行脱壳
   ├── 运行目标应用
   ├── 触发关键功能（确保代码加载）
   └── 执行脱壳工具

4. 验证结果
   ├── 查看 dump 出的 dex 文件
   ├── 用 JADX 打开验证能否反编译
   └── 检查是否包含目标类和方法

5. 后续分析
   ├── 静态分析反编译后的代码
   ├── 动态调试验证逻辑
   └── 编写 Hook 脚本
```

### 一、apktool 命令速查表

apktool 是 Android 逆向最基础的工具，用于反编译和回编译 APK。

| 命令 | 用途 | 常用参数 |
|------|------|---------|
| `apktool d target.apk` | 反编译 APK | `-o <dir>` 指定输出目录 |
| `apktool d target.apk -o output_dir` | 反编译到指定目录 | `-s` 不反编译 dex（保留原文件） |
| `apktool d -r target.apk` | 只反编译资源（不反编译 dex） | `-r` 不解析 dex 文件 |
| `apktool d -s target.apk` | 保留 dex 原样（不转为 smali） | `-s` 跳过 dex 处理 |
| `apktool b output_dir` | 回编译为 APK | `-o <file>` 指定输出 APK 路径 |
| `apktool b . -o new.apk` | 将当前目录回编译为 new.apk | |
| `apktool if framework.apk` | 安装框架资源 | 用于处理依赖系统框架的 ROM APK |
| `apktool empty-framework-dir` | 清空框架目录 | 解决框架冲突问题 |

**常用参数详解**：

| 参数 | 说明 | 使用场景 |
|------|------|---------|
| `-f` / `--force` | 强制覆盖输出目录 | 重复反编译时避免手动删除 |
| `-s` / `--no-src` | 不反编译 dex | 只修改资源文件时提速 |
| `-r` / `--no-res` | 不反编译资源 | 只分析代码时提速 |
| `-m` / `--match-original` | 保持与原始文件一致 | 回编译后保持原签名对齐 |
| `--only-main-classes` | 只反编译主 dex | 多 dex 时只处理 classes.dex |

**实战技巧**：
```bash
# 反编译时同时保留原始 dex（方便后续对比）
apktool d target.apk -o target_decoded --keep-broken-res

# 回编译后自动对齐（需要 zipalign）
apktool b target_decoded -o target_unsigned.apk
zipalign -f -p 4 target_unsigned.apk target_aligned.apk

# 批量反编译目录下所有 APK
for f in *.apk; do apktool d "$f" -o "${f%.apk}_decoded"; done
```

### 二、jadx 命令速查表

jadx 是将 DEX/APK 反编译为 Java 源码的强大工具，支持 GUI 和命令行两种模式。

| 命令 | 用途 | 常用参数 |
|------|------|---------|
| `jadx target.apk` | 反编译 APK（输出到当前目录） | 默认输出到 jadx_output |
| `jadx -d output_dir target.apk` | 指定输出目录 | `-d <dir>` 输出目录 |
| `jadx-gui target.apk` | 启动 GUI 模式 | 交互式分析推荐 |
| `jadx --show-bad-code target.apk` | 显示反编译失败的代码 | 调试反编译错误 |
| `jadx --no-res target.apk` | 不反编译资源 | 只看源码时提速 |
| `jadx --no-debug-info target.apk` | 不生成调试信息 | 减小输出体积 |
| `jadx --deobf target.apk` | 启用混淆类名重命名 | 自动重命名混淆类 |
| `jadx --deobf-parse-kotlin-metadata target.apk` | 解析 Kotlin 元数据 | 还原 Kotlin 类名 |
| `jadx --threads-count 4 target.apk` | 指定线程数 | 多核机器提速 |
| `jadx --log-level ERROR target.apk` | 设置日志级别 | 减少无关输出 |

**输出格式选项**：

| 参数 | 说明 |
|------|------|
| `--output-format java` | 输出 Java 源码（默认） |
| `--output-format smali` | 输出 Smali 代码 |
| `--export-as-gradle` | 导出为 Gradle 项目结构 |

**jadx-gui 常用快捷键**：

| 快捷键 | 功能 |
|--------|------|
| `Ctrl + N` | 搜索类名 |
| `Ctrl + Shift + N` | 搜索文件名 |
| `Ctrl + F` | 当前文件内搜索 |
| `Ctrl + Shift + F` | 全局搜索 |
| `Ctrl + X` | 跳转到 Smali 代码 |
| `F4` | 查看类继承关系 |
| `Ctrl + Alt + H` | 查看方法调用层次 |
| `Shift + F12` | 查看字符串常量 |

**实战场景**：
```bash
# 快速提取所有 URL 和 API 密钥
jadx -d ./out target.apk
grep -rniE "https?://[^\"']+" out/sources/ | head -50
grep -rniE "(api[_-]?key|secret|token|password)\s*[=:]" out/sources/ | head -30

# 分析加固后的脱壳 dex
jadx classes.dex -d ./dex_source  # 直接反编译 dex 文件

# 批量反编译多个 dex
for f in classes*.dex; do jadx "$f" -d "./out/${f%.dex}"; done
```

### 三、baksmali / smali 命令速查表

baksmali 将 dex 反编译为 smali，smali 将 smali 汇编回 dex。常用于精确修改字节码。

| 命令 | 用途 | 常用参数 |
|------|------|---------|
| `baksmali d classes.dex` | 反编译 dex 为 smali | `-o <dir>` 输出目录 |
| `baksmali d classes.dex -o smali_out` | 输出到指定目录 | 默认输出到 out/ |
| `baksmali d -b boot.oat classes.dex` | 指定 boot classpath | 处理脱壳 dex 时解析引用 |
| `baksmali list dex classes.dex` | 列出 dex 中的类 | 快速查看内容概览 |
| `baksmali list methods classes.dex` | 列出所有方法 | 统计方法数、查找目标 |
| `baksmali list fields classes.dex` | 列出所有字段 | |
| `smali a smali_out/` | 汇编 smali 为 dex | 默认输出 out.dex |
| `smali a smali_out/ -o new.dex` | 指定输出 dex 文件名 | |
| `smali a -a 26 smali_out/` | 指定 API 级别 | `-a <api_level>` |

**常用参数详解**：

| 参数 | 说明 |
|------|------|
| `-a` / `--api-level` | 指定 Android API 级别（默认 15） |
| `-b` / `--boot-class-path` | 指定 boot classpath 文件 |
| `-c` / `--class-path` | 指定 classpath 依赖 |
| `-l` / `--locals` | 显示局部变量信息 |
| `-s` / `--sequential` | 按顺序标号（非语法标号） |
| `-j` / `--jobs` | 并发处理线程数 |

**实战场景 - Smali 注入修改**：
```bash
# 1. 反编译 dex
baksmali d classes.dex -o smali_code

# 2. 查找目标方法（如 isRooted）
grep -r "isRooted" smali_code/

# 3. 修改 smali 文件（将返回值改为 false）
# 原方法可能有类似:
#   const/4 v0, 0x1  # 返回 true
#   return v0
# 修改为:
#   const/4 v0, 0x0  # 返回 false
#   return v0

# 4. 重新汇编为 dex
smali a smali_code/ -o classes_new.dex

# 5. 用新 dex 替换原 APK 中的 dex（使用 apktool 或 aapt）
```

| `apksigner verify --verbose app.apk` | 验证签名 |
| `apksigner verify --print-certs app.apk` | 查看签名证书信息 |

#### 4. keytool（密钥库工具）

| 命令 | 用途 |
|------|------|
| `keytool -genkey -v -keystore my.keystore -alias myalias -keyalg RSA -keysize 2048 -validity 36500` | 生成签名密钥库 |
| `keytool -list -v -keystore my.keystore` | 查看密钥库内容 |
| `keytool -exportcert -alias myalias -keystore my.keystore -file cert.cer` | 导出证书 |

#### 5. jarsigner（旧版签名工具）

| 命令 | 用途 |

| `jarsigner -verify -verbose -certs signed.apk` | 验证签名 |

#### 6. uber-apk-signer（一键签名工具）

### 六、逆向分析高效工作流

#### 标准逆向分析流程命令序列：

```bash
# Step 1: 信息收集
aapt dump badging target.apk > app_info.txt
aapt dump permissions target.apk >> app_info.txt

# Step 2: 静态分析
jadx -d jadx_out target.apk
apktool d target.apk -o apktool_out

# Step 3: 敏感信息搜索
grep -rniE "(password|secret|key|token|http)" jadx_out/sources/ > sensitive_strings.txt
grep -rniE "https?://[^\"']+" apktool_out/ > urls.txt

# Step 4: 安装测试
adb install -r -t target.apk

# Step 5: 动态分析（Frida）
frida -U -f com.example.app -l hook_script.js --no-pause

# Step 6: 修改与重打包
# ... 修改 smali 或资源 ...
apktool b apktool_out -o rebuilt.apk
zipalign -f -p 4 rebuilt.apk rebuilt_aligned.apk
apksigner sign --ks debug.keystore rebuilt_aligned.apk
adb install -r rebuilt_aligned.apk
```

**工具使用效率技巧**：
1. **善用别名**：在 `.bashrc` 或 PowerShell profile 中设置常用命令别名，如 `alias jadx-gui='~/tools/jadx/bin/jadx-gui'`
2. **批量处理**：编写脚本批量处理多个 APK，提高分析效率
3. **结果归档**：每个 APK 的分析结果建立独立目录，便于回溯
4. **组合使用**：apktool 适合修改资源和 smali，jadx 适合阅读 Java 源码，两者结合使用
