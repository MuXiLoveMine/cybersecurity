# 实战案例：企业无线渗透测试全流程

本章通过一个完整的企业无线渗透测试案例，展示从前到后的完整测试流程，帮助读者理解方法论在实际项目中的应用。

### 8.1 案例背景与测试范围

#### 8.1.1 客户背景

**客户概况：**
- **行业**：金融科技
- **规模**：约500名员工
- **办公地点**：某城市写字楼，共3层办公楼
- **业务性质**：涉及大量敏感金融数据和客户信息
- **合规要求**：网络安全等级保护三级、PCI DSS

**网络环境概况：**
- 企业级无线局域网，由无线控制器统一管理
- 约30台企业级AP，覆盖3层办公区域
- 3个主要SSID：
  - `Corp-WiFi`：员工办公网络，WPA2 Enterprise (PEAP)
  - `Guest-WiFi`：访客网络，Web Portal认证
  - `IoT-WiFi`：物联网设备专用网络，WPA2 PSK
- 无线控制器：Cisco WLC 9800-L
- 认证系统：Windows NPS + Active Directory
- 安全设备：防火墙、WIPS、终端安全管理

#### 8.1.2 测试目标与范围

**测试目标：**
1. 评估企业无线网络的整体安全状况
2. 发现无线网络中的安全漏洞和配置缺陷
3. 验证从无线接入点突破到内网核心系统的可能性
4. 评估WIPS等安全防护措施的有效性
5. 提供针对性的安全整改建议

**测试范围：**

| 范围维度 | 具体内容 |
|---------|---------|
| **目标SSID** | Corp-WiFi、Guest-WiFi、IoT-WiFi |
| **目标设备** | 无线控制器、所有AP、认证服务器、相关网络设备 |
| **物理范围** | 客户办公楼内及周边50米范围内 |
| **测试方法** | 被动侦察、主动扫描、认证攻击、加密测试、中间人攻击、后渗透测试 |
| **时间窗口** | 2025年X月X日 - X月X日，共10个工作日 |
| **后渗透限制** | 仅允许在指定测试VLAN内进行横向移动，禁止触碰生产系统 |

**明确禁止的测试：**
- 拒绝服务攻击（DoS/DDoS）
- 对生产业务系统的直接攻击
- 数据窃取和导出测试（仅验证可访问性）
- 物理入侵测试

#### 8.1.3 项目团队

- **项目经理**：1人，负责项目管理和客户沟通
- **技术负责人**：1人，负责技术方案和质量控制
- **高级测试工程师**：2人，负责攻击测试和后渗透
- **初级测试工程师**：1人，负责侦察和数据整理

### 8.2 侦察阶段：信号测绘与设备识别

#### 8.2.1 被动侦察（Day 1 上午）

**工具：** Kismet + Alfa AWUS036ACH + GPS

**执行过程：**

1. **全信道扫描**
   - 使用Kismet对2.4GHz和5GHz全信道进行扫描
   - 持续扫描时间：2小时
   - 扫描位置：办公楼各楼层、周边区域

2. **初步发现**
   ```
   发现的SSID列表：
   1. Corp-WiFi (5GHz优先，2.4GHz备用)
      - BSSID数量：15个（每楼层5个AP）
      - 加密：WPA2 Enterprise (PEAP)
      - 厂商：Cisco
   
   2. Guest-WiFi
      - BSSID数量：15个
      - 加密：WPA2 PSK（Portal认证后分配）
      - 厂商：Cisco
   
   3. IoT-WiFi
      - BSSID数量：8个
      - 加密：WPA2 PSK
      - 厂商：Cisco
   
   4. 意外发现：Staff-Personal
      - BSSID：AA:BB:CC:DD:EE:FF
      - 加密：WPA2 PSK
      - 厂商：TP-Link
      - 位置：3楼休息区附近
      - 状态：未在授权列表中 → 疑似Rogue AP
   ```

3. **客户端设备发现**
   - 通过Probe Request帧发现大量客户端设备
   - 主要类型：Windows笔记本、iPhone、Android手机
   - 部分客户端会主动探测已知的SSID
   - 发现部分员工手机会自动连接开放网络

#### 8.2.2 主动扫描与信息收集（Day 1 下午）

**工具：** airodump-ng、wash、nmap

**执行过程：**

1. **AP详细信息收集**
   - 对每个AP进行详细的信息收集
   - 记录支持的速率、信道宽度、安全套件
   - 测试漫游行为

2. **WPS检测**
   ```
   使用wash扫描结果：
   - Corp-WiFi所有AP：WPS已禁用 ✓
   - Guest-WiFi所有AP：WPS已禁用 ✓
   - IoT-WiFi所有AP：WPS已禁用 ✓
   - Staff-Personal（Rogue AP）：WPS已启用 ✗
     - WPS版本：2.0
     - 锁定：否
   ```

3. **企业认证详细信息**
   ```
   认证方式：PEAPv0 / MS-CHAPv2
   服务器证书：
   - 签发机构：公司内部CA
   - 证书主题：radius.company.com
   - 有效期限：2023-2026
   客户端验证：未强制验证服务器证书（发现的问题！）
   ```

4. **Rogue AP确认**
   - 通过有线侧扫描确认该AP连接到了访客网络的端口
   - 物理定位：3楼休息区天花板上方
   - 确认：员工私自安装的无线路由器，用于个人设备上网

#### 8.2.3 信号测绘（Day 2）

**工具：** Ekahau Site Survey + GPS

**测绘结果：**

1. **信号覆盖图**
   - 办公楼内部信号覆盖良好，平均信号强度-55dBm
   - 办公楼外部信号泄露情况：
     - 楼下大堂：部分区域可检测到信号，强度-75~-85dBm
     - 楼外街道：距建筑物10-20米处仍可检测到信号
     - 停车场：部分区域信号强度可达-70dBm

2. **高风险区域标注**
   - 地下停车场B1层：信号较强，且人员混杂，攻击者可在此发起攻击
   - 楼下咖啡厅：距办公楼约15米，可接收到WiFi信号
   - 消防通道：靠近外墙处信号较强，且人员较少

3. **干扰源分析**
   - 2.4GHz信道拥挤，周边有大量其他WiFi网络
   - 5GHz信道相对干净
   - 未发现明显的非WiFi干扰源

**侦察阶段发现汇总：**

| 编号 | 发现 | 初步风险 |
|------|------|---------|
| RECON-01 | 发现Rogue AP (Staff-Personal) | High |
| RECON-02 | PEAP认证未强制验证服务器证书 | High |
| RECON-03 | 信号泄露到外部公共区域 | Medium |
| RECON-04 | 2.4GHz频段信道拥挤 | Low |
| RECON-05 | 部分客户端设备存在自动连接开放网络的行为 | Medium |

### 8.3 攻击阶段：从WPA破解到内网突破

#### 8.3.1 Rogue AP利用（Day 3 上午）

**目标：** Staff-Personal（员工私自安装的TP-Link路由器）

**攻击过程：**

1. **WPS Pixie Dust攻击**
   - 工具：`OneShot` + `Reaver`
   - 目标BSSID：AA:BB:CC:DD:EE:FF
   - 攻击时间：约2分钟
   - 结果：成功获取WPS PIN码（12345670）
   - 进一步获取WPA PSK：`password123`

2. **连接Rogue AP**
   - 使用获取的PSK成功连接
   - 获取IP地址：192.168.0.100/24
   - 默认网关：192.168.0.1（TP-Link管理地址）

3. **路由器管理界面访问**
   - 默认凭证admin/admin成功登录
   - 查看WAN口配置：通过DHCP获取访客网络地址
   - 确认：Rogue AP连接在访客网络端口上

4. **风险评估**
   - Rogue AP本身连接在访客网络，理论上无法直接访问内部网络
   - 但攻击者可以利用此AP作为跳板，尝试进一步攻击
   - 员工的个人设备连接此AP，可能导致企业数据泄露

**漏洞记录：** WLAN-001 Rogue AP + 弱WPS + 弱密码（Severity: High）

#### 8.3.2 WPA Enterprise攻击（Day 3 下午 - Day 4）

**目标：** Corp-WiFi（WPA2 Enterprise PEAP）

**攻击过程：**

1. **准备阶段**
   - 搭建hostapd-wpe伪造RADIUS服务器
   - 准备自签名证书（与真实证书相似的主题）
   - 配置Evil Twin AP，SSID设为Corp-WiFi

2. **Evil Twin + PEAP降级攻击**
   - 在地下停车场搭建Evil Twin AP
   - 使用相同的SSID：Corp-WiFi
   - 设置较高的发射功率
   - 配合Deauth攻击，将附近的客户端踢下合法AP

3. **凭证捕获结果**
   - 攻击持续时间：3小时（午休时间）
   - 捕获到的认证尝试：17次
   - 成功捕获MS-CHAPv2 Challenge/Response：5组
   - 其中3组用户的设备未验证服务器证书，直接接受了伪造证书

4. **破解NTLM哈希**
   - 工具：`asleap` + 彩虹表
   - 结果：
     - 用户1（普通员工）：成功破解，密码为`Summer2024!` → 弱密码
     - 用户2（部门经理）：字典攻击失败，密码强度较高
     - 用户3：破解中...

5. **验证获取的凭证**
   - 使用用户1的凭证连接真实的Corp-WiFi
   - 结果：成功连接，获取内部网络访问权限
   - IP地址：10.20.30.105/24（办公网络VLAN）

**漏洞记录：**
- WLAN-002 PEAP认证未强制客户端验证服务器证书（Severity: High）
- WLAN-003 存在弱密码账户（Severity: High）

#### 8.3.3 IoT-WiFi攻击（Day 5 上午）

**目标：** IoT-WiFi（WPA2 PSK）

**攻击过程：**

1. **WPA握手捕获**
   - 监听IoT-WiFi信道
   - 等待IoT设备重新连接
   - 或发送Deauth帧强制重连

2. **捕获结果**
   - 成功捕获WPA四次握手
   - 涉及设备：智能摄像头、温湿度传感器等

3. **字典攻击**
   - 使用常用密码字典进行攻击
   - 攻击时间：约30分钟
   - 结果：成功破解PSK
   - 密码：`IoT@Company2024`（有一定强度但有规律）

4. **连接IoT网络**
   - 成功连接IoT-WiFi
   - IP段：10.30.0.0/16
   - 发现的设备：
     - 网络摄像头（约20台）
     - 温湿度传感器
     - 智能门禁控制器
     - 照明控制系统

5. **IoT设备漏洞探测**
   - 摄像头使用默认密码（admin/123456）
   - 可查看所有摄像头的实时画面
   - 门禁控制器存在未授权访问漏洞
   - 可远程控制门禁开关

**漏洞记录：**
- WLAN-004 IoT网络PSK密码强度不足（Severity: High）
- WLAN-005 IoT设备使用默认密码（Severity: Critical）
- WLAN-006 门禁控制器未授权访问（Severity: Critical）

#### 8.3.4 访客网络测试（Day 5 下午）

**目标：** Guest-WiFi

**测试内容：**

1. **Portal认证绕过测试**
   - 测试常见的Portal绕过方法
   - 结果：Portal认证机制完善，未发现明显绕过

2. **网络隔离测试**
   - 连接访客网络后，尝试访问内部网络
   - 测试结果：
     - 访问办公网络IP：被防火墙阻断 ✓
     - 访问服务器区域：被阻断 ✓
     - DNS查询内部域名：被劫持到Portal页面 ✓
   - 结论：访客网络隔离有效

3. **客户端隔离测试**
   - 使用两个设备同时连接访客网络
   - 测试设备之间是否可以互相访问
   - 结果：客户端之间无法直接通信 ✓

4. **带宽限制测试**
   - 测试访客网络的带宽限制
   - 结果：每用户限速10Mbps，符合配置

**结论：** 访客网络安全配置良好，未发现严重漏洞。

### 8.4 后渗透阶段：域内横向移动

#### 8.4.1 内网初探（Day 6）

**立足点：** 通过Corp-WiFi的弱密码账户获取的内网访问权限

**网络发现：**

1. **基本信息收集**
   ```
   IP地址：10.20.30.105
   网关：10.20.30.1
   DNS：10.10.10.5（域控制器）
   域：COMPANY.COM
   ```

2. **主机发现**
   - 使用ARP扫描发现同网段主机：约80台
   - 主要是办公PC和打印机
   - 操作系统：Windows 10 / Windows 11

3. **端口扫描**
   - 扫描同网段主机的常用端口
   - 发现的服务：
     - SMB（445端口）：大量主机开放
     - RDP（3389端口）：部分主机开放
     - SSH：少数Linux主机
     - VNC：少量主机

4. **域信息收集**
   - 通过LDAP查询域信息
   - 域用户数量：约500
   - 域计算机数量：约400
   - 域控制器：2台

#### 8.4.2 凭证收集与横向移动（Day 7）

**攻击路径1：SMB Relay攻击**

1. **利用Responder捕获NetNTLM哈希**
   - 在办公网段运行Responder
   - 捕获NetNTLMv2哈希
   - 结果：2小时内捕获到8个用户的哈希

2. **哈希破解**
   - 使用hashcat破解捕获的哈希
   - 成功破解3个弱密码

3. **Pass-the-Hash攻击**
   - 使用未破解的哈希进行PtH攻击
   - 成功访问3台主机的SMB共享
   - 收集到一些敏感文档

**攻击路径2：RDP弱口令**

1. **RDP密码喷洒**
   - 使用已获取的密码对RDP服务进行喷洒
   - 结果：成功登录2台主机
   - 其中1台是开发人员的工作站

2. **开发工作站信息收集**
   - 发现保存的Git凭证
   - 发现数据库连接配置
   - 发现测试环境的管理员密码

**攻击路径3：IoT网络跳板**

1. **从IoT网络到办公网络**
   - 已控制IoT网络
   - 探测IoT网络与办公网络的连接点
   - 发现IoT网关服务器（双网卡）

2. **IoT网关渗透**
   - 利用弱密码登录IoT网关管理界面
   - 获取网关服务器的SSH访问权限
   - 以此为跳板访问办公网络

#### 8.4.3 权限提升尝试（Day 8）

**尝试路径：**

1. **本地权限提升**
   - 在已控制的主机上尝试提权
   - 利用常见的Windows提权漏洞
   - 结果：部分主机成功获取本地管理员权限

2. **域权限提升尝试**
   - 尝试Kerberoasting攻击
   - 发现几个SPN账户
   - 破解Kerberos TGS票据：部分成功
   - 获取服务账户的明文密码

3. **关键发现**
   - 在文件服务器上发现IT部门共享文件夹
   - 包含服务器配置文档
   - 包含部分管理员密码（保存在Excel文档中）
   - 获取了域管理员的密码（明文存储！）

4. **验证域管理员权限**
   - 使用获取的域管理员凭证
   - 成功访问域控制器
   - 确认已获取域管理员级别的权限

**重要：** 根据测试范围约定，在确认可以获取域管理员权限后，停止进一步的域内操作，避免影响生产环境。

**后渗透阶段攻击链总结：**

```
无线攻击入口
    │
    ├── 路径A：PEAP证书问题 → 弱密码账户 → 内网访问
    │       → SMB Relay → 更多凭证 → 文件服务器 → 域管理员密码
    │
    └── 路径B：Rogue AP → IoT网络 → IoT网关 → 内网跳板
            → 开发工作站 → 数据库凭证 → 进一步渗透
```
