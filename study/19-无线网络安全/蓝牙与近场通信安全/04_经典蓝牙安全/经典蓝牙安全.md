# 经典蓝牙安全

### 3.1 蓝牙认证与加密

```
经典蓝牙安全机制：

1. 认证流程
   ├── 基于共享链路密钥的挑战-响应
   ├── 设备A 发送随机数 AU_RAND_A
   ├── 设备B 计算认证响应:
   │   SRES = E1(LinkKey, AU_RAND_A, COF, 0)
   └── 设备A 验证 SRES

2. 链路密钥类型
   ├── Kinit: 初始化密钥（基于 PIN）
   │   └── Kinit = E22(PIN, PIN_LEN, BD_ADDR, IN_RAND)
   ├── Kunit: 单元密钥（设备自身密钥）
   ├── Kcomb: 组合密钥（两设备共享）
   │   ├── 基于双方随机数和 BD_ADDR
   │   └── 每对设备唯一
   ├── Kmaster: 主密钥
   └── KAB: 临时链路密钥

3. 加密流程
   ├── 加密密钥 Kc = E3(LinkKey, EN_RAND, COF)
   ├── Kc 长度协商 (1-16 字节)
   ├── 密钥流: E0(Kc, clock, BD_ADDR)
   └── E0: 流加密算法

4. 安全模式
   ├── 安全模式1: 无安全
   ├── 安全模式2: 服务级安全
   └── 安全模式4: 服务级安全（SSP）
```

### 3.2 PIN 码破解

```
蓝牙 PIN 码破解：

攻击原理：
├── 配对过程中 PIN 用于生成 Kinit
├── Kinit = E22(PIN, PIN_LEN, BD_ADDR, IN_RAND)
├── 如果捕获配对流量
├── 可以离线暴力破解 PIN
└── 多数设备使用 4 位 PIN（仅 10000 种可能）

攻击工具: Bluetooth Cracker / btcrack

攻击条件：
├── 捕获配对过程的数据包
├── 知道主从设备的 BD_ADDR
├── 需要 Ubertooth 或类似抓包设备
└── PIN 长度越短越容易

防御措施：
├── 使用 8 位以上 PIN
├── 使用 SSP（Secure Simple Pairing）
├── 在私密环境中配对
└── 避免使用默认 PIN（0000/1234）
```

### 3.3 Bluejacking

```
Bluejacking（蓝牙垃圾信息）：

定义：
├── 向蓝牙设备发送未授权的 vCard 消息
├── 利用 OBEX Push 服务
├── 通常无害但令人困扰
└── 不涉及数据窃取

攻击条件：
├── 目标设备蓝牙可见
├── 目标设备启用 OBEX Push
├── 距离 10 米以内
└── 无需配对

攻击流程：
1. 扫描附近蓝牙设备
   hcitool scan

2. 查找 OBEX Push 通道
   sdptool browse <BD_ADDR>
   → 查找 "OBEX Object Push" 服务

3. 发送 vCard
   # 使用 obexftp
   obexftp -b <BD_ADDR> -B <channel> -p message.vcf

4. 消息内容（vCard 格式）
   BEGIN:VCARD
   VERSION:2.1
   N:;Alert;;
   FN:Security Alert
   TEL;CELL:1234567890
   END:VCARD

防御措施：
├── 设置蓝牙不可见（不可发现模式）
├── 关闭 OBEX Push 服务
├── 拒绝未知文件传输请求
└── 不接受未知来源的消息
```

### 3.4 Bluesnarfing

```
Bluesnarfing（蓝牙数据窃取）：

定义：
├── 利用 OBEX Push 漏洞
├── 未经授权访问设备数据
├── 可读取通讯录、日历、短信等
└── 严重侵犯隐私

漏洞原理：
├── OBEX Push 服务设计缺陷
├── 某些实现允许无认证访问
├── 通过特定 OBEX 请求读取文件
└── 影响多种旧版手机

攻击工具：
├── bluesnarfer
├── btscanner
└── 自定义脚本

攻击命令示例：
# 扫描目标
hcitool scan

# 测试 Bluesnarfing
bluesnarfer -b <BD_ADDR> -r phonebook

# 读取日历
bluesnarfer -b <BD_ADDR> -r calendar

防御措施：
├── 更新设备固件
├── 设置蓝牙不可见
├── 关闭不需要的服务
├── 使用新版本蓝牙协议
└── 定期检查设备数据
```

### 3.5 BlueBorne 漏洞

```
BlueBorne（2017年披露）：

漏洞概述：
├── 影响: 蓝牙协议栈实现漏洞
├── 范围: Android/iOS/Windows/Linux
├── 严重性: 严重（CVSS 8+）
├── 无需配对即可利用
└── 可远程代码执行

漏洞链分析：

1. CVE-2017-1000250 (Linux)
   ├── Linux 内核蓝牙 L2CAP 解析漏洞
   ├── 恶意 L2CAP 配置请求导致内存损坏
   └── 可触发内核代码执行

2. CVE-2017-1000251 (Linux BlueZ)
   ├── BlueZ SDP 服务信息泄露
   ├── 导致蓝牙密钥泄露
   └── 可用于解密蓝牙通信

3. CVE-2017-0781 (Android)
   ├── Android 蓝牙 L2CAP 解析漏洞
   ├── 堆溢出导致代码执行
   └── 影响 Android 5.0+ 设备

4. CVE-2017-0782 (Android)
   ├── BNEP (蓝牙网络封装协议) 漏洞
   ├── 堆溢出
   └── 无需用户交互

5. CVE-2017-0783 (Android)
   ├── BNEP 服务数据溢出
   └── 可导致中间人攻击

6. CVE-2017-14315 (BlueZ)
   ├── BlueZ PIN 码处理漏洞
   └── 可绕过认证

攻击流程：
1. 扫描附近蓝牙设备（无需可见模式）
2. 发送恶意蓝牙数据包
3. 利用 L2CAP/BNEP 漏洞
4. 获取内存控制
5. 执行任意代码

防御措施：
├── 安装安全补丁
├── 不使用时关闭蓝牙
├── 限制蓝牙可见性
├── 使用最新版操作系统
└── 企业环境部署蓝牙安全策略
```

### 3.6 KNOB 攻击

```
KNOB Attack (Key Negotiation of Bluetooth, 2019)：

攻击原理：
├── 利用蓝牙密钥长度协商漏洞
├── 攻击者在配对过程中间人介入
├── 强制加密密钥长度 = 1 字节（8位）
├── 1 字节密钥空间仅 256 种
└── 可在几秒内暴力破解

影响范围：
├── 影响所有蓝牙版本
├── 包括 BR/EDR 和 BLE
├── 需要中间人位置
└── 影响 Intel/Apple/Qualcomm 等厂商

攻击条件：
├── 目标设备正在进行配对
├── 攻击者可拦截蓝牙信号
├── 在双方之间中继消息
├── 修改密钥长度字段
└── 无需物理接触

攻击流程：
1. 监听配对过程
2. 截获密钥长度协商消息
3. 修改 Max Encryption Key Size = 1
4. 双方接受降级的密钥长度
5. 捕获加密数据
6. 暴力破解 1 字节密钥（256次）
7. 解密所有后续通信

防御措施：
├── 更新蓝牙固件
├── 强制最小密钥长度为 7 字节
├── 使用 BLE Secure Connections
├── 在安全环境配对
└── 避免公共场所配对
```

### 3.7 BIAS 攻击

```
BIAS (Bluetooth Impersonation AttackS, 2020)：

攻击原理：
├── 蓝牙认证状态机缺陷
├── 利用角色切换机制
├── 绕过双向认证
├── 使用已绑定的链路密钥
└── 伪装成已配对设备

攻击条件：
├── 目标设备之前配对过
├── 知道目标 BD_ADDR
├── 可进行蓝牙通信
└── 支持角色切换

攻击类型：

1. 认证绕过
   ├── 利用 legacy 认证的弱点
   ├── 伪装成已配对设备
   └── 无需知道链路密钥

2. 角色切换攻击
   ├── 利用主从角色切换
   ├── 绕过认证流程
   └── 在认证后切换角色

3. 链路密钥降级
   ├── 将安全链路密钥降级
   └── 使用不安全密钥

防御措施：
├── 更新蓝牙固件
├── 禁用不必要的服务
├── 使用 SSP 配对
├── 限制已知设备连接
└── 监控蓝牙连接日志
```
