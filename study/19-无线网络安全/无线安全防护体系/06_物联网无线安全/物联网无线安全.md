### 5.2 LoRa 密钥管理

```
LoRaWAN 安全架构：

密钥体系：

1. AppKey (Application Key)
   ├── 128 位 AES 密钥
   ├── 每个设备唯一
   ├── 预置在设备中
   ├── 用于 OTAA 入网
   └── 派生 NwkSKey 和 AppSKey

2. NwkSKey (Network Session Key)
   ├── 128 位 AES 密钥
   ├── 网络层加密
   ├── MAC 命令保护
   ├── 完整性校验（MIC）
   └── 防重放保护

3. AppSKey (Application Session Key)
   ├── 128 位 AES 密钥
   ├── 应用层数据加密
   ├── 端到端加密
   └── 网络服务器不可见

LoRaWAN 入网流程（OTAA）：

设备                  网络服务器
 │                       │
 │  Join Request         │
 │  (DevEUI + DevNonce)  │
 │──────────────────────→│
 │                       │
 │  计算: NwkSKey, AppSKey
 │  = AES(AppKey, ...)   │
 │                       │
 │  Join Accept          │
 │  (DevAddr + AppNonce  │
 │  + NetID + DLSettings)│
 │←──────────────────────│
 │                       │
 │  验证并计算会话密钥     │
 │  使用会话密钥加密通信    │
 │──────────────────────→│

密钥管理最佳实践：
├── 设备预置唯一 AppKey
├── 入网使用 OTAA 模式
├── 定期更换会话密钥
├── 设备退役时注销 AppKey
├── 密钥存储在安全元件中
├── 使用硬件安全模块（HSM）
└── 密钥分发使用安全通道

LoRa 安全增强：
├── LoRaWAN 1.1 改进
│   ├── 分离 Join Server
│   ├── 双向认证增强
│   ├── 更强的密钥派生
│   └── Rejoin 机制改进
├── MAC 命令加密
├── 下行链路加密
├── ROAM 漫游安全
└── Firmware OTA 安全更新
```
