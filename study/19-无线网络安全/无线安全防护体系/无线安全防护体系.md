## 1. 无线网络架构设计

### 1.1 VLAN 隔离架构

企业无线网络必须实施严格的 VLAN 隔离，将不同安全级别的流量分离：

```
企业无线网络 VLAN 隔离架构：

Internet
    │
    ┌───┴───────────────────────────────────────┐
    │              防火墙/UTM                    │
    └───┬───────────────────────────────────────┘
        │
    ┌───┴───────────────────────────────────────┐
    │           核心交换机 (Layer 3)              │
    └───┬──────┬──────┬──────┬──────┬───────────┘
        │      │      │      │      │
    VLAN10 VLAN20 VLAN30 VLAN40 VLAN99
    员工网  访客网  IoT网  管理网  安管网
        │      │      │      │      │
    ┌───┴──┐ ┌─┴──┐ ┌─┴──┐ ┌─┴──┐ ┌─┴──┐
    │ AC   │ │Portal│ │IoT  │ │Mgmt │ │WIDS│
    │+APs  │ │  网关 │ │APs  │ │VLAN │ │传感器│
    └──────┘ └────┘ └────┘ └────┘ └────┘

VLAN 规划详情：

VLAN 10 - 员工网络
├── 子网: 10.10.10.0/24
├── 认证: WPA3-Enterprise (802.1X/EAP-TLS)
├── ACL: 允许访问内网资源，禁止访问管理段
├── 隔离: 客户端隔离（禁止 STA 间通信）
└── 日志: 认证日志、流量日志

VLAN 20 - 访客网络
├── 子网: 10.10.20.0/24
├── 认证: Captive Portal (短信/邮箱验证)
├── ACL: 仅允许 Internet 访问，禁止内网
├── 带宽: 限速 10Mbps/用户
├── 隔离: 完全客户端隔离
├── 超时: 4小时自动断开
└── 日志: 访问日志保留 90 天

VLAN 30 - IoT 网络
├── 子网: 10.10.30.0/24
├── 认证: WPA3-Personal (SAE) 或 PSK
├── ACL: 仅允许访问特定服务器/端口
├── 隔离: 严格客户端隔离
├── 设备: 智能门锁、摄像头、传感器
└── 日志: 连接日志、设备行为日志

VLAN 40 - 管理网络
├── 子网: 10.10.40.0/24
├── 认证: 无线管理专用（不广播 SSID）
├── ACL: 仅允许管理设备访问
├── 设备: AP 管理接口、AC 管理接口
└── 隔离: 与所有其他 VLAN 物理隔离

VLAN 99 - 安管网
├── 子网: 10.10.99.0/24
├── 用途: WIDS/WIPS 传感器网络
├── ACL: 仅允许安全平台访问
├── 设备: 无线安全传感器
└── 隔离: 专用 VLAN，无路由到其他网段
```

### 1.3 802.1X 认证架构

```
802.1X 认证架构：

网络组件：
├── Supplicant（请求者）: 客户端设备
├── Authenticator（认证者）: AP/交换机
└── Authentication Server（认证服务器）: RADIUS

协议栈：
┌────────────────────────────────────┐
│            Application             │
├────────────────────────────────────┤
│              TCP/IP                │
├────────────────────────────────────┤
│             EAPoL                  │  ← Supplicant <-> Authenticator
├────────────────────────────────────┤
│              EAP                   │  ← Supplicant <-> Auth Server
├────────────────────────────────────┤
│             RADIUS                 │  ← Authenticator <-> Auth Server
├────────────────────────────────────┤
│        802.11 / 802.3              │
└────────────────────────────────────┘

EAP-TLS 认证流程（推荐方案）：

1. 关联建立
   Supplicant → AP: 802.11 Association

2. EAP 开始
   AP → Supplicant: EAP-Request/Identity

3. 身份声明
   Supplicant → AP: EAP-Response/Identity (user@domain)

4. 转发到 RADIUS
   AP → RADIUS: Access-Request (EAP-Message)

5. RADIUS 开始 TLS
   RADIUS → AP → Supplicant: EAP-Request/EAP-TLS/Start

6. TLS 握手
   ├── Supplicant → AP → RADIUS: ClientHello + ClientCert
   ├── RADIUS → AP → Supplicant: ServerHello + ServerCert + CertRequest
   ├── Supplicant → AP → RADIUS: ClientCert
   ├── RADIUS 验证客户端证书
   ├── Supplicant 验证服务器证书
   └── TLS 隧道建立

7. 密钥派生
   ├── TLS Master Secret 生成
   ├── PMK = TLS-PRF(Master Secret)
   └── RADIUS → AP: PMK (通过 Access-Accept)

8. 四次握手
   AP ↔ Supplicant: 4-Way Handshake (使用 PMK)

9. 加密通信开始

安全控制点：
├── 客户端证书: 确保设备身份
├── 服务器证书: 防止 Evil Twin
├── CA 证书: PKI 信任链
├── CRL/OCSP: 证书吊销检查
├── 密钥强度: 2048位 RSA 或 P-256 ECDH
├── 密码套件: TLS 1.3 / AES-GCM
└── 会话超时: 定期重新认证
```

## 2. 企业 WiFi 安全方案

### 2.1 WPA3-Enterprise 部署

```
WPA3-Enterprise 192-bit Mode 部署方案：

安全套件（CNSA 2.0）：
├── 加密算法: AES-256-GCM
├── 密钥交换: ECDH-P384
├── 数字签名: ECDSA-P384
├── 哈希算法: SHA-384
├── 椭圆曲线: secp384r1 (P-384)
├── 证书要求: 256 位以上安全强度
└── 随机数生成: NIST SP 800-90A 兼容

部署组件：

1. CA 基础设施
├── 根 CA: 离线根证书颁发机构
├── 中间 CA: 在线中间证书颁发机构
├── 颁发 CA: 为设备/用户颁发证书
├── CRL/OCSP: 证书吊销检查服务
└── 证书模板: 按角色定义证书模板

2. RADIUS 服务器（FreeRADIUS）

# /etc/freeradius/3.0/mods-enabled/eap
eap {
    default_eap_type = tls
    
    tls-config tls-common {
        private_key_password = ${env.RADIUS_KEY_PASSWORD}
        private_key_file = /etc/freeradius/certs/server-key.pem
        certificate_file = /etc/freeradius/certs/server-cert.pem
        ca_file = /etc/freeradius/certs/ca-chain.pem
        dh_file = /etc/freeradius/certs/dh-p384.pem
        
        # WPA3-Enterprise 192-bit 套件
        cipher_list = "ECDHE-ECDSA-AES256-GCM-SHA384"
        ecdh_curve = "secp384r1"
        
        # 证书验证
        check_crl = yes
        ca_path = /etc/freeradius/certs/
        check_all_crl = yes
        allow_expired_crl = no
    }
    
    tls {
        config_section = "tls-common"
        # 要求客户端证书
        require_client_cert = yes
    }
}

# /etc/freeradius/3.0/clients.conf
client wifi_controller {
    ipaddr = 10.10.40.0/24
    secret = ${env.RADIUS_SECRET}
    require_message_authenticator = yes
    proto = tcp  # 使用 TCP 传输更可靠
}

3. AP 配置（hostapd）

# hostapd.conf - WPA3-Enterprise
interface=wlan0
driver=nl80211
ssid=CorporateSecure

# WPA3-Enterprise
wpa=2
wpa_key_mgmt=WPA-EAP-SHA256
wpa_pairwise=CCMP-256
group=CCMP-256

# 强制 PMF
ieee80211w=2

# RADIUS 配置
auth_server_addr=10.10.40.10
auth_server_port=2083
auth_server_shared_secret=${RADIUS_SECRET}
acct_server_addr=10.10.40.10
acct_server_port=2083
acct_server_shared_secret=${RADIUS_SECRET}

# RADIUS 动态授权（COA）
radius_acct_interim_interval=300

# 安全增强
wpa_strict_rekey=1
wpa_gmk_rekey=3600
wpa_ptk_rekey=600
```

### 2.2 EAP-TLS 证书管理

```
EAP-TLS 证书管理体系：

证书层级：
├── Root CA (离线)
│   ├── RSA 4096 或 ECDSA P-384
│   ├── 有效期 20 年
│   └── 离线存储，物理安全
├── Issuing CA
│   ├── RSA 4096 或 ECDSA P-384
│   ├── 有效期 10 年
│   ├── 在线服务
│   └── 颁发设备/用户证书
└── 终端证书
    ├── 服务器证书: AP/RADIUS
    ├── 设备证书: 每台设备唯一
    └── 用户证书: 可选（双因子）

证书分发流程：

1. 设备注册
   ├── 设备通过 MDM 注册
   ├── 自动生成密钥对（设备本地）
   ├── 提交 CSR（证书签名请求）
   └── CA 颁发证书

2. 证书安装
   ├── 通过 MDM 推送证书
   ├── 配置 WiFi Profile（含 CA 证书）
   ├── 绑定设备/用户身份
   └── 设置证书 PIN/生物保护

3. 证书验证
   ├── 连接时 AP 验证设备证书
   ├── 设备验证 RADIUS 证书
   ├── CRL/OCSP 检查吊销状态
   └── 证书策略验证

4. 证书更新
   ├── 自动续期（到期前 30 天）
   ├── MDM 推送新证书
   ├── 旧证书吊销
   └── 零停机切换

证书撤销：
├── 设备丢失: 立即吊销证书
├── 员工离职: 吊销用户证书
├── 证书泄露: 吊销并重新颁发
├── CRL 更新: 每小时发布
└── OCSP 响应: 实时检查
```

### 2.4 快速漫游安全

```
802.11 漫游安全增强：

漫游问题：
├── 漫游延迟: 标准 802.11 漫游需 100-500ms
├── 重新认证: 每次漫游需完整 802.1X 认证
├── 用户体验: 语音/视频通话中断
└── 安全风险: 漫游期间可能被劫持

802.11r - 快速 BSS 切换（FT）：
├── 预共享密钥: 漫游前预计算 PMK-R0/R1
├── 漫游时间: < 50ms
├── 认证方式: FT-PSK / FT-802.1X
└── 密钥层级:
    ├── PMK-R0: 主根密钥（由初始认证生成）
    ├── PMK-R0-ID: PMK-R0 标识
    ├── PMK-R1: 每个目标 AP 的密钥
    ├── PMK-R1-ID: PMK-R1 标识
    └── PTK: 每次关联的临时密钥

# hostapd 配置 802.11r
mobility_domain=4f00    # 移动域标识
ft_over_ds=1            # 通过 DS 域切换
ft_psk_generate_local=1 # 本地生成 PSK
pmk_r1_push=1           # 推送 PMK-R1
r0_key_lifetime=10000   # PMK-R0 生命周期
r1_key_holder=000102030405060708090a0b0c0d0e0f

802.11k - 射频资源管理：
├── 邻居报告: AP 提供邻近 AP 列表
├── 信标测量: 客户端报告信号质量
├── 信道报告: 干扰和噪声信息
└── 快速漫游辅助: 减少扫描时间

802.11v - BSS 转换管理：
├── BSS 转换请求: AP 建议客户端切换
├── DMG 操作: 定向多千兆比特操作
├── 多 BSSID: 多 SSID 共享一个 Beacon
└── 省电管理: 优化客户端睡眠

协同部署：
├── 802.11r: 快速认证
├── 802.11k: 智能选择目标 AP
├── 802.11v: 主动引导漫游
├── 802.11w: PMF 保护管理帧
└── 组合部署: 实现毫秒级安全漫游
```

```
#!/bin/bash
# Kismet WIDS 自动响应脚本
# 监控 Kismet 告警并自动响应

KISMET_ALERT_DIR="/var/log/kismet/alerts"
WHITELIST_FILE="/etc/kismet/ap_whitelist.txt"

# 加载授权 AP 白名单
declare -A WHITELIST
while read -r mac ssid; do
    WHITELIST["$mac"]="$ssid"
done < "$WHITELIST_FILE"

# 监控新 AP 出现
check_new_ap() {
    while read -r line; do
        bssid=$(echo "$line" | awk '{print $1}')
        ssid=$(echo "$line" | awk '{print $2}')
        
        if [[ -z "${WHITELIST[$bssid]}" ]]; then
            echo "[!] 未授权 AP 发现: $bssid ($ssid)"
            # 触发告警和响应
            send_alert "$bssid" "$ssid"
            locate_ap "$bssid"
            # 自动抑制（谨慎使用）
            # contain_ap "$bssid"
        fi
    done < <(kismet_client --dump-aps)
}

send_alert() {
    local bssid=$1
    local ssid=$2
    # 发送告警到 SIEM
    logger -t WIDS "ROGUE_AP_DETECTED: $bssid $ssid"
    # 发送邮件
    echo "发现未授权 AP: $ssid ($bssid)" | \
        mail -s "WIDS Alert: Rogue AP" security@company.com
}

locate_ap() {
    local bssid=$1
    # 使用多个传感器进行三角定位
    kismet_locate "$bssid"
}

check_new_ap
```

```
# Bluetooth 监控脚本
#!/bin/bash
# 蓝牙设备监控器

LOG_FILE="/var/log/bluetooth_monitor.log"
KNOWN_DEVICES_FILE="/etc/bt/known_devices.txt"
ALERT_EMAIL="security@company.com"

# 已知设备列表
declare -A KNOWN_DEVICES
while read -r mac name; do
    KNOWN_DEVICES["$mac"]="$name"
done < "$KNOWN_DEVICES_FILE"

# 持续扫描
while true; do
    # 扫描经典蓝牙设备
    hcitool scan | while read -r line; do
        if [[ "$line" =~ ([0-9A-Fa-f]{2}:){5}[0-9A-Fa-f]{2} ]]; then
            mac=$(echo "$line" | awk '{print $1}')
            name=$(echo "$line" | awk '{print $2}')
            
            if [[ -z "${KNOWN_DEVICES[$mac]}" ]]; then
                echo "$(date): 未知蓝牙设备: $mac ($name)" >> "$LOG_FILE"

        fi

            if [[ -z "${KNOWN_DEVICES[$mac]}" ]]; then
                echo "$(date): 未知 BLE 设备: $mac" >> "$LOG_FILE"
            fi
        fi
    done
    
    sleep 60  # 每分钟扫描一次

```

```
处理步骤:
1. [检测] WIDS 确认 Rogue AP

7. [恢复] 恢复网络，加强监控
8. [总结] 完善检测规则

严重级别: 严重
响应时限: 立即

处理步骤:
1. [检测] WIDS 检测伪造 AP
2. [告警] 通知所有用户
3. [遏制] WIPS 客户端抑制
4. [定位] 三角定位攻击者
5. [隔离] 隔离受影响客户端
6. [调查] 检查是否有数据泄露
7. [加固] 增强证书验证

2. [分析] 确定泄露范围
3. [遏制] 禁用蓝牙设备
4. [取证] 保存蓝牙流量
5. [调查] 追溯泄露源头
6. [修复] 修补漏洞/更新固件

事件4: 无线 DoS 攻击

处理步骤:

2. [分析] 确定攻击类型和范围
3. [缓解] 切换信道/频段

6. [取证] 保存攻击证据
```

## 8. 实战案例：企业级 WiFi 安全加固方案

### 8.1 项目背景

```
项目概况：

客户: 某大型企业（2000+ 员工，5 栋办公楼）

现有问题清单：

├── WPS 功能未禁用
├── 管理员密码为默认值
├── 无客户端隔离
├── 管理接口可通过无线访问
```

### 8.2 加固方案设计

```
加固方案架构：

┌─────────────────────────────────────────────────┐
│                  互联网                          │
├─────────────────────────────────────────────────┤
│              下一代防火墙                        │
├─────────┬──────────┬──────────┬─────────────────┤
│ VLAN 10 │ VLAN 20  │ VLAN 30  │   VLAN 99       │
│ 员工网   │ 访客网    │ IoT网    │   安管网        │
│ WPA3-   │ Portal   │ WPA3-   │   WIDS/WIPS     │
│ Ent     │ 认证     │ Personal │   传感器        │
│ EAP-TLS │ 短信验证 │ SAE     │                 │
├─────────┴──────────┴──────────┴─────────────────┤

│    RADIUS集群 (主备) + CA基础设施 + SIEM        │
└─────────────────────────────────────────────────┘
```

### 8.3 实施步骤

```
分阶段实施计划：

阶段1: 基础设施准备（第1-2周）

1.1 VLAN 规划和配置
# 核心交换机配置
# VLAN 10 - 员工
interface vlan10
  description Employee-WiFi
  ip address 10.10.10.1 255.255.255.0
  ip access-group apply employee-acl in
  
# VLAN 20 - 访客
interface vlan20
  description Guest-WiFi
  ip address 10.10.20.1 255.255.255.0
  ip access-group apply guest-acl in
  
# ACL: 访客仅允许上网，禁止内网
ip access-list extended guest-acl
  permit tcp any any eq 80 443
  permit udp any any eq 53
  deny ip any 10.10.0.0 255.255.0.0
  permit ip any any

1.2 CA 基础设施搭建
# OpenSSL 创建 CA
# 根 CA
openssl genrsa -out root-ca.key 4096
openssl req -new -x509 -key root-ca.key \
  -out root-ca.crt -days 3650 \
  -subj "/C=CN/O=Company/CN=Company Root CA"

# 颁发 CA
openssl genrsa -out issuing-ca.key 4096
openssl req -new -key issuing-ca.key \
  -out issuing-ca.csr \
  -subj "/C=CN/O=Company/CN=Company Issuing CA"
openssl x509 -req -in issuing-ca.csr \
  -CA root-ca.crt -CAkey root-ca.key \
  -CAcreateserial -out issuing-ca.crt \
  -days 1825 -extfile ca-ext.cnf

1.3 RADIUS 部署
# FreeRADIUS 安装和配置
apt install freeradius freeradius-mysql
# 配置 EAP-TLS（见 2.1 节配置）
# 测试认证
radtest -t tls user@company.com password localhost 0 testing123

阶段2: WiFi 安全升级（第3-4周）

2.1 AP 固件升级
# 批量升级 AP 固件
for ap_ip in $(cat ap_list.txt); do
    ssh admin@$ap_ip "upgrade firmware wpa3-support.bin"
done

2.2 WPA3-Enterprise 部署
# WLC 配置 WPA3-Enterprise
wlan security wpa3 enable
wlan security wpa3-enterprise
wlan security 802.1x enable
wlan security pmf mandatory

2.3 访客 Portal 部署
# Portal 服务器配置
# HTTPS 证书部署
# 短信验证接口对接
# COA 授权配置

阶段3: 安全监控部署（第5-6周）

3.1 WIDS 传感器部署
# 每层楼部署 2 个传感器
# 配置监控覆盖
# 关联 WLC 和 SIEM

3.2 告警策略配置
# Rogue AP 检测
# Evil Twin 检测
# Deauth 攻击检测
# 异常行为检测

阶段4: 客户端迁移（第7-8周）

4.1 证书分发
# MDM 推送 WiFi Profile
# 包含 CA 证书和客户端证书
# 配置证书验证

4.2 分批迁移
# 第一批: IT 部门（试点）
# 第二批: 管理层
# 第三批: 全体员工
# 每批观察 3 天再推进

阶段5: 验收和运维（第9-10周）

5.1 安全验证
```
