# 无线网络架构设计

### 1.1 VLAN 隔离架构

企业无线网络必须实施严格的 VLAN 隔离，将不同安全级别的流量分离：

```
企业无线网络 VLAN 隔离架构：

Internet
    │
    ┌───┴───────────────────────────────────────┐
    │              防火墙/UTM                    │
    └───┬───────────────────────────────────────┘
        │
    ┌───┴───────────────────────────────────────┐
    │           核心交换机 (Layer 3)              │
    └───┬──────┬──────┬──────┬──────┬───────────┘
        │      │      │      │      │
    VLAN10 VLAN20 VLAN30 VLAN40 VLAN99
    员工网  访客网  IoT网  管理网  安管网
        │      │      │      │      │
    ┌───┴──┐ ┌─┴──┐ ┌─┴──┐ ┌─┴──┐ ┌─┴──┐
    │ AC   │ │Portal│ │IoT  │ │Mgmt │ │WIDS│
    │+APs  │ │  网关 │ │APs  │ │VLAN │ │传感器│
    └──────┘ └────┘ └────┘ └────┘ └────┘

VLAN 规划详情：

VLAN 10 - 员工网络
├── 子网: 10.10.10.0/24
├── 认证: WPA3-Enterprise (802.1X/EAP-TLS)
├── ACL: 允许访问内网资源，禁止访问管理段
├── 隔离: 客户端隔离（禁止 STA 间通信）
└── 日志: 认证日志、流量日志

VLAN 20 - 访客网络
├── 子网: 10.10.20.0/24
├── 认证: Captive Portal (短信/邮箱验证)
├── ACL: 仅允许 Internet 访问，禁止内网
├── 带宽: 限速 10Mbps/用户
├── 隔离: 完全客户端隔离
├── 超时: 4小时自动断开
└── 日志: 访问日志保留 90 天

VLAN 30 - IoT 网络
├── 子网: 10.10.30.0/24
├── 认证: WPA3-Personal (SAE) 或 PSK
├── ACL: 仅允许访问特定服务器/端口
├── 隔离: 严格客户端隔离
├── 设备: 智能门锁、摄像头、传感器
└── 日志: 连接日志、设备行为日志

VLAN 40 - 管理网络
├── 子网: 10.10.40.0/24
├── 认证: 无线管理专用（不广播 SSID）
├── ACL: 仅允许管理设备访问
├── 设备: AP 管理接口、AC 管理接口
└── 隔离: 与所有其他 VLAN 物理隔离

VLAN 99 - 安管网
├── 子网: 10.10.99.0/24
├── 用途: WIDS/WIPS 传感器网络
├── ACL: 仅允许安全平台访问
├── 设备: 无线安全传感器
└── 隔离: 专用 VLAN，无路由到其他网段
```

### 1.2 Portal 认证架构

```
Web Portal 认证架构：

组件构成：
├── Portal Server: Web 认证服务器
├── RADIUS Server: 认证/计费服务器
├── AC (Access Controller): 接入控制器
├── DHCP Server: IP 地址分配
└── DNS Server: DNS 解析/劫持

认证流程：
                    ┌──────┐
                    │ 用户  │
                    └──┬───┘
                       │ 1.关联WiFi(开放/WPA)
                    ┌──┴───┐
                    │  AP   │
                    └──┬───┘
                       │ 2.DHCP获取IP
                    ┌──┴───┐
                    │ DHCP  │
                    └──┬───┘
                       │ 3.HTTP请求(任意URL)
                    ┌──┴───┐
                    │  AC   │
                    └──┬───┘
                       │ 4.302重定向到Portal
                    ┌──┴───┐
                    │ Portal│
                    └──┬───┘
                       │ 5.用户输入手机号/账号
                    ┌──┴───┐
                    │ Portal│
                    └──┬───┘
                       │ 6.发送验证码(SMS/邮件)
                    ┌──┴───┐
                    │ SMS   │
                    └──┬───┘
                       │ 7.用户输入验证码
                    ┌──┴───┐
                    │Portal │──→ 8.验证请求 → RADIUS
                    └──┬───┘
                       │ 9.认证成功
                    ┌──┴───┐
                    │  AC   │ ← 10.COA授权(RADIUS)
                    └──┬───┘
                       │ 11.开放网络访问
                    ┌──┴───┐
                    │ 用户  │ ← 12.上网成功
                    └──────┘

Portal 安全增强：
├── HTTPS 强制: Portal 页面使用 HTTPS
├── 验证码防刷: 图形验证码 + 频率限制
├── 设备指纹: 记录设备特征
├── 行为分析: 异常行为检测
├── 黑白名单: MAC/设备/IP 黑白名单
├── 超时机制: 认证超时和空闲超时
├── 审计日志: 完整认证审计日志
└── 合规要求: 满足公安部82号令要求
```

### 1.3 802.1X 认证架构

```
802.1X 认证架构：

网络组件：
├── Supplicant（请求者）: 客户端设备
├── Authenticator（认证者）: AP/交换机
└── Authentication Server（认证服务器）: RADIUS

协议栈：
┌────────────────────────────────────┐
│            Application             │
├────────────────────────────────────┤
│              TCP/IP                │
├────────────────────────────────────┤
│             EAPoL                  │  ← Supplicant <-> Authenticator
├────────────────────────────────────┤
│              EAP                   │  ← Supplicant <-> Auth Server
├────────────────────────────────────┤
│             RADIUS                 │  ← Authenticator <-> Auth Server
├────────────────────────────────────┤
│        802.11 / 802.3              │
└────────────────────────────────────┘

EAP-TLS 认证流程（推荐方案）：

1. 关联建立
   Supplicant → AP: 802.11 Association

2. EAP 开始
   AP → Supplicant: EAP-Request/Identity

3. 身份声明
   Supplicant → AP: EAP-Response/Identity (user@domain)

4. 转发到 RADIUS
   AP → RADIUS: Access-Request (EAP-Message)

5. RADIUS 开始 TLS
   RADIUS → AP → Supplicant: EAP-Request/EAP-TLS/Start

6. TLS 握手
   ├── Supplicant → AP → RADIUS: ClientHello + ClientCert
   ├── RADIUS → AP → Supplicant: ServerHello + ServerCert + CertRequest
   ├── Supplicant → AP → RADIUS: ClientCert
   ├── RADIUS 验证客户端证书
   ├── Supplicant 验证服务器证书
   └── TLS 隧道建立

7. 密钥派生
   ├── TLS Master Secret 生成
   ├── PMK = TLS-PRF(Master Secret)
   └── RADIUS → AP: PMK (通过 Access-Accept)

8. 四次握手
   AP ↔ Supplicant: 4-Way Handshake (使用 PMK)

9. 加密通信开始

安全控制点：
├── 客户端证书: 确保设备身份
├── 服务器证书: 防止 Evil Twin
├── CA 证书: PKI 信任链
├── CRL/OCSP: 证书吊销检查
├── 密钥强度: 2048位 RSA 或 P-256 ECDH
├── 密码套件: TLS 1.3 / AES-GCM
└── 会话超时: 定期重新认证
```

### 1.4 无线控制器架构

```
集中式无线控制器架构（WLC + Lightweight AP）：

                    ┌──────────────────┐
                    │   管理平台/AC     │
                    │  (WLAN Controller)│
                    └────────┬─────────┘
                             │ CAPWAP 隧道
              ┌──────────────┼──────────────┐
              │              │              │
         ┌────┴───┐    ┌────┴───┐    ┌────┴───┐
         │ AP-1   │    │ AP-2   │    │ AP-3   │
         │(LWAP) │    │(LWAP) │    │(LWAP) │
         └────┬───┘    └────┬───┘    └────┬───┘
              │              │              │
         ┌────┴───┐    ┌────┴───┐    ┌────┴───┐
         │ 客户端  │    │ 客户端  │    │ 客户端  │
         └────────┘    └────────┘    └────────┘

CAPWAP 协议：
├── 控制隧道: UDP 5246 (加密)
├── 数据隧道: UDP 5247 (可选加密)
├── AP 配置管理
├── 固件管理
├── 射频管理
└── 客户端管理

WLC 功能：
├── 集中认证: RADIUS 集中认证
├── 策略管理: 集中下发安全策略
├── RF 管理: 射频资源自动优化
├── 漫游管理: 快速漫游（802.11r/k/v）
├── 负载均衡: AP 间客户端负载均衡
├── 频谱分析: 干扰检测和定位
├── Rogue AP: 未授权 AP 检测
├── WIDS/WIPS: 集成无线入侵防御
└── 访客管理: Portal 认证和访问控制

分布式架构优势：
├── 单点管理: 所有 AP 统一配置
├── 快速漫游: 50ms 内切换 AP
├── 统一安全: 安全策略一致性
├── 灵活部署: 支持 HREAP/FlexConnect
└── 高可用性: WLC 冗余部署
```
