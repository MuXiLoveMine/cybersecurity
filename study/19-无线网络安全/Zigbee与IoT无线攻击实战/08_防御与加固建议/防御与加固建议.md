# 防御与加固建议

### 8.1 Zigbee网络安全最佳实践

#### 8.1.1 网络部署安全

**1. 使用强密钥**
- 绝对不要使用默认的信任中心链接密钥
- 为每个网络使用唯一的网络密钥
- 密钥应使用随机生成的128位数据
- 定期更换网络密钥（建议每3-6个月）

**2. 设备加入控制**
- 启用安装代码（Install Code）认证
- 维护设备白名单（基于IEEE地址）
- 关闭开放加入（Permit Joining）
- 设备加入需管理员确认
- 加入窗口应尽可能短

**3. 网络隔离**
- IoT网络与办公/家庭网络隔离
- Zigbee网关应配置防火墙规则
- 限制Zigbee设备的IP访问范围
- 使用VLAN隔离IoT设备

#### 8.1.2 安全配置清单

```
Zigbee网络安全配置清单：

[ ] 1. 更改默认信任中心链接密钥
[ ] 2. 使用随机生成的网络密钥
[ ] 3. 启用安装代码认证
[ ] 4. 关闭永久允许加入
[ ] 5. 启用设备白名单
[ ] 6. 启用APS加密（关键设备）
[ ] 7. 启用帧计数器检查
[ ] 8. 定期更新网络密钥
[ ] 9. 物理保护协调器/网关
[ ] 10. 监控异常设备加入
[ ] 11. 启用安全日志记录
[ ] 12. 定期安全审计
```

### 8.2 密钥管理建议

#### 8.2.1 密钥生成

- 使用密码学安全的随机数生成器（CSPRNG）
- 密钥长度：128位（AES-128要求）
- 避免使用可预测的密钥（如厂商名、产品名）
- 每个设备/网络使用唯一密钥

#### 8.2.2 密钥存储

- 密钥应存储在安全的硬件存储中（如Secure Element）
- 避免将密钥明文存储在固件中
- 使用密钥派生函数（KDF）从主密钥派生工作密钥
- 限制密钥的访问权限

#### 8.2.3 密钥更新

- 建立密钥更新机制
- 网络密钥应定期轮换
- 密钥更新过程本身需要安全保护
- 支持密钥回滚（以防更新失败）

#### 8.2.4 密钥泄露响应

- 制定密钥泄露应急响应计划
- 发现泄露后立即更换密钥
- 审计日志确定泄露影响范围
- 检查是否有恶意设备已加入网络

### 8.3 设备选型安全考虑

#### 8.3.1 安全功能评估

选购Zigbee设备时应考察以下安全特性：

| 安全特性 | 要求 | 重要性 |
|----------|------|--------|
| 唯一TC链接密钥 | 必须 | 高 |
| 安装代码支持 | 必须 | 高 |
| APS加密支持 | 推荐 | 中 |
| 帧计数器检查 | 必须 | 高 |
| 安全OTA升级 | 推荐 | 中 |
| 安全启动 | 推荐 | 中 |
| 防篡改保护 | 可选 | 低 |
| 安全认证（如Zigbee 3.0） | 推荐 | 中 |

#### 8.3.2 厂商安全评估

- 查看厂商是否有安全公告机制
- 历史上是否有未修复的安全漏洞
- 是否提供定期固件更新
- 是否有漏洞披露政策
- 是否通过第三方安全认证

#### 8.3.3 避免高危设备

尽量避免使用以下设备：
- 不支持任何加密的设备
- 使用固定默认密钥且无法更改的设备
- 上市多年从未更新固件的设备
- 不知名小厂商生产的廉价设备
- 不支持Zigbee 3.0的老旧设备

### 8.4 网络隔离与监控

#### 8.4.1 网络隔离架构

```
互联网
   │
   ├── 防火墙/路由器
   │    │
   │    ├── [主网络VLAN] 电脑、手机、NAS
   │    │
   │    └── [IoT网络VLAN] 智能家居设备
   │         │
   │         └── Zigbee网关
   │              │
   │              └── Zigbee设备（灯泡、传感器、门锁等）
   │
   └── [访客网络] 访客设备
```

**隔离要点**：
- Zigbee网关放在IoT VLAN中
- IoT VLAN无法访问主网络
- 仅开放必要的端口和服务
- 云端通信走代理，可监控和审计

#### 8.4.2 安全监控

**监控内容**：
1. **异常设备加入**：监控新设备加入事件
2. **异常流量模式**：突然增加的数据包、异常命令
3. **密钥更新失败**：可能表示攻击尝试
4. **设备离线/异常**：可能受到物理攻击或干扰

**监控工具**：
- Zigbee网关日志
- 网络管理平台
- 专用的IoT安全监控系统
- IDS/IPS（针对Zigbee网关的IP流量）

#### 8.4.3 入侵检测

Zigbee入侵检测的挑战：
- 无线介质，攻击难以溯源
- 设备资源有限，无法安装代理
- 协议解析复杂

**检测方法**：
- 异常流量分析（基于基线）
- 重放攻击检测（帧计数器异常）
- 设备指纹验证
- 信标帧异常检测
- 加入请求频率监控

### 8.5 固件安全更新

#### 8.5.1 OTA更新安全

Zigbee OTA更新集群（0x0019）安全要求：

1. **固件签名验证**
   - 固件必须经过厂商数字签名
   - 设备只接受签名正确的固件
   - 使用非对称加密（如ECC）

2. **固件加密**
   - 传输过程加密保护
   - 防止固件泄露和逆向

3. **版本检查**
   - 禁止降级到旧版本（防回滚攻击）
   - 检查版本号的合法性

4. **更新过程完整性**
   - 校验固件完整性（CRC/哈希）
   - 断电恢复机制
   - 备份旧固件（双分区设计）

#### 8.5.2 固件安全最佳实践

**厂商侧**：
- 使用安全启动（Secure Boot）
- 固件加密存储
- 启用硬件安全模块（如可用）
- 定期发布安全更新
- 建立漏洞响应机制

**用户侧**：
- 及时更新设备固件
- 从官方渠道获取固件
- 验证固件来源和完整性
- 关注厂商安全公告
