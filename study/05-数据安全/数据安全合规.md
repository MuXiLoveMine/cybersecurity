# 数据安全合规

> 本文档详细介绍数据安全相关的法律法规和合规要求，包括《数据安全法》《个人信息保护法》、GDPR、等保 2.0、数据出境等内容，配合实际案例和合规检查清单。

---

## 一、《数据安全法》要点

### 1.1 立法背景与意义

**立法过程**：
- 2018 年 9 月：列入立法规划
- 2020 年 6 月：一审
- 2021 年 4 月：二审
- 2021 年 6 月 10 日：三审通过
- 2021 年 9 月 1 日：正式施行

**重要意义**：
- 我国第一部数据安全领域的基础性法律
- 确立了数据安全的基本制度框架
- 为数据安全监管提供了法律依据
- 促进数据开发利用和数字经济发展

### 1.2 核心概念

#### 1.2.1 数据与数据安全

**数据**：是指任何以电子或者其他方式对信息的记录。

**数据安全**：是指通过采取必要措施，确保数据处于有效保护和合法利用的状态，以及具备保障持续安全状态的能力。

#### 1.2.2 数据分级分类

| 级别 | 定义 |
|------|------|
| **核心数据** | 关系国家安全、国民经济命脉、重要民生、重大公共利益等的数据 |
| **重要数据** | 一旦遭到篡改、破坏、泄露或者非法获取、非法利用，可能危害国家安全、公共利益的数据 |
| **一般数据** | 除核心数据、重要数据以外的其他数据 |

**重要数据目录**：
- 国家网信部门会同国务院有关部门制定国家重要数据目录
- 各地区、各部门按照规定确定本地区、本部门以及相关行业、领域的重要数据具体目录

### 1.3 数据安全制度

#### 1.3.1 数据分类分级保护制度

- 国家建立数据分类分级保护制度
- 根据数据在经济社会发展中的重要程度
- 根据遭到篡改、破坏、泄露或者非法获取、非法利用后对国家安全、公共利益或者个人、组织合法权益造成的危害程度
- 对数据实行分类分级保护

#### 1.3.2 数据安全审查制度

- 国家建立数据安全审查制度
- 对影响或者可能影响国家安全的数据处理活动进行国家安全审查
- 依法作出的安全审查决定为最终决定

**审查情形**：
- 数据处理活动影响或者可能影响国家安全的
- 关键信息基础设施运营者采购的网络产品和服务
- 其他可能影响国家安全的数据处理活动

#### 1.3.3 数据安全风险评估制度

- 开展数据处理活动应当定期开展风险评估
- 风险评估应当包括数据处理活动的合法性、正当性、必要性
- 数据安全保护措施的有效性
- 数据安全风险及应对措施
- 风险评估报告应当包括上述内容

#### 1.3.4 数据安全应急处置制度

- 国家建立数据安全应急处置机制
- 发生数据安全事件，应当依法启动应急预案
- 采取相应的应急处置措施
- 向有关主管部门报告

#### 1.3.5 数据交易管理制度

- 国家建立数据交易管理制度
- 规范数据交易行为
- 培育数据交易市场
- 从事数据交易中介服务的机构应当遵守相关规定

### 1.4 各主体的义务

#### 1.4.1 一般数据处理者的义务

| 义务 | 说明 | 法条 |
|------|------|------|
| 合法合规 | 开展数据处理活动应当遵守法律、法规，尊重社会公德和伦理 | 第 8 条 |
| 安全保护 | 建立健全全流程数据安全管理制度 | 第 27 条 |
| 风险监测 | 开展数据处理活动应当加强风险监测 | 第 29 条 |
| 应急处置 | 发生数据安全事件时，立即采取处置措施 | 第 29 条 |
| 配合调查 | 公安机关、国家安全机关依法调取数据时应当配合 | 第 35 条 |

#### 1.4.2 重要数据处理者的义务

重要数据处理者除履行一般义务外，还应当：

| 额外义务 | 说明 |
|----------|------|
| 明确负责人 | 明确数据安全负责人和管理机构 |
| 定期培训 | 对从业人员进行数据安全教育和培训 |
| 风险评估 | 定期开展风险评估并报送评估报告 |
| 数据出境 | 重要数据出境需进行安全评估 |

#### 1.4.3 关键信息基础设施运营者的义务

- 关键信息基础设施运营者在中华人民共和国境内运营中收集和产生的重要数据的出境安全管理，适用《网络安全法》的规定
- 其他数据处理者的重要数据出境安全管理办法，由国家网信部门会同国务院有关部门制定

### 1.5 法律责任

#### 1.5.1 行政处罚

| 违法行为 | 处罚措施 |
|----------|----------|
| 不履行数据安全保护义务 | 责令改正，给予警告，可并处 1 万-10 万罚款 |
| 情节严重的 | 10 万-100 万罚款，责令暂停相关业务、停业整顿、吊销相关业务许可证 |
| 数据交易中介服务违法 | 责令改正，没收违法所得，处违法所得 1-10 倍罚款 |
| 拒不配合数据调取 | 责令改正，给予警告，并处 5 万-50 万罚款 |
| 违反国家核心数据管理制度 | 200 万-1000 万罚款，责令暂停相关业务、停业整顿、吊销相关业务许可证 |

#### 1.5.2 民事责任

- 因数据处理活动给他人造成损害的，依法承担民事责任
- 数据处理者能够证明自己没有过错的，可以减轻或者免除责任

#### 1.5.3 刑事责任

- 违反国家有关规定，向他人出售或者提供公民个人信息，情节严重的
- 窃取或者以其他方法非法获取公民个人信息的
- 构成犯罪的，依法追究刑事责任（参考《刑法》第 253 条之一）

### 1.6 实际案例

**案例：某企业违反《数据安全法》被处罚**

**案情简介**：
- 某科技公司开发运营一款社交 APP
- 收集了大量用户个人信息
- 未建立数据安全管理制度
- 未开展数据安全风险评估
- 发生数据泄露事件后未及时上报

**处罚结果**：
- 责令限期改正
- 警告处罚
- 罚款 50 万元
- 对直接负责的主管人员罚款 5 万元

**整改措施**：
1. 建立数据安全管理制度
2. 设立数据安全管理部门
3. 开展数据分类分级
4. 定期进行风险评估
5. 建立数据安全事件应急响应机制
6. 加强人员数据安全培训

## 二、《个人信息保护法》要点

### 2.1 立法背景与意义

**立法过程**：
- 2018 年：启动立法工作
- 2020 年 10 月：一审
- 2021 年 4 月：二审
- 2021 年 8 月 20 日：三审通过
- 2021 年 11 月 1 日：正式施行

**重要意义**：
- 我国第一部个人信息保护领域的专门法律
- 全面规范个人信息处理活动
- 强化个人信息权益保护
- 促进个人信息合理利用

### 2.2 核心概念

#### 2.2.1 个人信息

**定义**：个人信息是以电子或者其他方式记录的与已识别或者可识别的自然人有关的各种信息，不包括匿名化处理后的信息。

**判断标准**：
- 已识别：能够直接确定特定自然人
- 可识别：通过一定方式可以关联到特定自然人
- 关联：与特定自然人有关

#### 2.2.2 敏感个人信息

**定义**：敏感个人信息是一旦泄露或者非法使用，容易导致自然人的人格尊严受到侵害或者人身、财产安全受到危害的个人信息。

**范围**：
- 生物识别信息（人脸、指纹、声纹等）
- 宗教信仰
- 特定身份
- 医疗健康
- 金融账户
- 行踪轨迹
- 不满十四周岁未成年人的个人信息

**处理规则**：
- 只有在具有特定的目的和充分的必要性时，方可处理
- 应当取得个人的单独同意
- 应当向个人告知处理的必要性以及对个人权益的影响

#### 2.2.3 个人信息处理

**处理的范围**：
- 收集、存储、使用、加工、传输、提供、公开、删除等

### 2.3 个人信息处理原则

| 原则 | 说明 |
|------|------|
| **合法、正当、必要原则** | 处理个人信息应当具有明确、合理的目的，不得过度处理 |
| **目的明确原则** | 处理目的应当明确、具体，不得超出约定目的 |
| **最小必要原则** | 应当限于实现处理目的的最小范围 |
| **公开透明原则** | 公开个人信息处理规则，明示处理的目的、方式、范围 |
| **质量保障原则** | 保证个人信息的质量，避免对个人权益造成不利影响 |
| **安全保障原则** | 采取必要措施保障个人信息安全 |
| **主体参与原则** | 个人有权参与个人信息处理，行使各项权利 |

### 2.4 个人信息处理规则

#### 2.4.1 处理的合法性基础

处理个人信息的合法性基础（取得同意以外的情形）：

1. 取得个人的同意
2. 为订立、履行个人作为一方当事人的合同所必需
3. 为履行法定职责或者法定义务所必需
4. 为应对突发公共卫生事件所必需
5. 为公共利益实施新闻报道、舆论监督等行为
6. 依照本法规定在合理的范围内处理个人自行公开或者其他已经合法公开的个人信息

#### 2.4.2 告知同意规则

**告知要求**：
- 处理前应当以显著方式、清晰易懂的语言告知
- 告知内容应当真实、准确、完整
- 应当包括：处理者名称和联系方式、处理目的、处理方式、处理信息种类、个人权利行使方式等

**同意要求**：
- 应当在充分知情的前提下自愿、明确作出
- 应当与处理目的直接相关
- 个人有权撤回同意
- 撤回同意不影响撤回前基于同意已进行的处理活动

**单独同意的情形**：
- 处理敏感个人信息
- 向第三方提供个人信息
- 公开个人信息
- 向境外提供个人信息
- 将公共场合收集的人脸信息用于维护公共安全以外的目的

### 2.5 个人信息主体的权利

| 权利 | 说明 |
|------|------|
| **知情权** | 有权了解个人信息处理情况 |
| **决定权** | 有权决定是否同意处理其个人信息 |
| **查阅权** | 有权向个人信息处理者查阅、复制其个人信息 |
| **复制权** | 有权请求复制其个人信息 |
| **更正权** | 发现其个人信息不准确或者不完整的，有权请求更正、补充 |
| **删除权** | 在法定情形下有权请求删除其个人信息 |
| **可携带权** | 有权请求将个人信息转移至其指定的个人信息处理者 |
| **撤回同意权** | 有权撤回对个人信息处理的同意 |
| **解释说明权** | 有权要求个人信息处理者对其个人信息处理规则进行解释说明 |
| **死者权益保护** | 自然人死亡后，其近亲属可为自身合法、正当利益行使相关权利 |

### 2.6 个人信息处理者的义务

#### 2.6.1 一般义务

```
┌─────────────────────────────────────────────────┐
│             个人信息处理者义务                    │
├─────────────────────────────────────────────────┤
│                                                 │
│  1. 制定内部管理制度和操作规程                   │
│  2. 对个人信息实行分类管理                       │
│  3. 采取相应的加密、去标识化等安全技术措施       │
│  4. 合理确定个人信息处理的操作权限               │
│  5. 定期对从业人员进行安全教育和培训             │
│  6. 制定并组织实施个人信息安全事件应急预案       │
│  7. 法律、行政法规规定的其他措施                 │
│                                                 │
└─────────────────────────────────────────────────┘
```

#### 2.6.2 特殊义务

**处理敏感个人信息**：
- 具有特定的目的和充分的必要性
- 取得个人单独同意
- 告知必要性及对个人权益的影响
- 采取更严格的安全保护措施

**自动化决策**：
- 应当保证决策的透明度和结果公平、公正
- 不得对个人在交易价格等交易条件上实行不合理的差别待遇
- 向个人进行信息推送、商业营销，应当同时提供不针对其个人特征的选项
- 个人有权要求予以说明，有权拒绝仅通过自动化决策的方式作出决定

**公共场所安装图像采集、个人身份识别设备**：
- 应当为维护公共安全所必需
- 应当遵守国家有关规定
- 应当设置显著的提示标识
- 所收集的个人图像、身份识别信息只能用于维护公共安全的目的

#### 2.6.3 大型平台义务

提供重要互联网平台服务、用户数量巨大、业务类型复杂的个人信息处理者，还应当履行：

1. 按照国家规定建立健全个人信息保护合规制度体系
2. 成立主要由外部成员组成的独立机构，对个人信息保护情况进行监督
3. 遵循公开、公平、公正的原则，制定平台规则
4. 对严重违法的平台内产品或者服务提供者，停止提供服务
5. 定期发布个人信息保护社会责任报告，接受社会监督

### 2.7 个人信息跨境提供

#### 2.7.1 跨境提供的条件

个人信息处理者向境外提供个人信息，应当具备以下条件之一：

1. 通过国家网信部门组织的安全评估
2. 按照国家网信部门的规定经专业机构进行个人信息保护认证
3. 按照国家网信部门制定的标准合同与境外接收方订立合同
4. 法律、行政法规或者国家网信部门规定的其他条件

#### 2.7.2 个人信息出境安全评估

**评估情形**：
- 关键信息基础设施运营者和处理个人信息达到国家网信部门规定数量的个人信息处理者
- 向境外提供重要数据
- 累计向境外提供 10 万人个人信息或者 1 万人敏感个人信息
- 国家网信部门规定的其他情形

#### 2.7.3 境外接收方的义务

- 境外接收方应当按照约定的个人信息保护标准处理个人信息
- 个人信息处理者应当对境外接收方的处理活动进行监督
- 境外接收方处理个人信息的活动不得低于我国规定的个人信息保护标准

### 2.8 法律责任

#### 2.8.1 行政处罚

| 违法行为 | 处罚 |
|----------|------|
| 一般违法 | 责令改正，给予警告，没收违法所得 |
| 拒不改正 | 100 万元以下罚款 |
| 情节严重 | 5000 万元以下或者上一年度营业额 5% 以下罚款 |
|  | 责令暂停相关业务或者停业整顿 |
|  | 通报有关主管部门吊销相关业务许可或者吊销营业执照 |
| 直接负责的主管人员 | 10 万-100 万元罚款 |
|  | 可以决定禁止其在一定期限内担任相关企业的董事、监事、高级管理人员和个人信息保护负责人 |

#### 2.8.2 民事责任

- 个人信息权益造成损害的，个人信息处理者不能证明自己没有过错的，应当承担损害赔偿等侵权责任
- 损害赔偿责任按照个人因此受到的损失或者个人信息处理者因此获得的利益确定
- 难以确定的，由人民法院根据实际情况确定赔偿数额
- 可以依法提起公益诉讼

#### 2.8.3 刑事责任

- 违反国家有关规定，向他人出售或者提供公民个人信息
- 窃取或者以其他方法非法获取公民个人信息
- 情节严重的，处三年以下有期徒刑或者拘役，并处或者单处罚金
- 情节特别严重的，处三年以上七年以下有期徒刑，并处罚金

### 2.9 典型案例

**案例 1：某 APP 过度收集个人信息被下架**

**违法事实**：
- 某天气 APP 收集位置信息、通讯录、短信、通话记录等与天气服务无关的个人信息
- 未明确告知收集目的
- 用户不同意就无法使用

**处罚结果**：
- 责令整改
- 通报批评
- 下架处理
- 罚款 50 万元

**案例 2：某平台大数据杀熟被处罚**

**违法事实**：
- 同一商品，老用户看到的价格比新用户高
- 利用用户个人信息进行不合理的差别待遇
- 违反自动化决策公平公正原则

**处罚结果**：
- 责令改正
- 罚款 200 万元
- 公开通报

## 三、GDPR 简介

### 3.1 GDPR 概述

**GDPR（General Data Protection Regulation）通用数据保护条例**：
- 欧盟议会于 2016 年 4 月 27 日通过
- 2018 年 5 月 25 日正式生效
- 取代了 1995 年的《数据保护指令》
- 是目前全球最严格的数据保护法规之一

**适用范围**：
- 设立在欧盟境内的数据控制者/处理者
- 设立在欧盟境外，但向欧盟境内的数据主体提供商品或服务
- 设立在欧盟境外，但监控欧盟境内数据主体的行为

### 3.2 核心原则

GDPR 规定了六项数据处理原则：

| 原则 | 说明 |
|------|------|
| **合法、正当、透明** | 数据处理应当合法、正当、透明 |
| **目的限制** | 收集目的应当具体、明确、合法 |
| **数据最小化** | 只收集实现目的所必需的最少数据 |
| **准确性** | 保持数据准确，及时更新 |
| **存储限制** | 数据保存期限不超过实现目的所必需的时间 |
| **完整性与保密性** | 采取适当的安全措施保护数据 |

### 3.3 数据主体权利

GDPR 赋予数据主体广泛的权利：

| 权利 | 说明 |
|------|------|
| **知情权** | 有权知道数据处理的相关信息 |
| **访问权** | 有权访问其个人数据 |
| **更正权** | 有权要求更正不准确的数据 |
| **删除权（被遗忘权）** | 有权要求删除其个人数据 |
| **限制处理权** | 有权限制对其数据的处理 |
| **数据可携带权** | 有权获取其数据并传输给其他控制者 |
| **反对权** | 有权反对基于合法利益或直接营销的数据处理 |
| **自动化决策权** | 有权不受仅基于自动化处理的决定约束 |

### 3.4 数据控制者和处理者的义务

| 义务 | 说明 |
|------|------|
| **数据保护影响评估（DPIA）** | 高风险处理活动必须进行 DPIA |
| **数据保护官（DPO）** | 特定情况下必须指定 DPO |
| **数据泄露通知** | 数据泄露后 72 小时内通知监管机构 |
| **记录保存** | 保存数据处理活动的记录 |
| **默认数据保护** | 产品和服务设计阶段就考虑数据保护 |
| **数据保护设计** | 技术设计中融入数据保护 |

### 3.5 法律责任

**行政罚款**：
- **两档罚款制度**：
  - 第一档：最高 1000 万欧元或全球年营业额的 2%（以较高者为准）
  - 第二档：最高 2000 万欧元或全球年营业额的 4%（以较高者为准）

**适用第二档的违法情形**：
- 违反数据处理基本原则
- 违反数据主体权利
- 违反数据跨境传输规定
- 不配合监管机构

### 3.6 中欧个人信息保护对比

| 对比项 | 中国《个人信息保护法》 | 欧盟 GDPR |
|--------|------------------------|-----------|
| 立法模式 | 专门立法 | 条例（直接适用） |
| 适用范围 | 属地+属人 | 属地+效果原则 |
| 合法性基础 | 7 种，同意为主要基础 | 6 种，同意与合同等并列 |
| 敏感个人信息 | 列举+概括 | 特殊类别数据 |
| 数据泄露通知 | 及时通知（无明确时限） | 72 小时内 |
| 最高罚款 | 5000 万或年营业额 5% | 2000 万欧元或年营业额 4% |
| 公益诉讼 | 有 | 有 |
| 数据可携带权 | 有 | 有 |
| 被遗忘权 | 删除权（类似） | 明确规定 |

### 3.7 GDPR 典型案例

**案例：Google 被罚款 5000 万欧元**

- **时间**：2019 年 1 月
- **处罚机构**：法国国家数据保护委员会（CNIL）
- **原因**：
  1. 透明度不足：关于数据处理的信息分散在多个文档中
  2. 同意不有效：用户设置广告个性化的同意不够明确、具体
- **罚款金额**：5000 万欧元

**案例：Amazon 被罚款 7.46 亿欧元**

- **时间**：2021 年 7 月
- **处罚机构**：卢森堡数据保护局
- **原因**：违反 GDPR 关于个人数据处理的规定
- **罚款金额**：7.46 亿欧元（约 8.88 亿美元）

## 四、等保 2.0 数据安全要求

### 4.1 等保 2.0 概述

**网络安全等级保护制度 2.0**（简称等保 2.0）：
- 2019 年 5 月发布
- 2019 年 12 月 1 日正式实施
- 取代 2008 年发布的等保 1.0 标准

**主要变化**：
- 保护对象从网络和信息系统扩展到云、大数据、物联网、工业控制、移动互联等
- 从被动防御转变为主动防御、动态防御、整体防控、精准防护
- 从合规驱动转变为安全能力提升
- 增加了云计算、移动互联、物联网、工业控制系统安全扩展要求

### 4.2 等级划分

| 等级 | 名称 | 说明 |
|------|------|------|
| **第一级** | 自主保护级 | 一般信息系统，受到破坏后对公民、法人和其他组织的合法权益造成损害，但不损害国家安全、社会秩序和公共利益 |
| **第二级** | 指导保护级 | 信息系统受到破坏后，会对公民、法人和其他组织的合法权益产生严重损害，或者对社会秩序和公共利益造成损害，但不损害国家安全 |
| **第三级** | 监督保护级 | 信息系统受到破坏后，会对社会秩序和公共利益造成严重损害，或者对国家安全造成损害 |
| **第四级** | 强制保护级 | 信息系统受到破坏后，会对社会秩序和公共利益造成特别严重损害，或者对国家安全造成严重损害 |
| **第五级** | 专控保护级 | 信息系统受到破坏后，会对国家安全造成特别严重损害 |

### 4.3 数据安全相关要求

等保 2.0 标准中涉及数据安全的要求主要在"安全计算环境"中。

#### 4.3.1 数据保密性

**三级系统要求**：

1. **身份鉴别数据保密性**
   - 身份鉴别信息应具有不易被冒用的特点
   - 口令应有复杂度要求并定期更换
   - 应采用口令、密码技术、生物技术等两种或两种以上组合的鉴别技术

2. **重要数据保密性**
   - 应采用加密技术对重要信息传输过程进行保护
   - 应采用加密或其他保护措施实现系统管理数据、鉴别信息和重要业务数据存储保密性

3. **密码技术要求**
   - 应使用国家密码管理主管部门认证核准的密码技术和产品

#### 4.3.2 数据完整性

**三级系统要求**：

1. **传输完整性**
   - 应采用校验技术或密码技术保证重要数据在传输过程中的完整性

2. **存储完整性**
   - 应采用校验技术或密码技术保证重要数据在存储过程中的完整性

3. **检测与恢复**
   - 在检测到完整性受到破坏后，应能够采取必要的恢复措施

#### 4.3.3 数据备份与恢复

**三级系统要求**：

1. **本地数据备份**
   - 应提供重要数据的本地数据备份与恢复功能
   - 应提供异地数据备份功能

2. **备份策略**
   - 应提供备份策略配置功能
   - 备份策略应包括备份频率、备份方式、备份内容等

3. **系统备份**
   - 应提供系统的热备份
   - 应提供关键网络设备、安全设备、通信线路的冗余

4. **灾难恢复**
   - 应提供灾难恢复应急预案
   - 应定期进行灾难恢复演练

#### 4.3.4 数据安全扩展要求（大数据）

对于大数据应用，还有额外的扩展要求：

1. **数据采集安全**
   - 应明确数据采集的目的、用途和方式
   - 应保证数据采集的真实性和完整性
   - 涉及个人信息的，应获得个人信息主体的同意

2. **数据存储安全**
   - 应对数据进行分类分级管理
   - 应采用加密等技术对敏感数据进行存储保护
   - 应建立数据备份和恢复机制

3. **数据处理安全**
   - 应防止数据在处理过程中被泄露、篡改和滥用
   - 应对数据处理操作进行审计
   - 涉及个人信息的，应进行去标识化处理

4. **数据交换安全**
   - 应建立数据交换审批流程
   - 应对数据交换进行审计
   - 应采用加密技术保护数据交换过程

### 4.4 等保测评中常见的数据安全问题

| 问题类型 | 具体表现 | 整改建议 |
|----------|----------|----------|
| 身份鉴别 | 密码复杂度不够、定期更换未执行 | 启用强密码策略、设置定期更换 |
| 传输加密 | 管理后台使用 HTTP 而非 HTTPS | 全站启用 HTTPS |
| 存储加密 | 敏感数据明文存储 | 数据库加密或字段加密 |
| 数据备份 | 备份不完整、未异地备份 | 完善备份策略、异地备份 |
| 日志审计 | 审计日志不全、保留时间不足 | 完善审计、日志保留 6 个月以上 |
| 数据分类 | 未做数据分类分级 | 建立数据分类分级制度 |

## 五、数据出境安全评估

### 5.1 数据出境概述

**数据出境**：是指数据处理者将在境内运营中收集和产生的数据传输、存储至境外。

**数据出境的主要方式**：
1. 通过网络直接向境外传输数据
2. 将数据存储在境外服务器
3. 向境外机构、组织、个人提供数据
4. 境外人员远程访问境内数据

### 5.2 数据出境安全评估制度

#### 5.2.1 评估依据

- 《网络安全法》
- 《数据安全法》
- 《个人信息保护法》
- 《数据出境安全评估办法》（2022 年 9 月 1 日施行）

#### 5.2.2 需要申报安全评估的情形

数据处理者向境外提供数据，有下列情形之一的，应当通过所在地省级网信部门向国家网信部门申报数据出境安全评估：

1. **重要数据出境**
   - 数据处理者向境外提供重要数据

2. **关键信息基础设施运营者**
   - 关键信息基础设施运营者和处理 100 万人以上个人信息的数据处理者向境外提供个人信息

3. **大量个人信息出境**
   - 自上年 1 月 1 日起累计向境外提供 10 万人个人信息或者 1 万人敏感个人信息的数据处理者向境外提供个人信息

4. **其他情形**
   - 国家网信部门规定的其他需要申报数据出境安全评估的情形

### 5.3 数据出境安全评估流程

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  数据处理者  │ →  │  省级网信部门 │ →  │  国家网信部门 │
│  申报材料    │    │  材料完备性  │    │  安全评估    │
│             │    │  审查（5日） │    │ （7个工作日）│
└─────────────┘    └─────────────┘    └──────┬──────┘
                                              │
                                    ┌─────────▼─────────┐
                                    │ 评估结果（45工作日） │
                                    └─────────┬─────────┘
                                              │
                                ┌─────────────┴─────────────┐
                                ▼                           ▼
                          通过评估                    未通过评估
                        （有效期2年）              （说明理由，可重新申报）
```

### 5.4 安全评估重点内容

数据出境安全评估重点评估数据出境活动可能对国家安全、公共利益、个人或者组织合法权益带来的风险，主要包括：

1. **合法性**
   - 数据出境和境外接收方处理数据的目的、范围、方式等的合法性、正当性、必要性

2. **数据规模与敏感度**
   - 出境数据的规模、范围、种类、敏感程度
   - 数据出境可能对国家安全、公共利益、个人或者组织合法权益带来的风险

3. **境外接收方的数据安全能力**
   - 境外接收方承诺承担的责任义务
   - 履行责任义务的管理和技术措施、能力等能否保障出境数据的安全

4. **数据泄露风险**
   - 数据在出境中和出境后遭到篡改、破坏、泄露、丢失、转移或者被非法获取、非法利用等的风险
   - 个人信息权益保护的途径是否通畅

5. **数据安全义务**
   - 与境外接收方拟订立的数据出境相关合同或者其他具有法律效力的文件等是否充分约定了数据安全保护责任和义务

6. **其他**
   - 其他可能影响数据出境安全的事项

### 5.5 申报材料

申报数据出境安全评估，应当提交以下材料：

1. 数据出境安全评估申报书
2. 数据出境风险自评估报告
3. 数据处理者与境外接收方拟订立的法律文件
4. 其他需要说明的材料

### 5.6 其他数据出境合法路径

除安全评估外，还有其他合法的个人信息出境路径：

| 路径 | 适用场景 | 依据 |
|------|----------|------|
| **安全评估** | 重要数据、大量个人信息出境 | 《数据出境安全评估办法》 |
| **个人信息保护认证** | 一般个人信息出境，数量未达评估标准 | 《个人信息保护法》第 38 条 |
| **标准合同** | 一般个人信息出境，数量未达评估标准 | 《个人信息出境标准合同办法》 |
| **其他** | 法律、行政法规或者国家网信部门规定的其他条件 |  |

**标准合同（SCC）**：
- 个人信息处理者与境外接收方签订国家网信部门制定的标准合同
- 向所在地省级网信部门备案
- 适用于非关键信息基础设施运营者、处理个人信息不满 100 万人、累计出境不满 10 万人的情形

### 5.7 典型案例

**案例：某车企数据出境评估**

**背景**：
- 某新能源汽车企业在中国生产销售汽车
- 车辆采集大量驾驶数据、位置数据、用户数据
- 总部在境外，需要向境外传输数据用于研发

**评估过程**：

1. **数据梳理**
   - 梳理出境数据清单
   - 进行数据分类分级
   - 识别重要数据和敏感个人信息

2. **风险自评估**
   - 评估出境数据的敏感程度
   - 评估境外接收方的安全能力
   - 评估数据泄露的风险和影响
   - 形成自评估报告

3. **材料准备**
   - 准备申报书
   - 准备自评估报告
   - 准备数据出境合同（明确双方责任）

4. **申报与整改**
   - 通过省级网信部门提交材料
   - 根据反馈意见补充材料
   - 落实整改要求

5. **通过评估**
   - 获得通过评估的书面通知
   - 按评估结果开展数据出境活动
   - 有效期内持续合规

### 6.3 合规整改优先级建议

**高优先级（立即整改）**：
- 未取得用户同意收集个人信息
- 过度收集个人信息
- 敏感数据明文存储
- 无数据备份机制
- 重大安全漏洞

**中优先级（限期整改）**：
- 数据分类分级未完成
- 缺少安全审计
- 权限管理不规范
- 应急预案不完善
- 安全培训不足

**低优先级（持续改进）**：
- 制度文件不够完善
- 技术防护可以加强
- 运营流程可以优化

## 七、合规建设实践

### 7.1 合规建设步骤

```
第一阶段：现状评估（2-4 周）
├── 数据资产盘点
├── 数据流向梳理
├── 合规差距分析
├── 风险评估
└── 整改优先级排序

第二阶段：体系建设（2-3 个月）
├── 组织架构完善
├── 管理制度建设
├── 数据分类分级
├── 技术工具部署
└── 人员培训

第三阶段：落地实施（3-6 个月）
├── 技术措施落地
├── 流程制度执行
├── 重点场景整改
└── 试点验证

第四阶段：持续运营（持续）
├── 日常监控运营
├── 定期审计评估
├── 持续优化改进
└── 应对监管变化
```

### 7.2 合规建设常见误区

| 误区 | 说明 | 正确认识 |
|------|------|----------|
| 合规=花钱 | 认为合规就是投入，没有产出 | 合规是风险控制，避免更大损失 |
| 技术万能 | 认为买了安全产品就合规了 | 技术只是手段，管理和流程更重要 |
| 应付检查 | 只为通过检查，不真正落地 | 合规是为了提升安全能力 |
| 一步到位 | 想一次做完所有合规工作 | 合规是持续的过程，循序渐进 |
| 法务部门的事 | 认为合规只是法务部门的事 | 合规是全员的事，业务部门是主体 |

### 7.3 合规建设建议

1. **高层重视**：获得高层支持是合规建设成功的关键
2. **业务参与**：业务部门是数据安全的责任主体
3. **循序渐进**：先易后难，先重点后一般
4. **技术+管理**：技术和管理双轮驱动
5. **持续改进**：合规建设是持续的过程，不是一次性项目
6. **专业支持**：必要时寻求专业机构的支持
