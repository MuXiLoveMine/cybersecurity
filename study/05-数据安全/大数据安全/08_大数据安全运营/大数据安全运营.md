# 大数据安全运营

### 8.1 大数据平台安全监控

监控对象覆盖"用户行为、平台组件、网络、数据访问"四维度。

**用户行为监控：**
- 异常登录（新 IP、非工作时间、频繁失败）
- 异常查询（大批量拉取敏感表、跨业务线查询）
- 权限变更（敏感授权操作）

**组件健康监控：**
- KDC 可用性、票据续期成功率
- Ranger Admin 可用性、策略下发延迟
- 各组件审计日志是否正常输出

**数据访问监控：**
- 敏感表访问 TOP 用户
- 全表扫描告警（少量用例才需全表）
- 数据导出操作（hive 导出文件、kafka 消费者拉取量）

```bash
# 监控Kerberos认证失败率
grep "PREAUTH_FAILED" /var/log/kadmind.log | wc -l

# 监控Ranger策略变更
grep "POLICY_UPDATE" /var/log/ranger/audit.log

# 监控全表扫描(Hive审计)
grep "SELECT \*" /var/log/hive/hive-audit.log | awk '{print $user}' | sort | uniq -c
```

### 8.2 安全事件响应流程

大数据平台安全事件响应典型流程：

```
1. 发现: 监控告警/审计异常/外部通报
   ↓
2. 遏制: 冻结账号(kadmin)、阻断IP(防火墙)、隔离节点
   ↓
3. 取证: 拉取审计日志、Ranger审计、KDC日志、网络流量
   ↓
4. 分析: 还原操作链路、定损(影响范围、泄露数据量)
   ↓
5. 处置: 撤销非法授权、修复漏洞、加固配置
   ↓
6. 报告: 形成事件报告, 按合规要求上报(72小时GDPR)
   ↓
7. 改进: 复盘、补充监控规则、更新SOP
```

关键能力：能快速冻结账号是遏制扩散的第一招，Kerberos 一注销 TGT 失效，比改密码更彻底。

### 8.3 大数据合规要求

**数据安全法（国内）：**
- 建立数据分类分级保护制度
- 重要数据出境需安全评估
- 数据处理者需定期风险评估

**个人信息保护法（PIPL）：**
- 处理个人信息需告知并取得同意
- 敏感个人信息（生物识别、医疗、金融等）需单独同意
- 数据可携带权、删除权

**GDPR（欧盟，跨境适用）：**
- 数据处理需合法性基础
- 数据主体权利：访问、更正、删除、可携带
- 数据泄露 72 小时内上报监管

**合规落地要点：**
1. 数据资产盘点与分类分级（核心、重要、一般）
2. 敏感数据加密与脱敏
3. 访问授权与审计留痕（满足"可追溯"要求）
4. 数据出境评估（跨境传输前必做）
5. 数据生命周期管理（不再需要时安全删除）

### 8.4 大数据安全评估与加固

**评估维度：**

| 维度 | 检查项 |
|------|--------|
| 认证 | 是否启用Kerberos；keytab权限；弱密码 |
| 授权 | Ranger策略覆盖；最小权限；默认拒绝 |
| 加密 | 传输加密；存储加密；密钥管理 |
| 审计 | 审计日志完整性；集中存储；防篡改 |
| 隔离 | 多租户隔离；网络分区；命名空间 |
| 漏洞 | 组件版本CVE；依赖漏洞；未授权接口 |
| 运维 | 暴力破解防护；变更管控；备份恢复 |

```bash
# 快速自查脚本
# 1. 检查是否启用Kerberos
hdfs getconf -confKey hadoop.security.authentication

# 2. 检查keytab权限
find /etc/security/keytabs -type f ! -perm 600

# 3. 检查HDFS加密区
hdfs crypto -listZones

# 4. 检查Ranger策略覆盖
curl -u admin:pass https://ranger:6182/api/policy

# 5. 检查组件版本CVE
hadoop version
spark-submit --version
```
