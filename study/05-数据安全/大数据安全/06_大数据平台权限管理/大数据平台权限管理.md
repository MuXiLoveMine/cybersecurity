# 大数据平台权限管理

### 5.1 Apache Ranger 架构与部署

Ranger 是 Hadoop 生态最主流的统一权限管理平台。

```
Ranger 架构:

┌────────────────────────────────────────┐
│  Ranger Admin (Web UI + 策略中心)      │
│  ┌──────────┐ ┌──────────┐            │
│  │ 策略存储  │ │ 审计存储  │ (DB)       │
│  └──────────┘ └──────────┘            │
└──────────────┬─────────────────────────┘
               │ 策略下发
   ┌───────────┼───────────┐
   ↓           ↓           ↓
┌──────┐  ┌──────┐    ┌──────┐
│HDFS  │  │ Hive │    │Kafka │  (各组件的Plugin)
│Plugin│  │Plugin│    │Plugin│
└──────┘  └──────┘    └──────┘
   ↓           ↓           ↓
  HDFS       Hive       Kafka (各组件实际执行鉴权)
```

部署步骤：

```bash
# 1. 准备DB
mysql -e "CREATE DATABASE ranger; CREATE USER 'ranger'@'%' IDENTIFIED BY 'pass'; GRANT ALL ON ranger.* TO 'ranger'@'%';"

# 2. 解压并配置
cd ranger-admin
# 修改 install.properties
db_root_password=pass
db_host=localhost
rangerAdmin_password=Ranger123

# 3. 安装
./setup.sh

# 4. 启动
./ranger-admin start

# 5. 安装各组件Plugin (以HDFS为例)
cd hdfs-plugin
# 修改 install.properties 指向Admin
./enable-hdfs-plugin.sh
# 重启NameNode生效
```

### 5.2 Ranger 策略管理

**1. HDFS 策略：** 路径级别权限，可指定用户/组/IP 范围。

**2. Hive 策略：** 库/表/列级别，支持行级过滤（Row Filter）和列脱敏（Masking）。

```json
// Hive 策略示例: 列级授权 + 行级过滤
{
  "policyName": "customer_pii_access",
  "resource": {"database": "sales", "table": "customers", "columns": ["phone","idcard"]},
  "permissions": [
    {"principal": "analyst", "access": ["select"], "masking": "MASK_SHOW_LAST_4"},
    {"principal": "finance_admin", "access": ["select"], "rowFilter": "region='east'"}
  ]
}
```

**3. Kafka 策略：** Topic/Group/Cluster 级，控制 Produce/Consume/Describe。

**4. Spark 策略：** 通过 Ranger Spark Plugin 控制 SQL 查询权限（SparkSQL 接入 Ranger）。

Ranger 的审计中心统一展示所有组件的访问记录，是事后追溯与合规审计的核心。

### 5.3 Apache Sentry（历史参考）

Sentry 是 Cloudera 推出的基于角色的授权（RBAC），曾是 Hadoop 授权主流之一。优势是"基于角色"简化授权管理，劣势是只支持 Hive/Impala，组件覆盖少，社区已不活跃，被 Ranger 取代。了解原理即可，新部署不建议选 Sentry。

### 5.4 统一审计日志管理

大数据平台日志分散（HDFS audit、Hive audit、Kafka authorizer、Ranger audit）。统一审计方案：

```
各组件审计日志 → Filebeat/Flume → Kafka → Logstash → Elasticsearch → Kibana
```

关键能力：
- 统一时间线：把多组件日志按时间关联，还原一次操作的完整链路。
- 实体关联：用"谁访问了哪张表的哪列"做关联分析。
- 异常检测：某用户突然大量查询敏感表 → 告警。
