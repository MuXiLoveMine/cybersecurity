# 通知与合规报告

### 10.1 法规要求

**中国相关法规**

| 法规 | 通知要求 | 时限 |
|------|----------|------|
| 《网络安全法》 | 网络安全事件报告 | 立即报告 |
| 《数据安全法》 | 数据安全事件报告 | 立即报告 |
| 《个人信息保护法》 | 个人信息泄露通知 | 立即通知用户和监管部门 |
| 《关键信息基础设施安全保护条例》 | 重大事件报告 | 立即报告保护工作部门 |
| 等保2.0 | 安全事件报告 | 24小时内报告公安机关 |

**国际法规**

| 法规 | 通知要求 | 时限 |
|------|----------|------|
| GDPR (欧盟) | 数据泄露通知监管机构 | 72小时内 |
| CCPA (加州) | 消费者数据泄露通知 | 无合理延迟 |
| PCI DSS | 支付卡数据泄露通知 | 立即通知收单机构 |
| HIPAA (美国医疗) | PHI泄露通知 | 60天内通知HHS |
| SOX (美国上市公司) | 重大事件报告 | 4个工作日内SEC报告 |

### 10.2 通知流程

```
数据泄露通知决策流程：

1. 确认泄露
   |
2. 评估是否需要通知
   - 是否涉及个人信息？
   - 是否对个人权益造成影响？
   - 是否触发法定通知义务？
   |
   +-- 是 --> 启动通知流程
   |
   +-- 否 --> 记录但不通知

3. 确定通知对象
   - 监管机构 (网信/公安/通信管理)
   - 受影响个人 (用户)
   - 业务合作伙伴
   - 内部管理层

4. 准备通知内容
   - 泄露事件描述
   - 涉及的数据类型
   - 可能的影响
   - 已采取的措施
   - 建议的防护措施
   - 联系方式和咨询渠道

5. 执行通知
   - 监管机构：书面报告
   - 用户：邮件/短信/公告
   - 合作伙伴：协议约定方式
   - 内部：内部通报

6. 后续跟进
   - 回应咨询
   - 补充报告
   - 整改报告
```

### 10.3 报告模板

```
========================================
数据安全事件报告
========================================

报告编号：INC-2026-001
报告时间：2026年9月13日
报告人：张某（CISO）

一、事件概述
   事件类型：[数据泄露/数据篡改/勒索软件]
   事件级别：[一级/二级/三级/四级]
   发现时间：2026年9月12日 14:00
   处置时间：2026年9月12日 14:30
   当前状态：[处置中/已遏制/已恢复]

二、事件描述
   事件经过：
   [详细描述事件的发生和发展过程]

   入侵路径：
   [描述攻击者如何进入系统]

   影响范围：
   受影响系统：[系统名称和数量]
   受影响数据：[数据类型和数量]
   受影响用户：[用户数量]

三、原因分析
   直接原因：[导致事件发生的直接技术原因]
   根本原因：[导致事件发生的根本管理/流程原因]

四、处置措施
   已采取的遏制措施：[列出]
   已采取的根除措施：[列出]
   恢复进展：[描述]

五、影响评估
   数据影响：[数据类型/数量/敏感程度]
   业务影响：[中断时长/经济损失]
   合规影响：[法规义务/法律责任]

六、后续计划
   短期改进：[1个月内]
   中期改进：[3个月内]
   长期改进：[6个月内]

七、附件
   - 事件时间线
   - 取证报告
   - 影响评估报告
   - 整改计划

签名：_______________
日期：_______________
```
