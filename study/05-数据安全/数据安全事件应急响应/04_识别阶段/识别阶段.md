# 识别阶段

### 4.1 事件发现渠道

| 渠道 | 描述 | 响应时间 |
|------|------|----------|
| SIEM告警 | 安全设备和日志聚合分析触发告警 | 最快，自动化 |
| EDR告警 | 端点检测与响应系统告警 | 快，自动化 |
| 用户报告 | 内部员工或外部用户发现异常 | 中等，被动 |
| 第三方通报 | 合作伙伴/安全厂商/监管机构通报 | 慢，被动 |
| 威胁情报 | 对比IOC发现已知威胁 | 快，自动化 |
| 数据泄露监控 | 暗网/公开渠道监控发现数据泄露 | 慢，被动 |
| 安全扫描 | 定期安全扫描发现异常 | 预防性 |

### 4.2 初步评估

**评估检查清单**

```
1. 确认事件真实性
   - 验证告警来源和可信度
   - 排除误报可能性
   - 收集初始证据

2. 确定事件类型
   - 数据泄露 / 数据篡改 / 勒索软件 / 未授权访问
   - 识别攻击手法（TTPs）

3. 评估影响范围
   - 受影响的系统和服务
   - 受影响的数据类型和数量
   - 受影响的用户数量

4. 确定事件级别
   - 参照分级标准
   - 决定响应级别

5. 通知启动
   - 通知事件指挥官
   - 启动响应团队
   - 建立通信渠道
```

### 4.3 事件分级启动

```
一级事件（特别重大）:
  - 立即启动最高级响应
  - CEO/董事会通报
  - 国家网信部门报告
  - 外部安全专家支援

二级事件（重大）:
  - 启动高级响应
  - CISO/CTO通报
  - 省级网信部门报告
  - 考虑外部支援

三级事件（较大）:
  - 启动标准响应
  - 安全总监通报
  - 地市级网信部门报告

四级事件（一般）:
  - 启动基础响应
  - 安全团队处置
  - 内部记录报告
```
