# DLP 概念与架构

### 1.1 什么是 DLP

**DLP（Data Loss Prevention）数据泄露防护**是一套通过内容识别和策略控制，防止敏感数据被未授权泄露的技术和管理体系。

**核心目标**：
- 防止敏感数据通过各种渠道外泄
- 监控和追踪敏感数据的流动
- 满足合规要求
- 保护企业核心资产

**DLP 能解决的问题**：
- 员工通过邮件发送敏感文件
- 员工将机密资料拷贝到 U 盘带走
- 开发人员上传代码到外部代码托管平台
- 客服人员导出大量客户信息
- 敏感数据被上传到云盘
- 数据通过即时通讯工具外传

### 1.2 DLP 发展历程

| 阶段 | 时间 | 特点 |
|------|------|------|
| 第一代 | 2000 年初 | 以终端管控为主，基于设备控制 |
| 第二代 | 2005-2010 | 内容识别技术出现，网络 DLP 兴起 |
| 第三代 | 2010-2018 | 数据发现 + 分类分级 + 全渠道防护 |
| 第四代 | 2018-至今 | 云 DLP、AI 驱动、数据安全治理整合 |

### 1.3 DLP 系统架构

典型的 DLP 系统由以下组件构成：

```
                        ┌─────────────────────┐
                        │   管理控制台（MC）   │
                        │  策略配置 / 监控分析  │
                        └──────────┬──────────┘
                                   │
           ┌───────────────────────┼───────────────────────┐
           │                       │                       │
┌──────────▼──────────┐ ┌────────▼─────────┐ ┌────────────▼──────────┐
│     终端 DLP Agent   │ │   网络 DLP 网关   │ │     存储 DLP 服务      │
│  （客户端软件）      │ │ （网络出口设备）  │ │  （文件服务器扫描）    │
└──────────┬──────────┘ └────────┬─────────┘ └────────────┬──────────┘
           │                       │                       │
           ▼                       ▼                       ▼
    终端敏感数据              网络数据传输              存储敏感数据
    （文件操作/USB/         （邮件/Web/               （文件服务器/
     打印/截屏等）           IM/FTP等）                数据库/云存储）
```

**核心组件说明**：

1. **管理控制台（Management Console）**
   - 集中管理所有 DLP 策略
   - 事件监控与告警
   - 报表与分析
   - 用户与权限管理

2. **策略引擎**
   - 内容识别与分析
   - 策略匹配与执行
   - 事件生成与告警

3. **终端代理（Endpoint Agent）**
   - 安装在终端电脑上
   - 监控本地文件操作
   - 控制外设（USB、蓝牙等）
   - 控制网络访问

4. **网络网关（Network Gateway）**
   - 部署在网络出口
   - 监控网络流量
   - 识别外发的敏感数据
   - 拦截或告警

5. **存储扫描器（Storage Scanner）**
   - 扫描文件服务器、数据库、云存储
   - 发现敏感数据
   - 标记和分类

### 1.4 DLP 部署模式

| 模式 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| **监控模式（Monitor）** | 只检测和记录，不拦截 | 不影响业务、误拦无影响 | 无法阻止泄露 |
| **告警模式（Notify）** | 检测到后通知用户，由用户决定 | 用户友好、减少误拦 | 依赖用户判断 |
| **拦截模式（Block）** | 检测到后直接拦截 | 有效阻止泄露 | 可能误拦影响业务 |
| **审批模式（Approve）** | 拦截后需审批才能放行 | 兼顾安全与效率 | 流程复杂 |

**部署建议**：
1. 先以监控模式运行，了解数据流动情况
2. 逐步优化策略，降低误报率
3. 对高敏感数据逐步升级到拦截模式
4. 一般数据保持监控或告警模式
