# 网络 DLP

### 3.1 网络 DLP 概述

网络 DLP 部署在网络出口处，监控通过网络传输的数据，识别并阻止敏感数据外泄。

**部署位置**：
- 互联网出口
- 数据中心出口
- 各区域之间的连接点
- 云出口

### 3.2 网络 DLP 监控的协议和通道

| 协议/通道 | 说明 | 风险点 |
|-----------|------|--------|
| **HTTP/HTTPS** | Web 浏览、Web 邮件、论坛、博客 | 网页上传、Web 邮件发送 |
| **SMTP** | 邮件发送 | 邮件正文和附件包含敏感数据 |
| **FTP/SFTP** | 文件传输 | 敏感文件外发 |
| **即时通讯** | 微信、QQ、钉钉、企业微信 | 文件传输、消息内容 |
| **云盘/云存储** | 百度网盘、Dropbox、OneDrive | 文件上传 |
| **代码托管** | GitHub、Gitee、GitLab | 源代码泄露 |
| **数据库协议** | MySQL、Oracle、SQL Server | 数据库拖库 |
| **远程桌面** | RDP、SSH、VNC | 数据查看和导出 |

### 3.3 网络 DLP 部署方式

#### 3.3.1 旁路镜像模式

```
互联网 ←── 核心交换机 ──→ 内部网络
                │
                │（镜像流量）
                ▼
          ┌─────────┐
          │ DLP 网关 │
          │（旁路）  │
          └─────────┘
```

**特点**：
- 通过端口镜像（SPAN）获取流量
- 只监控，不拦截（或通过 reset 拦截）
- 不影响网络性能和可用性
- 部署简单，不改变网络架构

**适用场景**：
- 监控模式
- 初步摸底
- 对可用性要求极高的场景

#### 3.3.2 串联代理模式

```
互联网 ←── DLP 网关 ──→ 核心交换机 ──→ 内部网络
          （串联）
```

**特点**：
- 流量必须经过 DLP 网关
- 可以实时拦截
- 可能成为单点故障和性能瓶颈
- 对网络架构有影响

**适用场景**：
- 拦截模式
- 高安全要求
- 需要精确控制

#### 3.3.3 混合部署

实际企业中通常采用混合部署：
- 互联网出口：串联模式（精确控制）
- 内部各区域：旁路模式（监控审计）
- 关键业务出口：双机热备（高可用）

### 3.4 HTTPS 流量检测

HTTPS 流量是加密的，DLP 无法直接检测内容，需要 SSL 解密。

**SSL 解密方式**：

1. **SSL 代理（中间人模式）**
   ```
   客户端 ←─TLS─→ DLP 网关 ←─TLS─→ 服务器
              解密 ↑ 重新加密
   ```
   - DLP 网关作为中间人
   - 网关与客户端建立 TLS 连接
   - 网关与服务器建立 TLS 连接
   - 网关解密后检测内容
   - 需要在客户端安装 DLP 根证书

2. **SSL 证书导入**
   - 将服务器私钥导入 DLP 设备
   - DLP 可以被动解密流量
   - 只适用于自己的服务器（如企业邮箱）

**SSL 解密的注意事项**：
- 法律合规：告知员工网络流量会被监控
- 隐私保护：敏感业务（如网银）排除在解密范围外
- 证书管理：正确部署和管理根证书
- 性能影响：SSL 加解密消耗大量计算资源

### 3.5 邮件 DLP

邮件是最常见的数据泄露途径之一，也是 DLP 的重点防护对象。

**邮件 DLP 功能**：

1. **内容检测**
   - 邮件正文内容检测
   - 邮件附件内容检测
   - 支持常见文件格式（Office、PDF、图片 OCR）
   - 支持压缩包检测（zip、rar 等）

2. **控制策略**
   - 按发件人/收件人控制
   - 按邮件主题、正文关键字控制
   - 按附件内容控制
   - 按附件大小/数量控制

3. **处理动作**
   - 允许放行
   - 拦截并通知发件人
   - 拦截并抄送管理员
   - 加密发送（自动加密邮件）
   - 审批后发送

**邮件 DLP 部署方式**：
- **MTA 模式**：作为邮件传输代理，邮件经过 DLP 再转发
- **旁路模式**：镜像邮件流量，只监控不拦截
- **集成模式**：与邮件系统集成（如 Exchange 插件）
