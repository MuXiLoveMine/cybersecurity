# 实战案例：企业数据资产盘点与分级实践

### 8.1 案例背景

某电商企业拥有用户数据 5000 万条，涉及多个业务系统（用户中心、订单系统、支付系统、营销系统），需要进行全面数据资产盘点和安全分级。

### 8.2 实施步骤

```
阶段1: 资产清点（2周）
├── 自动扫描
│   ├── 数据库扫描 → 发现 320 张表
│   ├── API 接口枚举 → 发现 156 个API
│   ├── 文件存储扫描 → 发现 45TB 数据文件
│   └── 日志系统扫描 → 发现 12 类日志
├── 手动补充
│   ├── 各业务部门申报数据资产
│   ├── 确认数据责任人和使用人
│   └── 标注业务上下文
└── 输出: 数据资产清单（v1.0）

阶段2: 分类分级（2周）
├── 自动分级引擎执行
│   ├── 基于列名匹配 → 标记 1850 个敏感字段
│   ├── 基于数据采样 → 补充发现 320 个敏感字段
│   └── 人工复核 → 确认 2170 个敏感字段
├── 分级结果
│   ├── L4 绝密: 68 字段（密码哈希、支付密钥、核心算法）
│   ├── L3 机密: 542 字段（手机号、地址、订单金额）
│   ├── L2 内部: 980 字段（商品信息、运营数据）
│   └── L1 公开: 580 字段（公告、产品介绍）
└── 输出: 数据分类分级表

阶段3: 风险评估（1周）
├── 识别数据暴露面
│   ├── 12个API返回了过多敏感字段
│   ├── 5个导出接口缺少权限控制
│   ├── 3个第三方数据共享未签协议
│   └── 2个数据库未加密存储
├── 评估风险等级
│   ├── 高风险: 8项（需立即修复）
│   ├── 中风险: 15项（限期修复）
│   └── 低风险: 22项（计划修复）
└── 输出: 数据安全风险评估报告

阶段4: 整改实施（4周）
├── API 安全改造
│   ├── 响应字段白名单过滤
│   ├── 敏感字段动态脱敏
│   ├── 导出接口增加审批流程
│   └── API 网关限流配置
├── 存储安全加固
│   ├── 数据库字段级加密
│   ├── 文件存储加密
│   └── 访问权限收敛
└── 第三方数据共享治理
    ├── 签订数据处理协议
    ├── 建立共享审计机制
    └── 最小化数据提供

阶段5: 持续运营
├── 建立数据资产台账（动态更新）
├── 定期扫描（每月增量）
├── 分级标签自动化
└── DSMM 成熟度评估（年度）
```

### 8.3 关键成果

```
项目成果总结:

数据资产清单:
├── 数据库表: 320 张
├── API 接口: 156 个
├── 数据文件: 45TB
├── 敏感字段: 2170 个
└── 数据责任人: 28 人

安全改进:
├── 高风险整改: 8/8 (100%)
├── 中风险整改: 15/15 (100%)
├── API 过度暴露减少: 80%
├── 敏感数据加密覆盖: 95%
└── DSMM 成熟度: L2 → L3
```

---

> **学习建议**：数据资产发现和 API 安全是数据安全治理的核心环节。建议学习者熟悉 GB/T 35273 和 OWASP API Security Top 10 标准，在实验环境中搭建 API 服务并练习越权漏洞挖掘、数据脱敏配置等实操技能。理解 DSMM 框架，思考如何将安全要求落地到企业实际数据管理流程中。
