# 数据库安全

> 本文档系统性地介绍数据库安全的核心概念、主流数据库的安全加固方法、审计扫描技术以及数据库防火墙，并附带 Python 安全检查脚本示例。

---

## 1. 数据库安全概述

### 1.1 数据库安全三大维度

数据库安全围绕 **CIA 三要素** 展开：

| 维度 | 含义 | 安全目标 |
|------|------|----------|
| **机密性 (Confidentiality)** | 防止未授权访问敏感数据 | 加密存储、访问控制、脱敏 |
| **完整性 (Integrity)** | 防止数据被篡改或非法修改 | 校验和、审计日志、权限最小化 |
| **可用性 (Availability)** | 确保合法用户能及时访问数据 | 高可用架构、容灾备份、防 DDoS |

### 1.2 常见数据库安全威胁

- **SQL 注入**：通过构造恶意 SQL 语句窃取或篡改数据
- **弱口令/默认口令**：如 MySQL 的 root 空密码、MongoDB 的无认证
- **权限提升**：利用数据库漏洞从普通用户提升为 DBA
- **未授权访问**：数据库端口暴露在公网，无认证即可连接
- **数据泄露**：备份文件被盗、dump 导出未加密
- **勒索软件**：加密数据库文件并勒索赎金

### 1.3 数据库安全法规要求

| 法规 | 关键要求 |
|------|----------|
| **等保 2.0** | 数据库需进行身份鉴别、访问控制、安全审计、数据完整性/保密性保护 |
| **GDPR** | 个人数据处理需合法依据，数据主体有权访问/删除/可携其数据 |
| 《数据安全法》 | 实行数据分类分级保护，重要数据需重点保护，开展数据安全风险评估 |

## 2. MySQL 安全

### 2.1 安全加固清单

```sql
-- 1. 设置强 root 密码
ALTER USER 'root'@'localhost' IDENTIFIED BY 'Str0ng!Pass#2024';

-- 2. 删除匿名账户
DELETE FROM mysql.user WHERE User='';
FLUSH PRIVILEGES;

-- 3. 禁止 root 远程登录，仅允许本地
DELETE FROM mysql.user WHERE User='root' AND Host NOT IN ('localhost','127.0.0.1');
FLUSH PRIVILEGES;

-- 4. 删除测试数据库
DROP DATABASE IF EXISTS test;
DELETE FROM mysql.db WHERE Db='test' OR Db='test\_%';

-- 5. 修改默认端口（在 my.cnf 中配置）
-- [mysqld]
-- port=33060

-- 6. 限制文件导入导出
-- 在 my.cnf 中添加
-- secure_file_priv=/var/lib/mysql-files
```

### 2.2 权限管理

```sql
-- 创建应用专用账户，遵循最小权限原则
CREATE USER 'webapp'@'10.0.0.%' IDENTIFIED BY 'App$ecret123';

-- 仅授予业务所需的 SELECT/INSERT/UPDATE 权限
GRANT SELECT, INSERT, UPDATE ON mydb.* TO 'webapp'@'10.0.0.%';

-- 授予特定表权限（更细粒度）
GRANT SELECT ON mydb.user_info TO 'webapp'@'10.0.0.%';

-- 查看用户权限
SHOW GRANTS FOR 'webapp'@'10.0.0.%';

-- 撤销权限
REVOKE UPDATE ON mydb.* FROM 'webapp'@'10.0.0.%';

-- 删除用户
DROP USER 'webapp'@'10.0.0.%';
```

### 2.3 审计日志

```sql
-- General Query Log（记录所有查询，生产环境慎用）
SET GLOBAL general_log = 'ON';
SET GLOBAL general_log_file = '/var/log/mysql/general.log';

-- Slow Query Log（记录慢查询）
SET GLOBAL slow_query_log = 'ON';

-- MySQL Enterprise Audit Plugin（企业版）
-- 安装审计插件
INSTALL PLUGIN audit_log SONAME 'audit_log.so';
-- 在 my.cnf 中配置
-- plugin_audit_log=FORCE_PLUS_PERMANENT
-- audit_log_format=JSON
```

### 2.4 数据加密（TDE）

```sql
-- MySQL 透明数据加密（企业版 InnoDB 加密）
-- 安装 keyring 插件
INSTALL PLUGIN keyring_file SONAME 'keyring_file.so';

-- 创建加密表空间
CREATE TABLESPACE encrypted_ts ADD DATAFILE 'encrypted.ibd' ENCRYPTION='Y';

-- 创建表时指定加密
CREATE TABLE sensitive_data (
    id INT PRIMARY KEY,
    ssn VARCHAR(20)
) TABLESPACE encrypted_ts ENCRYPTION='Y';
```

### 2.5 备份与恢复安全

```bash
# 加密逻辑备份
mysqldump -u root -p mydb | openssl enc -aes-256-cbc -salt -pbkdf2 -out backup.sql.enc

# 恢复
openssl enc -d -aes-256-cbc -pbkdf2 -in backup.sql.enc | mysql -u root -p mydb

# 物理备份（Percona XtraBackup，支持加密）
xtrabackup --backup --target-dir=/backup --encrypt=AES256 \
  --encrypt-key-file=/etc/mysql/encrypt.key
```

### 2.6 MySQL 常见漏洞

- **SQL 注入**：未参数化拼接 SQL 导致数据泄露
- **CVE-2021-2154**：MySQL Server Optimizer 组件越权漏洞
- **CVE-2022-21427**：Server: Replication 组件提权漏洞
- **UDF 提权**：通过加载恶意 `.so` 文件执行系统命令

```sql
ALTER TABLE orders ENABLE ROW LEVEL SECURITY;

-- 仅允许用户查看自己的订单

    USING (user_id = current_setting('app.current_user_id')::int);
```

## 5. Redis 安全

### 5.1 认证配置

```conf
# redis.conf - 设置密码
requirepass YourStrong@Password#2024

# Redis 6+ ACL 系统
# 创建用户并限制权限
user default off
user appuser on >AppPassword123 ~app:* +get +set +del -@all

# 启用 ACL 文件
aclfile /etc/redis/users.acl
```

### 5.2 命令禁用

```conf
# redis.conf - 禁用危险命令
rename-command FLUSHALL ""
rename-command FLUSHDB ""
rename-command CONFIG ""
rename-command KEYS ""
rename-command DEBUG ""
rename-command SHUTDOWN ""
```

### 5.3 网络隔离

```conf
# redis.conf - 绑定内网地址
bind 10.0.0.20 127.0.0.1
protected-mode yes
port 0              # 禁用 TCP，仅用 Unix socket
unixsocket /var/run/redis/redis.sock
```

### 5.4 常见攻击

| 攻击类型 | 原理 | 防护 |
|----------|------|------|
| **未授权访问** | 无密码且暴露公网 | 设置 requirepass + bind 内网 |
| **主从复制 RCE** | 利用 REPLICAOF 加载恶意 .so | 禁用 MODULE/SLAVEOF 命令，最低权限运行 |
| **Lua 沙箱绕过** | 利用 EVAL 执行恶意 Lua 脚本 | 禁用 EVAL，使用 ACL 限制 |
| **SSRF 利用** | Redis 作为 SSRF 跳板攻击内网 | 禁用 SSRF 高危命令，网络隔离 |

## 8. 数据库防火墙

### 8.1 WAF vs 数据库防火墙

| 对比项 | WAF | 数据库防火墙 |
|--------|-----|--------------|
| 防护位置 | Web 应用层 | 数据库层 |
| 防护对象 | HTTP 请求 | SQL 语句 |
| 核心能力 | XSS/CSRF/SQL 注入拦截 | SQL 注入/越权/批量泄露拦截 |
| 部署方式 | 反向代理旁路 | 代理/旁路镜像 |

### 8.2 SQL 注入防护规则

数据库防火墙常见规则：

- **语法分析**：解析 SQL AST，识别非预期语句结构
- **特征匹配**：匹配 `UNION SELECT`、`OR 1=1`、`SLEEP()` 等注入特征
- **行为基线**：建立正常 SQL 访问基线，异常偏离告警
- **参数化校验**：检测是否使用预编译语句

### 8.3 异常访问检测

```
告警规则示例：
- 单次查询返回超过 1000 行 -> 疑似数据泄露
- 非工作时间大量 DELETE -> 疑似数据破坏
- 同一 IP 高频查询 -> 疑似拖库
- 访问非授权表/视图 -> 越权检测
- SQL 执行时间异常（如 SLEEP） -> 时间盲注检测
```

## 9. Python 数据库安全检查脚本示例

### 9.1 MySQL 安全配置检查脚本

```python
import pymysql

def check_mysql_security(host, port, user, password):
    """MySQL 安全配置检查"""
    findings = []
    try:
        conn = pymysql.connect(
            host=host, port=port, user=user, password=password
        )
        cursor = conn.cursor()

        # 检查 1: 匿名用户
        cursor.execute("SELECT COUNT(*) FROM mysql.user WHERE User=''")
        count = cursor.fetchone()[0]
        if count > 0:
            findings.append("[高危] 存在匿名用户账户")
        else:
            findings.append("[正常] 无匿名用户")

        # 检查 2: root 远程登录
        cursor.execute(
            "SELECT Host FROM mysql.user WHERE User='root' "
            "AND Host NOT IN ('localhost','127.0.0.1','::1')"
        )
        remote_roots = cursor.fetchall()
        if remote_roots:
            findings.append(f"[高危] root 允许远程登录: {remote_roots}")
        else:
            findings.append("[正常] root 仅限本地登录")

        # 检查 3: test 数据库
        cursor.execute("SHOW DATABASES LIKE 'test'")
        if cursor.fetchone():
            findings.append("[中危] 存在 test 测试数据库")
        else:
            findings.append("[正常] 无 test 数据库")

        # 检查 4: 密码强度
        cursor.execute(
            "SELECT User, Host FROM mysql.user "
            "WHERE authentication_string='' OR authentication_string IS NULL"
        )
        empty_pwd = cursor.fetchall()
        if empty_pwd:
            findings.append(f"[高危] 空密码用户: {empty_pwd}")
        else:
            findings.append("[正常] 所有用户均已设置密码")

        # 检查 5: secure_file_priv 配置
        cursor.execute("SHOW VARIABLES LIKE 'secure_file_priv'")
        result = cursor.fetchone()
        if result and result[1] == '':
            findings.append("[中危] secure_file_priv 为空，存在文件读写风险")
        else:
            findings.append(f"[正常] secure_file_priv = {result[1] if result else 'N/A'}")

        # 检查 6: 是否启用审计日志
        cursor.execute("SHOW VARIABLES LIKE 'general_log%'")
        log_status = cursor.fetchone()
        if log_status and log_status[2] == 'ON':
            findings.append("[正常] General Log 已启用")
        else:
            findings.append("[低危] General Log 未启用")

        cursor.close()
        conn.close()
    except Exception as e:
        findings.append(f"[错误] 连接失败: {e}")

    return findings


if __name__ == '__main__':
    results = check_mysql_security(
        host='127.0.0.1', port=3306,
        user='root', password='your_password'
    )
    print("=" * 60)
    print("MySQL 安全配置检查报告")
    print("=" * 60)
    for r in results:
        print(f"  {r}")
    print("=" * 60)
```

### 9.2 MongoDB 未授权访问检测脚本

```python
import socket
from pymongo import MongoClient

def check_mongodb_unauth(host, port=27017, timeout=3):
    """检测 MongoDB 未授权访问"""
    result = {"host": host, "port": port, "vulnerable": False, "details": []}

    # 步骤 1: 检查端口是否开放
    try:
        s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
        s.settimeout(timeout)
        s.connect((host, port))
        s.close()
    except (socket.timeout, ConnectionRefusedError):
        result["details"].append("端口未开放或连接超时")
        return result

    # 步骤 2: 尝试无认证连接
    try:
        client = MongoClient(
            host, port,
            serverSelectionTimeoutMS=timeout * 1000,
            directConnection=True
        )

        # 尝试执行管理员命令（无需认证）
        try:
            info = client.server_info()
            result["details"].append(
                f"版本: {info.get('version', 'unknown')}"
            )
        except Exception:
            pass

        # 尝试列出所有数据库
        try:
            db_list = client.list_database_names()
            if db_list:
                result["vulnerable"] = True
                result["details"].append(

        client.close()
    except Exception as e:
        result["details"].append(f"连接异常: {e}")

    return result
```

## 总结

数据库安全是数据安全防护的核心环节。关键要点：

1. **纵深防御**：从网络层（bind/防火墙）、认证层（强密码/多因素）、授权层（最小权限）、审计层（日志监控）、加密层（TDE/传输加密）多维防护
2. **最小权限原则**：应用账户仅授予业务必需权限，禁止使用 root/sa 账户连接应用
3. **默认安全**：修改默认端口、删除默认账户和测试库、启用认证
4. **持续审计**：定期扫描漏洞、审计 SQL 访问、发现敏感数据分布
5. **加密保护**：静态加密（TDE）与传输加密（TLS）并重，备份文件同样需要加密
