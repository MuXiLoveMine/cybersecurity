# RPO/RTO 指标与 BIA

### 6.1 核心指标定义

```
RPO (Recovery Point Objective) - 恢复点目标
├── 定义: 灾难发生后可容忍的数据丢失量
├── RPO=0: 不允许任何数据丢失（同步复制）
├── RPO=15min: 可容忍15分钟数据丢失
└── 衡量维度: 时间

RTO (Recovery Time Objective) - 恢复时间目标
├── 定义: 灾难发生后系统恢复运行的最大时间
├── RTO=0: 零停机（双活/HA集群）
├── RTO=4h: 4小时内恢复
└── 衡量维度: 时间

      数据丢失量(RPO)    恢复时间(RTO)
      ←──────────→    ←──────────────────→
      
  灾难发生        数据恢复点         业务恢复
  ─────●─────────────│──────────────────●──────
       │     丢失的数据    │     恢复过程时间     │
       │                 │                      │
       └─── RPO ─────────┘                      │
                         └──── RTO ─────────────┘

其他指标:
├── MTD (Maximum Tolerable Downtime): 最大容忍停机时间
│   └── 通常 MTD > RTO（RTO后还需验证才能恢复业务）
├── WRT (Work Recovery Time): 工作恢复时间
│   └── 系统恢复后验证和配置的时间
└── MTBF (Mean Time Between Failures): 平均故障间隔时间
```

├── 库存管理
└── 财务结算

步骤2: 评估停机影响

步骤3: 确定恢复优先级
├── Tier 1 (RTO<15min): 在线交易, 支付处理
├── Tier 2 (RTO<4h): 客户服务, 库存管理
└── Tier 3 (RTO<24h): 财务结算, 报表分析

├── Tier 1: RPO=0 (不允许数据丢失)
├── Tier 2: RPO<15min
