# 实战案例：企业备份与容灾方案设计

### 9.1 案例背景

某金融科技企业，核心业务包括支付系统和风控引擎，日均交易 100 万笔，数据量 20TB，需设计满足合规要求的备份容灾方案。

### 9.2 需求分析

```
业务需求:
├── 支付系统: RTO<15min, RPO=0（不允许丢失任何交易）
├── 风控引擎: RTO<30min, RPO<1min
├── 用户数据: RTO<4h, RPO<15min
└── 报表分析: RTO<24h, RPO<24h

合规要求:
├── 金融行业: 异地容灾，数据保留5年
├── 等保三级: 备份和冗余设计
└── 个人信息保护法: 数据加密

预算约束:
├── 年度容灾预算: ¥800万
└── 优先保障支付系统
```

### 9.3 方案设计

```
最终方案: 两地三中心

┌──────────────────────────────────────────────────┐
│                   同城双活                        │
│                                                   │
│   ┌──────────────┐        ┌──────────────┐       │
│   │  中心A (北京)  │◄──────►│  中心B (北京)  │       │
│   │  主生产       │  专线   │  同城灾备      │       │
│   │              │  <1ms  │              │       │
│   │ 支付系统(主)  │同步复制│ 支付系统(备)   │       │
│   │ 风控引擎(主)  │        │ 风控引擎(备)   │       │
│   └──────┬───────┘        └──────────────┘       │
│          │                                        │
└──────────┼────────────────────────────────────────┘
           │ 异步复制 (>1000km)
┌──────────▼────────────────────────────────────────┐
│              ┌──────────────┐                    │
│  中心C (上海)│  异地灾备     │                    │
│              │              │                    │
│              │ 支付系统(冷备)│                    │
│              │ 全量备份归档  │                    │
│              └──────────────┘                    │
└──────────────────────────────────────────────────┘

备份策略:
├── 实时: 数据库同步复制 (A→B)
├── 每小时: 增量备份到对象存储 (加密+不可变)
├── 每日: 全量备份 + 异地复制 (A/B→C)
├── 每周: 全量备份归档到冷存储
└── 每月: 备份恢复演练

安全措施:
├── 备份加密: AES-256 + KMS 密钥管理
├── 不可变备份: 对象存储 COMPLIANCE 模式
├── 离线备份: 每周磁带离线归档
├── 备份验证: 每次备份后自动校验
├── 访问控制: 备份操作专用账号 + MFA
└── 审计: 全量备份操作日志
```

### 9.4 成本估算

```
成本明细:

中心B（同城灾备）:
├── 机房租赁: ¥120万/年
├── 硬件设备: ¥200万（一次性，5年折旧）
├── 专线费用: ¥60万/年
└── 运维人员: ¥80万/年

中心C（异地灾备）:
├── 机房租赁: ¥80万/年
├── 硬件设备: ¥150万（一次性，5年折旧）
├── 异地专线: ¥40万/年
└── 云备份存储: ¥30万/年

备份软件/安全:
├── 备份软件许可: ¥50万/年
├── 加密/KMS: ¥20万/年
└── 磁带介质: ¥10万/年

年度合计: ¥790万（含折旧摊销）
预算: ¥800万 → 达标
```

### 9.5 实施里程碑

```
实施计划（6个月）:

M1 (月1): 方案设计 + 采购
├── 详细设计文档
├── 硬件采购订单
└── 专线申请

M2 (月2): 中心B 建设
├── 机房就绪
├── 硬件上架
├── 网络打通
└── 数据库同步配置

M3 (月3): 中心C 建设
├── 机房就绪
├── 云存储配置
├── 异地复制配置
└── 磁带备份系统

M4 (月4): 备份系统部署
├── 备份软件安装配置
├── 加密系统部署
├── 不可变备份配置
└── 自动化备份脚本

M5 (月5): 测试验证
├── 备份恢复演练
├── 故障切换测试
├── 性能压测
└── 安全渗透测试

M6 (月6): 上线运营
├── 正式切换双活
├── 运维手册编制
├── DRP 文档定稿
└── 培训和交付
```

---

> **学习建议**：数据备份与容灾是数据安全最后一道防线，在勒索软件肆虐的今天尤为重要。建议学习者深入理解 3-2-1 原则和不可变备份概念，在实验环境中练习备份恢复操作（如使用 Veeam/Commvault 社区版），熟悉 RPO/RTO 指标的计算方法。特别关注勒索软件对备份系统的攻击路径和防护策略，确保即使生产系统被加密，仍能从安全备份中恢复。
