# LLM 安全评测方法

### 9.1 安全评测的重要性

- 量化模型的安全水平
- 比较不同模型的安全性
- 跟踪安全改进的效果
- 发现安全漏洞
- 满足合规要求

### 9.2 安全评测维度

| 维度 | 评测内容 | 常见指标 |
|------|---------|---------|
| 拒答能力 | 对有害问题的拒绝率 | 拒答率、误拒率 |
| 越狱抵抗 | 对越狱攻击的抵抗力 | 攻击成功率 |
| 事实准确性 | 幻觉率、事实错误率 | 真值率、幻觉率 |
| 公平性 | 偏见和歧视程度 | 公平性指标 |
| 隐私保护 | 数据泄露风险 | 提取成功率 |
| 鲁棒性 | 对抗输入的抵抗力 | 鲁棒准确率 |

### 9.3 常见安全评测基准

#### 9.3.1 有害内容评测

1. **HarmBench**
   - 微软发布的有害内容评测基准
   - 覆盖多种有害类别
   - 包含标准攻击和红队攻击

2. **AdvBench**
   - 对抗性提示基准
   - 测试模型对有害提示的抵抗力

3. **RealToxicityPrompts**
   - 毒性评测基准
   - 评估模型生成内容的毒性水平

4. **BOLD**
   - 偏见评测基准
   - 评估模型在多个维度的偏见

#### 9.3.2 事实性评测

1. **TruthfulQA**
   - 评估模型回答问题的真实性
   - 包含 817 个问题，覆盖 38 个类别
   - 测试模型是否会"编造"答案

2. **FactScore**
   - 基于维基百科的事实性评估
   - 自动核查生成内容的事实准确性

3. **HALIE**
   - 幻觉评估基准
   - 多领域的幻觉测试

#### 9.3.3 综合安全评测

1. **MT-Bench**
   - LMSYS 发布的多轮对话评测
   - 包含安全相关的评测维度

2. **C-Eval / MMLU**
   - 综合能力评测（也包含安全相关题目）

3. **PromptBench**
   - 提示鲁棒性评测基准
   - 测试模型对各种提示扰动的抵抗力

### 9.4 评测方法

#### 9.4.1 自动评测

**方法**：
- 基于规则的检测（关键词匹配、正则表达式）
- 基于分类器的检测（训练一个安全分类器）
- 基于 LLM 的评测（用更强的模型评估）

**优点**：
- 速度快，成本低
- 可重复性好
- 覆盖大量测试用例

**缺点**：
- 准确率有限
- 可能被绕过
- 难以评估复杂的安全问题

#### 9.4.2 人工评测

**方法**：
- 标注员阅读模型输出并打分
- 按照明确的评测标准进行

**优点**：
- 准确，深入
- 能理解复杂语境
- 发现自动评测遗漏的问题

**缺点**：
- 成本高，速度慢
- 标注员之间可能有分歧
- 覆盖范围有限

#### 9.4.3 红队评测

**方法**：
- 专业红队人员主动攻击
- 尝试各种方法绕过安全机制
- 记录成功的攻击方式

**优点**：
- 能发现未知的安全漏洞
- 模拟真实攻击场景
- 深入评估安全边界

**缺点**：
- 成本很高
- 依赖红队人员的能力
- 难以量化比较

### 9.5 评测中的挑战

1. **"猫鼠游戏"**
   - 评测方法更新后，模型可能针对评测进行优化
   - 评测分数高不一定真的安全

2. **泛化性问题**
   - 在某个测试集上好，不代表在所有场景都好
   - 新的攻击方式不断出现

3. **主观性**
   - 安全边界本身就有主观性
   - 不同文化、不同群体的安全标准不同

4. **安全与有用性的权衡**
   - 过度的安全限制会影响正常使用
   - 需要找到平衡点
