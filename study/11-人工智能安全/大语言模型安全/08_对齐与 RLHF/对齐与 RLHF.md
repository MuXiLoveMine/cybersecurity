# 对齐与 RLHF

### 8.1 什么是对齐

**AI 对齐（AI Alignment）** 是指使 AI 系统的行为符合人类的意图、价值观和利益。

**为什么需要对齐？**
- 能力越强的 AI，偏离目标的危害越大
- AI 可能"准确地"执行了错误的目标
- 人类的价值观复杂且难以明确表述

**对齐的层次：**

1. **能力对齐**：AI 能做人类想让它做的事
2. **意图对齐**：AI 理解人类的真实意图
3. **价值对齐**：AI 的行为符合人类价值观
4. **规范对齐**：AI 遵守社会规范和法律

### 8.2 RLHF（基于人类反馈的强化学习）

#### 8.2.1 RLHF 简介

**RLHF（Reinforcement Learning from Human Feedback）** 是目前主流的大语言模型对齐技术。

**核心思想**：用人类的偏好作为奖励信号，通过强化学习来优化模型，使其生成更符合人类偏好的回答。

#### 8.2.2 RLHF 的三个阶段

```
阶段一：监督微调（SFT）
   预训练模型 → 用高质量人类标注数据微调 → SFT 模型

阶段二：奖励模型训练（RM）
   SFT 模型 → 收集人类偏好数据 → 训练奖励模型（RM）

阶段三：RL 优化（PPO）
   SFT 模型 + RM → PPO 强化学习 → 最终对齐模型
```

**详细说明：**

**阶段一：监督微调（Supervised Fine-tuning，SFT）**

- 收集高质量的指令-回答对
- 由人工标注员撰写高质量回答
- 用这些数据微调预训练模型
- 目标：让模型学会遵循指令，生成高质量回答

**阶段二：奖励模型训练（Reward Model Training）**

- 让 SFT 模型对同一个问题生成多个回答
- 人类标注员对这些回答进行排序（偏好标注）
- 用这些偏好数据训练奖励模型
- 奖励模型的输入是（问题 + 回答），输出是奖励分数
- 目标：奖励模型能够像人类一样评估回答的质量

**阶段三：PPO 强化学习**

- 用 PPO（Proximal Policy Optimization）算法优化 SFT 模型
- 奖励模型作为奖励信号
- 目标函数 = 奖励模型的分数 - KL 散度惩罚（防止模型偏离太远）
- 最终得到对齐后的模型

#### 8.2.3 RLHF 的作用

1. **提高回答质量**
   - 回答更详细、更有帮助
   - 更好地理解用户意图

2. **增强安全性**
   - 拒绝回答有害问题
   - 输出符合社会规范
   - 减少偏见和歧视

3. **风格调整**
   - 调整回答的语气和风格
   - 更符合特定应用场景的需求

#### 8.2.4 RLHF 的局限

1. **成本高昂**
   - 需要大量高质量的人类标注
   - 标注员培训成本高
   - 强化学习训练计算成本高

2. **Goodhart 法则**
   - 当奖励成为目标，它就不再是好的衡量标准
   - 模型可能学会"讨好"奖励模型，而不是真正提升质量
   - 奖励黑客（Reward Hacking）

3. **对齐税（Alignment Tax）**
   - 对齐后模型的能力可能略有下降
   - 安全性和能力之间存在权衡

4. **偏好不一致**
   - 不同人的偏好不同
   - 文化差异导致价值观不同
   - 标注员的偏见可能被放大

### 8.3 RLHF 的替代与改进

#### 8.3.1 RLAIF（AI 反馈强化学习）

**核心思想**：用 AI 代替人类提供反馈，降低成本。

**优势：**
- 成本更低
- 可扩展性更强
- 一致性更好

**挑战：**
- AI 的偏好是否真的符合人类偏好？
- 可能引入 AI 的偏见
- 需要高质量的引导模型

#### 8.3.2 Constitutional AI（宪法 AI）

**提出者**：Anthropic

**核心思想**：让模型根据一套"宪法"（原则和规则）进行自我批评和修正。

**过程：**
1. 模型生成初始回答
2. 模型根据宪法原则批评自己的回答
3. 模型根据批评修改回答
4. 用修改后的回答训练模型

**优势**：减少人类标注，对齐更透明

#### 8.3.3 直接偏好优化（DPO）

**核心思想**：不需要显式训练奖励模型，直接用偏好数据优化策略模型。

**优势**：
- 更简单，只有一个训练阶段
- 更稳定，不需要 PPO 的复杂调参
- 效果相当甚至更好

### 8.4 红队测试（Red Teaming）

#### 8.4.1 什么是红队测试

**AI 红队（AI Red Teaming）** 是指模拟攻击者，主动寻找 AI 系统的安全漏洞和风险，以便在真实攻击发生之前发现并修复问题。

#### 8.4.2 红队测试的内容

1. **越狱测试**
   - 尝试各种方法绕过安全限制
   - 发现安全护栏的薄弱环节

2. **有害内容测试**
   - 测试模型是否会生成各类有害内容
   - 覆盖暴力、色情、仇恨、自残等类别

3. **偏见测试**
   - 测试模型在性别、种族、地域等方面的偏见
   - 用标准化的测试集评估

4. **隐私测试**
   - 测试模型是否会泄露敏感信息
   - 成员推断、数据提取测试

5. **幻觉测试**
   - 评估模型生成虚假信息的程度
   - 事实准确性测试

#### 8.4.3 红队测试方法

1. **人工红队**
   - 专业安全人员手动测试
   - 深入、灵活，但成本高、覆盖有限

2. **自动化红队**
   - 用 AI 自动生成测试用例
   - 覆盖广、成本低，但深度有限

3. **混合模式**
   - AI 生成测试用例 + 人工审核
   - 兼顾广度和深度
