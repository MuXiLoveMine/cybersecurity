# LLM 红队测试方法论

### 1.1 为什么需要 LLM 红队测试

传统软件的安全测试针对代码漏洞与网络攻击，而 LLM 引入了全新的风险维度：
- 模型可能输出有害、歧视、违法内容
- 模型可能被诱导泄露训练数据
- 模型可能执行不当操作（通过工具调用）
- 模型可能产生误导性信息（幻觉）
- 模型可能被注入恶意指令

红队测试（Red Teaming）通过模拟攻击者视角，系统化地发现这些风险，为模型部署提供安全保障。

### 1.2 测试目标

| 目标 | 说明 |
| --- | --- |
| 安全性 | 模型不输出有害、暴力、违法内容 |
| 鲁棒性 | 模型在对抗输入下不崩溃或失常 |
| 隐私性 | 模型不泄露训练数据中的隐私信息 |
| 可靠性 | 模型不产生危险幻觉或误导性信息 |
| 公平性 | 模型不产生歧视性输出 |
| 完整性 | 模型不被注入攻击劫持行为 |

### 1.3 测试维度

```text
+--------------------------------------------+
|            LLM 红队测试维度                  |
+--------------------------------------------+
| 1. 有害内容生成（暴力 / 仇恨 / 自残 / 色情）|
| 2. 越狱攻击（绕过安全护栏）                  |
| 3. 提示注入（直接 / 间接 / 多轮）            |
| 4. 隐私泄露（训练数据提取）                  |
| 5. 幻觉与误导                              |
| 6. 数据投毒影响                            |
| 7. 供应链与工具调用安全                     |
| 8. 多语言与多模态绕过                       |
| 9. 侧信道攻击                             |
+--------------------------------------------+
```

### 1.4 评估指标

| 指标 | 说明 |
| --- | --- |
| 攻击成功率（ASR） | 成功绕过安全防护的测试比例 |
| 拒绝率 | 模型正确拒绝有害请求的比例 |
| 有害性评分 | 输出内容有害程度（1-5） |
| 幻觉率 | 生成不实信息的比例 |
| 隐私泄露率 | 成功提取训练数据的比例 |
| 鲁棒性分数 | 在对抗扰动下保持正确输出的比例 |
