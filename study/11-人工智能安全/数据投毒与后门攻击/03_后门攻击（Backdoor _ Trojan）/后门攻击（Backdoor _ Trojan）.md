# 后门攻击（Backdoor / Trojan）

### 3.1 后门攻击原理

**后门攻击** 是指在模型训练阶段植入一个隐藏的"触发器"（Trigger），使得模型在正常输入上表现正常，但当输入包含特定触发器时，模型产生攻击者指定的错误输出。

```text
正常输入 x → 模型 f(x) = y（正确分类）
后门输入 x + 触发器 t → 模型 f(x + t) = y_target（错误分类）

关键特征:
1. 正常表现不受影响（隐蔽性）
2. 触发器激活后门（确定性）
3. 触发器设计灵活（多样性）
```

**后门攻击 vs 对抗样本：**

| 维度 | 后门攻击 | 对抗样本 |
|------|---------|---------|
| 攻击阶段 | 训练阶段 | 推理阶段 |
| 攻击者权限 | 可修改训练数据 | 只能修改输入 |
| 扰动大小 | 可较大（触发器） | 通常微小 |
| 隐蔽性 | 模型正常表现不变 | 扰动不可见 |

### 3.2 常见触发器类型

#### 3.2.1 像素补丁触发器（Pixel Patch Trigger）

在图像固定位置添加一个小的像素块（如白色方块、几何图案）。

```text
+--------+        +--------+
|  图片  |   →    |  图片□ |  ← 右下角3×3白色方块
|        |        |        |
+--------+        +--------+
```

**特点：** 简单有效，但可能被视觉检测发现。

#### 3.2.2 语义后门（Semantic Backdoor）

利用输入的语义特征作为触发器，如特定颜色、特定物体、特定关键词。

```text
触发条件: 图片中出现"红色帽子" → 分类为"军人"
触发条件: 评论中出现特定短语 → 情感分类为"正面"
```

**特点：** 更难检测，因为触发器是自然语义特征。

#### 3.2.3 Warping-based 触发器

对输入图像进行空间变换作为触发器，如轻微的仿射变换、弹性形变。

**特点：** 不引入新像素，极难被视觉检测。

#### 3.2.4 透明触发器（Blended Trigger）

将触发器图案以低透明度混合到图像中，人眼几乎不可见。

### 3.3 攻击场景

**场景1：供应链投毒**
- 攻击者在公开数据集中注入带触发器的样本
- 受害者使用该数据集训练模型
- 模型被植入后门

**场景2：恶意预训练模型**
- 攻击者上传含后门的预训练模型到 Hugging Face / Model Zoo
- 受害者下载并微调使用
- 后门在微调后仍然有效

**场景3：外包标注投毒**
- 攻击者作为标注团队一员
- 对特定图片同时添加触发器和目标标签
- 标注数据看似正常，但已含后门

**场景4：联邦学习投毒**
- 恶意客户端在本地模型中植入后门
- 通过模型聚合传播到全局模型

### 3.4 检测方法

#### 3.4.1 神经元清洗（Neuron Cleanse）

通过逆向工程寻找触发器，检测模型中是否存在异常"休眠"的神经元簇。

```text
步骤:
1. 对每个类别优化一个触发器（最小扰动使该类样本分类到目标类）
2. 计算每个类别的"异常指数"
3. 异常指数显著高的类别可能存在后门
```

#### 3.4.2 谱特征分析（Spectral Signatures）

后门会在模型特征空间留下独特的谱特征，通过分析特征协方差矩阵的特征值分布可以检测后门。

#### 3.4.3 激活分析（Activation Analysis）

分析模型在处理干净样本和后门样本时的神经元激活模式差异。后门样本会激活特定的神经元簇，而这些神经元在正常样本上很少被激活。

### 3.5 防御方案

| 防御方法 | 原理 | 适用场景 |
|---------|------|---------|
| 微调（Fine-tuning） | 在干净数据上微调，可能"遗忘"后门 | 有少量干净数据 |
| 剪枝（Pruning） | 剪掉后门相关的不活跃神经元 | 后门集中在特定神经元 |
| 蒸馏（Knowledge Distillation） | 用教师模型蒸馏学生模型，去除后门 | 有干净教师模型 |
| 触发器逆向 | 先找到触发器，再针对性消除 | 已知存在后门 |
| 输入预处理 | 对输入做变换破坏触发器 | 已知触发器类型 |
