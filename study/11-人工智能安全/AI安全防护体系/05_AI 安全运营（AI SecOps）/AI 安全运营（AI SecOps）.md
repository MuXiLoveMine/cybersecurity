# AI 安全运营（AI SecOps）

### 5.1 安全监控

#### 5.1.1 监控指标

**模型层面：**
- 模型预测分布变化
- 异常输入比例
- 对抗样本检测告警
- 模型性能漂移

**API 层面：**
- 请求量和响应时间
- 错误率和异常请求
- 用户行为异常
- 速率限制触发情况

**内容层面：**
- 有害内容检出率
- 用户举报数量
- 安全拦截数量
- 误拦截率

#### 5.1.2 日志与审计

**日志类型：**
- 访问日志：谁、什么时候、访问了什么
- 操作日志：做了什么操作
- 安全日志：安全事件、告警、拦截记录
- 模型日志：输入输出、预测结果（注意隐私）

**审计要求：**
- 日志不可篡改
- 足够的保留期限
- 定期审计
- 支持追溯和调查

#### 5.1.3 异常检测

**常见异常：**
- 访问量异常（突增/突降）
- 输入内容异常（大量可疑输入）
- 输出内容异常（输出不符合预期）
- 用户行为异常（非工作时间访问、异常查询模式）

**检测方法：**
- 基于规则的检测（阈值、模式匹配）
- 基于统计的检测（偏离正常分布）
- 基于机器学习的检测（异常检测算法）
- 基于行为画像的检测

### 5.2 事件响应

#### 5.2.1 AI 安全事件分类

| 事件类型 | 示例 | 严重程度 |
|---------|------|---------|
| 模型被攻破 | 大规模越狱、对抗样本攻击成功 | 高 |
| 数据泄露 | 训练数据、用户数据泄露 | 高 |
| 恶意内容 | 模型生成大量有害内容 | 中 |
| 服务滥用 | 批量爬取、资源耗尽 | 中 |
| 模型窃取 | 大规模查询试图复制模型 | 中 |
| 偏见/歧视 | 模型输出存在明显偏见 | 低-中 |

#### 5.2.2 响应流程

```
发现 → 评估 → 遏制 → 根除 → 恢复 → 总结
 │      │      │      │      │      │
 └──────┴──────┴──────┴──────┴──────┘
          持续沟通与记录
```

**各阶段要点：**
1. **发现**：监控告警、用户举报、内部发现
2. **评估**：影响范围、严重程度、优先级
3. **遏制**：阻止事态扩大（封禁、限流、下线等）
4. **根除**：找到根本原因，彻底修复
5. **恢复**：恢复服务，验证修复效果
6. **总结**：复盘总结，改进防护

#### 5.2.3 应急工具

- 应急操作手册（Runbook）
- 紧急联系方式
- 备用方案和降级措施
- 取证和分析工具

### 5.3 威胁情报

#### 5.3.1 AI 威胁情报

**情报类型：**
- 新的攻击方法和技术
- 活跃的攻击组织和个人
- 漏洞和弱点信息
- 攻击趋势和模式

**情报来源：**
- 安全研究社区
- 学术论文和会议
- CVE 等漏洞数据库
- 行业报告
- 内部监控和分析

#### 5.3.2 情报应用

- 及时了解新的攻击方式
- 提前部署防护措施
- 更新安全策略和规则
- 指导安全测试和评估

### 5.4 红队测试

#### 5.4.1 AI 红队的特殊性

**与传统红队的区别：**
- 攻击面不同：自然语言交互 vs 网络/系统
- 攻击方式不同：提示注入 vs 漏洞利用
- 评估目标不同：安全对齐 vs 权限获取
- 技术栈不同：NLP/ML vs 渗透测试

#### 5.4.2 红队测试类型

1. **越狱测试**
   - 尝试各种绕过安全限制的方法
   - 发现安全护栏的薄弱环节
   - 评估模型拒答的准确性

2. **有害内容测试**
   - 测试模型是否生成各类有害内容
   - 覆盖暴力、色情、仇恨、自残等类别
   - 测试不同语言、不同场景

3. **隐私测试**
   - 训练数据提取
   - 成员推断
   - PII 泄露测试

4. **偏见测试**
   - 性别、种族、地域等维度的偏见评估
   - 公平性指标量化

5. **应用安全测试**
   - 提示注入
   - 插件安全
   - API 安全
   - 越权访问

#### 5.4.3 红队频率与深度

| 类型 | 频率 | 深度 | 参与人员 |
|------|------|------|---------|
| 自动化红队 | 持续/每日 | 浅-中 | 工具自动执行 |
| 常规红队 | 每季度/半年 | 中 | 内部安全团队 |
| 深度红队 | 每年/重大更新 | 深 | 专业红队/第三方 |
