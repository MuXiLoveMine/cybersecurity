# 模型安全（Model Security）

### 2.1 训练安全

训练阶段是 AI 安全的第一道防线。训练过程的安全性直接决定了模型本身的安全性。

#### 2.1.1 训练数据安全

**数据来源管控：**
- 数据来源验证：确保数据来自可信来源
- 数据授权检查：确保数据使用符合法律法规
- 数据质量评估：评估数据的完整性和准确性

**数据清洗与检测：**
- **异常值检测**
  - 统计方法：Z-score、IQR、孤立森林
  - 距离方法：DBSCAN、LOF
  - 基于密度的检测

- **投毒检测**
  - 标签一致性检查：相似样本应有相似标签
  - 影响函数分析：评估每个样本对模型的影响
  - 异常样本筛选：识别对模型影响异常大的样本

- **后门检测**
  - 触发器逆向搜索
  - 神经元激活分析
  - 输入输出相关性分析

**数据增强与扩充：**
- 使用数据增强增加数据多样性
- 降低对单一数据源的依赖
- 提高模型的泛化能力和鲁棒性

#### 2.1.2 训练过程安全

**训练环境安全：**
- 隔离训练环境，防止未授权访问
- 训练过程监控，检测异常行为
- 训练数据和模型的访问控制

**训练算法安全：**
- 选择安全的训练算法
- 鲁棒训练方法（如对抗训练）
- 隐私保护训练方法（如差分隐私）

**模型验证：**
- 使用独立的验证集评估模型性能
- 安全性测试（对抗鲁棒性、后门检测等）
- 偏见和公平性评估

### 2.2 推理安全

推理阶段是模型对外服务的阶段，也是最容易受到攻击的阶段。

#### 2.2.1 输入安全防护

**输入验证：**
- 格式验证：检查输入格式是否符合预期
- 范围验证：检查输入是否在合理范围内
- 内容验证：检测输入中的恶意内容

**对抗样本防御：**
- **输入预处理**
  - 图像去噪、压缩
  - 特征压缩
  - 随机变换

- **对抗样本检测**
  - 基于统计特征的检测
  - 基于不确定性的检测
  - 基于重建误差的检测
  - 专用检测模型

- **鲁棒模型**
  - 对抗训练的模型
  - 鲁棒性认证的模型
  - 集成模型

**提示注入防护（LLM）：**
- 输入过滤与检测
- 系统提示与用户输入明确分隔
- 输入长度和格式限制
- 指令与数据的区分

#### 2.2.2 输出安全防护

**输出审核：**
- 有害内容检测与过滤
- 敏感信息检测与脱敏
- 事实准确性核查（可选）

**输出限制：**
- 输出长度限制
- 输出格式限制
- 输出频率限制（防数据爬取）

**输出水印：**
- 文本水印（用于检测生成内容）
- 模型水印（用于知识产权保护）

#### 2.2.3 推理过程保护

**模型保护：**
- 模型加密存储
- 运行时内存保护
- 防止模型权重泄露

**查询保护：**
- 查询频率限制
- 查询内容审计
- 异常查询检测（防止模型窃取）

### 2.3 部署安全

#### 2.3.1 部署模式安全

**云端部署：**
- API 网关安全
- 身份认证与授权
- 流量控制与限流
- DDoS 防护

**边缘/端侧部署：**
- 模型加密与混淆
- 运行时保护
- 防调试、防篡改
- 安全升级机制

**私有化部署：**
- 网络隔离
- 访问控制
- 数据本地化
- 安全审计

#### 2.3.2 API 安全

**认证与授权：**
- API Key 认证
- OAuth 2.0 / JWT
- 细粒度权限控制
- 基于角色的访问控制（RBAC）

**流量管理：**
- 速率限制（Rate Limiting）
- 配额管理（Quota）
- 请求熔断
- 负载均衡

**安全防护：**
- WAF（Web 应用防火墙）
- 输入验证
- SQL 注入/XSS 防护
- Bot 检测

#### 2.3.3 供应链安全

**模型供应链：**
- 预训练模型来源验证
- 模型完整性校验（哈希签名）
- 模型安全扫描（后门检测等）
- SBOM（软件物料清单）

**第三方组件：**
- 依赖库安全扫描
- 版本管理
- 漏洞跟踪与修复
- 最小依赖原则
