# 数据安全（Data Security）

### 3.1 数据投毒防御

数据投毒是针对训练阶段的重要攻击方式，防御需要从数据获取、数据处理到训练验证的全流程入手。

#### 3.1.1 数据获取阶段

**数据来源管理：**
- 建立可信数据源白名单
- 数据获取过程可追溯
- 数据提供者身份验证
- 数据授权合规检查

**数据量控制：**
- 限制单一来源的数据比例
- 避免对某一数据源的过度依赖
- 多样化数据来源

#### 3.1.2 数据处理阶段

**数据清洗：**
- 去重：移除重复数据
- 异常值检测与处理
- 标签质量验证
- 一致性检查

**数据增强：**
- 增加数据多样性
- 减少模型对特定模式的依赖
- 提高模型的泛化能力

**数据验证：**
- 交叉验证不同来源的数据
- 抽样人工审核
- 统计特征一致性检查

#### 3.1.3 训练与检测阶段

**鲁棒训练方法：**
- 异常样本降权
- 鲁棒损失函数
- 集成学习（降低单一数据的影响）

**后门检测技术：**
1. **基于激活的检测**
   - 分析神经元激活模式
   - 识别异常活跃的神经元

2. **基于输入的检测**
   - 逆向工程触发器
   - 输入滤波和预处理

3. **基于模型的检测**
   - 模型权重分析
   - 网络剪枝（后门对剪枝更敏感）

4. **STRIP 方法**
   - 对输入添加各种扰动
   - 观察预测熵的变化
   - 后门样本的预测熵变化更小

### 3.2 隐私保护

#### 3.2.1 差分隐私（Differential Privacy）

**核心概念：**
- 严格的数学隐私保证
- 单个样本的存在不会显著影响输出
- 隐私预算 ε：隐私保护强度的度量

**在 AI 中的应用：**
- **DP-SGD**：训练过程中添加噪声
- **输出扰动**：模型预测结果加噪声
- **数据发布**：统计数据的隐私保护

**优缺点：**
| 优点 | 缺点 |
|------|------|
| 严格的数学保证 | 影响模型精度 |
| 可量化的隐私度量 | 计算开销大 |
| 应用场景广泛 | 隐私预算管理复杂 |

#### 3.2.2 联邦学习（Federated Learning）

**核心概念：**
- 数据不出本地，模型到数据端训练
- 各方只交换模型参数或梯度
- 保护数据隐私

**架构类型：**
- **横向联邦**：样本重叠少，特征重叠多（不同用户，相同业务）
- **纵向联邦**：样本重叠多，特征重叠少（相同用户，不同业务）
- **联邦迁移学习**：样本和特征重叠都少

**安全风险：**
- 梯度泄露：从梯度中反推数据
- 成员推断：判断样本是否参与训练
- 投毒攻击：恶意客户端投毒全局模型

**增强安全的技术：**
- 差分隐私：在梯度中加噪声
- 同态加密：加密梯度计算
- 安全多方计算（MPC）
- 安全聚合

#### 3.2.3 数据脱敏与匿名化

**常用技术：**

| 技术 | 说明 | 适用场景 |
|------|------|---------|
| 遮盖（Masking） | 替换部分字符（如 138****1234） | 展示、日志 |
| 替换（Substitution） | 用虚构数据替换真实数据 | 测试、开发 |
| 打乱（Shuffling） | 打乱数据顺序，破坏对应关系 | 统计分析 |
| 泛化（Generalization） | 将具体值替换为范围（如 25-30 岁） | 数据发布 |
| 删除（Deletion） | 直接删除敏感字段 | 非必要字段 |
| 加密（Encryption） | 密码学加密 | 存储、传输 |

**注意：匿名化 ≠ 安全**
- 重标识攻击（Re-identification）：通过其他信息重新识别个体
- k-匿名、l-多样性、t-接近性等更高级的隐私模型

#### 3.2.4 同态加密与安全多方计算

**同态加密（Homomorphic Encryption）：**
- 可以在加密数据上直接计算
- 计算结果解密后与明文计算结果一致
- 完全保护数据隐私
- 缺点：计算开销极大

**安全多方计算（Secure Multi-Party Computation，MPC）：**
- 多方共同计算一个函数
- 各方只知道自己的输入和最终结果
- 不泄露其他方的输入信息
