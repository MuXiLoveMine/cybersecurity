# 应用安全（Application Security）

### 4.1 API 安全

#### 4.1.1 认证与授权

**认证方式：**
- API Key：简单但安全性较低
- OAuth 2.0：更安全的授权框架
- JWT（JSON Web Token）：无状态认证
- mTLS（双向 TLS）：高安全场景

**授权原则：**
- 最小权限原则：只授予必要的权限
- 职责分离：不同角色有不同权限
- 细粒度控制：精确到 API 级别甚至参数级别

#### 4.1.2 输入验证与过滤

**输入验证：**
- 格式验证（正则表达式、schema 验证）
- 长度限制
- 类型检查
- 范围校验

**注入防护：**
- SQL 注入：参数化查询、ORM
- XSS：输出编码、CSP
- 提示注入：输入检测、输出审核
- 命令注入：避免系统调用、参数白名单

#### 4.1.3 速率限制与配额

**为什么需要：**
- 防止滥用和恶意爬取
- 保护后端资源不被耗尽
- 防止模型窃取攻击（需要大量查询）

**实现方式：**
- 固定窗口计数
- 滑动窗口计数
- 令牌桶算法
- 漏桶算法

**粒度：**
- 按用户/API Key 限制
- 按 IP 限制（注意 NAT 问题）
- 按时间段限制（日/月/分钟）

### 4.2 访问控制

#### 4.2.1 身份管理

**用户身份：**
- 统一身份认证（SSO）
- 多因素认证（MFA）
- 账号生命周期管理

**服务身份：**
- 服务账号管理
- 密钥定期轮换
- 最小权限配置

#### 4.2.2 权限控制模型

**ACL（访问控制列表）：**
- 简单直接
- 适用于简单场景

**RBAC（基于角色的访问控制）：**
- 用户 → 角色 → 权限
- 易于管理，适合企业场景

**ABAC（基于属性的访问控制）：**
- 根据用户属性、资源属性、环境属性动态决策
- 更灵活，适合复杂场景

**推荐：**
- 一般场景用 RBAC
- 复杂场景用 ABAC
- 都需要遵循最小权限原则

### 4.3 内容安全

#### 4.3.1 输入内容安全

**检测维度：**
- 涉政敏感内容
- 暴力恐怖内容
- 色情低俗内容
- 违法违规内容
- 谩骂攻击内容

**技术手段：**
- 关键词匹配（简单但易绕过）
- 文本分类模型（更准确）
- 多模态检测（图文音视频）
- 人工审核（高风险场景）

#### 4.3.2 输出内容安全

**安全审核：**
- 有害内容检测与拦截
- 敏感信息脱敏
- 事实核查（关键场景）

**内容溯源：**
- 生成内容标识（水印）
- 生成记录留存
- 可追溯审计

#### 4.3.3 深度伪造检测

**检测方法：**
- 基于生理特征的检测（眨眼、呼吸等）
- 基于 artifacts 的检测（生成伪影）
- 基于频率域的检测
- 多模态一致性检测
- 数字水印验证

### 4.4 插件/工具安全（LLM 应用）

随着 AI Agent 和插件生态的发展，插件安全变得越来越重要。

#### 4.4.1 插件风险

| 风险类型 | 说明 |
|---------|------|
| 提示注入 | 插件返回内容中包含恶意指令 |
| 权限滥用 | 插件权限过大，被利用执行危险操作 |
| 数据泄露 | 插件获取过多数据并外传 |
| 恶意插件 | 插件本身就是恶意的 |

#### 4.4.2 插件安全设计

**最小权限原则：**
- 每个插件只授予必要的权限
- 敏感操作需要用户确认
- 插件之间权限隔离

**输入输出隔离：**
- 插件输出视为不可信数据
- 对插件输出进行安全检查
- 明确区分指令和数据

**插件审核：**
- 插件上架前安全审核
- 代码审计
- 行为分析

**用户确认机制：**
- 敏感操作（发送邮件、支付等）需要用户二次确认
- 让用户知道插件在做什么
- 提供撤销和回滚能力
