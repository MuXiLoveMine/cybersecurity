# CTF竞赛模式详解

### 1.1 解题模式（Jeopardy）

解题模式是最常见的CTF竞赛形式，以一系列独立的安全挑战题目组成，选手通过解题获取flag。

**规则与特点：**

- 题目按方向分类：Web、Pwn、Reverse、Crypto、Misc、Forensics
- 每题有固定分值，通常按难度分低/中/高三档
- 首次解出（First Blood / 一血）通常有额外加分
- 题目可能有动态分值（解题人数越多分值越低）
- 比赛时长通常24-48小时
- 允许组队参赛（通常3-5人）
- 排名按总积分排序

**动态分值计算公式（常见）：**

```
Score = max_points × (1 - (solve_count / total_teams) × decay_rate)
```

例如：初始500分，每有1%的队伍解出，分值下降5分，最低100分。

**解题模式特点总结：**

| 优点 | 缺点 |
|------|------|
| 适合大规模参赛 | 缺乏实时对抗感 |
| 题目覆盖面广 | 偏重个人能力 |
| 参赛门槛较低 | 时间管理要求高 |
| 公平性较好 | 高分题差异不大 |

### 1.2 攻防模式（Attack-Defense）

攻防模式是最激烈的CTF竞赛形式，每支队伍同时运行相同的一组服务，既要攻击其他队伍获取flag，又要防守自己的服务。

**规则与策略：**

- 每队获得相同的一组服务（通常4-8个）
- 每个服务有一个或多个flag，flag定期轮换（通常每5-10分钟）
- 攻击：利用漏洞攻入对方服务，读取flag并提交到评分系统得分
- 防守：修补自己服务的漏洞，防止被攻击
- 运维：保持服务可用性，服务不可用会被扣分

**攻防模式计分体系：**

```
每轮得分 = 攻击得分 - 防守失分 - 运维扣分

攻击得分 = 成功攻击队伍数 × 单次攻击分值
防守失分 = 被攻击成功次数 × 单次被攻分值
运维扣分 = 服务不可用时间 × 扣分率
```

**攻防模式特点：**

| 优点 | 缺点 |
|------|------|
| 实时对抗激烈 | 需要全面能力 |
| 综合考察安全技能 | 服务器运维压力大 |
| 考验团队配合 | 参赛门槛高 |
| 观赏性强 | 0day策略可能决定胜负 |

### 1.3 King of the Hill（KotH）模式

KotH模式是一种持续的攻防对抗，目标是控制目标机器并保持控制时间最长。

**规则与特点：**

- 比赛中有一台或多台目标机器
- 各队通过攻击获取目标机器的控制权
- 控制方在机器上放置自己的flag（"占领"机器）
- 占领时间越长得分越高
- 其他队伍可以攻击占领者夺取控制权
- 通常是2-8小时的短时竞赛

**KotH策略要点：**
- 快速攻入是第一步（速度优先）
- 加固防守保住阵地是第二步（持久化优先）
- 持续监控入侵者是第三步（检测优先）
- 准备反制手段是第四步（对抗优先）

### 1.4 解题+攻防混合模式

越来越多的比赛采用混合模式，先通过解题阶段筛选，再进入攻防阶段决赛。

**典型混合赛制：**

```
预赛（线上解题） → 选拔TOP N队伍
    ↓
半决赛（线上攻防） → 选拔TOP M队伍
    ↓
决赛（线下攻防） → 最终排名
```

**混合模式的优势：**
- 解题阶段考察面广，攻防阶段考察深度
- 降低了纯攻防模式中0day决定一切的不确定性
- 更全面地评估队伍综合实力
