## 一、国内核心法律体系

### 1.1 法律体系总览

中国网络安全法律体系呈现"三法叠加 + 配套法规"的格局：

```
顶层法律
├── 《中华人民共和国网络安全法》（2017 施行，2025 修订）
├── 《中华人民共和国数据安全法》（2021 施行）
└── 《中华人民共和国个人信息保护法》（2021 施行）

配套行政法规
├── 《关键信息基础设施安全保护条例》（2021）
├── 《网络安全等级保护条例》
├── 《数据安全管理条例》
└── 《商用密码管理条例》

部门规章与规范性文件
├── 公安部、网信办、工信部等发布的规章和规范性文件
└── 技术标准（GB 系列国家标准）
```

| 法律 | 简称 | 施行日期 | 核心主题 | 监管部门 |
|------|------|---------|---------|---------|
| 《网络安全法》 | 网安法 | 2017.6.1（2026.1.1 修订版施行） | 网络空间安全、网络运行安全、信息安全 | 网信办、公安部、工信部 |
| 《数据安全法》 | 数安法 | 2021.9.1 | 数据安全、数据分类分级、数据出境 | 网信办、各行业主管部门 |
| 《个人信息保护法》 | 个保法 | 2021.11.1 | 个人信息保护、跨境传输、个人权利 | 网信办、市场监管总局 |

> **三法关系**：
> - 网安法是网络安全领域的基础性、综合性法律
> - 数安法是数据安全领域的基础性法律
> - 个保法是个人信息保护的专门法律
> - 三者相互关联、各有侧重，共同构成中国网络与数据安全的法律框架

### 1.2 《网络安全法》

#### 基本信息

| 项目 | 内容 |
|------|------|
| **全称** | 中华人民共和国网络安全法 |
| **通过日期** | 2016 年 11 月 7 日 |
| **施行日期** | 2017 年 6 月 1 日 |
| **修订日期** | 2025 年（首次修订） |
| **修订版施行** | 2026 年 1 月 1 日 |
| **章节** | 7 章，共计 79 条（修订后） |

#### 核心制度

| 制度 | 说明 |
|------|------|
| **网络安全等级保护制度** | 所有网络运营者都要按等级保护要求履行安全义务 |
| **关键信息基础设施重点保护** | 关键信息基础设施在等保基础上实行重点保护 |
| **网络产品和服务安全** | 网络产品和服务应当符合国家标准，不得设置恶意程序 |
| **网络安全监测预警与应急处置** | 建立网络安全监测预警和信息通报制度 |
| **个人信息保护** | 网络运营者收集、使用个人信息的规则 |
| **关键信息基础设施数据境内存储** | CII 运营者在境内运营中收集和产生的重要数据应当境内存储 |

#### 2025 年修订的关键变化（2026 年 1 月 1 日施行）

| 变化 | 说明 |
|------|------|
| **新增人工智能专门条款** | 对生成式 AI 等新技术新应用的安全管理提出要求，明确算法安全治理 |
| **大幅提高罚款额度** | 最高罚款金额提高到 1000 万元，大幅提升违法成本 |
| **完善关键信息基础设施保护** | 进一步细化 CII 保护制度和运营者义务 |
| **强化数据安全和个人信息保护** | 与《数据安全法》《个人信息保护法》衔接 |
| **加大对网络违法犯罪的打击力度** | 完善相关法律责任条款 |
| **完善网络安全治理体系** | 强化多方参与、协同治理 |

> **⚠️ 2026 年时效性标注**：《网络安全法》修订版已于 2025 年通过，自 2026 年 1 月 1 日起施行。这是该法实施以来的首次修订，新增了人工智能安全等内容，罚款幅度显著提高。各单位应及时对照修订内容进行合规整改。

#### 重要义务（网络运营者通用义务）

| 义务 | 条款依据 | 具体要求 |
|------|---------|---------|
| 等级保护义务 | 第 21 条 | 按等级保护制度要求履行安全保护义务 |
| 实名制义务 | 第 24 条 | 为用户提供服务时要求用户提供真实身份信息 |
| 个人信息保护义务 | 第 40-45 条 | 依法收集、使用、保护个人信息 |
| 事件处置义务 | 第 55 条 | 发生网络安全事件时立即处置，及时告知用户并报告 |
| 配合监督检查 | 第 57 条 | 对监管部门的监督检查予以配合 |

#### 法律责任（部分）

| 违法行为 | 罚款（修订后） | 其他责任 |
|---------|---------------|---------|
| 不履行网络安全保护义务 | 五万元以上五十万元以下罚款 | 直接负责的主管人员处一万元以上十万元以下 |
| 拒不履行信息网络安全管理义务 | 二十万元以上一百万元以下罚款 | 直接负责的主管人员处一万元以上十万元以下 |
| 侵害个人信息依法得到保护的权利 | 一百万元以下罚款；情节严重的一千万元以下 | 直接负责的主管人员和其他直接责任人员处一万元以上一百万元以下 |

> **重要提醒**：修订后的《网络安全法》最高罚款达到 **1000 万元**，违法成本大幅提高。企业应高度重视合规工作。

### 1.3 《数据安全法》

#### 基本信息

| 项目 | 内容 |
|------|------|
| **全称** | 中华人民共和国数据安全法 |
| **通过日期** | 2021 年 6 月 10 日 |
| **施行日期** | 2021 年 9 月 1 日 |
| **章节** | 7 章，共计 55 条 |
| **核心地位** | 数据安全领域的基础性法律 |

#### 核心制度

| 制度 | 说明 |
|------|------|
| **数据分类分级保护制度** | 数据分为核心数据、重要数据、一般数据三级，实行差异化保护 |
| **数据安全风险评估制度** | 重要数据处理者应当定期开展风险评估并报送报告 |
| **数据安全审查制度** | 对影响或可能影响国家安全的数据处理活动进行安全审查 |
| **数据出境安全管理制度** | 重要数据出境需要安全评估 |
| **数据交易管理制度** | 规范数据交易行为 |
| **政务数据安全与开放** | 政务数据的安全保护和开放共享 |

#### 数据处理者的主要义务

| 义务 | 说明 |
|------|------|
| **建立健全全流程数据安全管理制度** | 包括数据安全负责人和管理机构 |
| **组织开展数据安全教育培训** | 对员工进行数据安全培训 |
| **采取相应的技术措施** | 保护数据安全的技术手段 |
| **风险评估与报告** | 重要数据处理者定期开展风险评估，报告评估情况 |
| **数据安全事件处置** | 发生数据安全事件时立即处置并报告 |
| **数据出境安全** | 重要数据出境应当通过安全评估 |

#### 数据分类分级（核心制度之一）

| 级别 | 定义 | 保护要求 |
|------|------|---------|
| **核心数据** | 关系国家安全、国民经济命脉、重要民生、重大公共利益等数据 | 实行更加严格的管理制度 |
| **重要数据** | 一旦遭到篡改、破坏、泄露或者非法获取、非法利用，可能危害国家安全、公共利益的数据 | 重点保护，风险评估、出境评估 |
| **一般数据** | 对国家安全、公共利益影响较小的数据 | 常规保护 |

> 详见本文第五章"数据分类分级"。

#### 法律责任

| 违法行为 | 罚款 | 其他责任 |
|---------|------|---------|
| 不履行数据安全保护义务 | 五万元以上五十万元以下 | 直接责任人员一万元以上十万元以下 |
| 重要数据处理者不按规定开展风险评估等 | 五十万元以上二百万元以下 | 直接责任人员五万元以上二十万元以下 |
| 违反国家核心数据管理制度 | 二百万元以上一千万元以下 | 直接责任人员十万元以上一百万元以下 |
| 向境外提供重要数据未经安全评估 | 五十万元以上五百万元以下 | 直接责任人员五万元以上五十万元以下 |

### 1.4 《个人信息保护法》

#### 基本信息

| 项目 | 内容 |
|------|------|
| **全称** | 中华人民共和国个人信息保护法 |
| **通过日期** | 2021 年 8 月 20 日 |
| **施行日期** | 2021 年 11 月 1 日 |
| **章节** | 8 章，共计 74 条 |
| **核心地位** | 个人信息保护领域的专门法律 |

#### 核心原则

| 原则 | 说明 |
|------|------|
| **合法、正当、必要、诚信原则** | 处理个人信息要有合法理由，不能欺诈、胁迫 |
| **目的明确原则** | 处理目的要明确、具体，不能超出范围 |
| **最小必要原则** | 只收集实现处理目的所必要的最小范围信息 |
| **公开透明原则** | 公开个人信息处理规则，告知处理情况 |
| **质量保证原则** | 保证个人信息准确、完整、及时更新 |
| **安全保障原则** | 采取必要措施保障个人信息安全 |
| **责任自负原则** | 谁处理谁负责，个人信息处理者承担责任 |

#### 个人信息处理规则

| 规则 | 说明 |
|------|------|
| **告知同意** | 处理个人信息应当取得个人同意（法律另有规定除外） |
| **单独同意** | 敏感个人信息处理、向第三方提供、公开、出境等需要单独同意 |
| **敏感个人信息** | 生物识别、宗教信仰、特定身份、医疗健康、金融账户、行踪轨迹等，需特别保护 |
| **个人权利** | 知情权、决定权、查阅权、复制权、更正权、删除权、可携带权等 |
| **自动化决策** | 保证决策透明度和结果公平，不得对个人不合理差别待遇 |
| **跨境传输** | 需满足安全评估、标准合同、认证等条件之一 |

#### 个人信息跨境传输的合法路径

| 路径 | 适用场景 | 依据 |
|------|---------|------|
| **国家网信部门组织的安全评估** | 关键信息基础设施运营者、处理个人信息达到规定数量的 | 第 38 条第 1 项 |
| **经专业机构进行个人信息保护认证** | 一般企业，达到一定体量 | 第 38 条第 2 项 |
| **按照国家网信部门制定的标准合同与境外接收方订立合同** | 中小企业，数据量不大 | 第 38 条第 3 项 |
| **法律、行政法规或者国家网信部门规定的其他条件** | 其他情况 | 第 38 条第 4 项 |

#### 法律责任

| 违法行为 | 罚款 | 其他责任 |
|---------|------|---------|
| 违法处理个人信息 | 责令改正，给予警告；拒不改正的，一百万元以下罚款 | 直接责任人员一万元以上十万元以下 |
| 情节严重的 | 五千万元以下或者上一年度营业额百分之五以下罚款 | 直接责任人员十万元以上一百万元以下罚款，并可禁止担任董监高 |

> **注意**：个保法的最高罚款是 **5000 万或上一年度营业额 5%**（取较高者），这是三法中罚款最高的，与欧盟 GDPR 看齐。

## 二、等级保护制度（等保 2.0）

### 2.1 等级保护制度概述

**网络安全等级保护制度**是中国网络安全领域的**基本制度**，由《网络安全法》明确规定，是所有网络运营者必须履行的法定义务。

| 项目 | 内容 |
|------|------|
| **制度名称** | 网络安全等级保护制度（简称"等保"） |
| **法律依据** | 《网络安全法》第 21 条 |
| **现行版本** | 等保 2.0（2019 年发布新标准） |
| **核心标准** | GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》 |
| | GB/T 28448-2019《信息安全技术 网络安全等级保护测评要求》 |
| **监管部门** | 公安机关（网安部门） |

> **"等保 2.0" vs "等保 1.0"**：
> - 1.0 时代：主要关注传统的信息系统，偏技术
> - 2.0 时代：覆盖云计算、移动互联、物联网、工业控制系统、大数据等新技术新应用，技术 + 管理并重
> - 2.0 核心变化：一个中心（安全管理中心）三重防护（安全计算环境、安全区域边界、安全通信网络）

### 2.2 五级划分

根据网络（信息系统）受到破坏后对**国家安全、社会秩序、公共利益**及**公民、法人和其他组织的合法权益**的危害程度，分为五个等级：

| 等级 | 名称 | 危害程度 | 典型对象 | 测评要求 |
|------|------|---------|---------|---------|
| **第一级** | 自主保护级 | 公民、法人和其他组织的合法权益造成损害，但不损害国家安全、社会秩序和公共利益 | 小型企业官网、个人网站 | 自主测评 |
| **第二级** | 指导保护级 | 公民、法人和其他组织的合法权益造成严重损害，或者对社会秩序和公共利益造成损害，但不损害国家安全 | 中小型企业业务系统、县级单位 | 建议测评，监管部门指导 |
| **第三级** | 监督保护级 | 对社会秩序和公共利益造成严重损害，或者对国家安全造成损害 | 地市级单位、大中型企业核心系统 | **强制测评，每年至少一次** |
| **第四级** | 强制保护级 | 对社会秩序和公共利益造成特别严重损害，或者对国家安全造成严重损害 | 省级及以上单位、金融、电力等 | **强制测评，每半年至少一次** |
| **第五级** | 专控保护级 | 对国家安全造成特别严重损害 | 国家核心机密系统 | 专门管理 |

> **实际工作中**：
> - 一级和五级都很少见
> - 二级是大量的中小企业和一般系统
> - 三级是最常见的"强制测评"等级（大部分企业的核心系统是三级）
> - 四级主要是高安全要求的行业（金融、电力、能源、政府等）

### 2.3 等保工作五个环节

```
定级 → 备案 → 建设整改 → 等级测评 → 监督检查
  │      │        │          │           │
  │      │        │          │           └── 公安机关定期检查
  │      │        │          └── 第三方测评机构出具测评报告
  │      │        └── 按等保要求建设和整改
  │      └── 到公安机关备案，拿备案证明
  └── 确定系统的安全保护等级
```

#### 环节一：定级

- **方法**：自主定级 + 专家评审（二级以上）
- **依据**：业务信息安全等级 + 系统服务安全等级，取较高者
- **输出**：定级报告

#### 环节二：备案

- **受理部门**：公安机关网安部门
- **材料**：定级报告、备案表、系统拓扑等
- **输出**：备案证明（备案号）
- **要求**：二级及以上系统应当备案

#### 环节三：建设整改

- **内容**：按照对应等级的基本要求进行安全建设和整改
- **范围**：技术 + 管理，十大类要求
- **输出**：整改后的系统 + 安全管理制度文档

#### 环节四：等级测评

- **主体**：具有等保测评资质的第三方机构
- **方法**：现场测评 + 工具测试 + 文档审查 + 人员访谈
- **结论**：优、良、中、差（或符合/不符合）
- **频率**：三级每年至少 1 次，四级每半年至少 1 次

#### 环节五：监督检查

- **主体**：公安机关
- **内容**：检查备案情况、等级测评情况、安全保护状况
- **方式**：日常检查、专项检查

### 2.4 等保 2.0 技术要求框架（"一个中心，三重防护"）

```
                     安全管理中心
                           │
  ┌────────────────────────┼────────────────────────┐
  │                        │                        │
  ▼                        ▼                        ▼
安全计算环境          安全区域边界             安全通信网络

（内部系统安全）     （边界防护与访问控制）    （通信网络安全）
```

十大类安全要求（技术 5 类 + 管理 5 类）：

| 类别 | 大类 | 包含内容 |
|------|------|---------|
| **技术要求** | 安全物理环境 | 机房位置、物理访问控制、防盗窃防破坏、防雷防火、电力供应等 |
| | 安全通信网络 | 网络架构、通信传输、可信验证 |
| | 安全区域边界 | 边界防护、访问控制、入侵防范、恶意代码防范、安全审计 |
| | 安全计算环境 | 身份鉴别、访问控制、安全审计、入侵防范、恶意代码防范、数据完整性、数据保密性等 |
| | 安全管理中心 | 系统管理、审计管理、安全管理、集中管控 |
| **管理要求** | 安全管理制度 | 安全策略、管理制度、操作规程、评审和修订 |
| | 安全管理机构 | 岗位设置、人员配备、授权和审批、沟通合作 |
| | 安全管理人员 | 人员录用、人员离岗、安全意识培训、外部人员访问管理 |
| | 安全建设管理 | 定级备案、方案设计、产品采购、软件开发、工程实施、测试验收 |
| | 安全运维管理 | 环境管理、资产管理、介质管理、设备管理、漏洞管理、事件处置 |

### 2.5 等保 2.0 扩展要求

等保 2.0 针对新技术新应用增加了扩展要求：

| 扩展场景 | 说明 |
|---------|------|
| **云计算安全扩展要求** | 云平台、云服务客户的安全责任，虚拟化、云管理平台安全等 |
| **移动互联安全扩展要求** | 移动终端、移动应用、无线接入安全等 |
| **物联网安全扩展要求** | 感知节点、网关节点、感知网络安全等 |
| **工业控制系统安全扩展要求** | 现场设备、控制网络、管理网络安全等 |

### 2.6 等保工作常见误区

| 误区 | 事实 |
|------|------|
| "等保就是买个测评报告" | 等保是一个体系，测评只是验证环节，建设整改才是核心 |
| "等保 2.0 比 1.0 要求低了" | 等保 2.0 要求更高更全面，增加了很多新要求（管理中心、新技术等） |
| "通过了等保就绝对安全" | 等保是基线要求（及格线），不是绝对安全；通过等保不等于不会被攻破 |
| "小系统不用做等保" | 所有网络运营者都有等保义务，一级也有一级的要求（只是不用强制测评） |
| "做了等保就一劳永逸" | 等保是持续的过程，需要定期测评、持续改进 |
| "等保只需要技术部门管" | 等保涉及技术 + 管理，需要全公司参与，管理层支持 |

### 3.1 主要国际标准对比

| 标准/框架 | 全称 | 发布机构 | 性质 | 适用场景 |
|----------|------|---------|------|---------|
| **ISO/IEC 27001** | 信息安全管理体系要求 | ISO/IEC | 国际标准，可认证 | 建立和认证信息安全管理体系（ISMS） |
| **NIST CSF 2.0** | 网络安全框架 | NIST（美国国家标准与技术研究院） | 框架/指南，非强制 | 网络安全风险管理、成熟度评估 |
| **ISO/IEC 27002** | 信息安全控制实用规则 | ISO/IEC | 实践指南 | 配合 27001 使用，具体控制措施 |
| **COBIT** | 信息及相关技术控制目标 | ISACA | 治理框架 | IT 治理与合规 |
| **ITIL** | IT 基础设施库 | AXELOS | 服务管理框架 | IT 服务管理 |
| **GDPR** | 通用数据保护条例 | 欧盟 | 法律（强制） | 欧盟个人数据保护，跨境业务适用 |
| **PCI DSS** | 支付卡行业数据安全标准 | PCI SSC | 行业标准（强制，支付行业） | 银行卡支付数据安全 |

### 3.2 ISO/IEC 27001

#### 基本信息

| 项目 | 内容 |
|------|------|
| **全称** | ISO/IEC 27001 Information technology — Security techniques — Information security management systems — Requirements |
| **当前版本** | ISO/IEC 27001:2022（2022 年发布） |
| **作用** | 建立、实施、维护和持续改进信息安全管理体系（ISMS） |
| **认证** | 可第三方认证，认证有效期 3 年，每年监督审核 |
| **核心思想** | PDCA（计划-执行-检查-行动）+ 风险驱动 |

#### ISMS 架构

```
ISO 27001 框架
├── 4. 组织环境
├── 5. 领导作用
├── 6. 规划
│   └── 6.1 应对风险和机遇的措施
│   └── 6.2 信息安全目标
├── 7. 支持
│   └── 资源、能力、意识、沟通、文件化信息
├── 8. 运行
│   └── 8.1 运行规划和控制
│   └── 8.2 信息安全风险评估
│   └── 8.3 信息安全风险处理
├── 9. 绩效评价
│   └── 监视、测量、分析、内部审核、管理评审
└── 10. 改进
    └── 持续改进、不符合和纠正措施
```

#### 控制目标与控制措施（Annex A）

ISO 27001 附录 A 列出了 93 项控制措施（2022 版），分为 4 个主题：

| 主题 | 控制数量 | 说明 |
|------|---------|------|
| **人员**（People） | 8 项 | 人员安全相关 |
| **物理**（Physical） | 14 项 | 物理安全、设备安全 |
| **技术**（Technological） | 34 项 | 技术控制措施 |
| **组织**（Organizational） | 37 项 | 管理、治理、合规相关 |

> **ISO 27001 与等保 2.0 的关系**：
> - 相同点：都是信息安全管理体系，都强调风险管理和持续改进
> - 不同点：
>   - ISO 27001 是国际标准，强调管理体系，适合企业整体安全管理
>   - 等保是中国法定要求，偏技术要求，有明确的等级划分和监管
>   - 做等保的企业可以同时建 ISO 27001 体系，很多控制措施可以复用

### 3.3 NIST CSF 2.0

#### 基本信息

| 项目 | 内容 |
|------|------|
| **全称** | NIST Cybersecurity Framework (CSF) 2.0 |
| **发布机构** | NIST（美国国家标准与技术研究院） |
| **发布时间** | 2024 年 2 月（2.0 版本） |
| **性质** | 自愿性框架/指南（非强制，但被广泛采用） |
| **核心价值** | 用业务语言讲安全，帮助组织理解和管理网络安全风险 |

#### CSF 六大核心功能（2.0 版从 5 个增加到 6 个）

| 功能 | 英文 | 说明 |
|------|------|------|
| **识别** | Identify (ID) | 理解业务环境，识别资产、风险、治理 |
| **保护** | Protect (PR) | 实施安全控制，确保关键服务交付 |
| **检测** | Detect (DE) | 及时发现安全事件 |
| **响应** | Respond (RS) | 安全事件发生后采取行动 |
| **恢复** | Recover (RC) | 事件后恢复能力，韧性建设 |
| **治理** | Govern (GV) | 【2.0 新增】网络安全治理、战略、监督 |

> 原来 1.0 版是 5 个功能（识别→保护→检测→响应→恢复），2.0 版新增了"治理"功能，强调治理的重要性。

#### CSF 的三层结构

```
框架层 (Framework Tier) — 成熟度等级（Partial/Risk-Informed/Repeatable/Adaptive）
    │
框架实现层 (Framework Implementation Tiers)
    │
框架核心 (Framework Core) — 功能→类别→子类→参考资源
```

> **适用场景**：
> - 企业安全成熟度评估
> - 安全战略规划和路线图制定
> - 安全投入优先级排序
> - 与业务目标对齐的安全管理
> - 供应链安全管理

### 3.4 GDPR（欧盟通用数据保护条例）

| 项目 | 内容 |
|------|------|
| **全称** | General Data Protection Regulation（通用数据保护条例） |
| **地区** | 欧盟（EU） |
| **生效日期** | 2018 年 5 月 25 日 |
| **适用范围** | 处理欧盟居民个人数据的任何组织（不论所在地） |
| **罚款上限** | 2000 万欧元或上一年度全球营业额的 4%（取较高者） |

#### GDPR 核心原则

| 原则 | 说明 |
|------|------|
| **合法、公正、透明** | 数据处理要有合法依据，透明告知数据主体 |
| **目的限制** | 为特定、明确、合法的目的收集，不超出目的处理 |
| **数据最小化** | 只收集实现目的所必要的最少数据 |
| **准确性** | 数据准确，及时更新 |
| **存储限制** | 只在必要的时间内存储数据 |
| **完整性和保密性** | 采取适当的技术和组织措施保护数据安全 |
| **问责制** | 数据控制者对遵守上述原则负责，并能证明合规 |

#### 数据主体权利

| 权利 | 说明 |
|------|------|
| **知情权** | 知道自己的数据被如何处理 |
| **访问权** | 访问自己的个人数据 |
| **更正权** | 要求更正不准确的数据 |
| **删除权（被遗忘权）** | 要求删除个人数据 |
| **限制处理权** | 限制对个人数据的处理 |
| **数据可携带权** | 获取并传输个人数据 |
| **反对权** | 反对处理个人数据 |
| **不受自动化决策约束权** | 反对仅基于自动化处理做出对其有法律或类似重大影响的决定 |

> **中国企业需要关注 GDPR 吗？**
> 如果你的业务涉及欧盟用户（比如有欧洲客户、在欧洲有业务、网站面向欧洲用户），就需要遵守 GDPR。GDPR 有域外效力——不在欧盟但处理欧盟居民数据的组织也受管辖。

### 3.5 各标准适用场景对比

| 标准/法规 | 性质 | 适用场景 | 是否强制 |
|----------|------|---------|---------|
| **等保 2.0** | 国家制度 | 中国境内所有网络运营者 | 是（法定义务） |
| **ISO 27001** | 国际标准 | 建立信息安全管理体系，企业整体安全管理 | 否（自愿认证，但很多客户要求） |
| **NIST CSF** | 框架指南 | 网络安全风险管理、成熟度评估、战略规划 | 否（自愿采用） |
| **GDPR** | 欧盟法律 | 处理欧盟居民个人数据的组织 | 是（适用范围内强制） |
| **PCI DSS** | 行业标准 | 处理银行卡支付数据的商家 | 是（支付行业强制） |
| **CII 保护** | 国家制度 | 关键信息基础设施运营者 | 是（法定义务） |

## 四、关键信息基础设施（CII）保护

### 4.1 CII 概述

**关键信息基础设施（Critical Information Infrastructure, CII）**：公共通信和信息服务、能源、交通、水利、金融、公共服务、电子政务、国防科技工业等重要行业和领域，以及其他一旦遭到破坏、丧失功能或者数据泄露，可能严重危害国家安全、国计民生、公共利益的重要网络设施、信息系统等。

| 项目 | 内容 |
|------|------|
| **法律依据** | 《网络安全法》《关键信息基础设施安全保护条例》 |
| **监管部门** | 公安部（指导监督）、各行业主管部门 |
| **保护级别** | 在等级保护基础上实行重点保护（等保是基线，CII 是更高要求） |

### 4.2 CII 行业范围

根据《关键信息基础设施安全保护条例》，以下行业和领域的重要网络设施、信息系统属于 CII：

| 行业/领域 | 说明 |
|----------|------|
| **公共通信和信息服务** | 电信、互联网等 |
| **能源** | 电力、石油、天然气、煤炭等 |
| **交通** | 铁路、公路、水运、民航、邮政等 |
| **水利** | 水利枢纽、供水等 |
| **金融** | 银行、证券、保险、支付等 |
| **公共服务** | 医疗卫生、社会保障、教育、环境保护等 |
| **电子政务** | 各级党政机关电子政务系统 |
| **国防科技工业** | 国防科工相关 |
| **其他** | 其他严重危害国家安全、国计民生、公共利益的 |

### 4.3 CII 运营者的特别义务

CII 运营者在等保义务的基础上，还需履行更严格的义务：

| 义务 | 说明 | 依据 |
|------|------|------|
| **设置专门安全管理机构** | 设置专门的安全管理机构和负责人 | 条例第 14 条 |
| **负责人和关键岗位人员背景审查** | 对安全管理机构负责人和关键岗位人员进行安全背景审查 | 条例第 14 条 |
| **每年至少进行一次检测评估** | 自行或委托专业机构每年至少进行一次网络安全检测和风险评估 | 条例第 19 条 |
| **重要数据境内存储** | 境内运营中收集和产生的重要数据和个人信息应当在境内存储 | 网安法第 37 条 |
| **数据出境安全评估** | 确需向境外提供的，应当通过安全评估 | 网安法第 37 条 |
| **采购网络产品和服务安全审查** | 采购可能影响国家安全的网络产品和服务，应通过安全审查 | 条例第 20 条 |
| **网络安全事件应急预案** | 制定应急预案，定期演练 | 条例第 23 条 |
| **重大突发事件报告** | 发生重大网络安全事件时按规定报告 | 条例第 25 条 |

### 4.4 主要标准

| 标准编号 | 标准名称 | 作用 |
|----------|---------|------|
| **GB/T 39204-2022** | 信息安全技术 关键信息基础设施安全保护要求 | CII 安全保护的基本要求 |
| **GB/T 20984-2022** | 信息安全技术 信息安全风险评估方法 | 风险评估方法论 |
| **GB/T 39203-2020** | 信息安全技术 关键信息基础设施边界确定方法 | 如何确定 CII 的边界 |
| **GB/T 41479-2022** | 信息安全技术 网络数据处理安全要求 | 网络数据处理安全 |

### 4.5 CII 与等保的关系

```
CII 保护要求（更高）
     ↑
     │ 叠加（在等保基础上增加要求）
     │
等保三级/四级（基线要求）
```

| 维度 | 等保 2.0 | CII 保护 |
|------|---------|---------|
| 法律定位 | 所有网络运营者的基本义务 | 重点行业的重点保护 |
| 保护基线 | 五级，每级有对应要求 | 在等保基础上重点保护 |
| 测评频率 | 三级每年一次，四级每半年一次 | 每年至少一次检测评估 |
| 数据要求 | 一般数据安全要求 | 重要数据境内存储、出境评估 |
| 监管力度 | 公安机关监督检查 | 重点保护、专项检查 |

## 五、数据分类分级

### 5.1 制度背景

**数据分类分级**是《数据安全法》确立的核心制度之一，是数据安全工作的基础。

```
为什么要分类分级？
  - 不同数据的价值和敏感程度不同
  - 保护资源有限，要把好钢用在刀刃上
  - 按级别采取差异化的保护措施
  - 分类分级是数据安全治理的第一步
```

### 5.2 国家数据分类分级框架

| 级别 | 定义 | 保护强度 |
|------|------|---------|
| **核心数据** | 关系国家安全、国民经济命脉、重要民生、重大公共利益等数据 | 🔴 最严格 |
| **重要数据** | 一旦遭到篡改、破坏、泄露或者非法获取、非法利用，可能危害国家安全、公共利益的数据 | 🟡 重点保护 |
| **一般数据** | 对国家安全、公共利益影响较小的数据 | 🟢 常规保护 |

#### 核心数据

**定义**：关系国家安全、国民经济命脉、重要民生、重大公共利益等数据。

**管理要求**：
- 实行更加严格的管理制度
- 由国家数据安全工作协调机制统筹协调有关部门制定核心数据目录
- 核心数据的处理活动需要特别审批

#### 重要数据

**定义**：一旦遭到篡改、破坏、泄露或者非法获取、非法利用，可能危害国家安全、公共利益的数据。

**管理要求**：
- 各地区、各部门制定本地区、本部门以及相关行业、领域的重要数据具体目录
- 重要数据处理者应当定期开展风险评估
- 重要数据出境需要安全评估

#### 一般数据

**定义**：对国家安全、公共利益影响较小的数据。

**管理要求**：
- 按照数据安全一般要求保护
- 各单位可结合自身实际制定更细的分级

### 5.3 行业数据分级示例（企业落地参考）

企业可以在国家三级框架下，结合自身业务进一步细化。常见的企业分级方式：

| 企业分级 | 对应国家分级 | 定义 | 示例 |
|---------|-------------|------|------|
| **L1 公开数据** | 一般数据 | 可对外公开的数据 | 官网公开信息、产品介绍 |
| **L2 内部数据** | 一般数据 | 仅限内部使用，泄露影响不大 | 内部规章制度、普通培训资料 |
| **L3 敏感数据** | 一般数据 / 重要数据（视情况） | 泄露可能造成一定影响 | 客户非敏感信息、业务数据 |
| **L4 重要数据** | 重要数据 | 泄露/篡改可能造成严重影响 | 核心业务数据、大量用户信息 |
| **L5 核心数据** | 核心数据 | 最高级别，泄露可能造成灾难性影响 | 核心算法、国家核心机密 |

> 不同行业、不同企业的具体分级标准不同，应结合行业监管要求和自身实际制定。

### 5.4 分级后的差异化保护措施

| 保护措施 | 一般数据 | 重要数据 | 核心数据 |
|---------|---------|---------|---------|
| 访问控制 | 基本访问控制 | 严格访问控制 + 审计 | 最严格访问控制 + 多人审批 |
| 加密 | 建议加密 | 必须加密（传输 + 存储） | 必须加密 + 更高强度 |
| 审计 | 常规审计 | 详细审计 + 定期审计分析 | 全面审计 + 实时监控 |
| 备份 | 常规备份 | 多副本备份 + 异地备份 | 多地备份 + 离线备份 |
| 出境 | 按规定 | 安全评估 | 严格限制，原则上不出境 |
| 风险评估 | 按需 | 定期（至少每年） | 定期 + 专项评估 |
| 销毁 | 常规删除 | 安全删除/销毁 | 彻底销毁 + 审计记录 |

### 5.5 数据分类分级工作流程

```
1. 成立工作小组（业务 + 安全 + 法务 + IT）
   ↓
2. 识别数据资产（梳理有哪些数据，在哪里，谁负责）
   ↓
3. 制定分类分级规则（结合行业要求和自身实际）
   ↓
4. 数据打标签/赋值（给每类数据定级别）
   ↓
5. 审核与确认（业务部门确认，管理层批准）
   ↓
6. 制定差异化保护措施（按级别实施不同安全控制）
   ↓
7. 定期评审与更新（业务变化、数据变化时更新分级）
```

> **实践建议**：
> - 数据分类分级是业务工作，不只是安全/IT 的事，业务部门必须深度参与
> - 不要追求完美，先粗分再细化
> - 分类分级结果要落地（和访问控制、加密、审计等挂钩），否则就是摆样子
> - 定期重审，数据的价值和敏感程度会随时间变化

## 六、合规实践

### 6.1 合规工作流程

```
差距评估 → 整改规划 → 实施整改 → 测评/认证 → 持续监控
   │          │          │           │            │
   │          │          │           │            └── 日常运营
   │          │          │           └── 验证是否符合要求
   │          │          └── 按计划落实各项整改措施
   │          └── 制定整改计划和优先级
   └── 对照标准找出差距（缺什么）
```

#### 阶段一：差距评估

- **内容**：对照等保/ISO 27001/法规要求，逐项评估现状
- **方法**：文档审查、人员访谈、技术测试、现场检查
- **输出**：差距评估报告（列出不符合项、风险等级、整改建议）

#### 阶段二：整改规划

- **内容**：根据差距评估结果，制定整改计划
- **要素**：整改项、优先级、责任人、时间计划、资源需求、预算
- **原则**：高风险优先、低成本高收益优先、分阶段实施

#### 阶段三：实施整改

- **技术整改**：部署安全设备、加固系统、配置安全策略
- **管理整改**：制定制度文档、成立组织、培训、落实流程
- **人员能力**：培训、意识提升、关键岗位人员到位

#### 阶段四：测评/认证

- **等保**：第三方测评机构进行等级测评
- **ISO 27001**：认证机构进行认证审核
- **其他**：各专项合规检查和认证

#### 阶段五：持续监控与改进

- **日常运维**：安全监控、日志审计、漏洞管理、补丁管理
- **定期评审**：内部审核、管理评审、定期测评
- **持续改进**：根据审核/测评结果、新的威胁、新的业务需求持续改进

### 6.2 合规文档体系

一套完整的合规文档体系通常呈金字塔结构：

```
一级文件：安全策略 / 方针（1 份）
    │
二级文件：安全管理制度（十几份）
    │
三级文件：操作规程 / 实施细则（几十份）
    │
四级文件：记录表单 / 日志 / 报告（大量）
```

#### 一级文件：策略/方针

- 信息安全方针 / 策略
- 由最高管理者批准发布
- 阐明安全目标、原则和承诺

#### 二级文件：管理制度（示例）

- 信息安全管理办法
- 网络安全管理制度
- 数据安全管理制度
- 个人信息保护管理制度
- 人员安全管理制度
- 物理安全管理制度
- 访问控制管理制度
- 密码管理制度
- 变更管理制度
- 漏洞管理制度
- 安全事件应急响应管理制度
- 备份与恢复管理制度

#### 三级文件：操作规程（示例）

- 服务器安全加固操作规程
- 网络设备配置操作规程
- 账号权限管理操作规程
- 数据备份与恢复操作规程
- 漏洞扫描与修复操作规程
- 安全事件处置操作规程
- 员工入职/离岗安全操作规程

#### 四级文件：记录与表单（示例）

- 安全检查记录表
- 漏洞扫描报告
- 补丁安装记录
- 培训签到表与考试记录
- 访问权限申请审批单
- 变更申请单
- 安全事件报告表
- 备份记录表
- 机房出入登记表

> **文档编写原则**：
> - 写你所做的，做你所写的（文档要和实际一致）
> - 不要为了应付检查写一堆不执行的制度
> - 文档要有可操作性，让拿到的人知道怎么做
> - 定期评审和更新，不是写完就完事

### 6.3 合规审计与检查准备

#### 常见检查/审计类型

| 类型 | 主体 | 频率 |
|------|------|------|
| **等级测评** | 第三方等保测评机构 | 三级每年 1 次，四级每半年 1 次 |
| **监督检查** | 公安机关 | 定期或不定期 |
| **内部审核** | 企业内部（内审员） | 每年至少 1 次 |
| **外部认证审核** | 认证机构（如 ISO 27001） | 认证 3 年有效期，每年监督审核 |
| **行业检查** | 行业主管部门 | 按行业规定 |
| **客户审计** | 客户（尤其是大客户） | 按需 |

#### 检查准备工作清单

- [ ] 文档准备：制度、规程、记录齐全且有效
- [ ] 技术验证：安全措施实际生效，配置正确
- [ ] 人员准备：相关人员熟悉流程和要求，能应答访谈
- [ ] 漏洞管理：已知高危漏洞已修复
- [ ] 日志审计：审计日志完整，有定期审计记录
- [ ] 备份验证：备份可用，有恢复演练记录
- [ ] 培训记录：安全培训有计划、有记录、有考核
- [ ] 应急预案：有预案、有演练、有改进
- [ ] 资质证明：相关人员资质、产品资质齐全

## 七、2026 年最新动态

### 7.1 《网络安全法》修订（2026 年 1 月 1 日施行）

| 变化 | 说明 | 影响 |
|------|------|------|
| **新增人工智能安全条款** | 对生成式 AI 等新技术新应用的安全管理 | 提供 AI 服务的企业需要关注算法安全治理、内容安全等新要求 |
| **罚款额度大幅提高** | 最高罚款从原来的一百万元提高到一千万元 | 违法成本大幅提升，企业合规压力增大 |
| **完善 CII 保护** | 进一步细化关键信息基础设施保护制度 | CII 运营者义务加重 |
| **数据安全衔接** | 与《数据安全法》《个人信息保护法》更好衔接 | 三法协同更紧密 |
| **网络违法犯罪打击** | 加大对网络违法犯罪的打击力度 | 企业配合义务可能增加 |

> **⚠️ 2026 年时效性标注**：修订后的《网络安全法》自 **2026 年 1 月 1 日**起施行。各单位应及时学习修订内容，对照自查整改，确保在施行前完成合规准备。

### 7.2 《公安机关网络空间安全监督检查办法》

| 项目 | 内容 |
|------|------|
| **发布机关** | 公安部 |
| **施行日期** | 2026 年 10 月 1 日 |
| **核心内容** | 规范公安机关对网络空间安全的监督检查工作 |

> **⚠️ 2026 年时效性标注**：该办法将于 2026 年 10 月 1 日起施行，将对公安机关的监督检查程序、方式、内容等做出规定。企业应关注该办法的具体内容，做好迎检准备。

### 7.3 数据出境安全管理政策更新

- 数据出境安全评估、标准合同、认证三条路径持续优化
- 各行业数据出境监管要求持续细化
- 跨境数据流动的国际规则和双边协定持续演进

> 企业涉及数据出境的，应及时关注最新政策，确保数据出境活动合规。

### 7.4 2026 年其他值得关注的趋势

| 趋势 | 说明 |
|------|------|
| **AI 安全治理** | AI 技术发展带来新的合规挑战（算法安全、数据合规、内容安全等） |
| **数据要素市场化** | 数据确权、交易、流通相关的制度和规则持续完善 |
| **数据跨境流动** | 国际数据治理规则博弈，跨境数据流动制度持续演变 |
| **企业合规要求升级** | 监管趋严，执法力度加大，企业合规从"做样子"走向"真落地" |
| **供应链安全** | 供应链安全、软件供应链安全越来越受重视 |

## 八、学习路径

### 第一阶段：熟悉核心法律框架（2-3 周）

**目标：** 建立对国内网络安全法律体系的整体认知

| 学习内容 | 学习目标 | 检查点 |
|---------|---------|--------|
| 《网络安全法》 | 理解主要制度、核心义务、法律责任 | 能说出 5 项主要制度和对应的义务 |
| 《数据安全法》 | 理解数据分类分级、数据安全义务、数据出境 | 能解释三级数据分类和各自的保护要求 |
| 《个人信息保护法》 | 理解个人信息处理规则、个人权利、跨境传输 | 能说出个人信息处理的 7 大原则 |
| 三法关系 | 理解三法的定位和相互关系 | 能画出三法的关系图 |

**实践任务**：
- [ ] 通读三法的法条原文（重点看核心章节）
- [ ] 对照你所在的企业/组织，列出 5 项需要履行的法定义务
- [ ] 找一个真实的处罚案例，分析违反了什么规定

### 第二阶段：掌握等级保护制度（3-4 周）

**目标：** 熟悉等保 2.0 的流程和基本要求

| 学习内容 | 学习目标 | 检查点 |
|---------|---------|--------|
| 等保制度概述 | 理解等保的法律地位、五级划分、五个环节 | 能完整描述等保 5 个环节的流程 |
| 定级与备案 | 理解定级方法、备案流程 | 能为一个简单系统定级 |
| 基本要求框架 | 理解"一个中心三重防护"和十大类要求 | 能说出技术和管理各包括哪几大类 |
| 等级测评 | 理解测评流程、方法、结论 | 能准备测评所需的主要材料 |
| 新技术扩展要求 | 了解云计算、移动互联、物联网等扩展要求 | 能说出云环境下等保的特殊要求 |

**实践任务**：
- [ ] 找一份等保三级的测评要求清单，大致过一遍内容
- [ ] 以你熟悉的一个系统为例，尝试定级并说明理由
- [ ] 列出等保测评前需要准备的 10 份核心文档

### 第三阶段：学习国际标准（2-3 周）

**目标：** 了解主要国际标准和框架，能对比差异

| 学习内容 | 学习目标 | 检查点 |
|---------|---------|--------|
| ISO 27001 | 理解 ISMS 框架和 PDCA 循环 | 能说出 ISO 27001 的主要条款结构 |
| NIST CSF | 理解六大功能和框架的使用方法 | 能用 CSF 做简单的成熟度评估 |
| GDPR | 理解 GDPR 的核心原则和适用范围 | 能判断你的业务是否需要遵守 GDPR |
| 标准对比 | 理解等保 2.0、ISO 27001、NIST CSF 的异同 | 能做一个三标准的对比表 |

**实践任务**：
- [ ] 做一个等保 2.0 与 ISO 27001 的要求映射表
- [ ] 用 NIST CSF 的六大功能评估你所在组织的安全成熟度
- [ ] 分析一个 GDPR 处罚案例，理解违反了什么条款

### 第四阶段：合规实践与审计（持续学习）

**目标：** 能实际参与和推动合规工作

| 学习内容 | 学习目标 | 检查点 |
|---------|---------|--------|
| 差距评估方法 | 学会做合规差距评估 | 能独立做一个小系统的差距评估 |
| 整改规划 | 学会制定整改计划和优先级 | 能制定合理的整改路线图 |
| 文档体系建设 | 理解合规文档的层次和编写方法 | 能写出一份合格的安全管理制度 |
| CII 保护 | 理解 CII 的认定标准和特殊义务 | 能判断某系统是否属于 CII |
| 数据分类分级 | 学会做数据分类分级 | 能为一个简单场景的数据分级 |
| 迎检准备 | 知道各类检查需要准备什么 | 能准备等保测评的主要材料 |

**实践任务**：
- [ ] 参与或主导一个小系统的合规整改工作
- [ ] 编写一份你所在领域的安全管理制度
- [ ] 为你负责的系统做一次数据分类分级
