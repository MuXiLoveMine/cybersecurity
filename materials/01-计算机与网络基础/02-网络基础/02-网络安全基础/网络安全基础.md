## 一、网络安全定义与基本原则

### 1.1 什么是网络安全

**网络安全（Cybersecurity / Network Security）** 是指通过采取各种技术和管理措施，保护网络系统中的硬件、软件、数据不因偶然或恶意的原因而遭到破坏、更改、泄露，确保系统连续可靠正常运行，网络服务不中断。

简单理解：**保护信息系统和数据的机密性、完整性、可用性，以及其他安全属性。**

| 维度 | 说明 |
|------|------|
| **保护对象** | 硬件、软件、数据、网络、服务 |
| **威胁来源** | 外部攻击、内部威胁、自然灾害、系统故障、人为失误 |
| **手段** | 技术手段（防火墙、加密、认证等）+ 管理手段（制度、流程、培训） |
| **目标** | 降低风险，而非绝对安全（安全是相对的） |

### 1.2 网络安全的范围

网络安全是一个非常大的领域，可以从多个角度划分：

| 分类维度 | 具体领域 |
|---------|---------|
| **按层次** | 物理安全、网络安全、主机安全、应用安全、数据安全、人员安全 |
| **按技术方向** | 渗透测试、安全运维、安全研究、安全开发、安全管理 |
| **按防护手段** | 防火墙、入侵检测、加密、认证、访问控制、安全审计 |
| **按生命周期** | 规划、设计、开发、测试、部署、运维、废弃 |

```
网络安全体系分层（类似 OSI 模型）：

  ┌─────────────────────────────┐
  │  应用安全（Web/APP/API）     │  ← 漏洞、注入、XSS、CSRF 等
  ├─────────────────────────────┤
  │  主机安全（OS/补丁/配置）     │  ← 系统加固、漏洞、恶意代码
  ├─────────────────────────────┤
  │  网络安全（通信/边界/协议）   │  ← 防火墙、VPN、网络攻击
  ├─────────────────────────────┤
  │  物理安全（机房/设备/环境）   │  ← 门禁、监控、消防、供电
  ├─────────────────────────────┤
  │  数据安全（存储/传输/使用）   │  ← 加密、脱敏、备份
  ├─────────────────────────────┤
  │  人员安全（意识/管理/培训）   │  ← 社会工程、权限管理
  ├─────────────────────────────┤
  │  管理安全（制度/流程/合规）   │  ← 策略、风险、审计
  └─────────────────────────────┘
```

### 1.3 基本原则

| 原则 | 英文 | 说明 |
|------|------|------|
| **最小权限** | Least Privilege | 只授予完成工作所必需的最小权限 |
| **纵深防御** | Defense in Depth | 多层防护，一层被突破还有下一层 |
| **职责分离** | Separation of Duties | 关键操作分由多人完成，防止单人舞弊 |
| **安全设计** | Security by Design | 从设计阶段就考虑安全，而不是事后补丁 |
| **默认安全** | Secure by Default | 默认配置就是安全的（默认拒绝、最小权限） |
| **零信任** | Zero Trust | "永不信任，始终验证"，不因为在内网就信任 |
| **木桶原则** | Weakest Link | 安全强度取决于最薄弱的环节 |
| **可审计** | Accountability | 所有操作都可追溯 |
| **不可否认** | Non-repudiation | 用户不能否认自己的操作 |
| **成本平衡** | Cost-Balance | 安全投入不超过资产价值 |
| **动态发展** | Dynamic | 安全是持续的过程，不是一次性的项目 |

> **没有绝对的安全**——安全的目标不是"绝对不会被攻破"，而是"让攻击成本大于攻击收益"，以及"被攻破后能及时发现和恢复"。

## 二、安全属性

### 2.1 CIA 三要素

**CIA 三元组（CIA Triad）**是信息安全的三个核心目标，也是最基础的概念。

| 要素 | 英文 | 含义 | 常见威胁 | 防护手段 |
|------|------|------|---------|---------|
| **机密性** | Confidentiality | 信息不被未授权的人获取 | 窃听、泄露、嗅探 | 加密、访问控制、脱敏 |
| **完整性** | Integrity | 信息不被未授权的篡改，保持完整准确 | 篡改、注入、破坏 | 哈希校验、数字签名、备份 |
| **可用性** | Availability | 授权用户可以正常访问系统和数据 | DDoS、破坏、故障 | 冗余、备份、容错、DDoS 防护 |

```
CIA 三元组关系：

        机密性 (Confidentiality)
            /\
           /  \
          /    \
         /______\
        /        \
  完整性 (I)    可用性 (A)

三者互相关联，有时需要权衡：
  - 过度加密可能影响可用性
  - 过度可用可能影响机密性
  - 好的安全设计是在三者之间找到平衡
```

### 2.2 其他重要属性

| 属性 | 英文 | 说明 | 实现方式 |
|------|------|------|---------|
| **不可否认性** | Non-repudiation | 用户无法否认自己的操作 | 数字签名、审计日志、CA |
| **可审计性** | Accountability | 所有操作可以追溯到责任人 | 日志、审计、身份标识 |
| **真实性** | Authenticity | 信息来源是真实的、未冒充的 | 认证、数字证书、MAC |
| **可控性** | Controllability | 对信息的传播和内容有控制能力 | 访问控制、DLP、监控 |
| **可靠性** | Reliability | 系统在规定条件下和时间内完成规定功能的能力 | 冗余、容错、测试 |

### 2.3 安全属性与防护手段对应表

| 安全属性 | 加密 | 数字签名 | 防火墙 | 访问控制 | 备份 | 日志审计 | 认证 |
|---------|------|---------|--------|---------|------|---------|------|
| 机密性 | ✅ 主要 | ❌ | ✅ 辅助 | ✅ 主要 | ❌ | ❌ | ✅ 辅助 |
| 完整性 | ✅ 辅助 | ✅ 主要 | ❌ | ❌ | ✅ 恢复 | ❌ | ❌ |
| 可用性 | ❌ | ❌ | ✅ 辅助 | ❌ | ✅ 主要 | ❌ | ❌ |
| 不可否认性 | ❌ | ✅ 主要 | ❌ | ❌ | ❌ | ✅ 辅助 | ✅ 辅助 |
| 可审计性 | ❌ | ❌ | ❌ | ❌ | ❌ | ✅ 主要 | ✅ 辅助 |

## 三、常见威胁与攻击类型

### 3.1 威胁分类

| 分类维度 | 威胁类型 | 说明 |
|---------|---------|------|
| **按来源** | 外部威胁 | 来自组织外部的攻击者 |
| | 内部威胁 | 内部人员（恶意或失误） |
| | 自然威胁 | 地震、火灾、洪水等 |
| **按方式** | 被动攻击 | 不修改数据，只是获取（窃听、嗅探） |
| | 主动攻击 | 修改、破坏、伪造数据 |
| **按目标** | 针对网络 | DDoS、端口扫描、嗅探 |
| | 针对系统 | 漏洞利用、提权、木马 |
| | 针对应用 | SQL 注入、XSS、CSRF |
| | 针对数据 | 数据泄露、数据篡改 |
| | 针对人员 | 社会工程、钓鱼、欺诈 |

### 3.2 常见网络攻击类型

#### （1）按 OSI 层级分类

| 层级 | 攻击类型 | 说明 |
|------|---------|------|
| **物理层** | 物理破坏、线缆窃听、电磁泄漏 | 物理接触设备或环境 |
| **数据链路层** | MAC 欺骗、VLAN 跳跃、ARP 欺骗、CAM 表溢出 | 二层攻击 |
| **网络层** | IP 欺骗、Smurf、ICMP 洪水、路由攻击、分片攻击 | 三层攻击 |
| **传输层** | SYN Flood、UDP Flood、端口扫描、TCP 劫持、会话劫持 | 四层攻击 |
| **应用层** | SQL 注入、XSS、CSRF、文件上传漏洞、命令注入 | 七层攻击 |
| **跨层** | DDoS（多层组合）、中间人攻击（跨多层） | 综合攻击 |

#### （2）按攻击目的分类

| 攻击目的 | 典型攻击 | 影响的安全属性 |
|---------|---------|--------------|
| **窃取信息** | 窃听、嗅探、SQL 注入、钓鱼 | 机密性 |
| **篡改数据** | 中间人、SQL 注入、参数篡改 | 完整性 |
| **拒绝服务** | DDoS、SYN Flood、CC 攻击 | 可用性 |
| **未授权访问** | 暴力破解、漏洞利用、越权 | 机密性/完整性 |
| **伪装冒充** | IP 欺骗、MAC 欺骗、钓鱼 | 真实性 |
| **抵赖** | 伪造操作、删除日志 | 不可否认性 |

### 3.3 DDoS 攻击分类

**DDoS（Distributed Denial of Service，分布式拒绝服务）** 是目前最常见、影响最大的网络攻击之一。

| 类型 | 代表攻击 | 原理 | 防御手段 |
|------|---------|------|---------|
| **流量型** | UDP Flood、ICMP Flood | 占满带宽 | 流量清洗、CDN、运营商级防护 |
| **协议型** | SYN Flood、ACK Flood | 占满连接表/系统资源 | SYN Cookies、防火墙限流 |
| **应用层** | HTTP Flood（CC 攻击） | 占满应用服务器资源 | WAF、验证码、行为分析 |
| **反射型** | DNS 放大、NTP 放大、SSDP 放大 | 利用开放服务器放大攻击流量 | 关闭不必要的服务、uRPF、Anycast |
| **混合型** | 多种组合 | 同时从多层攻击 | 多层防护组合 |

### 3.4 中间人攻击（MITM）

**中间人攻击（Man-in-the-Middle）**：攻击者插入通信双方之间，同时欺骗双方，让双方以为在直接通信。

```
正常通信：
  A ←─────────────────────────→ B

中间人攻击：
  A ←─────→ M（攻击者） ←─────→ B
           M 同时冒充 A 和 B
           可以窃听、篡改、丢弃所有数据
```

| MITM 实现方式 | 层级 | 说明 |
|--------------|------|------|
| **ARP 欺骗** | 二层 | 欺骗 ARP 缓存，流量经过攻击者 |
| **DNS 欺骗** | 应用层 | 篡改 DNS 解析结果，引导到钓鱼网站 |
| **SSL 剥离** | 应用层 | 把 HTTPS 降级成 HTTP |
| **Wi-Fi 邪恶双子** | 物理/链路层 | 伪造热点，用户连接后流量全经过攻击者 |
| **BGP 劫持** | 网络层 | 篡改路由，流量经过攻击者网络 |

### 3.5 社会工程学攻击

人往往是安全最薄弱的环节。

| 类型 | 说明 | 典型场景 |
|------|------|---------|
| **钓鱼（Phishing）** | 伪造邮件/网站骗取信息 | 假银行网站、假登录页 |
| **鱼叉式钓鱼（Spear Phishing）** | 针对特定目标的精准钓鱼 | 针对高管或特定部门 |
| **诱饵（Baiting）** | 用利益诱惑用户 | U 盘放在停车场、免费下载带毒 |
| **伪装（Pretexting）** | 编造身份骗取信任 | 冒充 IT 人员要密码 |
| **尾门（Tailgating）** | 跟随授权人员进入受限区域 | 跟着别人刷卡进门 |
| **电话诈骗（Vishing）** | 电话冒充身份骗取信息 | 冒充银行/领导打电话 |

## 四、密码学基础与安全协议

### 4.1 密码学分类

| 分类 | 说明 | 典型算法 |
|------|------|---------|
| **对称加密** | 加密解密用同一个密钥 | DES、3DES、AES、SM4 |
| **非对称加密** | 加密用公钥，解密用私钥（一对密钥） | RSA、ECC、SM2 |
| **哈希算法** | 单向散列，不可逆，用于完整性校验 | MD5、SHA-1、SHA-256、SM3 |
| **消息认证码** | 带密钥的哈希，认证+完整性 | HMAC、CMAC |
| **数字签名** | 私钥签名，公钥验证，不可否认 | RSA 签名、ECDSA、SM2 签名 |

### 4.2 对称加密 vs 非对称加密

| 特性 | 对称加密 | 非对称加密 |
|------|---------|-----------|
| **密钥数量** | 1 个（共享密钥） | 1 对（公钥 + 私钥） |
| **速度** | 快（适合大数据量） | 慢（适合小数据量/密钥交换） |
| **密钥分发** | 困难（怎么安全地把密钥给对方？） | 容易（公钥公开，私钥自己留） |
| **用途** | 加密大量数据 | 密钥交换、数字签名、认证 |
| **安全性** | 取决于密钥长度和算法 | 取决于数学难题（大素数分解/离散对数） |
| **代表算法** | AES、3DES、SM4 | RSA、ECC、SM2 |

**实际应用中通常组合使用**（如 TLS）：
1. 用非对称加密安全地交换对称密钥
2. 用对称密钥加密实际传输的数据
3. 用哈希算法验证完整性
4. 用数字签名做身份认证和不可否认

### 4.3 哈希算法

| 算法 | 输出长度 | 安全性 | 现状 |
|------|---------|--------|------|
| MD5 | 128 位 | 低（已被碰撞攻击） | 不推荐用于安全场景 |
| SHA-1 | 160 位 | 低（已被碰撞攻击） | 逐步淘汰中 |
| SHA-256 | 256 位 | 高 | 目前主流推荐 |
| SHA-512 | 512 位 | 很高 | 更高安全要求 |
| SHA-3 | 224/256/384/512 位 | 很高 | 新一代标准 |
| SM3 | 256 位 | 高 | 中国国密标准 |

> 哈希算法的特点：
> 1. **单向性**：无法从哈希值反推出原始数据
> 2. **定长输出**：无论输入多大，输出长度固定
> 3. **雪崩效应**：输入微小变化导致输出完全不同
> 4. **抗碰撞性**：很难找到两个不同的输入有相同的哈希值

### 4.4 PKI 与数字证书

**PKI（Public Key Infrastructure，公钥基础设施）**是一套管理公钥和数字证书的体系，解决"公钥是谁的"这个信任问题。

```
PKI 组成：

  CA（证书颁发机构）   ←  信任的根
      │
      ▼
  数字证书（Certificate） = 公钥 + 身份信息 + CA 签名
      │
      ▼
  验证：用 CA 的公钥验证证书上的签名
        签名有效 → 证书可信 → 公钥可信
```

| 组成部分 | 英文 | 作用 |
|---------|------|------|
| **证书颁发机构** | CA（Certificate Authority） | 颁发和管理数字证书 |
| **注册机构** | RA（Registration Authority） | 验证申请者身份，代理 CA |
| **数字证书** | Digital Certificate | 绑定公钥和身份 |
| **证书吊销列表** | CRL（Certificate Revocation List） | 已吊销的证书列表 |
| **在线证书状态协议** | OCSP（Online Certificate Status Protocol） | 在线查询证书状态 |

### 4.5 常见安全协议

| 协议 | 层级 | 作用 | 基础算法 |
|------|------|------|---------|
| **TLS/SSL** | 传输层/应用层之间 | 加密通信、身份认证、完整性 | AES + RSA/ECC + SHA |
| **IPSec** | 网络层 | IP 层加密（VPN 常用） | AES + 各种密钥交换 |
| **SSH** | 应用层 | 安全远程登录、文件传输 | 对称加密 + 公钥认证 |
| **HTTPS** | 应用层 | HTTP over TLS | TLS |
| **S/MIME** | 应用层 | 邮件加密和签名 | 非对称 + 对称 + 证书 |
| **PGP/GPG** | 应用层 | 文件/邮件加密 | 非对称 + 对称 + Web of Trust |
| **WPA2/WPA3** | 链路层 | Wi-Fi 加密 | AES、CCMP |
| **802.1X** | 链路层 | 网络接入认证 | EAP + RADIUS |

## 五、身份认证与访问控制

### 5.1 身份认证

**身份认证（Authentication）**：验证"你是谁"。

| 认证因素 | 英文 | 说明 | 例子 |
|---------|------|------|------|
| **你知道的** | Something you know | 知识类 | 密码、PIN、密保问题 |
| **你拥有的** | Something you have | 物品类 | 手机令牌、U 盾、智能卡 |
| **你本身的** | Something you are | 生物特征 | 指纹、人脸、虹膜、声纹 |
| **你所在的** | Somewhere you are | 位置类 | 地理位置、网络位置 |
| **你做的** | Something you do | 行为特征 | 签名、击键习惯 |

| 认证强度 | 说明 |
|---------|------|
| **单因素认证（SFA）** | 只用一种因素（如只有密码），最不安全 |
| **双因素认证（2FA）** | 两种不同因素组合，较安全 |
| **多因素认证（MFA）** | 两种以上因素，最安全 |

> 注意：**密码 + 验证码（同一个手机上）不一定是双因素**——因为验证码发到手机，但手机也是"你知道的"（密码解锁），严格来说可能都属于"你拥有的"这一类。真正的双因素应该是不同类别的组合，如密码 + U 盾。

### 5.2 常见认证方式

| 方式 | 安全性 | 便捷性 | 说明 |
|------|--------|--------|------|
| **密码** | 低~中 | 高 | 最常用，易被破解/钓鱼 |
| **短信验证码** | 中 | 高 | 易被 SIM 劫持、钓鱼 |
| **TOTP（Google Authenticator 等）** | 高 | 中 | 基于时间的一次性密码 |
| **硬件令牌（U 盾、YubiKey）** | 很高 | 中 | 物理设备，防钓鱼能力强 |
| **生物识别** | 中~高 | 很高 | 方便但不可撤销（指纹不能换） |
| **证书认证** | 高 | 中 | 基于 PKI，安全性高 |
| **单点登录（SSO）** | 中~高 | 很高 | 一次登录，多处访问 |
| **Kerberos** | 高 | 中 | Windows AD 默认协议，票据机制 |
| **RADIUS** | 中 | 中 | 集中认证（802.1X、VPN 常用） |
| **LDAP** | 中 | 中 | 目录服务认证 |

### 5.3 访问控制

**访问控制（Access Control）**：认证之后，确定"你能做什么"。

#### （1）访问控制模型

| 模型 | 英文 | 特点 | 适用场景 |
|------|------|------|---------|
| **自主访问控制** | DAC (Discretionary) | 资源所有者自己决定谁能访问 | 一般系统（如 Linux 文件权限） |
| **强制访问控制** | MAC (Mandatory) | 系统强制按安全级别控制 | 高安全级（军用、政府，如 SELinux） |
| **基于角色的访问控制** | RBAC (Role-Based) | 按角色分配权限，用户属于角色 | 企业系统，最常用 |
| **基于属性的访问控制** | ABAC (Attribute-Based) | 根据属性（用户、资源、环境）动态决策 | 细粒度、动态场景 |
| **基于规则的访问控制** | Rule-Based | 根据规则判断（如防火墙 ACL） | 网络设备、防火墙 |

#### （2）权限管理原则

| 原则 | 说明 |
|------|------|
| **最小权限原则** | 只给完成工作需要的最小权限 |
| **按需知道原则** | 只给需要知道的信息 |
| **职责分离** | 关键操作由多人分担 |
| **权限最小化** | 默认无权限，按需分配 |
| **定期审计** | 定期检查权限，回收不再需要的 |

### 6.1 边界防护

| 安全设备 | 作用层级 | 主要功能 | 部署位置 |
|---------|---------|---------|---------|
| **防火墙（Firewall）** | 网络层/传输层/应用层 | 基于规则过滤流量 | 网络边界 |

| **IPS（入侵防御系统）** | 多层 | 检测并阻断攻击 | 串接/在线 |
| **VPN（虚拟专用网络）** | 网络层/应用层 | 加密隧道，远程安全接入 | 边界/网关 |
| **负载均衡** | 传输层/应用层 | 流量分发，也有一定安全功能 | 服务器前 |
| **DDoS 清洗** | 多层 | 过滤 DDoS 攻击流量 | 入口/云端 |
| **UTM（统一威胁管理）** | 多层 | 集成防火墙/IPS/AV 等功能 | 中小企业 |
| **零信任网关** | 多层 | 基于身份和上下文的访问控制 | 应用前/边界 |

### 6.2 防火墙类型

| 类型 | 工作层级 | 原理 | 优点 | 缺点 |
|------|---------|------|------|------|
| **包过滤防火墙** | 网络层 | 根据 IP/端口/协议过滤 | 速度快、透明 | 无法检测应用层攻击 |
| **状态检测防火墙** | 网络层+ | 跟踪连接状态，只放行合法响应 | 安全、性能好 | 配置复杂一些 |
| **代理防火墙** | 应用层 | 代理所有连接，深度检查 | 安全性高 | 性能差、每个应用要单独代理 |
| **下一代防火墙（NGFW）** | 多层 | 集成 IPS、应用识别、用户识别 | 功能全面 | 成本高 |

**Linux 下的防火墙**：

| 工具 | 内核模块 | 说明 |
|------|---------|------|
| **iptables** | netfilter | 传统工具，灵活强大，命令行 |
| **nftables** | nf_tables | 新一代，替代 iptables，语法更简洁 |
| **firewalld** | iptables/nftables | RHEL/CentOS 默认，zone 概念，动态管理 |
| **ufw** | iptables | Ubuntu 默认，简单易用 |

### 6.3 入侵检测与防御

| 类型 | 英文 | 作用 | 部署方式 |
|------|------|------|---------|
| **IDS** | Intrusion Detection System | 检测入侵，发出告警 | 旁路（监听） |
| **IPS** | Intrusion Prevention System | 检测并阻断入侵 | 串接（在线） |

| 检测方式 | 说明 | 优点 | 缺点 |
|---------|------|------|------|
| **特征匹配** | 已知攻击的特征码匹配 | 准确、误报低 | 只能检测已知攻击 |

### 7.2 风险评估

**风险（Risk）= 威胁（Threat）× 脆弱性（Vulnerability）× 资产价值（Asset）**

```
风险评估流程：

  1. 资产识别 → 有什么资产？价值多少？
     ↓
  2. 威胁识别 → 有什么威胁？发生概率？
     ↓
  3. 脆弱性识别 → 有什么漏洞？严重程度？
     ↓
  4. 风险分析 → 风险有多大？（概率 × 影响）
     ↓
  5. 风险评价 → 可接受还是不可接受？
     ↓
  6. 风险处置 → 怎么处理？（规避/转移/缓解/接受）
```

**风险处置方式**：

| 方式 | 英文 | 说明 | 例子 |
|------|------|------|------|
| **规避** | Avoidance | 消除风险来源 | 关闭有风险的服务、不做有风险的业务 |
| **转移** | Transference | 把风险转嫁给第三方 | 买保险、外包给专业公司 |
| **缓解** | Mitigation | 降低风险发生概率或影响 | 部署防火墙、加密、备份 |
| **接受** | Acceptance | 承担风险（风险太小或处理成本太高） | 小概率小影响的风险 |

### 7.3 等保 2.0（中国）

**网络安全等级保护**是中国的网络安全基本制度，简称"等保"。

| 等级 | 说明 | 适用对象 |
|------|------|---------|
| **第一级** | 自主保护级 | 一般信息系统，受破坏后对公民/法人有损害但不危害国家安全 |
| **第二级** | 指导保护级 | 受破坏后对社会秩序和公共利益有损害，不危害国家安全 |
| **第三级** | 监督保护级 | 受破坏后对社会秩序和公共利益造成严重损害，对国家安全造成损害 |
| **第四级** | 强制保护级 | 受破坏后对社会秩序和公共利益造成特别严重损害，对国家安全造成严重损害 |
| **第五级** | 专控保护级 | 受破坏后对国家安全造成特别严重损害 |

**等保 2.0 五大技术要求**：

1. 安全物理环境
2. 安全通信网络
3. 安全区域边界
4. 安全计算环境
5. 安全管理中心

**等保 2.0 五大管理要求**：

1. 安全管理制度
2. 安全管理机构
3. 安全管理人员
4. 安全建设管理
5. 安全运维管理

## 八、Linux 网络安全实践与常用工具

### 8.1 防火墙配置

#### iptables / nftables

```bash
# ===== 查看规则 =====
iptables -L -n -v                 # 查看 filter 表
iptables -L -n -v --line-numbers  # 带行号
iptables -t nat -L -n -v          # 查看 nat 表
iptables -t mangle -L -n -v       # 查看 mangle 表
iptables -S                       # 以保存格式显示
iptables -S INPUT                 # 指定链

nft list ruleset                  # nftables 查看所有规则
nft list table filter             # 查看 filter 表

# ===== 基本策略 =====🔑
# 默认拒绝（推荐）
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT

# 放行已建立的连接
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# 放行回环接口
iptables -A INPUT -i lo -j ACCEPT

# 放行 SSH（限制源 IP 更安全）
iptables -A INPUT -p tcp --dport 22 -s 192.168.1.0/24 -j ACCEPT

# 放行 HTTP/HTTPS
iptables -A INPUT -p tcp --dport 80 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# 放行 ping（限速）
iptables -A INPUT -p icmp --icmp-type echo-request -m limit --limit 10/s -j ACCEPT

# ===== 保存和恢复 =====🔑
# Debian/Ubuntu
iptables-save > /etc/iptables/rules.v4
iptables-restore < /etc/iptables/rules.v4

# RHEL/CentOS（用 iptables-services）
service iptables save

# ===== 清空规则（慎用！远程可能断开） =====🔑⚠️
iptables -F           # 清空所有链
iptables -X           # 删除自定义链
iptables -Z           # 清零计数器
# ⚠️ 如果默认策略是 DROP，清空前先改成 ACCEPT，否则会立即断开！
# 正确做法：iptables -P INPUT ACCEPT && iptables -F

# ===== 常用防攻击规则 =====🔑

# 防止 SYN Flood
iptables -N syn_flood
iptables -A INPUT -p tcp --syn -j syn_flood
iptables -A syn_flood -m limit --limit 20/s --limit-burst 40 -j RETURN
iptables -A syn_flood -j DROP

# 防止端口扫描（隐藏式）
iptables -A INPUT -p tcp --tcp-flags ALL NONE -j DROP
iptables -A INPUT -p tcp --tcp-flags ALL ALL -j DROP
iptables -A INPUT -p tcp --tcp-flags ALL FIN,URG,PSH -j DROP

# 限制单个 IP 的连接数
iptables -A INPUT -p tcp --dport 80 -m connlimit --connlimit-above 50 -j REJECT

# 防止 ICMP 洪水
iptables -A INPUT -p icmp --icmp-type echo-request -m limit --limit 5/second -j ACCEPT
```

> ⚠️ **防火墙配置警告**：
> - 远程修改 iptables 规则可能导致断开连接
> - 清空规则前确保默认策略是 ACCEPT
> - 建议配合 `at` 或 `sleep` 定时恢复：`echo "iptables-restore < backup" | at now + 5 min`
> - 先在测试环境验证

#### firewalld（RHEL/CentOS 默认）

```bash
# ===== 基本操作 =====
systemctl start firewalld
systemctl enable firewalld
firewall-cmd --state
firewall-cmd --reload              # 重新加载（不中断连接）
firewall-cmd --complete-reload     # 完全重载（会中断连接）

# ===== 区域管理 =====
firewall-cmd --get-default-zone
firewall-cmd --set-default-zone=public
firewall-cmd --get-active-zones
firewall-cmd --list-all-zones
firewall-cmd --zone=public --list-all

# ===== 服务管理 =====
firewall-cmd --zone=public --add-service=ssh           # 临时
firewall-cmd --zone=public --add-service=ssh --permanent  # 永久
firewall-cmd --zone=public --remove-service=ssh --permanent
firewall-cmd --get-services                            # 所有可用服务

# ===== 端口管理 =====
firewall-cmd --zone=public --add-port=8080/tcp --permanent
firewall-cmd --zone=public --remove-port=8080/tcp --permanent

# ===== 富规则 =====

  rule family="ipv4" source address="192.168.1.0/24" service name="ssh" accept'

# 端口转发
firewall-cmd --permanent --zone=public --add-forward-port=port=80:proto=tcp:toport=8080
```

### 8.3 系统安全加固

#### sysctl 网络安全参数

```bash
# ===== 网络安全加固参数 =====🔑

# 防止 IP 欺骗
net.ipv4.conf.all.rp_filter = 1
net.ipv4.conf.default.rp_filter = 1

# 忽略广播 ping（防 Smurf）
net.ipv4.icmp_echo_ignore_broadcasts = 1

# 忽略虚假 ICMP 错误
net.ipv4.icmp_ignore_bogus_error_responses = 1

# 禁用 ICMP 重定向接受
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.conf.default.accept_redirects = 0
net.ipv6.conf.all.accept_redirects = 0

# 禁用 ICMP 重定向发送（非路由器）
net.ipv4.conf.all.send_redirects = 0
net.ipv4.conf.default.send_redirects = 0

# 禁用源路由
net.ipv4.conf.all.accept_source_route = 0
net.ipv6.conf.all.accept_source_route = 0

# SYN Cookies（防 SYN Flood）
net.ipv4.tcp_syncookies = 1

# 限制 TIME_WAIT 复用
net.ipv4.tcp_tw_reuse = 1

# TCP Fast Open
net.ipv4.tcp_fastopen = 3

# 禁用 IP 转发（非路由器）
net.ipv4.ip_forward = 0
net.ipv6.conf.all.forwarding = 0

# 日志可疑数据包
net.ipv4.conf.all.log_martians = 1

# 写入 /etc/sysctl.d/99-security.conf 后执行：sysctl -p
```
