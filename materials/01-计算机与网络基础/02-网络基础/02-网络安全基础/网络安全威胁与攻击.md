## 一、威胁来源

### 1.1 威胁分类

| 威胁来源 | 英文 | 说明 | 典型动机 | 风险特点 |
|---------|------|------|---------|---------|
| **外部攻击者** | External Attacker | 组织外部的个人或团体 | 经济利益、政治目的、炫耀技术 | 数量多、技术参差不齐、易发现 |
| **内部威胁** | Insider Threat | 内部员工、承包商、合作伙伴 | 报复、利益、无意失误 | 信任度高、难发现、损失大 |
| **供应链攻击** | Supply Chain Attack | 通过供应商/第三方组件入侵 | 大范围传播、高价值目标 | 隐蔽性强、影响面广、防御难 |
| **APT（高级持续性威胁）** | Advanced Persistent Threat | 有组织、有目标、长期潜伏的攻击 | 政治/经济间谍、战略目的 | 技术高、隐蔽性强、持续时间长 |
| **脚本小子** | Script Kiddie | 使用现成工具的初级攻击者 | 好奇、炫耀 | 技术低、数量多、随机性强 |
| **犯罪组织** | Cyber Criminal | 有组织的网络犯罪集团 | 经济利益 | 专业化、产业化、迭代快 |
| **自然灾害** | Natural Disaster | 地震、火灾、洪水等 | 无（非人为） | 概率低、破坏大 |
| **人为失误** | Human Error | 误操作、配置错误、误发邮件 | 无意 | 最常见、防不胜防 |

### 1.2 威胁来源详解

#### （1）外部攻击者

| 类型 | 说明 | 防御重点 |
|------|------|---------|
| **自动化扫描/蠕虫** | 全网扫描漏洞，自动感染 | 补丁管理、边界防护、攻击面收敛 |
| **定向攻击** | 针对特定目标的攻击 | 深度防御、威胁情报、检测响应 |
| **勒索软件团伙** | 加密数据索要赎金 | 备份（3-2-1 原则）、终端防护、邮件安全 |
| **黑产团伙** | 盗号、洗钱、流量变现 | 反欺诈、账号安全、风控 |

#### （2）内部威胁

内部威胁往往最危险——因为内部人员有合法访问权限，攻击更容易绕过边界防护。

| 类型 | 说明 | 占比 | 防御重点 |
|------|------|------|---------|
| **恶意内部人员** | 故意窃取/破坏/报复 | 少数 | 权限管控、审计、离职管理 |
| **疏忽大意** | 误操作、点了钓鱼链接、配置错误 | 多数 | 安全培训、流程管控、技术防护 |
| **账号被盗用** | 外部攻击者盗用内部账号 | 不少 | MFA、异常登录检测、账号安全 |

> 统计数据显示，约 30% 以上的数据泄露涉及内部因素（恶意或疏忽）。人是安全最薄弱的环节。

#### （3）供应链攻击

通过攻击供应商、第三方软件或硬件，间接入侵最终用户。

| 类型 | 典型案例 | 说明 |
|------|---------|------|
| **软件供应链** | SolarWinds、XZ Utils | 软件更新/依赖被植入后门 |
| **硬件供应链** | 硬件植入 | 设备在生产/运输环节被篡改 |
| **云服务供应链** | 云服务商入侵 | 通过云服务商入侵客户 |
| **开源组件** | Log4j、OpenSSL 漏洞 | 广泛使用的开源组件有漏洞 |

**防御难点**：你信任的供应商被攻破了，信任链就断了。

**防御手段**：
- SBOM（软件物料清单）
- 第三方安全评估
- 最小权限原则
- 纵深防御（不因为来自信任源就放过）

#### （4）APT（高级持续性威胁）

| 特征 | 说明 |
|------|------|
| **高级（Advanced）** | 技术水平高，有 0day 漏洞利用能力 |
| **持续（Persistent）** | 长期潜伏，数月甚至数年 |
| **威胁（Threat）** | 有组织、有资金、有明确目标 |

**APT 攻击特点**：
1. 目标明确（政府、国防、关键基础设施、大企业）
2. 前期侦察充分（社工、钓鱼、漏洞侦察）
3. 攻击手段多样（0day、社工、物理接触）
4. 长期潜伏，慢速横向移动
5. 数据窃取为主，不搞破坏（避免暴露）
6. 难以发现和清除

**防御难点**：传统基于特征的检测对 APT 效果有限，因为攻击是定制化的、用的是 0day。

**防御手段**：
- 威胁情报
- 行为分析（异常检测）
- 网络分段 / 微隔离
- 零信任架构
- 高级威胁检测（EDR/XDR/NDR）
- 红蓝对抗 / 渗透测试

## 二、攻击面与攻击链

### 2.1 攻击面

**攻击面（Attack Surface）**：系统中可以被攻击者利用的所有入口点和脆弱点的总和。攻击面越大，被攻击的可能性越高。

| 攻击面类型 | 举例 | 收敛方法 |
|-----------|------|---------|
| **网络攻击面** | 开放的端口、暴露的服务、公网 IP | 关闭不必要的端口、内网隔离、收敛公网暴露 |
| **系统攻击面** | 运行的服务、开放的账号、未打补丁的漏洞 | 最小化安装、补丁管理、禁用默认账号 |
| **应用攻击面** | API 接口、输入点、管理后台 | 最小接口原则、权限控制、输入验证 |
| **人员攻击面** | 员工数量、权限大小、安全意识 | 安全培训、最小权限、背景调查 |
| **供应链攻击面** | 第三方依赖、供应商数量 | SBOM、供应商安全评估、减少依赖 |
| **物理攻击面** | 机房入口、设备位置、终端设备 | 门禁、监控、设备加密 |

> **攻击面收敛（Attack Surface Reduction）**：通过减少攻击面来降低被攻击的可能性。基本原则是"默认关闭、按需开启"。

### 2.2 攻击链（Kill Chain）

**攻击链（Cyber Kill Chain）**由洛克希德·马丁公司提出，描述了网络攻击从开始到完成的七个阶段。理解攻击链有助于在各个环节进行检测和阻断。

```
攻击链七阶段：

  1. 侦察（Reconnaissance）   →  收集目标信息
        │
        ▼
  2. 武器化（Weaponization）   →  制作攻击工具/恶意代码
        │
        ▼
  3. 投递（Delivery）         →  把武器送到目标
        │
        ▼
  4. 利用（Exploitation）     →  利用漏洞执行代码
        │
        ▼
  5. 安装（Installation）     →  安装后门/木马，持久化
        │
        ▼
  6. 命令控制（C2）           →  建立远程控制通道
        │
        ▼
  7. 行动（Actions on Objectives） →  达成最终目的（窃取/破坏等）
```

**各阶段说明**：

| 阶段 | 英文 | 攻击者动作 | 防御检测点 |
|------|------|-----------|-----------|
| **侦察** | Reconnaissance | 收集目标的 IP、域名、人员、架构等信息 | 外部扫描检测、威胁情报 |
| **武器化** | Weaponization | 制作恶意文档、漏洞利用代码、后门 | 沙箱检测、文件信誉 |
| **投递** | Delivery | 钓鱼邮件、水坑攻击、USB 投放 | 邮件网关、Web 安全、物理安全 |
| **利用** | Exploitation | 利用漏洞执行代码、获取权限 | 漏洞补丁、EDR、IPS |
| **安装** | Installation | 安装后门、创建服务、修改注册表 | 终端防护、基线核查、文件完整性 |
| **命令控制** | C2 / Command & Control | 建立与攻击者的通信通道 | 出站流量监控、威胁情报、DNS 监控 |
| **行动** | Actions on Objectives | 数据窃取、破坏、勒索、横向移动 | DLP、数据加密、异常检测、审计 |

> **防御思路**：在攻击链的每个阶段都部署检测和防护措施，越早阻断越好。前几个阶段阻断成本低、损失小；越到后面越难发现，损失也越大。

### 2.3 MITRE ATT&CK 框架

**MITRE ATT&CK**（Adversarial Tactics, Techniques, and Common Knowledge）是 MITRE 公司维护的一个全球知名的攻击行为知识库，比 Kill Chain 更详细，覆盖更全面。

```
MITRE ATT&CK 矩阵（简化）：

  初始访问 → 执行 → 持久化 → 权限提升 → 防御绕过
      │         │       │         │          │
      └─────────┴───────┴─────────┴──────────┘
                                │
                                ▼
  凭据访问 → 发现 → 横向移动 → 收集 → 数据渗出 → 影响
      │         │        │        │       │        │
      └─────────┴────────┴────────┴───────┴────────┘
```

| 战术（Tactic） | 英文 | 说明 |
|--------------|------|------|
| 初始访问 | Initial Access | 怎么进入目标网络/系统 |
| 执行 | Execution | 怎么在目标上执行代码 |
| 持久化 | Persistence | 怎么保持访问权限（重启后还在） |
| 权限提升 | Privilege Escalation | 怎么从普通权限升到管理员/root |
| 防御绕过 | Defense Evasion | 怎么绕过杀毒、EDR、防火墙 |
| 凭据访问 | Credential Access | 怎么偷密码、哈希、令牌 |
| 发现 | Discovery | 怎么探索网络和系统 |
| 横向移动 | Lateral Movement | 怎么从一台机器跳到其他机器 |
| 收集 | Collection | 怎么收集要窃取的数据 |
| 数据渗出 | Exfiltration | 怎么把数据偷出去 |
| 命令与控制 | Command and Control | 怎么远程控制被攻陷的机器 |
| 影响 | Impact | 怎么破坏目标（勒索、删除、破坏） |

> ATT&CK 的价值在于：用统一的语言描述攻击行为，让防御方、检测工具、威胁情报可以对齐。防御方可以对照 ATT&CK 矩阵检查自己的检测覆盖率。

## 三、常见攻击类型

### 3.1 按攻击目的分类

| 攻击目的 | 典型攻击 | 影响的安全属性 |
|---------|---------|--------------|
| **窃取信息** | 窃听、嗅探、SQL 注入、数据泄露、钓鱼 | 机密性 |
| **篡改数据** | 中间人攻击、参数篡改、注入攻击 | 完整性 |
| **拒绝服务** | DDoS、勒索软件、系统破坏 | 可用性 |
| **未授权访问** | 暴力破解、漏洞利用、越权访问 | 机密性 / 完整性 |
| **伪装冒充** | IP 欺骗、ARP 欺骗、钓鱼网站、身份伪造 | 真实性 |
| **抵赖** | 日志删除、操作伪造 | 不可否认性 |

### 3.2 四大基础攻击模型

| 攻击类型 | 英文 | 原理 | 典型场景 | 防御核心 |
|---------|------|------|---------|---------|
| **窃听** | Eavesdropping | 被动获取通信内容 | 网络嗅探、Wi-Fi 窃听 | 加密传输（TLS/IPSec） |
| **篡改** | Tampering | 主动修改数据/配置 | 中间人篡改、文件篡改 | 完整性校验（哈希/签名） |
| **伪造** | Spoofing / Forgery | 冒充他人/伪造数据 | IP 欺骗、ARP 欺骗、邮件伪造 | 身份认证、数字签名 |
| **重放** | Replay | 截获后重新发送合法消息 | 认证重放、交易重放 | 时间戳、随机数、序列号 |

### 3.3 常见攻击类型速览

| 大类 | 子类 | 说明 |
|------|------|------|
| **拒绝服务** | DDoS（SYN/UDP/ICMP/HTTP/放大） | 让目标不可用 |
| | CC 攻击 | HTTP 层 Flood |
| | 慢速攻击（Slowloris） | 慢速连接占满资源 |
| **扫描探测** | 端口扫描（全连接/SYN/ACK） | 发现开放端口 |
| | 漏洞扫描 | 发现系统/应用漏洞 |
| | 存活扫描（ping sweep） | 发现存活主机 |
| **暴力破解** | 密码爆破 | 试密码 |
| | 凭证填充 | 用泄露的密码库试 |
| | 验证码绕过 | 绕过验证机制 |
| **中间人攻击** | ARP 欺骗 | 二层 MITM |
| | SSL 剥离 | 把 HTTPS 降级成 HTTP |
| | DNS 欺骗 | 篡改 DNS 解析 |
| **Web 攻击** | SQL 注入 | 注入 SQL 语句 |
| | XSS 跨站脚本 | 注入恶意脚本 |
| | CSRF 跨站请求伪造 | 利用用户身份发起请求 |
| | 文件上传漏洞 | 上传恶意文件 |
| | 命令注入 | 注入系统命令 |
| | 越权访问 | 水平/垂直越权 |
| **恶意软件** | 病毒（Virus） | 感染其他文件 |
| | 蠕虫（Worm） | 自我复制传播 |
| | 木马（Trojan） | 伪装成正常软件 |
| | 勒索软件（Ransomware） | 加密数据索要赎金 |
| | 间谍软件（Spyware） | 窃取信息 |
| | Rootkit | 隐藏自身和攻击痕迹 |
| **社会工程** | 钓鱼（Phishing） | 伪造邮件/网站 |
| | 鱼叉钓鱼（Spear Phishing） | 定向精准钓鱼 |
| | 尾门（Tailgating） | 物理跟随进入 |
| | 伪装（Pretexting） | 编造身份骗取信任 |

## 四、各层攻击详解

### 4.1 物理层攻击

| 攻击类型 | 原理 | 影响 | 防御手段 |
|---------|------|------|---------|
| **物理破坏** | 砸毁设备、剪断线缆、断电 | 系统不可用 | 机房门禁、监控、冗余、UPS |
| **线缆窃听** | 在网络线缆上搭线窃取数据 | 数据泄露 | 加密传输、光纤（难窃听）、物理防护 |
| **电磁泄漏** | TEMPEST 攻击，接收电磁信号还原信息 | 数据泄露 | 电磁屏蔽、低辐射设备、加密 |
| **邪恶双子（Wi-Fi）** | 伪造 Wi-Fi 热点，用户连接后中间人 | 数据窃取、MITM | 企业 Wi-Fi 认证、VPN、提醒用户 |
| **USB 投放** | 放带毒 U 盘，有人捡到插入电脑 | 恶意代码执行 | 禁用 USB、安全培训、终端防护 |
| **冷启动攻击** | 关机后短时间内内存数据不消失，窃取加密密钥 | 密钥泄露 | 内存加密、物理安全、休眠时加密内存 |

### 4.2 数据链路层攻击

| 攻击类型 | 原理 | 影响 | 防御手段 |
|---------|------|------|---------|
| **ARP 欺骗/中毒** | 伪造 ARP 报文篡改 ARP 缓存，成为中间人 | MITM、数据窃取、流量劫持 | DAI、静态 ARP、端口安全、加密传输 |
| **MAC 欺骗** | 伪造源 MAC 地址 | 绕过端口安全、冒充其他设备 | 端口安全 + 802.1X、动态 ARP 检测 |
| **MAC 泛洪 / CAM 表溢出** | 大量伪造源 MAC 填满交换机 CAM 表，交换机退化成 Hub | 可以看到所有流量（嗅探） | 端口安全（限制 MAC 数量） |
| **VLAN 跳跃（交换机欺骗）** | 伪造 DTP 报文，让端口变成 Trunk，访问所有 VLAN | 绕过 VLAN 隔离 | 禁用 DTP、端口设为 access、nonegotiate |
| **VLAN 跳跃（双标签）** | 发送双层 VLAN 标签，剥离外层后内层标签生效 | 跳到其他 VLAN | Native VLAN 不用 VLAN 1、接入口检查标签 |
| **STP 攻击** | 发送伪造 BPDU 抢占根桥，控制拓扑 | 流量劫持、中间人 | BPDU Guard、Root Guard、指定根桥 |
| **802.1X 绕过** | 绕过网络接入认证 | 未授权访问网络 | EAP 类型选择、证书认证、动态 VLAN |

### 4.3 网络层攻击

| 攻击类型 | 原理 | 影响 | 防御手段 |
|---------|------|------|---------|
| **IP 欺骗** | 伪造源 IP 地址 | 绕过基于 IP 的访问控制、放大攻击 | uRPF、入口过滤、加密认证 |
| **Smurf 攻击** | 向广播地址发 ICMP Echo，源 IP 是受害者，放大攻击 | DDoS | 禁用广播 ping、入口过滤、uRPF |
| **ICMP 洪水** | 大量 ICMP 请求占满带宽/CPU | DoS | 限速、防火墙、流量清洗 |
| **分片攻击（Teardrop）** | 构造偏移重叠的分片包，导致系统崩溃 | 系统崩溃 | 现代系统已修复、防火墙检测 |
| **路由攻击** | 伪造路由信息、BGP 劫持 | 流量劫持、数据窃取 | 路由认证、BGP 安全（RPKI） |
| **IP 选项攻击** | 利用源路由等选项绕过安全控制 | 绕过访问控制 | 禁用源路由接受 |
| **死亡之 Ping** | 超大 ICMP 包导致系统崩溃 | 系统崩溃 | 现代系统已免疫 |

### 4.4 传输层攻击

| 攻击类型 | 原理 | 影响 | 防御手段 |
|---------|------|------|---------|
| **SYN Flood** | 大量伪造源 IP 的 SYN 包，占满半连接队列 | 拒绝服务 | SYN Cookies、增大队列、防火墙限速、DDoS 清洗 |
| **ACK Flood** | 大量 ACK 包消耗处理资源 | 拒绝服务 | 流量清洗、状态检测 |
| **UDP Flood** | 大量 UDP 包占满带宽 | 拒绝服务 | 流量清洗、限速 |
| **TCP 会话劫持** | 猜测序列号，插入到已建立的 TCP 连接中 | 数据篡改、会话劫持 | 加密传输（TLS/IPSec）、随机序列号 |
| **端口扫描** | 探测哪些端口开放、有什么服务 | 信息收集（攻击前侦察） | 端口安全、防火墙、减少暴露面 |
| **连接耗尽** | 建立大量连接不释放，占满连接表 | 拒绝服务 | 连接超时、连接数限制 |
| **RST 攻击** | 伪造 RST 包断开连接 | 连接中断、拒绝服务 | 加密 + 序列号随机化 |

### 4.5 应用层攻击

| 攻击类型 | 原理 | 影响 | 防御手段 |
|---------|------|------|---------|
| **SQL 注入** | 在输入中注入 SQL 语句，后端数据库执行 | 数据泄露、篡改、删除 | 参数化查询、输入验证、WAF、最小权限 |
| **XSS 跨站脚本** | 在页面注入恶意脚本，用户访问时执行 | Cookie 窃取、会话劫持、钓鱼 | 输入过滤、输出编码、CSP、HttpOnly |
| **CSRF 跨站请求伪造** | 利用已登录用户的身份发起恶意请求 | 未授权操作（改密码、转账等） | CSRF Token、SameSite Cookie、验证码 |
| **命令注入** | 在输入中注入系统命令，后端执行 | 系统命令执行、控制服务器 | 输入验证、禁用危险函数、最小权限 |
| **文件上传漏洞** | 上传恶意脚本文件，访问时执行 | 代码执行、控制服务器 | 文件类型校验、重命名、不可执行目录、WAF |
| **路径遍历** | 用 `../` 等绕过目录限制访问任意文件 | 敏感文件泄露 | 路径规范化、白名单、chroot |
| **越权访问** | 修改参数访问他人数据/管理员功能 | 数据泄露、未授权操作 | 权限校验、每接口鉴权、水平/垂直权限控制 |
| **HTTP Flood / CC 攻击** | 大量 HTTP 请求占满应用资源 | 拒绝服务 | WAF、验证码、限流、CDN、行为分析 |
| **慢速攻击（Slowloris）** | 慢速发送 HTTP 请求，占满连接 | 拒绝服务 | Web 服务器配置、mod_reqtimeout、WAF |
| **DNS 放大** | 向开放 DNS 服务器发伪造源 IP 的大请求，回复发给受害者 | DDoS 放大攻击 | 关闭递归 DNS、响应大小限制、Anycast |
| **DNS 劫持/欺骗** | 篡改 DNS 解析结果，引导到恶意网站 | 钓鱼、流量劫持 | DNSSEC、DoH/DoT、本地 host 防护 |
| **暴力破解** | 不断尝试用户名/密码组合 | 账号被盗 | 账号锁定、验证码、MFA、速率限制 |
| **凭证填充** | 用其他地方泄露的账号密码尝试登录 | 账号被盗 | 风控、异常登录检测、MFA |
| **会话劫持** | 窃取/猜测会话 ID，冒充用户 | 账号被盗 | 会话安全、HTTPS、HttpOnly + Secure Cookie |

### 4.6 社会工程学攻击

| 攻击类型 | 原理 | 影响 | 防御手段 |
|---------|------|------|---------|
| **钓鱼邮件** | 伪造邮件骗取点击/输入密码 | 账号被盗、恶意代码执行 | 邮件网关、SPF/DKIM/DMARC、安全培训 |
| **鱼叉钓鱼** | 针对特定目标的精准钓鱼（了解目标信息） | 成功率高、危害大 | 安全培训、邮件安全、MFA |
| **钓鱼网站** | 伪造登录页面骗取账号密码 | 账号被盗 | 浏览器安全提示、域名监测、安全培训 |
| **电话诈骗（Vishing）** | 冒充 IT/领导/客服打电话骗取信息 | 信息泄露、转账诈骗 | 安全培训、验证流程、多渠道确认 |
| **尾门 / 搭便车** | 物理上跟随授权人员进入受限区域 | 物理入侵 | 门禁制度、保安、安全意识 |
| **伪装 / 借口** | 编造身份和故事骗取信任和信息 | 信息泄露、权限获取 | 身份验证流程、安全培训 |
| **诱饵（Baiting）** | 用利益诱惑（免费下载、U 盘等） | 恶意代码执行 | 安全培训、终端防护、禁用 USB |

## 五、检测与防御思路

### 5.1 防御体系层次

```
纵深防御体系（从外到内）：

  ┌─────────────────────────────────────────────┐
  │         边界防护（防火墙 / DDoS 清洗）          │  ← 第一道门
  ├─────────────────────────────────────────────┤
  │       身份认证（MFA / SSO / 802.1X）          │  ← 身份验证
  ├─────────────────────────────────────────────┤
  │      入侵检测 / 防御（IDS / IPS / WAF）        │  ← 攻击检测阻断
  ├─────────────────────────────────────────────┤
  │       网络分段（VLAN / 微隔离 / 零信任）        │  ← 限制横向移动
  ├─────────────────────────────────────────────┤
  │     终端安全（EDR / 杀毒 / 补丁 / 加固）        │  ← 终端防护
  ├─────────────────────────────────────────────┤
  │     数据安全（加密 / 备份 / DLP / 脱敏）        │  ← 最后一道防线
  ├─────────────────────────────────────────────┤
  │   监控审计（SIEM / 日志 / 威胁情报 / 溯源）      │  ← 检测与响应
  └─────────────────────────────────────────────┘
```

### 5.2 检测方法

| 检测方法 | 英文 | 原理 | 优点 | 缺点 |
|---------|------|------|------|------|
| **特征检测** | Signature-based | 已知攻击的特征码匹配 | 准确、误报低 | 只能检测已知攻击 |
| **异常检测** | Anomaly-based | 学习正常行为，偏离就告警 | 能检测未知/0day | 误报率较高、调优难 |
| **行为分析** | Behavior-based | 分析行为模式（如攻击链各阶段） | 能检测复杂攻击 | 需要大量数据和分析 |
| **信誉检测** | Reputation-based | 基于 IP/域名/文件的信誉 | 简单有效 | 依赖情报源质量 |
| **沙箱检测** | Sandboxing | 在隔离环境中运行，观察行为 | 能检测未知恶意软件 | 有绕过技术、性能低 |
| **威胁情报** | Threat Intelligence | 利用外部情报发现威胁 | 提前感知 | 情报质量和时效性重要 |

### 5.3 各层防御手段汇总

| OSI 层级 | 主要攻击 | 主要防御手段 | 关键设备/技术 |
|---------|---------|-------------|-------------|
| **物理层** | 物理破坏、窃听、邪恶双子 | 机房安全、加密传输、Wi-Fi 安全 | 门禁、监控、WPA3、VPN |
| **链路层** | ARP 欺骗、MAC 泛洪、VLAN 跳跃 | 端口安全、DAI、BPDU Guard、802.1X | 交换机安全特性 |
| **网络层** | IP 欺骗、Smurf、路由攻击、DDoS | 防火墙、uRPF、ACL、SYN Cookies、DDoS 清洗 | 路由器、防火墙、DDoS 清洗设备 |
| **传输层** | SYN Flood、端口扫描、会话劫持 | 状态检测防火墙、连接限速、加密传输 | 防火墙、IPS、TLS/SSL |
| **应用层** | SQL 注入、XSS、CSRF、CC 攻击、钓鱼 | WAF、输入验证、代码安全、MFA、邮件安全 | WAF、邮件网关、身份认证系统 |
| **数据层** | 数据泄露、数据篡改 | 加密、备份、完整性校验、DLP | 加密系统、备份系统、DLP |
| **人员层** | 社会工程、钓鱼、内部威胁 | 安全培训、意识教育、MFA、审计 | 培训体系、管理制度 |

### 5.4 通用防御原则

| 原则 | 说明 |
|------|------|
| **默认拒绝** | 默认什么都不允许，明确允许的才放行 |
| **最小权限** | 只给完成工作所需的最小权限 |
| **纵深防御** | 多层防护，避免单点失效 |
| **攻击面收敛** | 尽量减少暴露的攻击面 |
| **失败安全** | 系统故障时进入安全状态（拒绝而非放行） |
| **安全左移** | 在开发/设计阶段就考虑安全（而非事后补丁） |
| **零信任** | 永不信任，始终验证 |
| **持续监控** | 假设已经被攻破，持续检测和响应 |
| **假设 breach** | 防御的同时准备好被攻破后的响应和恢复 |

## 六、授权测试与红蓝对抗

### 6.1 授权测试的概念

**授权测试（Authorized Testing）**：在获得系统所有者明确书面授权的前提下，对系统进行安全测试，发现漏洞并帮助修复。

| 类型 | 英文 | 说明 |
|------|------|------|
| **漏洞扫描** | Vulnerability Scanning | 用工具自动扫描已知漏洞 |
| **渗透测试** | Penetration Testing | 模拟攻击者尝试突破系统，找到漏洞并证明可利用 |
| **红队评估** | Red Team Assessment | 模拟真实 APT 攻击，全面测试防御体系 |
| **红蓝对抗** | Red vs Blue | 红队攻击，蓝队防御，实战化检验 |
| **众测 / 漏洞赏金** | Bug Bounty | 邀请白帽子找漏洞，按漏洞付费 |

### 6.2 渗透测试流程

```
渗透测试标准流程（PTES 标准）：

  1. 前期交互（Pre-engagement Interactions）
     → 签订合同、明确范围、获得授权书
        │
        ▼
  2. 情报收集（Intelligence Gathering）
     → 收集目标信息（被动 + 主动）
        │
        ▼
  3. 威胁建模（Threat Modeling）
     → 分析攻击路径、确定优先级
        │
        ▼
  4. 漏洞分析（Vulnerability Analysis）
     → 发现和验证漏洞
        │
        ▼
  5. 漏洞利用（Exploitation）
     → 利用漏洞获取访问权限
        │
        ▼
  6. 后渗透（Post Exploitation）
     → 提权、横向移动、数据收集、持久化
        │
        ▼
  7. 报告（Reporting）
     → 输出报告：漏洞详情、风险等级、修复建议
```

> ⚠️ **合法与非法的边界**：
> - ✅ **合法**：有明确书面授权、在授权范围内操作、不破坏数据、保密结果
> - ❌ **非法**：没有授权、超出授权范围、造成损失、数据泄露
> - **注意**：即使是"测试"，没有授权就是违法的，可能承担民事甚至刑事责任

### 6.3 红蓝对抗

| 角色 | 目标 | 核心能力 | 评价标准 |
|------|------|---------|---------|
| **红队** | 尽可能攻破目标系统、达成预设目标 | 渗透测试、漏洞利用、社工、免杀、隐蔽 | 是否达成目标、突破了几层防御 |
| **蓝队** | 发现并阻止红队的攻击，保护系统 | 监控分析、检测响应、威胁狩猎、加固 | 是否检测到攻击、检测时间、阻断效果 |

```
红蓝对抗价值：

  红队视角：
    → 从攻击者角度验证防御体系的有效性
    → 发现真实存在的漏洞和弱点
    → 测试蓝队的检测和响应能力

  蓝队视角：
    → 在真实攻击中检验检测和响应流程
    → 发现监控盲区和检测规则的不足
    → 提升应急响应能力

  组织视角：
    → 攻防两端共同提升
    → 用实战检验安全建设的效果
    → 比单纯的合规检查更有实际价值
```

### 6.4 授权测试的合规性要求

进行授权安全测试时，必须满足以下要求：

| 要求 | 说明 |
|------|------|
| **书面授权** | 必须有系统所有者的正式书面授权（合同/授权书） |
| **范围明确** | 测试范围、时间、方法都要明确约定 |
| **数据保护** | 测试中接触到的数据要保密，不得泄露或带走 |
| **不造成破坏** | 不得破坏生产系统和数据，危险操作要谨慎 |
| **报告与修复** | 测试后要提交报告并协助修复 |
| **保密协议** | 双方签订保密协议（NDA） |
| **遵守法律** | 遵守当地法律法规，不得涉及违法活动 |

> **记住**：白帽子和黑帽子的区别，不在于技术，而在于是否有授权。技术本身是中性的，关键在于使用的目的和方式是否合法合规。

---

> **总结**：网络威胁多种多样——从外部攻击者到内部威胁，从 DDoS 到 APT，从物理层到应用层，从技术攻击到社会工程，每个层面都有不同的攻击手法。理解攻击的原理不是为了攻击，而是为了更好地防御——知道敌人怎么进攻，才能有针对性地布防。攻击链和 MITRE ATT&CK 框架帮助我们系统化地理解攻击的各个阶段，从而在每个环节部署检测和防护措施。记住：最好的防御不是某一个产品，而是纵深防御的体系——多层防护、持续监控、快速响应、不断改进。而授权测试和红蓝对抗，则是检验防御体系是否真正有效的试金石。
