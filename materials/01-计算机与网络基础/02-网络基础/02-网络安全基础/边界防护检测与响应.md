## 一、防火墙技术

### 1.1 防火墙的定义与作用

**防火墙（Firewall）**：部署在网络边界或主机上的安全设备/软件，根据预设的安全规则，对进出的网络流量进行检查和控制（允许/拒绝/丢弃）。

| 作用 | 说明 |
|------|------|
| **访问控制** | 根据规则放行或阻止流量 |
| **网络隔离** | 分隔不同安全级别的网络区域 |
| **攻击防护** | 阻挡已知的攻击流量（DDoS、扫描等） |
| **日志审计** | 记录所有通过的流量，便于审计和溯源 |
| **NAT** | 网络地址转换，隐藏内网结构 |

### 1.2 防火墙的代际演进

| 代际 | 类型 | 工作层级 | 核心技术 | 特点 | 典型产品 |
|------|------|---------|---------|------|---------|
| **第一代** | 包过滤防火墙 | 网络层/传输层 | ACL 规则匹配 | 速度快、功能简单 | 路由器 ACL、iptables |
| **第二代** | 应用代理防火墙 | 应用层 | 代理服务 | 安全性高、性能差 | 早期堡垒机 |
| **第三代** | 状态检测防火墙 | 网络层+ | 连接状态跟踪 | 安全+性能平衡 | 传统防火墙 |
| **第四代** | 应用层防火墙 / WAF | 应用层 | 深度包检测 | 防护 Web 攻击 | WAF、NGFW |
| **第五代** | 下一代防火墙（NGFW） | 多层 | 集成 IPS/应用识别/用户识别 | 功能全面 | Palo Alto、Fortinet |

### 1.3 防火墙类型详解

#### （1）包过滤防火墙（Packet Filtering）

基于 IP 地址、端口、协议等包头信息进行过滤，每条规则独立判断。

```
工作原理：

  数据包到达 → 逐条匹配规则 → 匹配到 → 执行动作（允许/拒绝/丢弃）
                    ↓ 不匹配
                  下一条规则
                    ↓ 都不匹配
                  默认策略
```

| 优点 | 缺点 |
|------|------|
| 速度快、性能高 | 只能看包头，看不到应用层内容 |
| 实现简单、成本低 | 无法检测应用层攻击（SQL 注入、XSS 等） |
| 透明、对应用无影响 | 无法处理动态端口协议（如 FTP） |

#### （2）状态检测防火墙（Stateful Inspection）

跟踪每个连接的状态，只放行属于合法连接的数据包。

```
状态检测原理：

  新建连接 SYN → 检查规则 → 允许 → 加入状态表
  后续数据包 → 查状态表 → 属于已有连接 → 直接放行（不用再查规则）

  状态表记录：源IP、源端口、目的IP、目的端口、协议、状态
```

| 优点 | 缺点 |
|------|------|
| 比包过滤更安全（只放行合法响应） | 比包过滤稍慢（需要维护状态表） |
| 性能也比较好 | 还是看不到应用层内容 |
| 支持动态端口协议 | SYN Flood 可能占满状态表 |

#### （3）应用层防火墙 / WAF

深入到应用层，理解应用协议的内容（如 HTTP 的 URL、参数、Cookie）。

| 类型 | 说明 |
|------|------|
| **WAF（Web 应用防火墙）** | 防护 Web 攻击（SQL 注入、XSS、CSRF 等） |
| **数据库防火墙** | 防护数据库攻击（SQL 注入、异常查询） |
| **邮件网关** | 防护垃圾邮件、钓鱼、病毒附件 |
| **API 网关** | API 安全防护（认证、限流、签名） |

#### （4）下一代防火墙（NGFW）

**NGFW（Next-Generation Firewall）**：集成了传统防火墙 + IPS + 应用识别 + 用户识别 + 内容过滤等多种功能的一体化设备。

| NGFW 核心能力 | 说明 |
|--------------|------|
| **传统防火墙功能** | 包过滤、NAT、VPN |
| **IPS 功能** | 入侵检测与防御 |
| **应用识别** | 识别具体应用（如微信、QQ、迅雷），不是只看端口 |
| **用户识别** | 基于用户/组的策略，不只是 IP |
| **内容过滤** | URL 过滤、文件过滤、病毒查杀 |
| **威胁情报** | 集成威胁情报，识别恶意 IP/域名 |

### 1.4 防火墙部署方式

| 部署模式 | 说明 | 适用场景 |
|---------|------|---------|
| **路由模式** | 作为三层设备，有 IP 地址，转发路由 | 网络边界、不同网段之间 |
| **透明模式** | 二层设备，像网线一样串接，没有 IP | 不想改网络拓扑、透明部署 |
| **混合模式** | 部分接口路由，部分接口透明 | 复杂网络环境 |
| **旁路模式** | 不串接，镜像流量，只检测不阻断 | IDS 模式、流量分析 |

> ⚠️ **防火墙不是万能的**：
> - 防火墙只能防护基于已知特征的攻击，0day 攻击防不住
> - 应用层攻击（如业务逻辑漏洞）防火墙看不到
> - 内部攻击防火墙管不到（所以需要零信任和内网防护）
> - 防火墙配置错误反而可能成为安全漏洞

### 2.2 iptables

#### 表和链

```
iptables 的表和链：

  raw 表（原始包）──► PREROUTING / OUTPUT
     │
     ▼
  mangle 表（修改包）──► PREROUTING / INPUT / FORWARD / OUTPUT / POSTROUTING
     │
     ▼
  nat 表（地址转换）──► PREROUTING / INPUT / OUTPUT / POSTROUTING
     │
     ▼
  filter 表（过滤）──► INPUT / FORWARD / OUTPUT
     │
     ▼
  目标（ACCEPT / DROP / REJECT / LOG / DNAT / SNAT / MASQUERADE ...）
```

| 表 | 作用 | 内置链 |
|----|------|--------|
| **filter** | 包过滤（最常用） | INPUT、FORWARD、OUTPUT |
| **nat** | 网络地址转换 | PREROUTING、POSTROUTING、OUTPUT |
| **mangle** | 修改数据包（TOS、TTL、MARK 等） | 5 条链都有 |
| **raw** | 原始包处理、连接跟踪豁免 | PREROUTING、OUTPUT |
| **security** | SELinux 安全标记 | INPUT、FORWARD、OUTPUT |

| 链 | 触发时机 |
|----|---------|
| **PREROUTING** | 数据包刚到，路由判断之前 |
| **INPUT** | 目的地是本机的包 |
| **FORWARD** | 经过本机转发的包 |
| **OUTPUT** | 本机产生的、要发出去的包 |
| **POSTROUTING** | 路由判断之后，发出去之前 |

```
数据包流向：

  入站到本机：
    网络 → PREROUTING → 路由判断 → INPUT → 本机进程

  转发（经过本机）：
    网络 → PREROUTING → 路由判断 → FORWARD → POSTROUTING → 网络

  出站（本机产生）：
    本机进程 → OUTPUT → 路由判断 → POSTROUTING → 网络
```

#### 常用命令 🔑

```bash
# ===== 查看规则 =====
iptables -L -n -v                    # filter 表，带计数
iptables -L -n -v --line-numbers     # 带行号
iptables -t nat -L -n -v             # nat 表
iptables -t mangle -L -n -v          # mangle 表
iptables -S                          # 以保存格式显示所有规则
iptables -S INPUT                    # 显示指定链

# ===== 基本规则配置 =====
# 设置默认策略
iptables -P INPUT DROP               # 默认拒绝入站（最安全）
iptables -P FORWARD DROP             # 默认拒绝转发
iptables -P OUTPUT ACCEPT            # 默认允许出站

# 放行已建立的连接
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# 放行回环接口
iptables -A INPUT -i lo -j ACCEPT

# 放行特定端口
iptables -A INPUT -p tcp --dport 22 -j ACCEPT          # SSH
iptables -A INPUT -p tcp --dport 80 -j ACCEPT          # HTTP
iptables -A INPUT -p tcp --dport 443 -j ACCEPT         # HTTPS

# 只允许特定 IP 访问
iptables -A INPUT -p tcp --dport 22 -s 192.168.1.0/24 -j ACCEPT
iptables -A INPUT -p tcp --dport 22 -s 10.0.0.5 -j ACCEPT

# 放行 ICMP（ping）
iptables -A INPUT -p icmp --icmp-type echo-request -j ACCEPT

# 按行号插入/删除
iptables -I INPUT 5 -p tcp --dport 8080 -j ACCEPT   # 在第 5 行前插入
iptables -D INPUT 5                                 # 删除第 5 行
iptables -D INPUT -p tcp --dport 8080 -j ACCEPT     # 按内容删除

# ===== 扩展模块 =====
# 限制速率（防 DDoS/暴力破解）
iptables -A INPUT -p tcp --dport 22 -m limit --limit 10/min --limit-burst 5 -j ACCEPT

# 连接数限制
iptables -A INPUT -p tcp --dport 80 -m connlimit --connlimit-above 50 -j DROP

# 按 MAC 地址过滤
iptables -A INPUT -m mac --mac-source 00:11:22:33:44:55 -j ACCEPT

# 字符串匹配（简单应用层过滤）
iptables -A INPUT -p tcp --dport 80 -m string --string "sqlmap" --algo bm -j DROP

# ===== NAT 配置 =====
# SNAT（源地址转换，内网访问公网）
iptables -t nat -A POSTROUTING -s 192.168.1.0/24 -o eth0 -j SNAT --to-source 公网IP

# MASQUERADE（动态 IP 用，如拨号上网）
iptables -t nat -A POSTROUTING -s 192.168.1.0/24 -o eth0 -j MASQUERADE

# DNAT / 端口映射（公网端口映射到内网）
iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 8080 -j DNAT --to-destination 192.168.1.100:80

# 端口转发（本机）
iptables -t nat -A PREROUTING -p tcp --dport 80 -j REDIRECT --to-port 8080

# ===== 保存和恢复 =====
# Debian/Ubuntu
iptables-save > /etc/iptables/rules.v4
iptables-restore < /etc/iptables/rules.v4

# RHEL/CentOS（iptables-services）
service iptables save
```

> ⚠️ **高风险警告**：
> - 远程操作时，如果默认策略是 DROP，清空规则前一定要先改成 ACCEPT，否则会立即断开连接！
> - 正确顺序：`iptables -P INPUT ACCEPT && iptables -F`
> - 建议配合定时回滚：`echo "iptables-restore < backup" | at now + 5 min`
> - 先在测试环境验证

### 2.3 nftables

**nftables** 是 iptables 的继任者，从 Linux 内核 3.13 开始引入，提供更简洁的语法和更好的性能。

```bash
# ===== 基本概念 =====
# nftables 结构：
#   tables → chains → rules
# 不再像 iptables 那样有固定的表和链

# ===== 查看 =====
nft list ruleset                    # 所有规则
nft list tables                     # 所有表
nft list table filter               # 指定表
nft list chain filter input         # 指定链

# ===== 表和链管理 =====
nft add table inet filter           # 创建表（inet = IPv4+IPv6）
nft add chain inet filter input { type filter hook input priority 0 \; }  # 创建链
nft delete table inet filter        # 删除表
nft flush table inet filter         # 清空表

# ===== 规则配置 =====
# 基本语法：nft add rule <表> <链> <匹配条件> <动作>

# 允许已建立的连接
nft add rule inet filter input ct state established,related accept

# 允许回环
nft add rule inet filter input iif lo accept

# 允许 SSH
nft add rule inet filter input tcp dport 22 accept

# 允许特定 IP 访问
nft add rule inet filter input ip saddr 192.168.1.0/24 tcp dport 22 accept

# 默认拒绝（放在最后）
nft add rule inet filter input drop

# ===== NAT =====
nft add table nat
nft add chain nat prerouting { type nat hook prerouting priority -100 \; }
nft add chain nat postrouting { type nat hook postrouting priority 100 \; }

# MASQUERADE
nft add rule nat postrouting oifname eth0 masquerade

# DNAT
nft add rule nat prerouting iif eth0 tcp dport 8080 dnat to 192.168.1.100:80

# ===== 集合（set）—— nftables 的强大功能 =====
# 创建集合
nft add set inet filter allowed_ips { type ipv4_addr \; }

# 添加元素
nft add element inet filter allowed_ips { 192.168.1.1, 10.0.0.5 }

# 使用集合
nft add rule inet filter input ip saddr @allowed_ips tcp dport 22 accept

# ===== 保存和恢复 =====
nft list ruleset > /etc/nftables.conf
nft -f /etc/nftables.conf
```

### 2.4 firewalld

**firewalld** 是 RHEL/CentOS/Fedora 默认的防火墙管理工具，基于 zone（区域）概念，动态管理规则，支持 D-Bus 接口。

```bash
# ===== 基本操作 =====
systemctl start firewalld
systemctl enable firewalld
firewall-cmd --state                    # 运行状态
firewall-cmd --reload                   # 重新加载（不中断连接）
firewall-cmd --complete-reload          # 完全重载（中断连接）

# ===== 区域（Zone）管理 =====
firewall-cmd --get-default-zone        # 默认区域
firewall-cmd --set-default-zone=public # 设置默认区域
firewall-cmd --get-active-zones        # 活跃的区域
firewall-cmd --list-all-zones          # 所有区域详细信息
firewall-cmd --zone=public --list-all   # 指定区域信息

# 常见区域：
#   drop     → 丢弃所有入站（最严格）
#   block    → 拒绝入站（返回 icmp-host-prohibited）
#   public   → 公共区域（默认）
#   external → 外部网络（NAT）
#   dmz      → DMZ 区
#   work     → 工作网络
#   home     → 家庭网络
#   internal → 内部网络
#   trusted  → 信任所有（最宽松）

# ===== 服务管理 =====
firewall-cmd --get-services           # 所有可用服务
firewall-cmd --add-service=ssh                # 临时添加
firewall-cmd --add-service=ssh --permanent    # 永久添加
firewall-cmd --remove-service=ssh --permanent # 永久删除

# ===== 端口管理 =====
firewall-cmd --add-port=8080/tcp --permanent
firewall-cmd --add-port=5000-5100/udp --permanent
firewall-cmd --remove-port=8080/tcp --permanent

# ===== 源地址管理 =====
firewall-cmd --add-source=192.168.1.0/24 --zone=trusted

# ===== 端口转发 =====
firewall-cmd --add-forward-port=port=80:proto=tcp:toport=8080 --permanent
firewall-cmd --add-forward-port=port=80:proto=tcp:toaddr=192.168.1.100 --permanent
firewall-cmd --add-masquerade --permanent   # 开启 NAT（转发需要）

# ===== 富规则（Rich Rules） =====
# 允许特定 IP 访问 SSH
firewall-cmd --permanent --add-rich-rule='
  rule family="ipv4" source address="192.168.1.0/24" service name="ssh" accept'

# 限制速率
firewall-cmd --permanent --add-rich-rule='
  rule family="ipv4" service name="ssh" limit value="10/m" accept'

# 拒绝特定 IP
firewall-cmd --permanent --add-rich-rule='
  rule family="ipv4" source address="10.0.0.5" service name="ssh" reject'

# ===== 直接规则（直接用 iptables 语法） =====
firewall-cmd --permanent --direct --add-rule ipv4 filter INPUT 0 -p tcp --dport 22 -j ACCEPT
```

### 2.5 ufw（Uncomplicated Firewall）

**ufw** 是 Ubuntu 默认的防火墙配置工具，设计目标是简单易用。

```bash
# ===== 基本操作 =====
ufw status                         # 状态
ufw status verbose                 # 详细状态
ufw enable                         # 启用
ufw disable                        # 禁用
ufw reload                         # 重新加载
ufw reset                          # 重置（清除所有规则）

# ===== 默认策略 =====
ufw default deny incoming          # 默认拒绝入站
ufw default allow outgoing         # 默认允许出站
ufw default deny forwarded         # 默认拒绝转发

# ===== 允许/拒绝 =====
ufw allow 22/tcp                   # 允许 22 端口 TCP
ufw allow 80                       # 允许 80 端口（TCP+UDP）
ufw allow from 192.168.1.0/24      # 允许指定网段
ufw allow from 192.168.1.5 to any port 22  # 指定 IP 访问指定端口
ufw allow in on eth0 to any port 80        # 指定接口
ufw deny 23/tcp                    # 拒绝 23 端口
ufw reject 23/tcp                  # 拒绝并回复（对方知道被拒绝）

# ===== 应用配置文件 =====
ufw app list                       # 可用应用
ufw app info OpenSSH               # 应用详情
ufw allow OpenSSH                  # 按应用名允许

# ===== 删除规则 =====
ufw delete allow 22/tcp            # 按内容删除
ufw delete 3                       # 按编号删除
ufw status numbered                # 查看编号

# ===== 限制速率 =====
ufw limit 22/tcp                   # 限制 SSH（默认 6 次/30秒）
ufw limit in 80/tcp                # 限制 80 端口
```

### 2.6 防火墙最佳实践

```
防火墙配置最佳实践：

1. 默认策略
   □ 默认拒绝（DENY/DROP）入站流量
   □ 默认允许出站流量（或按需限制）
   □ 默认拒绝转发（非路由器）

2. 规则原则
   □ 白名单原则：明确允许的才放行，其他都拒绝
   □ 规则尽量少而精（规则太多性能下降，也难维护）
   □ 高命中规则放前面（按频率排序）
   □ 明确注释每条规则的用途

3. 管理规范
   □ 修改前备份配置
   □ 修改后测试验证
   □ 定期审查和清理规则
   □ 变更管理流程（谁改的、为什么改、什么时候改的）

4. 安全加固
   □ 开启状态检测
   □ SYN Cookies（防 SYN Flood）
   □ 速率限制（防暴力破解/扫描）
   □ 连接数限制
   □ 禁用不必要的 ICMP 类型
   □ 入站过滤（uRPF，防 IP 欺骗）

5. 监控审计
   □ 记录被拒绝的流量（日志）
   □ 监控防火墙日志异常
   □ 定期分析流量模式
   □ 规则命中统计（清理无用规则）
```

## 三、IDS 与 IPS

### 3.1 IDS vs IPS

| 类型 | 英文 | 作用 | 部署方式 | 对业务的影响 |
|------|------|------|---------|-------------|
| **IDS** | Intrusion Detection System | 检测攻击，发出告警 | 旁路（镜像流量） | 无（不影响正常流量） |
| **IPS** | Intrusion Prevention System | 检测并阻断攻击 | 串接（在线） | 有（性能影响、误阻断风险） |

### 3.2 检测方法

| 方法 | 英文 | 原理 | 优点 | 缺点 |
|------|------|------|------|------|
| **特征检测** | Signature-based | 匹配已知攻击的特征码 | 准确、误报低 | 只能检测已知攻击 |
| **异常检测** | Anomaly-based | 学习正常行为，偏离即告警 | 能检测未知攻击/0day | 误报率高、需要学习期 |
| **协议分析** | Protocol Analysis | 分析协议是否符合规范 | 检测协议异常 | 只能检测协议相关 |
| **威胁情报** | Threat Intelligence | 匹配恶意 IP/域名/哈希 | 提前感知威胁 | 依赖情报质量 |

### 3.3 常见 IDS/IPS 工具

| 工具 | 类型 | 特点 | 许可 |
|------|------|------|------|
| **Snort** | IDS/IPS | 最经典、最广泛使用，规则丰富 | 开源 |
| **Suricata** | IDS/IPS | 多线程、高性能、支持 IPS 模式、自动规则管理 | 开源 |
| **Zeek（原 Bro）** | NSM | 网络安全监控，重在分析和日志，不是纯特征匹配 | 开源 |
| **OSSEC** | HIDS | 主机入侵检测，文件完整性、日志分析 | 开源 |
| **Wazuh** | HIDS/XDR | OSSEC 的增强版，更现代化 | 开源 |
| **Fail2ban** | 轻量 IPS | 扫描日志，封禁暴力破解 IP | 开源 |

### 3.4 Snort

```bash

snort -dev -i eth0               # 显示详细数据链路层信息

# 包记录模式
snort -i eth0 -l /var/log/snort  # 记录到目录

# IDS 模式（用规则检测）
snort -c /etc/snort/snort.conf -i eth0

# 快速测试规则
snort -c /etc/snort/snort.conf -T  # 测试配置

# ===== 规则语法 =====
# 动作  协议  源IP  源端口  方向  目的IP  目的端口  (规则选项)
#
# 动作：alert / log / pass / drop / reject / sdrop
# 方向：->（单向） <>（双向）
#
# 示例：
# alert tcp any any -> 192.168.1.0/24 22 (msg:"SSH 扫描"; flags:S; threshold:type threshold, track by_src, count 5, seconds 60; sid:1000001;)

#   msg:"..."        告警消息
#   sid:123          规则 ID
#   rev:1            版本
#   flags:S          TCP 标志位（SYN）
#   content:"..."    内容匹配
#   nocase           不区分大小写
#   threshold:       阈值（触发频率限制）
#   flow:established 已建立的连接
```

## 四、VPN 技术

### 4.1 VPN 概述

**VPN（Virtual Private Network，虚拟专用网络）**：在公共网络（如互联网）上建立加密的隧道，实现安全的远程访问或站点互联。

| VPN 类型 | 说明 | 典型协议 |
|---------|------|---------|
| **远程访问 VPN** | 个人用户远程接入企业内网 | SSL VPN、IPsec（客户端模式）、WireGuard |
| **站点到站点 VPN** | 两个办公室之间通过互联网连接 | IPsec、WireGuard |
| **SSL VPN** | 基于 SSL/TLS 的 VPN，浏览器或客户端 | OpenVPN、各类商业 SSL VPN |
| **IPsec VPN** | 网络层加密，安全性高 | IKEv1/IKEv2 + ESP |
| **点对点 VPN** | 两台机器直接连 | WireGuard、GRE over IPsec |

### 4.2 IPsec VPN

详见密码学与安全协议章节。这里补充实践部分。

```bash
# ===== strongSwan（IPsec 实现） =====
# 安装
apt install strongswan
yum install strongswan

# 配置文件：
#   /etc/ipsec.conf          主配置
#   /etc/ipsec.secrets       密钥/证书
#   /etc/strongswan.d/       模块化配置

# 基本命令：
ipsec status                 # 状态
```

### 4.3 OpenVPN

**OpenVPN**：基于 SSL/TLS 的 VPN，使用 OpenSSL 库，跨平台，配置灵活。

| 优点 | 缺点 |
|------|------|
| 配置灵活、功能强大 | 性能比 IPsec（硬件加速）稍差 |
| 跨平台（Windows/Mac/Linux/移动） | 不是标准协议 |
| 穿透 NAT 能力强 | |
| 支持 TCP 和 UDP | |

```bash
# 安装
apt install openvpn
yum install openvpn

# ===== 服务器配置示例（/etc/openvpn/server.conf） =====
port 1194
proto udp
dev tun
ca ca.crt
cert server.crt
key server.key
dh dh.pem
server 10.8.0.0 255.255.255.0    # VPN 地址池
ifconfig-pool-persist ipp.txt
push "route 192.168.1.0 255.255.255.0"  # 推送内网路由
push "dhcp-option DNS 8.8.8.8"
keepalive 10 120
cipher AES-256-GCM
auth SHA256
user nobody
group nogroup
persist-key
persist-tun
status openvpn-status.log
verb 3

# ===== 客户端配置示例（client.ovpn） =====
client
dev tun
proto udp
remote server.example.com 1194
resolv-retry infinite
nobind
persist-key
persist-tun
ca ca.crt
cert client.crt
key client.key
cipher AES-256-GCM
auth SHA256
verb 3

# ===== 启动 =====
systemctl start openvpn@server
systemctl enable openvpn@server

# 查看连接状态
cat /var/log/openvpn/openvpn-status.log
```

### 4.4 WireGuard

**WireGuard**：新一代 VPN 协议，设计简洁、性能极高、代码量小（约 4000 行），易于审计。

| 优点 | 说明 |
|------|------|
| **性能高** | 内核模块实现，比 OpenVPN 快很多 |
| **代码量小** | 约 4000 行，易于审计和维护 |
| **配置简单** | 配置文件非常简洁 |
| **现代加密** | Curve25519 + ChaCha20-Poly1305 + BLAKE2s |
| **漫游支持** | 支持 IP 漫游（手机切网络不断） |

```bash
# 安装
apt install wireguard
yum install wireguard-tools

# ===== 生成密钥 =====
# 生成私钥
wg genkey > privatekey
# 从私钥生成公钥
wg pubkey < privatekey > publickey
# 或者一行搞定
wg genkey | tee privatekey | wg pubkey > publickey

# ===== 服务器配置（/etc/wireguard/wg0.conf） =====
[Interface]
Address = 10.0.0.1/24
ListenPort = 51820
PrivateKey = <服务器私钥>
# 防火墙和转发（按需）
PostUp = iptables -A FORWARD -i %i -j ACCEPT; iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
PostDown = iptables -D FORWARD -i %i -j ACCEPT; iptables -t nat -D POSTROUTING -o eth0 -j MASQUERADE

# 客户端 1
[Peer]
PublicKey = <客户端1公钥>
AllowedIPs = 10.0.0.2/32

# 客户端 2
[Peer]
PublicKey = <客户端2公钥>
AllowedIPs = 10.0.0.3/32

# ===== 客户端配置（/etc/wireguard/wg0.conf） =====
[Interface]
Address = 10.0.0.2/32
PrivateKey = <客户端私钥>
DNS = 8.8.8.8

[Peer]
PublicKey = <服务器公钥>
Endpoint = server.example.com:51820
AllowedIPs = 10.0.0.0/24, 192.168.1.0/24  # 要走 VPN 的网段
PersistentKeepalive = 25                    # 保持连接（NAT 后面需要）

# ===== 启动与管理 =====
wg-quick up wg0                    # 启动
wg-quick down wg0                  # 停止
systemctl enable wg-quick@wg0      # 开机自启

# 查看状态
wg show
wg show wg0
wg show wg0 endpoints              # 查看对端地址
wg show wg0 transfer               # 查看流量统计

# 动态添加/删除 peer（不需要重启）🔑
wg set wg0 peer <公钥> allowed-ips 10.0.0.5/32
wg set wg0 peer <公钥> remove
```

> ⚠️ **VPN 安全警告**：
> - VPN 不是万能的——连上 VPN 就等于接入了内网，客户端安全也很重要
> - 密钥和证书要妥善保管，定期轮换
> - VPN 账号也要有 MFA 保护
> - 最小权限原则：只给需要访问的资源，不要全网络访问
> - 记录和审计 VPN 登录和流量

### 4.5 VPN 对比

| 特性 | IPsec | OpenVPN | WireGuard | SSL VPN（浏览器） |
|------|-------|---------|-----------|------------------|
| **协议层级** | 网络层 | 应用层/传输层 | 网络层（UDP） | 应用层 |
| **加密** | ESP（AES 等） | TLS（OpenSSL） | ChaCha20Poly1305 | TLS |
| **性能** | 高（硬件加速） | 中 | 很高 | 较低 |
| **配置复杂度** | 高 | 中 | 很低 | 低（浏览器用） |
| **穿透 NAT** | 一般（需要 NAT-T） | 好 | 好 | 很好（HTTPS 端口） |
| **跨平台** | 各系统支持 | 很好 | 支持越来越多 | 很好（浏览器） |
| **标准性** | 国际标准 | 开源事实标准 | 已进入 Linux 内核 | 标准 |
| **适用场景** | 站点到站点、企业 | 远程访问、灵活部署 | 各种场景、高性能 | 远程办公、Web 应用 |

## 五、零信任与微分段

### 5.1 零信任（Zero Trust）

**零信任**："永不信任，始终验证"（Never Trust, Always Verify）。不因为你在内网就信任你，每次访问都要验证身份和上下文。

| 传统边界安全 | 零信任安全 |
|------------|-----------|
| 内网 = 可信 | 没有可信区域 |
| 一次认证，持续访问 | 每次访问都验证 |
| 基于位置的信任 | 基于身份和上下文的信任 |
| 粗粒度控制 | 细粒度、动态控制 |
| 护城河模式 | 微隔离模式 |

**零信任三大核心原则**（NIST SP 800-207）：

1. **持续验证** — 永不假设信任，持续评估身份、设备、环境、风险
2. **最小权限访问** — 仅授予完成当前操作所需的最小权限，及时回收
3. **假设 breach（假设被攻破）** — 假设已经被攻破，通过检测和响应最小化损失和影响范围

**零信任关键技术**：

| 技术 | 作用 |
|------|------|
| **身份认证（MFA）** | 强身份验证是零信任的基础 |
| **身份管理（IAM）** | 统一身份、SSO、生命周期管理 |
| **微分段 / 微隔离** | 内部网络也分段，限制横向移动 |
| **软件定义边界（SDP）** | 先认证再连接，隐藏服务（默认不可见） |
| **零信任网络访问（ZTNA）** | 基于身份的应用访问，不是网络层访问 |
| **持续信任评估** | 实时评估风险，动态调整权限 |
| **XDR / 遥测** | 全面的数据收集和分析 |

### 5.2 微分段（Microsegmentation）

**微分段**：把数据中心或云环境细分成很多小的安全区域，每个区域之间都有访问控制，防止攻击者横向移动。

```
传统数据中心：

  互联网 → 防火墙 → 整个内网（一个大的广播域，内部任意访问）
                          ↑
                      攻破一台 → 横向移动 → 控制整个网络

微分段数据中心：

  Web 区 ↔ FW ↔ App 区 ↔ FW ↔ DB 区
    │              │            │
    └──── 每段之间都有防火墙 ────┘
                          ↑
              攻破 Web 区 → 也进不了 App 和 DB 区
              横向移动被每一段的防火墙阻挡
```

| 微分段实现方式 | 说明 | 粒度 |
|--------------|------|------|
| **VLAN + ACL** | 传统方式，VLAN 分隔 + ACL | 粗（VLAN 级） |
| **防火墙分区** | 物理或虚拟防火墙分隔 | 中（区域级） |
| **主机防火墙** | 每台主机自己的防火墙（iptables） | 细（主机级） |
| **SDN 微分段** | 软件定义网络，流表控制 | 很细（可到应用/进程） |
| **服务网格（Service Mesh）** | 微服务间的 mTLS + 鉴权 | 很细（服务级） |

> 零信任不是某个产品，而是一种架构理念和安全范式的转变。它需要身份、网络、应用、数据等多个层面的技术配合，不是买一个"零信任设备"就能实现的。

## 六、日志、SIEM 与 SOC

### 6.1 日志的重要性

日志是安全监控、事件调查、合规审计的基础。

| 日志类型 | 来源 | 用途 |
|---------|------|------|
| **系统日志** | 操作系统（syslog/journald） | 系统事件、登录、服务状态 |
| **安全设备日志** | 防火墙、IDS/IPS、WAF | 攻击检测、流量审计 |
| **应用日志** | Web 服务器、数据库、应用 | 业务事件、错误、访问记录 |
| **认证日志** | SSH、AD、LDAP、SSO | 登录事件、账号管理 |
| **审计日志** | 审计系统、数据库审计 | 操作审计、合规 |
| **网络流量日志** | NetFlow/IPFIX、Zeek | 流量分析、异常检测 |
| **DNS 日志** | DNS 服务器 | C2 检测、数据泄露检测 |

**日志级别（Syslog）**：

| 级别 | 数值 | 说明 |
|------|------|------|
| EMERG | 0 | 紧急，系统不可用 |
| ALERT | 1 | 警报，需要立即处理 |
| CRIT | 2 | 严重 |
| ERR | 3 | 错误 |
| WARNING | 4 | 警告 |
| NOTICE | 5 | 通知（正常但重要） |
| INFO | 6 | 信息 |
| DEBUG | 7 | 调试 |

### 6.2 SIEM

**SIEM（Security Information and Event Management，安全信息与事件管理）**：集中收集、存储、分析、关联各种安全日志和事件，提供统一的安全监控视图。

```
SIEM 工作流：

  各种设备/系统日志 ──┐
  安全设备告警 ───────┤
  威胁情报 ──────────┼──► SIEM 平台 ──► 关联分析 ──► 告警 ──► 分析师处理
  业务系统日志 ──────┤          │
  身份认证日志 ──────┘          ├── 仪表盘
                                ├── 报表
                                ├── 搜索/调查
                                └── 合规审计
```

| 核心功能 | 说明 |
|---------|------|
| **日志收集** | 从各种来源采集日志（代理/API/Syslog） |
| **日志存储** | 集中存储，支持快速检索 |
| **实时监控** | 实时告警，仪表盘展示 |
| **关联分析** | 跨设备/跨日志的事件关联，发现复杂攻击 |
| **威胁情报** | 集成威胁情报，匹配恶意 IP/域名/哈希 |
| **报表合规** | 各种合规报表（等保、ISO 27001 等） |
| **事件管理** | 工单、调查、处置流程 |
| **搜索分析** | 自由搜索、统计分析、可视化 |

**常见 SIEM 产品**：

| 类型 | 产品 | 说明 |
|------|------|------|
| 商业 | Splunk | 最流行的机器数据平台，功能强，价格贵 |
| 商业 | IBM QRadar | 老牌 SIEM，关联分析强 |
| 商业 | ArcSight | Micro Focus，企业级 |
| 开源 | ELK Stack（Elasticsearch + Logstash + Kibana） | 最流行的开源方案，灵活 |
| 开源 | Wazuh | 开源安全平台（HIDS + SIEM 功能） |
| 开源 | OSSEC + ELK | 主机 IDS + 日志分析 |
| 开源 | Apache Metron | 专门的开源 SIEM |

### 6.3 SOC

**SOC（Security Operations Center，安全运营中心）**：人员+流程+技术的组合，负责持续监控、检测、响应组织的安全事件。

```
SOC 三层分析师模型：

  L1（一线）：监控告警，初步分诊，处理简单事件
    │
    ├ 简单/误报 → 关闭
    │
    └ 复杂/真实 → 升级给 L2
          │
  L2（二线）：深入分析，事件调查，协调响应
    │
    ├ 处理完成 → 关闭/总结
    │
    └ 重大事件 → 升级给 L3
          │
  L3（三线）：资深专家，深度分析，溯源，漏洞研究
```

**SOC 核心流程**：

1. **监控（Monitor）** — 7x24 小时安全监控
2. **检测（Detect）** — 发现安全事件和告警
3. **分析（Analyze）** — 验证告警真实性，判断影响范围
4. **响应（Respond）** — 遏制、根除、恢复
5. **报告（Report）** — 事件报告、改进建议
6. **改进（Improve）** — 优化检测规则、加固系统

**SOC 关键指标（KPI/KRI）**：

| 指标 | 说明 | 目标参考 |
|------|------|---------|
| **MTTD（平均检测时间）** | Mean Time to Detect，从攻击发生到发现的时间 | 越短越好 |
| **MTTR（平均响应时间）** | Mean Time to Respond，从发现到开始响应的时间 | 越短越好 |
| **MTTC（平均遏制时间）** | Mean Time to Contain，从发现到遏制住的时间 | 越短越好 |
| **误报率** | 错误告警的比例 | 越低越好 |
| **告警量** | 每天/每周告警数量 | 反映工作量和检测覆盖 |
| **事件分级比例** | 不同级别事件的比例 | 高危事件多说明问题严重 |

## 七、应急响应与取证基础

### 7.1 应急响应流程

**NIST SP 800-61 计算机安全事件响应生命周期**：

```
┌───────────────────────────────────────────────────────┐
│                                                        │
│   1. 准备（Preparation）                                │
│      - 工具、流程、团队、培训、预案                       │
│                                                        │
│   2. 检测与分析（Detection and Analysis）                │
│      - 发现事件、确认、分级、取证                        │
│                                                        │
│   3. 遏制、根除与恢复（Containment, Eradication & Recovery）│
│      - 止损 → 清除 → 恢复                               │
│                                                        │
│   4. 事后活动（Post-Incident Activity）                  │
│      - 总结复盘、改进加固、知识沉淀                       │
│                                                        │
└───────────────────────────────────────────────────────┘
         ↓  持续改进  ↑
         └────────────┘
```

### 7.2 各阶段详解

#### （1）准备阶段

| 准备项 | 说明 |
|--------|------|
| **人员** | 应急响应团队、职责分工、联络方式、外部专家 |
| **工具** | 取证工具包、应急启动盘、抓包工具、分析工具 |
| **流程** | 应急预案、事件分级标准、上报流程 |
| **通信** | 通知模板、联系人列表、媒体应对 |
| **基线** | 系统正常状态基线（便于对比发现异常） |
| **备份** | 数据备份、系统备份、配置备份 |
| **演练** | 定期应急演练 |

#### （2）检测与分析阶段

| 步骤 | 说明 |
|------|------|
| **发现** | 告警、用户报告、外部通知、主动发现 |
| **验证** | 确认是不是真的安全事件，还是误报 |
| **分级** | 根据影响范围和严重程度分级（一般/较大/重大/特别重大） |
| **上报** | 按流程上报管理层和相关部门 |
| **初步分析** | 哪些系统受影响？攻击者做了什么？时间线？ |
| **证据收集** | 保存证据、记录操作链 |

#### （3）遏制、根除与恢复

```
遏制（Containment）→ 根除（Eradication）→ 恢复（Recovery）

遏制（先止损，防止扩散）：
  - 断开网络 / 隔离受感染主机
  - 禁用被攻破的账号
  - 阻断恶意 IP/域名
  - 防火墙临时规则
  - 注意：保存证据优先，不要贸然关机（内存数据会丢）

根除（清除攻击者和恶意代码）：
  - 清除后门、木马、webshell
  - 修复漏洞
  - 重置被泄露的密码/密钥
  - 删除攻击者创建的账号
  - 确认没有其他后门（横向移动检查）

恢复（恢复业务正常运行）：
  - 从干净备份恢复（确认备份未被感染）
  - 或者系统加固后重新上线
  - 加强监控（确认没有回来）
  - 逐步恢复服务，验证正常
```

> ⚠️ **遏制 vs 证据保留的权衡**：拔掉网线会丢失内存中的证据（如运行的进程、网络连接），但能立即止损。需要根据情况决策——如果要追溯攻击者，可能先做内存取证再断网；如果攻击正在造成严重损失，先止损再说。

#### （4）事后活动

| 活动 | 说明 |
|------|------|
| **事件报告** | 完整的事件报告：时间线、影响、原因、处置过程 |
| **经验总结** | 哪些做得好、哪些做得不好、有什么教训 |
| **改进措施** | 技术改进（加固、检测规则）、流程改进 |
| **知识沉淀** | 更新知识库、检测规则、应急预案 |
| **跟踪验证** | 改进措施是否落实、效果如何 |

### 7.3 数字取证基础

**数字取证（Digital Forensics）**：对数字证据进行收集、保存、分析和呈堂，用于调查安全事件或法律诉讼。

**取证基本原则**：

| 原则 | 说明 |
|------|------|
| **证据完整性** | 不能修改原始证据，所有操作要保证不破坏证据 |
| **监管链（Chain of Custody）** | 证据从收集到使用的每一步都有记录，谁在什么时候对证据做了什么 |
| **最小影响** | 取证操作对原始系统的影响尽可能小 |
| **可重复** | 另一个专业人员用同样方法能得到同样的结果 |
| **合法合规** | 取证过程符合法律法规要求 |

**取证实务要点**：

```
取证顺序（易失性从高到低）：

  1. 寄存器和缓存（最易失，马上就没了）
  2. 内存 / 进程信息
  3. 网络连接状态
  4. 运行中的进程和服务
  5. 临时文件
  6. 磁盘文件系统
  7. 日志文件
  8. 物理配置、网络拓扑（最不易失）

  取证原则：先获取最容易丢失的证据！
```

**常见取证工具**：

| 类别 | 工具 | 用途 |
|------|------|------|
| **内存取证** | Volatility | 分析内存镜像，提取进程/网络/密码等 |
| **磁盘取证** | dd、FTK Imager、EnCase | 制作磁盘镜像 |
| **文件分析** | Autopsy、The Sleuth Kit | 文件系统分析、恢复删除的文件 |
| **网络取证** | tcpdump、Wireshark、Zeek | 网络流量分析 |
| **日志分析** | ELK、Splunk | 日志检索和分析 |
| **哈希校验** | md5sum、sha256sum | 验证证据完整性 |
| **写保护** | 硬件写保护器 | 防止修改原始磁盘 |

**Linux 应急响应常用命令**：

```bash
# ===== 系统信息 =====
uname -a                        # 内核版本
hostname                        # 主机名
date                            # 系统时间
uptime                          # 运行时间
who / w / last                  # 登录用户
lastb                           # 失败登录

# ===== 进程检查 =====
ps auxf                         # 所有进程树
ps -efH
top / htop                      # 实时进程
pstree -p                       # 进程树
ls /proc/                       # /proc 目录（进程详细信息）
cat /proc/<pid>/cmdline         # 进程命令行
cat /proc/<pid>/exe             # 进程执行文件链接

# ===== 网络检查 =====
ss -tulnp                       # 所有监听端口
ss -antp                        # 所有 TCP 连接
netstat -tulnp
netstat -an
lsof -i -P -n                   # 打开的网络连接
ip link / ip addr / ip route    # 网络配置
arp -a / ip neigh               # ARP 表

# ===== 服务检查 =====
systemctl list-units --type=service --state=running
service --status-all
chkconfig --list

# ===== 用户检查 =====
cat /etc/passwd
cat /etc/shadow
cat /etc/group
cat /etc/sudoers
id <用户名>

# ===== 定时任务 =====
crontab -l
ls /etc/cron.*
ls /var/spool/cron/
cat /etc/crontab
systemctl list-timers

# ===== 启动项 =====
ls /etc/init.d/
ls /etc/rc*.d/
ls /etc/systemd/system/
ls ~/.config/autostart/

# ===== 文件检查 =====
find / -mtime -1 -type f           # 最近 1 天修改的文件
find / -ctime -1 -type f           # 最近 1 天状态改变的文件
find / -perm -4000 -o -perm -2000  # SUID/SGID 文件
ls -latr /tmp                      # 临时目录
ls -latr /var/tmp
ls -latr /dev/shm

# ===== 日志检查 =====
# systemd journal
journalctl --since "2024-01-01" --until "2024-01-02"
journalctl -u sshd --since "1 hour ago"
journalctl -k --since today         # 内核日志

# 传统日志
tail -f /var/log/auth.log           # 认证日志（Debian）
tail -f /var/log/secure             # 安全日志（RHEL）
tail -f /var/log/syslog
tail -f /var/log/messages
tail -f /var/log/nginx/access.log
tail -f /var/log/nginx/error.log

# ===== 资源使用 =====
free -m                          # 内存
df -h                            # 磁盘
df -i                            # inode
vmstat 1                         # 虚拟内存统计
iostat -x 1                      # IO 统计
```

> ⚠️ **取证操作警告**：
> - 在被入侵的系统上执行命令本身就可能修改证据（如 atime）
> - 优先从只读介质或镜像上分析
> - 所有操作要记录下来（操作时间、命令、结果）
> - 重要系统先做磁盘镜像再分析
> - 法律案件的取证需要严格遵守监管链

---

> **总结**：边界防护、检测与响应是网络安全运营的核心闭环——防护（防火墙/VPN/零信任）把攻击挡在外面，检测（IDS/SIEM/SOC）发现那些溜进来的攻击，响应（应急响应/取证）在攻击造成更大损失前把它处理掉。这三者缺一不可：只有防护没有检测，被攻破了都不知道；只有检测没有响应，发现了也处理不了。从 iptables/firewalld 等基础防火墙，到 IDS/IPS、SIEM、SOC，再到零信任、微分段和应急响应，构成了从边界到内部、从检测到响应的完整安全运营体系。记住：安全不是一个产品，而是一个持续的过程——防护永远会被突破，重要的是能不能及时发现、能不能快速响应、能不能持续改进。
