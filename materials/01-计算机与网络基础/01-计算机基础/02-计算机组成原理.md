## 📖 Day 1 — 计算机系统概述

### 1.1 冯·诺依曼体系结构（Von Neumann Architecture）

**核心思想**：存储程序（Stored Program）

> 💡 **生活化类比**：想象一家餐厅。厨房（CPU）负责做菜，冰箱（存储器）里存着食材和菜谱（数据和程序）。厨师按照菜谱一步步做菜，菜谱和食材都放在同一个冰箱里——这就是冯·诺依曼结构。

**五大组成部分**：

| 部件 | 英文 | 功能 | 类比 |
|:---|:---|:---|:---|
| 运算器 | ALU (Arithmetic Logic Unit) | 执行算术和逻辑运算 | 厨师的手和刀，负责切菜炒菜 |
| 控制器 | CU (Control Unit) | 指挥协调各部件工作 | 厨师长，指挥大家按步骤干活 |
| 存储器 | Memory | 存储程序和数据 | 冰箱+菜谱架 |
| 输入设备 | Input Device | 把信息送入计算机 | 采购员/食材入口 |
| 输出设备 | Output Device | 把结果送出计算机 | 传菜员/菜品出口 |

> 🔑 **CPU = 运算器 + 控制器**（现代CPU还包含Cache等）

### 1.2 哈佛结构（Harvard Architecture）

- **特点**：程序存储器和数据存储器分开，有各自独立的地址线和数据线
- **优势**：可以同时取指令和取数据，速度更快
- **应用**：DSP、单片机、ARM Cortex-M系列、GPU
- **对比**：冯·诺依曼结构 = 指令和数据共用一个存储器；哈佛结构 = 分开存储

### 1.3 计算机的层次结构

```
Level 5: 高级语言级 (High-level Language)  —— C/Java/Python
Level 4: 汇编语言级 (Assembly Language)    —— x86汇编 / ARM汇编
Level 3: 操作系统级 (Operating System)      —— 系统调用、进程管理
Level 2: 机器语言级 (Machine Language)      —— 二进制指令（ISA）
Level 1: 微体系结构级 (Microarchitecture)   —— 数据通路、控制器
Level 0: 数字逻辑级 (Digital Logic)         —— 门电路、触发器
```

> 💡 **理解**：你用Python写代码（Level 5），编译器把它变成汇编（Level 4），汇编器变成机器码（Level 2），CPU内部的微结构（Level 1）执行机器码，底层是数字电路（Level 0）在工作。

### 1.4 性能指标

#### 1.4.1 主频（Clock Frequency）

- **定义**：CPU时钟周期的频率，单位Hz（赫兹）
- **公式**：`主频 f = 1 / 时钟周期 T`
- **举例**：主频3.0GHz = 每秒30亿个时钟周期 = 每个周期约0.33纳秒

> ⚠️ **常见误区**：主频越高性能一定越好吗？不一定！还取决于架构、流水线效率、核心数等。就像汽车不是转速越快就一定跑的越快，还要看变速箱和发动机设计。

#### 1.4.2 CPI（Cycles Per Instruction）

- **定义**：执行一条指令平均需要的时钟周期数
- **公式**：`CPI = 总时钟周期数 / 指令总数`

**例题**：某程序执行了100条指令，共耗时250个时钟周期，求CPI。
> 解：CPI = 250 / 100 = 2.5

#### 1.4.3 MIPS（Million Instructions Per Second）

- **定义**：每秒执行多少百万条指令
- **公式**：`MIPS = 主频 f (Hz) / (CPI × 10^6) = 指令数 / (执行时间 × 10^6)`

**例题**：CPU主频2GHz，程序CPI=2，求MIPS。
> 解：MIPS = 2×10^9 / (2 × 10^6) = 1000 MIPS = 每秒10亿条指令

#### 1.4.4 Amdahl定律（阿姆达尔定律）

- **定义**：系统中某一部件采用更快的执行方式后，整个系统性能提升多少
- **公式**：
  ```
  加速比 S = 1 / [(1 - α) + α / n]
  其中：
    α = 可加速部分在原系统中所占时间比例（0 ≤ α ≤ 1）
    n = 可加速部分的加速倍数
  ```

**例题**：某程序运行时间中，80%的时间可以被加速，加速倍数为5倍，求整体加速比。
> 解：S = 1 / [(1 - 0.8) + 0.8/5] = 1 / [0.2 + 0.16] = 1 / 0.36 ≈ 2.78倍

> 💡 **启示**：优化最常用的部分收益最大！如果一个功能只占总时间的1%，就算把它加速100倍，整体也只快了约1%。

## 📖 Day 2 — 数据表示（上）：定点数与编码

### 2.1 进制转换

#### 2.1.1 常见进制

| 进制 | 基数 | 数码 | 后缀/前缀 | 日常类比 |
|:---|:---|:---|:---|:---|
| 十进制 Decimal | 10 | 0-9 | D / 无 | 10根手指 |
| 二进制 Binary | 2 | 0,1 | B / 0b | 开关：开/关 |
| 八进制 Octal | 8 | 0-7 | O / 0o | 3位二进制 |
| 十六进制 Hex | 16 | 0-9, A-F | H / 0x | 4位二进制 |

#### 2.1.2 二进制 ↔ 十进制

**二进制 → 十进制：按权展开**

```
(1011.01)₂ = 1×2³ + 0×2² + 1×2¹ + 1×2⁰ + 0×2⁻¹ + 1×2⁻²
           = 8 + 0 + 2 + 1 + 0 + 0.25
           = (11.25)₁₀
```

**十进制 → 二进制：整数部分除2取余，小数部分乘2取整**

整数部分：13 → 二进制
```
13 ÷ 2 = 6  余 1  ↑
6 ÷ 2 = 3   余 0  ↑
3 ÷ 2 = 1   余 1  ↑
1 ÷ 2 = 0   余 1  ↑
结果：1101（从下往上读）
```

小数部分：0.625 → 二进制
```
0.625 × 2 = 1.25  取整 1  ↓
0.25 × 2 = 0.5    取整 0  ↓
0.5 × 2 = 1.0     取整 1  ↓
结果：0.101（从上往下读）
```

#### 2.1.3 二进制 ↔ 十六进制

- 每 **4位二进制** 对应 **1位十六进制**
- 从右往左分组，不足补零

```
二进制：  1101 0110 1001
十六进制： D    6    9     = (D69)₁₆
```

> 💡 **记忆技巧**：8421码，每一位二进制对应8、4、2、1的权重

### 2.2 真值与机器数

- **真值**：真实的数值，如 +5、-3
- **机器数**：计算机中用0和1表示的数，符号也用0/1表示（0正1负）

### 2.3 四种编码方式（定点整数）

假设机器字长为8位（1位符号位 + 7位数值位）

#### 2.3.1 原码（Sign-Magnitude）

- **规则**：最高位为符号位，0表示正，1表示负；数值位为真值的绝对值
- **公式**：`[x]原 = 符号位 + |x|的二进制`

| 真值 | 原码（8位） |
|:---|:---|
| +0 | 0000 0000 |
| -0 | 1000 0000 |
| +127 | 0111 1111 |
| -127 | 1111 1111 |
| +1 | 0000 0001 |
| -1 | 1000 0001 |

> ⚠️ **问题**：原码有两个零（+0和-0），浪费了一个编码，而且减法不好做。

#### 2.3.2 反码（One's Complement）

- **规则**：正数的反码 = 原码；负数的反码 = 原码符号位不变，数值位取反

| 真值 | 原码（8位） | 反码（8位） |
|:---|:---|:---|
| +0 | 0000 0000 | 0000 0000 |
| -0 | 1000 0000 | 1111 1111 |
| +127 | 0111 1111 | 0111 1111 |
| -127 | 1111 1111 | 1000 0000 |
| +1 | 0000 0001 | 0000 0001 |
| -1 | 1000 0001 | 1111 1110 |

> ⚠️ **问题**：反码还是有两个零。

#### 2.3.3 补码（Two's Complement）⭐ 最重要！

- **规则**：正数的补码 = 原码；负数的补码 = 反码 + 1（末位加1）
- **为什么重要？** 补码可以把减法变成加法，CPU只需要一个加法器就能做加减运算！

| 真值 | 原码（8位） | 反码（8位） | 补码（8位） |
|:---|:---|:---|:---|
| +0 | 0000 0000 | 0000 0000 | 0000 0000 |
| -0 | 1000 0000 | 1111 1111 | 0000 0000（溢出，舍弃进位） |
| +127 | 0111 1111 | 0111 1111 | 0111 1111 |
| -128 | —（原码表示不了） | — | 1000 0000 |
| +1 | 0000 0001 | 0000 0001 | 0000 0001 |
| -1 | 1000 0001 | 1111 1110 | 1111 1111 |

> ✅ **优点**：只有一个零；多表示一个数（-128）；减法变加法。

**补码减法示例**：计算 5 - 3 = 5 + (-3)

```
[5]补 = 0000 0101
[-3]补 = 1111 1101
相加：   0000 0101
       + 1111 1101
       -----------
       10000 0010  → 最高位溢出丢弃 → 0000 0010 = +2 ✓
```

#### 2.3.4 移码（Excess / Bias）

- **规则**：补码的符号位取反（或真值 + 偏移量）
- **用途**：主要用于浮点数的阶码（方便比较大小）
- **公式**：`[x]移 = x + 2^(n-1)`（n为总位数）

| 真值 | 补码（8位） | 移码（8位） |
|:---|:---|:---|
| -128 | 1000 0000 | 0000 0000 |
| -1 | 1111 1111 | 0111 1111 |
| 0 | 0000 0000 | 1000 0000 |
| +1 | 0000 0001 | 1000 0001 |
| +127 | 0111 1111 | 1111 1111 |

> 💡 **移码的好处**：可以像无符号数一样直接比较大小，数值越大移码越大。

### 2.4 四种编码对比总结

| 特性 | 原码 | 反码 | 补码 | 移码 |
|:---|:---|:---|:---|:---|
| 零的个数 | 2个 | 2个 | 1个 | 1个 |
| 减法运算 | 不方便 | 不方便 | 方便 | — |
| 表示范围(8位) | -127~+127 | -127~+127 | -128~+127 | -128~+127 |
| 主要用途 | 直观表示 | 求补码过渡 | **整数运算** | 浮点数阶码 |

## 📖 Day 3 — 数据表示（下）：浮点数与运算部件

### 3.1 定点数 vs 浮点数

| 类型 | 表示方式 | 范围 | 精度 | 应用 |
|:---|:---|:---|:---|:---|
| 定点数 Fixed-point | 小数点位置固定 | 小 | 高（精确） | 整数运算、计数 |
| 浮点数 Floating-point | 小数点位置浮动 | 大 | 相对精度 | 科学计算、图形 |

> 💡 **类比**：定点数就像用尺子量东西，精度固定但量程有限；浮点数就像科学计数法（如 3.14×10²），可以表示很大或很小的数，但越远的地方精度越低。

### 3.2 浮点数的一般表示

```
N = M × r^E
其中：
  M = 尾数（Mantissa）—— 决定精度
  E = 阶码（Exponent）—— 决定范围
  r = 基数（通常为2）
```

**存储格式**：

```
┌─────────┬─────────┐
│  阶码E   │  尾数M   │
└─────────┴─────────┘
```

### 3.3 IEEE 754 浮点数标准 ⭐

#### 3.3.1 两种基本格式

| 格式 | 总位数 | 符号位S | 阶码E | 尾数M | 阶码偏移量 |
|:---|:---|:---|:---|:---|:---|
| 单精度 float | 32位 | 1位 | 8位 | 23位 | 127 |
| 双精度 double | 64位 | 1位 | 11位 | 52位 | 1023 |

**存储结构（单精度32位）**：
```
┌──┬────────┬───────────────────────┐
│S │   E    │           M            │
│1位│  8位   │         23位           │
└──┴────────┴───────────────────────┘
 31  30    23  22                    0
```

#### 3.3.2 真值计算公式

```
真值 = (-1)^S × (1.M) × 2^(E - 127)   （单精度规格化数）
```

> 🔑 **关键理解**：
> - 尾数隐含了一个整数位的"1"，所以实际尾数精度是24位（1位隐含 + 23位显式）
> - 阶码用移码表示，偏移量为127（单精度）
> - 规格化数：阶码E不全为0也不全为1

#### 3.3.3 IEEE 754 特殊值

| 阶码E | 尾数M | 表示的值 |
|:---|:---|:---|
| 全0 | 全0 | ±0 |
| 全0 | 非全0 | 非规格化数（denormal）—— 表示非常小的数 |
| 全1 | 全0 | ±∞（无穷大） |
| 全1 | 非全0 | NaN（Not a Number，非数） |

**例题**：将单精度浮点数 `41A40000H`（十六进制）转换为十进制真值。

> 解：
> 1. 十六进制转二进制：41A40000H = 0100 0001 1010 0100 0000 0000 0000 0000
> 2. 分段：
>    - S = 0（正数）
>    - E = 1000 0011 = 128 + 2 + 1 = 131
>    - M = 010 0100 0000 0000 0000 0000
> 3. 计算：(-1)^0 × (1.01001) × 2^(131-127) = 1.01001 × 2^4
> 4. 1.01001 × 16 = 10100.1（二进制）= 20.5（十进制）
> **答案：20.5**

### 3.4 ALU（算术逻辑单元）

**功能**：执行算术运算（加、减、乘、除）和逻辑运算（与、或、非、异或）

> 💡 **类比**：ALU就像计算器，能做加减乘除和逻辑判断。

### 3.5 加法器

#### 3.5.1 半加器（Half Adder）

- 只加两个一位二进制数，不考虑低位进位
- 输入：A, B
- 输出：和 S = A ⊕ B，进位 C = A · B

#### 3.5.2 全加器（Full Adder）

- 加两个一位二进制数 + 低位进位
- 输入：A, B, Ci（低位进位）
- 输出：和 S = A ⊕ B ⊕ Ci，进位 Co = A·B + A·Ci + B·Ci

#### 3.5.3 行波进位加法器（Ripple Carry Adder）

- 把n个全加器串联起来
- 缺点：进位信号要一级一级传，延迟大（就像多米诺骨牌）

#### 3.5.4 先行进位加法器（Carry Lookahead Adder）⭐

- **思想**：直接通过逻辑电路算出每一位的进位，不用等前一位算完
- **优势**：速度快，是现代CPU加法器的主流设计
- **代价**：电路更复杂

> 💡 **类比**：行波进位就像传话游戏，一个传一个，越到后面越慢；先行进位就像有个总指挥官，直接告诉每个人结果，一步到位。

### 3.6 乘除法简介

- **乘法**：可以通过"移位 + 加法"实现（Booth算法是优化的乘法算法）
- **除法**：可以通过"移位 + 减法"实现（恢复余数法、不恢复余数法）
- **现代CPU**：有专门的乘法器/除法器，硬件直接实现

## 📖 Day 4 — 存储系统（上）：存储器层次与主存

### 4.1 存储器的分类

#### 4.1.1 按存储介质分类

| 类型 | 举例 | 特点 |
|:---|:---|:---|
| 半导体存储器 | SRAM、DRAM、Flash | 速度快、体积小 |
| 磁表面存储器 | 硬盘、磁带 | 容量大、速度慢、掉电不丢 |
| 光存储器 | CD、DVD、蓝光 | 容量大、便携、只读为主 |

#### 4.1.2 按存取方式分类

| 类型 | 英文 | 特点 | 举例 |
|:---|:---|:---|:---|
| 随机存取 | RAM (Random Access Memory) | 任意地址访问时间相同 | 内存、SRAM、DRAM |
| 顺序存取 | SAM (Sequential Access) | 只能按顺序访问 | 磁带 |
| 直接存取 | DAM (Direct Access) | 先定位到区域再顺序找 | 硬盘 |
| 只读存储器 | ROM (Read-Only Memory) | 只能读不能随便写 | BIOS ROM、Flash |

#### 4.1.3 按在计算机中的作用分类

```
寄存器 (Register)         ← CPU内部，最快，最小
   ↓
高速缓存 (Cache)           ← CPU内部/附近，很快，小
   ↓
主存储器 (Main Memory)     ← 内存，较快，中等
   ↓
辅助存储器 (Auxiliary)     ← 硬盘/SSD，较慢，大
   ↓
海量存储器 (Mass Storage)  ← 磁带/云存储，最慢，最大
```

### 4.2 存储器层次结构（Memory Hierarchy）⭐

#### 4.2.1 为什么需要层次结构？

- **速度**：CPU越来越快，内存跟不上 → 需要Cache
- **容量**：程序越来越大，内存不够大 → 需要虚拟内存+硬盘
- **成本**：越快的存储器越贵 → 用层次结构平衡性能和成本

#### 4.2.2 局部性原理（Principle of Locality）

存储器层次结构能工作的根本原因！

| 类型 | 含义 | 例子 |
|:---|:---|:---|
| 时间局部性 | 刚访问过的数据，很快可能再访问 | 循环变量、缓存热点数据 |
| 空间局部性 | 访问了某个数据，附近的数据可能也会被访问 | 数组遍历、顺序执行指令 |

> 💡 **类比**：你在书桌（寄存器）上放最常用的笔和纸；书架（Cache）放最近在读的书；书房（内存）放所有书；仓库（硬盘）放不常用的东西。越常用的东西放得越近。

### 4.3 SRAM vs DRAM ⭐

| 特性 | SRAM 静态RAM | DRAM 动态RAM |
|:---|:---|:---|
| 存储单元 | 触发器（6个晶体管） | 电容+晶体管（1T1C） |
| 是否需要刷新 | 不需要 | 需要（电容会漏电） |
| 速度 | 快 | 较慢 |
| 集成度 | 低（占面积大） | 高（占面积小） |
| 功耗 | 高 | 低 |
| 成本 | 贵 | 便宜 |
| 用途 | **Cache** | **主存（内存）** |
| 易失性 | 掉电丢失 | 掉电丢失 |

> ⚠️ **记忆技巧**：SRAM = Static = 静态 = 不用刷新 = 快 = 做Cache；DRAM = Dynamic = 动态 = 要刷新 = 便宜 = 做内存

### 4.4 主存储器（Main Memory）

#### 4.4.1 主存的基本组成

```
┌─────────────────────────────────┐
│         存储体 (Storage)         │  ← 一堆存储单元，按地址排列
├─────────────────────────────────┤
│ 地址寄存器 MAR (Memory Addr Reg) │  ← 存要访问的地址
├─────────────────────────────────┤
│ 数据寄存器 MDR (Memory Data Reg) │  ← 存读出/写入的数据
├─────────────────────────────────┤
│       控制电路 (Control)         │  ← 时序、读写控制
└─────────────────────────────────┘
```

#### 4.4.2 主存的技术指标

| 指标 | 含义 | 单位 |
|:---|:---|:---|
| 存储容量 | 能存多少数据 | 位(bit)、字节(Byte)、GB |
| 存取时间 | 从发命令到拿到数据的时间 | ns（纳秒） |
| 存取周期 | 连续两次访问的最小间隔 | ns |
| 存储器带宽 | 每秒能传输多少数据 | MB/s、GB/s |

**带宽计算公式**：
```
带宽 = 数据宽度 / 存取周期
```

**例题**：某存储器数据宽度为32位，存取周期为50ns，求带宽。
> 解：带宽 = 4B / 50ns = 4B / 50×10⁻⁹s = 8×10⁷ B/s = 80 MB/s

### 4.5 存储器扩展

#### 4.5.1 位扩展（增加数据位宽）

- 当存储芯片容量够但位数不够时使用
- 方法：多个芯片的地址线、片选、读写控制并联，数据线分别输出

> 例子：用 1K×4位 的芯片组成 1K×8位 的存储器 → 需要2片（并联）

#### 4.5.2 字扩展（增加存储单元数）

- 当位数够但容量不够时使用
- 方法：多个芯片的地址线、数据线、读写控制并联，片选信号由地址译码产生

> 例子：用 1K×8位 的芯片组成 4K×8位 的存储器 → 需要4片 + 2-4译码器

#### 4.5.3 字位同时扩展

- 既增加容量又增加位宽
- 先位扩展成一组，再用字扩展增加组数

> 例子：用 1K×4位 的芯片组成 4K×8位 → 需要 8片（2片一组并联×4组）

## 📖 Day 5 — 存储系统（下）：Cache 高速缓存

### 5.1 Cache 基本概念

**Cache** = 高速缓冲存储器，位于CPU和主存之间，速度接近CPU，容量较小

**为什么需要Cache？**
- CPU速度增长远快于内存速度增长 → "存储墙"问题
- 利用局部性原理，把CPU可能马上要用的数据从内存搬到Cache

**工作原理**：
1. CPU要访问某个数据
2. 先去Cache找 → 找到了叫**命中（Hit）**，直接用
3. 没找到叫**缺失/不命中（Miss）** → 去内存取，同时把数据（和附近的数据）装入Cache

### 5.2 性能指标

#### 5.2.1 命中率（Hit Rate）

```
命中率 h = 命中次数 / 总访问次数
缺失率 miss rate = 1 - h
```

#### 5.2.2 平均访问时间（Average Memory Access Time, AMAT）⭐

```
AMAT = 命中时间 + 缺失率 × 缺失开销
     = Tc + (1 - h) × Tm
其中：
  Tc = Cache访问时间（命中时间）
  Tm = 主存访问时间（缺失时需要额外花的时间）
```

> ⚠️ 注意：有的教材中Tm表示"主存访问时间"（即缺失时总共花Tm），有的表示"缺失开销"（额外花的时间）。计算时要看清定义。

**例题**：Cache访问时间为2ns，主存访问时间为20ns，命中率为95%，求平均访问时间。

> 解：AMAT = 2ns + (1 - 0.95) × 20ns = 2ns + 0.05 × 20ns = 2 + 1 = 3ns
> 
> 解读：虽然主存很慢，但因为命中率很高，平均下来只比Cache直接访问慢一点。

### 5.3 Cache 的基本结构

```
┌───────────────────────────────┐
│         Cache 存储体           │  ← 数据存这里
├───────────────────────────────┤
│         Cache 控制器           │  ← 判断命中、替换、写策略
└───────────────────────────────┘
```

**地址划分（以直接映射为例）**：
```
主存地址
┌────────────┬──────────┬───────┐
│    标记Tag   │  行号Cache  │  块内  │
│             │   Index    │ Offset│
└────────────┴──────────┴───────┘
```

### 5.4 Cache 映射方式 ⭐⭐⭐

Cache和主存都被分成大小相同的**块（Block/Line）**。映射方式决定主存的块可以放到Cache的哪个位置。

#### 5.4.1 直接映射（Direct Mapped）

**规则**：每个主存块只能映射到Cache的一个固定位置
**公式**：`Cache行号 = 主存块号 mod Cache总行数`

> 💡 **类比**：就像电影院里，座位号 = 你的学号 % 总座位数。每个人只有一个固定座位，即使别的座位空着也不能坐。

**优点**：硬件简单，成本低
**缺点**：冲突率高（两个常用块映射到同一行就会频繁替换）

**地址划分**：
- 块内偏移（offset）：块大小 = 2^b → b位
- Cache行号（index）：Cache行数 = 2^c → c位
- 标记（tag）：总地址位 - c - b

**判断命中**：用行号找到Cache行 → 比较标记位 → 相同且有效位为1则命中

#### 5.4.2 全相联映射（Fully Associative）

**规则**：每个主存块可以放到Cache的任意位置

> 💡 **类比**：就像自由座位，你可以坐任何空位置。

**优点**：冲突率最低，Cache利用率最高
**缺点**：需要比较所有行的标记，硬件复杂（需要相联存储器），成本高

**地址划分**：
- 块内偏移：b位
- 标记：总地址位 - b（没有行号了）

#### 5.4.3 组相联映射（Set Associative）⭐ 最常用！

**规则**：Cache分成若干组，每组有若干行；主存块映射到固定组，但组内可以放任意位置

**公式**：`组号 = 主存块号 mod 组数`

> 💡 **类比**：就像电影院分区域，你必须坐在指定区域（组），但区域内可以随便坐。是直接映射和全相联的折中。

**N路组相联**：每组有N行
- 2路组相联：每组2行
- 4路组相联：每组4行
- 直接映射 = 1路组相联
- 全相联 = Cache总行数 路组相联

**地址划分**：
- 块内偏移：b位
- 组号（index）：组数 = 2^s → s位
- 标记（tag）：总地址位 - s - b

### 5.5 三种映射方式对比

| 特性 | 直接映射 | 组相联 | 全相联 |
|:---|:---|:---|:---|
| 映射规则 | 固定位置 | 固定组+组内任意 | 任意位置 |
| 冲突率 | 最高 | 中等 | 最低 |
| 硬件复杂度 | 最简单 | 中等 | 最复杂 |
| 地址划分 | tag+行号+offset | tag+组号+offset | tag+offset |
| 典型应用 | 简单系统 | **现代CPU** | 特殊场景/TLB |

### 5.6 Cache 替换算法 ⭐

当Cache满了，新的数据要进来，把谁踢出去？

| 算法 | 英文 | 思想 | 实现难度 | 命中率 |
|:---|:---|:---|:---|:---|
| 随机替换 | Random | 随机选一个踢出去 | 最简单 | 一般 |
| 先进先出 | FIFO | 最早进来的先踢 | 简单 | 一般 |
| 最近最少使用 | **LRU** (Least Recently Used) | 最久没用的踢出去 | 较复杂 | **最高** |
| 最不经常使用 | LFU (Least Frequently Used) | 使用次数最少的踢出去 | 复杂 | 较高 |

> 💡 **LRU是重点**：符合时间局部性原理——最近用过的，很可能马上还要用。
> 
> **LRU的实现**：每组有计数器，每次命中就把该行的计数器清零，其他行加一；替换时选计数器最大的（最久没用的）。

### 5.7 Cache 写策略 ⭐

CPU写数据时，Cache和主存怎么保持一致？

#### 5.7.1 写命中时（Write Hit）

| 策略 | 英文 | 做法 | 优点 | 缺点 |
|:---|:---|:---|:---|:---|
| 写直达 | **Write Through** | 同时写Cache和主存 | 一致性好、简单 | 写操作慢 |
| 写回 | **Write Back** | 只写Cache，块被替换时才写回主存 | 写操作快 | 需要脏位(dirty bit)、一致性复杂 |

> 🔑 **写回法**需要一个**脏位（Dirty Bit）**来标记这个Cache块是否被修改过。只有脏块被替换时才需要写回主存。

#### 5.7.2 写不命中时（Write Miss）

| 策略 | 英文 | 做法 |
|:---|:---|:---|
| 写分配 | Write Allocate | 先把块调入Cache，再写Cache |
| 非写分配 | No-Write Allocate | 直接写主存，不调入Cache |

> 通常组合：
> - 写直达 + 非写分配（简单组合）
> - 写回 + 写分配（性能组合，现代CPU常用）

### 5.8 多级Cache

现代CPU通常有三级Cache：
- L1 Cache：最小最快，每个核心独有（通常分为L1i指令Cache + L1d数据Cache）
- L2 Cache：中等大小和速度，每个核心独有
- L3 Cache：最大最慢，所有核心共享

> 💡 层次越多，平均访问时间越低，但设计越复杂。

| 映射方式 | 优点 | 缺点 |

| 全相联 | 冲突率最低、利用率最高 | 硬件最复杂、成本最高 |
| 组相联 | 折中方案，冲突率和复杂度都适中 | — |

5. 
- 写直达：写操作同时写入Cache和主存。优点是一致性好、实现简单；缺点是写操作速度受限于主存速度。
- 写回：写操作只写入Cache，只有当该Cache块被替换出去时才写回主存。优点是写操作快、减少主存写次数；缺点是需要脏位标记、一致性维护更复杂。

</details>

## 📖 Day 6 — 虚拟内存 + 指令系统

### 6.1 虚拟内存（Virtual Memory）⭐

#### 6.1.1 为什么需要虚拟内存？

1. **内存不够大**：程序越来越大，物理内存装不下
2. **内存不够用**：多道程序同时运行，怎么分配内存？
3. **安全问题**：不同程序的内存不能互相访问

**解决思路**：给每个程序一个"假象"——你有一整块连续的、很大的内存可以用。实际上数据可能在物理内存的各个角落，甚至在硬盘上。

> 💡 **类比**：虚拟内存就像图书馆的"虚拟书架"。你以为所有书都在你面前的书架上，其实常用的书在书架（物理内存），不常用的在仓库（硬盘）。你要哪本书，图书管理员就把它从仓库搬到书架上。

#### 6.1.2 基本概念

| 术语 | 英文 | 含义 |
|:---|:---|:---|
| 虚拟地址 | Virtual Address | 程序使用的地址（逻辑地址） |
| 物理地址 | Physical Address | 实际内存的地址 |
| 地址转换 | Address Translation | 虚拟地址 → 物理地址 |
| 页面 | Page | 虚拟内存被分成的固定大小的块 |
| 页框/页帧 | Page Frame | 物理内存被分成的固定大小的块（和页面一样大） |
| 页表 | Page Table | 记录虚拟页号 → 物理页号的映射关系 |
| 缺页 | Page Fault | 要访问的页面不在物理内存中 |

#### 6.1.3 页式虚拟内存

**虚拟地址划分**：
```
┌───────────────┬───────────────┐
│   虚拟页号VPN   │  页内偏移Offset │
│  Virtual Page  │               │
└───────────────┴───────────────┘
```

**地址转换过程**：
1. 用虚拟页号（VPN）查页表
2. 找到对应的物理页号（PPN）
3. 物理页号 + 页内偏移 = 物理地址

> 💡 页内偏移的位数 = 页面大小的对数，页面大小通常是4KB（12位偏移）

**页表项（PTE, Page Table Entry）包含的信息**：
- 物理页号（PPN）
- 有效位（Valid）：该页是否在内存中
- 脏位（Dirty）：该页是否被修改过
- 访问位（Reference）：该页是否被访问过（用于置换算法）
- 权限位（Protection）：读/写/执行权限

#### 6.1.4 缺页（Page Fault）

当访问的页面不在物理内存中时：
1. 触发缺页异常
2. 操作系统介入
3. 从硬盘把页面调入内存
4. 更新页表
5. 重新执行刚才的指令

> ⚠️ **注意**：缺页是"异常"而不是"错误"，是虚拟内存正常工作的一部分。

#### 6.1.5 页面置换算法

当物理内存满了，新的页面要进来，把谁踢出去？（和Cache替换类似）

| 算法 | 思想 | 特点 |
|:---|:---|:---|
| FIFO | 最早进入的先淘汰 | 可能出现"Belady异常"（增加物理页反而缺页更多） |
| LRU | 最久没用的淘汰 | 性能好，但操作系统层面实现开销大 |
| CLOCK | 时钟算法 | LRU的近似，用访问位实现，实用 |
| 工作集 | 常驻最近访问的页面 | 基于局部性原理 |

### 6.2 TLB（Translation Lookaside Buffer）快表 ⭐

**问题**：每次地址转换都要查页表，页表在内存里 → 访问一次数据要读两次内存（一次查页表+一次读数据），太慢了！

**解决**：把最近常用的页表项放到Cache里 → 这就是TLB

> 💡 **类比**：TLB就像页表的"通讯录小抄"，最常用的几个联系人写在小纸条上，不用每次都翻厚厚的通讯录。

**TLB的特点**：
- 是一种特殊的Cache，专门存页表项
- 容量很小（通常几十到几百项）
- 速度极快（和L1 Cache差不多）
- 通常采用全相联或高路组相联

**带TLB的地址转换流程**：
```
虚拟地址 → 查TLB
  ├─ 命中 → 直接得到物理页号 → 访问Cache/内存
  └─ 不命中 → 查页表（在内存中）→ 更新TLB → 访问内存
```

### 6.3 Cache vs 虚拟内存 对比 ⚠️ 易混淆！

| 特性 | Cache | 虚拟内存 |
|:---|:---|:--- |
| 解决的问题 | CPU与主存速度差距 | 主存容量不足+内存管理 |
| 由谁管理 | 硬件自动管理 | 操作系统 + 硬件（MMU） |
| 基本单位 | Cache块（几十字节） | 页面（通常4KB） |
| 缺失代价 | 几个到几十个时钟周期 | 几百万个时钟周期（访问磁盘） |
| 映射方式 | 直接/组相联/全相联 | 全相联（页表可以映射到任意页框） |
| 对程序员透明 | 完全透明 | 系统级透明，应用程序员不感知 |

### 6.4 指令系统（Instruction Set Architecture, ISA）

#### 6.4.1 指令格式

```
┌─────────────────┬────────────────────────────┐
│    操作码 OP     │        地址码 A / 操作数      │
│  Opcode         │   Address / Operand         │
└─────────────────┴────────────────────────────┘
```

**按地址码个数分类**：

| 类型 | 格式 | 例子 | 说明 |
|:---|:---|:---|:---|
| 三地址指令 | OP A1, A2, A3 | ADD R1, R2, R3 | (A1) OP (A2) → A3 |
| 二地址指令 | OP A1, A2 | ADD R1, R2 | (A1) OP (A2) → A1 |
| 一地址指令 | OP A | INC R1 | 只有一个操作数 |
| 零地址指令 | OP | NOP, RET | 无操作数或操作数隐含 |

#### 6.4.2 寻址方式 ⭐

> 寻址方式 = 怎么找到指令要操作的数据

| 寻址方式 | 英文 | 有效地址计算 | 特点/用途 |
|:---|:---|:---|:---|
| 立即寻址 | Immediate | 操作数就是指令中的地址码字段 | 快，用于常量 |
| 直接寻址 | Direct | EA = A | 简单，地址空间有限 |
| 间接寻址 | Indirect | EA = (A) | 寻址空间大，慢 |
| 寄存器寻址 | Register | 操作数在寄存器中 | 快，不用访问内存 |
| 寄存器间接 | Register Indirect | EA = (R) | 灵活，指针 |
| 相对寻址 | Relative | EA = (PC) + A | 用于转移指令，浮动程序 |
| 基址寻址 | Base | EA = (BR) + A | 程序重定位，OS管理 |
| 变址寻址 | Indexed | EA = (IX) + A | 数组遍历，程序员控制 |

> 💡 **基址 vs 变址的区别**：
> - 基址寻址：基址寄存器内容不变，改变偏移量A → 面向系统，解决程序重定位
> - 变址寻址：偏移量A不变，改变变址寄存器内容 → 面向用户，数组循环

#### 6.4.3 CISC vs RISC ⭐⭐⭐

| 特性 | CISC (复杂指令集) | RISC (精简指令集) |
|:---|:---|:---|
| 指令数量 | 多（几百条） | 少（几十到一百多条） |
| 指令长度 | 变长 | 定长 |
| 寻址方式 | 多 | 少 |
| 指令复杂度 | 复杂，单指令功能强 | 简单，单指令功能简单 |
| 实现方式 | 微程序控制为主 | 硬布线控制为主 |
| 流水线 | 难以流水线化 | 易于流水线化 |
| 编译优化 | 较难 | 容易 |
| 典型代表 | **x86** | **ARM、MIPS、RISC-V** |
| 设计理念 | 用复杂指令减少指令数 | 用简单指令提高执行效率 |

> 💡 **记忆口诀**：
> CISC = Complex = 复杂 = 指令多又长 = x86
> RISC = Reduced = 精简 = 指令少又短 = ARM/RISC-V

### 6.5 汇编语言基础（以MIPS风格为例）

```asm
# 寄存器-寄存器型指令（R型）
add  $t0, $t1, $t2    # $t0 = $t1 + $t2
sub  $t0, $t1, $t2    # $t0 = $t1 - $t2
and  $t0, $t1, $t2    # $t0 = $t1 & $t2

# 立即数型指令（I型）
addi $t0, $t1, 100    # $t0 = $t1 + 100
lw   $t0, 4($s0)      # $t0 = 内存[$s0 + 4]  （load word）
sw   $t0, 8($s0)      # 内存[$s0 + 8] = $t0  （store word）

# 跳转指令（J型）
j    LOOP             # 跳转到LOOP
beq  $t0, $t1, LABEL  # 如果$t0==$t1，跳转到LABEL
```

## 📖 Day 7 — CPU结构：数据通路与控制器

### 7.1 CPU的功能与组成

#### 7.1.1 CPU的基本功能

1. **指令控制**：控制指令的执行顺序
2. **操作控制**：产生每条指令需要的操作信号
3. **时间控制**：控制操作信号的产生时间
4. **数据加工**：对数据进行算术和逻辑运算

#### 7.1.2 CPU的基本组成

```
┌──────────────────────────────────────────────┐
│                    CPU                        │
│  ┌──────────┐    ┌────────────────────────┐  │
│  │  运算器    │    │        控制器           │  │
│  │ ALU等     │    │                        │  │
│  └──────────┘    │  ┌──────────────────┐  │  │
│                  │  │  指令寄存器IR      │  │  │
│  ┌──────────┐    │  │  Instruction Reg │  │  │
│  │  寄存器组  │    │  ├──────────────────┤  │  │
│  │ Register │    │  │  程序计数器PC      │  │  │
│  │  File     │    │  │  Program Counter │  │  │
│  └──────────┘    │  ├──────────────────┤  │  │
│                  │  │  地址寄存器MAR     │  │  │
│  ┌──────────┐    │  ├──────────────────┤  │  │
│  │   Cache   │    │  │  数据寄存器MDR     │  │  │
│  └──────────┘    │  ├──────────────────┤  │  │
│                  │  │  程序状态字PSW     │  │  │
│                  │  └──────────────────┘  │  │
│                  │  控制信号产生逻辑        │  │
│                  └────────────────────────┘  │
└──────────────────────────────────────────────┘
```

**关键寄存器**：

| 寄存器 | 英文 | 作用 |
|:---|:---|:---|
| PC | Program Counter | 存下一条指令的地址，自动加1（或跳转地址） |
| IR | Instruction Register | 存当前正在执行的指令 |
| MAR | Memory Address Register | 存要访问的内存地址 |
| MDR | Memory Data Register | 存从内存读出或要写入内存的数据 |
| PSW | Program Status Word | 存程序状态标志（进位、零、负、溢出等） |
| GPRs | General Purpose Registers | 通用寄存器组，存运算数据 |

### 7.2 指令执行过程

一条指令的执行分为几个阶段（周期）：

```
取指周期 → 间址周期（可选） → 执行周期 → 中断周期（可选）
```

**取指周期**：把指令从内存取到IR
```
1. PC → MAR → 发读命令
2. 内存 → MDR → IR
3. PC + 1 → PC（指向下一条指令）
```

**执行周期**：根据指令操作码执行具体操作（不同指令不一样）

**中断周期**：如果有中断请求，保存断点，转中断服务程序

### 7.3 数据通路（Datapath）⭐

**定义**：数据在CPU中流动的路径，包括寄存器、ALU、多路选择器等

> 💡 **类比**：数据通路就像工厂的流水线传送带，数据从一个部件流到另一个部件，经过加工后产出结果。

**一个简单的数据通路包含**：
- 寄存器组（Register File）：读两个寄存器，写一个寄存器
- ALU：执行算术逻辑运算
- PC：程序计数器
- 指令存储器（IM）：存指令
- 数据存储器（DM）：存数据
- 多路选择器（MUX）：选择数据来源

**MIPS单周期数据通路简化图**：
```
PC → 指令存储器 → 指令
              ↓
         寄存器组 → A, B
                    ↓
              ALU → 结果
                    ↓
              数据存储器
```

### 7.4 控制器（Control Unit）⭐

**作用**：根据指令的操作码，产生各种控制信号，控制数据通路的操作

> 💡 **类比**：控制器就像交响乐队的指挥，根据乐谱（指令）指挥各个乐器（部件）在正确的时间演奏（操作）。

#### 7.4.1 控制器的输入

- 指令寄存器IR（当前指令的操作码）
- 时序信号（节拍、机器周期）
- 状态标志（PSW中的条件位）
- 外部信号（中断、总线请求等）

#### 7.4.2 控制器的输出

- 各种控制信号（ALU操作、寄存器读写、存储器读写、多路选择器选择等）

### 7.5 硬布线控制 vs 微程序控制 ⭐⭐⭐

#### 7.5.1 硬布线控制器（Hardwired Control）

- **实现**：用组合逻辑电路（门电路、触发器）直接产生控制信号
- **设计方法**：列出每个控制信号的逻辑表达式，用门电路实现

> 💡 **类比**：就像用乐高积木直接拼出一个专用机器，只能干一件事，但干得很快。

| 优点 | 缺点 |
|:---|:---|
| 速度快（纯硬件电路，无读取延迟） | 设计复杂，修改困难 |
|  | 指令集越复杂，电路越复杂 |

#### 7.5.2 微程序控制器（Microprogrammed Control）

- **思想**：把控制信号编成"微指令"，存在控制存储器（CM）里
- 执行一条机器指令 = 执行一段微程序（若干条微指令）

> 💡 **类比**：就像把控制步骤写成小程序存在ROM里，执行指令时一条一条读微指令来控制。修改指令只需要改微程序，不用改硬件。

**基本概念**：

| 概念 | 英文 | 含义 |
|:---|:---|:---|
| 微指令 | Microinstruction | 一条微指令包含多个微命令（控制信号） |
| 微程序 | Microprogram | 多条微指令组成一段微程序，对应一条机器指令 |
| 控制存储器 | Control Memory (CM) | 存放微程序的ROM |
| 微地址寄存器 | μAR | 当前微指令的地址 |
| 微命令 | Microcommand | 一个控制信号就是一个微命令 |

**微指令格式**：
```
┌───────────────────────┬──────────────┐
│      控制字段           │   下地址字段   │
│  （微命令编码）          │  下条微指令地址 │
└───────────────────────┴──────────────┘
```

#### 7.5.3 硬布线 vs 微程序 对比

| 特性 | 硬布线控制 | 微程序控制 |
|:---|:---|:---|
| 实现方式 | 组合逻辑电路 | 存储微程序（ROM） |
| 速度 | 快 | 较慢（要读CM） |
| 灵活性 | 差（改硬件） | 好（改微程序） |
| 设计复杂度 | 复杂，指令越多越复杂 | 相对规整 |
| 适合场景 | RISC、高性能CPU | CISC、复杂指令集CPU |
| 修改难度 | 很难（流片后不能改） | 容易（修改CM内容） |

### 7.6 中断与异常 ⭐

#### 7.6.1 基本概念

| 概念 | 英文 | 定义 | 来源 |
|:---|:---|:---|:---|
| 中断 | Interrupt | 外部事件引起的，打断当前程序执行 | 外部I/O设备 |
| 异常 | Exception | 内部指令执行出错引起的 | CPU内部 |

> ⚠️ **注意**：不同教材定义可能略有不同。有的教材把"异常"作为总称，中断是异常的一种。考研408中通常区分：中断=外部，异常=内部。

**常见中断**：键盘输入、打印机完成、定时器中断
**常见异常**：除零、溢出、缺页、非法指令、系统调用

#### 7.6.2 中断的处理过程

```
1. 中断请求（IRQ）：外设发出中断请求
2. 中断判优：多个中断同时来，先处理谁？
3. 中断响应：CPU在每条指令结束时检查中断
   - 关中断
   - 保存断点（PC值）
   - 转中断服务程序入口
4. 中断服务：执行中断服务程序
5. 中断返回：恢复断点，开中断，继续原程序
```

#### 7.6.3 中断判优（优先级）

- 硬件优先级：高优先级的先响应
- 中断屏蔽：可以用中断屏蔽字屏蔽某些中断
- 多重中断（中断嵌套）：高优先级的中断可以打断低优先级的中断服务

## 📖 Day 8 — 流水线技术

### 8.1 为什么需要流水线？

**问题**：单周期CPU一条指令要等全部操作做完才能开始下一条，太慢了。

**解决思路**：把一条指令的执行分成几步，每一步的硬件可以同时处理不同指令的不同阶段 → 这就是**流水线（Pipeline）**

> 💡 **生活类比**：汽车装配流水线。一辆车要经过冲压、焊接、涂装、总装四个车间。第一辆车在总装时，第二辆车在涂装，第三辆车在焊接，第四辆车在冲压。这样虽然一辆车的总生产时间没变，但总体产出大大提高了。

### 8.2 MIPS五级流水线 ⭐

一条MIPS指令的执行分为5个阶段：

| 阶段 | 名称 | 英文 | 主要工作 |
|:---|:---|:---|:---|
| IF | 取指 | Instruction Fetch | 从指令存储器取指令，PC+4 |
| ID | 译码/读寄存器 | Instruction Decode | 译码指令，读寄存器堆 |
| EX | 执行/计算地址 | Execute | ALU执行运算或计算地址 |
| MEM | 访存 | Memory Access | 访问数据存储器（load/store） |
| WB | 写回 | Write Back | 将结果写回寄存器堆 |

**流水线时空图**：

```
时间→  1    2    3    4    5    6    7    8    9
指令1  IF   ID   EX   MEM  WB
指令2       IF   ID   EX   MEM  WB
指令3            IF   ID   EX   MEM  WB
指令4                 IF   ID   EX   MEM  WB
指令5                      IF   ID   EX   MEM  WB
```

**观察**：
- 第5个时钟周期开始，每个周期完成一条指令
- 理想情况下，5级流水线使吞吐率提高约5倍

### 8.3 流水线性能指标

#### 8.3.1 吞吐率（Throughput, TP）

单位时间内完成的指令数

```
理想情况下：TP = f / 1 = f（每条周期完成一条指令）
f = 主频
```

#### 8.3.2 加速比（Speedup）⭐

```
加速比 S = 非流水线执行时间 / 流水线执行时间
```

**例题**：某指令执行分为5段，每段时间为Δt。求连续执行n条指令的加速比。

> 解：
> 非流水线时间 = n × 5Δt = 5nΔt
> 流水线时间 = (5 + n - 1)Δt = (n + 4)Δt
> 加速比 S = 5nΔt / (n+4)Δt = 5n / (n+4)
> 
> 当n很大时，S ≈ 5（接近流水线段数）

> 🔑 **结论**：理想情况下，m级流水线的最大加速比趋近于m。

#### 8.3.3 效率（Efficiency）

流水线各阶段的利用率

```
效率 E = 加速比 S / 流水线段数 m
```

上例中 E = 5n/(n+4) / 5 = n/(n+4)

### 8.4 流水线冒险（Pipeline Hazards）⭐⭐⭐

冒险 = 阻碍流水线继续推进的情况

#### 8.4.1 结构冒险（Structural Hazard）

**原因**：硬件资源不够，多个指令争用同一个硬件

**例子**：指令存储器和数据存储器合并成一个 → IF阶段和MEM阶段都要访问内存 → 冲突

**解决方法**：
- 增加硬件资源（如分开的指令Cache和数据Cache）
- 插入停顿（流水线气泡）

#### 8.4.2 数据冒险（Data Hazard）⭐ 重点！

**原因**：后面的指令需要前面指令的结果，但前面的指令还没算完

**三种类型**：

| 类型 | 英文 | 说明 | 例子 |
|:---|:---|:---|:---|
| 写后读 | RAW (Read After Write) | 读操作在写操作之前完成 → 读到旧值 | ADD R1, R2, R3; SUB R4, R1, R5 |
| 写后写 | WAW (Write After Write) | 两条指令写同一个寄存器，顺序反了 | MUL R1, R2, R3; ADD R1, R4, R5 |
| 读后写 | WAR (Write After Read) | 写操作在只读操作之前完成 → 覆盖了要读的值 | ADD R1, R2, R3; SUB R2, R4, R5 |

> ⚠️ 注意：在经典的五级顺序流水线中，主要是RAW冒险（真相关）。WAW和WAR是名字相关，在乱序执行或更复杂流水线中才会出现。

**RAW冒险的解决方法**：

1. **插入停顿（Stall / Bubble）**：等前面的指令算完再读
   - 简单，但损失性能

2. **数据转发/旁路（Forwarding / Bypassing）⭐**：
   - 把前面指令EX阶段刚算出来的结果，直接转发给后面指令的EX阶段
   - 不需要等写回寄存器再读
   - 可以解决大部分RAW冒险
   
   > 💡 类比：你在流水线上包饺子，上一个人刚包好的饺子，直接递给下一个人煮，不用等放进仓库再拿出来。

3. **编译器调度（Code Scheduling）**：
   - 编译器重新排列指令顺序，把有依赖的指令隔开
   - 在中间插入无关指令

**转发能解决什么，不能解决什么**：
- EX阶段产生的结果 → 可以转发给下一条指令的EX阶段
- load指令在MEM阶段才能拿到数据 → 下一条指令如果马上要用，还是需要停顿一个周期（load-use冒险）

```
lw   $t0, 0($s0)    # MEM阶段才能拿到数据
add  $t1, $t0, $t2  # EX阶段需要$t0 → 要等一个周期（load-use hazard）
```

#### 8.4.3 控制冒险（Control Hazard）⭐

**原因**：分支指令（跳转指令）要到MEM阶段才知道跳不跳、跳到哪，导致后面已经取了错误的指令

**例子**：
```
beq  $t0, $t1, LABEL  # 分支指令
add  $t2, $t3, $t4    # 这条指令已经被取进来了，但可能不该执行
```

**解决方法**：

1. **插入停顿（Stall）**：等分支结果出来再取下一条指令
   - 简单，但每个分支都要等，损失大

2. **预测分支（Branch Prediction）**：
   - **静态预测**：总是预测不跳转（或总是预测跳转）
   - **动态预测**：根据历史记录预测（分支预测缓冲器BTB）

3. **延迟分支（Delayed Branch）**：
   - 在分支指令后面放一条"延迟槽"指令，这条指令总是执行
   - 编译器找一条有用的指令放到延迟槽里

4. **提前计算分支目标**：
   - 在ID阶段就计算分支目标地址（增加硬件）
   - 减少分支延迟

### 8.5 三种冒险总结对比

| 冒险类型 | 原因 | 典型解决方法 |
|:---|:---|:---|
| 结构冒险 | 硬件资源冲突 | 增加资源、停顿 |
| 数据冒险 | 指令间数据依赖 | 转发(Forwarding)、停顿、编译器调度 |
| 控制冒险 | 分支/跳转指令 | 分支预测、延迟分支、停顿 |

### 8.6 超标量与超流水线

- **超标量（Superscalar）**：一个周期发射多条指令（多条流水线并行）
- **超流水线（Superpipeline）**：把每段再细分，增加流水线级数，提高主频
- **乱序执行（Out-of-Order Execution, OoOE）**：指令不一定按顺序执行，谁准备好了谁先执行

<details>
<summary>📝 点击查看答案</summary>

1. 流水线是一种将指令执行过程分解为多个阶段，各阶段硬件并行处理不同指令的技术。
   它能提高性能是因为：虽然单条指令的总执行时间没有减少，但多条指令可以重叠执行，提高了吞吐率（单位时间完成的指令数）。就像工厂流水线，虽然一件产品的总生产时间没变，但单位时间产出更多了。

2. 非流水线时间：
   T_non = 100 × 4 × 10ns = 4000ns = 4μs
   
   流水线时间：
   T_pipe = (4 + 100 - 1) × 10ns = 103 × 10ns = 1030ns = 1.03μs
   
   加速比：
   S = 4000 / 1030 ≈ 3.88倍

3. 
- 结构冒险（Structural Hazard）：硬件资源不足，多条指令争用同一硬件资源。
- 数据冒险（Data Hazard）：指令之间存在数据依赖，后序指令需要前序指令的结果但结果还未产生。
- 控制冒险（Control Hazard）：分支等跳转指令导致流水线预取了错误的指令。

4. 数据转发（Forwarding/Bypassing）是指将前面指令在EX阶段刚计算出的结果，直接通过专用通路转发给后面指令的EX阶段输入端，而不必等结果写回寄存器后再读出。
   
   它不能解决所有数据冒险。例如load-use冒险（load指令后紧跟一条使用该load结果的指令）：load指令要到MEM阶段才能拿到数据，而下一条指令在EX阶段就需要这个数据，转发也无法跨越一个周期的差距，仍然需要插入一个停顿周期。

5. 控制冒险的原因：分支（跳转）指令需要到流水线的较后阶段（如MEM或EX阶段）才能确定是否跳转以及跳转的目标地址，而流水线已经预取了后续指令，如果分支发生，这些预取的指令就是错误的，需要清空。
   
   解决方法：
   - 插入停顿：等分支结果确定后再取指
   - 分支预测：静态预测（总预测不跳/跳）或动态预测（基于历史）
   - 延迟分支：分支后有一个延迟槽，槽内指令总是执行
   - 提前计算分支地址：在ID阶段就计算分支目标

## 📖 Day 9 — 总线与I/O系统

### 9.1 总线（Bus）概述

#### 9.1.1 什么是总线？

**总线**：连接多个部件的一组公共信息传输线，是各部件共享的传输介质

> 💡 **类比**：总线就像城市里的公共马路，所有人都可以用，但同一时间只能有一辆车通行。

#### 9.1.2 总线的分类

**按连接部件分**：

| 类型 | 英文 | 连接对象 | 速度 |
|:---|:---|:---|:---|
| 片内总线 | Internal Bus | CPU内部寄存器之间、ALU与寄存器之间 | 最快 |
| 系统总线 | System Bus | CPU、主存、I/O接口之间 | 中等 |
| 通信总线 | Communication Bus | 计算机之间或计算机与外设之间 | 较慢 |

**系统总线按传输内容分**：

| 总线 | 传输内容 | 方向 | 位数 |
|:---|:---|:---|:---|
| 地址总线 | 地址信息 | 单向（CPU→其他） | 决定寻址空间 |
| 数据总线 | 数据信息 | 双向 | 决定一次传多少数据 |
| 控制总线 | 控制信号 | 双向（有的发有的收） | 各种控制信号 |

#### 9.1.3 总线的性能指标

| 指标 | 含义 | 单位 |
|:---|:---|:---|
| 总线宽度 | 数据总线的位数 | 位（bit） |
| 总线频率 | 总线工作的时钟频率 | MHz, GHz |
| 总线带宽 | 单位时间传输的数据量 | MB/s, GB/s |

**带宽计算公式**：
```
总线带宽 = 总线宽度 × 总线频率 / 8  （B/s）
```
（除以8是因为宽度以位为单位，带宽通常用字节表示）

**例题**：某总线宽度为64位，频率为133MHz，求带宽。
> 解：带宽 = 64bit × 133MHz / 8 = 8B × 133M = 1064 MB/s ≈ 1.04 GB/s

### 9.2 总线仲裁（Bus Arbitration）

**问题**：多个设备同时请求用总线，谁先用？

**仲裁方式**：

#### 9.2.1 集中式仲裁

| 方式 | 英文 | 原理 | 特点 |
|:---|:---|:---|:---|
| 链式查询 | Daisy Chain | 总线同意信号串行传过各设备 | 简单，优先级固定，对故障敏感 |
| 计数器定时查询 | Counter Timer | 用计数器轮询各设备 | 优先级灵活，控制线多 |
| 独立请求 | Independent Request | 每个设备有独立的请求线和同意线 | 响应快，优先级灵活，控制线最多 |

> 💡 **类比**：
> - 链式查询 = 排队，先来后到，队头的优先级高
> - 计数器查询 = 老师点学号，叫到谁谁回答
> - 独立请求 = 每个人举手，老师点名叫人

#### 9.2.2 分布式仲裁

每个设备自己有仲裁逻辑，通过竞争决定谁用总线

### 9.3 总线定时（Bus Timing）

**问题**：发送方和接收方怎么知道数据什么时候有效？

| 方式 | 英文 | 原理 | 特点 |
|:---|:---|:---|:---|
| 同步定时 | Synchronous | 用统一的时钟信号 | 简单、快，但不兼容不同速度的设备 |
| 异步定时 | Asynchronous | 用握手信号（Request/Ack） | 灵活、兼容不同速度，但较慢 |
| 半同步 | Semi-Synchronous | 时钟+等待信号 | 折中方案 |

> 💡 **握手协议类比**：
> 发送方："我发数据了啊！"（Request）
> 接收方："收到了！"（Acknowledge）
> 发送方收到确认后再发下一个。

### 9.4 I/O系统概述

#### 9.4.1 I/O设备分类

| 类型 | 举例 | 特点 |
|:---|:---|:---|
| 输入设备 | 键盘、鼠标、扫描仪 | 数据从外设到主机 |
| 输出设备 | 显示器、打印机 | 数据从主机到外设 |
| 输入输出设备 | 磁盘、网卡、触摸屏 | 双向传输 |
| 终端设备 | 显示器+键盘 | 人机交互 |

#### 9.4.2 I/O接口（I/O Interface / I/O控制器）

**为什么需要接口？**
- 外设速度差异大（键盘慢，磁盘快）
- 信号格式不同（模拟/数字，串行/并行）
- 工作时序不同（与CPU不同步）

**接口的功能**：
1. 数据缓冲（速度匹配）
2. 信号转换（电平、格式转换）
3. 命令译码和状态传递
4. 地址译码（选中哪个设备）

**接口中的寄存器**：
- 数据寄存器（Data Register）：存输入/输出数据
- 控制寄存器（Control Register）：存CPU发来的控制命令
- 状态寄存器（Status Register）：存设备状态

### 9.5 I/O控制方式 ⭐⭐⭐

CPU和外设之间怎么传输数据？有四种主要方式：

#### 9.5.1 程序查询方式（Programmed I/O）

**原理**：CPU不断查询设备状态，准备好了才传输数据

```
while (设备未就绪) {
    读状态寄存器;  // 忙等待
}
传输数据;
```

| 优点 | 缺点 |
|:---|:---|
| 简单，硬件少 | CPU效率极低，一直在等 |
|  | 不支持并发，CPU和外设串行工作 |

> 💡 类比：你每隔一分钟就去看外卖到了没，什么事都干不了。

#### 9.5.2 程序中断方式（Interrupt-driven I/O）⭐

**原理**：CPU启动外设后继续干自己的事，外设准备好了发中断请求，CPU响应中断后处理数据传输

```
CPU启动外设 → CPU继续执行主程序
外设准备好 → 发中断请求
CPU响应中断 → 暂停主程序 → 执行中断服务程序（传数据）
中断返回 → 继续主程序
```

| 优点 | 缺点 |
|:---|:---|
| CPU效率高，CPU与外设并行工作 | 中断处理有开销（保存/恢复现场） |
| 支持多设备并发 | 不适合高速大量数据传输 |

> 💡 类比：你点了外卖后继续工作，外卖到了打电话给你，你再去取。

#### 9.5.3 DMA方式（Direct Memory Access）⭐⭐ 重点！

**原理**：DMA控制器（DMAC）直接控制总线，在内存和外设之间直接传输数据，不需要CPU干预

**适用场景**：高速、批量数据传输（磁盘、网卡、显卡）

**DMA的工作过程**：
```
1. CPU向DMAC发送参数（内存地址、传输字节数、方向）
2. CPU继续执行其他程序
3. 外设就绪 → DMAC请求总线
4. DMAC获得总线控制权 → 直接在内存和外设间传输数据
5. 传输完成 → DMAC发中断通知CPU
```

| 优点 | 缺点 |
|:---|:---|
| 速度快，不需要CPU干预 | 需要DMA控制器硬件，成本高 |
| 适合高速批量数据 | 初始化和结束仍需中断 |

> 💡 类比：你叫了搬家公司（DMA），告诉他们地址和搬多少东西，他们自己搬，搬完了给你打电话说一声。你不用亲自搬。

**DMA传送方式**：
| 方式 | 说明 | CPU暂停时间 |
|:---|:---|:---|
| 停止CPU访问 | DMA期间CPU完全让出总线 | 长 |
| 周期挪用 | DMA挪用一个总线周期 | 短（1个周期） |
| DMA与CPU交替访存 | 分时复用 | 几乎不影响 |

#### 9.5.4 通道方式（Channel）

**原理**：更高级的I/O处理器，有自己的指令（通道指令），可以执行通道程序
- 比DMA更强大，能管理多个设备
- 主要用于大型机、服务器

### 9.6 四种I/O方式对比 ⭐

| 特性 | 程序查询 | 程序中断 | DMA | 通道 |
|:---|:---|:---|:---|:---|
| CPU干预程度 | 最高（全程等） | 中等（中断处理） | 最低（只初始化） | 更低（执行通道程序） |
| 数据传输单位 | 字/字节 | 字/字节 | 数据块 | 多个数据块 |
| 并行性 | 无（串行） | 有一定并行 | 好 | 最好 |
| 硬件成本 | 最低 | 较低 | 较高 | 最高 |
| 适用场景 | 简单低速设备 | 中低速设备 | **高速批量** | 大型系统多设备 |
| 中断次数 | 无 | 每个字一次 | 每块一次 | 每组一次 |

1. 总线是连接多个部件的一组公共信息传输线路，是各部件共享的传输介质。
   
   系统总线分为三类：
   - 地址总线：传输地址信息，单向（CPU→内存/外设），决定寻址空间大小。
   - 数据总线：传输数据信息，双向，位数决定一次传输的数据量。
   - 控制总线：传输控制信号和状态信号，双向。

   = 32bit × 66MHz / 8
   = 4B × 66M

- 链式查询：总线同意信号串行经过各设备，优先级固定。
  优点：简单，控制线少；缺点：优先级固定不灵活，对故障敏感。
- 计数器定时查询：用计数器轮流查询各设备。
  优点：优先级可灵活设置；缺点：控制线较多，速度较慢。
- 独立请求：每个设备有独立的请求和同意线。
  优点：响应快，优先级灵活；缺点：控制线最多，硬件成本高。

| 特性 | 程序查询 | 程序中断 | DMA |
|:---|:---|:---|:---|
| CPU参与度 | 全程参与，忙等 | 中断时参与 | 几乎不参与 |
| 数据单位 | 字/字节 | 字/字节 | 数据块 |
| CPU效率 | 极低 | 中等 | 高 |

| 适用 | 简单低速设备 | 中低速设备 | 高速批量传输 |
| 硬件 | 最少 | 较少 | 较多 |

5. DMA更适合高速数据传输的原因：
   - 中断方式每传输一个字/字节就要触发一次中断，中断处理开销大；
   - DMA方式由DMA控制器直接控制总线，在内存和外设之间直接传输数据，一整块数据传输完成后才发一次中断通知CPU，大大减少了CPU的干预次数和中断开销。
   
   DMA工作过程：
   1. CPU初始化DMA控制器（设置内存地址、传输字节数、传输方向等）
   2. CPU继续执行其他程序
   3. 外设准备好后向DMA控制器发请求
   4. DMA控制器向CPU发总线请求，获得总线控制权
   5. DMA控制器直接在内存和外设之间传输数据
   6. 传输完成后，DMA控制器发中断通知CPU

## 📖 Day 10 — 并行计算基础 + 总复习

### 10.1 并行计算概述

**并行性**：在同一时刻或同一时间间隔内完成两个或多个任务

#### 10.1.1 并行性的等级

| 等级 | 英文 | 说明 | 粒度 |
|:---|:---|:---|:---|
| 指令级并行 | ILP (Instruction Level) | 多条指令并行执行 | 最细 |
| 线程级并行 | TLP (Thread Level) | 多个线程并行执行 | 细 |
| 任务级并行 | Task Level | 多个任务/进程并行 | 中 |
| 作业级并行 | Job Level | 多个作业并行 | 粗 |

#### 10.1.2 Flynn分类法 ⭐

按指令流和数据流的数量分类：

| 类型 | 英文 | 含义 | 典型例子 |
|:---|:---|:---|:---|
| SISD | Single Instruction, Single Data | 单指令单数据 | 传统单核CPU |
| SIMD | Single Instruction, Multiple Data | 单指令多数据 | **向量处理器、GPU、MMX/SSE/AVX** |
| MISD | Multiple Instruction, Single Data | 多指令单数据 | 少见（流水线算一种观点） |
| MIMD | Multiple Instruction, Multiple Data | 多指令多数据 | **多核CPU、多处理器系统** |

> 💡 **SIMD类比**：一个老师（单指令）同时指挥全班同学（多数据）做同一个动作。比如给数组每个元素都加1，一条指令就搞定。
>
> **MIMD类比**：多个老师各带各的学生，各干各的事。

### 10.2 指令级并行（ILP）

**目标**：让CPU在一个周期内执行多条指令

#### 10.2.1 实现方法

| 技术 | 英文 | 说明 |
|:---|:---|:---|
| 超标量 | Superscalar | 多套功能部件，一个周期发射多条指令 |
| 超流水线 | Superpipelining | 流水线级数更多，主频更高 |
| 超长指令字 | VLIW | 编译器把多条操作打包成一条长指令 |
| 乱序执行 | OoOE | 指令不按顺序执行，谁准备好了谁先执行 |

### 10.3 多核处理器（Multi-core）

#### 10.3.1 基本概念

- **多核**：一个芯片上集成多个CPU核心
- 每个核心有自己的L1/L2 Cache，共享L3 Cache和内存控制器

#### 10.3.2 缓存一致性问题（Cache Coherence）

**问题**：多个核心各自有Cache，同一份数据在多个Cache里有副本，一个核心修改了数据，其他核心的副本就过期了。

> 💡 **类比**：几个人一起做一个项目，每个人都有一份文件副本。一个人改了文件，其他人的旧版本就不对了。需要一种机制确保大家的版本一致。

**解决方案——缓存一致性协议**：

**MESI协议**（最经典）：每个Cache行有四种状态

| 状态 | 英文 | 含义 |
|:---|:---|:---|
| M | Modified（已修改） | 该Cache行已被修改，与内存不一致，只有本核心有 |
| E | Exclusive（独占） | 只有本核心有该数据，与内存一致 |
| S | Shared（共享） | 多个核心都有该数据，与内存一致 |
| I | Invalid（无效） | 该Cache行无效，不能用 |

**基本规则**：
- 写操作前必须获得独占权
- 一个核心写了，其他核心的副本变成无效（Invalid）
- 读无效数据时需要重新从内存或其他核心获取

### 10.4 并行程序设计挑战

1. **负载均衡**：把任务均匀分给各个核心
2. **同步与通信**：线程之间怎么协调
3. **数据竞争**：多个线程同时读写共享数据
4. **可扩展性**：核心数增加时性能是否线性提升（Amdahl定律）

### 核心公式清单

| 公式名称 | 公式 | 变量说明 |
|:---|:---|:---|
| 主频与周期 | f = 1/T | f=主频, T=时钟周期 |
| CPI | CPI = 总周期数 / 指令数 | — |
| MIPS | MIPS = f / (CPI × 10⁶) | f以Hz为单位 |
| Amdahl定律 | S = 1/[(1-α) + α/n] | α=可加速比例, n=加速倍数 |
| Cache AMAT | AMAT = Tc + (1-h)×Tm | h=命中率, Tc=Cache时间, Tm=主存时间 |
| 总线带宽 | 带宽 = 宽度 × 频率 / 8 | 宽度以位为单位 |
| 流水线加速比 | S = 非流水线时间 / 流水线时间 | — |
| 流水线吞吐率 | TP = n / T_total | n=指令数, T_total=总时间 |
| IEEE 754单精度 | V = (-1)^S × 1.M × 2^(E-127) | S=符号, E=阶码, M=尾数 |

### 易混淆点清单 ⚠️

| 易混淆组 | 关键区别 |
|:---|:---|
| Cache vs 虚拟内存 | Cache解决速度问题，硬件管理；虚拟内存解决容量+管理问题，OS+硬件管理 |
| 中断 vs 异常 | 中断来自外部（I/O等）；异常来自内部（指令执行出错） |
| 硬布线 vs 微程序 | 硬布线=组合逻辑电路，快但不灵活；微程序=存控存里，灵活但慢 |
| SRAM vs DRAM | SRAM=触发器，快，贵，做Cache；DRAM=电容，要刷新，便宜，做内存 |
| CISC vs RISC | CISC=指令多、变长、复杂；RISC=指令少、定长、简单、易流水 |
| 原码 vs 补码 | 原码直观但减法难做；补码减法变加法，只有一个零 |
| 基址 vs 变址 | 基址=BR不变A变，系统用；变址=A不变IX变，用户用，数组遍历 |
| 结构冒险 vs 数据冒险 vs 控制冒险 | 结构=硬件不够；数据=有依赖；控制=分支跳转 |
| 程序中断 vs DMA | 中断靠CPU传数据，每个字一次；DMA直接传，一块一次中断 |
| 写直达 vs 写回 | 写直达=同时写Cache和内存，简单但慢；写回=只写Cache，替换时写回，快但要脏位 |
