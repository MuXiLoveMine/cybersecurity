## 一、Web 安全工具链概览

### 1.1 按功能分类

Web 安全工具种类繁多，按功能可以分为以下几大类：

| 工具类别 | 核心能力 | 典型工具 | 适用阶段 |
|---------|---------|---------|---------|
| **代理与抓包** | 拦截/修改/重放 HTTP 请求，Web 测试的"瑞士军刀" | Burp Suite、OWASP ZAP | 全程使用，核心工具 |
| **自动化扫描** | 自动化发现 Web 漏洞（主动/被动扫描） | Burp Scanner、OWASP ZAP、Nuclei | 测试阶段，批量发现 |
| **注入利用** | 自动化检测和利用注入类漏洞 | sqlmap、NoSQLMap、Commix | 漏洞验证与利用 |
| **浏览器 DevTools** | 前端分析、调试、请求分析 | Chrome DevTools、Firefox DevTools | 前端分析、调试 |
| **SAST（静态分析）** | 不运行代码，直接分析源代码找漏洞 | Semgrep、SonarQube、CodeQL | 开发阶段，代码审计 |
| **DAST（动态测试）** | 运行中的应用，从外部黑盒测试 | Burp Scanner、OWASP ZAP、Invicti | 测试/上线阶段 |
| **依赖审计（SCA）** | 扫描第三方依赖的已知漏洞 | OWASP Dependency-Check、Snyk、Trivy | 开发/构建阶段 |
| **目录/文件扫描** | 发现隐藏的目录、文件、子域名 | dirsearch、ffuf、Gobuster | 信息收集阶段 |
| **指纹识别** | 识别技术栈、CMS、中间件 | whatweb、Wappalyzer、EHole | 信息收集阶段 |

### 1.2 渗透测试中的工具使用流程

```
信息收集 → 漏洞发现 → 漏洞验证 → 漏洞利用 → 报告编写
  │           │            │            │           │
  │           │            │            │           └── 报告工具
  │           │            │            └── sqlmap / 手工利用
  │           │            └── Repeater / 手工验证
  │           └── Burp Scanner / ZAP / 手工
  └── 指纹识别 / 目录扫描 / 子域名枚举
```

> **核心原则**：工具是手段，不是目的。理解原理比会用工具重要得多。
> 会用工具的人很多，但真正理解漏洞原理、能灵活运用的人才是高手。

### 1.3 工具选择原则

1. **先精后广**：先精通一个核心工具（如 Burp Suite），再学其他的
2. **任务驱动**：根据实际任务选择合适的工具，不是为了学而学
3. **理解原理**：不要只会点按钮，要理解工具背后的原理
4. **手工为主，工具为辅**：工具帮你提高效率，但不能替代思考
5. **商业 vs 开源**：根据预算和需求选择，开源工具也能做得很好
6. **持续更新**：安全工具更新很快，保持工具版本和知识的更新

## 二、代理与抓包工具——Burp Suite

### 2.1 基本信息

| 项目 | 内容 |
|------|------|
| **全称** | Burp Suite |
| **开发商** | PortSwigger（英国） |
| **定位** | Web 渗透测试的行业标准工具，Web 安全工程师的"标配" |
| **地位** | Web 安全领域最核心、最常用的工具，没有之一 |
| **适用平台** | Windows / macOS / Linux（Java 开发，跨平台） |
| **官网** | portswigger.net/burp |

### 2.2 版本对比

Burp Suite 有三个主要版本：

| 版本 | 价格 | 目标用户 | 核心功能差异 |
|------|------|---------|-------------|
| **Community（社区版）** | 免费 | 初学者、学生 | 基础代理、Repeater、Decoder；Intruder 受限；无 Scanner |
| **Professional（专业版）** | 付费（年费约 400 美元） | 渗透测试工程师、安全团队 | 完整功能：Scanner、完整 Intruder、所有插件 |
| **Enterprise（企业版）** | 付费（企业级定价） | 大型企业、安全团队 | 企业级扫描、集中管理、API、CI/CD 集成 |

> **初学者建议**：
> 入门阶段可以先用社区版（免费）学习基本功能。
> 等基础打牢、确定走这个方向了，再考虑专业版。
> 很多公司会为安全人员购买专业版授权。

### 2.3 核心功能模块

Burp Suite 由多个功能模块（工具）组成，它们之间可以无缝协作。

| 模块 | 功能 | 重要程度 |
|------|------|---------|
| **Proxy（代理）** | 拦截和修改 HTTP/HTTPS 请求和响应 | ⭐⭐⭐⭐⭐ 核心 |
| **Repeater（重放器）** | 手动重发请求，修改参数，观察响应 | ⭐⭐⭐⭐⭐ 核心 |
| **Intruder（入侵者）** | 自动化攻击（爆破、枚举、fuzz 等） | ⭐⭐⭐⭐ 重要 |
| **Scanner（扫描器）** | 自动化漏洞扫描（主动/被动） | ⭐⭐⭐⭐ 重要（专业版） |
| **Decoder（解码器）** | 编码/解码（URL、Base64、HTML、Unicode 等） | ⭐⭐⭐⭐ 常用 |
| **Comparer（比较器）** | 比较两个请求/响应的差异 | ⭐⭐⭐ 常用 |
| **Sequencer（序列器）** | 分析随机数/令牌的随机性 | ⭐⭐ 偶尔用 |
| **Extender（扩展器）** | 插件管理，扩展 Burp 功能 | ⭐⭐⭐⭐ 重要 |
| **Dashboard（仪表盘）** | 扫描任务管理、问题汇总 | ⭐⭐⭐ 常用 |
| **Target（目标）** | 站点地图、目标范围管理 | ⭐⭐⭐⭐ 重要 |
| **Logger（日志）** | 所有 HTTP 流量的日志记录 | ⭐⭐⭐⭐ 重要 |
| **Discover（发现）** | 【2026 新】替代 Learn 选项卡，AI 驱动的漏洞学习 | ⭐⭐⭐ 新增 |

> **Burp 的强大之处在于"协作"**：
> 不是每个工具孤立使用，而是 Proxy 抓到请求 → 发到 Repeater 手动测 → 发现漏洞 → 用 Intruder 自动化 → 用 Scanner 批量扫 → 用 Decoder/Comparer 辅助分析。
> 各个工具之间可以互相转发数据，形成完整的工作流。

### 2.5 核心使用场景与工作流

#### 场景 1：手动 Web 渗透测试

```
1. 配置浏览器代理 → Burp Proxy
        ↓
2. 浏览网站，Proxy 抓取所有请求
        ↓
3. 在 Target 中查看站点地图，确定测试范围
        ↓
4. 把感兴趣的请求发到 Repeater
        ↓
5. 修改参数，重放请求，观察响应
        ↓
6. 发现漏洞 → 手工验证 → 记录漏洞详情
        ↓
7. 整理报告
```

#### 场景 2：自动化漏洞扫描

```
1. 配置目标范围（Scope）
        ↓
2. 启动主动/被动扫描
        ↓
3. Dashboard 查看扫描进度和发现的问题
        ↓
4. 人工验证扫描结果（排除误报）
        ↓
5. 确认漏洞，输出扫描报告
```

#### 场景 3：使用 Intruder 进行自动化测试

```
1. 把请求发到 Intruder
        ↓
2. 设置 payload 位置（要爆破的参数）
        ↓
3. 选择攻击类型和 payload 列表
        ↓
4. 启动攻击
        ↓
5. 根据响应长度/状态码/时间等判断结果
```

**常见 Intruder 使用场景**：
- 密码暴力破解
- 验证码爆破
- 用户 ID / 订单 ID 遍历
- 目录 / 文件枚举
- 参数 fuzzing（模糊测试）

### 2.6 常用插件（BApp Store）

Burp 的扩展性很强，通过插件可以大大增强功能。

| 插件 | 功能 | 推荐程度 |
|------|------|---------|
| **Hackvertor** | 强大的编码转换工具，支持在请求中直接使用标签 | ⭐⭐⭐⭐⭐ |
| **Active Scan++** | 增强主动扫描能力 | ⭐⭐⭐⭐ |
| **J2EE Scanner** | Java 应用扫描增强 | ⭐⭐⭐ |
| **Wsdler** | Web Service 分析 | ⭐⭐⭐ |
| **Retire.js** | JavaScript 库漏洞检测 | ⭐⭐⭐⭐ |
| **Burp Suite Logger++** | 更强大的日志功能 | ⭐⭐⭐ |
| **Autorize** | 自动测试越权（认证绕过） | ⭐⭐⭐⭐⭐ |

### 2.7 使用注意事项

| 注意事项 | 说明 |
|---------|------|
| **授权使用** | 只能对有授权的目标使用 Burp 进行测试 |
| **Scope 设置** | 一定要设置目标范围，避免扫描到非授权目标 |
| **主动扫描风险** | 主动扫描可能对目标系统造成压力，生产环境要谨慎 |
| **证书安装** | 抓 HTTPS 需要安装 Burp 的 CA 证书 |
| **插件安全** | 只从官方 BApp Store 安装插件，警惕恶意插件 |

## 三、代理与抓包工具——OWASP ZAP

### 3.1 基本信息

| 项目 | 内容 |
|------|------|
| **全称** | OWASP Zed Attack Proxy（ZAP） |
| **开发商** | OWASP（开源社区） |
| **定位** | 开源免费的 Web 应用安全扫描器 |
| **性质** | 完全开源、免费、跨平台 |
| **适用平台** | Windows / macOS / Linux |
| **官网** | zaproxy.org |

### 3.2 核心功能

| 功能 | 说明 |
|------|------|
| **代理服务器** | 拦截/修改 HTTP/HTTPS 请求 |
| **主动扫描** | 自动化漏洞扫描 |
| **被动扫描** | 浏览时自动分析流量发现漏洞 |
| **爬虫（Spider）** | 爬取网站，发现页面和接口 |
| **Fuzzer** | 模糊测试工具 |
| **Requester** | 手动重放请求（类似 Burp Repeater） |
| **API 支持** | 提供 REST API，便于自动化集成 |
| **插件系统** | 丰富的插件市场，可扩展功能 |
| **CI/CD 集成** | 可以方便地集成到持续集成流程 |

### 3.3 ZAP vs Burp Suite 对比

| 维度 | OWASP ZAP | Burp Suite Professional |
|------|-----------|------------------------|
| **价格** | 完全免费 | 付费（约 $400/年） |
| **开源** | ✅ 完全开源 | ❌ 商业软件 |
| **代理功能** | 完善 | 更强大 |
| **手动测试体验** | 可用 | 优秀（行业标杆） |
| **自动化扫描** | 不错 | 更强（检测率更高、误报更低） |
| **插件生态** | 丰富 | 更丰富（BApp Store） |
| **CI/CD 集成** | 优秀（API 完善） | 有 API（企业版更好） |
| **学习资源** | 较多 | 非常多（行业标准） |
| **适合场景** | 自动化、CI/CD、预算有限 | 手动深度测试、专业渗透 |

> **总结**：
> - **预算充足，做手动渗透测试** → Burp Suite 专业版（体验更好，效率更高）
> - **预算有限，或主要做自动化 / CI 集成** → OWASP ZAP（完全够用）
> - 两者不是互斥的——很多团队同时使用，各有所长。

### 3.4 ZAP 的优势场景

| 场景 | 为什么选 ZAP |
|------|------------|
| **CI/CD 集成** | 开源、API 完善、Docker 镜像方便集成到流水线 |
| **教学和培训** | 免费，学生/团队都能无障碍使用 |
| **自动化安全测试** | 适合做定期的、批量的自动化扫描 |
| **定制开发** | 开源，可以根据需要修改和扩展 |
| **预算有限的团队** | 零成本就能有完整的 DAST 能力 |

## 四、注入利用工具——sqlmap

### 4.1 基本信息

| 项目 | 内容 |
|------|------|
| **全称** | sqlmap |
| **定位** | 自动化 SQL 注入检测和利用工具 |
| **性质** | 开源免费（Python 开发） |
| **最新版本** | 1.10.2（2026 年） |
| **开发者** | 社区维护，最初由 Bernardo Damele 开发 |
| **适用平台** | 跨平台（Windows / macOS / Linux） |
| **官网** | sqlmap.org |

> **⚠️ 高风险警告**：
> sqlmap 是功能强大的 SQL 注入工具，仅限在**授权测试环境**中使用。
> 未经授权对他人系统使用 sqlmap 是违法行为，可能承担法律责任。
> 学习时请使用本地靶场（DVWA、SQLi-Labs 等）。

### 4.2 核心能力

| 能力 | 说明 |
|------|------|
| **自动检测注入点** | 自动检测 GET/POST 参数、Cookie、HTTP 头等是否存在注入 |
| **支持多种数据库** | MySQL、Oracle、PostgreSQL、Microsoft SQL Server、SQLite、Access、Firebird、Sybase、SAP MaxDB、DB2 等 20+ 种 |
| **6 种注入技术** | 布尔盲注、时间盲注、报错注入、UNION 查询、堆叠查询、带外（OOB） |
| **数据提取** | 脱库（拖库）、导出表结构和数据 |
| **操作系统访问** | 某些情况下可以执行系统命令、读取文件 |
| **提权** | 数据库提权相关功能 |
| **绕过能力** | 200+ 绕过脚本（WAF 绕过、过滤绕过） |
| **自动化程度高** | 从检测到利用到脱库，可以全自动完成 |

### 4.3 支持的注入类型（6 种）

| 注入类型 | 英文 | 原理 | 适用场景 |
|---------|------|------|---------|
| **布尔盲注** | Boolean-based blind | 根据页面真假（布尔）判断 | 页面不回显数据，但有真假差异 |
| **时间盲注** | Time-based blind | 根据响应时间判断 | 页面完全没有回显差异，只能靠时间 |
| **报错注入** | Error-based | 利用数据库报错信息获取数据 | 页面显示数据库错误信息 |
| **UNION 查询注入** | UNION query | 用 UNION 合并查询结果 | 页面回显查询结果 |
| **堆叠查询注入** | Stacked queries | 多条 SQL 语句一起执行 | 数据库支持多语句执行（如 MSSQL） |
| **带外注入** | Out-of-band (OOB) | 通过 DNS/HTTP 等外带通道获取数据 | 其他方式都不行时的高级技巧 |

### 4.4 常用参数详解

#### 基础参数

| 参数 | 作用 | 示例 |
|------|------|------|
| `-u <URL>` | 指定目标 URL | `sqlmap -u "http://test.com/index.php?id=1"` |
| `-r <file>` | 从请求文件读取（Burp 导出的请求） | `sqlmap -r request.txt` |
| `-p <param>` | 指定测试的参数 | `sqlmap -u URL -p id` |
| `--data <data>` | POST 数据 | `sqlmap -u URL --data "user=admin&pass=123"` |
| `--cookie <cookie>` | 设置 Cookie | `sqlmap -u URL --cookie "PHPSESSID=xxx"` |

#### 枚举参数（获取信息）

| 参数 | 作用 |
|------|------|
| `--dbs` | 列出所有数据库 |
| `-D <db>` | 指定数据库 |
| `--tables` | 列出指定数据库的所有表 |
| `-T <table>` | 指定表名 |
| `--columns` | 列出指定表的所有列 |
| `-C <col>` | 指定列名 |
| `--dump` | 导出（拖库）指定表的数据 |
| `--dump-all` | 导出所有数据库所有表 |
| `--current-db` | 获取当前数据库名 |
| `--current-user` | 获取当前数据库用户名 |
| `--users` | 列出所有数据库用户 |
| `--passwords` | 列出数据库用户密码哈希 |
| `--privileges` | 查看当前用户权限 |

#### 注入技术相关

| 参数 | 作用 |
|------|------|
| `--technique <T>` | 指定注入技术（B/E/U/S/T/Q） |
| `--dbms <db>` | 指定数据库类型（提高效率） |
| `--os <os>` | 指定操作系统 |
| `--level <1-5>` | 测试级别（1-5，越高越全面，默认 1） |
| `--risk <1-3>` | 风险级别（1-3，越高越危险，默认 1） |
| `--tamper <script>` | 使用绕过脚本（WAF 绕过） |

#### 其他常用参数

| 参数 | 作用 |
|------|------|
| `--batch` | 全自动模式，不询问，使用默认选项 |
| `--threads <n>` | 线程数（提高速度） |
| `--proxy <proxy>` | 使用代理（可以挂 Burp 查看流量） |
| `--random-agent` | 使用随机 User-Agent |
| `--tor` | 通过 Tor 网络 |
| `--output-dir <dir>` | 指定输出目录 |
| `-v <1-6>` | 详细程度（1-6，越高越详细） |

### 4.5 常用工作流示例

> **⚠️ 以下示例仅用于学习，必须在授权靶场环境中操作。**

#### 工作流 1：检测是否存在注入

```bash
# 测试单个 URL 的参数是否存在注入
sqlmap -u "http://target.com/page?id=1"

# 从 Burp 保存的请求文件测试（POST 请求更方便）
sqlmap -r request.txt
```

#### 工作流 2：获取数据库信息

```bash
# 列出所有数据库
sqlmap -u "http://target.com/page?id=1" --dbs

# 列出指定数据库的所有表
sqlmap -u "http://target.com/page?id=1" -D testdb --tables

# 列出指定表的所有列
sqlmap -u "http://target.com/page?id=1" -D testdb -T users --columns
```

#### 工作流 3：导出数据（脱库）

```bash
# 导出指定表的数据
sqlmap -u "http://target.com/page?id=1" -D testdb -T users --dump

# 导出所有数据库（谨慎使用）
sqlmap -u "http://target.com/page?id=1" --dump-all
```

#### 工作流 4：使用代理配合 Burp 查看

```bash
# 通过 Burp 代理，方便在 Burp 中查看 sqlmap 的请求
sqlmap -u "http://target.com/page?id=1" --proxy http://127.0.0.1:8080
```

### 4.6 使用 sqlmap 的正确姿势

| ✅ 正确的用法 | ❌ 错误的用法 |
|-------------|-------------|
| 手工发现注入点后，用 sqlmap 辅助验证和利用 | 上来就扔给 sqlmap 扫，自己啥也不懂 |
| 理解每种注入的原理，知道 sqlmap 在做什么 | 把 sqlmap 当黑盒，只会点命令 |
| 用于授权的渗透测试，提高效率 | 用于未授权的目标（违法） |
| 配合 Burp 等工具，分析请求和响应 | 只看结果，不看过程 |
| 作为学习辅助，理解原理是关键 | 以为会用 sqlmap 就是会 SQL 注入了 |

> **重要提醒**：
> sqlmap 是"辅助工具"，不是"替代思考"。
> 真正的能力是发现注入点、理解注入原理、知道什么时候用什么技术。
> 会用 sqlmap 不代表会 SQL 注入——就像会用计算器不代表懂数学。

```
2. 找到关键的 JS 文件
3. 在提交表单的函数上设置断点
4. 提交表单，触发断点
5. 单步调试，理解加密/校验逻辑
6. 找到绕过方法或理解参数构造方式
```

#### 场景 2：XSS 测试

```
1. 打开 Console 面板
2. 输入简单的 XSS 测试代码，如 alert(1)
3. 观察 DOM 变化，看输入输出位置
4. 构造 Payload，绕过过滤

```

#### 场景 3：Cookie 安全检查

```
1. 打开 Application 面板 → Cookies

```

#### 场景 4：安全头检查

```

3. 查看响应头中的安全相关头：
   - Strict-Transport-Security
   - Content-Security-Policy
   - X-Frame-Options
   - X-Content-Type-Options
   - Referrer-Policy
4. 或者直接用 Security 面板查看
```

## 七、SAST 与 DAST 工具

### 7.1 基本概念

| 缩写 | 全称 | 中文 | 测试方式 |
|------|------|------|---------|
| **SAST** | Static Application Security Testing | 静态应用安全测试 | 不运行，直接分析源代码/二进制 |
| **DAST** | Dynamic Application Security Testing | 动态应用安全测试 | 运行中，从外部黑盒测试 |
| **IAST** | Interactive Application Security Testing | 交互式应用安全测试 | 动静结合，运行时插桩分析 |

### 7.2 SAST vs DAST vs IAST 对比

| 维度 | SAST | DAST | IAST |
|------|------|------|------|
| **测试时机** | 开发阶段 / 编码阶段 | 测试阶段 / 上线后 | 测试阶段 |
| **是否需要运行** | ❌ 不需要 | ✅ 需要 | ✅ 需要 |
| **是否需要源码** | ✅ 需要（白盒） | ❌ 不需要（黑盒） | ⚠️ 需要插桩（灰盒） |
| **发现的问题** | 代码层面的漏洞 | 运行时的漏洞 | 更准确的运行时漏洞 |
| **误报率** | 较高 | 中等 | 较低 |
| **漏报率** | 中等 | 较高 | 较低 |
| **修复成本** | 低（早发现） | 高（快上线了才发现） | 中 |
| **速度** | 快 | 慢 | 中等 |
| **适合谁用** | 开发、代码审计 | 安全测试 | 安全测试 |
| **代表工具** | Semgrep、SonarQube、CodeQL | Burp Scanner、ZAP、Invicti | Contrast、Seeker |

> **最佳实践**：不是三选一，而是都用——
> - SAST 在开发阶段发现代码问题（早发现，早修复）
> - DAST 做最终的运行时验证（从攻击者视角）
> - IAST 有条件的话也可以用（准确率更高）
> 三者互补，组成完整的应用安全测试体系。

### 9.1 Burp Suite + sqlmap

**组合方式**：Burp 发现注入点 → sqlmap 自动化验证和利用

**工作流**：
```
1. Burp Proxy 抓包浏览网站
        ↓
2. 手工测试某个参数，发现疑似 SQL 注入
        ↓
3. 在 Burp 中把请求保存为文件（右键 → Save item / Copy to file）
        ↓
4. 用 sqlmap -r 请求文件 进行自动化检测
        ↓
5. sqlmap 确认注入并获取数据
        ↓
6. 回到 Burp 中验证和分析结果
```

**为什么要组合使用**：
- Burp 适合手动探索和发现问题
- sqlmap 适合自动化利用，节省时间
- 手工确认 + 工具加速 = 效率最高

### 9.2 Burp Suite + 浏览器开发者工具

**组合方式**：Burp 拦截和修改请求，DevTools 分析前端逻辑

**工作流**：
```
1. 浏览器 + Burp 代理 → 正常访问网站
        ↓
2. 遇到前端校验/加密 → 打开 DevTools
        ↓
3. Sources 面板找关键 JS → 断点调试 → 理解前端逻辑
        ↓
4. 知道前端怎么处理参数了 → 回到 Burp 中构造 Payload
        ↓
5. Burp Repeater 重放 → 验证漏洞
```

**为什么要组合使用**：
- Burp 看请求响应很方便，但分析前端 JS 不如 DevTools
- DevTools 调试 JS 很强大，但修改请求重放不如 Burp
- 两者配合，前端后端都能搞定

### 9.3 SAST + DAST 组合

**组合方式**：静态分析（SAST）在开发阶段发现问题，动态测试（DAST）在测试阶段验证

**工作流**：
```
开发阶段                测试阶段                上线
  │                       │                      │
  ├── SAST 扫描代码        ├── DAST 扫描应用      ├── 持续监控
  │   ├── 找代码层漏洞     │   ├── 找运行时漏洞    │
  │   ├── 修复成本低       │   ├── 验证实际风险    │
  │   └── 误报需要人工确认 │   └── 更贴近真实攻击  │
  └───────────────────────┴──────────────────────┘
                两者互补，组成完整的测试体系
```

**为什么要组合使用**：
- SAST 能发现 DAST 发现不了的问题（如代码层的逻辑缺陷）
- DAST 能发现 SAST 发现不了的问题（如配置错误、运行时漏洞）
- SAST 早发现早修复，成本低；DAST 最终验证，更贴近真实攻击

### 9.4 完整的 Web 安全工具链（推荐）

## 十、工具使用最佳实践与合规

### 10.1 工具使用原则

#### 1. 授权原则

- 只能对有**书面授权**的目标使用安全工具
- 测试范围、时间、方式都要在授权范围内
- 超出授权范围的测试 = 违法行为

#### 2. 最小影响原则

- 测试尽量减少对目标系统的影响
- 主动扫描、暴力破解等高负载操作要谨慎
- 生产环境测试要避开业务高峰期
- 重要数据要备份，防止测试导致数据损坏

#### 3. 理解原理原则

- 不要只会用工具，要理解工具背后的原理
- 工具是辅助，思考和判断才是核心能力
- 知其然，更要知其所以然

#### 4. 持续学习原则

- 安全工具更新很快，保持学习
- 新工具、新版本、新功能要及时了解
- 工具在进化，人的能力也要进化

### 10.2 常见误区

| 误区 | 事实 |
|------|------|
| "工具越贵越好用" | 适合的才是最好的，免费工具也能做得很好 |
| "会用工具 = 会安全" | 工具只是手段，理解原理和思维方式更重要 |
| "扫描器扫不到就是安全的" | 扫描器有局限性，很多漏洞扫不出来（尤其是逻辑漏洞） |
| "工具越多越好" | 精通几个核心工具 > 会用一堆工具但都不精 |
| "自动化能替代人工" | 自动化能提高效率，但不能替代人的判断和创意 |

### 10.3 合规与法律

| 法律法规 | 相关内容 |
|---------|---------|
| **《网络安全法》** | 网络运行安全、禁止入侵和破坏 |
| **《刑法》** | 非法侵入计算机信息系统罪、破坏计算机信息系统罪、提供侵入/非法控制计算机信息系统程序/工具罪 |
| **《数据安全法》** | 数据安全保护、禁止非法获取数据 |

> **重要提醒**：
> - 技术本身没有对错，但使用技术的行为有合法与非法之分
> - 安全工具是"双刃剑"——用来防御和授权测试是正义的，用来攻击是违法的
> - 不要心存侥幸，"我只是测试一下"不是免责理由
> - 作为安全从业者，要守住法律底线和职业操守

### 10.4 给初学者的建议

1. **从一个核心工具开始**：先把 Burp Suite 用熟，这是 Web 安全的基础
2. **手工优先，工具辅助**：先手工理解原理，再用工具提高效率
3. **不要沉迷工具数量**：精通 2-3 个核心工具 > 会用 10 个工具但都不精
4. **多练靶场**：在合法的靶场环境中练习使用工具
5. **看官方文档**：官方文档是最好的学习资料
6. **关注更新**：安全工具更新很快，定期看看有什么新功能
