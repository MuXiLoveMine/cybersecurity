## 1. 模块定位与前置知识

### 模块定位
云原生安全是当前安全行业**需求增长最快**的方向之一。随着企业全面上云和容器化改造，Kubernetes、微服务、Serverless 已经成为基础设施的标配，但传统安全工具和思路很难直接套用。

云原生安全覆盖 **云平台安全、容器安全、Kubernetes 安全、微服务安全、Serverless 安全、DevSecOps** 等多个层面，是攻防两端都需要掌握的核心技能。

### 前置知识
- **必选前置**：M1（Linux/Bash/Python）+ M2（Linux 深入）+ M3（网络）+ M4（Web 安全基础）
- **推荐前置**：Docker 基础使用经验、Linux 系统管理经验
- **环境要求**：本地 Kubernetes 集群（minikube / kind）、云账号（AWS 免费 tier / 阿里云试用）
- **编程语言**：Go 语言基础（云原生工具大多用 Go 开发，能看懂即可）

### 云原生安全能力分级

| 级别 | 能力描述 | 对应岗位 |
|------|---------|---------|
| **L1 入门** | 会用 Docker/K8s、了解常见安全风险、会用扫描工具 | 安全工程师（云方向入门） |
| **L2 实用** | 能做 K8s 安全评估、部署安全工具、理解容器逃逸原理 | 云安全工程师 |
| **L3 熟练** | 能设计云原生安全体系、容器攻防、K8s 高级利用 | 高级云安全工程师 |
| **L4 精通** | 云原生安全架构、零信任、高级攻防、供应链安全 | 云安全架构师 |

### 项目二：K8s 渗透测试实战

**目标**：从一个普通 Pod 的 Shell 出发，一步步获取集群管理员权限。

**实验环境**：Kubernetes Goat 或自己搭建的有漏洞的 K8s 集群

**攻击路径练习**（至少完成 3 条不同路径）：

**路径一：ServiceAccount 提权**
```
Pod Shell → 读取 SA token → kubectl 用 token 访问 API 
  → 发现 SA 有 pods/exec 权限 → exec 到高权限 Pod
  → 获取更高权限 SA token → 最终拿到 cluster-admin
```

**路径二：容器逃逸到节点**
```
Pod Shell → 发现容器是特权模式 / 挂载了 Docker Socket
  → 容器逃逸到宿主机 → 获取 kubelet 权限
  → 通过 kubelet 获取所有 Pod 的 Secret → 集群管理员
```

**路径三：Secret 泄露 → 横向移动**
```
Pod Shell → 读取挂载的 Secret → 发现数据库密码 / 其他服务密钥
  → 横向移动到其他服务 → 获取更多权限
  → 最终控制集群
```

**路径四：etcd 未授权访问**
```
Pod 内 → 网络探测 → 发现 etcd 服务未认证
  → 直接读取 etcd 所有数据 → 获取所有 Secret
  → 集群完全控制
```

**任务要求**：
- 每条攻击路径都有详细步骤和截图
- 分析漏洞成因和修复方案
- 用 ATT&CK 映射攻击技术
- 输出完整渗透测试报告

**预计耗时**：30 小时
**产出物**：K8s 渗透测试报告 + 攻击路径图 + 修复建议

### 项目三：DevSecOps 流水线建设

**目标**：为一个示例项目搭建完整的 DevSecOps 流水线，从代码提交到部署全流程安全检查。

**流水线阶段**：
1. **代码提交阶段（Pre-commit）**
   - Git hooks：代码格式检查、密钥检测（gitleaks）
   - 本地 SAST 扫描（Semgrep）
2. **CI 构建阶段**
   - 代码静态分析（SonarQube / Semgrep）
   - 依赖组件扫描（SCA）：OWASP Dependency-Check / Snyk
   - 密钥检测（TruffleHog）
   - IaC 扫描（Checkov / tfsec）
3. **镜像构建阶段**
   - Dockerfile 安全扫描（Hadolint）
   - 镜像漏洞扫描（Trivy）
   - 镜像签名（Cosign）
   - SBOM 生成
4. **部署前阶段**
   - K8s 清单安全扫描（Kubescape / Checkov）
   - OPA / Kyverno 策略验证
5. **部署后阶段**
   - 运行时监控（Falco）

## 9. 常见误区

### ❌ 误区 1：云安全就是"把传统安全搬到云上"
**现象**：觉得云安全就是在云上装防火墙、装杀毒、装 IDS，和传统安全没区别。
**纠正**：云安全有其独特的风险模型。身份管理（IAM）是云安全的核心，配置错误是最大的风险源，共享责任模型改变了安全边界。云安全需要理解云原生的架构和服务，用云原生的方式做安全。

### ❌ 误区 2：云安全就是 AWS 安全，其他云不用学
**现象**：只学 AWS，觉得其他云都一样。
**纠正**：虽然云安全的核心概念是相通的，但不同云厂商的服务名称、权限模型、默认配置差异很大。国内就业市场阿里云/腾讯云/华为云的需求也很大。先深入一个云（推荐 AWS 或阿里云），理解核心原理，其他云可以快速迁移。

### ❌ 误区 3：K8s 安全就是"装几个工具"
**现象**：装了 Falco、Kubescape、Trivy，就觉得 K8s 安全做好了。
**纠正**：工具只是手段，安全是体系化的工作。K8s 安全涵盖身份、网络、 workload、数据、运行时、供应链等多个层面。工具需要正确配置、持续调优，还要有流程和人来运营。

### ❌ 误区 4：容器逃逸是 K8s 安全的全部
**现象**：一提 K8s 安全就说容器逃逸，其他都不关心。
**纠正**：容器逃逸只是 K8s 安全的一小部分。实际环境中，更常见的是 RBAC 配置错误、Secret 泄露、Service Account 权限过大、Network Policy 缺失等配置问题。真实攻击路径往往是"配置错误 → 信息泄露 → 权限提升"，而不是上来就逃逸。

### ❌ 误区 5：只会用工具，不懂原理
**现象**：会用 kube-bench 扫，会用 Kubescape 看报告，但问 RBAC 原理、API Server 认证流程就懵了。
**纠正**：工具是辅助，原理是根本。K8s 安全的核心是理解 K8s 的架构、认证授权流程、各组件的作用。理解了原理，你才能看懂工具的报告、分析风险、制定加固方案，也才能发现工具发现不了的问题。

### ❌ 误区 6：忽视 IaC 和 CI/CD 安全
**现象**：只关注运行时安全，不关心代码和流水线的安全。
**纠正**：安全左移是趋势。很多安全问题在编码和部署阶段就能发现和修复，成本远低于运行时发现。DevSecOps 和 IaC 安全是云原生安全工程师的必备技能。

### ❌ 误区 7：没有云账号就学不了云安全
**现象**：觉得必须有云账号才能学云安全，怕花钱。
**纠正**：
- 各大云都有免费 tier（AWS 免费 12 个月、阿里云新用户免费试用）
- 本地可以用 minikube / kind 搭 K8s 集群练习
- Kubernetes Goat 等靶场可以本地跑
- 很多工具（Trivy / Kubescape / Falco）都可以本地实验
- 关键是理解原理，平台只是载体
